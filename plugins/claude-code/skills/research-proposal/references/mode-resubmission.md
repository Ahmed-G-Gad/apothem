## Mode: `--resubmission` (Grant Resubmission Response)

`--resubmission <PATH>` answers a funder's critique of an earlier application outside the thirteen-stage pipeline. **The Sequence Gate does not apply**: the synthesis, the theory, and the Handoff Manifest are neither required nor read, because the operator supplies the inputs — the critique at `<PATH>`, the call text (`--call`), the application as submitted, and the revised draft. The application and the revised draft are requested through the structured-inquiry channel, as paths or pasted text, when the session has not named them. Phases 1 to 5 do not run, and one obligation carries over: the call's policy on automated-tool use resolves as the Phase 1 tool-use policy gate sets out before step 2 writes any text. The fifteen-bar pre-emission gate still runs on `{suite}/_outputs/resubmission-response.md`, which names `/research-proposal --resubmission` as its producer in its header per `rules/context-management-scratch.md` §2, records no stage attestation, and leaves the manifest untouched. `{suite}` resolves as the `--suite-name` input row sets: the named suite, else the active suite context, else the name the structured-inquiry channel returns. The mode adds no scientific content: a response that needs new evidence returns to the operator, who routes it to `/research-design` or `/research-experiment`.

1. **Eligibility and limits.** Read from the supplied call text whether a resubmission is permitted, how many the call allows, the deadline, and the limits on the response and the revised application, as call-requirement rows. A rule the text leaves unstated is an operator inquiry, never recall, and without call text this step is itself an operator inquiry and the response cannot reach `ready`. A resubmission the text forbids stops the mode.
2. **Revision matrix.** One row per critique comment, numbered as the funder numbers it: the comment, quoted; the action (`changed`, `clarified`, `declined`); the revised locus (aim, method, timeline, budget line, or data-plan entry); the scientific consequence (what the change does to aims, design, feasibility, or risk, or `none`); the unresolved question (what it leaves open, or `none`); and the status (`answered`, `partly-answered`, `not-answered`) with the revised text that supports it. A declined comment carries its reason and evidence.
3. **Propagation check.** Trace each `changed` row to every plan element it touches: aims, methods, timeline, budget lines, data management and sharing plan, risk register. An element the change touches and the revised draft leaves unchanged is `unpropagated`. No response claims a change the draft lacks.

The response is `ready` when every row is `answered` or carries an operator-accepted residual, no element is `unpropagated`, and every call limit is met. The command stops there; the operator submits.
