# Assets

The `apothem` brand assets — logo, icon, favicon, and social-banner files. This directory is the repository-root source of truth: it is referenced by the README, `SUPPORT.md`, the GitHub Pages public surface, and the OG / Twitter Card meta tags. Brand text renders with system UI fonts so the SVG sources carry no embedded font payload while preserving deterministic raster rebuilds.

## Source vs. generated vs. hand-authored runtime

| Path | Role |
|------|------|
| `src/logo.svg`, `src/logo-dark.svg`, `src/logo-animated.svg` | The **editable SVG sources** for the mark — hand-authored vector originals. Edits start here. |
| `src/apple-touch.svg`, `src/icon-maskable.svg` | The **editable SVG sources** for the dark-tile Apple touch icons and the full-bleed maskable PWA icons — rendered on an opaque tile so the mark stays legible over any wallpaper or adaptive-launcher crop. |
| `src/og-banner.svg`, `src/twitter-card.svg` | The **editable SVG sources** for the two social cards. |
| `logo.svg`, `logo-dark.svg`, `logo-animated.svg` | Generated / optimized SVG renderings used at runtime. |
| `logo-16.png` … `logo-1024.png`, `logo.png` | Generated raster logo set (light), regenerated from `src/logo.svg` — includes the `logo-192.png` / `logo-512.png` PWA-manifest `purpose: any` icons. |
| `logo-dark-16.png` … `logo-dark-1024.png` | Generated raster logo set (dark), regenerated from `src/logo-dark.svg`. |
| `logo-maskable-192.png`, `logo-maskable-512.png` | Generated maskable PWA icons, rendered from `src/icon-maskable.svg` (the PWA-manifest `purpose: maskable` icons). |
| `favicon.ico`, `favicon-16x16.png`, `favicon-32x32.png` | Generated favicon set from the simplified `favicon.svg` master. |
| `apple-touch-icon-120.png` … `apple-touch-icon-180.png` | Generated Apple touch-icon set, rendered from the `src/apple-touch.svg` dark-tile master so the mark stays legible on dark backgrounds. |
| `og-banner-1200x630.png`, `twitter-card.png` | Generated social-share banners (Open Graph 1200×630; Twitter / X 1200×628). |
| `logo-wordmark.svg`, `logo-wordmark-dark.svg` | Hand-authored horizontal lockups: mark + `apothem` wordmark for light and dark surfaces. |
| `favicon.svg` | Hand-authored compact monogram favicon for browser-tab legibility at 16px. |
| `github-avatar.svg` | Hand-authored 420×420 monogram avatar for the GitHub organization. |
| `social-preview.svg` | Hand-authored 1200×630 social preview card for the README and GitHub repository social-image surface. |

The raster files, primary `logo.png`, three runtime SVGs (`logo.svg`, `logo-dark.svg`, `logo-animated.svg`), and two social-card PNGs (`og-banner-1200x630.png`, `twitter-card.png`) are regenerated or synchronized from `src/` by the single canonical generator [`scripts/dev/rebuild-assets-resvg.py`](../scripts/dev/rebuild-assets-resvg.py) (a `resvg` binary plus Pillow); a `--check-only` mode verifies the toolchain. One generator means one deterministic raster corpus — every icon the PWA manifest references is produced from the correct master in a single pass, and `tests/unit/test_assets_manifest_coverage.py` asserts that coverage. The favicon PNG / ICO set is rendered from the compact root `favicon.svg`; the generator mirrors web-served assets — including the hero logo sources the site references — into `site/public/`. The five hand-authored runtime SVGs (`logo-wordmark.svg`, `logo-wordmark-dark.svg`, `favicon.svg`, `github-avatar.svg`, `social-preview.svg`) are not regenerated by the generator; edits land directly at the assets root before rerunning the mirror step.

## Design system

The brand's color, spacing, and typography tokens live beside the logo assets
and are the single source of truth the site theme and the docs brand pages
consume.

| Path | Role |
|------|------|
| `DESIGN-SYSTEM.md` | Hand-authored design-system reference — the human-readable specification of the brand's tokens, usage rules, and rationale. |
| `design-tokens.css` | Hand-authored CSS custom-property token surface consumed by the site theme. |
| `design-tokens.json` | Hand-authored machine-readable token export mirroring `design-tokens.css` for tooling. |

These three files are hand-edited (not generated by the raster generator);
keep `design-tokens.css` and `design-tokens.json` in sync when a token changes,
and mirror any token or usage-rule change into `site/content/docs/brand/`.

## Conventions

- Edit `src/` for generated mark and social-card sources; edit hand-authored root SVGs directly when changing favicon, wordmark, avatar, or GitHub social-preview masters. Never edit a generated raster or generated runtime SVG by hand — the next rebuild overwrites it.
- Keep social cards in the logo-left lockup: the hexagon mark anchors the left side, while the full lockup is centered inside the inner panel padding and the headline, supporting lines, and chips are left-aligned within the right-hand content column.
- Raster sizes follow the `logo-<px>.png` naming pattern.
- Regenerate after any source edit so the committed raster set and `site/public/` mirror stay current — a stale committed output is a defect.
- SVG sources carry no embedded font payload (brand text renders with system UI fonts); preserve that so raster rebuilds stay deterministic.

## Working in this folder

To change a mark: edit the `src/` source, then run
[`scripts/dev/rebuild-assets-resvg.py`](../scripts/dev/rebuild-assets-resvg.py)
and commit the regenerated outputs and `site/` mirrors in the same change-set.
To change a hand-authored runtime SVG: edit it at the assets root, then rerun
the generator's mirror step. Verify the toolchain and that committed outputs match
sources with the generator's `--check-only` mode before handoff.
