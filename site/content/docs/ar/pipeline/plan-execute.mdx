**الدور:** المُنفِّذ
**موضع خط الأنابيب:** طرفي

يُنفِّذ مرحلة محدّدة من حزمة الخطة الرئيسية مع فحص المطابقة.

## الاستدعاء المعياري

```bash
/plan-execute
```

مع وسائط:

```bash
/plan-execute [path/to/plan-suite/] [phase-id] [--dry-run]
```

## المدخلات

حزمة خطة مُولَّدة + مُراجَعة؛ ملف <bdi>`_inputs/handoff-manifest.yml`</bdi> المُراجَع

## المخرجات

ملفات <bdi>REPORT.md</bdi> لكل مرحلة، ومُنتَجات قاعدة الشيفرة، و<bdi>COMPLETION.md</bdi>

## في اتجاه المصبّ

يُحصِّن <bdi>`/fortress`</bdi> العمل المُنفَّذ إلى حالة خاضعة لبوابة الإصدار في استدعاء واحد (الكشف، والتحقّق، والمعالجة، وإعادة التدقيق، والبوابة). وبصورة افتراضية يتوقّف مؤقتًا للتأكيد عند حدّ كل جولة؛ و<bdi>`--autonomous`</bdi> يُنفِّذ الجولات دون توقّف. ‏<bdi>`/code-review`</bdi> — نقطة الدخول المعيارية لتسلسل مراجعة التدقيق ذي الأحد عشر أمرًا، الذي يسير في السلسلة مرحلةً بعد أخرى. ‏<bdi>`/plan-execute`</bdi> هو المرحلة الطرفية من خط أنابيب *الخطة*؛ وحين تكتمل المرحلة الأخيرة، تُسلَّم الشيفرة المبنيّة إلى تسلسل مراجعة التدقيق لمراجعتها.

## مراحل سير العمل

يتّبع الأمر سير العمل المعياري لخط أنابيب <bdi>`/plan`</bdi>:

1. **تحميل السياق** — قراءة حزمة الخطّة والقواعد وعقد الاستئناف.
2. **التحقّق من المتطلبات المسبقة** — تأكيد اكتمال مراحل التبعية.
3. **تنفيذ المهام** — أداء مهمّة الأمر.
4. **التحقّق من المخرجات** — تأكيد وجود جميع المخرجات المُعلَنة واجتيازها لبوابات الجودة.
5. **إصدار <bdi>REPORT.md</bdi>** — تُسجَّل نتيجة بوابة ما قبل الإصدار.
6. **تحديث <bdi>PROGRESS.md</bdi>** — تسجيل المخرجات المُتحقَّق منها في سجلّ مخرجات المرحلة.

## أنماط الفشل

| العَرَض | السبب | الاستعادة |
|---------|-------|----------|
| متطلب مسبق غير مكتمل | لم تنتهِ المرحلة المعتمَد عليها | أكمل المرحلة في اتجاه المنبع أولًا |
| بوّابة الجودة FAIL | المُخرَج لا يفي بالمعايير | أصلح المُخرَج وأعد التشغيل |
| ملف إدخال مفقود | ملف حزمة الخطة غائب | شغّل <bdi>`/plan-generate`</bdi> لإنشائه |

## أمثلة

```bash
# Dry-run to preview what would happen
/plan-execute --dry-run

# Execute against a named plan suite
/plan-execute path/to/plan-suite/
```
