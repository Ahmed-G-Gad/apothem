يُبلِّغ عن حالة التثبيت والتحقّق والانحراف لكل مساعد برمجي مُسجَّل.

## الموجز

```
apothem status [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

<bdi>`status`</bdi> أمر فحص للقراءة فقط. يتنقّل عبر كل مُحَوِّل مساعد برمجي مُسجَّل ويُبلِّغ عن ثلاث حقائق لكل مساعد برمجي: ما إذا كان مُثبَّتًا، وما إذا كانت أهدافه المُدارة تتحقّق، وما إذا كانت التهيئة المُثبَّتة قد انحرفت عن الملف الشخصي المشترك. ولا يكتب أي شيء على القرص.

لكل مساعد برمجي، يُبلِّغ <bdi>`status`</bdi> عن:

| العمود | المعنى |
|---|---|
| `installed` | تهيئة المُحَوِّل المُدارة موجودة في مسار هدفه. |
| `verified` | أهداف المُحَوِّل المُدارة موجودة وصالحة. |
| `drift` | حُكم وفاء الملف الشخصي (انظر أدناه). |

قيمة <bdi>`drift`</bdi> هي إحدى التالية:

| القيمة | المعنى |
|---|---|
| `in-sync` | تحمل التهيئة المُثبَّتة الملف الشخصي المشترك المُسقَط حديثًا حرفيًّا. |
| `drift` | المساعد البرمجي مُثبَّت لكن محتوى ملفه الشخصي المُسقَط لم يعد مطابقًا للملف الشخصي المشترك الحالي. أعِد تشغيل <bdi>`apothem install`</bdi> لإعادة الإسقاط. |
| `absent` | المساعد البرمجي غير مُثبَّت، فلا يوجد ما يُقارَن. |
| `needs-project` | جرى الإبلاغ عن مساعد برمجي بنطاق المشروع دون <bdi>`--project`</bdi>، لذا تعذّر حلّ هدفه. مرّر <bdi>`--project PATH`</bdi> لفحصه. |

يُبلَّغ عن الانحراف ولا يُعامَل أبدًا كخطأ: يخرج <bdi>`status`</bdi> بالرمز 0 حتى عندما يُبلِّغ مساعد برمجي واحد أو أكثر عن <bdi>`drift`</bdi>. الانحراف حقيقة عن إعدادك، وليس فشلًا في الأمر.

إذا تعذّر تحميل الملف الشخصي المشترك، يتراجع الانحراف إلى <bdi>`absent`</bdi> للمساعدات البرمجية المُثبَّتة (مع استمرار الإبلاغ عن حقائق installed/verified) بدلًا من إجهاض المسح.

## الخيارات

| الخيار | الوصف |
|---|---|
| `--project PATH` | جذر المشروع للمساعدات البرمجية بنطاق المشروع. وبدونه، تُبلِّغ المساعدات البرمجية بنطاق المشروع عن <bdi>`needs-project`</bdi>. |
| `--quiet`, `-q` | يُخمِد المخرجات المعلوماتية؛ تُصدَر الأخطاء فقط. |
| `--verbose`, `-v` | يُصدِر مخرجات تشخيصية إضافية. |
| `--format plain\|json` | تنسيق المخرجات (الافتراضي: `plain`). |
| `--json` | اختصار لـ `--format json`. |
| `--no-color` | يُعطِّل رموز ألوان <bdi>ANSI</bdi> في المخرجات. |
| `-h`, `--help` | يعرض المساعدة ويخرج. |

## مخرجات JSON

يحمل غلاف <bdi>`--json`</bdi> صفّ نتيجة واحدًا لكل مساعد برمجي مُسجَّل. ويحمل كل صف المفاتيح المُوثَّقة <bdi>`harness`</bdi> و<bdi>`installed`</bdi> و<bdi>`verified`</bdi> و<bdi>`drift`</bdi>.

```json
{
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

عزل الأعطال لكل مُحَوِّل: إذا أطلق مُحَوِّل واحد استثناءً أثناء الإبلاغ عن حالته، يحمل صف ذلك المساعد البرمجي <bdi>`outcome: "error"`</bdi> ورسالة <bdi>`message`</bdi>، وتستمر بقية المساعدات البرمجية في الإبلاغ بشكل طبيعي، وتخرج العملية بالرمز 2.

## أمثلة

```bash
apothem status
apothem status --project .
apothem status --json
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | جرى الإبلاغ عن الحالة (الانحراف يُبلَّغ عنه، وليس خطأً) |
| 2 | أخفق مُحَوِّل واحد على الأقل في الإبلاغ عن حالته |
