الإبلاغ عن حالة التثبيت والتحقّق والانحراف لكل إطار عمل مُسجَّل.

## الموجز

```
apothem status [--profile PATH] [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

<bdi>`status`</bdi> أمر فحص للقراءة فقط. يمرّ على كل محوّل إطار عمل مُسجَّل ويُبلِغ عن
ثلاث حقائق لكل إطار عمل: هل هو مُثبَّت، وهل تجتاز أهدافه المُدارة التحقّق، وهل انحرف
الإعداد المُثبَّت عن الملف التعريفي المشترك. ولا يكتب أي شيء على القرص.

لكل إطار عمل، يُبلِغ <bdi>`status`</bdi> عن:

| العمود | المعنى |
|---|---|
| <bdi>`installed`</bdi> | إعداد المحوّل المُدار موجود في مسار هدفه. |
| <bdi>`verified`</bdi> | أهداف المحوّل المُدارة موجودة وصالحة. |
| <bdi>`drift`</bdi> | حكم الأمانة للملف التعريفي (انظر أدناه). |

قيمة <bdi>`drift`</bdi> واحدة مما يلي:

| القيمة | المعنى |
|---|---|
| <bdi>`in-sync`</bdi> | يحمل الإعداد المُثبَّت الملف التعريفي المشترك المُسقَط حديثًا حرفيًا. |
| <bdi>`drift`</bdi> | إطار العمل مُثبَّت لكن محتوى ملفه التعريفي المُسقَط لم يعد يطابق الملف التعريفي المشترك الحالي. أعِد تشغيل <bdi>`apothem install`</bdi> لإعادة الإسقاط. |
| <bdi>`absent`</bdi> | إطار العمل غير مُثبَّت، فلا يوجد ما يُقارَن. |
| <bdi>`needs-project`</bdi> | جرى الإبلاغ عن إطار عمل ذي نطاق مشروع دون <bdi>`--project`</bdi>، لذا يتعذّر تحليل هدفه. مرِّر <bdi>`--project PATH`</bdi> لفحصه. |
| <bdi>`unknown`</bdi> | تعذّر تحميل الملف التعريفي الافتراضي، لذا لا يملك إطار العمل المُثبَّت خطَّ أساس يُقارَن به. أصلِح الملف التعريفي لاستعادة حكم الانحراف. |

يُبلَّغ عن الانحراف ولا يُعامَل أبدًا بوصفه خطأً: يخرج <bdi>`status`</bdi> بالرمز 0 حتى
عندما يُبلِغ إطار عمل واحد أو أكثر عن <bdi>`drift`</bdi>. الانحراف حقيقة عن إعدادك، لا
إخفاق للأمر.

إذا تعذّر تحميل الملف التعريفي المشترك الافتراضي، يتراجع الانحراف إلى
<bdi>`unknown`</bdi> لأُطُر العمل المُثبَّتة (مع استمرار الإبلاغ عن حقيقتَي
<bdi>installed/verified</bdi>) بدلًا من إجهاض المسح. أما <bdi>`--profile`</bdi> الصريح
الذي يتعذّر تحميله فهو خطأ من المستخدم، فيُجهَض الأمر بخطأ مُهيكَل بدلًا من ذلك.

ويُبلَّغ عن هذا التراجع دائمًا: يطبع <bdi>`status`</bdi> تنبيهًا يُسمّي الملف التعريفي
والإصلاح، ويحمل غلاف <bdi>`--json`</bdi> مُدخَلًا مطابقًا
<bdi>`drift_baseline_unavailable`</bdi> في <bdi>`warnings`</bdi>. ويكتسب هذا أهمية
قصوى عندما لا يكون أي إطار عمل مُثبَّتًا — إذ يظهر كل صف عندئذٍ بالقيمة
<bdi>`absent`</bdi> ولا توجد أي خلية <bdi>`unknown`</bdi>، فيكون التنبيه الإشارة
الوحيدة إلى أن خط الأساس لم يُحمَّل قطّ.

## الخيارات

| الخيار | الوصف |
|---|---|
| <bdi>`--profile PATH`</bdi> | ملف <bdi>YAML</bdi> للملف التعريفي المشترك الذي يحدّد خط أساس الانحراف. ومن دونه، يُستخدَم الملف التعريفي الافتراضي (<bdi>`~/.config/apothem/profile.yaml`</bdi>). |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. ومن دونه، تُبلِغ أُطُر العمل ذات نطاق المشروع عن <bdi>`needs-project`</bdi>. |
| <bdi>`--quiet`</bdi>، <bdi>`-q`</bdi> | يُخمِد المخرجات المعلوماتية؛ لا تُصدَر إلا الأخطاء. |
| <bdi>`--verbose`</bdi>، <bdi>`-v`</bdi> | يُصدِر مخرجات تشخيصية إضافية. |
| <bdi>`--format plain\|json`</bdi> | صيغة المخرجات (الافتراضي: <bdi>`plain`</bdi>). |
| <bdi>`--json`</bdi> | اختصار لـ <bdi>`--format json`</bdi>. |
| <bdi>`--no-color`</bdi> | يُعطِّل رموز ألوان <bdi>ANSI</bdi> في المخرجات. |
| <bdi>`-h`</bdi>، <bdi>`--help`</bdi> | يعرض المساعدة ويخرج. |

## مخرجات <bdi>JSON</bdi>

يحمل غلاف <bdi>`--json`</bdi> صفّ نتيجة واحدًا لكل إطار عمل مُسجَّل. ويحمل كل صف
المفاتيح المُوثَّقة <bdi>`harness`</bdi>، و<bdi>`installed`</bdi>، و<bdi>`verified`</bdi>،
و<bdi>`drift`</bdi>. وتكون <bdi>`warnings`</bdi> فارغة في المسح النظيف؛ وعندما يتعذّر
تحميل الملف التعريفي الافتراضي تحمل مُدخَلًا واحدًا
<bdi>`drift_baseline_unavailable`</bdi> مع <bdi>`path`</bdi>، و<bdi>`code`</bdi>،
و<bdi>`reason`</bdi>، و<bdi>`fix`</bdi>.

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

عزل الإخفاق لكل محوّل: إذا رفع محوّل واحد استثناءً أثناء الإبلاغ عن حالته، يحمل صفّ
إطار العمل ذاك <bdi>`outcome: "error"`</bdi> و<bdi>`message`</bdi>، وتظلّ بقية أُطُر
العمل تُبلِغ على نحو طبيعي، وتخرج العملية بالرمز 2.

## أمثلة

```bash
apothem status
apothem status --project .
apothem status --json
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | جرى الإبلاغ عن الحالة (يُبلَّغ عن الانحراف، وليس خطأً) |
| 1 | خطأ تحقّق متوقَّع (<bdi>`--profile`</bdi> غير صالح، أو مسار <bdi>`--project`</bdi> غير موجود) |
| 2 | أخفق محوّل واحد على الأقل في الإبلاغ عن حالته |
| 64 | خطأ في الاستخدام: خيار أو أمر غير معروف، أو قيمة خيار مفقودة أو غير صالحة. مع <bdi>`--json`</bdi> يكون الخطأ غلاف <bdi>JSON</bdi> بالرمز <bdi>`cli.usage`</bdi>. |
