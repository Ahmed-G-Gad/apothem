يزيل إعداد محوّل إطار عمل.

## الموجز

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

يزيل أهداف إطار العمل التي يديرها المحوّل، ثم الأدلة التي أنشأها التثبيت متى صارت فارغة
(يبقى الدليل الذي يحوي أي شيء يخصّك).

تُنسَخ الذاكرةُ والسياقاتُ ومخازنُ التعلّم في دليل العمل المشترك احتياطيًا وتُزال فقط حين
يكون هذا آخرَ إطار عمل مُثبَّت في ذلك الدليل. ويُزيلها أمرُ الإزالة في الموقع الذي سجّله التثبيت،
فيجدها أينما كتبها التثبيت (راجِع حقول <bdi>`workspace`</bdi> في الملف التعريفي). ولا يُزال دليل <bdi>`plans/`</bdi> أبدًا.

يطلب التأكيد ما لم يُمرَّر <bdi>`--yes`</bdi>. وحين يتعذّر عرض مطالبة — مع <bdi>`--format json`</bdi>
(إذ سيُفسد نصُّ المطالبة مستندَ <bdi>JSON</bdi> الوحيد) أو في صدفة غير تفاعلية (دون <bdi>TTY</bdi>) —
يرفض الأمر منذ البداية بخطأ مُهيكَل <bdi>`uninstall.confirmation_required`</bdi> (رمز الخروج 1) ما لم
يُمرَّر <bdi>`--yes`</bdi>. وإذا لم يكن إطار عمل مختار مثبّتًا، ينجح الأمر (رمز الخروج 0)، ويطبع في
المخرج النصي العادي <bdi>`NAME is not installed; nothing to remove.`</bdi>، حيث <bdi>`NAME`</bdi> هو معرّف إطار العمل.

تبقى مخازن البيانات المشتركة تحت <bdi>`.apothem/`</bdi> في جذر التثبيت
(<bdi>`memory/`</bdi>، و<bdi>`contexts/`</bdi>، و<bdi>`learning/`</bdi>) ما دام إطار
عمل مثبّت آخر في الجذر نفسه ما يزال يستخدمها. وحين يكون إطار العمل الذي تزيله هو
الأخير في ذلك الجذر، ينسخ الأمر كل مخزن أولًا إلى جذر النسخ الاحتياطي الخاص بـ
<bdi>Apothem</bdi> (<bdi>`~/.apothem/backups/`</bdi>)، ثم يزيله بكل ما فيه. وأي شيء
تحتفظ به في <bdi>`plans/`</bdi> لا يُزال أبدًا.

## المجلّدات المشتركة في دليلك المنزلي

يمكن لعدّة تثبيتات أن تستخدم مجلّدًا واحدًا في دليلك المنزلي: مجلّد المهارات
(<bdi>`~/.agents/skills/`</bdi>، أو <bdi>`~/.codebuddy/skills/`</bdi>، أو <bdi>`~/.kiro/skills/`</bdi>، أو
<bdi>`~/.trae/skills/`</bdi>) و<bdi>`~/.config/apothem/rules/`</bdi> و
<bdi>`~/.config/apothem/templates/`</bdi>. وتسرد صفحة [التثبيت](/docs/cli-reference/install#المجلّدات-في-دليلك-المنزلي)
أيّ محوّل يكتب أيّها. ويسجّل <bdi>Apothem</bdi> التثبيتات التي تستخدم كل مجلّد،
ويتبع إلغاء التثبيت قاعدة واحدة: لا يُزيل مجلّدًا إلا حين لا يعود أي تثبيت آخر لـ
<bdi>Apothem</bdi> يستخدمه.

- يُبقي إلغاء تثبيت أداة واحدة المهاراتِ ما دام تثبيت آخر يستخدمها، ويقول ذلك.
  وتُعَدّ الأداة الواحدة المثبّتة في مشروعين تثبيتين، لذا فإن إلغاء تثبيتها من المشروع
  A يُبقي المجلّدات ما دام المشروع B يستخدمها. وآخر إلغاء تثبيت يُزيلها (انظر المثال
  الثاني أدناه).
- لا يُزال إلا ما يسرده سجلّ التثبيت الخاص. والتثبيت الذي جرى قبل أن تصبح المجلّدات
  مُدارة ليس له مثل هذا السجلّ، لذا فإن إلغاء تثبيته لا يُزيل شيئًا من دليلك المنزلي.
  وتبقى الملفات التي أضفتها إلى المجلّدات، وكذلك المجلّد الذي يحمل اسم مهارة من
  <bdi>Apothem</bdi> ولم يكتبه <bdi>Apothem</bdi>.
- يُتجاهَل التثبيت الذي لم يعد مجلّد مشروعه موجودًا، فلا يُبقي مشروعٌ محذوف المجلّداتِ
  إلى الأبد. وتسمّيه الملاحظة.
- إذا تعذّرت قراءة سجلّ تثبيتٍ يمكن أن يستخدم المجلّدات، يتوقّف إلغاء التثبيت مع خطأ
  قبل أن يُزيل أي شيء، ويبقى التثبيت مُسجَّلًا. أصلِح السجلّ غير المقروء أو انقله، ثم
  شغّل الأمر مجدّدًا. أما السجلّ التالف لأداة لا تكتب هذه المجلّدات أبدًا فيُتجاهَل.
- حين يذهب آخر استخدام، تُزال أيضًا المجلّدات التي تبقى فارغة. ويُنسَخ كل مجلّد
  احتياطيًا تحت <bdi>`~/.apothem/backups/`</bdi> قبل إزالته.

يطبع كل إلغاء تثبيت ملاحظة <bdi>`Note:`</bdi> واحدة لكل مجلّد، مثل <bdi>`Note: <harness> -
~/.agents/skills/ was kept: still used by <harness> (/path/to/project)`</bdi>، أو
<bdi>`was removed: no other Apothem install uses it`</bdi>. وفي غلاف <bdi>`--format json`</bdi> تكون كل
ملاحظة مُدخَلًا في <bdi>`warnings`</bdi> يحمل <bdi>`"outcome": "advisory"`</bdi>،
و<bdi>`"operation": "shared_root"`</bdi>، و<bdi>`"role"`</bdi> مضبوطًا على <bdi>`retained`</bdi> أو <bdi>`released`</bdi>. وهو
يحمل <bdi>`path`</bdi>، و<bdi>`holders`</bdi> (التثبيتات التي تُبقي المجلّد)، و<bdi>`stale`</bdi> (التثبيتات
المُتجاهَلة)، و<bdi>`kept`</bdi> و<bdi>`total`</bdi> (المُدخلات المُسجَّلة التي أُبقيت والمُدخلات التي سردها
التثبيت).

إذا بقي مجلّد بسبب تثبيت لا تستطيع العثور عليه، فإن الملاحظة تسمّيه. وحين يكون مجلّد
المشروع قد حُذف، يُتجاهَل التثبيت ويذهب المجلّد مع إلغاء التثبيت التالي. وحين يكون
المشروع موجودًا لكنك أزلت كتلة <bdi>Apothem</bdi> من ملف قواعده يدويًا، يُبلغ
<bdi>`uninstall`</bdi> عن إطار العمل بأنه غير مثبّت ولا يتخلّى عن مطالبته؛ شغّل
<bdi>`install`</bdi> لإطار العمل ذاك والمشروع ذاك، ثم <bdi>`uninstall`</bdi>، للتخلّي عنها.
ويُظهر <bdi>`apothem verify`</bdi> ما إذا كان المجلّد لا يزال مكتملًا.

الإزالة بـ <bdi>`--harness all`</bdi> شاملة عمدًا: تغطّي كل إطار عمل مُسجَّل، بما في ذلك أي إطار عمل
يتخطّاه <bdi>`exclude_harnesses`</bdi> في الملف التعريفي أثناء التثبيت، فيصل التنظيف إلى حالة ربما
خلّفها تثبيتٌ سابق أوسع نطاقًا. وتتلقّى أُطُر العمل التي لم تُثبَّت قطّ الإشعارَ نفسه.

يُحَلّ الاسم المستعار بصيغة الاستمرار <bdi>`apothem uninstalling`</bdi> (ويُقبَل أيضًا
بالصيغة <bdi>`apothem Uninstalling`</bdi>) إلى المعالج نفسه.

## الخيارات

| الخيار | الوصف |
|---|---|
| <bdi>`--harness NAME`</bdi> | محوّل إطار العمل المراد إزالته، أو <bdi>`all`</bdi> للمجموعة الشاملة للسجلّ كله (مطلوب). |
| <bdi>`--yes`</bdi> | يتخطّى مطالبة التأكيد. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. |
| <bdi>`--quiet`</bdi>، <bdi>`-q`</bdi> | يُخمِد المخرجات المعلوماتية؛ لا تُصدَر إلا الأخطاء. |
| <bdi>`--verbose`</bdi>، <bdi>`-v`</bdi> | يُقبَل من أجل الاتّساق مع الأوامر الأخرى؛ ولا يطبع هذا الأمر أي مخرجات إضافية. |
| <bdi>`--format plain\|json`</bdi> | صيغة المخرجات (الافتراضي: <bdi>`plain`</bdi>). |
| <bdi>`--json`</bdi> | اختصار لـ <bdi>`--format json`</bdi>. |
| <bdi>`--no-color`</bdi> | يعطّل رموز ألوان <bdi>ANSI</bdi> في المخرجات. |
| <bdi>`-h`</bdi>، <bdi>`--help`</bdi> | يعرض المساعدة ويخرج. |

## مخرجات <bdi>JSON</bdi>

عندما يكون المحوّل مثبّتًا وتنجح إزالته:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

عندما لا يكون المحوّل مثبّتًا، يخرج الأمر برمز <bdi>`0`</bdi>. وفي مخرجات <bdi>JSON</bdi> يحمل الغلاف <bdi>`"status": "success"`</bdi> و<bdi>`"action": "uninstalled"`</bdi>، ويحمل صف النتائج <bdi>`"outcome": "skipped"`</bdi> مع الرسالة <bdi>`"not installed; no files removed"`</bdi>. ولا يكون حقل <bdi>`status`</bdi> أبدًا <bdi>`"not_installed"`</bdi>.

## أمثلة

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

يبقى مجلّد المهارات المشترك حتى يذهب آخر تثبيت يستخدمه:

```bash
apothem install --harness codex
apothem install --harness cursor --project A
apothem uninstall --harness codex --yes                  # keeps ~/.agents/skills/, the cursor install uses it
apothem uninstall --harness cursor --project A --yes     # removes it: no install uses it now
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | أُلغي تثبيت المحوّل، أو لم يكن مثبّتًا |
| 1 | إطار العمل غير موجود، أو رُفض التأكيد أو تعذّر (الوضع غير التفاعلي أو وضع <bdi>JSON</bdi> دون <bdi>`--yes`</bdi>)، أو أخفقت كل عمليات الإزالة |
| 2 | إزالة جزئية — أُزيل إطار عمل واحد على الأقل قبل وقوع إخفاق |
| 64 | خطأ استخدام: خيار أو أمر غير معروف، أو قيمة خيار مفقودة أو غير صالحة. ومع <bdi>`--json`</bdi> يكون الخطأ غلاف <bdi>JSON</bdi> يحمل الرمز <bdi>`cli.usage`</bdi>. |

## انظر أيضًا

- <bdi>`apothem uninstalling`</bdi> — اسم مستعار بصيغة الاستمرار لهذا الأمر (موثّق
  هنا؛ تقبل واجهة سطر الأوامر الصيغتين كلتيهما)
- [<bdi>apothem install</bdi>](/docs/cli-reference/install) — تثبيت إعداد إطار عمل
- [<bdi>apothem verify</bdi>](/docs/cli-reference/verify) — تأكيد حالة التثبيت
