تشغيل أوّل موجَّه: يضمن وجود ملف تعريفي، ويعاين عمليات الكتابة، ثم يثبّت.

## الموجز

```
apothem quickstart [--harness NAME|all] [--project PATH] [--profile PATH]
                   [--yes] [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

<bdi>`quickstart`</bdi> هو نقطة الدخول الموجَّهة الوحيدة للمُشغِّل الجديد. ففي تدفّق
خطّي واحد: (1) يضمن وجود ملف تعريفي مشترك — فيُنشئ ملفًا تعريفيًا مبدئيًا مع تنبيه
يحثّ على تخصيصه إن لم يعثر على أي ملف؛ (2) يعاين الملفات الفعلية التي ستكتبها أُطُر
العمل المختارة، مُجمَّعةً بحسب جذر المشروع مقابل دليلك المنزلي؛ (3) يطلب التأكيد؛
(4) يثبّت مع مخرجات ملاحظات القدرات المُجمَّعة والمُنقّاة من الضجيج؛ و(5) يطبع
الأوامر التالية الموصى بها.

وهو يركّب اللبنات نفسها التي يستخدمها الأمر <bdi>`install`</bdi> — ولا يعيد تنفيذها.
القيمة الافتراضية لـ <bdi>`--project`</bdi> هي الدليل الحالي. أمّا
<bdi>`--harness`</bdi> فلا قيمة افتراضية له: عند إغفاله، يسأل <bdi>`quickstart`</bdi>
عن إطار العمل المراد تثبيته، فيكتب التشغيل الأوّل إعداد إطار عمل واحد.
و<bdi>`--harness all`</bdi> يثبّت كل إطار عمل مدعوم، وهو دائمًا اختيار صريح.

## السلوك

- **إطار العمل** — دون <bdi>`--harness`</bdi>، يسرد التشغيل التفاعلي الأسماء المدعومة (إضافةً إلى <bdi>`all`</bdi>) ويطلب اختيار واحد منها قبل كتابة أي شيء. أما التشغيل الذي لا يستطيع السؤال — <bdi>`--yes`</bdi>، أو <bdi>`--format json`</bdi>، أو غياب الطرفية — فيتوقّف بخطأ استخدام يسمّي الخيار <bdi>`--harness`</bdi>، ولا يكتب شيئًا.
- **الملف التعريفي** — إذا لم يوجد ملف في مسار الملف التعريفي المُحَلّ، يعرض <bdi>`quickstart`</bdi> إنشاء ملف تعريفي مبدئي (ويُنشئه تلقائيًا مع <bdi>`--yes`</bdi>، أو في صدفة غير تفاعلية، أو مع <bdi>`--format json`</bdi>)، ويسمّي حقول الهوية النائبة التي ينبغي تخصيصها.
- **المعاينة + التأكيد** — بالنسبة إلى <bdi>`--harness all`</bdi>، تُسرَد الأهداف تحت عنوانين (جذر المشروع مقابل دليلك المنزلي)، ويطلب التشغيل التفاعلي التأكيد قبل الكتابة خارج المشروع. ويُثبَّت إطار عمل واحد محدَّد دون معاينة أو مطالبة. ويمضي كلٌّ من <bdi>`--yes`</bdi>، والصدفة غير التفاعلية، و<bdi>`--format json`</bdi> دون مطالبة. ورفض معاينة <bdi>`--harness all`</bdi> يُلغي التثبيت قبل كتاباته، أما الملف التعريفي المبدئي الذي أُنشئ في الخطوة 1 فيبقى محفوظًا.
- **التثبيت** — تُلخَّص القدرات التي لا يدعمها إطار العمل أصليًا في ملاحظة مُجمَّعة واحدة لكل إطار عمل (مرِّر <bdi>`--verbose`</bdi> للتفصيل لكل قدرة)؛ وتوجد المجموعة الكاملة دائمًا في مصفوفة التحذيرات في <bdi>`--format json`</bdi>.
- **الخطوة التالية** — تسمّي مخرجات الطرفية الأوامر اللاحقة (<bdi>`apothem verify …`</bdi>، <bdi>`apothem doctor`</bdi>). ويُوضَع مجلّد <bdi>`--project`</bdi> بين علامتَي اقتباس من أجل الصدفة، كما يقتبسه [<bdi>`doctor`</bdi>](/docs/cli-reference/doctor). وحين لا تستطيع علامات الاقتباس حمله، تطبع المخرجات الأمر حتى <bdi>`--project`</bdi> وتسمّي المجلّد بالكلمات بعده، ويكون مُدخَل <bdi>`recommended_next`</bdi> في <bdi>JSON</bdi> بالنصّ <bdi>`Run apothem verify --harness … with --project set to <folder>`</bdi>، وهو ليس أمرًا يُشغَّل كما هو.

## الخيارات

| الخيار | الوصف |
|---|---|
| <bdi>`--harness NAME`</bdi> | محوّل إطار العمل المراد تثبيته، أو <bdi>`all`</bdi> للمجموعة الشاملة للسجلّ كله. لا قيمة افتراضية: يسأل التشغيل التفاعلي؛ ويجب أن يمرّره التشغيل غير التفاعلي. |
| <bdi>`--profile PATH`</bdi> | مسار ملف <bdi>YAML</bdi> للملف التعريفي المشترك. القيمة الافتراضية <bdi>`~/.config/apothem/profile.yaml`</bdi>. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. القيمة الافتراضية هي الدليل الحالي. |
| <bdi>`--yes`</bdi> | يشغّل التسلسل الموجَّه الكامل على نحو غير تفاعلي (يتخطّى كل مطالبة). |
| <bdi>`--quiet`</bdi>، <bdi>`-q`</bdi> | يُخمِد المخرجات المعلوماتية؛ لا تُصدَر إلا الأخطاء. |
| <bdi>`--verbose`</bdi>، <bdi>`-v`</bdi> | يطبع تعليل كل قدرة غير مُسقَطة بدلًا من الملاحظة المُجمَّعة. |
| <bdi>`--format plain\|json`</bdi> | صيغة المخرجات (الافتراضي: <bdi>`plain`</bdi>). |
| <bdi>`--json`</bdi> | اختصار لـ <bdi>`--format json`</bdi>. |
| <bdi>`--no-color`</bdi> | يعطّل رموز ألوان <bdi>ANSI</bdi> في المخرجات. |
| <bdi>`-h`</bdi>، <bdi>`--help`</bdi> | يعرض المساعدة ويخرج. |

## مخرجات <bdi>JSON</bdi>

يُصدِر <bdi>`--format json`</bdi> مستندًا واحدًا يلخّص كل خطوة موجَّهة:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "quickstart",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "steps": [
    {"step": "profile", "outcome": "created", "path": "…", "placeholder_identity": ["name", "email", "github"]},
    {"step": "install", "status": "success", "harness": "all", "files_written": ["…"], "warnings": [], "results": []},
    {"step": "recommend", "next": ["apothem verify --harness all --project \".\"", "apothem doctor"]}
  ],
  "recommended_next": ["apothem verify --harness all --project \".\"", "apothem doctor"]
}
```

عندما تترك خطوة التثبيت ملفًا كما هو بسبب أسطر علامات <bdi>Apothem</bdi> فيه (انظر
[<bdi>`install`</bdi>](/docs/cli-reference/install#capability-notes))، تكون قيمتا
<bdi>`status`</bdi> كلتاهما <bdi>`"partial"`</bdi> ويكون رمز الخروج <bdi>`2`</bdi>. وفي
الوضع العادي يطبع التشغيل سطر <bdi>`✗`</bdi> الخاص بالتثبيت، ثم الخطوات التالية الموصى
بها. ولأن <bdi>`apothem verify`</bdi> يفشل لذلك الملف إلى أن تُصلحه، تكون الخطوة الأولى
عندئذٍ إصلاح كل ملف تركه التثبيت كما هو، وفق ما يقوله تحذيره، ثم تشغيل
<bdi>`apothem update`</bdi> للأدوات نفسها (<bdi>`Fix the files it left:`</bdi> في الوضع
العادي، وأول مُدخَل في <bdi>`recommended_next`</bdi> في <bdi>JSON</bdi>،
<bdi>`Fix each file the install left as it is, as its warning says, then run apothem update --harness …`</bdi>)،
بدلًا من <bdi>`apothem verify`</bdi>.

## أمثلة

```bash
apothem quickstart                                  # asks which harness
apothem quickstart --harness claude-code --yes
apothem quickstart --harness all --project . --yes  # every harness, explicitly
apothem quickstart --harness claude-code --json
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | اكتمل التشغيل الموجَّه |
| 1 | خطأ متوقّع في التحقّق، أو الملف التعريفي، أو إطار العمل، أو المشروع، أو المحوّل |
| 2 | جزئي: توقّفت دفعة بعد عملية كتابة واحدة على الأقل، أو ترك التثبيت ملفًا يحتفظ <bdi>Apothem</bdi> بكتلته فيه كما هو بسبب أسطر علامات <bdi>Apothem</bdi> فيه |
| 64 | خطأ استخدام: خيار أو أمر غير معروف، أو قيمة خيار مفقودة أو غير صالحة. ومع <bdi>`--json`</bdi> يكون الخطأ غلاف <bdi>JSON</bdi> يحمل الرمز <bdi>`cli.usage`</bdi>. |
