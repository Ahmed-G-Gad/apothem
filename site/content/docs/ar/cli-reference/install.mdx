تثبيت إعداد محوّل إطار عمل من الملف التعريفي المشترك.

## الموجز

```
apothem install --harness NAME|all [--profile PATH] [--dry-run]
                 [--clean|--fresh] [--yes] [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

يحمّل الملف التعريفي المشترك ويتحقّق منه، ويختار محوّلًا مُسمّى أو مجموعة
<bdi>`all`</bdi> الشاملة للسجلّ كله، ويتحقّق من خطة التجسيد، ويكتب الإعداد الأصلي
لإطار العمل إضافةً إلى حزم الدعم. وتتطلّب المحوّلات ذات نطاق المشروع
<bdi>`--project PATH`</bdi>. ويُقرَأ المجلّد مع اتّباع روابطه وتوسيع <bdi>`~`</bdi>،
ويُسمّيه سجلّ التثبيت على هذا النحو. والتثبيت المُسجَّل تحت تهجئة أخرى للمجلّد، مثل
رابط احتفظت به شيفرة <bdi>Python</bdi> أو إصدار سابق، يُنقَل إلى تلك التهجئة بمجرّد أن
يجتاز التثبيت فحوصه (انظر [<bdi>`uninstall`</bdi>](/docs/cli-reference/uninstall)).

يُحَلّ الاسم المستعار بصيغة الاستمرار <bdi>`apothem installing`</bdi> (ويُقبَل أيضًا
بالصيغة <bdi>`apothem Installing`</bdi>) إلى المعالج نفسه.

## التشغيل الأول دون ملف تعريفي

عند إغفال <bdi>`--profile`</bdi> وعدم وجود ملف تعريفي في المسار الافتراضي
(<bdi>`~/.config/apothem/profile.yaml`</bdi>)، يكتب <bdi>`install`</bdi> الملف
التعريفي المبدئي هناك أولًا، ويطبع <bdi>`Created a starter profile at <path>`</bdi>،
ثم يتابع. يحمل الملف التعريفي المبدئي حقول هوية نائبة، لذا يطبع التثبيت أيضًا ملاحظة
الهوية النائبة؛ خصّص الملف التعريفي، ثم شغّل
[<bdi>`update`</bdi>](/docs/cli-reference/update) لتطبيقه. ومع <bdi>`--json`</bdi>
يُبلَّغ عن الإنشاء بوصفه مُدخَلًا في <bdi>`warnings`</bdi> يحمل
<bdi>`"operation": "profile_created"`</bdi>.

- لا يكتب <bdi>`--dry-run`</bdi> الملف التعريفي أبدًا: تستخدم المعاينة الملف
  التعريفي المبدئي في الذاكرة وتُبلغ عن
  <bdi>`"operation": "profile_scaffold_preview"`</bdi>.
- لا يُنشَأ أبدًا ملفٌ مُحدَّد صراحةً عبر <bdi>`--profile PATH`</bdi> وغير موجود؛
  بل يخرج الأمر بالرمز 1 مع <bdi>`profile.not_found`</bdi>.

## معاينة نطاق الأثر

يتفرّع <bdi>`install --harness all`</bdi> إلى نطاقات مختلطة: تكتب المحوّلات ذات نطاق المشروع تحت جذر <bdi>`--project`</bdi> المُمرَّر، بينما تكتب المحوّلات ذات نطاق المستخدم تحت دليلك المنزلي — خارج ذلك الجذر. وقبل أن يكتب التثبيت أيّ ملف، يطبع الأمر الأهداف الفعلية مُجمَّعةً تحت عنوانين: تلك الموجودة داخل جذر المشروع، وتلك الموجودة تحت دليلك المنزلي. ويسرد عنوانٌ ثالث المجلّدات المشتركة في دليلك المنزلي التي تكتبها المحوّلات ذات نطاق المشروع، خارج <bdi>`--project`</bdi>: مجلد المهارات و<bdi>`~/.config/apothem/`</bdi> (انظر [المجلّدات في دليلك المنزلي](#المجلّدات-في-دليلك-المنزلي)). والاستثناء الوحيد هو <bdi>`--clean`</bdi>: فخطوة البداية النظيفة فيه تعمل قبل هذه المعاينة، فتكتب نسخة احتياطية وتُزيل الأهداف السابقة، كما هو موضّح أدناه.

عندما يكتب الاختيار خارج جذر المشروع، سواء إلى مجلد محوّل متجذّر في الدليل المنزلي
أو إلى مجلد مشترك، يحرس تأكيدٌ تفاعلي عمليات الكتابة المتجذّرة في الدليل المنزلي. ويمضي كلٌّ من <bdi>`--yes`</bdi>، والصدفة غير التفاعلية (دون
<bdi>TTY</bdi>)، و<bdi>`--dry-run`</bdi>، و<bdi>`--format json`</bdi> دون مطالبة. ولا
يكتب <bdi>`--dry-run`</bdi> وحده شيئًا؛ أما <bdi>`--format json`</bdi> فيتخطّى
المعاينة ومطالبة التأكيد لكنه يُجري عمليات الكتابة مع ذلك. ورفض مطالبة الدليل المنزلي
يُلغي التثبيت قبل كتاباته. ومع <bdi>`--clean`</bdi>، تعمل خطوة البداية النظيفة أولًا
ضمن تأكيدها الخاص بكل هدف: تكتب نسخة احتياطية تحت <bdi>`~/.apothem/backups`</bdi>
وتُزيل الأهداف التي تؤكّدها. وتبقى تلك الإزالات والنسخة الاحتياطية في مكانها عند
رفض مطالبة التثبيت.
والأهداف هي دائمًا المجلّدات الأربعة نفسها في دليلك المنزلي، أيًّا كان إطار العمل الذي يسمّيه
<bdi>`--harness`</bdi>:

```text
~/.claude
~/.codex
~/.agents
~/.config/apothem
```

ولا يُزال أي مجلّد آخر، ويبقى سائر محتوى <bdi>`~/.config`</bdi>.
والهدف الذي هو نفسه رابط، بما في ذلك نقطة الوصل (<bdi>junction</bdi>) على <bdi>Windows</bdi>،
لا يفقد إلّا الرابط، ويُزال الرابط الموجود داخل هدفٍ دون الدخول إليه. وعندما يكون
<bdi>`~/.config`</bdi> رابطًا يقود إلى خارج دليلك المنزلي، تتوقّف خطوة البداية النظيفة مع
<bdi>`Clean-slate removal was refused`</bdi> قبل أن تنسخ احتياطيًا أو تُزيل أي شيء، لأن
إزالة <bdi>`~/.config/apothem`</bdi> ستحذف المجلّد في الطرف الآخر من ذلك الرابط. ويُسمّي
الخطأ الرابط: استبدله بمجلّد حقيقي، أو اجعله يقود إلى مجلّد داخل دليلك المنزلي. وتتوقّف
الخطوة أيضًا قبل أن تُغيّر أي شيء، وقبل أن تُنشئ الملف التعريفي المبدئي، عندما لا يكون
دليلك المنزلي مسارًا كاملًا، أو يكون جذر محرّك أقراص أو نظام ملفات، أو يكون رابطًا أو
نقطة وصل تقود إلى أحدهما، أو يُوصَل إليه عبر رابط يدور في حلقة.

تُزيل خطوة البداية النظيفة الملف التعريفي الافتراضي،
<bdi>`~/.config/apothem/profile.yaml`</bdi>، مع <bdi>`~/.config/apothem`</bdi>، ثم تكتبه
مجدّدًا بعد ذلك. أمّا الملف التعريفي الذي لم تُزله، مثل ملف تمرّره بـ
<bdi>`--profile PATH`</bdi> من مجلّد آخر، فلا يُكتَب إطلاقًا. وتتبع إعادة الكتابة القاعدة
نفسها التي تتبعها كل كتابة أخرى للملف التعريفي: تُرفَض عندما يقودها رابط إلى خارج دليلك
المنزلي. وعندما تتعذّر إعادة كتابة الملف التعريفي، يخرج الأمر بالرمز 1 ويُسمّي الخطأ
النسخة الاحتياطية التي تحمله. ويكون رمز الخطأ
<bdi>`clean_slate.profile_restore_refused`</bdi> عندما يرفض رابطٌ الكتابة، و
<bdi>`clean_slate.profile_restore_failed`</bdi> عندما تفشل الكتابة نفسها.
وعندما تتوقّف إزالةٌ في منتصفها، مثلًا عند ملف يُبقيه برنامج آخر مفتوحًا، يُكتَب الملف
التعريفي مجدّدًا أولًا. ثم يخرج الأمر بالرمز 1 مع رمز الخطأ
<bdi>`clean_slate.removal_failed`</bdi>، ويُسمّي الخطأ مجلّد النسخ الاحتياطي. وإذا تعذّرت
إعادة كتابة الملف التعريفي، يكون الخطأ بدلًا من ذلك أحد رمزَي الملف التعريفي أعلاه.

## المجلّدات في دليلك المنزلي

تكتب سبعة محوّلات ذات نطاق المشروع مهارات <bdi>Apothem</bdi>، والقواعد والقوالب التي
تُحيل إليها المهارات، إلى مجلّدات في دليلك المنزلي:

```text
cursor, github-copilot, windsurf, zed  ->  ~/.agents/skills/ (codex writes it too)
codebuddy                               ->  ~/.codebuddy/skills/
kiro                                    ->  ~/.kiro/skills/
trae                                    ->  ~/.trae/skills/
all seven                               ->  ~/.config/apothem/rules/ and templates/ (codex uses them too)
```

- يختار <bdi>`--project`</bdi> ملف القواعد والمشروعَ الذي ينتمي إليه التثبيت. ولا
  يغيّر المكان الذي تذهب إليه المهارات: فالتثبيت مع <bdi>`--project A`</bdi> والتثبيت
  مع <bdi>`--project B`</bdi> يكتبان المجلّدات نفسها.
- كل تثبيت يسمّي مجلّدًا يكتب الملفات نفسها. ويجدها التثبيت الثاني ويُبلغ عن
  <bdi>`unchanged`</bdi>، ولا يهمّ الترتيب الذي تثبّت به.
- تُكتَب المجلّدات المنزلية قبل أي شيء في المشروع. فإن فشلت كتابةٌ هناك، يتوقّف
  تثبيت المحوّل مع الخطأ ويبقى المشروع دون تغيير. ويسمّي الخطأ المسار المُعترِض،
  مثل ملف اسمه <bdi>`~/.agents`</bdi> حيث ينبغي أن يكون المجلّد.
- يُكتَب كل مجلّد مهارة في مجلّد مخفي <bdi>`.<name>.apothem-staging`</bdi> بجواره ثم
  تُعاد تسميته إلى مكانه عند اكتماله، فلا تترك كتابةٌ فاشلة أو مقطوعة أبدًا مجلّد
  مهارة مكتوبًا جزئيًا تحت اسمه النهائي. شغّل التثبيت مجدّدًا لإكماله؛ فهو يستبدل
  أي مجلّد تجهيز متبقٍّ.
- الرابط عند أحد هذه المجلّدات أو فوقه، كالذي تُنشئه أدوات إدارة ملفات الإعداد
  النقطية لـ <bdi>`~/.config`</bdi> أو <bdi>`~/.agents`</bdi>، يُتَّبَع حين يقود إلى مكان
  داخل دليلك المنزلي. وعلى <bdi>Windows</bdi> تُعَدّ نقطة الوصل رابطًا. أما الرابط الذي
  يخرج من دليلك المنزلي فيوقف التثبيت مع <bdi>`target escapes the
  allowed materialization root`</bdi>، متبوعًا بالرابط، والمجلّد الذي يقود إليه،
  والإصلاح: استبدل الرابط بمجلّد حقيقي. ولا يُكتَب أبدًا عبر مجلّد مهارة هو نفسه رابط:
  يتخطّاه التثبيت مع تحذير، أو يتوقّف إذا كان <bdi>Apothem</bdi> قد كتب تلك المهارة هناك
  من قبل. والرابط الموجود داخل مجلّد مهارة كتبه <bdi>Apothem</bdi> يُستبدَل بمجلّد في المرّة
  التالية التي يكتب فيها التثبيت تلك المهارة.
- مجلّد إطار العمل الواقع تحت <bdi>`~/.config`</bdi>، مثل <bdi>`~/.config/opencode/`</bdi>
  الخاص بـ <bdi>OpenCode</bdi> أو <bdi>`CODEX_HOME`</bdi> هناك، يتبع أيضًا رابطًا عند
  <bdi>`~/.config`</bdi> يقود إلى مكان داخل دليلك المنزلي. أما الرابط عند
  <bdi>`~/.config`</bdi> الذي يخرج من دليلك المنزلي فيوقف التثبيت قبل أن يكتب أي ملف،
  وكذلك الرابط على مسار يكتبه التثبيت داخل مجلّد إطار العمل. وفي التشغيل الأول، لا يُكتَب
  الملف التعريفي المبدئي، الواقع أيضًا تحت <bdi>`~/.config`</bdi>، عبر رابط يخرج من دليلك
  المنزلي كذلك: يتوقّف التشغيل مع <bdi>`Apothem could
  not create the starter profile`</bdi>، كما تفعل <bdi>`apothem quickstart`</bdi>
  و<bdi>`apothem profile
  init`</bdi> و<bdi>`apothem profile set`</bdi> و<bdi>`apothem profile edit`</bdi>. ولإبقاء
  الملف التعريفي خارج دليلك المنزلي، أنشئه هناك أولًا باستخدام <bdi>`apothem
  profile init --profile PATH`</bdi>، مع كتابة <bdi>PATH</bdi> بمساره الخاص خارج دليلك
  المنزلي، ومرّر <bdi>`--profile PATH`</bdi> نفسه إلى كل أمر. ولا يتجاوز ذلك إلّا خطوة
  الملف التعريفي: فالتثبيت الذي يكتب تحت <bdi>`~/.config`</bdi> لا يزال يتوقّف عند الرابط.
  ولـ <bdi>OpenCode</bdi>، اضبط أيضًا <bdi>`XDG_CONFIG_HOME`</bdi> (انظر
  [<bdi>OpenCode</bdi>](/docs/harnesses/opencode)). أمّا إطار العمل الذي يكتب تثبيته دائمًا
  <bdi>`~/.config/apothem/`</bdi> فيحتاج بدلًا من ذلك إلى أن يقود الرابط إلى داخل دليلك
  المنزلي؛ وتذكر صفحة إطار العمل ذلك.
- المجلّد المنزلي الذي هو نفسه رابط، مثل ملف مستخدم <bdi>Windows</bdi> نُقِل إلى محرّك
  أقراص آخر خلف نقطة وصل، يُتَّبَع: فتبقى كل كتابة داخل المجلّد الذي يقود إليه.
- لا يضيف التثبيت أي ملف مهارة أو قاعدة إلى مستودعك. ويحصل المشروع على ملف
  القواعد الخاص بالمحوّل، إضافةً إلى مجلّد البيانات <bdi>`.apothem/`</bdi> الذي يُنشئه
  كل تثبيت على مستوى المشروع.
- مجلّد المهارة الذي يحمل اسم مهارة من <bdi>Apothem</bdi> ولم يكتبه <bdi>Apothem</bdi>
  يُتخطّى. ويطبع التثبيت سطر <bdi>`Warning:`</bdi> ويحمل غلاف <bdi>`--format json`</bdi>
  مُدخَلًا في <bdi>`warnings`</bdi> يحمل <bdi>`"outcome": "warning"`</bdi>
  و<bdi>`"operation": "skill_conflict"`</bdi> ويسمّي المجلّد. أعد تسمية المجلّد أو
  انقله، ثم شغّل [<bdi>`update`</bdi>](/docs/cli-reference/update).
- تشمل هذه القاعدة كل مجلّد مهارات مشترك في الجدول أعلاه:
  <bdi>`~/.agents/skills/`</bdi> و<bdi>`~/.codebuddy/skills/`</bdi> و<bdi>`~/.kiro/skills/`</bdi>
  و<bdi>`~/.trae/skills/`</bdi>. يُثبِت سجلّ التثبيت أن مجلّد مهارة هناك يخصّ
  <bdi>Apothem</bdi> ما دام مجلّد تثبيته (مشروع، أو <bdi>`CODEX_HOME`</bdi>) حيًّا: أي موجودًا
  ولا يزال يحوي أحد الملفات التي سجّلها ذلك التثبيت فيه، بمحتوى <bdi>Apothem</bdi>. والملف
  الذي يملكه <bdi>Apothem</bdi> يُحتسَب ما دام موجودًا. أمّا الملف الذي يخصّك، مثل ملف
  تعليمات أضاف إليه <bdi>Apothem</bdi> كتلته، فلا يُحتسَب إلّا ما دام يحوي تلك الكتلة أو،
  لملف بلا كتلة، المحتوى الذي سجّله <bdi>Apothem</bdi>، لذا فالمشروع المُستنسَخ من جديد
  الذي يحتفظ بنسخته الخاصة فقط من الملف ليس حيًّا. وتُحتسَب ملفات الدعم التي يكتبها التثبيت
  تحت <bdi>`.apothem/support/`</bdi>؛ أمّا مخازن البيانات تحت <bdi>`.apothem/`</bdi> (الذاكرة،
  والسياقات، والخطط) فلا تُحتسَب، ولا يُحتسَب كذلك الملف الذي يُوصَل إليه عبر رابط داخل
  مجلّد التثبيت.
- أيّ سجلّ آخر، لم يعد مجلّد تثبيته موجودًا، أو لا يحوي أي ملفات لـ <bdi>Apothem</bdi>، أو
  يتعذّر قراءته (محرّك أقراص أو مشاركة شبكة لا تستجيب، أو خطأ صلاحيات)، لا يُثبِت أن مجلّد
  مهارة يخصّ <bdi>Apothem</bdi> إلّا ما دام ذلك المجلّد يحوي بالضبط الملفات التي سجّلها ذلك
  التثبيت، دون تغيير، دون ملف مُضاف ودون رابط بداخله. والمجلّد الذي يحوي بالفعل ما يكتبه هذا
  الإصدار يُترَك كما هو، لذا لا يتأثّر المجلّد غير المُحرَّر الذي كتبه إصدار سابق ما دام لا
  يزال يطابق ما يكتبه هذا الإصدار.
- لا تُحتسَب المجلّدات المشتركة نفسها أبدًا من ملفات مجلّد التثبيت، لذا لا يكون المشروع
  المُثبَّت في المجلّد المنزلي حيًّا لمجرّد وجود <bdi>`~/.agents/skills/`</bdi> أو
  <bdi>`~/.config/apothem/`</bdi>.
- لذا عندما لا يسرد مجلّدَ مهارةٍ إلّا سجلّاتٌ من هذا النوع، يتخطّاه التثبيت ويتركه دون مساس
  في ثلاث حالات: وضعتَ مهارتك الخاصّة هناك، أو حرّرتها (غيّرت ملفًا أو أضفته أو أزلته)، أو
  كتبه إصدار سابق لم يُسجِّل ملفاته ويكتب هذا الإصدار شيئًا مختلفًا.
  والأمر نفسه ينطبق عندما لا يسرده إلّا تثبيت سابق في المجلّد نفسه: فالتثبيت الذي تخطّى
  المجلّد لا يسرده، ولا يزال غير مُثبَت ما لم يحوِ بالضبط الملفات التي سجّلها ذلك التثبيت
  السابق.
  ويذكر تحذير التثبيت والتحديث والتشغيل التجريبي السبب والطريقتين للمتابعة، بالكلمات نفسها
  التي يستخدمها [<bdi>`verify`</bdi>](/docs/cli-reference/verify)، الذي يُبلِّغ عن إطار
  العمل بأنه غير
  مُتحقَّق منه ويُسمّي تلك المجلّدات. للإبقاء على مهارتك، اتركها هناك. ولاستخدام نسخة
  <bdi>Apothem</bdi>، انقل المجلّد خارج مجلّد المهارات، ثم شغّل
  [<bdi>`update`</bdi>](/docs/cli-reference/update) لإطار العمل ذاك (مع <bdi>`--project`</bdi>
  لإطار عمل ذي نطاق مشروع).
- يطبع كل تثبيت وتحديث وتشغيل تجريبي من هذا النوع ملاحظة <bdi>`Note:`</bdi> تسمّي
  المجلّدات التي يكتبها خارج <bdi>`--project`</bdi>. وفي غلاف <bdi>JSON</bdi> تكون
  مُدخَلًا في <bdi>`warnings`</bdi> يحمل <bdi>`"operation": "user_level_write"`</bdi>
  وقائمة <bdi>`paths`</bdi>.

## ملاحظات القدرات

لا يُسقِط كل محوّل إلا القدرات التي يدعمها إطار عمله أصليًا؛ أمّا القدرات التي لا
سطح أصليًا لها فيُبلَّغ عنها، ولا تُستبعَد بصمت. وفي الوضع <bdi>plain</bdi> يكون ذلك
ملاحظةً مُجمَّعة واحدة لكل إطار عمل (مثلًا
<bdi>`Note: <harness> - 9 capabilities not projected; pass --verbose for detail`</bdi>)؛
ومع <bdi>`--verbose`</bdi> تطبع كل قدرة سطر تعليلها الخاص. وأي تحذير آخر من المحوّل
يُطبَع هو أيضًا في الوضع <bdi>plain</bdi> على سطر <bdi>`Warning:`</bdi> خاص به، مثل
تحذير <bdi>Zed</bdi> الذي يسمّي ملف تعليمات يحجبه الملف <bdi>`.rules`</bdi> الجديد،
والتحذير الذي يسمّي ملفًا يحوي علامة <bdi>BEGIN</bdi> من <bdi>Apothem</bdi> لا تليها علامة
<bdi>END</bdi>: يُبقي التثبيت النصّ الذي يلي تلك العلامة ويكتب كتلة <bdi>Apothem</bdi> بمعزل
عنه، لذا يسمّي التحذير سطر العلامة، ويعطي خطوات مُرقَّمة تُغيّر ذلك السطر وكل سطر علامة
<bdi>BEGIN</bdi> آخر عدا السطر الذي يفتح كتلة <bdi>Apothem</bdi> (بما في ذلك علامة
<bdi>BEGIN</bdi> تقتبسها في شيفرة)، ويقول ألّا تُعيد إضافة علامة <bdi>END</bdi> بدلًا من ذلك،
إذ سيترك ذلك عندئذٍ كتلتين لـ <bdi>Apothem</bdi> (انظر
[استكشاف الأخطاء وإصلاحها](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker)).
وكذلك التحذير الخاص بملف يحوي كتلتين كاملتين أو أكثر بين علامات <bdi>Apothem</bdi>، الذي
يسمّي كل كتلة بأسطرها (انظر
[ملف يحوي كتلتين بين علامات <bdi>Apothem</bdi>](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers))،
والتحذير الخاص بملف لا يستطيع فيه <bdi>Apothem</bdi> تمييز كتلته من نصّك، الذي يسمّي كل
زوج علامات وكيف تُصلحه (انظر
[لا يستطيع <bdi>Apothem</bdi> تمييز كتلته من نصّك](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)):
يترك التثبيت هذا الملف كما هو (لأزواج العلامات، ما دام سجلّ تثبيت يسرد الملف؛ انظر
[<bdi>`update`</bdi>](/docs/cli-reference/update)). والتثبيت الذي يترك ملفًا كهذا كما هو
ينتهي جزئيًا، لأن الأداة لا تحصل من ذلك الملف على كتلة <bdi>Apothem</bdi> حالية: فبدلًا من
سطر <bdi>`✓`</bdi> يطبع سطر <bdi>`✗`</bdi> على الخطأ القياسي يسمّي الملف (لذا يُبقيه
<bdi>`--quiet`</bdi>)، ويكون <bdi>`status`</bdi> في غلاف <bdi>`--format json`</bdi> هو
<bdi>`"partial"`</bdi> ويحمل تحذير ذلك الملف <bdi>`"detail": {"left_as_is": "1"}`</bdi>، ويكون
رمز الخروج <bdi>`2`</bdi>. وينتهي كل تثبيت وتحديث على هذا النحو إلى أن تُصلح أسطر العلامات
التي يسمّيها التحذير. ومن دون <bdi>`--quiet`</bdi>، ينتهي تثبيت كهذا مع
<bdi>`--harness all`</bdi> بسطر ملخّص يبدأ بـ <bdi>`!`</bdi> بدلًا من <bdi>`✓`</bdi> ويعدّ
الملفات المتروكة كما هي:
<bdi>`! Installed <n> harnesses (<m> files written); <k> file(s) left as they are, named above.`</bdi>
ومع <bdi>`--clean`</bdi>، لا يطبع تثبيت كهذا خطوته التالية،
<bdi>`apothem verify`</bdi>، التي تفشل إلى أن تُصلح الملف. وفي التشغيل التجريبي، يقول
التحذير الخاص بملف متروك كما هو إن <bdi>Apothem</bdi>
<bdi>"would leave the file as it is"</bdi>، ولا يزال التشغيل ينتهي بـ <bdi>`status`</bdi>
<bdi>`"dry_run"`</bdi> ورمز الخروج <bdi>`0`</bdi>. والقاعدة في ملفك التعريفي التي تفتح كتلة
شيفرة ولا تُغلقها أبدًا لا تحجب علامة <bdi>END</bdi> للكتلة التي يكتبها التثبيت: إذ يُغلق
التثبيت كتلة الشيفرة تلك في نهاية الكتلة. أمّا الكتلة التي كتبها إصدار سابق من قاعدة كهذه
فليس فيها سطر إغلاق كهذا. وكتلة الشيفرة الخاصة بك التي تُفتَح فوق كتلة <bdi>Apothem</bdi>
ولا تُغلَق أبدًا حالةٌ مختلفة: فسطر إغلاق في الكتلة يُغلقها، فتُقرَأ الكتلة على أنها شيفرة.
ويُحذِّر التثبيت من كتلة كهذه بمجرّد أن يكتبها، ويسمّي التحذير كتلة الشيفرة التي يجب إغلاقها
فوق علامة <bdi>BEGIN</bdi> (انظر
[لا يستطيع <bdi>Apothem</bdi> تمييز كتلته من نصّك](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)).
ويقرأ التشغيل التجريبي الملف قبل كتابة أي شيء، لذا لا يُظهِر أن الكتلة ستُقرَأ على أنها
شيفرة بمجرّد كتابتها.
ويحمل غلاف <bdi>`--format json`</bdi> دائمًا مصفوفة <bdi>`warnings`</bdi> كاملةً
بصرف النظر عن مستوى الإسهاب.

يطبع التثبيت والتحديث أيضًا تنبيهات استشارية على هيئة أسطر <bdi>`Note:`</bdi>. ولا
يغيّر التنبيه الاستشاري أبدًا ما يكتبه التثبيت. عندما يكتب تثبيتٌ جذرًا مشتركًا، أي
مسارًا تحمّله أدوات أخرى أيضًا (مثل مجلد المهارات <bdi>`~/.agents/skills/`</bdi>)،
تسمّي الملاحظة تلك الأدوات، وتضع بين قوسين الأداة التي لا تحمّل المسار إلا تحت شرط،
مثل <bdi>`Open-Claw (only under its default state
directory)`</bdi>. والتثبيت الذي يكتب مجلّدًا تكتبه تثبيتات أخرى أيضًا (دور
<bdi>`holder`</bdi>) يذكر أن المجلّد يبقى حتى إلغاء تثبيت آخر تثبيت لـ
<bdi>Apothem</bdi> يستخدمه، ويسمّي التثبيتات التي تستخدمه الآن. وعندما يستهدف تثبيتٌ
أداةً تحمّل بالفعل محتوى <bdi>Apothem</bdi> من الجذر المشترك لتثبيت آخر، تسمّي
الملاحظة التثبيت الذي وضعه: المالك المُسجَّل ما دام لا يزال يستخدم المجلّد، وإلا
فأقدم تثبيت يستخدمه. وفي غلاف <bdi>`--format json`</bdi> يكون كل تنبيه استشاري
مُدخَلًا في <bdi>`warnings`</bdi> يحمل <bdi>`"outcome": "advisory"`</bdi>
و<bdi>`"operation": "shared_root"`</bdi>؛ ويكون <bdi>`role`</bdi> فيه
<bdi>`owner`</bdi> أو <bdi>`holder`</bdi> أو <bdi>`reader`</bdi>، ويسرد
<bdi>`holders`</bdi> التثبيتات التي تستخدم المجلّد، ويسمّي <bdi>`owner_of_record`</bdi>
المالك المُسجَّل.

ويطبع التثبيت الذي يسجّل خطّافات أيضًا ملاحظات عن ملف الخطّافات. فالتنبيه الاستشاري
<bdi>`hook_review`</bdi> يسمّي الخطوة التي تحتاجها الأداة قبل أن تشغّل الخطّافات (إعادة
تشغيل ومراجعة، أو منح الثقة لمساحة العمل)، أو خطر ملف خطّافات يُودِعه مستودعٌ ويسمّي
مفسّر هذا الجهاز. ويظهر التنبيه الاستشاري <bdi>`hook_import`</bdi> لأداة تشغّل أيضًا
الخطّافات الموجودة في ملفات إعدادات <bdi>Claude Code</bdi>، مثل تلك التي يكتبها تثبيت
<bdi>Apothem</bdi> لـ <bdi>Claude Code</bdi>، ويسمّي مفتاح الأداة الخاص لإيقاف ذلك
الاستيراد وما يوقفه المفتاح أيضًا. وكلٌّ منهما مُدخَل في <bdi>`warnings`</bdi> يحمل
<bdi>`"outcome": "advisory"`</bdi>، و<bdi>`harness`</bdi>، و<bdi>`path`</bdi> ملف
الخطّافات، و<bdi>`message`</bdi>.

يحمل أمر الخطّاف مسار المشروع ومسار المفسّر داخل علامتي اقتباس مزدوجتين، وهو ما يقرؤه
كلٌّ من <bdi>`sh`</bdi> و<bdi>Git Bash</bdi> و<bdi>PowerShell</bdi>. والمسار الذي يحتوي
<bdi>`$`</bdi>، أو علامة اقتباس خلفية، أو علامة اقتباس مزدوجة، أو شرطة مائلة عكسية من
شأنه أن يجعل الأمر يشغّل ملفًا مختلفًا، لذا يتوقّف التثبيت (و<bdi>`--dry-run`</bdi>) مع
خطأ يسمّي المسار ولا يكتب شيئًا؛ انقل المشروع أو أعد تسميته ثم شغّله مجدّدًا. أما
المسافة أو الفاصلة العليا في المسار فلا بأس بها.

بعض الأدوات لا تحمّل إلّا أول ملف فيه نصّ من قائمة ثابتة في مجلّد، لذا فإن ملفًا خاصًا
بك يسبق الملف الذي يكتبه <bdi>Apothem</bdi> يمنع الأداة من تحميل كتلة <bdi>Apothem</bdi>.
فمثلًا، تقرأ
[إحدى الأدوات المدعومة](/docs/harnesses/codex#compatibility-notes) الملف
<bdi>`AGENTS.override.md`</bdi> الذي فيه نصّ بدلًا من <bdi>`AGENTS.md`</bdi> الذي يكتبه
<bdi>Apothem</bdi> بجواره في المجلّد المنزلي لتلك الأداة. عندئذٍ يطبع التثبيت والتحديث ملاحظة
تسمّي ذلك الملف، بما في ذلك التشغيلات التجريبية. ويُتخطّى ملف التجاوز الفارغ، وكذلك الرابط
الرمزي إلى <bdi>`AGENTS.md`</bdi>؛ أمّا الرابط الصلب أو النسخة فيحصلان على الملاحظة، لأن
التثبيت الذي يُعيد كتابة <bdi>`AGENTS.md`</bdi> يتركه ملفًا منفصلًا. ويعمل <bdi>OpenCode 1</bdi>
على نحوٍ مختلف: فقائمة <bdi>`instructions`</bdi> في <bdi>`opencode.jsonc`</bdi>، ولو كانت
فارغة، تستبدل القائمة التي يكتبها <bdi>Apothem</bdi> في <bdi>`opencode.json`</bdi> في المجلّد
نفسه. والملف <bdi>`config.json`</bdi> أو <bdi>`opencode.json`</bdi> أو <bdi>`opencode.jsonc`</bdi>
هناك الذي يتعذّر عليه قراءته أو تحليله، أو الذي ليس مستواه الأعلى كائنًا، أو الذي ليست
قيمة <bdi>`instructions`</bdi> فيه قائمة نصوص، أو الذي يحوي <bdi>`{file:path}`</bdi> يسمّي
ملفًا يتعذّر عليه قراءته، يمنعه من تحميل أي من إعداداته، وكذلك المجلّد الذي يحمل أحد تلك
الأسماء. ويطبع التثبيت والتحديث ملاحظة
<bdi>`instruction_override`</bdi> لكل ملف من هذا النوع أيضًا، عدا <bdi>`opencode.json`</bdi>
الذي يتعذّر عليهما تحليله حتى بوصفه <bdi>JSON5</bdi>، فيرفضانه بخطأ <bdi>`config.unparseable`</bdi>
([ملاحظات <bdi>OpenCode</bdi>](/docs/harnesses/opencode#compatibility-notes)). والملاحظة
مُدخَل في <bdi>`warnings`</bdi> يحمل <bdi>`"outcome": "advisory"`</bdi> و<bdi>`"operation": "instruction_override"`</bdi>،
و<bdi>`harness`</bdi>، و<bdi>`path`</bdi> الملف الذي تتناوله الملاحظة، و<bdi>`target`</bdi>
الذي يكتبه التثبيت، و<bdi>`message`</bdi>.

تحصل خوادم <bdi>MCP</bdi> في الملف التعريفي على ثلاثة تنبيهات استشارية، يسمّي كلٌّ
منها حقل الملف التعريفي المعنيّ:

| العملية | الشرط | الإصلاح |
| --- | --- | --- |
| <bdi>`mcp_deprecated_transport`</bdi> | <bdi>`transport: sse`</bdi> (تُهمِل مواصفة <bdi>MCP</bdi> نقل <bdi>HTTP+SSE</bdi>) | استخدم <bdi>`streamable-http`</bdi> حين يدعمه الخادم. |
| <bdi>`mcp_plain_http`</bdi> | عنوان <bdi>URL</bdi> بصيغة <bdi>`http://`</bdi> يشير إلى مضيف ليس مضيف الاسترجاع المحلي | استخدم عنوان <bdi>URL</bdi> بصيغة <bdi>`https://`</bdi>. |
| <bdi>`mcp_literal_credential`</bdi> | قيمة في <bdi>`headers`</bdi> أو <bdi>`env`</bdi> تشبه رمزًا مميّزًا (<bdi>`ghp_`</bdi>، أو <bdi>`gho_`</bdi>، أو <bdi>`ghu_`</bdi>، أو <bdi>`ghs_`</bdi>، أو <bdi>`ghr_`</bdi>، أو <bdi>`github_pat_`</bdi>، أو <bdi>`sk-`</bdi>، أو <bdi>`xoxa-`</bdi>، أو <bdi>`xoxb-`</bdi>، أو <bdi>`xoxo-`</bdi>، أو <bdi>`xoxp-`</bdi>، أو <bdi>`xoxr-`</bdi>، أو <bdi>`xoxs-`</bdi>، أو <bdi>`Bearer`</bdi> متبوعًا برمز مميّز طويل) | احتفظ بالسرّ في متغيّر بيئة واكتب مراجع بنمط <bdi>`${GITHUB_TOKEN}`</bdi>. |

لا يطبع تنبيه بيانات الاعتماد أبدًا القيمة التي عثر عليها. ولا تُعلَّم أبدًا قيمةٌ
تحتوي مرجعًا من نوع <bdi>`${...}`</bdi>.

## إعدادات المُشغِّل التي تحمل تعليقات

بعض إعدادات أُطُر العمل ملفات تحرّرها أنت أيضًا، مثل <bdi>`settings.json`</bdi>،
و<bdi>`opencode.json`</bdi> (الذي قد يكون بصيغة <bdi>JSONC</bdi>)،
و<bdi>`openclaw.json`</bdi> (<bdi>JSON5</bdi>)، و<bdi>`config.yaml`</bdi>. يدمج
التثبيت مفاتيحه في هذه الملفات ويُبقي كل مفتاح أضفته.

يعيد الدمج كتابة الملف بصيغة <bdi>JSON</bdi> أو <bdi>YAML</bdi> عادية، وهذا من شأنه
أن يُسقِط التعليقات، والفواصل اللاحقة، وصياغة <bdi>JSON5</bdi>. لذلك:

- عندما لا يغيّر الدمج أي قيمة (مثلًا، إذا كنت قد أضفت مفاتيح <bdi>Apothem</bdi>
  بنفسك مسبقًا)، يُترَك الملف كما هو بايتًا ببايت.
- عندما يتعيّن على الدمج تغيير قيمة في ملف يحمل تعليقات أو صياغة <bdi>JSON5</bdi>،
  أو في ملف لا يمكن تحليله إطلاقًا، لا يكتب التثبيت شيئًا لإطار العمل ذاك ويخرج
  بالرمز 1 مع رمز الخطأ <bdi>`config.unparseable`</bdi>. ويسمّي الحقل
  <bdi>`fix`</bdi> المفاتيح التي كان التثبيت سيضيفها، لتتمكّن من تحويل الملف إلى
  <bdi>JSON</bdi> أو <bdi>YAML</bdi> عادية، أو إضافة تلك المفاتيح يدويًا ثم إعادة
  التشغيل.
- عندما يحمل مفتاحٌ يملؤه التثبيت بخريطة (<bdi>mapping</bdi>) أو بقائمة (مثل
  <bdi>`skills.external_dirs`</bdi> في <bdi>`config.yaml`</bdi>) قيمةً مفردة (<bdi>scalar</bdi>)، أو شكل
  الحاوية الآخر، في ملفك، لا يكتب التثبيت شيئًا لإطار العمل ذاك ويخرج بالرمز 1 مع رمز
  الخطأ نفسه، لأن ملء المفتاح من شأنه أن يُهدِر قيمتك. ويسمّي الخطأ المفتاح؛ غيّره إلى
  الشكل الذي يسمّيه، أو أزِله، ثم أعد التشغيل. أما المفتاح الذي تركته فارغًا
  (<bdi>`skills:`</bdi> دون شيء تحته) فيُملأ.

## الخيارات

| الخيار | الوصف |
|---|---|
| <bdi>`--harness NAME`</bdi> | محوّل إطار العمل المراد تثبيته، أو <bdi>`all`</bdi> للمجموعة الشاملة للسجلّ كله (مطلوب). مع <bdi>`all`</bdi>، تُتخطّى أُطُر العمل المُدرَجة في <bdi>`exclude_harnesses`</bdi> الخاصة بالملف التعريفي، لكن إطار العمل المُسمّى صراحةً يُثبَّت حتى لو كان مُدرَجًا فيها. شغّل <bdi>`apothem harnesses list`</bdi> لمعرفة الأسماء المُسجَّلة. |
| <bdi>`--profile PATH`</bdi> | مسار ملف <bdi>YAML</bdi> للملف التعريفي المشترك. القيمة الافتراضية <bdi>`~/.config/apothem/profile.yaml`</bdi>. |
| <bdi>`--dry-run`</bdi> | يعاين التثبيت دون كتابة ملفات. |
| <bdi>`--clean`</bdi>، <bdi>`--fresh`</bdi> | بداية نظيفة اختيارية: ينسخ احتياطيًا المجلّدات الأربعة المذكورة في [معاينة نطاق الأثر](#معاينة-نطاق-الأثر) ويزيلها قبل التثبيت، أيًّا كان إطار العمل الذي يسمّيه <bdi>`--harness`</bdi>. |
| <bdi>`--yes`</bdi> | يتخطّى التأكيد لكل هدف أثناء إزالة البداية النظيفة (مطلوب لتشغيلات <bdi>`--clean`</bdi> غير التفاعلية). |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. |
| <bdi>`--quiet`</bdi>، <bdi>`-q`</bdi> | يُخمِد المخرجات المعلوماتية؛ لا تُصدَر إلا الأخطاء. |
| <bdi>`--verbose`</bdi>، <bdi>`-v`</bdi> | يطبع تعليل كل قدرة غير مُسقَطة بدلًا من الملاحظة المُجمَّعة لكل إطار عمل. |
| <bdi>`--format plain\|json`</bdi> | صيغة المخرجات (الافتراضي: <bdi>`plain`</bdi>). |
| <bdi>`--json`</bdi> | اختصار لـ <bdi>`--format json`</bdi>. |
| <bdi>`--no-color`</bdi> | يعطّل رموز ألوان <bdi>ANSI</bdi> في المخرجات. |
| <bdi>`-h`</bdi>، <bdi>`--help`</bdi> | يعرض المساعدة ويخرج. |

## مخرجات <bdi>JSON</bdi>

عند تمرير <bdi>`--json`</bdi> (أو <bdi>`--format json`</bdi>)، يُكتَب مستند
<bdi>JSON</bdi> واحد إلى <bdi>stdout</bdi>:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "install",
  "action": "installed",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": ["C:\\Users\\Example\\.claude\\settings.json"],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

التثبيت الذي ترك ملفًا كما هو بسبب أسطر علامات <bdi>Apothem</bdi> فيه يكون
<bdi>`status`</bdi> فيه <bdi>`"partial"`</bdi> ويخرج بالرمز <bdi>`2`</bdi> (انظر
[ملاحظات القدرات](#ملاحظات-القدرات)).

مع <bdi>`--dry-run`</bdi>، لا يُكتَب شيء ويسرد <bdi>`results`</bdi> كل مسار كان
التثبيت سيكتبه، ولكلٍّ منها النتيجة التي كانت ستكون له (<bdi>`created`</bdi> أو
<bdi>`updated`</bdi> أو <bdi>`unchanged`</bdi>)، ولملفٍ تحرّره أنت أيضًا، الفرق
الموحّد في <bdi>`detail.diff`</bdi> — وهي الخطة نفسها التي يعرضها
[<bdi>`apothem diff`</bdi>](/docs/cli-reference/diff):

```json
{
  "schema_version": 1,
  "status": "dry_run",
  "command": "install",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "created",
      "operation": "write_text",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "dry run: no filesystem changes made"
    }
  ],
  "warnings": [],
  "error": null
}
```

النتيجة المرفوضة عند رابط تسمّي الرابط في <bdi>`detail.symlink`</bdi> والمسار الذي يقود
إليه في <bdi>`detail.leads_to`</bdi>. والنتيجة المرفوضة لأن رابطًا يقود مجلّد أداة إلى
خارج دليلك المنزلي تحمل أيضًا الإصلاح في <bdi>`detail.fix`</bdi>.

عند تمرير <bdi>`--clean`</bdi>، يحمل الغلاف إضافةً إلى ذلك كائن <bdi>`clean`</bdi>
يصف مرحلة الإزالة — قائمة مآل كل هدف، وما إذا كان التشغيل معاينةً، ودليل النسخ
الاحتياطي المختوم بالوقت (<bdi>`null`</bdi> في التشغيل التجريبي):

```json
{
  "clean": {
    "dry_run": true,
    "backup_dir": null,
    "targets": [
      {
        "path": "C:\\Users\\Example\\.claude",
        "present": true,
        "removed": false,
        "skipped_reason": null
      }
    ]
  }
}
```

يعاين التشغيل التجريبي مع البداية النظيفة المرحلتين كلتيهما في مستند واحد: معاينة
الإزالة تحت <bdi>`clean`</bdi>، ومعاينة الكتابة الجديدة تحت <bdi>`results`</bdi>.

تستخدم أخطاء التحقّق المتوقّعة الغلاف نفسه وتتضمّن كائن خطأ:

```json
{
  "schema_version": 1,
  "status": "error",
  "command": "install",
  "harness": "all",
  "files_written": [],
  "error": {
    "code": "project.required",
    "field": "project",
    "reason": "project-scope harnesses require --project: cursor, gemini-cli, github-copilot, kimi-code, windsurf, codebuddy, kiro, trae, zed, glm.",
    "fix": "Pass --project PATH or select only user-scope harnesses."
  }
}
```

## أمثلة

```bash
apothem install --harness claude-code
apothem install --harness claude-code --dry-run
apothem install --harness cursor --project . --profile ~/profile.yaml --json
apothem install --harness all --project . --dry-run --json
apothem installing --harness claude-code   # continuous-form alias
apothem Installing --harness claude-code   # capitalized variant
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | ثُبِّت المحوّل بنجاح، أو خُطِّط التشغيل التجريبي دون أخطاء |
| 1 | خطأ متوقّع في التحقّق، أو الملف التعريفي، أو إطار العمل، أو المشروع، أو المحوّل |
| 2 | جزئي: توقّفت دفعة بعد عملية كتابة واحدة على الأقل، أو ترك التثبيت ملفًا يحفظ فيه <bdi>Apothem</bdi> كتلته كما هو بسبب أسطر علامات <bdi>Apothem</bdi> فيه (انظر [ملاحظات القدرات](#ملاحظات-القدرات))؛ ويكون <bdi>`status`</bdi> هو <bdi>`"partial"`</bdi> |
| 64 | خطأ استخدام: خيار أو أمر غير معروف، أو قيمة خيار مفقودة أو غير صالحة. ومع <bdi>`--json`</bdi> يكون الخطأ غلاف <bdi>JSON</bdi> يحمل الرمز <bdi>`cli.usage`</bdi>. |
