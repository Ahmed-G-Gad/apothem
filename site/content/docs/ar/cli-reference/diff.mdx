معاينة تغييرات الإعداد المُعلَّقة لإطار عمل واحد.

## الموجز

```
apothem diff --harness NAME [--profile PATH] [--project PATH]
             [--quiet|-q] [--verbose|-v]
             [--format plain|json] [--json] [--no-color]
```

<bdi>`diff`</bdi> أمر فحص للقراءة فقط. ينفّذ التجسيد نفسه الذي كان أمر
<bdi>`install`</bdi> سينفّذه، لكن في وضع التشغيل التجريبي — فلا يُكتَب أي شيء على
القرص. ولكل هدف مُعلَّق يعرض إجراءً بلغة واضحة (مثل <bdi>`Write file`</bdi>، أو
<bdi>`Merge directory`</bdi>، أو <bdi>`Install skills`</bdi>، أو
<bdi>`Prune stale files`</bdi>)، ومسار الهدف، وحالة معاينة (<bdi>`would create`</bdi>،
أو <bdi>`would update`</bdi>، أو <bdi>`would remove`</bdi>، أو <bdi>`no change`</bdi>)،
و— بالنسبة إلى المراسي التي يملكها المُشغِّل والتي سيجري دمجها — الفرق الموحّد
للتغيير. تُحسَب الحالة بمقارنة المصدر بالهدف الحالي على القرص، لذا يظهر الهدف
المطابق أصلًا بالحالة <bdi>`no change`</bdi> ويُخفى من العرض الافتراضي. إنه الإجابة
عن سؤال «ماذا سيفعل <bdi>`apothem install`</bdi> بإطار العمل هذا الآن؟» دون إجراء
التغيير.

تغطّي الخطة كل مسار يكتبه التثبيت: مدخلات البيان، وملف الإعداد الخاص بإطار العمل
نفسه (مثل <bdi>`opencode.json`</bdi> أو <bdi>`config.yaml`</bdi>)، ومرساة التعليمات
أو مستند الملف التعريفي الذي يُسقَط فيه الملف التعريفي المشترك (مثل
<bdi>`CLAUDE.md`</bdi>)، ومخازن البيانات المشتركة تحت <bdi>`.apothem/`</bdi>. بعد
التثبيت مباشرةً، لا يُبلِغ <bdi>`diff`</bdi> عن أي تغيير مُعلَّق؛ وعندئذٍ لا تكتب إعادة
التثبيت شيئًا ولا تأخذ نسخة احتياطية جديدة. ويعرض <bdi>`install --dry-run`</bdi> الخطة
نفسها.

بالنسبة إلى الأهداف التي يملكها المُشغِّل — وهي الملفات التي تحمل محتواك الخاص وكتلة
يديرها <bdi>Apothem</bdi> معًا — يُظهِر الفرق الأسطر التي ستتغيّر بالضبط. أما الأهداف
الأخرى، فيُلخَّص الإجراء المُخطَّط وحالة المعاينة.

لا يسرد العرض الافتراضي إلا التغييرات المُعلَّقة. مرِّر <bdi>`--verbose`</bdi> لرؤية
الخطة الكاملة، بما فيها الأهداف غير المتغيّرة، مشروحةً بنوع العملية الداخلي الخام
ونتيجتها. ولا تؤثّر طبقة العرض في غلاف <bdi>`--json`</bdi>: فهو يحمل دائمًا الحقلين
الخامّين <bdi>`operation`</bdi> و<bdi>`outcome`</bdi> للمستهلكين الآليين.

يعمل <bdi>`diff`</bdi> على إطار عمل واحد. وبخلاف <bdi>`install`</bdi> أو
<bdi>`verify`</bdi>، لا يقبل <bdi>`all`</bdi>؛ مرِّر اسم إطار عمل واحد.

## الخيارات

| الخيار | الوصف |
|---|---|
| <bdi>`--harness NAME`</bdi> | محوّل إطار العمل المراد معاينته (إلزامي؛ إطار عمل واحد، لا <bdi>`all`</bdi>). |
| <bdi>`--profile PATH`</bdi> | مسار ملف <bdi>YAML</bdi> للملف التعريفي المشترك. القيمة الافتراضية <bdi>`~/.config/apothem/profile.yaml`</bdi>. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. مطلوب عندما يكون إطار العمل المحدّد ذا نطاق مشروع. |
| <bdi>`--quiet`</bdi>، <bdi>`-q`</bdi> | يُخمِد المخرجات المعلوماتية؛ لا تُصدَر إلا الأخطاء. |
| <bdi>`--verbose`</bdi>، <bdi>`-v`</bdi> | يعرض الخطة الكاملة، بما فيها الأهداف غير المتغيّرة، مشروحةً بنوع العملية الخام ونتيجتها. |
| <bdi>`--format plain\|json`</bdi> | صيغة المخرجات (الافتراضي: <bdi>`plain`</bdi>). |
| <bdi>`--json`</bdi> | اختصار لـ <bdi>`--format json`</bdi>. |
| <bdi>`--no-color`</bdi> | يُعطِّل رموز ألوان <bdi>ANSI</bdi> في المخرجات. |
| <bdi>`-h`</bdi>، <bdi>`--help`</bdi> | يعرض المساعدة ويخرج. |

## مخرجات <bdi>JSON</bdi>

يعكس غلاف <bdi>`--json`</bdi> غلاف التثبيت في وضع التشغيل التجريبي. قيمة
<bdi>`status`</bdi> هي <bdi>`dry_run`</bdi>، و<bdi>`files_written`</bdi> فارغة دائمًا،
وتحمل كتلة <bdi>`materialization`</bdi> وقائمة <bdi>`results`</bdi> التفاصيل الكاملة
للأهداف المُخطَّطة. ويحمل الحقل <bdi>`detail.diff`</bdi> في كل صف نتيجة خاص بهدف
يملكه المُشغِّل سلسلة الفرق الموحّد.

```json
{
  "schema_version": 1,
  "status": "dry_run",
  "command": "diff",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "sentinel_merge",
      "path": "C:\\Users\\Example\\.claude\\CLAUDE.md",
      "message": "dry run: no filesystem changes made",
      "detail": {
        "ownership_class": "operator-owned",
        "diff": "--- a/CLAUDE.md\n+++ b/CLAUDE.md\n@@ ..."
      }
    }
  ],
  "warnings": [],
  "error": null,
  "materialization": { "...": "..." }
}
```

## أمثلة

```bash
apothem diff --harness claude-code
apothem diff --harness cursor --project .
apothem diff --harness claude-code --json
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | جرى الإبلاغ عن الفرق (يُبلَّغ عن التغييرات المُعلَّقة، وليست خطأً) |
| 1 | خطأ متوقَّع في التحقّق، أو الملف التعريفي، أو إطار العمل، أو المشروع |
| 64 | خطأ في الاستخدام: خيار أو أمر غير معروف، أو قيمة خيار مفقودة أو غير صالحة. مع <bdi>`--json`</bdi> يكون الخطأ غلاف <bdi>JSON</bdi> بالرمز <bdi>`cli.usage`</bdi>. |
