يتحقّق من تثبيت محوّل إطار عمل.

## الموجز

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

يستدعي تنفيذ <bdi>`verify()`</bdi> لكل محوّل مختار. ولا يخرج بالرمز 0 إلا عندما تُبلغ
كل المحوّلات المختارة أن أهدافها المُدارة موجودة وصالحة. دون <bdi>`--profile`</bdi>
يكون الفحص **بنيويًا** — يجب أن يكون كل هدف مُدار موجودًا وصالحًا. ومع
<bdi>`--profile`</bdi> يشترط الفحص إضافةً إلى ذلك **الأمانة للملف التعريفي**، فيُخفق
التحقّق من تثبيتٍ موجود لكنه منحرف، مجيبًا عن السؤال «هل هذا الملف التعريفي بعينه
مثبّت بأمانة؟» لا عن مجرّد «هل هو موجود؟».

بالنسبة إلى المحوّل الذي يكتب المهارات إلى دليلك المنزلي، يتحقّق <bdi>verify</bdi>
أيضًا من أن كل مجلّد مهارة يتوقّعه موجود ومعه <bdi>`SKILL.md`</bdi>، أيًّا كان التثبيت
الذي كتبه، لذا يجتاز التحقّق جهازٌ لم تُثبَّت عليه إلا أداة واحدة من الأدوات التي
تتشارك مجلّدًا. ويُخفق حين يكون مجلّد مفقودًا، وحين يعود مجلّد يحمل اسم مهارة من
<bdi>Apothem</bdi> إلى شيء لم يكتبه <bdi>Apothem</bdi>. ويذكر الصف الفاشل أيّهما:
في الوضع العادي يليه سطر <bdi>`Note:`</bdi>، وفي صف <bdi>JSON</bdi> يسرد كائن
<bdi>`user_level`</bdi> المسارات <bdi>`missing`</bdi> و<bdi>`unlisted`</bdi>
ورسالة <bdi>`message`</bdi>. شغّل [<bdi>`install`</bdi>](/docs/cli-reference/install)
لاستعادة مجلّد مفقود؛ وأعد تسمية المجلّد الغريب أو انقله، ثم شغّل
[<bdi>`update`</bdi>](/docs/cli-reference/update).

يحترم المسح بـ <bdi>`--harness all`</bdi> قائمة <bdi>`exclude_harnesses`</bdi> في
الملف التعريفي — وهي الاستثناءات نفسها التي طبّقتها دفعة
<bdi>`install`/`update`</bdi> — لذا لا يُبلغ التحقّق أبدًا عن إطار عمل مُستثنى عمدًا
بوصفه مفقودًا. تأتي الاستثناءات من <bdi>`--profile`</bdi> عند تمريره، وإلا فمن الملف
التعريفي الافتراضي؛ وإذا كان الملف الافتراضي غير قابل للقراءة أو غائبًا، يتراجع
السلوك إلى السجلّ الكامل.

## الخيارات

| الخيار | الوصف |
|---|---|
| <bdi>`--harness NAME`</bdi> | محوّل إطار العمل المراد التحقّق منه، أو <bdi>`all`</bdi> للمجموعة الشاملة للسجلّ كله (مطلوب). |
| <bdi>`--profile PATH`</bdi> | ملف <bdi>YAML</bdi> للملف التعريفي المشترك الذي تُفحَص الأمانة له. ودونه يكون الفحص بنيويًا بحتًا. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. |
| <bdi>`--quiet`, `-q`</bdi> | يُخمِد المخرجات المعلوماتية؛ لا تُصدَر إلا الأخطاء. |
| <bdi>`--verbose`, `-v`</bdi> | يُصدِر مخرجات تشخيصية إضافية. |
| <bdi>`--format plain\|json`</bdi> | صيغة المخرجات (الافتراضي: <bdi>`plain`</bdi>). |
| <bdi>`--json`</bdi> | اختصار لـ <bdi>`--format json`</bdi>. |
| <bdi>`--no-color`</bdi> | يعطّل رموز ألوان <bdi>ANSI</bdi> في المخرجات. |
| <bdi>`-h`, `--help`</bdi> | يعرض المساعدة ويخرج. |

## مخرجات <bdi>JSON</bdi>

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

عندما يكون أي إطار عمل مختار مفقودًا أو غير صالح، تكون قيمة <bdi>`status`</bdi> هي
<bdi>`error`</bdi>، ويحمل صفّ النتيجة المُخفِق <bdi>`verified: false`</bdi>، وتخرج
العملية بالرمز 1.

## أمثلة

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## رموز الخروج

| الرمز | المعنى |
|---|---|
| 0 | تُحقِّق من إطار العمل — كل الأهداف المُدارة موجودة وصالحة |
| 1 | لم يُتحقَّق من إطار العمل — أهداف مُدارة مفقودة أو غير صالحة |
| 64 | خطأ استخدام: خيار أو أمر غير معروف، أو قيمة خيار مفقودة أو غير صالحة. ومع <bdi>`--json`</bdi> يكون الخطأ غلاف <bdi>JSON</bdi> يحمل الرمز <bdi>`cli.usage`</bdi>. |
