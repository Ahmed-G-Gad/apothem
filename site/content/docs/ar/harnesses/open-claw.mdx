**المورّد:** <bdi>Open-Claw</bdi>
**اسم التثبيت:** <bdi>`open-claw`</bdi>
**الحالة:** معاينة
**الإعداد الأصلي:** <bdi>`~/.openclaw/openclaw.json`</bdi>

## التثبيت

```bash
apothem install --harness open-claw
```

يترجم المحوّل الملف التعريفي المشترك إلى ملف الإعداد العام على مستوى المستخدم في
<bdi>OpenClaw</bdi>، ويثبّت حزم دعم <bdi>Apothem</bdi> تحت جذر إطار العمل. الإعداد
الأصلي لـ <bdi>OpenClaw</bdi> بصيغة <bdi>JSON</bdi>؛ ويُجسِّد المُجسِّد <bdi>JSON</bdi>
مطابقًا لذلك.

**الملفات المكتوبة:** <bdi>`~/.openclaw/openclaw.json`</bdi>، ووثيقة الملف التعريفي
<bdi>`~/.openclaw/apothem/rules/00-apothem-profile.md`</bdi>، وملفات الدعم تحت
<bdi>`~/.openclaw/.apothem/support/`</bdi>

تنتهي وثيقة الملف التعريفي بقسم ملفات دعم <bdi>Apothem</bdi> الذي يُسمّي الدليل المطلق
تحت <bdi>`~/.openclaw/.apothem/support/`</bdi> الذي تُحَلّ نسبةً إليه كل إحالة بأسلوب
المستودع (<bdi>`rules/<name>.md`</bdi>، و<bdi>`templates/...`</bdi>،
و<bdi>`hooks/...`</bdi>).

## تعيين الملف التعريفي إلى الإعداد الأصلي

يقرأ المحوّل الملف التعريفي المشترك لـ <bdi>Apothem</bdi> لكنه لا يؤلّف أي مفاتيح
إعداد: يُكتَب <bdi>`openclaw.json`</bdi> بوصفه كائنًا فارغًا. تذهب هوية الملف التعريفي
وتفضيلاته وقواعده إلى وثيقة الملف التعريفي. وتُثبَّت الأوامر، والمهارات، والقواعد،
والقوالب، ومطالبات الخطّافات المشتركة بوصفها مادة دعم تحت
<bdi>`~/.openclaw/.apothem/support/`</bdi>.

## ملاحظات التوافق

محوّل في مرحلة المعاينة. لا يُحمِّل <bdi>OpenClaw</bdi> شجرة الدعم ولا وثيقة الملف
التعريفي من تلقاء نفسه: لا يشير إليهما أيٌّ من مواقع المهارات لديه، ولا ملفات تعليمات
مساحة العمل لديه، ولا إعداده، لذا يعمل <bdi>OpenClaw</bdi> بعد التثبيت دون قواعد
<bdi>Apothem</bdi> أو مهاراته أو خوادم <bdi>MCP</bdi> الخاصة به. يقرأ
<bdi>OpenClaw</bdi> المهارات من مجلّدَي <bdi>`skills/`</bdi> و<bdi>`.agents/skills/`</bdi>
في مساحة العمل الخاصة به، ومن <bdi>`~/.agents/skills`</bdi>، ومن دليل الحالة الخاص به،
ومن أي مجلّد مُدرَج في <bdi>`skills.load.extraDirs`</bdi>؛ ولاستخدام مهارات
<bdi>Apothem</bdi>، أضِف <bdi>`~/.openclaw/.apothem/support/skills`</bdi> إلى تلك
القائمة بنفسك؛ ويحتفظ <bdi>`apothem update`</bdi> بالمفاتيح التي تضيفها إلى
<bdi>`openclaw.json`</bdi>. تقع خوادم <bdi>MCP</bdi> في كتلة <bdi>`mcp.servers`</bdi>
من إعداد <bdi>OpenClaw</bdi>، التي تديرها عبر <bdi>`openclaw mcp add`</bdi> والأوامر
الفرعية ذات الصلة؛ ولا يكتب المحوّل أي مُدخَلات هناك. (سلوك <bdi>OpenClaw</bdi> وفق
وثائقه عن [المهارات](https://docs.openclaw.ai/tools/skills)
و[واجهة سطر أوامر <bdi>MCP</bdi>](https://docs.openclaw.ai/cli/mcp)، كما قُرئت في 2026-10-02.)

## التحقّق

```bash
apothem verify --harness open-claw
```

يؤكّد أمر التحقّق ما يلي:

1. الإعداد الأصلي موجود في المسار المتوقَّع.
2. جميع الحقول الإلزامية من الملف التعريفي المشترك موجودة.
3. روتين التحقّق الخاص بالمحوّل يُبلِغ عن النجاح.

## التحديث

```bash
apothem update --harness open-claw
```

يُعيد اشتقاق الإعداد الأصلي من الحالة الراهنة للملف التعريفي المشترك.
شغّله بعد تحرير <bdi>`~/.config/apothem/profile.yaml`</bdi> أو ترقية حزمة
<bdi>Apothem</bdi> المُثبَّتة.

## إلغاء التثبيت

```bash
apothem uninstall --harness open-claw
```

يُزيل ملفات الإعداد الأصلي التي كتبها المحوّل.
لا يتأثّر ملف <bdi>YAML</bdi> الخاص بالملف التعريفي المشترك ولا محرّك <bdi>Apothem</bdi>.

## بوابة المطابقة

```bash
python -m apothem.conformity.gate --all .
```

## استكشاف الأخطاء وإصلاحها

| العَرَض | الإصلاح |
|---------|-----|
| ملف الإعداد غير موجود | أعد تشغيل <bdi>`apothem install --harness open-claw`</bdi> |
| فشل التحقّق | شغّل <bdi>`apothem update --harness open-claw`</bdi>، ثم تحقّق مجدّدًا |
| محتوى إعداد غير متوقَّع | افحص <bdi>`~/.config/apothem/profile.yaml`</bdi> أو <bdi>`--profile PATH`</bdi>، ثم أعد تشغيل <bdi>`apothem update --harness open-claw`</bdi> |
