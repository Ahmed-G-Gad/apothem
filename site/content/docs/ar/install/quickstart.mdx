هذا هو المسار السريع من لا شيء إلى إعداد إطار عمل مُتحقَّق منه: ثبِّت، وألِّف
الملف التعريفي المشترك، وجسِّد الإعداد الأصلي لأداة واحدة، وأكِّده، وأجرِ أول
تعديل لك. كل أمر حقيقي وقابل للتشغيل بالنسخ واللصق، وتُظهر كل خطوة ما يطبعه
التشغيل النظيف. يكتمل التثبيت نفسه في أقل من دقيقتين؛ وتحرير الملف التعريفي هو
الجزء الوحيد الذي يستغرق من الوقت ما تريده.

في النهاية سيكون لديك إعداد إطار عمل عامل مُولَّد من ملف تعريفي كتبته بنفسك —
وستعرف الأمر الوحيد الذي يدفع أي تغيير في الملف التعريفي مجددًا إلى أداة واحدة
أو إلى جميع الأدوات.

<Callout title="تريد النسخة المتأنّية المشروحة؟">
  يقطع [الدرس التعليمي للبدء](/docs/tutorials/getting-started) الطريق نفسه مع
  شرح أوفى لكل خطوة ولسبب أهميتها. أما هذه الصفحة فهي الجولة المقتضبة التي
  تُقدِّم المخرجات أولًا.
</Callout>

ستستخدم **<bdi>Claude Code</bdi>** إطارَ عمل للمثال — فهو الإطار الافتراضي
للمُثبِّت. بدِّل اسم المحوّل في أي خطوة لاستهداف أداة أخرى؛ تضمّ
[قائمة أُطُر العمل](/docs/harnesses) كل اسم مدعوم.

## 1. ثبِّت <bdi>Apothem</bdi>

يُشحَن <bdi>Apothem</bdi> بوصفه زمن التشغيل المكتفي ذاتيًا — يعمل المحرّك مباشرةً من شجرة مصدره مع اعتماديّات مُضمَّنة. أمر واحد يجلب المصدر، ويضع المحرّك، ويُجسِّد أول إطار عمل لك. يتحقّق الأمر من الإصدار الموقَّع أولًا، لذا استورِد مفتاح توقيع المشرف مرةً واحدة قبل أول تثبيت، وتحقّق من أن البصمة هي <bdi>`5C89 98F9 F241 7204 45D3  F28B 7039 6FED 9C63 4163`</bdi>:

```bash title="macOS · Linux · WSL2 · BSD — import the key once"
curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import
gpg --fingerprint 70396FED9C634163
```

```powershell title="Windows · PowerShell — import the key once"
& "$env:ProgramFiles\Git\bin\bash.exe" -c 'curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import && gpg --fingerprint 70396FED9C634163'
```

ثم شغّل المُثبِّت:

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 5.1+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

يتطلّب المُثبِّت <bdi>Python 3.10+</bdi> على مستوى النظام، إضافةً إلى <bdi>`git`</bdi> و<bdi>`gpg`</bdi> للصيغة الشبكية. يتحقّق من المتطلّبات المُسبقة ويضع المحرّك تحت <bdi>`~/.apothem`</bdi>. وعندما يكون <bdi>`click`</bdi> أو <bdi>`rich`</bdi> مفقودًا، يثبّت الحزمة بعد موافقتك، أو عند استخدام <bdi>`--yes`</bdi> (<bdi>`-Yes`</bdi> في <bdi>PowerShell</bdi>) أو <bdi>`APOTHEM_AUTO_INSTALL_DEPS=1`</bdi>، وإلا فيتوقّف مع أمر <bdi>pip</bdi> الذي يجب تشغيله (راجع [المتطلّبات المُسبقة بلمحة](/docs/install#المتطلّبات-المُسبقة-بلمحة)). وعند الاكتمال يطبع لافتة الخطوات التالية؛ وفي <bdi>POSIX</bdi>، عندما يكون دليل الغلاف موجودًا بالفعل على <bdi>`PATH`</bdi>، تبدو اللافتة هكذا:

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="التشغيل الأول دون ملف تعريفي">
  إن لم يكن لديك ملف تعريفي بعد، ينسخ المُثبِّت الملف التعريفي المثال إلى
  <bdi>`~/.config/apothem/profile.yaml`</bdi> ويتابع: فيُجسِّد أول إطار عمل لك
  ويتحقّق منه في التشغيل نفسه. حقول الهوية في المثال عناصر نائبة، لذا يطبع
  التثبيت ملاحظة. اجعل الملف التعريفي ملكك في الخطوة 2، ثم طبِّقه بالأمر
  <bdi>`apothem update --harness <name>`</bdi> كما في الخطوة 5.
</Callout>

<Callout title={<>الأمر <bdi>`apothem`</bdi></>}>
  يكتب المُثبِّت غلاف <bdi>`apothem`</bdi> في <bdi>`$HOME/.local/bin`</bdi>
  (<bdi>POSIX</bdi>) أو في <bdi>`%LOCALAPPDATA%\Microsoft\WindowsApps`</bdi>
  (<bdi>Windows</bdi>) ولا يعدّل <bdi>`PATH`</bdi> لديك أبدًا. وما إن يصبح ذلك
  الدليل على <bdi>`PATH`</bdi> حتى تُشغِّل المحرّك مباشرةً بالصيغة
  <bdi>`apothem <command>`</bdi>. وإن لم يكن على <bdi>`PATH`</bdi> بعد، تطبع
  اللافتة بديلًا مكتفيًا ذاتيًا —
  <bdi>`PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>`</bdi> — لا
  يحتاج إلى غلاف؛ ضع البادئة الدقيقة التي طبعتها لافتتك قبل كل أمر.
</Callout>

يغطّي [دليل التثبيت](/docs/install) مسارات التثبيت الأخرى — إضافة
<bdi>Claude Code</bdi> (<bdi>`/plugin marketplace add ahmed-g-gad/apothem`</bdi>
ثم <bdi>`/plugin install apothem@apothem`</bdi>)؛ وامتدادات عائلة
<bdi>VS Code</bdi> وغيرها من الامتدادات الأصلية للأدوات؛ وصيغة <bdi>npx</bdi> عند
الطلب (<bdi>`npx @ahmed-g-gad/apothem <command>`</bdi>) — إلى جانب خيارات متغيّرات
البيئة.

## 2. أنشئ الملف التعريفي المشترك

يكتب <bdi>`apothem profile init`</bdi> أصغر ملف تعريفي صالح وفق المخطط إلى
<bdi>`~/.config/apothem/profile.yaml`</bdi>. وإذا كان ملف تعريفي موجودًا هناك
بالفعل، كما حين ينسخ المُثبِّت المثال في الخطوة 1، يتوقّف <bdi>`init`</bdi> بخطأ
ويترك الملف دون تغيير؛ مرِّر <bdi>`--force`</bdi> للكتابة فوقه، أو احتفظ بالملف
وحرِّره كما هو موضّح أدناه. ومرِّر <bdi>`--profile PATH`</bdi> عندما تحتفظ بملف
تعريفي خاص بمشروع أو بـ <bdi>CI</bdi> في مكان آخر.

```bash
apothem profile init
apothem profile show --json
```

يستخدم الهيكل الأولي بيانات هوية نائبة زائفة، ومن الآمن تحريره قبل أن تُثبِّت أي
مخرجات لإطار عمل. ويقرؤه <bdi>`show --json`</bdi> مجددًا ويُبلِغ عن الملف التعريفي
المُتحقَّق منه مع ملء كل قيمة افتراضية، بدءًا بالحقل <bdi>`schema_version`</bdi>.
يطبعه الأمر في سطر واحد؛ وهو مُوسَّع هنا:

```json
{
  "schema_version": 1,
  "identity": {
    "name": "Example User",
    "role": "senior software engineer",
    "email": "dev@example.invalid",
    "github": "example-user"
  },
  "preferences": {
    "language": "python",
    "style": "concise"
  },
  "rules": [],
  "seriousness": "PERSONAL_USE",
  "enforcement": {
    "sprints": false,
    "agent_teams": false,
    "multitasking": false,
    "continuous_execution": false,
    "learning_loop": false
  },
  "mcp_servers": {},
  "agent_mcp_servers": {},
  "harnesses": {},
  "exclude_harnesses": [],
  "workspace": {
    "directory_name": ".apothem",
    "scope": "project-local"
  }
}
```

وهنا أيضًا يظهر التعديل المشوّه — إذا كان <bdi>YAML</bdi> غير صالح، يُبلِغ
<bdi>`show`</bdi> عنه هنا، قبل كتابة أي إعداد لإطار عمل. اجعل الملف التعريفي ملكك
بالأمر <bdi>`apothem profile edit`</bdi> (يفتحه في محرّرك) أو اضبط مفتاحًا واحدًا
في مكانه:

```bash
apothem profile set identity.name "Your Name"
```

## 3. ثبِّت محوّلات أُطُر العمل

جسِّد المحوّل الخاص بإطار عملك الأساسي. يقرأ هذا ملفك التعريفي ويكتب الإعداد
الأصلي لتلك الأداة:

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

تكتب المحوّلات ذات نطاق المشروع ملف قواعدها داخل مشروع، لذا تحتاج إلى
<bdi>`--project PATH`</bdi>؛ ويكتب سبعة منها أيضًا مهارات وقواعد مشتركة في مجلّدات
داخل دليلك المنزلي، ولا يغيّر <bdi>`--project`</bdi> مكان كتابتها. عايِن أي تثبيت
دون كتابة ملفات باستخدام <bdi>`--dry-run`</bdi>:

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

ثبِّت المجموعة الكاملة المستندة إلى السجلّ دفعةً واحدة بالخيار
<bdi>`--harness all`</bdi>. ولأن هذا الاختيار يكتب ملفات بنطاق المشروع وملفات بنطاق
المستخدم معًا، يطبع الأمر الأهداف الفعلية مُجمَّعةً حسب الموقع. وفي الطرفية
التفاعلية يطلب التأكيد قبل الكتابة خارج جذر المشروع. ويكتب التشغيل بلا طرفية، أو
التشغيل مع <bdi>`--yes`</bdi>، أو التشغيل مع <bdi>`--format json`</bdi> دون سؤال؛
أما <bdi>`--dry-run`</bdi> فلا يكتب شيئًا. وشغّل المجموعة الكاملة بالأمر:

```bash
apothem install --harness all --project .
```

راجع [القائمة الكاملة لأُطُر العمل](/docs/harnesses) لكل اسم مدعوم،
و[مرجع الأمر <bdi>install</bdi>](/docs/cli-reference/install) لمجموعة الخيارات
الكاملة.

## 4. تحقَّق

التجسيد نصف العمل فقط؛ إذ يؤكّد <bdi>`verify`</bdi> أن ملفات الإعداد المتوقَّعة
لإطار العمل قد وصلت وأنها صالحة:

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

يخرج <bdi>`verify`</bdi> برمز غير صفري إذا فُقد هدف مُدار، أو كان ملف مُدار فارغًا،
أو لم يُحلَّل إعداد <bdi>JSON</bdi> أو <bdi>YAML</bdi>. وأضِف
<bdi>`--profile PATH`</bdi> ليفشل أيضًا عندما يختلف ملف مثبّت عن ذلك الملف
التعريفي، فيصبح <bdi>`verify`</bdi> فحصًا للانحراف؛ ومن دونه يبقى الإعداد القديم
ناجحًا في التحقّق. ويتيح الخروج برمز غير صفري استخدام <bdi>`verify`</bdi> بوابةً
في سكربت إعداد. وللتحقّق من صحّة الجهاز كله عبر كل محوّل مُسجَّل، شغّل:

```bash
apothem doctor
```

يفحص <bdi>`doctor`</bdi> كل إطار عمل مُثبَّت: يجب أن يجتاز التحقّق، ويجب أن يبدأ
كل أمر خطّاف سجّله تثبيته. أما إطار العمل الذي لم تُثبِّته فيُدرَج لكنه لا يُعدّ
فشلًا، لذا يخرج <bdi>`doctor`</bdi> بالقيمة 0 عندما لا يفشل أي فحص، حتى لو لم
يكن مُثبَّتًا سوى إطار عمل واحد.

## 5. تشغيلك الأول

افتح إطار العمل الذي أعددته للتوّ — <bdi>Claude Code</bdi> في هذا المثال — وابدأ
جلسة في أي مشروع. الملف التعريفي الذي أعددته في الخطوة 2 صار الآن جزءًا من سلوك
تلك الأداة. هذا هو التشغيل الأول العامل: ملف تعريفي واحد يُشكِّل جلسة حقيقية.

عندما تُغيِّر الملف التعريفي لاحقًا، أعِد تطبيقه دون إعادة التثبيت:

```bash
apothem update --harness claude-code
```

سمِّ محوّلًا آخر لإعادة تطبيق الملف التعريفي على تلك الأداة (وأضِف
<bdi>`--project PATH`</bdi> للمحوّل ذي نطاق المشروع)، أو مرِّر
<bdi>`--harness all --project .`</bdi> لإعادة تطبيقه على كل إطار عمل مدعوم.
