هذا هو أقصر مسار من الصفر إلى تهيئة بيئة مُتحقَّق منها — تُثبِّت، وتُعرِّف ملف
التعريف المشترك، وتحوِّل التهيئة الأصلية لأداة ما، وتؤكِّدها، ثم تجري أول تحرير
لك. كل أمر حقيقي، وقابل للنسخ واللصق، وكل خطوة تُظهر ما يخرجه التشغيل النظيف.
يكتمل التثبيت نفسه في أقل من دقيقتين، وتحرير ملف التعريف هو الجزء الوحيد الذي
يستغرق ما تشاء من الوقت.

بنهاية ذلك ستملك تهيئة بيئة عاملة مُولَّدة من ملف تعريف كتبته بنفسك — وستعرف
الأمر الوحيد الذي يدفع تغييرًا في ملف التعريف إلى كل أداة.

<Callout title="تريد نسخة أبطأ وأوفر شرحًا؟">
  يقطع [دليل البدء التعليمي](/docs/tutorials/getting-started) المسار نفسه، مع
  شرح أوفى لكل خطوة ولماذا هي مهمّة. أما هذه الصفحة فجولة موجزة موجَّهة نحو
  المخرجات.
</Callout>

سنستخدم <bdi>Claude Code</bdi> مثالًا للبيئة — وهو الخيار الافتراضي للمثبِّت.
غيِّر اسم المحوِّل في أي خطوة لتشير إلى أداة أخرى. تجد كل الأسماء المدعومة في
[قائمة البيئات](/docs/harnesses).

## 1. ثبِّت Apothem

يُوزَّع <bdi>Apothem</bdi> بوصفه زمن تشغيل مكتفيًا ذاتيًا — يعمل المحرّك مباشرةً
من شجرة شفرة مصدرية تدمج اعتماداتها. أمر واحد يُنزِّل الشفرة المصدرية، ويضع
المحرّك، ويحوِّل أول بيئة.

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 7+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

يتطلّب المثبِّت <bdi>Python</bdi> 3.10+ يمكن من خلاله استيراد `click` و`rich`،
و`git` في الصيغة الشبكية. يفحص المتطلّبات المُسبقة، ويضع المحرّك في `~/.apothem`،
ويطبع عند الانتهاء استدعاء المحرّك الدقيق المناسب لصدفتك.

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="اختصار `apothem`">
  يضع المثبِّت اختصار `apothem` على `PATH`، فتشغّل المحرّك مباشرةً بصيغة
  `apothem <command>`. وإن لم يكن دليل الاختصار على `PATH` بعد، تطبع اللافتة
  بديلًا مكتفيًا ذاتيًا —
  `PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>` — لا يحتاج إلى
  اختصار؛ فضع البادئة الدقيقة التي طبعتها لافتتك قبل كل أمر.
</Callout>

يتناول [دليل التثبيت](/docs/install) مسارات التثبيت الأخرى — إضافة
<bdi>Claude Code</bdi> (`/plugin marketplace add ahmed-g-gad/apothem` يليه
`/plugin install apothem@apothem`)، وملحقات عائلة <bdi>VS Code</bdi> وغيرها من
الملحقات الأصلية للأدوات، وصيغة <bdi>npx</bdi> عند الطلب
(`npx @ahmed-g-gad/apothem <command>`) — مع خيارات متغيرات البيئة.

## 2. أنشئ ملف التعريف المشترك

يكتب `apothem profile init` ملف تعريف صحيحًا بحدّه الأدنى في
`~/.config/apothem/profile.yaml`. مرِّر `--profile PATH` إن كنت تدير ملف تعريف
خاصًا بمشروع أو بـ <bdi>CI</bdi> في مكان آخر.

```bash
apothem profile init
apothem profile show --json
```

يستخدم هذا الهيكل بيانات هوية وهمية بديلة، ومن الآمن تحريره قبل تثبيت أي مخرَج
بيئة. أما `show --json` فيعيد قراءته ويُبلِغ عن ملف تعريف مُتحقَّق منه.

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

هنا أيضًا تظهر التحريرات غير الصحيحة. إن كان <bdi>YAML</bdi> غير صالح، يُبلِغ
`show` عن ذلك في هذه اللحظة — قبل كتابة أي تهيئة بيئة. اجعل ملف التعريف ملكك عبر
`apothem profile edit` (يفتحه في محرِّر)، أو اضبط مفتاحًا واحدًا في مكانه.

```bash
apothem profile set identity.name "Your Name"
```

## 3. ثبِّت محوِّلات البيئة

حوِّل محوِّل الأداة البرمجية التي تستخدمها بصورة أساسية. يقرأ هذا ملف تعريفك،
ويكتب التهيئة الأصلية لتلك الأداة.

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

تتطلّب المحوِّلات ذات نطاق المشروع `--project PATH`، لأنها تكتب داخل المشروع
لا في دليل المنزل. ولمعاينة أي تثبيت دون كتابة ملفات، استخدم `--dry-run`.

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

ولتثبيت المجموعة الكاملة المدعومة بالسجلّ دفعةً واحدة، استخدم `--harness all`.
يكتب هذا الاختيار ملفات بنطاق المشروع وبنطاق المستخدم معًا، لذا يعرض الأمر
الوجهات المحدّدة مجمّعةً بحسب المكان، ويطلب التأكيد قبل الكتابة خارج جذر مشروعك.

```bash
apothem install --harness all --project .
```

تجد كل الأسماء المدعومة في [القائمة الكاملة للبيئات](/docs/harnesses)، ومجموعة
الخيارات الكاملة في [مرجع install](/docs/cli-reference/install).

## 4. تحقَّق

التحويل نصف العمل فقط. يؤكِّد `verify` أن ملفات التهيئة المتوقَّعة للبيئة قد كُتبت
وأنها تطابق ما يصرِّح به ملف التعريف.

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

يخرج `verify` برمز غير صفري إن كانت التهيئة مفقودة أو منحرفة، فيصلح بذلك بوّابةً
في برامج الإعداد النصية. وللفحص الصحّي على مستوى الجهاز لكل محوِّل مُسجَّل، شغِّل:

```bash
apothem doctor
```

يُبلِغ `doctor` عن حالة تثبيت كل محوِّل، ويخرج برمز غير صفري إن أبلغ أي محوِّل
مُسجَّل عن أنه غير مُثبَّت.

## 5. التشغيل الأول

افتح الأداة البرمجية التي أعددتَها للتوّ — <bdi>Claude Code</bdi> في هذا المثال —
وابدأ جلسة في أي مشروع. القواعد والإعدادات التي كتبتها في ملف التعريف بالخطوة 2
صارت بالفعل جزءًا من سلوك تلك الأداة. ذلك هو تشغيلك الأول العامل — ملف تعريف
واحد يصوغ جلسة حقيقية.

حين تُغيِّر ملف التعريف لاحقًا، أعد تطبيقه دون إعادة تثبيت.

```bash
apothem update --harness claude-code
```
