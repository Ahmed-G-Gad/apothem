## تحديث مُلحَق <bdi>Claude Code</bdi>

حدّث إدراج السوق (<bdi>marketplace</bdi>)، ثم حدّث المُلحَق من قائمة <bdi>`/plugin`</bdi>
داخل <bdi>Claude Code</bdi>:

```text title="Inside Claude Code"
/plugin marketplace update apothem
```

افتح <bdi>`/plugin`</bdi>، واختر **<bdi>apothem</bdi>**، ثم اختر إجراء التحديث عندما يُدرَج إصدار
أحدث من المُلحَق.

## يُشغّل <bdi>npx</bdi> الإصدار الحالي دائمًا

يحلّ <bdi>`npx @ahmed-g-gad/apothem`</bdi> إلى الحزمة المنشورة الحالية في كل
تشغيل، لذا لا يوجد شيء لتحديثه. عندما تقدّم ذاكرة <bdi>npx</bdi> المؤقتة القديمة نسخةً
أقدم، ثبّت وسم التوزيع (<bdi>dist-tag</bdi>) صراحةً:

```bash
npx @ahmed-g-gad/apothem@latest --version
```

## تحديث إعداد قائم على المُثبِّت

أعِد تشغيل المُثبِّت — فهو متّسق (<bdi>idempotent</bdi>) ويسحب وسم الإصدار في الشجرة الموجودة —
أو شغّل نص التحديث المخصّص:

```bash title="macOS · Linux · WSL2 · BSD"
bash scripts/installer/update.sh
```

```powershell title="Windows · PowerShell"
pwsh -NoProfile -File scripts/installer/update.ps1
```

يعيد نص التحديث سحب شجرة المصدر في <bdi>`APOTHEM_HOME`</bdi> (الافتراضي <bdi>`~/.apothem`</bdi>) إلى <bdi>`APOTHEM_REF`</bdi>؛ فإن لم يُضبَط يحلّ إلى أحدث وسم إصدار موقَّع بصيغة <bdi>`vMAJOR.MINOR.PATCH`</bdi>، وقيمة الوسم تثبّته، ويختار <bdi>`main`</bdi> الفرع المتحرّك فقط عندما يُضبط <bdi>`APOTHEM_ALLOW_UNVERIFIED=1`</bdi> أيضًا. ومن دون هذا التجاوز، يسحب التحديث المرجع ثم يُجهِض قبل إعادة التجسيد، لأن الفرع ليس وسم إصدار موقَّعًا. ويتحقّق من توقيع الوسم بـ <bdi>`git verify-tag`</bdi> قبل إعادة التجسيد؛ فيُجهَض عند وسم غير موقَّع أو مُتلاعَب به، ما لم يُخفِّض <bdi>`APOTHEM_ALLOW_UNVERIFIED=1`</bdi> الإجهاض إلى تحذير. والوسم الموقَّع الذي لا يوجد مفتاح ناشره العام في حلقة المفاتيح المحلية يُجهَض مع إرشادات لاستيراد المفتاح، تشير إلى البصمة المنشورة في [<bdi>SECURITY.md</bdi>](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md). ثم يُعيد تجسيد إطار العمل المُسمّى بـ <bdi>`APOTHEM_HARNESS`</bdi> بتشغيل <bdi>`apothem update`</bdi> من الشجرة المُحدَّثة (ويأخذ إطار العمل قيمته الافتراضية وفق جدول [متغيّرات بيئة المُثبِّت](/docs/how-to/installer-environment-variables)). ويتطلّب تثبيتًا سابقًا: فعندما لا توجد شجرة في <bdi>`APOTHEM_HOME`</bdi> ولم يُضبَط <bdi>`APOTHEM_SOURCE`</bdi>، يخرج برسالة توجّهك إلى المُثبِّت أولًا.

## إعادة تجسيد مُخرَج إطار العمل

بعد تحديث المحرّك أو تحرير <bdi>`~/.config/apothem/profile.yaml`</bdi>،
أعِد اشتقاق إعداد إطار العمل المُثبَّت. لا تحتاج المحوّلات ذات نطاق المستخدم إلى
<bdi>`--project`</bdi>؛ بينما تحتاجها المحوّلات ذات نطاق المشروع.

```bash
apothem update --harness claude-code
apothem update --harness cursor --project /path/to/project
apothem update --harness all --project /path/to/project
```

شغّل الأمر نفسه مع <bdi>`--dry-run --json`</bdi> عندما تحتاج إلى معاينة قابلة للقراءة آليًا
دون أي كتابة على نظام الملفات.

## حدود الأمر الحالية

يحدّث <bdi>`apothem update`</bdi> مُخرَج إطار العمل فقط. ولا تنفّذ واجهة سطر الأوامر
<bdi>`update --self`</bdi> أو <bdi>`update --check`</bdi> أو <bdi>`update --apply`</bdi>؛ حدّث المحرّك
نفسه عبر القناة التي ثبّتت منها — مسار <bdi>`/plugin`</bdi>، أو تشغيل
<bdi>`npx`</bdi> جديد، أو نصوص المُثبِّت/التحديث أعلاه.

## التحقّق من إصدار المحرّك

```bash
apothem --version
npx @ahmed-g-gad/apothem --version
```
