يرشدك هذا الدليل التعليمي عبر إعداد <bdi>Apothem</bdi> الأول بأكمله. تبدأ من حالة
لا شيء فيها مُثبَّت، وتنتهي بتهيئة إطار عمل حقيقي — مُولَّدة من ملف تعريف كتبتَه،
ومُتحقَّق منها، ومُؤكَّد أنها تعمل. يستغرق الأمر نحو خمس عشرة دقيقة. كل أمر أدناه
حقيقي وقابل للنسخ واللصق.

<Callout title="أعددتَه من قبل؟">
  إن كنت تريد مرجعًا موجزًا للأوامر الأربعة الأساسية فحسب، راجع
  [سير العمل الأساسي](/docs/usage/getting-started). أما هذه الصفحة فجولة موجَّهة
  من الصفر إلى التشغيل الأول.
</Callout>

عند الانتهاء سيكون لديك ما يلي.

1. <bdi>Apothem</bdi> مُثبَّتًا من مثبِّت البرنامج النصي.
2. ملف تعريف مشترك (مُحرَّر) يقود كل إطار عمل.
3. التهيئة الأصلية لإطار عمل واحد مُحوَّلة.
4. تأكيدٌ بأن تلك التهيئة قد تحقَّقت، وأن تشغيلًا أوّل عاملًا قد ثبت.

طوال الدليل، نستخدم <bdi>Claude Code</bdi> مثالًا لإطار العمل، لأنه الخيار الافتراضي
للمثبِّت. تنطبق الخطوات نفسها على أي إطار عمل مدعوم. غيِّر الاسم حين تصل إلى
[قائمة أُطُر العمل](/docs/harnesses).

## ما تحتاجه أولًا

- صدفة شبيهة بـ <bdi>Unix</bdi> (<bdi>macOS</bdi>، أو <bdi>Linux</bdi>، أو
  <bdi>WSL</bdi>). يغطّي مثبِّت <bdi>PowerShell</bdi> نظام <bdi>Windows</bdi>.
  يعرض هذا الدليل مسار `bash`.
- <bdi>Python</bdi> 3.10 أو أحدث على `PATH`. تأكَّد بـ `python3 --version`.
- المكتبتان لزمن التشغيل اللتان يستوردهما المحرّك من مفسّرك: `click` و`rich`. أما بقية الحزمة (`pyyaml`، `jsonschema`) فهي مضمّنة (vendored) داخل الشجرة، لذا يكفي أن تكون هاتان المكتبتان قابلتين للاستيراد. يفحصهما المثبِّت، ويذكر ما ينقص منهما، ويعرض تثبيت الأجزاء الناقصة نيابةً عنك، حتى تؤكّد وتتابع.

لا يُوزَّع <bdi>Apothem</bdi> بوصفه حزمةً عامة، بل بوصفه شجرة شفرة مصدرية
محزومة — لا خطوة `pip install`. يستنسخ المثبِّت الشجرة ويشغّل المحرّك منها مباشرة.

## الخطوة 1 — ثبِّت Apothem

شغِّل المثبِّت الشبكي.

```bash
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

ينفّذ المثبِّت هذه الخطوات:

1. **فحص المتطلّبات المُسبقة.** يجد المثبِّت مُفسِّر <bdi>Python</bdi> 3.10+ حقيقيًا، ويتأكّد من إمكانية استيراد مكتبتَي زمن التشغيل (`click` و`rich`). إن غابت إحداهما، يذكرها ويعرض تثبيتها نيابةً عنك — أو اضبط `APOTHEM_AUTO_INSTALL_DEPS=1` للتثبيت دون مطالبة.
2. **وضع الشفرة المصدرية.** تُستنسخ الشجرة المحزومة في `~/.apothem` (يمكن تجاوزه
   بمتغيّر البيئة `APOTHEM_HOME`). إعادة التشغيل تُحدِّث الاستنساخ القائم لا
   تكرّره.
3. **تهيئة ملف التعريف.** إن لم يكن لديك ملف تعريف بعد، ينسخ المثبِّت ملف تعريف
   نموذجيًا إلى `~/.config/apothem/profile.yaml`، و**يتوقّف ويطلب التحرير** قبل
   المتابعة. هذا متعمَّد. النموذج يستخدم بيانات هوية بديلة، وعليك أن تجعله ملكك
   قبل كتابة أي تهيئة إطار عمل. ستفعل ذلك في الخطوة 2.

يمكن التحكّم في التثبيت بمتغيرات البيئة. أكثرها استخدامًا ما يلي.

```bash
# Install a different harness as the default, and point at a project profile.
APOTHEM_HARNESS=cursor \
APOTHEM_PROFILE="$HOME/.config/apothem/profile.yaml" \
  curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

ومن المتغيرات الأخرى المعروفة: `APOTHEM_REPO` و`APOTHEM_REF` (أيُّ بعيد يُستنسخ،
وأيُّ مرجع <bdi>git</bdi> يُنزَّل؛ إن لم يُعرَّف، يحلّ أحدث وسم إصدار موقَّع
ويتحقّق منه، فاضبط وسمًا للتثبيت أو `main` للفرع المتغيّر باستمرار)،
و`APOTHEM_ALLOW_UNVERIFIED=1` (يخفّض فشل التحقّق من توقيع الوسم إلى تحذير)،
و`APOTHEM_SOURCE` (يستخدم فحصًا محليًا قائمًا بدل الاستنساخ)، و`APOTHEM_SKIP_VERIFY=1`
(يتخطّى التحقّق بعد التثبيت؛ اترُكه غير مُعرَّف هذه المرة لأننا نريد تشغيله).

حين يُتمّ المثبِّت تشغيلًا كاملًا، يطبع لافتةً تُظهر كيفية استدعاء المحرّك. يضع
اختصار `apothem` على `PATH` (في <bdi>POSIX</bdi>: `$HOME/.local/bin`؛ في
<bdi>Windows</bdi>: `%LOCALAPPDATA%\Microsoft\WindowsApps`)، فما إن يكون ذلك
الدليل على `PATH` حتى تشغّل المحرّك مباشرةً.

```bash
apothem <command>
```

وإن تعذّر وضع الاختصار — أو لم يكن دليله على `PATH` بعد — تطبع اللافتة بديلًا
مكتفيًا ذاتيًا لا يحتاج إلى اختصار.

```bash
PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>
```

تكتب بقية هذا الدليل `apothem <command>`؛ وإن كنت على الصيغة البديلة، فضع البادئة
الدقيقة التي طبعتها لافتة المثبِّت قبلها.

## الخطوة 2 — اجعل ملف التعريف ملكك

ملف التعريف المشترك في `~/.config/apothem/profile.yaml` هو مصدر الحقيقة الوحيد.
يقرؤه كل محوِّل إطار عمل، ويشتقّ منه التهيئة الأصلية لذلك الإطار. حرِّره مرّةً، يبقَ
كل إطار عمل تثبِّته متّسقًا.

افتحه بمحرِّر المحرّك أو بأي محرِّر نصوص.

```bash
apothem profile edit
```

يبدو ملف تعريف صحيح بحدّه الأدنى كما يلي.

```yaml
identity:
  name: "Example User"
preferences:
  style: "concise"
rules:
  - "Validate external input before writing files."
```

استبدل `name` البديل باسمك، وأضِف القواعد التي تريد أن تُطبَّق على كل إطار عمل. اترُك
القيم الوهمية النموذجية كما هي. صُمِّم ملف التعريف هذا ليكون آمنًا للمشاركة.

تأكَّد أن المحرّك يُعيد قراءة تحريرك دون مشكلة.

```bash
apothem profile show --json
```

إن كان <bdi>YAML</bdi> غير صحيح، ستعرف هنا. أصلِحه، وأعد التشغيل قبل المتابعة.

## الخطوة 3 — حوِّل تهيئة إطار العمل

سبق أن حوّل المثبِّت إطار العمل الافتراضي في الخطوة 1. لفعل ذلك صراحةً — أو لتحويل
إطار عمل ثانٍ — شغِّل `install`.

```bash
apothem install --harness claude-code
```

يقرأ هذا ملف تعريفك ويكتب التهيئة الأصلية لـ <bdi>Claude Code</bdi>. ولمعاينة كل
إطار عمل يمكنك تحديده، شغِّل:

```bash
apothem harnesses list
```

بعض أُطُر العمل ذات نطاق مشروع لا نطاق مستخدم، وتلك تتطلّب مسار `--project` ليعرف
المحوِّل أين يكتب.

```bash
apothem install --harness cursor --project .
```

## الخطوة 4 — تحقَّق وأكِّد التشغيل الأول

التحويل نصف القصّة فقط. بعد ذلك، تتأكّد من أن التهيئة طُبِّقت على نحو صحيح.

```bash
apothem verify --harness claude-code
```

يفحص `verify` أن ملف التهيئة المتوقَّع لإطار العمل موجود، وأنه يطابق ما يصرِّح به ملف
التعريف. التشغيل النظيف يعني نجاح التحويل.

وللفحص الصحّي على مستوى الجهاز لكل محوِّل مُسجَّل، شغِّل:

```bash
apothem doctor
```

يُبلِغ `doctor` عن حالة تثبيت كل محوِّل، ويخرج برمز غير صفري إن أبلغ أي محوِّل
مُسجَّل عن أنه غير مُثبَّت. بوّابة مفيدة في برامج الإعداد النصية.

**التشغيل الأول.** افتح الأداة البرمجية التي أعددتَها للتوّ — <bdi>Claude Code</bdi>
في هذا المثال — وابدأ جلسة في أي مشروع. القواعد والإعدادات التي كتبتها في ملف
التعريف صارت بالفعل جزءًا من سلوك تلك الأداة. ذلك هو تشغيلك الأول العامل. ملف
التعريف الذي حرَّرته في الخطوة 2 يصوغ جلسة حقيقية.

## ما الذي بنيتَه

بدأت من جهاز فارغ، وثبَّتَّ <bdi>Apothem</bdi>، وكتبت ملف تعريف مشترك، وحوّلت منه
التهيئة الأصلية لإطار عمل واحد، وتحقّقت من النتيجة، وأكَّدت أنها تعمل. ملف التعريف
أثرٌ دائم. غيِّره مرّةً، وأعد تشغيل `apothem update --harness <name>`، لتدفع ذلك
التغيير إلى أي إطار عمل.

## إلى أين بعد ذلك

- **أضِف أداة أخرى.** تغطّي [قائمة أُطُر العمل](/docs/harnesses) كل منصّة مدعومة واسم
  محوِّلها. كرِّر الخطوة 3 بـ `--harness` جديد.
- **تعمَّق في مهمّة واحدة.** [أدلّة الكيفية](/docs/how-to) وصفات موجَّهة نحو المهام
  لكتابة القواعد، وإنشاء الخطط، وتشغيل بوابة المطابقة.
- **ابحث عن تفصيل محدّد.** يوثّق [المرجع](/docs/harnesses) كل محوِّل، ومخطط ملف
  التعريف، وكل سطح من أسطح <bdi>CLI</bdi>.
- **خطِّط لعمل يتجاوز الجلسة الواحدة.** يشرح
  [التخطيط القابل للاستئناف](/docs/concepts/resumable-planning) كيف يُخرِج
  <bdi>Apothem</bdi> العملَ الطويل الأمد إلى مجموعة `.apothem/plans/` محلية
  للمشروع، فتستأنفه جلسة جديدة على أي جهاز في مكانه.

## الخطوة الموصى بها التالية

**شغِّل `apothem doctor`** لتأكيد أن كل محوِّل على جهازك يُبلِغ عن حالة تثبيت
سليمة قبل أن تنتقل إلى إضافة مزيد من أُطُر العمل.
