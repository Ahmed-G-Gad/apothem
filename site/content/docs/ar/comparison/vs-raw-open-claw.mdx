يقرأ <bdi>Open-Claw</bdi> ملف `~/.openclaw/openclaw.json`. يثبّت <bdi>Apothem</bdi>
مجموعات الأوامر والمهارات المشتركة تحت `~/.openclaw/.apothem/support/skills/` ويؤلّف مفتاحًا
واحدًا هناك، `skills.load.extraDirs`، يسرد ذلك الدليل كي يحمّل <bdi>OpenClaw</bdi> المهارات.
أما حقله `agents.defaults.skills` فهو قائمة أسماء مسموح بها تملكها أنت، و<bdi>MCP</bdi> سطح
<bdi>CLI</bdi>، لذا لا يؤلّف <bdi>Apothem</bdi> أيًّا منهما.

## الحالة

**معاينة.** يستهدف محوِّل <bdi>Open-Claw</bdi> ملف التهيئة المُوثَّق حاليًا وسطح
دليل المهارات الإضافي. تبقى الحزم غير المهارية مواد دعم لـ <bdi>Apothem</bdi>.

## مقارنة الجهد

| المهمة | تهيئة يدوية خام | مُدارة بـ Apothem |
| ---- | --------------- | --------------- |
| تأليف مهارات قابلة لإعادة الاستخدام | تحرير التهيئة وأدلّة المهارات يدويًا | الكتابة مرّة واحدة في المتن المشترك |
| إبقاء الحزم متوائمة مع أُطُر العمل الأخرى | يدويًا، لكل أداة | تلقائيًا عند `apothem update` |
| تثبيت / إزالة التهيئة | يدويًا | `apothem install` / `apothem uninstall` |
| التحقّق من صحّة التهيئة | فحص يدوي | `apothem verify --harness open-claw` |

## ما يديره Apothem

يكتب محوِّل <bdi>Open-Claw</bdi> ملف `openclaw.json`، ويلفّ أوامر الشَّرطة المائلة
الخاصة بـ <bdi>Apothem</bdi> بوصفها مهارات، وينسخ مهارات <bdi>Apothem</bdi> إلى
دليل الدعم المُشار إليه، ويحفظ القواعد والقوالب و<bdi>agents</bdi> ومادة الخطّاف تحت شجرة دعم <bdi>Apothem</bdi> الفرعية.
يقرأ <bdi>OpenClaw</bdi> المفتاح `skills.load.extraDirs` بأدنى أسبقية بين مصادر مهاراته، لذا
تُستخدَم مهارة بالاسم نفسه في مساحة عملك، أو في `~/.agents/skills`، أو في
`~/.openclaw/skills` بدلًا من نسخة <bdi>Apothem</bdi>.

## مسار الهجرة

1. شغّل `apothem profile init` لإنشاء الملف التعريفي المشترك إن لم تكن قد فعلت بعد.
2. انقل مهارات <bdi>Open-Claw</bdi> أو مُوجِّهات الأوامر القابلة لإعادة الاستخدام
   إلى المتن المشترك.
3. شغّل `apothem install --harness open-claw` لتصيير التهيئة الأصلية ودليل مهارات
   الدعم.
4. شغّل `apothem verify --harness open-claw` لتأكيد أن التهيئة قد هبطت.
