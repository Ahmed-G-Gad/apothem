<bdi>GLM (Z.ai)</bdi> واجهة خلفية للنماذج يتوجّه إليها إطار عمل متوافق بضبط عنوان
<bdi>URL</bdi> أساسي ومفتاح. يمكنك تصدير متغيّرات البيئة تلك يدويًا، لكل مشروع، ولكل
جهاز، إلى الأبد. يُسجِّل محوّل <bdi>glm</bdi> في <bdi>Apothem</bdi> نقاط نهاية الواجهة
الخلفية والعناصر النائبة التي يضبطها المُشغِّل في ملف مزوّد واحد، ويكتب القالب نفسه
في كل مشروع. تقابل هذه الصفحة بين الربط اليدوي لتلك الواجهة الخلفية وإدارتها بـ
<bdi>Apothem</bdi>.

## مقارنة الجهد

| المهمة | إعداد يدوي خام | مُدار عبر <bdi>Apothem</bdi> |
| ---- | --------------- | --------------- |
| تسجيل عناوين <bdi>URL</bdi> للواجهة الخلفية | الحفظ عن ظهر قلب وإعادة التصدير لكل مشروع | تُكتَب في ملف مزوّد واحد |
| مصدر الحقيقة | تصديرات كل صدفة الخاصة بها | ملف مزوّد مرجعي واحد |
| إبقاء الواجهات الخلفية متوائمة عبر المشاريع | إعادة الربط لكل مشروع | يُكتَب القالب نفسه في كل مشروع |
| استعادة الإعداد | إعادة التصدير في كل مشروع | <bdi>`apothem update --harness glm --project <path>`</bdi> يكتب الملف من جديد فقط حين يكون مفقودًا |
| إزالة الإعداد | حذف يدوي | <bdi>`apothem uninstall`</bdi> مع نسخة احتياطية |

## ما يديره <bdi>Apothem</bdi>

يُصيِّر محوّل <bdi>glm</bdi> ملف مزوّد واحدًا في
<bdi>`<project>/.apothem/providers/glm.toml`</bdi> ولا يكتب شيئًا غيره. ويُسجِّل عنوان
<bdi>URL</bdi> الأساسي المتوافق مع <bdi>Anthropic</bdi>
(<bdi>`https://api.z.ai/api/anthropic`</bdi>)، وعنوان <bdi>URL</bdi> الأساسي المتوافق
مع <bdi>OpenAI</bdi> (<bdi>`https://api.z.ai/api/coding/paas/v4`</bdi>)، وعنصرًا
نائبًا لرمز المصادقة، وعناصر نائبة لتعيين النماذج. يبقى مفتاح <bdi>Z.ai</bdi> الخاص بك
واختياراتك لمُعرِّفات النماذج ملكًا للمُشغِّل — لا يكتب <bdi>Apothem</bdi> سرًّا
حقيقيًا أبدًا، ولا يُثبِّت أي مُعرِّف نموذج متقلّب بتغيّر النسخ.

## مسار الترحيل

1. شغّل <bdi>`apothem profile init`</bdi> لإنشاء الملف التعريفي المشترك إن لم تكن قد
   فعلت ذلك بعد.
2. شغّل <bdi>`apothem install --harness glm --project <path>`</bdi> لتصيير ملف المزوّد
   <bdi>`glm.toml`</bdi>.
3. املأ مفتاح <bdi>Z.ai</bdi> الخاص بك ومُعرِّفات النماذج التي تريدها من
   [وثائق <bdi>Z.ai</bdi>](https://docs.z.ai/devpack/tool/claude) الحالية.
4. شغّل <bdi>`apothem verify --harness glm --project <path>`</bdi> للتأكّد من وصول
   الإعداد.
5. عدّل <bdi>`.apothem/providers/glm.toml`</bdi> مع كل تغيير لاحق. لا يُعيد
   <bdi>Apothem</bdi> كتابة ملف مزوّد موجود أبدًا؛ أما
   <bdi>`apothem update --harness glm --project <path>`</bdi> فيكتبه من جديد فقط حين
   يكون مفقودًا.
