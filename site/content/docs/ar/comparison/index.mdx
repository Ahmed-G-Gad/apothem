<bdi>Apothem</bdi> مدير تهيئة أُطُر عمل ذكاء اصطناعي مستقل عن المضيف. يُحوَّل ملف
تعريف مشترك واحد في `~/.config/apothem/profile.yaml` إلى سبعة عشر سطح تهيئة
أصلي لإطار العمل. يؤطّر هذا القسم كيفية تقييم <bdi>Apothem</bdi> أمام البدائل التي
تستخدمها بالفعل.

## مقارنة Apothem

تحلّ أدوات أخرى جزءًا مجاورًا من هذه المشكلة. مديرو التهيئة المعتمدون على الملفات
مثل <bdi>chezmoi</bdi> و<bdi>GNU Stow</bdi> يضعون الملفات أو يقولِبونها، لكنهم لا
يترجمون مصدرًا واحدًا إلى التهيئة *الأصلية* لكل أداة برمجية. أدوات سطر الأوامر
لمزامنة القواعد عبر الأدوات مثل <bdi>rulesync</bdi> تولّد ملفات أصلية لكل أداة
عبر أدوات أكثر من سبعة عشر لدى <bdi>Apothem</bdi>، ووحدةً مُزامَنة واسعة بشكل
مماثل. ما يميّز <bdi>Apothem</bdi> هو **انضباط الحوكمة ودورة الحياة الموزَّع حول
المزامنة** — بوابة مطابقة آلية، وخطوط أنابيب حتمية، وحصن تدقيق، ودورة حياة قابلة
للعكس ومُتحقَّق منها.

| القدرة | Apothem | مديرو تهيئة الملفات (chezmoi, Stow) | مزامنة القواعد عبر الأدوات (rulesync) | تهيئة أصلية لكل أداة |
| ---------- | :-----: | :----------------------------------: | :-----------------------------: | :--------------------: |
| مصدر واحد إلى مخططات أصلية لأدوات كثيرة | نعم — سبعة عشر محوِّل إطار عمل | لا — نسخ / ربط رمزي، دون ترجمة | نعم | لا — أداة واحدة |
| الوحدة المُزامَنة | قواعد، مهارات، خطّافات، أوامر شرطة مائلة، MCP | أي ملفات | قواعد، تجاهل، MCP، أوامر، وكلاء فرعيون، مهارات، خطّافات، أذونات | — |
| مجموعة محكومة (قواعد سلوك إضافةً إلى بوابة مطابقة آلية) | نعم — `python -m apothem.conformity.gate` | لا | لا | لا |
| خط أنابيب تخطيط وبحث حتمي | نعم — من `/plan-spec` إلى `/plan-execute`، و`/research` بثلاث عشرة مرحلة | لا | لا | لا |
| حصن تدقيق يكتشف ويصحّح | نعم — مسح بأحد عشر أمرًا، حلقة إعادة تدقيق `/fortress` | لا | لا | لا |
| إصدارات مُحصَّنة ضد سلسلة التوريد | نعم — SBOM، وSigstore، وSLSA، وأهداف Scorecard | لا | أحيانًا | لا |
| دورة حياة قابلة للعكس ومُتحقَّق منها | نعم — نسخ احتياطي، و`apothem verify --json`، وإلغاء تثبيت بلا أيتام | أحيانًا | أحيانًا | — |

وحيثما يكون منافسٌ أقوى، نُسمّيه. <bdi>rulesync</bdi> يصل إلى أدوات أكثر ويحمل
وحدة مزامنة واسعة بشكل مماثل، وبعض الأدوات تحوِّل مخططات أصلية في المزامنة.
يستبدل <bdi>Apothem</bdi> عددَ الأدوات الخام بانضباط الحوكمة والتدقيق ودورة
الحياة الموزَّع حول المزامنة — بوابة مطابقة، وخطوط أنابيب حتمية `/plan`
و`/research`، وحصن تدقيق بأحد عشر أمرًا، وذاكرة دائمة، ودورة حياة قابلة للعكس
ومُتحقَّق منها — وهو ما لا تحمله أداة مزامنة القواعد.

## كيفية المقارنة

قارِن على ثلاثة محاور.

1. **مصدر الحقيقة.** أين تعيش قواعدك، وعمّالك المُفوَّضون، وأوامرك، وإعداداتك؟ يحفظ
   <bdi>Apothem</bdi> مجموعة مشتركة واحدة، ويرسم منها الصيغة الأصلية لكل إطار عمل.
   أما التهيئة اليدوية فتحفظ نسخةً لكل أداة.
2. **كلفة الانحراف.** ماذا يحدث حين تُغيِّر قاعدةً واحدة؟ ينشر <bdi>Apothem</bdi>
   التغيير إلى كل إطار عمل مُثبَّت عند تشغيل `apothem update`. أما التهيئة اليدوية
   فتتطلّب تحرير الملف الأصلي لكل أداة على حِدَة، والحفاظ على الاتّساق اعتمادًا
   على الذاكرة.
3. **التحقّق.** كيف تعرف أن كل إطار عمل مُهيّأ على نحو صحيح؟ يأتي <bdi>Apothem</bdi>
   مع `apothem verify --harness <name>` و`apothem doctor`. أما التهيئة اليدوية
   فلا تحقّق مدمجًا فيها.

## مصفوفة الميزات

تقابل هذه المصفوفة <bdi>Apothem</bdi> أمام البديلين اللذين يلجأ إليهما المشغِّل
أوّلًا — صيانة التهيئة الأصلية لكل إطار عمل يدويًا، وإدارة تلك الملفات بمدير
<bdi>dotfiles</bdi> عام.

| القدرة | تهيئة مُدارة يدويًا | مدير dotfiles | Apothem |
| ---------- | ---------------------- | --------------- | ------- |
| مصدر حقيقة مشترك واحد | لا (نسخة لكل أداة) | لا (يتتبّع ملفات لا ملف تعريف) | نعم (ملف تعريف واحد) |
| يرسم الصيغة الأصلية لإطار العمل | يدويًا | لا | نعم (محوِّل لكل محوِّل) |
| يمنع الانحراف بين أُطُر العمل | مواءمة يدوية | مزامنة ملفات فقط | نعم (`apothem update`) |
| التثبيت / إلغاء التثبيت لكل إطار عمل | يدويًا | جزئيًا (ربط / نسخ) | نعم (`install` / `uninstall`) |
| تحقّق مدمج | لا يوجد | لا يوجد | نعم (`verify` / `doctor`) |
| ترجمة الصيغة لكل أداة | لا يوجد | لا يوجد | نعم (`.mdc`، و`.toml`، و`.md` مضمّن) |
| سبعة عشر إطار عمل من مُدخَل واحد | لا | لا | نعم |
