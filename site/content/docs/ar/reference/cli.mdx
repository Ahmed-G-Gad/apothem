واجهة سطر الأوامر <bdi>`apothem`</bdi> هي الواجهة الأساسية للمُشغِّل لإدارة الملف
التعريفي المشترك ومحوّلات أُطُر العمل.

## الرايات العامة

| الراية | الوصف |
|------|-------------|
| <bdi>`--version`</bdi> | يطبع نسخة <bdi>Apothem</bdi> ويخرج |
| <bdi>`--help`</bdi> | يطبع التعليمات الخاصة بالأمر |

## الأوامر الفرعية

### <bdi>`apothem install`</bdi>

يُثبّت محوّل إطار عمل من الملف التعريفي المشترك.

```bash
apothem install --harness <name|all> [--profile PATH] [--project PATH] [--dry-run] [--clean|--fresh] [--yes]
```

| الخيار | الوصف |
|--------|-------------|
| <bdi>`--harness <name>`</bdi> | اسم محوّل إطار العمل (راجع القيم المرجعية أدناه). مطلوب. |
| <bdi>`--profile PATH`</bdi> | المسار إلى ملف <bdi>YAML</bdi> للملف التعريفي المشترك. القيمة الافتراضية <bdi>`~/.config/apothem/profile.yaml`</bdi>. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. |
| <bdi>`--dry-run`</bdi> | معاينة التثبيت دون كتابة ملفات. |
| <bdi>`--clean`</bdi>، <bdi>`--fresh`</bdi> | بداية نظيفة اختيارية: نسخ حالة التثبيت السابقة احتياطيًا ثم إزالتها (<bdi>`~/.claude`</bdi>، و<bdi>`~/.codex`</bdi>، و<bdi>`~/.agents`</bdi>، و<bdi>`~/.config/apothem`</bdi>) قبل التثبيت. |
| <bdi>`--yes`</bdi> | تخطّي التأكيد لكل هدف أثناء إزالة البداية النظيفة (مطلوب لتشغيلات <bdi>`--clean`</bdi> غير التفاعلية). |

قيم <bdi>`--harness`</bdi> المرجعية:

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

استخدم <bdi>`--harness all --project <path>`</bdi> لاختيار المجموعة على مستوى السجلّ
كله. وتُحترَم قائمة <bdi>`exclude_harnesses`</bdi> في الملف التعريفي أثناء الاختيار
الدفعي في التثبيت/التحديث.

### <bdi>`apothem update`</bdi>

يُعيد اشتقاق الإعداد الأصلي لمحوّل إطار عمل من الملف التعريفي المشترك الحالي.

```bash
apothem update --harness <name|all> [--profile PATH] [--project PATH] [--dry-run]
```

| الخيار | الوصف |
|--------|-------------|
| <bdi>`--harness <name>`</bdi> | اسم محوّل إطار العمل. مطلوب. |
| <bdi>`--profile PATH`</bdi> | المسار إلى ملف <bdi>YAML</bdi> للملف التعريفي المشترك. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. |
| <bdi>`--dry-run`</bdi> | معاينة التحديث دون كتابة ملفات. |

يُعيد <bdi>`update`</bdi> تجسيد مُخرَجات إطار العمل. ولا يُرقّي محرّك <bdi>Apothem</bdi>
نفسه؛ حدِّث المحرّك عبر القناة التي ثبّتّه بها (مسار <bdi>`/plugin`</bdi>، أو <bdi>`npx`</bdi>،
أو سكربتات المُثبِّت والتحديث)، كما هو موضَّح في [التحديث](/docs/install/updating).

### <bdi>`apothem uninstall`</bdi>

يزيل الإعداد الأصلي لمحوّل إطار عمل.

```bash
apothem uninstall --harness <name|all> [--project PATH] [--yes]
```

| الخيار | الوصف |
|--------|-------------|
| <bdi>`--harness <name>`</bdi> | اسم محوّل إطار العمل. مطلوب. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. |
| <bdi>`--yes`</bdi> | تخطّي مُطالَبة التأكيد. |

### <bdi>`apothem verify`</bdi>

يتحقّق من أن الأهداف المُدارة لمحوّل إطار عمل موجودة وصالحة.

```bash
apothem verify --harness <name|all> [--profile PATH] [--project PATH]
```

| الخيار | الوصف |
|--------|-------------|
| <bdi>`--harness <name>`</bdi> | اسم محوّل إطار العمل أو <bdi>`all`</bdi>. مطلوب. |
| <bdi>`--profile PATH`</bdi> | ملف <bdi>YAML</bdi> للملف التعريفي المشترك الذي يُفحَص مدى أمانة التثبيت له. ومن دونه يكون الفحص بنيويًا بحتًا. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. |

من دون <bdi>`--profile`</bdi> يكون الفحص بنيويًا: يجب أن يكون كل هدف مُدار موجودًا
وصالحًا. ومع <bdi>`--profile`</bdi> يشترط الفحص الأمانةَ أيضًا، فيُخفِق التحقّق في
تثبيتٍ موجود لكنه انحرف عن ذلك الملف التعريفي — استخدمه للتأكّد من أن ملفًا
تعريفيًا بعينه مُثبَّت بأمانة.

رمز الخروج هو <bdi>`0`</bdi> عندما يُتحقَّق من إطار العمل (ويكون، مع
<bdi>`--profile`</bdi>، أمينًا له)، و<bdi>`1`</bdi> عندما يكون هدفٌ مفقودًا أو غير
صالح، أو عندما يُمرَّر <bdi>`--profile`</bdi> ويكون التثبيت قد انحرف.

### <bdi>`apothem status`</bdi>

يُبلِغ عن حالة التثبيت والتحقّق والانحراف لكل إطار عمل مُسجَّل.

```bash
apothem status [--profile PATH] [--project PATH]
```

| الخيار | الوصف |
|--------|-------------|
| <bdi>`--profile PATH`</bdi> | الملف التعريفي المشترك الذي يُستخدَم خطَّ أساسٍ للانحراف. والملف التعريفي الافتراضي غير القابل للقراءة يُخفِّض الانحراف إلى <bdi>`unknown`</bdi> بدلًا من إجهاض المسح. |
| <bdi>`--project PATH`</bdi> | جذر المشروع لأُطُر العمل ذات نطاق المشروع. ومن دونه تُبلِغ هذه الأُطُر عن <bdi>`needs-project`</bdi>. |

يقرن كل صفٍّ راية <bdi>`installed`</bdi> براية <bdi>`verified`</bdi>، وتجتمع
الرايتان في حالة الانحراف:

| الحالة | المعنى |
|-------|---------|
| <bdi>`absent`</bdi> | لم يُثبِّت <bdi>Apothem</bdi> في إطار العمل هذا. |
| <bdi>`in-sync`</bdi> | مُثبَّت ومطابق لخط أساس الملف التعريفي. |
| <bdi>`drift`</bdi> | مُثبَّت لكنه لم يعد مطابقًا — عالِجه بـ <bdi>`apothem update`</bdi>. |
| <bdi>`unknown`</bdi> | مُثبَّت، لكن تعذّرت قراءة الملف التعريفي الأساس. |
| <bdi>`needs-project`</bdi> | أُبلِغ عن إطار عمل ذي نطاق مشروع من دون <bdi>`--project`</bdi>، فتعذّر تحديد هدفه. |

تُجيب <bdi>`installed`</bdi> عن السؤال «هل ثبّت <bdi>Apothem</bdi> هنا؟»، لا عن
«هل إطار العمل هذا موجود على الجهاز؟». وهي مبنيّة على مُنتَجات <bdi>Apothem</bdi>
نفسه — الكتلة المُدارة داخل مرساة التعليمات، والمحتوى تحت الشجرة الفرعية
<bdi>`.apothem/`</bdi> التي يملكها <bdi>Apothem</bdi> — ولا تُبنى أبدًا على ملف يملكه
المورّد يكتبه إطار العمل لنفسه. وإطار العمل الذي يوجد دليل إعداده لكن
<bdi>Apothem</bdi> لم يمسّه قطّ يُبلِغ عن <bdi>`absent`</bdi>، والإطار الذي أُلغي
تثبيته يُبلِغ عن <bdi>`absent`</bdi> حتى وإن بقيت الأدلة المُفرَغة.

### <bdi>`apothem profile`</bdi>

يُدير الملف التعريفي المشترك لـ <bdi>Apothem</bdi>.

```bash
apothem profile show [--profile PATH]
apothem profile init [--profile PATH] [--force]
apothem profile set <key> <value> [--profile PATH]
apothem profile edit [--profile PATH]
```

| الأمر الفرعي | الوصف |
|------------|-------------|
| <bdi>`profile init`</bdi> | يُنشئ هيكلًا أوّليًّا مُصغَّرًا لملف تعريفي صالح وفق المخطط. |
| <bdi>`profile show`</bdi> | يطبع الملف التعريفي المُحلَّل بصيغة <bdi>JSON</bdi> إلى <bdi>stdout</bdi>. ومع <bdi>`--json`</bdi> يتصدّر المستند الحقل <bdi>`schema_version`</bdi>. |
| <bdi>`profile set <key> <value>`</bdi> | يضبط حقلًا في الملف التعريفي. تُخزَّن القيمة سلسلةً نصّية حرفية؛ فلا تُحوَّل الكلمات المجرّدة قسرًا، فتبقى <bdi>`no`</bdi> على هيئة <bdi>`"no"`</bdi> وتبقى <bdi>`1.0`</bdi> سلسلة نصّية، باستثناء <bdi>`true`</bdi>/<bdi>`false`</bdi> ومُدخَلات القوائم والخرائط الصريحة <bdi>`[...]`</bdi> / <bdi>`{...}`</bdi>. ويُتحقَّق من الملف التعريفي المُجمَّع عبر المخطط قبل كتابته. |
| <bdi>`profile edit`</bdi> | يفتح الملف التعريفي في <bdi>`$EDITOR`</bdi> (ويرجع إلى المحرّر الافتراضي للمنصّة). |

يُوجِّه الخيار <bdi>`--profile PATH`</bdi> كلَّ أمر فرعي إلى ملف تعريفي بديل. والقيمة
الافتراضية <bdi>`~/.config/apothem/profile.yaml`</bdi>.

### <bdi>`apothem harnesses`</bdi>

يسرد محوّلات أُطُر العمل المُسجَّلة ويفحصها.

```bash
apothem harnesses list
apothem harnesses show <name>
```

| الأمر الفرعي | الوصف |
|------------|-------------|
| <bdi>`harnesses list`</bdi> | يطبع جدولًا بكل محوّل مُسجَّل مع راية حالة تثبيته ومسار مُخرَجه. |
| <bdi>`harnesses show <name>`</bdi> | يطبع الاسم وحالة التثبيت ومسار المُخرَج لمحوّل واحد. |

### <bdi>`apothem doctor`</bdi>

يُشغّل تشخيصات النظام لتثبيت <bdi>Apothem</bdi>.

```bash
apothem doctor
```

يطبع إصدار <bdi>Apothem</bdi>، ومُفسِّر <bdi>Python</bdi>، والمنصّة، ومسار الملف التعريفي المُحلَّل، وجدول حالة التثبيت لكل إطار عمل. ورمز الخروج هو <bdi>`1`</bdi> عندما يفشل أي فحص: ملف تعريفي غير صالح، أو إطار عمل مثبّت لا يجتاز التحقّق، أو أمر خطّاف مُسجَّل لا يمكن تشغيله، أو محوّل تعذّر تحميله أو استجوابه، أو سجلّ غير قابل للقراءة. ويُبلَّغ عن إطار العمل غير المثبّت ولا يُعدّ فشلًا، والملاحظات الإعلامية لا تغيّر رمز الخروج.
