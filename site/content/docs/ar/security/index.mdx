تقوم وضعية الأمان في <bdi>Apothem</bdi> على خمس ركائز: تقوية سلسلة التوريد، والاستجابة للثغرات، وحماية الفرع، وتوقيع الإصدارات، والتحليل الأمني المستمر. يوثّق هذا القسم كل سطح.

## نموذج التهديد

<bdi>Apothem</bdi> مُجسِّد إعدادات. يقرأ ملفًا تعريفيًا مشتركًا ويكتب ملفات إعداد
أصلية لأُطُر العمل في الأدلة التي يقرأها كل إطار عمل. وتلك الوظيفة الواحدة تحدّد
ما يثق به وما لا يثق به.

- **ما يثق به <bdi>Apothem</bdi>.** الملف التعريفي المشترك الذي تؤلّفه، وشجرة
  المصدر المُحزَّمة التي يضعها المُثبِّت. الملف التعريفي هو نيّتك المُعلَنة؛
  ويعامله المحرّك بوصفه مُدخَلًا مرجعيًا بعد التحقّق منه عبر المخطط.
- **ما لا يثق به <bdi>Apothem</bdi>.** لا يصل محتوى الملف التعريفي إلى نظام الملفات
  إلا بعد التحقّق: إخفاقات المخطط، ومُعرِّفات أُطُر العمل غير المعروفة، ومسارات
  المشروع غير الآمنة، ومصادر البيان المفقودة، واجتياز مسار الهدف، وعبور الروابط
  الرمزية، كلّها تتوقّف قبل أي كتابة وتُعيد تشخيصات مُهيكَلة مع
  <bdi>`files_written: []`</bdi>.
- **ما لا يحمله الخرج المُجسَّد أبدًا.** لا أسرار. تُنقّح تشخيصات الملف التعريفي
  المفاتيح الشبيهة بالأسرار والقيم ذات هيئة الرموز المميّزة قبل أن تصل إلى الخرج
  النصّي العادي، أو <bdi>JSON</bdi>، أو السجلات، أو مقتطفات الوثائق، أو الاختبارات،
  وتستخدم الأمثلة العامة هويات ونطاقات نائبة زائفة. الإعداد المُجسَّد مُعدّ لكي
  يُودَع في المستودع ويُشارَك؛ ولا يحمل أي بيانات اعتماد.
- **أرضية الرفض الشاملة.** تحمل القواعد التي يُجسِّدها <bdi>Apothem</bdi> أرضية رفض
  غير قابلة للتفاوض بصرف النظر عن أي قائمة سماح خاصة بإطار عمل — مسارات الأسرار
  (<bdi>`.env*`</bdi>، و<bdi>`~/.ssh/**`</bdi>، ومخازن بيانات الاعتماد)، وعمليات
  الصدفة التدميرية (<bdi>`rm -rf`</bdi>، و<bdi>`sudo`</bdi>، والدفع بالقوة إلى
  الفروع المحمية)، وتنفيذ المُدخَلات غير الموثوقة. ولا توسّع أي قائمة سماح هذه
  الأرضية بصمت.
- **نطاق الأثر.** تُحصَر عمليات الكتابة في أدلة أُطُر العمل وأشجار الدعم الفرعية
  التي يملكها <bdi>Apothem</bdi>. تُنسَخ الأهداف المُدارة الموجودة احتياطيًا قبل
  استبدالها، وتُدمَج أدلة الاكتشاف المشتركة عنصرًا فرعيًا تلو الآخر، فتبقى الملفات
  غير ذات الصلة التي ألّفها المُشغِّل في مكانها.

## وضعية الأمان في وقت التشغيل

تتحقّق أوامر دورة حياة أُطُر العمل وكتابة الملف التعريفي قبل الكتابة. وتتوقّف
إخفاقات مخطط الملف التعريفي، ومُعرِّفات أُطُر العمل غير المعروفة، ومسارات المشروع
غير الآمنة، ومصادر البيان المفقودة، واجتياز مسار الهدف، وعبور الروابط الرمزية قبل
الكتابة إلى نظام الملفات، وتُعيد تشخيصات مُهيكَلة مع <bdi>`files_written: []`</bdi>.

تحافظ عمليات التثبيت والتحديث على الأهداف المُدارة الموجودة بنسخها احتياطيًا قبل
استبدالها. وتُدمَج أدلة الاكتشاف المشتركة عنصرًا فرعيًا تلو الآخر بحيث تبقى الملفات
غير ذات الصلة التي ألّفها المُشغِّل في مكانها. ويُجري <bdi>`--dry-run`</bdi> التحقّق
نفسه ويُبلِغ عن النتائج المُخطَّطة دون إنشاء أدلة أو ملفات.

تُنقّح تشخيصات الملف التعريفي المفاتيح الشبيهة بالأسرار والقيم ذات هيئة الرموز
المميّزة قبل أن تصل إلى الخرج النصّي العادي، أو خرج <bdi>JSON</bdi>، أو السجلات، أو
مقتطفات الوثائق، أو الاختبارات. وتستخدم الأمثلة العامة هويات ونطاقات نائبة زائفة.

## إثباتات الإصدار لسلسلة التوريد

يُشحَن كل مُنتَج إصدار مع:

- **إثبات منشأ البناء <bdi>SLSA-3</bdi>** عبر [<bdi>`slsa-framework/slsa-github-generator`</bdi>](https://github.com/slsa-framework/slsa-github-generator)
- **تواقيع <bdi>Sigstore</bdi>** عبر [<bdi>`sigstore/cosign-installer`</bdi>](https://github.com/sigstore/cosign-installer)
- **<bdi>CycloneDX SBOM</bdi>** للـ <bdi>wheel</bdi> والـ <bdi>sdist</bdi> المشحونين، يكتبه <bdi>`scripts/release/generate_sbom.py`</bdi>: حزمة <bdi>apothem</bdi>، وكل حزمة مُضمَّنة تحت <bdi>`apothem/_vendor`</bdi> مع رخصتها، ومتطلّبات بيئة التشغيل المُعلَنة، وقيمة <bdi>SHA-256</bdi> لكل توزيعة. الـ <bdi>SBOM</bdi> موقَّع ومشمول بإثبات منشأ البناء مثل التوزيعات
- **بيانات إثبات المنشأ في <bdi>npm</bdi>** عبر <bdi>Trusted Publishing OIDC</bdi> على <bdi>`@ahmed-g-gad/apothem`</bdi>
- **وسوم <bdi>git</bdi> موقَّعة بـ <bdi>GPG</bdi>** (مفتاح <bdi>EDDSA</bdi> <bdi>`70396FED9C634163`</bdi>)

## التحقّق من إصدار

نزِّل كل أصول إصدارٍ ما إلى دليل فارغ، ثم افحص التواقيع وإثبات منشأ البناء. استبدل
<bdi>`vX.Y.Z`</bdi> و<bdi>`X.Y.Z`</bdi> بالإصدار الذي نزّلته.

```bash
gh release download vX.Y.Z --repo ahmed-g-gad/apothem
cosign verify-blob \
  --bundle apothem-X.Y.Z-py3-none-any.whl.cosign.bundle \
  --certificate-identity https://github.com/Ahmed-G-Gad/apothem/.github/workflows/release.yml@refs/tags/vX.Y.Z \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  apothem-X.Y.Z-py3-none-any.whl
slsa-verifier verify-artifact \
  --provenance-path provenance.intoto.jsonl \
  --source-uri github.com/Ahmed-G-Gad/apothem \
  --source-tag vX.Y.Z \
  apothem-X.Y.Z-py3-none-any.whl apothem-X.Y.Z.tar.gz
```

يطبع <bdi>`cosign`</bdi> النص <bdi>`Verified OK`</bdi>، ويطبع <bdi>`slsa-verifier`</bdi>
النص <bdi>`PASSED: SLSA verification passed`</bdi>. كرّر أمر <bdi>`cosign`</bdi> لأي
أصل آخر مع ملف <bdi>`<asset>.cosign.bundle`</bdi> الخاص به (تُسمّي الإصدارات السابقة
حِزم أرشيفات المنصّات و<bdi>`SHA256SUMS`</bdi> بالاسم <bdi>`<asset>.sig`</bdi>).
أرشيفا <bdi>darwin</bdi> و<bdi>linux</bdi> هما البايتات نفسها تحت اسمين، لذا يسرد
<bdi>`SHA256SUMS`</bdi> بصمةً واحدة مرّتين. ومن نسخة مُستنسَخة من المستودع، يُشغِّل
<bdi>`bash scripts/release/verify-provenance.sh <download-dir>`</bdi> الفحوص الثلاثة
كلها، بما فيها بيان <bdi>`SHA256SUMS`</bdi>، في تمريرة واحدة.

تفصيلان يحدّدان ما إذا كان للتحقّق أي معنى:

- **حالة أحرف اسم المالك.** فحوص الهوية حسّاسة لحالة الأحرف، وتحمل الشهادات اسم
  المالك كما يُبلغ عنه <bdi>GitHub</bdi>: <bdi>`Ahmed-G-Gad`</bdi>. يفشل اسم المالك
  المكتوب بأحرف صغيرة في الأداتين كلتيهما.
- **الهوية الدقيقة.** فضِّل <bdi>`--certificate-identity`</bdi> مع الموضوع الكامل
  أعلاه. ولقبول أي وسم إصدار، اربط النمط بمرساة عند طرفيه كليهما:

  ```bash
  --certificate-identity-regexp '^https://github\.com/Ahmed-G-Gad/apothem/\.github/workflows/release\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+$'
  ```

  النمط غير المربوط بمرساة، مثل <bdi>`github.com/Ahmed-G-Gad/apothem`</bdi>، يطابق
  أيضًا موضوعًا مُزوَّرًا لا يفعل سوى احتواء ذلك النص، على سبيل المثال سير عمل في
  مستودع آخر على فرع مُسمّى باسم هذا المستودع.

يُسجّل [دليل تشغيل دورة الإصدار](/docs/runbooks/release-cycle) الأوامر نفسها بوصفها
فحص المشرف بعد الإصدار.

### إعادة بناء إصدار ومقارنته

الـ <bdi>wheel</bdi> والـ <bdi>sdist</bdi> قابلان لإعادة الإنتاج: إعادة بناء الوسم
بسلسلة أدوات الإصدار تُعطي بصمات <bdi>SHA-256</bdi> المنشورة. استخدم
<bdi>Python 3.12</bdi> على <bdi>Linux</bdi>، كما يفعل الإصدار:

```bash
git clone https://github.com/ahmed-g-gad/apothem && cd apothem
git checkout vX.Y.Z
python3.12 -m venv .build && . .build/bin/activate
pip install --require-hashes -r scripts/release/requirements-build-linux.txt
export SOURCE_DATE_EPOCH="$(git log -1 --pretty=%ct)"
python -m build --no-isolation
python scripts/release/normalize_sdist.py dist/*.tar.gz
sha256sum dist/*
```

قارِن البصمات بالـ <bdi>wheel</bdi> والـ <bdi>sdist</bdi> المنشورين. يستخدم البناء
<bdi>setuptools</bdi> المقفولة بالبصمات التي يُحدِّد <bdi>`pyproject.toml`</bdi>
نسختها بدقّة، ويُزيل <bdi>`normalize_sdist.py`</bdi> وقت البناء ومالكي الملفات
والطوابع الزمنية للنسخة المسحوبة من الـ <bdi>sdist</bdi>.
