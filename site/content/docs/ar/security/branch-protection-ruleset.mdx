فرع <bdi>`main`</bdi> في <bdi>Apothem</bdi> محميّ بقاعدة حماية فرع كلاسيكية في <bdi>GitHub</bdi>. لا توجد في المستودع أي مجموعات قواعد. تفرض الحماية انضباط مجموعة التغييرات المُعلَن في <bdi>`rules/production-ready-prs.md`</bdi> وتُغذّي فحصَي **<bdi>Branch-Protection</bdi>** و**<bdi>Code-Review</bdi>** في <bdi>OpenSSF Scorecard</bdi>.

تُسجّل هذه الصفحة الإعدادات الفعّالة بدقّة، كما قُرئت آخر مرة من واجهة برمجة تطبيقات <bdi>GitHub</bdi> في 2026-10-07. أي إعداد ينويه المشرف لكنه لم يُطبّقه بعد لا يظهر إلا تحت [تغييرات المشرف المعلّقة](#تغييرات-المشرف-المعلّقة).

## إعدادات الحماية

| الإعداد | حقل الواجهة البرمجية | القيمة الفعّالة | الأثر |
|---|---|---|---|
| **اشتراط طلب سحب قبل الدمج** | <bdi>`required_pull_request_reviews`</bdi> (موجود) | ✅ | تصل التغييرات إلى <bdi>`main`</bdi> عبر طلب سحب. |
| **المراجعات الموافِقة المطلوبة** | <bdi>`required_approving_review_count`</bdi> | **0** | يُدمَج طلب السحب دون مراجعة موافِقة. راجع [نموذج المشرف المنفرد](#نموذج-المشرف-المنفرد). |
| **إسقاط الموافقات القديمة عند الكوميتات الجديدة** | <bdi>`dismiss_stale_reviews`</bdi> | ✅ | لا تُحتسَب الموافقة الممنوحة قبل دفع جديد. |
| **اشتراط مراجعة من <bdi>Code Owners</bdi>** | <bdi>`require_code_owner_reviews`</bdi> | ❌ | تفعيل هذا قبل انضمام مشرف ثانٍ يُوقِع طلبات سحب المشرف المنفرد في انسداد. |
| **اشتراط الموافقة على أحدث دفع قابل للمراجعة** | <bdi>`require_last_push_approval`</bdi> | ❌ | يشترط <bdi>GitHub</bdi> أن تأتي تلك الموافقة من شخص غير الذي أجرى الدفع، وهو ما لا يستطيع المشرف المنفرد توفيره. |
| **اشتراط نجاح فحوص الحالة** | <bdi>`required_status_checks`</bdi> | ✅ | يجب أن تنجح السياقات الـ 12 المسرودة تحت [فحوص الحالة المطلوبة](#فحوص-الحالة-المطلوبة). |
| **اشتراط أن تكون الفروع مُحدَّثة قبل الدمج** | <bdi>`required_status_checks.strict`</bdi> | ❌ | يمكن دمج طلب سحب عندما تكون فحوصه المطلوبة قد نجحت مقابل <bdi>`main`</bdi> أقدم. ثم تختبر سِيَر العمل التي تعمل عند الدفع إلى <bdi>`main`</bdi> النتيجةَ المدموجة. |
| **اشتراط حلّ المحادثات قبل الدمج** | <bdi>`required_conversation_resolution`</bdi> | ✅ | تحجب خيوط المراجعة المفتوحة الدمج. |
| **اشتراط كوميتات موقَّعة** | <bdi>`required_signatures`</bdi> | ❌ | تُوقَّع كوميتات الإصدار محليًا. ينتظر الفرض حتى توثّق وثائق انضمام المساهمين إعداد التوقيع عبر <bdi>SSH</bdi> أو <bdi>GPG</bdi>. |
| **اشتراط تاريخ خطّي** | <bdi>`required_linear_history`</bdi> | ✅ | يُبقي التاريخ العام لـ <bdi>`main`</bdi> خطًّا واحدًا. |
| **قفل الفرع** | <bdi>`lock_branch`</bdi> | ❌ | يقبل <bdi>`main`</bdi> عمليات الدمج. |
| **عدم السماح بتجاوز الإعدادات أعلاه** | <bdi>`enforce_admins`</bdi> | ❌ | لا تُلزِم الإعدادات أعلاه مسؤول المستودع. يستطيع المسؤول الدمج دون الفحوص المطلوبة أو الدفع إلى <bdi>`main`</bdi> مباشرةً. |
| **السماح بالدفع بالقوة** | <bdi>`allow_force_pushes`</bdi> | ❌ | الدفع بالقوة إلى <bdi>`main`</bdi> محظور على الجميع، بمن فيهم المسؤولون. |
| **السماح بالحذف** | <bdi>`allow_deletions`</bdi> | ❌ | لا يستطيع أحد حذف <bdi>`main`</bdi>، بمن فيهم المسؤولون. |

## نموذج المشرف المنفرد

للمستودع مشرف واحد. ينصّ <bdi>GitHub</bdi> على ما يلي: «لا يستطيع مؤلّفو طلبات السحب الموافقة على طلبات السحب الخاصة بهم.» لذلك فإن أي عدد موافقات مطلوب يزيد على 0 سيحجب كل طلب سحب من المشرف. تشترط القاعدة الفعّالة طلب سحب مع 0 موافقات وتترك <bdi>`enforce_admins`</bdi> مُعطَّلًا.

بالنسبة لأي شخص لا يملك صلاحية المسؤول، لا يزال الدمج يتطلّب أن تكون فحوص الحالة المطلوبة خضراء، وأن تكون محادثات المراجعة محلولة، وأن يكون التاريخ خطّيًا. ويبقى الدفع بالقوة وحذف <bdi>`main`</bdi> محظورَين على كل حساب.

عندما ينضمّ مشرف ثانٍ، تكون الإعدادات الأقوى: موافقة مطلوبة واحدة على الأقل، والموافقة على أحدث دفع، ومراجعة <bdi>CODEOWNERS</bdi>، وتفعيل <bdi>`enforce_admins`</bdi>. ولا تنطبق [مراسم دمج المشرف المنفرد](/docs/runbooks/solo-maintainer-merge) إلا على حماية تشترط موافقةً وتفرضها على المسؤولين.

## فحوص الحالة المطلوبة

كلٌّ من هذه السياقات الـ 12 مطلوب، ومصدره <bdi>GitHub Actions</bdi> (مُعرِّف التطبيق <bdi>`15368`</bdi>):

```text
quality / ubuntu-latest / py3.10
quality / ubuntu-latest / py3.11
quality / ubuntu-latest / py3.12
quality / ubuntu-latest / py3.13
quality / ubuntu-latest / py3.14
quality / windows-latest / py3.10
quality / windows-latest / py3.11
quality / windows-latest / py3.12
quality / windows-latest / py3.13
quality / windows-latest / py3.14
coverage
Require Signed-off-by
```

| السياق | سير العمل والمهمة | كيف يُبلِغ عن حالته في كل طلب سحب |
|---|---|---|
| <bdi>`quality / <os> / py<ver>`</bdi> (10) | <bdi>`ci.yml`</bdi>، المهمة <bdi>`quality`</bdi> | يعمل <bdi>`ci.yml`</bdi> عندما يمسّ طلب السحب مسار شيفرة أو إعدادات. ويُبلِغ <bdi>`ci-docs-stub.yml`</bdi> عن السياقات نفسها في طلب سحب يقتصر على الوثائق. |
| <bdi>`coverage`</bdi> | <bdi>`ci.yml`</bdi>، المهمة <bdi>`coverage`</bdi> | مثل <bdi>`quality`</bdi>. |
| <bdi>`Require Signed-off-by`</bdi> | <bdi>`dco.yml`</bdi>، المهمة <bdi>`dco`</bdi> | لا يحمل مُشغِّل طلبات السحب الخاص به مُرشِّح <bdi>`paths`</bdi>، لذا يعمل على كل طلب سحب إلى <bdi>`main`</bdi>. |

تعمل خلية الإصدار التمهيدي <bdi>`quality / ubuntu-latest / py3.15`</bdi> في <bdi>`ci.yml`</bdi> مع <bdi>`continue-on-error`</bdi> وهي غير مطلوبة. ويجوز لأي سير عمل آخر، بما في ذلك <bdi>CodeQL</bdi> و<bdi>Scorecard</bdi> و<bdi>pip-audit</bdi>، أن يُبلِغ عن حالة، لكن نتيجته لا تكون شرطًا للدمج ما لم يُضَف سياقه إلى هذه القائمة.

## تغييرات المشرف المعلّقة

ينوي المشرف إضافة هذه السياقات الـ 25 إلى القائمة المطلوبة. تُعلِن ترويسة كل سير عمل أن المهمة فحصٌ مطلوب، ولا يحمل مُشغِّل طلبات السحب الخاص به مُرشِّح <bdi>`paths`</bdi>، لذا يعمل على كل طلب سحب إلى <bdi>`main`</bdi>. وإلى أن يُضاف سياقٌ ما، لا يحجب الفشلُ فيه الدمج.

<bdi>`clean-install-gate.yml`</bdi>، 7 سياقات:

```text
installer-shell-compat / ubuntu-latest
installer-shell-compat / macos-latest
installer-shell-compat / windows-latest
clean-install-gate / ubuntu-latest
clean-install-gate / windows-latest
wheel-smoke / ubuntu-latest
wheel-smoke / windows-latest
```

<bdi>`harness-matrix.yml`</bdi>، 17 سياقًا، سياق <bdi>`matrix (<adapter>)`</bdi> واحد لكل محوّل في مصفوفة المهمة:

```text
matrix (antigravity)
matrix (claude-code)
matrix (codebuddy)
matrix (codex)
matrix (cursor)
matrix (gemini-cli)
matrix (github-copilot)
matrix (glm)
matrix (hermes)
matrix (kimi-code)
matrix (kiro)
matrix (open-claw)
matrix (opencode)
matrix (qwen-code)
matrix (trae)
matrix (windsurf)
matrix (zed)
```

<bdi>`installer-lint.yml`</bdi>، سياق واحد:

```text
installer-lint
```

بمجرد أن تصبح سياقات <bdi>`harness-matrix.yml`</bdi> مطلوبة، يضيف تسجيل محوّل جديد سياق <bdi>`matrix (<adapter>)`</bdi>، وتكتسبه القائمة المطلوبة في التغيير نفسه. ويبقى الإعداد «اشتراط أن تكون الفروع مُحدَّثة قبل الدمج» مُعطَّلًا. وعند تطبيق تغيير معلّق، انقله إلى الأقسام الفعّالة أعلاه في التغيير نفسه.

## وتيرة التدقيق

يُراجَع هذا الملف في كل تدقيق أمني وعند كل نقطة تفتيش لهندسة الإصدار. الانحراف بين هذا الملف والتهيئة الفعلية لحماية الفرع اكتشافٌ عالي الخطورة. اقرأ التهيئة الفعّالة باستخدام:

```bash
gh api repos/ahmed-g-gad/apothem/branches/main/protection
gh api repos/ahmed-g-gad/apothem/rulesets
```
