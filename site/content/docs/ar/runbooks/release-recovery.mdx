يعيد دليل التشغيل هذا <bdi>`ahmed-g-gad/apothem`</bdi> إلى حالة عاملة عندما يفشل
تسلسل إصدار من نوع التطهير الكامل في المكان في منتصف الطريق. لا يُحذف المستودع
العام ولا يُعاد إنشاؤه أثناء الإصدار. يعتمد الاسترداد على وسم أمان التاريخ
الخاص بالإصدار، والنسخة المحلية للمشرف، وحالة مدير الحِزَم في المراحل اللاحقة.

## 1. تصنيف المراحل

| المرحلة | الإجراء | وضع الفشل | مسار الاسترداد |
|---|---|---|---|
| 1 | التقاط وسم أمان التاريخ ودفعه | الوسم مفقود، أو غير موقَّع، أو يشير إلى الرسم البياني الخطأ | أعد إنشاء الوسم من نقطة الدمج قبل السحق قبل تحريك <bdi>`main`</bdi> |
| 2 | التحقق من <bdi>CI</bdi> وقلعة التدقيق وحالة الحِزَم وسجل التغييرات | فشل أيّ بوابة | توقَّف؛ أصلِح محليًا؛ لا تُحرِّك <bdi>`main`</bdi> |
| 3 | تحريك <bdi>`main`</bdi> إلى كوميت الإصدار الموقَّع الواحد | فشل <bdi>force-with-lease</bdi>، أو الكوميت غير موقَّع، أو رسالة الكوميت خاطئة | أعِد ضبط <bdi>`main`</bdi> المحلي إلى الكوميت الموقَّع المقصود وأعِد المحاولة بِـ<bdi>lease</bdi> جديد |
| 4 | نشر إصدار <bdi>GitHub</bdi> و<bdi>Pages</bdi> و<bdi>npm</bdi> والبيانات الوصفية | فشل ناشر أو سطح تحقُّق | احتفظ بكوميت الإصدار؛ أعِد تشغيل الناشر الفاشل وحده بعد تسجيل الفشل |

كل إجراء استرداد عديم الأثر (idempotent). تشغيله على حالة نظيفة لا يفعل شيئًا؛
وتشغيله على حالة جزئية يعيد الشرط المتوقَّع لما بعد المرحلة.

## 2. استرداد وسم الأمان

تحقَّق من وسم الأمان قبل أيّ إعادة كتابة للتاريخ:

```bash
git fetch origin --tags
git show --summary --show-signature <history-safety-tag>
git merge-base --is-ancestor origin/main <history-safety-tag>
```

المتوقَّع: الوسم موجود، ويَنجح التحقُّق من التوقيع عندما يكون الوسم موقَّعًا،
ويمكن الوصول إلى الرسم البياني الكامل قبل السحق من الوسم. إذا كان الوسم مفقودًا
محليًا لكنه موجود عن بُعد، فاجلِبه. وإذا كان مفقودًا عن بُعد، فأوقِف الإصدار
وأعِد إنشاءه قبل لمس <bdi>`main`</bdi>:

```bash
git tag -s <history-safety-tag> <pre-squash-commit>
git push origin <history-safety-tag>
```

## 3. استرداد الفرع الرئيسي

شخِّص حالة <bdi>`main`</bdi> العامة:

```bash
gh api repos/ahmed-g-gad/apothem/commits/main \
  --jq '.sha, .commit.message, .commit.verification.verified, .commit.verification.reason'
```

المتوقَّع بعد التبديل: الرسالة هي بالضبط
<bdi>`release: Apothem <release-version>`</bdi> و<bdi>`verification.verified`</bdi>
هي <bdi>`true`</bdi>.

إذا فشل دفع <bdi>force-with-lease</bdi> قبل تغيير <bdi>GitHub</bdi>، فاترك
المستودع البعيد كما هو، واجلِبه، وأعِد بناء كوميت الإصدار الموقَّع محليًا، ولا
تُعِد المحاولة إلا بعد أن يتطابق الـ<bdi>lease</bdi>:

```bash
git fetch origin main
git push --force-with-lease=main:<expected-remote-sha> origin main
```

إذا هبط الدفع بكوميت غير موقَّع أو غير مُتحقَّق منه، فأصلِح إعداد التوقيع
المحلي، وأعِد إنشاء كوميت الإصدار من الشجرة نفسها، وادفع بالقوة مرة أخرى
بِـ<bdi>lease</bdi>. لا تحذف وسم الأمان.

## 4. استرداد الناشرين

يُعاد تشغيل كل ناشر بشكل مستقل بعد التحقُّق من كوميت إصدار <bdi>GitHub</bdi>:

| السطح | التشخيص | الاسترداد |
|---|---|---|
| إصدار <bdi>GitHub</bdi> | <bdi>`gh release view <release-tag> --json tagName,isDraft,isPrerelease,assets`</bdi> | احذف فقط المسودّة المُشوَّهة؛ وإلا فارفع الأصول المفقودة بِـ<bdi>`gh release upload --clobber`</bdi> |
| وسم الإصدار | <bdi>`git ls-remote origin refs/tags/<release-tag>`</bdi> و<bdi>`git tag -v <release-tag>`</bdi> | أعِد الوسم من نفس الـ<bdi>SHA</bdi> بِـ<bdi>`-a -s`</bdi> إذا كان الوسم مفقودًا أو غير موقَّع؛ ولا تُعِد أبدًا استخدام اسم وسم لكوميت مختلف |
| <bdi>npm</bdi> | <bdi>`npm view @ahmed-g-gad/apothem version`</bdi> و<bdi>`npx @ahmed-g-gad/apothem@<version> --version`</bdi> | أعِد تشغيل <bdi>`publish-npm.yml`</bdi> لِـ<bdi>`<release-tag>`</bdi> بعد تأكيد <bdi>npm Trusted Publishing</bdi> لِـ<bdi>`@ahmed-g-gad/apothem`</bdi> |
| <bdi>Pages</bdi> | <bdi>`gh run list --workflow=publish-static-site.yml --limit=1`</bdi> و<bdi>`curl -sSI https://apothem.ahmedgad.com/`</bdi> | أعِد تشغيل <bdi>`publish-static-site.yml`</bdi>؛ وتحقَّق من أن الـ<bdi>CNAME</bdi> لا يزال يُحَلّ إلى <bdi>`ahmed-g-gad.github.io`</bdi> |
| البيانات الوصفية لـ<bdi>GitHub</bdi> | <bdi>`gh repo view ahmed-g-gad/apothem --json description,homepageUrl,repositoryTopics,visibility`</bdi> | رقِّع الوصف والصفحة الرئيسية والمواضيع في المكان؛ لا تُعِد إنشاء المستودع |

## 5. التراجع

التراجع هو الملاذ الأخير. فضِّل استرداد الناشرين الموجَّه أولًا. إذا تعيَّن
التراجع عن كوميت الإصدار الواحد، فاستعِد <bdi>`main`</bdi> من وسم الأمان:

```bash
git fetch origin --tags
git switch main
git reset --hard <history-safety-tag>
git push --force-with-lease origin main
```

بعد التراجع، أعِد تشغيل <bdi>CI</bdi>، وأعِد تطبيق حماية الفرع إذا أبلغ
<bdi>GitHub</bdi> عن انحراف، وسجِّل التراجع بوصفه حادثًا يحجب الإصدار. احتفظ بوسم
الإصدار فقط إذا ظلَّت مُخرَجات الإصدار صالحة؛ وإلا فاحذف الإصدار والوسم
المُشوَّهين قبل إعادة المحاولة.
