يستعيد دليل التشغيل هذا حالةً عاملة عندما يفشل إصدار <bdi>`vX.Y.Z`</bdi> من
<bdi>`ahmed-g-gad/apothem`</bdi> في منتصف الطريق. ويتبع نموذج الإصدار نفسه الذي
يتبعه [دليل تشغيل دورة الإصدار](/docs/runbooks/release-cycle): نموذجًا **تراكميًا**.
يضيف كل إصدار كوميتًا واحدًا على <bdi>`main`</bdi> ووسمًا واحدًا موقَّعًا ومُعلَّقًا؛
ويُشغِّل دفعُ الوسم سيرَي عمل الإصدار و<bdi>npm</bdi>. لا يُدفَع أي شيء بالقوة،
ولا يُعاد أبدًا كتابة التاريخ على <bdi>`main`</bdi>.

التاريخ المنشور دائم. يبقى منشورًا كلُّ وسم إصدار، وكلُّ إصدار <bdi>GitHub</bdi>،
وكلُّ نسخة <bdi>npm</bdi> نشرها المشروع: للمشروع ثلاثة إصدارات، لكلٍّ منها وسمه
وإصدار <bdi>GitHub</bdi> الخاص به ونسخة <bdi>npm</bdi> الخاصة به. نسخ <bdi>npm</bdi>
غير قابلة للتغيير: لا يمكن أبدًا استبدال <bdi>`name@version`</bdi> منشور، ولا يمكن
أبدًا استخدام رقم نسخة أُلغي نشره مرة أخرى. لذلك يمضي الاسترداد إلى الأمام بإصدار
تصحيحي جديد؛ فهو لا يحذف ولا يُعيد توجيه أي شيء ربما يكون المستخدم قد ثبّته بالفعل.

## 1. تصنيف المراحل

| المرحلة | الإجراء | نمط الفشل | مسار الاسترداد |
|---|---|---|---|
| 1 | إنزال كوميت الإصدار على <bdi>`main`</bdi> (القسم 2.1 من دليل تشغيل دورة الإصدار) | يفشل <bdi>CI</bdi> على كوميت الإصدار | أصلِح إلى الأمام بكوميت آخر على <bdi>`main`</bdi>؛ لا تضع الوسم حتى يصبح <bdi>CI</bdi> أخضر |
| 2 | دفع الوسم الموقَّع والمُعلَّق | يُرفَض الدفع، أو يكون الوسم غير موقَّع أو على الكوميت الخطأ | القسم 2 أدناه |
| 3 | يبني <bdi>`release.yml`</bdi> إصدار <bdi>GitHub</bdi> ويوقّعه وينشره | تفشل إحدى المهام، أو تكون الأصول مفقودة | القسم 3 أدناه |
| 4 | ينشر <bdi>`publish-npm.yml`</bdi> الحزمة <bdi>`@ahmed-g-gad/apothem`</bdi> (ويعمل على دفع الوسم نفسه) | يفشل النشر | القسم 3 أدناه |
| 5 | <bdi>Pages</bdi> والبيانات الوصفية للمستودع | الموقع أو البيانات الوصفية قديمة | القسم 3 أدناه |

كل إجراء استرداد متماثل الأثر عند تكراره. تشغيله على حالة نظيفة لا يفعل شيئًا؛
وتشغيله على حالة جزئية يستعيد الحالة المتوقَّعة لما بعد المرحلة.

## 2. استرداد الوسم

شخِّص الوسم:

```bash
git fetch origin --tags
git ls-remote origin refs/tags/vX.Y.Z
git cat-file -t vX.Y.Z      # "tag" for an annotated tag
git tag -v vX.Y.Z           # signature check
```

يتوقف ما تفعله على ما إذا كان أي شيء قد نُشِر من الوسم:

- **لم يُنشَر شيء بعد** (فشل سير عمل الإصدار قبل مهمة النشر الخاصة به، ولم ينشر
  <bdi>`publish-npm.yml`</bdi> شيئًا): احذف الوسم وأعِد وضع الوسم على الكوميت نفسه
  باستخدام <bdi>`-a -s`</bdi>.

  ```bash
  git push --delete origin vX.Y.Z
  git tag -d vX.Y.Z
  git tag -a -s vX.Y.Z -m "vX.Y.Z" <release-commit-sha>
  git push origin vX.Y.Z
  ```

- **نُشِر أي شيء** (إصدار <bdi>GitHub</bdi> بأصول، أو نسخة <bdi>npm</bdi>):
  لا تنقل الوسم أبدًا، ولا تحذفه، ولا تُعِد استخدامه. أصلِح إلى الأمام بـ
  <bdi>`vX.Y.(Z+1)`</bdi>.

لا يُعاد أبدًا استخدام اسم وسم لكوميت مختلف.

## 3. استرداد الناشرين

يُعاد تشغيل كل ناشر بمفرده:

| السطح | التشخيص | الاسترداد |
|---|---|---|
| سير عمل الإصدار | يُسمّي <bdi>`gh run view <run-id> --log`</bdi> المهمة الفاشلة | <bdi>`gh run rerun <run-id> --failed`</bdi>. يعني الفشل عند <bdi>`Check the plugin version changed with the plugin`</bdi> أن رقم النسخة لم يُرفَع: راجع جدول حالات الفشل في دليل تشغيل دورة الإصدار |
| إصدار <bdi>GitHub</bdi> | <bdi>`gh release view vX.Y.Z --json tagName,isDraft,isPrerelease,assets`</bdi> | أعِد تشغيل مهمة <bdi>`publish GitHub Release`</bdi>؛ فهي تُعدِّل الإصدار الموجود وتُعيد رفع الأصول باستخدام <bdi>`--clobber`</bdi> |
| <bdi>npm</bdi> | <bdi>`npm view @ahmed-g-gad/apothem version`</bdi> و<bdi>`npx @ahmed-g-gad/apothem@X.Y.Z --version`</bdi> | أعِد تشغيل <bdi>`publish-npm.yml`</bdi> لـ <bdi>`vX.Y.Z`</bdi> (<bdi>`gh workflow run publish-npm.yml --field tag=vX.Y.Z`</bdi>) بعد التأكد من تفعيل النشر الموثوق في <bdi>npm</bdi> للحزمة. إذا كانت النسخة موجودة بالفعل في السجلّ، يتخطّى سير العمل النشر، لأن نسخ <bdi>npm</bdi> غير قابلة للتغيير |
| <bdi>Pages</bdi> | <bdi>`gh run list --workflow=publish-static-site.yml --limit=1`</bdi> و<bdi>`curl -sSI https://apothem.ahmedgad.com/`</bdi> | أعِد تشغيل <bdi>`publish-static-site.yml`</bdi>؛ وتحقّق من أن سجلّ <bdi>CNAME</bdi> لا يزال يُحَلّ إلى <bdi>`ahmed-g-gad.github.io`</bdi> |
| البيانات الوصفية للمستودع | <bdi>`gh repo view ahmed-g-gad/apothem --json description,homepageUrl,repositoryTopics,visibility`</bdi> | رقِّع الوصف والصفحة الرئيسية والمواضيع في مكانها؛ لا تُعِد إنشاء المستودع أبدًا |

## 4. التراجع

يُتراجَع عن الإصدار المعيب بإصدار إصلاحه، لا بإزالته:

1. اعكِس الكوميتات المُسبِّبة للخلل على <bdi>`main`</bdi> (كوميت عكس عادي).
2. أصدِر <bdi>`vX.Y.(Z+1)`</bdi> باتباع دليل تشغيل دورة الإصدار.
3. علِّم النسخة المعيبة: أضِف ملاحظة <bdi>`### Yanked`</bdi> إلى قسمها في
   <bdi>`CHANGELOG.md`</bdi>، وعدِّل ملاحظات إصدار <bdi>GitHub</bdi> الخاص بها لتشير
   إلى الإصلاح، وأعلِن إهمالها على <bdi>npm</bdi>:

   ```bash
   npm deprecate @ahmed-g-gad/apothem@X.Y.Z "Contains <defect>; use X.Y.(Z+1)"
   ```

يبقى الوسم المعيب وإصدار <bdi>GitHub</bdi> ونسخة <bdi>npm</bdi> منشورة، بحيث تظل
عمليات التثبيت المقيّدة بنسخة محدّدة وعمليات البناء القابلة لإعادة الإنتاج قابلةً
للحلّ. سجِّل التراجع بوصفه حادثة إصدار.

## 5. قاعدة واجهة الإصدار

تطلب قاعدة واجهة الإصدار في المستودع (قسم <bdi>Release Facade</bdi> في تعليمات
المساهمين) وسم إصدار مرئيًا واحدًا وإصدار <bdi>GitHub</bdi> واحدًا. أمّا الممارسة
فتحتفظ بكل إصدار، ولا يستطيع <bdi>npm</bdi> الامتثال: فنسخه غير قابلة للتغيير. وإلى
أن يحسم المشرف تلك القاعدة، يتبع دليل التشغيل هذا النموذج التراكمي أعلاه، ولا يحذف
أبدًا الوسوم المنشورة أو إصدارات <bdi>GitHub</bdi> أو نسخ <bdi>npm</bdi> ولا يعيد
كتابتها للوفاء بها.
