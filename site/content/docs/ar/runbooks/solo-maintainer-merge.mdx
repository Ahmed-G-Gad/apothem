> **المرجع المعياري لدمج طلبات السحب ذاتيًا في ظل حماية الفرع الخاصة بالمشروع.** تشترط الحماية الفعّالة على <bdi>`main`</bdi> 0 مراجعات موافِقة وتترك <bdi>`enforce_admins`</bdi> مُعطَّلًا، كما هو مُسجَّل في صفحة [حماية الفرع](/docs/security/branch-protection-ruleset). لذلك يدمج المشرف طلب السحب الخاص به مباشرةً. ولا تنطبق مراسم التبديل المؤقت الواردة في هذه الصفحة إلا عندما تشترط الحماية موافقةً وتفرضها على المسؤولين.

---

## 1. الانسداد

تحمل حماية <bdi>`main`</bdi> الفعّالة ما يلي:

- <bdi>`required_pull_request_reviews.required_approving_review_count: 0`</bdi>
- <bdi>`enforce_admins: false`</bdi>

في ظل هذه الإعدادات لا يوجد انسداد. يُدمَج طلب سحب المشرف باستخدام <bdi>`gh pr merge <pr-number> --squash --delete-branch`</bdi> متى أصبحت فحوص الحالة المطلوبة الخاصة به خضراء وحُلَّت محادثات المراجعة الخاصة به.

لا يوجد انسداد إلا عندما تحمل الحماية كلا هذين الإعدادين الأكثر صرامة:

- <bdi>`required_pull_request_reviews.required_approving_review_count: 1`</bdi>
- <bdi>`enforce_admins: true`</bdi>

هذه القواعد صحيحة لسيناريوهات تعدّد المشرفين (كل تغيير يصل إلى <bdi>`main`</bdi> عبر طلب سحب راجعه قرين؛ والمسؤولون غير مُعفَين). لكنها تُنتِج انسدادًا للمشرفين المنفردين: تمنع سياسة <bdi>GitHub</bdi> الموافقة الذاتية على طلب سحب أنشأته بنفسك، ويمنع <bdi>`enforce_admins=true`</bdi> تجاوز <bdi>`gh pr merge --admin`</bdi> لمتطلّب الموافقة على المراجعة. ومع <bdi>`enforce_admins: false`</bdi>، يتجاوز <bdi>`--admin`</bdi> متطلّب الموافقة ولا حاجة إلى أي تبديل، لكنه يتجاوز أيضًا الفحوص المطلوبة الحمراء، لذا تأكّد من أنها خضراء قبل استخدامه.

توجد ثلاثة مسارات للحلّ:

| المسار | متى يُستخدَم |
|------|-------------|
| تعيين <bdi>`required_approving_review_count: 0`</bdi> بشكل دائم (**الإعداد الفعّال**) | اعتمِده فقط إذا كان المستودع سيبقى بمشرف منفرد إلى أجل غير مسمّى؛ فهو ينقض نية المراجعة في الحماية |
| **مراسم التبديل المؤقت** | للدمج الذاتي من المشرف المنفرد بينما تشترط الحماية موافقةً مع <bdi>`enforce_admins=true`</bdi>؛ تحافظ على ثابت الحماية خارج نافذة الدمج |
| توفير هوية روبوت <bdi>CI</bdi> بصلاحية كتابة | اعتمِده فقط إذا كان انضمام عدة مشرفين وشيكًا؛ فموافقة الروبوت تُقوّض نية المراجعة البشرية في الحماية |

يستخدم هذا المستودع حاليًا مسار **الموافقة الصفرية الدائمة**. و**مراسم التبديل المؤقت** هي المسار المعياري متى اشترطت الحماية موافقةً وفرضتها على المسؤولين.

## 2. مراسم التبديل المؤقت

ثابت المراسم: حالة الحماية في بداية المراسم تساوي حالة الحماية في نهايتها. ولا يعيش التخفيف إلا داخل نافذة الدمج.

الصيغة اليدوية:

```bash
# 1. Open the PR, push branch, wait for CI green.
gh pr create --base main --head <feature-branch> --title "..." --body "..."
gh pr checks <pr-number>            # poll until all green

# 2. Relax approver-count to 0.
gh api repos/<owner>/<repo>/branches/main/protection/required_pull_request_reviews \
    -X PATCH -F required_approving_review_count=0

# 3. Squash-merge with admin override (admin override now succeeds because the
#    review-approval requirement is the only block enforce_admins refuses).
gh pr merge <pr-number> --squash --delete-branch --admin

# 4. Restore approver-count to 1.
gh api repos/<owner>/<repo>/branches/main/protection/required_pull_request_reviews \
    -X PATCH -F required_approving_review_count=1
```

الصيغة المُغلَّفة: راجِع [<bdi>`scripts/dev/admin_merge.py`</bdi>](https://github.com/ahmed-g-gad/apothem/blob/main/scripts/dev/admin_merge.py) للاطّلاع على غلاف <bdi>Python</bdi> الذرّي الذي ينفّذ الخطوات 2 ← 3 ← 4 في تسلسل واحد غير تفاعلي مع أمان التراجع عبر <bdi>`try`</bdi> / <bdi>`finally`</bdi> عند فشل الخطوة 3.

```bash
python scripts/dev/admin_merge.py <pr-number>
```

## 3. الثوابت

- **تقليص نافذة التبديل إلى أدنى حدّ.** تُنفَّذ الخطوات 2 ← 3 ← 4 في تسلسل واحد غير تفاعلي. لا تكون الحماية في حالتها المُخفَّفة إلا طوال مدة استدعاء واجهة برمجة تطبيقات الدمج — أقل من ثانية واحدة في كل تشغيل مُلاحَظ.
- **الاستعادة غير مشروطة.** تُنفَّذ الخطوة 4 حتى عند فشل الخطوة 3 (تضمن عبارة <bdi>`try`</bdi> / <bdi>`finally`</bdi> في الغلاف الاستعادة في أي مسار خروج). ولا تترك محاولة دمج فاشلة الحماية مُخفَّفة.
- **بوابة <bdi>CI</bdi> محفوظة طوال الوقت، ما دام <bdi>`enforce_admins`</bdi> مُفعَّلًا.** لا يتأثّر <bdi>`required_status_checks`</bdi> بالتبديل؛ ومع <bdi>`enforce_admins: true`</bdi> لا يزال الدمج يتطلّب أن تكون سياقات فحص الحالة المُهيَّأة خضراء. ومع <bdi>`enforce_admins: false`</bdi>، يتجاوز دمج <bdi>`--admin`</bdi> في الخطوة 3 أيضًا الفحوص المطلوبة الحمراء، لذا لا تُشغِّل المراسم في تلك الحالة.
- **مسار التدقيق مرئي.** يظهر تعليق <bdi>`gh pr merge --admin`</bdi> في البيانات الوصفية لدمج طلب السحب؛ وتظهر عمليات التبديل عبر واجهة برمجة تطبيقات الحماية في سجلّ تدقيق المستودع تحت هوية المشرف.

## 4. متى لا تُستخدَم المراسم

ما دامت الحماية تشترط 0 مراجعات موافِقة أو تترك <bdi>`enforce_admins`</bdi> مُعطَّلًا، فالمراسم غير ضرورية: ادمج مباشرةً كما يصف القسم 1.

المراسم مخصّصة لـ **الدمج الذاتي** لطلبات سحب المشرف نفسه. وعندما يتوفّر مراجع قرين (مساهم بصلاحية كتابة)، يكون المسار القياسي <bdi>`gh pr review --approve`</bdi> + <bdi>`gh pr merge --squash --delete-branch`</bdi> هو الصحيح، وتغدو المراسم غير ضرورية.

إذا ضمّ المستودع مشرفًا ثانيًا، فأحِل المراسم إلى التقاعد: يستعيد مسار مراجعة طلبات السحب القياسي نية المراجعة البشرية في الحماية دون أي تبديل.

## 5. تدقيق تشغيل سابق

يترك كل استدعاء للمراسم أثرًا على ثلاثة أسطح دائمة يمكن للمُشغِّل تفحّصها لاحقًا:

- **البيانات الوصفية لدمج طلب السحب.** يُرجِع <bdi>`gh pr view <pr-number> --json mergedBy,mergedAt,mergeCommit`</bdi> الجهة المُنفِّذة للدمج، وطابع وقت الدمج، وقيمة <bdi>SHA</bdi> لكوميت الـ <bdi>squash</bdi>. وتطابق الجهة <bdi>`mergedBy`</bdi> هوية المشرف الذي شغّل الخطوة 3.
- **سجلّ تدقيق المستودع.** يربط <bdi>`gh api /repos/<owner>/<repo>/actions/runs --jq '.workflow_runs[] | select(.event=="push")'`</bdi> تشغيل <bdi>CI</bdi> اللاحق للدمج بكوميت الدمج؛ ويُظهر سجلّ تدقيق قاعدة الحماية في المستودع (تاريخ <bdi>`gh api /repos/<owner>/<repo>/branches/main/protection`</bdi> عبر واجهة <bdi>Settings → Branches</bdi>) عمليتَي التبديل في الخطوة 2 والخطوة 4 المُحيطتين بنافذة الدمج.
- **تاريخ <bdi>git</bdi> لدى المشرف.** يسرد <bdi>`git log main --merges --first-parent`</bdi> كل كوميت دمج <bdi>squash</bdi> على <bdi>`main`</bdi> مع رقم طلب السحب المقابل في موضوع الكوميت (اللاحقة <bdi>`(#<pr-number>)`</bdi> وفق الافتراضي في <bdi>`gh pr merge --squash`</bdi>)، مما يتيح للمُشغِّل تتبّع أي إنزال سابق رجوعًا إلى طلب السحب الخاص به واستدعاء المراسم.

عندما يكون <bdi>`scripts/dev/admin_merge.py`</bdi> هو نقطة الدخول، يُسمّي سجلّه غير التفاعلي (<bdi>stdout</bdi>) استدعاءات واجهة برمجة تطبيقات الحماية الثلاثة واستدعاء واجهة برمجة تطبيقات الدمج بالتسلسل؛ وتوجيه خرج الغلاف عبر أنبوب إلى <bdi>`tee`</bdi> يلتقط جزءًا تدقيقيًا لكل تشغيل دون الاعتماد على احتفاظ <bdi>GitHub</bdi> بالسجلّ من جانبه.
