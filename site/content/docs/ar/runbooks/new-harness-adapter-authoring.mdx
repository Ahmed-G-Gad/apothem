استخدم هذا الدليل التشغيلي عند تأليف محوّل إطار عمل جديد ليُدرَج بشكل أصيل في
<bdi>Apothem</bdi> أو كحزمة طرف ثالث.

## المتطلّبات المسبقة

- الإلمام بـ [بروتوكول <bdi>HarnessAdapter</bdi>](/docs/architecture/harness-adapter-abstraction)
- فهم صيغة تهيئة إطار العمل المستهدف
- <bdi>Python 3.10+</bdi>

## الخطوات

### 1. نفِّذ المحوّل

اتبع مثال [تأليف محوّل إطار عمل](/docs/examples/authoring-a-harness-adapter)
لتنفيذ `HarnessAdapter` لإطار العمل المستهدف.

إذا كان المحوّل يكتب قالبًا نصيًا عاديًا (ملفًا ليس JSON ولا YAML)
باستخدام `mode: write_text` و`ownership_class: operator-owned`، فإن `uninstall`
لا يحذف الملف إلا ما دام نسخة غير معدَّلة من قالب شحنه Apothem. وحين يغيّر
إصدار لاحق القالب، أضف بصمة SHA-256 للنص السابق إلى قائمة `earlier_digests`
في مُدخل البيان ذاك ضمن التغيير نفسه، وإلا ترك `uninstall` في مكانها كل نسخة
غير معدَّلة كتبها الإصدار الأقدم. خذ بصمة النص عند وسم آخر إصدار باستخدام
`git show <tag>:<template path> | sha256sum`؛ ويجب ألا يحمل القالب أي رمز مسار
`${...}`. يفشل `tests/unit/test_template_digests.py` حين لا يُؤخذ قالب مشحون
في الحسبان.

### 2. اكتب صفحة التوثيق

أنشئ `site/content/docs/harnesses/<slug>.mdx` يغطّي:

- تدفّق التثبيت
- تخطيط الملف التعريفي إلى التهيئة الأصلية
- محاذير التوافق
- وصفات التحقّق
- وصفات التحديث وإلغاء التثبيت
- سطح بوّابة المطابقة
- جدول استكشاف الأخطاء وإصلاحها
- جدول مقابض التهيئة

### 3. اكتب الاختبارات

```bash
tests/packaging/test_<slug>_adapter.py
tests/unit/test_<slug>_adapter.py
```

الحد الأدنى لتغطية الاختبارات:
- `test_install_creates_expected_files`
- `test_verify_passes_after_install`
- `test_uninstall_removes_files`

### 4. تحقّق محليًا

```bash
apothem install --harness <slug>
apothem verify --harness <slug>
python -m apothem.conformity.gate --all .
```

### 5. قدِّم طلب السحب

افتح <bdi>PR</bdi> يتضمّن:

- تنفيذ المحوّل
- صفحة التوثيق في `site/content/docs/harnesses/<slug>.mdx`
- الاختبارات
- تسجيل نقطة الدخول في `pyproject.toml`، ومدخل `HARNESS_REGISTRY` في `src/apothem/lib/harness_registry_data.py` (مع رفع `SUPPORTED_HARNESS_COUNT` هناك)، والمعرّف في تعداد `harnessId` الخاص بـ`src/apothem/schemas/profile.schema.json`
- مدخل في سجلّ التغييرات
