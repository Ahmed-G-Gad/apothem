> **النطاق.** تتحقق قائمة التحقق هذه من طبقة قابلية النقل لعمليتي التثبيت والإزالة لـ **محوّل <bdi>Claude Code</bdi>** على مضيف ثانٍ جديد. أما أُطُر العمل الأخرى فلها وصفات تحقق خاصة بكل مضيف موثّقة ضمن [`site/content/docs/harnesses/<harness>.mdx`](/docs/harnesses).

> **مساران ولكلٍّ منهما دور.** أبقِهما منفصلين أثناء قراءة قائمة التحقق هذه. <bdi>`$HOME/.apothem`</bdi> هو **الدليل الرئيسي للمحرّك**، وهو المكان الذي تُستنسخ فيه شجرة المصدر ومنه تقرأ المثبّتات، ويمكن تجاوزه بـ<bdi>`APOTHEM_HOME`</bdi>. أما <bdi>`~/.claude/`</bdi> فهو **جذر إعدادات Claude Code**، أي سطح إخراج المحوّل الذي تستقرّ فيه ملفات <bdi>`settings.json`</bdi> المُجسَّدة وشجرة الدعم الفرعية. ولا يُثبَّت المحرّك أبدًا داخل <bdi>`~/.claude/`</bdi>؛ فاستبدل مسار الإخراج الأصلي للمحوّل عند التحقق من إطار عمل مختلف.

> **تحقّق يقوده المشغِّل لطبقة قابلية النقل في التثبيت والإزالة على مضيف ثانٍ جديد.** كُتب مستوى النشر (<bdi>`vX.Y.Z`</bdi>) على مضيف <bdi>Windows</bdi> واحد، ويحتاج ادعاء قابلية النقل (<bdi>`CLAUDE.md`</bdi> <bdi>`portability: universal`</bdi>) إلى تمرين شامل من طرف إلى طرف على مضيف ثانٍ قبل أن يكتسب الثابت متعدد المضيفات وزنه. هذه القائمة هي وصفة التحقق المعيارية على المضيف الثاني (محوّل <bdi>Claude Code</bdi>).

---

## 1. الشروط المسبقة على المضيف الثاني

نفّذ على المضيف الثاني قبل بدء التحقق:

| البند | الأمر | المتوقَّع |
|------|---------|----------|
| <bdi>Git</bdi> مثبَّت | <bdi>`git --version`</bdi> | <bdi>Git 2.40+</bdi> |
| <bdi>Python 3.10+</bdi> متاح | <bdi>`python3 --version`</bdi> (<bdi>POSIX</bdi>) أو <bdi>`py -3 --version`</bdi> (<bdi>Windows</bdi>) | <bdi>3.10 / 3.11 / 3.12 / 3.13</bdi> |
| مصادقة <bdi>GitHub</bdi> (اختيارية، للاستنساخ المصادَق عليه وفحوص <bdi>API</bdi>) | <bdi>`gh auth status`</bdi> | مسجَّل الدخول بالحساب المخوَّل للمستودع عند استخدام سير العمل المصادَق عليه |
| <bdi>Shell</bdi> متاح | <bdi>`bash --version`</bdi> (<bdi>POSIX</bdi>) أو <bdi>`pwsh --version`</bdi> (<bdi>Windows</bdi>) | <bdi>Bash 4+</bdi> أو <bdi>PowerShell 7+</bdi> |
| لا يوجد دليل رئيسي مسبق للمحرّك | <bdi>`ls "$HOME/.apothem" 2>&1`</bdi> | "No such file or directory" — إن وُجد، فاحتفظ بنسخة احتياطية قبل المتابعة |

## 2. التحقق من الاستنساخ والتثبيت

نفّذ على المضيف الثاني:

```bash
# Clone the published repo to the engine home. This is NOT ~/.claude — that
# is the Claude Code configuration root the adapter writes into, and cloning
# a source tree on top of it would bury the harness's own config.
git clone https://github.com/ahmed-g-gad/apothem.git "$HOME/.apothem"
cd "$HOME/.apothem"

# (POSIX path) Run scripts/installer/install.sh dry-run first
bash scripts/installer/install.sh --dry-run                                    # exit 0; prints Dry-run complete — no changes were made.

# (POSIX path) Run scripts/installer/install.sh for real
bash scripts/installer/install.sh                                               # exit 0; idempotent

# (Windows path) PowerShell parallel
pwsh -File scripts/installer/install.ps1 -DryRun                                # exit 0; prints Dry-run complete - no changes were made.
pwsh -File scripts/installer/install.ps1                                        # exit 0
```

التقط رمز الخروج وشعار <bdi>stdout</bdi> لكل أمر. سجِّل في <bdi>`<second-host>/.audit/cross-machine-clone-install.md`</bdi>.

## 3. انضباط العناصر الأربعة (وفق <bdi>`src/apothem/rules/production-ready-prs.md`</bdi>)

تحقّق من كل ثابت من الثوابت الأربعة على المضيف الثاني:

### 3.1 أمان الوجهة الموجودة

```bash
# Re-run installer at the same destination.
bash scripts/installer/install.sh                                               # POSIX
pwsh -File scripts/installer/install.ps1                                        # Windows
```

**المتوقَّع:** يكتشف المُثبِّت الدليل الرئيسي الموجود للمحرّك، ويُجري له تقديمًا سريعًا (fast-forward) بدلًا من إعادة التثبيت أو التكرار؛ رمز الخروج <bdi>0</bdi>.

### 3.2 فحص المتطلبات المسبقة

```bash
# Run from a copy outside any checkout, with git not on PATH.
d="$(mktemp -d)" && cp scripts/installer/install.sh "$d/" && PATH=<directory holding python3, click, rich and coreutils, but no git> /bin/sh "$d/install.sh"                            # POSIX (no git)
```

**المتوقَّع:** يرفض المُثبِّت التشغيل، ويُصدر تشخيص "git not found" صريحًا؛ رمز الخروج غير صفري.

### 3.3 إعادة تشغيل متماثلة (idempotent)

```bash
# Run installer N times back-to-back.
for i in 1 2 3 4 5; do bash scripts/installer/install.sh; done                  # POSIX
1..5 | ForEach-Object { pwsh -File scripts/installer/install.ps1 }              # Windows
```

**المتوقَّع:** يخرج كل استدعاء برمز <bdi>0</bdi>؛ ولا آثار جانبية بعد الاستدعاء الأول؛ ولا ملفات مكرّرة؛ ولا تكرار لإدخال <bdi>RC</bdi> في <bdi>shell-profile</bdi>.

### 3.4 قابل للتهيئة عبر متغيّرات البيئة

```bash
# Install to a non-default engine home. APOTHEM_HOME is the destination
# override the installers actually read; see the installer-environment-variables
# reference for the full set.
APOTHEM_HOME=/tmp/alt-apothem bash scripts/installer/install.sh                 # POSIX
$env:APOTHEM_HOME='C:\tmp\alt-apothem'; pwsh -File scripts/installer/install.ps1   # Windows
```

**المتوقَّع:** يحترم المُثبِّت متغيّر البيئة؛ ولا يُنشأ الدليل الافتراضي <bdi>`$HOME/.apothem`</bdi>؛ وتحتوي الوجهة البديلة على التخطيط المتوقَّع.

## 4. التحقق من حزمة المدقِّقات (بعد التثبيت)

```bash
cd "$HOME/.apothem"
make validate                                                 # conformity gate --all --strict; exit 0
make headers-doctor                                           # file-header-grep → passed:true
make ai-surfaces-doctor                                       # multi-surface-coherence → passed:true
make plans-doctor                                             # no-global-plans + plans-discipline-language
make lint                                                     # ruff check + ruff format --check
make test                                                     # exit 0, no failures
```

**المتوقَّع:** كل بوابة خضراء. التقط رموز الخروج وأسطر الملخص.

## 5. التحقق من الإزالة

```bash
# POSIX path — interactive uninstall
bash scripts/installer/uninstall.sh                           # answers: "y" to confirm
PYTHONPATH="$HOME/.apothem/src/apothem/_vendor:$HOME/.apothem/src" python3 -m apothem verify --harness claude-code    # reports the harness as not installed

# Re-install from the kept checkout, then uninstall non-interactively
bash scripts/installer/install.sh
bash scripts/installer/uninstall.sh --yes
PYTHONPATH="$HOME/.apothem/src/apothem/_vendor:$HOME/.apothem/src" python3 -m apothem verify --harness claude-code    # reports the harness as not installed
```

**المتوقَّع:** يطالب المسار التفاعلي بالتأكيد؛ ويتخطّى <bdi>`--yes`</bdi> المطالبة في التشغيلات الدفعية؛ ويترك كلا المسارين جذر إعدادات <bdi>Claude Code</bdi> خاليًا من ملفات <bdi>Apothem</bdi> المُجسَّدة؛ وتُزال أداة الغلاف <bdi>`apothem`</bdi> (<bdi>`~/.local/bin/apothem`</bdi>؛ وأمّا أداة الغلاف <bdi>`apothem.cmd`</bdi> في <bdi>`%LOCALAPPDATA%\Microsoft\WindowsApps`</bdi> فلا تُزال إلا بواسطة <bdi>`uninstall.ps1`</bdi>).

## 6. التحقق من حواجز الأمان

يعتمد حارس أداة الإزالة على فحص شكل شجرة المصدر، لا على ملف الحارس (sentinel): فهو يمضي قدمًا فقط حين يحتوي الهدف على <bdi>`src/apothem/`</bdi> إلى جانب أيٍّ من <bdi>`pyproject.toml`</bdi> أو <bdi>`.claude-plugin/`</bdi>. شغّل هذه الفحوص عبر <bdi>`APOTHEM_HOME`</bdi>، وهو المتغيّر الذي يقرؤه السكربت؛ فالفحص المكتوب على متغيّر يتجاهله السكربت لا يختبر الحارس، بل يشغّل أداة الإزالة على تثبيتك الفعلي.

```bash
# Run uninstall against a directory that is not an apothem source tree.
mkdir -p /tmp/not-an-apothem-install
APOTHEM_HOME=/tmp/not-an-apothem-install bash scripts/installer/uninstall.sh --yes
```

**المتوقَّع:** ترفض أداة الإزالة، وتُصدر <bdi>`No apothem source found at /tmp/not-an-apothem-install — nothing to uninstall`</bdi>؛ رمز الخروج غير صفري. لم يُمسّ المسار على الإطلاق.

```bash
# Run uninstall against $HOME and /.
APOTHEM_HOME=$HOME bash scripts/installer/uninstall.sh --yes 2>&1 | tail -3
APOTHEM_HOME=/ bash scripts/installer/uninstall.sh --yes 2>&1 | tail -3
```

**المتوقَّع:** يرفض كلٌّ من <bdi>`APOTHEM_HOME=$HOME`</bdi> و<bdi>`APOTHEM_HOME=/`</bdi> بالتشخيص <bdi>`No apothem source found at …`</bdi>، ولا يمسّ أيٌّ منهما نظام الملفات. أما <bdi>`APOTHEM_HOME`</bdi> الفارغ فقد استُبعد عمدًا، لأنه يرجع إلى <bdi>`~/.apothem`</bdi> حيث يمكن أن يوجد تثبيت فعلي.

```bash
# An explicit APOTHEM_SOURCE that is not a source tree is rejected separately.
APOTHEM_SOURCE=/tmp/not-an-apothem-install bash scripts/installer/uninstall.sh --yes
```

**المتوقَّع:** يرفض مع <bdi>`APOTHEM_SOURCE is not an apothem source tree: /tmp/not-an-apothem-install`</bdi>؛ رمز الخروج غير صفري.

## 7. الإبلاغ

بعد التشغيل على المضيف الثاني، التقط النتائج في:

- <bdi>`<second-host>/.audit/cross-machine-clone-install.md`</bdi> (نتائج أوامر الاستنساخ والتثبيت)
- <bdi>`<second-host>/.audit/cross-machine-validators.md`</bdi> (نتائج المدقِّقات في القسم 4)
- <bdi>`<second-host>/.audit/cross-machine-uninstall.md`</bdi> (نتائج الإزالة والأمان في القسمين 5–6)

اعرض النتائج على المُشرِف:

- ✅ تتحقق كل ثوابت انضباط العناصر الأربعة، وكل بوابات المدقِّقات خضراء، وترفض كل حواجز أمان الإزالة الأهداف غير الآمنة ← يُتحقَّق من ادعاء النشر <bdi>`portability: universal`</bdi> من طرف إلى طرف
- ❌ عند أي إخفاق ← افتح مشكلة على <bdi>`https://github.com/ahmed-g-gad/apothem/issues/new`</bdi> مع القسم المُخفِق والمخرجات الملتقطة؛ ويتولى المُشرِف الفرز
