Vérifie l'installation d'un adaptateur d'environnement.

## Synopsis

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

Appelle l'implémentation `verify()` de chaque adaptateur sélectionné. Se
termine avec le code 0 uniquement lorsque tous les adaptateurs sélectionnés
signalent que leurs cibles gérées sont présentes et valides. Sans
`--profile`, la vérification est **structurelle** — chaque cible gérée doit
être présente et valide. Avec `--profile`, la vérification exige en plus la
**fidélité au profil** : une installation présente mais qui a dérivé échoue
donc à la vérification, ce qui répond à la question « CE profil est-il
fidèlement installé ? » plutôt qu'à la simple question « existe-t-il ? ».

Un balayage `--harness all` respecte le champ `exclude_harnesses` du profil —
les mêmes exclusions que celles appliquées par le lot `install`/`update` —, de
sorte que verify ne signale jamais comme manquant un environnement
délibérément exclu. Les exclusions proviennent de `--profile` lorsqu'il est
fourni, sinon du profil par défaut ; un profil par défaut illisible ou absent
se replie sur le registre complet.

## Options

| Option | Description |
|---|---|
| `--harness NAME` | Adaptateur d'environnement à vérifier, ou `all` pour l'ensemble couvrant tout le registre (obligatoire). |
| `--profile PATH` | YAML du profil partagé par rapport auquel vérifier la fidélité. Sans cette option, la vérification est purement structurelle. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. |
| `--quiet`, `-q` | Supprime la sortie informative ; seules les erreurs sont émises. |
| `--verbose`, `-v` | Émet une sortie de diagnostic supplémentaire. |
| `--format plain\|json` | Format de sortie (par défaut : `plain`). |
| `--json` | Raccourci de `--format json`. |
| `--no-color` | Désactive les codes de couleur ANSI dans la sortie. |
| `-h`, `--help` | Affiche l'aide et quitte. |

## Sortie JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Lorsqu'un environnement sélectionné est manquant ou invalide, `status` vaut
`error`, la ligne de résultat en échec porte `verified: false` et le processus
se termine avec le code 1.

## Exemples

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## Codes de sortie

| Code | Signification |
|---|---|
| 0 | Environnement vérifié — toutes les cibles gérées sont présentes et valides |
| 1 | Environnement non vérifié — des cibles gérées sont manquantes ou invalides |
| 64 | Erreur d'utilisation : une option ou une commande inconnue, ou une valeur d'option manquante ou invalide. Sous `--json`, l'erreur est une enveloppe JSON avec le code `cli.usage`. |
