Supprime la configuration d'un adaptateur d'environnement.

## Synopsis

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

Supprime les cibles de l'environnement gérées par l'adaptateur, puis les
répertoires que l'installation a créés, une fois qu'ils sont vides (un
répertoire contenant quoi que ce soit qui vous appartient est conservé).

La mémoire, les contextes et les magasins d'apprentissage du répertoire de
travail partagé sont sauvegardés et supprimés uniquement lorsque c'est le
dernier environnement installé dans ce répertoire. La désinstallation les
supprime à l'emplacement enregistré par l'installation : elle les retrouve donc
là où l'installation les a écrits (voir les champs `workspace` du profil). Le
répertoire `plans/` n'est jamais supprimé.

Demande une confirmation, sauf si `--yes` est fourni. Lorsqu'aucune invite
n'est possible (`--format json`, car le texte de l'invite corromprait l'unique
document JSON, ou un shell non interactif, sans TTY), la commande refuse
d'emblée avec une erreur structurée `uninstall.confirmation_required` (code de
sortie 1), sauf si `--yes` est fourni. Si un environnement sélectionné n'est pas
installé, la commande réussit (code de sortie 0) et, en sortie texte, affiche
`NAME is not installed; nothing to remove.`, où `NAME` est l'identifiant de
l'environnement.

Les magasins de données partagés sous `.apothem/` à la racine d'installation
(`memory/`, `contexts/`, `learning/`) restent en place tant qu'un autre
environnement installé à la même racine les utilise encore. Lorsque
l'environnement que vous supprimez est le dernier à cette racine, la commande
copie d'abord chaque magasin dans la racine de sauvegarde d'Apothem
(`~/.apothem/backups/`), puis le supprime avec tout son contenu. Tout ce que
vous conservez dans `plans/` n'est jamais supprimé.

## Dossiers partagés dans votre répertoire personnel

Plusieurs installations peuvent utiliser un même dossier de votre répertoire
personnel : le dossier de skills (`~/.agents/skills/`, ou `~/.codebuddy/skills/`,
`~/.kiro/skills/` ou `~/.trae/skills/`) ainsi que `~/.config/apothem/rules/` et
`~/.config/apothem/templates/`. La page [install](/docs/cli-reference/install#dossiers-dans-votre-répertoire-personnel)
indique quel adaptateur écrit lequel. Apothem enregistre les installations qui
utilisent chaque dossier, et une désinstallation suit une seule règle : elle ne
supprime un dossier que lorsqu'aucune autre installation Apothem ne l'utilise
encore.

- Désinstaller un outil conserve les skills tant qu'une autre installation les
  utilise encore, et le signale. Un même outil installé dans deux projets compte
  comme deux installations : le désinstaller du projet A conserve donc les
  dossiers tant que le projet B les utilise encore. La dernière désinstallation
  les supprime (voir le second exemple ci-dessous).
- Seul ce que liste l'enregistrement propre à l'installation est supprimé. Une
  installation effectuée avant que les dossiers ne soient gérés n'a pas
  d'enregistrement de ce type : la désinstaller ne supprime donc rien dans votre
  répertoire personnel. Les fichiers que vous avez ajoutés aux dossiers restent
  en place, tout comme un dossier qui porte le nom d'un skill Apothem et
  qu'Apothem n'a pas écrit.
- Une installation dont le dossier de projet n'existe plus est ignorée, de sorte
  qu'un projet supprimé ne conserve pas les dossiers indéfiniment. La note la
  nomme.
- Si l'enregistrement d'une installation susceptible d'utiliser les dossiers ne
  peut pas être lu, la désinstallation s'arrête avec une erreur avant de
  supprimer quoi que ce soit, et l'installation reste enregistrée. Réparez ou
  déplacez l'enregistrement illisible, puis relancez la commande. Un
  enregistrement endommagé d'un outil qui n'écrit jamais dans ces dossiers est
  ignoré.
- Lorsque la dernière utilisation disparaît, les dossiers laissés vides sont
  également supprimés. Chaque dossier est sauvegardé sous `~/.apothem/backups/`
  avant d'être supprimé.

Chaque désinstallation affiche une `Note:` par dossier, par exemple `Note: <harness> -
~/.agents/skills/ was kept: still used by <harness> (/path/to/project)`, ou
`was removed: no other Apothem install uses it`. Dans l'enveloppe `--format json`,
chaque note est une entrée `warnings` avec `"outcome": "advisory"`,
`"operation": "shared_root"` et `"role"` défini à `retained` ou `released`. Elle
porte `path`, `holders` (les installations qui conservent le dossier), `stale`
(les installations ignorées), ainsi que `kept` et `total` (les entrées
enregistrées conservées et les entrées que l'installation listait).

Si un dossier reste en place à cause d'une installation que vous ne retrouvez
pas, la note la nomme. Lorsque le dossier du projet a été supprimé,
l'installation est ignorée et le dossier disparaît à la prochaine
désinstallation. Lorsque le projet existe mais que vous avez retiré à la main le
bloc Apothem de son fichier de règles, `uninstall` signale l'environnement comme
non installé et ne libère pas sa revendication ; exécutez `install` pour cet
environnement et ce projet, puis `uninstall`, afin de la libérer.
`apothem verify` indique si un dossier est toujours complet.

Une suppression `--harness all` est délibérément exhaustive : elle couvre
chaque environnement enregistré, y compris ceux que le champ `exclude_harnesses`
du profil ignore lors de l'installation. Le nettoyage atteint l'état qu'une
installation antérieure, de portée plus large, a pu laisser derrière elle. Les
environnements qui n'ont jamais été installés reçoivent le même avis.

L'alias en forme continue `apothem uninstalling` (également accepté sous la
forme `apothem Uninstalling`) se résout vers le même gestionnaire.

## Options

| Option | Description |
|---|---|
| `--harness NAME` | Adaptateur d'environnement à supprimer, ou `all` pour l'ensemble couvrant tout le registre (obligatoire). |
| `--yes` | Ignore l'invite de confirmation. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. |
| `--quiet`, `-q` | Supprime la sortie informative ; seules les erreurs sont émises. |
| `--verbose`, `-v` | Accepté par cohérence avec les autres commandes ; cette commande n'affiche aucune sortie supplémentaire. |
| `--format plain\|json` | Format de sortie (par défaut : `plain`). |
| `--json` | Raccourci de `--format json`. |
| `--no-color` | Désactive les codes de couleur ANSI dans la sortie. |
| `-h`, `--help` | Affiche l'aide et quitte. |

## Sortie JSON

Lorsque l'adaptateur est installé et supprimé avec succès :

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Lorsque l'adaptateur n'était pas installé, la commande se termine avec le code `0`. Dans la sortie JSON, l'enveloppe contient `"status": "success"` et `"action": "uninstalled"`, et la ligne de résultats contient `"outcome": "skipped"` avec le message `"not installed; no files removed"`. Le champ `status` ne prend jamais la valeur `"not_installed"`.

## Exemples

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

Un dossier de skills partagé reste en place jusqu'à ce que la dernière
installation qui l'utilise disparaisse :

```bash
apothem install --harness codex
apothem install --harness cursor --project A
apothem uninstall --harness codex --yes                  # keeps ~/.agents/skills/, the cursor install uses it
apothem uninstall --harness cursor --project A --yes     # removes it: no install uses it now
```

## Codes de sortie

| Code | Signification |
|---|---|
| 0 | Adaptateur désinstallé, ou qui n'était pas installé |
| 1 | Environnement introuvable, confirmation refusée ou impossible (mode non interactif ou JSON sans `--yes`), ou échec de chaque suppression |
| 2 | Suppression partielle — au moins un environnement a été supprimé avant un échec |
| 64 | Erreur d'utilisation : une option ou une commande inconnue, ou une valeur d'option manquante ou invalide. Sous `--json`, l'erreur est une enveloppe JSON avec le code `cli.usage`. |
