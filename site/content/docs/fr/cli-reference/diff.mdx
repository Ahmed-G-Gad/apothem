Prévisualise les changements de configuration en attente pour un seul assistant de
codage.

## Synopsis

```
apothem diff --harness NAME [--profile PATH] [--project PATH]
             [--quiet|-q] [--verbose|-v]
             [--format plain|json] [--json] [--no-color]
```

`diff` est une commande d'inspection en lecture seule. Elle exécute la même
matérialisation que celle qu'exécuterait la commande `install`, mais en mode simulation
— rien n'est écrit sur le disque. Elle rend ensuite, par cible planifiée, l'opération, le
chemin de la cible, le résultat et (pour les ancres détenues par l'opérateur qui seraient
fusionnées) le diff unifié du changement. C'est la réponse à « que ferait `apothem
install` à cet harness en ce moment ? » sans effectuer le changement.

Pour les cibles détenues par l'opérateur — des fichiers qui portent à la fois votre
propre contenu et un bloc géré par Apothem — le diff montre les lignes exactes qui
changeraient. Pour les autres cibles, l'opération et le résultat planifiés sont résumés.

`diff` opère sur un seul harness. Contrairement à `status`, elle n'accepte
pas `all` ; passez un nom de harness.

## Options

| Option | Description |
|---|---|
| `--harness NAME` | Adaptateur de harness à prévisualiser (requis ; un seul harness, pas `all`). |
| `--profile PATH` | Chemin vers le YAML du profil partagé. Par défaut : `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Racine de projet pour les harness à portée de projet. Requise lorsque le harness sélectionné est à portée de projet. |
| `--quiet`, `-q` | Supprime la sortie informative ; seules les erreurs sont émises. |
| `--verbose`, `-v` | Émet une sortie de diagnostic supplémentaire. |
| `--format plain\|json` | Format de sortie (par défaut : `plain`). |
| `--json` | Raccourci pour `--format json`. |
| `--no-color` | Désactive les codes de couleur ANSI dans la sortie. |
| `-h`, `--help` | Affiche l'aide et quitte. |

## Sortie JSON

L'enveloppe `--json` reflète l'enveloppe de l'installation en mode simulation. `status`
vaut `dry_run`, `files_written` est toujours vide, et le bloc `materialization` ainsi que
la liste `results` portent tout le détail de la cible planifiée. Le champ `detail.diff` de
chaque ligne de résultat détenue par l'opérateur porte la chaîne du diff unifié.

```json
{
  "status": "dry_run",
  "command": "diff",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "sentinel_merge",
      "path": "C:\\Users\\Example\\.claude\\CLAUDE.md",
      "message": "dry run: no filesystem changes made",
      "detail": {
        "ownership_class": "operator-owned",
        "diff": "--- a/CLAUDE.md\n+++ b/CLAUDE.md\n@@ ..."
      }
    }
  ],
  "warnings": [],
  "error": null,
  "materialization": { "...": "..." }
}
```

## Exemples

```bash
apothem diff --harness claude-code
apothem diff --harness cursor --project .
apothem diff --harness claude-code --json
```

## Codes de sortie

| Code | Signification |
|---|---|
| 0 | Diff signalé (les changements en attente sont signalés, pas une erreur) |
| 1 | Erreur attendue de validation, de profil, de harness ou de projet |
