Réinstalle la configuration d'un adaptateur d'environnement à partir du profil
partagé actuel.

## Synopsis

```
apothem update --harness NAME|all [--profile PATH] [--dry-run]
                [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

`update` rematérialise la sortie de l'environnement à partir du profil partagé
actuel. La commande utilise la même validation de profil, la même sélection
`--harness all`, la même vérification de la portée de projet, le même
comportement de dry-run et la même enveloppe JSON que `install`.

Pour les adaptateurs à portée de projet qui écrivent des skills dans votre
répertoire personnel (voir
[`install`](/docs/cli-reference/install#dossiers-dans-votre-répertoire-personnel)),
`update` met également ces dossiers à jour et affiche la même `Note:` qui les
nomme. Un adaptateur installé avant qu'il n'écrive des skills les reçoit lors de
sa prochaine mise à jour. Un dossier de skill qu'Apothem n'a pas écrit est ignoré
avec un avertissement, comme pour [`install`](/docs/cli-reference/install#dossiers-dans-votre-répertoire-personnel).
Une installation qui écrivait auparavant le dossier de skills partagé est
réécrite, lors de sa prochaine mise à jour, sous la forme que partagent toutes
les installations ; chaque dossier modifié est d'abord sauvegardé.

L'alias en forme continue `apothem updating` (également accepté sous la forme
`apothem Updating`) se résout vers le même gestionnaire.

## Options

| Option | Description |
|---|---|
| `--harness NAME` | Adaptateur d'environnement à mettre à jour, ou `all` pour l'ensemble couvrant tout le registre (obligatoire). Avec `all`, les environnements listés dans `exclude_harnesses` du profil sont ignorés, mais un environnement nommé explicitement est mis à jour même s'il figure dans cette liste. |
| `--profile PATH` | Chemin vers le YAML du profil partagé. Par défaut : `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Prévisualise la mise à jour sans écrire de fichiers. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. Obligatoire lorsque l'ensemble d'environnements sélectionné inclut des adaptateurs à portée de projet. |
| `--quiet`, `-q` | Supprime la sortie informative ; seules les erreurs sont émises. |
| `--verbose`, `-v` | Émet une sortie de diagnostic supplémentaire. |
| `--format plain\|json` | Format de sortie (par défaut : `plain`). |
| `--json` | Raccourci de `--format json`. |
| `--no-color` | Désactive les codes de couleur ANSI dans la sortie. |
| `-h`, `--help` | Affiche l'aide et quitte. |

## Sortie JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "update",
  "action": "updated",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

`--dry-run` renvoie `status: "dry_run"` et `files_written: []`.

## Exemples

```bash
apothem update --harness claude-code
apothem update --harness claude-code --dry-run
apothem update --harness all --project . --dry-run --json
apothem Updating --harness claude-code   # continuous-form alias
apothem updating --harness claude-code   # lowercase variant
```

## Codes de sortie

| Code | Signification |
|---|---|
| 0 | Adaptateur mis à jour avec succès ou dry-run planifié sans erreur |
| 1 | Erreur attendue de validation, de profil, d'environnement, de projet ou d'adaptateur |
| 2 | Matérialisation partielle du lot après au moins une écriture |
| 64 | Erreur d'utilisation : une option ou une commande inconnue, ou une valeur d'option manquante ou invalide. Sous `--json`, l'erreur est une enveloppe JSON avec le code `cli.usage`. |
