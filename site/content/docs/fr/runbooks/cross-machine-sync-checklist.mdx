> **Portée.** Cette liste de vérification vérifie la couche de portabilité de l'installation et de la désinstallation de l'**adaptateur Claude Code** sur un second hôte neuf. Les autres environnements disposent de leurs propres recettes de vérification par hôte, documentées sous [`site/content/docs/harnesses/<harness>.mdx`](/docs/harnesses).

> **Deux chemins, deux rôles.** Gardez-les distincts pendant la lecture de cette liste de vérification. `$HOME/.apothem` est le **répertoire racine du moteur** — là où l'arbre source est cloné et où les installateurs lisent, modifiable avec `APOTHEM_HOME`. `~/.claude/` est la **racine de configuration de Claude Code** — la surface de sortie de l'adaptateur, où sont déposés le `settings.json` matérialisé et la sous-arborescence de support. Le moteur n'est jamais installé dans `~/.claude/` ; substituez le chemin de sortie natif de l'adaptateur lors de la validation d'un autre environnement.

> **Vérification pilotée par l'opérateur de la couche de portabilité de l'installation et de la désinstallation sur un second hôte neuf.** Le niveau de publication (`vX.Y.Z`) a été rédigé sur un seul hôte Windows ; l'affirmation de portabilité (`CLAUDE.md` `portability: universal`) nécessite un exercice de bout en bout sur un second hôte avant que l'invariant multi-hôtes ait du poids. Cette liste de vérification constitue la recette canonique de vérification sur un second hôte (adaptateur Claude Code).

## 1. Conditions préalables sur le second hôte

À exécuter sur le second hôte avant de démarrer la vérification :

| Élément | Commande | Attendu |
|------|---------|----------|
| Git installé | `git --version` | Git 2.40+ |
| Python 3.10+ disponible | `python3 --version` (POSIX) ou `py -3 --version` (Windows) | 3.10 / 3.11 / 3.12 / 3.13 |
| Authentification GitHub (facultative, pour le clonage authentifié et les contrôles d'API) | `gh auth status` | Connecté avec le compte autorisé du dépôt lors de l'utilisation de flux de travail authentifiés |
| Shell disponible | `bash --version` (POSIX) ou `pwsh --version` (Windows) | Bash 4+ ou PowerShell 7+ |
| Aucun répertoire racine du moteur préexistant | `ls "$HOME/.apothem" 2>&1` | "No such file or directory" — s'il est présent, faites une sauvegarde avant de poursuivre |

## 2. Vérification du clonage et de l'installation

À exécuter sur le second hôte :

```bash
# Clone the published repo to the engine home. This is NOT ~/.claude — that
# is the Claude Code configuration root the adapter writes into, and cloning
# a source tree on top of it would bury the harness's own config.
git clone https://github.com/ahmed-g-gad/apothem.git "$HOME/.apothem"
cd "$HOME/.apothem"

# (POSIX path) Run scripts/installer/install.sh dry-run first
bash scripts/installer/install.sh --dry-run                                    # exit 0; prints Dry-run complete — no changes were made.

# (POSIX path) Run scripts/installer/install.sh for real
bash scripts/installer/install.sh                                               # exit 0; idempotent

# (Windows path) PowerShell parallel
pwsh -File scripts/installer/install.ps1 -DryRun                                # exit 0; prints Dry-run complete - no changes were made.
pwsh -File scripts/installer/install.ps1                                        # exit 0
```

Capturez le code de sortie et la bannière stdout de chaque commande. Consignez le résultat dans `<second-host>/.audit/cross-machine-clone-install.md`.

## 3. La discipline des quatre éléments (selon `src/apothem/rules/production-ready-prs.md`)

Vérifiez chacun des quatre invariants sur le second hôte :

### 3.1 Sécurité de la destination existante

```bash
# Re-run installer at the same destination.
bash scripts/installer/install.sh                                               # POSIX
pwsh -File scripts/installer/install.ps1                                        # Windows
```

**Attendu :** L'installateur détecte le répertoire racine du moteur existant et y extrait l'étiquette de version plutôt que de le réinstaller ou de le dupliquer ; code de sortie 0.

### 3.2 Contrôle des prérequis

```bash
# Run from a copy outside any checkout, with git not on PATH.
d="$(mktemp -d)" && cp scripts/installer/install.sh "$d/" && PATH=<directory holding python3, click, rich and coreutils, but no git> /bin/sh "$d/install.sh"                            # POSIX (no git)
```

**Attendu :** L'installateur refuse de s'exécuter ; il émet un diagnostic explicite « git not found » ; code de sortie non nul.

### 3.3 Réexécution idempotente

```bash
# Run installer N times back-to-back.
for i in 1 2 3 4 5; do bash scripts/installer/install.sh; done                  # POSIX
1..5 | ForEach-Object { pwsh -File scripts/installer/install.ps1 }              # Windows
```

**Attendu :** Chaque invocation se termine avec le code 0 ; aucun effet de bord après la première invocation ; aucun fichier dupliqué ; aucune duplication des entrées RC du profil shell.

### 3.4 Configurable via des variables d'environnement

```bash
# Install to a non-default engine home. APOTHEM_HOME is the destination
# override the installers actually read; see the installer-environment-variables
# reference for the full set.
APOTHEM_HOME=/tmp/alt-apothem bash scripts/installer/install.sh                 # POSIX
$env:APOTHEM_HOME='C:\tmp\alt-apothem'; pwsh -File scripts/installer/install.ps1   # Windows
```

**Attendu :** L'installateur respecte la variable d'environnement ; le répertoire par défaut `$HOME/.apothem` n'est PAS créé ; la destination alternative contient l'agencement attendu.

## 4. Vérification de la suite de validateurs (post-installation)

```bash
cd "$HOME/.apothem"
make validate                                                 # conformity gate --all --strict; exit 0
make headers-doctor                                           # file-header-grep → passed:true
make ai-surfaces-doctor                                       # multi-surface-coherence → passed:true
make plans-doctor                                             # no-global-plans + plans-discipline-language
make lint                                                     # ruff check + ruff format --check + mypy
make test                                                     # exit 0, no failures
```

**Attendu :** Chaque portail au vert. Capturez les codes de sortie et les lignes de résumé.

## 5. Vérification de la désinstallation

```bash
# POSIX path — interactive uninstall
bash scripts/installer/uninstall.sh                           # answers: "y" to confirm
PYTHONPATH="$HOME/.apothem/src/apothem/_vendor:$HOME/.apothem/src" python3 -m apothem verify --harness claude-code    # reports the harness as not installed

# Re-install from the kept checkout, then uninstall non-interactively
bash scripts/installer/install.sh
bash scripts/installer/uninstall.sh --yes
PYTHONPATH="$HOME/.apothem/src/apothem/_vendor:$HOME/.apothem/src" python3 -m apothem verify --harness claude-code    # reports the harness as not installed
```

**Attendu :** Le flux interactif demande confirmation ; `--yes` saute l'invite pour les exécutions par lots ; les deux flux laissent la racine de configuration de Claude Code exempte de fichiers matérialisés par Apothem ; le shim `apothem` est supprimé (`~/.local/bin/apothem` ; le shim `apothem.cmd` dans `%LOCALAPPDATA%\Microsoft\WindowsApps` n'est supprimé que par `uninstall.ps1`).

## 6. Vérification des garde-fous de sécurité

Le garde-fou du désinstallateur est une vérification de la forme de l'arborescence source, et non un fichier sentinelle : il ne poursuit que si la cible contient `src/apothem/` et l'un des deux éléments `pyproject.toml` ou `.claude-plugin/`. Pilotez ces sondes avec `APOTHEM_HOME`, la variable que lit le script : une sonde écrite pour une variable que le script ignore ne teste pas le garde-fou, elle exécute le désinstallateur contre votre installation réelle.

```bash
# Run uninstall against a directory that is not an apothem source tree.
mkdir -p /tmp/not-an-apothem-install
APOTHEM_HOME=/tmp/not-an-apothem-install bash scripts/installer/uninstall.sh --yes
```

**Attendu :** Le désinstallateur refuse ; il émet `No apothem source found at /tmp/not-an-apothem-install — nothing to uninstall` ; code de sortie non nul. Le chemin n'a PAS été touché.

```bash
# Run uninstall against $HOME and /.
APOTHEM_HOME=$HOME bash scripts/installer/uninstall.sh --yes 2>&1 | tail -3
APOTHEM_HOME=/ bash scripts/installer/uninstall.sh --yes 2>&1 | tail -3
```

**Attendu :** `APOTHEM_HOME=$HOME` et `APOTHEM_HOME=/` refusent chacun avec le diagnostic `No apothem source found at …`, et aucun des deux ne touche au système de fichiers. Un `APOTHEM_HOME` vide est volontairement laissé de côté : il retombe sur `~/.apothem`, emplacement où peut se trouver une installation réelle.

```bash
# An explicit APOTHEM_SOURCE that is not a source tree is rejected separately.
APOTHEM_SOURCE=/tmp/not-an-apothem-install bash scripts/installer/uninstall.sh --yes
```

**Attendu :** Refuse avec `APOTHEM_SOURCE is not an apothem source tree: /tmp/not-an-apothem-install` ; code de sortie non nul.

## 7. Rapport

Après l'exécution sur le second hôte, consignez les résultats aux emplacements suivants :

- `<second-host>/.audit/cross-machine-clone-install.md` (résultats des commandes de clonage et d'installation)
- `<second-host>/.audit/cross-machine-validators.md` (résultats des validateurs de la section 4)
- `<second-host>/.audit/cross-machine-uninstall.md` (résultats de désinstallation et de sécurité des sections 5–6)

Remontez les constats au mainteneur :

- ✅ tous les invariants de la discipline des quatre éléments tiennent, tous les portails de validateurs sont au vert et tous les garde-fous de sécurité de la désinstallation ont refusé les cibles non sûres → l'affirmation `portability: universal` de la publication est vérifiée de bout en bout
- ❌ tout échec → ouvrez un ticket sur `https://github.com/ahmed-g-gad/apothem/issues/new` avec la section en échec et la sortie capturée ; le mainteneur effectue le tri
