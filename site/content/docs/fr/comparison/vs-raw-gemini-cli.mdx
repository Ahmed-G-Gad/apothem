Gemini CLI lit un unique fichier de règles `GEMINI.md`. L'adaptateur gemini-cli
d'Apothem le rend depuis le profil partagé. Cette page met en regard la
maintenance manuelle de cette configuration et sa gestion avec Apothem.

## Comparaison d'effort

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Rédiger les règles | Modifier à la main un seul `GEMINI.md` | Rendues : les consignes valables pour tout le projet dans `GEMINI.md` ; les règles dans `.gemini/.apothem/support/` |
| Garder les règles alignées avec les autres environnements | Manuel, par outil | Automatique lors de `apothem update` |
| Installer / supprimer la configuration | Écrire et supprimer `GEMINI.md` à la main | `apothem install` / `apothem uninstall` |
| Vérifier que la configuration est correcte | Inspection manuelle | `apothem verify --harness gemini-cli --project <path>` |

## Ce que gère Apothem

L'adaptateur gemini-cli écrit un bloc Apothem délimité par des marqueurs sentinelles dans `<project>/GEMINI.md`. Ce bloc porte les consignes valables pour tout le projet et renvoie au matériel d'Apothem. Les règles, les templates et les hooks sont placés comme fichiers de support sous `<project>/.gemini/.apothem/support/`, et les commandes, les skills et les agents sous `<project>/.gemini/`. Gemini CLI n'a pas de hook PreToolUse : l'intention des garde-fous s'exprime donc dans la prose des règles plutôt qu'en un point d'interception d'appel d'outil. Chaque modification des règles partagées régénère `GEMINI.md` lors du prochain `apothem update`.

## Chemin de migration

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez pas encore fait.
2. Déplacez les règles de votre `GEMINI.md` existant vers le corpus partagé.
3. Exécutez `apothem install --harness gemini-cli --project <path>` pour générer et écrire `GEMINI.md`.
4. Exécutez `apothem verify --harness gemini-cli --project <path>` pour confirmer que la configuration est bien en place.
5. Utilisez `apothem update --harness gemini-cli --project <path>` pour chaque modification ultérieure.
