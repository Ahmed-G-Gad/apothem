Kiro lit le pilotage depuis un répertoire `.kiro/steering/` de fichiers Markdown.
L'adaptateur kiro d'Apothem rend un fichier de pilotage `apothem-rules.md` dédié à
partir du profil partagé. Cette page oppose la maintenance manuelle de cette
configuration à sa gestion avec Apothem.

## Comparaison de l'effort

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Rédiger les règles de pilotage | Écrire à la main chaque fichier sous `.kiro/steering/` | Rendues depuis le corpus partagé |
| Garder intacts les fichiers de fondation | Penser à ne pas écraser `product.md` / `tech.md` / `structure.md` | L'adaptateur n'écrit que `apothem-rules.md` |
| Garder les règles alignées avec les autres environnements | Manuel, par outil | Automatique lors de `apothem update` |
| Partager des skills et des commandes réutilisables | Copier à la main chaque dossier de skill dans `~/.kiro/skills/` et garder les copies à jour | Écrits dans `~/.kiro/skills/` par l'adaptateur, une seule copie pour tous les projets, et actualisés lors de `apothem update` |
| Garder les auxiliaires réutilisables synchronisés | Écrire à la main chaque fichier d'agent personnalisé sous `.kiro/agents/` et suivre les catégories d'outils de Kiro | Quatorze auxiliaires écrits dans `.kiro/agents/` avec leurs outils traduits, et actualisés lors de `apothem update` |
| Vérifier que la configuration est correcte | Inspection manuelle | `apothem verify --harness kiro --project <path>` |

## Ce qu'Apothem gère

L'adaptateur kiro rend les règles partagées dans un fichier de pilotage
`apothem-rules.md` dédié avec un front matter `inclusion: always` et ne touche pas aux
fichiers de fondation rédigés par l'opérateur de Kiro. Il écrit aussi les quatorze
auxiliaires d'Apothem sous forme d'agents personnalisés Kiro dans
`<project>/.kiro/agents/`, pour Kiro IDE 1.0 et Kiro CLI V3. Kiro documente des
hooks d'agent, que l'adaptateur n'écrit pas, l'intention de garde-fou réside donc dans la prose des règles plutôt que dans un point
d'interception des appels d'outil. Chaque modification des règles partagées rend à
nouveau le fichier lors du prochain `apothem update`.

## Chemin de migration

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez pas encore fait.
2. Déplacez les règles de votre `.kiro/steering/` existant vers le corpus partagé.
3. Exécutez `apothem install --harness kiro --project <path>` pour générer le fichier de pilotage `apothem-rules.md`.
4. Exécutez `apothem verify --harness kiro --project <path>` pour confirmer que la configuration est bien en place.
5. Utilisez `apothem update --harness kiro --project <path>` pour chaque modification ultérieure.
