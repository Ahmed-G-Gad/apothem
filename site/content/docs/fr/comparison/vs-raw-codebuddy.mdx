CodeBuddy lit les règles de projet depuis `.codebuddy/rules/*.md`. Vous pouvez rédiger ces fichiers à la main, par projet, pour toujours. L'adaptateur codebuddy d'Apothem en génère un à partir du profil partagé et le maintient cohérent dans chaque environnement et dans chaque projet. Cette page oppose la maintenance manuelle de cette configuration à sa gestion avec Apothem.

## Comparaison de l'effort

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Rédiger les règles | Copier-coller les mêmes disciplines dans `.codebuddy/rules/` pour chaque projet | Générées à partir d'un seul corpus partagé |
| Source de vérité | Les fichiers propres à chaque projet | Une cohorte canonique |
| Garder les règles alignées entre environnements | Re-dériver pour chaque outil | Projetées automatiquement |
| Mettre à jour les règles | Modifier à la main chaque projet | `apothem update --harness codebuddy --project <path>` |
| Supprimer la configuration | Suppression manuelle | `apothem uninstall` avec sauvegarde horodatée |
| Partager des skills et des commandes réutilisables | Copier à la main chaque dossier de skill dans `~/.codebuddy/skills/` et garder les copies à jour | Écrits dans `~/.codebuddy/skills/` par l'adaptateur, une seule copie pour tous les projets, et actualisés lors de `apothem update` |

## Ce qu'Apothem gère

L'adaptateur codebuddy génère les règles partagées dans un fichier dédié `<project>/.codebuddy/rules/apothem-rules.md`. Il écrit aussi deux dossiers de votre répertoire personnel que tous les projets partagent : les skills, ainsi que les commandes enveloppées sous forme de skills, vont dans `~/.codebuddy/skills/`, et les règles et templates que ces skills citent vont dans `~/.config/apothem/rules/` et `~/.config/apothem/templates/`. Votre fichier de mémoire `CODEBUDDY.md`, vos permissions et serveurs MCP dans `.codebuddy/settings.json`, ainsi que tout autre fichier de règles que vous rédigez restent entièrement la propriété de l'opérateur : l'adaptateur reconnaît ces surfaces mais ne les modifie jamais. Chaque modification des règles partagées régénère le fichier de règles lors du prochain `apothem update`.

## Chemin de migration

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez pas encore fait.
2. Déplacez les disciplines de vos fichiers `.codebuddy/rules/` existants dans le
   corpus partagé.
3. Exécutez `apothem install --harness codebuddy --project <path>` pour générer le
   fichier `apothem-rules.md` à côté de vos propres règles, laissées intactes.
4. Exécutez `apothem verify --harness codebuddy --project <path>` pour confirmer que la
   configuration a bien été installée.
5. Utilisez `apothem update --harness codebuddy --project <path>` pour chaque
   modification ultérieure.
