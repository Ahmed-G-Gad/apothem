Zed lit les instructions de l'agent depuis un unique fichier plat `.rules` à la
racine du projet (aux côtés de la famille `AGENTS.md` / `CLAUDE.md`). L'adaptateur
zed d'Apothem rend ce fichier depuis le profil partagé. Cette page oppose la
maintenance manuelle de cette configuration à sa gestion avec Apothem.

## Comparaison de l'effort

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Écrire des instructions | Écrire à la main le fichier `.rules` | Rendu depuis le corpus partagé |
| Préserver un `.rules` antérieur | Penser à le copier de côté vous-même | L'adaptateur sauvegarde le fichier existant avant le remplacement |
| Garder les règles alignées avec d'autres environnements | Manuel, par outil | Automatique lors de `apothem update` |
| Vérifier que la configuration est correcte | Inspection manuelle | `apothem verify --harness zed` |

## Ce qu'Apothem gère

L'adaptateur zed rend les règles partagées dans le fichier plat `.rules` de la
racine du projet. Zed n'a pas de hook PreToolUse, de sorte que l'intention de
garde-fou vit dans la prose de la règle plutôt qu'à un point d'interception
d'appel d'outil. Le fichier d'instructions global `~/.config/zed/AGENTS.md` et le
bloc serveur de contexte MCP de `.zed/settings.json` appartiennent à l'opérateur
et sont laissés intacts. Chaque changement des règles partagées rend de nouveau le
fichier lors du prochain `apothem update`.

## Chemin de migration

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez
   pas encore.
2. Déplacez les instructions de votre `.rules` existant (et tout contenu
   `AGENTS.md` spécifique au projet que vous voulez partager) vers le corpus
   partagé.
3. Exécutez `apothem install --harness zed` pour rendre le fichier `.rules`. Votre
   `.rules` antérieur est sauvegardé d'abord.
4. Exécutez `apothem verify --harness zed` pour confirmer que la configuration a
   été installée.
5. Utilisez `apothem update --harness zed` pour chaque modification ultérieure.
