Cursor lit des règles au format MDC sous `.cursor/rules/`. Le format MDC exige
des champs de frontmatter — `description`, `globs` et `alwaysApply`. L'adaptateur
cursor d'Apothem rend un seul fichier de règles `.mdc` depuis le profil partagé.
Cette page oppose la maintenance manuelle de cette configuration à sa gestion avec Apothem.

## Comparaison des efforts

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Rédiger les règles | Rédiger à la main chaque fichier `.mdc` sous `.cursor/rules/` | Rendues depuis le corpus partagé |
| Écrire le frontmatter MDC | Rédiger à la main `description` / `globs` / `alwaysApply` pour chaque fichier | Généré par l'adaptateur |
| Garder un seul format de règles | Choisir à la main entre les règles MDC et un fichier unique `.cursorrules` | L'adaptateur écrit un seul fichier MDC, `.cursor/rules/apothem-rules.mdc`, et aucun `.cursorrules` |
| Garder les règles alignées avec les autres environnements | Manuel, par outil | Automatique lors de `apothem update` |
| Partager des skills et des commandes réutilisables | Copier à la main chaque dossier de skill dans `~/.agents/skills/` et garder les copies à jour | Écrits dans `~/.agents/skills/` par l'adaptateur, une seule copie pour tous les projets, et actualisés lors de `apothem update` |
| Vérifier que la configuration est correcte | Inspection manuelle | `apothem verify --harness cursor --project <path>` |

## Ce qu'Apothem gère

L'adaptateur cursor rend les règles partagées en un seul fichier `.mdc`,
`<project>/.cursor/rules/apothem-rules.mdc`, en générant le frontmatter MDC requis
(`description`, `globs`, `alwaysApply`). L'adaptateur n'écrit que le format MDC
basé sur les répertoires que Cursor lit ; il n'écrit pas de fichier unique
`.cursorrules`. Il écrit aussi les skills, ainsi que les commandes enveloppées
sous forme de skills, dans `~/.agents/skills/`, et les règles et templates que ces
skills citent dans `~/.config/apothem/`, tous deux dans votre répertoire personnel.
Cursor documente les hooks dans des fichiers `hooks.json` et via son format de
plugin. L'adaptateur ne construit aucun plugin ; il ajoute une seule entrée
`sessionStart` au fichier `.cursor/hooks.json` du projet, qui charge l'amorçage de
session, et laisse vos propres entrées telles quelles. Il n'enregistre aucune
garde d'appel d'outil, donc l'intention des garde-fous réside dans la prose des
règles.

## Chemin de migration

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez pas encore fait.
2. Déplacez les règles de votre `.cursor/rules/` existant (et de tout `.cursorrules`) vers le corpus partagé.
3. Exécutez `apothem install --harness cursor --project <path>` pour générer `apothem-rules.mdc` avec le frontmatter MDC correct.
4. Exécutez `apothem verify --harness cursor --project <path>` pour confirmer que la configuration est bien en place.
5. Utilisez `apothem update --harness cursor --project <path>` pour chaque modification ultérieure.
