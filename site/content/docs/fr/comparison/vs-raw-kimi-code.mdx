Kimi Code reads project-root `AGENTS.md` as its instruction file and keeps
project configuration under `<project>/.kimi-code/`, including the
operator-owned `.kimi-code/mcp.json` MCP surface. You can author that
instruction file and its supporting cohorts by hand, per project, forever.
Apothem's kimi-code adapter renders the governance surface into `AGENTS.md` as a
managed block from the shared profile and keeps it consistent across every
harness and every project. This page contrasts hand-maintaining that config
against managing it with Apothem.

## Effort comparison

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Rédiger la surface d'instructions `AGENTS.md` | Rédiger et resynchroniser à la main pour chaque projet | Un bloc géré unique, rendu à partir du profil partagé |
| Garder règles, commandes, skills et agents synchronisés | Copie manuelle par projet | Matérialisés sous `<project>/.kimi-code/.apothem/support/` à chaque installation |
| Conserver la prose de l'opérateur lors d'une actualisation | Fusion manuelle | Bloc délimité par des marqueurs sentinelles ; la prose de l'opérateur hors de ce bloc est conservée |
| Garder les règles alignées avec les autres environnements | Manuel, par outil | Automatique lors de `apothem update` |
| Vérifier que la configuration est correcte | Inspection manuelle | `apothem verify --harness kimi-code --project <path>` |

## What Apothem manages

The kimi-code adapter renders the shared rules and governance surface into the
project-root `AGENTS.md` managed block and installs the commands, skills, hooks,
agents, rules, and templates cohorts under `.kimi-code/.apothem/support/`. It does not
author `.kimi-code/mcp.json`; the MCP surface stays operator-owned. The rendered
instruction surface drives the project directly. Every change to the shared
rules re-renders the files on the next `apothem update`.

## Migration path

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez pas encore fait.
2. Déplacez les règles de votre `AGENTS.md` existant vers le corpus partagé.
3. Exécutez `apothem install --harness kimi-code --project <path>` pour générer la surface d'instructions `AGENTS.md` et l'arborescence de support `.kimi-code/.apothem/support/`.
4. Exécutez `apothem verify --harness kimi-code --project <path>` pour confirmer que la configuration est bien en place.
5. Utilisez `apothem update --harness kimi-code --project <path>` pour chaque modification ultérieure.
