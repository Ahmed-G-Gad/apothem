Kimi Code lit le fichier `AGENTS.md` à la racine du projet comme son fichier
d'instructions et conserve la configuration du projet sous
`<project>/.kimi-code/`, y compris la surface MCP `.kimi-code/mcp.json`, qui
appartient à l'opérateur. Vous pouvez rédiger ce fichier d'instructions et ses
cohortes de support à la main, projet par projet, indéfiniment. L'adaptateur
kimi-code d'Apothem rend la surface de gouvernance dans `AGENTS.md` sous la forme
d'un bloc géré, à partir du profil partagé, et la garde cohérente entre tous les
environnements et tous les projets. Cette page oppose la maintenance manuelle de
cette configuration à sa gestion avec Apothem.

## Comparaison de l'effort

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Rédiger la surface d'instructions `AGENTS.md` | Rédiger et resynchroniser à la main pour chaque projet | Un bloc géré unique, rendu à partir du profil partagé |
| Garder règles, commandes, skills et agents synchronisés | Copie manuelle par projet | Matérialisés sous `<project>/.kimi-code/.apothem/support/` à chaque installation |
| Conserver la prose de l'opérateur lors d'une actualisation | Fusion manuelle | Bloc délimité par des marqueurs sentinelles ; la prose de l'opérateur hors de ce bloc est conservée |
| Garder les règles alignées avec les autres environnements | Manuel, par outil | Automatique lors de `apothem update` |
| Vérifier que la configuration est correcte | Inspection manuelle | `apothem verify --harness kimi-code --project <path>` |

## Ce qu'Apothem gère

L'adaptateur kimi-code rend les règles partagées et la surface de gouvernance dans
le bloc géré du fichier `AGENTS.md` à la racine du projet, et installe les
cohortes de commandes, de skills, de hooks, d'agents, de règles et de templates
sous `.kimi-code/.apothem/support/`. Il ne rédige pas `.kimi-code/mcp.json` ; la
surface MCP reste la propriété de l'opérateur. Kimi Code lit les instructions du
projet depuis `AGENTS.md` ou `.kimi-code/AGENTS.md` ; l'adaptateur n'écrit que le
fichier `AGENTS.md` à la racine du projet, et la documentation de Kimi Code ne
précise pas lequel des deux fichiers l'emporte lorsque les deux existent. Chaque
changement des règles partagées rend de nouveau les fichiers lors du prochain
`apothem update`.

## Chemin de migration

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez pas encore fait.
2. Déplacez les règles de votre `AGENTS.md` existant vers le corpus partagé.
3. Exécutez `apothem install --harness kimi-code --project <path>` pour générer la surface d'instructions `AGENTS.md` et l'arborescence de support `.kimi-code/.apothem/support/`.
4. Exécutez `apothem verify --harness kimi-code --project <path>` pour confirmer que la configuration est bien en place.
5. Utilisez `apothem update --harness kimi-code --project <path>` pour chaque modification ultérieure.
