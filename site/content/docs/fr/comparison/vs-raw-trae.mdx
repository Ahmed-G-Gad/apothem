Trae lit les règles depuis un répertoire `.trae/rules/` dont les ancres du fournisseur
sont `project_rules.md` et `user_rules.md`. L'adaptateur trae d'Apothem rend un fichier
`apothem-rules.md` dédié dans ce répertoire à partir du profil partagé. Cette page
oppose la maintenance manuelle de cette configuration à sa gestion avec Apothem.

## Comparaison de l'effort

| Tâche | Configuration manuelle | Géré par Apothem |
| ---- | --------------- | --------------- |
| Rédiger les règles | Écrire à la main chaque fichier sous `.trae/rules/` | Rendues depuis le corpus partagé |
| Garder la surface d'Apothem séparée | Penser à ne pas surcharger `project_rules.md` | L'adaptateur écrit un `apothem-rules.md` dédié |
| Garder les règles alignées avec les autres environnements | Manuel, par outil | Automatique lors de `apothem update` |
| Partager des skills et des commandes réutilisables | Copier à la main chaque dossier de skill dans `~/.trae/skills/` et garder les copies à jour | Écrits dans `~/.trae/skills/` par l'adaptateur, une seule copie pour tous les projets, et actualisés lors de `apothem update` |
| Vérifier que la configuration est correcte | Inspection manuelle | `apothem verify --harness trae --project <path>` |

## Ce qu'Apothem gère

L'adaptateur trae rend les règles partagées dans un fichier `apothem-rules.md` dédié
sous `.trae/rules/` et laisse intactes les ancres `project_rules.md` et
`user_rules.md` détenues par l'opérateur. Trae n'a pas de hook PreToolUse, l'intention
de garde-fou réside donc dans la prose des règles plutôt que dans un point
d'interception des appels d'outil. Chaque modification des règles partagées rend à
nouveau le fichier lors du prochain `apothem update`.

## Chemin de migration

1. Exécutez `apothem profile init` pour créer le profil partagé si vous ne l'avez pas encore fait.
2. Déplacez les règles de vos fichiers `.trae/rules/` existants vers le corpus partagé.
3. Exécutez `apothem install --harness trae --project <path>` pour générer le fichier `apothem-rules.md`.
4. Exécutez `apothem verify --harness trae --project <path>` pour confirmer que la configuration est bien en place.
5. Utilisez `apothem update --harness trae --project <path>` pour chaque modification ultérieure.
