**Rôle :** Auditeur de performance
**Position dans le pipeline :** forteresse

Audite les budgets de performance par classe (runtime des hooks, verify-ecosystem, portail de conformité, tests, travailleurs délégués, shell, lint), selon la méthode USE.

## Invocation canonique

```bash
/perf-audit
```

Avec des arguments :

```bash
/perf-audit [path/to/repo/] [--focus CLASS] [--dry-run]
```

## Entrées

Dépôt hôte qui contient `hooks/`, `src/apothem/benchmarks/`, `tests/` et les stubs d'amorçage des hooks `hooks/lib/bootstrap.{sh,ps1}`

## Sorties

Constats de performance dans `_inputs/perf-audit-findings.md`

## En aval

L'étape d'audit de performance de la Séquence de Revue d'Audit

## Phases du flux de travail

La commande exécute cinq phases d'audit : ingestion des entrées, découverte des budgets par classe, exécution des benchmarks, identification des chemins critiques par la méthode USE, et émission des constats avec le portail de validation.

## Modes d'échec

| Symptôme | Cause | Récupération |
|---------|-------|----------|
| Portail de qualité FAIL | La sortie ne respecte pas les normes | Corrigez la sortie et relancez |
| Fichier d'entrée manquant | Le dépôt ne contient pas `src/apothem/benchmarks/` | Ajoutez les pilotes de benchmarks, puis relancez ; la commande refuse de s'exécuter tant qu'ils n'existent pas |

## Exemples

```bash
# Dry-run to preview what would happen
/perf-audit --dry-run

# Execute against a repository root
/perf-audit path/to/repo/
```
