**Rôle :** Réviseur UX
**Position dans le pipeline :** forteresse

Revue de l'expérience développeur portant sur l'ergonomie de la CLI, la documentation et la prise en main.

## Invocation canonique

```bash
/ux-review
```

Avec arguments :

```bash
/ux-review [path/to/plan-suite/] [phase-id] [--dry-run]
```

## Entrées

Dépôt hôte dans n'importe quel état de cycle de vie

## Sorties

Constats UX + REPORT.md

## En aval

L'étape de revue UX de la Séquence d'Audit de Revue

## Phases du flux de travail

La commande suit le flux de travail standard du pipeline `/plan` :

1. **Charger le contexte** — Lire la suite de plan, les règles et le Contrat de Reprise.
2. **Vérifier les prérequis** — Confirmer que les phases dépendantes sont achevées.
3. **Exécuter les tâches** — Accomplir la mission de la commande.
4. **Vérifier les sorties** — Confirmer que toutes les sorties déclarées existent et passent les portes qualité.
5. **Mettre à jour PROGRESS.md** — Consigner les sorties vérifiées dans le Registre des Sorties de Phase.
6. **Émettre REPORT.md** — Preuve de publication de la porte de pré-émission consignée.

## Modes de défaillance

| Symptôme | Cause | Récupération |
|---------|-------|----------|
| Prérequis incomplet | Phase dépendante non terminée | Achevez d'abord la phase amont |
| Porte qualité FAIL | La sortie ne respecte pas les standards | Corrigez la sortie et relancez |
| Fichier d'entrée manquant | Fichier de la suite de plan absent | Exécutez `/plan-generate` pour le créer |

## Exemples

```bash
# Dry-run to preview what would happen
/ux-review --dry-run

# Execute against a named plan suite
/ux-review path/to/plan-suite/
```
