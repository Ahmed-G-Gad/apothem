**Rôle :** Auditeur d'accessibilité
**Position dans le pipeline :** forteresse

Audit d'accessibilité par rapport à WCAG 2.2 AA pour chaque page rendue.

## Invocation canonique

```bash
/a11y-audit
```

Avec des arguments :

```bash
/a11y-audit [path/to/site/ or URL] [--focus PAGE_OR_DIR] [--dry-run]
```

## Entrées

Site web du projet déployé ou servi localement

## Sorties

Constats d'accessibilité (A11y) dans `_inputs/a11y-audit-findings.md`

## En aval

L'étape d'audit d'accessibilité de la Séquence de Revue d'Audit

## Phases du flux de travail

La commande exécute cinq phases d'audit : ingestion des entrées, audit page par page, tri constat par constat, émission des constats, et le portail de validation.

## Modes d'échec

| Symptôme | Cause | Récupération |
|---------|-------|----------|
| Portail de qualité FAIL | La sortie ne respecte pas les normes | Corrigez la sortie et relancez |
| Fichier d'entrée manquant | Le chemin du site ou l'URL ne se résout pas | Passez un répertoire de site compilé ou une URL accessible |

## Exemples

```bash
# Dry-run to preview what would happen
/a11y-audit --dry-run

# Execute against a built site directory
/a11y-audit path/to/site/
```
