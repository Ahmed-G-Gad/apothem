## Supprimer d'abord les configurations d'environnement

La commande `apothem` nue utilisée sur cette page est le shim que l'installateur en une étape (canal 3 du [guide d'installation](/docs/install)) écrit ; elle s'exécute dès que le répertoire de ce shim figure dans `PATH`. Sur les autres canaux d'installation, remplacez `apothem` par `npx @ahmed-g-gad/apothem`, comme le décrit le guide d'installation.

Avant de désinstaller Apothem, supprimez la configuration de chaque adaptateur
d'environnement afin de laisser vos environnements dans un état propre.
Exécutez `apothem harnesses list` pour voir quels adaptateurs sont actuellement
installés, puis supprimez-les un par un ou utilisez le sélecteur couvrant tout
le registre :

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness cursor --project /path/to/project
apothem uninstall --harness all --project /path/to/project --yes
```

Passez `--yes` pour ignorer l'invite de confirmation par environnement.

## Supprimer le moteur

La suppression dépend du canal d'installation que vous avez utilisé. Les numéros
de canal sont ceux du
[tableau des canaux d'installation](/docs/install#choisir-un-canal) :

- **Plugin Claude Code (canal 1)** — supprimez le plugin depuis Claude Code :
  `/plugin uninstall apothem@apothem` (l'entrée de marketplace peut être
  supprimée avec `/plugin marketplace remove ahmed-g-gad/apothem`).
- **npx (canal 2)** — rien à supprimer ; `npx` s'exécute depuis son cache.
  Videz-le avec `npm cache clean --force` si vous voulez supprimer la copie
  en cache.
- **Installateur en une seule étape (canal 3)** — exécutez le script de
  désinstallation correspondant depuis le checkout :
  `scripts/installer/uninstall.sh` (POSIX) ou
  `scripts/installer/uninstall.ps1` (PowerShell). Chaque script supprime
  l'environnement nommé par `--harness` (`-Harness` sous PowerShell), sinon
  `APOTHEM_HARNESS`, sinon Claude Code. Il supprime aussi le shim de commande
  `apothem`. La source provient de `APOTHEM_SOURCE` lorsque cette variable est
  définie, ou de `APOTHEM_HOME` (par défaut `$HOME/.apothem`). La source reste en
  place, sauf si vous passez `--remove-source` (`-RemoveSource` sous PowerShell).
  Cet indicateur ne supprime que le clone géré situé dans `APOTHEM_HOME`, et
  seulement lorsqu'il contient un répertoire `.git`. Avec l'emplacement par
  défaut, il supprime aussi les sauvegardes d'installation et le journal situé
  sous `~/.apothem/`. Les deux demandent confirmation avant de supprimer les
  configurations d'environnement et la source. `--yes` (`-Yes` sous PowerShell)
  ignore ces invites. Les deux refusent les cibles non sûres.
- **Extension de la famille VS Code (canal 4)** — exécutez d'abord
  **Apothem: Uninstall** depuis la palette de commandes pour supprimer les
  configurations d'environnement, puis supprimez l'extension depuis la vue
  Extensions ou avec `code --uninstall-extension ahmed-g-gad.apothem-vscode`
  (une copie installée depuis un `apothem.vsix` antérieur porte l'identifiant
  `ahmed-g-gad.apothem`). Par défaut, l'extension exécute le moteur via `npx` ;
  l'entrée **npx** ci-dessus couvre donc le cache.
- **Amorçages en ligne de commande (canaux 5–7)** — supprimez l'extension ou le
  plugin avec son outil hôte une fois les configurations d'environnement
  supprimées. Les hôtes :

  ```text
  channel 5   Gemini CLI extension
  channel 6   Qwen Code extension
  channel 7   Codex plugin
  ```

  L'amorçage ajoute seulement un contexte d'assistant (un fichier de contexte,
  une commande ou un skill) qui appelle le moteur via `npx` ; il ne reste donc
  rien d'autre. Les hôtes d'extensions des canaux 5 et 6 acceptent une commande
  de désinstallation ; pour l'hôte de plugins du canal 7, désinstallez `apothem`
  dans son navigateur de plugins.

  ```bash
  gemini extensions uninstall apothem   # channel 5
  qwen extensions uninstall apothem     # channel 6
  ```
- **Moteur direct (canal 8)** — rien à désinstaller ; supprimez le clone une
  fois les configurations d'environnement supprimées.
- **Sauvegardes et état** — les sauvegardes d'installation se trouvent sous
  `~/.apothem/backups/` et le journal d'installation sous `~/.apothem/state/`.
  Les deux restent bornés : après chaque installation, désinstallation et
  retour arrière, Apothem conserve les 10 enregistrements d'installation les
  plus récents par racine d'installation et les 10 ensembles de sauvegardes les
  plus récents par environnement, et ne supprime jamais une sauvegarde dont un
  enregistrement conservé a encore besoin, de sorte que les 10 dernières
  installations peuvent toujours faire l'objet d'un retour arrière. Pour en
  conserver moins, exécutez
  [`apothem backups prune --keep N`](/docs/cli-reference/backups) (ajoutez
  `--dry-run` pour voir d'abord ce que la commande supprimerait) ; elle ne supprime
  jamais la sauvegarde à partir de laquelle le retour arrière de la dernière
  installation d'un environnement effectue sa restauration. Une fois le moteur
  supprimé, et lorsque vous n'avez plus besoin d'aucune partie de l'historique,
  supprimez `~/.apothem/`.

## Ce qui n'est PAS supprimé

- Le fichier YAML du profil partagé à `~/.config/apothem/profile.yaml` ou
  `--profile PATH` n'est jamais supprimé par `apothem uninstall`.
- Les fichiers sans rapport rédigés par l'opérateur dans les répertoires
  d'environnement sont préservés.
- Les entrées que vous avez ajoutées à un fichier de paramètres partagé sont
  préservées : vos propres règles de permission, serveurs MCP et gestionnaires
  de hooks restent en place. La désinstallation ne supprime que les clés et les
  entrées de liste que le journal d'installation consigne comme appartenant à
  Apothem (voir
  [Paramètres](/docs/reference/settings#fusion-dans-votre-propre-fichier-de-settings)).
- Les magasins de données partagés sous `.apothem/` à la racine d'installation
  (`memory/`, `contexts/`, `learning/`) restent en place tant qu'un autre
  environnement installé à la même racine les utilise encore. La désinstallation
  du dernier environnement à cette racine copie d'abord chaque magasin dans
  `~/.apothem/backups/`, puis le supprime avec tout son contenu.
- Les suites de planification sous `<project>/.apothem/plans/` (et l'ancien `<project>/.plans/`) ne sont pas affectées.

## Répertoires

La désinstallation supprime aussi les répertoires que l'installation a créés
(par exemple un `~/.claude/` qui n'existait pas avant la première installation),
une fois qu'ils sont vides. Un répertoire qui contient encore l'un de vos
fichiers, ou des données qu'utilise un autre environnement installé, est
conservé. Les répertoires qui existaient avant l'installation ne sont jamais
supprimés.

Pour nettoyer entièrement la racine d'un environnement, supprimez le chemin
natif de l'environnement documenté sur les
[pages de référence des environnements](/docs/harnesses) après avoir vérifié que
vous avez sauvegardé toutes les règles, tous les auxiliaires ou fichiers de
profil personnalisés que vous souhaitez conserver.
