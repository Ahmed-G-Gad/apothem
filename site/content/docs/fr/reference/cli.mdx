La CLI `apothem` est l'interface principale de l'opérateur pour gérer le profil
partagé et les adaptateurs d'environnement.

## Options globales

| Option | Description |
|------|-------------|
| `--version` | Affiche la version d'Apothem et quitte |
| `--help` | Affiche l'aide de la commande |

## Sous-commandes

### `apothem install`

Installe un adaptateur d'environnement depuis le profil partagé.

```bash
apothem install --harness <name|all> [--profile PATH] [--project PATH] [--dry-run] [--clean|--fresh] [--yes]
```

| Option | Description |
|--------|-------------|
| `--harness <name>` | Nom de l'adaptateur d'environnement (voir les valeurs canoniques ci-dessous). Obligatoire. |
| `--profile PATH` | Chemin vers le YAML du profil partagé. Par défaut, `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. |
| `--dry-run` | Prévisualise l'installation sans écrire de fichiers. |
| `--clean`, `--fresh` | Table rase sur demande explicite : sauvegarde puis supprime l'état d'installation antérieur (`~/.claude`, `~/.codex`, `~/.agents`, `~/.config/apothem`) avant l'installation. |
| `--yes` | Ignore la confirmation par cible lors d'une suppression en table rase (obligatoire pour les exécutions `--clean` non interactives). |

Valeurs canoniques de `--harness` :

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

Utilisez `--harness all --project <path>` pour sélectionner l'ensemble complet du
registre. La liste `exclude_harnesses` du profil est respectée pendant la
sélection par lot d'installation/mise à jour.

### `apothem update`

Re-dérive la configuration native d'un adaptateur d'environnement à partir du
profil partagé actuel.

```bash
apothem update --harness <name|all> [--profile PATH] [--project PATH] [--dry-run]
```

| Option | Description |
|--------|-------------|
| `--harness <name>` | Nom de l'adaptateur d'environnement. Obligatoire. |
| `--profile PATH` | Chemin vers le YAML du profil partagé. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. |
| `--dry-run` | Prévisualise la mise à jour sans écrire de fichiers. |

`update` rematérialise la sortie de l'environnement. Elle ne met pas à jour le
paquet de la CLI d'Apothem ; pour les mises à niveau du paquet, utilisez le
gestionnaire de paquets ayant servi à installer Apothem.

### `apothem uninstall`

Supprime la configuration native d'un adaptateur d'environnement.

```bash
apothem uninstall --harness <name|all> [--project PATH] [--yes]
```

| Option | Description |
|--------|-------------|
| `--harness <name>` | Nom de l'adaptateur d'environnement. Obligatoire. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. |
| `--yes` | Ignore l'invite de confirmation. |

### `apothem verify`

Vérifie que les cibles gérées d'un adaptateur d'environnement sont présentes et
valides.

```bash
apothem verify --harness <name|all> [--profile PATH] [--project PATH]
```

| Option | Description |
|--------|-------------|
| `--harness <name>` | Nom de l'adaptateur d'environnement ou `all`. Obligatoire. |
| `--profile PATH` | YAML du profil partagé par rapport auquel vérifier la fidélité. Sans cette option, la vérification est purement structurelle. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. |

Sans `--profile`, la vérification est structurelle : chaque cible gérée doit être
présente et valide. Avec `--profile`, elle exige en plus la fidélité, de sorte
qu'une installation qui existe mais a dérivé par rapport à ce profil échoue à
verify — utilisez cette option pour confirmer qu'un profil précis est fidèlement
installé.

Le code de sortie est `0` lorsque l'environnement est vérifié (et, avec
`--profile`, fidèle à ce profil), et `1` lorsqu'une cible est manquante ou
invalide, ou lorsque `--profile` est fourni et que l'installation a dérivé.

### `apothem status`

Signale l'état d'installation, de vérification et de dérive de chaque
environnement enregistré.

```bash
apothem status [--profile PATH] [--project PATH]
```

| Option | Description |
|--------|-------------|
| `--profile PATH` | Profil partagé à utiliser comme référence de dérive. Un profil par défaut illisible dégrade la dérive en `unknown` plutôt que d'interrompre le balayage. |
| `--project PATH` | Racine du projet pour les environnements à portée de projet. Sans cette option, ces environnements signalent `needs-project`. |

Chaque ligne associe un indicateur `installed` à un indicateur `verified`, et les
deux se combinent pour donner l'état de dérive :

| État | Signification |
|-------|---------|
| `absent` | Apothem n'a effectué aucune installation dans cet environnement. |
| `in-sync` | Installé et conforme au profil de référence. |
| `drift` | Installé mais plus conforme — corrigez avec `apothem update`. |
| `unknown` | Installé, mais le profil de référence n'a pas pu être lu. |

`installed` répond à « Apothem a-t-il effectué une installation ici ? », et non à
« cet environnement est-il présent sur la machine ? ». Il repose sur les propres
artefacts d'Apothem — le bloc géré à l'intérieur d'une ancre d'instructions et
le contenu de la sous-arborescence `.apothem/` détenue par Apothem —, jamais sur
un fichier détenu par l'éditeur que l'environnement écrit pour lui-même. Un
environnement dont le répertoire de configuration existe mais auquel Apothem n'a
jamais touché signale `absent`, et un environnement désinstallé signale `absent`
même si les répertoires vidés subsistent.

### `apothem profile`

Gère le profil partagé d'Apothem.

```bash
apothem profile show [--profile PATH]
apothem profile init [--profile PATH] [--force]
apothem profile set <key> <value> [--profile PATH]
apothem profile edit [--profile PATH]
```

| Sous-commande | Description |
|------------|-------------|
| `profile init` | Crée un échafaudage de profil minimal valide selon le schéma. |
| `profile show` | Affiche le profil résolu en JSON sur stdout. Avec `--json`, le document commence par `schema_version`. |
| `profile set <key> <value>` | Définit un champ du profil. La valeur est stockée comme chaîne littérale — les mots nus ne sont pas convertis, donc `no` reste `"no"` et `1.0` reste une chaîne —, sauf `true`/`false` et les saisies explicites de liste et de mappage `[...]` / `{...}`. Le profil assemblé est validé selon le schéma avant d'être écrit. |
| `profile edit` | Ouvre le profil dans `$EDITOR` (à défaut, l'éditeur par défaut de la plateforme). |

L'option `--profile PATH` dirige chaque sous-commande vers un autre fichier de
profil. Par défaut, `~/.config/apothem/profile.yaml`.

### `apothem harnesses`

Liste et inspecte les adaptateurs d'environnement enregistrés.

```bash
apothem harnesses list
apothem harnesses show <name>
```

| Sous-commande | Description |
|------------|-------------|
| `harnesses list` | Affiche un tableau de chaque adaptateur enregistré avec son indicateur d'état d'installation et son chemin de sortie. |
| `harnesses show <name>` | Affiche le nom, l'état d'installation et le chemin de sortie d'un adaptateur. |

### `apothem doctor`

Exécute les diagnostics système pour l'installation d'Apothem.

```bash
apothem doctor
```

Affiche la version d'Apothem, l'interpréteur Python, la plateforme, le chemin du profil résolu et un tableau de l'état d'installation par environnement. Le code de sortie vaut `1` dès qu'un contrôle échoue : profil invalide, environnement installé qui ne passe pas la vérification, commande de hook enregistrée qui ne peut pas démarrer, adaptateur qui ne peut pas être chargé ou sondé, ou journal illisible. Un environnement non installé est signalé sans constituer un échec, et les notes informatives ne modifient pas le code de sortie.
