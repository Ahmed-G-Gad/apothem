Les auxiliaires persistants vivent sous forme de fichiers plats dans le
répertoire canonique des auxiliaires, avec le suffixe `<name>.md`. Le chemin
canonique est :

```text
src/apothem/agents/
```

Chaque auxiliaire est un rôle ciblé, tel que la recherche, l'audit, la qualité,
la refactorisation ou la génération de squelettes, doté de ses propres
restrictions d'outils et de son propre prompt système.

Le tableau et la liste de chemins ci-dessous présentent quatre des auxiliaires.
L'inventaire généré à la fin de cette page liste chaque définition d'auxiliaire.

| Auxiliaire | Fichier | Motif | Politique de modèle |
|-------|------|---------|--------------|
| Codebase Explorer | voir le chemin du manifeste ci-dessous | Recherche | sélectionné par l'hôte |
| Convention Auditor | voir le chemin du manifeste ci-dessous | Audit | sélectionné par l'hôte |
| Quality Gate | voir le chemin du manifeste ci-dessous | Qualité | sélectionné par l'hôte |
| Memory Auditor | voir le chemin du manifeste ci-dessous | Audit | sélectionné par l'hôte |

```text
src/apothem/agents/codebase-explorer.md

```

## Contrat de frontmatter

```yaml
---
name: <agent name>
version: <semver>
updated: <YYYY-MM-DD>
description: <one-line role>
tools: <comma-separated tool list>
disallowedTools: <comma-separated deny list>
maxTurns: <integer>
---
```

`tools` est facultatif. Un auxiliaire qui l'omet hérite de chaque outil dont
dispose la session, outils MCP connectés compris, et `disallowedTools` porte sa
limite. Les quatorze auxiliaires livrés listent tous `tools`.

## Serveurs MCP connectés

Un auxiliaire qui liste `tools` ne peut appeler que ce qu'il liste. Claude Code
n'admet un outil MCP dans cette liste que lorsque l'entrée nomme le serveur,
comme dans `mcp__<server>__*` ; un `mcp__*` seul est documenté comme entrée de
`disallowedTools` et nulle part ailleurs. Les noms de serveurs appartiennent à
la personne qui les connecte, de sorte qu'un auxiliaire livré ne peut pas les
nommer.

`citation-auditor` et `research-scout` recherchent des sources savantes. Chacun
est livré avec `tools: Read, Glob, Grep, WebSearch, WebFetch` et refuse les
outils qui écrivent des fichiers, exécutent des commandes, lancent d'autres
auxiliaires ou publient : `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `Bash`,
`PowerShell`, `Monitor`, `Agent`, `Artifact` et les outils de liste de tâches.
Sans réglage de profil, aucun des deux n'atteint un outil MCP, et tous deux
recherchent les sources par la recherche web et la récupération web.

Pour donner à l'un d'eux un index savant connecté, nommez le serveur dans la
clé `agent_mcp_servers` du profil, qui associe un nom d'agent à des noms de
serveurs. L'installation de Claude Code par le moteur (`apothem install`)
ajoute alors une entrée `mcp__<server>__*` par serveur nommé à la ligne `tools`
de cet agent, et ne modifie aucun autre agent. L'installation de Gemini CLI
fait de même avec une entrée `mcp_<server>_*` par serveur dans la liste
d'autorisation `tools` de l'agent, pour un nom de serveur composé de lettres,
de chiffres et de `-`. Sur les deux, un serveur que nomme le propre
`disallowedTools` de l'agent reste refusé. L'entrée admet chaque outil de ce
serveur, y compris ceux qui écrivent, ne nommez donc qu'un serveur auquel vous
faites confiance pour des recherches : les instructions des auxiliaires les
limitent aux appels de recherche, de consultation, de lecture, de vérification
et de résolution, mais l'environnement n'applique que les noms que liste la
ligne `tools`. Un nom pour un agent qui n'existe pas, ou qui n'a pas de ligne
`tools` explicite, est signalé et ignoré.

Les environnements autres que Claude Code et Gemini CLI ignorent la clé.
L'arborescence du plugin Claude Code est assemblée sans profil et conserve la
liste simple, de sorte qu'un utilisateur du plugin définit plutôt un agent de
niveau utilisateur sous `~/.claude/agents/`. La syntaxe du profil, les règles
sur les noms de serveurs et ce contournement se trouvent sur
[Donner à un auxiliaire l'accès aux serveurs MCP](/docs/reference/mcp#donner-à-un-auxiliaire-laccès-aux-serveurs-mcp).

## Conversion par environnement

Un auxiliaire dont l'octroi `tools`, après application de `disallowedTools`,
n'inclut aucun outil de modification de fichiers (`Write`, `Edit`, `MultiEdit`
ou `NotebookEdit`) est en lecture seule. Un auxiliaire sans octroi `tools` est
en lecture seule lorsque `disallowedTools` refuse au moins `Write` et `Edit`.
Chaque environnement qui convertit les auxiliaires applique cette limite
nativement, l'énonce dans les instructions de l'auxiliaire ou retire la mention
de lecture seule :

| Environnement | Limite d'outils | Limite de tours | Modèle et effort |
| --- | --- | --- | --- |
| Claude Code | `tools` / `disallowedTools` tels qu'écrits, plus les éventuelles entrées `mcp__<server>__*` que la clé `agent_mcp_servers` du profil ajoute à une ligne `tools` listée ; sans `tools`, chaque outil est hérité, MCP compris | `maxTurns` | hérité (non défini) |
| Codex | aucune émise ; les instructions de l'auxiliaire l'énoncent, et le bac à sable de la session parente régit les écritures | non disponible | hérité (non défini) |
| Gemini CLI | liste d'autorisation `tools` de noms d'outils Gemini, plus les éventuelles entrées `mcp_<server>_*` que la clé `agent_mcp_servers` du profil ajoute à une liste explicite listée ; sans `tools`, la liste d'autorisation qu'impliquent les refus plus `mcp_*` | `max_turns` | hérité (non défini) |
| Qwen Code | `tools` / `disallowedTools` en noms d'outils Qwen ; sans `tools`, aucune liste n'est émise, de sorte que les outils MCP sont hérités et que les refus s'appliquent | non mappé | `model: inherit` |
| OpenCode | `permission` (`allow` / `deny` par outil) ; les outils MCP ne sont pas restreints | non mappé | hérité (non défini) |
| Antigravity | aucune émise ; la description retire « read-only » | non disponible | hérité (non défini) |
| CodeBuddy | `tools` / `disallowedTools` sous forme de chaînes séparées par des virgules, limitées aux noms d'outils que documente CodeBuddy ; aucune entrée MCP | `maxTurns` | hérité (non défini) |
| Trae | `tools` / `disallowedTools` sous forme de chaînes séparées par des virgules, limitées aux noms d'outils que documente Trae ; aucune entrée MCP | non disponible | hérité (non défini) |
| GitHub Copilot | liste d'autorisation `tools` d'alias Copilot (`read`, `search`, `edit`, `execute`, `web`, `agent`, `todo`) dans laquelle les refus sont intégrés, car Copilot n'a pas de clé de refus ; un alias qui couvre un outil refusé est omis ; aucune entrée MCP | non disponible | hérité (non défini) |
| Cursor | aucune liste d'outils (Cursor n'en a pas) ; `readonly: true` pour les cinq auxiliaires en lecture seule sans `Bash`, et les autres auxiliaires en lecture seule retirent la mention « read-only » | non disponible | hérité (non défini) |
| Kimi Code | `tools` / `disallowedTools` sous forme de listes de noms d'outils Kimi Code (`WebFetch` devient `FetchURL`, `TodoWrite` devient `TodoList` ; les noms pour lesquels Kimi Code n'a pas d'outil sont omis) ; aucune entrée MCP | non disponible | hérité (non défini) |
| Kiro | liste d'autorisation `tools` de catégories d'outils Kiro (`read`, `write`, `shell`, `web`, `subagent`) dans laquelle les refus sont intégrés, car la liste est la seule restriction écrite ; une catégorie qui couvre un outil refusé est omise ; aucune entrée MCP | non disponible | hérité (non défini) |
| Windsurf | liste d'autorisation `allowed-tools` de noms d'outils Devin (`read`, `edit`, `grep`, `glob`, `exec`, `write`) dans laquelle les refus sont intégrés, car Devin n'a pas de clé de refus ; les trois auxiliaires qui ont besoin d'outils web ne sont pas installés ; aucune entrée MCP | non disponible | modèle de sous-agent par défaut de Devin (non défini) |

Hermes et Open-Claw reçoivent les fichiers des auxiliaires comme matériel de
support, et non comme auxiliaires natifs.

## Orchestration

Le déploiement des auxiliaires, le protocole de lancement en parallèle,
l'application du contrat de retour et la discipline d'isolation vivent dans la
règle d'orchestration. L'arbre de répartition par travailleur vit dans la règle
des motifs d'orchestration, §Decision Tree. Chemins canoniques :

```text
src/apothem/rules/agent-orchestration.md
src/apothem/rules/agent-orchestration-patterns.md
```
