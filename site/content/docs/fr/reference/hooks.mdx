Les hooks se déclenchent sur les événements d'outils et chargent des contextes de message que
l'assistant traite comme des prompts système supplémentaires. Le câblage vit dans
le bloc de hooks du `settings.json` de Claude Code, le fichier de hooks `hooks.json` de Codex
et la table de hooks du `settings.json` de Qwen Code.

| Événement | Délai d'attente | Objectif |
|-------|--------:|---------|
| SessionStart | 30 secondes | Lire la mémoire, vérifier l'état du plan, signaler la disponibilité |
| PreCompact | 30 secondes | Vérifier que l'état est externalisé avant la compaction |
| PostCompact | 30 secondes | Restaurer l'état de travail après la compaction |
| Stop | 60 secondes | Externalisation en fin de session |
| PreToolUse (Bash) | 10 secondes | Validation de Bash — isolation des artefacts git |
| PreToolUse (Write/Edit/NotebookEdit/apply_patch) | 10 secondes | Isolation des références aux plans, vérifications de frontmatter |

## Répartiteur

Les entrées de hook installées invoquent le répartiteur par le chemin absolu du script.
Les modèles de réglages portent le jeton `${HARNESS_ROOT}` —
`python "${HARNESS_ROOT}/apothem/hooks/dispatch.py" <event> [<message-name>]`
— que l'installateur rend en chemin réel de la racine du harness au moment
de l'installation (Claude Code et Qwen Code matérialisent le répartiteur sous
`<harness-root>/apothem/hooks/` ; Codex sous `<harness-root>/hooks/`). Le
répartiteur est un script autonome de la bibliothèque standard : il amorce son propre `sys.path`,
de sorte qu'aucun paquet `apothem` importable n'est nécessaire sur l'hôte. Depuis un
checkout des sources, la forme de module `python -m apothem.hooks.dispatch <event>` (avec
`PYTHONPATH=src`) exécute le même code pour le développement. Le répartiteur charge
`hooks/lib/resolve_root.py` pour la résolution de la racine de l'écosystème et délègue à
`hooks/emit_hook_context.py` et `hooks/session_start_bootstrap.py`.

## Contextes de message

Les contextes Markdown par événement vivent sous `src/apothem/hooks/messages/` :

- `postcompact.md`, `precompact.md`, `stop.md`
- `pretooluse-bash.md`, `pretooluse-write.md`, `pretooluse-edit.md`,
  `pretooluse-notebookedit.md`

Chaque fichier de contexte est chargé par le répartiteur lorsque son événement se déclenche
et que son argument de contexte est enregistré dans le fichier de réglages.
