Apothem est un gestionnaire de configuration d'environnements indépendant de
l'hôte. Vous rédigez un seul profil partagé dans
`~/.config/apothem/profile.yaml`, et Apothem le matérialise dans la surface de
configuration native de dix-sept environnements : Claude Code, Cursor,
Gemini CLI, GitHub Copilot, Codex, Windsurf, Zed et le reste du catalogue
enregistré.

L'unité qu'Apothem synchronise est plus large que les seules règles : les règles,
les commandes slash, les skills, les hooks, les output-styles, les settings
(avec les serveurs MCP), les schémas et la documentation voyagent ensemble comme
un seul corpus gouverné, matérialisé dans le format natif de chaque environnement
ou dans une sous-arborescence de support propre à Apothem lorsque l'outil n'a pas
de primitive équivalente.

## Vous débutez ? Commencez en deux étapes

1. **[Installation](/docs/install/quickstart)** — choisissez une voie
   d'installation (plugins et extensions natifs des outils, `npx` ou scripts en une
   seule étape) et lancez la première étape guidée. Les seuls prérequis sont
   [Node.js](https://nodejs.org/) et Python 3.10 ou plus récent du système.
2. **[Atteignez votre première exécution fonctionnelle](/docs/tutorials/getting-started)** —
   rédigez un profil partagé, matérialisez-en la configuration native d'un
   environnement et vérifiez le résultat. Environ quinze minutes, de bout en bout.

## Comment fonctionne Apothem

- **Un profil, de nombreuses configurations natives.** Vous rédigez l'intention
  une seule fois ; Apothem la traduit dans la surface de configuration native de
  chaque outil, sans aplatissement au plus petit dénominateur commun. Voir
  [la posture indépendante de l'hôte](/docs/concepts/ai-platform-agnosticism).
- **La boucle opératoire : planifier → durcir → livrer.** Un flux de planification
  (`/plan`) fait passer un changement par la spécification, la génération, la
  révision et l'exécution ; un flux de durcissement (`/fortress`) amène ce travail
  à un état verrouillé pour la publication ; la porte de publication ferme la
  boucle. Voir [le flux de commandes](/docs/pipeline).
- **Un travail qui survit aux frontières.** Le travail de longue durée externalise
  tout son état dans une suite `.apothem/plans/` locale au projet, de sorte qu'une nouvelle
  session sur n'importe quel compte ou machine le reprend sur place. Voir
  [la planification reprenable](/docs/concepts/resumable-planning).
