**Éditeur :** Devin Desktop (anciennement Codeium Windsurf)
**Nom d'installation :** `windsurf`
**Statut :** GA
**Configuration native :** `<project>/.devin/rules/apothem-rules.md`

Windsurf est désormais Devin Desktop, et `.devin/rules/` est l'emplacement
privilégié des règles d'espace de travail (il a priorité sur
`.windsurf/rules/`).

## Installation

```bash
apothem install --harness windsurf --project /path/to/project
```

L'adaptateur écrit un fichier de règles Windsurf de portée projet à partir des
règles partagées d'Apothem et de la surface de gouvernance.

**Fichiers écrits :** `<project>/.devin/rules/apothem-rules.md`

## Correspondance entre le profil et la configuration native

L'adaptateur lit le profil partagé d'Apothem et rend le fichier de règles du
projet à chaque exécution de `apothem install` ou de `apothem update`. Le profil
partagé est la source de vérité ; les modifications locales au projet apportées
au fichier généré sont sauvegardées avant que la synchronisation suivante ne
remplace le contenu géré par Apothem.

Le fichier s'ouvre sur son frontmatter `trigger: always_on`, qui définit le mode
d'activation de la règle. Le bloc géré par Apothem le suit ; le texte que vous
ajoutez après le bloc est conservé à chaque synchronisation.

## Notes de compatibilité

La surface de règles actuelle de Windsurf a une portée de projet, sous
`.devin/rules/` (l'emplacement privilégié, qui a priorité sur le repli de
rétrocompatibilité `.windsurf/rules/`). Les flux de travail et les mémoires
locales à la machine sont détenus par l'opérateur ; Apothem ne les écrit pas.
La forme à fichier unique `.windsurfrules` n'est volontairement pas écrite.

## Vérification

```bash
apothem verify --harness windsurf --project /path/to/project
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Chaque cible gérée existe ; les fichiers gérés ne sont pas vides, et les configurations JSON ou YAML s'analysent correctement. Ajoutez `--profile PATH` pour vérifier en plus que les fichiers installés correspondent à ce profil.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness windsurf --project /path/to/project
```

Redérive le fichier de règles du projet à partir de l'état actuel du profil
partagé.

## Désinstallation

```bash
apothem uninstall --harness windsurf --project /path/to/project
```

Supprime les fichiers de configuration native écrits par l'adaptateur.
Le YAML du profil partagé et le moteur Apothem ne sont pas affectés.

## Portail de conformité

```bash
python -m apothem.conformity.gate --all .
```

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness windsurf --project /path/to/project` |
| Échec de la vérification | Exécutez `apothem update --harness windsurf --project /path/to/project`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez `apothem update --harness windsurf --project /path/to/project` |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
