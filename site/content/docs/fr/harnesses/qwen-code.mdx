**Éditeur :** Alibaba Cloud
**Nom d'installation :** `qwen-code`
**Statut :** Bêta
**Configuration native :** `~/.qwen/`

## Installation

```bash
apothem install --harness qwen-code
```

L'adaptateur écrit les settings de Qwen Code, installe une ancre de contexte
`QWEN.md`, enregistre les répartiteurs de hooks Apothem, convertit les commandes
Apothem en fichiers de commande Markdown Qwen, installe les skills sous forme de
répertoires SKILL.md et adapte les définitions d'auxiliaires en sous-assistants
Qwen.

**Fichiers écrits :**

```text
~/.qwen/settings.json
~/.qwen/QWEN.md
~/.qwen/apothem/rules/00-apothem-profile.md
~/.qwen/commands/
~/.qwen/skills/
~/.qwen/agents/
~/.qwen/.apothem/support/{rules,templates,hooks}/
```

Le fichier `~/.qwen/apothem/rules/00-apothem-profile.md` est le document de
profil. Il porte votre identité et vos préférences issues du profil partagé.

## Correspondance entre le profil et la configuration native

L'adaptateur rend les clés documentées de `settings.json` pour le contexte et
les hooks, écrit `QWEN.md` et intègre les commandes, les skills et les
définitions d'auxiliaires Apothem dans les répertoires de découverte natifs de
Qwen Code. Les règles, les templates et le matériel source des hooks restent du
matériel de support sous `~/.qwen/.apothem/support/`.

## Notes de compatibilité

`~/.qwen/.apothem/support/` est du matériel de support référencé par `QWEN.md`
et par les commandes de hook des settings ; ce n'est pas un espace de noms de
découverte détenu par l'éditeur.
Le bloc Apothem de `QWEN.md` se termine par une section consacrée aux fichiers
de support Apothem, qui nomme le répertoire absolu sous
`~/.qwen/.apothem/support/` par rapport auquel se résout chaque citation de
style dépôt (`rules/<name>.md`, `templates/...`, `hooks/...`).

**Listes d'outils des skills.** `Qwen Code` lit la liste d'autorisation d'outils
d'un skill dans la clé de frontmatter en camelCase `allowedTools`, et la valeur
doit être une liste YAML. Il ignore la clé à trait d'union `allowed-tools` écrite
pour d'autres agents. Les skills installés portent donc `allowedTools` sous forme
de liste, une entrée par ligne, à la place de la chaîne `allowed-tools` séparée
par des virgules du corpus source. Chaque entrée conserve l'orthographe de la
source, y compris des motifs tels que `Bash(git status *)`. Toutes les autres
clés du skill, ainsi que le corps du skill, sont installés sans modification.

**Dossiers de skills.** L'adaptateur écrit les skills dans `~/.qwen/skills/`.
`Qwen Code` lit aussi `~/.agents/skills/` et, dans un projet, `.qwen/skills/` et
`.agents/skills/`. Lorsque deux dossiers contiennent un skill du même nom, celui
situé sous `.qwen` l'emporte ; un skill Apothem dans `~/.qwen/skills/` a donc
priorité sur un skill du même nom qu'un autre adaptateur a écrit dans
`~/.agents/skills/`.

**Événements de hook.** L'adaptateur raccorde `SessionStart`, `PreToolUse`,
`PreCompact`, `PostCompact` et `Stop`. `Qwen Code` définit 22 événements de hook,
et chacun de ces cinq en fait partie. Trois des 22 (`SessionDelete`,
`TodoCreated` et `TodoCompleted`) n'ont aucun événement `Claude Code` du même nom
(`Claude Code` nomme les événements de todo `TaskCreated` et `TaskCompleted`) ;
l'adaptateur n'en raccorde aucun.

## Vérification

```bash
apothem verify --harness qwen-code
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Chaque cible gérée existe ; les fichiers gérés ne sont pas vides, et les
   configurations JSON ou YAML s'analysent correctement. Ajoutez
   `--profile PATH` pour vérifier en plus que les fichiers installés
   correspondent à ce profil.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness qwen-code
```

Actualise `settings.json`, `QWEN.md`, les commandes natives, les skills, les
sous-assistants et l'arborescence de support Apothem.

## Désinstallation

```bash
apothem uninstall --harness qwen-code
```

Supprime les entrées que l'adaptateur a ajoutées à `~/.qwen/settings.json` (vos
propres clés, vos serveurs MCP et vos gestionnaires de hook restent en place, et
le fichier n'est supprimé que si Apothem l'a créé et qu'il n'y reste plus rien
qui vous appartienne). Supprime le bloc Apothem de `~/.qwen/QWEN.md` et du
document de profil `~/.qwen/apothem/rules/00-apothem-profile.md` et conserve
tout autre texte qu'ils contiennent ; chaque fichier n'est supprimé que si rien
d'autre n'y subsiste. Supprime aussi les fichiers Apothem de
`~/.qwen/commands/`, `~/.qwen/skills/`, `~/.qwen/agents/` et
`~/.qwen/.apothem/support/` ; les autres fichiers de ces dossiers restent en
place. Chaque fichier est sauvegardé sous `~/.apothem/backups/` avant d'être
modifié ou supprimé. Le YAML du profil partagé et le moteur Apothem ne sont pas
affectés.

## Portail de conformité

```bash
python -m apothem.conformity.gate --all .
```

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness qwen-code` |
| Échec de la vérification | Exécutez `apothem update --harness qwen-code`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez `apothem update --harness qwen-code` |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
