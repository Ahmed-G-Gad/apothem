**Éditeur :** Anysphere
**Nom d'installation :** `cursor`
**Statut :** GA
**Configuration native :** `.cursor/rules/` à la racine du projet

## Installation

```bash
apothem install --harness cursor --project /path/to/project
```

L'adaptateur rend un seul fichier de règles `.mdc` de portée projet à partir de
la surface partagée de règles et de gouvernance d'Apothem.

**Fichiers écrits :** `<project>/.cursor/rules/apothem-rules.mdc`

Ce fichier constitue l'intégralité de l'installation : aucun fichier de règle,
de skill, de commande, de template ni de hook n'est placé à côté de lui ; le
fichier l'indique donc au lieu de pointer vers des fichiers Apothem qui ne se
trouvent pas dans le projet.

## Correspondance entre le profil et la configuration native

L'adaptateur lit le profil partagé d'Apothem et rend le fichier de règles du
projet à chaque exécution de `apothem install` ou de `apothem update`. Le profil
partagé est la source de vérité ; les modifications locales au projet apportées
au fichier généré sont sauvegardées avant que la synchronisation suivante ne
remplace le contenu géré par Apothem.

Le fichier commence par son frontmatter YAML (`description`, `globs`,
`alwaysApply: true`), car Cursor ne lit le type d'une règle que dans un
frontmatter placé au début du fichier. Le bloc géré par Apothem le suit ; le
texte que vous ajoutez après le bloc est conservé à chaque synchronisation.

## Notes de compatibilité

Cursor 0.45+ prend en charge des instructions au niveau du projet via
`.cursor/rules/`. L'adaptateur écrit par défaut dans le répertoire
`.cursor/rules/` de portée projet ; Cursor ne documente aucun chemin de règles
globales utilisateur sous forme de fichiers que cet adaptateur pourrait gérer.

## Vérification

```bash
apothem verify --harness cursor --project /path/to/project
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Chaque cible gérée existe ; les fichiers gérés ne sont pas vides, et les
   configurations JSON ou YAML s'analysent correctement. Ajoutez
   `--profile PATH` pour vérifier en plus que les fichiers installés
   correspondent à ce profil.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness cursor --project /path/to/project
```

Redérive le fichier de règles du projet à partir de l'état actuel du profil
partagé.

## Désinstallation

```bash
apothem uninstall --harness cursor --project /path/to/project
```

Supprime le bloc Apothem, ainsi que le frontmatter qu'Apothem a écrit au-dessus
de lui, de `<project>/.cursor/rules/apothem-rules.mdc` et conserve tout autre
texte qui s'y trouve. Le fichier n'est supprimé que lorsqu'il n'y reste plus
rien d'autre. Avant la modification, une copie horodatée du fichier est
enregistrée sous `~/.apothem/backups/` ; aucun fichier de sauvegarde n'est laissé
dans le projet. Le YAML du profil partagé et le moteur Apothem ne sont pas
affectés.

## Portail de conformité

```bash
python -m apothem.conformity.gate --all .
```

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness cursor --project /path/to/project` |
| Échec de la vérification | Exécutez `apothem update --harness cursor --project /path/to/project`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez `apothem update --harness cursor --project /path/to/project` |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
