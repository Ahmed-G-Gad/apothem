**Éditeur :** ByteDance
**Nom d'installation :** `trae`
**Statut :** GA
**Configuration native :** `<project>/.trae/rules/apothem-rules.md`

## Installation

```bash
apothem install --harness trae --project /path/to/project
```

L'adaptateur écrit un fichier de règles Trae de portée projet à partir des
règles partagées d'Apothem et de la surface de gouvernance.

**Fichiers écrits :** `<project>/.trae/rules/apothem-rules.md`

## Correspondance entre le profil et la configuration native

L'adaptateur lit le profil partagé d'Apothem et rend le fichier de règles du
projet à chaque exécution de `apothem install` ou de `apothem update`. Le profil
partagé est la source de vérité ; les modifications locales au projet apportées
au fichier généré sont sauvegardées avant que la synchronisation suivante ne
remplace le contenu géré par Apothem.

Le fichier s'ouvre sur un frontmatter YAML qui définit `alwaysApply: true` et
une `description`, ce qui correspond au mode Always Apply de Trae selon la
[documentation des règles de Trae](https://docs.trae.ai/ide/rules). Le bloc géré
par Apothem le suit ; le texte que vous ajoutez après le bloc est conservé à
chaque synchronisation.

## Notes de compatibilité

La surface de règles actuelle de Trae a une portée de projet, sous
`.trae/rules/` ; les règles globales se trouvent sous `~/.trae/user_rules`.
L'adaptateur écrit un fichier dédié, `apothem-rules.md`, et n'écrase jamais les
autres fichiers de règles de ce répertoire ni vos règles globales. La
surface de serveurs d'outils `.trae/mcp.json` et la surface de skills
`.trae/skills/` sont détenues par l'opérateur ; Apothem ne les écrit pas.

## Vérification

```bash
apothem verify --harness trae --project /path/to/project
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Chaque cible gérée existe ; les fichiers gérés ne sont pas vides, et les
   configurations JSON ou YAML s'analysent correctement. Ajoutez
   `--profile PATH` pour vérifier en plus que les fichiers installés
   correspondent à ce profil.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness trae --project /path/to/project
```

Redérive le fichier de règles du projet à partir de l'état actuel du profil
partagé.

## Désinstallation

```bash
apothem uninstall --harness trae --project /path/to/project
```

Supprime le bloc Apothem, ainsi que le frontmatter qu'Apothem a écrit au-dessus,
de `<project>/.trae/rules/apothem-rules.md` et conserve tout autre texte qu'il
contient. Le fichier n'est supprimé que si rien d'autre n'y subsiste. Avant la
modification, une copie horodatée du fichier est enregistrée sous
`~/.apothem/backups/` ; aucun fichier de sauvegarde n'est laissé dans le projet.
Le YAML du profil partagé et le moteur Apothem ne sont pas affectés.

## Portail de conformité

```bash
python -m apothem.conformity.gate --all .
```

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness trae --project /path/to/project` |
| Échec de la vérification | Exécutez `apothem update --harness trae --project /path/to/project`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez `apothem update --harness trae --project /path/to/project` |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
