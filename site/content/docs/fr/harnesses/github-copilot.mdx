**Éditeur :** GitHub / Microsoft
**Nom d'installation :** `github-copilot`
**Statut :** GA
**Configuration native :** `<project>/.github/copilot-instructions.md`

## Installation

```bash
apothem install --harness github-copilot --project /path/to/project
```

L'adaptateur dérive le fichier d'instructions du projet à partir de votre profil
partagé et de la surface partagée de règles et de gouvernance d'Apothem.

**Fichiers écrits :** `<project>/.github/copilot-instructions.md`

## Correspondance entre le profil et la configuration native

L'adaptateur lit le profil partagé d'Apothem et rend le fichier d'instructions
Copilot valable pour tout le dépôt à chaque exécution de `apothem install` ou
de `apothem update`. Le profil partagé est la source de vérité ; les
modifications locales au projet apportées au fichier généré sont sauvegardées
avant que la synchronisation suivante ne remplace le contenu géré par Apothem.

À l'intérieur du bloc Apothem, la section rendue à partir de votre profil
(opérateur, préférences, règles personnalisées, comportements activés
explicitement, noms des serveurs MCP) vient en premier, avant le texte de
gouvernance partagé. GitHub indique que les fichiers d'instructions plus courts
ont plus de chances d'être traités en entier par la revue de code
([Personnaliser la revue de code](https://docs.github.com/en/copilot/tutorials/customize-code-review)) ;
la partie qui vous est propre ouvre donc le fichier.

## Notes de compatibilité

GitHub Copilot n'expose aucun chemin d'instructions globales utilisateur sous
forme de fichier que cet adaptateur pourrait gérer. Apothem cible le fichier
d'instructions de portée projet documenté et laisse les paramètres utilisateur
au niveau de l'IDE sous la propriété de l'opérateur.

Dans le dépôt Apothem, `.github/copilot-instructions.md` est une voix parmi les
surfaces d'instructions d'assistant de ce dépôt. Dans un checkout de ce dépôt, le
contrôle de cohérence multisurface du portail de conformité compare les
affirmations partagées de `AGENTS.md`, `CLAUDE.md` et
`.github/copilot-instructions.md`. Il signale une affirmation partagée que l'un
des trois fichiers omet, ainsi qu'un fichier qui contredit une affirmation
formulée par `AGENTS.md`. Le contrôle ne lit pas le fichier d'instructions
qu'Apothem écrit dans votre projet. Le portail est consultatif par défaut : il
signale les constats et se termine avec le code `0`.

## Vérification

```bash
apothem verify --harness github-copilot --project /path/to/project
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Chaque cible gérée existe ; les fichiers gérés ne sont pas vides, et les
   configurations JSON ou YAML s'analysent correctement. Ajoutez
   `--profile PATH` pour vérifier en plus que les fichiers installés
   correspondent à ce profil.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness github-copilot --project /path/to/project
```

Redérive le fichier d'instructions du projet à partir de l'état actuel du
profil partagé.

## Désinstallation

```bash
apothem uninstall --harness github-copilot --project /path/to/project
```

Supprime le bloc Apothem de `<project>/.github/copilot-instructions.md` et
conserve tout texte situé en dehors de ce bloc. Le fichier n'est supprimé que
lorsqu'il ne contient plus rien d'autre. Avant la modification, une copie
horodatée du fichier est enregistrée sous `~/.apothem/backups/`. Le YAML du
profil partagé et le moteur Apothem ne sont pas affectés.

## Portail de conformité

```bash
python -m apothem.conformity.gate --all .
```

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness github-copilot --project /path/to/project` |
| Échec de la vérification | Exécutez `apothem update --harness github-copilot --project /path/to/project`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez `apothem update --harness github-copilot --project /path/to/project` |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
