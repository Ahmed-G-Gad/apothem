**Éditeur :** Open-Claw
**Nom d'installation :** `open-claw`
**Statut :** Préversion
**Configuration native :** `~/.openclaw/openclaw.json`

## Installation

```bash
apothem install --harness open-claw
```

L'adaptateur traduit le profil partagé vers le fichier de configuration global
à l'utilisateur d'OpenClaw et installe les cohortes de support Apothem sous la
racine de l'environnement. La configuration native d'OpenClaw est en JSON ; le
materializer rend donc du JSON pour s'y conformer.

**Fichiers écrits :** `~/.openclaw/openclaw.json`, le document de profil
`~/.openclaw/apothem/rules/00-apothem-profile.md` et des fichiers de support
sous `~/.openclaw/.apothem/support/`

Le document de profil se termine par une section consacrée aux fichiers de
support Apothem, qui nomme le répertoire absolu sous
`~/.openclaw/.apothem/support/` par rapport auquel se résout chaque citation de
style dépôt (`rules/<name>.md`, `templates/...`, `hooks/...`).

## Correspondance entre le profil et la configuration native

L'adaptateur lit le profil partagé d'Apothem mais ne rédige aucune clé de
configuration : `openclaw.json` est écrit sous la forme d'un objet vide.
L'identité, les préférences et les règles du profil vont dans le document de
profil. Les commandes, skills, règles, templates et prompts de hook partagés
sont installés comme matériel de support sous `~/.openclaw/.apothem/support/`.

## Notes de compatibilité

Adaptateur en préversion. OpenClaw ne charge pas de lui-même l'arborescence de
support ni le document de profil : aucun de ses emplacements de skills, aucun de
ses fichiers d'instructions d'espace de travail ni sa configuration n'y
pointent ; après l'installation, OpenClaw s'exécute donc sans les règles, les
skills ni les serveurs MCP d'Apothem. OpenClaw lit les skills depuis les
dossiers `skills/` et `.agents/skills/` de son espace de travail,
`~/.agents/skills`, son répertoire d'état et tout dossier listé dans
`skills.load.extraDirs` ; pour utiliser les skills Apothem, ajoutez vous-même
`~/.openclaw/.apothem/support/skills` à cette liste ; `apothem update` conserve
les clés que vous ajoutez à `openclaw.json`. Les serveurs MCP se trouvent dans
le bloc `mcp.servers` de la configuration OpenClaw, que vous gérez avec
`openclaw mcp add` et les sous-commandes associées ; l'adaptateur n'y écrit
aucune entrée. (Comportement d'OpenClaw selon sa documentation sur les
[skills](https://docs.openclaw.ai/tools/skills) et sur la
[CLI MCP](https://docs.openclaw.ai/cli/mcp), consultée le 2026-10-02.)

## Vérification

```bash
apothem verify --harness open-claw
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Tous les champs obligatoires du profil partagé sont présents.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness open-claw
```

Redérive la configuration native à partir de l'état actuel du profil partagé.
Exécutez cette commande après avoir modifié `~/.config/apothem/profile.yaml` ou
mis à niveau le paquet Apothem installé.

## Désinstallation

```bash
apothem uninstall --harness open-claw
```

Supprime les fichiers de configuration native écrits par l'adaptateur.
Le YAML du profil partagé et le moteur Apothem ne sont pas affectés.

## Portail de conformité

```bash
python -m apothem.conformity.gate --all .
```

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness open-claw` |
| Échec de la vérification | Exécutez `apothem update --harness open-claw`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez `apothem update --harness open-claw` |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
