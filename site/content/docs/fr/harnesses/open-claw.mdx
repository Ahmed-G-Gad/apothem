**Éditeur :** Open-Claw
**Nom d'installation :** `open-claw`
**Statut :** Préversion
**Configuration native :** `~/.openclaw/openclaw.json`

## Installation

```bash
apothem install --harness open-claw
```

L'adaptateur écrit le fichier de configuration globale utilisateur d'OpenClaw,
projette le profil partagé dans un document de profil et installe les cohortes
de support Apothem sous la racine de l'environnement. La configuration native
d'OpenClaw est en JSON ; le materializer rend un objet JSON vide, et un fichier
existant conserve ses clés.

**Fichiers écrits :** `~/.openclaw/openclaw.json`, le document de profil
`~/.openclaw/apothem/rules/00-apothem-profile.md` et des fichiers de support
sous `~/.openclaw/.apothem/support/`

Le document de profil se termine par une section consacrée aux fichiers de
support Apothem, qui nomme le répertoire absolu sous
`~/.openclaw/.apothem/support/` par rapport auquel se résout chaque citation de
style dépôt (`rules/<name>.md`, `templates/...`, `hooks/...`).

## Correspondance entre le profil et la configuration native

L'adaptateur lit le profil partagé d'Apothem mais ne rédige aucune clé de
configuration : un `openclaw.json` nouveau ou vide est écrit sous la forme d'un
objet vide, et un fichier existant conserve ses clés. L'identité, les
préférences et les règles du profil vont dans le document de profil. Les
commandes, skills, règles, templates et prompts de hook partagés sont installés
comme matériel de support sous `~/.openclaw/.apothem/support/`.

## Notes de compatibilité

Adaptateur en préversion. OpenClaw ne charge pas de lui-même l'arborescence de support ni le document de profil : aucun de ses emplacements de skills, aucun de ses fichiers d'instructions d'espace de travail ni sa configuration n'y pointent ; après l'installation, OpenClaw s'exécute donc sans les règles, les skills ni les serveurs MCP d'Apothem. OpenClaw lit les skills depuis les dossiers `skills/` et `.agents/skills/` de son espace de travail, depuis `~/.agents/skills` et depuis son répertoire d'état, puis les filtre au moyen de la liste d'autorisation des noms de skills sous `agents.defaults.skills`. `skills.load.extraDirs` n'est pas un chargeur de skills : les skills d'Apothem situés sous `~/.openclaw/.apothem/support/skills` ne se chargent donc qu'une fois placés dans l'un de ces dossiers et nommés dans cette liste d'autorisation. `apothem update` conserve les clés que vous ajoutez à `openclaw.json`. Les serveurs MCP se trouvent dans le bloc `mcp.servers` de la configuration d'OpenClaw, que vous gérez avec `openclaw mcp add` et les sous-commandes associées ; l'adaptateur n'y écrit aucune entrée. (Comportement d'OpenClaw selon sa documentation sur les [skills](https://docs.openclaw.ai/tools/skills) et sur la [CLI MCP](https://docs.openclaw.ai/cli/mcp), consultées le 2026-10-02.)

## Vérification

```bash
apothem verify --harness open-claw
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Chaque cible gérée existe ; les fichiers gérés ne sont pas vides, et les
   configurations JSON ou YAML s'analysent correctement. Ajoutez
   `--profile PATH` pour vérifier en plus que les fichiers installés
   correspondent à ce profil.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness open-claw
```

Redérive le document de profil à partir de l'état actuel du profil partagé et
actualise les fichiers de support ; `openclaw.json` conserve les clés qu'il
possède déjà.
Exécutez cette commande après avoir modifié `~/.config/apothem/profile.yaml` ou
mis à niveau le paquet Apothem installé.

## Désinstallation

```bash
apothem uninstall --harness open-claw
```

Supprime ce que l'adaptateur a ajouté : le document de profil et
l'arborescence de support. Vos propres clés dans `openclaw.json` restent en
place, et le fichier n'est supprimé que si Apothem l'a créé et qu'il n'y reste
plus rien qui vous appartienne. Le YAML du profil partagé et le moteur Apothem
ne sont pas affectés.

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness open-claw` |
| Échec de la vérification | Exécutez `apothem update --harness open-claw`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Apothem n'écrit aucune clé dans `openclaw.json` et conserve celles qui s'y trouvent déjà, si bien que le contenu du profil n'y est pas écrit. Le contenu du profil est écrit dans `~/.openclaw/apothem/rules/00-apothem-profile.md` : vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez la commande sous [Mise à jour](#mise-à-jour) |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
