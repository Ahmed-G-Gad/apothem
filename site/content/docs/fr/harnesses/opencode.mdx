**Éditeur :** OpenCode
**Nom d'installation :** `opencode`
**Statut :** Bêta
**Configuration native :** `~/.config/opencode/`

## Installation

```bash
apothem install --harness opencode
```

L'adaptateur écrit la configuration JSON d'OpenCode, installe les skills Apothem
dans la surface de skills d'OpenCode, convertit les prompts de commande en
fichiers de commande Markdown OpenCode et normalise les définitions
d'auxiliaires Apothem en sous-auxiliaires OpenCode.

**Fichiers écrits :**

```text
~/.config/opencode/opencode.json
~/.config/opencode/apothem/rules/00-apothem-profile.md
~/.config/opencode/commands/
~/.config/opencode/skills/
~/.config/opencode/agents/
~/.config/opencode/.apothem/support/{rules,templates,hooks}/
```

## Correspondance entre le profil et la configuration native

L'adaptateur rend `opencode.json` avec une liste de fichiers `instructions` qui
nomme votre document de profil, les quatre règles centrales et l'index des
règles, puis propage chaque cohorte Apothem partagée soit vers une surface
native d'OpenCode, soit vers une sous-arborescence de support détenue par
Apothem. Les enfants existants correspondants gérés par Apothem sont
sauvegardés avant remplacement.

## Notes de compatibilité

OpenCode combine chaque fichier que nomme la liste `instructions` dans chaque
session ([règles d'OpenCode](https://opencode.ai/docs/rules/)). La liste nomme
donc d'abord votre document de profil, puis uniquement les règles dont
`alwaysApply` vaut `true`, chacune par un chemin explicite
`~/.config/opencode/.apothem/support/rules/<name>.md` ; OpenCode développe le
`~/` initial par rapport à votre répertoire personnel. Ces règles sont
`agnostic-posture`, `authority-inquiry`, `context-management`,
`session-closure` et l'index des règles, `apothem-rule-index`. OpenCode ne
restreint aucune règle par chemin ; toute autre règle est donc lue à la demande.
Elle reste installée comme matériel de référence sous
`~/.config/opencode/.apothem/support/`, et l'index nomme chaque règle et la
situation qui l'appelle. Une règle, une skill ou une commande qui cite une
règle, un template ou un prompt de hook le lit à partir de cet emplacement. Les
commandes, les skills et les définitions d'auxiliaires utilisent les
emplacements de découverte natifs.

Le document de profil `~/.config/opencode/apothem/rules/00-apothem-profile.md`
porte votre identité et vos préférences issues du profil partagé, et se termine
par une section consacrée aux fichiers de support Apothem, qui nomme le
répertoire absolu sous `~/.config/opencode/.apothem/support/` par rapport auquel
se résout chaque citation de style dépôt (`rules/<name>.md`, `templates/...`,
`hooks/...`). C'est la première entrée de `instructions` ; OpenCode le charge
donc dans chaque session.

Un `opencode.json` écrit par une publication antérieure liste le glob unique
`~/.config/opencode/.apothem/support/rules/*.md`, qui charge toutes les règles,
ou un chemin explicite pour chacune des 28 règles alors toujours actives.
`apothem install` et `apothem update` remplacent l'une ou l'autre forme par la
liste ci-dessus, ce qui retire les 24 chemins qui ne sont plus chargés au
lancement, et `apothem uninstall` les supprime tous. Vos propres entrées
`instructions` sont conservées dans tous les cas.

## Vérification

```bash
apothem verify --harness opencode
```

La commande verify confirme que :

1. La configuration native existe au chemin attendu.
2. Chaque cible gérée existe ; les fichiers gérés ne sont pas vides, et les
   configurations JSON ou YAML s'analysent correctement. Ajoutez
   `--profile PATH` pour vérifier en plus que les fichiers installés
   correspondent à ce profil.
3. La routine de vérification propre à l'adaptateur signale un succès.

## Mise à jour

```bash
apothem update --harness opencode
```

Actualise `opencode.json`, les commandes natives, les skills, les définitions
d'auxiliaires et l'arborescence de support Apothem.

## Désinstallation

```bash
apothem uninstall --harness opencode
```

Supprime les entrées que l'adaptateur a ajoutées à
`~/.config/opencode/opencode.json` (vos propres clés, vos serveurs MCP et vos
entrées `instructions` restent en place, et le fichier n'est supprimé que si
Apothem l'a créé et qu'il n'y reste plus rien qui vous appartienne). Supprime le
bloc Apothem du document de profil
`~/.config/opencode/apothem/rules/00-apothem-profile.md` et conserve tout autre
texte qu'il contient ; ce fichier n'est supprimé que si rien d'autre n'y
subsiste. Supprime aussi les fichiers Apothem de `~/.config/opencode/commands/`,
`~/.config/opencode/skills/`, `~/.config/opencode/agents/` et
`~/.config/opencode/.apothem/support/` ; les autres fichiers de ces dossiers
restent en place. Chaque fichier est sauvegardé sous `~/.apothem/backups/` avant
d'être modifié ou supprimé. Le YAML du profil partagé et le moteur Apothem ne
sont pas affectés.

## Portail de conformité

```bash
python -m apothem.conformity.gate --all .
```

## Dépannage

| Symptôme | Correctif |
|---------|-----|
| Fichier de configuration introuvable | Relancez `apothem install --harness opencode` |
| Échec de la vérification | Exécutez `apothem update --harness opencode`, puis vérifiez à nouveau |
| Contenu de configuration inattendu | Vérifiez `~/.config/apothem/profile.yaml` ou `--profile PATH`, puis relancez `apothem update --harness opencode` |

## Paramètres de configuration

| Option | Par défaut | Description |
|------|---------|-------------|
| `--dry-run` | `false` | Prévisualise l'installation sans écrire de fichiers. |
