Cette feuille de route décrit la direction que prend Apothem. C'est une
déclaration d'intention, non un engagement ; les priorités évoluent à mesure que
le projet et ses utilisateurs évoluent. Pour ce qui a déjà été livré, consultez
le [changelog](https://github.com/ahmed-g-gad/apothem/blob/main/CHANGELOG.md).
Le
[ROADMAP.md](https://github.com/ahmed-g-gad/apothem/blob/main/ROADMAP.md) du
dépôt est l'unique feuille de route ; la
[page de la feuille de route](https://apothem.ahmedgad.com/docs/community/roadmap)
du site web du projet est générée à partir de celui-ci.

Légende des statuts : **prévu** · **en cours** · **livré**.

## Publication actuelle

La ligne actuelle livre le gestionnaire de configuration d'environnements
indépendant de l'hôte : un profil partagé (`~/.config/apothem/profile.yaml`)
matérialisé en configuration native des environnements pour les adaptateurs
enregistrés, piloté par la ligne de commande `apothem` (`quickstart` ·
`install` · `update` · `uninstall` · `rollback` · `verify` · `status` · `diff`
· `harnesses` · `profile` · `doctor` · `migrate-workspace` · `completion`).

| Élément | Statut | Notes |
| ---- | ------ | ----- |
| Dix-sept adaptateurs d'environnement | livré | Chacun avec installation, désinstallation, mise à jour et vérification ; les pages des [environnements pris en charge](https://apothem.ahmedgad.com/docs/harnesses) les répertorient |
| Propagation de templates pilotée par manifeste | livré | Une source de vérité unique pour la propagation, à `src/apothem/lib/propagation-manifest.yaml` |
| Site de documentation | livré | Site public avec des index de référence générés, des ressources de marque, un index du site lisible par machine et des runbooks de publication |
| Publications signées | livré | Chaque GitHub Release porte des artefacts signés, un SBOM et une provenance de compilation |
| Pipelines `/plan` et `/research` | livré | Le pipeline de planification par étapes (spécification, génération, revue et exécution), plus le pipeline de recherche à treize étapes |
| Commandes d'audit et boucle `/fortress` | livré | Audits à la demande de sécurité, de code, d'accessibilité, de performance, de dépendances, de chaîne d'approvisionnement, de modèle de menace, d'architecture, de revue de code, de revue de documentation et d'UX, encapsulés par la boucle de durcissement `/fortress` |
| Infrastructure d'audit et de revue de dérive | livré | Scanners d'inventaire et de dérive sur lesquels reposent les commandes d'audit |
| Portail de conformité | livré | Validateurs des en-têtes d'auteur, du nommage, de la facture du code, des formulations évasives et de la réciprocité des liaisons sur chaque surface matérialisée, avec des goldens de behavior-diff qui verrouillent la sortie de chaque adaptateur |
| Mémoire durable et apprentissage continu sur option | livré | Un niveau de mémoire persistant et une boucle d'apprentissage sur option qui transmettent les conventions confirmées d'une session à l'autre |
| Pipeline CI/CD et chaîne d'approvisionnement des publications signées | livré | Chaque changement est conditionné au lint, aux tests, aux vérifications de types, à une compilation de la documentation et à des contrôles de chaîne d'approvisionnement avant la publication |

## À court terme

| Élément | Statut | Notes |
| ---- | ------ | ----- |
| Guides de documentation | en cours | Davantage de guides orientés tâches, de diagrammes et d'exemples pour des configurations d'environnement réelles |
| Distribution npm / npx | prévu | Garder le point d'entrée npx `@ahmed-g-gad/apothem` aligné sur chaque publication et élargir sa couverture de plateformes |
| Fiche du plugin Claude Code | prévu | Développer la fiche du plugin à mesure que la surface de la marketplace se stabilise |
| Davantage d'adaptateurs d'environnement | prévu | Des environnements supplémentaires à mesure que leurs conventions de configuration se stabilisent et que les utilisateurs les demandent |
| Améliorations du schéma de profil | prévu | Des surfaces de surcharge par environnement plus riches et des diagnostics de validation plus stricts |
| Validation du profil dans le portail de conformité | prévu | Valider le profil partagé par rapport à son schéma en tant que contrôle du portail |
| Versionnage et migration du profil | prévu | Versionner le format du profil et faire migrer les profils plus anciens vers le format actuel |
| `apothem update --watch` | prévu | Re-matérialiser la configuration des environnements lorsque le profil change |

## À plus long terme

| Élément | Statut | Notes |
| ---- | ------ | ----- |
| Synchronisation de profil hébergée dans le cloud | prévu | Optionnelle et contrôlée par l'opérateur |
| Gestion de profil partagé en équipe | prévu | Un seul profil partagé au sein d'une équipe |
| Extension d'éditeur avec retour de conformité en direct | prévu | Les constats de conformité pendant que vous modifiez, dans les éditeurs de la famille VS Code |

## Vision à long terme

Apothem vise à être la manière par défaut dont chacun gère la configuration des
environnements dans tous les outils qu'il utilise : écrire les conventions une
seule fois, les matérialiser partout, et les garder synchronisées à mesure que
les préférences comme les environnements évoluent.

## Comment influencer la feuille de route

- Ouvrez une issue, ou votez pour une issue existante, dans le
  [suivi des issues](https://github.com/ahmed-g-gad/apothem/issues) ; une
  demande de fonctionnalité déposée là est le moyen de proposer un élément de
  feuille de route. Les demandes populaires avancent plus vite.
- Consultez [CONTRIBUTING.md](https://github.com/ahmed-g-gad/apothem/blob/main/CONTRIBUTING.md)
  pour savoir comment proposer des changements et les faire intégrer.
