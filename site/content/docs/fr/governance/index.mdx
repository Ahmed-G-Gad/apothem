Cette section documente la gouvernance qualité interne du projet : les registres
de mandats qui définissent ce que chaque artefact émis doit satisfaire, le
contrôle qui vérifie les artefacts avant leur publication, les catégories de
question qui séparent ce que l'outil peut décider de ce qu'il doit demander, et
les politiques qui gouvernent les versions, les badges et le positionnement du
projet.

Ces pages font autorité pour les mainteneurs et pour les contrôles automatisés du
dépôt. Les guides d'utilisation au quotidien se trouvent dans [Guides](/docs/usage),
et les schémas et conventions qu'ils citent se trouvent dans
[Référence](/docs/reference).

## Pages

| Page | Description |
|------|-------------|
| [Mandats transversaux](/docs/governance/cross-cutting-mandates) | Le registre de mandats internes de l'écosystème (CM-1–CM-28) qui gouverne toutes les interactions et opérations du pipeline. |
| [Registre de conformité externe](/docs/governance/outward-conformity-registry) | Le registre de quinze mandats (M1–M15) que tout artefact généré dans un projet hôte doit satisfaire. |
| [Registre du contrôle de pré-émission](/docs/governance/pre-emission-gate-registry) | Le contrôle de conformité obligatoire à quinze barres exécuté avant toute émission d'envergure significative. |
| [Registre de question autoritaire](/docs/governance/authoritative-inquiry-registry) | Les catégories de question requises et les exceptions de décision automatique : ce qui est demandé face à ce qui est décidé. |

| [Politique d'ingénierie de version](/docs/governance/release-engineering-policy) | Versionnage, étiquetage des versions, cycles d'obsolescence, changements incompatibles et procédures de retour arrière. |
| [Positionnement](/docs/governance/positioning) | Comment Apothem se présente : gouvernance de ratification d'artefacts pour le développement assisté. |
