La puerta de conformidad en `src/apothem/conformity/gate.py` ejecuta la
fracción mecánica de la puerta de pre-emisión de quince barras (M1-M15)
contra cada artefacto que redacta el operador.

Los comandos de esta página suponen un checkout de Apothem, así que antepón `PYTHONPATH=src` a cada uno. Tras una instalación con script, usa `PYTHONPATH="$HOME/.apothem/src"` en lugar de `src`.

## Ejecutar la puerta

La puerta es **consultiva de forma predeterminada**: informa los hallazgos y
sale con `0`, de modo que una ejecución local nunca te bloquea. Agrega
`--strict` (o establece `APOTHEM_CONFORMITY_STRICT=1`) para salir con un código
distinto de cero ante un hallazgo bloqueante — el modo que usan CI y pre-commit
para hacer fallar un cambio que incumple.

```bash
# Advisory: report every validator's findings across the repo, exit 0
PYTHONPATH=src python -m apothem.conformity.gate --all .

# Strict: exit non-zero (code 2) when a blocking finding is present
PYTHONPATH=src python -m apothem.conformity.gate --all --strict .
```

Códigos de salida: `0` limpio (o consultivo), `2` un bloqueo por hallazgos en
modo estricto, `3` un error de uso: un indicador o un nombre de validador
desconocido, un archivo que no existe o un directorio raíz que no existe.
`--help` imprime el uso completo y sale con `0`. Cada validador independiente
acepta el mismo `--help` y sale con `3` ante un indicador desconocido o una raíz
faltante.

Una raíz relativa como `.` se resuelve a una ruta absoluta antes de que se
ejecute cualquier validador, de modo que `--all .` y `--all "$PWD"` inspeccionan
el mismo árbol. Cada validador informa `inspected` — cuántos destinos examinó —
y `--all` copia ese recuento en cada entrada del resultado. Un validador que no
inspeccionó nada informa `passed: false`, de modo que un directorio de trabajo
equivocado no puede pasar en silencio. Los dos validadores de suites de plan son
la excepción: las suites de plan residen en el árbol `.apothem/plans/`, ignorado
por git, así que informan `empty_scope_expected: true` en un checkout limpio y
aun así pasan. Los validadores de flujos de trabajo hacen lo mismo cuando el
proyecto todavía no tiene un directorio `.github/workflows/`, y el validador de
asuntos de commit lo hace cuando el directorio no tiene historial de commits.

## Comprobaciones dirigidas

```bash
# List every registered validator
PYTHONPATH=src python -m apothem.conformity.gate --list

# Run a single named validator
PYTHONPATH=src python -m apothem.conformity.gate --check multi-surface-coherence

# Run every validator against one file
PYTHONPATH=src python -m apothem.conformity.gate src/apothem/rules/my-rule.md
```

El modo `--hook` (`python -m apothem.conformity.gate --hook`) es el punto de
entrada que despacha el entorno: lee desde stdin una carga útil JSON de entrada
de herramienta y ejecuta la cadena de emparejadores por escritura contra la
escritura pendiente. Esta es la forma que invoca el hook `PreToolUse`
desplegado; rara vez lo llamas a mano.

El modo hook está **limitado a un conjunto de directorios**. Ejecuta la cadena
de emparejadores solo en las escrituras cuyo destino está dentro de alguno de
ellos; una escritura fuera de todos los alcances termina de inmediato como un
pase silencioso. Los valores predeterminados son las raíces de entorno de
alcance de usuario con capacidad de hooks en las que Apothem instala — la página
de cada entorno bajo Adaptadores de entorno nombra su propia raíz. Establece
`APOTHEM_CONFORMITY_SCOPE` en un directorio para reemplazarlos:

```bash
# Run the per-write matcher chain against one project tree instead
export APOTHEM_CONFORMITY_SCOPE=/path/to/project
```

Un hook que parece no hacer nada suele deberse a un destino fuera de alcance más
que a un fallo — compara primero el destino de la escritura con los alcances
anteriores.

## Integración con CI

El trabajo de calidad de `.github/workflows/ci.yml` ejecuta la puerta en modo estricto (`python -m apothem.conformity.gate --all . --strict`) en los push a `main` y en las pull requests a `main` que tocan las rutas que ese trabajo vigila. El flujo de trabajo independiente `.github/workflows/conformity.yml` ejecuta el barrido de fixtures (`tests/conformity-scenarios/verify.py --strict`).
