> **Referencia canónica del frontmatter YAML en cada clase de artefacto.** El resumen de la sección Conventions de [`CLAUDE.md`](https://github.com/ahmed-g-gad/apothem/blob/main/CLAUDE.md) es la declaración en línea; los JSON Schemas por clase en [`src/apothem/schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas) (`additionalProperties` rechaza las claves desconocidas) son el contrato legible por máquina y prevalecen ante cualquier discrepancia. Esta página es el índice de claves obligatorias, y [`artifact-schema.mdx`](/docs/reference/artifact-schema) lleva las plantillas y los ejemplos desarrollados por clase; ambas son proyecciones legibles por humanos de esos esquemas.

---

## 1. Estructura del bloque de frontmatter

Cada artefacto lleva frontmatter YAML al inicio, delimitado por líneas `---`. En los archivos de la familia Markdown, el frontmatter es el primer contenido del archivo, y el banner canónico del encabezado de autoría según [`site/content/docs/reference/authorship-header.mdx`](/docs/reference/authorship-header) va después del `---` de cierre.

Las claves de los comandos usan `kebab-case`. Las claves de las skills usan `kebab-case`, salvo `userInvocable`, la escritura en camelCase que usa el corpus fuente (la instalación de Claude Code la renombra como `user-invocable`). Las claves de reglas y de trabajadores delegados son camelCase, tal como enumera la tabla de claves obligatorias de la sección 2. Los valores escalares van sin comillas o entre comillas dobles; los valores de cadena que contienen dos puntos, almohadillas u otros caracteres significativos para YAML se escriben entre comillas.

## 2. Campos obligatorios por clase

El conjunto de claves obligatorias varía según la clase de artefacto. La estructura autoritativa la aplican `scripts/dev/validate_ecosystem.py` y los JSON Schemas por clase bajo el directorio `src/apothem/schemas/` (un archivo de esquema por clase de artefacto).

```text
src/apothem/schemas/agent.schema.json
src/apothem/schemas/skill.schema.json
src/apothem/schemas/command.schema.json
src/apothem/schemas/output-style.schema.json
src/apothem/schemas/plan.schema.json
```

| Clase | Claves obligatorias |
|-------|---------------|
| `CLAUDE.md` (configuración raíz) | `name`, `version`, `updated`, `description`, `scope`, `portability` |
| Reglas (`src/apothem/rules/*.md`) | `name`, `description`, `pathFilter`, `alwaysApply` |
| Comandos (`src/apothem/commands/*.md`) | `name`, `version`, `updated`, `description`, `argument-hint`, `disable-model-invocation`, `portability`, `allowed-tools` |
| Trabajadores delegados (directorio canónico que se muestra abajo) | `name`, `version`, `updated`, `description`, `tools`, `disallowedTools`, `maxTurns`, `effort` |
| Skills (`src/apothem/skills/*/SKILL.md`) | `name`, `version`, `updated`, `description`, `archetype`, `userInvocable`, `disable-model-invocation`, `allowed-tools`; la instalación y el plugin de Claude Code renombran `userInvocable` a `user-invocable`, y el esquema acepta exactamente una de las dos grafías |
| Estilos de salida (`src/apothem/output-styles/*.md`) | `name`, `description`; cada estilo distribuido también establece `keep-coding-instructions: true` para que Claude Code conserve sus instrucciones de ingeniería de software |

Los esquemas por clase en [`src/apothem/schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas) llevan el conjunto completo de restricciones, incluidas las de tipo, formato, enum y patrón, y los límites de longitud: la `description` de una skill o de un comando tiene como máximo 1024 caracteres, el límite de [Agent Skills](https://agentskills.io/specification).

## 3. Validadores

`scripts/dev/validate_ecosystem.py` recorre el árbol de artefactos, aplica los conjuntos de claves obligatorias anteriores e informa `[FAIL]` en cualquier artefacto al que le falte un campo obligatorio. El `frontmatter-grep` por escritura en `src/apothem/conformity/frontmatter_grep.py` aplica la misma estructura en los límites de los hooks PreToolUse de Write/Edit.
