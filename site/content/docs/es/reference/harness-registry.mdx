El registro de entornos es el inventario de adaptadores que sirve como fuente de
verdad para la CLI, la documentación, las pruebas de fixtures y la validación de
los anclajes de convención. La fuente en tiempo de ejecución es
`src/apothem/lib/harness_registry.py`; cada fila de abajo es rastreable hasta ese
registro, hasta el `capabilities.yml` de cada adaptador y hasta el
`STANDARD-CONVENTION-PIN.md` de cada adaptador.

## Soporte de cohortes de carga útil

Los valores de estado son `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable` y
`discovery-pending`.

Una cohorte `converted` se reescribe en el formato propio del entorno, y algunos
campos de origen no tienen cabida en él. Para cada cohorte convertida de
comandos, agentes o reglas, el `capabilities.yml` del adaptador lleva un mapa
`conversion_losses` que indica qué ocurre con cada campo de frontmatter de
origen:

| Valor | Significado |
| --- | --- |
| `native:<field>` | El entorno lo lee bajo ese campo. |
| `sidecar:<path>` | Se escribe en un archivo separado junto al convertido, como `agents/openai.yaml` de Codex. |
| `filename` | Lo lleva el nombre del archivo o de la carpeta. |
| `inlined` | Pasa al texto del prompt o del cuerpo. |
| `ignored` | Permanece en el archivo, pero el entorno no lo lee. |
| `dropped` | Se omite. |

Una prueba renderiza cada archivo convertido y comprueba los mapas contra la
salida.

| Entorno | Cargas útiles nativas o convertidas | Cargas útiles en el subárbol de soporte | Advertencias de no admitido o pendiente |
| --- | --- | --- | --- |
| Antigravity | comandos, agentes y reglas convertidos; skills, despacho de subagentes y plantillas de prompt de sistema nativos | hooks, plantillas | líneas de estado, output-styles; descubrimiento de MCP y de memoria pendiente |

## Raíces compartidas

Algunos destinos de instalación los cargan entornos distintos del que los
escribe. El registro anota cada una de esas rutas en `SHARED_ROOTS` con un único
propietario registrado (el adaptador para el que el proveedor documenta la ruta),
los coinstaladores que escriben en ella los mismos archivos y los lectores cuya
documentación de proveedor la carga por defecto, además de las páginas del
proveedor que lo muestran y la fecha en que se consultaron.

Una ruta con coinstaladores es una carpeta de nivel de usuario en el directorio
personal que varias instalaciones escriben con los mismos bytes. Una máquina con
solo `Cursor` instalado no tiene ningún `Codex` que escriba `~/.agents/skills/`,
así que cada instalación que nombra la carpeta la escribe, y el registro de
instalación cuenta las instalaciones que la usan. El propietario de referencia es
el propietario registrado mientras use la carpeta y, si no, la instalación más
antigua que la use; nada se mueve cuando se desinstala el propietario registrado.
Una desinstalación elimina la carpeta solo cuando ninguna otra instalación la
sigue usando (consulta [`uninstall`](/docs/cli-reference/uninstall#carpetas-compartidas-en-tu-directorio-personal)).
Instalar un lector no pone ningún archivo en la carpeta; instalar el propietario
o un coinstalador pone el contenido de Apothem delante de cada lector.

| Ruta | Propietario | Coinstaladores | Lectores |
| --- | --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, GitHub Copilot, Windsurf, Zed | Gemini CLI, Kimi Code, Open-Claw, OpenCode, Qwen Code |
| `~/.config/apothem/rules/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | ninguno |
| `~/.config/apothem/templates/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | ninguno |
| `~/.claude/skills/` | Claude Code | ninguno | Cursor, OpenCode |
| `~/.claude/agents/` | Claude Code | ninguno | Cursor |
| `~/.codex/agents/` | Codex | ninguno | Cursor |
| `~/.claude/CLAUDE.md` | Claude Code | ninguno | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | ninguno | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | ninguno | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | ninguno | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | ninguno | Zed |

`~/.config/apothem/rules/` y `~/.config/apothem/templates/` contienen los archivos
que citan las propias skills y archivos de instrucciones de Apothem. Ninguna otra
herramienta los carga, así que no tienen lectores ni páginas de proveedor.
`CodeBuddy`, `Kiro` y `Trae` también escriben una carpeta de skills propia
(`~/.codebuddy/skills/`, `~/.kiro/skills/` y `~/.trae/skills/`); solo esa
herramienta la carga, así que no es una raíz compartida.

Un lector solo figura donde la documentación de su proveedor muestra una carga
por defecto de esa ruta exacta. Un lector lleva una condición, y la nota de
instalación la repite: `Open-Claw` indexa `~/.agents/skills/` solo bajo su
directorio de estado predeterminado (omite la carpeta cuando `OPENCLAW_STATE_DIR`
apunta a otro lugar). La documentación de `Cursor` enumera `~/.codex/agents/` como
carpeta de compatibilidad con `Codex`, pero no dice qué formatos de archivo analiza
`Cursor` allí, y una instalación de `Codex` escribe archivos TOML, así que no está
confirmado si `Cursor` lee esos asistentes. La instalación de `Cursor` también
escribe su propia copia de los asistentes en `<project>/.cursor/agents/`, que la
precedencia del proveedor sitúa por encima de las carpetas que importa, así que en
un proyecto instalado la copia nativa sustituye a la de `~/.claude/agents/`.

Algunas herramientas no son lectoras de `~/.agents/skills/` de forma deliberada:
la documentación de `Antigravity`, `CodeBuddy`, `Kiro` y `Trae` no dice que la
carguen por defecto (`Trae` carga la carpeta `.agents/skills/` del proyecto solo
después de activar un ajuste), y por eso `CodeBuddy`, `Kiro` y `Trae` reciben una
carpeta de skills propia. La documentación de `Hermes` la nombra solo como valor
de ejemplo de `skills.external_dirs`. `GitHub Copilot` no es lector de
`~/.claude/agents/`: la documentación de VS Code enumera esa carpeta para el
agente Claude de Anthropic, no para el agente que ejecuta `GitHub Copilot`.

El bloque de Apothem que un propietario escribe en un archivo de instrucciones
compartido no nombra ninguna herramienta concreta como su lectora.
`tests/unit/test_shared_roots.py` falla cuando los adaptadores que escriben un
destino del registro no son exactamente su propietario y sus coinstaladores, y
cuando un destino del registro con nombre de archivo de
instrucciones entre herramientas (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`copilot-instructions.md`) no tiene un propietario declarado. La única excepción
es `~/.codex/AGENTS.md`, cuya carga no documenta ningún otro entorno registrado.

## Hooks de validación

El registro se mantiene sincronizado mediante estas comprobaciones:

| Comprobación | Propósito |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | Confirma que cada adaptador tiene un anclaje de convención de 90 días de antigüedad como máximo, que cita al menos una URL del proveedor y que no tiene ningún destino de descubrimiento vencido. La CI lo ejecuta en cada pull request, cada semana y antes de un lanzamiento. |
| `python scripts/dev/check_vendor_urls.py` | Descarga cada URL de proveedor que citan los anclajes y las plantillas de los entornos, y falla ante una página movida o inexistente, incluido un nombre de host que ya no se resuelve o un certificado que no supera la verificación; un tiempo de espera agotado, una conexión rechazada o restablecida, o un error de servidor 5xx se informa como inaccesible y no lo hace fallar. El monitor semanal de convenciones lo ejecuta. |
| `python -m apothem.conformity.gate --all .` | Ejecuta las comprobaciones de conformidad de la documentación y de la implementación. |
| `python -m pytest` | Ejercita las pruebas de fixtures del registro y las pruebas de contrato de los adaptadores. |
