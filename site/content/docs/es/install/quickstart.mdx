Este es el camino rápido desde cero hasta una configuración de entorno
verificada: instalar, redactar el perfil compartido, materializar la
configuración nativa de una herramienta, confirmarla y hacer tu primera edición.
Cada comando es real y se puede copiar, pegar y ejecutar, y cada paso muestra lo
que imprime una ejecución limpia. La instalación en sí termina en menos de dos
minutos; editar el perfil es la única parte que lleva tanto tiempo como quieras
dedicarle.

Al final tendrás una configuración de entorno funcional generada a partir de un
perfil que escribiste tú — y conocerás el único comando que vuelve a enviar un
cambio del perfil a una herramienta o a todas.

<Callout title="¿Quieres la versión pausada y narrada?">
  El [tutorial de primeros pasos](/docs/tutorials/getting-started) recorre el
  mismo terreno con más explicación de cada paso y de por qué importa. Esta
  página es el recorrido conciso, centrado en la salida.
</Callout>

Usarás **Claude Code** como entorno de ejemplo — es el predeterminado del
instalador. Cambia el nombre del adaptador en cualquier paso para apuntar a otra
herramienta; la [lista de entornos](/docs/harnesses) tiene todos los nombres
admitidos.

## 1. Instalar Apothem

Apothem se distribuye como un tiempo de ejecución autónomo: el motor se ejecuta directamente desde su árbol de código fuente con dependencias incorporadas. Un solo comando descarga el código fuente, coloca el motor y materializa tu primer entorno. Verifica primero el lanzamiento firmado, así que importa la clave de firma del mantenedor una sola vez antes de la primera instalación y comprueba que la huella digital es `5C89 98F9 F241 7204 45D3  F28B 7039 6FED 9C63 4163`:

```bash title="macOS · Linux · WSL2 · BSD — import the key once"
curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import
gpg --fingerprint 70396FED9C634163
```

```powershell title="Windows · PowerShell — import the key once"
& "$env:ProgramFiles\Git\bin\bash.exe" -c 'curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import && gpg --fingerprint 70396FED9C634163'
```

Después, ejecuta el instalador:

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 5.1+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

El instalador requiere un Python 3.10+ del sistema, además de `git` y `gpg` para la forma por red. Comprueba los requisitos previos y coloca el motor en `~/.apothem`. Cuando falta `click` o `rich`, instala el paquete con tu confirmación o cuando se pasa `--yes` (`-Yes` en PowerShell) o se define `APOTHEM_AUTO_INSTALL_DEPS=1`, y en caso contrario se detiene con el comando de pip que hay que ejecutar (consulta [Requisitos previos de un vistazo](/docs/install#requisitos-previos-de-un-vistazo)). Al terminar imprime un banner de próximos pasos; en POSIX, cuando el directorio del shim ya está en `PATH`, el banner tiene este aspecto:

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="Primera ejecución sin perfil">
  Si todavía no tienes un perfil, el instalador copia el perfil de ejemplo en
  `~/.config/apothem/profile.yaml` y continúa: materializa tu primer entorno y lo
  verifica en la misma ejecución. Los campos de identidad del ejemplo son
  marcadores de posición, por lo que la instalación imprime un aviso. Haz tuyo el
  perfil en el Paso 2 y después aplícalo con `apothem update --harness <name>`
  como en el Paso 5.
</Callout>

<Callout title="El comando `apothem`">
  El instalador escribe un shim `apothem` en `$HOME/.local/bin` (POSIX) o en
  `%LOCALAPPDATA%\Microsoft\WindowsApps` (Windows) y nunca modifica tu `PATH`.
  Una vez que ese directorio está en `PATH`, ejecutas el motor directamente como
  `apothem <command>`. Si todavía no está en `PATH`,
  el banner imprime una alternativa autónoma —
  `PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>` — que no
  necesita ningún shim; antepón a cada comando el prefijo exacto que imprimió tu
  banner.
</Callout>

La [guía de instalación](/docs/install) cubre las demás vías de instalación — el
plugin de Claude Code (`/plugin marketplace add ahmed-g-gad/apothem` y después
`/plugin install apothem@apothem`); las extensiones de la familia VS Code y otras
extensiones nativas de cada herramienta; y la forma bajo demanda con npx
(`npx @ahmed-g-gad/apothem <command>`) — junto con las opciones de variables de
entorno.

## 2. Crear el perfil compartido

`apothem profile init` escribe el perfil más pequeño válido según el esquema en
`~/.config/apothem/profile.yaml`. Si ya hay un perfil allí, como cuando el
instalador del Paso 1 copió el ejemplo, `init` se detiene con un error y deja el
archivo sin cambios; pasa `--force` para sobrescribirlo, o conserva el archivo y
edítalo como se muestra más abajo. Pasa `--profile PATH` cuando mantengas en otra
ubicación un perfil específico de un proyecto o de CI.

```bash
apothem profile init
apothem profile show --json
```

El esqueleto usa datos de identidad ficticios como marcadores de posición y es
seguro editarlo antes de instalar cualquier salida de entorno. `show --json` lo
vuelve a leer e informa del perfil validado:

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

Aquí es también donde aflora una edición malformada: si el YAML no es válido,
`show` lo informa en este punto, antes de que se escriba cualquier configuración
de entorno. Haz tuyo el perfil con `apothem profile edit` (lo abre en tu editor)
o establece una sola clave in situ:

```bash
apothem profile set identity.name "Your Name"
```

## 3. Instalar adaptadores de entorno

Materializa el adaptador de tu entorno principal. Esto lee tu perfil y escribe la
configuración nativa de esa herramienta:

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

Los adaptadores de ámbito de proyecto escriben dentro de un proyecto en lugar de
en tu directorio personal, por lo que necesitan un `--project PATH`. Previsualiza
cualquier instalación sin escribir archivos con `--dry-run`:

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

Instala de una vez todo el conjunto respaldado por el registro con
`--harness all`. Como esa selección escribe archivos tanto de ámbito de proyecto
como de ámbito de usuario, el comando imprime los destinos concretos agrupados
por ubicación. En una terminal interactiva, pide confirmación antes de escribir
fuera de la raíz del proyecto. Una ejecución sin terminal, una ejecución con
`--yes` o una ejecución con `--format json` escribe sin preguntar; `--dry-run` no
escribe nada. Ejecuta el conjunto completo con:

```bash
apothem install --harness all --project .
```

Consulta la [lista completa de entornos](/docs/harnesses) para ver todos los
nombres admitidos, y la [referencia de install](/docs/cli-reference/install) para
el conjunto completo de opciones.

## 4. Verificar

Materializar es solo la mitad del trabajo — `verify` confirma que los archivos de
configuración esperados del entorno se escribieron y son válidos:

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

`verify` termina con un código distinto de cero si falta un destino gestionado,
si un archivo gestionado está vacío o si una configuración JSON o YAML no se
analiza. Añade `--profile PATH` para que también falle cuando un archivo
instalado difiera de ese perfil, lo que convierte a `verify` en una comprobación
de deriva; sin él, una configuración obsoleta sigue superando la verificación. El
código de salida distinto de cero permite que `verify` sirva de puerta en un
script de configuración. Para una comprobación del estado de toda la máquina en
todos los adaptadores registrados, ejecuta:

```bash
apothem doctor
```

`doctor` comprueba cada entorno instalado: debe superar la verificación, y cada
comando de hook que registró su instalación debe arrancar. Un entorno que no has
instalado aparece en la lista, pero no cuenta como fallo, por lo que `doctor`
termina con 0 cuando ninguna comprobación falla, aunque solo haya un entorno
instalado.

## 5. Tu primera ejecución

Abre el entorno que acabas de configurar — Claude Code, en este ejemplo — e
inicia una sesión en cualquier proyecto. El perfil que configuraste en el Paso 2
ya forma parte del comportamiento de esa herramienta. Esa es la primera
ejecución funcional: un perfil que da forma a una sesión real.

Cuando cambies el perfil más adelante, vuelve a aplicarlo sin reinstalar:

```bash
apothem update --harness claude-code
```

Indica otro adaptador para volver a aplicar el perfil a esa herramienta (añade
`--project PATH` para un adaptador de ámbito de proyecto), o pasa
`--harness all --project .` para volver a aplicarlo a todos los entornos
admitidos.
