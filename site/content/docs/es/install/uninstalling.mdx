## Elimina primero las configuraciones de entorno

Antes de desinstalar Apothem, elimina la configuración de cada adaptador de
entorno para dejar tus entornos en un estado limpio. Ejecuta
`apothem harnesses list` para ver qué adaptadores están instalados actualmente
y, después, elimínalos de uno en uno o usa el selector de todo el registro:

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness cursor --project /path/to/project
apothem uninstall --harness all --project /path/to/project --yes
```

Pasa `--yes` para omitir la solicitud de confirmación por entorno.

## Elimina el motor

La eliminación depende del canal de instalación que usaste:

- **Plugin de Claude Code** — elimina el plugin desde dentro de Claude Code:
  `/plugin uninstall apothem@apothem` (la entrada del marketplace se puede
  eliminar con `/plugin marketplace remove ahmed-g-gad/apothem`).
- **npx** — no hay nada que eliminar; `npx` se ejecuta desde su caché. Vacíala
  con `npm cache clean --force` si quieres que desaparezca la copia en caché.
- **Instalador de un solo paso** — ejecuta el script de desinstalación
  correspondiente desde el checkout: `scripts/installer/uninstall.sh` (POSIX) o
  `scripts/installer/uninstall.ps1` (PowerShell). Ambos piden confirmación antes
  de eliminar y rechazan destinos inseguros.
- **Copias de seguridad y estado** — las copias de seguridad de instalación
  residen bajo `~/.apothem/backups/` y el historial de instalaciones bajo
  `~/.apothem/state/`. Ambos tienen un tamaño acotado: después de cada
  instalación, desinstalación y reversión, Apothem conserva los 10 registros de
  instalación más recientes por raíz de instalación y los 10 conjuntos de copias
  de seguridad más recientes por entorno, y nunca elimina una copia de seguridad
  que un registro conservado todavía necesite, de modo que las 10 últimas
  instalaciones aún se pueden revertir. Para conservar menos, ejecuta
  [`apothem backups prune --keep N`](/docs/cli-reference/backups) (añade
  `--dry-run` para ver primero qué eliminaría); nunca elimina la copia de
  seguridad desde la que restaura la reversión de la instalación más reciente de
  un entorno. Una vez eliminado el motor, y cuando ya no necesites nada del
  historial, elimina `~/.apothem/`.

## Lo que NO se elimina

- `apothem uninstall` nunca elimina el YAML del perfil compartido en
  `~/.config/apothem/profile.yaml` o `--profile PATH`.
- Los archivos no relacionados escritos por el operador en los directorios de
  los entornos se conservan.
- Las entradas que añadiste a un archivo de ajustes compartido se conservan: tus
  propias reglas de permisos, servidores MCP y manejadores de hooks permanecen.
  La desinstalación elimina solo las claves y las entradas de lista que el
  historial de instalaciones registra como de Apothem (consulta
  [Configuración](/docs/reference/settings#fusión-con-tu-propio-archivo-de-ajustes)).
- Las suites de plan bajo `<project>/.apothem/plans/` (y el heredado `<project>/.plans/`) no se ven afectadas.

## Directorios

La desinstalación también elimina los directorios que creó la instalación (por
ejemplo, un `~/.claude/` que no existía antes de la primera instalación), una
vez que están vacíos. Un directorio que todavía contiene un archivo tuyo, o
datos que usa otro entorno instalado, permanece. Los directorios que existían
antes de la instalación nunca se eliminan.

Para limpiar por completo la raíz de un entorno, elimina la ruta nativa del
entorno documentada en las [páginas de referencia de entornos](/docs/harnesses)
después de confirmar que has hecho una copia de seguridad de cualquier regla,
utilidad o archivo de perfil personalizado que quieras conservar.
