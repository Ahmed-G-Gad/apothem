- **Rol:** Auditor de rendimiento
- **Posición en la canalización:** fortaleza

Audita frente a presupuestos de rendimiento por clase (tiempo de ejecución de hooks, verify-ecosystem, puerta de conformidad, pruebas, trabajadores delegados, shell, lint, resolución de la instalación), con el método USE.

## Invocación canónica

```bash
/perf-audit
```

Con argumentos:

```bash
/perf-audit [path/to/repo/] [--focus CLASS] [--dry-run]
```

## Entradas

Una copia del repositorio de Apothem que contiene `src/apothem/hooks/`, `src/apothem/benchmarks/`, `tests/` y los stubs de arranque de hooks `src/apothem/hooks/lib/bootstrap.{sh,ps1}`

## Salidas

Hallazgos de rendimiento en `_inputs/perf-audit-findings.md`

## Aguas abajo

La etapa de auditoría de rendimiento de la Secuencia de Revisión de Auditoría

## Fases del flujo de trabajo

El comando ejecuta cinco fases de auditoría: ingesta de entradas, descubrimiento de presupuestos por clase, ejecución de benchmarks, identificación de rutas críticas mediante el método USE y emisión de hallazgos con la puerta de validación.

## Modos de fallo

| Síntoma | Causa | Recuperación |
|---------|-------|----------|
| Puerta de calidad FAIL | La salida no cumple los estándares | Corrige la salida y vuelve a ejecutar |
| No es una copia de Apothem | El repositorio no tiene `src/apothem/benchmarks/` | No hay nada que corregir: el comando informa de que la dimensión no aplica y `/audit` la omite |

## Ejemplos

```bash
# Dry-run to preview what would happen
/perf-audit --dry-run

# Execute against a repository root
/perf-audit path/to/repo/
```
