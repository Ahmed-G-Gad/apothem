**Rol:** Auditor de accesibilidad
**Posición en el pipeline:** fortaleza

Auditoría de accesibilidad frente a WCAG 2.2 AA para cada página renderizada.

## Invocación canónica

```bash
/a11y-audit
```

Con argumentos:

```bash
/a11y-audit [path/to/site/ or URL] [--focus PAGE_OR_DIR] [--dry-run]
```

## Entradas

Sitio web del proyecto desplegado o servido localmente

## Salidas

Hallazgos de accesibilidad en `_inputs/a11y-audit-findings.md`

## Aguas abajo

La etapa de auditoría de accesibilidad de la Secuencia de Revisión de Auditoría

## Fases del flujo de trabajo

El comando ejecuta cinco fases de auditoría: ingesta de entradas, auditoría por página, clasificación por hallazgo, emisión de hallazgos y la puerta de validación.

## Modos de fallo

| Síntoma | Causa | Recuperación |
|---------|-------|----------|
| Puerta de calidad FAIL | La salida no cumple los estándares | Corrige la salida y vuelve a ejecutar |
| Falta un archivo de entrada | La ruta del sitio o la URL no se resuelve | Indica un directorio de sitio compilado o una URL accesible |

## Ejemplos

```bash
# Dry-run to preview what would happen
/a11y-audit --dry-run

# Execute against a built site directory
/a11y-audit path/to/site/
```
