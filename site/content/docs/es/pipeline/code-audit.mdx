**Rol:** Auditor
**Posición en el pipeline:** fortaleza

Auditoría forense de código entre archivos a escala del corpus del repositorio.

## Invocación canónica

```bash
/code-audit
```

Con argumentos:

```bash
/code-audit [path/to/repo/] [--focus AREA] [--dry-run]
```

## Entradas

Repositorio anfitrión con una disposición de código fuente aprobada, una línea base de cobertura de pruebas y (en SHARED+) una puerta de CI superada

## Salidas

Hallazgos a nivel de corpus en `_inputs/code-audit-findings.md`

## Aguas abajo

La etapa de auditoría forense de código de la Secuencia de Auditoría de Revisión

## Fases del flujo de trabajo

El comando ejecuta seis fases forenses: ingesta de entradas, recorrido de dependencias entre archivos, auditoría de anotaciones de tipo y cobertura, detección de código muerto y duplicado, auditoría de integridad arquitectónica y emisión de hallazgos con la puerta de validación.

## Modos de fallo

| Síntoma | Causa | Recuperación |
|---------|-------|----------|
| Puerta de calidad FAIL | La salida no cumple los estándares | Corrige la salida y vuelve a ejecutar |
| Falta un archivo de entrada | No hay ejecución de la puerta de CI ni línea base de cobertura de pruebas en SHARED+ | Ejecuta primero el pipeline de CI del anfitrión y luego vuelve a ejecutar el comando |

## Ejemplos

```bash
# Dry-run to preview what would happen
/code-audit --dry-run

# Execute against a repository root
/code-audit path/to/repo/
```
