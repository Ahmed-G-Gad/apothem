**Rol:** Revisor de UX
**Posición en el pipeline:** fortaleza

Revisión de experiencia de desarrollador sobre la ergonomía de la CLI, la documentación y la incorporación.

## Invocación canónica

```bash
/ux-review
```

Con argumentos:

```bash
/ux-review [path/to/plan-suite/] [phase-id] [--dry-run]
```

## Entradas

Repositorio anfitrión en cualquier estado del ciclo de vida

## Salidas

Hallazgos de UX + REPORT.md

## Aguas abajo

La etapa de revisión de UX de la Secuencia de Auditoría de Revisión

## Fases del flujo de trabajo

El comando sigue el flujo de trabajo estándar del pipeline `/plan`:

1. **Cargar contexto** — Leer la suite de plan, las reglas y el Contrato de Reanudación.
2. **Verificar prerrequisitos** — Confirmar que las fases dependientes están completas.
3. **Ejecutar tareas** — Realizar la misión del comando.
4. **Verificar salidas** — Confirmar que todas las salidas declaradas existen y pasan las compuertas de calidad.
5. **Actualizar PROGRESS.md** — Registrar las salidas verificadas en el Registro de Salidas de Fase.
6. **Emitir REPORT.md** — Prueba de publicación de la compuerta de pre-emisión registrada.

## Modos de fallo

| Síntoma | Causa | Recuperación |
|---------|-------|----------|
| Prerrequisito incompleto | Fase dependiente no terminada | Completa primero la fase aguas arriba |
| Compuerta de calidad FAIL | La salida no cumple los estándares | Corrige la salida y reejecuta |
| Falta un archivo de entrada | Archivo de la suite de plan ausente | Ejecuta `/plan-generate` para crearlo |

## Ejemplos

```bash
# Dry-run to preview what would happen
/ux-review --dry-run

# Execute against a named plan suite
/ux-review path/to/plan-suite/
```
