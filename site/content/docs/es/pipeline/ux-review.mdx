**Rol:** Revisor de UX
**Posición en la canalización:** fortaleza

Revisión de experiencia de desarrollador sobre la ergonomía de la CLI, la documentación y la incorporación.

## Invocación canónica

```bash
/ux-review
```

Con argumentos:

```bash
/ux-review [path/to/repo/] [--focus SURFACE] [--dry-run]
```

## Entradas

Repositorio anfitrión desplegado con README, scripts de instalación y un punto de entrada de CLI

## Salidas

Hallazgos de UX en `_inputs/ux-review-findings.md`

## Aguas abajo

La etapa de revisión de UX de la Secuencia de Auditoría de Revisión

## Fases del flujo de trabajo

El comando ejecuta cinco fases: ingesta de entradas, recorrido de ergonomía de la CLI, auditoría del flujo de instalación y de recuperación de errores, barrido de descubribilidad de la documentación y emisión de hallazgos con la puerta de validación.

## Modos de fallo

| Síntoma | Causa | Recuperación |
|---------|-------|----------|
| Prerrequisito incompleto | Fase dependiente no terminada | Completa primero la fase aguas arriba |
| Puerta de calidad FAIL | La salida no cumple los estándares | Corrige la salida y vuelve a ejecutar |
| Destino no desplegado | El destino no tiene la superficie orientada al operador | Indica la raíz del repositorio desplegado |

## Ejemplos

```bash
# Dry-run to preview what would happen
/ux-review --dry-run

# Execute against a host repository
/ux-review path/to/repo/
```
