**Rol:** Auditor de seguridad
**Posición en el pipeline:** fortaleza

Auditoría integral de la postura de seguridad frente a OWASP ASVS 4.0 o posterior y frente al OWASP Top 10.

La versión mínima de referencia del comando es la última publicación de parche de ASVS 4.0. No consulta por sí mismo versiones más recientes de ASVS. Los hallazgos citan los capítulos de ASVS por número y título breve, como V5 (Validation, Sanitization, Encoding), V12 (File and Resources) y V14 (Configuration).

## Invocación canónica

```bash
/security-audit
```

Con argumentos:

```bash
/security-audit [path/to/repo/] [--focus CATEGORY] [--dry-run]
```

## Entradas

Repositorio anfitrión en un commit de git fijado

## Salidas

Hallazgos de seguridad en `_inputs/security-audit-findings.md`

## Aguas abajo

La etapa security-audit de la Secuencia de Revisión de Auditoría

## Fases del flujo de trabajo

El comando ejecuta seis fases de auditoría: ingesta de entradas, secretos y permisos, validación de entradas e inyección, deserialización y recorrido de rutas, CVE de dependencias y CodeQL, y emisión de hallazgos con la puerta de validación.

## Modos de fallo

| Síntoma | Causa | Recuperación |
|---------|-------|----------|
| Prerrequisito incompleto | Fase dependiente no terminada | Completa primero la fase aguas arriba |
| Puerta de calidad FAIL | La salida no cumple los estándares | Corrige la salida y vuelve a ejecutar |
| Destino rechazado | La ruta no es un árbol de trabajo de git | Indica la raíz del repositorio como ruta |

## Ejemplos

```bash
# Dry-run to preview what would happen
/security-audit --dry-run

# Execute against a host repository
/security-audit path/to/repo/
```
