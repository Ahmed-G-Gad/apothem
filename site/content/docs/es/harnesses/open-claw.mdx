**Proveedor:** Open-Claw
**Nombre de instalación:** `open-claw`
**Estado:** Vista previa
**Configuración nativa:** `~/.openclaw/openclaw.json`

## Instalación

```bash
apothem install --harness open-claw
```

El adaptador escribe el archivo de configuración global de usuario de OpenClaw,
proyecta el perfil compartido en un documento de perfil e instala las cohortes
de soporte de Apothem bajo la raíz del entorno. La configuración nativa de
OpenClaw es JSON; el materializador renderiza un objeto JSON vacío, y un archivo
existente conserva sus claves.

**Archivos escritos:** `~/.openclaw/openclaw.json`, el documento de perfil
`~/.openclaw/apothem/rules/00-apothem-profile.md` y archivos de soporte bajo
`~/.openclaw/.apothem/support/`

El documento de perfil termina con una sección de archivos de soporte de
Apothem que nombra el directorio absoluto bajo `~/.openclaw/.apothem/support/`
contra el que se resuelve cada cita con estilo de repositorio
(`rules/<name>.md`, `templates/...`, `hooks/...`).

## Asignación del perfil a la configuración nativa

El adaptador lee el perfil compartido de Apothem, pero no redacta ninguna clave
de configuración: un `openclaw.json` nuevo o vacío se escribe como un objeto
vacío, y un archivo existente conserva sus claves. La identidad, las
preferencias y las reglas del perfil van al documento de perfil. Los comandos,
las skills, las reglas, las plantillas y los prompts de hooks compartidos se
instalan como material de soporte bajo `~/.openclaw/.apothem/support/`.

## Notas de compatibilidad

Adaptador en vista previa. OpenClaw no carga por sí solo el subárbol de soporte ni el documento de perfil: ninguna de sus ubicaciones de skills, ninguno de sus archivos de instrucciones del espacio de trabajo ni su configuración apuntan allí. Por eso, tras la instalación, OpenClaw se ejecuta sin las reglas, las skills ni los servidores MCP de Apothem. OpenClaw lee las skills desde las carpetas `skills/` y `.agents/skills/` de su espacio de trabajo, desde `~/.agents/skills` y desde su directorio de estado, y luego las filtra con la lista de permitidos de nombres de skills bajo `agents.defaults.skills`. `skills.load.extraDirs` no es un cargador de skills, así que las skills de Apothem en `~/.openclaw/.apothem/support/skills` solo se cargan cuando las colocas en una de esas carpetas y las nombras en esa lista de permitidos. `apothem update` conserva las claves que agregas a `openclaw.json`. Los servidores MCP residen en el bloque `mcp.servers` de la configuración de OpenClaw, que gestionas con `openclaw mcp add` y los subcomandos relacionados; el adaptador no escribe ninguna entrada allí. (Comportamiento de OpenClaw según su documentación de [skills](https://docs.openclaw.ai/tools/skills) y de [la CLI de MCP](https://docs.openclaw.ai/cli/mcp), consultada el 2026-10-02.)

## Verificación

```bash
apothem verify --harness open-claw
```

El comando verify confirma que:

1. La configuración nativa existe en la ruta esperada.
2. Cada destino gestionado existe; los archivos gestionados no están vacíos y
   las configuraciones JSON o YAML se analizan correctamente. Añade
   `--profile PATH` para confirmar también que los archivos instalados coinciden
   con ese perfil.
3. La rutina de verificación específica del adaptador informa de éxito.

## Actualización

```bash
apothem update --harness open-claw
```

Vuelve a derivar el documento de perfil a partir del estado actual del perfil
compartido y refresca los archivos de soporte; `openclaw.json` conserva las
claves que ya tiene.
Ejecútalo después de editar `~/.config/apothem/profile.yaml` o de actualizar el
paquete de Apothem instalado.

## Desinstalación

```bash
apothem uninstall --harness open-claw
```

Elimina lo que agregó el adaptador: el documento de perfil y el árbol de
soporte. Tus propias claves en `openclaw.json` permanecen, y el archivo se
elimina solo cuando Apothem lo creó y no queda nada tuyo. El YAML del perfil
compartido y el motor de Apothem no se ven afectados.

## Puerta de conformidad

```bash
python -m apothem.conformity.gate --all .
```

## Solución de problemas

| Síntoma | Solución |
|---------|-----|
| No se encuentra el archivo de configuración | Vuelve a ejecutar `apothem install --harness open-claw` |
| La verificación falló | Ejecuta `apothem update --harness open-claw` y luego verifica de nuevo |
| Contenido de configuración inesperado | Apothem no crea ninguna clave en `openclaw.json` y conserva las que ya contiene, así que el contenido del perfil no llega allí. El contenido del perfil llega a `~/.openclaw/apothem/rules/00-apothem-profile.md`: revisa `~/.config/apothem/profile.yaml` o `--profile PATH` y luego vuelve a ejecutar el comando descrito en [Actualización](#actualización) |
