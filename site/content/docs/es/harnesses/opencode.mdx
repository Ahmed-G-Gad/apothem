**Proveedor:** OpenCode
**Nombre de instalación:** `opencode`
**Estado:** Beta
**Configuración nativa:** `~/.config/opencode/`

## Instalación

```bash
apothem install --harness opencode
```

El adaptador escribe la configuración JSON de OpenCode, instala las skills de
Apothem en la superficie de skills de OpenCode, convierte los prompts de comando
en archivos de comando Markdown de OpenCode y normaliza las definiciones de
ayudantes de Apothem como subayudantes de OpenCode.

**Archivos escritos:**

```text
~/.config/opencode/opencode.json
~/.config/opencode/commands/
~/.config/opencode/skills/
~/.config/opencode/agents/
~/.config/opencode/.apothem/support/{rules,templates,hooks}/
```

## Asignación del perfil a la configuración nativa

El adaptador renderiza `opencode.json` con una lista de archivos `instructions`
que nombra tu documento de perfil y las reglas siempre activas de Apothem, y
luego propaga cada cohorte compartida de Apothem a una superficie nativa de
OpenCode o a un subárbol de soporte propiedad de Apothem. Los hijos existentes
gestionados por Apothem que coinciden se respaldan antes de reemplazarse.

## Notas de compatibilidad

OpenCode combina en cada sesión todos los archivos que nombra la lista
`instructions` ([reglas de OpenCode](https://opencode.ai/docs/rules/)). Por eso
la lista nombra primero tu documento de perfil y después solo las reglas cuyo
`alwaysApply` es `true`, cada una con una ruta
`~/.config/opencode/.apothem/support/rules/<name>.md` explícita; OpenCode
expande el `~/` inicial contra tu directorio personal. Las reglas filtradas por
ruta, las plantillas y los prompts de hooks quedan instalados como material de
referencia bajo `~/.config/opencode/.apothem/support/`, donde una regla, una
skill o un comando que cite uno de ellos lo lee bajo demanda. Los comandos, las
skills y las definiciones de ayudantes usan ubicaciones de descubrimiento
nativas.

El documento de perfil `~/.config/opencode/apothem/rules/00-apothem-profile.md`
lleva tu identidad y tus preferencias del perfil compartido, y termina con una
sección de archivos de soporte de Apothem que nombra el directorio absoluto bajo
`~/.config/opencode/.apothem/support/` contra el que se resuelve cada cita con
estilo de repositorio (`rules/<name>.md`, `templates/...`, `hooks/...`). Es la
primera entrada de `instructions`, así que OpenCode lo carga en cada sesión.

Un `opencode.json` escrito por un lanzamiento anterior lista el único glob
`~/.config/opencode/.apothem/support/rules/*.md`, que carga todas las reglas.
`apothem install` y `apothem update` lo reemplazan por la lista de reglas
siempre activas, y `apothem uninstall` elimina ambas formas. Tus propias
entradas de `instructions` se conservan en todos los casos.

## Verificación

```bash
apothem verify --harness opencode
```

El comando verify confirma que:

1. La configuración nativa existe en la ruta esperada.
2. Cada destino gestionado existe; los archivos gestionados no están vacíos y las configuraciones JSON o YAML se analizan correctamente. Añade `--profile PATH` para confirmar también que los archivos instalados coinciden con ese perfil.
3. La rutina de verificación específica del adaptador informa de éxito.

## Actualización

```bash
apothem update --harness opencode
```

Refresca `opencode.json`, los comandos nativos, las skills, las definiciones de
ayudantes y el árbol de soporte de Apothem.

## Desinstalación

```bash
apothem uninstall --harness opencode
```

Elimina los archivos de configuración nativa escritos por el adaptador.
El YAML del perfil compartido y el motor de Apothem no se ven afectados.

## Puerta de conformidad

```bash
python -m apothem.conformity.gate --all .
```

## Solución de problemas

| Síntoma | Solución |
|---------|-----|
| No se encuentra el archivo de configuración | Vuelve a ejecutar `apothem install --harness opencode` |
| La verificación falló | Ejecuta `apothem update --harness opencode` y luego verifica de nuevo |
| Contenido de configuración inesperado | Revisa `~/.config/apothem/profile.yaml` o `--profile PATH` y luego vuelve a ejecutar `apothem update --harness opencode` |

## Opciones de configuración

| Indicador | Predeterminado | Descripción |
|------|---------|-------------|
| `--dry-run` | `false` | Previsualiza la instalación sin escribir archivos. |
