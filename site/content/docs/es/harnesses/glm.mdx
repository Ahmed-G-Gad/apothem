**Proveedor:** Z.ai
**Nombre de instalación:** `glm`
**Estado:** GA
**Configuración nativa:** `<project>/.apothem/providers/glm.toml`

GLM (Z.ai) es un **backend de modelos**, no una herramienta de programación
propia. Z.ai no distribuye ninguna línea de comandos de GLM propia; en su lugar,
una herramienta que habla el protocolo compatible con Anthropic o el compatible
con OpenAI se dirige a GLM estableciendo una URL base de backend y una clave.
Apothem sigue contando a GLM entre sus adaptadores de entorno, así que lo
seleccionas con `--harness glm` como a cualquier otro. El adaptador `glm`
escribe un archivo de configuración de proveedor que registra ambas superficies
de compatibilidad, de modo que cualquier herramienta compatible pueda
conectarse a la familia de modelos GLM.

## Instalación

```bash
apothem install --harness glm --project /path/to/project
```

El adaptador escribe un archivo de proveedor con alcance de proyecto que
registra los endpoints del backend de GLM y marcadores de posición que el
operador puede configurar.

**Archivos escritos:** `<project>/.apothem/providers/glm.toml`

## Asignación del perfil a la configuración nativa

El archivo de proveedor registra dos backends. El backend compatible con
Anthropic usa la URL base `https://api.z.ai/api/anthropic`; una herramienta que
habla el protocolo de Anthropic se enruta a GLM estableciendo
`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` y, opcionalmente,
`API_TIMEOUT_MS`. La tabla `[backends.anthropic_compatible.env]` del archivo
lista esas variables y también `ANTHROPIC_DEFAULT_OPUS_MODEL`,
`ANTHROPIC_DEFAULT_SONNET_MODEL` y `ANTHROPIC_DEFAULT_HAIKU_MODEL`, que asignan
los roles opus, sonnet y haiku de la herramienta a modelos GLM. El backend
compatible con OpenAI usa la URL base `https://api.z.ai/api/coding/paas/v4`. El
token de autenticación es un marcador de posición que reemplazas con tu propia
clave de Z.ai: Apothem nunca escribe un secreto real. Los ID de modelo cambian
entre versiones, así que Apothem no fija ninguno; el archivo lleva marcadores de
posición `<GLM_MODEL_ID>` que completas a partir de la
[documentación de Z.ai](https://docs.z.ai/devpack/tool/claude) actual. Nada del
perfil compartido se incorpora a este archivo; es una plantilla fija.

## Notas de compatibilidad

Como GLM es un backend y no una herramienta de programación, no expone ninguna
superficie para reglas, comandos, skills ni hooks: el adaptador escribe solo el
archivo de proveedor del backend y nada más. Tu clave de Z.ai y tus elecciones de
ID de modelo siguen siendo propiedad del operador. Las convenciones de la
superficie del proveedor en las que se apoya el adaptador están fijadas en
`src/apothem/harnesses/glm/STANDARD-CONVENTION-PIN.md`, capturadas en una
instantánea frente a la documentación en vivo de Z.ai.

GLM ejecuta la familia de modelos GLM de Z.ai; consulta la
[referencia de configuración del proveedor](https://docs.z.ai/devpack/tool/claude)
para conocer la superficie actual de configuración del backend, de los modelos y
de la compatibilidad con Anthropic.

## Verificación

```bash
apothem verify --harness glm --project /path/to/project
```

El comando verify confirma que:

1. La configuración nativa existe en la ruta esperada.
2. El archivo de proveedor está presente y no está vacío.
3. La rutina de verificación específica del adaptador informa éxito.

## Actualización

```bash
apothem update --harness glm --project /path/to/project
```

El archivo de proveedor es tuyo una vez que existe. `install` y `update`
escriben la plantilla solo cuando `.apothem/providers/glm.toml` no existe, y
ninguno de los dos lo sobrescribe nunca después, así que tu referencia de clave y
tus elecciones de modelo se conservan en cada nueva ejecución. Para obtener una
plantilla más reciente, aparta tu archivo, ejecuta `update` y copia tus valores
en el archivo nuevo.

## Desinstalación

```bash
apothem uninstall --harness glm --project /path/to/project
```

Elimina el archivo de proveedor solo cuando Apothem lo creó y sigue siendo la
plantilla sin editar, y antes lo respalda bajo la raíz de respaldos de Apothem.
Un archivo que creaste o editaste se deja en su lugar. El YAML del perfil
compartido y el motor de Apothem no se ven afectados.

python -m apothem.conformity.gate --all .

## Solución de problemas

| Síntoma | Solución |
|---------|-----|
| No se encuentra el archivo de configuración | Vuelve a ejecutar `apothem install --harness glm --project /path/to/project` |
| La verificación falló | El archivo de proveedor falta o está vacío. Si falta, ejecuta `apothem update --harness glm --project /path/to/project`. Si está vacío, aparta primero `.apothem/providers/glm.toml`, luego ejecuta `update` y verifica de nuevo |
| Contenido de configuración inesperado | Edita `.apothem/providers/glm.toml` directamente; Apothem nunca reescribe un archivo existente y el perfil compartido no le añade nada. Para obtener una plantilla nueva, aparta el archivo y ejecuta `apothem update --harness glm --project /path/to/project` |
