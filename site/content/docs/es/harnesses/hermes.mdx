**Proveedor:** Hermes
**Nombre de instalación:** `hermes`
**Estado:** Vista previa
**Configuración nativa:** `~/.hermes/config.yaml`

## Instalación

```bash
apothem install --harness hermes
```

El adaptador traduce el perfil compartido al archivo de configuración global de
usuario de Hermes Agent e instala las cohortes de soporte de Apothem bajo la
raíz del entorno.

**Archivos escritos:** `~/.hermes/config.yaml`, el documento de perfil
`~/.hermes/apothem/rules/00-apothem-profile.md` y archivos de soporte bajo
`~/.hermes/.apothem/support/`

El documento de perfil termina con una sección de archivos de soporte de
Apothem que nombra el directorio absoluto bajo `~/.hermes/.apothem/support/`
contra el que se resuelve cada cita con estilo de repositorio
(`rules/<name>.md`, `templates/...`, `hooks/...`).

## Asignación del perfil a la configuración nativa

El adaptador lee el perfil compartido de Apothem y renderiza la configuración
YAML nativa, incluido el inventario MCP del perfil. La identidad, las
preferencias y las reglas del perfil van al documento de perfil. Los comandos,
las skills, las definiciones de ayudantes, las reglas, las plantillas y los
prompts de hook compartidos quedan como material de soporte bajo
`~/.hermes/.apothem/support/`.

## Notas de compatibilidad

Adaptador en vista previa. Hermes no carga por sí mismo el árbol de
soporte ni el documento de perfil: nada en `config.yaml` ni ninguno de los
archivos de contexto que lee Hermes apunta allí, así que después de la
instalación Hermes se ejecuta sin las reglas, las skills ni los hooks de
Apothem. Hermes lee skills de `~/.hermes/skills/` y de cada carpeta listada
bajo `skills.external_dirs` en `config.yaml`; para usar las skills de Apothem,
agrega tú mismo `~/.hermes/.apothem/support/skills` a esa lista;
`apothem update` conserva las claves que agregues a `config.yaml`. El adaptador
escribe el inventario MCP del perfil bajo la clave de nivel superior
`mcp_servers`, donde Hermes lee los servidores MCP. Los lanzamientos anteriores
de Apothem lo escribían bajo `auxiliary.mcp`, que Hermes lee como el modelo
auxiliar para el despacho de herramientas MCP; tanto `apothem update` como
`apothem uninstall` eliminan ese bloque cuando sigue coincidiendo con lo que
escribiría uno de esos lanzamientos a partir de tu perfil compartido actual
(consulta [Desinstalación](#desinstalación) para saber cuándo se conserva).
(Comportamiento de Hermes según las páginas de su guía de usuario sobre
[skills](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md)
y [MCP](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/mcp.md),
consultadas el 2026-10-02.)

## Verificación

```bash
apothem verify --harness hermes
```

El comando verify confirma que:

1. La configuración nativa existe en la ruta esperada.
2. Cada destino gestionado existe; los archivos gestionados no están vacíos y
   las configuraciones JSON o YAML se analizan correctamente. Añade
   `--profile PATH` para confirmar también que los archivos instalados coinciden
   con ese perfil.
3. La rutina de verificación específica del adaptador informa de éxito.

## Actualización

```bash
apothem update --harness hermes
```

Vuelve a derivar la configuración nativa a partir del estado actual del perfil
compartido.
Ejecútalo después de editar `~/.config/apothem/profile.yaml` o de actualizar el
paquete de Apothem instalado.

## Desinstalación

```bash
apothem uninstall --harness hermes
```

Elimina lo que agregó el adaptador: las entradas de `mcp_servers` que su
instalación registró en `config.yaml` (tus propias claves se conservan, y el
archivo se elimina solo cuando Apothem lo creó y no queda nada tuyo en él), el
documento de perfil y el árbol de soporte. El YAML del perfil compartido y el
motor de Apothem no se ven afectados.

En una instalación hecha por un lanzamiento anterior, que escribía los
servidores del perfil bajo `auxiliary.mcp`, también se elimina ese bloque
cuando sigue coincidiendo con lo que escribiría ese lanzamiento a partir de tu
perfil compartido actual en `~/.config/apothem/profile.yaml`. Es la misma regla
que aplica `apothem update`, así que desinstalar sin actualizar antes no deja
ningún bloque obsoleto mientras los servidores MCP del perfil no cambien. Un
bloque que hayas editado, uno que ya no coincide con los servidores MCP de tu
perfil actual, o uno sin un perfil compartido legible con el que compararlo, se
queda en su lugar, y el resto de tus ajustes de `auxiliary` siempre se conserva.

```bash
python -m apothem.conformity.gate --all .
```

## Solución de problemas

| Síntoma | Solución |
|---------|-----|
| No se encuentra el archivo de configuración | Vuelve a ejecutar `apothem install --harness hermes` |
| La verificación falló | Ejecuta `apothem update --harness hermes` y luego verifica de nuevo |
| Contenido de configuración inesperado | Revisa `~/.config/apothem/profile.yaml` o `--profile PATH` y luego vuelve a ejecutar `apothem update --harness hermes` |

## Opciones de configuración

| Indicador | Predeterminado | Descripción |
|------|---------|-------------|
| `--dry-run` | `false` | Previsualiza la instalación sin escribir archivos. |
