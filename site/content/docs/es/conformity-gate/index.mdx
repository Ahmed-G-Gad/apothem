## Escala de severidad

La puerta de conformidad no tiene escala Crítica, Importante ni Consultiva, y tampoco umbral de dos hallazgos. Sin `--strict` (o `APOTHEM_CONFORMITY_STRICT=1`), la puerta informa los hallazgos y termina con `0`. Con `--strict`, una comprobación de un archivo o de hook termina con `2` cuando falla cualquier comparador, y una ejecución sobre el corpus (`--all-perwrite`) termina con `2` cuando falla un comparador bloqueante; los comparadores consultivos solo se informan. El hook de Write/Edit instalado no pasa `--strict`, así que informa los hallazgos y la escritura continúa, salvo que `APOTHEM_CONFORMITY_STRICT=1` esté definido en el entorno de ese hook.

## Validadores

La fracción mecánica reside en [`src/apothem/conformity/`](https://github.com/ahmed-g-gad/apothem/tree/main/src/apothem/conformity), orquestada por [`src/apothem/conformity/gate.py`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/conformity/gate.py).
Cada validador se ejecuta de una de tres maneras:

- **por escritura**: en cada escritura pendiente (`--hook`), o en cada archivo rastreado con `--all-perwrite`.
- **independiente**: en todo el repositorio con `--all`, o de uno en uno con `--check <name>`.
- **por conjunto de cambios**: sobre un diff preparado, ejecutado directamente como `python -m apothem.conformity.semver_stability_grep --staged`, no a través de la puerta.

## Ejecutar la puerta

En un entorno instalado, la puerta se ejecuta automáticamente: el
`settings.json` de Claude Code la conecta como un hook `PreToolUse` que invoca
la copia materializada en `~/.claude/.apothem/support/conformity/gate.py` antes
de cada Write/Edit. Desde un checkout del código fuente, la forma de módulo
ejecuta el mismo código. La puerta es consultiva de forma predeterminada:
informa los hallazgos y termina con `0`. Agrega `--strict` para terminar con
`2` ante un hallazgo bloqueante. Un nombre de validador desconocido termina con
`3`.

```shell
# Every standalone validator across the repository:
python -m apothem.conformity.gate --all .

# The same sweep, failing on a blocking finding (the CI form):
python -m apothem.conformity.gate --all --strict .

# Every per-write validator against every tracked file:
python -m apothem.conformity.gate --all-perwrite .

# One validator by name (names come from --list):
python -m apothem.conformity.gate --check naming-grep .

# List every registered validator as JSON:
python -m apothem.conformity.gate --list

# Single-file dispatch (mimics the PreToolUse hook):
echo '{"tool_input": {"file_path": "path/to/file", "content": "..."}}' \
    | python -m apothem.conformity.gate --hook
```

`python -m apothem.conformity.gate --help` imprime el resumen de uso.
Consulta [Ejecutar la puerta de conformidad](/docs/usage/conformity-gate) para ver el procedimiento completo.
