Informa el estado de instalación, de verificación y de desviación de cada entorno
registrado.

## Sinopsis

```
apothem status [--profile PATH] [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status` es un comando de inspección de solo lectura. Recorre cada adaptador de
entorno registrado e informa tres hechos por entorno: si está instalado, si sus
destinos gestionados se verifican y si la configuración instalada se ha desviado
del perfil compartido. No escribe nada en disco.

Para cada entorno, `status` informa:

| Columna | Significado |
|---|---|
| `installed` | La configuración gestionada del adaptador existe en su ruta de destino. |
| `verified` | Los destinos gestionados del adaptador están presentes y son válidos. |
| `drift` | El veredicto de fidelidad al perfil (ver más abajo). |

El valor de `drift` es uno de los siguientes:

| Valor | Significado |
|---|---|
| `in-sync` | La configuración instalada lleva textualmente el perfil compartido recién proyectado. |
| `drift` | El entorno está instalado, pero el contenido de perfil proyectado ya no coincide con el perfil compartido actual. Vuelve a ejecutar `apothem install` para proyectarlo de nuevo. |
| `absent` | El entorno no está instalado, así que no hay nada que comparar. |
| `needs-project` | Se informó un entorno con alcance de proyecto sin `--project`, así que su destino no puede resolverse. Pasa `--project PATH` para inspeccionarlo. |
| `unknown` | No se pudo cargar el perfil predeterminado, así que un entorno instalado no tiene una referencia con la que compararse. Corrige el perfil para recuperar el veredicto de desviación. |

La desviación se informa y nunca se trata como un error: `status` sale con 0
incluso cuando uno o más entornos informan `drift`. La desviación es un hecho
sobre tu configuración, no un fallo del comando.

Si no se puede cargar el perfil compartido predeterminado, la desviación se
degrada a `unknown` para los entornos instalados (los hechos de instalación y de
verificación se siguen informando) en lugar de abortar el barrido. Un
`--profile` explícito que no se puede cargar es un error del usuario y, en
cambio, aborta con un error estructurado.

La degradación siempre se informa: `status` imprime un aviso que nombra el
perfil y la corrección, y el sobre `--json` lleva una entrada
`drift_baseline_unavailable` correspondiente en `warnings`. Esto importa sobre
todo cuando no hay ningún entorno instalado: entonces cada fila muestra `absent`
y no existe ninguna celda `unknown`, así que el aviso es la única señal de que la
referencia nunca se cargó.

## Opciones

| Opción | Descripción |
|---|---|
| `--profile PATH` | YAML del perfil compartido que selecciona la referencia de desviación. Sin esta opción, se usa el perfil predeterminado (`~/.config/apothem/profile.yaml`). |
| `--project PATH` | Raíz del proyecto para los entornos con alcance de proyecto. Sin esta opción, los entornos con alcance de proyecto informan `needs-project`. |
| `--quiet`, `-q` | Suprime la salida informativa; solo se emiten errores. |
| `--verbose`, `-v` | Emite salida de diagnóstico adicional. |
| `--format plain\|json` | Formato de salida (por defecto: `plain`). |
| `--json` | Abreviatura de `--format json`. |
| `--no-color` | Desactiva los códigos de color ANSI en la salida. |
| `-h`, `--help` | Muestra la ayuda y sale. |

## Salida JSON

El sobre `--json` lleva una fila de resultado por cada entorno registrado. Cada
fila lleva las claves documentadas `harness`, `installed`, `verified` y `drift`.
`warnings` está vacío en un barrido limpio; cuando no se pudo cargar el perfil
predeterminado, lleva una entrada `drift_baseline_unavailable` con `path`,
`code`, `reason` y `fix`.

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

Aislamiento de fallos por adaptador: si un único adaptador lanza una excepción
al informar su estado, la fila de ese entorno lleva `outcome: "error"` y un
`message`, los entornos restantes siguen informando con normalidad y el proceso
sale con el código 2.

## Ejemplos

```bash
apothem status
apothem status --project .
apothem status --json
```

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Estado informado (la desviación se informa, no es un error) |
| 1 | Error de validación esperado (un `--profile` no válido, o una ruta de `--project` que no existe) |
| 2 | Al menos un adaptador no pudo informar su estado |
| 64 | Error de uso: una opción o un comando desconocidos, o un valor de opción ausente o no válido. Con `--json`, el error es un sobre JSON con el código `cli.usage`. |
