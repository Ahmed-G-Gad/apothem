Verifica la instalación de un adaptador de entorno.

## Sinopsis

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

Llama a la implementación `verify()` de cada adaptador seleccionado. Sale con 0
solo cuando todos los adaptadores seleccionados informan que sus destinos
gestionados están presentes y son válidos. Sin `--profile`, la comprobación es
**estructural**: cada destino gestionado debe estar presente y ser válido. Con
`--profile`, la comprobación exige además **fidelidad al perfil**, de modo que
una instalación presente pero desviada no supera verify, y responde a «¿está
ESTE perfil instalado fielmente?» en lugar de solo a «¿existe?».

Para un adaptador que escribe skills en tu directorio personal, verify también
comprueba que cada carpeta de skill que espera exista con un `SKILL.md`, sea cual
sea la instalación que la escribió, de modo que una máquina donde solo está
instalada una de las herramientas que comparten una carpeta supera la
verificación. Falla cuando falta una carpeta, y cuando una carpeta con el nombre
de una skill de Apothem pertenece a algo que Apothem no escribió. Una fila
fallida indica cuál de los dos casos es: en modo plain le sigue una línea
`Note:`, y en la fila JSON un objeto `user_level` lista las rutas `missing` y
`unlisted` y un `message`. Ejecuta [`install`](/docs/cli-reference/install) para
restaurar una carpeta que falta; cambia el nombre de una carpeta ajena o muévela
y luego ejecuta [`update`](/docs/cli-reference/update).

Un barrido con `--harness all` respeta el `exclude_harnesses` del perfil — las
mismas exclusiones que aplicó el lote de `install`/`update` —, de modo que
verify nunca informa como ausente un entorno excluido deliberadamente. Las
exclusiones provienen de `--profile` cuando se proporciona y, en caso contrario,
del perfil predeterminado; un perfil predeterminado ilegible o ausente se
degrada al registro completo.

## Opciones

| Opción | Descripción |
|---|---|
| `--harness NAME` | Adaptador de entorno que se verifica, o `all` para el conjunto de todo el registro (obligatorio). |
| `--profile PATH` | YAML del perfil compartido contra el que se comprueba la fidelidad. Sin él, la comprobación es puramente estructural. |
| `--project PATH` | Raíz del proyecto para los entornos de alcance de proyecto. |
| `--quiet`, `-q` | Suprime la salida informativa; solo se emiten errores. |
| `--verbose`, `-v` | Emite salida de diagnóstico adicional. |
| `--format plain\|json` | Formato de salida (predeterminado: `plain`). |
| `--json` | Abreviatura de `--format json`. |
| `--no-color` | Desactiva los códigos de color ANSI en la salida. |
| `-h`, `--help` | Muestra la ayuda y sale. |

## Salida JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Cuando cualquier entorno seleccionado falta o no es válido, `status` es
`error`, la fila de resultado que falla lleva `verified: false` y el proceso
sale con el código 1.

## Ejemplos

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Entorno verificado — todos los destinos gestionados están presentes y son válidos |
| 1 | Entorno no verificado — faltan destinos gestionados o no son válidos |
| 64 | Error de uso: una opción o un comando desconocidos, o un valor de opción ausente o no válido. Con `--json`, el error es un sobre JSON con el código `cli.usage`. |
