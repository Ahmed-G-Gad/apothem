Elimina la configuración de un adaptador de entorno.

## Sinopsis

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

Elimina los destinos del entorno gestionados por el adaptador y luego los
directorios que creó la instalación, una vez que están vacíos (un directorio que
contiene algo tuyo se queda).

La memoria, los contextos y los almacenes de aprendizaje del directorio de trabajo compartido se respaldan y se eliminan solo cuando este es el último entorno instalado en ese directorio. La desinstalación los elimina en la ubicación que registró la instalación, de modo que los encuentra dondequiera que la instalación los haya escrito (consulta los campos `workspace` del perfil). El directorio `plans/` nunca se elimina.

Pide confirmación a menos que se proporcione `--yes`. Cuando no es posible mostrar una solicitud — `--format json` (el texto de la solicitud corrompería el único documento JSON) o una shell no interactiva (sin TTY) — el comando se niega de antemano con un error estructurado `uninstall.confirmation_required` (código de salida 1) a menos que se proporcione `--yes`. Si un entorno seleccionado no está instalado, el comando tiene éxito (código de salida 0) y, en la salida de texto plano, imprime `NAME is not installed; nothing to remove.`, donde `NAME` es el identificador del entorno.

Los almacenes de datos compartidos bajo `.apothem/` en la raíz de instalación
(`memory/`, `contexts/`, `learning/`) se conservan mientras otro entorno
instalado en la misma raíz siga usándolos. Cuando el entorno que eliminas es el
último en esa raíz, el comando copia primero cada almacén en la raíz de copias de
seguridad de Apothem (`~/.apothem/backups/`) y luego lo elimina con todo su
contenido. Lo que conserves en `plans/` nunca se elimina.

## Carpetas compartidas en tu directorio personal

Varias instalaciones pueden usar una misma carpeta de tu directorio personal: la
carpeta de skills (`~/.agents/skills/`, o `~/.codebuddy/skills/`,
`~/.kiro/skills/` o `~/.trae/skills/`) y `~/.config/apothem/rules/` y
`~/.config/apothem/templates/`. La página de [install](/docs/cli-reference/install#carpetas-en-tu-directorio-personal)
lista qué adaptador escribe cada una. Apothem registra qué instalaciones usan
cada carpeta, y una desinstalación sigue una regla: elimina una carpeta solo
cuando ninguna otra instalación de Apothem la sigue usando.

- Desinstalar una herramienta conserva las skills mientras otra instalación
  siga usándolas, y lo indica. Una herramienta instalada en dos proyectos cuenta
  como dos instalaciones, así que desinstalarla del proyecto A conserva las
  carpetas mientras el proyecto B siga usándolas. La última desinstalación las
  elimina (consulta el segundo ejemplo más abajo).
- Solo se elimina lo que lista el registro propio de la instalación. Una
  instalación hecha antes de que las carpetas se gestionaran no tiene tal
  registro, así que desinstalarla no elimina nada de tu directorio personal. Los
  archivos que agregaste a las carpetas se quedan, y también una carpeta que
  tiene el nombre de una skill de Apothem y que Apothem no escribió.
- Una instalación cuya carpeta de proyecto ya no existe se ignora, de modo que un
  proyecto eliminado no retiene las carpetas para siempre. La nota la nombra.
- Si no se puede leer el registro de una instalación que podría usar las
  carpetas, la desinstalación se detiene con un error antes de eliminar nada, y
  la instalación sigue registrada. Repara o mueve el registro ilegible y luego
  vuelve a ejecutar el comando. Se ignora un registro dañado de una herramienta
  que nunca escribe estas carpetas.
- Cuando desaparece el último uso, las carpetas que quedan vacías también se
  eliminan. Cada carpeta se respalda en `~/.apothem/backups/` antes de
  eliminarla.

Cada desinstalación imprime una `Note:` por carpeta, por ejemplo `Note: <harness> -
~/.agents/skills/ was kept: still used by <harness> (/path/to/project)`, o
`was removed: no other Apothem install uses it`. En el sobre de `--format json`,
cada nota es una entrada de `warnings` con `"outcome": "advisory"`,
`"operation": "shared_root"` y `"role"` con valor `retained` o `released`. Lleva
`path`, `holders` (las instalaciones que conservan la carpeta), `stale`
(instalaciones ignoradas), y `kept` y `total` (las entradas registradas que se
conservan y las entradas que listaba la instalación).

Si una carpeta se queda por una instalación que no encuentras, la nota la nombra.
Cuando se eliminó la carpeta del proyecto, la instalación se ignora y la carpeta
desaparece con la siguiente desinstalación. Cuando el proyecto existe pero
quitaste a mano el bloque de Apothem de su archivo de reglas, `uninstall` informa
que el entorno no está instalado y no libera su reclamación; ejecuta `install`
para ese entorno y ese proyecto, y luego `uninstall`, para liberarla.
`apothem verify` muestra si una carpeta sigue completa.

Una eliminación con `--harness all` es deliberadamente exhaustiva: abarca cada entorno registrado, incluidos los que `exclude_harnesses` del perfil omite durante la instalación — la limpieza alcanza el estado que una instalación anterior de mayor alcance pueda haber dejado atrás. Los entornos que nunca se instalaron reciben el mismo aviso.

El alias en forma continua `apothem uninstalling` (también aceptado como
`apothem Uninstalling`) se resuelve en el mismo manejador.

## Opciones

| Opción | Descripción |
|---|---|
| `--harness NAME` | Adaptador de entorno que se elimina, o `all` para el conjunto de todo el registro (obligatorio). |
| `--yes` | Omite la solicitud de confirmación. |
| `--project PATH` | Raíz del proyecto para los entornos con alcance de proyecto. |
| `--quiet`, `-q` | Suprime la salida informativa; solo se emiten errores. |
| `--verbose`, `-v` | Se acepta por coherencia con otros comandos; este comando no imprime salida adicional. |
| `--format plain\|json` | Formato de salida (predeterminado: `plain`). |
| `--json` | Abreviatura de `--format json`. |
| `--no-color` | Desactiva los códigos de color ANSI en la salida. |
| `-h`, `--help` | Muestra la ayuda y sale. |

## Salida JSON

Cuando el adaptador está instalado y se elimina correctamente:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Cuando el adaptador no estaba instalado, el comando termina con código `0`. En
la salida JSON, el sobre tiene `"status": "success"` y
`"action": "uninstalled"`, y la fila de resultados tiene `"outcome": "skipped"`
con el mensaje `"not installed; no files
removed"`. El campo `status` nunca es `"not_installed"`.

## Ejemplos

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

Una carpeta de skills compartida se mantiene hasta que desaparece la última
instalación que la usa:

```bash
apothem install --harness codex
apothem install --harness cursor --project A
apothem uninstall --harness codex --yes                  # keeps ~/.agents/skills/, the cursor install uses it
apothem uninstall --harness cursor --project A --yes     # removes it: no install uses it now
```

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Adaptador desinstalado, o no estaba instalado |
| 1 | Entorno no encontrado, confirmación rechazada o no disponible (modo no interactivo o JSON sin `--yes`), o todas las eliminaciones fallaron |
| 2 | Eliminación parcial — al menos un entorno se eliminó antes de un fallo |
| 64 | Error de uso: una opción o un comando desconocidos, o un valor de opción ausente o no válido. Con `--json`, el error es un sobre JSON con el código `cli.usage`. |
