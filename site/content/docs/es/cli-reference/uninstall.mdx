Elimina la configuración de un adaptador de entorno.

## Sinopsis

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

Elimina los destinos del entorno gestionados por el adaptador y luego los
directorios que creó la instalación, una vez que están vacíos (un directorio que
contiene algo tuyo se queda). Pide confirmación a menos que se proporcione
`--yes`. Cuando no es posible mostrar una solicitud — `--format json` (el texto
de la solicitud corrompería el único documento JSON) o una shell no interactiva
(sin TTY) — el comando se niega de antemano con un error estructurado
`uninstall.confirmation_required` (código de salida 1) a menos que se
proporcione `--yes`. Si un entorno seleccionado no está instalado, el comando
tiene éxito (código de salida 0) con un aviso «nada que eliminar».

Una eliminación con `--harness all` es exhaustiva de forma deliberada: abarca
cada entorno registrado, incluidos los que `exclude_harnesses` del perfil omite
durante la instalación — la limpieza alcanza el estado que una instalación
anterior de mayor alcance pueda haber dejado atrás. Los entornos que nunca se
instalaron informan «nada que eliminar».

El alias en forma continua `apothem uninstalling` se resuelve en el mismo
manejador.

## Opciones

| Opción | Descripción |
|---|---|
| `--harness NAME` | Adaptador de entorno que se elimina, o `all` para el conjunto de todo el registro (obligatorio). |
| `--yes` | Omite la solicitud de confirmación. |
| `--project PATH` | Raíz del proyecto para los entornos con alcance de proyecto. |
| `--quiet`, `-q` | Suprime la salida informativa; solo se emiten errores. |
| `--verbose`, `-v` | Emite salida de diagnóstico adicional. |
| `--format plain\|json` | Formato de salida (por defecto: `plain`). |
| `--json` | Abreviatura de `--format json`. |
| `--no-color` | Desactiva los códigos de color ANSI en la salida. |
| `-h`, `--help` | Muestra la ayuda y sale. |

## Salida JSON

Cuando el adaptador está instalado y se elimina correctamente:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Cuando el adaptador no estaba instalado, el comando termina con código `0`. En
la salida JSON, el sobre tiene `"status": "success"` y
`"action": "uninstalled"`, y la fila de resultados tiene `"outcome": "skipped"`
con el mensaje `"not installed; no files
removed"`. El campo `status` nunca es `"not_installed"`.

## Ejemplos

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem Uninstalling --harness cursor --project . --yes   # continuous-form alias
```

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Adaptador desinstalado, o no estaba instalado |
| 1 | Entorno no encontrado, confirmación rechazada o no disponible (modo no interactivo o JSON sin `--yes`), o todas las eliminaciones fallaron |
| 2 | Eliminación parcial — al menos un entorno se eliminó antes de un fallo |
| 64 | Error de uso: una opción o un comando desconocidos, o un valor de opción ausente o no válido. Con `--json`, el error es un sobre JSON con el código `cli.usage`. |
