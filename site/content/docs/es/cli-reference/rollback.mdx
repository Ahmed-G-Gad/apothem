Restaura un entorno al estado anterior a su instalación registrada.

## Sinopsis

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` devuelve cada entorno seleccionado al estado en el que estaba antes
de la pasada de instalación registrada: la más reciente por defecto, o la
indicada por `--install-id`. Recorriendo el registro de esa instalación en el
historial, empezando por el cambio más reciente:

- restaura cada archivo y cada directorio que la instalación sobrescribió a
  partir de la copia de seguridad que la instalación capturó, en su ruta
  registrada (un directorio que la instalación reemplazó se restaura
  exactamente, sin los archivos que la instalación le agregó);
- elimina cada archivo y cada directorio que la instalación creó, y vuelve a
  colocar cualquier ruta de la estructura heredada que la instalación barrió;
- elimina los almacenes de datos compartidos (`memory`, `contexts`, `learning`)
  que la instalación creó, a menos que otro entorno instalado todavía los use;
- elimina los directorios que la instalación creó, una vez que están vacíos.

Todo lo que rollback elimina o reemplaza se copia primero en la raíz de copias
de seguridad de Apothem (`~/.apothem/backups/`), de modo que una reversión puede, a
su vez, deshacerse a mano. Después agrega un registro `rollback` al historial del
entorno. Revertir una instalación más antigua también deshace cada instalación
posterior a ella en la misma raíz.

El historial conserva los 10 registros de instalación más recientes por raíz de
instalación (con las copias de seguridad a las que hacen referencia); una
instalación más antigua ya no puede revertirse por su id e informa
`rollback.no_record`. [`apothem backups prune`](/docs/cli-reference/backups)
reduce ese límite a petición, y nunca elimina la copia de seguridad a partir de
la cual restaura la instalación más reciente.

Los registros escritos por un lanzamiento de Apothem anterior a que se agregara
este comportamiento no indican qué archivos creó la instalación; revertir uno de
esos registros restaura solo los archivos sobrescritos.

Se solicita confirmación por cada entorno, a menos que se proporcione `--yes`.
Cuando no es posible mostrar una solicitud —`--format json` (el texto de la
solicitud corrompería el único documento JSON) o una shell no interactiva (sin
TTY)—, el comando se niega de antemano con un error estructurado
`rollback.confirmation_required` (código de salida 1), a menos que se
proporcione `--yes`. `--install-id` y `--last` seleccionan la pasada de
instalación y son mutuamente excluyentes.

Una reversión con `--harness all` es exhaustiva de forma deliberada: abarca cada
entorno registrado, incluidos los que `exclude_harnesses` del perfil omite
durante la instalación. Restaurar el estado previo a la instalación es una
operación de limpieza, así que alcanza los registros que una instalación anterior
de mayor alcance pueda haber dejado. Los entornos sin ninguna instalación
registrada informan, por entorno, «nada que revertir».

## Opciones

| Opción | Descripción |
|---|---|
| `--harness NAME` | Adaptador de entorno que se revierte, o `all` para el conjunto de todo el registro (obligatorio). |
| `--install-id ULID` | Revierte la pasada de instalación indicada. Por defecto, la instalación registrada más reciente. |
| `--last` | Revierte la instalación registrada más reciente (el valor por defecto, en su forma explícita). Mutuamente excluyente con `--install-id`. |
| `--yes` | Omite la solicitud de confirmación por entorno. |
| `--project PATH` | Raíz del proyecto para los entornos con alcance de proyecto. Obligatoria cuando el conjunto seleccionado incluye adaptadores con alcance de proyecto. |
| `--quiet`, `-q` | Suprime la salida informativa; solo se emiten errores. |
| `--verbose`, `-v` | Emite salida de diagnóstico adicional. |
| `--format plain\|json` | Formato de salida (por defecto: `plain`). |
| `--json` | Abreviatura de `--format json`. |
| `--no-color` | Desactiva los códigos de color ANSI en la salida. |
| `-h`, `--help` | Muestra la ayuda y sale. |

## Salida JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Cada destino restaurado o eliminado aparece en `results` con
`"operation": "rollback"` y un `outcome` de `created` o `updated` (y en
`files_written`); el `message` indica si la ruta se restauró o se eliminó. Una
restauración fallida (por ejemplo, una copia de seguridad que se borró) es
`"outcome": "error"`. Una instalación que no registró cambios se informa con
`"outcome": "skipped"`. Cuando no existe ningún registro de instalación
coincidente, el comando informa un error `rollback.no_record` con
`"status": "error"`.

## Ejemplos

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Revertido correctamente, o nada que revertir (la instalación no registró cambios) |
| 1 | Error esperado: no hay registro de instalación, selectores en conflicto, entorno desconocido, raíz del proyecto ausente, o confirmación rechazada o no disponible (modo no interactivo o JSON sin `--yes`) |
| 2 | Restauración parcial después de que se revirtiera al menos un destino |
| 64 | Error de uso: una opción o un comando desconocidos, o un valor de opción ausente o no válido. Con `--json`, el error es un sobre JSON con el código `cli.usage`. |
