Migra un espacio de trabajo heredado por entorno a la estructura compartida
`.apothem`.

## Sinopsis

```
apothem migrate-workspace [--project PATH] [--dry-run]
                          [--quiet|-q] [--verbose|-v]
                          [--format plain|json] [--json] [--no-color]
```

`migrate-workspace` consolida un directorio de datos heredado por entorno
(`.apothem/<harness>/...`) y un árbol `.plans/` heredado en el único directorio
de trabajo compartido `.apothem/{plans,memory,learning,contexts}`. La base es la
raíz de `--project` resuelta cuando se proporciona; en caso contrario, el
directorio de trabajo actual (el valor predeterminado local al proyecto).

Los almacenes de memoria, de contextos y de aprendizaje por entorno se fusionan
por unión en el almacén compartido según el id; las señales de aprendizaje se
concatenan y se deduplican; un registro en conflicto (mismo id, cuerpo distinto)
se omite, nunca se sobrescribe. Un árbol `.plans/` heredado se mueve bajo
`.apothem/plans/`. De cada origen consumido se hace primero una copia de
seguridad. La migración es idempotente: volver a ejecutarla sobre un árbol ya
migrado no tiene ningún efecto.

## Opciones

| Opción | Descripción |
|---|---|
| `--project PATH` | Raíz del proyecto para los adaptadores con alcance de proyecto que materializan en un árbol de proyecto en lugar de en un directorio de configuración con alcance de usuario. |
| `--dry-run` | Detecta la estructura heredada e informa qué se migraría, sin escribir. |
| `--quiet`, `-q` | Suprime la salida informativa; solo se emiten errores. |
| `--verbose`, `-v` | Emite salida de diagnóstico adicional. |
| `--format plain\|json` | Formato de salida (por defecto: `plain`). |
| `--json` | Abreviatura de `--format json`. |
| `--no-color` | Desactiva los códigos de color ANSI en la salida. |
| `-h`, `--help` | Muestra la ayuda y sale. |

## Salida JSON

El sobre `--json` lleva el resultado de la migración. En una migración
completada, `status` es `success` y la carga útil informa los recuentos de
registros fusionados, si se reubicó un árbol `.plans/`, la raíz de las copias de
seguridad y cualquier conflicto omitido. Una invocación con `--dry-run` informa
en su lugar `legacy_layout_detected`.

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "status": "success",
  "base": "/home/example/project",
  "migrated": true,
  "backup_root": "/home/example/project/.apothem/backups/migrate-20260101T120000Z",
  "memory_merged": 12,
  "contexts_merged": 4,
  "learning_merged": 7,
  "conflicts": [],
  "plans_moved": true,
  "notes": []
}
```

Cuando no hay ninguna estructura heredada presente, `migrated` es `false` y no
se escribe nada. El sobre de `--dry-run` omite los recuentos del resultado e
informa solo de la detección:

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "base": "/home/example/project",
  "dry_run": true,
  "legacy_layout_detected": false
}
```

## Ejemplos

```bash
apothem migrate-workspace
apothem migrate-workspace --project .
apothem migrate-workspace --dry-run --json
```

## Códigos de salida

| Código | Significado |
|---|---|
| 0 | Migración completada, o no se encontró ninguna estructura heredada (nada que migrar) |
| 1 | Error esperado: un error de validación o de raíz del proyecto, o un fallo de la migración |
| 64 | Error de uso: una opción o un comando desconocidos, o un valor de opción ausente o no válido. Con `--json`, el error es un sobre JSON con el código `cli.usage`. |
