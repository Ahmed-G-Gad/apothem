GLM (Z.ai) es un backend de modelos al que un entorno compatible se dirige
estableciendo una URL base y una clave. Puedes exportar esas variables de
entorno a mano, por proyecto, por máquina, para siempre. El adaptador glm de
Apothem registra los endpoints del backend y los marcadores de posición que el
operador puede configurar en un único archivo de proveedor y escribe la misma
plantilla en cada proyecto. Esta página contrasta la conexión manual de ese
backend con su gestión mediante Apothem.

## Comparación de esfuerzo

| Tarea | Configuración manual | Gestionada por Apothem |
| ---- | --------------- | --------------- |
| Registrar las URL del backend | Memorizarlas y volver a exportarlas en cada proyecto | Escritas en un único archivo de proveedor |
| Fuente de verdad | Las exportaciones propias de cada shell | Un único archivo de proveedor canónico |
| Mantener los backends alineados entre proyectos | Volver a conectar cada proyecto | La misma plantilla se escribe en cada proyecto |
| Restaurar la configuración | Volver a exportar en cada proyecto | `apothem update --harness glm --project <path>` vuelve a escribir el archivo solo cuando falta |
| Eliminar la configuración | Borrado manual | `apothem uninstall` con una copia de respaldo |

## Qué gestiona Apothem

El adaptador glm renderiza un único archivo de proveedor en
`<project>/.apothem/providers/glm.toml` y no escribe nada más. Registra la URL
base compatible con Anthropic (`https://api.z.ai/api/anthropic`), la URL base
compatible con OpenAI (`https://api.z.ai/api/coding/paas/v4`), un marcador de
posición para el token de autenticación y marcadores de posición para la
asignación de modelos. Tu clave de Z.ai y tus elecciones de ID de modelo siguen
siendo propiedad del operador: Apothem nunca escribe un secreto real y no fija
ningún ID de modelo que cambie entre versiones.

## Ruta de migración

1. Ejecuta `apothem profile init` para crear el perfil compartido si aún no lo
   tienes.
2. Ejecuta `apothem install --harness glm --project <path>` para renderizar el
   archivo de proveedor `glm.toml`.
3. Completa tu clave de Z.ai y los ID de modelo que quieras a partir de la
   [documentación de Z.ai](https://docs.z.ai/devpack/tool/claude) actual.
4. Ejecuta `apothem verify --harness glm --project <path>` para confirmar que la
   configuración se instaló.
5. Edita `.apothem/providers/glm.toml` para cada cambio posterior. Apothem nunca
   reescribe un archivo de proveedor existente; `apothem update --harness glm --project
   <path>` lo vuelve a escribir solo cuando falta.
