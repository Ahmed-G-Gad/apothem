CodeBuddy lee las reglas de proyecto desde `.codebuddy/rules/*.md`. Puedes escribir esos archivos a mano, por proyecto, para siempre. El adaptador de CodeBuddy de Apothem renderiza uno de ellos a partir del perfil compartido y lo mantiene coherente en cada entorno y en cada proyecto. Esta página contrasta mantener esa configuración a mano frente a gestionarla con Apothem.

## Comparación de esfuerzo

| Tarea | Configuración a mano | Gestionada con Apothem |
| ---- | --------------- | --------------- |
| Escribir reglas | Copiar y pegar las mismas disciplinas en `.codebuddy/rules/` en cada proyecto | Renderizadas desde un único corpus compartido |
| Fuente de verdad | Los archivos propios de cada proyecto | Una cohorte canónica |
| Mantener las reglas alineadas entre entornos | Volver a derivarlas por herramienta | Proyectadas automáticamente |
| Actualizar las reglas | Editar a mano cada proyecto | `apothem update --harness codebuddy --project <path>` |
| Eliminar la configuración | Borrado manual | `apothem uninstall` con copia de seguridad con marca de tiempo |

## Qué gestiona Apothem

El adaptador de codebuddy renderiza las reglas compartidas en un archivo dedicado `<project>/.codebuddy/rules/apothem-rules.md` y no escribe nada más. Tu archivo de memoria `CODEBUDDY.md`, tus permisos y servidores MCP en `.codebuddy/settings.json`, y cualquier otro archivo de reglas que escribas siguen siendo propiedad del operador: el adaptador reconoce esas superficies, pero nunca las edita. Cada cambio en las reglas compartidas vuelve a renderizar el archivo en la siguiente ejecución de `apothem update`.

## Ruta de migración

1. Ejecuta `apothem profile init` para crear el perfil compartido si aún no lo tienes.
2. Mueve las disciplinas de tus archivos `.codebuddy/rules/` existentes al corpus compartido.
3. Ejecuta `apothem install --harness codebuddy --project <path>` para renderizar el archivo `apothem-rules.md` junto a tus reglas propias, que no se tocan.
4. Ejecuta `apothem verify --harness codebuddy --project <path>` para confirmar que la configuración se instaló.
5. Usa `apothem update --harness codebuddy --project <path>` para cada cambio posterior.
