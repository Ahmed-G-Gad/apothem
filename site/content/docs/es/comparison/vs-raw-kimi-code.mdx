Kimi Code reads project-root `AGENTS.md` as its instruction file and keeps
project configuration under `<project>/.kimi-code/`, including the
operator-owned `.kimi-code/mcp.json` MCP surface. You can author that
instruction file and its supporting cohorts by hand, per project, forever.
Apothem's kimi-code adapter renders the governance surface into `AGENTS.md` as a
managed block from the shared profile and keeps it consistent across every
harness and every project. This page contrasts hand-maintaining that config
against managing it with Apothem.

## Effort comparison

| Tarea | Configuración manual | Gestionada por Apothem |
| ---- | --------------- | --------------- |
| Redactar la superficie de instrucciones `AGENTS.md` | Escribir a mano y resincronizar en cada proyecto | Un único bloque gestionado, renderizado desde el perfil compartido |
| Mantener sincronizadas reglas, comandos, skills y agentes | Copia manual en cada proyecto | Materializados en `<project>/.kimi-code/.apothem/support/` en cada instalación |
| Conservar la prosa del operador al actualizar | Fusión manual | Bloque delimitado por centinelas; la prosa del operador fuera de él se conserva |
| Mantener las reglas alineadas con otros entornos | Manual, por herramienta | Automático con `apothem update` |
| Verificar que la configuración es correcta | Inspección manual | `apothem verify --harness kimi-code --project <path>` |

## What Apothem manages

The kimi-code adapter renders the shared rules and governance surface into the
project-root `AGENTS.md` managed block and installs the commands, skills, hooks,
agents, rules, and templates cohorts under `.kimi-code/.apothem/support/`. It does not
author `.kimi-code/mcp.json`; the MCP surface stays operator-owned. The rendered
instruction surface drives the project directly. Every change to the shared
rules re-renders the files on the next `apothem update`.

## Migration path

1. Ejecuta `apothem profile init` para crear el perfil compartido si aún no lo tienes.
2. Mueve las reglas de tu `AGENTS.md` existente al corpus compartido.
3. Ejecuta `apothem install --harness kimi-code --project <path>` para renderizar la superficie de instrucciones `AGENTS.md` y el árbol de soporte `.kimi-code/.apothem/support/`.
4. Ejecuta `apothem verify --harness kimi-code --project <path>` para confirmar que la configuración quedó instalada.
5. Usa `apothem update --harness kimi-code --project <path>` para cada cambio posterior.
