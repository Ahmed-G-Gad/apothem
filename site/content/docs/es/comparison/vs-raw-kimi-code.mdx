Kimi Code lee el `AGENTS.md` de la raíz del proyecto como su archivo de
instrucciones y guarda la configuración del proyecto en `<project>/.kimi-code/`,
incluida la superficie MCP `.kimi-code/mcp.json`, que es propiedad del operador.
Puedes redactar a mano ese archivo de instrucciones y sus cohortes de apoyo,
proyecto por proyecto, para siempre. El adaptador de kimi-code de Apothem
renderiza la superficie de gobernanza en `AGENTS.md` como un bloque gestionado a
partir del perfil compartido y la mantiene coherente en todos los entornos y en
todos los proyectos. Esta página contrasta mantener esa configuración a mano
frente a gestionarla con Apothem.

## Comparación de esfuerzo

| Tarea | Configuración manual | Gestionada por Apothem |
| ---- | --------------- | --------------- |
| Redactar la superficie de instrucciones `AGENTS.md` | Escribir a mano y resincronizar en cada proyecto | Un bloque gestionado, renderizado desde el perfil compartido |
| Mantener sincronizadas reglas, comandos, skills y agentes | Copia manual en cada proyecto | Materializados en `<project>/.kimi-code/.apothem/support/` en cada instalación |
| Conservar la prosa del operador al actualizar | Fusión manual | Bloque delimitado por centinelas; la prosa del operador fuera de él se conserva |
| Mantener las reglas alineadas con otros entornos | Manual, herramienta por herramienta | Automático con `apothem update` |
| Verificar que la configuración es correcta | Inspección manual | `apothem verify --harness kimi-code --project <path>` |

## Qué gestiona Apothem

El adaptador de kimi-code renderiza las reglas compartidas y la superficie de
gobernanza en el bloque gestionado del `AGENTS.md` de la raíz del proyecto, e
instala las cohortes de comandos, skills, hooks, agentes, reglas y plantillas
bajo `.kimi-code/.apothem/support/`. No redacta `.kimi-code/mcp.json`; la
superficie MCP sigue siendo propiedad del operador. Kimi Code lee las
instrucciones del proyecto desde `AGENTS.md` o desde `.kimi-code/AGENTS.md`; el
adaptador escribe solo el `AGENTS.md` de la raíz del proyecto, y la documentación
de Kimi Code no indica cuál de los dos archivos prevalece cuando ambos existen.
Cada cambio en las reglas compartidas vuelve a renderizar los archivos en el
siguiente `apothem update`.

## Ruta de migración

1. Ejecuta `apothem profile init` para crear el perfil compartido si aún no lo tienes.
2. Mueve las reglas de tu `AGENTS.md` existente al corpus compartido.
3. Ejecuta `apothem install --harness kimi-code --project <path>` para renderizar la
   superficie de instrucciones `AGENTS.md` y el árbol de soporte
   `.kimi-code/.apothem/support/`.
4. Ejecuta `apothem verify --harness kimi-code --project <path>` para confirmar que la
   configuración quedó instalada.
5. Usa `apothem update --harness kimi-code --project <path>` para cada cambio
   posterior.
