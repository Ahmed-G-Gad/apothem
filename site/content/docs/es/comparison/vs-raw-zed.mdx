Zed lee las instrucciones del agente desde un único archivo plano `.rules` en la
raíz del proyecto (junto a la familia `AGENTS.md` / `CLAUDE.md`). El adaptador
zed de Apothem renderiza ese archivo desde el perfil compartido. Esta página
contrasta mantener esa configuración a mano frente a gestionarla con Apothem.

## Comparación de esfuerzo

| Tarea | Configuración manual | Gestionada por Apothem |
| ---- | --------------- | --------------- |
| Escribir instrucciones | Escribir a mano el archivo `.rules` | Renderizadas desde el corpus compartido |
| Conservar un `.rules` anterior | Recordar copiarlo aparte por tu cuenta | El adaptador respalda el archivo existente antes de reemplazarlo |
| Mantener las reglas alineadas con otros entornos | Manual, por herramienta | Automático con `apothem update` |
| Compartir skills y comandos reutilizables | Copiar a mano cada carpeta de skill en `~/.agents/skills/` y mantener las copias al día | Escritas en `~/.agents/skills/` por el adaptador, una copia para todos los proyectos, y actualizadas con `apothem update` |
| Verificar que la configuración es correcta | Inspección manual | `apothem verify --harness zed --project <path>` |

## Qué gestiona Apothem

El adaptador zed renderiza las reglas compartidas en el archivo plano `.rules` de
la raíz del proyecto. Zed no tiene hook PreToolUse, por lo que la intención de
guardarraíl vive en la prosa de la regla en vez de en un punto de intercepción de
llamada a herramienta. El archivo de instrucciones global
`~/.config/zed/AGENTS.md` y el bloque del servidor de contexto MCP de
`.zed/settings.json` son propiedad del operador y se dejan intactos. Cada cambio
en las reglas compartidas vuelve a renderizar el archivo en el siguiente
`apothem update`.

## Ruta de migración

1. Ejecuta `apothem profile init` para crear el perfil compartido si aún no lo tienes.
2. Mueve las instrucciones de tu `.rules` existente (y cualquier contenido de `AGENTS.md` específico del proyecto que quieras compartir) al corpus compartido.
3. Ejecuta `apothem install --harness zed --project <path>` para renderizar el archivo `.rules`. Tu `.rules` anterior se respalda primero.
4. Ejecuta `apothem verify --harness zed --project <path>` para confirmar que la configuración quedó instalada.
5. Usa `apothem update --harness zed --project <path>` para cada cambio posterior.
