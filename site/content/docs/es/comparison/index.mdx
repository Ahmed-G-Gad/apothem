Apothem es un gestor de configuración de entornos de IA agnóstico al host. Un
único perfil compartido en `~/.config/apothem/profile.yaml` se materializa en
diecisiete superficies de configuración nativas de entorno. Esta sección
plantea cómo evaluar Apothem frente a las alternativas que ya usas.

## Cómo se compara Apothem

Los datos sobre otras herramientas de esta página corresponden al
**2026-10-02** y se tomaron del README o de la documentación propios de cada
proyecto (consulta [Fuentes](#fuentes)); vuelve a comprobarlos en cada versión
menor.

Otras herramientas resuelven porciones adyacentes de este problema. Los gestores de archivos de configuración, como **chezmoi** y **GNU Stow**, colocan, enlazan o generan plantillas de archivos, pero nunca traducen una única fuente al esquema de configuración *nativo* de cada entorno. Las CLI de sincronización entre herramientas generan archivos por herramienta a partir de una sola fuente: **rulesync** genera configuración nativa para 60 herramientas de programación y dos estándares abiertos, a través de una unidad sincronizada que añade MCP, archivos ignore, permisos y comprobaciones de revisión, ninguno de los cuales sincroniza el manifiesto de Apothem; Apothem renderiza sus servidores MCP a partir del perfil mediante los materializadores de los adaptadores que los definen. **ruler** distribuye un único directorio `.ruler/` a 33 destinos, concatena las reglas en el archivo de instrucciones de cada herramienta y traduce los servidores MCP, las skills y los subagentes a configuración nativa. La diferencia de Apothem está en la **disciplina de gobernanza y de ciclo de vida que se distribuye junto con la sincronización**: una puerta de conformidad mecanizada, canalizaciones deterministas, una secuencia de revisión de auditoría y un ciclo de vida verificado y reversible.

| Capacidad | Apothem | Gestores de configuración basados en archivos (chezmoi, Stow) | rulesync | ruler |
| ---------- | :-----: | :----------------------------------: | :------: | :---: |
| Una fuente hacia los esquemas nativos de muchas herramientas | Sí — diecisiete adaptadores de entorno | No — copia, enlace simbólico o plantilla, sin traducción | Sí — 60 herramientas más los estándares AGENTS.md y Agent Skills | En parte — reglas concatenadas en el archivo de instrucciones de cada herramienta; MCP, skills y subagentes escritos en forma nativa |
| Unidad sincronizada | reglas, skills, subagentes, hooks, comandos de barra, output-styles, statuslines, plantillas, validadores de conformidad, esquemas, plantillas de instrucciones por entorno y la plantilla de ajustes de Claude Code | archivos arbitrarios | reglas, ignore, MCP, comandos, subagentes, skills, hooks, permisos, checks (instrucciones de comprobación para la revisión de código) | reglas, MCP, skills, subagentes |
| Corpus de gobernanza (reglas de comportamiento más una puerta de conformidad mecánica) | Sí — `python -m apothem.conformity.gate` | No | No — su función `checks` sincroniza comprobaciones de revisión de código con las herramientas; no hay puerta de conformidad sobre las reglas | No |
| Canalizaciones deterministas de planificación e investigación | Sí — de `/plan-spec` a `/plan-execute`, `/research` de trece etapas | No | No | No |
| Secuencia de revisión de auditoría que detecta y corrige | Sí — barrido de once comandos, bucle de reauditoría `/fortress` | No | No | No |
| Memoria duradera entre sesiones | Sí — almacén `memory/records.json` bajo el directorio de datos de Apothem, creado en la instalación | No comparado | No indicado en su README | No indicado en su README |
| Lanzamientos con la cadena de suministro endurecida | Sí — SBOM, Sigstore, SLSA, objetivo de Scorecard | No comparado | No indicado en su README | No indicado en su README |
| Ciclo de vida reversible y verificado | Sí — copia de seguridad, `apothem verify --json`, desinstalación sin huérfanos | chezmoi: `chezmoi verify` comprueba cada destino; Stow: solo enlaces simbólicos | No indicado en su README | Copias de seguridad `.bak` y `ruler revert`; ningún comando de verificación en su README |

Donde otra herramienta es más fuerte, se la nombra: **rulesync** llega a más del triple de herramientas y sincroniza MCP, archivos ignore, permisos y comprobaciones de revisión, algo que el manifiesto de Apothem no sincroniza; **ruler** llega a casi el doble de herramientas y tiene un comando de reversión propio. Apothem cambia el número bruto de herramientas por la disciplina de gobernanza, auditoría y ciclo de vida que se distribuye en torno a la sincronización (una puerta de conformidad, canalizaciones deterministas de planificación e investigación, una secuencia de revisión de auditoría de once comandos, memoria duradera y un ciclo de vida reversible y verificado), que ninguna de las dos herramientas de sincronización lleva.

## Cómo comparar

Compara según tres ejes:

1. **Fuente de verdad.** ¿Dónde residen tus reglas, agentes, comandos y
   ajustes? Apothem mantiene un único corpus compartido y renderiza a partir de
   él el formato nativo de cada entorno. La configuración mantenida a mano
   guarda una copia por herramienta.
2. **Coste de la deriva.** ¿Qué ocurre cuando cambias una regla? Apothem
   propaga el cambio a cada entorno instalado con `apothem update`. La
   configuración mantenida a mano te exige editar el archivo nativo de cada
   herramienta por separado y mantenerlos alineados de memoria.
3. **Verificación.** ¿Cómo sabes que cada entorno está configurado
   correctamente? Apothem incluye `apothem verify --harness <name>` y
   `apothem doctor`. La configuración mantenida a mano no tiene verificación
   incorporada.

## Matriz de funciones

La matriz contrasta Apothem con las dos alternativas a las que los operadores
recurren primero: mantener a mano la configuración nativa de cada entorno y
gestionar esos archivos mediante un gestor de dotfiles de propósito general.

| Capacidad | Configuración mantenida a mano | Gestor de dotfiles | Apothem |
| ---------- | ---------------------- | --------------- | ------- |
| Una única fuente de verdad compartida | No (una copia por herramienta) | No (rastrea archivos, no un perfil) | Sí (un perfil) |
| Renderiza formatos nativos del entorno | Manual | No | Sí (materializador por adaptador) |
| Prevención de la deriva entre entornos | Alineación manual | Solo sincronización de archivos | Sí (`apothem update`) |
| Instalación/desinstalación por entorno | Manual | Parcial (enlace simbólico/copia) | Sí (`install` / `uninstall`) |
| Verificación incorporada | Ninguna | Ninguna | Sí (`verify` / `doctor`) |
| Traducción de formato por herramienta | Ninguna | Ninguna | Sí (`.mdc`, `.toml`, `.md` incrustado) |
| Diecisiete entornos desde una sola entrada | No | No | Sí |
