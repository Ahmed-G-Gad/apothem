Cursor lee reglas en formato MDC bajo `.cursor/rules/`. El formato MDC requiere
campos de frontmatter — `description`, `globs` y `alwaysApply`. El adaptador de
cursor de Apothem renderiza esos archivos `.mdc` desde el perfil compartido.
Esta página contrasta mantener esa configuración a mano con gestionarla con
Apothem.

## Comparación de esfuerzo

| Tarea | Configuración manual | Gestionada por Apothem |
| ---- | --------------- | --------------- |
| Escribir reglas | Escribir a mano cada archivo `.mdc` bajo `.cursor/rules/` | Renderizadas desde el corpus compartido |
| Escribir el frontmatter MDC | Redactar a mano `description` / `globs` / `alwaysApply` por archivo | Generado por el adaptador |
| Mantener un solo formato de reglas | Elegir a mano entre reglas MDC y un único archivo `.cursorrules` | El adaptador escribe solo archivos MDC de `.cursor/rules/` |
| Mantener las reglas alineadas con otros entornos | Manual, por herramienta | Automático con `apothem update` |
| Verificar que la configuración es correcta | Inspección manual | `apothem verify --harness cursor` |

## Qué gestiona Apothem

El adaptador de cursor renderiza las reglas compartidas en archivos `.mdc` bajo
`.cursor/rules/`, generando el frontmatter MDC requerido (`description`,
`globs`, `alwaysApply`) para cada archivo. El adaptador escribe solo el formato
MDC basado en directorios que Cursor lee; no escribe un único archivo
`.cursorrules`.
Cursor no tiene un hook PreToolUse, así que la intención de las barreras de
protección vive en la prosa de las reglas.

## Ruta de migración

1. Ejecuta `apothem profile init` para crear el perfil compartido si aún no lo tienes.
2. Mueve las reglas de tu `.cursor/rules/` existente (y cualquier `.cursorrules`)
   al corpus compartido.
3. Ejecuta `apothem install --harness cursor` para renderizar los archivos `.mdc`
   con el frontmatter MDC correcto.
4. Ejecuta `apothem verify --harness cursor` para confirmar que la configuración aterrizó.
5. Usa `apothem update --harness cursor` para cada cambio posterior.
