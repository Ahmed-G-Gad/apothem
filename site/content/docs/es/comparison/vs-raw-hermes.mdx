Hermes lee `~/.hermes/config.yaml`. Apothem escribe la configuración YAML
nativa (proyecta el inventario de MCP del perfil en `mcp_servers`) e instala
cohortes compartidas de comandos y skills bajo
`~/.hermes/.apothem/support/skills/`, que incluye en `skills.external_dirs` para
que Hermes las cargue. El propio `skills.config` de Hermes contiene ajustes por
skill, así que Apothem no lo redacta.

## Estado

**Vista previa.** El adaptador de Hermes apunta al archivo de configuración
documentado actual y a la superficie de descubrimiento de skills. Las cohortes
que no son de skills siguen siendo material de soporte de Apothem.

## Comparación de esfuerzo

| Tarea | Configuración manual | Gestionada por Apothem |
| ---- | --------------- | --------------- |
| Redactar skills reutilizables | Editar a mano la configuración y los directorios de skills | Escribir una vez en el corpus compartido |
| Mantener las cohortes alineadas con otros entornos | Manual, por herramienta | Automático con `apothem update` |
| Instalar / eliminar la configuración | Manual | `apothem install` / `apothem uninstall` |
| Verificar que la configuración es correcta | Inspección manual | `apothem verify --harness hermes` |

## Qué gestiona Apothem

El adaptador de Hermes escribe `config.yaml`, envuelve los comandos de barra de
Apothem como skills, copia las skills de Apothem en el directorio de soporte y
mantiene las reglas, las plantillas, los agentes y el material de hooks bajo el
subárbol de soporte de Apothem. También añade
`~/.hermes/.apothem/support/skills` a `skills.external_dirs` en `config.yaml`,
para que Hermes cargue esas skills. Esa lista va en último lugar en el orden de
precedencia documentado de Hermes, así que es probable que una skill con el
mismo nombre en tu proyecto o en `~/.hermes/skills/` prevalezca sobre la copia
de Apothem; la documentación de Hermes revisada no indica la regla para ese
conflicto.

## Ruta de migración

1. Ejecuta `apothem profile init` para crear el perfil compartido si aún no lo
   has hecho.
2. Mueve las skills o los prompts de comandos reutilizables de Hermes al corpus
   compartido.
3. Ejecuta `apothem install --harness hermes` para renderizar la configuración
   nativa, que incluye el directorio de skills de soporte en
   `skills.external_dirs`, y para instalar las skills. `apothem update`
   conserva las claves que añadas a `config.yaml`.
4. Ejecuta `apothem verify --harness hermes` para confirmar que la
   configuración quedó escrita.
