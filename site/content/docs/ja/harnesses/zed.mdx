**ベンダー：** Zed Industries
**インストール名：** `zed`
**ステータス：** GA
**ネイティブ設定：** `<project>/.rules`

## インストール

```bash
apothem install --harness zed --project /path/to/project
```

アダプターは、共有の Apothem ルールとガバナンス面から、プロジェクトスコープの Zed
命令ファイルを 1 つ書き込みます。Zed が読み込むプロジェクト命令ファイルは 1 つだけで、
次のリストで最初に一致したものです。

```text
.rules
.cursorrules
.windsurfrules
.clinerules
.github/copilot-instructions.md
AGENT.md
AGENTS.md
CLAUDE.md
GEMINI.md
```

ツールごとのルールディレクトリはないため、Apothem 面全体が、このリストの先頭にある
フラットな `.rules` ファイルに収まります。

また、プロジェクトに触れる前に、Apothem のスキルと、それらが引用するルールとテンプレートを、
あなたのユーザーホームに書き込みます（[プロジェクト外のファイル](#プロジェクト外のファイル)を参照）。

**書き込まれるファイル：**

- `<project>/.rules`：命令ファイル。
- `~/.agents/skills/<name>/SKILL.md`：Apothem の各スキルと各コマンドにつき 1 つ、あなたのユーザーホームに。
- `~/.config/apothem/rules/` と `~/.config/apothem/templates/`：あなたのユーザーホームに。

## プロジェクト外のファイル

インストールは、プロジェクト内の何かを変更する前に、Apothem のスキルをあなたのユーザーホームにも書き込みます。

| フォルダー | Apothem がそこに書き込むもの |
| --- | --- |
| `~/.agents/skills/` | Apothem の各スキルにつき `SKILL.md` を含むフォルダーを 1 つ、そして Apothem の各コマンドにつき 1 つ（コマンドは同じ名前のスキルになります）。 |
| `~/.config/apothem/rules/`, `~/.config/apothem/templates/` | スキルと命令ファイルが参照するルールとテンプレート。 |

これらのフォルダーは共有されます。プロジェクト専用ではありません。

- `zed` をインストールするすべてのプロジェクトと、そのフォルダーを指定する他のすべての Apothem のインストールが同じコピーを使い、同じファイルを書き込むため、インストールの順序は関係ありません。他のいくつかのツールも `~/.agents/skills/` を読みます。[ハーネスレジストリ](/docs/reference/harness-registry#共有ルート)がそれらを一覧にしています。
- `--project` は、書き込む命令ファイルと、インストールがどのプロジェクトに属するかを選びます。スキルの書き込み先は変わりません。
- インストールは、あなたのリポジトリにスキルファイルもルールファイルも追加しません。プロジェクトが受け取るのは、命令ファイルと、プロジェクトへのインストールが毎回作成する `.apothem/` データフォルダーです。
- ホームのフォルダーが最初に書き込まれます。それが失敗した場合、たとえばパス内のフォルダーがホームディレクトリの外へ出るリンクである場合（内側にとどまるリンクはたどられます）や書き込めない場合、インストールはプロジェクト内の何かが変わる前にエラーで停止します。
- Apothem のスキルの名前を持ち、Apothem が書き込んだのではないスキルフォルダーはそのまま残され、インストールはその名前を挙げる警告を表示します。名前を変えるか移動してから、`apothem update` を実行してください。その名前が占有されている間、`apothem verify` は失敗します。
- ファイルの合計は数メガバイトになります。

インストールは、`--project` の外に書き込むフォルダーを挙げるメモを表示し、`--dry-run` はそれらを一覧表示します。

## プロファイルからネイティブ設定へのマッピング

アダプターは Apothem の共有プロファイルを読み取り、`apothem install` または `apothem update` を
実行するたびに、プロジェクトの `.rules` ファイルをレンダリングします。共有プロファイルが
信頼できる情報源です。既存の `.rules`（または生成されたファイルへのプロジェクトローカルな
編集）は、次回の同期が Apothem 管理のコンテンツを置き換える前にバックアップされます。

## 互換性に関する注意

Zed は `AGENTS.md` を主要な命令ファイルとし、プロジェクトの `.rules` をサポート対象の
互換ファイルとして維持しています（[Zed の命令](https://zed.dev/docs/ai/instructions)）。
Zed は最初に一致したものだけを読み込むため、新しい `.rules` は、プロジェクトがすでに依存して
いる `AGENTS.md`、`CLAUDE.md`、またはリストのより下位にある他のファイルを隠してしまいます。
インストールがそれらのファイルを編集することは決してありません。`.rules` に Apothem ブロック
しかなく、より優先度の低いファイルにあなたのテキストがある場合、インストールと更新は、
隠されたファイルを名指しする警告を出力します。必要な命令を Zed で維持するには、それらを
`.rules` の Apothem ブロックの外側にコピーしてください。

グローバルな `~/.config/zed/AGENTS.md` 命令ファイルと MCP コンテキストサーバーブロック
（`.zed/settings.json` の `context_servers`）はオペレーターの所有であり、Apothem はそれらを
書き込みません。

Zed はグローバルなスキルを `~/.agents/skills/` からのみ、スキルごとに 1 つのフォルダーを置く
フラットなレイアウトで読み込みます。これはインストールが書き込むレイアウトです。Zed は
プロジェクトローカルなスキルを信頼されたワークツリーに限定しており、そのドキュメントは
グローバルなフォルダーにそのような制限を結び付けていません。ある報告は、Zed がモデルに送る
スキルカタログにサイズの上限があるとしています。Apothem はそれを確認しておらず、モデルによる
呼び出しをオフにするスキルがそれに数えられるかどうかも確認していません。Apothem のスキルの
名前と説明の合計は約 20 KB です。また、記載のない `SKILL.md` のヘッダーキーを Zed がどう
扱うかも、Apothem は確認していません。

## 検証

```bash
apothem verify --harness zed --project /path/to/project
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. 管理対象の各ターゲットが存在すること。管理対象のファイルは空ではなく、JSON または YAML の設定は解析できること。`--profile PATH` を追加すると、インストールされたファイルがそのプロファイルと一致することも確認します。
3. どのインストールが書き込んだかにかかわらず、Apothem の各スキルフォルダーが `SKILL.md` とともに所定の場所にあり、Apothem の名前を持つスキルフォルダーがどれも、Apothem が書き込んだのではないものに属していないこと。チェックが失敗すると、欠けているフォルダーや外部のフォルダーの名前が挙げられます。
4. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness zed --project /path/to/project
```

現在の共有プロファイルの状態から、プロジェクトの `.rules` ファイルを再導出します。

更新は、ファイルが現在のものと異なるスキルフォルダーも書き直します。
スキルを書き込まなかった以前のリリースでインストールした場合、更新はスキルを追加します。

## アンインストール

```bash
apothem uninstall --harness zed --project /path/to/project
```

Apothem の管理ブロックを、ネイティブ設定ファイル `.rules` から削除し、あなた自身の文章は残します。ファイルは、ほかに何も残っていない場合にのみ削除されます。変更の前に、ファイルのタイムスタンプ付きのコピーが `~/.apothem/backups/` の下に保存されます。プロジェクトにバックアップファイルは残りません。共有プロファイルの YAML と Apothem エンジンには影響しません。

アンインストールは、`~/.agents/skills/` に書き込んだスキルフォルダーと `~/.config/apothem/` 内のルールとテンプレートも削除しますが、それは他の Apothem のインストールがまだそれらを使っていない場合に限ります。
別のプロジェクトや、そのフォルダーを共有する別のツールが使っている可能性があります。
その場合、アンインストールはフォルダーを残し、どのインストールがそれらを使っているかを表示し、最後のアンインストールがそれらを削除します。
あなたがそれらのフォルダーに追加したファイルは残り、空になったフォルダーは削除されます。
各フォルダーは、削除される前に `~/.apothem/backups/` 配下にバックアップされます。

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness zed --project /path/to/project` を再実行する |
| 検証が失敗した | `apothem update --harness zed --project /path/to/project` を実行してから、再度検証する |
| `apothem verify` が欠けているスキルフォルダーの名前を挙げる | `apothem install --harness zed --project /path/to/project` を実行する。これでフォルダーが復元される |
| インストールまたは更新が、スキルフォルダーをスキップしたと警告する | Apothem のスキルの名前を持つフォルダーがスキルフォルダー内にすでに存在し、Apothem が書き込んだものではない。名前を変えるか移動してから、`apothem update` を実行する |
| インストールがプロジェクトを変更する前に停止する | ホーム内への書き込みが失敗した。エラーを読み、それが挙げるフォルダー（ホームディレクトリの外へ出るリンク、フォルダーがあるべき場所にあるファイル、または読み取り専用のフォルダー）を修正してから、再度インストールする |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness zed --project /path/to/project` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
