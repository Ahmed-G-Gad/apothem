**ベンダー：** ByteDance
**インストール名：** `trae`
**ステータス：** GA
**ネイティブ設定：** `<project>/.trae/rules/apothem-rules.md`

## インストール

```bash
apothem install --harness trae --project /path/to/project
```

アダプターは、共有された Apothem のルールおよびガバナンス面から、プロジェクト
スコープの Trae ルールファイルを 1 つ書き込みます。

**書き込まれるファイル：** `<project>/.trae/rules/apothem-rules.md`

## プロファイルからネイティブ設定へのマッピング

アダプターは Apothem の共有プロファイルを読み取り、`apothem install` または
`apothem update` の実行のたびにプロジェクトルールファイルをレンダリングします。
共有プロファイルが真実の源です。生成されたファイルへのプロジェクトローカルな編集は、
次回の同期が Apothem 管理下のコンテンツを置き換える前にバックアップされます。

## 互換性に関する注意

Trae の現在のルール面は `.trae/rules/` 配下でプロジェクトスコープになっています。
アダプターは専用の `apothem-rules.md` ファイルを書き込み、これはオペレーターが所有
する `project_rules.md` および `user_rules.md` アンカーと共存し、それらを決して
上書きしません。`.trae/mcp.json` ツールサーバー面と `.trae/skills/` スキル面は
オペレーターの所有物であり、Apothem はそれらを書き込みません。

## 検証

```bash
apothem verify --harness trae --project /path/to/project
```

verify コマンドは、次のことを確認します。

1. ネイティブ設定が期待されるパスに存在すること。
2. 共有プロファイルのすべての必須フィールドが存在すること。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness trae --project /path/to/project
```

現在の共有プロファイルの状態からプロジェクトルールファイルを再導出します。

## アンインストール

```bash
apothem uninstall --harness trae --project /path/to/project
```

アダプターによって書き込まれたネイティブ設定ファイルを削除します。
共有プロファイルの YAML と Apothem エンジンは影響を受けません。

## 適合ゲート

```bash
python -m apothem.conformity.gate --all .
```

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness trae --project /path/to/project` を再実行する |
| 検証に失敗した | `apothem update --harness trae --project /path/to/project` を実行してから、再度検証する |
| 予期しない設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認し、`apothem update --harness trae --project /path/to/project` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
