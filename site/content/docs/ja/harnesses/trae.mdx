**ベンダー：** ByteDance
**インストール名：** `trae`
**ステータス：** GA
**ネイティブ設定：** `<project>/.trae/rules/apothem-rules.md`

## インストール

```bash
apothem install --harness trae --project /path/to/project
```

アダプターは、共有の Apothem ルールとガバナンス面から、プロジェクトスコープの Trae ルールファイルを 1 つ書き込み、さらに Apothem のヘルパーを Trae サブエージェントとしてプロジェクト内に書き込みます（[サブエージェント](#サブエージェント)を参照）。

また、プロジェクトに触れる前に、Apothem のスキルと、それらが引用するルールとテンプレートを、あなたのユーザーホームに書き込みます（[プロジェクト外のファイル](#プロジェクト外のファイル)を参照）。

**書き込まれるファイル：**

- `<project>/.trae/rules/apothem-rules.md`：ルールファイル。
- `<project>/.trae/agents/<name>.md`：Apothem の各ヘルパーにつき 1 つ、プロジェクト内に。
- `~/.trae/skills/<name>/SKILL.md`：Apothem の各スキルと各コマンドにつき 1 つ、あなたのユーザーホームに。
- `~/.config/apothem/rules/` と `~/.config/apothem/templates/`：あなたのユーザーホームに。

## プロジェクト外のファイル

インストールは、プロジェクト内の何かを変更する前に、Apothem のスキルをあなたのユーザーホームにも書き込みます。

| フォルダー | Apothem がそこに書き込むもの |
| --- | --- |
| `~/.trae/skills/` | Apothem の各スキルにつき `SKILL.md` を含むフォルダーを 1 つ、そして Apothem の各コマンドにつき 1 つ（コマンドは同じ名前のスキルになります）。 |
| `~/.config/apothem/rules/`, `~/.config/apothem/templates/` | スキルとルールファイルが参照するルールとテンプレート。 |

これらのフォルダーは共有されます。プロジェクト専用ではありません。

- `trae` をインストールするすべてのプロジェクトが同じ `~/.trae/skills/` のコピーを使い、インストールは毎回同じファイルをそこに書き込みます。そのフォルダーを読むツールは Trae だけです。`~/.config/apothem/` 配下のルールとテンプレートは、他のツールのインストールによっても同じファイルで書き込まれます。
- `--project` は、書き込むルールファイルと、インストールがどのプロジェクトに属するかを選びます。スキルの書き込み先は変わりません。
- インストールは、あなたのリポジトリにスキルファイルもルールファイルも追加しません。プロジェクトが受け取るのは、ルールファイルと `.trae/agents/` 内のサブエージェントファイル、そしてプロジェクトへのインストールが毎回作成する `.apothem/` データフォルダーです。
- ホームのフォルダーが最初に書き込まれます。それが失敗した場合、たとえばパス内のフォルダーがホームディレクトリの外へ出るリンクである場合（内側にとどまるリンクはたどられます）や書き込めない場合、インストールはプロジェクト内の何かが変わる前にエラーで停止します。
- Apothem のスキルの名前を持ち、Apothem が書き込んだのではないスキルフォルダーはそのまま残され、インストールはその名前を挙げる警告を表示します。名前を変えるか移動してから、`apothem update` を実行してください。その名前が占有されている間、`apothem verify` は失敗します。
- ファイルの合計は数メガバイトになります。

インストールは、`--project` の外に書き込むフォルダーを挙げるメモを表示し、`--dry-run` はそれらを一覧表示します。

## サブエージェント

[Trae のサブエージェントに関するドキュメント](https://docs.trae.ai/ide/subagents)によれば、Trae はサブエージェントを `<project>/.trae/agents/` 内の Markdown ファイルから読み取ります。
インストールは、Apothem のヘルパーごとに 1 つのファイルをそのフォルダーに書き込みます。
インストールはプロジェクト向けのみです。ドキュメントはユーザーレベルのフォルダーを `~/.trae-cn/agents/` としている一方で、他の Trae のユーザーフォルダーはすべて `~/.trae/` 配下にあり、国際版のインストールがどちらを読むのかを Apothem は確認していないため、どちらにも書き込みません。

各ファイルはヘルパーの指示を変更せずに保持し、次のフロントマターキーを持ちます。

| キー | Apothem が書き込むもの |
| --- | --- |
| `name`, `description` | ヘルパーの名前と説明。Trae は両方を必要とします。 |
| `tools` | ヘルパーに許可されたツール。カンマ区切りの 1 つの文字列として。 |
| `disallowedTools` | ヘルパーに拒否されたツール。カンマ区切りの 1 つの文字列として。Trae はこれを `tools` より優先して適用します。ヘルパーに拒否ツールがない場合は省略されます。 |

Trae のサブエージェントのページにあるツール名だけが書き込まれます。

```text
Bash, Edit, Glob, Grep, Read, Skill, TodoWrite, WebFetch, WebSearch, Write, LSP
```

ソースが挙げるツールのうちこの一覧にないもの（たとえば `MultiEdit` や `PowerShell`）は、両方のフィールドから除外されます。
`Bash(rm *)` のようなパターン付きのツールはカンマ区切りの一覧では表せません。許可ツールとしては除外され、拒否ツールとしてはそのツール全体を拒否します。
ファイルを編集できないヘルパーはその制限を保ちます。ツールに `Write` も `Edit` も挙げず、両方を拒否します。
Trae はターン数の上限を文書化していないため、ヘルパーの `maxTurns` は書き込まれません。
インストールは `model` キーを書き込まないため、ヘルパーはチャットボックスで選ばれたモデルを使います。また `mcpServers` キーも書き込みません。

知っておくべきこと：

- Trae の英語のドキュメントは、`.trae/agents/` を読み込む前に **Settings > Beta > Subagents > Enable Subagents Directory** をオンにするよう述べています。後に更新された中国語のページは、この機能は通常デフォルトでオンだと述べています。Trae がヘルパーを 1 つも一覧表示しない場合は、そのスイッチを確認してください。
- サブエージェントファイルは通常のプロジェクトファイルです。プロジェクトと一緒にコミットするか、`.trae/agents/` を `.gitignore` に記載してください。Apothem はあなたの代わりに選びません。
- Apothem のヘルパーの名前を持つあなたのファイルは、`~/.apothem/backups/` 配下に保存されてから置き換えられます。アンインストールはそれを元に戻しません。他の名前のファイルには決して触れません。
- Trae のドキュメントは、記載のないフロントマターキーをどう扱うか、また統合された「all-new TRAE」の 2 つ目のウィンドウで、IDE ウィンドウと同様に `.trae/agents/` が適用されるかどうかを述べていません。

## プロファイルからネイティブ設定へのマッピング

アダプターは Apothem の共有プロファイルを読み取り、`apothem install` または `apothem update` を実行するたびに、プロジェクトのルールファイルをレンダリングします。
共有プロファイルが信頼できる情報源です。生成されたファイルへのプロジェクトローカルな編集は、次回の同期が Apothem 管理のコンテンツを置き換える前にバックアップされます。

このファイルは、`alwaysApply: true` と `description` を設定する YAML フロントマターで始まります。これは、[Trae のルールに関するドキュメント](https://docs.trae.ai/ide/rules)によれば Trae の Always Apply モードです。
Apothem 管理のブロックはその後に続きます。ブロックの後にあなたが追加したテキストは、同期のたびに保持されます。

## 互換性に関する注意

Trae の現在のルール面は `.trae/rules/` 配下のプロジェクトスコープです。グローバルルールは `~/.trae/user_rules` 配下に置かれます。
アダプターは専用の `apothem-rules.md` ファイルを書き込み、そのディレクトリ内の他のルールファイルやあなたのグローバルルールを決して上書きしません。
`.trae/mcp.json` のツールサーバー面とプロジェクトの `.trae/skills/` のスキル面はオペレーターの所有であり、Apothem はそれらを書き込みません。

Trae はグローバルスキル用に `~/.trae/skills/` を文書化しています。
ツール横断の `.agents/skills/` フォルダーは設定 `Enable .agents Skills
Directory` をオンにした後でのみ読むため、インストールは Trae のフォルダーに書き込みます。
中国版（TRAE CN）は代わりに `~/.trae-cn/skills/` を文書化しています。その変更履歴によれば、TRAE CN と国際版のグローバルスキルディレクトリは、個人版に限り互換性があります。
インストールは `~/.trae/skills/` にのみ書き込み、他の TRAE CN の版がそれを読むかどうかを Apothem は確認していません。
また、記載のない `SKILL.md` のヘッダーキーを Trae がどう扱うかも、Apothem は確認していません。

## 検証

```bash
apothem verify --harness trae --project /path/to/project
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. `.trae/agents/` フォルダーを含め、管理対象の各ターゲットが存在すること。管理対象のファイルは空ではなく、JSON または YAML の設定は解析できること。`--profile PATH` を追加すると、インストールされたファイルがそのプロファイルと一致することも確認します。`.trae/agents/` については、フォルダーが存在することを確認し、各ヘルパーファイルがその中にあることは確認しません。コマンド `apothem diff --harness trae --project /path/to/project` は、欠けているヘルパーファイルや古くなったヘルパーファイルを一覧表示します。
3. どのインストールが書き込んだかにかかわらず、Apothem の各スキルフォルダーが `SKILL.md` とともに所定の場所にあり、Apothem の名前を持つスキルフォルダーがどれも、Apothem が書き込んだのではないものに属していないこと。チェックが失敗すると、欠けているフォルダーや外部のフォルダーの名前が挙げられます。
4. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness trae --project /path/to/project
```

現在の共有プロファイルの状態から、プロジェクトのルールファイルを再導出します。

更新は、ファイルが現在のものと異なるスキルフォルダーも書き直します。
スキルを書き込まなかった以前のリリースでインストールした場合、更新はスキルを追加します。
現在のものと異なるサブエージェントファイルを書き直し、欠けているものを追加します。

## アンインストール

```bash
apothem uninstall --harness trae --project /path/to/project
```

`<project>/.trae/rules/apothem-rules.md` から、Apothem のブロックと、Apothem がその上に書き込んだフロントマターを削除し、その中の他のテキストは残します。
このファイルは、その中に他に何も残っていない場合にのみ削除されます。
変更の前に、このファイルのタイムスタンプ付きコピーが `~/.apothem/backups/` 配下に保存されます。プロジェクト内にバックアップファイルは残りません。
共有プロファイルの YAML と Apothem エンジンには影響しません。

アンインストールは、`<project>/.trae/agents/` に書き込んだサブエージェントファイルも削除し、そこにある他のファイルは残します。フォルダーは空になった場合に削除されます。
`~/.trae/skills/` に書き込んだスキルフォルダーと `~/.config/apothem/` 内のルールとテンプレートも削除しますが、それは他の Apothem のインストールがまだそれらを使っていない場合に限ります。
別のプロジェクトや、そのフォルダーを共有する別のツールが使っている可能性があります。
その場合、アンインストールはフォルダーを残し、どのインストールがそれらを使っているかを表示し、最後のアンインストールがそれらを削除します。
あなたがそれらのフォルダーに追加したファイルは残り、空になったフォルダーは削除されます。
各フォルダーは、削除される前に `~/.apothem/backups/` 配下にバックアップされます。

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness trae --project /path/to/project` を再実行する |
| 検証が失敗した | `apothem update --harness trae --project /path/to/project` を実行してから、再度検証する |
| Trae が Apothem のヘルパーを 1 つも一覧表示しない | Settings > Beta > Subagents > Enable Subagents Directory をオンにしてから、新しいチャットを開始する |
| `apothem verify` が欠けているスキルフォルダーの名前を挙げる | `apothem install --harness trae --project /path/to/project` を実行する。これでフォルダーが復元される |
| インストールまたは更新が、スキルフォルダーをスキップしたと警告する | Apothem のスキルの名前を持つフォルダーがスキルフォルダー内にすでに存在し、Apothem が書き込んだものではない。名前を変えるか移動してから、`apothem update` を実行する |
| インストールがプロジェクトを変更する前に停止する | ホーム内への書き込みが失敗した。エラーを読み、それが挙げるフォルダー（ホームディレクトリの外へ出るリンク、フォルダーがあるべき場所にあるファイル、または読み取り専用のフォルダー）を修正してから、再度インストールする |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness trae --project /path/to/project` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
