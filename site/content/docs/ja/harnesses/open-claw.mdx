**ベンダー：** Open-Claw
**インストール名：** `open-claw`
**ステータス：** プレビュー
**ネイティブ設定：** `~/.openclaw/openclaw.json`

## インストール

```bash
apothem install --harness open-claw
```

アダプターは OpenClaw のユーザーグローバル設定ファイルを書き込み、共有プロファイルをプロファイルドキュメントへ投影し、Apothem のサポートコホートをハーネスルート配下にインストールします。
OpenClaw のネイティブ設定は JSON であり、マテリアライザーは空の JSON オブジェクトをレンダリングし、既存のファイルはそのキーを保持します。

**書き込まれるファイル：** `~/.openclaw/openclaw.json`、プロファイルドキュメント
`~/.openclaw/apothem/rules/00-apothem-profile.md`、および
`~/.openclaw/.apothem/support/` 配下のサポートファイル

プロファイルドキュメントは Apothem サポートファイルのセクションで終わります。
このセクションは、リポジトリ形式の各参照（`rules/<name>.md`、`templates/...`、`hooks/...`）が解決される先の、`~/.openclaw/.apothem/support/` 配下の絶対ディレクトリを示します。

## プロファイルからネイティブ設定へのマッピング

アダプターは Apothem の共有プロファイルを読み取りますが、設定キーは一切作成しません。
新規または空の `openclaw.json` は空のオブジェクトとして書き込まれ、既存のファイルはそのキーを保持します。
プロファイルのアイデンティティ、プリファレンス、ルールはプロファイルドキュメントに入ります。
共有のコマンド、スキル、ルール、テンプレート、フックプロンプトは、`~/.openclaw/.apothem/support/` 配下にサポート素材としてインストールされます。

## 互換性に関する注意

プレビュー版のアダプターです。
OpenClaw は、サポートツリーもプロファイルドキュメントも自力では読み込みません。スキルの場所、ワークスペースの命令ファイル、設定のいずれもそこを指していないため、インストール後の OpenClaw は Apothem のルール、スキル、MCP サーバーなしで動作します。
OpenClaw は、ワークスペースの `skills/` フォルダーと `.agents/skills/` フォルダー、`~/.agents/skills`、自身の状態ディレクトリ、そして `skills.load.extraDirs` に列挙された任意のフォルダーからスキルを読み込みます。Apothem のスキルを使うには、`~/.openclaw/.apothem/support/skills` をそのリストに自分で追加してください。`apothem update` は、あなたが `openclaw.json` に追加したキーを保持します。
MCP サーバーは OpenClaw 設定の `mcp.servers` ブロックに置かれ、`openclaw mcp add` と関連するサブコマンドで管理します。アダプターはそこにエントリを一切書き込みません。
（OpenClaw の振る舞いは、[スキル](https://docs.openclaw.ai/tools/skills)と [MCP CLI](https://docs.openclaw.ai/cli/mcp) に関するドキュメントに基づき、2026-10-02 に参照したものです。）

## 検証

```bash
apothem verify --harness open-claw
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. 管理対象の各ターゲットが存在すること。管理対象のファイルは空ではなく、JSON または YAML の設定は解析できること。`--profile PATH` を追加すると、インストールされたファイルがそのプロファイルと一致することも確認します。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness open-claw
```

現在の共有プロファイルの状態からプロファイルドキュメントを再導出し、サポートファイルを更新します。`openclaw.json` は、すでに持っているキーを保持します。
`~/.config/apothem/profile.yaml` を編集した後、またはインストール済みの Apothem パッケージをアップグレードした後に実行してください。

## アンインストール

```bash
apothem uninstall --harness open-claw
```

アダプターが書き込んだネイティブ設定ファイルを削除します。
共有プロファイルの YAML と Apothem エンジンには影響しません。

## コンフォーミティゲート

```bash
python -m apothem.conformity.gate --all .
```

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness open-claw` を再実行する |
| 検証が失敗した | `apothem update --harness open-claw` を実行してから、再度検証する |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness open-claw` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
