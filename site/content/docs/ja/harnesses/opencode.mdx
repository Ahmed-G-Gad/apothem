**ベンダー：** OpenCode
**インストール名：** `opencode`
**ステータス：** ベータ版
**ネイティブ設定：** `~/.config/opencode/`

## インストール

```bash
apothem install --harness opencode
```

アダプターは OpenCode の JSON 設定を書き込み、Apothem のスキルを OpenCode のスキル面に
インストールし、コマンドプロンプトを OpenCode の Markdown コマンドファイルに変換し、
Apothem のヘルパー定義を OpenCode のサブヘルパーとして正規化します。

**書き込まれるファイル：**

```text
~/.config/opencode/opencode.json
~/.config/opencode/commands/
~/.config/opencode/skills/
~/.config/opencode/agents/
~/.config/opencode/.apothem/support/{rules,templates,hooks}/
```

## プロファイルからネイティブ設定へのマッピング

アダプターは、あなたのプロファイルドキュメントと Apothem の常時適用ルールを指定する
`instructions` ファイルリストを含めて `opencode.json` をレンダリングし、その後、共有された
各 Apothem コホートを、OpenCode のネイティブ面または Apothem 所有のサポートサブツリーの
いずれかへ伝播します。既存の、一致する Apothem 管理の子要素は、置き換えの前に
バックアップされます。

## 互換性に関する注意

OpenCode は、`instructions` リストが指定するすべてのファイルを、すべてのセッションに
結合します（[OpenCode のルール](https://opencode.ai/docs/rules/)）。そのため、このリストは
最初にあなたのプロファイルドキュメントを指定し、続いて `alwaysApply` が `true` である
ルールのみを、それぞれ 1 つの明示的な
`~/.config/opencode/.apothem/support/rules/<name>.md` パスとして指定します。OpenCode は
先頭の `~/` をあなたのホームディレクトリに展開します。パスでフィルタリングされるルール、
テンプレート、フックプロンプトは、`~/.config/opencode/.apothem/support/` 配下に参照素材として
インストールされたまま残り、それを参照するルール、スキル、コマンドがオンデマンドで読み込みます。
コマンド、スキル、ヘルパー定義はネイティブの検出場所を使用します。

プロファイルドキュメント `~/.config/opencode/apothem/rules/00-apothem-profile.md` は、
共有プロファイルに由来するあなたのアイデンティティとプリファレンスを保持し、Apothem
サポートファイルのセクションで終わります。このセクションは、リポジトリ形式の各参照
（`rules/<name>.md`、`templates/...`、`hooks/...`）が解決される先の、
`~/.config/opencode/.apothem/support/` 配下の絶対ディレクトリを示します。このドキュメントは
最初の `instructions` エントリであるため、OpenCode はすべてのセッションでこれを読み込みます。

以前のリリースが書き込んだ `opencode.json` には、すべてのルールを読み込む単一のグロブ
`~/.config/opencode/.apothem/support/rules/*.md` が記載されています。
`apothem install` と `apothem update` はそれを常時適用のリストに置き換え、
`apothem uninstall` は両方の形式を削除します。あなた自身の `instructions` エントリは、
いずれの場合も保持されます。

## 検証

```bash
apothem verify --harness opencode
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. 管理対象の各ターゲットが存在すること。管理対象のファイルは空ではなく、JSON または YAML の設定は解析できること。`--profile PATH` を追加すると、インストールされたファイルがそのプロファイルと一致することも確認します。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness opencode
```

`opencode.json`、ネイティブコマンド、スキル、ヘルパー定義、Apothem サポートツリーを
更新します。

## アンインストール

```bash
apothem uninstall --harness opencode
```

アダプターが書き込んだネイティブ設定ファイルを削除します。
共有プロファイルの YAML と Apothem エンジンには影響しません。

## コンフォーミティゲート

```bash
python -m apothem.conformity.gate --all .
```

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness opencode` を再実行する |
| 検証が失敗した | `apothem update --harness opencode` を実行してから、再度検証する |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness opencode` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
