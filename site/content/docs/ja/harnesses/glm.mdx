**ベンダー：** Z.ai
**インストール名：** `glm`
**ステータス：** GA
**ネイティブ設定：** `<project>/.apothem/providers/glm.toml`

`glm` アダプターは、GLM (Z.ai) を**モデルバックエンド**として設定します。
Anthropic 互換または OpenAI 互換のプロトコルを話すツールを、バックエンドのベース URL とキーを設定することで GLM に向け、他のものと同様に `--harness glm` でアダプターを選択します。
アダプターは、両方の互換面を記録したプロバイダー設定ファイルを書き込むため、互換性のある任意のツールを GLM モデルファミリーに接続できます。

Z.ai は独自のファーストパーティのコーディングツールである ZCode も提供しており、Z.ai の[ドキュメント](https://docs.z.ai/devpack/tool/zcode)はこれを「Agentic Development Environment」と呼んでいます。
このアダプターは ZCode を設定しません。
Apothem は ZCode 自身の設定面を確認していないため、アダプターはそれ向けには何も書き込みません。

## インストール

```bash
apothem install --harness glm --project /path/to/project
```

アダプターは、GLM バックエンドのエンドポイントと、オペレーターが設定可能なプレースホルダーを記録した、プロジェクトスコープのプロバイダーファイルを 1 つ書き込みます。

**書き込まれるファイル：** `<project>/.apothem/providers/glm.toml`

## プロファイルからネイティブ設定へのマッピング

プロバイダーファイルは 2 つのバックエンドを記録します。
Anthropic 互換バックエンドは、ベース URL `https://api.z.ai/api/anthropic` を使用します。Anthropic プロトコルを話すツールは、`ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、および任意で `API_TIMEOUT_MS` を設定することで GLM へルーティングされます。
ファイル内の `[backends.anthropic_compatible.env]` テーブルには、これらの変数に加えて `ANTHROPIC_DEFAULT_OPUS_MODEL`、`ANTHROPIC_DEFAULT_SONNET_MODEL`、`ANTHROPIC_DEFAULT_HAIKU_MODEL` も列挙されており、これらはツールの opus、sonnet、haiku の役割を GLM のモデルに対応付けます。
OpenAI 互換バックエンドは、ベース URL `https://api.z.ai/api/coding/paas/v4` を使用します。
認証トークンは、あなた自身の Z.ai キーに置き換えるプレースホルダーです。Apothem が本物のシークレットを書き込むことは決してありません。
モデル ID はバージョンによって変わりやすいため、Apothem はどれもピン留めしません。ファイルには `<GLM_MODEL_ID>` プレースホルダーが含まれており、最新の [Z.ai ドキュメント](https://docs.z.ai/devpack/tool/claude)を参照して埋めます。
共有プロファイルの内容がこのファイルに入ることはありません。これは固定のテンプレートです。

### 役割からモデルへのマッピング

役割からモデルへのマッピングについての Z.ai 自身の記述は食い違っているため、ファイルは 3 つの `ANTHROPIC_DEFAULT_*_MODEL` の値をプレースホルダーのまま残し、その上に `TODO(clarify)` コメントを置きます。
どのマッピングを使うかはあなたが決めます。

- ベンダーの Anthropic 互換セットアップガイドにある手動の `settings.json` の例は、opus と sonnet を `glm-5.3[1m]` に、haiku を `glm-5.3-flash[1m]` に対応付け、`CLAUDE_CODE_AUTO_COMPACT_WINDOW` を `1000000` に設定します。
- 同じガイドに記載されたデフォルトのマッピングは、3 つの役割すべてに `GLM-5.3-Flash` を挙げています。
- Z.ai の `@z_ai/coding-helper` ツールは、デフォルトで `glm-5.3-flash` を使い、3 つの役割すべてに `[1m]` を付加し、コンパクションウィンドウとして `1048576` を書き込みます。

Apothem はこれらの値のどれもピン留めせず、それらの間で選択もしません。

## 互換性に関する注意

GLM バックエンドはルール、コマンド、スキル、フックのための面を公開しないため、アダプターはバックエンドのプロバイダーファイルのみを書き込み、それ以外は何も書き込みません。
ZCode がそのような面を公開しているかどうかを、Apothem は確認していません。
あなたの Z.ai キーとモデル ID の選択は、オペレーターの所有のままです。
アダプターが依拠するベンダー面の規約は `src/apothem/harnesses/glm/STANDARD-CONVENTION-PIN.md` にピン留めされており、公開中の Z.ai ドキュメントに対してスナップショットが取られています。

GLM は Z.ai の GLM モデルファミリーを実行します。
現在のバックエンド、モデル、Anthropic 互換の設定面については、[ベンダーの設定リファレンス](https://docs.z.ai/devpack/tool/claude)を参照してください。

## 検証

```bash
apothem verify --harness glm --project /path/to/project
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. プロバイダーファイルが存在し、空でないこと。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness glm --project /path/to/project
```

プロバイダーファイルは、いったん存在すればあなたのものです。
`install` と `update` はどちらも、`.apothem/providers/glm.toml` が存在しない場合にのみテンプレートを書き込み、その後はどちらもそれを決して上書きしないため、あなたのキー参照とモデルの選択はすべての再実行を経ても残ります。
より新しいテンプレートを取り込むには、自分のファイルを別の場所へ移動し、`update` を実行してから、自分の値を新しいファイルにコピーしてください。

## アンインストール

```bash
apothem uninstall --harness glm --project /path/to/project
```

プロバイダーファイルを削除するのは、Apothem がそれを作成し、かつ編集されていないテンプレートのままである場合のみで、その際は先に Apothem のバックアップルート配下にバックアップします。
以前のリリースが書き込んだ未編集のファイルも、プロジェクトに対する Apothem のインストール記録がそのファイルを書き込んだことを示していれば対象になります。マニフェストは、そのプロジェクトがこれまでに出荷した各テンプレートのダイジェストを記録しています。
インストール記録がない場合は、現在のテンプレートと完全に一致するコピーだけが削除されます。
あなたが作成または編集したファイルはそのまま残されます。
共有プロファイルの YAML と Apothem エンジンには影響しません。

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness glm --project /path/to/project` を再実行する |
| 検証が失敗した | プロバイダーファイルが存在しないか、空である。存在しない場合は、`apothem update --harness glm --project /path/to/project` を実行する。空の場合は、先に `.apothem/providers/glm.toml` を別の場所へ移動してから、`update` を実行し、再度検証する |
| 想定外の設定内容 | `.apothem/providers/glm.toml` を直接編集する。Apothem が既存のファイルを書き換えることはなく、共有プロファイルがそこに何かを加えることもない。新しいテンプレートが必要な場合は、ファイルを別の場所へ移動してから `apothem update --harness glm --project /path/to/project` を実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
