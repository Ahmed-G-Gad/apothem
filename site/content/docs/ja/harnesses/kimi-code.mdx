**ベンダー：** Moonshot
**インストール名：** `kimi-code`
**ステータス：** GA
**ネイティブ設定：** `<project>/AGENTS.md`、`<project>/.kimi-code/skills/`、`<project>/.kimi-code/agents/`、および `<project>/.kimi-code/.apothem/support/`

## インストール

```bash
apothem install --harness kimi-code --project /path/to/project
```

アダプターは、共有の Apothem ガバナンス面を、センチネルで区切られた管理ブロックとしてプロジェクトルートの `AGENTS.md` に書き込みます（センチネルの外側にあるオペレーターの文章は保持されます）。
スキルと、スキルとしてラップされたコマンドを、Kimi Code のネイティブなプロジェクトスキルディレクトリである `<project>/.kimi-code/skills/` にインストールし、Apothem のヘルパーを Kimi Code サブエージェントとして `<project>/.kimi-code/agents/` にインストールします（[サブエージェント](#サブエージェント)を参照）。
その他のコホートは、`<project>/.kimi-code/.apothem/support/` にある Apothem 所有のサポートツリー配下にとどまります。
プロジェクトの `AGENTS.md` は Kimi Code 以外にも多くのコーディングツールに読み込まれるため、このブロックは、単一のツールを読み手として名指ししない、プロジェクト全体のガイダンスとして書かれます。

Kimi Code は、汎用的な AGENTS.md 規約に従ってプロジェクトルートの `AGENTS.md` 命令ファイルを読み込み、プロジェクト設定は `<project>/.kimi-code/` 配下に置かれます。
Kimi Code は、作業ディレクトリから上方向に探索して `.git` を含む最も近いディレクトリをプロジェクトルートとみなすため、`--project` にはリポジトリのルートを渡してください。
`<project>/.kimi-code/mcp.json` 面はオペレーターの所有です。Apothem はそれを名指ししますが、エントリは一切作成しません。

**書き込まれるファイル：** `<project>/AGENTS.md`（管理ブロック）、`<project>/.kimi-code/skills/` 配下のスキルとコマンド（スキルとして）、
Apothem の各ヘルパーにつき 1 つの `<project>/.kimi-code/agents/<name>.md`、そして
`<project>/.kimi-code/.apothem/support/` 配下のフック、ルール、テンプレートの各コホート。

## サブエージェント

[カスタムサブエージェントに関する Kimi Code のドキュメント](https://moonshotai.github.io/kimi-code/en/customization/agents.md)によれば、Kimi Code はサブエージェントを `.kimi-code/agents/`（または `.agents/agents/`）内の Markdown ファイルから読み取ります。
インストールは、14 個すべてのヘルパーについて、Apothem のヘルパーごとに 1 つのファイルを `<project>/.kimi-code/agents/` に書き込みます。
インストールはプロジェクト向けのみで、`~/.kimi-code/agents/` フォルダーには書き込みません。

各ファイルはヘルパーの指示を変更せずに保持し、次のフロントマターキーを持ちます。

| キー | Apothem が書き込むもの |
| --- | --- |
| `name`, `description` | ヘルパーの名前と説明。 |
| `tools` | ヘルパーが使えるツール。Kimi Code のツール名の一覧として。 |
| `disallowedTools` | ヘルパーが拒否されるツール。Kimi Code のツール名の一覧として。Kimi Code はこれを `tools` の後に適用します。 |

Kimi Code はツール名を大文字小文字を含めて完全一致で照合し、対応するツールがない名前については警告します。
そのため、インストールは Kimi Code が異なる綴りを使う 2 つのツールの名前を変え（`WebFetch` を `FetchURL` に、`TodoWrite` を `TodoList` に）、Kimi Code に対応するツールがない名前（`MultiEdit`、`NotebookEdit`、`PowerShell`、`Monitor`、`Artifact`、`TaskCreate`、`TaskUpdate`）は除外します。
拒否されたツールは拒否されたままです。
このようにしてヘルパーの許可ツールがすべて消えた場合、ファイルは `tools: []` を持ち、これはどのツールも許可しません。`tools` を省略すると、すべてのツールが許可されてしまいます。

インストールは、`model`（Kimi Code にはサブエージェント用のモデルキーがなく、サブエージェントはメインセッションのモデルか `config.toml` 内の `[secondary_model]` を使います）、`override`（プロジェクトのファイルが組み込みのサブエージェントを置き換えられるようになってしまいます）、`subagents`、`whenToUse`、Apothem の `maxTurns`、`version`、`updated`、`portability` キーのいずれも決して書き込みません。

知っておくべきこと：

- サブエージェントファイルは通常のプロジェクトファイルです。プロジェクトと一緒にコミットするか、`.kimi-code/agents/` を `.gitignore` に記載してください。Apothem はあなたの代わりに選びません。
- Kimi Code は、委任が求められたときにヘルパーを使います。2026-10-25 のリリース以降、Kimi Code はデフォルトで、自らサブエージェントを起動するのではなくタスクを自身で処理するため、メッセージの中または `AGENTS.md` の中で、ヘルパーを名前で指定して求めてください。ベンダーのカスタムサブエージェントのページは依然として自動的なスケジューリングを説明しているため、これは変わる可能性があります。
- `.kimi-code/agents/` 内のプロジェクトレベルのファイルは、extra、ユーザー、プラグインの各レベルにある同じ名前の定義より優先されます。あなた自身のヘルパーには、Apothem のものとは異なる名前を付けてください。Kimi Code のコードは、Apothem が決して書き込まない共有の `.agents/agents/` フォルダーよりも先に `.kimi-code/agents/` を読み、同じ名前の 2 つのファイルのうち最初のものを保持します。ドキュメントはこれについて述べていません。
- Apothem のヘルパーの名前を持つあなたのファイルは、`~/.apothem/backups/` 配下に保存されてから置き換えられます。アンインストールはそれを元に戻しません。他の名前のファイルには決して触れません。
- 以前のリリースは、ヘルパーファイルをサポートツリー内の `.kimi-code/.apothem/support/agents/` に置いており、そこでは Kimi Code はそれらを読み込みませんでした。`apothem update` または `apothem uninstall` は、そのコピーを `~/.apothem/backups/` 配下に保存した後で削除します。

## プロファイルからネイティブ設定へのマッピング

アダプターは Apothem の共有プロファイルを読み取り、`apothem install` または `apothem update` を実行するたびに、プロジェクトルートの `AGENTS.md` 命令面をレンダリングします。
振る舞いルールとガバナンスコーパスは `AGENTS.md` の管理ブロックに置かれます。
各スキルと、スキルとしてラップされた各コマンドは、Kimi Code が読み込むプロジェクトスキルディレクトリである `.kimi-code/skills/<name>/SKILL.md` に置かれます。
アダプターはこの Kimi 固有のフォルダーにのみ書き込み、他のツールも読む `.agents/skills/` には決して書き込みません。
あなたが自分で `.kimi-code/skills/` に他の名前で追加したスキルは、インストール、更新、アンインストールのいずれでも保持されます。
そこにある、Apothem のスキルと同じ名前のスキルは置き換えられます。インストールと更新はそれを上書きし、アンインストールはそれを削除します。いずれも `~/.apothem/backups/` 配下にタイムスタンプ付きコピーを保存した後で行われ、インストールは名前の衝突について何の通知も表示しません。
あなた自身のスキルには、Apothem のものとは異なる名前を付けてください。

フック、ルール、テンプレートの各コホートは `.kimi-code/.apothem/support/` 配下に配置され、命令面から参照されます。
Kimi Code はそれらをサポートツリーからは読み込まないため、そこにある Apothem のコピーは、`AGENTS.md` ブロックが指し示す参照用の素材です。
ブロックは Apothem サポートファイルのセクションで終わります。このセクションは、リポジトリ形式の各参照（`rules/<name>.md`、`templates/...`、`hooks/...`）が解決される先の `.kimi-code/.apothem/support/` 配下のディレクトリを、プロジェクトルートからの相対パスで示します。そのため、コミットされた `AGENTS.md` にはマシン固有のパスが含まれません。
（Kimi Code の振る舞いは、[スキル](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/skills.html)、[ヘルパーの定義](https://moonshotai.github.io/kimi-code/en/customization/agents.md)、[フック](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html)に関するカスタマイズページに基づき、スキルとフックについては 2026-10-24 に、ヘルパーの定義については 2026-10-27 に参照したものです。）

## ネイティブにはインストールされないもの

Kimi Code はフック用のネイティブな場所を文書化しています。
アダプターは、次の理由により、まだそこには書き込みません。

- **フック。** Kimi Code は `~/.kimi-code/config.toml`（その変数が設定されている場合は `$KIMI_CODE_HOME/config.toml`）の `[[hooks]]` 配列からフックを読み込みます。Apothem は 1 つも書き込みません。そのファイルはユーザースコープですが、このアダプターはプロジェクトルート配下に書き込みます。エントリーには 4 つのフィールドしか許されず（`event` と `command` が必須、`matcher` と `timeout` が任意）、余分なフィールドがあると設定が読み込まれなくなります。また Apothem には、後で自身のエントリーだけを削除できる TOML のマージ機能がありません。フックのヘルパースクリプトはサポートツリーにとどまります。
- **スキルのフロントマター。** ベンダーのページは、`SKILL.md` のキーとして `name` と `description`（どちらも必須）、`type`、`whenToUse`、`disableModelInvocation`（`disable-model-invocation` としても受け付けられます）、`arguments` を文書化しています。それ以外のキーについての規則は述べていません。スキルは Apothem のソース内で持っているフロントマターのままインストールされるため、`version`、`updated`、`archetype`、`userInvocable`、`argument-hint`、`portability`、`allowed-tools` などのキーが Kimi Code に届き、Kimi Code はそれらを無視するか拒否する可能性があります。
- **同じ名前のスキル。** Kimi Code はプロジェクトレベルをユーザーレベルより優先するため、`<project>/.kimi-code/skills/` 内のスキルは、別の Apothem アダプターが書き込む `~/.agents/skills/` 内の同じ名前のスキルより優先されます。プロジェクトレベルの中で `.kimi-code/skills/` と `.agents/skills/` がどのように順位付けされるかを、ベンダーのページは述べていません。

## 互換性に関する注意

Kimi Code はプロジェクトの命令を `AGENTS.md` または `.kimi-code/AGENTS.md` から読み込み、`.kimi-code/mcp.json` をオペレーター所有の MCP 面として認識します。Apothem はその面を名指ししますが、そこにエントリを一切作成しません。
2 つの命令ファイルのうち、アダプターが書き込むのはプロジェクトルートの `AGENTS.md` だけで、これは Kimi Code がプロジェクトの命令として読み込むファイルです。両方のファイルが存在する場合にどちらが優先されるかは、Kimi Code のドキュメントに記載がありません。
Kimi Code はステータスラインや出力スタイルのファイル面を公開していないため、それらのコホートはマテリアライズされません。

Kimi Code は Moonshot の Kimi モデルファミリーで動作します。
現在のモデルと設定面については、[ベンダーの設定リファレンス](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/config-files)を参照してください。

## 検証

```bash
apothem verify --harness kimi-code --project /path/to/project
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. スキルとサブエージェントのディレクトリを含め、管理対象の各ターゲットが存在すること。管理対象のファイルは空ではなく、JSON または YAML の設定は解析できること。`--profile PATH` を追加すると、インストールされたファイルがそのプロファイルと一致することも確認します。`.kimi-code/agents/` については、フォルダーが存在することを確認し、各ヘルパーファイルがその中にあることは確認しません。コマンド `apothem diff --harness kimi-code --project /path/to/project` は、欠けているヘルパーファイルや古くなったヘルパーファイルを一覧表示します。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness kimi-code --project /path/to/project
```

現在の共有プロファイルの状態から、プロジェクトルートの `AGENTS.md` 管理ブロック、スキル、サブエージェントファイル、サポートコホートを再導出します。
スキルが `.kimi-code/skills/` に移る前に行われたインストールに対する更新は、古い `<project>/.kimi-code/.apothem/support/skills/` ディレクトリを削除するため、各スキルは 1 つだけ存在します。
ヘルパーが `.kimi-code/agents/` に移る前のインストールに対する更新は、同じように古い `<project>/.kimi-code/.apothem/support/agents/` ディレクトリを削除します。
削除される各ディレクトリのタイムスタンプ付きコピーが、先に `~/.apothem/backups/` 配下に保存されます。

## アンインストール

```bash
apothem uninstall --harness kimi-code --project /path/to/project
```

プロジェクトルートの `AGENTS.md` から Apothem ブロックを削除し、センチネルの外側にあるテキストは保持します。
ファイルが削除されるのは、その中に他に何も残っていない場合のみです。
また、Apothem が `<project>/.kimi-code/skills/` 配下に配置したスキル（あなたがそこに他の名前で追加したスキルは保持されます）、`<project>/.kimi-code/agents/` 配下のサブエージェントファイル（あなたがそこに他の名前で追加したファイルは保持され、フォルダーは空になった場合に削除されます）、そして、一度も更新されなかったインストールのサポートツリー内の古い `skills/` と `agents/` ディレクトリを含む、`<project>/.kimi-code/.apothem/support/` 配下のサポートファイルも削除します。
変更の前に、各ファイルのタイムスタンプ付きコピーが `~/.apothem/backups/` 配下に保存されます。プロジェクト内にバックアップファイルは残りません。
共有プロファイルの YAML と Apothem エンジンには影響しません。

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness kimi-code --project /path/to/project` を再実行する |
| 検証が失敗した | `apothem update --harness kimi-code --project /path/to/project` を実行してから、再度検証する |
| Kimi Code でスキルやヘルパーが見つからない | `--project` がリポジトリのルート（`.git` を含むディレクトリ）を指していることを確認してから、インストールを再実行する |
| Kimi Code がヘルパーを一度も使わない | ヘルパーを名前で指定して求める。委任が求められない限り、Kimi Code はタスクを自身で処理する |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness kimi-code --project /path/to/project` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
