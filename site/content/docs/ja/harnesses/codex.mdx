**ベンダー：** OpenAI
**インストール名：** `codex`
**ステータス：** ベータ
**ネイティブ設定：** `~/.codex/AGENTS.md`、`~/.codex/hooks.json`、
`~/.codex/hooks/`、`~/.codex/agents/*.toml`、および `~/.agents/skills/`

## インストール

```bash
apothem install --harness codex
```

アダプターは Codex ネイティブの命令とフックをインストールし、Apothem のエージェントを Codex の TOML エージェントに変換し、再利用可能なコマンドプロンプトを Codex のスキルとしてラップします。

**書き込まれるファイル：** `~/.codex/AGENTS.md`、`~/.codex/hooks.json`、
`~/.codex/hooks/`、`~/.codex/agents/*.toml`、
`~/.agents/skills/*/SKILL.md`、ユーザー起動スキル向けの `~/.agents/skills/*/agents/openai.yaml`、
および `~/.config/apothem/{rules,templates}/` 配下のサポートファイル。

**フックインタープリター。** 何かを書き込む前に、インストールは CPython 3.10+ の
インタープリターを解決します。Windows では、`hooks.json` 内の各フックの
`commandWindows` エントリは、`py -3` ランチャーの代わりにそのインタープリターの
絶対パスを実行します。POSIX の `command` エントリは `python3` のままです。
インタープリターが移動または削除された後は、`apothem update --harness codex` を
再実行してください。CPython 3.10+ が見つからない場合、インストールは
ファイルを 1 つも書き込む前に停止します。

`AGENTS.md` 内の Apothem ブロックは、Apothem サポートファイルのセクションで終わります。
このセクションは、インストールされたスキルとルール内にあるリポジトリ形式の各参照が解決される先の絶対ディレクトリを示します。`rules/<name>.md` と `templates/...` は `~/.config/apothem/` 配下に、`hooks/...` は `~/.codex/hooks/` 配下に解決されます。
Codex のインストールは `schemas/` ツリーも `conformity/` ツリーも同梱しないため、このセクションはどちらも列挙しません。

**ユーザー起動スキル。** Codex は `disable-model-invocation` キーを無視します。
ソースで `disable-model-invocation: true` が設定されているすべてのスキルまたはコマンドについて、アダプターは `SKILL.md` の隣に `policy.allow_implicit_invocation: false` を指定した `agents/openai.yaml` を書き込みます。
これにより、Codex がそのスキルを自ら選ぶことはありません。`$skill-name` を使えば、引き続き明示的に実行できます。
[Codex のスキルに関するドキュメント](https://developers.openai.com/codex/skills)を参照してください。

## プロファイルからネイティブ設定へのマッピング

アダプターは Apothem の共有コホートを読み取り、それぞれを正しい Codex の面にインストールします。
命令は `AGENTS.md` へ、フックは `hooks.json` と `hooks/` へ、エージェントは TOML へ、スキルは `~/.agents/skills/` へ、ネイティブでない Markdown のルール/テンプレートはサポート素材として `~/.config/apothem/` へインストールされます。

変換された各ヘルパーは `name`、`description`、`developer_instructions` を設定し、後者はヘルパーの本文を保持します。
モデルも推論エフォートも設定されないため、各ヘルパーはセッションの選択を継承します。
Codex にはヘルパーごとのツールリストもターン数の上限もないため、ヘルパーの `tools` と `maxTurns` は引き継がれません。

読み取り専用のヘルパー（[エージェントのリファレンス](/docs/reference/agents)を参照）は、自身の指示の中で何も編集しないと述べています。
読み取り専用は、ヘルパーの TOML ファイルではなく、親セッションのサンドボックスによって強制されます。すべてのヘルパーは、それを開始したセッションのサンドボックスと承認の設定の下で実行されます。
ヘルパーファイルはセッションのサンドボックスモード、承認ポリシー、モデルプロバイダー、MCP サーバーを上書きできないため、アダプターはそれらを 1 つも書き込みません。また、ヘルパーの指示は編集を避けるよう求めることはできても、別個の読み取り専用サンドボックスを作り出すことはできません。
読み取り専用の制限を拘束力のあるものにするには、Codex のセッション自体でサンドボックスと承認の制御を設定してください。
この制限を追加したリリースより古い `Codex` のビルドは、ヘルパーファイル内の `sandbox_mode` をまだ尊重する可能性があります。それがどのリリースかを Apothem は確定しておらず、いずれにせよ `sandbox_mode` は書き込みません。

## 互換性に関する注意

`~/.agents/skills/` は Codex が所有する共有ルートです。サポート対象の他の 9 つのツールもこれを読み込むため（[ハーネスレジストリ](/docs/reference/harness-registry)に列挙されています）、Codex のインストールがそこに書き込む Apothem のスキルはそれらのツールにも表示されます。
それらのツールのうち 4 つは、インストールしたときに自らもこのフォルダーに書き込み（レジストリでは共同インストーラーとして列挙されています）、Codex のインストールが書き込むのと同じファイルを書き込むため、Codex のインストールがないマシンにもスキルが存在します。
`~/.config/apothem/` 内のルールとテンプレートについても同様で、7 つのプロジェクトスコープのアダプターもこれらを書き込みます。
このフォルダーは、`CODEX_HOME` が何であっても常にあなたのユーザーホームにあります。Codex は `$HOME/.agents/skills` を読むため、`~/.codex` 以外の `CODEX_HOME` は Codex のファイルを移動させますが、スキルは移動させません。
このフォルダーを使うすべての Apothem のインストールはそこに同じファイルを書き込み、インストールはどのインストールがそれを使っているかを記録するため、インストールする順序は関係ありません。
Codex のアンインストールは、スキルをまだ使っている他の Apothem のインストールがない場合にのみそれらを取り除きます。そうでなければスキルを残し、どのインストールが使っているかを示します（[アンインストール](#アンインストール)を参照）。
登録された所有者は、ベンダーがそのパスを文書化しているツールです。
ファイルを配置したインストールは、まだそれらを使っているインストールのいずれかであり、インストールの注記がそれを名指しします。
Apothem が書き込んだのではなく、Apothem のスキルと同じ名前を持つスキルフォルダーはそのまま残され、その名前を挙げる警告が出ます。
インストール時には、それらのツールを名指しする注記が出力されます。
`~/.codex/agents/` は 2 つ目の共有ルートです。サポート対象の別のツールがこのフォルダーを互換性のための場所として挙げており（レジストリがそのツールを名指ししています）、そのドキュメントは、`Codex` のインストールがそこに書き込む TOML ファイルを読むかどうかを述べていません。

Codex は `~/.codex/rules/` を `.rules` 実行ポリシー用に予約しています。
Apothem は Markdown の振る舞いルールをそこに配置しません。それらを `~/.config/apothem/` に保持し、`AGENTS.md` とインストールされたスキルから参照します。

## Codex プラグイン

Apothem は、リポジトリのプラグインマーケットプレイスから追加する Codex プラグインも提供しています（[インストールガイド](/docs/install)のチャネル 7 にコマンドが列挙されています）。
このプラグインはブートストラップです。エンジンを実行するエントリースキルを 1 つ同梱し、上に列挙したすべてのものは `apothem install --harness codex` が書き込みます。

プラグインは `plugins/apothem/` にあります。
そのマニフェストはルートの `plugin.json` で、Codex が新しいパッケージ向けに文書化している場所です。
Codex はプラグインのルートからプラグインの `skills/` ディレクトリを検出するため、マニフェストはスキルのパスを指定しません。
その隣には、古い場所しか読まない Codex のビルド向けの互換性のためのフォールバックとして `.codex-plugin/plugin.json` ファイルが残されています。Codex は引き続きこれをサポートし、プラグインの識別情報についてはルートのマニフェストを正規のものとして扱います。
どちらのファイルもリリースのバージョンを持ち、テストがそれらをエンジンのバージョンに一致させます。

プラグインはエージェント、フック、MCP サーバーを同梱しません。
Codex はプラグイン向けのカスタムエージェントのコンポーネントを文書化していないため、エンジンは引き続きエージェントを `~/.codex/agents/*.toml` に書き込みます。
プラグインに同梱されたフックは、Codex デスクトップに手動でインストールされたプラグインに限られ、自動的には信頼されないため、エンジンは引き続きフックを `~/.codex/hooks.json` に書き込みます。

マーケットプレイスのエントリーは、Codex が作成者に常に含めるよう求めている `policy` ブロックを設定します。`policy.installation` は `AVAILABLE`、`policy.authentication` は `ON_INSTALL` で、Codex が新しいエントリー向けに文書化しているデフォルトです。

## 検証

```bash
apothem verify --harness codex
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. 管理対象の各ターゲットが存在すること。管理対象のファイルは空ではなく、JSON または YAML の設定は解析できること。`--profile PATH` を追加すると、インストールされたファイルがそのプロファイルと一致することも確認します。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness codex
```

Codex のブートストラップ、変換されたエージェント、スキル、サポートコホートを更新します。

`~/.agents/skills/` 内のスキルフォルダーは、そのフォルダーへのすべての Apothem のインストールが共有する 1 つの形式で書き込まれます。`SKILL.md` のヘッダーキー `version`、`updated`、`archetype`、`portability` は `metadata` マップの下に置かれ、`userInvocable` は `user-invocable` と書かれます。
アップグレード後の最初の更新は、Codex のインストールが以前に書き込んだフォルダーをその形式に書き直し、変更する各フォルダーをバックアップします。
`apothem rollback --harness codex` でそれらを復元できます。

## アンインストール

```bash
apothem uninstall --harness codex
```

`~/.codex/AGENTS.md` から Apothem ブロックを取り除き、その外側にあるテキストはそのまま残します。また、`~/.codex/hooks.json` から Apothem のエントリを取り除き、あなた自身のエントリは残します。
さらに、`~/.codex/hooks/`、`~/.codex/agents/`、`~/.agents/skills/`、`~/.config/apothem/{rules,templates}/` 内にある Apothem のファイルを取り除きます。ただし、他の Apothem のインストールがまだそれらを使っている場合は除きます（アンインストールはそれらを残し、一覧表示します）。これらのフォルダー内の他のファイルはそのまま残ります。
`~/.agents/skills/` から取り除かれたスキルは、これを読み込む他のツールからも消えます（[互換性に関する注意](#互換性に関する注意)を参照）。
`CODEX_HOME` を `~/.codex` 以外のフォルダーに設定し、以前のリリースでインストールした場合、そのリリースがそのフォルダーの隣に書き込んだコピー（`<CODEX_HOME>/../.agents/skills/` と `<CODEX_HOME>/../.config/apothem/`）は取り除かれません。手動で削除してください。
各ファイルは、変更または削除される前に `~/.apothem/backups/` 配下にバックアップされます。
共有プロファイルの YAML と Apothem エンジンには影響しません。

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness codex` を再実行する |
| 検証が失敗した | `apothem update --harness codex` を実行してから、再度検証する |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness codex` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
