**ベンダー：** Alibaba Cloud
**インストール名：** `qwen-code`
**ステータス：** ベータ版
**ネイティブ設定：** `~/.qwen/`

## インストール

```bash
apothem install --harness qwen-code
```

アダプターは Qwen Code の設定を書き込み、`QWEN.md` コンテキストアンカーをインストールし、
Apothem のフックディスパッチャーを登録し、Apothem のコマンドを Qwen の Markdown
コマンドファイルに変換し、スキルを SKILL.md ディレクトリとしてインストールし、ヘルパー定義を
Qwen のサブエージェントとして適合させます。

**書き込まれるファイル：**

```text
~/.qwen/settings.json
~/.qwen/QWEN.md
~/.qwen/commands/
~/.qwen/skills/
~/.qwen/agents/
~/.qwen/.apothem/support/{rules,templates,hooks}/
```

## プロファイルからネイティブ設定へのマッピング

アダプターは、コンテキストとフック向けに文書化された `settings.json` のキーをレンダリングし、
`QWEN.md` を書き込み、Apothem のコマンド、スキル、ヘルパー定義を Qwen Code のネイティブな
検出ディレクトリに組み込みます。ルール、テンプレート、フックのソース素材は、
`~/.qwen/.apothem/support/` 配下のサポート素材として残ります。

## 互換性に関する注意

`~/.qwen/.apothem/support/` は、`QWEN.md` と設定のフックコマンドから参照されるサポート素材で
あり、ベンダー所有の検出名前空間ではありません。
`QWEN.md` 内の Apothem ブロックは Apothem サポートファイルのセクションで終わります。
このセクションは、リポジトリ形式の各参照（`rules/<name>.md`、`templates/...`、`hooks/...`）が
解決される先の、`~/.qwen/.apothem/support/` 配下の絶対ディレクトリを示します。

## 検証

```bash
apothem verify --harness qwen-code
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. 共有プロファイルのすべての必須フィールドが存在すること。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness qwen-code
```

`settings.json`、`QWEN.md`、ネイティブコマンド、スキル、サブエージェント、Apothem
サポートツリーを更新します。

## アンインストール

```bash
apothem uninstall --harness qwen-code
```

アダプターが書き込んだネイティブ設定ファイルを削除します。
共有プロファイルの YAML と Apothem エンジンには影響しません。

## コンフォーミティゲート

```bash
python -m apothem.conformity.gate --all .
```

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness qwen-code` を再実行する |
| 検証が失敗した | `apothem update --harness qwen-code` を実行してから、再度検証する |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness qwen-code` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
