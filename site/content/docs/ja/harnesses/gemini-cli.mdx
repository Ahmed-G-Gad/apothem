**ベンダー：** Google
**インストール名：** `gemini-cli`
**ステータス：** GA
**ネイティブ設定：** プロジェクトローカルの `GEMINI.md` と `.gemini/`

## インストール

```bash
apothem install --harness gemini-cli --project /path/to/project
```

このアダプターはプロジェクトスコープです。プロジェクトの `GEMINI.md` をインストールし、Apothem の
コマンドを Gemini の TOML スラッシュコマンドに変換し、ローカルヘルパー定義を正規化し、ネイティブで
ないサポートコホートを `.gemini/.apothem/support/` 配下に配置します。
他のコーディングツールもプロジェクトの `GEMINI.md` を読み取るため、その中の Apothem ブロックは、
単一のツールを読み手として名指ししない、プロジェクト全体のガイダンスとして書かれます。

**書き込まれるファイル：**

```text
GEMINI.md
.gemini/commands/*.toml
.gemini/agents/*.md
.gemini/skills/
.gemini/.apothem/support/
```

## プロファイルからネイティブ設定へのマッピング

アダプターは Apothem の共有コホートを読み取り、それぞれを Gemini 互換の面を通じて振り分けます。
Markdown のルール、テンプレート、フック素材は、Gemini ネイティブのルールディレクトリではなく
サポート素材であるため、`.gemini/.apothem/support/` 配下に残ります。
`GEMINI.md` 内の Apothem ブロックは、Apothem サポートファイルのセクションで終わります。この
セクションは、リポジトリ形式の各参照（`rules/<name>.md`、`templates/...`、`hooks/...`）が解決
される先の `.gemini/.apothem/support/` 配下のディレクトリを、プロジェクトルートからの相対パスで
示します。パスが相対であるため、コミットされた `GEMINI.md` にはマシン固有のパスが含まれません。

`.gemini/commands/` 内の変換された各コマンドは、`description` と `prompt` を持ちます。プロンプトは
コマンドの命令のみです。ソースファイル先頭の Apothem メタデータ（バージョン、ツールリスト、および
同様のフィールド）は除外されるため、モデルがそれを命令として読むことは決してありません。Gemini が
カスタムコマンドを実行するのは、あなたがそれを入力した場合のみです。

`.gemini/agents/` 内のヘルパー定義は、ツールの制限とターン数の上限を保持します。ソースの `tools`
の付与から `disallowedTools` を差し引いたものが、Gemini のツール名による Gemini の `tools`
許可リストになり、`maxTurns` は `max_turns` になります。そのため、読み取り専用のヘルパーには
`write_file` ツールも `replace` ツールも与えられません。モデルは設定されないため、各ヘルパーは
セッションのモデルを継承します。

## 互換性に関する注意

`~/.gemini/` は、グローバルな Gemini プロファイルを使用するツールのためのユーザースコープの領域の
ままです。Gemini CLI アダプターは、`--project` で渡されたプロジェクトにのみ書き込みます。

## 検証

```bash
apothem verify --harness gemini-cli --project /path/to/project
```

verify コマンドは次のことを確認します。

1. ネイティブ設定が想定されたパスに存在すること。
2. 管理対象の各ターゲットが存在すること。管理対象のファイルは空ではなく、JSON または YAML の設定は解析できること。`--profile PATH` を追加すると、インストールされたファイルがそのプロファイルと一致することも確認します。
3. アダプター固有の検証ルーチンが成功を報告すること。

## 更新

```bash
apothem update --harness gemini-cli --project /path/to/project
```

`GEMINI.md`、変換されたコマンド、ローカルヘルパー定義、インストールされたスキル、および
`.gemini/.apothem/support/` サポートツリーを更新します。

## アンインストール

```bash
apothem uninstall --harness gemini-cli --project /path/to/project
```

アダプターが書き込んだネイティブ設定ファイルを削除します。
共有プロファイルの YAML と Apothem エンジンには影響しません。

## コンフォーミティゲート

```bash
python -m apothem.conformity.gate --all .
```

## トラブルシューティング

| 症状 | 対処 |
|---------|-----|
| 設定ファイルが見つからない | `apothem install --harness gemini-cli --project /path/to/project` を再実行する |
| 検証が失敗した | `apothem update --harness gemini-cli --project /path/to/project` を実行してから、再度検証する |
| 想定外の設定内容 | `~/.config/apothem/profile.yaml` または `--profile PATH` を確認してから、`apothem update --harness gemini-cli --project /path/to/project` を再実行する |

## 設定ノブ

| フラグ | デフォルト | 説明 |
|------|---------|-------------|
| `--dry-run` | `false` | ファイルを書き込まずにインストールをプレビューする。 |
