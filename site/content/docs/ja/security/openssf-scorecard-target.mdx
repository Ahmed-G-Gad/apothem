Apothem は OpenSSF Scorecard の最高スコアを目標としつつ、新しい単独メンテナーのリポジトリから Scorecard が推論できることとできないことについて、公開ファサードを誠実に保ちます。このドキュメントは、各チェック、それを裏付ける証拠面、そして姿勢を最新に保つコントロールを列挙します。

現在のスコアは [Scorecard ビューア](https://securityscorecards.dev/viewer/?uri=github.com/ahmed-g-gad/apothem)で確認できます。バッジは [README のヘッダー](https://github.com/ahmed-g-gad/apothem/blob/main/README.md)にあります。

## チェックごとの証拠マトリクス

| チェック | 証拠面 | 備考 |
|---|---|---|
| **Binary-Artifacts** | [binary-artifacts-sweep.md](/docs/security/binary-artifacts-sweep) | ソースで追跡されている実行可能バイナリはゼロです。生成された配布アーカイブは `dist/` に留まります。 |
| **Branch-Protection** | [branch-protection-ruleset.md](/docs/security/branch-protection-ruleset) | `main` は公開リリースへの昇格の前に保護されます。新しいリリースコミットが着地した後は、強制プッシュと削除がブロックされます。 |
| **CI-Tests** | [`.github/workflows/ci.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/ci.yml) | Pytest マトリクス、ruff、mypy、CodeQL、Trivy、ドキュメントビルド、パッケージングのスモークチェック。 |
| **CII-Best-Practices** | OpenSSF Best Practices への登録 | OpenSSF Best Practices サイトでのメンテナー側の登録が必要です。これはリポジトリのファイルだけでは完了できません。 |
| **Code-Review** | ブランチ保護 + CODEOWNERS | リポジトリ管理者を除くすべての人に対して、`main` にはプルリクエストが必須です。また、プロジェクトのメンテナーが 1 人である間、ブランチ保護が要求する承認レビューは 0 件です（[branch-protection-ruleset.md](/docs/security/branch-protection-ruleset) を参照）。レビュー済みの PR が存在するまで、Scorecard の履歴は限定的なままです。 |
| **Contributors** | [AUTHORS](https://github.com/ahmed-g-gad/apothem/blob/main/AUTHORS) | 新しい単独メンテナーのプロジェクトは、複数組織にわたる貢献履歴を作り出すことはできません。これはコントリビューターが参加するにつれて自然に改善します。 |
| **Dangerous-Workflow** | ワークフロー監査 | `pull_request_target` はありません。Actions は SHA で固定され、明示的な権限でスコープが限定されています。 |
| **Dependency-Update-Tool** | [`renovate.json`](https://github.com/ahmed-g-gad/apothem/blob/main/renovate.json) | Renovate は、グループ化された依存関係 PR を利用可能に保ちつつ、GitHub Actions、Python マニフェスト、ハッシュロックされたリリース要件、npm の面をカバーします。 |
| **Fuzzing** | [`tests/property/`](https://github.com/ahmed-g-gad/apothem/tree/main/tests/property) | Hypothesis のプロパティテストが、パーサーと frontmatter の不変条件を検証します。上流の Scorecard は、Hypothesis をファザー統合として評価しない場合があります。 |
| **License** | [LICENSE](https://github.com/ahmed-g-gad/apothem/blob/main/LICENSE) | リポジトリルートにある MIT ライセンス。 |
| **Maintained** | Git 履歴 | 現在のリリースコミットとアクティブなワークフローの頻度が、メンテナンスされていることを示します。非常に新しいリポジトリは、経過期間に関する警告を受ける場合があります。 |
| **Packaging** | [`.github/workflows/`](https://github.com/ahmed-g-gad/apothem/tree/main/.github/workflows) | sdist、wheel、SBOM、SLSA 来歴、Sigstore 署名を生成するリリース、Pages、npmjs.com のワークフロー。 |
| **Pinned-Dependencies** | ワークフロー監査 + ハッシュロックされた要件 | Actions は SHA で固定されています。リリースツールのインストールは `--require-hashes` を使用します。ワークフロー専用の pip ツールは正確なピンを使用します。 |
| **SAST** | [`.github/workflows/codeql.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/codeql.yml) | Python と Actions を対象とする CodeQL の `security-extended` クエリ。 |
| **Security-Policy** | [SECURITY.md](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md) | 協調的開示ポリシー、サポート対象バージョンマトリクス、対応タイムライン。 |
| **Signed-Releases** | [`.github/workflows/release.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/release.yml) | Sigstore のキーレス署名、SLSA 来歴、SBOM、チェックサム、リリース成果物。 |
| **Token-Permissions** | ワークフロー監査 | ワークフローのデフォルトは読み取り専用の権限です。書き込みスコープはジョブローカルで、デプロイ／パッケージ操作に結び付けられています。 |
| **Vulnerabilities** | [`.github/workflows/pip-audit.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/pip-audit.yml) + [`.github/workflows/dependency-review.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/dependency-review.yml) | 毎週の脆弱性スキャンと、SARIF アップロード付きの CI スキャン。dependency-review ゲートは、脆弱な依存関係や許可されていないライセンスの依存関係を導入するプルリクエストをブロックします。 |

## スコアの解釈

Scorecard は各チェックを 0〜10 のスケールで採点し、総合スコアは加重平均です。リポジトリの履歴、サードパーティへの登録、コントリビューターの多様性に依存するコントロールは、過大に主張するのではなく明示的に追跡されます。ファイルで制御されるチェックのいずれかでドリフトが生じると、即座の是正がトリガーされます。

## 更新の周期

- **プッシュごと:** Scorecard ワークフローは、`main` へのすべてのプッシュで再実行されます。
- **毎週:** 月曜日 02:30 UTC — 上流の採点方法論の変更と、既存の固定済み依存関係に対して新たに開示された脆弱性を捕捉します。
- **リリースごと:** 公開への昇格の前に、メンテナーが現在の Scorecard ビューアの面を検証し、プラットフォームの状態による制約を記録します。
