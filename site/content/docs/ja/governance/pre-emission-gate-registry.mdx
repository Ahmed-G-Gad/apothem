> **十五バーの事前出力ゲートの正規の登録簿。** この文書には、十五バーのゲート表全体と、ゲート結果スキーマの YAML ブロックが含まれます。実質的な表とスキーマはここにあり、`src/apothem/rules/pre-emission-gate.md` によって運用可能にされています。

意味のあるスコープのアーティファクトを出力する前に（`site/content/docs/governance/outward-conformity-registry.mdx` §1 のトリビアル対非トリビアルの閾値に従い）、十五バーの事前出力ゲートを実行してください。可能な箇所では PreToolUse フックで機械化します（`src/apothem/conformity/gate.py` によってオーケストレーションされる `src/apothem/conformity/*-grep.py` の機械的な grep）。機械化が不可能な箇所では、推論によって検討します。**いずれか 1 つのバーが失敗すると出力はブロックされます。すべてのバーが合格するまで修正し、ゲート結果を記録したうえで出力してください。**

| # | バー | 検査種別 | 失敗 → アクション |
| - | --- | ---------- | ---------------- |
| 1 | M1 ホスト非依存 | 推論 | ホストの規約に合わせて修正 |
| 2 | M2 編集的開示 | 推論 | 開示台帳を追加 |
| 3 | M3 十次元 | 混合（機械的 + 推論） | 失敗した次元で修正 |
| 4 | M4 自己適用 | 推論（検証ブロックが存在） | 検証ブロックを記録 |
| 5 | M5 権威 | 機械的（`<USER-CONFIRM:…>` プレースホルダーの grep） | 照会面へ再ルーティング |
| 6 | M6 専門性 | 推論（表面化したギャップの節が存在） | ギャップを表面化させ、引用する |
| 7 | M7 選択肢注釈 | 機械的（選択肢の集合が推奨マーカーを伴う） | 注釈を付ける |
| 8 | M8 確定性 | 機械的（ぼかし語彙の grep） | ぼかし表現を条件文に格上げ |
| 9 | M9 視覚的レバレッジ | 混合（機械的：図の検証日付、推論：構造的な箇所に図が存在） | 図を作成または更新 |
| 10 | M10 双方向バインディング | 機械的（バインディングの相互性の grep） | 半端なエッジを閉じる |
| 11 | M11 アジャイルスプリント | 推論（スプリントの装置がインスタンス化済み） | スプリントとして再構成 |
| 12 | M12 フェーズ報告とレイアウト | 機械的（孤児出力の grep）+ 推論 | 集約を作成し、再配置 |
| 13 | M13 コードクラフト | 機械的（lint / フォーマット / 型チェック；bare-except、マジックナンバー、コメントアウトされたコードの grep） | 修正 |
| 14 | M14 システム性 | 混合（機械的：生成元の来歴；推論：上流、下流、同位、強制者を宣言） | 宣言し、索引化 |
| 15 | M15 本番対応 | 機械的（production-ready-pr の grep）+ 推論 | テスト、ドキュメント、CHANGELOG を追加 |

## 1. ゲート結果スキーマ

各ゲート実行は、成果物の作業トレース（隠しコメント、メタデータブロック、独立した発行ログファイル——ホストの規約が許す形式）に結果を記録します：

```yaml
conformity-attestation:
  artifact: <path-or-identifier>
  ecosystem-version: <git-commit-sha-or-equivalent ratifying the rule set in force>
  bars:
    M1-host-agnosticism:        pass | n/a (with reason)
    M2-editorial-disclosure:    pass | n/a
    M3-ten-dimensions:          pass | n/a
    M4-self-application:        pass
    M5-authority:               pass
    M6-expertise:               pass | n/a
    M7-option-annotation:       pass | n/a (no option set)
    M8-definitiveness:          pass
    M9-visual-leverage:         pass | n/a (subject not structural)
    M10-bidirectional-binding:  pass
    M11-agile-sprints:          pass | n/a (trivial work)
    M12-phase-layout:           pass | n/a
    M13-code-craft:             pass | n/a (not code)
    M14-systemicity:            pass
    M15-production-ready:       pass | n/a (no host-public-surface change)
  surfaced-gaps: []
  unresolved-inquiries: []
  amendments-disclosed: []
  date: <ISO-8601>
```

`n/a` の印は明示的で、根拠を伴うものです。暗黙の省略は決してありません。`ecosystem-version` フィールドは、ゲート結果を、ユーザースコープのエコシステムの再現可能な状態に結びつけます（ゲートの実行時にアクティブだった Apothem ソースツリーの git コミット。たとえば Claude Code アダプターの場合は `~/.claude/` のチェックアウト）。これにより、将来の監査は、同じルール本文に対してゲートを再生できます。
