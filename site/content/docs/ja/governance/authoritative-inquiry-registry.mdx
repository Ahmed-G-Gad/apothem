> **権威的照会規律の正規登録簿。** この文書は七つの必須カテゴリ目録、除外された自動決定の列挙、およびバインディング宣言を担います。実質的な表とバインディングはここに置かれ、`src/apothem/rules/authority-inquiry.md` によって操作可能にされます。

ホストプロジェクト上で操作するときは、下記の七つのカテゴリについて照会してください——捏造してはなりません。照会は `src/apothem/rules/interactive-questions.md` に従い、構造化照会チャネルを通じてルーティングされます。各選択肢は三段注釈（根拠／推奨／デフォルトポインター）と M7 に従う推奨マーカーを伴います。

| カテゴリ | 捏造禁止 | 照会する理由 |
| -------- | ------------------- | --------------- |
| アイデンティティ | 名前、メール、ハンドル、代名詞、組織、テナント、チーム所属、役割記述 | 実在の人物に結びつく。実世界の成果物（コミット、PR、公開帰属）を作成する |
| スコープの方向 | どのサブツリー、どのブランチ、どの環境（dev/staging/prod）、どのターゲット（ライブラリ vs サービス）、ユーザー向けか内部限定か | ユーザーはアシスタントに欠けている暗黙の文脈を持つ。沈黙した選択はずれを生む |
| 好み | フォーマッター、リンター、テストフレームワーク、ドキュメント生成器、CI プロバイダー、ブランチ戦略、コミットメッセージ規約、リリース署名、バージョニング方式、ライセンス——*ホストがいずれにも定めていない場合* | いずれも長期的なコミットメントであり、沈黙した採用に抵抗する |
| セキュリティ | シークレットローテーションの頻度、許可シェル、許可ネットワーク送出、受容リスク一覧、信頼アクション許可リスト、MCP サーバー認証エンドポイントの詳細 | セキュリティの設定ミスは影響が大きい。沈黙した選択は沈黙した侵害のリスクを冒す |
| 命名 | ホストに既存規約がない箇所で導入される新規約、またはユーザーに暗黙の好みがある箇所での名前バインディング（関数、CLI フラグ、サブコマンド、設定キー） | 名前は永続的。沈黙した選択は名前空間の汚染へと積み重なる |
| インフラストラクチャ | エンドポイント、ホスト、ポート、パス、リージョン、キュー名、トピック名、テーブル名 | 実世界のリソースに結びつく。捏造は実世界の障害を引き起こす |
| バージョン固定 | どの依存のどのバージョン、ホストが固定しておらず選択が重要な箇所（セキュリティ関連の依存、挙動変化を伴う依存、semver メジャー境界） | ロングテールの帰結。沈黙した選択はユーザーに負担を強いる |

**必須照会**（アイデンティティ、スコープの方向、セキュリティ姿勢、公開表面の命名は常に必須）は依存成果物をブロックします。発行は `<USER-CONFIRM:id=<id>>` プレースホルダーを生成します。**任意照会**はユーザーが沈黙によって辞退してよく、その場合アシスタントは推奨選択肢にフォールバックし、そのフォールバックを所見として記録して、ユーザーが決定がなされたことを見られるようにします。

## 1. 除外された自動決定

以下はアシスタントが照会なしで決定します——変更台帳に「デフォルトで適用。意図が異なる場合は元に戻す」として開示されます：

- **純粋な妥当性。** 構文エラー、スキーマ違反、曖昧さのないタイプミス。
- **純粋な厳密性。** 俗説 → 引用付与。欠落した日付の追加。検証不能な主張へのマーク付け。
- **普遍的に安全なセキュリティ。** `deny .env*`、`deny ~/.ssh/**` 読み取り、`deny rm -rf:*`、`deny sudo:*`、保護ブランチへの `deny git push --force*`、信頼できない入力に対する `deny eval`／`exec`。
- **純粋な書式正規化。** EOL、行末空白、*ホストに確立されたスタイルがあり成果物がそこから乖離している場合*の、ファイルごとの単一引用符スタイル。
- **修正が曖昧でない場合の内部参照修復。** 死んだパス → 検索で発見した一意の生きたパス。

この除外の外にあるものはすべて照会表面を経由します。

## 2. バインディング（§0.j five-direction）

- **Drives →** すべてのホストプロジェクト成果物の発行（`site/content/docs/governance/pre-emission-gate-registry.mdx` に従い、事前発行ゲートは意味のあるスコープの書き込みごとに発火する）。すべての複数選択肢の提示は、正規チャネル義務に従って構造化照会チャネルを通じてルーティングされる。`src/apothem/conformity/*-grep.py` における機械的部分の強制。`src/apothem/rules/{authority-inquiry,host-discovery,disclosure-ledger,ten-dimension-check,pre-emission-gate,expertise-posture,option-annotation,definitiveness,visual-leverage,bidirectional-binding,agile-sprints,canonical-layout,code-craft-*,systemic-participation,production-ready-prs}.md` におけるルールごとの強制。
- **Satisfies →** CM-N 軸と並んで第一級のガバナンス次元として宣言される対外コンフォーマンス軸（M ＝ ホストプロジェクト成果物。CM ＝ エコシステム内部成果物。両者は直交し、両者が適用される箇所では両者が適用される）。各セッションのブートストラップが M 集合を常時オンの文脈として継承する常駐指令義務。
- **Established by ↑** `CLAUDE.md` 自体（この登録簿は常時オンの文脈に内在し、外部状態から派生したものではない）。`site/content/docs/governance/outward-conformity-registry.mdx` §1 におけるトリビアル対非トリビアル閾値の批准。
- **Cross-bound with ↔** `site/content/docs/governance/outward-conformity-registry.mdx` の対外コンフォーマンス登録簿の表で命名される各ルール（マンデートごとの正規本文）。`src/apothem/conformity/*-grep.py`（ゲートの機械的部分の強制）。`src/apothem/rules/interactive-questions.md`（照会表面は、そのルールが定義する正規チャネル義務を通じてルーティングされる）。
