このチュートリアルは、Apothem の最初のセットアップを最初から最後まで案内します。
何もインストールされていない状態から始め、実際のハーネス構成 — あなたが書いたプロファイルから生成され、検証され、動作が確認されたもの — で終わります。
所要時間は約 15 分を見込んでください。
以下のすべてのコマンドは実在し、コピー＆ペーストでそのまま実行できます。

<Callout title="セットアップ済みですか？">
  4 つの中核コマンドの簡潔なリファレンスだけが必要な場合は、[コアワークフロー](/docs/usage/getting-started)を参照してください。
  このページは、ゼロから初回実行までのガイド付きツアーです。
</Callout>

終わるころには、次のことが完了しています。

1. スクリプトインストーラーからの Apothem のインストール。
2. すべてのハーネスを駆動する共有プロファイルの編集。
3. ハーネスのネイティブ設定のマテリアライズ。
4. その設定の検証と、動作する初回実行の確認。

全体を通して、例のハーネスとして **Claude Code** を使います。インストーラーのデフォルトだからです。
同じ手順は、サポートされているどのハーネスにも当てはまります — [ハーネス一覧](/docs/harnesses)にたどり着いたら名前を差し替えてください。

## 最初に必要なもの

- Unix ライクなシェル（macOS、Linux、または WSL）。Windows は PowerShell インストーラーが対応します。
  このチュートリアルでは `bash` の経路を示します。
- `PATH` 上にある Python 3.10 以降。`python3 --version` で確認してください。
- エンジンがあなたのインタープリターからインポートする 2 つのランタイムライブラリ、`click` と `rich`。
  スタックの残り（`pyyaml`、`jsonschema`）はツリーにベンダリングされているため、インポート可能である必要があるのはこの 2 つだけです。
  インストーラーはこれらの有無をチェックし、欠けているものの名前を示し、欠けているものをあなたの代わりにインストールすることを提案します — そのため、確認して続行できます。

Apothem は公開パッケージではなく、バンドルされたソースツリーとして出荷されます — `pip install` のステップはありません。
インストーラーはツリーをクローンし、そこから直接エンジンを実行します。

## ステップ 1 — Apothem をインストールする

ネットワークインストーラーを実行します。

```bash
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

インストーラーは次の手順を実行します。

1. **前提条件のチェック。** インストーラーは実際の Python 3.10+ インタープリターを見つけ、2 つのランタイムライブラリ（`click` と `rich`）がインポート可能であることを確認します。
   いずれかが欠けている場合は、その名前を示し、あなたの代わりにインストールすることを提案します — または、確認なしでインストールするには `APOTHEM_AUTO_INSTALL_DEPS=1` を設定します。
2. **ソースの配置。** バンドルされたツリーが `~/.apothem` にクローンされます（`APOTHEM_HOME` 環境変数で上書きできます）。
   再実行すると、既存のクローンを複製するのではなく、それを fast-forward します。
3. **プロファイルのブートストラップ。** まだプロファイルがない場合、インストーラーはサンプルプロファイルを `~/.config/apothem/profile.yaml` にコピーし、続行する前に**停止して、それを編集するよう求めます**。
   これは意図的です — サンプルはプレースホルダーの識別情報を使用しており、ハーネス設定が書き込まれる前にそれを自分のものにすべきだからです。
   これはステップ 2 で行います。

環境変数でインストールを制御できます。
最もよく使う可能性が高いものは次のとおりです。

```bash
# Install a different harness as the default, and point at a project profile.
APOTHEM_HARNESS=cursor \
APOTHEM_PROFILE="$HOME/.config/apothem/profile.yaml" \
  curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

認識されるその他の変数は、`APOTHEM_REPO` と `APOTHEM_REF`（どのリモートをクローンし、どの git ref をチェックアウトするか — 未設定の場合は最新の署名付きリリースタグを解決して検証します。固定するにはタグを、移動するブランチには `main` を設定します）、`APOTHEM_ALLOW_UNVERIFIED=1`（タグ署名検証の失敗を警告に格下げします）、`APOTHEM_SOURCE`（クローンする代わりに既存のローカルチェックアウトを使用します）、そして `APOTHEM_SKIP_VERIFY=1`（インストール後の検証をスキップします。この検証は実行したいので、未設定のままにしてください）です。

インストーラーは完全な実行を終えると、エンジンの呼び出し方を示すバナーを出力します。
インストーラーは `apothem` の shim を `PATH` 上に配置する（POSIX: `$HOME/.local/bin`、Windows: `%LOCALAPPDATA%\Microsoft\WindowsApps`）ため、そのディレクトリが `PATH` に入っていれば、エンジンを直接実行できます。

```bash
apothem <command>
```

shim を配置できなかった場合 — またはそのディレクトリがまだ `PATH` 上にない場合 — バナーは shim を必要としない自己完結型のフォールバックを出力します。

```bash
PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>
```

このチュートリアルの残りでは `apothem <command>` と書きます。フォールバック形式を使っている場合は、インストーラーのバナーが出力した正確なプレフィックスを前に付けてください。

## ステップ 2 — プロファイルを自分のものにする

`~/.config/apothem/profile.yaml` にある共有プロファイルが、唯一の信頼できる情報源です。
すべてのハーネスアダプターがこれを読み取り、そこからそのハーネスのネイティブ設定を導出します。
一度編集すれば、インストールするすべてのハーネスが一貫した状態を保ちます。

エンジンのエディター、または任意のテキストエディターで開きます。

```bash
apothem profile edit
```

最小限の有効なプロファイルは次のようになります。

```yaml
identity:
  name: "Example User"
preferences:
  style: "concise"
rules:
  - "Validate external input before writing files."
```

プレースホルダーの `name` をあなた自身の名前に置き換え、すべてのハーネスに適用させたいルールを追加します。
例の値は架空のままにしてください — プロファイルは共有しても安全であることを意図しています。

エンジンがあなたの編集を問題なく読み戻せることを確認します。

```bash
apothem profile show --json
```

YAML の形式が不正な場合は、ここでそれが分かります — 先に進む前に修正して再実行してください。

## ステップ 3 — ハーネス構成をマテリアライズする

ステップ 1 の実行が完全なパスを完了した場合 — つまり、すでにプロファイルがあったためにインストーラーがブートストラップで停止しなかった場合 — インストーラーはデフォルトのハーネスをマテリアライズ済みです。
初回の実行では、代わりにプロファイルのブートストラップで停止しているため、いま `install` を実行して、編集したばかりのプロファイルからハーネスをマテリアライズしてください（これは 2 つ目のハーネスも追加します）。

```bash
apothem install --harness claude-code
```

これはあなたのプロファイルを読み取り、Claude Code のネイティブ設定を書き込みます。
対象にできるすべてのハーネスを確認するには、次を実行します。

```bash
apothem harnesses list
```

一部のハーネスはユーザースコープではなくプロジェクトスコープであり、それらにはアダプターが書き込み先を判断できるように `--project` パスが必要です。

```bash
apothem install --harness cursor --project .
```

## ステップ 4 — 検証して初回実行を確認する

マテリアライズは話の半分にすぎません。
次に、構成が正しく配置されたことを確認します。

```bash
apothem verify --harness claude-code
```

`verify` は、ハーネスに期待される設定ファイルが存在し、プロファイルの宣言内容と一致していることをチェックします。
クリーンな実行は、マテリアライズが成功したことを意味します。

登録済みのすべてのアダプターを対象とする、マシン全体のヘルスチェックを行うには、次を実行します。

```bash
apothem doctor
```

`doctor` はインストール済みのすべてのハーネスをチェックし（各ハーネスは検証に合格しなければならず、その登録済みのフックコマンドは起動しなければなりません）、いずれかのチェックが失敗した場合は非ゼロで終了します。
インストールしていないハーネスは一覧に表示されますが、それによって失敗にはならないため、セットアップスクリプトでの有用なゲートになります。

**初回実行。** 設定したばかりのハーネス — この例では Claude Code — を開き、任意のプロジェクトでセッションを開始します。
プロファイルに書いたルールと設定は、いまやそのツールの振る舞いの一部です。
これが動作する初回実行です。ステップ 2 で編集したプロファイルが、実際のセッションを形作っています。

## 作ったもの

空のマシンから始めて、Apothem をインストールし、共有プロファイルを作成し、そこからハーネスのネイティブ設定をマテリアライズし、結果を検証し、それが動作することを確認しました。
プロファイルは永続するアーティファクトです — 一度変更し、`apothem update --harness <name>` を再実行すれば、その変更を任意のハーネスへ送り出せます。

## 次に進む先

- **別のツールを追加する。** [ハーネス一覧](/docs/harnesses)は、サポートされているすべてのプラットフォームとそのアダプター名を扱っています。
  新しい `--harness` でステップ 3 を繰り返してください。
- **1 つのタスクをより深く掘り下げる。** [ハウツーガイド](/docs/how-to)は、ルールの記述、プランの作成、コンフォーミティゲートの実行のための、タスクに焦点を当てたレシピです。
- **具体的な内容を調べる。** [リファレンス](/docs/harnesses)は、各アダプター、プロファイルスキーマ、CLI の面を余すところなく文書化しています。
- **セッションより長く続く作業を計画する。** [再開可能なプランニング](/docs/concepts/resumable-planning)では、Apothem が長時間に及ぶ作業をプロジェクトローカルの `.apothem/plans/` スイートへ外部化し、どのマシン上の新しいセッションでもその作業をその場で再開できるようにする方法を説明します。

## 推奨される次のステップ

さらにハーネスを追加する作業に進む前に、**`apothem doctor` を実行**してセットアップを確認してください — このコマンドは登録済みのすべてのアダプターの状態を報告するため、インストールしたばかりのハーネスは正常と表示され、残りは未インストールと表示されます。
