メンテナー向けの運用手順です。
各ランブックは、順序立てられた、文脈に依存しない手順です。既知の開始状態を検証済みの終了状態へと進め、有能なコントリビューターが事前の文脈なしに従えるように書かれています。

## ページ

| ページ | 説明 |
|------|-------------|
| [Pages 有効化](/docs/runbooks/pages-enablement) | `apothem.ahmedgad.com` を、新規の GitHub Pages 設定から、`200 OK` を返す HTTPS のランディングページまで進めます。 |
| [リリースサイクル](/docs/runbooks/release-cycle) | `vX.Y.Z` リリースを、クリーンな作業ツリーから、検証済みの GitHub Release と npm の面まで進めます。 |
| [パブリッシャーアカウントのセットアップ](/docs/runbooks/publisher-account-setup) | `@ahmed-g-gad/apothem` 向けの npmjs.com 信頼済みパブリッシャーと、GitHub 側のリリース前提条件を構成します。 |
| [リリースの復旧](/docs/runbooks/release-recovery) | リリースのカットオーバーシーケンスが途中で失敗したときに、`ahmed-g-gad/apothem` を動作する状態へ復元します。 |
| [新しいハーネスアダプターの作成](/docs/runbooks/new-harness-adapter-authoring) | ファーストパーティへの組み込みに向けて、新しいハーネスアダプターを作成して公開します。 |
| [デプロイチェックリスト](/docs/runbooks/deployment-checklist) | Apothem エコシステムをデプロイまたは共有する前に、事前検証チェックリストを実行します。 |
| [単独メンテナーのマージ儀式](/docs/runbooks/solo-maintainer-merge) | メンテナーが自分のプルリクエストを直接マージできる場合と、承認を要求し管理者にもそれを強制する保護のもとでの自己マージ儀式。 |
| [マシン間同期チェックリスト](/docs/runbooks/cross-machine-sync-checklist) | 完全な移植性チェックを行い、Claude Code アダプターが新しいホストで正しくインストール、検証、アンインストールされることを確認します。 |
