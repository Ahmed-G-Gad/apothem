`apothem` CLI は、共有プロファイルとハーネスアダプターを管理するための主要な
オペレーターインターフェースです。

## グローバルフラグ

| フラグ | 説明 |
|------|-------------|
| `--version` | Apothem のバージョンを出力して終了します |
| `--help` | コマンドのヘルプを出力します |

## サブコマンド

### `apothem install`

共有プロファイルからハーネスアダプターをインストールします。

```bash
apothem install --harness <name|all> [--profile PATH] [--project PATH] [--dry-run] [--clean|--fresh] [--yes]
```

| オプション | 説明 |
|--------|-------------|
| `--harness <name>` | ハーネスアダプター名（下記の正規の値を参照）。必須です。 |
| `--profile PATH` | 共有プロファイル YAML へのパス。デフォルトは `~/.config/apothem/profile.yaml` です。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。 |
| `--dry-run` | ファイルを書き込まずにインストールをプレビューします。 |
| `--clean`, `--fresh` | オプトインのクリーンスレート: インストールの前に、以前のインストール状態（`~/.claude`、`~/.codex`、`~/.agents`、`~/.config/apothem`）をバックアップして削除します。 |
| `--yes` | クリーンスレートの削除中に、ターゲットごとの確認をスキップします（非対話的な `--clean` の実行では必須）。 |

正規の `--harness` の値:

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

レジストリ全体の集合を選択するには `--harness all --project <path>` を使用します。
プロファイルの `exclude_harnesses` リストは、インストール/更新のバッチ選択時に
尊重されます。

### `apothem update`

現在の共有プロファイルから、ハーネスアダプターのネイティブ設定を再導出します。

```bash
apothem update --harness <name|all> [--profile PATH] [--project PATH] [--dry-run]
```

| オプション | 説明 |
|--------|-------------|
| `--harness <name>` | ハーネスアダプター名。必須です。 |
| `--profile PATH` | 共有プロファイル YAML へのパス。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。 |
| `--dry-run` | ファイルを書き込まずに更新をプレビューします。 |

`update` はハーネスの出力を再マテリアライズします。Apothem CLI パッケージは
更新しません。パッケージのアップグレードには、Apothem をインストールした
パッケージマネージャーを使用してください。

### `apothem uninstall`

ハーネスアダプターのネイティブ設定を削除します。

```bash
apothem uninstall --harness <name|all> [--project PATH] [--yes]
```

| オプション | 説明 |
|--------|-------------|
| `--harness <name>` | ハーネスアダプター名。必須です。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。 |
| `--yes` | 確認プロンプトをスキップします。 |

### `apothem verify`

ハーネスアダプターの管理対象ターゲットが存在し、有効であることを検証します。

```bash
apothem verify --harness <name|all> [--profile PATH] [--project PATH]
```

| オプション | 説明 |
|--------|-------------|
| `--harness <name>` | ハーネスアダプター名、または `all`。必須です。 |
| `--profile PATH` | 忠実性の照合対象とする共有プロファイル YAML。指定しない場合、チェックは純粋に構造的なものになります。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。 |

`--profile` を指定しない場合、チェックは構造的です。すべての管理対象ターゲットが
存在し、有効でなければなりません。`--profile` を指定すると忠実性も求められるため、
存在はしていてもそのプロファイルからドリフトしたインストールは verify に失敗します。
特定のプロファイルが忠実にインストールされていることを確認するには、これを使用してください。

終了コードは、ハーネスが検証された場合（`--profile` を指定した場合は、さらにそのプロファイルに
忠実である場合）は `0`、ターゲットが欠落しているか無効な場合、または `--profile` が指定されて
インストールがドリフトしている場合は `1` です。

### `apothem status`

登録済みのすべてのハーネスについて、インストール、検証、ドリフトの状態を報告します。

```bash
apothem status [--profile PATH] [--project PATH]
```

| オプション | 説明 |
|--------|-------------|
| `--profile PATH` | ドリフトのベースラインとして使用する共有プロファイル。デフォルトのプロファイルを読み取れない場合は、スイープを中断するのではなく、ドリフトを `unknown` に格下げします。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。指定しない場合、それらのハーネスは `needs-project` を報告します。 |

各行は `installed` フラグと `verified` フラグを組み合わせており、この 2 つを合わせたものが
ドリフト状態になります。

| 状態 | 意味 |
|-------|---------|
| `absent` | Apothem はこのハーネスにインストールしていません。 |
| `in-sync` | インストール済みで、プロファイルのベースラインと一致しています。 |
| `drift` | インストール済みですが、もはや一致していません — `apothem update` で修復します。 |
| `unknown` | インストール済みですが、ベースラインのプロファイルを読み取れませんでした。 |

`installed` が答えるのは「Apothem はここにインストールしたか？」であり、「このハーネスは
マシン上に存在するか？」ではありません。判定は Apothem 自身のアーティファクト — 命令アンカー内の
管理ブロックと、Apothem 所有の `.apothem/` サブツリー配下のコンテンツ — に基づいて行われ、
ハーネスが自身のために書き込むベンダー所有のファイルに基づくことは決してありません。
設定ディレクトリは存在するものの Apothem が一度も触れていないハーネスは `absent` を報告し、
アンインストールされたハーネスは、空になったディレクトリが残っていても `absent` を報告します。

### `apothem profile`

共有 Apothem プロファイルを管理します。

```bash
apothem profile show [--profile PATH]
apothem profile init [--profile PATH] [--force]
apothem profile set <key> <value> [--profile PATH]
apothem profile edit [--profile PATH]
```

| サブコマンド | 説明 |
|------------|-------------|
| `profile init` | スキーマに準拠した最小限のプロファイルのひな型を作成します。 |
| `profile show` | 解決済みのプロファイルを JSON として stdout に出力します。`--json` を指定すると、ドキュメントの先頭は `schema_version` になります。 |
| `profile set <key> <value>` | プロファイルのフィールドを設定します。値はリテラル文字列として保存されます。裸の単語は型変換されないため、`no` は `"no"` のまま、`1.0` は文字列のままです。ただし、`true`/`false` と、明示的な `[...]` / `{...}` のリストおよびマップ入力は例外です。組み立てられたプロファイルは、書き込まれる前にスキーマ検証されます。 |
| `profile edit` | `$EDITOR` でプロファイルを開きます（プラットフォームの既定値にフォールバックします）。 |

`--profile PATH` オプションは、各サブコマンドを別のプロファイルファイルに向けます。
デフォルトは `~/.config/apothem/profile.yaml` です。

### `apothem harnesses`

登録済みのハーネスアダプターを一覧表示し、検査します。

```bash
apothem harnesses list
apothem harnesses show <name>
```

| サブコマンド | 説明 |
|------------|-------------|
| `harnesses list` | 登録済みのすべてのアダプターを、インストール状態フラグと出力パスとともに表として出力します。 |
| `harnesses show <name>` | 1 つのアダプターの名前、インストール状態、出力パスを出力します。 |

### `apothem doctor`

Apothem インストールのシステム診断を実行します。

```bash
apothem doctor
```

Apothem のバージョン、Python インタープリター、プラットフォーム、解決済みのプロファイルパス、およびハーネスごとのインストール状態の表を出力します。いずれかのチェックが失敗すると、終了コードは `1` になります。失敗の原因となるのは、無効なプロファイル、検証に通らないインストール済みのハーネス、起動できない登録済みのフックコマンド、読み込みも確認もできないアダプター、読み取れない台帳のいずれかです。インストールされていないハーネスは報告されますが、失敗にはなりません。情報提供の注記は、終了コードを変えません。
