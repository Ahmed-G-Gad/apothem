> **すべてのアーティファクトクラスにおける YAML フロントマターの正規リファレンス。** [`CLAUDE.md`](https://github.com/ahmed-g-gad/apothem/blob/main/CLAUDE.md) の規約（Conventions）にある要約は、インラインの宣言です。[`schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/schemas) にあるクラスごとの JSON Schema（`additionalProperties` が未知のキーを拒否します）は機械可読な契約であり、食い違いがある場合は常にこちらが優先されます。このページは必須キーの索引であり、[`artifact-schema.mdx`](/docs/reference/artifact-schema) はクラスごとのテンプレートと実例を扱います — どちらも、それらのスキーマを人間が読める形にした投影です。

---

## 1. フロントマターブロックの形

すべてのアーティファクトは、先頭に `---` 行で区切られた YAML フロントマターを持ちます。[`site/content/docs/reference/authorship-header.mdx`](/docs/reference/authorship-header) に従う正規の著作者ヘッダーバナーは、Markdown 系のファイルではフロントマターの上に置かれ、フロントマターはその直後に続きます。

コマンドのキーは `kebab-case` を使います。スキルのキーは、ソースコーパスが使う camelCase の表記である `userInvocable` を除き、`kebab-case` を使います（Claude Code のインストールでは `user-invocable` に名前が変わります）。ルールと委譲ワーカーのキーは、セクション 2 の必須キー表に示されるとおり camelCase です。スカラー値は、引用符なしか、ダブルクォートで囲むかのどちらかです。コロン、ハッシュ記号、その他 YAML で意味を持つ文字を含む文字列値は、引用符で囲みます。

## 2. クラスごとの必須フィールド

必須キーのセットは、アーティファクトクラスによって異なります。権威ある形は、`scripts/dev/validate_ecosystem.py` と、`schemas/` ディレクトリ配下のクラスごとの JSON Schema（アーティファクトクラスごとに 1 つのスキーマファイル）によって強制されます。

```text
schemas/agent.schema.json
schemas/skill.schema.json
schemas/command.schema.json
schemas/output-style.schema.json
schemas/plan.schema.json
```

| クラス | 必須キー |
|-------|---------------|
| `CLAUDE.md`（ルート設定） | `name`、`version`、`updated`、`description`、`scope`、`portability` |
| ルール（`src/apothem/rules/*.md`） | `name`、`description`、`pathFilter`、`alwaysApply` |
| コマンド（`src/apothem/commands/*.md`） | `name`、`version`、`updated`、`description`、`argument-hint`、`disable-model-invocation`、`portability`、`allowed-tools` |
| 委任ワーカー（正規のディレクトリは下記に示す） | `name`、`version`、`updated`、`description`、`tools`、`disallowedTools`、`maxTurns`、`effort` |
| スキル（`src/apothem/skills/*/SKILL.md`） | `name`、`version`、`updated`、`description`、`archetype`、`userInvocable`、`disable-model-invocation`、`allowed-tools`。Claude Code のインストールとプラグインでは `userInvocable` が `user-invocable` に名前変更され、スキーマは 2 つの綴りのうち正確に 1 つを受け付ける |
| 出力スタイル（`src/apothem/output-styles/*.md`） | `name`、`description`。出荷されるすべてのスタイルは `keep-coding-instructions: true` も設定しており、Claude Code がソフトウェアエンジニアリングの指示を保持するようにしている |

[`schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/schemas) にあるクラスごとのスキーマは、型、形式、enum、パターンの制約、および長さの制限を含む、制約の完全なセットを備えています: スキルまたはコマンドの `description` は最大 1,024 文字で、これは [Agent Skills](https://agentskills.io/specification) の上限です。

## 3. バリデーター

`scripts/dev/validate_ecosystem.py` はアーティファクトツリーを走査し、上記の必須キーのセットを適用して、必須フィールドが欠けているアーティファクトがあれば `[FAIL]` を報告します。`src/apothem/conformity/frontmatter_grep.py` にある書き込みごとの `frontmatter-grep` は、PreToolUse の Write/Edit フックの境界で同じ形を強制します。
