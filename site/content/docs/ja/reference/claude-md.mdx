`CLAUDE.md` は常に読み込まれるエコシステム構成です。ホストの
ハーネスのランタイムがすべてのやり取りでこれを読み込むため、
その内容は他のすべてのアーティファクトが拡張する*ベースラインコンテキスト*です。

## セクション

| セクション | 目的 |
|---------|---------|
| §1 計画スイート | マスター計画スイートテンプレートと 8 つの `/plan-<stage>` コマンドを命名 |
| §2 認知アイデンティティとソフトウェアアーキテクチャ | シニアソフトウェアアーキテクトの役割と創造的姿勢を宣言 |
| §3 アーティファクトディレクトリ | クラスごとのオンディスクルート（ルール、コマンド、スキル、委任ワーカーなど） |
| §4 重大度スケール式ガバナンス | 4 階層のスケーリングレンズ（EXPLORING / PERSONAL_USE / SHARED / PUBLIC_LAUNCH） |
| §5 操作ディレクティブ | 問題解決、戦略的発見、コミュニケーションのフレームワーク |
| §6 横断的強制要件 | CM-N レジストリ（CM-1 から CM-28 まで） |
| §7 レジストリ | コマンド、ルール、委任ワーカー、フック、スキル、進化、空クラスのサブレジストリ |

## 強制要件識別子の規約

3 つの接頭辞は異なる意味を持ちます：

- **CM-N** — 構成強制要件。ルールコホートに定義されます。
- **TM-N** — テンプレート強制要件。
  `src/apothem/skills/plan-suite/master-template.md` §4 に定義されます。
- **CP-N** — コア原則。同じテンプレートの §6 に定義されます。

計画スイートテンプレートは規範的な TM/CP レジストリです。`/plan`
パイプラインの各ステージは、そのファイルを通じて相互参照を解決します。
