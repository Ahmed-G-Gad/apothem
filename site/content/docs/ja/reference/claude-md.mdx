`CLAUDE.md` は、常に読み込まれるプロジェクト設定です。ホストのハーネスはすべての対話でこれを読み込むため、その内容は、他のすべてのアーティファクトが拡張する*ベースラインのコンテキスト*になります。`AGENTS.md`（正規のエージェント向けの命令面）および `.github/copilot-instructions.md` と整合を保ち、それらは同じ規律を写したものです。

## 含まれる内容

プロジェクトの `CLAUDE.md` は、散文のセクションとして書かれています。AI-surface の正典、plan → harden → ship の運用ループ、プロジェクトの目的とソースレイアウト、plans／リリース／ファイルヘッダーの規律、曖昧さの扱い、そしてコーディングとハーネスアダプターの規約を含みます。ここでは *プロジェクトが何であるか* と *そこでどう作業するか* を述べ、ガバナンスのマンデートそのものは再掲しません。それらはルールコホートに置かれ、ルールファイルとしてランタイムに公開されています。

| ガバナンスの面 | 配置場所 |
|---|---|
| 横断的なマンデート（CM-N） | `src/apothem/rules/operational-mandates.md` と、マンデートごとのルールファイル |
| 15 の本番向けのマンデート（M-N） | マンデートごとのルールファイル（`definitiveness.md`、`pre-emission-gate.md`、`production-ready-prs.md`、…） |
| 認知のアイデンティティとアーキテクチャの姿勢 | `src/apothem/rules/cognitive-identity.md` |
| シリアスネスに応じたガバナンス | 各ルール自身の *Seriousness Scaling* セクション |
| `/plan` パイプライン | `/plan-*` コマンドと `src/apothem/skills/plan-suite/` |
| アーティファクトのディレクトリ | ソースレイアウト（`rules/`、`commands/`、`skills/`、`agents/`、`hooks/`） |

## マンデートの識別子の規約

三つの接頭辞には、それぞれ異なる意味があります:

- **CM-N** — 設定マンデート（config mandate）。ルールコホートで定義されます
  （`src/apothem/rules/operational-mandates.md` と、マンデートごとのルールファイル）。
- **TM-N** — テンプレートマンデート（template mandate）。
  `src/apothem/skills/plan-suite/master-template.md` の §4 で定義されます。
- **CP-N** — 中核原則（core principle）。同じテンプレートの §6 で定義されます。

プランスイートのテンプレートが TM／CP の正規のレジストリであり、`/plan` パイプラインの各ステージは、このファイルを通じて相互参照を解決します。
