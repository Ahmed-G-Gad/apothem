ハーネスレジストリは、CLI、ドキュメント、フィクスチャテスト、規約ピンの検証が使用する、
信頼できる情報源としてのアダプターインベントリです。ランタイムのソースは
`src/apothem/lib/harness_registry.py` であり、以下のすべての行は、そのレジストリ、
アダプターごとの `capabilities.yml`、そして各アダプターの
`STANDARD-CONVENTION-PIN.md` まで追跡できます。

## ペイロードコホートのサポート

ステータス値は `native`、`converted`、`support-tree`、
`profile-projected`、`unsupported`、`not-applicable`、
`discovery-pending` です。

`converted` のコホートはハーネス独自のフォーマットに書き換えられ、ソースのフィールドの一部は
そこに収まる場所がありません。変換されるコマンド、エージェント、ルールの各コホートについて、
アダプターの `capabilities.yml` は、ソースの各 frontmatter フィールドがどうなるかを示す
`conversion_losses` マップを持ちます。

| 値 | 意味 |
| --- | --- |
| `native:<field>` | ハーネスはそのフィールドの下でそれを読み取ります。 |
| `sidecar:<path>` | 変換後のファイルの隣にある別のファイルに書き込まれます。たとえば Codex の `agents/openai.yaml` です。 |
| `filename` | ファイル名またはフォルダー名がそれを担います。 |
| `inlined` | プロンプトまたは本文のテキストに移されます。 |
| `ignored` | ファイルには残りますが、ハーネスはそれを読み取りません。 |
| `dropped` | 除外されます。 |

テストが変換後のすべてのファイルをレンダリングし、マップを出力と照合します。

| ハーネス | ネイティブまたは変換済みのペイロード | サポートツリーのペイロード | 未サポートまたは保留中の警告 |

## 共有ルート

一部のインストールターゲットは、それを書き込むハーネス以外のハーネスによって読み込まれます。
レジストリは、そのような各パスを `SHARED_ROOTS` に記録します。記録には、1 つのオーナー
（そのパスを書き込む唯一のアダプター）と、ベンダーのドキュメントがデフォルトでそれを
読み込むとしているリーダー、さらにそれを示すベンダーのページと、それらを取得した日付が
含まれます。オーナーをインストールすると Apothem のコンテンツがすべてのリーダーの前に
置かれ、オーナーをアンインストールするとすべてのリーダーからそれが取り除かれます。

| パス | オーナー | リーダー |
| --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor、Gemini CLI、GitHub Copilot、Kimi Code、Open-Claw、OpenCode、Windsurf、Zed |
| `~/.claude/skills/` | Claude Code | Cursor、OpenCode |
| `~/.claude/CLAUDE.md` | Claude Code | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | Antigravity、CodeBuddy、Codex、Cursor、GitHub Copilot、Hermes、Kiro、OpenCode、Windsurf、Zed |
| `<project>/GEMINI.md` | Gemini CLI | Antigravity、GitHub Copilot、Zed |
| `~/.gemini/GEMINI.md` | Antigravity | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | Zed |

オーナーが共有の命令ファイルに書き込む Apothem ブロックは、特定の 1 つのツールをリーダーとして
名指ししません。`tests/unit/test_shared_roots.py` は、2 つのアダプターが同じレジストリ
ターゲットを書き込んでいる場合、およびツール横断の命令ファイル（`AGENTS.md`、`CLAUDE.md`、
`GEMINI.md`、`copilot-instructions.md`）のような名前を持つレジストリターゲットに宣言された
オーナーがない場合に失敗します。唯一の例外は `~/.codex/AGENTS.md` で、これを読み込むと
文書化している登録済みのハーネスは他にありません。

## 検証フック

レジストリは、次のチェックによって同期が保たれます。

| チェック | 目的 |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | 各アダプターが、経過日数が 90 日以内の規約ピンを持ち、そのピンが少なくとも 1 つのベンダー URL を引用し、期限切れのディスカバリーターゲットを持たないことを確認します。CI は、すべてのプルリクエストで、毎週、そしてリリースの前にこれを実行します。 |
| `python scripts/dev/check_vendor_urls.py` | ピンとハーネステンプレートが引用するすべてのベンダー URL を取得し、移動したページやリンク切れのページがあれば失敗します。これには、もはや名前解決できないホスト名や、検証に失敗する証明書も含まれます。タイムアウト、拒否またはリセットされた接続、5xx サーバーエラーは到達不能として報告され、失敗にはなりません。週次の規約モニターがこれを実行します。 |
| `python -m apothem.conformity.gate --all .` | ドキュメントと実装のコンフォーミティチェックを実行します。 |
| `python -m pytest` | レジストリのフィクスチャテストとアダプターの契約テストを実行します。 |
