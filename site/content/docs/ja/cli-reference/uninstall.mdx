ハーネスアダプターの設定を削除します。

## 構文

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

アダプターが管理するハーネスのターゲットを削除し、続いて、インストールが作成した
ディレクトリを、空になった時点で削除します（あなたのものが何か入っている
ディレクトリは残ります）。

共有の作業ディレクトリのメモリ、コンテキスト、学習ストアは、このハーネスがそのディレクトリに
インストールされた最後のハーネスである場合にのみ、バックアップしたうえで削除
されます。アンインストールは、インストール時に記録された場所でそれらを削除する
ため、インストールがそれらを書き込んだ場所に関係なく見つけられます（`workspace`
プロファイルのフィールドを参照）。`plans/` ディレクトリは決して削除されません。

`--yes` が指定されない限り、確認を求めます。プロンプトを表示できない場合 —
`--format json`（プロンプトのテキストが単一の JSON ドキュメントを壊してしまうため）
または非対話型のシェル（TTY なし）— の場合、`--yes` が指定されない限り、
コマンドは処理を始める前に、構造化された `uninstall.confirmation_required`
エラー（終了コード 1）で拒否します。選択したハーネスがインストールされていない
場合、コマンドは成功し（終了コード 0）、通常の出力では
`NAME is not installed; nothing to remove.` と表示します（`NAME` はハーネス ID です）。

インストールルートの `.apothem/` 配下にある共有データストア（`memory/`、`contexts/`、`learning/`）は、同じルートにある別のインストール済みハーネスがそれらをまだ使用している間は残ります。
削除するハーネスがそのルートで最後の 1 つである場合、コマンドは各ストアをまず Apothem のバックアップルート（`~/.apothem/backups/`）へコピーし、その後、中身ごとストアを削除します。
あなたが `plans/` に保管しているものは、決して削除されません。

## ホームディレクトリ内の共有フォルダー

複数のインストールが、ホームディレクトリ内の 1 つのフォルダーを使用することがあります。スキルフォルダー（`~/.agents/skills/`、または `~/.codebuddy/skills/`、`~/.kiro/skills/`、`~/.trae/skills/`）と、`~/.config/apothem/rules/` および `~/.config/apothem/templates/` です。
どのアダプターがどれに書き込むかは、[install](/docs/cli-reference/install#ホームディレクトリ内のフォルダー) のページに記載されています。
Apothem は各フォルダーをどのインストールが使用しているかを記録しており、アンインストールは 1 つのルールに従います。そのフォルダーをまだ使用している他の Apothem インストールがない場合にのみ、フォルダーを削除します。

- 1 つのツールをアンインストールしても、別のインストールがまだスキルを使用している間はスキルが残り、その旨が表示されます。
  2 つのプロジェクトにインストールされた 1 つのツールは 2 つのインストールとして数えられるため、プロジェクト A からそれをアンインストールしても、プロジェクト B がまだ使用している間はフォルダーが残ります。最後のアンインストールがそれらを削除します（以下の 2 つ目の例を参照）。
- 削除されるのは、そのインストール自身の記録に列挙されているものだけです。
  フォルダーが管理されるようになる前に行われたインストールにはそのような記録がないため、それをアンインストールしてもホーム内の何も削除されません。
  あなたがフォルダーに追加したファイルは残り、Apothem のスキルの名前を持ち、Apothem が書き込んだものではないフォルダーも残ります。
- プロジェクトフォルダーがもはや存在しないインストールは無視されるため、削除されたプロジェクトがフォルダーをいつまでも保持し続けることはありません。注記はその名前を挙げます。
- フォルダーを使用し得るインストールの記録が読み取れない場合、アンインストールは何も削除する前にエラーとともに停止し、そのインストールは記録されたまま残ります。
  読み取れない記録を修復または移動してから、コマンドを再度実行してください。これらのフォルダーに一度も書き込まないツールの破損した記録は無視されます。
- 最後の使用がなくなると、空になったフォルダーも削除されます。
  各フォルダーは、削除される前に `~/.apothem/backups/` の下にバックアップされます。

各アンインストールは、フォルダーごとに 1 つの `Note:` を出力します。たとえば `Note: <harness> -
~/.agents/skills/ was kept: still used by <harness> (/path/to/project)`、または `was removed: no other Apothem install uses it` です。
`--format json` のエンベロープでは、各注記は `"outcome": "advisory"`、`"operation": "shared_root"`、および `retained` または `released` に設定された `"role"` を持つ `warnings` エントリです。
これは `path`、`holders`（フォルダーを保持しているインストール）、`stale`（無視されたインストール）、および `kept` と `total`（保持された記録済みエントリと、インストールが列挙したエントリ）を含みます。

見つけられないインストールのためにフォルダーが残っている場合、注記はその名前を挙げます。
プロジェクトフォルダーが削除されていた場合、そのインストールは無視され、フォルダーは次のアンインストールで削除されます。
プロジェクトは存在するものの、そのルールファイルから Apothem ブロックを手作業で削除した場合、`uninstall` はそのハーネスをインストールされていないと報告し、その使用の登録を解除しません。解除するには、そのハーネスとプロジェクトに対して `install` を実行してから `uninstall` を実行してください。
`apothem verify` は、フォルダーがまだ完全であるかどうかを表示します。

`--harness all` による削除は意図的に網羅的です。登録済みのすべてのハーネスを対象とし、
インストール時にプロファイルの `exclude_harnesses` がスキップするハーネスも含みます。
クリーンアップは、以前のより広範なインストールが残した可能性のある状態にまで及びます。
一度もインストールされていないハーネスにも、同じ通知が表示されます。

進行形のエイリアス `apothem uninstalling`（`apothem Uninstalling` としても受け付けられます）は、同じハンドラーに解決されます。

## オプション

| オプション | 説明 |
|---|---|
| `--harness NAME` | 削除するハーネスアダプター、またはレジストリ全体の集合を表す `all`（必須）。 |
| `--yes` | 確認プロンプトをスキップします。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。 |
| `--quiet`, `-q` | 情報出力を抑制します。エラーのみが出力されます。 |
| `--verbose`, `-v` | 他のコマンドとの一貫性のために受け付けられます。このコマンドは追加の出力を表示しません。 |
| `--format plain\|json` | 出力形式（デフォルト: `plain`）。 |
| `--json` | `--format json` の短縮形です。 |
| `--no-color` | 出力中の ANSI カラーコードを無効にします。 |
| `-h`, `--help` | ヘルプを表示して終了します。 |

## JSON 出力

アダプターがインストールされていて、正常に削除された場合:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

アダプターがインストールされていなかった場合、コマンドは `0` で終了します。JSON 出力では、エンベロープに `"status": "success"` と `"action": "uninstalled"` が含まれ、結果の行には `"outcome": "skipped"` と、メッセージ `"not installed; no files
removed"` が含まれます。`status` フィールドが `"not_installed"` になることはありません。

## 例

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

共有スキルフォルダーは、それを使用する最後のインストールがなくなるまで残ります。

```bash
apothem install --harness codex
apothem install --harness cursor --project A
apothem uninstall --harness codex --yes                  # keeps ~/.agents/skills/, the cursor install uses it
apothem uninstall --harness cursor --project A --yes     # removes it: no install uses it now
```

## 終了コード

| コード | 意味 |
|---|---|
| 0 | アダプターがアンインストールされた、またはインストールされていなかった |
| 1 | ハーネスが見つからない、確認が拒否されたか利用できない（`--yes` なしの非対話モードまたは JSON モード）、またはすべての削除が失敗した |
| 2 | 部分的な削除 — 失敗の前に少なくとも 1 つのハーネスが削除された |
| 64 | 使用法エラー: 不明なオプションまたはコマンド、あるいは欠落した、または無効なオプション値。`--json` の下では、エラーはコード `cli.usage` を持つ JSON エンベロープになります。 |
