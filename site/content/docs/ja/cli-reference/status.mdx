登録済みのすべてのハーネスについて、インストール、検証、ドリフトの状態を報告します。

## 構文

```
apothem status [--profile PATH] [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status` は読み取り専用の検査コマンドです。
登録済みのすべてのハーネスアダプターを順に走査し、ハーネスごとに 3 つの事実を報告します。インストールされているかどうか、管理対象のターゲットが検証に合格するかどうか、そしてインストールされた設定が共有プロファイルからドリフトしているかどうかです。
ディスクには何も書き込みません。

各ハーネスについて、`status` は次を報告します。

| 列 | 意味 |
|---|---|
| `installed` | アダプターの管理対象の設定が、そのターゲットパスに存在する。 |
| `verified` | アダプターの管理対象のターゲットが存在し、有効である。 |
| `drift` | プロファイル忠実度の判定（下記参照）。 |

`drift` の値は次のいずれかです。

| 値 | 意味 |
|---|---|
| `in-sync` | インストールされた設定が、新たに投影された共有プロファイルをそのまま含んでいる。 |
| `drift` | ハーネスはインストールされているが、投影されたプロファイルの内容が現在の共有プロファイルと一致しなくなっている。再投影するには `apothem install` を再実行する。 |
| `absent` | ハーネスがインストールされていないため、比較するものがない。 |
| `needs-project` | プロジェクトスコープのハーネスが `--project` なしで報告されたため、そのターゲットを解決できない。検査するには `--project PATH` を渡す。 |
| `unknown` | デフォルトのプロファイルを読み込めなかったため、インストール済みのハーネスに比較の基準がない。ドリフトの判定を取り戻すには、プロファイルを修正する。 |

ドリフトは報告されるものであり、エラーとして扱われることは決してありません。1 つ以上のハーネスが `drift` を報告しても、`status` は 0 で終了します。
ドリフトはあなたのセットアップに関する事実であり、コマンドの失敗ではありません。

デフォルトの共有プロファイルを読み込めない場合、走査を中止するのではなく、インストール済みのハーネスについてドリフトが `unknown` に格下げされます（installed/verified の事実は引き続き報告されます）。
明示的に指定した `--profile` を読み込めない場合はユーザーエラーであり、その場合は代わりに構造化されたエラーで中止します。

この格下げは常に報告されます。`status` はプロファイルと修正方法を示す注意喚起を出力し、`--json` のエンベロープは `warnings` に、対応する `drift_baseline_unavailable` エントリを含みます。
これが最も重要になるのは、ハーネスが 1 つもインストールされていない場合です。その場合、すべての行が `absent` となり、`unknown` のセルは存在しないため、基準が一度も読み込まれなかったことを示すシグナルはこの注意喚起だけになります。

## オプション

| オプション | 説明 |
|---|---|
| `--profile PATH` | ドリフトの基準を選択する共有プロファイル YAML。指定しない場合は、デフォルトのプロファイル（`~/.config/apothem/profile.yaml`）が使用されます。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。指定しない場合、プロジェクトスコープのハーネスは `needs-project` を報告します。 |
| `--quiet`, `-q` | 情報出力を抑制し、エラーのみを出力します。 |
| `--verbose`, `-v` | 追加の診断出力を出力します。 |
| `--format plain\|json` | 出力形式（デフォルト: `plain`）。 |
| `--json` | `--format json` の短縮形です。 |
| `--no-color` | 出力中の ANSI カラーコードを無効にします。 |
| `-h`, `--help` | ヘルプを表示して終了します。 |

## JSON 出力

`--json` のエンベロープは、登録済みのハーネスごとに 1 行の結果を含みます。
各行は、文書化されたキー `harness`、`installed`、`verified`、`drift` を含みます。
問題のない走査では `warnings` は空です。デフォルトのプロファイルを読み込めなかった場合は、`path`、`code`、`reason`、`fix` を持つ `drift_baseline_unavailable` エントリを 1 つ含みます。

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

アダプターごとの障害分離: 単一のアダプターが自身の状態を報告する際に例外を送出した場合、そのハーネスの行は `outcome: "error"` と `message` を含み、残りのハーネスは引き続き通常どおり報告し、プロセスはコード 2 で終了します。

## 例

```bash
apothem status
apothem status --project .
apothem status --json
```

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 状態を報告した（ドリフトは報告されるものであり、エラーではない） |
| 1 | 予期される検証エラー（無効な `--profile`、または存在しない `--project` パス） |
| 2 | 少なくとも 1 つのアダプターが自身の状態を報告できなかった |
| 64 | 使用法エラー: 不明なオプションまたはコマンド、あるいは欠落した、または無効なオプション値。`--json` の下では、エラーはコード `cli.usage` を持つ JSON エンベロープになります。 |
