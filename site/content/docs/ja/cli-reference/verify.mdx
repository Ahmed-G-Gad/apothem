ハーネスアダプターのインストールを検証します。

## 構文

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

選択された各アダプターの `verify()` 実装を呼び出します。
選択されたすべてのアダプターが、管理対象ターゲットが存在し有効であると報告した場合にのみ、0 で終了します。
`--profile` がない場合、チェックは<strong>構造的</strong>です —— すべての管理対象ターゲットが存在し、有効でなければなりません。
`--profile` がある場合、チェックはさらに<strong>プロファイルへの忠実性</strong>を要求するため、存在してはいるもののドリフトしたインストールは verify に失敗します。これにより、単に「存在するか？」ではなく、「まさにこのプロファイルが忠実にインストールされているか？」に答えます。
改行コードは考慮されないため、CRLF または CR の改行コードで保存されたファイルも合格します。
いずれの場合も、Apothem が管理ブロックを保持するファイルは、完全なブロックを開始しない BEGIN マーカー（たとえば END マーカーが失われたもの。[トラブルシューティング](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker)を参照）、
Apothem のマーカーの間にある 2 つ以上の完全なブロック（[ファイルが Apothem のマーカーの間に 2 つのブロックを持つ](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers)を参照）、
または完全なブロックがなく、Apothem があなたのテキストと区別できないマーカーのペア（たとえば、そのブロックがあなたのコードブロックの中にある場合。[Apothem が自身のブロックをあなたのテキストと区別できない](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)を参照）を保持している間、verify に失敗します。
更新はそのようなマーカーを保持するか、そのようなファイルをそのまま残すため、`apothem update` を実行しても失敗は解消されません。
チェックされるファイルは、ハーネスのインストールがブロックを書き込むファイルと、最後に完了したアンインストール以降のインストールレコードが列挙するファイルです。インストールがもう使用していない OpenClaw ワークスペースのルールファイルも含まれます。
プロジェクトのメモファイルのような、あなた自身のファイル内のマーカーでは失敗しません。
インストールレコードがない場合、`CLAUDE.md` とプロファイルドキュメントはチェックされません。インストールがそれらを書き込んだことを示すのはレコードだけだからです。
OpenClaw の verify は、見つけたワークスペースのルールファイルが完全なブロックを保持していないか、ブロックを開始しない BEGIN マーカーを保持している場合、ファイル名を示さずに引き続き失敗します。
失敗した行はそのような各ファイルを示し、修正すべき内容を示します。
迷い込んだマーカーの行については、その行と、Apothem のブロックを開始する行を除くほかのすべての BEGIN マーカー行（コード内で引用している BEGIN マーカーも含む）を変更する番号付きの手順をファイルごとに示します（注記は、代わりに END マーカーを戻さないようにも案内します。インストールまたは更新が Apothem のブロックをそれとは別に書き込んだ時点で、Apothem のブロックが 2 つ残ってしまうためです）。完全なブロックについては、各ブロックをその行で示します。
Apothem があなたのテキストと区別できないマーカーのペアについては、各ペアの行、その内容と修正方法を示し、あわせてマーカーのペアを開始しない各 BEGIN マーカーも示します。
OpenClaw のルールファイルは、OpenClaw のファイルごとの上限に収まる間だけ更新が書き込むため、注記は、ファイルがその時点で上限に収まれば次回の更新が Apothem のブロックを書き込むこと、そしてあなたが残している古い Apothem のテキストもその上限に数えられることを示します
（[Open-Claw](/docs/harnesses/open-claw#rules-in-each-workspace)を参照）。
plain モードでは行の後に `Note:` 行が続き、その行からは期待されるパスが省かれます。JSON の行には `files` と `message` を持つ `stray_begin` オブジェクトが加わります。

スキルをホームディレクトリに書き込むアダプターについては、verify は、期待されるすべてのスキルフォルダーが `SKILL.md` とともに存在することも、どのインストールがそれを書き込んだかにかかわらずチェックします。そのため、フォルダーを共有するツールのうち 1 つだけがインストールされているマシンでも検証に合格します。
フォルダーが欠落している場合、および Apothem のスキルの名前を持つフォルダーが Apothem が書き込んだものではない何かに属している場合に失敗します。
失敗した行はそのどちらであるかを示します。plain モードではその後に `Note:` 行が続き、JSON の行では `user_level` オブジェクトが `missing`、`unlisted`、`unproven` のパス、および `message` を列挙します。
欠落したフォルダーを復元するには [`install`](/docs/cli-reference/install) を実行してください。外部のフォルダーはリネームまたは移動してから、[`update`](/docs/cli-reference/update) を実行してください。
`unproven` のフォルダーとは、Apothem が書き込んだことを証明できないフォルダーです。
それを列挙したインストールが、消えたフォルダー、Apothem のファイルを保持していないフォルダー、または読み取れないフォルダーにあるか、もうそれを列挙していません。
そして、それらが記録したファイルをそのとおりに保持していません（[`install`](/docs/cli-reference/install) を参照）。
あなたがそれを作成または編集したか、以前のリリースがそのファイルを記録せずに書き込んだものです。
注記はそれぞれを示し、インストールの警告にある 2 つの進め方を示します。
保持するには、そのままにしておいてください。
Apothem のバージョンを使うには、それをスキルフォルダーの外へ移動してから、そのハーネスに対して `update` を実行してください。プロジェクトスコープのハーネスの場合、注記は `--project` を、doctor と同じようにシェル向けに引用して、または言葉で示します。
このリリースが書き込む内容をすでに保持しているフォルダーは、インストールがそれを保持するため、示されることはありません。
verify は、インストールされているハーネスについてのみ unproven および unlisted のフォルダーを探すため、`verify --harness all` はインストールされているハーネスの下でのみそれらを示します。

検証されたかどうかにかかわらず、行の後に注記が続くことがあります。
Apothem が書き込んだ内容は配置されているものの、あなたのファイルがツールにそれを読み込ませない場合、`Note:` 行がそのファイルを示し、JSON エンベロープの `warnings` に `"operation": "instruction_override"` を持つエントリーが加わります（[`install`](/docs/cli-reference/install) で説明しています）。
そのようなファイルの 1 つは、[サポートされているあるツール](/docs/harnesses/codex#compatibility-notes)がホームフォルダーから読み込む `AGENTS.md` の横にある、テキストを持つ `AGENTS.override.md` です。
ほかには、[OpenCode 1](/docs/harnesses/opencode#compatibility-notes) が設定フォルダーから読み込むファイルがあります。独自の `instructions` リストを持つ `opencode.jsonc`、および OpenCode 1 がまったく読み込めない `config.json`、`opencode.json`、`opencode.jsonc` です。
この注記はチェックを失敗させません。
Apothem のブロックがその `AGENTS.md` にない場合、または `opencode.json` がインストールの書き込んだエントリーを列挙していない場合、注記はありません。OpenCode 1 が読み込めない `opencode.json` に対する注記は、インストールが書き込むプロファイルドキュメントが Apothem のブロックを保持していることだけを必要とします。

`--harness all` のスイープは、プロファイルの `exclude_harnesses` —— `install`/`update` のバッチが適用したのと同じ除外 —— に従うため、verify が意図的に除外されたハーネスを欠落として報告することは決してありません。
除外は、`--profile` が指定されている場合はそこから、そうでない場合はデフォルトのプロファイルから取得されます。デフォルトが読み取れないか存在しない場合は、レジストリ全体にフォールバックします。

## オプション

| オプション | 説明 |
|---|---|
| `--harness NAME` | 検証するハーネスアダプター、またはレジストリ全体のセットを表す `all`（必須）。 |
| `--profile PATH` | 忠実性をチェックする基準となる共有プロファイル YAML。これがない場合、チェックは純粋に構造的なものになります。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。 |
| `--quiet`, `-q` | 情報出力を抑制します。エラーのみが出力されます。 |
| `--verbose`, `-v` | 追加の診断出力を出力します。 |
| `--format plain\|json` | 出力形式（デフォルト: `plain`）。 |
| `--json` | `--format json` の短縮形。 |
| `--no-color` | 出力中の ANSI カラーコードを無効にします。 |
| `-h`, `--help` | ヘルプを表示して終了します。 |

## JSON 出力

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

選択されたハーネスのいずれかが欠落しているか無効な場合、`status` は `error` になり、失敗した結果の行は `verified: false` を持ち、プロセスはコード 1 で終了します。

## 例

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## 終了コード

| コード | 意味 |
|---|---|
| 0 | ハーネスが検証された — すべての管理対象ターゲットが存在し、有効である |
| 1 | ハーネスが検証されなかった — 管理対象ターゲットが欠落しているか無効である |
| 64 | 使用法エラー: 不明なオプションまたはコマンド、あるいは欠落した、または無効なオプション値。`--json` のもとでは、エラーはコード `cli.usage` を持つ JSON エンベロープになります。 |
