ハーネスを、記録されているインストールの前の状態に復元します。

## 構文

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` は、選択した各ハーネスを、記録されたインストール実行の前の状態に戻します。対象は、デフォルトではまだ有効な最新のインストール、または `--install-id` で指定したインストール実行です。
そのため、2 回目の `rollback` は、1 回目が取り消したインストールの 1 つ前のインストールを取り消します。
ロールバックまたはアンインストールによってすでに取り消されたインストールを指す `--install-id` は、`rollback.already_reversed`（終了コード 1）で拒否され、何も変更されません。
そのインストールの台帳レコードを新しい変更から順にたどりながら、次の処理を行います。

- インストールが上書きしたすべてのファイルとディレクトリを、そのインストールが取得したバックアップから、記録されているパスに復元します（インストールが置き換えたディレクトリは、インストールがそこに追加したファイルを含まない状態で、正確に復元されます）。
- インストールが作成したすべてのファイルとディレクトリを、そのインストールが書き込んだ内容をまだ保持している限り削除します。その後あなたがそのパスに作成したファイルや、あなたが編集したファイルは `Warning:` 行（`--json` の下では `warnings` エントリ）とともに残され、それを含むフォルダーも同様です。
  インストールが作成したフォルダー内にある空のフォルダーは、あなたが作成したものも含めて削除されます。
  その行は、復元が失敗したかどうかにかかわらず、残された各ファイル（残されたフォルダー内のファイルを含む）を列挙し、`warnings` エントリはそれらを `files` として列挙します。
  以前のリリースが記録したインストールは何を書き込んだかを示さず、ロールバックはこのリリースとの比較を行わないため、それが作成したものは残ります。そのような各パスには、ロールバックがそれを Apothem のものと判断できないことを示す `Warning:` 行が付きます。
  また、インストールが一掃したレガシーレイアウトのパスがあれば元に戻します。
  現在のリリースがもう一掃しないパス（あなた自身のファイルを含む可能性があるフォルダー）は、ファイルが欠けている箇所だけが復元されます。現在そこにあるすべてのファイルは保持され、出力は使用したバックアップの名前を挙げます。
  書き込めないファイルは手作業でコピーするよう列挙され、ほかのファイルを 1 つでも書き込んだ場合、ロールバックは 2（部分的）で終了します。
  現在リンク（シンボリックリンクまたは Windows のジャンクション）になっているパスや、バックアップにはフォルダーがあるのにファイルになっているパス（またはその逆）を介して書き込まれることは決してありません。
  そこには何も復元されず、パスのバックアップが失われている場合も何も復元されません。
  ロールバックは依然として 0 で終了し、手作業でコピーする元のバックアップの名前を挙げる `Warning:` 行（`--json` の下では `warnings` エントリ）を出力します。
  ロールバックがそのインストールに到達できるのは、そのレコードが保持される最新 10 件（後述）に含まれている間だけです。
  `apothem backups prune --keep N` は 1 回だけ `N` 件まで刈り込み、次のインストール、更新、アンインストール、またはロールバックで再び 10 件まで刈り込まれます。
  バックアップセット自体はレコードがなくなった後も残るため、そこから手作業でファイルをコピーすることが確実な戻し方です。
- インストールが作成した共有データストア（`memory`、`contexts`、`learning`）を、他のインストール済みハーネスがまだ使用している場合を除いて削除します。
- インストールが作成したディレクトリを、空になった時点で削除します。

他のインストールも使用する、ホームディレクトリ内のファイルまたはフォルダー（スキルフォルダー、または `~/.config/apothem/`）は、共有データストアと同様に扱われます。
ロールバックは、別のインストールがまだそれを列挙している間はそれを残し、それを使用する最後のインストールに対してのみ復元または削除します。
このインストールがすでに存在する状態で見つけたフォルダー（最初のツールの後にインストールされた 2 つ目のツール）は、その後それを手放したインストールが作成したものである場合、それを使用する最後のインストールとともに削除されます。そのため、フォルダーを作成したツールがその間に再インストールまたは更新されていても、すべてのツールをロールバックすると何も残りません。
Apothem が削除し、あなたが自分で（たとえばバックアップから）戻したフォルダーはあなたのものであり、ロールバックはそれを残します。
ロールバックが取り消すのは、ロールバック実行時と同じ表記のホームで記録されたインストールだけです。
同じツールが別の表記のホーム（ホームへのリンクを介したもの、または Windows や macOS での大文字・小文字の違い）でもインストールされていた場合、そのインストールは引き続き共有フォルダーを使用し、それらを保持します。
ツール自身のフォルダー内のファイルは 1 つずつ扱われます。それらを最初に書き込んだインストールをロールバックすると、もう一方のインストールがそのまま残したもの（フックスクリプトなど）は削除され、もう一方のインストールが書き直したもの（命令ファイルなど）は警告とともに残されます。
その後、もう一方の表記のホームで `apothem update` を実行し、そのインストールが再び `apothem verify` に合格するようにしてください。
その表記のホームで実行したロールバックは、そのインストールも取り消します。
フォルダーを使用し得るインストールの記録が読み取れない場合、ロールバックは何かを変更する前にエラーとともに停止し、`rollback` レコードを書き込みません。記録を修復して、再度実行してください。

リンクがツールのフォルダーをホームディレクトリの外へ導く場合も、ロールバックは何かを変更する前に停止し、`rollback` レコードを書き込みません。たとえば、ホームディレクトリ内の表記で指定された `CODEX_HOME` や `XDG_CONFIG_HOME`（`~/work/tool` など）で、インストール後に `~/work` が別のドライブへのリンクになった場合です。
Windows では、ジャンクションもリンクとして扱われます。
エラーは `rollback
refused: target path crosses a link` となり、リンクとそのリンク先のフォルダーの名前を挙げ、コマンドは確認を求めずに 1 で終了します。
リンクがホームディレクトリ内のフォルダーを指すようにするか、リンクをフォルダー自体に置き換えて、ロールバックを再度実行してください。
ホームディレクトリの外のパスとして指定したフォルダーは辿られます。

ロールバックが削除または置き換えるものはすべて、まず Apothem のバックアップルート（`~/.apothem/backups/`）にコピーされるため、ロールバック自体を手作業で取り消すことができます。
その後、ロールバックはハーネスの台帳に `rollback` レコードを追記します。
古いインストールをロールバックすると、その古いインストールが記録した対象のみが復元または削除され、同じルートでそれより後のすべてのインストールは、台帳の有効なインストールから外されます。
後のインストールがそれらの対象の外に追加したファイルは、そのまま残ります。

台帳は、インストールルートごとに最新 10 件のインストールレコードを（それらが参照するバックアップとともに）保持します。
それより古いインストールは、もはや id ではロールバックできず、`rollback.no_record` を報告します。
[`apothem backups prune`](/docs/cli-reference/backups) は、必要に応じてこの上限を引き下げますが、最新のインストールの復元元となるバックアップは決して削除しません。

インストールが作成したファイルを示さない以前のリリースのインストールレコードは、上書きされたファイルのみを復元することでロールバックされます。

`--yes` が指定されない限り、確認はハーネスごとに求められます。
プロンプトを表示できない場合 — `--format json`（プロンプトのテキストが単一の JSON ドキュメントを壊してしまうため）または非対話型のシェル（TTY なし）— は、`--yes` が指定されない限り、コマンドは処理を始める前に、構造化された `rollback.confirmation_required` エラー（終了コード 1）で拒否します。
`--install-id` と `--last` はインストール実行を選択するもので、相互に排他的です。

`--harness all` のロールバックは、意図的に網羅的です。登録済みのすべてのハーネスを対象とし、プロファイルの `exclude_harnesses` がインストール時にスキップするハーネスも含みます —— インストール前の状態を復元することはクリーンアップ操作であるため、以前のより広範なインストールが残した可能性のあるレコードにも及びます。記録されたインストールがないハーネスは、`results` 内の `"outcome": "error"` の行として失敗し（JSON 出力を参照）、実行は残りのハーネスで続行されます。その後、コマンドは、何もロールバックされなかった場合は終了コード 1 で終了し、少なくとも 1 つのターゲットがロールバックされ、かつ失敗も記録された場合は終了コード 2（部分的な結果）で終了します。

## オプション

| オプション | 説明 |
|---|---|
| `--harness NAME` | ロールバックするハーネスアダプター、またはレジストリ全体の集合を表す `all`（必須）。 |
| `--install-id ULID` | 指定したインストール実行を、それがまだ有効であればロールバックします。デフォルトは、まだ有効な最新のインストールです。 |
| `--last` | まだ有効な最新のインストールをロールバックします（デフォルトの動作を明示する形式）。`--install-id` とは相互に排他的です。 |
| `--yes` | ハーネスごとの確認プロンプトをスキップします。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。選択した集合にプロジェクトスコープのアダプターが含まれる場合は必須です。 |
| `--quiet`, `-q` | 情報出力を抑制し、エラーのみを出力します。 |
| `--verbose`, `-v` | 追加の診断出力を出力します。 |
| `--format plain\|json` | 出力形式（デフォルト: `plain`）。 |
| `--json` | `--format json` の短縮形です。 |
| `--no-color` | 出力中の ANSI カラーコードを無効にします。 |
| `-h`, `--help` | ヘルプを表示して終了します。 |

## JSON 出力

この例は、名前を指定した単一のハーネスのエンベロープです。`--harness all` の場合、`harness` は `all`、`output_path` は `null` となり、`results` には選択されたすべてのハーネスの行が含まれます。

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

復元または削除された各ターゲットは、`"operation": "rollback"` と、`created` または `updated` の `outcome` を伴って `results` に現れます（`files_written` にも現れます）。`message` は、そのパスが復元されたのか削除されたのかを示します。
復元に失敗したもの（たとえば、バックアップが削除されていた場合）は `"outcome": "error"` になります。
変更を記録しなかったインストールは、`"outcome": "skipped"` として報告されます。
何も復元されなかった一掃済みのパス（現在リンクになっている、バックアップにはフォルダーがある場所にファイルがある、またはその逆、あるいはそのバックアップが失われている）は、`results` 内の `skipped` の行であると同時に `warnings` 内のエントリでもあり、ロールバックは依然として 0 で終了します。

```json
{
  "harness": "claude-code",
  "outcome": "advisory",
  "operation": "rollback",
  "path": "C:\\Users\\Example\\.claude\\commands",
  "message": "left in place: C:\\Users\\Example\\.claude\\commands is now a link, so nothing was restored there; copy what you need from C:\\Users\\Example\\.apothem\\backups\\20261001T000000Z\\claude_code\\.claude\\commands"
}
```

リンクで拒否された結果は、[`apothem install`](/docs/cli-reference/install#json-output) と同様に、`detail.symlink` にリンクを、`detail.leads_to` にリンク先のフォルダーを示します。

名前を指定した単一のハーネスに一致するインストールレコードが存在しない場合、コマンドは `"status": "error"` とともに `rollback.no_record` エラーを報告し、すでにロールバックまたはアンインストールされたインストールの `--install-id` は `rollback.already_reversed` を報告します。
台帳がそのレコードを刈り込んだ後は（前述）、そのような id は代わりに `rollback.no_record` を報告します。
`--harness all` の場合は、一致するレコードがないハーネスは、代わりに `results` 内の `"outcome": "error"` の行になります。

## 例

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常にロールバックした、またはロールバックするものがなかった（インストールが変更を記録していなかった）。一掃済みのパスが `Warning:` 行（`--json` の下では `warnings` エントリ）とともにそのまま残された場合も含む |
| 1 | 予期されるエラー — インストールレコードがない、セレクターの競合、不明なハーネス、プロジェクトルートの欠落、または確認が拒否されたか利用できない（`--yes` なしの非対話モードまたは JSON モード） |
| 2 | 部分的な結果 — 少なくとも 1 つのターゲットがロールバックされ、同時に失敗も記録された（復元の失敗、または `--harness all` の場合はインストールレコードのないハーネス） |
| 64 | 使用法エラー: 不明なオプションまたはコマンド、あるいは欠落した、または無効なオプション値。`--json` の下では、エラーはコード `cli.usage` を持つ JSON エンベロープになります。 |
