ハーネスを、記録されたインストールの前の状態に復元します。

## 構文

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` は、選択した各ハーネスを、記録されたインストール実行（デフォルトでは最新のもの、または `--install-id` で指定したもの）の前の状態に戻します。
そのインストールの台帳レコードを新しい変更から順にたどりながら、次の処理を行います。

- インストールが上書きしたすべてのファイルとディレクトリを、そのインストールが取得したバックアップから、記録されたパスに復元します（インストールが置き換えたディレクトリは、インストールがそこに追加したファイルを含まない形で、正確に復元されます）。
- インストールが作成したすべてのファイルとディレクトリを削除し、インストールが一掃したレガシーレイアウトのパスがあれば元に戻します。
- インストールが作成した共有データストア（`memory`、`contexts`、`learning`）を、他のインストール済みハーネスがまだそれらを使用していない限り削除します。
- インストールが作成したディレクトリを、空になった時点で削除します。

ロールバックが削除または置き換えるものはすべて、まず Apothem のバックアップルート（`~/.apothem/backups/`）にコピーされるため、ロールバック自体を手作業で取り消すことができます。その後、ハーネスの台帳に `rollback` レコードを追記します。古いインストールをロールバックすると、そのインストールが記録した対象だけが復元または削除され、同じルートでそれ以降に行われたすべてのインストールは、有効な記録から外れます。後のインストールがそれらの対象の外に追加したファイルは、そのまま残ります。

台帳は、インストールルートごとに最新 10 件のインストールレコードを（それらが参照するバックアップとともに）保持します。それより古いインストールは、もはや id でロールバックできず、`rollback.no_record` を報告します。
[`apothem backups prune`](/docs/cli-reference/backups) は、必要に応じてこの上限を引き下げますが、最新のインストールの復元元となるバックアップは決して削除しません。

この動作が追加される前の Apothem リリースが書き込んだレコードには、インストールが作成したファイルが記載されていません。そのようなレコードをロールバックすると、上書きされたファイルのみが復元されます。

`--yes` が指定されない限り、ハーネスごとに確認を求めます。
プロンプトを表示できない場合、すなわち `--format json` の場合（プロンプトのテキストが単一の JSON ドキュメントを壊してしまうため）や非対話型のシェル（TTY なし）の場合は、`--yes` が指定されない限り、コマンドは処理を始める前に、構造化された `rollback.confirmation_required` エラー（終了コード 1）で拒否します。
`--install-id` と `--last` はインストール実行を選択するもので、相互に排他的です。

`--harness all` のロールバックは、意図的に網羅的です。プロファイルの `exclude_harnesses` がインストール時にスキップするものも含め、登録済みのすべてのハーネスを対象とします。インストール前の状態の復元はクリーンアップ操作であるため、以前のより広範なインストールが残した可能性のあるレコードにも及びます。
記録されたインストールがないハーネスは、ハーネスごとに「ロールバックするものがない」と報告します。

## オプション

| オプション | 説明 |
|---|---|
| `--harness NAME` | ロールバックするハーネスアダプター、またはレジストリ全体の集合を表す `all`（必須）。 |
| `--install-id ULID` | 指定したインストール実行をロールバックします。デフォルトは、最後に記録されたインストールです。 |
| `--last` | 最後に記録されたインストールをロールバックします（デフォルトの動作を明示する形式）。`--install-id` とは相互に排他的です。 |
| `--yes` | ハーネスごとの確認プロンプトをスキップします。 |
| `--project PATH` | プロジェクトスコープのハーネス向けのプロジェクトルート。選択した集合にプロジェクトスコープのアダプターが含まれる場合は必須です。 |
| `--quiet`, `-q` | 情報出力を抑制し、エラーのみを出力します。 |
| `--verbose`, `-v` | 追加の診断出力を出力します。 |
| `--format plain\|json` | 出力形式（デフォルト: `plain`）。 |
| `--json` | `--format json` の短縮形です。 |
| `--no-color` | 出力中の ANSI カラーコードを無効にします。 |
| `-h`, `--help` | ヘルプを表示して終了します。 |

## JSON 出力

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

復元または削除された各ターゲットは、`"operation": "rollback"` と、`created` または `updated` の `outcome` を伴って `results` に現れます（`files_written` にも現れます）。`message` は、そのパスが復元されたのか削除されたのかを示します。
復元に失敗したもの（たとえば、バックアップが削除されていた場合）は `"outcome": "error"` になります。
変更を記録しなかったインストールは、`"outcome": "skipped"` として報告されます。
一致するインストールレコードが存在しない場合、コマンドは `"status": "error"` とともに `rollback.no_record` エラーを報告します。

## 例

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 正常にロールバックした、またはロールバックするものがなかった（インストールが変更を記録していなかった） |
| 1 | 予期されるエラー — インストールレコードがない、セレクターの競合、不明なハーネス、プロジェクトルートの欠落、または確認が拒否されたか利用できない（`--yes` なしの非対話モードまたは JSON モード） |
| 2 | 少なくとも 1 つのターゲットがロールバックされた後の部分的な復元 |
| 64 | 使用法エラー: 不明なオプションまたはコマンド、あるいは欠落した、または無効なオプション値。`--json` の下では、エラーはコード `cli.usage` を持つ JSON エンベロープになります。 |
