**役割：** 主任研究者（理論的基盤づけ）
**パイプライン上の位置：** 中段

構築済みの研究課題に対する基礎的な概念的・理論的フレームワークを組み立てます。これは、体系的な検索と統合の段階が遡って参照する事前的な基盤です。すべての構成概念は一次理論に根ざし、理論化されたすべての関係は反証可能な形で記述されます。

## 標準的な呼び出し

```bash
/research-theory
```

引数付き：

```bash
/research-theory [--suite-name NAME] [--override] [--framework NAME]
```

## 入力

スイートの `_spec/research-spec.md`（`/research-spec` によって生成された、構築済みで反証可能な課題セット）。

## 出力

`_inputs/theory.md`（概念的 / 理論的フレームワーク、変化の理論 / ロジックモデル、操作的定義を備えた構成概念、そして概念モデル図）。

## 下流

/research-sources（下流の消費者——体系的な検索は、その包含基準をこれらの構成概念まで遡ります）。

## ワークフローのフェーズ

このコマンドは標準的な `/research` パイプラインのワークフローに従います。

1. **コンテキストの読み込み** —— `_spec/research-spec.md`、ルール、および既存のスイート状態を読み込みます。
2. **概念モデルの枠組み化** —— 構成概念とその操作的定義を定義し、それぞれを一次理論に根ざさせます。
3. **変化の理論の描画** —— 構成概念を期待される結果に結びつけるロジックモデルを構築し、各関係を反証可能な形で記述します。
4. **モデルの図示** —— 下流の段階が参照する概念モデル図を発行します。
5. **出力の検証** —— すべての構成概念が理論に根ざし、すべての関係が反証可能であることを確認し、構造化された問い合わせチャネルを通じて曖昧さを解消します。
6. **フレームワークの発行** —— `_inputs/theory.md` と更新された引き継ぎマニフェスト。

## 失敗モード

| 症状 | 原因 | 回復 |
|---------|-------|----------|
| 構成概念に操作的定義がない | 概念が抽象的に記述されている | 構成概念を測定可能な用語で定義し、一次理論を引用する |
| 理論化された関係が反証可能でない | 関係が自明の真理として記述されている | 関係を反証可能な主張として記述し直す |
| 仕様入力が欠落 | `/research-spec` がまだ実行されていない | まず `/research-spec` を実行して課題を構築する |

## 例

```bash
# 構築済みの課題に対する理論的フレームワークを組み立てる
/research-theory --suite-name retrieval-latency

# 名前付きの理論的フレームワークに固定する
/research-theory --framework "information foraging theory"
```
