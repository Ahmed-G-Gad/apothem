**役割：** レポーター
**パイプライン位置：** 読み取り専用

読み取り専用のプランスイート進捗レポーター——ファイルを一切変更せずにステータスを発行します。

## 正規の呼び出し

```bash
/plan-status
```

引数付き：

```bash
/plan-status [path/to/plan-suite/] [--verbose]
```

## 入力

ライフサイクルのいずれの状態にある任意のプランスイート —— `PROGRESS.md`、`PLAN-NOTES.md`、`MASTER-PLAN.md`、および `phases/` のレポートを読み取ります。

## 出力

オペレーターの出力ストリームへ書き出される戦略的ステータスレポート。このコマンドは読み取り専用であり、ファイルを一切作成・変更しません。

## 下流

進捗の確認のために単独で使用します —— 標準シーケンスとは直交し、任意の時点で読み取り専用で呼び出せます。

## ワークフローのフェーズ

このコマンドは読み取り専用です —— スイートのトラッキングファイルを読んで報告し、何も書き込みません。

1. **コンテキストの読み込み** — `PROGRESS.md`、`PLAN-NOTES.md`、`MASTER-PLAN.md` を読み取り、既存のレポートを求めて `phases/` を走査します。
2. **ステータスの評価** — タスク／フェーズ／成果物の各次元を調査し、再開コントラクトを読み取ります。
3. **ステータスレポートの発行** — 完了状況、フェーズトラッカー、および戦略的分析をオペレーターに直接提示します。
4. **スポットチェック** — `--verbose` の場合、スイートの健全性を採点し、既存ファイルに対するスポットチェックの証拠（マークダウンリンク、行範囲、コミット SHA）を、いかなるファイルも変更せずに引用します。

## 失敗モード

| 症状 | 原因 | 復旧 |
|---------|-------|----------|
| 必須のトラッキングファイルが欠落 | プランスイートが不完全 | ギャップを指摘事項として表面化する。`/plan-generate` を実行してスイートを作成する |
| トラッキングファイルが不正 | セクションが切り詰められているか解析不能 | レポートで欠落／矛盾を指摘する。修復は書き込み系コマンドへ回す |
| ファイル間でフィールドが欠落または矛盾 | トラッキングのドリフト | 矛盾を明示的に報告する。欠落値を合成しない |

## 例

```bash
# 最新のプランスイートについて報告する
/plan-status

# 指定したプランスイートに対する詳細な健全性採点
/plan-status path/to/plan-suite/ --verbose
```
