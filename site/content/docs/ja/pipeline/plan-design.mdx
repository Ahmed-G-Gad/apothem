**役割：** アーキテクト
**パイプライン位置：** 条件付き、レビュー後・実行前

プランスイートにアーキテクチャを伴う作業がある場合に、`_inputs/design.md` に
アーキテクチャ設計成果物を生成します。これは意図的に条件付きです。プロセ、
ドキュメント、メタデータ、または狭いフィクスチャのスイートは `/plan-review`
から `/plan-execute` へ直接進みます。コンポーネント、インターフェース、
スキーマ、データフロー、アダプター、リリーストポロジー、セキュリティ境界、
またはランタイム挙動を変更するスイートは、まず `/plan-design` を通過します。

## 正規の呼び出し

```bash
/plan-design path/to/plan-suite/
```

引数付き：

```bash
/plan-design [path/to/plan-suite/] [--refine-existing] [--dry-run]
```

## 入力

レビュー済みプランスイート + `_spec/spec.md` + `_inputs/handoff-manifest.yml`
+ `/plan-review` からの PASS レビュースコアカード。

## 出力

`_inputs/design.md`、加えて設計成果物のパス、設計ゲートの結果、七軸カバレッジの
結果、双方向バインディングマトリクスの要約を携える、拡張された
`_inputs/handoff-manifest.yml`。

## 適用性ゲート

少なくとも 1 つの下流フェーズが次のいずれかを宣言または含意する場合、
`/plan-design` を実行します。

- ソースレイアウト、パッケージ境界、アダプター境界、またはモジュール境界の
  変更。
- 公開インターフェース、プロトコル、スキーマ、構成契約、または CLI の挙動。
- コンポーネント間のデータフロー、ライフサイクルの順序付け、状態遷移、または
  依存関係エッジ。
- セキュリティ、性能、並行性、可観測性、デプロイ、リリース、またはサプライ
  チェーンのアーキテクチャ。
- 実装を設計成果物まで遡って追跡しなければならない、後続の
  `/architecture-review` パス。

スイートが文案編集、生成済みインベントリの更新、狭いフィクスチャ更新、
一回限りのドキュメント修正、または実装をアーキテクチャ追跡面なしで検証できる
その他の作業に限られる場合は、`/plan-design` をスキップします。スキップ
パスは明示的です。`/plan-review` が非アーキテクチャ分類を記録し、その後
`/plan-execute` がレビュー済みプランスイートから続行します。

## 下流

`/plan-execute` はアーキテクチャを伴うフェーズで設計成果物を消費します。
`/architecture-review` は監査レビューシーケンス中に同じ成果物を消費します。
アーキテクチャを伴う作業で `_inputs/design.md` が欠落している場合、
アーキテクチャレビューは停止し、スイートを `/plan-design` へ戻します。

## ワークフローのフェーズ

このコマンドはアーキテクチャ固有の 6 つの変換フェーズに従います。

1. **入力の取り込み** — レビュー済みスイート、スコアカード、フェーズ出力、
   交接マニフェストを読み取り、SHARED+ では欠落または不合格のレビュー証跡で
   ブロックします。
2. **アーキテクチャ分解** — アーキテクチャ、並行性、性能、セキュリティ、
   テスト、ツーリング、可観測性を巡回し、コンポーネント、エッジ、未解決の
   アーキテクチャ上の問いを特定します。
3. **コンポーネントインターフェース設計** — 公開インターフェース、プロトコル
   契約、スキーマ、不変条件、失敗モード、依存性逆転境界を定義します。
4. **コンポーネント間バインディングの批准** — 上流、下流、兄弟、基準、アンカー
   の各エッジを閉じ、コンポーネントグラフがマトリクス閾値を越えた場合に
   双方向バインディングマトリクスを発行します。
5. **設計成果物の発行** — コンポーネントセクション、図、決定記録、検証結果、
   バインディングを含む `_inputs/design.md` を書き出します。
6. **設計検証ゲート** — 十五バーの事前発行ゲートを実行し、設計が合格した後に
   のみ `_inputs/handoff-manifest.yml` を更新します。

## 設計成果物の形

発行される `_inputs/design.md` には次が含まれます。

- コンポーネント数と七軸カバレッジを含むエグゼクティブサマリー。
- 主要コンポーネントごとに 1 セクション。内側のドメイン面から外側の
  アダプターおよびオペレーター面へと順序付けられます。
- 構造が他の方法では曖昧になる箇所での、Mermaid のアーキテクチャ図、
  シーケンス図、状態図、または依存関係図。
- 代替案、トレードオフ、可逆性のメモを伴う、確定したアーキテクチャ決定記録。
- 該当する場合の検証ゲート結果と双方向バインディングマトリクス。
- 成果物自身による、上流および下流の計画面への五方向バインディング。

## 失敗モード

| 症状 | 原因 | 回復 |
|---------|-------|----------|
| 前提条件が未完了 | 依存フェーズが未完了 | まず上流フェーズを完了する |
| 品質ゲート FAIL | 出力が基準を満たさない | 出力を修正して再実行する |
| レビュー済みスイートの欠落 | プランスイートまたはレビュースコアカードが欠落 | `/plan-generate`、続いて `/plan-review` を実行する |
| 非アーキテクチャスイート | アーキテクチャ追跡面を必要とするフェーズがない | スキップを記録して `/plan-execute` へ進む |
| アーキテクチャレビューがブロック | アーキテクチャを伴う実装で `_inputs/design.md` が欠落 | `/plan-design` を実行し、`/architecture-review` を再実行する |

## 例

```bash
# 適用性、コンポーネント数、未解決の問いをプレビューするためのドライラン
/plan-design --dry-run

# 名前付きのアーキテクチャを伴うスイートに対して設計を発行する
/plan-design path/to/plan-suite/
```
