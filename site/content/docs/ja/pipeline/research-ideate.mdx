**役割:** 主任研究者（問題構築）
**パイプライン上の位置:** 先頭

ゼロから問題空間を構築します — 機会とギャップのスキャン、無効化された先行仮説のスキャン、そしてランク付けを伴う候補リサーチクエスチョンの生成 — `/research` パイプラインの入口ステージです。各候補は事前の理論的アンカーに照らして枠づけられ、先行研究に根ざし、反証可能な形で述べられ、`/research-spec` に渡せる状態になります。

## 標準的な呼び出し

```bash
/research-ideate
```

引数付き:

```bash
/research-ideate [path/to/domain-notes] [--suite-name NAME] [--override] [--domain NAME]
```

## 入力

ドメインシード — 自由形式のドメインノート（オペレーターがインラインで、またはパスとして提供）、あるいはゼロから始める場合の `--domain` 名のみ。

## 出力

`_inputs/ideation.md`（枠づけされた問題空間、機会とギャップのスキャン、無効化された先行仮説のスキャン、そしてランク付けされた候補クエスチョンのスレート）と、リサーチスイートフォルダー内のハンドオフマニフェスト。

## 下流

/research-spec（下流のコンシューマー — 選ばれた候補を反証可能な仕様へと枠づける）。

## ワークフローのフェーズ

このコマンドは標準的な `/research` パイプラインのワークフローに従います:

1. **コンテキストの読み込み** — ドメインシード、ルール、そして既存のスイート状態を読み込む。
2. **機会とギャップの空間をスキャン** — このドメインで何が研究され、何が争点となり、何が未対応のまま残っているかをマッピングする。
3. **無効化された先行仮説をスキャン** — 先行研究によって既に反駁された仮説を浮かび上がらせ、スレートが既に決着のついた地点を再びたどらないようにする。
4. **候補を生成しランク付け** — 候補リサーチクエスチョンを生成し、それぞれを反証可能な形で述べ、扱いやすさとインパクトでランク付けする。
5. **出力を検証** — 各候補が一次の先行研究に根ざし反駁可能であることを確認する。あらゆる曖昧さを構造化照会チャネルを通じて解消する。
6. **構想スレートを発行** — `_inputs/ideation.md` とハンドオフマニフェスト。

## 失敗モード

| 症状 | 原因 | 回復 |
|---------|-------|----------|
| 反証可能な候補が出ない | ドメインシードが広すぎるか純粋に記述的 | 構造化照会でドメインを絞り込む。候補を反駁可能なクエスチョンとして枠づけし直す |
| 候補が無効化された先行仮説を言い換えている | 先行研究スキャンが省略された | 無効化された先行仮説のスキャンを実行する。重複する候補を破棄するか枠づけし直す |
| ドメインシードが欠落 | ノートも `--domain` も提供されていない | ドメインノートをインライン/パスとして提供するか、`--domain NAME` を渡す |

## 例

```bash
# ドメインをスキャンしてランク付けされた候補クエスチョンを生成する
/research-ideate ~/notes/retrieval-systems.md --suite-name retrieval-latency

# 裸のドメイン名から始める
/research-ideate --domain "vector-index recall under drift"
```
