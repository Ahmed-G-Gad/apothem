Apothem は、アーキテクチャを考慮した `/plan` パイプライン、13 ステージの
`/research` パイプライン、そして 11 コマンドの監査シーケンスを出荷しています。
これにより、すべてのプロジェクトに、生の散文から本番品質で多軸のレビューを経たコードへ、
そして生のアイデアから広く発信され査読を経た論文へと至る、構造化された道筋が与えられます。

## パイプラインの概要

```mermaid
flowchart LR
    accTitle: Plan pipeline command flow
    accDescr: Left-to-right flowchart of the apothem plan pipeline from the spec stage through the generate and review stages, then through a conditional architecture-bearing decision that either runs the design stage or skips directly to the execute stage. The orthogonal audit stage wraps the spec-through-review span as a closed remediation loop, and the re-entrant amend stage revises an existing suite and returns it to review.
    A[/plan-spec] --> B[/plan-generate]
    B --> C[/plan-review]
    AUD[/plan-audit<br/>orthogonal: wraps spec → review] -.->|closed-loop remediation| A
    AM[/plan-amend<br/>re-entrant: revises an existing suite] -.->|re-review| C
    C --> Q{Architecture-bearing suite?}
    Q -->|yes| F[/plan-design<br/>emit _inputs/design.md]
    Q -->|no| D[/plan-execute]
    F --> D
    D --> E[/plan-status]
    D --> G[Audit review sequence]
    G --> H[Completion milestone]
```

## プランニングのステージ

パイプラインは、ステージごとに 1 つずつ、8 つのファーストクラスのスラッシュコマンドとして出荷されます —
それぞれ `/plan-<stage>` として個別に呼び出せます。
[/plan](/docs/pipeline/plan) オーケストレーターは、ミッションから実行済みのスイートまで、これらのステージを駆動します。

| ステージ | 役割 | 位置 |
|-------|------|----------|
| [/plan-spec](/docs/pipeline/plan-spec) | フォージ — 散文から仕様へ | 先頭 |
| [/plan-generate](/docs/pipeline/plan-generate) | ジェネレーター — 仕様からプランスイートへ | チェーンの中間 |
| [/plan-review](/docs/pipeline/plan-review) | オーディター — フォレンジックなプラン監査 | チェーンの中間 |
| [/plan-design](/docs/pipeline/plan-design) | アーキテクト — アーキテクチャに関わるスイートのための `_inputs/design.md` | 条件付きゲート |
| [/plan-execute](/docs/pipeline/plan-execute) | エグゼキューター — フェーズの実行 | 終端 |
| [/plan-status](/docs/pipeline/plan-status) | レポーター — 読み取り専用のステータス | 読み取り専用 |
| [/plan-audit](/docs/pipeline/plan-audit) | ガーディアン — spec → generate → review のクローズドループによるラップ | 直交（実行前） |
| [/plan-amend](/docs/pipeline/plan-amend) | スチュワード — 既存スイートの再入可能な修正 | 再入可能 |

`/plan-audit` は線形フローに対して直交しており、その中のステージではありません。
`/plan-spec → /plan-generate → /plan-review` を 1 つのクローズドループとしてラップし、
欠けている上流のステージだけを実行し、検出結果を能動的に是正し、スイートを `/plan-execute` の準備が整った状態にします。
これは後述の監査レビューシーケンスとは別物です。監査レビューシーケンスは、プランスイートではなく、実行済みのコードベースを監査します。

`/plan-design` は、すべての場合に行う儀式ではありません。`/plan-review` は、
スイートがアーキテクチャに関わる面を変更するかどうかを分類します。
変更する場合、`/plan-design` は、`/plan-execute` と `/architecture-review` が利用する設計トレースを出力します。
変更しない場合、レビュー済みのスイートはそのまま実行に進みます。

## リサーチパイプライン

リサーチパイプラインは、ステージごとに 1 つずつ、13 のファーストクラスのスラッシュコマンドとして出荷されます —
それぞれ `/research-<stage>` として個別に呼び出せ、シーケンスゲートとハンドオフマニフェストによって連結され、
10 の厳密性マンデート（権威ある情報源、再現性、反証可能性、引用の完全性、事前登録、
倫理 / 利益相反、統計的厳密性、オープンサイエンス / FAIR、報告ガイドラインへの準拠、
理論的基盤 / インパクト）の下で動作します。

```mermaid
flowchart LR
    accTitle: Research pipeline command flow
    accDescr: Left-to-right flowchart of the apothem research pipeline from the ideate stage through spec, theory, sources, synthesis, proposal, study design, experiment, analysis, paper, and peer review to publish and disseminate, with a revision loop from review back to paper.
    RI[/research-ideate] --> RS[/research-spec]
    RS --> RT[/research-theory]
    RT --> RSO[/research-sources]
    RSO --> RSY[/research-synthesis]
    RSY --> RPR[/research-proposal]
    RPR --> RD[/research-design]
    RD --> RE[/research-experiment]
    RE --> RA[/research-analysis]
    RA --> RP[/research-paper]
    RP --> RR[/research-review]
    RR --> RPU[/research-publish]
    RPU --> RDI[/research-disseminate]
    RR -.->|revision loop| RP
```

| ステージ | 役割 | 位置 |
|-------|------|----------|
| [/research-ideate](/docs/pipeline/research-ideate) | 問題の定式化 — ドメインのシードから候補となる問いを導く | 先頭 |
| [/research-spec](/docs/pipeline/research-spec) | 問いの枠組み — 反証可能な仮説 + スコープ | チェーンの中間 |
| [/research-theory](/docs/pipeline/research-theory) | 概念フレームワーク + 変化の理論 | チェーンの中間 |
| [/research-sources](/docs/pipeline/research-sources) | 体系的な情報源の収集 | チェーンの中間 |
| [/research-synthesis](/docs/pipeline/research-synthesis) | SOTA マップ + ギャップ分析 | チェーンの中間 |
| [/research-proposal](/docs/pipeline/research-proposal) | 目的 + 実現可能性 + インパクト + 事前登録の計画 | チェーンの中間 |
| [/research-design](/docs/pipeline/research-design) | 研究デザイン + 事前登録 | チェーンの中間 |
| [/research-experiment](/docs/pipeline/research-experiment) | 実行 + 記録、再現可能 | チェーンの中間 |
| [/research-analysis](/docs/pipeline/research-analysis) | 結果 + 統計 | チェーンの中間 |
| [/research-paper](/docs/pipeline/research-paper) | トップティアの論文ドラフト | チェーンの中間 |
| [/research-review](/docs/pipeline/research-review) | 査読レベルの批評 | チェーンの中間 |
| [/research-publish](/docs/pipeline/research-publish) | 投稿先向けのパッケージ + 投稿 | チェーンの中間 |
| [/research-disseminate](/docs/pipeline/research-disseminate) | 普及 + インパクト + FAIR なアーカイブ | 終端 |

[/research](/docs/pipeline/research) のラップ型ワークフローオーケストレーターは、生の問いから公開された論文まで、
これらのステージを駆動します（オーケストレーター自体はステージではありません）。
次のステージが前のステージの出力に基づいて構築を始める前に、各ステージの出力を独立してチェックします。
`--quick` は、1 回限りの引用付きレポートのために `/research-sources` + `/research-synthesis` だけを実行します。

経験的なステージ（情報源、研究デザイン、実験、分析）と執筆のステージ（論文、レビュー、公開、普及）は、
さらに厳密性を運用に落とし込む面 — 公平な複数手法の比較、比較対象の来歴、実験プログラムの足場、
計算資源の利用計画、オプトインの自律実験ループ、完了の定義による前進ゲート、段階的な開示を伴う盲検化 — を活用します。
これらは 10 のマンデートを拡張することなく、運用上の詳細を加えるものです。

## 監査レビューシーケンス

[/audit](/docs/pipeline/audit) のラップ型ワークフローオーケストレーターは、以下の 11 の次元すべてを 1 回の並列パスで一掃します — `/plan` と `/research` に相当する監査フォートレス版です — そして、重複を排除し重大度で振り分けた 1 つの検出結果レポートにまとめます（レポートのみ。是正は `/elevate` に回されます）。各次元は個別に呼び出すこともできます。

[/fortress](/docs/pipeline/fortress) のラップ型ワークフローオーケストレーターは、`/audit` が報告するループを閉じます。`/audit` を通じて検出し、各検出結果を検証し、検証を通過したすべての検出結果をその所有元の面で是正し、上限のあるループで再監査し、結果を [/release-readiness](/docs/pipeline/release-readiness) でゲートします — `/plan` と `/research` に相当する本番堅牢化版です。

| コマンド | 品質領域 |
|---------|--------------|
| [/code-review](/docs/pipeline/code-review) | コード品質 |
| [/code-audit](/docs/pipeline/code-audit) | コードコーパス |
| [/security-audit](/docs/pipeline/security-audit) | OWASP / ASVS |
| [/perf-audit](/docs/pipeline/perf-audit) | パフォーマンス |
| [/architecture-review](/docs/pipeline/architecture-review) | アーキテクチャ |
| [/ux-review](/docs/pipeline/ux-review) | 開発者体験 |
| [/a11y-audit](/docs/pipeline/a11y-audit) | アクセシビリティ |
| [/docs-review](/docs/pipeline/docs-review) | ドキュメント |
| [/dependency-audit](/docs/pipeline/dependency-audit) | 依存関係 |
| [/supply-chain-audit](/docs/pipeline/supply-chain-audit) | サプライチェーン |
| [/threat-model-audit](/docs/pipeline/threat-model-audit) | 脅威モデル |
