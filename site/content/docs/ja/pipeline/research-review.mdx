**役割:** 主任研究者（査読）
**パイプライン上の位置:** チェーン中段

発表先の基準に照らして、論文に査読水準の対抗的批評を加えます——新規性、厳密性、再現性、明瞭性、倫理、統計レビュー、報告ガイドライン適合性。**7軸**のレビュアースコアカードと、重大度で振り分けた必須修正リストを発行し、各所見に具体的な根拠（コンクリート・ドライバー）の理由を付けます。デフォルトで反証の姿勢をとり、すべての指摘は草稿自体の言葉と証拠に基づき、発表先、機関、著者の地位には決して基づきません。

## 正規の呼び出し

```bash
/research-review
```

引数付き：

```bash
/research-review [--suite-name NAME] [--venue STANDARD] [--paper PATH [--scale SPEC] [--roles LIST] [--out PATH]]
```

## 入力

論文段階が記録した、ホストに自然な場所にある論文成果物。`--paper` を指定した場合、論文はリサーチスイートの成果物ではなく、あなたが提供する PDF またはテキストファイル（あるいは貼り付けたテキスト）であり、スイートは不要です。

## 出力

`_outputs/review-report.md` —— **7軸**のレビュアースコアカード（新規性 · 厳密性 · 再現性 · 明瞭性 · 倫理 · 統計レビュー · 報告ガイドライン適合性）、重大度で振り分けた（HIGH / MEDIUM / LOW）必須修正リスト（各所見に具体的な根拠の理由を付与）、再現性パッケージと再実行の判定、引用整合性監査、および全体の `accept · minor-revision · major-revision · reject` 判定。

`--paper` を指定した場合、レポートはプロジェクトルートの `.apothem/plans/<date>--review-<slug>.md`（または `--out` のパス）に書き出されます。内容は、レビュアーの役割ごとに 1 行を持つ 7 軸のスコアカード、数式・アブレーション・ベースラインのチェック行、重大度順に並べた必須修正、著者への最大 5 つの質問、そしてあなたが指定した推奨スケールに対応付けた判定です。これは査読ではなく、モデル支援による読解として表示されます。

## 下流

/research-publish（下流の消費者）。`major-revision` または `reject` の判定は、`/research-publish` を実行する前に必須の修正に対応しなければならないことを意味します。

## ワークフローのフェーズ

このコマンドは標準的な `/research` パイプラインのワークフローに従います：

1. **コンテキストの読み込み** — 論文の成果物を読み込みます。
2. **シーケンスゲートの検証** — 論文、`_outputs/analysis.md`、`_inputs/synthesis.md` が存在し、空でないことを確認します。そうでない場合は、`Blocked: run /research-paper first` で停止します。
3. **対抗的にレビュー** — 7 つの軸（新規性 · 厳密性 · 再現性 · 明瞭性 · 倫理 · 統計レビュー · 報告ガイドラインへの適合）を採点します。各主張を記述的、関連的、因果的のいずれかに分類し、繰り返し見られる評価上の誤りをチェックします。図が誠実に符号化され、色なしでも読めることをチェックします。再現性の再実行と引用の整合性の監査を実行します。デフォルトで反証し、証拠とともに具体的な欠陥を特定します。
4. **修正の振り分け** — 必須の修正を、具体的な根拠とともに HIGH / MEDIUM / LOW にランク付けします。レビューが判断できない軸には判定を与えません。その軸は理由とともに未判断リストに残り、全体の判定はそれを括弧書きで扱います。
5. **ハンドオフマニフェストの更新** — レビューレポートと、スコアカードの判定を記録します。
6. **レビューの出力** — `_outputs/review-report.md`。

## 他者の論文のレビュー

`--paper` は、リサーチスイートの一部ではない原稿をレビューします。たとえば、査読を依頼された投稿論文や同僚の草稿です。

- **発表先プロファイル。** `--venue` は汎用プロファイルの ID（たとえば `empirical-conference` や `field-journal`）を受け取ります。名指しされた発表先には最も近い汎用プロファイルが使われ、レポートにはその旨が記載されます。Apothem は汎用プロファイルのみを同梱し、いかなる発表先固有の基準も主張しません。あなたがガイドラインを貼り付けた場合はそれが優先され、レポートのヘッダーにはその出典、日付、および対象とする年またはサイクルとトラックが記録されます。
- **原稿のバージョン。** レポートには、どのバージョンを読んだか（プレプリント、受理原稿、記録版、または不明）、ファイルが持つバージョン表示、入手元、そして読んだ日付が記録されるため、レビューは 1 つの改訂版に固定されます。
- **レビュアーの役割。** デフォルトの役割は methods、domain、skeptical です。`--roles` でこのリストを変更できます。役割間で意見が分かれる場合、レポートは平均をとらずに、その不一致を記載します。
- **機密性。** 論文が機密の投稿論文か、出版済みの論文か、あなた自身の草稿かを一度だけ尋ねられます。答えが不明な場合はより厳格な取り扱いが適用されます。検索にはタイトル、識別子、または一般的なトピック用語を使い、原稿中の文は決して使いません。
- **新規性。** スイートがなければ先行研究のマップがないため、レビューは論文が名指しする近隣研究と、範囲を限定した検索記録を使います。空の検索結果が新規性の証拠とみなされることは決してなく、記録が学術索引をカバーしていない限り、新規性の確信度は低いままです。
- **匿名性。** 二重盲検の発表先に向けたあなた自身の準備状況のチェックでは、レビューは本文以外の面（文書のプロパティ、同梱およびリンクされたファイル、リポジトリの履歴、補足アーカイブ、レンダリングされた図）を検査します。開けない面は未判断リストに入り、決して問題なしのリストには入りません。あなたに割り当てられた機密の投稿論文については、レビューはそれらの面で身元を探しません。探さずに遭遇した身元は漏洩としてあなたに報告され、いかなるスコアにも算入されません。

## 厳密性の下限

いかなる軸の判定、所見、確信度も、ジャーナルレベルの指標、引用数、著者レベルの指数、または発表先・機関・著者の評判には基づきません。そのような数値を引用するレビューは、それが何を測定するか、出典、日付とともに、記述的に引用します。HIGH 重大度の所見には、開示されていない継ぎ合わせ、合成、または処理工程を含む実験画像、そして理由の記載なく報告されたアウトカムと異なる登録済みアウトカムが含まれます。統計レビューでは、n が 1 つの単位の反復測定、フォールド、シードではなく、独立した単位を数えていることをチェックします。

レビューは、経験的な主張を進出ゲートの基準に照らして採点します——適切な複製、効果量と臨界差ランクを伴うノンパラメトリックな有意性、および比較される手法間での予算の同等性——そして、その判定を明示的な進出ゲートとして扱います。論文が進出するのは、発表先の基準を説得力をもって有意に上回り、その通過が記録されたときだけです。二重盲検の発表先では、レビュアーはいかなる身元の漏洩も匿名化の欠陥として指摘します。

## 失敗モード

| 症状 | 原因 | 回復 |
|---------|-------|----------|
| Blocked: run /research-paper first | 論文がない | `/research-paper` を実行して原稿を作成する |
| Blocked: no paper supplied | `--paper` のファイルが存在しないか読み取れない | 読み取り可能な PDF またはテキストファイルを渡すか、テキストを貼り付ける |
| 甘い採点 | レビュアーが最良のケースを想定した | デフォルトで反証；提示された証拠に基づいて採点する |
| 地位に基づく指摘 | 発表先、機関、著者、ジャーナルレベルの指標、または引用数が証拠として使われた | それを取り除き、草稿自体の言葉と証拠から指摘を述べ直す |
| 理由のない所見 | 修正が主張されただけで論証されていない | 各所見に具体的な根拠の理由を付ける |

## 例

```bash
# 論文を査読し、レビュアーのスコアカードを出力する
/research-review --suite-name <name>

# 提供された PDF を汎用の発表先プロファイルに照らして 1-10 のスケールでレビューする
/research-review --paper ./submission.pdf --venue empirical-conference --scale 1-10
```
