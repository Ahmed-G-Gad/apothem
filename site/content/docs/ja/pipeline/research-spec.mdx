**役割：** 主任研究者（フレーミング）
**パイプライン位置：** チェーン中段

自由形式の研究課題や生メモを、仕様グレードの `_spec/research-spec.md` —— 明示的な範囲、包含／除外基準、成功指標を備えた、検証可能で反証可能な仮説セット —— に構成し、`/research-theory` にすぐ渡せる状態にします。

## 標準的な呼び出し

```bash
/research-spec
```

引数付き：

```bash
/research-spec [path/to/question-or-notes] [--suite-name NAME] [--quick SLUG]
```

## 入力

自由形式の研究課題または生メモ（操作者がインラインで、またはパスとして提供）。

## 出力

`_spec/research-spec.md`（課題、反証可能な仮説、範囲、包含／除外基準、成功指標、用語集）＋ `_inputs/handoff-manifest.yml`。`--quick` の場合は、代わりに軽量なプロジェクトローカルの研究ブリーフを書き込みます。

## 下流

/research-theory（下流の消費者）

## ワークフローのフェーズ

このコマンドは標準的な `/research` パイプラインワークフローに従います。

1. **コンテキストを読み込む** —— 課題／メモ、ルール、および既存のスイート状態を読み込む。
2. **課題をフレーミングする** —— 明示的な範囲と包含／除外基準を備えた反証可能な仮説に分解する。構造化問い合わせチャネルを通じてあらゆる曖昧さを表面化する。
3. **成功指標を設定する** —— この研究を判定するための測定可能な基準を述べる。
4. **出力を検証する** —— 仕様が確定的であること（すべての権威データのギャップが構造化問い合わせチャネルを通じて解決され、未記入の確認プレースホルダーが残されていないこと）を確認し、厳密性マンデートの下限を満たすことを確認する。
5. **引き継ぎマニフェストを更新する** —— 仕様パスと未解決／解決済みの問い合わせ件数を記録する。
6. **仕様を発行する** —— `_spec/research-spec.md` と引き継ぎマニフェスト。

## 厳密性の下限

主張される各貢献は、明確で・実質的で・独立してアブレーション可能であるように制約され、その限界的な効果が後で切り分けられるようにします。求められる厳密性の下限の深さは、対象とする発表先の野心に応じてスケールします。その野心が明示されていない場合は、構造化問い合わせを通じて確認され、決して臆造されません。

## 失敗モード

| 症状 | 原因 | 復旧 |
|---------|-------|----------|
| 未解決の仮説の曖昧さ | 課題の規定が不十分 | 構造化問い合わせで表面化する。範囲を臆造しない |
| 測定可能な成功指標がない | 目標が成果ではなく活動として述べられている | 検証可能で反証可能な成果として再フレーミングする |
| 課題入力の欠落 | 文章／メモが提供されていない | 研究課題をインラインで、またはパスとして提供する |

## 例

```bash
# Frame a question into a research spec
/research-spec ~/notes/retrieval-latency-study.md --suite-name retrieval-latency

# Lightweight project-local research brief
/research-spec --quick retrieval-latency
```
