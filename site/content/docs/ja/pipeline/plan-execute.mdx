**役割：** 実行者
**パイプライン位置：** ターミナル

コンフォーミティチェックのもとで、マスタープランスイートから特定のフェーズを実行します。

## 正規の呼び出し

```bash
/plan-execute
```

引数付き：

```bash
/plan-execute [path/to/plan-suite/] [phase-id] [--dry-run]
```

## 入力

生成済み + レビュー済みのプランスイート、レビュー済みの `_inputs/handoff-manifest.yml`

## 出力

フェーズごとの REPORT.md ファイル、コードベース制作物、COMPLETION.md

## 下流

`/fortress` は、実行済みの作業を 1 回の呼び出しで、リリースゲートを通過した状態まで堅牢化します（検出、検証、修復、再監査、ゲート判定）。既定では、各ラウンドの境界で確認のために一時停止します。`--autonomous` を指定すると、一時停止せずにラウンドを実行します。`/code-review`——11 コマンドからなる監査レビューシーケンスの正規エントリーポイントです。このシーケンスは、チェーンを 1 ステージずつたどります。`/plan-execute` は*プラン*パイプラインの終端ステージです。最終フェーズが完了すると、構築されたコードはレビューのために監査レビューシーケンスへ引き継がれます。

## ワークフローのフェーズ

このコマンドは標準の `/plan` パイプラインワークフローに従います。

1. **コンテキストの読み込み** — プランスイート、ルール、再開コントラクトを読み取ります。
2. **前提条件の検証** — 依存フェーズが完了していることを確認します。
3. **タスクの実行** — コマンドのミッションを遂行します。
4. **出力の検証** — 宣言されたすべての出力が存在し、品質ゲートを通過することを確認します。
5. **REPORT.md の出力** — 事前出力ゲートのゲート結果を記録します。
6. **PROGRESS.md の更新** — 検証済みの出力をフェーズ出力レジストリに記録します。

## 失敗モード

| 症状 | 原因 | 復旧 |
|---------|-------|----------|
| 前提条件が未完了 | 依存フェーズが終わっていない | まず上流のフェーズを完了させる |
| 品質ゲート FAIL | 出力が基準を満たさない | 出力を修正して再実行する |
| 入力ファイルが欠落 | プランスイートのファイルが存在しない | `/plan-generate` を実行して作成する |

## 例

```bash
# Dry-run to preview what would happen
/plan-execute --dry-run

# Execute against a named plan suite
/plan-execute path/to/plan-suite/
```
