**役割：** 主任研究者（基準計画）
**パイプラインの位置：** チェーン中段

統合されたギャップと理論的枠組みを、資金獲得可能でレビュー可能な基準計画に変換します。倫理的実現可能性は冒頭で提示され、事前登録計画と報告ガイドラインの選択は、いかなる研究設計が具体化される前に確定されます。

## 標準的な呼び出し

```bash
/research-proposal
```

引数付き：

```bash
/research-proposal [--suite-name NAME] [--override] [--guideline NAME] [--prereg-registry NAME] [--call PATH] [--resubmission PATH]
```

## 入力

スイートの `_inputs/synthesis.md`（SOTA マップ ＋ ギャップ分析）と `_inputs/theory.md`（概念的枠組み）。

`--call` を指定した場合は、資金提供機関の公募文をファイルパスとして、または貼り付けたテキストの場合は `-` として与えます。提供されたテキストが、資金提供機関の要件の唯一の情報源です。`--resubmission` を指定した場合は、以前の申請に対する資金提供機関の批評を与え、統合や理論は不要です（後述）。

## 出力

`_inputs/proposal.md`（SMART 目標の階層、実現可能性の評価、コンティンジェンシーを伴うリソース／タイムライン／リスクの登録簿、インパクト経路、事前登録計画、データ管理・共有計画、および EQUATOR 報告ガイドラインの事前選択）。

`--call` を指定した場合は、`_inputs/call-requirements.md`（公募要件マトリクス）も出力します。`--resubmission` を指定した場合は、提案の代わりに `_outputs/resubmission-response.md` を出力します。

## 下流

/research-design（下流の消費者——提案を具体化して、凍結された事前登録済みの研究設計にします）。

## ワークフローのフェーズ

このコマンドは標準的な `/research` パイプラインのワークフローに従います。

1. **コンテキストの読み込み**——`_inputs/synthesis.md` と `_inputs/theory.md`、ルール、および既存のスイート状態を読み込みます。
2. **SMART 目標の階層を構築**——ギャップを、具体的・測定可能・達成可能・関連性があり・期限のある目標に変換します。
3. **実現可能性とリスクの評価**——リソース／タイムライン／リスクの登録簿を構築し、目標の達成可能性に及ぶ各リスクにコンティンジェンシー記録を与えてその背後にある判断をストレステストし、提供された費用項目を照合し、倫理的実現可能性を冒頭で提示します。
4. **事前登録、データ、報告の計画**——登録先を選択し、事前登録計画を起草し、データ管理・共有計画を確定し、EQUATOR 報告ガイドラインを事前選択します。
5. **インパクト経路のマッピング**——目標が達成された場合に、どのように下流のインパクトを生み出すかを追跡します。
6. **検証と発行**——目標が検証可能であり計画が再現可能であることを確認し、`_inputs/proposal.md` と引き継ぎマニフェストを発行します。

## 提供された資金提供機関の公募

`--call` を指定した場合、公募文が提案の形を決定します。このステージは要件マトリクスを `_inputs/call-requirements.md` に書き出します。要件（セクション、制限、応募資格、添付書類、審査基準、またはポリシー）ごとに 1 行で、それに応える提案セクション、オペレーターの草稿内での位置、そして `met`、`partly-met`、`gap`、`operator-owned` のいずれかのステータスを記載します。各審査基準が 1 行となるため、すべての目標は自らが応える基準まで追跡できます。どの基準にも重み付けは行わず、採択の見込みについての主張も一切行いません。

- **ツール利用ポリシーを最初に。** 自動化ツールに関する公募のポリシーは、いかなるテキストが書かれる前にも確定されます。許可、開示を条件とした許可（ツール利用声明を起草します）、または制限のいずれかです。制限ポリシーの下では、このステージはマトリクスの後で停止し、判断をオペレーターに戻します。ポリシーについて言及のない公募については質問し、決して推測しません。
- **記憶に頼らず、予算も作らない。** 資金提供機関の要件、制限、日付、レート、上限は、提供されたテキストまたはオペレーターから得るものであり、決して記憶からではありません。このステージは予算を作成しません。オペレーターの費用項目を検査し、どの目標にも結び付かない項目は `orphan`、リソースの割り当てがない目標は `unresourced`、合計が合わないものは `unreconciled` となります。
- **資金提供機関向けの叙述は書かない。** このステージが発行するのは基準計画であり、意義やアプローチの文章ではありません。チーム、略歴、施設、支援レター、および現在・申請中の支援は `operator-owned` の行であり、決して起草されません。

## 再申請モード

`--resubmission PATH` は、以前の申請に対する資金提供機関の批評に回答するもので、13 ステージのチェーンの外で動作します。シーケンスゲートは適用されず、引き継ぎマニフェストには手を触れません。オペレーターは批評、公募文（`--call`）、提出時の申請書、および改訂版の草稿を提供し、このステージは 3 つの部分から `_outputs/resubmission-response.md` を書き出します。

- **応募資格と制限**——再申請が許可されるかどうか、公募が許容する回数、締め切り、そして回答と改訂版申請書に対する制限を公募文から読み取ります。テキストに記載のない規則はオペレーターに質問します。公募文がない場合、回答は `ready` に到達できません。
- **改訂マトリクス**——資金提供機関の番号付けに従い、批評コメントごとに 1 行を設けます。引用したコメント、対応（`changed`、`clarified`、または `declined`）、改訂箇所、科学的な帰結、未解決の問い、そして改訂テキストに裏付けられた `answered`、`partly-answered`、`not-answered` のいずれかのステータスです。却下したコメントには、その理由と証拠を付けます。
- **波及チェック**——各 `changed` 行を、それが関わるすべての計画要素（目標、方法、タイムライン、予算項目、データ計画、リスク登録簿）まで追跡します。変更が関わるにもかかわらず改訂版の草稿で変更されていない要素は `unpropagated` となります。

すべての行が `answered` であるかオペレーターが受け入れた残余を伴い、`unpropagated` の要素がなく、公募のすべての制限が満たされているとき、回答は `ready` となります。新たな証拠を必要とする回答はオペレーターに戻され、オペレーターがそれを `/research-design` または `/research-experiment` に回します。提出はオペレーターが行います。

## 厳密性の下限

対象とする発表先の野心は、報告ガイドラインの選択だけでなく、下流の設計・実験の各段階が満たさなければならない厳密性の下限の深さも定めます——複製の下限、予算の同等性、互いに素な分割でのチューニング、および効果量を伴う有意性——に加えて、成果物が携える再現性証拠パッケージも定めます。

各リスクは、計画がどのように失敗するかについての反証可能な予測です。目標の達成可能性に及ぶリスクは、その緩和策で終わりません。データ収集の前に確定されるコンティンジェンシー記録（トリガー、責任を負う役割、レビュー日、リードタイム、バックアップの費用、残余リスク）を伴い、計画に書き込まれた対応は逸脱ではなく計画された適応です。データ管理・共有計画は、設計がデータを確定する前に、リポジトリの種別、各制限の根拠を伴うアクセス条件、および保持期間を確定します。また、同意の範囲は、計画が約束する共有を許容するものでなければなりません。

## 失敗モード

| 症状 | 原因 | 回復 |
|---------|-------|----------|
| 目標が測定不能 | 目標が結果ではなく活動として記述されている | 明示的な成功指標を伴う SMART 目標として再構成する |
| 事前登録計画がない | 事前登録ステップがスキップされた | `/research-design` に進む前に登録先を選択して計画を起草する |
| 統合入力が欠落 | `/research-synthesis` がまだ実行されていない | 先に `/research-synthesis` を実行してギャップ分析を生成する |
| 資金提供機関の公募が名指しされているがテキストがない | `--call` が省略されたか、テキストが読み取れない | 公募文を提供する。このステージは資金提供機関の規則を決して記憶から補わない |
| 再申請の回答が `ready` でない | コメントに回答されていない、変更が `unpropagated` である、または公募の制限を超えている | 変更を改訂版の草稿に波及させる、コメントに回答する、または回答を制限内に収める |

## 例

```bash
# ギャップを資金獲得可能な基準計画に変換する
/research-proposal --suite-name retrieval-latency

# 報告ガイドラインと事前登録の登録先を固定する
/research-proposal --guideline PRISMA --prereg-registry OSF

# 資金提供機関の公募を基準計画にマッピングする
/research-proposal --suite-name retrieval-latency --call funder-call.md

# 以前の申請に対する資金提供機関の批評に回答する
/research-proposal --resubmission critique.md --call funder-call.md
```
