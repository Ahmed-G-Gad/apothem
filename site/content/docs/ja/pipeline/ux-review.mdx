**役割：** UX レビュアー
**パイプライン位置：** 要塞

CLI のエルゴノミクス、ドキュメント、オンボーディングを対象とした開発者体験レビュー。

## 正規の呼び出し

```bash
/ux-review
```

引数付き：

```bash
/ux-review [path/to/plan-suite/] [phase-id] [--dry-run]
```

## 入力

任意のライフサイクル状態にあるホストリポジトリ

## 出力

UX の発見 + REPORT.md

## 下流

監査レビューシーケンスの UX レビューステージ

## ワークフローのフェーズ

このコマンドは標準の `/plan` パイプラインワークフローに従います。

1. **コンテキストの読み込み** — 計画スイート、ルール、再開契約を読み込みます。
2. **前提条件の検証** — 依存フェーズが完了していることを確認します。
3. **タスクの実行** — コマンドの使命を遂行します。
4. **出力の検証** — 宣言されたすべての出力が存在し、品質ゲートを通過することを確認します。
5. **PROGRESS.md の更新** — 検証済みの出力をフェーズ出力レジストリに記録します。
6. **REPORT.md の発出** — 事前発行ゲートのリリース証明を記録します。

## 失敗モード

| 症状 | 原因 | 回復 |
|---------|-------|----------|
| 前提条件が未完了 | 依存フェーズが未完了 | まず上流フェーズを完了する |
| 品質ゲート FAIL | 出力が基準を満たさない | 出力を修正して再実行する |
| 入力ファイルの欠落 | 計画スイートのファイルがない | `/plan-generate` を実行して作成する |

## 例

```bash
# Dry-run to preview what would happen
/ux-review --dry-run

# Execute against a named plan suite
/ux-review path/to/plan-suite/
```
