Apothem はいくつかの設計上の考え方の上に成り立っています。このセクションではそれらを
説明します — なぜガバナンスがプラットフォーム非依存なのか、アシスタントという
協働者がどう位置づけられているのか、監査レビューシーケンスが何を保証するのか、そして
ガバナンスのオーバーヘッドが取り組みの規模にどう合わせて調整されるのか。

## ページ

| ページ | 説明 |
|------|-------------|
| [ホスト非依存の姿勢](/docs/concepts/ai-platform-agnosticism) | Apothem が共有プロファイルとハーネスアダプターを通じてどのようにホスト非依存の姿勢を実現するか。 |
| [再開可能なプランニング](/docs/concepts/resumable-planning) | 作業状態をプロジェクトローカルの `.apothem/plans/` スイートへどのように外部化し、長時間にわたる作業がセッション・アカウント・マシンの境界を越えて存続するか。 |
| [監査レビューシーケンス](/docs/concepts/review-fortress) | 本番準備状態をチェックする 11 コマンドの品質保証スイープ。 |
| [認知的アイデンティティ](/docs/concepts/cognitive-identity) | テクニカル・コファウンダーという位置づけ — Apothem がアシスタントとの協働をどう形づくるか。 |
| [シリアスネスティア](/docs/concepts/seriousness-tiers) | ガバナンスのオーバーヘッドを取り組みのレベルに合わせて調整する 4 つのティア。 |
