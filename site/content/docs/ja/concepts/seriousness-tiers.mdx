Apothem はガバナンスのオーバーヘッドを取り組みのレベルに合わせてスケールします。
手早い探索に署名付きコミットは不要ですが、本番リリースには必要です。

## 4 つのティア

| ティア | 使用する場面 | ガバナンスの下限 |
|------|-------------|-----------------|
| **EXPLORING** | プロトタイプ、使い捨ての実験 | リント + テスト + 中核となるマンデート(批判的評価、最良解の推論、率直な誠実さ) |
| **PERSONAL_USE** | 個人用ツール、ローカルスクリプト | + 型チェック + フェーズごとのコミット + PROGRESS.md |
| **SHARED** | チームプロジェクト、オープンソース | + チェック失敗が実行をブロック + タスクごとのコミット + 完全なドキュメント + 並行レビュー |
| **PUBLIC_LAUNCH** | 本番サービス、公開パッケージ | + セキュリティスキャン + 署名付きコミット + セマンティックバージョニング + 再レビュー必須 |

## アドホックなデフォルト

重大度ティアが指定されていない場合、Apothem は **PERSONAL_USE** を
デフォルトとします。

## 実用最小限のガバナンス

EXPLORING においても、ティアにかかわらず 3 つの横断的マンデートが常に適用されます:
- CM-1(批判的評価)
- CM-5(最良解)
- CM-10(容赦ない誠実さ)

## ティアの昇格

重大度ティアはプロジェクトの途中で昇格させることができます。PERSONAL_USE の
プロジェクトが SHARED へと格上げされる際は、ローカルのリリース準備スイープを
完全に実行し、より低いティアで蓄積したガバナンス上のギャップを洗い出してください。
