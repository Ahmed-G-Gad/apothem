これは、何もない状態から検証済みのハーネス構成に至る最短経路です。インストールし、共有プロファイルを作成し、1 つのツールのネイティブ設定をマテリアライズし、それを確認し、最初の編集を行います。
すべてのコマンドは実在し、コピー＆ペーストでそのまま実行でき、各ステップはクリーンな実行で何が出力されるかを示します。
インストール自体は 2 分未満で完了します。プロファイルの編集は、あなたが望むだけの時間がかかる唯一の部分です。

終わるころには、あなたが書いたプロファイルから生成された、動作するハーネス構成が手元にあります — そして、プロファイルの変更をすべてのツールへ送り出し直す 1 つのコマンドも分かるようになります。

<Callout title="説明付きの、ゆっくり進む版が必要ですか？">
  [入門チュートリアル](/docs/tutorials/getting-started)は、同じ範囲を、各ステップとそれが重要な理由をより詳しく説明しながら進みます。
  このページは、簡潔で出力を主体としたツアーです。
</Callout>

例のハーネスとして **Claude Code** を使います — これはインストーラーのデフォルトです。
別のツールを対象にするには、どのステップでもアダプター名を差し替えてください。サポートされているすべての名前は[ハーネス一覧](/docs/harnesses)にあります。

## 1. Apothem をインストールする

Apothem は自己完結型ランタイムとして出荷されます — エンジンは、ベンダリングされた依存関係とともに、そのソースツリーから直接実行されます。
1 つのコマンドがソースを取得し、エンジンを配置し、最初のハーネスをマテリアライズします。

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 7+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

インストーラーには、`click` と `rich` をインポートできるシステムの Python 3.10+ と、ネットワーク形式の場合はさらに `git` が必要です。
インストーラーは前提条件をチェックし、エンジンを `~/.apothem` 配下に配置し、完了時にあなたのシェル向けの正確なエンジン呼び出しを出力します。

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="プロファイルなしでの初回実行">
  まだプロファイルがない場合、インストーラーはサンプルプロファイルを `~/.config/apothem/profile.yaml` にコピーし、そのまま続行します。同じ実行の中で最初のハーネスをマテリアライズし、それを検証します。
  サンプルの識別情報フィールドはプレースホルダーであるため、インストールは注意書きを出力します。
  ステップ 2 でプロファイルを自分のものにし、ステップ 5 と同様に `apothem update --harness <name>` で適用してください。
</Callout>

<Callout title="`apothem` コマンド">
  インストーラーは `apothem` の shim を `PATH` 上に配置するため、エンジンを `apothem <command>` として直接実行します。
  shim のディレクトリがまだ `PATH` 上にない場合、バナーは shim を必要としない自己完結型のフォールバック — `PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>` — を出力します。各コマンドの前に、バナーが出力した正確なプレフィックスを付けてください。
</Callout>

[インストールガイド](/docs/install)は、環境変数のオプションとあわせて、その他のインストール経路 — Claude Code プラグイン（`/plugin marketplace add ahmed-g-gad/apothem` の後に `/plugin install apothem@apothem`）、VS Code 系およびその他のツールネイティブな拡張機能、そしてオンデマンドの npx 形式（`npx @ahmed-g-gad/apothem <command>`） — を扱います。

## 2. 共有プロファイルを作成する

`apothem profile init` は、スキーマ上有効な最小のプロファイルを `~/.config/apothem/profile.yaml` に書き込みます。
プロジェクト固有または CI 固有のプロファイルを別の場所に置いている場合は、`--profile PATH` を渡します。

```bash
apothem profile init
apothem profile show --json
```

このスキャフォールドは架空のプレースホルダーの識別情報を使用しており、ハーネスの出力をインストールする前に編集しても安全です。
`show --json` はそれを読み戻し、検証済みのプロファイルを報告します。

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

不正な形式の編集が表面化するのもここです — YAML が無効な場合、ハーネス設定が書き込まれる前に、`show` がここでそれを報告します。
`apothem profile edit`（エディターでプロファイルを開きます）でプロファイルを自分のものにするか、1 つのキーをその場で設定します。

```bash
apothem profile set identity.name "Your Name"
```

## 3. ハーネスアダプターをインストールする

主に使うハーネスのアダプターをマテリアライズします。
これはあなたのプロファイルを読み取り、そのツールのネイティブ設定を書き込みます。

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

プロジェクトスコープのアダプターは、ホームディレクトリではなくプロジェクトの内部に書き込むため、`--project PATH` が必要です。
`--dry-run` を使うと、ファイルを書き込まずに任意のインストールをプレビューできます。

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

`--harness all` で、レジストリに基づくセット全体を一度にインストールします。
この選択はプロジェクトスコープとユーザースコープの両方のファイルを書き込むため、コマンドは具体的な書き込み先を場所ごとにグループ化して出力し、プロジェクトルートの外へ書き込む前に確認を求めます。

```bash
apothem install --harness all --project .
```

サポートされているすべての名前は[ハーネスの完全な一覧](/docs/harnesses)を、オプションの全体は [install リファレンス](/docs/cli-reference/install)を参照してください。

## 4. 検証する

マテリアライズは仕事の半分にすぎません — `verify` は、ハーネスに期待される設定ファイルが配置され、プロファイルの宣言内容と一致していることを確認します。

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

`verify` は、設定が存在しない、またはドリフトしている場合に非ゼロで終了するため、セットアップスクリプトのゲートとしても機能します。
登録済みのすべてのアダプターを対象とする、マシン全体のヘルスチェックを行うには、次を実行します。

```bash
apothem doctor
```

`doctor` はインストール済みのすべてのハーネスをチェックします。各ハーネスは検証に合格しなければならず、そのインストールが登録した各フックコマンドは起動しなければなりません。
インストールしていないハーネスは一覧に表示されますが失敗にはならないため、正常なハーネスが 1 つある状態で `doctor` は 0 で終了します。

## 5. 初回実行

設定したばかりのハーネス — この例では Claude Code — を開き、任意のプロジェクトでセッションを開始します。
ステップ 2 でプロファイルに書いたルールと設定は、いまやそのツールの振る舞いの一部です。
これが動作する初回実行です。1 つのプロファイルが、実際のセッションを形作っています。

後でプロファイルを変更したときは、再インストールせずに再適用します。

```bash
apothem update --harness claude-code
```
