## 最初にハーネス設定を削除する

このページで使われている素の `apothem` コマンドは、ワンショットインストーラー（[インストールガイド](/docs/install)のチャネル 3）が書き込むシムです。そのシムのディレクトリが `PATH` に含まれていれば実行できます。その他のインストールチャネルでは、インストールガイドに記載されているとおり、`apothem` を `npx @ahmed-g-gad/apothem` に置き換えてください。

Apothem をアンインストールする前に、各ハーネスアダプターの設定を削除して、ハーネスをクリーンな状態にしておきます。
`apothem harnesses list` を実行して現在どのアダプターがインストールされているかを確認し、それらを 1 つずつ削除するか、レジストリ全体のセレクターを使用します。

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness cursor --project /path/to/project
apothem uninstall --harness all --project /path/to/project --yes
```

ハーネスごとの確認プロンプトをスキップするには `--yes` を渡します。

## エンジンを削除する

削除方法は、使用したインストールチャネルに対応します。チャネル番号は、[インストールチャネルの表](/docs/install#チャネルを選ぶ)のものです。

- **Claude Code プラグイン（チャネル 1）** — Claude Code 内からプラグインを削除します：`/plugin uninstall apothem@apothem`（マーケットプレイスのエントリーは `/plugin marketplace remove ahmed-g-gad/apothem` で削除できます）。
- **npx（チャネル 2）** — 削除するものはありません。`npx` はそのキャッシュから実行されます。キャッシュされたコピーを消去したい場合は、`npm cache clean --force` を実行してください。
- **ワンショットインストーラー（チャネル 3）** — チェックアウトから、対応するアンインストールスクリプトを実行します：POSIX では `scripts/installer/uninstall.sh`、PowerShell では `scripts/installer/uninstall.ps1` です。各スクリプトは、`--harness`（PowerShell では `-Harness`）で指定されたハーネスを削除します。指定がない場合は `APOTHEM_HARNESS` を使い、それもない場合は Claude Code を削除します。`apothem` コマンドのシムも削除します。ソースは、`APOTHEM_SOURCE` が設定されていればそこから、そうでなければ `APOTHEM_HOME`（デフォルトは `$HOME/.apothem`）から取得されます。ソースは、`--remove-source`（PowerShell では `-RemoveSource`）を渡さない限り残ります。このフラグが削除するのは `APOTHEM_HOME` にある管理対象のクローンだけであり、それも `.git` ディレクトリがある場合に限られます。デフォルトの場所を使う場合は、`~/.apothem/` 配下のインストールバックアップと台帳も削除されます。どちらのスクリプトも、ハーネス設定とソースを削除する前に確認を求めます。`--yes`（PowerShell では `-Yes`）を指定すると確認をスキップします。どちらも安全でない対象を拒否します。
- **VS Code 系拡張機能（チャネル 4）** — まず、コマンドパレットから **Apothem: Uninstall** を実行してハーネス設定を削除します。その後、拡張機能ビューから、または `code --uninstall-extension ahmed-g-gad.apothem-vscode` で拡張機能を削除します（以前の `apothem.vsix` からインストールしたコピーは `ahmed-g-gad.apothem` です）。デフォルトでは、拡張機能は `npx` を介してエンジンを実行するため、キャッシュについては上の **npx** の項目が該当します。
- **コマンドラインのブートストラップ（チャネル 5–7）** — ハーネス設定が削除された後で、ホストツールを使って拡張機能またはプラグインを削除します。ホストは次のとおりです：

  ```text
  channel 5   Gemini CLI extension
  channel 6   Qwen Code extension
  channel 7   Codex plugin
  ```

  ブートストラップが追加するのは、`npx` を介してエンジンを呼び出すアシスタントのコンテキスト（コンテキストファイル、コマンド、またはスキル）だけであるため、それ以外に残るものはありません。
  チャネル 5 と 6 の拡張機能ホストにはアンインストールコマンドがあります。チャネル 7 のプラグインホストでは、そのプラグインブラウザーで `apothem` をアンインストールします。

  ```bash
  gemini extensions uninstall apothem   # channel 5
  qwen extensions uninstall apothem     # channel 6
  ```
- **直接エンジン（チャネル 8）** — アンインストールするものはありません。ハーネス設定を削除した後で、クローンを削除します。
- **バックアップと状態** — インストールのバックアップは `~/.apothem/backups/` 配下に、インストール台帳は `~/.apothem/state/` 配下にあります。
  どちらも上限内に保たれます。インストール、アンインストール、ロールバックのたびに、Apothem はインストールルートごとに最新 10 件のインストール記録と、ハーネスごとに最新 10 件のバックアップセットを保持し、保持された記録がまだ必要とするバックアップは決して削除しません。そのため、直近 10 回のインストールは引き続きロールバックできます。
  保持数を減らすには [`apothem backups prune --keep N`](/docs/cli-reference/backups) を実行します（何が削除されるかを先に確認するには `--dry-run` を追加します）。このコマンドは、ハーネスの最新のインストールをロールバックする際の復元元となるバックアップを決して削除しません。
  エンジンを削除し、履歴がまったく不要になったら、`~/.apothem/` を削除してください。

## 削除されないもの

- `~/.config/apothem/profile.yaml` または `--profile PATH` にある共有プロファイル YAML は、`apothem uninstall` によって削除されることは決してありません。
- ハーネスディレクトリ内の、無関係なオペレーター作成のファイルは保持されます。
- 共有の設定ファイルにあなたが追加したエントリは保持されます。あなた自身の権限ルール、MCP サーバー、フックハンドラーはそのまま残ります。
  アンインストールが削除するのは、インストール台帳が Apothem のものとして記録しているキーとリストエントリだけです（[設定](/docs/reference/settings#自分の設定ファイルへのマージ)を参照）。
- インストールルートの `.apothem/` 配下にある共有データストア（`memory/`、`contexts/`、`learning/`）は、同じルートにある別のインストール済みハーネスがまだそれらを使用している間は残ります。
  そのルートで最後のハーネスをアンインストールすると、各ストアをまず `~/.apothem/backups/` にコピーしてから、中身ごと削除します。
- `<project>/.apothem/plans/`（およびレガシーの `<project>/.plans/`）配下のプランスイートは影響を受けません。

## ディレクトリ

アンインストールは、インストールが作成したディレクトリ（たとえば、最初のインストールの前には存在しなかった `~/.claude/`）も、空になった時点で削除します。
あなたのファイル、または別のインストール済みハーネスが使用するデータがまだ残っているディレクトリは、そのまま残ります。
インストールの前から存在していたディレクトリが削除されることは決してありません。

ハーネスルートを完全にクリーンアップするには、保持したいカスタムルール、ヘルパー、プロファイルファイルをバックアップしたことを確認したうえで、[ハーネスリファレンスページ](/docs/harnesses)に記載されているハーネスネイティブのパスを削除してください。
