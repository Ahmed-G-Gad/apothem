Cursor は `.cursor/rules/` 下の MDC 形式でルールを読み取ります。MDC 形式は
frontmatter フィールド——`description`、`globs`、`alwaysApply`——を要求します。
Apothem の cursor アダプターは、共有プロファイルから `.mdc` ルールファイルを 1 つ
レンダリングします。本ページは、その構成を手作業で維持することと、Apothem で
管理することとを対比します。

## 労力の比較

| タスク | 手作業の構成 | Apothem 管理 |
| ---- | --------------- | --------------- |
| ルールを書く | `.cursor/rules/` 配下の各 `.mdc` ファイルを手で書く | 共有コーパスからレンダリング |
| MDC の frontmatter を書く | ファイルごとに `description` / `globs` / `alwaysApply` を手で書く | アダプターが生成 |
| ルール形式を 1 つに保つ | MDC ルールと単一の `.cursorrules` ファイルの間で手作業で選ぶ | アダプターは MDC ファイル `.cursor/rules/apothem-rules.mdc` を 1 つ書き込み、`.cursorrules` は書き込まない |
| ルールを他のハーネスと揃えて保つ | 手作業、ツールごと | `apothem update` で自動 |
| 再利用可能なスキルとコマンドを共有する | 各スキルフォルダーを `~/.agents/skills/` へ手でコピーし、コピーを最新に保つ | アダプターが `~/.agents/skills/` に書き込み、すべてのプロジェクトで 1 つのコピーを共有し、`apothem update` で更新 |
| 構成が正しいか検証する | 手作業での確認 | `apothem verify --harness cursor --project <path>` |

## Apothem が管理するもの

cursor アダプターは共有ルールを 1 つの `.mdc` ファイル
`<project>/.cursor/rules/apothem-rules.mdc` へレンダリングし、必要な MDC
frontmatter（`description`、`globs`、`alwaysApply`）を生成します。アダプターは
Cursor が読み取るディレクトリベースの MDC 形式だけを書き、単一ファイルの
`.cursorrules` は書きません。また、スキルと、スキルとしてラップしたコマンドを
`~/.agents/skills/` へ、それらのスキルが参照するルールとテンプレートを
`~/.config/apothem/` へ書き込みます。どちらもあなたのホームディレクトリにあります。
Cursor は、フックを `hooks.json` ファイルで、またプラグイン形式を通じて文書化して
います。アダプターはプラグインを構築しません。プロジェクトの `.cursor/hooks.json` に、
セッションブートストラップを読み込む `sessionStart` エントリを 1 つ追加し、あなた自身の
エントリはそのまま残します。ツール呼び出しのガードは登録しないため、ガードレールの
意図はルールの散文の中に存在します。

## 移行手順

1. まだ作成していなければ、`apothem profile init` を実行して共有プロファイルを作成します。
2. 既存の `.cursor/rules/`（および任意の `.cursorrules`）のルールを、共有コーパスへ移します。
3. `apothem install --harness cursor --project <path>` を実行して、正しい MDC frontmatter を持つ `apothem-rules.mdc` をレンダリングします。
4. `apothem verify --harness cursor --project <path>` を実行して、構成が配置されたことを確認します。
5. 以降の変更には毎回 `apothem update --harness cursor --project <path>` を使います。
