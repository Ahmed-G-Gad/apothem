Windsurf は `.devin/rules/` ディレクトリからルールを読み込みます。Apothem の
windsurf アダプターは、ディレクトリベースのルールを共有プロファイルから
レンダリングします。このページでは、その構成を手作業で保守する場合と apothem で
管理する場合を対比します。

## 手間の比較

| タスク | 手作業の構成 | Apothem 管理 |
| ---- | --------------- | --------------- |
| ルールを書く | `.windsurf/rules/` 配下の各ファイルを手で書く | 共有コーパスからレンダリング |
| ルール形式を 1 つに保つ | `.windsurf/rules/` と単一ファイルの `.windsurfrules` のどちらかを手で選ぶ | アダプターが書き込むのは `.devin/rules/` のみ |
| ルールを他のハーネスと揃えて保つ | 手作業、ツールごと | `apothem update` で自動 |
| 構成が正しいか検証する | 手作業での確認 | `apothem verify --harness windsurf --project <path>` |

## apothem が管理するもの

windsurf アダプターは共有ルールを `.devin/rules/` ディレクトリへ
レンダリングし、単一ファイルの `.windsurfrules` は書き込みません。Windsurf には
PreToolUse フックがないため、ガードレールの意図はツール呼び出しの傍受地点では
なくルールの文章の中に存在します。共有ルールへの変更はすべて、次の
`apothem update` でディレクトリを再レンダリングします。

## 移行パス

1. まだ作成していなければ、`apothem profile init` を実行して共有プロファイルを作成します。
2. 既存の `.windsurf/rules/`（および任意の単一ファイル `.windsurfrules`）からルールを、共有コーパスへ移します。
3. `apothem install --harness windsurf --project <path>` を実行して、`.devin/rules/` ディレクトリをレンダリングします。
4. `apothem verify --harness windsurf --project <path>` を実行して、構成が配置されたことを確認します。
5. 以降の変更には毎回 `apothem update --harness windsurf --project <path>` を使います。
