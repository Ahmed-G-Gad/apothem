CodeBuddy は、プロジェクトのルールを `.codebuddy/rules/*.md` から読み込みます。これらのファイルは、プロジェクトごとに、いつまでも手作業で作成できます。Apothem の codebuddy アダプターは、共有プロファイルからそのうちの一つをレンダリングし、すべてのハーネスとすべてのプロジェクトにわたって一貫性を保ちます。このページでは、その設定を手作業で管理する場合と、Apothem で管理する場合を比較します。

## 作業量の比較

| タスク | 手作業の設定 | Apothem で管理 |
| ---- | --------------- | --------------- |
| ルールを作成する | 同じ規律を、プロジェクトごとに `.codebuddy/rules/` へコピー＆ペーストする | 共有コーパスからレンダリングされる |
| 正とする情報源 | 各プロジェクト独自のファイル | 正規のコホートが一つ |
| ルールをハーネス間で揃えて保つ | ツールごとに導き直す | 自動的に投影される |
| ルールを更新する | すべてのプロジェクトを手作業で編集する | `apothem update --harness codebuddy --project <path>` |
| 設定を削除する | 手作業で削除 | タイムスタンプ付きバックアップを取って `apothem uninstall` |
| 再利用可能なスキルとコマンドを共有する | 各スキルフォルダーを `~/.codebuddy/skills/` へ手作業でコピーし、コピーを最新に保つ | アダプターが `~/.codebuddy/skills/` に書き込み、すべてのプロジェクトで 1 つのコピーを共有し、`apothem update` で更新される |

## Apothem が管理する対象

codebuddy アダプターは、共有ルールを専用ファイル `<project>/.codebuddy/rules/apothem-rules.md` にレンダリングします。また、すべてのプロジェクトが共有する 2 つのフォルダーをホームディレクトリに書き込みます。スキルと、スキルとしてラップしたコマンドは `~/.codebuddy/skills/` へ、それらのスキルが参照するルールとテンプレートは `~/.config/apothem/rules/` と `~/.config/apothem/templates/` へ書き込まれます。`CODEBUDDY.md` のメモリファイル、`.codebuddy/settings.json` の権限と MCP サーバー、作成したその他のルールファイルは、すべてオペレーターが所有したままです。アダプターはこれらの面を認識しますが、編集することは決してありません。共有ルールへの変更はすべて、次の `apothem update` の際にルールファイルを再レンダリングします。

## 移行の手順

1. まだの場合は、`apothem profile init` を実行して共有プロファイルを作成します。
2. 既存の `.codebuddy/rules/` ファイルにある規律を、
   共有コーパスへ移します。
3. `apothem install --harness codebuddy --project <path>` を実行して、手を加えていない自分のルールと並べて `apothem-rules.md` ファイルをレンダリングします。
4. `apothem verify --harness codebuddy --project <path>` を実行して、設定が配置されたことを確認します。
5. 以降の変更はすべて `apothem update --harness codebuddy --project <path>` を使います。
