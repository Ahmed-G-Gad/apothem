Kiro は Markdown ファイルの `.kiro/steering/` ディレクトリからステアリングを読み取り
ます。Apothem の kiro アダプターは、共有プロファイルから専用の `apothem-rules.md`
ステアリングファイルをレンダリングします。本ページは、その構成を手作業で維持するのと
Apothem で管理するのとを対比します。

## 労力の比較

| タスク | 手作業の構成 | Apothem 管理 |
| ---- | --------------- | --------------- |
| ステアリングルールを書く | `.kiro/steering/` 配下の各ファイルを手で書く | 共有コーパスからレンダリング |
| 基盤ファイルに触れずに保つ | `product.md` / `tech.md` / `structure.md` を上書きしないよう注意する | アダプターが書き込むのは `apothem-rules.md` のみ |
| ルールを他のハーネスと揃えて保つ | 手作業、ツールごと | `apothem update` で自動 |
| 構成が正しいか検証する | 手作業での確認 | `apothem verify --harness kiro --project <path>` |

## Apothem が管理するもの

kiro アダプターは共有ルールを `inclusion: always` フロントマター付きの専用
`apothem-rules.md` ステアリングファイルへレンダリングし、Kiro の操作者が作成した
基盤ファイルには触れません。Kiro には PreToolUse フックがないため、ガードレールの
意図はツール呼び出しの傍受点ではなくルールの散文に宿ります。共有ルールへの変更が
あるたびに、次の `apothem update` でファイルが再レンダリングされます。

## 移行手順

1. まだ作成していなければ、`apothem profile init` を実行して共有プロファイルを作成します。
2. 既存の `.kiro/steering/` のルールを、共有コーパスへ移します。
3. `apothem install --harness kiro --project <path>` を実行して、`apothem-rules.md` ステアリングファイルをレンダリングします。
4. `apothem verify --harness kiro --project <path>` を実行して、構成が配置されたことを確認します。
5. 以降の変更には毎回 `apothem update --harness kiro --project <path>` を使います。
