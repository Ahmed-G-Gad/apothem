Hermes は `~/.hermes/config.yaml` を読み取ります。
Apothem はネイティブの YAML 設定を書き込み（プロファイルの MCP インベントリを `mcp_servers` へ投影します）、共有のコマンドコホートとスキルコホートを `~/.hermes/.apothem/support/skills/` 配下にインストールし、Hermes がそれらを読み込むように、そのディレクトリを `skills.external_dirs` に列挙します。
Hermes 自身の `skills.config` はスキルごとの設定を保持するため、Apothem はそれを作成しません。

## ステータス

**プレビュー。** Hermes アダプターは、現在ドキュメント化されている設定ファイルとスキル探索の面を対象とします。
スキル以外のコホートは、Apothem のサポート素材のままです。

## 労力の比較

| タスク | 素の手作業設定 | Apothem 管理 |
| ---- | --------------- | --------------- |
| 再利用可能なスキルを作成する | 設定とスキルディレクトリを手作業で編集 | 共有コーパスに一度だけ書く |
| コホートを他のハーネスと揃えておく | ツールごとに手動 | `apothem update` で自動 |
| 設定をインストール／削除する | 手動 | `apothem install` / `apothem uninstall` |
| 設定が正しいことを検証する | 手動での確認 | `apothem verify --harness hermes` |

## Apothem が管理するもの

Hermes アダプターは `config.yaml` を書き込み、Apothem のスラッシュコマンドをスキルとしてラップし、Apothem のスキルをサポートディレクトリへコピーし、ルール、テンプレート、エージェント、フックの素材を Apothem のサポートサブツリー配下に保持します。
また、`~/.hermes/.apothem/support/skills` を `config.yaml` の `skills.external_dirs` に追加し、Hermes がそれらのスキルを読み込むようにします。
このリストは Hermes が文書化している優先順位の最後に位置するため、あなたのプロジェクト内または `~/.hermes/skills/` にある同じ名前のスキルが、Apothem のコピーより優先される可能性が高いです。確認した Hermes のドキュメントには、衝突時の規則は記載されていません。

## 移行パス

1. まだ作成していない場合は、`apothem profile init` を実行して共有プロファイルを作成します。
2. 再利用可能な Hermes のスキルやコマンドプロンプトを共有コーパスへ移します。
3. `apothem install --harness hermes` を実行して、サポートスキルディレクトリを `skills.external_dirs` に列挙するネイティブ設定をレンダリングし、スキルをインストールします。`apothem update` は、あなたが `config.yaml` に追加したキーを保持します。
4. `apothem verify --harness hermes` を実行して、設定が配置されたことを確認します。
