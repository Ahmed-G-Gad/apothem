Apothem सत्रह अंतर्निहित हार्नेस अडैप्टर के साथ आता है। प्रत्येक अडैप्टर
उन्हीं साझा समूह को प्लेटफ़ॉर्म-मूल फ़ाइलों में अनुवादित करता है जहाँ प्लेटफ़ॉर्म उनका समर्थन
करता है, और जहाँ नहीं करता वहाँ Apothem-स्वामित्व वाले समर्थन वृक्ष में।

## समर्थित हार्नेस

समर्थित रजिस्ट्री में ठीक सत्रह अडैप्टर हैं। `--harness` के साथ इन्हीं सटीक
इंस्टॉल नामों का उपयोग करें, या नियतात्मक रजिस्ट्री
समुच्चय के लिए `all` का उपयोग करें:

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

विस्तृत रजिस्ट्री मैट्रिक्स, लक्ष्य पथ, क्षमता अवस्थाएँ, MCP समर्थन,
और कन्वेंशन-पिन साक्ष्य [तकनीकी रजिस्ट्री संदर्भ](/docs/reference/harness-registry) में हैं।

## एकाधिक हार्नेस इंस्टॉल करें

एक हार्नेस इंस्टॉल करें, या रजिस्ट्री को नियतात्मक
क्रम में चुनने के लिए `all` का उपयोग करें। प्रोजेक्ट-स्कोप हार्नेस के लिए `--project PATH` आवश्यक है; इसमें `all`
भी शामिल है क्योंकि रजिस्ट्री में यूज़र-स्कोप और प्रोजेक्ट-स्कोप दोनों लक्ष्य शामिल हैं।

```bash
apothem install --harness claude-code
apothem install --harness cursor --project /path/to/project
apothem install --harness gemini-cli --project /path/to/project
apothem install --harness all --project /path/to/project
```

## अपने इंस्टॉल सत्यापित करें

प्रत्येक हार्नेस अडैप्टर को अलग-अलग सत्यापित करें, या हर पंजीकृत अडैप्टर में
प्रति-अडैप्टर इंस्टॉल-स्थिति सारांश के लिए `apothem doctor` को कॉल करें:

```bash
apothem verify --harness claude-code
apothem verify --harness all --project /path/to/project
apothem doctor
```

## अडैप्टर कैसे काम करते हैं

प्रत्येक अडैप्टर setuptools एंट्री-पॉइंट्स के माध्यम से पंजीकृत `HarnessAdapter`
प्रोटोकॉल को लागू करता है। इंस्टॉल पर, CLI साझा
YAML प्रोफ़ाइल को लोड और सत्यापित करता है, रजिस्ट्री के माध्यम से अडैप्टर को रिज़ॉल्व करता है,
मूर्तीकरण योजना को सत्यापित करता है, और प्लेटफ़ॉर्म-मूल कॉन्फ़िग को हार्नेस के
मूल यूज़र या प्रोजेक्ट स्थान पर लिखता है। अपडेट पर, यह वर्तमान
प्रोफ़ाइल स्थिति से फिर से व्युत्पन्न करता है।

```
profile.yaml + packaged cohorts
    identity / preferences / rules
    commands / skills / delegated definitions / hooks / templates
         |
         +-- antigravity    --> ~/.gemini/GEMINI.md + ~/.gemini/antigravity-cli/plugins/apothem/
         +-- claude-code    --> ~/.claude/ native folders + ~/.claude/.apothem/support/
         +-- codex          --> ~/.codex/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- cursor         --> <project>/.cursor/rules/*.mdc + <project>/.cursor/agents/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- gemini-cli     --> <project>/GEMINI.md + <project>/.gemini/
         +-- github-copilot --> <project>/.github/copilot-instructions.md + <project>/.github/agents/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- windsurf       --> <project>/.devin/rules/ + <project>/.devin/agents/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- ...
```

## आपकी होम डायरेक्टरी में स्किल

सात प्रोजेक्ट-स्कोप अडैप्टर आपके प्रोजेक्ट में एक नियम फ़ाइल लिखते हैं (उनमें से छह
Apothem के सहायकों को भी वहाँ सबएजेंट फ़ाइलों के रूप में लिखते हैं; हर हार्नेस पेज
फ़ोल्डर का नाम बताता है), और वे Apothem की स्किल, और स्किल जिन नियमों और टेम्पलेट
का हवाला देती हैं, उन्हें भी आपकी होम डायरेक्टरी के फ़ोल्डरों में लिखते हैं:

```text
cursor, github-copilot, windsurf, zed  ->  ~/.agents/skills/ (codex writes it too)
codebuddy                               ->  ~/.codebuddy/skills/
kiro                                    ->  ~/.kiro/skills/
trae                                    ->  ~/.trae/skills/
all seven                               ->  ~/.config/apothem/rules/ and templates/ (codex uses them too)
```

- फ़ोल्डर का नाम लेने वाला हर इंस्टॉल वही फ़ाइलें लिखता है, इसलिए आप किस क्रम में
  इंस्टॉल करते हैं इससे फ़र्क नहीं पड़ता, और एक ही प्रति हर प्रोजेक्ट की सेवा करती है।
- इंस्टॉल पहले होम फ़ोल्डर लिखता है। यदि यह विफल होता है, तो वह प्रोजेक्ट बदलने से
  पहले रुक जाता है, और वह आपकी रिपॉज़िटरी में कोई स्किल या नियम फ़ाइल नहीं जोड़ता।
- अनइंस्टॉल किसी साझा फ़ोल्डर को केवल तभी हटाता है जब कोई अन्य Apothem इंस्टॉल अब भी
  उसका उपयोग न कर रहा हो, और बताता है कि कौन-सा इंस्टॉल उसे रखे हुए है।
- Apothem स्किल के नाम वाला कोई स्किल फ़ोल्डर जिसे Apothem ने नहीं लिखा, एक चेतावनी
  के साथ छोड़ दिया जाता है।

हर हार्नेस पेज अपने फ़ोल्डर सूचीबद्ध करता है।
[हार्नेस रजिस्ट्री](/docs/reference/harness-registry#साझा-रूट) दिखाती है कि कौन-से
टूल कौन-सा फ़ोल्डर साझा करते हैं।

प्रोटोकॉल विनिर्देश के लिए [हार्नेस अडैप्टर एब्स्ट्रैक्शन](/docs/architecture/harness-adapter-abstraction)
देखें।
