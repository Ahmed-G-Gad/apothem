**विक्रेता:** Anthropic
**इंस्टॉल नाम:** `claude-code`
**स्थिति:** GA
**नेटिव कॉन्फ़िग:** `~/.claude/`

## इंस्टॉलेशन

```bash
apothem install --harness claude-code
```

`claude-code` अडैप्टर साझा Apothem कॉर्पस को Claude Code के नेटिव डिस्कवरी ट्री
में इंस्टॉल करता है। Markdown एजेंट, नियम, स्किल, आउटपुट स्टाइल, और सेटिंग्स अपने
नेटिव स्थानों पर इंस्टॉल होते हैं; कमांड प्रॉम्प्ट स्किल में परिवर्तित किए जाते
हैं ताकि पुनः प्रयोज्य वर्कफ़्लो वर्तमान Claude Code स्किल सतह के माध्यम से
दृश्यमान बने रहें। स्टेटसलाइन रेंडरर `~/.claude/statuslines/` में कॉपी किया जाता
है, लेकिन जोड़ा नहीं जाता: Claude Code अपनी स्टेटस लाइन `statusLine` सेटिंग से
पढ़ता है, जिसे अडैप्टर अनसेट छोड़ देता है। इसे चालू करने के लिए, `settings.json`
में `"type": "command"` वाली एक `statusLine` प्रविष्टि जोड़ें जो
`~/.claude/statuslines/render.py` चलाती है।

**लिखी गई फ़ाइलें:** `~/.claude/` के अंतर्गत `settings.json`, `CLAUDE.md` में
Apothem ब्लॉक, `agents/`, `rules/`, `skills/`, `statuslines/`, `output-styles/`,
और `.apothem/support/` समर्थन उप-वृक्ष (`.apothem/support/hooks/`,
`.apothem/support/conformity/`, `.apothem/support/schemas/`,
`.apothem/support/templates/`)।
कमांड फ़ाइलें चाइल्ड स्किल डायरेक्टरियों में परिवर्तित की जाती हैं। हुक
डिस्पैचर और अनुरूपता गेट अपनी मूर्त प्रतियों से चलते हैं — `settings.json` की हुक
प्रविष्टियाँ `~/.claude/.apothem/support/hooks/dispatch.py` और
`~/.claude/.apothem/support/conformity/gate.py` को निरपेक्ष पथ से इनवोक करती हैं,
इसलिए होस्ट पर किसी आयात-योग्य `apothem` पैकेज की आवश्यकता नहीं होती।

`~/.claude/CLAUDE.md` ऑपरेटर-स्वामित्व वाली बनी रहती है। अडैप्टर उसमें
सेंटिनल-सीमांकित एक Apothem ब्लॉक लिखता है, जिसमें प्रोफ़ाइल प्रक्षेपण (पहचान,
प्राथमिकताएँ, नियम, गंभीरता, और ऑप्ट-इन किए गए व्यवहार) और एक Apothem समर्थन
फ़ाइल अनुभाग होता है, और सेंटिनलों के बाहर की हर पंक्ति को शब्दशः संरक्षित रखता
है। समर्थन फ़ाइल अनुभाग इंस्टॉल किए गए नियमों, स्किल, और एजेंटों में प्रत्येक
रिपॉज़िटरी-शैली उद्धरण के लिए वह निरपेक्ष डायरेक्टरी बताता है जिसके सापेक्ष वह
उद्धरण हल होता है: `rules/<name>.md` `~/.claude/rules/` के अंतर्गत, और
`templates/...`, `schemas/...`, `hooks/...`, तथा `conformity/...`
`~/.claude/.apothem/support/` के अंतर्गत। Apothem शासन सतह का शेष भाग प्रसारित
`rules/` वृक्ष और SessionStart हुक के माध्यम से Claude Code तक पहुँचता है। जब कोई
`~/.config/opencode/AGENTS.md` मौजूद नहीं होती, तब OpenCode भी
`~/.claude/CLAUDE.md` लोड करता है, इसलिए यह ब्लॉक किसी एक टूल को अपने पाठक के
रूप में नामित नहीं करता।

## प्रोफ़ाइल-से-नेटिव-कॉन्फ़िग मैपिंग

प्रत्येक `apothem install` या `apothem update` पर, अडैप्टर साझा `apothem` कॉर्पस
को प्रसार मैनिफ़ेस्ट के अनुसार `~/.claude/` में प्रसारित करता है। अडैप्टर जहाँ
संभव हो वहाँ नेटिव डायरेक्टरियों का सीधे उपयोग करता है और कमांड प्रॉम्प्ट को
स्किल फ़ोल्डरों में परिवर्तित करता है। मेल खाने वाले मौजूदा Apothem-प्रबंधित
चाइल्ड प्रतिस्थापन से पहले बैकअप किए जाते हैं; असंबंधित ऑपरेटर-लिखित प्रविष्टियाँ
संरक्षित रहती हैं। `settings.json` को मर्ज किया जाता है ताकि ऑपरेटर-लिखित
कुंजियाँ पुनर्प्राप्त करने योग्य बनी रहें।

इंस्टॉल किए गए स्किल, और Claude Code प्लगइन में बंडल किए गए स्किल, स्रोत कॉर्पस
के `userInvocable` के बजाय `user-invocable` रखते हैं, क्योंकि Claude Code केवल
हाइफ़न-युक्त कुंजी पढ़ता है। दो टेम्पलेट कंटेनर (`plan-suite`, `research-suite`)
इसे `false` पर सेट करते हैं, ताकि वे `/` मेनू से बाहर रहें। हर आउटपुट स्टाइल
`keep-coding-instructions: true` सेट करती है, ताकि किसी एक को चुनने पर Claude Code
के अंतर्निहित सॉफ़्टवेयर इंजीनियरिंग निर्देश बने रहें।

## संगतता टिप्पणियाँ

कमांड प्रॉम्प्ट स्किल डायरेक्टरियों में परिवर्तित किए जाते हैं; एजेंट, नियम,
स्किल, और आउटपुट स्टाइल जैसे हैं वैसे ही कॉपी किए जाते हैं। इंस्टॉल यह सत्यापित
करता है कि प्रोफ़ाइल सुगठित है और settings.json में सभी हुक बाइंडिंग हल करने
योग्य हैं। अडैप्टर कोई MCP सर्वर प्रविष्टि नहीं लिखता: सर्वरों को
`claude mcp add` से पंजीकृत करें ([MCP सर्वर](/docs/reference/mcp) देखें)।

Claude Code हर सत्र आरंभ पर settings.json में सभी हुक बाइंडिंग लागू करता है। प्रत्येक अडैप्टर अपने स्वयं के नेटिव हार्नेस के विरुद्ध सत्यापित होता है — कोई विशेषाधिकार-प्राप्त "संदर्भ" हार्नेस नहीं है।

### अनुमति नियम सीमाएँ

सेटिंग्स टेम्पलेट `.env*` और `~/.ssh/**` जैसे सीक्रेट और कैश पथों पर
`Read(...)` अस्वीकार करता है। Claude Code `Read` अस्वीकार को अपने फ़ाइल टूल्स पर,
Bash में अपने द्वारा पहचाने जाने वाले फ़ाइल कमांडों (`cat`, `head`, `tail`, `sed`,
`tee`) पर, और रीडायरेक्शन लक्ष्यों पर लागू करता है। यह अस्वीकार को ऐसी खोज पर
लागू नहीं करता जो फ़ाइलों का नाम लिए बिना उन्हें पढ़ती है, जैसे
`grep -r pattern .`, और न ही ऐसी स्क्रिप्ट पर जो फ़ाइलें स्वयं खोलती है
([अनुमति संदर्भ](https://code.claude.com/docs/en/permissions))। macOS, Linux, और
WSL पर, Claude Code `Glob` और `Grep` टूल्स को डिफ़ॉल्ट टूल सेट से बाहर रखता है और
इसके बजाय Bash के माध्यम से खोजता है, इसलिए टेम्पलेट की `Glob` और `Grep` अनुमति
प्रविष्टियाँ केवल वहीं प्रभावी होती हैं जहाँ वे टूल्स मौजूद हों। हर प्रक्रिया को
किसी पथ को पढ़ने से रोकने के लिए, Claude Code सैंडबॉक्स सक्षम करें।

जो स्किल और सहायक परिभाषाएँ `TodoWrite` का नाम लेती हैं, वे `TaskCreate`,
`TaskGet`, `TaskList`, और `TaskUpdate` का भी नाम लेती हैं, क्योंकि Claude Code उन
टूल्स के पक्ष में `TodoWrite` को डिफ़ॉल्ट रूप से बंद रखता है।

## सत्यापन

```bash
apothem verify --harness claude-code
```

verify कमांड पुष्टि करता है कि:

1. नेटिव कॉन्फ़िग अपेक्षित पथ पर मौजूद है।
2. साझा प्रोफ़ाइल के सभी अनिवार्य फ़ील्ड मौजूद हैं।
3. अडैप्टर-विशिष्ट सत्यापन रूटीन सफलता की रिपोर्ट करता है।

## अपडेट करना

```bash
apothem update --harness claude-code
```

वर्तमान साझा प्रोफ़ाइल से नेटिव कॉन्फ़िग को पुनः व्युत्पन्न करता है। इंस्टॉल किए
गए `apothem` पैकेज के अपडेट होने के बाद इसे चलाएँ, ताकि प्रसारित परिपाटी सतह
(एजेंट, नियम, स्किल, स्टेटसलाइन, आउटपुट-स्टाइल) नए संस्करण को प्रतिबिंबित करे।
`CLAUDE.md` में, update केवल उसके सेंटिनलों के बीच के Apothem ब्लॉक को फिर से
लिखता है।

## अनइंस्टॉल करना

```bash
apothem uninstall --harness claude-code
```

अडैप्टर द्वारा लिखी गई नेटिव कॉन्फ़िग फ़ाइलों को हटाता है और `CLAUDE.md` से
Apothem ब्लॉक निकाल देता है, जबकि आपका अपना गद्य अपनी जगह बना रहता है।
इंस्टॉल किया गया `apothem` पैकेज और स्रोत रिपॉज़िटरी अप्रभावित रहते हैं।

## अनुरूपता गेट

```bash
python -m apothem.conformity.gate --all .
```
