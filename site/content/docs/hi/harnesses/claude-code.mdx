**विक्रेता:** Anthropic
**इंस्टॉल नाम:** `claude-code`
**स्थिति:** GA
**नेटिव कॉन्फ़िग:** `~/.claude/`

## इंस्टॉलेशन

```bash
apothem install --harness claude-code
```

`claude-code` एडॉप्टर साझा Apothem कॉर्पस को Claude Code के नेटिव डिस्कवरी ट्री में
इंस्टॉल करता है। Markdown एजेंट, नियम, स्किल, आउटपुट स्टाइल, स्टेटसलाइन हेल्पर, और
सेटिंग्स अपने नेटिव स्थानों पर इंस्टॉल होते हैं; कमांड प्रॉम्प्ट को इसके अतिरिक्त
स्किल के रूप में लपेटा जाता है ताकि पुनः उपयोग योग्य वर्कफ़्लो वर्तमान Claude Code
स्किल सतह के माध्यम से दृश्यमान बने रहें।

**लिखी गई फ़ाइलें:** `~/.claude/` के अंतर्गत `settings.json`, `agents/`, `rules/`,
`skills/`, `statuslines/`, `output-styles/`, और `apothem/` समर्थन उप-ट्री
(`apothem/hooks/`, `apothem/conformity/`, `apothem/schemas/`,
`apothem/templates/`)। कमांड फ़ाइलें चाइल्ड स्किल डायरेक्टरी में परिवर्तित होती हैं।
हुक डिस्पैचर और कन्फ़ॉर्मिटी गेट अपनी मटेरियलाइज़्ड प्रतियों से चलते हैं —
`settings.json` की हुक प्रविष्टियाँ `~/.claude/.apothem/support/hooks/dispatch.py` और
`~/.claude/.apothem/support/conformity/gate.py` को निरपेक्ष पथ द्वारा इनवोक करती हैं, इसलिए
होस्ट पर किसी आयात-योग्य `apothem` पैकेज की आवश्यकता नहीं है।

एडॉप्टर `CLAUDE.md` का प्रबंधन **नहीं** करता — वह फ़ाइल ऑपरेटर के स्वामित्व वाला
क्षेत्र है। Apothem गवर्नेंस सतह मटेरियलाइज़्ड `CLAUDE.md` के माध्यम से नहीं, बल्कि
प्रसारित `rules/` ट्री और SessionStart हुक के माध्यम से Claude Code तक पहुँचती है।

## प्रोफ़ाइल-से-नेटिव-कॉन्फ़िग मैपिंग

प्रत्येक `apothem install` या `apothem update` पर, एडॉप्टर साझा `apothem` कॉर्पस को
प्रसार मैनिफ़ेस्ट के अनुसार `~/.claude/` में प्रसारित करता है। एडॉप्टर जहाँ संभव हो
वहाँ नेटिव डायरेक्टरी का सीधे उपयोग करता है और कमांड प्रॉम्प्ट को स्किल फ़ोल्डर में
परिवर्तित करता है। पहले से मौजूद, Apothem-प्रबंधित मेल खाने वाले चाइल्ड को प्रतिस्थापन
से पहले बैकअप किया जाता है; असंबंधित, ऑपरेटर-रचित प्रविष्टियाँ संरक्षित रहती हैं।
`settings.json` को मर्ज किया जाता है ताकि ऑपरेटर-रचित कुंजियाँ पुनर्प्राप्त करने योग्य
बनी रहें।

## संगतता टिप्पणियाँ

कोई अनुवाद नहीं होता। इंस्टॉल यह सत्यापित करता है कि प्रोफ़ाइल सुगठित है और settings.json में सभी हुक बाइंडिंग हल करने योग्य हैं।

Claude Code प्रत्येक सत्र आरंभ पर settings.json में सभी हुक बाइंडिंग लागू करता है। प्रत्येक एडॉप्टर अपने स्वयं के नेटिव हार्नेस के विरुद्ध सत्यापित होता है — कोई विशेषाधिकार-प्राप्त "संदर्भ" हार्नेस नहीं है।

## सत्यापन

```bash
apothem verify --harness claude-code
```

verify कमांड पुष्टि करता है कि:

1. नेटिव कॉन्फ़िग अपेक्षित पथ पर मौजूद है।
2. साझा प्रोफ़ाइल के सभी अनिवार्य फ़ील्ड मौजूद हैं।
3. एडॉप्टर-विशिष्ट सत्यापन रूटीन सफलता की रिपोर्ट करता है।

## अपडेट करना

```bash
apothem update --harness claude-code
```

वर्तमान साझा प्रोफ़ाइल से नेटिव कॉन्फ़िग को फिर से व्युत्पन्न करता है। इंस्टॉल किए गए
`apothem` पैकेज के अपडेट होने के बाद इसे चलाएँ, ताकि प्रसारित कन्वेंशन सतह (एजेंट,
नियम, स्किल, स्टेटसलाइन, आउटपुट स्टाइल) नए संस्करण को प्रतिबिंबित करे। `CLAUDE.md`
ऑपरेटर के स्वामित्व में है और एडॉप्टर द्वारा कभी नहीं छुआ जाता।

## अनइंस्टॉल करना

```bash
apothem uninstall --harness claude-code
```

एडॉप्टर द्वारा लिखी गई नेटिव कॉन्फ़िग फ़ाइलों को हटाता है।
इंस्टॉल किया गया `apothem` पैकेज और स्रोत रिपॉज़िटरी अप्रभावित रहते हैं।

## कन्फ़ॉर्मिटी गेट

```bash
python -m apothem.conformity.gate --all .
```

## समस्या निवारण

| लक्षण | समाधान |
|---------|-----|
| कॉन्फ़िग फ़ाइल नहीं मिली | `apothem install --harness claude-code` को फिर से चलाएँ |
| सत्यापन विफल | `apothem update --harness claude-code` चलाएँ, फिर दोबारा सत्यापित करें |
| अप्रत्याशित कॉन्फ़िग सामग्री | `apothem update` को फिर से चलाएँ; साझा `apothem` प्रोफ़ाइल सत्य का स्रोत है, `~/.claude/` नहीं |
