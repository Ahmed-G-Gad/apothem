**विक्रेता:** Z.ai
**इंस्टॉल नाम:** `glm`
**स्थिति:** GA
**नेटिव कॉन्फ़िग:** `<project>/.apothem/providers/glm.toml`

GLM (Z.ai) एक **मॉडल बैकएंड** है, अपने-आप में कोई कोडिंग टूल नहीं। Z.ai कोई
प्रथम-पक्ष GLM कमांड लाइन शिप नहीं करता; इसके बजाय, Anthropic-संगत या OpenAI-संगत
प्रोटोकॉल बोलने वाले किसी टूल को एक बैकएंड बेस URL और एक कुंजी सेट करके GLM की ओर
निर्देशित किया जाता है। फिर भी Apothem GLM को अपने हार्नेस अडैप्टरों में गिनता है,
इसलिए आप इसे किसी अन्य की तरह `--harness glm` से चुनते हैं। `glm` अडैप्टर एक प्रदाता
कॉन्फ़िगरेशन फ़ाइल लिखता है जो दोनों संगतता सतहों को दर्ज करती है, ताकि किसी भी
संगत टूल को GLM मॉडल परिवार से जोड़ा जा सके।

## इंस्टॉलेशन

```bash
apothem install --harness glm --project /path/to/project
```

अडैप्टर एक प्रोजेक्ट-स्कोप प्रदाता फ़ाइल लिखता है जो GLM बैकएंड एंडपॉइंट और
ऑपरेटर द्वारा कॉन्फ़िगर करने योग्य प्लेसहोल्डर दर्ज करती है।

**लिखी गई फ़ाइलें:** `<project>/.apothem/providers/glm.toml`

## प्रोफ़ाइल-से-नेटिव-कॉन्फ़िग मैपिंग

प्रदाता फ़ाइल दो बैकएंड दर्ज करती है। Anthropic-संगत बैकएंड बेस URL
`https://api.z.ai/api/anthropic` का उपयोग करता है; Anthropic प्रोटोकॉल बोलने वाला
कोई टूल `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, और वैकल्पिक रूप से
`API_TIMEOUT_MS` सेट करके GLM की ओर रूट होता है। फ़ाइल की
`[backends.anthropic_compatible.env]` तालिका उन्हीं वेरिएबलों को सूचीबद्ध करती है और
साथ ही `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`, और
`ANTHROPIC_DEFAULT_HAIKU_MODEL` को भी, जो टूल की opus, sonnet, और haiku भूमिकाओं को
GLM मॉडलों से मैप करते हैं। OpenAI-संगत बैकएंड बेस URL
`https://api.z.ai/api/coding/paas/v4` का उपयोग करता है। ऑथ टोकन एक प्लेसहोल्डर है
जिसे आप अपनी स्वयं की Z.ai कुंजी से बदलते हैं — Apothem कभी कोई वास्तविक सीक्रेट
नहीं लिखता। मॉडल ID संस्करण के साथ बदलते रहते हैं, इसलिए Apothem किसी को भी पिन
नहीं करता; फ़ाइल में `<GLM_MODEL_ID>` प्लेसहोल्डर होते हैं जिन्हें आप वर्तमान
[Z.ai दस्तावेज़](https://docs.z.ai/devpack/tool/claude) से भरते हैं। साझा प्रोफ़ाइल
से कुछ भी इस फ़ाइल में नहीं जाता; यह एक निश्चित टेम्पलेट है।

## संगतता टिप्पणियाँ

चूँकि GLM एक कोडिंग टूल के बजाय एक बैकएंड है, यह नियमों, कमांडों, स्किल, या हुक के
लिए कोई सतह उजागर नहीं करता — अडैप्टर केवल बैकएंड प्रदाता फ़ाइल लिखता है और कुछ
नहीं। आपकी Z.ai कुंजी और आपके मॉडल-ID विकल्प ऑपरेटर-स्वामित्व में रहते हैं।
अडैप्टर जिन विक्रेता सतह परिपाटियों पर निर्भर करता है, वे
`src/apothem/harnesses/glm/STANDARD-CONVENTION-PIN.md` पर पिन की गई हैं, और उनका
स्नैपशॉट लाइव Z.ai दस्तावेज़ के विरुद्ध लिया गया है।

GLM, Z.ai का GLM मॉडल परिवार चलाता है; वर्तमान बैकएंड, मॉडल, और Anthropic-संगत
कॉन्फ़िगरेशन सतह के लिए
[विक्रेता कॉन्फ़िगरेशन संदर्भ](https://docs.z.ai/devpack/tool/claude) देखें।

## सत्यापन

```bash
apothem verify --harness glm --project /path/to/project
```

verify कमांड पुष्टि करता है कि:

1. नेटिव कॉन्फ़िग अपेक्षित पथ पर मौजूद है।
2. प्रदाता फ़ाइल मौजूद है और खाली नहीं है।
3. अडैप्टर-विशिष्ट सत्यापन रूटीन सफलता की रिपोर्ट करता है।

## अपडेट करना

```bash
apothem update --harness glm --project /path/to/project
```

प्रदाता फ़ाइल एक बार मौजूद हो जाने के बाद आपकी है। `install` और `update` दोनों
टेम्पलेट केवल तभी लिखते हैं जब `.apothem/providers/glm.toml` अनुपस्थित हो, और उसके
बाद दोनों में से कोई भी उसे कभी अधिलेखित नहीं करता, इसलिए आपका कुंजी संदर्भ और मॉडल
विकल्प हर पुनः-रन के बाद भी बने रहते हैं। नया टेम्पलेट पाने के लिए, अपनी फ़ाइल को एक
ओर हटा दें, `update` चलाएँ, और अपने मान नई फ़ाइल में कॉपी करें।

## अनइंस्टॉल करना

```bash
apothem uninstall --harness glm --project /path/to/project
```

प्रदाता फ़ाइल को केवल तभी हटाता है जब उसे Apothem ने बनाया हो और वह अभी भी
असंपादित टेम्पलेट हो, और हटाने से पहले उसका बैकअप Apothem बैकअप रूट के अंतर्गत
लेता है। जो फ़ाइल आपने बनाई या संपादित की है, वह अपनी जगह छोड़ दी जाती है। साझा
प्रोफ़ाइल YAML और Apothem इंजन अप्रभावित रहते हैं।

## अनुरूपता गेट

```bash
python -m apothem.conformity.gate --all .
```

## समस्या निवारण

| लक्षण | समाधान |
|---------|-----|
| कॉन्फ़िग फ़ाइल नहीं मिली | `apothem install --harness glm --project /path/to/project` फिर से चलाएँ |
| सत्यापन विफल रहा | प्रदाता फ़ाइल या तो अनुपस्थित है या खाली है। यदि वह अनुपस्थित है, तो `apothem update --harness glm --project /path/to/project` चलाएँ। यदि वह खाली है, तो पहले `.apothem/providers/glm.toml` को एक ओर हटा दें, फिर `update` चलाएँ और दोबारा सत्यापित करें |
| अप्रत्याशित कॉन्फ़िग सामग्री | `.apothem/providers/glm.toml` को सीधे संपादित करें; Apothem किसी मौजूदा फ़ाइल को कभी दोबारा नहीं लिखता, और साझा प्रोफ़ाइल इसमें कुछ नहीं जोड़ती। नया टेम्पलेट पाने के लिए, फ़ाइल को एक ओर हटा दें और `apothem update --harness glm --project /path/to/project` चलाएँ |
