**विक्रेता:** Zed Industries
**इंस्टॉल नाम:** `zed`
**स्थिति:** GA
**नेटिव कॉन्फ़िग:** `<project>/.rules`

## इंस्टॉलेशन

```bash
apothem install --harness zed --project /path/to/project
```

अडैप्टर साझा Apothem नियमों और शासन सतह से प्रोजेक्ट-स्कोप वाली एक Zed निर्देश
फ़ाइल लिखता है। Zed एक प्रोजेक्ट निर्देश फ़ाइल पढ़ता है, जो इस सूची में पहला मिलान
होती है:

```text
.rules
.cursorrules
.windsurfrules
.clinerules
.github/copilot-instructions.md
AGENT.md
AGENTS.md
CLAUDE.md
GEMINI.md
```

प्रति-टूल कोई नियम डायरेक्टरी नहीं है, इसलिए पूरी Apothem सतह उस सूची के शीर्ष
पर स्थित सपाट `.rules` फ़ाइल में उतरती है।

**लिखी गई फ़ाइलें:** `<project>/.rules`

## प्रोफ़ाइल-से-नेटिव-कॉन्फ़िग मैपिंग

अडैप्टर Apothem की साझा प्रोफ़ाइल पढ़ता है और हर `apothem install` या
`apothem update` रन पर प्रोजेक्ट `.rules` फ़ाइल रेंडर करता है। साझा प्रोफ़ाइल
सत्य का स्रोत है; किसी भी पूर्व-मौजूद `.rules` (या जनित फ़ाइल में किए गए
प्रोजेक्ट-स्थानीय संपादनों) का बैकअप अगली सिंक द्वारा Apothem-प्रबंधित सामग्री
को बदलने से पहले ले लिया जाता है।

## संगतता टिप्पणियाँ

Zed `AGENTS.md` को अपनी प्राथमिक निर्देश फ़ाइल बताता है और प्रोजेक्ट `.rules`
को एक समर्थित संगतता फ़ाइल के रूप में रखता है
([Zed निर्देश](https://zed.dev/docs/ai/instructions))। चूँकि Zed केवल पहला मिलान
पढ़ता है, इसलिए एक नई `.rules` फ़ाइल किसी `AGENTS.md`, किसी `CLAUDE.md`, या सूची
में नीचे की किसी भी अन्य ऐसी फ़ाइल को छिपा देती है जिस पर प्रोजेक्ट पहले से
निर्भर है। इंस्टॉल उन फ़ाइलों को कभी संपादित नहीं करता। जब `.rules` में केवल
Apothem ब्लॉक हो और कोई कम-प्राथमिकता वाली फ़ाइल आपका टेक्स्ट रखती हो, तब
इंस्टॉल और अपडेट एक चेतावनी प्रिंट करते हैं जो छिपी हुई फ़ाइल का नाम बताती है;
जिन निर्देशों की आपको आवश्यकता है, उन्हें Zed में बनाए रखने के लिए Apothem ब्लॉक
के बाहर `.rules` में कॉपी करें।

वैश्विक `~/.config/zed/AGENTS.md` निर्देश फ़ाइल और MCP कॉन्टेक्स्ट-सर्वर ब्लॉक
(`.zed/settings.json` में `context_servers`) ऑपरेटर-स्वामित्व वाले हैं; Apothem
उन्हें नहीं लिखता।

## सत्यापन

```bash
apothem verify --harness zed --project /path/to/project
```

verify कमांड पुष्टि करता है कि:

1. नेटिव कॉन्फ़िग अपेक्षित पथ पर मौजूद है।
2. हर प्रबंधित टारगेट मौजूद है; प्रबंधित फ़ाइलें खाली नहीं हैं, और JSON या YAML
   कॉन्फ़िग पार्स होते हैं। `--profile PATH` जोड़ने पर यह भी पुष्टि होती है कि
   इंस्टॉल की गई फ़ाइलें उस प्रोफ़ाइल से मेल खाती हैं।
3. अडैप्टर-विशिष्ट सत्यापन रूटीन सफलता की रिपोर्ट करता है।

## अपडेट करना

```bash
apothem update --harness zed --project /path/to/project
```

वर्तमान साझा प्रोफ़ाइल स्थिति से प्रोजेक्ट `.rules` फ़ाइल को पुनः व्युत्पन्न करता
है।

## अनइंस्टॉल करना

```bash
apothem uninstall --harness zed --project /path/to/project
```

नेटिव कॉन्फ़िग फ़ाइल `.rules` से Apothem का प्रबंधित ब्लॉक हटाता है और आपका अपना टेक्स्ट रखता है। फ़ाइल तभी हटाई जाती है जब उसमें कुछ और न बचे। बदलाव से पहले फ़ाइल की एक टाइमस्टैम्प-युक्त प्रति `~/.apothem/backups/` के अंतर्गत सहेजी जाती है; प्रोजेक्ट में कोई बैकअप फ़ाइल नहीं छोड़ी जाती। साझा प्रोफ़ाइल YAML और Apothem इंजन अप्रभावित रहते हैं।

## अनुरूपता गेट

```bash
python -m apothem.conformity.gate --all .
```

## समस्या निवारण

| लक्षण | समाधान |
|---------|-----|
| कॉन्फ़िग फ़ाइल नहीं मिली | `apothem install --harness zed --project /path/to/project` फिर से चलाएँ |
| सत्यापन विफल रहा | `apothem update --harness zed --project /path/to/project` चलाएँ, फिर दोबारा सत्यापित करें |
| अप्रत्याशित कॉन्फ़िग सामग्री | `~/.config/apothem/profile.yaml` या `--profile PATH` जाँचें, फिर `apothem update --harness zed --project /path/to/project` फिर से चलाएँ |
