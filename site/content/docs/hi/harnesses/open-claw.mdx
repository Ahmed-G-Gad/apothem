**विक्रेता:** Open-Claw
**इंस्टॉल नाम:** `open-claw`
**स्थिति:** पूर्वावलोकन
**नेटिव कॉन्फ़िग:** `~/.openclaw/openclaw.json`

## इंस्टॉलेशन

```bash
apothem install --harness open-claw
```

अडैप्टर OpenClaw की उपयोगकर्ता-वैश्विक कॉन्फ़िग फ़ाइल लिखता है, साझा प्रोफ़ाइल को
एक प्रोफ़ाइल दस्तावेज़ में प्रक्षेपित करता है, और हार्नेस रूट के अंतर्गत Apothem
समर्थन समूह इंस्टॉल करता है। OpenClaw का नेटिव कॉन्फ़िग JSON है; मूर्तीकारक एक
कुंजी, `skills.load.extraDirs`, रेंडर करता है, और मौजूदा फ़ाइल अपनी अन्य कुंजियाँ
बनाए रखती है।

**लिखी गई फ़ाइलें:** `~/.openclaw/openclaw.json`, प्रोफ़ाइल दस्तावेज़
`~/.openclaw/apothem/rules/00-apothem-profile.md`, और
`~/.openclaw/.apothem/support/` के अंतर्गत समर्थन फ़ाइलें

प्रोफ़ाइल दस्तावेज़ एक Apothem समर्थन फ़ाइल अनुभाग के साथ समाप्त होता है, जो
`~/.openclaw/.apothem/support/` के अंतर्गत वह निरपेक्ष डायरेक्टरी बताता है जिसके
सापेक्ष प्रत्येक रिपॉज़िटरी-शैली उद्धरण (`rules/<name>.md`, `templates/...`,
`hooks/...`) हल होता है।

## प्रोफ़ाइल-से-नेटिव-कॉन्फ़िग मैपिंग

अडैप्टर एक कॉन्फ़िग कुंजी लिखता है। यह `~/.openclaw/.apothem/support/skills` को
`skills.load.extraDirs` में जोड़ता है, जो उन अतिरिक्त स्किल डायरेक्टरियों की सूची है
जिन्हें OpenClaw पढ़ता है, और इसी तरह OpenClaw इंस्टॉल किए गए स्किल खोजता है।
प्रविष्टि आपके द्वारा पहले से सूचीबद्ध किसी भी प्रविष्टि के बाद जाती है, और आपकी अन्य
कुंजियाँ जैसी हैं वैसी रहती हैं। प्रोफ़ाइल की पहचान, प्राथमिकताएँ, और नियम
प्रोफ़ाइल दस्तावेज़ में जाते हैं। साझा कमांड, स्किल, नियम, टेम्पलेट, और हुक
प्रॉम्प्ट `~/.openclaw/.apothem/support/` के अंतर्गत समर्थन सामग्री के रूप में
इंस्टॉल किए जाते हैं।

## संगतता टिप्पणियाँ

पूर्वावलोकन अडैप्टर। OpenClaw, Apothem स्किल को `skills.load.extraDirs` के माध्यम
से लोड करता है, लेकिन वह समर्थन वृक्ष के शेष भाग या प्रोफ़ाइल दस्तावेज़ को अपने आप नहीं
लोड करता: उसकी कोई भी वर्कस्पेस निर्देश फ़ाइल या उसका कॉन्फ़िग वहाँ इंगित नहीं करता,
इसलिए इंस्टॉल के बाद OpenClaw, Apothem के नियमों या MCP सर्वरों के बिना चलता है।

**नाम टकराव।** OpenClaw इन स्रोतों से स्किल पढ़ता है, सर्वोच्च प्राथमिकता पहले, और
जब एक ही स्किल नाम एक से अधिक स्थानों पर आता है तो सर्वोच्च स्रोत जीतता है:
वर्कस्पेस `skills/` फ़ोल्डर, वर्कस्पेस `.agents/skills/` फ़ोल्डर, `~/.agents/skills`
(केवल डिफ़ॉल्ट स्टेट डायरेक्टरी), स्टेट डायरेक्टरी का `skills/` फ़ोल्डर (डिफ़ॉल्ट रूप
से `~/.openclaw/skills`), वर्कशॉप स्किल, बंडल और कस्टोडियन स्किल, और अंत में
`skills.load.extraDirs` के अंतर्गत सूचीबद्ध फ़ोल्डर तथा प्लगइन स्किल। Apothem
डायरेक्टरी एक `extraDirs` प्रविष्टि है, इसलिए उसी नाम का जो स्किल आप किसी भी पहले
वाले स्रोत में रखते हैं, OpenClaw उसी का उपयोग करता है, और उस स्किल की Apothem
प्रति डिस्क पर अप्रयुक्त रहती है। Apothem केवल `openclaw.json` में और
`~/.openclaw/.apothem/support/` के अंतर्गत लिखता है, उन पहले वाले फ़ोल्डरों में कभी
नहीं, इसलिए इंस्टॉल, अपडेट, और अनइंस्टॉल वहाँ रखे आपके किसी स्किल को नहीं बदलते।

`agents.defaults.skills` स्किल नामों की अनुमति-सूची (allowlist) है; Apothem इसे
संपादित नहीं करता, इसलिए यदि आप एक रखते हैं, तो जाँचें कि उसमें वे Apothem स्किल
दर्ज हैं जो आप चाहते हैं। `apothem update` उन कुंजियों को बनाए रखता है जिन्हें आप `openclaw.json` में जोड़ते हैं। MCP सर्वर OpenClaw कॉन्फ़िग के `mcp.servers` ब्लॉक में रहते हैं, जिसे आप `openclaw mcp add` और संबंधित सबकमांड से प्रबंधित करते हैं; अडैप्टर वहाँ कोई प्रविष्टि नहीं लिखता। (OpenClaw का व्यवहार उसके [स्किल](https://docs.openclaw.ai/tools/skills),
[स्किल कॉन्फ़िग](https://docs.openclaw.ai/tools/skills-config), और
[कॉन्फ़िग एक्सटेंशन](https://docs.openclaw.ai/gateway/config-extensions) दस्तावेज़ों
के अनुसार है, 2026-10-24 को पढ़ा गया, और उसके [MCP CLI](https://docs.openclaw.ai/cli/mcp)
दस्तावेज़ों के अनुसार, 2026-10-02 को पढ़ा गया।)

**`openclaw.json` में टिप्पणियाँ।** OpenClaw अपना कॉन्फ़िग JSON5 के रूप में पढ़ता है,
और Apothem फ़ाइल को सादे JSON के रूप में फिर से लिखता है। जब फ़ाइल में टिप्पणियाँ या
अन्य JSON5 सिंटैक्स हो और प्रविष्टि अनुपस्थित हो, तो Apothem फ़ाइल को अछूता छोड़ देता
है और इंस्टॉल एक संदेश के साथ रुक जाता है जो कुंजी का नाम बताता है। इस प्रविष्टि को
स्वयं अपनी फ़ाइल में मर्ज करें, या फ़ाइल को सादे JSON में बदलें, फिर इंस्टॉल दोबारा
चलाएँ:

```json
{
  "skills": {
    "load": {
      "extraDirs": ["~/.openclaw/.apothem/support/skills"]
    }
  }
}
```

आपके द्वारा स्वयं जोड़ी गई प्रविष्टि आपकी मानी जाती है: अनइंस्टॉल उसे अपनी जगह
रहने देता है।

## सत्यापन

```bash
apothem verify --harness open-claw
```

verify कमांड पुष्टि करता है कि:

1. नेटिव कॉन्फ़िग अपेक्षित पथ पर मौजूद है।
2. हर प्रबंधित टारगेट मौजूद है; प्रबंधित फ़ाइलें खाली नहीं हैं, और JSON या YAML
   कॉन्फ़िग पार्स होते हैं। `--profile PATH` जोड़ने पर यह भी पुष्टि होती है कि
   इंस्टॉल की गई फ़ाइलें उस प्रोफ़ाइल से मेल खाती हैं।
3. नेटिव कॉन्फ़िग में `skills.load.extraDirs`
   `~/.openclaw/.apothem/support/skills` को सूचीबद्ध करता है। उस प्रविष्टि के बिना
   OpenClaw इंस्टॉल किए गए स्किल लोड नहीं करता; `apothem update` उसे वापस जोड़ता है।
4. अडैप्टर-विशिष्ट सत्यापन रूटीन सफलता की रिपोर्ट करता है।

## अपडेट करना

```bash
apothem update --harness open-claw
```

वर्तमान साझा प्रोफ़ाइल स्थिति से प्रोफ़ाइल दस्तावेज़ को पुनः व्युत्पन्न करता है और
समर्थन फ़ाइलों को ताज़ा करता है; `openclaw.json` में पहले से मौजूद कुंजियाँ बनी
रहती हैं, और `skills.load.extraDirs` में Apothem प्रविष्टि एक ही बार सूचीबद्ध रहती
है, चाहे आप कितनी भी बार अपडेट करें। `~/.config/apothem/profile.yaml` संपादित करने या इंस्टॉल किए गए Apothem
पैकेज को अपग्रेड करने के बाद चलाएँ।

## अनइंस्टॉल करना

```bash
apothem uninstall --harness open-claw
```

अडैप्टर ने जो जोड़ा था उसे हटाता है: `skills.load.extraDirs` में उसकी प्रविष्टि,
प्रोफ़ाइल दस्तावेज़, और समर्थन वृक्ष। `openclaw.json` में आपकी अपनी कुंजियाँ, आपकी
अपनी `extraDirs` प्रविष्टियों सहित, बनी रहती हैं, और फ़ाइल केवल तभी हटाई जाती
है जब उसे Apothem ने बनाया हो और आपका कुछ भी शेष न बचा हो। साझा प्रोफ़ाइल YAML
और Apothem इंजन अप्रभावित रहते हैं।

## अनुरूपता गेट

```bash
python -m apothem.conformity.gate --all .
```

## समस्या निवारण

| लक्षण | समाधान |
|---------|-----|
| कॉन्फ़िग फ़ाइल नहीं मिली | `apothem install --harness open-claw` फिर से चलाएँ |
| सत्यापन विफल रहा | `apothem update --harness open-claw` चलाएँ, फिर दोबारा सत्यापित करें |
| अप्रत्याशित कॉन्फ़िग सामग्री | Apothem `openclaw.json` में केवल `skills.load.extraDirs` प्रविष्टि लिखता है और उसमें पहले से मौजूद कुंजियों को रखता है, इसलिए प्रोफ़ाइल सामग्री वहाँ नहीं जाती। प्रोफ़ाइल सामग्री `~/.openclaw/apothem/rules/00-apothem-profile.md` में जाती है: `~/.config/apothem/profile.yaml` या `--profile PATH` जाँचें, फिर [अपडेट करना](#अपडेट-करना) में दिए गए कमांड को दोबारा चलाएँ |
| इंस्टॉल `openclaw.json` में टिप्पणियों या JSON5 सिंटैक्स के बारे में संदेश के साथ रुक जाता है | Apothem ऐसी फ़ाइल को फिर से नहीं लिखता जिससे उसे टिप्पणियाँ हटानी पड़ें। [संगतता टिप्पणियाँ](#संगतता-टिप्पणियाँ) के अंतर्गत दिखाई गई `skills.load.extraDirs` प्रविष्टि स्वयं जोड़ें, या फ़ाइल को सादे JSON में बदलें, फिर इंस्टॉल दोबारा चलाएँ |
| कोई Apothem स्किल OpenClaw में दिखाई नहीं देता | वर्कस्पेस, `~/.agents/skills`, या `~/.openclaw/skills` में उसी नाम का स्किल Apothem प्रति पर प्राथमिकता लेता है ([संगतता टिप्पणियाँ](#संगतता-टिप्पणियाँ) देखें)। साथ ही `apothem verify --harness open-claw` चलाएँ, और जाँचें कि आपके द्वारा रखी गई कोई भी `agents.defaults.skills` अनुमति-सूची उस स्किल का नाम दर्ज करती है |
