**विक्रेता:** Open-Claw
**इंस्टॉल नाम:** `open-claw`
**स्थिति:** पूर्वावलोकन
**नेटिव कॉन्फ़िग:** `~/.openclaw/openclaw.json`

## इंस्टॉलेशन

```bash
apothem install --harness open-claw
```

अडैप्टर OpenClaw की उपयोगकर्ता-वैश्विक कॉन्फ़िग फ़ाइल लिखता है, साझा प्रोफ़ाइल को
एक प्रोफ़ाइल दस्तावेज़ में प्रक्षेपित करता है, और हार्नेस रूट के अंतर्गत Apothem
समर्थन समूह इंस्टॉल करता है। OpenClaw का नेटिव कॉन्फ़िग JSON है; मटेरियलाइज़र एक
खाली JSON ऑब्जेक्ट रेंडर करता है, और मौजूदा फ़ाइल अपनी कुंजियाँ बनाए रखती है।

**लिखी गई फ़ाइलें:** `~/.openclaw/openclaw.json`, प्रोफ़ाइल दस्तावेज़
`~/.openclaw/apothem/rules/00-apothem-profile.md`, और
`~/.openclaw/.apothem/support/` के अंतर्गत समर्थन फ़ाइलें

प्रोफ़ाइल दस्तावेज़ एक Apothem समर्थन फ़ाइल अनुभाग के साथ समाप्त होता है, जो
`~/.openclaw/.apothem/support/` के अंतर्गत वह निरपेक्ष डायरेक्टरी बताता है जिसके
सापेक्ष प्रत्येक रिपॉज़िटरी-शैली उद्धरण (`rules/<name>.md`, `templates/...`,
`hooks/...`) हल होता है।

## प्रोफ़ाइल-से-नेटिव-कॉन्फ़िग मैपिंग

अडैप्टर Apothem की साझा प्रोफ़ाइल पढ़ता है, लेकिन कोई कॉन्फ़िग कुंजी नहीं लिखता:
नया या खाली `openclaw.json` एक खाली ऑब्जेक्ट के रूप में लिखा जाता है, और मौजूदा
फ़ाइल अपनी कुंजियाँ बनाए रखती है। प्रोफ़ाइल की पहचान, प्राथमिकताएँ, और नियम
प्रोफ़ाइल दस्तावेज़ में जाते हैं। साझा कमांड, स्किल, नियम, टेम्पलेट, और हुक
प्रॉम्प्ट `~/.openclaw/.apothem/support/` के अंतर्गत समर्थन सामग्री के रूप में
इंस्टॉल किए जाते हैं।

## संगतता टिप्पणियाँ

पूर्वावलोकन अडैप्टर। OpenClaw समर्थन वृक्ष या प्रोफ़ाइल दस्तावेज़ को अपने आप नहीं लोड करता: उसका कोई भी स्किल स्थान, उसकी वर्कस्पेस निर्देश फ़ाइलें, या उसका कॉन्फ़िग वहाँ इंगित नहीं करता, इसलिए इंस्टॉल के बाद OpenClaw, Apothem के नियमों, स्किल या MCP सर्वरों के बिना चलता है। OpenClaw स्किल अपने वर्कस्पेस के `skills/` और `.agents/skills/` फ़ोल्डरों, `~/.agents/skills`, और अपनी स्टेट डायरेक्टरी से पढ़ता है, फिर उन्हें `agents.defaults.skills` के अंतर्गत स्किल नामों की अनुमति-सूची (allowlist) से छानता है। `skills.load.extraDirs` स्किल लोडर नहीं है, इसलिए `~/.openclaw/.apothem/support/skills` के अंतर्गत Apothem स्किल तभी लोड होते हैं जब आप उन्हें उन फ़ोल्डरों में से किसी एक में रखें और उस अनुमति-सूची में उनके नाम दर्ज करें। `apothem update` उन कुंजियों को बनाए रखता है जिन्हें आप `openclaw.json` में जोड़ते हैं। MCP सर्वर OpenClaw कॉन्फ़िग के `mcp.servers` ब्लॉक में रहते हैं, जिसे आप `openclaw mcp add` और संबंधित सबकमांड से प्रबंधित करते हैं; अडैप्टर वहाँ कोई प्रविष्टि नहीं लिखता। (OpenClaw का व्यवहार उसके [स्किल](https://docs.openclaw.ai/tools/skills) और [MCP CLI](https://docs.openclaw.ai/cli/mcp) दस्तावेज़ों के अनुसार है, 2026-10-02 को पढ़ा गया।)

## सत्यापन

```bash
apothem verify --harness open-claw
```

verify कमांड पुष्टि करता है कि:

1. नेटिव कॉन्फ़िग अपेक्षित पथ पर मौजूद है।
2. हर प्रबंधित टारगेट मौजूद है; प्रबंधित फ़ाइलें खाली नहीं हैं, और JSON या YAML
   कॉन्फ़िग पार्स होते हैं। `--profile PATH` जोड़ने पर यह भी पुष्टि होती है कि
   इंस्टॉल की गई फ़ाइलें उस प्रोफ़ाइल से मेल खाती हैं।
3. अडैप्टर-विशिष्ट सत्यापन रूटीन सफलता की रिपोर्ट करता है।

## अपडेट करना

```bash
apothem update --harness open-claw
```

वर्तमान साझा प्रोफ़ाइल स्थिति से प्रोफ़ाइल दस्तावेज़ को पुनः व्युत्पन्न करता है और
समर्थन फ़ाइलों को ताज़ा करता है; `openclaw.json` में पहले से मौजूद कुंजियाँ बनी
रहती हैं। `~/.config/apothem/profile.yaml` संपादित करने या इंस्टॉल किए गए Apothem
पैकेज को अपग्रेड करने के बाद चलाएँ।

## अनइंस्टॉल करना

```bash
apothem uninstall --harness open-claw
```

अडैप्टर ने जो जोड़ा था उसे हटाता है: प्रोफ़ाइल दस्तावेज़ और समर्थन वृक्ष।
`openclaw.json` में आपकी अपनी कुंजियाँ बनी रहती हैं, और फ़ाइल केवल तभी हटाई जाती
है जब उसे Apothem ने बनाया हो और आपका कुछ भी शेष न बचा हो। साझा प्रोफ़ाइल YAML
और Apothem इंजन अप्रभावित रहते हैं।

## अनुरूपता गेट

```bash
python -m apothem.conformity.gate --all .
```

## समस्या निवारण

| लक्षण | समाधान |
|---------|-----|
| कॉन्फ़िग फ़ाइल नहीं मिली | `apothem install --harness open-claw` फिर से चलाएँ |
| सत्यापन विफल रहा | `apothem update --harness open-claw` चलाएँ, फिर दोबारा सत्यापित करें |
| अप्रत्याशित कॉन्फ़िग सामग्री | Apothem `openclaw.json` में कोई कुंजी नहीं लिखता और उसमें पहले से मौजूद कुंजियों को रखता है, इसलिए प्रोफ़ाइल सामग्री वहाँ नहीं जाती। प्रोफ़ाइल सामग्री `~/.openclaw/apothem/rules/00-apothem-profile.md` में जाती है: `~/.config/apothem/profile.yaml` या `--profile PATH` जाँचें, फिर [अपडेट करना](#अपडेट-करना) में दिए गए कमांड को दोबारा चलाएँ |
