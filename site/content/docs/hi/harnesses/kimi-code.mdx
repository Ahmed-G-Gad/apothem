**विक्रेता:** Moonshot
**इंस्टॉल नाम:** `kimi-code`
**स्थिति:** GA
**नेटिव कॉन्फ़िग:** `<project>/AGENTS.md`, `<project>/.kimi-code/skills/`, `<project>/.kimi-code/agents/`, तथा `<project>/.kimi-code/.apothem/support/`

## इंस्टॉलेशन

```bash
apothem install --harness kimi-code --project /path/to/project
```

अडैप्टर साझा Apothem शासन सतह को प्रोजेक्ट-रूट `AGENTS.md` में एक
सेंटिनल-सीमांकित प्रबंधित ब्लॉक के रूप में लिखता है (सेंटिनलों के बाहर ऑपरेटर का
गद्य संरक्षित रहता है)। यह स्किल, और स्किल के रूप में लपेटे गए कमांड, Kimi Code की
नेटिव प्रोजेक्ट स्किल डायरेक्टरी `<project>/.kimi-code/skills/` में इंस्टॉल करता है,
और Apothem के सहायकों को Kimi Code सबएजेंट के रूप में `<project>/.kimi-code/agents/`
में इंस्टॉल करता है ([सबएजेंट](#सबएजेंट) देखें)। अन्य समूह
`<project>/.kimi-code/.apothem/support/` पर Apothem-स्वामित्व वाले समर्थन वृक्ष के
अंतर्गत रहते हैं। किसी प्रोजेक्ट की `AGENTS.md` फ़ाइल को Kimi Code के अलावा कई
कोडिंग टूल पढ़ते हैं, इसलिए ब्लॉक प्रोजेक्ट-व्यापी मार्गदर्शन के रूप में लिखा
जाता है, जो किसी एक टूल को अपने पाठक के रूप में नामित नहीं करता।

Kimi Code सार्वभौमिक AGENTS.md परिपाटी का पालन करते हुए प्रोजेक्ट-रूट `AGENTS.md`
निर्देश फ़ाइल पढ़ता है, और प्रोजेक्ट कॉन्फ़िगरेशन `<project>/.kimi-code/` के
अंतर्गत रहता है। Kimi Code प्रोजेक्ट रूट को वह निकटतम डायरेक्टरी मानता है जिसमें
`.git` हो, कार्यशील डायरेक्टरी से ऊपर की ओर खोजते हुए, इसलिए `--project` के रूप में
रिपॉज़िटरी रूट दें। `<project>/.kimi-code/mcp.json` सतह ऑपरेटर-स्वामित्व वाली है;
Apothem उसे नामित करता है, लेकिन उसमें कोई प्रविष्टि नहीं लिखता।

**लिखी गई फ़ाइलें:** `<project>/AGENTS.md` (प्रबंधित ब्लॉक),
`<project>/.kimi-code/skills/` के अंतर्गत स्किल और कमांड (स्किल के रूप में), हर
Apothem सहायक के लिए एक `<project>/.kimi-code/agents/<name>.md`, और
`<project>/.kimi-code/.apothem/support/` के अंतर्गत हुक, नियम, और टेम्पलेट समूह।

## सबएजेंट

Kimi Code,
[कस्टम सबएजेंट पर Kimi Code दस्तावेज़](https://moonshotai.github.io/kimi-code/en/customization/agents.md)
के अनुसार, `.kimi-code/agents/` (या `.agents/agents/`) में एक Markdown फ़ाइल से
सबएजेंट पढ़ता है। इंस्टॉल सभी चौदह सहायकों के लिए हर Apothem सहायक की एक फ़ाइल
`<project>/.kimi-code/agents/` में लिखता है। यह केवल प्रोजेक्ट के लिए इंस्टॉल करता
है और कोई `~/.kimi-code/agents/` फ़ोल्डर नहीं लिखता।

हर फ़ाइल सहायक के निर्देशों को अपरिवर्तित रखती है और ये फ़्रंट मैटर कुंजियाँ रखती
है:

| कुंजी | Apothem क्या लिखता है |
| --- | --- |
| `name`, `description` | सहायक का नाम और विवरण। |
| `tools` | सहायक के अनुमत टूल, Kimi Code टूल नामों की सूची के रूप में। |
| `disallowedTools` | सहायक के वर्जित टूल, Kimi Code टूल नामों की सूची के रूप में। Kimi Code इसे `tools` के बाद लागू करता है। |

Kimi Code टूल नामों का मिलान सटीक रूप से, बड़े अक्षरों सहित, करता है, और ऐसे नाम
के बारे में चेतावनी देता है जिसके लिए उसके पास कोई टूल नहीं है। इसलिए इंस्टॉल उन दो
टूल का नाम बदलता है जिन्हें Kimi Code अलग ढंग से लिखता है, `WebFetch` को `FetchURL`
और `TodoWrite` को `TodoList`, और उन नामों को छोड़ देता है जिनके लिए Kimi Code के
पास कोई टूल नहीं है: `MultiEdit`, `NotebookEdit`, `PowerShell`, `Monitor`,
`Artifact`, `TaskCreate` और `TaskUpdate`। वर्जित टूल वर्जित ही रहता है। यदि इस तरह
किसी सहायक के सभी अनुमत टूल हट जाते हैं, तो फ़ाइल `tools: []` रखती है, जो किसी भी
टूल की अनुमति नहीं देता; छोड़ा गया `tools` हर टूल की अनुमति देगा।

इंस्टॉल कभी `model` नहीं लिखता (Kimi Code में सबएजेंट के लिए कोई मॉडल कुंजी नहीं है;
सबएजेंट मुख्य सत्र का मॉडल या `config.toml` में `[secondary_model]` उपयोग करता है),
न `override` (यह किसी प्रोजेक्ट फ़ाइल को एक बिल्ट-इन सबएजेंट बदलने देगा), न
`subagents`, न `whenToUse`, और न ही Apothem की `maxTurns`, `version`, `updated` और
`portability` कुंजियाँ।

जानने योग्य बातें:

- सबएजेंट फ़ाइलें सामान्य प्रोजेक्ट फ़ाइलें हैं। उन्हें प्रोजेक्ट के साथ कमिट करें या
  `.gitignore` में `.kimi-code/agents/` सूचीबद्ध करें; Apothem आपके लिए यह नहीं
  चुनता।
- Kimi Code किसी सहायक का उपयोग तब करता है जब प्रत्यायोजन (delegation) का अनुरोध
  किया जाता है। 2026-10-25 के अपने रिलीज़ से यह स्वयं सबएजेंट शुरू करने के बजाय
  डिफ़ॉल्ट रूप से कार्य स्वयं संभालता है, इसलिए किसी सहायक को नाम से माँगें, किसी
  संदेश में या `AGENTS.md` में। कस्टम सबएजेंट पर विक्रेता का पृष्ठ अब भी स्वचालित
  शेड्यूलिंग का वर्णन करता है, इसलिए यह बदल सकता है।
- `.kimi-code/agents/` में प्रोजेक्ट-स्तर की फ़ाइल extra, user और plugin स्तरों पर
  उसी नाम वाली परिभाषा से ऊपर रैंक करती है। अपने सहायकों को Apothem के नामों से भिन्न
  नाम दें। Kimi Code का कोड साझा `.agents/agents/` फ़ोल्डर से पहले, जिसे Apothem कभी
  नहीं लिखता, `.kimi-code/agents/` भी पढ़ता है, और एक ही नाम वाली दो फ़ाइलों में से
  पहली रखता है; दस्तावेज़ यह नहीं बताते।
- Apothem सहायक के नाम वाली आपकी कोई फ़ाइल `~/.apothem/backups/` के अंतर्गत
  सहेजी जाती है और फिर बदल दी जाती है। अनइंस्टॉल उसे वापस नहीं रखता। अन्य नामों
  वाली फ़ाइलों को कभी नहीं छुआ जाता।
- पुराने रिलीज़ सहायक फ़ाइलों को समर्थन वृक्ष में,
  `.kimi-code/.apothem/support/agents/` पर, रखते थे, जहाँ Kimi Code उन्हें लोड नहीं
  करता था। `apothem update` या `apothem uninstall` उस प्रति को
  `~/.apothem/backups/` के अंतर्गत सहेजने के बाद हटा देता है।

## प्रोफ़ाइल-से-नेटिव-कॉन्फ़िग मैपिंग

अडैप्टर Apothem की साझा प्रोफ़ाइल पढ़ता है और हर `apothem install` या
`apothem update` रन पर प्रोजेक्ट-रूट `AGENTS.md` निर्देश सतह रेंडर करता है।
व्यवहारगत नियम और शासन कॉर्पस `AGENTS.md` के प्रबंधित ब्लॉक में उतरते हैं। हर
स्किल, और स्किल के रूप में लपेटा गया हर कमांड, `.kimi-code/skills/<name>/SKILL.md`
पर उतरता है, जो एक प्रोजेक्ट स्किल डायरेक्टरी है जिसे Kimi Code लोड करता है। अडैप्टर
केवल वह Kimi-विशिष्ट फ़ोल्डर लिखता है और कभी `.agents/skills/` नहीं, जिसे अन्य टूल
भी पढ़ते हैं। `.kimi-code/skills/` में आपके द्वारा स्वयं अन्य नामों से जोड़ी गई स्किल
इंस्टॉल, अपडेट, और अनइंस्टॉल पर बनी रहती हैं। वहाँ Apothem स्किल के समान नाम वाली
स्किल बदल दी जाती है: इंस्टॉल और अपडेट उसे अधिलेखित करते हैं, और अनइंस्टॉल उसे हटाता
है, हर बार `~/.apothem/backups/` के अंतर्गत एक टाइमस्टैम्प-युक्त प्रति के बाद, और
इंस्टॉल इस टकराव की कोई सूचना प्रिंट नहीं करता। अपनी स्किल को Apothem के नामों से
भिन्न नाम दें।

हुक, नियम, और टेम्पलेट समूह `.kimi-code/.apothem/support/` के अंतर्गत रखे जाते हैं
और निर्देश सतह से संदर्भित किए जाते हैं। Kimi Code उन्हें समर्थन वृक्ष से लोड नहीं
करता, इसलिए वहाँ रखी Apothem प्रतियाँ वह संदर्भ सामग्री हैं जिसकी ओर `AGENTS.md`
ब्लॉक इंगित करता है। ब्लॉक एक Apothem समर्थन फ़ाइल अनुभाग के साथ समाप्त होता है,
जो प्रोजेक्ट रूट के सापेक्ष `.kimi-code/.apothem/support/` के अंतर्गत वह डायरेक्टरी
बताता है जिसके सापेक्ष प्रत्येक रिपॉज़िटरी-शैली उद्धरण (`rules/<name>.md`,
`templates/...`, `hooks/...`) हल होता है, ताकि कमिट की गई `AGENTS.md` फ़ाइल में
कोई मशीन-विशिष्ट पथ न रहे। (Kimi Code का व्यवहार उसके अनुकूलन पृष्ठों
[स्किल](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/skills.html),
[सहायक परिभाषाएँ](https://moonshotai.github.io/kimi-code/en/customization/agents.md), और
[हुक](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html) के अनुसार,
स्किल और हुक के लिए 2026-10-24 को, सहायक परिभाषाओं के लिए 2026-10-27 को पढ़ा गया।)

## नेटिव रूप से इंस्टॉल नहीं किया गया

Kimi Code हुक के लिए एक नेटिव स्थान प्रलेखित करता है। अडैप्टर अभी उसमें नहीं लिखता,
इन कारणों से।

- **हुक।** Kimi Code `~/.kimi-code/config.toml` में `[[hooks]]` ऐरे से हुक पढ़ता है
  (जब वह वेरिएबल सेट हो, तो `$KIMI_CODE_HOME/config.toml`)। Apothem कोई नहीं लिखता। वह फ़ाइल उपयोगकर्ता
  स्कोप की है जबकि यह अडैप्टर प्रोजेक्ट रूट के अंतर्गत लिखता है; एक प्रविष्टि केवल
  चार फ़ील्ड की अनुमति देती है (`event` और `command` आवश्यक, `matcher` और `timeout`
  वैकल्पिक) और एक अतिरिक्त फ़ील्ड कॉन्फ़िग को लोड होने से रोक देता है; और Apothem के
  पास कोई TOML विलय नहीं है जो बाद में केवल उसकी अपनी प्रविष्टियाँ हटा सके। हुक
  हेल्पर स्क्रिप्ट समर्थन वृक्ष में रहती हैं।
- **स्किल फ़्रंट मैटर।** विक्रेता पृष्ठ `SKILL.md` कुंजियाँ `name` और `description`
  (दोनों आवश्यक), `type`, `whenToUse`, `disableModelInvocation` (जिसे
  `disable-model-invocation` के रूप में भी स्वीकार किया जाता है), और `arguments`
  प्रलेखित करता है। यह अन्य कुंजियों के लिए कोई नियम नहीं बताता। स्किल उसी फ़्रंट
  मैटर के साथ इंस्टॉल होती हैं जो Apothem स्रोत में उनके पास है, इसलिए `version`,
  `updated`, `archetype`, `userInvocable`, `argument-hint`, `portability`, और
  `allowed-tools` जैसी कुंजियाँ Kimi Code तक पहुँचती हैं, जो उन्हें अनदेखा या
  अस्वीकार कर सकता है।
- **समान-नाम वाली स्किल।** Kimi Code प्रोजेक्ट स्तर को उपयोगकर्ता स्तर पर प्राथमिकता
  देता है, इसलिए `<project>/.kimi-code/skills/` में कोई स्किल `~/.agents/skills/` में
  उसी नाम की स्किल पर प्राथमिकता लेती है, जिसे एक अलग Apothem अडैप्टर लिखता है।
  विक्रेता पृष्ठ यह नहीं बताता कि प्रोजेक्ट स्तर के भीतर `.kimi-code/skills/` और
  `.agents/skills/` एक-दूसरे के सापेक्ष कैसे रैंक करते हैं।

## संगतता टिप्पणियाँ

Kimi Code प्रोजेक्ट निर्देश `AGENTS.md` या `.kimi-code/AGENTS.md` से पढ़ता है और
`.kimi-code/mcp.json` को ऑपरेटर-स्वामित्व वाली MCP सतह के रूप में पहचानता है;
Apothem उस सतह को नामित करता है, लेकिन उसमें कोई प्रविष्टि नहीं लिखता। दोनों
निर्देश फ़ाइलों में से अडैप्टर केवल प्रोजेक्ट-रूट `AGENTS.md` लिखता है, जिसे
Kimi Code प्रोजेक्ट निर्देश के रूप में पढ़ता है; Kimi Code का दस्तावेज़ यह नहीं बताता
कि दोनों फ़ाइलें मौजूद होने पर किस फ़ाइल को प्राथमिकता मिलती है। Kimi Code कोई
स्टेटसलाइन या आउटपुट-स्टाइल फ़ाइल सतह उजागर नहीं करता, इसलिए वे समूह मटेरियलाइज़
नहीं किए जाते।

Kimi Code, Moonshot के Kimi मॉडल परिवार पर चलता है; वर्तमान मॉडल और कॉन्फ़िगरेशन
सतह के लिए
[विक्रेता कॉन्फ़िगरेशन संदर्भ](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/config-files)
देखें।

```bash
apothem verify --harness kimi-code --project /path/to/project
```

verify कमांड पुष्टि करता है कि:

1. नेटिव कॉन्फ़िग अपेक्षित पथ पर मौजूद है।
2. हर प्रबंधित टारगेट मौजूद है, स्किल और सबएजेंट डायरेक्टरी सहित; प्रबंधित फ़ाइलें
   खाली नहीं हैं, और JSON या YAML कॉन्फ़िग पार्स होते हैं। `--profile PATH` जोड़ने
   पर यह भी पुष्टि होती है कि इंस्टॉल की गई फ़ाइलें उस प्रोफ़ाइल से मेल खाती हैं।
   `.kimi-code/agents/` के लिए जाँच यह है कि फ़ोल्डर मौजूद है, यह नहीं कि हर सहायक
   फ़ाइल उसमें है; कमांड
   `apothem diff --harness kimi-code --project /path/to/project` उन सहायक फ़ाइलों को
   सूचीबद्ध करता है जो अनुपस्थित या पुरानी हैं।
3. अडैप्टर-विशिष्ट सत्यापन रूटीन सफलता की रिपोर्ट करता है।

## अपडेट करना

```bash
apothem update --harness kimi-code --project /path/to/project
```

वर्तमान साझा प्रोफ़ाइल स्थिति से प्रोजेक्ट-रूट `AGENTS.md` प्रबंधित ब्लॉक, स्किल,
सबएजेंट फ़ाइलों, और समर्थन समूहों को पुनः व्युत्पन्न करता है। स्किल के
`.kimi-code/skills/` में जाने से पहले किए गए इंस्टॉल पर अपडेट पुरानी
`<project>/.kimi-code/.apothem/support/skills/` डायरेक्टरी हटा देता है, ताकि हर स्किल
एक बार मौजूद रहे। सहायकों के `.kimi-code/agents/` में जाने से पहले के इंस्टॉल पर
अपडेट उसी तरह पुरानी `<project>/.kimi-code/.apothem/support/agents/` डायरेक्टरी
हटा देता है। हर हटाई गई डायरेक्टरी की एक टाइमस्टैम्प-युक्त प्रति पहले
`~/.apothem/backups/` के अंतर्गत सहेजी जाती है।

## अनइंस्टॉल करना

```bash
apothem uninstall --harness kimi-code --project /path/to/project
```

प्रोजेक्ट-रूट `AGENTS.md` से Apothem ब्लॉक हटाता है और सेंटिनलों के बाहर का कोई भी
टेक्स्ट बनाए रखता है। फ़ाइल केवल तभी हटाई जाती है जब उसमें और कुछ शेष न रहे। साथ
ही `<project>/.kimi-code/skills/` के अंतर्गत Apothem द्वारा रखी गई स्किल (वहाँ आपके
द्वारा अन्य नामों से जोड़ी गई स्किल बनी रहती हैं), `<project>/.kimi-code/agents/` के
अंतर्गत सबएजेंट फ़ाइलें (वहाँ आपके द्वारा अन्य नामों से जोड़ी गई फ़ाइलें बनी रहती हैं,
और खाली रह जाने पर फ़ोल्डर हटा दिया जाता है), और
`<project>/.kimi-code/.apothem/support/` के अंतर्गत समर्थन फ़ाइलें भी हटाता है,
जिनमें ऐसे इंस्टॉल की पुरानी समर्थन-वृक्ष `skills/` और `agents/` डायरेक्टरी भी शामिल
हैं जिसे कभी अपडेट नहीं किया गया। बदलाव से पहले, प्रत्येक फ़ाइल की एक टाइमस्टैम्प-युक्त प्रति
`~/.apothem/backups/` के अंतर्गत सहेजी जाती है; प्रोजेक्ट में कोई बैकअप फ़ाइल नहीं
छोड़ी जाती। साझा प्रोफ़ाइल YAML और Apothem इंजन अप्रभावित रहते हैं।

## अनुरूपता गेट

```bash
python -m apothem.conformity.gate --all .
```

## समस्या निवारण

| लक्षण | समाधान |
|---------|-----|
| कॉन्फ़िग फ़ाइल नहीं मिली | `apothem install --harness kimi-code --project /path/to/project` फिर से चलाएँ |
| सत्यापन विफल रहा | `apothem update --harness kimi-code --project /path/to/project` चलाएँ, फिर दोबारा सत्यापित करें |
| Kimi Code में स्किल या सहायक अनुपस्थित हैं | जाँचें कि `--project` रिपॉज़िटरी रूट (वह डायरेक्टरी जिसमें `.git` है) बताता है, फिर इंस्टॉल फिर से चलाएँ |
| Kimi Code कभी किसी सहायक का उपयोग नहीं करता | उसे नाम से माँगें। जब तक प्रत्यायोजन का अनुरोध न किया जाए, Kimi Code कार्य स्वयं संभालता है |
| अप्रत्याशित कॉन्फ़िग सामग्री | `~/.config/apothem/profile.yaml` या `--profile PATH` जाँचें, फिर `apothem update --harness kimi-code --project /path/to/project` फिर से चलाएँ |
