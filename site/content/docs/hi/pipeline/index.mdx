Apothem एक आर्किटेक्चर-जागरूक `/plan` पाइपलाइन, एक तेरह-चरणीय `/research`
पाइपलाइन, साथ ही एक ग्यारह-कमांड ऑडिट अनुक्रम के साथ आता है — जो हर परियोजना
को कच्चे गद्य से बहु-अक्षीय रूप से समीक्षित, उत्पादन-स्तरीय कोड तक, और एक कच्चे
विचार से एक प्रसारित, सहकर्मी-समीक्षित शोध-पत्र तक का एक संरचित मार्ग देता है।

## पाइपलाइन अवलोकन

```mermaid
flowchart LR
    accTitle: Plan pipeline command flow
    accDescr: Left-to-right flowchart of the apothem plan pipeline from the spec stage through the generate and review stages, then through a conditional architecture-bearing decision that either runs the design stage or skips directly to the execute stage.     A[/plan-spec] --> B[/plan-generate]
    B --> C[/plan-review]
    AUD[/plan-audit<br/>orthogonal: wraps spec → review] -.->|closed-loop remediation| A
    C --> Q{Architecture-bearing suite?}
    Q -->|yes| F[/plan-design<br/>emit _inputs/design.md]
    Q -->|no| D[/plan-execute]
    F --> D
    D --> E[/plan-status]
    D --> G[Audit review sequence]
    G --> H[Completion milestone]
```

## योजना चरण

पाइपलाइन आठ प्रथम-श्रेणी स्लैश कमांड के रूप में आती है, प्रति चरण एक — प्रत्येक
स्वतंत्र रूप से `/plan-<stage>` के रूप में आह्वान-योग्य।

| चरण | भूमिका | स्थिति |
|-------|------|----------|
| [/plan-spec](/docs/pipeline/plan-spec) | फ़ोर्ज — गद्य से विनिर्देश तक | प्रारंभिक |
| [/plan-generate](/docs/pipeline/plan-generate) | जनरेटर — विनिर्देश से प्लान-सूट तक | मध्य-श्रृंखला |
| [/plan-review](/docs/pipeline/plan-review) | ऑडिटर — फ़ोरेंसिक प्लान ऑडिट | मध्य-श्रृंखला |
| [/plan-design](/docs/pipeline/plan-design) | आर्किटेक्ट — आर्किटेक्चर-धारक सूट के लिए `_inputs/design.md` | सशर्त गेट |
| [/plan-execute](/docs/pipeline/plan-execute) | एक्ज़ीक्यूटर — फ़ेज़ निष्पादन | टर्मिनल |
| [/plan-status](/docs/pipeline/plan-status) | रिपोर्टर — केवल-पढ़ने वाली स्थिति | केवल-पढ़ने |
| [/plan-audit](/docs/pipeline/plan-audit) | गार्जियन — spec → generate → review का बंद-लूप रैपर | ऑर्थोगोनल (पूर्व-निष्पादन) |
| /plan-amend | स्टीवर्ड — मौजूदा सूट का पुनः-प्रवेश योग्य संशोधन | पुनः-प्रवेश योग्य |

`/plan-audit` रैखिक प्रवाह के लिए ऑर्थोगोनल है, इसके भीतर एक चरण नहीं। यह
`/plan-spec → /plan-generate → /plan-review` को एक एकल बंद लूप के रूप में लपेटता
है, केवल लुप्त ऊपरी-धारा चरणों को चलाता है, निष्कर्षों का सक्रिय रूप से निवारण
करता है, और सूट को `/plan-execute` के लिए तैयार छोड़ देता है। यह नीचे दिए ऑडिट
समीक्षा अनुक्रम से भिन्न है, जो एक प्लान-सूट के बजाय एक निष्पादित कोडबेस का ऑडिट
करता है।

`/plan-design` एक सार्वभौमिक अनुष्ठान नहीं है। `/plan-review` वर्गीकृत करता है कि
क्या सूट आर्किटेक्चर-धारक सतहों को बदलता है। यदि हाँ, तो `/plan-design` वह डिज़ाइन
ट्रेस उत्सर्जित करता है जिसका उपभोग `/plan-execute` और `/architecture-review`
करते हैं। यदि नहीं, तो समीक्षित सूट सीधे निष्पादन में चला जाता है।

## शोध पाइपलाइन

शोध पाइपलाइन तेरह प्रथम-श्रेणी स्लैश कमांड के रूप में आती है, प्रति चरण एक —
प्रत्येक स्वतंत्र रूप से `/research-<stage>` के रूप में आह्वान-योग्य, एक अनुक्रम
गेट और एक हैंडऑफ़ मेनिफ़ेस्ट द्वारा शृंखलित, दस कठोरता अधिदेशों के तहत (आधिकारिक
स्रोत, पुनरुत्पादकता, मिथ्याकरणीयता, उद्धरण अखंडता, पूर्व-पंजीकरण,
नैतिकता / हितों का टकराव, सांख्यिकीय कठोरता, मुक्त-विज्ञान / FAIR,
रिपोर्टिंग-दिशानिर्देश अनुरूपता, सैद्धांतिक आधार / प्रभाव)।

```mermaid
flowchart LR
    accTitle: Research pipeline command flow
    accDescr: Left-to-right flowchart of the apothem research pipeline from the ideate stage through spec, theory, sources, synthesis, proposal, study design, experiment, analysis, paper, and peer review to publish and disseminate, with a revision loop from review back to paper.
    RI[/research-ideate] --> RS[/research-spec]
    RS --> RT[/research-theory]
    RT --> RSO[/research-sources]
    RSO --> RSY[/research-synthesis]
    RSY --> RPR[/research-proposal]
    RPR --> RD[/research-design]
    RD --> RE[/research-experiment]
    RE --> RA[/research-analysis]
    RA --> RP[/research-paper]
    RP --> RR[/research-review]
    RR --> RPU[/research-publish]
    RPU --> RDI[/research-disseminate]
    RR -.->|revision loop| RP
```

| चरण | भूमिका | स्थिति |
|-------|------|----------|
| [/research-ideate](/docs/pipeline/research-ideate) | समस्या तैयार करना — एक डोमेन बीज से उम्मीदवार प्रश्न | प्रारंभिक |
| [/research-spec](/docs/pipeline/research-spec) | प्रश्न को रूपायित करना — मिथ्याकरणीय परिकल्पनाएँ + दायरा | मध्य-श्रृंखला |
| [/research-theory](/docs/pipeline/research-theory) | वैचारिक ढाँचा + परिवर्तन-सिद्धांत | मध्य-श्रृंखला |
| [/research-sources](/docs/pipeline/research-sources) | व्यवस्थित स्रोत संग्रह | मध्य-श्रृंखला |
| [/research-synthesis](/docs/pipeline/research-synthesis) | SOTA मानचित्र + अंतराल विश्लेषण | मध्य-श्रृंखला |
| [/research-proposal](/docs/pipeline/research-proposal) | उद्देश्य + व्यवहार्यता + प्रभाव + पूर्व-पंजीकरण योजना | मध्य-श्रृंखला |
| [/research-design](/docs/pipeline/research-design) | अध्ययन डिज़ाइन + पूर्व-पंजीकरण | मध्य-श्रृंखला |
| [/research-experiment](/docs/pipeline/research-experiment) | चलाना + रिकॉर्ड करना, पुनरुत्पाद्य | मध्य-श्रृंखला |
| [/research-analysis](/docs/pipeline/research-analysis) | परिणाम + सांख्यिकी | मध्य-श्रृंखला |
| [/research-paper](/docs/pipeline/research-paper) | शीर्ष-स्तरीय शोध-पत्र मसौदा | मध्य-श्रृंखला |
| [/research-review](/docs/pipeline/research-review) | सहकर्मी-समीक्षा-स्तरीय आलोचना | मध्य-श्रृंखला |
| [/research-publish](/docs/pipeline/research-publish) | प्रकाशन-स्थल पैकेज + प्रस्तुति | मध्य-श्रृंखला |
| [/research-disseminate](/docs/pipeline/research-disseminate) | प्रसार + प्रभाव + FAIR अभिलेखन | टर्मिनल |

`/research` लिपटा हुआ वर्कफ़्लो ऑर्केस्ट्रेटर इन चरणों को कच्चे प्रश्न से
प्रकाशित शोध-पत्र तक संचालित करता है (यह स्वयं एक चरण नहीं है), अगला चरण उस पर
निर्माण करने से पहले प्रत्येक चरण के आउटपुट की स्वतंत्र रूप से जाँच करता है;
`--quick` एक एकल-शॉट उद्धृत रिपोर्ट के लिए केवल `/research-sources` +
`/research-synthesis` चलाता है।

आनुभविक चरण (स्रोत, डिज़ाइन, प्रयोग, विश्लेषण) और लेखन चरण (शोधपत्र, समीक्षा,
प्रकाशन, प्रसार) अतिरिक्त रूप से कठोरता को परिचालित करने वाली सतहों पर आधारित
होते हैं — निष्पक्ष बहु-विधि तुलना, तुलनित्र उद्गम, एक प्रयोग-कार्यक्रम मचान, एक
संगणना-उपयोग योजना, एक ऑप्ट-इन स्वायत्त प्रयोग लूप, एक परिभाषा-समाप्ति उन्नति
द्वार, और चरणबद्ध प्रकटन सहित अंधीकरण — जो दस अधिदेशों को उन्हें विस्तारित किए
बिना परिचालनात्मक विवरण जोड़ती हैं।

## ऑडिट समीक्षा अनुक्रम

`/audit` लिपटा हुआ वर्कफ़्लो ऑर्केस्ट्रेटर नीचे दिए सभी ग्यारह आयामों को एक एकल समानांतर पास के रूप में बहार देता है — यह `/plan` और `/research` का ऑडिट-दुर्ग सादृश्य है — एक एकल अद्वितीयकृत, गंभीरता-त्रिआज किया गया निष्कर्ष-रिपोर्ट संश्लेषित करता है (केवल-रिपोर्ट; निवारण `/elevate` को रूट किया जाता है)। प्रत्येक आयाम व्यक्तिगत रूप से भी आह्वान-योग्य है।

`/fortress` लिपटा हुआ वर्कफ़्लो ऑर्केस्ट्रेटर उस लूप को बंद करता है जिसकी `/audit` रिपोर्ट करता है: यह `/audit` के माध्यम से पता लगाता है, प्रत्येक निष्कर्ष को सत्यापित करता है, प्रत्येक उत्तरजीवी का उसकी स्वामी सतह पर निवारण करता है, एक बद्ध लूप में पुनः-ऑडिट करता है, और परिणाम को `/release-readiness` गेट से गुज़ारता है — यह `/plan` और `/research` का उत्पादन-सुदृढ़ीकरण सादृश्य है।
