**भूमिका:** ऑडिटर
**पाइपलाइन स्थिति:** मध्य

किसी मौजूदा प्लान सूट का फ़ोरेंसिक ऑडिट — गद्य निष्ठा, संगति, गुणवत्ता।

## विहित आह्वान

```bash
/plan-review
```

तर्कों के साथ:

```bash
/plan-review [path/to/plan-suite/] [--focus AREA] [--dry-run]
```

## इनपुट

`/plan-generate` से जनरेट किया गया प्लान सूट + `_inputs/handoff-manifest.yml`।

## आउटपुट

`PLAN-NOTES.md` में समीक्षा स्कोरकार्ड (`## Review Scorecards`), `PROGRESS.md` में एक समीक्षा सारांश, `PLAN-NOTES.md` में प्रति-निष्कर्ष संशोधन-प्रभाव मानचित्र (टिकाऊ बड़ी रिपोर्ट `_outputs/` में), और समीक्षा फ़ैसला वहन करता संवर्धित `_inputs/handoff-manifest.yml`।

## अनुप्रवाह

`/plan-design` (सशर्त — केवल वास्तुकला-वाहक सूट) फिर `/plan-execute`; गैर-वास्तुकला-वाहक सूट के लिए, `/plan-execute` SHARED+ पर निष्पादन को गेट करने हेतु समीक्षा स्कोरकार्ड सीधे उपभोग करता है।

## वर्कफ़्लो फ़ेज़

यह कमांड एक फ़ोरेंसिक, अंध, पंक्ति-दर-पंक्ति ऑडिट चलाता है फिर परस्पर-संवादी प्रश्नोत्तर के माध्यम से परिष्कृत करता है:

1. **संदर्भ लोड करें** — प्रत्येक प्लान-सूट फ़ाइल (`phases/**/PHASE.md`, अवसंरचना फ़ाइलें, रिपोर्ट) और अपस्ट्रीम हैंडऑफ़ मैनिफ़ेस्ट पढ़ें; सूट अनुपस्थित होने पर `Blocked: run /plan-generate first` के साथ अस्वीकार करें।
2. **ऑडिट करें** — अंध-समीक्षा अधिदेश के तहत आयामों (गद्य निष्ठा, आंतरिक संगति, पूर्णता, गुणवत्ता, जोखिम, मानक, डोमेन, वास्तुकला, रचनात्मक गुणवत्ता) का सर्वेक्षण करें।
3. **निष्कर्षों का वर्गीकरण करें** — प्रति-निष्कर्ष गंभीरता गणना के साथ संरचित-पूछताछ चैनल के माध्यम से प्रत्येक निष्कर्ष का निपटान करें (स्वीकार · संशोधित · अस्वीकार · स्थगित)।
4. **पूर्व-उत्सर्जन गेट चलाएँ** — समीक्षा रिपोर्ट और अद्यतन स्कोरकार्ड के विरुद्ध पंद्रह-बार गेट चलाएँ; विफलता पदोन्नति रोकती है।
5. **समीक्षा उत्सर्जित करें** — समीक्षा स्कोरकार्ड `PLAN-NOTES.md` में, समीक्षा सारांश `PROGRESS.md` में, और संवर्धित हैंडऑफ़ मैनिफ़ेस्ट लिखें।

## विफलता मोड

| लक्षण | कारण | पुनर्प्राप्ति |
|---------|-------|----------|
| Blocked: run /plan-generate first | कोई जनरेट किया गया सूट नहीं | यह कमांड जिस सूट का ऑडिट करता है उसे बनाने के लिए `/plan-generate` चलाएँ |
| खुले निष्कर्ष शेष | ऑडिट ने अनसुलझे दोष उजागर किए | टर्मिनल फ़ैसले से पहले प्रत्येक निष्कर्ष का निपटान करें (स्वीकार · संशोधित · अस्वीकार · स्थगित) |
| स्कोरकार्ड FAIL | कोई आयाम CONDITIONAL सीमा से नीचे गिरता है | विफल आयाम को संबोधित करें और पुनः-समीक्षा करें |

## उदाहरण

```bash
# ऑडिट दायरे का पूर्वावलोकन करने के लिए Dry-run
/plan-review --dry-run

# एक नामित प्लान सूट का ऑडिट, एक क्षेत्र पर केंद्रित
/plan-review path/to/plan-suite/ --focus architecture
```
