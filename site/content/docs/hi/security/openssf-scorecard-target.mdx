Apothem अधिकतम OpenSSF Scorecard स्कोर का लक्ष्य रखता है, साथ ही सार्वजनिक मुखौटे को इस बारे में ईमानदार रखता है कि Scorecard एक नई एकल-अनुरक्षक रिपॉज़िटरी से क्या अनुमान लगा सकता है और क्या नहीं। यह दस्तावेज़ प्रत्येक जाँच, उसका आधार बनने वाली साक्ष्य सतह, और मुद्रा को वर्तमान रखने वाले नियंत्रण को सूचीबद्ध करता है।

लाइव स्कोर [Scorecard व्यूअर](https://securityscorecards.dev/viewer/?uri=github.com/ahmed-g-gad/apothem) पर है; बैज [README हेडर](https://github.com/ahmed-g-gad/apothem/blob/main/README.md) में है।

## प्रति-जाँच साक्ष्य मैट्रिक्स

| जाँच | साक्ष्य सतह | टिप्पणियाँ |
|---|---|---|
| **Binary-Artifacts** | [binary-artifacts-sweep.md](/docs/security/binary-artifacts-sweep) | स्रोत में कोई निष्पादन-योग्य बाइनरी ट्रैक नहीं की जाती; उत्पन्न वितरण आर्काइव `dist/` में रहते हैं। |
| **Branch-Protection** | [branch-protection-ruleset.md](/docs/security/branch-protection-ruleset) | `main` सार्वजनिक रिलीज़ पदोन्नति से पहले सुरक्षित है; नया रिलीज़ कमिट उतरने के बाद फ़ोर्स-पुश और विलोपन अवरुद्ध हैं। |
| **CI-Tests** | [`.github/workflows/ci.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/ci.yml) | Pytest मैट्रिक्स, ruff, mypy, CodeQL, Trivy, दस्तावेज़ बिल्ड, और पैकेजिंग स्मोक जाँचें। |
| **CII-Best-Practices** | OpenSSF Best Practices पंजीकरण | OpenSSF Best Practices साइट पर अनुरक्षक-पक्ष पंजीकरण आवश्यक है; इसे केवल रिपॉज़िटरी फ़ाइलों से पूरा नहीं किया जा सकता। |
| **Code-Review** | ब्रांच सुरक्षा + CODEOWNERS | रिपॉज़िटरी व्यवस्थापकों को छोड़कर सभी के लिए `main` हेतु पुल रिक्वेस्ट आवश्यक हैं, और जब तक परियोजना का एक ही अनुरक्षक है, ब्रांच सुरक्षा 0 अनुमोदक समीक्षाओं की माँग करती है ([branch-protection-ruleset.md](/docs/security/branch-protection-ruleset) देखें); जब तक समीक्षित PR मौजूद नहीं होते, Scorecard इतिहास सीमित रहता है। |
| **Contributors** | [AUTHORS](https://github.com/ahmed-g-gad/apothem/blob/main/AUTHORS) | एक नई एकल-अनुरक्षक परियोजना बहु-संगठन योगदान इतिहास गढ़ नहीं सकती; जैसे-जैसे योगदानकर्ता जुड़ते हैं, यह स्वाभाविक रूप से बेहतर होता है। |
| **Dangerous-Workflow** | वर्कफ़्लो ऑडिट | कोई `pull_request_target` नहीं; Actions SHA-पिन किए गए हैं और स्पष्ट अनुमतियों के साथ सीमित हैं। |
| **Dependency-Update-Tool** | [`renovate.json`](https://github.com/ahmed-g-gad/apothem/blob/main/renovate.json) | Renovate GitHub Actions, Python मैनिफ़ेस्ट, हैश-लॉक की गई रिलीज़ आवश्यकताओं और npm सतहों को कवर करता है, साथ ही समूहीकृत निर्भरता PR उपलब्ध रखता है। |
| **Fuzzing** | [`tests/property/`](https://github.com/ahmed-g-gad/apothem/tree/main/tests/property) | Hypothesis प्रॉपर्टी परीक्षण पार्सर और frontmatter अपरिवर्तनीयों को परखते हैं; हो सकता है कि अपस्ट्रीम Scorecard Hypothesis को फ़ज़र एकीकरण के रूप में श्रेय न दे। |
| **License** | [LICENSE](https://github.com/ahmed-g-gad/apothem/blob/main/LICENSE) | रिपॉज़िटरी रूट पर MIT लाइसेंस। |
| **Maintained** | Git इतिहास | वर्तमान रिलीज़ कमिट और सक्रिय वर्कफ़्लो ताल अनुरक्षण को प्रदर्शित करते हैं; बहुत नई रिपॉज़िटरी को आयु चेतावनी मिल सकती है। |
| **Packaging** | [`.github/workflows/`](https://github.com/ahmed-g-gad/apothem/tree/main/.github/workflows) | sdist, wheel, SBOM, SLSA प्रोवेनेंस और Sigstore हस्ताक्षर उत्पन्न करने वाले रिलीज़, Pages और npmjs.com वर्कफ़्लो। |
| **Pinned-Dependencies** | वर्कफ़्लो ऑडिट + हैश-लॉक आवश्यकताएँ | Actions SHA-पिन किए गए हैं; रिलीज़ टूलिंग इंस्टॉल `--require-hashes` का उपयोग करते हैं; केवल-वर्कफ़्लो pip टूल सटीक पिन का उपयोग करते हैं। |
| **SAST** | [`.github/workflows/codeql.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/codeql.yml) | Python और Actions में CodeQL `security-extended` क्वेरी। |
| **Security-Policy** | [SECURITY.md](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md) | समन्वित-प्रकटीकरण नीति, समर्थित-संस्करण मैट्रिक्स, और प्रतिक्रिया समयरेखा। |

| **Token-Permissions** | वर्कफ़्लो ऑडिट | वर्कफ़्लो डिफ़ॉल्ट रूप से केवल-पठन अनुमतियों का उपयोग करते हैं; लेखन स्कोप जॉब-स्थानीय हैं और डिप्लॉयमेंट/पैकेज संचालन से बँधे हैं। |
| **Vulnerabilities** | [`.github/workflows/pip-audit.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/pip-audit.yml) + [`.github/workflows/dependency-review.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/dependency-review.yml) | साप्ताहिक भेद्यता स्कैन और SARIF अपलोड के साथ CI स्कैन; dependency-review गेट उन पुल रिक्वेस्ट को अवरुद्ध करता है जो भेद्य या अननुमत-लाइसेंस वाली निर्भरताएँ लाते हैं। |

## स्कोर व्याख्या

Scorecard प्रत्येक जाँच को 0-10 पैमाने पर अंक देता है और समग्र स्कोर एक भारित औसत है। रिपॉज़िटरी इतिहास, तृतीय-पक्ष पंजीकरण, या योगदानकर्ता विविधता पर निर्भर नियंत्रणों को बढ़ा-चढ़ाकर दावा करने के बजाय स्पष्ट रूप से ट्रैक किया जाता है। किसी भी फ़ाइल-नियंत्रित जाँच पर विचलन तत्काल सुधार को ट्रिगर करता है।

## ताज़गी ताल

- **प्रति-पुश:** Scorecard वर्कफ़्लो `main` पर हर पुश पर फिर से चलता है।
- **साप्ताहिक:** सोमवार 02:30 UTC — अपस्ट्रीम-स्कोरिंग पद्धति में परिवर्तनों + मौजूदा पिन की गई निर्भरताओं के विरुद्ध प्रकट हुई नई भेद्यताओं को पकड़ता है।
- **प्रति-रिलीज़:** सार्वजनिक पदोन्नति से पहले, अनुरक्षक लाइव Scorecard व्यूअर सतह को सत्यापित करता है और किसी भी प्लेटफ़ॉर्म-स्थिति सीमा को दर्ज करता है।
