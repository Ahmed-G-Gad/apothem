किसी विरासत प्रति-हार्नेस वर्कस्पेस को साझा `.apothem` लेआउट में माइग्रेट करें।

## सारांश

```
apothem migrate-workspace [--project PATH] [--dry-run]
                          [--quiet|-q] [--verbose|-v]
                          [--format plain|json] [--json] [--no-color]
```

`migrate-workspace` एक विरासत प्रति-हार्नेस डेटा होम
(`.apothem/<harness>/...`) और एक विरासत `.plans/` वृक्ष को एकल साझा
`.apothem/{plans,memory,learning,contexts}` वर्किंग डायरेक्टरी में समेट देता है।
आधार, दिए जाने पर, हल किया गया `--project` रूट होता है, अन्यथा वर्तमान वर्किंग
डायरेक्टरी (प्रोजेक्ट-स्थानीय डिफ़ॉल्ट)।

प्रति-हार्नेस मेमोरी, कॉन्टेक्स्ट और लर्निंग स्टोर id के आधार पर साझा स्टोर में
यूनियन-मर्ज होते हैं; लर्निंग सिग्नल जोड़े जाते हैं और उनके दोहराव हटा दिए जाते
हैं; विरोधी रिकॉर्ड (समान id, भिन्न बॉडी) छोड़ दिया जाता है, कभी अधिलेखित नहीं
किया जाता। विरासत `.plans/` वृक्ष `.apothem/plans/` के अंतर्गत चला जाता है। हर
उपभोग किए गए स्रोत का पहले बैकअप लिया जाता है। माइग्रेशन इडेम्पोटेंट है —
पहले से माइग्रेट किए गए वृक्ष पर इसे फिर से चलाना कोई प्रभाव नहीं डालता (no-op)।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--project PATH` | उन प्रोजेक्ट-स्कोप अडैप्टरों के लिए प्रोजेक्ट रूट जो उपयोगकर्ता-स्कोप कॉन्फ़िगरेशन डायरेक्टरी के बजाय किसी प्रोजेक्ट वृक्ष में मटेरियलाइज़ करते हैं। |
| `--dry-run` | विरासत लेआउट का पता लगाता है और बिना लिखे रिपोर्ट करता है कि क्या माइग्रेट होगा। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट दबाता है; केवल त्रुटियाँ उत्सर्जित होती हैं। |
| `--verbose`, `-v` | अतिरिक्त निदान आउटपुट उत्सर्जित करता है। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड अक्षम करता है। |
| `-h`, `--help` | सहायता दिखाता है और बाहर निकलता है। |

## JSON आउटपुट

`--json` एनवेलप माइग्रेशन का परिणाम रखता है। पूर्ण हुए माइग्रेशन पर `status`
`success` होता है और पेलोड मर्ज किए गए रिकॉर्डों की गिनती, कोई `.plans/` वृक्ष
स्थानांतरित हुआ या नहीं, बैकअप रूट, और छोड़े गए कोई भी विरोध रिपोर्ट करता है।
`--dry-run` आह्वान इसके बजाय `legacy_layout_detected` रिपोर्ट करता है।

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "status": "success",
  "base": "/home/example/project",
  "migrated": true,
  "backup_root": "/home/example/project/.apothem/.backups/01J9Z…",
  "memory_merged": 12,
  "contexts_merged": 4,
  "learning_merged": 7,
  "conflicts": [],
  "plans_moved": true,
  "notes": []
}
```

जब कोई विरासत लेआउट मौजूद नहीं होता, तो `migrated` `false` होता है और कुछ भी
नहीं लिखा जाता। `--dry-run` एनवेलप परिणाम की गिनतियाँ छोड़ देता है और केवल पहचान
की रिपोर्ट करता है:

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "base": "/home/example/project",
  "dry_run": true,
  "legacy_layout_detected": false
}
```

## उदाहरण

```bash
apothem migrate-workspace
apothem migrate-workspace --project .
apothem migrate-workspace --dry-run --json
```

## निकास कोड

| कोड | अर्थ |
|---|---|
| 0 | माइग्रेशन पूर्ण हुआ, या कोई विरासत लेआउट नहीं मिला (माइग्रेट करने के लिए कुछ नहीं) |
| 1 | अपेक्षित त्रुटि — कोई सत्यापन या प्रोजेक्ट-रूट त्रुटि, या माइग्रेशन विफलता |
| 64 | उपयोग त्रुटि: कोई अज्ञात विकल्प या कमांड, या कोई लुप्त या अमान्य विकल्प मान। `--json` के अंतर्गत त्रुटि `cli.usage` कोड वाला एक JSON एनवेलप होती है। |
