प्रति-कोडिंग-सहायक एक लीगेसी वर्कस्पेस को साझा `.apothem` लेआउट में माइग्रेट करता है।

## सारांश

```
apothem migrate-workspace [--project PATH] [--dry-run]
                          [--quiet|-q] [--verbose|-v]
                          [--format plain|json] [--json] [--no-color]
```

`migrate-workspace` एक प्रति-कोडिंग-सहायक लीगेसी डेटा होम
(`.apothem/<harness>/...`) और एक लीगेसी `.plans/` ट्री को एकल साझा कार्यशील डायरेक्टरी
`.apothem/{plans,memory,learning,contexts}` में समेट देता है। आधार वह हल किया गया
`--project` रूट होता है जब प्रदान किया जाए, अन्यथा वर्तमान कार्यशील डायरेक्टरी
(परियोजना-स्थानीय डिफ़ॉल्ट)।

प्रति-कोडिंग-सहायक मेमोरी, कॉन्टेक्स्ट और लर्निंग स्टोर id के अनुसार साझा स्टोर में
यूनियन-मर्ज होते हैं; लर्निंग सिग्नल जोड़े और डिडुप्लिकेट किए जाते हैं; एक विरोधी रिकॉर्ड
(समान id, भिन्न बॉडी) छोड़ दिया जाता है, कभी अधिलेखित नहीं होता। एक लीगेसी `.plans/` ट्री
`.apothem/plans/` के नीचे ले जाया जाता है। प्रत्येक उपभोग किए गए स्रोत का पहले बैकअप लिया
जाता है। यह माइग्रेशन इडम्पोटेंट है — पहले से माइग्रेट किए गए ट्री पर फिर से चलाना कोई-ऑप है।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--project PATH` | परियोजना-स्कोप्ड अडैप्टरों के लिए परियोजना रूट जो उपयोगकर्ता-स्कोप्ड कॉन्फ़िगरेशन डायरेक्टरी के बजाय परियोजना ट्री में मूर्तिकृत होते हैं। |
| `--dry-run` | लीगेसी लेआउट का पता लगाता है और बिना लिखे रिपोर्ट करता है कि क्या माइग्रेट होगा। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट को दबाता है; केवल त्रुटियाँ उत्सर्जित होती हैं। |
| `--verbose`, `-v` | अतिरिक्त नैदानिक आउटपुट उत्सर्जित करता है। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड को अक्षम करता है। |
| `-h`, `--help` | सहायता दिखाता है और बाहर निकलता है। |

## JSON आउटपुट

`--json` एनवेलप माइग्रेशन परिणाम ले जाता है। पूर्ण हुए माइग्रेशन पर `status` `success`
होता है और पेलोड मर्ज किए गए रिकॉर्ड की गिनती, क्या `.plans/` ट्री को स्थानांतरित किया गया,
बैकअप रूट, और कोई भी छोड़े गए विरोध रिपोर्ट करता है। एक `--dry-run` आह्वान इसके बजाय
`legacy_layout_detected` रिपोर्ट करता है।

```json
{
  "command": "migrate-workspace",
  "status": "success",
  "base": "/home/example/project",
  "migrated": true,
  "backup_root": "/home/example/project/.apothem/.backups/01J9Z…",
  "memory_merged": 12,
  "contexts_merged": 4,
  "learning_merged": 7,
  "conflicts": [],
  "plans_moved": true,
  "notes": []
}
```

जब कोई लीगेसी लेआउट मौजूद नहीं होता, तो `migrated` `false` होता है और कुछ भी नहीं लिखा जाता।
`--dry-run` एनवेलप परिणाम गिनती को छोड़ देता है और केवल पहचान रिपोर्ट करता है:

```json
{
  "command": "migrate-workspace",
  "base": "/home/example/project",
  "dry_run": true,
  "legacy_layout_detected": false
}
```

## उदाहरण

```bash
apothem migrate-workspace
apothem migrate-workspace --project .
apothem migrate-workspace --dry-run --json
```

## निकास कोड

| कोड | अर्थ |
|---|---|
| 0 | माइग्रेशन पूर्ण हुआ, या कोई लीगेसी लेआउट नहीं मिला (माइग्रेट करने के लिए कुछ नहीं) |
| 1 | अपेक्षित त्रुटि — एक मान्यता या परियोजना-रूट त्रुटि, या माइग्रेशन विफलता |
