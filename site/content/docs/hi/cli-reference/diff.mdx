किसी एकल हार्नेस के लिए लंबित कॉन्फ़िगरेशन परिवर्तनों का पूर्वावलोकन करें।

## सारांश

```
apothem diff --harness NAME [--profile PATH] [--project PATH]
             [--quiet|-q] [--verbose|-v]
             [--format plain|json] [--json] [--no-color]
```

`diff` एक केवल-पढ़ने वाला निरीक्षण कमांड है। यह वही मटेरियलाइज़ेशन चलाता है जो
`install` कमांड चलाता, लेकिन ड्राई-रन मोड में — डिस्क पर कुछ भी नहीं लिखा जाता।
प्रत्येक लंबित लक्ष्य के लिए यह एक सरल-भाषा क्रिया (उदाहरण के लिए `Write file`,
`Merge directory`, `Install skills`, या `Prune stale files`), लक्ष्य पथ, एक
पूर्वावलोकन स्थिति (`would create`, `would update`, `would remove`, या
`no change`), और — उन ऑपरेटर-स्वामित्व वाले एंकरों के लिए जिन्हें मर्ज किया
जाएगा — परिवर्तन का एकीकृत diff रेंडर करता है। स्थिति की गणना स्रोत की तुलना
वर्तमान ऑन-डिस्क लक्ष्य से करके की जाती है, इसलिए पहले से मेल खाने वाला लक्ष्य
`no change` दिखाता है और डिफ़ॉल्ट दृश्य से छिपा रहता है। यह परिवर्तन किए बिना इस
प्रश्न का उत्तर है: "इस समय `apothem install` इस हार्नेस के साथ क्या करेगा?"

योजना उन सभी पथों को कवर करती है जिन पर इंस्टॉल लिखता है: मैनिफ़ेस्ट प्रविष्टियाँ,
हार्नेस की अपनी कॉन्फ़िग फ़ाइल (उदाहरण के लिए `opencode.json` या
`config.yaml`), वह निर्देश एंकर या प्रोफ़ाइल दस्तावेज़ जिसमें साझा प्रोफ़ाइल
प्रक्षेपित की जाती है (जैसे `CLAUDE.md`), और `.apothem/` के अंतर्गत साझा डेटा
स्टोर। किसी इंस्टॉल के ठीक बाद `diff` कोई लंबित परिवर्तन रिपोर्ट नहीं करता; तब
पुनः-इंस्टॉल कुछ भी नहीं लिखता और कोई नया बैकअप नहीं लेता। `install --dry-run`
वही योजना दिखाता है।

ऑपरेटर-स्वामित्व वाले लक्ष्यों के लिए — वे फ़ाइलें जिनमें आपकी अपनी सामग्री और
एक Apothem-प्रबंधित ब्लॉक दोनों होते हैं — diff ठीक वे पंक्तियाँ दिखाता है जो
बदलेंगी। अन्य लक्ष्यों के लिए, नियोजित क्रिया और पूर्वावलोकन स्थिति का सारांश
दिया जाता है।

डिफ़ॉल्ट दृश्य केवल लंबित परिवर्तनों को सूचीबद्ध करता है। अपरिवर्तित लक्ष्यों
सहित पूरी योजना देखने के लिए `--verbose` पास करें; उसमें प्रत्येक लक्ष्य पर कच्चा
आंतरिक ऑपरेशन प्रकार और परिणाम अंकित होता है। `--json` एनवेलप डिस्प्ले परत से
अप्रभावित रहता है: यह मशीन उपभोक्ताओं के लिए हमेशा कच्चे `operation` और
`outcome` फ़ील्ड रखता है।

`diff` एकल हार्नेस पर कार्य करता है। `install` या `verify` के विपरीत, यह `all`
स्वीकार नहीं करता; एक हार्नेस नाम पास करें।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--harness NAME` | पूर्वावलोकन करने के लिए हार्नेस अडैप्टर (आवश्यक; एकल हार्नेस, `all` नहीं)। |
| `--profile PATH` | साझा प्रोफ़ाइल YAML का पथ। डिफ़ॉल्ट `~/.config/apothem/profile.yaml` है। |
| `--project PATH` | प्रोजेक्ट-स्कोप हार्नेसों के लिए प्रोजेक्ट रूट। चयनित हार्नेस प्रोजेक्ट-स्कोप होने पर आवश्यक। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट दबाता है; केवल त्रुटियाँ उत्सर्जित होती हैं। |
| `--verbose`, `-v` | अपरिवर्तित लक्ष्यों सहित पूरी योजना दिखाता है, जिसमें कच्चा ऑपरेशन प्रकार और परिणाम अंकित होता है। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड अक्षम करता है। |
| `-h`, `--help` | सहायता दिखाता है और बाहर निकलता है। |

## JSON आउटपुट

`--json` एनवेलप ड्राई-रन इंस्टॉल एनवेलप को प्रतिबिंबित करता है। `status`
`dry_run` होता है, `files_written` हमेशा खाली रहता है, और `materialization` ब्लॉक
तथा `results` सूची पूर्ण नियोजित-लक्ष्य विवरण रखते हैं। प्रत्येक
ऑपरेटर-स्वामित्व वाली परिणाम पंक्ति का `detail.diff` फ़ील्ड एकीकृत diff
स्ट्रिंग रखता है।

```json
{
  "schema_version": 1,
  "status": "dry_run",
  "command": "diff",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "sentinel_merge",
      "path": "C:\\Users\\Example\\.claude\\CLAUDE.md",
      "message": "dry run: no filesystem changes made",
      "detail": {
        "ownership_class": "operator-owned",
        "diff": "--- a/CLAUDE.md\n+++ b/CLAUDE.md\n@@ ..."
      }
    }
  ],
  "warnings": [],
  "error": null,
  "materialization": { "...": "..." }
}
```

## उदाहरण

```bash
apothem diff --harness claude-code
apothem diff --harness cursor --project .
apothem diff --harness claude-code --json
```

## निकास कोड

| कोड | अर्थ |
|---|---|
| 0 | diff रिपोर्ट किया गया (लंबित परिवर्तन रिपोर्ट किए जाते हैं, यह त्रुटि नहीं है) |
| 1 | अपेक्षित सत्यापन, प्रोफ़ाइल, हार्नेस, या प्रोजेक्ट त्रुटि |
| 64 | उपयोग त्रुटि: कोई अज्ञात विकल्प या कमांड, या कोई लुप्त या अमान्य विकल्प मान। `--json` के अंतर्गत त्रुटि `cli.usage` कोड वाला एक JSON एनवेलप होती है। |
