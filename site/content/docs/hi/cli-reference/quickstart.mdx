निर्देशित पहला रन: सुनिश्चित करें कि एक प्रोफ़ाइल मौजूद है, लेखन का पूर्वावलोकन
करें, फिर इंस्टॉल करें।

## सारांश

```
apothem quickstart [--harness NAME|all] [--project PATH] [--profile PATH]
                   [--yes] [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

`quickstart` एक नए ऑपरेटर के लिए एकमात्र निर्देशित प्रवेश बिंदु है। एक रैखिक
प्रवाह में यह: (1) सुनिश्चित करता है कि एक साझा प्रोफ़ाइल मौजूद है — यदि कोई
नहीं मिलती, तो वैयक्तिकरण के संकेत के साथ एक स्टार्टर प्रोफ़ाइल बनाता है;
(2) उन ठोस फ़ाइलों का पूर्वावलोकन करता है जिन्हें चयनित हार्नेस लिखेंगे,
प्रोजेक्ट रूट बनाम आपकी होम डायरेक्टरी के अनुसार समूहबद्ध; (3) पुष्टि माँगता
है; (4) समूहबद्ध, शोर-रहित क्षमता-नोट आउटपुट के साथ इंस्टॉल करता है; और
(5) अनुशंसित अगले कमांड प्रिंट करता है।

यह उन्हीं बिल्डिंग ब्लॉकों को जोड़ता है जिनका उपयोग `install` कमांड करता है —
यह उन्हें फिर से लागू नहीं करता। `--project` का डिफ़ॉल्ट वर्तमान डायरेक्टरी है।
`--harness` का कोई डिफ़ॉल्ट नहीं है: जब इसे छोड़ा जाता है, तो `quickstart`
पूछता है कि कौन-सा हार्नेस इंस्टॉल करना है, इसलिए पहला रन एक हार्नेस का
कॉन्फ़िगरेशन लिखता है। `--harness all` हर समर्थित हार्नेस इंस्टॉल करता है और
हमेशा एक स्पष्ट चुनाव होता है।

## व्यवहार

- **हार्नेस** — `--harness` के बिना, एक इंटरैक्टिव रन समर्थित नाम (साथ में
  `all`) सूचीबद्ध करता है और कुछ भी लिखे जाने से पहले उनमें से एक के लिए पूछता
  है। जो रन पूछ नहीं सकता — `--yes`, `--format json`, या कोई टर्मिनल नहीं — वह
  `--harness` विकल्प का नाम बताने वाली एक उपयोग त्रुटि के साथ रुक जाता है, और
  कुछ भी नहीं लिखता।
- **प्रोफ़ाइल** — यदि रिज़ॉल्व किए गए प्रोफ़ाइल पथ पर कोई फ़ाइल नहीं है, तो
  `quickstart` एक स्टार्टर प्रोफ़ाइल बनाने की पेशकश करता है (`--yes`, एक
  गैर-इंटरैक्टिव शेल, या `--format json` के अंतर्गत स्वतः बनाता है) और
  वैयक्तिकृत करने के लिए प्लेसहोल्डर पहचान फ़ील्ड के नाम बताता है।
- **पूर्वावलोकन + पुष्टि** — किसी भी लेखन से पहले, टारगेट दो शीर्षकों के
  अंतर्गत सूचीबद्ध किए जाते हैं (प्रोजेक्ट रूट बनाम आपकी होम डायरेक्टरी); एक
  इंटरैक्टिव रन प्रोजेक्ट के बाहर लिखने से पहले पुष्टि करवाता है। `--yes`, एक
  गैर-इंटरैक्टिव शेल, और `--format json` बिना प्रॉम्प्ट किए आगे बढ़ते हैं।
  अस्वीकार करने पर किसी भी लेखन से पहले कार्य निरस्त हो जाता है।
- **इंस्टॉल** — जिन क्षमताओं का कोई हार्नेस नेटिव रूप से समर्थन नहीं करता,
  उन्हें प्रति हार्नेस एक समूहबद्ध नोट के रूप में सारांशित किया जाता है
  (प्रति-क्षमता विवरण के लिए `--verbose` पास करें); पूरा सेट हमेशा
  `--format json` की warnings ऐरे में होता है।
- **अगला चरण** — टर्मिनल आउटपुट अनुवर्ती कमांड के नाम बताता है
  (`apothem verify …`, `apothem doctor`)।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--harness NAME` | इंस्टॉल करने के लिए हार्नेस अडैप्टर, या रजिस्ट्री-व्यापी सेट के लिए `all`। कोई डिफ़ॉल्ट नहीं: एक इंटरैक्टिव रन पूछता है; एक गैर-इंटरैक्टिव रन को इसे पास करना होगा। |
| `--profile PATH` | साझा प्रोफ़ाइल YAML का पथ। डिफ़ॉल्ट `~/.config/apothem/profile.yaml` है। |
| `--project PATH` | प्रोजेक्ट-स्कोप हार्नेसों के लिए प्रोजेक्ट रूट। डिफ़ॉल्ट वर्तमान डायरेक्टरी है। |
| `--yes` | पूरे निर्देशित अनुक्रम को गैर-इंटरैक्टिव रूप से चलाएँ (हर प्रॉम्प्ट छोड़ें)। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट दबाएँ; केवल त्रुटियाँ उत्सर्जित होती हैं। |
| `--verbose`, `-v` | समूहबद्ध नोट के बजाय प्रत्येक गैर-प्रक्षेपित क्षमता का औचित्य प्रिंट करें। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड अक्षम करें। |
| `-h`, `--help` | सहायता दिखाएँ और बाहर निकलें। |

## JSON आउटपुट

`--format json` एक एकल दस्तावेज़ उत्सर्जित करता है जो प्रत्येक निर्देशित चरण का
सारांश देता है:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "quickstart",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "steps": [
    {"step": "profile", "outcome": "created", "path": "…", "placeholder_identity": ["name", "email", "github"]},
    {"step": "install", "status": "success", "harness": "all", "files_written": ["…"], "warnings": [], "results": []},
    {"step": "recommend", "next": ["apothem verify --harness all --project .", "apothem doctor"]}
  ],
  "recommended_next": ["apothem verify --harness all --project .", "apothem doctor"]
}
```

## उदाहरण

```bash
apothem quickstart                                  # asks which harness
apothem quickstart --harness claude-code --yes
apothem quickstart --harness all --project . --yes  # every harness, explicitly
apothem quickstart --harness claude-code --json
```

## निकास कोड

| कोड | अर्थ |
|---|---|
| 0 | निर्देशित रन पूरा हुआ |
| 1 | अपेक्षित सत्यापन, प्रोफ़ाइल, हार्नेस, प्रोजेक्ट या अडैप्टर त्रुटि |
| 2 | कम से कम एक लेखन के बाद आंशिक बैच मूर्तीकरण |
| 64 | उपयोग त्रुटि: एक अज्ञात विकल्प या कमांड, या एक लुप्त या अमान्य विकल्प मान। `--json` के अंतर्गत त्रुटि `cli.usage` कोड वाला एक JSON एनवेलप होती है। |
