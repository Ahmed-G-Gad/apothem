हर पंजीकृत हार्नेस के लिए इंस्टॉल, सत्यापन और ड्रिफ़्ट स्थिति की रिपोर्ट करें।

## सारांश

```
apothem status [--profile PATH] [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status` एक केवल-पढ़ने वाला निरीक्षण कमांड है। यह हर पंजीकृत हार्नेस अडैप्टर पर
क्रम से जाता है और प्रति हार्नेस तीन तथ्यों की रिपोर्ट करता है: क्या वह इंस्टॉल
है, क्या उसके प्रबंधित लक्ष्य सत्यापित होते हैं, और क्या इंस्टॉल किया गया
कॉन्फ़िगरेशन साझा प्रोफ़ाइल से भटक (ड्रिफ़्ट हो) गया है। यह डिस्क पर कुछ भी नहीं
लिखता।

प्रत्येक हार्नेस के लिए, `status` यह रिपोर्ट करता है:

| स्तंभ | अर्थ |
|---|---|
| `installed` | अडैप्टर का प्रबंधित कॉन्फ़िग उसके लक्ष्य पथ पर मौजूद है। |
| `verified` | अडैप्टर के प्रबंधित लक्ष्य मौजूद और मान्य हैं। |
| `drift` | प्रोफ़ाइल-निष्ठा निर्णय (नीचे देखें)। |

`drift` मान इनमें से एक होता है:

| मान | अर्थ |
|---|---|
| `in-sync` | इंस्टॉल किया गया कॉन्फ़िगरेशन ताज़ा प्रक्षेपित साझा प्रोफ़ाइल को अक्षरशः रखता है। |
| `drift` | हार्नेस इंस्टॉल है, लेकिन उसकी प्रक्षेपित प्रोफ़ाइल सामग्री अब वर्तमान साझा प्रोफ़ाइल से मेल नहीं खाती। फिर से प्रक्षेपित करने के लिए `apothem install` दोबारा चलाएँ। |
| `absent` | हार्नेस इंस्टॉल नहीं है, इसलिए तुलना करने के लिए कुछ नहीं है। |
| `needs-project` | किसी प्रोजेक्ट-स्कोप हार्नेस की रिपोर्ट `--project` के बिना की गई, इसलिए उसका लक्ष्य हल नहीं किया जा सकता। उसका निरीक्षण करने के लिए `--project PATH` पास करें। |
| `unknown` | डिफ़ॉल्ट प्रोफ़ाइल लोड नहीं की जा सकी, इसलिए किसी इंस्टॉल किए गए हार्नेस के पास तुलना के लिए कोई आधार-रेखा नहीं है। ड्रिफ़्ट निर्णय बहाल करने के लिए प्रोफ़ाइल ठीक करें। |

ड्रिफ़्ट की रिपोर्ट की जाती है, उसे कभी त्रुटि नहीं माना जाता: एक या अधिक हार्नेस
के `drift` रिपोर्ट करने पर भी `status` 0 के साथ बाहर निकलता है। ड्रिफ़्ट आपके
सेटअप के बारे में एक तथ्य है, कमांड की विफलता नहीं।

यदि डिफ़ॉल्ट साझा प्रोफ़ाइल लोड नहीं की जा सकती, तो स्वीप रद्द करने के बजाय
इंस्टॉल किए गए हार्नेसों के लिए ड्रिफ़्ट `unknown` पर अवनत हो जाता है
(installed/verified तथ्य फिर भी रिपोर्ट किए जाते हैं)। स्पष्ट रूप से दिया गया
`--profile` जो लोड नहीं किया जा सकता, एक उपयोगकर्ता त्रुटि है और इसके बजाय एक
संरचित त्रुटि के साथ रद्द हो जाता है।

यह अवनति हमेशा रिपोर्ट की जाती है: `status` प्रोफ़ाइल और समाधान को नामित करने
वाली एक सलाह प्रिंट करता है, और `--json` एनवेलप `warnings` में एक संगत
`drift_baseline_unavailable` प्रविष्टि रखता है। यह सबसे अधिक तब मायने रखता है जब
कोई हार्नेस इंस्टॉल नहीं है — तब हर पंक्ति `absent` दिखाती है और कोई `unknown`
सेल मौजूद नहीं होता, इसलिए सलाह ही एकमात्र संकेत है कि आधार-रेखा कभी लोड नहीं
हुई।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--profile PATH` | साझा प्रोफ़ाइल YAML जो ड्रिफ़्ट आधार-रेखा चुनती है। इसके बिना, डिफ़ॉल्ट प्रोफ़ाइल (`~/.config/apothem/profile.yaml`) का उपयोग होता है। |
| `--project PATH` | प्रोजेक्ट-स्कोप हार्नेसों के लिए प्रोजेक्ट रूट। इसके बिना, प्रोजेक्ट-स्कोप हार्नेस `needs-project` रिपोर्ट करते हैं। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट दबाता है; केवल त्रुटियाँ उत्सर्जित होती हैं। |
| `--verbose`, `-v` | अतिरिक्त निदान आउटपुट उत्सर्जित करता है। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड अक्षम करता है। |
| `-h`, `--help` | सहायता दिखाता है और बाहर निकलता है। |

## JSON आउटपुट

`--json` एनवेलप प्रति पंजीकृत हार्नेस एक परिणाम पंक्ति रखता है। हर पंक्ति
प्रलेखित कुंजियाँ `harness`, `installed`, `verified`, और `drift` रखती है।
स्वच्छ स्वीप पर `warnings` खाली होता है; जब डिफ़ॉल्ट प्रोफ़ाइल लोड नहीं की जा
सकी हो, तब इसमें `path`, `code`, `reason`, और `fix` के साथ एक
`drift_baseline_unavailable` प्रविष्टि होती है।

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

प्रति-अडैप्टर विफलता पृथक्करण: यदि कोई एकल अडैप्टर अपनी स्थिति रिपोर्ट करते समय
अपवाद उठाता है, तो उस हार्नेस की पंक्ति में `outcome: "error"` और एक `message`
होता है, शेष हार्नेस फिर भी सामान्य रूप से रिपोर्ट करते हैं, और प्रक्रिया कोड 2
के साथ बाहर निकलती है।

## उदाहरण

```bash
apothem status
apothem status --project .
apothem status --json
```

## निकास कोड

| कोड | अर्थ |
|---|---|
| 0 | स्थिति रिपोर्ट की गई (ड्रिफ़्ट की रिपोर्ट की जाती है, यह त्रुटि नहीं है) |
| 1 | अपेक्षित सत्यापन त्रुटि (अमान्य `--profile`, या ऐसा `--project` पथ जो मौजूद नहीं है) |
| 2 | कम से कम एक अडैप्टर अपनी स्थिति रिपोर्ट करने में विफल रहा |
| 64 | उपयोग त्रुटि: कोई अज्ञात विकल्प या कमांड, या कोई लुप्त या अमान्य विकल्प मान। `--json` के अंतर्गत त्रुटि `cli.usage` कोड वाला एक JSON एनवेलप होती है। |
