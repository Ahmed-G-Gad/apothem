प्रत्येक पंजीकृत कोडिंग-सहायक के लिए इंस्टॉल, सत्यापन और बहाव की स्थिति की रिपोर्ट करता है।

## सारांश

```
apothem status [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status` एक केवल-पढ़ने योग्य निरीक्षण कमांड है। यह प्रत्येक पंजीकृत कोडिंग-सहायक अडैप्टर को क्रमवार देखता है और प्रति कोडिंग-सहायक तीन तथ्यों की रिपोर्ट करता है: क्या वह इंस्टॉल है, क्या उसके प्रबंधित लक्ष्य सत्यापित होते हैं, और क्या इंस्टॉल किया गया कॉन्फ़िगरेशन साझा प्रोफ़ाइल से बह गया है। यह डिस्क पर कुछ भी नहीं लिखता।

प्रत्येक कोडिंग-सहायक के लिए, `status` रिपोर्ट करता है:

| स्तंभ | अर्थ |
|---|---|
| `installed` | अडैप्टर का प्रबंधित कॉन्फ़िगरेशन उसके लक्ष्य पथ पर मौजूद है। |
| `verified` | अडैप्टर के प्रबंधित लक्ष्य मौजूद और मान्य हैं। |
| `drift` | प्रोफ़ाइल-निष्ठा निर्णय (नीचे देखें)। |

`drift` मान निम्नलिखित में से एक होता है:

| मान | अर्थ |
|---|---|
| `in-sync` | इंस्टॉल किया गया कॉन्फ़िगरेशन ताज़ा प्रक्षेपित साझा प्रोफ़ाइल को अक्षरशः धारण करता है। |
| `drift` | कोडिंग-सहायक इंस्टॉल है लेकिन उसका प्रक्षेपित प्रोफ़ाइल सामग्री अब वर्तमान साझा प्रोफ़ाइल से मेल नहीं खाती। पुनः प्रक्षेपण के लिए `apothem install` फिर से चलाएँ। |
| `absent` | कोडिंग-सहायक इंस्टॉल नहीं है, इसलिए तुलना करने के लिए कुछ नहीं है। |
| `needs-project` | एक परियोजना-स्कोप्ड कोडिंग-सहायक की रिपोर्ट `--project` के बिना की गई, इसलिए उसका लक्ष्य हल नहीं किया जा सकता। उसका निरीक्षण करने के लिए `--project PATH` पास करें। |

बहाव की रिपोर्ट की जाती है, उसे कभी त्रुटि के रूप में नहीं माना जाता: एक या अधिक कोडिंग-सहायक `drift` की रिपोर्ट करने पर भी `status` 0 के साथ बाहर निकलता है। बहाव आपके सेटअप के बारे में एक तथ्य है, कमांड की विफलता नहीं।

यदि साझा प्रोफ़ाइल लोड नहीं की जा सकती, तो इंस्टॉल किए गए कोडिंग-सहायकों के लिए बहाव `absent` पर अवनत हो जाता है (installed/verified तथ्य फिर भी रिपोर्ट किए जाते हैं) बजाय इसके कि पूरा स्वीप रद्द हो जाए।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--project PATH` | परियोजना-स्कोप्ड कोडिंग-सहायकों के लिए परियोजना रूट। इसके बिना, परियोजना-स्कोप्ड कोडिंग-सहायक `needs-project` की रिपोर्ट करते हैं। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट को दबाता है; केवल त्रुटियाँ निकाली जाती हैं। |
| `--verbose`, `-v` | अतिरिक्त नैदानिक आउटपुट निकालता है। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड अक्षम करता है। |
| `-h`, `--help` | सहायता दिखाता है और बाहर निकलता है। |

## JSON आउटपुट

`--json` एनवेलप प्रत्येक पंजीकृत कोडिंग-सहायक के लिए एक परिणाम पंक्ति ले जाता है। प्रत्येक पंक्ति प्रलेखित कुंजियाँ `harness`, `installed`, `verified` और `drift` ले जाती है।

```json
{
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

प्रति-अडैप्टर विफलता पृथक्करण: यदि कोई एकल अडैप्टर अपनी स्थिति की रिपोर्ट करते समय अपवाद उठाता है, तो उस कोडिंग-सहायक की पंक्ति `outcome: "error"` और एक `message` ले जाती है, शेष कोडिंग-सहायक फिर भी सामान्य रूप से रिपोर्ट करते हैं, और प्रक्रिया कोड 2 के साथ बाहर निकलती है।

## उदाहरण

```bash
apothem status
apothem status --project .
apothem status --json
```

## निकास कोड

| कोड | अर्थ |
|---|---|
| 0 | स्थिति रिपोर्ट की गई (बहाव की रिपोर्ट की जाती है, त्रुटि नहीं) |
| 2 | कम से कम एक अडैप्टर अपनी स्थिति रिपोर्ट करने में विफल रहा |
