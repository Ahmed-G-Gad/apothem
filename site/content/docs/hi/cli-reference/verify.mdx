एक हार्नेस अडैप्टर इंस्टॉलेशन सत्यापित करें।

## सारांश

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

प्रत्येक चयनित अडैप्टर के `verify()` कार्यान्वयन को कॉल करता है। केवल तभी 0 के
साथ बाहर निकलता है जब सभी चयनित अडैप्टर रिपोर्ट करें कि उनके प्रबंधित टारगेट
मौजूद और वैध हैं। `--profile` के बिना जाँच **संरचनात्मक** होती है — हर
प्रबंधित टारगेट का मौजूद और वैध होना अनिवार्य है। `--profile` के साथ जाँच को
अतिरिक्त रूप से **प्रोफ़ाइल-निष्ठा** की आवश्यकता होती है, इसलिए एक
मौजूद-लेकिन-ड्रिफ़्ट हुआ इंस्टॉल verify में विफल होता है, और यह केवल "क्या यह
मौजूद है?" के बजाय "क्या ठीक यही प्रोफ़ाइल निष्ठापूर्वक इंस्टॉल है?" का उत्तर
देता है।

जो अडैप्टर आपकी होम डायरेक्टरी में स्किल लिखता है, उसके लिए verify यह भी जाँचता
है कि हर अपेक्षित स्किल फ़ोल्डर एक `SKILL.md` के साथ मौजूद है, चाहे उसे किसी भी
इंस्टॉल ने लिखा हो, ताकि ऐसी मशीन verify में सफल हो जहाँ किसी फ़ोल्डर को साझा करने
वाले टूल में से केवल एक इंस्टॉल है। यह तब विफल होता है जब कोई फ़ोल्डर लुप्त हो,
और तब जब किसी Apothem स्किल के नाम वाला फ़ोल्डर किसी ऐसी चीज़ का हो जिसे Apothem
ने नहीं लिखा। विफल पंक्ति बताती है कि कौन-सा: plain मोड में उसके बाद एक `Note:`
पंक्ति आती है, और JSON पंक्ति में एक `user_level` ऑब्जेक्ट `missing` और
`unlisted` पथ तथा एक `message` सूचीबद्ध करता है। लुप्त फ़ोल्डर को पुनर्स्थापित
करने के लिए [`install`](/docs/cli-reference/install) चलाएँ; किसी बाहरी फ़ोल्डर
का नाम बदलें या उसे कहीं और ले जाएँ, फिर [`update`](/docs/cli-reference/update)
चलाएँ।

`--harness all` स्वीप प्रोफ़ाइल के `exclude_harnesses` का पालन करता है — वही
बहिष्करण जो `install`/`update` बैच ने लागू किए थे — इसलिए verify किसी
जान-बूझकर बहिष्कृत हार्नेस को कभी लुप्त के रूप में रिपोर्ट नहीं करता। बहिष्करण
`--profile` दिए जाने पर उससे आते हैं, अन्यथा डिफ़ॉल्ट प्रोफ़ाइल से; एक अपठनीय
या अनुपस्थित डिफ़ॉल्ट प्रोफ़ाइल होने पर यह पूरी रजिस्ट्री पर लौट आता है।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--harness NAME` | सत्यापित करने के लिए हार्नेस अडैप्टर, या रजिस्ट्री-व्यापी सेट के लिए `all` (आवश्यक)। |
| `--profile PATH` | वह साझा प्रोफ़ाइल YAML जिसके विरुद्ध निष्ठा जाँचनी है। इसके बिना जाँच पूरी तरह संरचनात्मक होती है। |
| `--project PATH` | प्रोजेक्ट-स्कोप हार्नेसों के लिए प्रोजेक्ट रूट। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट दबाएँ; केवल त्रुटियाँ उत्सर्जित होती हैं। |
| `--verbose`, `-v` | अतिरिक्त नैदानिक आउटपुट उत्सर्जित करें। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड अक्षम करें। |
| `-h`, `--help` | सहायता दिखाएँ और बाहर निकलें। |

## JSON आउटपुट

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

जब कोई चयनित हार्नेस लुप्त या अमान्य होता है, तो `status` `error` होता है,
विफल परिणाम पंक्ति `verified: false` वहन करती है, और प्रक्रिया कोड 1 के साथ
बाहर निकलती है।

## उदाहरण

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## निकास कोड

| कोड | अर्थ |
|---|---|
| 0 | हार्नेस सत्यापित — सभी प्रबंधित टारगेट मौजूद और वैध |
| 1 | हार्नेस सत्यापित नहीं — प्रबंधित टारगेट लुप्त या अमान्य |
| 64 | उपयोग त्रुटि: एक अज्ञात विकल्प या कमांड, या एक लुप्त या अमान्य विकल्प मान। `--json` के अंतर्गत त्रुटि `cli.usage` कोड वाला एक JSON एनवेलप होती है। |
