एक कोडिंग-सहायक को उसके रिकॉर्ड किए गए इंस्टॉल से पहले की स्थिति में पुनर्स्थापित करता है।

## सारांश

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` प्रत्येक चयनित कोडिंग-सहायक के इंस्टॉल-पूर्व बाइट्स को Apothem बैकअप रूट से पुनर्निर्मित करता है। यह रिकॉर्ड किए गए इंस्टॉल पास को रिज़ॉल्व करता है — डिफ़ॉल्ट रूप से सबसे नवीनतम, या `--install-id` द्वारा नामित वह — उस इंस्टॉल द्वारा कैप्चर किए गए प्रत्येक बैकअप को पुनर्स्थापित करता है, फिर कोडिंग-सहायक लेजर में एक `rollback` रिकॉर्ड जोड़ता है।

जब तक `--yes` न दिया जाए, प्रत्येक कोडिंग-सहायक के लिए पुष्टि का संकेत दिया जाता है। `--install-id` और `--last` इंस्टॉल पास का चयन करते हैं और परस्पर अनन्य हैं।

## विकल्प

| विकल्प | विवरण |
|---|---|
| `--harness NAME` | रोल बैक करने के लिए कोडिंग-सहायक अडैप्टर, या रजिस्ट्री-व्यापी सेट के लिए `all` (आवश्यक)। |
| `--install-id ULID` | नामित इंस्टॉल पास को रोल बैक करें। डिफ़ॉल्ट रूप से सबसे नवीनतम रिकॉर्ड किए गए इंस्टॉल पर। |
| `--last` | सबसे नवीनतम रिकॉर्ड किए गए इंस्टॉल को रोल बैक करें (डिफ़ॉल्ट; स्पष्ट रूप)। `--install-id` के साथ परस्पर अनन्य। |
| `--yes` | प्रति-कोडिंग-सहायक पुष्टि संकेत को छोड़ता है। |
| `--project PATH` | परियोजना-स्कोप्ड कोडिंग-सहायकों के लिए परियोजना रूट। आवश्यक जब चयनित सेट में परियोजना-स्कोप्ड अडैप्टर शामिल हों। |
| `--quiet`, `-q` | सूचनात्मक आउटपुट को दबाता है; केवल त्रुटियाँ उत्सर्जित होती हैं। |
| `--verbose`, `-v` | अतिरिक्त नैदानिक आउटपुट उत्सर्जित करता है। |
| `--format plain\|json` | आउटपुट प्रारूप (डिफ़ॉल्ट: `plain`)। |
| `--json` | `--format json` का संक्षिप्त रूप। |
| `--no-color` | आउटपुट में ANSI रंग कोड अक्षम करता है। |
| `-h`, `--help` | सहायता दिखाता है और बाहर निकलता है। |

## JSON आउटपुट

```json
{
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

प्रत्येक पुनर्स्थापित लक्ष्य `results` में `"operation": "rollback"` और `created` या `updated` के `outcome` के साथ प्रकट होता है (और `files_written` में)। एक ऐसा लक्ष्य जिसे इंस्टॉल ने नया बनाया था — जिसके पास पुनर्स्थापित करने के लिए कोई पूर्व बाइट्स नहीं थे — उसे `"outcome": "skipped"` के साथ रिपोर्ट किया जाता है; एक विफल पुनर्स्थापना `"outcome": "error"` है। जब कोई मिलान करने वाला इंस्टॉल रिकॉर्ड मौजूद नहीं होता, तो कमांड `"status": "error"` के साथ एक `rollback.no_record` त्रुटि रिपोर्ट करती है।

## उदाहरण

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## एग्ज़िट कोड

| कोड | अर्थ |
|---|---|
| 0 | सफलतापूर्वक रोल बैक किया गया, या पुनर्स्थापित करने के लिए कुछ नहीं था (इंस्टॉल ने कोई बैकअप कैप्चर नहीं किया) |
| 1 | अपेक्षित त्रुटि — कोई इंस्टॉल रिकॉर्ड नहीं, परस्पर विरोधी चयनकर्ता, अज्ञात कोडिंग-सहायक, अनुपस्थित परियोजना रूट, या निरस्त पुष्टि |
| 2 | कम से कम एक लक्ष्य के रोल बैक होने के बाद आंशिक पुनर्स्थापना |
