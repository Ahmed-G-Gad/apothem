यह शून्य से सत्यापित हार्नेस कॉन्फ़िगरेशन तक का सबसे तेज़ रास्ता है: इंस्टॉल करें,
साझा प्रोफ़ाइल परिभाषित करें, किसी टूल के नेटिव कॉन्फ़िगरेशन को मूर्त रूप दें, उसकी
पुष्टि करें, और अपना पहला संपादन करें। हर कमांड वास्तविक है और कॉपी-पेस्ट करने योग्य
है, और हर चरण दिखाता है कि एक स्वच्छ रन क्या प्रिंट करता है। इंस्टॉलेशन स्वयं दो
मिनट से कम में पूरा हो जाता है; केवल प्रोफ़ाइल संपादन में उतना ही समय लगता है जितना
आप चाहें।

अंत तक आपके पास एक कार्यशील हार्नेस कॉन्फ़िगरेशन होगा, जो आपकी लिखी प्रोफ़ाइल से
उत्पन्न हुआ — और आप वह एक कमांड जान जाएँगे जो किसी प्रोफ़ाइल परिवर्तन को हर टूल तक
वापस पहुँचा देता है।

<Callout title="वर्णन-सहित, इत्मीनान वाला संस्करण चाहिए?">
  [शुरुआती ट्यूटोरियल](/docs/tutorials/getting-started) उसी क्षेत्र को प्रत्येक
  चरण और वह क्यों महत्वपूर्ण है, इसकी अधिक व्याख्या के साथ पार करता है। यह पृष्ठ
  संक्षिप्त, आउटपुट-उन्मुख मार्गदर्शिका है।
</Callout>

आप उदाहरण हार्नेस के रूप में **Claude Code** का उपयोग करेंगे: यह इंस्टॉलर का
डिफ़ॉल्ट है। किसी अन्य टूल की ओर इंगित करने के लिए किसी भी चरण में अडैप्टर का नाम
बदलें; [हार्नेस सूची](/docs/harnesses) में सभी समर्थित नाम हैं।

## 1. Apothem इंस्टॉल करें

Apothem एक स्व-निहित रनटाइम के रूप में वितरित होता है: इंजन अंतर्निहित निर्भरताओं के
साथ सीधे अपने स्रोत-कोड वृक्ष से चलता है। एक कमांड स्रोत-कोड डाउनलोड करता है, इंजन
रखता है, और आपके पहले हार्नेस को मूर्त रूप देता है।

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 7+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

इंस्टॉलर को `click` और `rich` के आयात-योग्य होने के साथ एक सिस्टम Python 3.10+
चाहिए, साथ ही नेटवर्क रूप के लिए `git`। यह पूर्वापेक्षाएँ जाँचता है, इंजन को
`~/.apothem` में रखता है, और समाप्त होने पर आपके शेल के लिए सटीक इंजन-आह्वान
प्रिंट करता है।

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="`apothem` कमांड">
  इंस्टॉलर आपके `PATH` पर एक `apothem` shim रखता है, इसलिए आप इंजन को सीधे
  `apothem <command>` के रूप में चलाते हैं। यदि shim की डायरेक्टरी अभी `PATH` पर
  नहीं है, तो बैनर एक स्व-निहित फ़ॉलबैक प्रिंट करता है —
  `PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>` — जिसे किसी shim
  की ज़रूरत नहीं; अपने बैनर द्वारा प्रिंट किया गया सटीक उपसर्ग हर कमांड से पहले
  लगाएँ।
</Callout>

[इंस्टॉलेशन मार्गदर्शिका](/docs/install) अन्य इंस्टॉलेशन पथों को कवर करती है —
Claude Code प्लगइन (`/plugin marketplace add ahmed-g-gad/apothem` फिर
`/plugin install apothem@apothem`); VS Code-परिवार और अन्य टूल-नेटिव एक्सटेंशन;
और npx के साथ मांग-पर रूप (`npx @ahmed-g-gad/apothem <command>`) — पर्यावरण-चर
विकल्पों के साथ।

## 2. साझा प्रोफ़ाइल बनाएँ

`apothem profile init` सबसे छोटी संभव वैध प्रोफ़ाइल को
`~/.config/apothem/profile.yaml` में लिखता है। जब आप किसी परियोजना-विशिष्ट या
CI-विशिष्ट प्रोफ़ाइल को किसी अन्य स्थान पर रखें तो `--profile PATH` पास करें।

```bash
apothem profile init
apothem profile show --json
```

यह कंकाल प्लेसहोल्डर के काल्पनिक पहचान-डेटा का उपयोग करता है और किसी भी हार्नेस
आउटपुट को इंस्टॉल करने से पहले इसे संपादित करना सुरक्षित है। `show --json` इसे फिर
से पढ़ता है और सत्यापित प्रोफ़ाइल की रिपोर्ट करता है।

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

यहीं एक त्रुटिपूर्ण संपादन भी सामने आता है: यदि YAML अमान्य है, तो `show` इसे इसी
बिंदु पर रिपोर्ट करता है, किसी भी हार्नेस कॉन्फ़िगरेशन को लिखने से पहले। प्रोफ़ाइल
को अपना बनाएँ `apothem profile edit` से (यह इसे आपके संपादक में खोलता है) या मौके
पर एक कुंजी सेट करें।

```bash
apothem profile set identity.name "Your Name"
```

## 3. हार्नेस अडैप्टर इंस्टॉल करें

अपने मुख्य हार्नेस के अडैप्टर को मूर्त रूप दें। यह आपकी प्रोफ़ाइल पढ़ता है
और उस टूल का नेटिव कॉन्फ़िगरेशन लिखता है।

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

परियोजना-दायरे वाले अडैप्टर आपकी होम निर्देशिका के बजाय किसी परियोजना के भीतर
लिखते हैं, इसलिए उन्हें `--project PATH` चाहिए। फ़ाइलें लिखे बिना किसी भी इंस्टॉलेशन
का पूर्वावलोकन `--dry-run` से करें।

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

रजिस्ट्री-समर्थित पूरा सेट एक साथ `--harness all` से इंस्टॉल करें। चूँकि वह चयन
परियोजना-दायरे और उपयोगकर्ता-दायरे दोनों की फ़ाइलें लिखता है, कमांड स्थान के अनुसार
समूहीकृत ठोस गंतव्य प्रिंट करता है और परियोजना की जड़ के बाहर लिखने से पहले पुष्टि
माँगता है।

```bash
apothem install --harness all --project .
```

सभी समर्थित नामों के लिए [पूर्ण हार्नेस सूची](/docs/harnesses) देखें, और विकल्पों
के पूर्ण सेट के लिए [install संदर्भ](/docs/cli-reference/install) देखें।

## 4. सत्यापन

मूर्तीकरण काम का केवल आधा हिस्सा है: `verify` पुष्टि करता है कि हार्नेस की अपेक्षित
कॉन्फ़िगरेशन फ़ाइलें लिखी गई हैं और प्रोफ़ाइल जो घोषित करती है उससे मेल खाती हैं।

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

`verify` कॉन्फ़िगरेशन के गायब होने या विचलित होने पर शून्येतर कोड के साथ बाहर
निकलता है, इसलिए यह सेटअप स्क्रिप्ट में एक द्वार के रूप में भी काम करता है। हर
पंजीकृत अडैप्टर पर पूरे-मशीन स्वास्थ्य-जाँच के लिए चलाएँ:

```bash
apothem doctor
```

`doctor` हर अडैप्टर की इंस्टॉलेशन स्थिति की रिपोर्ट करता है और यदि कोई पंजीकृत
अडैप्टर स्वयं को अनइंस्टॉल बताए तो शून्येतर कोड के साथ बाहर निकलता है।

## 5. आपका पहला रन

जिस हार्नेस को आपने अभी कॉन्फ़िगर किया — इस उदाहरण में Claude Code — उसे
खोलें और किसी भी परियोजना में सत्र शुरू करें। चरण 2 में आपने प्रोफ़ाइल में जो नियम
और प्राथमिकताएँ लिखीं वे पहले से ही उस टूल के व्यवहार का हिस्सा हैं। यही पहला
कार्यशील रन है: एक प्रोफ़ाइल, एक वास्तविक सत्र को आकार देती हुई।

जब आप बाद में प्रोफ़ाइल बदलें, तो उसे पुनः इंस्टॉल किए बिना फिर से लागू करें।

```bash
apothem update --harness claude-code
```
