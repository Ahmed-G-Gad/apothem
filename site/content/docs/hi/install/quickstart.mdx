यह शून्य से एक सत्यापित हार्नेस कॉन्फ़िगरेशन तक का तेज़ रास्ता है: इंस्टॉल करें,
साझा प्रोफ़ाइल लिखें, एक टूल के नेटिव कॉन्फ़िग को मूर्त रूप दें, उसकी पुष्टि करें,
और अपना पहला संपादन करें। हर कमांड वास्तविक है और कॉपी-पेस्ट करके चलाया जा सकता
है, और हर चरण दिखाता है कि एक स्वच्छ रन क्या प्रिंट करता है। इंस्टॉल स्वयं दो
मिनट से कम में पूरा हो जाता है; प्रोफ़ाइल संपादित करना ही एकमात्र हिस्सा है जिसमें
उतना समय लगता है जितना आप चाहें।

अंत तक आपके पास आपकी लिखी प्रोफ़ाइल से उत्पन्न एक कार्यशील हार्नेस कॉन्फ़िगरेशन
होगा — और आप वह एक कमांड जान जाएँगे जो किसी प्रोफ़ाइल परिवर्तन को किसी एक टूल तक
या उन सभी तक वापस पहुँचा देता है।

<Callout title="धीमा, वर्णन-सहित संस्करण चाहिए?">
  [शुरुआती ट्यूटोरियल](/docs/tutorials/getting-started) उसी रास्ते से गुज़रता है,
  हर चरण और उसके महत्व की अधिक व्याख्या के साथ। यह पृष्ठ संक्षिप्त, आउटपुट-प्रथम
  मार्गदर्शिका है।
</Callout>

आप उदाहरण हार्नेस के रूप में **Claude Code** का उपयोग करेंगे — यह इंस्टॉलर का
डिफ़ॉल्ट है। किसी दूसरे टूल को लक्षित करने के लिए किसी भी चरण में अडैप्टर का नाम
बदल दें; [हार्नेस सूची](/docs/harnesses) में हर समर्थित नाम है।

## 1. Apothem इंस्टॉल करें

Apothem एक स्व-निहित रनटाइम के रूप में आता है — इंजन वेंडर की गई निर्भरताओं के
साथ सीधे अपने स्रोत ट्री से चलता है। एक कमांड स्रोत लाता है, इंजन को उसकी जगह
रखता है, और आपके पहले हार्नेस को मूर्त रूप देता है। चूँकि यह हस्ताक्षरित रिलीज़
को पहले सत्यापित करता है, इसलिए पहले इंस्टॉल से पहले एक बार मेंटेनर की हस्ताक्षर
कुंजी आयात करें और जाँच करें कि फ़िंगरप्रिंट
`5C89 98F9 F241 7204 45D3  F28B 7039 6FED 9C63 4163` पढ़ता है:

```bash title="macOS · Linux · WSL2 · BSD — import the key once"
curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import
gpg --fingerprint 70396FED9C634163
```

```powershell title="Windows · PowerShell — import the key once"
& "$env:ProgramFiles\Git\bin\bash.exe" -c 'curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import && gpg --fingerprint 70396FED9C634163'
```

फिर इंस्टॉलर चलाएँ:

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 5.1+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

इंस्टॉलर को एक सिस्टम Python 3.10+ चाहिए, और नेटवर्क इंस्टॉल के लिए `git` और
`gpg` भी। वह पूर्वापेक्षाओं की जाँच करता है और इंजन को `~/.apothem` के अंतर्गत
रखता है। जब `click` या `rich` अनुपस्थित हो, तो वह आपकी पुष्टि के साथ, या `--yes`
(PowerShell पर `-Yes`) अथवा `APOTHEM_AUTO_INSTALL_DEPS=1` होने पर, पैकेज
इंस्टॉल करता है; अन्यथा वह चलाने के लिए pip कमांड के साथ रुक जाता है
([पूर्वापेक्षाएँ एक नज़र में](/docs/install#पूर्वापेक्षाएँ-एक-नज़र-में) देखें)।
पूरा होने पर वह अगले-चरणों का बैनर प्रिंट करता है; POSIX पर, जब शिम की
डायरेक्टरी पहले से `PATH` पर हो, तो बैनर इस तरह दिखता है:

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="प्रोफ़ाइल के बिना पहला रन">
  यदि आपके पास अभी कोई प्रोफ़ाइल नहीं है, तो इंस्टॉलर उदाहरण प्रोफ़ाइल को
  `~/.config/apothem/profile.yaml` में कॉपी करता है और आगे बढ़ता है: वह आपके पहले
  हार्नेस को मूर्त रूप देता है और उसी रन में उसे सत्यापित करता है। उदाहरण के पहचान
  फ़ील्ड प्लेसहोल्डर हैं, इसलिए इंस्टॉल एक नोट प्रिंट करता है। चरण 2 में प्रोफ़ाइल
  को अपना बनाएँ, फिर चरण 5 की तरह उसे `apothem update --harness <name>` से लागू
  करें।
</Callout>

<Callout title="`apothem` कमांड">
  इंस्टॉलर एक `apothem` शिम को `$HOME/.local/bin` (POSIX) या
  `%LOCALAPPDATA%\Microsoft\WindowsApps` (Windows) में लिखता है और आपका `PATH`
  कभी संपादित नहीं करता। जब वह डायरेक्टरी `PATH` पर हो, तब आप इंजन को सीधे
  `apothem <command>` के रूप में चलाते हैं। यदि वह अभी `PATH` पर नहीं है,
  तो बैनर एक स्व-निहित फ़ॉलबैक प्रिंट करता है —
  `PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>` — जिसे किसी शिम
  की ज़रूरत नहीं होती; आपके बैनर ने जो सटीक उपसर्ग प्रिंट किया है, उसे हर कमांड के
  आगे लगाएँ।
</Callout>

[इंस्टॉलेशन गाइड](/docs/install) अन्य इंस्टॉल पथों को कवर करती है — Claude Code
प्लगइन (`/plugin marketplace add ahmed-g-gad/apothem` फिर
`/plugin install apothem@apothem`); VS Code-परिवार और अन्य टूल-नेटिव एक्सटेंशन;
और ऑन-डिमांड npx रूप (`npx @ahmed-g-gad/apothem <command>`) — साथ ही पर्यावरण-चर
विकल्प भी।

## 2. साझा प्रोफ़ाइल बनाएँ

`apothem profile init` सबसे छोटी स्कीमा-मान्य प्रोफ़ाइल को
`~/.config/apothem/profile.yaml` में लिखता है। यदि वहाँ पहले से कोई प्रोफ़ाइल है,
जैसे तब जब चरण 1 में इंस्टॉलर ने उदाहरण कॉपी किया हो, तो `init` त्रुटि के साथ रुक
जाता है और फ़ाइल को अपरिवर्तित छोड़ देता है; उसे अधिलेखित करने के लिए `--force`
पास करें, या फ़ाइल को रखें और नीचे दिखाए अनुसार संपादित करें। जब आप कोई
प्रोजेक्ट-विशिष्ट या CI-विशिष्ट प्रोफ़ाइल कहीं और रखते हों, तब `--profile PATH`
पास करें।

```bash
apothem profile init
apothem profile show --json
```

यह ढाँचा नकली प्लेसहोल्डर पहचान डेटा का उपयोग करता है, और किसी भी हार्नेस आउटपुट
को इंस्टॉल करने से पहले इसे संपादित करना सुरक्षित है। `show --json` इसे वापस पढ़ता
है और सत्यापित प्रोफ़ाइल की रिपोर्ट करता है:

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

यहीं कोई विकृत संपादन भी सामने आता है — यदि YAML अमान्य है, तो `show` इसकी
रिपोर्ट यहीं करता है, किसी भी हार्नेस कॉन्फ़िग के लिखे जाने से पहले।
`apothem profile edit` (जो इसे आपके संपादक में खोलता है) से प्रोफ़ाइल को अपना
बनाएँ, या एक अकेली कुंजी को उसी स्थान पर सेट करें:

```bash
apothem profile set identity.name "Your Name"
```

## 3. हार्नेस अडैप्टर इंस्टॉल करें

अपने प्राथमिक हार्नेस के लिए अडैप्टर को मूर्त रूप दें। यह आपकी प्रोफ़ाइल पढ़ता है
और उस टूल का नेटिव कॉन्फ़िगरेशन लिखता है:

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

प्रोजेक्ट-स्कोप अडैप्टर आपकी होम डायरेक्टरी के बजाय किसी प्रोजेक्ट के भीतर लिखते
हैं, इसलिए उन्हें एक `--project PATH` चाहिए। `--dry-run` का उपयोग करके फ़ाइलें
लिखे बिना किसी भी इंस्टॉल का पूर्वावलोकन करें:

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

`--harness all` से पूरे रजिस्ट्री-समर्थित सेट को एक साथ इंस्टॉल करें। चूँकि वह
चयन प्रोजेक्ट-स्कोप और उपयोगकर्ता-स्कोप दोनों की फ़ाइलें लिखता है, कमांड स्थान
के अनुसार समूहित ठोस टारगेट प्रिंट करता है। इंटरैक्टिव टर्मिनल में यह प्रोजेक्ट
रूट के बाहर लिखने से पहले पूछता है। बिना टर्मिनल वाला रन, `--yes` दिया गया रन, या
`--format json` वाला रन बिना पूछे लिखता है; `--dry-run` कुछ नहीं लिखता। पूरा सेट
इस कमांड से चलाएँ:

```bash
apothem install --harness all --project .
```

हर समर्थित नाम के लिए [पूर्ण हार्नेस सूची](/docs/harnesses) देखें, और विकल्पों के
पूरे सेट के लिए [install संदर्भ](/docs/cli-reference/install) देखें।

## 4. सत्यापित करें

मूर्त रूप देना केवल आधा काम है — `verify` पुष्टि करता है कि हार्नेस की अपेक्षित
कॉन्फ़िग फ़ाइलें सही जगह पहुँचीं और मान्य हैं:

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

यदि कोई प्रबंधित टारगेट गायब है, कोई प्रबंधित फ़ाइल खाली है, या कोई JSON या YAML
कॉन्फ़िग पार्स नहीं होती, तो `verify` शून्येतर एग्ज़िट कोड के साथ बाहर निकलता है।
`--profile PATH` जोड़ने पर इंस्टॉल की गई कोई फ़ाइल उस प्रोफ़ाइल से भिन्न होने पर भी
विफल होती है, जिससे `verify` एक ड्रिफ़्ट जाँच बन जाता है; उसके बिना पुरानी कॉन्फ़िग
भी सत्यापित हो जाती है। शून्येतर एग्ज़िट कोड `verify` को किसी सेटअप स्क्रिप्ट में
गेट के रूप में काम करने देता है। हर पंजीकृत अडैप्टर पर पूरी-मशीन की स्वास्थ्य जाँच
के लिए चलाएँ:

```bash
apothem doctor
```

`doctor` हर इंस्टॉल किए गए हार्नेस की जाँच करता है: उसका सत्यापन सफल होना चाहिए,
और उसके इंस्टॉल द्वारा पंजीकृत हर हुक कमांड को शुरू होना चाहिए। जो हार्नेस आपने
इंस्टॉल नहीं किया है, वह सूचीबद्ध होता है पर विफलता नहीं माना जाता, इसलिए जब कोई
जाँच विफल नहीं होती, तब `doctor` 0 के साथ बाहर निकलता है, भले ही केवल एक हार्नेस
इंस्टॉल हो।

## 5. आपका पहला रन

वह हार्नेस खोलें जिसे आपने अभी कॉन्फ़िगर किया — इस उदाहरण में Claude Code — और
किसी भी प्रोजेक्ट में एक सत्र शुरू करें। चरण 2 में आपने जो प्रोफ़ाइल सेट की, वह अब
उस टूल के व्यवहार का हिस्सा है। यही कार्यशील पहला रन है: एक प्रोफ़ाइल, जो एक
वास्तविक सत्र को आकार दे रही है।

जब आप बाद में प्रोफ़ाइल बदलें, तो उसे दोबारा इंस्टॉल किए बिना फिर से लागू करें:

```bash
apothem update --harness claude-code
```

उस टूल पर प्रोफ़ाइल को फिर से लागू करने के लिए किसी दूसरे अडैप्टर का नाम दें
(प्रोजेक्ट-स्कोप अडैप्टर के लिए `--project PATH` जोड़ें), या उसे हर समर्थित हार्नेस
पर फिर से लागू करने के लिए `--harness all --project .` पास करें।
