Apothem दो मिनट से कम में इंस्टॉल हो जाता है और आपके मौजूदा हार्नेस
कॉन्फ़िगरेशन के साथ-साथ काम करता है। हर पथ वही स्व-निहित इंजन चलाता है — स्रोत
ट्री अपनी वेंडर की गई निर्भरताएँ साथ रखता है और सिस्टम Python 3.10 या नए पर एक
चेकआउट से चलता है (देखें
[स्व-निहित रनटाइम](/docs/architecture/self-contained-runtime))।

**दो पूर्वापेक्षाएँ हर पथ में साझा हैं:** `PATH` पर सिस्टम **Python 3.10 या नया**,
जिसके अंतर्गत `click` और `rich` पैकेज आयात-योग्य हों। npm शिम (चैनल 2),
VS Code-परिवार एक्सटेंशन (चैनल 4), और कमांड-लाइन बूटस्ट्रैप (चैनल 5–7) को `npx`
चलाने के लिए अतिरिक्त रूप से **Node.js 18 या नए** की आवश्यकता होती है।
Python 3.10 तथा Node.js 18 और 20 अपस्ट्रीम जीवन-अंत पार कर चुके हैं; वे समर्थित और
परीक्षित बने रहते हैं, लेकिन नए संस्करणों को प्राथमिकता दी जाती है (देखें
[पूर्वापेक्षाएँ एक नज़र में](#पूर्वापेक्षाएँ-एक-नज़र-में))। नीचे प्रत्येक चैनल का
अपना अनुभाग उसकी सटीक पूर्वापेक्षाएँ, एक कॉपी-रेडी कमांड, और एक सत्यापन चरण
दोहराता है।

## 1. Claude Code प्लगइन

**पूर्वापेक्षाएँ:** Claude Code, और `PATH` पर सिस्टम Python 3.10+।

प्लगइन पथ पूरी तरह Claude Code के भीतर चलता है। यह Apothem इंजन को उसके स्लैश
कमांड, प्रत्यायोजित वर्कर, स्किल, नियम, और हुक के साथ बंडल करता है, जो सभी
स्व-निहित प्लगइन ट्री से चलाए जा सकते हैं:

```text title="Inside Claude Code"
/plugin marketplace add ahmed-g-gad/apothem
/plugin install apothem@apothem
```

इंस्टॉल के बाद, Apothem कमांड सेट, बंडल किए गए प्रत्यायोजित वर्कर, स्किल, और चार
[आउटपुट शैलियाँ](/docs/reference/output-styles) (`/output-style` से या `/config`
से कोई एक चुनें) हर Claude Code सत्र में उपलब्ध होते हैं। प्लगइन कमांड प्लगइन का
उपसर्ग रखते हैं: `/apothem:plan-spec`, `/apothem:security-audit`, और बाकी। Claude
Code संक्षिप्त रूप (`/plan-spec`) भी स्वीकार करता है, जब तक कोई अन्य कमांड उस नाम
का उपयोग नहीं करता। दो नाम स्वयं Claude Code ने ले रखे हैं: `/plan` प्लान मोड में
प्रवेश करता है और `/code-review` बंडल की गई समीक्षा चलाता है, इसलिए Apothem कमांड
के लिए `/apothem:plan` और `/apothem:code-review` टाइप करें। जब प्लगइन के बजाय
Apothem इंजन Claude Code में इंस्टॉल होता है, तो कमांड बिना उपसर्ग के
`~/.claude/skills/` के अंतर्गत व्यक्तिगत स्किल बन जाते हैं, और एक व्यक्तिगत
`code-review` स्किल बंडल किए गए `/code-review` का स्थान ले लेती है (उसका `/review`
उपनाम अब भी बंडल की गई समीक्षा चलाता है)। दो नाम, `projectify` और `workflow`,
कमांड और स्किल दोनों के रूप में शिप होते हैं; दोनों मौजूद होने पर Claude Code
स्किल चलाता है, इसलिए प्लगइन स्किल चलाता है और इंजन इंस्टॉल केवल स्किल को, कमांड से
व्युत्पन्न किसी स्किल को नहीं, `~/.claude/skills/<name>/` में लिखता है। पूर्ण कमांड
कैटलॉग के लिए [स्लैश कमांड](/docs/reference/commands) देखें।

**सत्यापित करें:** Claude Code के भीतर `/plugin` चलाएँ और पुष्टि करें कि **apothem**
इंस्टॉल के रूप में सूचीबद्ध है, या किसी टर्मिनल से ड्रिफ़्ट रिपोर्ट जाँचें:

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 2. npm शिम (`npx`)

**पूर्वापेक्षाएँ:** Node.js 18+ (`npx` के लिए) और `PATH` पर सिस्टम Python 3.10+।
शिम इंटरप्रेटर का पता लगाता है और हर CLI कमांड को बंडल किए गए इंजन को अग्रेषित
करता है — आपके सिस्टम पर स्थायी रूप से कुछ नहीं रखा जाता। यह इसी क्रम में
`python3`, `python`, फिर `py -3` आज़माता है; उसे सबसे पहले आज़माने के लिए
**`APOTHEM_PYTHON`** को किसी इंटरप्रेटर पथ पर सेट करें — इसकी आवश्यकता आपको तब होती
है जब Python इंस्टॉल है लेकिन `PATH` पर नहीं है, या जब कई संस्करण इंस्टॉल हैं और
आप कोई विशिष्ट संस्करण चाहते हैं। आपके द्वारा नामित इंटरप्रेटर को अब भी Python 3.10+
जाँच पास करनी होती है; जब वह पास नहीं करता, तो शिम `python3`, `python`, फिर
`py -3` पर लौट जाता है।

```bash title="npx"
npx @ahmed-g-gad/apothem install --harness claude-code
```

जिस मशीन पर कोई प्रोफ़ाइल नहीं है, वहाँ यह पहला `install`
`~/.config/apothem/profile.yaml` पर प्रारंभिक प्रोफ़ाइल बनाता है और इसकी सूचना देता
है। इसके पहचान फ़ील्ड प्लेसहोल्डर हैं: उन्हें वैयक्तिकृत करें
(`npx @ahmed-g-gad/apothem profile edit`), फिर उन्हें लागू करने के लिए `install` के
स्थान पर `update` के साथ कमांड दोबारा चलाएँ।

यह सीधे रिपॉज़िटरी से भी चलता है:

```bash title="npx from the repository"
npx github:ahmed-g-gad/apothem install --harness claude-code
```

[CLI संदर्भ](/docs/cli-reference) का हर कमांड इस रूप में काम करता है; `apothem` के
स्थान पर `npx @ahmed-g-gad/apothem` रखें। यही OpenCode और हर उस अन्य टूल के लिए भी
इंस्टॉल पथ है जो कोई अलग प्लगइन या एक्सटेंशन रजिस्ट्री उपलब्ध नहीं कराता — Apothem
उन्हें सीधे उनकी नेटिव कॉन्फ़िग डायरेक्टरी में सिंक करता है
(`npx @ahmed-g-gad/apothem install --harness opencode`)।

**सत्यापित करें:**

```bash title="Verify"
npx @ahmed-g-gad/apothem --version
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 3. वन-शॉट इंस्टॉलर

**पूर्वापेक्षाएँ:** `PATH` पर सिस्टम Python 3.10+ (इंस्टॉलर आपके लिए `click` /
`rich` पूर्वापेक्षाएँ जोड़ने की पेशकश करता है); नेटवर्क इंस्टॉल के लिए `git` और
`gpg`, जो स्रोत को क्लोन करता है और उसके हस्ताक्षरित रिलीज़ टैग को सत्यापित
करता है (Git for Windows दोनों के साथ आता है)।

इंस्टॉलर स्क्रिप्ट नवीनतम हस्ताक्षरित रिलीज़ टैग को हल करती हैं, उसके हस्ताक्षर को
सत्यापित करती हैं, Apothem स्रोत ट्री को उस टैग पर `~/.apothem` में रखती हैं, कोई
प्रोफ़ाइल न होने पर एक प्रारंभिक प्रोफ़ाइल बनाती हैं, आपके पहले हार्नेस को मूर्त
रूप देती हैं, और परिणाम को सत्यापित करती हैं — यह सब एक ही रन में। प्रारंभिक
प्रोफ़ाइल में प्लेसहोल्डर पहचान फ़ील्ड होते हैं: उसे संपादित करें, फिर अपने फ़ील्ड
लागू करने के लिए `apothem update --harness <name>` चलाएँ। पुनः चलाना इडेम्पोटेंट
है: मौजूदा ट्री को हल किए गए टैग पर फिर से चेकआउट किया जाता है और हार्नेस को फिर
से मूर्त रूप दिया जाता है। टैग-पिन किया गया सत्यापित इंस्टॉल डिफ़ॉल्ट और अनुशंसित
पथ है।

पहले एक बार मेंटेनर की हस्ताक्षर कुंजी आयात करें। जब कुंजी आपकी कीरिंग में नहीं
होती, तब इंस्टॉलर रुक जाता है। जाँच करें कि फ़िंगरप्रिंट
`5C89 98F9 F241 7204 45D3  F28B 7039 6FED 9C63 4163` पढ़ता है, यह वही मान है
जिसे
[SECURITY.md](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md#maintainer-signing-key)
प्रकाशित करता है। Windows पर, `git verify-tag` उस `gpg` की कीरिंग पढ़ता है जो
Git for Windows के साथ आता है, इसलिए आयात Git के अपने `bash` के माध्यम से चलता
है:

```bash title="macOS · Linux · WSL2 · BSD — import the key once"
curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import
gpg --fingerprint 70396FED9C634163
```

```powershell title="Windows · PowerShell — import the key once"
& "$env:ProgramFiles\Git\bin\bash.exe" -c 'curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import && gpg --fingerprint 70396FED9C634163'
```

```bash title="macOS · Linux · WSL2 · BSD — latest signed tag, verified"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell — latest signed tag, verified"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

वही स्क्रिप्ट एक चेकआउट में `scripts/installer/` के अंतर्गत शिप होती हैं —
`install`, `uninstall`, और `update`, `.sh`, `.ps1`, और `.bat` रूपों में — ताकि आप
क्लोन करने के बाद उन्हें सीधे चला सकें:

```bash title="From a checkout"
APOTHEM_HARNESS=claude-code sh scripts/installer/install.sh                                 # POSIX
$env:APOTHEM_HARNESS = 'claude-code'; pwsh -NoProfile -File scripts/installer/install.ps1   # Windows
```

### विश्वास मॉडल

`APOTHEM_REF` सेट न होने पर, इंस्टॉलर सबसे ऊँचे `vMAJOR.MINOR.PATCH` रिलीज़ टैग
को हल करता है और *उसी* को चेकआउट करता है — कभी भी चलती हुई `main` ब्रांच को
नहीं। किसी भी कॉन्फ़िगरेशन के मूर्त रूप दिए जाने से पहले, प्राप्त टैग के
हस्ताक्षर को `git verify-tag` से सत्यापित किया जाता है; कोई बिना-हस्ताक्षर वाला,
छेड़छाड़ किया हुआ, या असत्यापनीय टैग कुछ भी लिखे जाने से पहले इंस्टॉल को निरस्त
कर देता है। जिस हस्ताक्षरित टैग के मेंटेनर की सार्वजनिक कुंजी अभी स्थानीय कीरिंग
में नहीं है, वह इसके बजाय कुंजी-आयात मार्गदर्शन के साथ इंस्टॉल को निरस्त कर देता
है: ऊपर दिखाए अनुसार कुंजी आयात करें, उसके फ़िंगरप्रिंट की तुलना
[SECURITY.md](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md) में
प्रकाशित मान से करें, और फिर से चलाएँ। `APOTHEM_REF` से किसी विशिष्ट रिलीज़ को
पिन करें:

```bash title="Pinned, verified install"
APOTHEM_REF=vMAJOR.MINOR.PATCH sh -c "$(curl -fsSL https://apothem.ahmedgad.com/install.sh)"
```

`vMAJOR.MINOR.PATCH` को
[रिलीज़ पृष्ठ](https://github.com/ahmed-g-gad/apothem/releases) के किसी टैग से
बदलें। सबसे पुराना रिलीज़ टैग एक लाइटवेट टैग है जिसका अपना कोई हस्ताक्षर नहीं है,
इसलिए टैग जाँच उस पर इंस्टॉल निरस्त कर देती है, भले ही उसका कमिट हस्ताक्षरित हो; उसके
बाद का हर रिलीज़ टैग एनोटेटेड और हस्ताक्षरित है।
[SECURITY.md](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md) का
रिलीज़-हस्ताक्षर अनुभाग हर टैग और उसे सत्यापित करने का तरीका सूचीबद्ध करता है।

स्पष्ट ओवरराइड डिफ़ॉल्ट को शिथिल करते हैं। `APOTHEM_ALLOW_UNVERIFIED=1` सत्यापन विफलता को चेतावनी में घटाकर आगे बढ़ता है — एयर-गैप्ड या स्थानीय उपयोग के लिए, या ऐसी रिलीज़ इंस्टॉल करने के लिए जो टैग हस्ताक्षर से पहले की है। `APOTHEM_REF=main` चलती हुई ब्रांच को सत्यापन के बिना केवल `APOTHEM_ALLOW_UNVERIFIED=1` के साथ ही चेकआउट करता है। अकेले `APOTHEM_REF=main` के साथ, इंस्टॉलर `main` को `APOTHEM_HOME` में लाता है, फिर किसी भी कॉन्फ़िगरेशन को मूर्त रूप दिए जाने से पहले निरस्त कर देता है, क्योंकि ब्रांच एक हस्ताक्षरित रिलीज़ टैग नहीं होती। `APOTHEM_SOURCE` के माध्यम से स्थानीय चेकआउट कुछ भी नहीं लाता और सत्यापन छोड़ देता है।

`APOTHEM_VERIFY=checksum` उस होस्ट के लिए मध्य मार्ग है जिसके पास अभी अनुरक्षक की
सार्वजनिक कुंजी नहीं है: क्लोन करने के बजाय, इंस्टॉलर रिलीज़ का प्लेटफ़ॉर्म आर्काइव
और उसका `SHA256SUMS` डाउनलोड करता है, कुछ भी निकालने से पहले डाइजेस्ट बेमेल होने
पर निरस्त कर देता है, और चेतावनी देता है कि मेल खाता डाइजेस्ट यह सिद्ध करता है कि आर्काइव
वही है जिसे रिलीज़ सूचीबद्ध करती है, यह नहीं कि उसे किसने प्रकाशित किया।

इसके बाद इंजन रखे गए ट्री से सीधे चलता है। `click` और `rich` को छोड़कर हर
तृतीय-पक्ष निर्भरता स्रोत ट्री के भीतर वेंडर की गई है, और एंट्री पॉइंट उस वेंडर
डायरेक्टरी को स्वयं `sys.path` पर रखता है:

```bash
PYTHONPATH="$HOME/.apothem/src" python -m apothem <command>
```

दोनों स्क्रिप्ट एक ही कॉन्फ़िगरेशन पर्यावरण चर पढ़ती हैं (`APOTHEM_HOME`,
`APOTHEM_REPO`, `APOTHEM_REF`, `APOTHEM_ALLOW_UNVERIFIED`,
`APOTHEM_VERIFY`, `APOTHEM_RELEASE_BASE`, `APOTHEM_SOURCE`, `APOTHEM_HARNESS`, `APOTHEM_PROFILE`,
`APOTHEM_SKIP_VERIFY`, `APOTHEM_AUTO_INSTALL_DEPS`, `APOTHEM_BIN_DIR`); पूर्ण तालिका
के लिए
[इंस्टॉलर पर्यावरण चर](/docs/how-to/installer-environment-variables) देखें और
`python -m` आह्वान मॉडल कैसे काम करता है, इसके लिए
[स्व-निहित रनटाइम](/docs/architecture/self-contained-runtime) देखें।

**`apothem` कमांड।** सफल इंस्टॉल के बाद, इंस्टॉलर एक `apothem` शिम लिखता है जो
बंडल किए गए इंजन को अग्रेषित करता है — POSIX पर `$HOME/.local/bin` में, Windows पर
`%LOCALAPPDATA%\Microsoft\WindowsApps` में (एक उपयोगकर्ता डायरेक्टरी जो पहले से
डिफ़ॉल्ट Windows `PATH` पर है)। इंस्टॉलर कभी भी आपके `PATH` को संपादित नहीं करता।
डायरेक्टरी के `PATH` पर आ जाने के बाद आप बिना किसी मैनुअल `PYTHONPATH` के सीधे
`apothem <command>` चलाते हैं।

**सत्यापित करें:**

```bash title="Verify"
apothem verify --harness claude-code

# or, before the shim is on PATH, from the bundled source:
PYTHONPATH="$HOME/.apothem/src" python -m apothem verify --harness claude-code
```

## 4. VS Code परिवार एक्सटेंशन

**पूर्वापेक्षाएँ:** VS Code, Node.js 18+, और `PATH` पर सिस्टम Python 3.10+।

**Apothem for VS Code** एक्सटेंशन [Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=ahmed-g-gad.apothem-vscode) पर
`ahmed-g-gad.apothem-vscode` के रूप में उपलब्ध है: इसे एक्सटेंशन व्यू से या
`code --install-extension ahmed-g-gad.apothem-vscode` से इंस्टॉल करें। यह एक
`apothem.vsix` पैकेज से भी इंस्टॉल होता है:
`code --install-extension apothem.vsix`, या संपादक का *Install from VSIX…*
कमांड। रिलीज़ वर्कफ़्लो पैकेज पर हस्ताक्षर करता है और उसे हर GitHub Release से
संलग्न करता है। जो रिलीज़ वर्कफ़्लो द्वारा एक्सटेंशन को पैकेज किए जाने से पहले प्रकाशित हुईं,
उनमें कोई `.vsix` नहीं होता; जब नवीनतम रिलीज़ में यह न हो, तो किसी चेकआउट से
`.github/vsce/` में लॉक की गई vsce रिलीज़ के साथ पैकेज बिल्ड करें (उस vsce रिलीज़ के लिए
Node.js 22 या उसके बाद का संस्करण चाहिए):
`npm ci --prefix .github/vsce --ignore-scripts` चलाएँ, फिर
`cd vscode-extension && ../.github/vsce/node_modules/.bin/vsce package --no-dependencies --out apothem.vsix`
चलाएँ। पहले के `apothem.vsix` से इंस्टॉल की गई प्रति पहचानकर्ता `ahmed-g-gad.apothem`
रखती है; उसे अनइंस्टॉल करें (`code --uninstall-extension ahmed-g-gad.apothem`), ताकि
दोनों प्रतियाँ एक साथ एक ही कमांड पंजीकृत न करें। एक ही एक्सटेंशन VS Code परिवार के संपादकों को कवर करता है।
इसके पैलेट कमांड
(`Apothem: Install`, `Verify`,
`Update`, `Uninstall`, `Doctor`) कॉन्फ़िगर किए गए रनर के माध्यम से वही इंजन चलाते
हैं (डिफ़ॉल्ट रूप से `npx @ahmed-g-gad/apothem@<extension version>`, ताकि
एक्सटेंशन वही इंजन संस्करण चलाए जिसके साथ वह शिप हुआ था; स्रोत से चलाने के लिए
`apothem.runner` उपयोगकर्ता सेटिंग को किसी स्थानीय चेकआउट की ओर इंगित करें)।
Install, Verify, Update और Uninstall पूछते हैं कि किस हार्नेस पर कार्य करना है, और
संपादक का अपना हार्नेस पहले प्रस्तुत करते हैं; `all` एक विकल्प है, कभी डिफ़ॉल्ट
नहीं। `apothem.runner` सेटिंग मशीन-स्कोप वाली है, इसलिए कोई वर्कस्पेस इसे बदल
नहीं सकता, और एक्सटेंशन केवल किसी विश्वसनीय वर्कस्पेस में चलता है।

**सत्यापित करें:** संपादक के कमांड पैलेट से **Apothem: Verify** कमांड चलाएँ, या
किसी टर्मिनल से:

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 5. कमांड-लाइन बूटस्ट्रैप (एक्सटेंशन होस्ट)

**पूर्वापेक्षाएँ:** इसका होस्ट कमांड-लाइन टूल, Node.js 18+, और `PATH` पर सिस्टम
Python 3.10+।

Apothem को सीधे रिपॉज़िटरी से एक एक्सटेंशन के रूप में इंस्टॉल करें — कमांड में
सटीक होस्ट और हार्नेस स्लग शामिल है:

```bash title="Install the extension"
gemini extensions install https://github.com/ahmed-g-gad/apothem
```

यह एक्सटेंशन एक **बूटस्ट्रैप** है, स्वयं में पूर्ण इंस्टॉल नहीं: यह एक Apothem
संदर्भ फ़ाइल लोड करता है और एक `/apothem` कमांड जोड़ता है जो इंजन को शेल-आउट करता है
(`npx @ahmed-g-gad/apothem`)। इसके माध्यम से इंस्टॉल चलाकर पूर्ण हार्नेस को मूर्त
रूप दें:

```bash title="Materialize the full harness"
npx @ahmed-g-gad/apothem install --harness gemini-cli --project .
```

**सत्यापित करें:**

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness gemini-cli --project .
```

## 8. प्रत्यक्ष इंजन (`python -m apothem`)

**पूर्वापेक्षाएँ:** सिस्टम Python 3.10+, जिसमें `click` और `rich` पैकेज आयात-योग्य
हों, साथ ही रिपॉज़िटरी का एक चेकआउट। Node.js की आवश्यकता नहीं।

इंजन को सीधे किसी क्लोन से चलाएँ। एंट्री पॉइंट वेंडर की गई निर्भरताओं
(`src/apothem/_vendor`) को `sys.path` पर रखता है, इसलिए `click` और `rich`
आयात-योग्य होने पर `PYTHONPATH=src` ही पूरा सेटअप है:

```bash title="Direct engine"
git clone https://github.com/ahmed-g-gad/apothem
cd apothem
PYTHONPATH=src python -m apothem install --harness claude-code
```

npm शिम की तरह, बिना प्रोफ़ाइल वाली मशीन पर पहला `install`
`~/.config/apothem/profile.yaml` पर प्रारंभिक प्रोफ़ाइल बनाता है और आगे बढ़ता है।

**सत्यापित करें:**

```bash title="Verify"
PYTHONPATH=src python -m apothem verify --harness claude-code
```

## किसी भी इंस्टॉल को सत्यापित करें

ऊपर का हर चैनल अपनी सत्यापन कमांड बताता है। दो सामान्य रूप ये हैं:

```bash title="Installer path"
PYTHONPATH="$HOME/.apothem/src" python -m apothem verify --harness claude-code
```

```bash title="npx path"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

हार्नेस के नाम को उस अडैप्टर से बदलें जिसे आपने इंस्टॉल किया है; सभी समर्थित नामों
के लिए [हार्नेस सूची](/docs/harnesses) देखें। हर इंस्टॉल किए गए अडैप्टर को एक साथ
जाँचने के लिए (उसकी सत्यापन जाँच और उसके हुक कमांड), ऊपर जिस रूप का आपने उपयोग किया
उसी रूप में `verify --harness NAME` के स्थान पर `doctor` चलाएँ:
`apothem doctor`, `PYTHONPATH="$HOME/.apothem/src" python -m apothem doctor`, या
`npx @ahmed-g-gad/apothem doctor`। प्लगइन पथ के लिए, Claude Code के
भीतर `/plugin` चलाएँ और पुष्टि करें कि **apothem** इंस्टॉल के रूप में सूचीबद्ध है।

## पूर्वापेक्षाएँ एक नज़र में

- **Python 3.10 या उसके बाद का** — जो पथ इसे खोजते हैं वे नाम से खोजते हैं, और नाम
  पथ के अनुसार भिन्न होते हैं। npm शिम `python3`, `python`, फिर `py -3` आज़माता है।
  इंस्टॉलर `python3`, `python`, और संस्करण-युक्त नाम `python3.14` से लेकर
  `python3.10` तक आज़माते हैं।
- उस इंटरप्रेटर के अंतर्गत **`click` और `rich` आयात-योग्य** — वे दो टर्मिनल-उन्मुख
  निर्भरताएँ जिन्हें इंजन वेंडर नहीं करता। इंस्टॉलर दोनों की जाँच करते हैं, जो भी
  अनुपस्थित हो उसका नाम बताते हैं, और उसे आपके लिए इंस्टॉल करने की पेशकश करते हैं
  — आपकी पुष्टि के साथ, या `--yes` (PowerShell पर `-Yes`) या
  `APOTHEM_AUTO_INSTALL_DEPS=1` के साथ स्वचालित रूप से। हर अन्य चैनल पर, कोई
  अनुपस्थित पैकेज इंजन को एक त्रुटि (exit 1) के साथ रोक देता है, जो मिले हुए
  इंटरप्रेटर के लिए सटीक कमांड बताती है, उन संस्करण बाधाओं के साथ जिनके विरुद्ध
  Apothem का परीक्षण होता है (`<interpreter> -m pip install "click==…" "rich>=…"`);
  `--json` के साथ वही त्रुटि `runtime.dependency_missing` कोड वाले एक JSON
  लिफ़ाफ़े के रूप में आती है।
- **Node.js 18 या उसके बाद का** — केवल वे पथ जो `npx` चलाते हैं: npm शिम (2),
  VS Code-परिवार एक्सटेंशन (4), और कमांड-लाइन बूटस्ट्रैप (5–7)।
- **जीवन-अंत तक पहुँच चुके रनटाइम।** Python 3.10 2026-10-01 को अपस्ट्रीम
  जीवन-अंत तक पहुँचा, और Node.js 18 और 20 क्रमशः 2025-04-30 और 2026-04-30 को।
  Apothem अब भी उन्हें अपने घोषित फ़्लोर के रूप में समर्थन देता है और CI में
  प्रत्येक का परीक्षण करता है, लेकिन उन्हें अब अपस्ट्रीम सुरक्षा सुधार नहीं मिलते,
  इसलिए Python 3.11 या नए और Node.js 22 या नए को प्राथमिकता दें।
  [रनटाइम-फ़्लोर नीति](/docs/governance/release-engineering-policy#रनटाइम-फ़्लोर)
  बताती है कि कोई फ़्लोर कैसे बढ़ाया जाता है।
- **Git** — केवल इंस्टॉलर पथ, और केवल नेटवर्क रूप के लिए (स्क्रिप्ट स्रोत को क्लोन
  करती है; स्थानीय चेकआउट को क्लोन की आवश्यकता नहीं होती)।
- **Claude Code** — केवल प्लगइन पथ। **VS Code** और प्रत्येक कमांड-लाइन बूटस्ट्रैप
  का अपना होस्ट टूल केवल अपने-अपने चैनल (4–7) के लिए आवश्यक हैं।
