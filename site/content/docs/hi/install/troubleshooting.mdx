आम Apothem इंस्टॉल और रनटाइम समस्याओं के समाधान।

## इंस्टॉलेशन संबंधी समस्याएँ

### कोई Python 3.10+ नहीं मिला

इंस्टॉलर और npx शिम `python3`, `python`, संस्करण-युक्त
नाम (`python3.14` से `python3.10` तक), और Windows पर `py -3` की जाँच करते हैं — Microsoft Store
लॉन्चर शिम को अस्वीकार करते हैं — और जब कोई भी उम्मीदवार 3.10 की न्यूनतम सीमा पूरी नहीं करता तो `No Python >= 3.10 found in
PATH` के साथ रुक जाते हैं। python.org या अपने OS पैकेज रिपॉज़िटरी से
CPython 3.10 या नया इंस्टॉल करें, पुष्टि करें कि `python3 --version`
(या Windows पर `py -3 --version`) कम से कम 3.10 रिपोर्ट करता है, फिर फिर से चलाएँ।

### अनुपस्थित रनटाइम निर्भरताएँ: click, rich

इंजन अपनी अधिकांश तृतीय-पक्ष निर्भरताओं को स्रोत
ट्री के भीतर वेंडर करता है, लेकिन `click` और `rich` को इंस्टॉलर द्वारा चुने गए
इंटरप्रेटर के अंतर्गत आयात-योग्य होना चाहिए। जब इनमें से कोई अनुपस्थित हो, तो इंस्टॉलर उसका
नाम बताता है और उसे आपके लिए इंस्टॉल करने की पेशकश करता है:

```text
! Missing runtime dependencies: click rich
```

संकेत को स्वीकार करें ताकि इंस्टॉलर उस इंटरप्रेटर के अंतर्गत `pip install` चलाए।
संकेत को छोड़ने के लिए, `--yes` (`-Yes` PowerShell पर) पास करें या स्वचालित रूप
से इंस्टॉल करने के लिए `APOTHEM_AUTO_INSTALL_DEPS=1` सेट करें। यदि आप मना करते हैं
— या `pip` उपलब्ध नहीं है, या आप अपने OS पैकेज प्रबंधक को प्राथमिकता देते हैं — तो
नामित पैकेजों को स्वयं इंस्टॉल करें (उदाहरण के लिए Debian-परिवार के होस्ट पर
`python3-click` और `python3-rich`, या `pip install click rich`) और फिर से चलाएँ।

### इंस्टॉलर चलाने के बाद `apothem` नहीं मिला

इंस्टॉलर स्रोत ट्री को `~/.apothem` पर रखता है और आपके `PATH` में एक
`apothem` एक्ज़ीक्यूटेबल नहीं जोड़ता। इंजन को उस आह्वान के माध्यम से चलाएँ
जिसे इंस्टॉलर पूरा होने पर प्रिंट करता है:

```bash
PYTHONPATH="$HOME/.apothem/src" python -m apothem <command>
```

या npx रूप का उपयोग करें (`npx @ahmed-g-gad/apothem <command>`), जिसके लिए किसी
`PATH` प्रविष्टि की आवश्यकता नहीं है।

### `/plugin marketplace add` विफल हो जाता है

`/plugin marketplace add ahmed-g-gad/apothem` GitHub से मार्केटप्लेस
लिस्टिंग प्राप्त करता है। जब यह विफल हो, तो पुष्टि करें कि मशीन
`https://github.com/ahmed-g-gad/apothem` तक पहुँच सकती है (नेटवर्क, प्रॉक्सी, या फ़ायरवॉल
नियम), फिर पुनः प्रयास करें। यदि मार्केटप्लेस पहले किसी आंशिक
फ़ेच के तहत जोड़ा गया था, तो
`/plugin install apothem@apothem` चलाने से पहले इसे हटाएँ और फिर से जोड़ें।

### npx एक बासी संस्करण परोसता है

`npx` डाउनलोड किए गए पैकेजों को कैश करता है। जब `npx @ahmed-g-gad/apothem --version`
वर्तमान रिलीज़ से पुराने संस्करण की रिपोर्ट करता है, तो कैश साफ़ करें या
dist-tag पिन करें:

```bash
npx clear-npx-cache
npx @ahmed-g-gad/apothem@latest --version
```

### Windows पर irm / iex अवरुद्ध

यदि PowerShell निष्पादन नीति इंस्टॉलर को अवरुद्ध करती है:

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

## रनटाइम संबंधी समस्याएँ

### apothem install को कोई हार्नेस नहीं मिलता

पता लगाए गए हार्नेस निर्देशिकाओं को सूचीबद्ध करने के लिए apothem doctor चलाएँ। यदि कोई नहीं मिलता, तो सुनिश्चित करें कि आपका
हार्नेस इंस्टॉल है और कम से कम एक बार लॉन्च किया गया है।

### apothem verify एक विफल एडॉप्टर की रिपोर्ट करता है

एडॉप्टर को फिर से-मटेरियलाइज़ करने के लिए apothem install फिर से चलाएँ। यदि समस्या बनी रहती है, तो
[हार्नेस एडॉप्टर](/docs/harnesses) के अंतर्गत एडॉप्टर-विशिष्ट पृष्ठ जाँचें।

### Claude Code में हुक सक्रिय नहीं हो रहे

पुष्टि करें कि Apothem वायर्ड है, इसके लिए हुक प्रविष्टियों के लिए ~/.claude/settings.json जाँचें।
यदि फ़ाइल में हुक अनुपस्थित हैं, तो apothem install फिर से चलाएँ।
