आम Apothem इंस्टॉल और रनटाइम समस्याओं के समाधान।

## इंस्टॉलेशन संबंधी समस्याएँ

### कोई Python 3.10+ नहीं मिला

इंस्टॉलर `python3`, `python`, और संस्करण-युक्त नामों (`python3.14` से
`python3.10` तक) की जाँच करते हैं — Microsoft Store लॉन्चर शिम को अस्वीकार करते हुए —
और जब कोई भी उम्मीदवार 3.10 की न्यूनतम सीमा पूरी नहीं करता, तो
`No Python >= 3.10 found in PATH` के साथ रुक जाते हैं। npx शिम, `APOTHEM_PYTHON`
सेट होने पर पहले उसकी, फिर `python3`, `python` और `py -3` की जाँच करता है, और जब
कोई भी योग्य नहीं ठहरता तो अपने ही संदेश के साथ एग्ज़िट कोड 1 पर बाहर निकलता है।
python.org या अपने OS पैकेज रिपॉज़िटरी से CPython 3.10 या नया इंस्टॉल करें,
पुष्टि करें कि `python3 --version` (या Windows पर `py -3 --version`) कम से कम 3.10
रिपोर्ट करता है, फिर फिर से चलाएँ।

### अनुपस्थित रनटाइम निर्भरताएँ: click, rich

इंजन अपनी अधिकांश तृतीय-पक्ष निर्भरताओं को स्रोत ट्री के भीतर वेंडर करता है, लेकिन
`click` और `rich` को इंस्टॉलर द्वारा चुने गए इंटरप्रेटर के अंतर्गत आयात-योग्य होना
चाहिए। जब इनमें से कोई अनुपस्थित हो, तो इंस्टॉलर उसका नाम बताता है और उसे आपके लिए
इंस्टॉल करने की पेशकश करता है:

```text
! Missing Python prerequisites under <python>: click rich
  Install click rich under <python> now? [y/N]
```

प्रॉम्प्ट को स्वीकार करें ताकि इंस्टॉलर उस इंटरप्रेटर के अंतर्गत `pip install`
चलाए। प्रॉम्प्ट को छोड़ने के लिए `--yes` (PowerShell पर `-Yes`) पास करें, या
स्वचालित रूप से इंस्टॉल करने के लिए `APOTHEM_AUTO_INSTALL_DEPS=1` सेट करें। यदि आप
मना करते हैं — या `pip` उपलब्ध नहीं है, या आप अपने OS पैकेज प्रबंधक को प्राथमिकता
देते हैं — तो नामित पैकेजों को स्वयं इंस्टॉल करें (उदाहरण के लिए Debian-परिवार के
होस्ट पर `python3-click` और `python3-rich`, या `pip install click rich`) और फिर से
चलाएँ।

### इंस्टॉलर चलाने के बाद `apothem` नहीं मिला

इंस्टॉलर स्रोत ट्री को `~/.apothem` पर रखता है और एक `apothem` शिम डिफ़ॉल्ट रूप से
`~/.local/bin` (POSIX) या `%LOCALAPPDATA%\Microsoft\WindowsApps` (Windows) में लिखता
है। यह आपका `PATH` नहीं बदलता। यदि `apothem` नहीं मिलता, तो वह डायरेक्टरी `PATH` पर
नहीं है; उसे जोड़ें, या जब तक आप ऐसा नहीं करते, तब तक नीचे दिए `PYTHONPATH` रूप का
उपयोग करें। इंजन को उस आह्वान के माध्यम से चलाएँ जिसे इंस्टॉलर पूरा होने पर प्रिंट
करता है:

```bash
PYTHONPATH="$HOME/.apothem/src" python -m apothem <command>
```

या npx रूप का उपयोग करें (`npx @ahmed-g-gad/apothem <command>`), जिसके लिए किसी
`PATH` प्रविष्टि की आवश्यकता नहीं है।

### `/plugin marketplace add` विफल हो जाता है

`/plugin marketplace add ahmed-g-gad/apothem` GitHub से मार्केटप्लेस
लिस्टिंग प्राप्त करता है। जब यह विफल हो, तो पुष्टि करें कि मशीन
`https://github.com/ahmed-g-gad/apothem` तक पहुँच सकती है (नेटवर्क, प्रॉक्सी, या फ़ायरवॉल
नियम), फिर पुनः प्रयास करें। यदि मार्केटप्लेस पहले किसी आंशिक
फ़ेच के तहत जोड़ा गया था, तो
`/plugin install apothem@apothem` चलाने से पहले इसे हटाएँ और फिर से जोड़ें।

### प्लगइन होस्ट का मार्केटप्लेस जोड़ने का समय समाप्त हो जाता है

मार्केटप्लेस जोड़ने वाला प्लगइन होस्ट का कमांड उसकी रिपॉज़िटरी को क्लोन करता है और
30 सेकंड के बाद हार मान लेता है। धीमी डिस्क पर, जैसे WSL के अंतर्गत एक Windows
ड्राइव पर, इस रिपॉज़िटरी के पूर्ण क्लोन में इससे अधिक समय लग सकता है, और जब कोई
बाद का रीफ़्रेश समय-सीमा पार कर जाता है, तो पहले का पूर्ण क्लोन प्लगइन को किसी पुराने
संस्करण पर अटका भी छोड़ सकता है। केवल वे दो फ़ोल्डर फ़ेच करें जिनकी प्लगइन को
आवश्यकता है:

```bash
codex plugin marketplace remove apothem
codex plugin marketplace add ahmed-g-gad/apothem --sparse .agents/plugins --sparse plugins/apothem
codex plugin add apothem@apothem
```

इसके बाद होस्ट के प्लगइन सूचीबद्ध करने पर `apothem@apothem` का वर्तमान संस्करण
दिखता है।

### npx एक पुराना संस्करण परोसता है

`npx` डाउनलोड किए गए पैकेजों को कैश करता है। जब `npx @ahmed-g-gad/apothem --version`
वर्तमान रिलीज़ से पुराने संस्करण की रिपोर्ट करता है, तो कैश साफ़ करें या
dist-tag पिन करें:

```bash
npx clear-npx-cache
npx @ahmed-g-gad/apothem@latest --version
```

### इंस्टॉलर रुक जाता है: मेंटेनर की सार्वजनिक कुंजी स्थानीय कीरिंग में नहीं है

इंस्टॉलर हस्ताक्षरित रिलीज़ टैग को सत्यापित करता है, और जब हस्ताक्षर कुंजी आपकी
कीरिंग में नहीं होती तो रुक जाता है। इसे एक बार आयात करें, जाँच करें कि
फ़िंगरप्रिंट `5C89 98F9 F241 7204 45D3  F28B 7039 6FED 9C63 4163` पढ़ता है, और
फिर इंस्टॉलर दोबारा चलाएँ:

```bash title="macOS · Linux · WSL2 · BSD — import the key once"
curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import
gpg --fingerprint 70396FED9C634163
```

```powershell title="Windows · PowerShell — import the key once"
& "$env:ProgramFiles\Git\bin\bash.exe" -c 'curl -fsSL https://github.com/ahmed-g-gad.gpg | gpg --import && gpg --fingerprint 70396FED9C634163'
```

Windows पर, दिखाए अनुसार Git के `bash` के माध्यम से आयात करें: `git verify-tag`
उस `gpg` की कीरिंग पढ़ता है जो Git for Windows के साथ आता है। जिस होस्ट पर `gpg`
नहीं है, वह `APOTHEM_VERIFY=checksum` के साथ इंस्टॉल कर सकता है, जो टैग
हस्ताक्षर के बजाय रिलीज़ आर्काइव के डाइजेस्ट की जाँच करता है।

### Windows पर irm / iex अवरुद्ध

यदि PowerShell निष्पादन नीति इंस्टॉलर को अवरुद्ध करती है:

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

## रनटाइम संबंधी समस्याएँ

### apothem install को कोई हार्नेस नहीं मिलता

Harness Status तालिका पढ़ने के लिए apothem doctor चलाएँ, जिसमें हर हार्नेस के लिए एक पंक्ति होती है। `not installed` चिह्नित पंक्ति का अर्थ है कि Apothem को उस हार्नेस का कोई इंस्टॉल नहीं मिला। `needs --project` चिह्नित पंक्ति एक प्रोजेक्ट-स्कोप हार्नेस की है, जिसे doctor केवल तभी जाँचता है जब आप `--project <path>` पास करें। यदि doctor `No harness is installed yet` रिपोर्ट करता है, तो सुनिश्चित करें कि आपका हार्नेस इंस्टॉल है, फिर `apothem install --harness <name>` चलाएँ।

### apothem verify एक विफल अडैप्टर की रिपोर्ट करता है

अडैप्टर को फिर से मूर्त रूप देने के लिए apothem install फिर से चलाएँ। यदि समस्या बनी
रहती है, तो [हार्नेस अडैप्टर](/docs/harnesses) के अंतर्गत अडैप्टर-विशिष्ट पृष्ठ
जाँचें।

### Claude Code में हुक सक्रिय नहीं हो रहे

पुष्टि करें कि Apothem जुड़ा हुआ है; इसके लिए हुक प्रविष्टियों के लिए
~/.claude/settings.json जाँचें। यदि फ़ाइल में हुक अनुपस्थित हैं, तो apothem install
फिर से चलाएँ।
