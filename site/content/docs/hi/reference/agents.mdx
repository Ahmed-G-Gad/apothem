स्थायी सहायक कैनोनिकल सहायक डायरेक्टरी के अंतर्गत `<name>.md` प्रत्यय वाली सपाट
फ़ाइलों के रूप में रहते हैं। कैनोनिकल पथ है:

```text
src/apothem/agents/
```

प्रत्येक सहायक एक केंद्रित भूमिका है, जैसे अनुसंधान, ऑडिट, गुणवत्ता, रिफ़ैक्टरिंग,
या स्कैफ़ोल्डिंग, जिसके अपने टूल प्रतिबंध और अपना सिस्टम प्रॉम्प्ट होते हैं।

नीचे की तालिका और पथ सूची चार सहायकों को दिखाती हैं। इस पृष्ठ के अंत में जनित
इन्वेंट्री हर सहायक परिभाषा को सूचीबद्ध करती है।

| सहायक | फ़ाइल | पैटर्न | मॉडल नीति |
|-------|------|---------|--------------|
| Codebase Explorer | नीचे मैनिफ़ेस्ट पथ देखें | अनुसंधान | होस्ट-चयनित |
| Convention Auditor | नीचे मैनिफ़ेस्ट पथ देखें | ऑडिट | होस्ट-चयनित |
| Quality Gate | नीचे मैनिफ़ेस्ट पथ देखें | गुणवत्ता | होस्ट-चयनित |
| Memory Auditor | नीचे मैनिफ़ेस्ट पथ देखें | ऑडिट | होस्ट-चयनित |

कैनोनिकल मैनिफ़ेस्ट पथ:

```text
src/apothem/agents/codebase-explorer.md
src/apothem/agents/convention-auditor.md
src/apothem/agents/quality-gate.md
src/apothem/agents/memory-auditor.md
```

## फ़्रंटमैटर अनुबंध

```yaml
---
name: <agent name>
version: <semver>
updated: <YYYY-MM-DD>
description: <one-line role>
tools: <comma-separated tool list>
disallowedTools: <comma-separated deny list>
maxTurns: <integer>
---
```

`tools` वैकल्पिक है। जो सहायक इसे छोड़ देता है वह सत्र के पास मौजूद हर टूल,
कनेक्टेड MCP टूल सहित, इनहेरिट करता है, और `disallowedTools` उसकी सीमा वहन करता
है। सभी चौदह शिप किए गए सहायक `tools` सूचीबद्ध करते हैं।

## कनेक्टेड MCP सर्वर

जो सहायक `tools` सूचीबद्ध करता है वह केवल वही कॉल कर सकता है जो वह सूचीबद्ध
करता है। Claude Code किसी MCP टूल को उस सूची में केवल तब स्वीकार करता है जब
प्रविष्टि सर्वर का नाम देती है, जैसे `mcp__<server>__*`; बिना सर्वर नाम वाला `mcp__*` केवल
`disallowedTools` प्रविष्टि के रूप में प्रलेखित है, और कहीं नहीं। सर्वर नाम उस
व्यक्ति के होते हैं जो उन्हें कनेक्ट करता है, इसलिए कोई शिप किया गया सहायक उनका
नाम नहीं दे सकता।

`citation-auditor` और `research-scout` विद्वत्तापूर्ण स्रोत खोजते हैं। प्रत्येक
`tools: Read, Glob, Grep, WebSearch, WebFetch` के साथ शिप होता है और उन टूलों को
अस्वीकार करता है जो फ़ाइलें लिखते हैं, कमांड चलाते हैं, अन्य सहायक शुरू करते हैं,
या प्रकाशित करते हैं: `Write`, `Edit`, `MultiEdit`, `NotebookEdit`, `Bash`,
`PowerShell`, `Monitor`, `Agent`, `Artifact`, और कार्य-सूची टूल। किसी प्रोफ़ाइल
सेटिंग के बिना, दोनों में से कोई भी किसी MCP टूल तक नहीं पहुँचता, और दोनों वेब
सर्च और वेब फ़ेच के माध्यम से स्रोत खोजते हैं।

इनमें से किसी एक को कनेक्टेड विद्वत्तापूर्ण इंडेक्स देने के लिए, प्रोफ़ाइल की
`agent_mcp_servers` कुंजी में सर्वर का नाम दें, जो एक एजेंट नाम को सर्वर नामों से
मैप करती है। तब Claude Code इंजन इंस्टॉल (`apothem install`) उस एजेंट की `tools`
पंक्ति में प्रति नामित सर्वर एक `mcp__<server>__*` प्रविष्टि जोड़ता है, और किसी
अन्य एजेंट को नहीं बदलता। Gemini CLI इंस्टॉल अक्षरों, अंकों और `-` से बने सर्वर
नाम के लिए, एजेंट की `tools` अनुमति-सूची में प्रति सर्वर एक `mcp_<server>_*`
प्रविष्टि के साथ यही करता है। दोनों पर, जिस सर्वर का नाम एजेंट का अपना
`disallowedTools` देता है वह अस्वीकृत ही रहता है। प्रविष्टि उस सर्वर के हर टूल को
स्वीकार करती है, जिसमें लिखने वाला कोई भी टूल शामिल है, इसलिए केवल उसी सर्वर का
नाम दें जिस पर आप खोजों के लिए भरोसा करते हैं: सहायकों के निर्देश उन्हें search,
look-up, read, verify, और resolve कॉल तक सीमित करते हैं, लेकिन हार्नेस केवल उन्हीं
नामों को लागू करता है जिन्हें `tools` पंक्ति सूचीबद्ध करती है। ऐसे एजेंट का नाम
जो मौजूद नहीं है, या जिसकी कोई स्पष्ट `tools` पंक्ति नहीं है, रिपोर्ट किया जाता
है और छोड़ दिया जाता है।

Claude Code और Gemini CLI के अलावा अन्य हार्नेस इस कुंजी को अनदेखा करते हैं।
Claude Code प्लगइन ट्री बिना प्रोफ़ाइल के जोड़ा जाता है और सादी सूची रखता है,
इसलिए प्लगइन उपयोगकर्ता इसके बजाय `~/.claude/agents/` के अंतर्गत एक
उपयोगकर्ता-स्तरीय एजेंट परिभाषित करता है। प्रोफ़ाइल सिंटैक्स, सर्वर-नाम नियम, और
वह वैकल्पिक उपाय
[किसी सहायक को MCP सर्वरों तक पहुँच दें](/docs/reference/mcp#किसी-सहायक-को-mcp-सर्वरों-तक-पहुँच-दें)
पर हैं।

## प्रति-हार्नेस रूपांतरण

जिस सहायक के `tools` अनुदान में, `disallowedTools` लागू होने के बाद, कोई फ़ाइल-संपादन
टूल (`Write`, `Edit`, `MultiEdit`, या `NotebookEdit`) शामिल नहीं होता, वह केवल-पठन है।
जिस सहायक का कोई `tools` अनुदान नहीं है, वह तब केवल-पठन है जब `disallowedTools`
कम से कम `Write` और `Edit` को अस्वीकार करता है। सहायकों को रूपांतरित करने वाला
प्रत्येक हार्नेस उस सीमा को नेटिव रूप से लागू करता है, उसे सहायक के निर्देशों में
बताता है, या केवल-पठन लेबल हटा देता है:

| हार्नेस | टूल सीमा | टर्न सीमा | मॉडल और प्रयास |
| --- | --- | --- | --- |
| Claude Code | `tools` / `disallowedTools` जैसा लिखा गया है, साथ ही कोई भी `mcp__<server>__*` प्रविष्टियाँ जिन्हें प्रोफ़ाइल की `agent_mcp_servers` कुंजी किसी सूचीबद्ध `tools` पंक्ति में जोड़ती है; `tools` के बिना, हर टूल इनहेरिट होता है, MCP सहित | `maxTurns` | इनहेरिट (सेट नहीं) |
| Codex | कुछ भी उत्सर्जित नहीं होता; सहायक के निर्देश इसे बताते हैं, और पैरेंट सत्र का सैंडबॉक्स लेखन को नियंत्रित करता है | उपलब्ध नहीं | इनहेरिट (सेट नहीं) |
| Gemini CLI | Gemini टूल नामों की `tools` अनुमति-सूची, साथ ही कोई भी `mcp_<server>_*` प्रविष्टियाँ जिन्हें प्रोफ़ाइल की `agent_mcp_servers` कुंजी किसी सूचीबद्ध स्पष्ट सूची में जोड़ती है; `tools` के बिना, अस्वीकृतियों से निहित अनुमति-सूची और साथ में `mcp_*` | `max_turns` | इनहेरिट (सेट नहीं) |
| Qwen Code | Qwen टूल नामों में `tools` / `disallowedTools`; `tools` के बिना, कोई सूची उत्सर्जित नहीं होती, इसलिए MCP टूल इनहेरिट होते हैं और अस्वीकृतियाँ लागू होती हैं | मैप नहीं किया गया | `model: inherit` |
| OpenCode | `permission` (प्रति टूल `allow` / `deny`); MCP टूल प्रतिबंधित नहीं हैं | मैप नहीं किया गया | इनहेरिट (सेट नहीं) |
| Antigravity | कुछ भी उत्सर्जित नहीं होता; विवरण से "read-only" हटा दिया जाता है | उपलब्ध नहीं | इनहेरिट (सेट नहीं) |
| CodeBuddy | अल्पविराम स्ट्रिंग के रूप में `tools` / `disallowedTools`, CodeBuddy द्वारा प्रलेखित टूल नामों तक सीमित; कोई MCP प्रविष्टि नहीं | `maxTurns` | इनहेरिट (सेट नहीं) |
| Trae | अल्पविराम स्ट्रिंग के रूप में `tools` / `disallowedTools`, Trae द्वारा प्रलेखित टूल नामों तक सीमित; कोई MCP प्रविष्टि नहीं | उपलब्ध नहीं | इनहेरिट (सेट नहीं) |
| GitHub Copilot | Copilot उपनामों (`read`, `search`, `edit`, `execute`, `web`, `agent`, `todo`) की `tools` अनुमति-सूची जिसमें अस्वीकृतियाँ समाहित हैं, क्योंकि Copilot में कोई deny कुंजी नहीं है; जो उपनाम किसी अस्वीकृत टूल को कवर करता है उसे छोड़ दिया जाता है; कोई MCP प्रविष्टि नहीं | उपलब्ध नहीं | इनहेरिट (सेट नहीं) |

| Kimi Code | Kimi Code टूल नामों की सूचियों के रूप में `tools` / `disallowedTools` (`WebFetch` `FetchURL` बन जाता है, `TodoWrite` `TodoList` बन जाता है; जिन नामों के लिए Kimi Code में कोई टूल नहीं है उन्हें छोड़ दिया जाता है); कोई MCP प्रविष्टि नहीं | उपलब्ध नहीं | इनहेरिट (सेट नहीं) |
| Kiro | Kiro टूल श्रेणियों (`read`, `write`, `shell`, `web`, `subagent`) की `tools` अनुमति-सूची जिसमें अस्वीकृतियाँ समाहित हैं, क्योंकि लिखा जाने वाला एकमात्र प्रतिबंध यही सूची है; जो श्रेणी किसी अस्वीकृत टूल को कवर करती है उसे छोड़ दिया जाता है; कोई MCP प्रविष्टि नहीं | उपलब्ध नहीं | इनहेरिट (सेट नहीं) |

Hermes और Open-Claw सहायक फ़ाइलों को नेटिव सहायकों के रूप में नहीं, बल्कि समर्थन
सामग्री के रूप में प्राप्त करते हैं।

## ऑर्केस्ट्रेशन

सहायक परिनियोजन, समानांतर-लॉन्च प्रोटोकॉल, रिटर्न-अनुबंध प्रवर्तन, और आइसोलेशन
अनुशासन ऑर्केस्ट्रेशन नियम में रहते हैं। प्रति-वर्कर डिस्पैच ट्री ऑर्केस्ट्रेशन

```text

```
