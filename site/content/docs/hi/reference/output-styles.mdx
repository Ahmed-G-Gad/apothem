आउटपुट-स्टाइल प्रोफ़ाइल `src/apothem/output-styles/` के अंतर्गत रहती हैं और
प्रति-स्टाइल ऑपरेटर-टोन मार्गदर्शन वहन करती हैं। होस्ट हार्नेस
`/output-style <name>` के माध्यम से किसी स्टाइल को प्रति-सत्र आधार पर सक्रिय करता है।

## कैनोनिकल प्रोफ़ाइल

| प्रोफ़ाइल | फ़ाइल | टोन |
|---------|------|------|
| डिफ़ॉल्ट | `src/apothem/output-styles/default.md` | आधारभूत टोन, जिसका हर अन्य स्टाइल पूरक है |
| डिफ़ॉल्ट आर्किटेक्ट | `src/apothem/output-styles/default-architect.md` | वरिष्ठ सॉफ़्टवेयर आर्किटेक्ट टोन |
| संक्षिप्त इंजीनियर | `src/apothem/output-styles/concise-engineer.md` | संक्षिप्त-रूप इंजीनियरिंग टोन |
| फ़ोरेंसिक ऑडिटर | `src/apothem/output-styles/forensic-auditor.md` | निष्कर्ष-दर-निष्कर्ष ऑडिट टोन |

## स्टाइल कहाँ इंस्टॉल होती हैं

`apothem install --harness claude-code` स्टाइल को
`~/.claude/output-styles/` में कॉपी करता है। Claude Code प्लगइन वही फ़ाइलें अपने
`output-styles/` फ़ोल्डर में शिप करता है, जिसे Claude Code प्लगइन आउटपुट-स्टाइल के
लिए स्कैन करता है ([प्लगइन संदर्भ](https://code.claude.com/docs/en/plugins-reference)),
इसलिए केवल प्लगइन इंस्टॉल होने पर भी स्टाइल चुनी जा सकती हैं। किसी अन्य हार्नेस में
आउटपुट-स्टाइल सतह नहीं है, इसलिए कोई अन्य इंस्टॉल उन्हें शिप नहीं करता।

## frontmatter अनुबंध

```yaml
---
name: <style name>
description: <one-line tone summary>
keep-coding-instructions: true
---
```

`name` और `description` आवश्यक हैं। हर शिप की गई स्टाइल
`keep-coding-instructions: true` भी सेट करती है। जब तक यह कुंजी `true` न हो, Claude
Code अपने अंतर्निहित सॉफ़्टवेयर इंजीनियरिंग निर्देशों (परिवर्तनों का दायरा कैसे तय
करें, टिप्पणियाँ कैसे लिखें, और कार्य कैसे सत्यापित करें) को किसी भी कस्टम आउटपुट
स्टाइल से बाहर रखता है; इसका डिफ़ॉल्ट `false` है। Apothem स्टाइल यह बदलती हैं कि
कार्य कैसे प्रस्तुत किया जाता है, यह नहीं कि वह कैसे किया जाता है, इसलिए वे उन
निर्देशों को बनाए रखती हैं।
[Claude Code आउटपुट-स्टाइल संदर्भ](https://code.claude.com/docs/en/output-styles)
देखें।

## नई प्रोफ़ाइल लिखना

`src/apothem/output-styles/` के अंतर्गत कैनोनिकल frontmatter के साथ एक नई
`<name>.md` फ़ाइल बनाएँ — जिसमें `keep-coding-instructions: true` शामिल हो, सिवाय तब
जब स्टाइल इंजीनियरिंग कार्य के लिए अभिप्रेत न हो — मुख्य भाग में टोन घोषित करें, और अपने अगले
सत्र की शुरुआत में `/output-style <name>` का आह्वान करके इसकी पुष्टि करें।
