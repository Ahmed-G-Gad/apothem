हुक टूल इवेंट पर सक्रिय होते हैं और ऐसे संदेश संदर्भ लोड करते हैं जिन्हें सहायक
अतिरिक्त सिस्टम प्रॉम्प्ट के रूप में मानता है। वायरिंग Claude Code के
`settings.json` हुक ब्लॉक (इंजन इंस्टॉल) या प्लगइन के `hooks.json` (प्लगइन
इंस्टॉल), Codex की `hooks.json` हुक फ़ाइल, Qwen Code के `settings.json` हुक
मैप, CodeBuddy की `.codebuddy/settings.local.json` हुक कुंजी (केवल SessionStart
और PostToolUse), Kiro की हुक फ़ाइल `.kiro/hooks/apothem.json` (केवल
SessionStart), GitHub Copilot की हुक फ़ाइल `.github/hooks/apothem.json` (केवल
sessionStart और postToolUse), Windsurf (Devin Local) की
`.devin/config.local.json` हुक कुंजी (केवल SessionStart और PostToolUse), और
Cursor की प्रोजेक्ट हुक फ़ाइल `.cursor/hooks.json` (केवल sessionStart) में रहती
है।

| इवेंट | टाइमआउट | उद्देश्य |
|-------|--------:|---------|
| SessionStart | 30 सेकंड | मेमोरी पढ़ें, प्लान स्थिति जाँचें, तत्परता की रिपोर्ट करें; कॉम्पैक्शन के बाद, रिकवरी संदर्भ पहुँचाएँ; ऐसे नॉलेज बेस को चिह्नित करें जो अपनी बेसलाइन के बाद से बदल गया है |
| PreCompact | 30 सेकंड | सत्यापित करें कि कॉम्पैक्शन से पहले स्थिति बाहर सहेजी जा चुकी है (Codex, Qwen Code; Claude Code पर पंजीकृत नहीं) |
| PostCompact | 30 सेकंड | कॉम्पैक्शन के बाद कार्यशील स्थिति बहाल करें (Codex, Qwen Code; Claude Code पर पंजीकृत नहीं) |
| Stop | 60 सेकंड | सत्र-समाप्ति प्रोटोकॉल, ऑप्ट-इन |
| PostToolUse | 10 सेकंड | संदर्भ-आकार सलाह: पहले चिह्न पर स्थिति सहेजें, और दूसरे पर ऑपरेटर को बताया जाता है कि सत्र लंबा है; प्रति कॉम्पैक्शन चक्र अधिकतम दो बार; Claude Code पर पृष्ठभूमि में चलती है |
| PreToolUse (शेल: Bash, PowerShell, `run_shell_command`) | 10 सेकंड | Git-आर्टिफ़ैक्ट आइसोलेशन, प्लान स्थानीयता, डायनेमिक-eval गार्ड |
| PreToolUse (Write/Edit/NotebookEdit/apply_patch) | 10 सेकंड | प्लान-संदर्भ आइसोलेशन, लेखकत्व हेडर, प्लान स्थानीयता, निर्भरता और डायनेमिक-eval गार्ड |
| PreToolUse (AskUserQuestion) | 10 सेकंड | `(Recommended)`-मार्कर की सुगठितता |

## डिस्पैचर

इंजन द्वारा इंस्टॉल की गई हुक प्रविष्टियाँ डिस्पैचर को उसके निरपेक्ष स्क्रिप्ट पथ
से, इंस्टॉल के समय हल किए गए इंटरप्रेटर के साथ, बुलाती हैं। टेम्पलेट
`${PYTHON_BIN}` और `${HARNESS_ROOT}` टोकन रखते हैं, जिन्हें इंस्टॉलर इंस्टॉल के
समय रेंडर करता है। Claude Code और Qwen Code डिस्पैचर को
`<harness-root>/.apothem/support/hooks/` के अंतर्गत मूर्त रूप देते हैं; Codex
`<harness-root>/hooks/` के अंतर्गत। Claude Code प्रविष्टियाँ exec रूप (`command`
और `args`) का उपयोग करती हैं, इसलिए उन्हें किसी शेल की आवश्यकता नहीं होती।
Claude Code प्लगइन प्रत्येक हुक को
`bash "${CLAUDE_PLUGIN_ROOT}/lib/apothem/hooks/lib/bootstrap.sh" <event> [<message-file> ...]`
के रूप में, Claude Code के डिफ़ॉल्ट हुक शेल (macOS और Linux पर `sh`, Windows पर
Git Bash) में चलाता है; बूटस्ट्रैप एक Python 3.10+ इंटरप्रेटर ढूँढता है और बंडल
किए गए डिस्पैचर को चलाता है। यह मिले हुए इंटरप्रेटर को हुक स्थिति डायरेक्टरी
(नीचे) के अंतर्गत `interpreter-path` (`bootstrap.ps1` के लिए
`interpreter-path-ps1`) में कैश करता है और जब तक वह इंटरप्रेटर मौजूद रहता है
उसका पुनः उपयोग करता है, इसलिए PATH जाँच हर टूल कॉल से पहले नहीं बल्कि एक बार
चलती है; नई जाँच बाध्य करने के लिए कैश फ़ाइल हटा दें। केवल निरपेक्ष स्थिति
डायरेक्टरी और निरपेक्ष कैश किया गया पथ ही मान्य होते हैं।

हर सतह प्रति इवेंट और मैचर एक डिस्पैचर प्रविष्टि पंजीकृत करती है, जो उन सभी
संदेशों को सूचीबद्ध करती है जिनका वह मैचर मूल्यांकन करता है: एक प्रक्रिया पेलोड
को एक बार पढ़ती है, हर गार्ड चलाती है, और एक एनवेलप के साथ उत्तर देती है, इसलिए
एक Write हर गार्ड के लिए एक नहीं बल्कि एक ही डिस्पैचर शुरू करता है। Claude Code
इंजन इंस्टॉल Write और Edit पर अनुरूपता गेट (`gate.py --hook`) को भी उसकी अपनी
प्रविष्टि के रूप में चलाता है। Git for Windows के बिना Windows पर, इंजन इंस्टॉल
(`apothem install --harness claude-code`) का उपयोग करें, जिसके exec-रूप हुक को
किसी शेल की आवश्यकता नहीं होती। डिस्पैचर एक स्वतंत्र stdlib स्क्रिप्ट है: यह
अपना `sys.path` स्वयं बूटस्ट्रैप करता है, इसलिए होस्ट पर किसी आयात-योग्य
`apothem` पैकेज की आवश्यकता नहीं होती। किसी स्रोत चेकआउट से, मॉड्यूल रूप
`python -m apothem.hooks.dispatch <event>` (`PYTHONPATH=src` के साथ) विकास के लिए
वही कोड चलाता है। डिस्पैचर इकोसिस्टम-रूट निर्धारण के लिए
`hooks/lib/resolve_root.py` लोड करता है और `hooks/emit_hook_context.py` तथा
`hooks/session_start_bootstrap.py` को कार्य सौंपता है।

## वेंडर अनुबंध

जो हार्नेस Claude Code नहीं है, वह वही डिस्पैचर स्क्रिप्ट के बाद
`--contract <id>` के साथ चलाता है, उदाहरण के लिए
`"<python>" "<project>/.apothem/support/hooks/dispatch.py" --contract codebuddy SessionStart`।
अनुबंध (`hooks/lib/vendor_contract.py`) वेंडर की इवेंट और टूल-नाम वर्तनियों तथा
पेलोड कुंजियों को उस Claude आकार में अनुवादित करता है जिसे हैंडलर पढ़ते हैं,
एनवेलप को उस आकार में फिर से लिखता है जिसे वेंडर पढ़ता है, और ऐसे इवेंट को छोड़
देता है जिसे वेंडर मॉडल को नहीं सौंपता। फ़्लैग के बिना कुछ भी अनुवादित नहीं होता
और आउटपुट बाइट-दर-बाइट Claude एनवेलप होता है। यह फ़्लैग डिस्पैचर की प्रलेखित
कमांड लाइन का हिस्सा है: `dispatch.py [--contract <id>]
<Event> [<message> ...]`।

| अनुबंध | पढ़ता है | आउटपुट | पहुँचाए गए इवेंट |
| --- | --- | --- | --- |
| `codebuddy` | Claude का stdin | Claude एनवेलप | SessionStart, UserPromptSubmit, PostToolUse |
| `devin` | लोअरकेस टूल नामों (`exec`, `write`, `edit`) वाला Claude का stdin; `DEVIN_PROJECT_DIR` से प्रोजेक्ट रूट | Claude एनवेलप | SessionStart, UserPromptSubmit, PostToolUse |
| `cursor` | camelCase इवेंट, `conversation_id`, `workspace_roots` | `{"additional_context": ...}` | SessionStart |
| `copilot` | camelCase `sessionId`, `toolName`, `toolArgs`, या PascalCase snake_case रूप | `{"additionalContext": ...}` | SessionStart, PostToolUse, Notification |
| `kiro` | Claude-जैसा stdin, Kiro टूल id (`execute_bash`, `fs_write`, `str_replace`) | सादा पाठ | SessionStart, UserPromptSubmit |
| `claude` | Claude का stdin | Claude एनवेलप | हर इवेंट |

`codebuddy`, `copilot`, `cursor`, `devin` और `kiro` अनुबंध आज एक Apothem
एडैप्टर द्वारा इंस्टॉल किए जाते हैं (`devin` Windsurf एडैप्टर द्वारा); `claude`
अनुबंध प्रमाणित करता है कि डिफ़ॉल्ट कमांड लाइन अपरिवर्तित है। डिस्पैचर हर अनुबंध
के अंतर्गत सलाहकारी बना रहता है: कोई भी आकार अनुमति, निर्णय, ब्लॉक या फिर से
लिखा गया टूल इनपुट नहीं ले जाता।

Cursor और Devin Local अपने हुक के साथ-साथ Claude Code की सेटिंग्स फ़ाइलों में
रखे हुक भी लोड करते हैं, इसलिए उसी मशीन पर Apothem Claude Code इंस्टॉल होने पर
दो सेट चल सकते हैं। SessionStart बूटस्ट्रैप एक बार पहुँचाया जाता है: वेंडर का
अपना कमांड (`--contract cursor` या `--contract devin`) और Claude Code प्रति, जो
डिफ़ॉल्ट कमांड लाइन है, हुक स्थिति डायरेक्टरी में प्रति सत्र और स्रोत एक मार्कर
साझा करते हैं, और जो भी दूसरे क्रम पर चलता है वह मौन रहता है। डिफ़ॉल्ट कमांड लाइन
केवल तब भाग लेती है जब प्रक्रिया परिवेश होस्ट का नाम देता है (`CURSOR_PROJECT_DIR`,
`CURSOR_VERSION` या `DEVIN_PROJECT_DIR`); Claude Code, Codex और Qwen Code के
अंतर्गत यह मार्कर कभी नहीं पढ़ती। मार्कर दस सेकंड के लिए बाँधता है, इसलिए उसी
सत्र की बाद की शुरुआत, जैसे दूसरा कॉम्पैक्शन, फिर भी अपना रिकवरी संदर्भ पहुँचाती
है। किसी PostToolUse काउंटर का दोहराव नहीं हटाया जाता, इसलिए संदर्भ-आकार काउंटर
दोनों जगह चलता है और अपनी सीमाओं तक जल्दी पहुँचता है। इंस्टॉल एक नोट प्रिंट करता
है जो आयात बंद करने के लिए वेंडर के स्विच का नाम देता है (Cursor का "Include
Third-Party Plugins, Skills, and Other Configs"; Devin का
`read_config_from.claude`)।

कोई कमांड केवल वहीं पंजीकृत होता है जहाँ वेंडर उसका आउटपुट मॉडल को सौंपता है।
Kiro किसी हुक का stdout केवल `SessionStart` और `UserPromptSubmit` के लिए संदर्भ
में जोड़ता है, इसलिए Kiro फ़ाइल केवल `SessionStart` पंजीकृत करती है। Copilot
`sessionStart` और `postToolUse` से `additionalContext` पढ़ता है और `preToolUse`
से केवल अनुमति फ़ील्ड, इसलिए Copilot फ़ाइल वे दो इवेंट, उनके camelCase नामों के
अंतर्गत, पंजीकृत करती है और कोई गार्ड नहीं। हर Copilot प्रविष्टि एक `bash` और एक
`powershell` कमांड रखती है। दोनों फ़ाइलें Apothem-स्वामित्व वाली हैं और उस मशीन
के इंटरप्रेटर और प्रोजेक्ट पथ का नाम देती हैं जिसने इंस्टॉल चलाया; हार्नेस पृष्ठ
बताते हैं कि किसी रिपॉज़िटरी द्वारा कमिट की गई फ़ाइल के लिए इसका क्या अर्थ है।

Devin Local `SessionStart`, `UserPromptSubmit` और `PostToolUse` से
`additionalContext` पढ़ता है और `PreToolUse` के लिए ऐसा कुछ प्रलेखित नहीं करता,
इसलिए Windsurf पंजीकरण `SessionStart` और `PostToolUse` रखता है, बिना मैचर के
(Devin का मैचर एक रेगुलर एक्सप्रेशन है, और छोड़ा गया मैचर हर टूल से मेल खाता है)।
यह स्थानीय ओवरराइड `.devin/config.local.json` में जाता है, जिसे Devin gitignored
के रूप में प्रलेखित करता है और `.git/info/exclude` के माध्यम से स्वयं git से बाहर
रखता है।
Cursor का `sessionStart` हुक बातचीत के प्रारंभिक संदर्भ में `additional_context`
जोड़ता है; पहला संस्करण केवल वही इवेंट पंजीकृत करता है। Cursor की
`.cursor/hooks.json` एकमात्र प्रोजेक्ट हुक फ़ाइल है, इसलिए यह ऑपरेटर की है:
इंस्टॉल उसमें एक प्रविष्टि मर्ज करता है, ऑपरेटर की प्रविष्टियाँ और कुंजियाँ रखता
है, ऐसी फ़ाइल को अस्वीकार करता है जिसे वह बिना हानि के फिर से नहीं लिख सकता, और
कमांड में डिस्पैचर पथ से अपनी प्रविष्टि को पहचानता है। Cursor का डेस्कटॉप ऐप
Windows पर हुक कमांड PowerShell के माध्यम से चलाता है, इसलिए Windows होस्ट पर
कमांड `& ` से शुरू होता है।

सभी पाँच फ़ाइलों में कोई प्रविष्टि Apothem की तब होती है जब उसका कमांड
`--contract <id>` के साथ `.apothem/support/[<harness>/]hooks/dispatch.py` चलाता
है, चाहे वह किसी भी प्रोजेक्ट पथ के अंतर्गत लिखी गई हो। इसलिए नाम बदला गया,
स्थानांतरित या क्लोन किया गया प्रोजेक्ट प्रविष्टियों का एक ही सेट रखता है, और
आपका कोई हुक, जैसे आपके अपने ट्री में `hooks/dispatch.py` या
`python -m apothem.conformity.gate`, कभी बदला या हटाया नहीं जाता। जब फ़ाइल में
Apothem की कोई प्रविष्टि नहीं बचती तो `apothem verify` पंजीकरण को अनुपस्थित
रिपोर्ट करता है, और जो अनइंस्टॉल फ़ाइल नहीं पढ़ सकता वह उसे छोड़ा गया रिपोर्ट
करता है। जिस प्रोजेक्ट या इंटरप्रेटर पथ में `$`, बैकटिक, डबल कोट या बैकस्लैश हो,
उसे इंस्टॉल के समय पथ का नाम देते हुए अस्वीकार कर दिया जाता है, क्योंकि उद्धृत
कमांड कोई दूसरी फ़ाइल चलाएगा।
