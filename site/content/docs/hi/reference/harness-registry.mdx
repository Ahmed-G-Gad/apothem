हार्नेस रजिस्ट्री वह सत्य-स्रोत अडैप्टर इन्वेंट्री है जिसका उपयोग CLI,
दस्तावेज़ीकरण, फ़िक्स्चर परीक्षण और परिपाटी-पिन सत्यापन करते हैं। रनटाइम स्रोत
`src/apothem/lib/harness_registry.py` है; नीचे की हर पंक्ति उस रजिस्ट्री,
प्रति-अडैप्टर `capabilities.yml`, और प्रत्येक अडैप्टर की
`STANDARD-CONVENTION-PIN.md` तक अनुरेखणीय है।

## पेलोड समूह समर्थन

स्थिति मान `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable`, और
`discovery-pending` हैं।

एक `converted` समूह हार्नेस के अपने प्रारूप में फिर से लिखा जाता है, और कुछ
स्रोत फ़ील्ड के लिए उसमें कोई स्थान नहीं होता। प्रत्येक रूपांतरित कमांड, एजेंट,
या नियम समूह के लिए, अडैप्टर की `capabilities.yml` एक `conversion_losses` मैप
रखती है जो बताता है कि हर स्रोत frontmatter फ़ील्ड के साथ क्या होता है:

| मान | अर्थ |
| --- | --- |
| `native:<field>` | हार्नेस इसे उसी फ़ील्ड के अंतर्गत पढ़ता है। |
| `sidecar:<path>` | इसे रूपांतरित फ़ाइल के बगल में एक अलग फ़ाइल में लिखा जाता है, जैसे Codex की `agents/openai.yaml`। |
| `filename` | फ़ाइल या फ़ोल्डर का नाम इसे वहन करता है। |
| `inlined` | यह प्रॉम्प्ट या मुख्य पाठ में चला जाता है। |
| `ignored` | यह फ़ाइल में रहता है, किंतु हार्नेस इसे नहीं पढ़ता। |
| `dropped` | इसे छोड़ दिया जाता है। |

एक परीक्षण हर रूपांतरित फ़ाइल को रेंडर करता है और मैप की जाँच आउटपुट के विरुद्ध

## साझा रूट

कुछ इंस्टॉल टारगेट उन्हें लिखने वाले हार्नेस के अलावा अन्य हार्नेसों द्वारा भी
लोड किए जाते हैं। रजिस्ट्री ऐसे प्रत्येक पथ को `SHARED_ROOTS` में एक स्वामी (वह
एकमात्र अडैप्टर जो इसे लिखता है) और उन पाठकों के साथ दर्ज करती है जिनके वेंडर
दस्तावेज़ इसे डिफ़ॉल्ट रूप से लोड करते हैं, साथ ही वे वेंडर पृष्ठ भी जो इसे दिखाते
हैं और उन्हें प्राप्त करने की तिथि। स्वामी को इंस्टॉल करने से Apothem सामग्री हर
पाठक के सामने आ जाती है, और स्वामी को अनइंस्टॉल करने से वह हर पाठक से हट जाती है।

| पथ | स्वामी | पाठक |
| --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, Gemini CLI, GitHub Copilot, Kimi Code, Open-Claw, OpenCode, Windsurf, Zed |
| `~/.claude/skills/` | Claude Code | Cursor, OpenCode |
| `~/.claude/CLAUDE.md` | Claude Code | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | Zed |

कोई स्वामी किसी साझा निर्देश फ़ाइल में जो Apothem ब्लॉक लिखता है, वह किसी एक
टूल को उसके पाठक के रूप में नामित नहीं करता। `tests/unit/test_shared_roots.py`
तब विफल होता है जब दो अडैप्टर एक ही रजिस्ट्री टारगेट लिखते हैं, और तब भी जब किसी
क्रॉस-टूल निर्देश फ़ाइल (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`copilot-instructions.md`) जैसे नाम वाले रजिस्ट्री टारगेट का कोई घोषित स्वामी नहीं
होता। एकमात्र अपवाद `~/.codex/AGENTS.md` है, जिसे लोड करने का दस्तावेज़ीकरण कोई अन्य
पंजीकृत हार्नेस नहीं करता।
