# Changelog — Apothem

All notable changes to this project are documented in this file.

This changelog follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **CodeBuddy and Trae now get Apothem's helpers as their own subagents.** The
  install writes each Apothem helper into the project as a Markdown subagent
  file, in `.codebuddy/agents/` for CodeBuddy and `.trae/agents/` for Trae,
  where before neither tool received the helpers. A file keeps the helper's
  instructions and carries the keys the tool documents: the name, the
  description, the allowed and denied tools as the comma-separated strings both
  tools read, and, for CodeBuddy only, the turn limit. A tool the tool's own
  documentation does not name is left out of both lists, a helper that could
  not edit files still cannot, and no model is set. Trae installs for the
  project only, because its documentation gives two different user-level
  folders for subagents and one of them is not confirmed. The two harness pages
  explain the files, the switch Trae may need, and how an uninstall treats a
  file of yours with an Apothem helper's name.
- **GitHub Copilot and Cursor now get Apothem's helpers as their own agents.**
  The install writes each Apothem helper into the project as a Markdown agent
  file, in `.github/agents/` as `<name>.agent.md` for GitHub Copilot and in
  `.cursor/agents/` as `<name>.md` for Cursor, where before neither tool
  received the helpers. A file keeps the helper's instructions and carries the
  keys the tool documents. Copilot has no key that denies a tool, so the
  helper's allowed and denied tools become one list of Copilot tool aliases, and
  an alias that would let a helper use a tool it is denied is left out. Cursor has
  no tool list at all, so five read-only helpers that cannot run commands are
  marked `readonly: true`, and the seven read-only helpers that run commands
  drop the "read-only" label from their descriptions, since Cursor would not
  enforce it. No model is set for either tool. Both install for the project
  only; the Copilot files are part of your repository, so the cloud agent and
  your teammates see them. The two harness pages explain the files, and how an
  uninstall treats a file of yours with an Apothem helper's name.
- **Kimi Code and Windsurf now get Apothem's helpers as their own subagents.**
  The install writes each Apothem helper into the project as a Markdown subagent
  file, in `.kimi-code/agents/` for Kimi Code and in `.devin/agents/` for
  Windsurf's Devin Local agent. Kimi Code kept the helpers in a support folder
  where it never loaded them; the first update or uninstall after this release
  removes that old folder, `.kimi-code/.apothem/support/agents/`, after saving a
  copy under `~/.apothem/backups/`. Windsurf received no helpers before. Both
  tools spell tools their own way, so the install translates them. Kimi Code
  gets lists of its own tool names (`WebFetch` becomes `FetchURL`, `TodoWrite`
  becomes `TodoList`, and a name Kimi Code has no tool for is left out). Devin
  has no key that denies a tool, so a helper's allowed and denied tools become
  one lowercase `allowed-tools` list, and `Bash` becomes `exec`. Windsurf gets
  eleven of the fourteen helpers: Devin documents no tool name for web search
  or web fetch, so `citation-auditor`, `fact-checker` and `research-scout` wait
  until it does. No model is set for either tool, and Kimi Code never gets
  `override`. Both install for the project only. Kimi Code uses a helper when
  you ask for it by name, since its 2.3.2 release stopped delegating on its own,
  and Devin labels custom subagents experimental and puts them behind a
  Subagents (Preview) setting. The two harness pages explain the files, and how
  an uninstall treats a file of yours with an Apothem helper's name.
- **Kiro now gets Apothem's helpers as its own custom agents.** The install
  writes each Apothem helper into the project as a Markdown agent file in
  `.kiro/agents/`, where before Kiro received no helpers. The files are for Kiro
  IDE 1.0 and Kiro CLI V3 (`kiro-cli --v3`), the versions that read the Markdown
  format; no JSON profile and none of the older CLI 2.x keys are written. A file
  keeps the helper's instructions and carries the name, the description and one
  list of Kiro tool categories (`read`, `write`, `shell`, `web`, `subagent`).
  Kiro has a single list for tools, so a helper's allowed and denied tools are
  folded into it, and a category that would let a helper use a tool it is denied
  is left out. No model is set. The install is for the project only, and Kiro
  does not load a project's agents until you trust the workspace. The Kiro page
  explains the files, the trust step, and how an uninstall treats a file of
  yours with an Apothem helper's name.

### Changed

- **The docs site's Node type definitions match the Node it runs on.**
  `@types/node` moves from 25 to 22, the major of the site's Node floor
  (`engines` and `.nvmrc`), so the type-check no longer accepts Node APIs that
  Node 22 lacks. Dependabot stops proposing `@types/node` major updates for the
  site; raise that major together with the floor.

### Fixed

- **Dependabot assigns its pull requests without a warning.** The assignee in
  `.github/dependabot.yml` now spells the maintainer's login with GitHub's own
  capitals. The assignable-users lookup Dependabot runs is case-sensitive, so
  the lowercase spelling made it comment that the user "could not be added" on
  every pull request, although the assignment itself went through.
- **The workflow audit's open finding is resolved with its reason.** zizmor's
  self-repository audit asks the test matrix to call its reusable workflow with
  GitHub's `$/` form, which the pinned actionlint does not accept yet. The call
  keeps `./` with an inline ignore that records why neither of the audit's
  risks applies, and the zizmor workflow's egress note now describes how the
  current action installs zizmor (a hash-locked wheel from PyPI).
- **Switching the docs language in the page now updates the page's language
  and direction.** The language switcher moves between locales without a page
  load, and the site set `<html lang>` and `dir` only when a page first loaded,
  so after a switch from German to Arabic the Arabic page stayed marked German
  and laid out left to right. A client component now applies the new page's
  language tag and direction after every navigation, before the page paints.
  Search already followed the switch.

## [1.4.0] - 2026-10-26

### Added

- **Gemini CLI helpers can reach an MCP server you name.** The
  `agent_mcp_servers` key now also reaches the Gemini CLI install: for each
  listed helper, its `tools` allowlist gains one `mcp_<server>_*` entry per
  server, the form Gemini CLI's subagent docs give, and no other helper
  changes. Gemini CLI cannot address a server name with an underscore, so
  Apothem writes a grant only for a name of letters, digits and `-`; any other
  name is skipped and reported rather than rewritten. A server the helper's
  own `disallowedTools` names stays denied, as it does on Claude Code, and a
  helper that already reaches every server is left as it is; both are
  reported. With no setting the helpers are written exactly as before.
- **A stricter research method, end to end.** The research suite gains seven
  reference guides and uses them at the stage that needs them, without adding a
  rigor mandate:
  - design fixes the experimental unit, allocation and its concealment,
    masking, nuisance factors and run order, control conditions, and within-unit
    and multi-factor structure (`study-allocation-and-structure.md`), and sizes
    the study for the analysis it will run: the effect range, sidedness and
    allocation ratio, multiplicity, attrition, clustering, sequential looks and
    simulation where no formula fits (`power-and-sample-size.md`);
  - analysis picks tests from the design, counts independent units, states its
    missing-data handling, reads a null result without observed power, holds a
    Bayesian plan to its priors and diagnostics, and rates bias per result
    (`analysis-discipline.md`); figures disclose binning, smoothing and
    normalisation, carry a cue beyond colour and keep experimental images
    traceable (`figure-integrity.md`);
  - source collection keeps a search record (queries as run, filters, dates,
    counts, chaining backward and forward, a pass for contrary evidence), links
    reports of one study, and carries each source's retraction and correction
    status through to the paper and the submission (`search-record.md`);
  - the proposal stage reads a funder call into a requirement matrix, answers a
    critique with `--resubmission`, plans data management and sharing, and
    gives each risk a contingency with an owner, a review date and a trigger
    (`plan-branching-and-contingencies.md`); publication and dissemination
    record each venue rule with its source and date, count pages the venue's
    way, check the compiled PDF, and plan talks and posters by time budget and
    audience (`talk-and-poster.md`).
- **Reference entries from identifiers.** `paper-toolkit` gains an `entries`
  mode: DOIs, arXiv identifiers, ISBNs and similar become reference entries
  with every field copied from the registry record, in one normalised form, and
  the style pass covers chapters, datasets, software releases and unpublished
  work (`bibliography-entries.md`).

### Changed

- **Dependabot proposes dependency updates.** The repository's docs and workflow
  comments said Renovate bumped the pinned action SHAs weekly, but Renovate never
  ran here. `.github/dependabot.yml` now proposes grouped weekly updates for the
  GitHub Actions pins (moving each SHA and its version comment, with CodeQL's
  steps kept together), the website and the pre-commit hooks, and monthly
  updates for the vsce packager and channel-smoke lockfiles, each held for seven
  days after a release. Pins that move in lockstep with another file (the
  runtime floors, the hash-locked release requirements, the vendored closure,
  the ruff, mypy and gitleaks hooks) stay hand edits. `renovate.json` is gone.
  The npm audit workflow now also audits and installs the two tool lockfiles,
  so a pull request that changes one is tested. The PR title check moves to its
  own PR Title workflow, which re-runs when a title is edited, and the
  repository's squash default now takes the PR title, so a long Dependabot
  title is fixed by a retitle before it merges. `.gitattributes` keeps
  `.github/dependabot.yml` in source archives, where Scorecard looks for the
  update tool.
- **Fetched text is data, and standing is not evidence.** The provenance rule
  now states that text fetched from the web or returned by an index is data to
  read, never instructions to follow; the research agents, the
  multi-source-research skill and the paper tools apply it and report an
  instruction-like sentence instead of acting on it. A second new section says a
  journal-level measure, a citation count or a venue's or author's standing is
  not evidence that a work is sound; reviews and certainty ratings rest on the
  work's own evidence.
- **The autonomous experiment loop separates search from admission.** A change
  is retained only after it wins on the search set and is confirmed on a
  separate admission set; the loop records how often the admission set was
  read, keeps a final untouched set (or labels results development-only),
  logs each trial's prediction, lesson and failure cause, makes a noise-aware
  keep decision, and stops at a campaign ceiling.
- **Security metadata and one vendor link are current.** `SECURITY-INSIGHTS.yml`
  carries today's review date and lists npm audit, Dependabot security updates,
  secret-scanning push protection and the approval-gated publishing jobs. The
  GitHub Copilot pin and the harness registry cite the agent-skills page at the
  address GitHub moved it to. The packaging contract page explains the
  "1 with warnings" badge claude.ai shows for the Apothem marketplace: its sync
  strips the directory listing links that Anthropic's directory reads.

### Fixed

- **Site search follows the page language.** The search dialog stays mounted
  when a reader switches language, and the docs framework now keeps a search
  client's query function for as long as the client's own dependencies stay
  the same; the static client's dependencies do not include the index URL, so
  after a switch the dialog went on searching the first language's index. The
  dialog now re-binds when the index URL changes.
- **Markdown lint passes, and CI runs it.** Eighteen markdownlint findings had
  landed unnoticed because only contributors' machines ran the hook: untagged
  code fences, emphasis used as a heading, and one-item numbered lists in the
  generated plugin copy, where each numbered command step becomes its own
  reference file. The sources are fixed, the hook skips the generated
  `plugins/claude-code/` tree as it skips test fixtures, and a Markdown Lint
  workflow runs the hook on every change to Markdown, the lint policy or the
  hook pin.
- **Windows CI runs get room to finish.** The Windows quality cells take 30 to
  55 minutes, and the 60-minute cap cancelled healthy runs on slow runners; the
  cap is now 90 minutes, the matrix-job ceiling the workflow validator allows.
- **The Codex plugin installs with a sparse checkout.** `codex plugin
  marketplace add` cloned the whole repository, more than 8,000 files, to read
  one small folder, and Codex gives up on a clone after 30 seconds, so on a slow
  disk such as a Windows drive under WSL the add or a later refresh timed out
  and the plugin stayed at an old version. The documented command now passes
  `--sparse .agents/plugins --sparse plugins/apothem`, the channel smoke runs
  it, and the troubleshooting page shows how to re-add an existing marketplace.
- **Uninstall removes an unedited copy of an earlier release's template.**
  Uninstall deleted a plain operator-owned file such as `glm.toml` only when it
  matched the current template, so a release that changed the template left
  every unedited copy an earlier release wrote in place, as if you had edited
  it. A manifest entry now lists the SHA-256 digests of the templates earlier
  releases shipped (`earlier_digests`), and uninstall deletes such a copy when
  Apothem's install record shows it wrote the file. Without a record, only an
  exact copy of the current template is removed, as before, and a copy you
  placed is always kept. `glm.toml` records the digests of the templates from
  `v1.0.1` through `v1.2.2`. A test fails when a shipped template changes
  without its previous digest recorded, and the release-preflight job checks
  the record against every release tag and fails once a newer release exists,
  until the record is refreshed.

## [1.3.0] - 2026-10-25

### Added

- **Four skills.** `knowledge-wiki` grows an index-first Markdown knowledge
  base from project sources (each source page records what was actually read,
  relations carry a confidence, and lint, drift and hub reports keep it
  honest); `decision-matrix` chooses between options with weighted,
  evidence-cited scores, dealbreakers first and a check that the winner
  survives weight changes; `issue-lifecycle` takes an issue from a
  duplicate-checked draft through sizing and a marked failing-test checkpoint
  to a fix (you run it; it never files on its own); `ui-design` designs and
  refines interfaces to a craft floor with a `DESIGN.md` project context.
- **Two read-only subagents.** `citation-auditor` verifies references and
  whether each cited source says what it is cited for; `design-critic` reviews
  an interface with heuristic scoring and measured accessibility evidence kept
  apart, and says so when the evidence could not be gathered.
- **Two path-scoped rules.** `authoritative-referencing-provenance` asks
  research files to label how each claim's evidence was read and keep a
  search record; `code-craft-ui` carries the interface craft floor onto UI
  source files.
- **Sharper research, review and planning stages.** Source pages record their
  basis and an acquisition worklist; papers get an approved argument sketch
  before prose; reviews run a constructive then an adversarial pass and can
  pre-screen against a venue profile; rebuttals can be checked against the
  revision; a published archive is downloaded and verified. Audits and code
  review accept "no findings", review deletions too, and keep a ledger of
  findings dropped in verification. Plan execution ties each gate to the
  commit it ran on, and tests and evals include a control that must fail.
- **Paper work without a research suite, a viewpoint panel, and course
  material.** `paper-toolkit` writes a reading note that records what was
  actually read, compares two to five papers (saying when results are not
  directly comparable and which paper to cite for which claim), drafts related
  work from the sources you supply with a coverage report and visible
  citation-needed markers, critiques a draft before submission, and runs a
  reference style pass. `perspectives` runs several separate viewpoints on a
  contested question, then reconciles them into agreement, real disagreements,
  a recommendation with its confidence and the strongest dissent.
  `teaching-pack` turns one paper or technical document into learning goals, a
  curriculum, formula walk-throughs, worked examples, a quiz with an answer key
  and a glossary, marking every line with its source section and reporting thin
  parts instead of padding them. `/research-review --paper` reviews a PDF or
  text you supply, outside any suite, against a generic venue profile with
  reviewer roles and equation, ablation and baseline checks.
  `authoritative-referencing-assurance` asks research files to list a proof's
  assumptions and weakest step, bind each number to its run, name the closest
  prior work behind a novelty claim, state tool and model use, and fix a
  gate's definition before results are seen; `/research-publish` drafts the
  tool and model use statement from the session record, and the provenance
  rule now asks that a check be shown to fail when its target is altered, that
  success be matched on the whole token, and that a lookup connector which
  never loaded be listed as blocked. `gate-evidence-grep` is an
  advisory conformity check that flags plan gate claims recorded without a
  command, an exit status or output, and the commit it ran on.
  `issue-lifecycle` can draft a request to the reporter for missing details
  and, only when you name the `publish` stage, open a draft pull request
  after three separate confirmations. `citation-auditor` and `research-scout`
  use a scholarly lookup server you grant them and fall back to web lookup. The session-start hook adds one line when a project's knowledge
  base has changed since its recorded baseline.

### Changed

- **Claude Code sessions start with about 6K tokens of rules, not about
  58K.** Four rules stay loaded in every session (agnostic posture,
  authority and inquiry, session closure, context management), with a short
  rule index that names every other rule and when to read it. The other 24
  rules that loaded at launch now load when a matching file is read or
  edited, or when a skill that cites them runs. Installed rule copies leave
  out their `## Bindings` cross-references, which stay in the source, and a
  plugin-only session is told to read the same four rules first.
- **Read-only skills and commands are model-invocable; side effects stay
  manual.** 35 audit, review, planning, research and authoring commands and
  skills can now be chosen by the model when a request matches them. Commands
  that edit, publish, release or rotate secrets (`elevate`, `fortress`,
  `freshify`, both GitHub deploy commands, `release-readiness`, `workflow`,
  `plan-execute`, `research-experiment`, `research-publish`,
  `dependency-upgrade`, `secret-rotation` and `issue-lifecycle`) run only when
  you invoke them. `plan-suite` and `research-suite` are reference templates
  read by path and are not listed. Every description now leads with what the
  skill does and the requests it serves, in about 300 characters (the 55
  model-invocable descriptions total about 15,800 characters; the 52 that
  predate this release's three new skills went from about 42,000 characters
  to about 15,000 by trimming), and overlapping skills, commands and
  subagents name where each neighbouring request goes instead.
- **Session start lists the skills by task.** A short generated index (one
  line per domain, about 400 tokens) reaches Claude Code at session start, so
  the model still knows a skill exists when its harness drops descriptions
  from a long skill listing. `scripts/dev/generate_skill_index.py --check`
  keeps it in step with the catalog.
- **OpenClaw and Hermes load Apothem's skills without hand wiring.** Install
  adds Apothem's support skills folder to OpenClaw's `skills.load.extraDirs`
  and Hermes's `skills.external_dirs`, after any entries you already have;
  uninstall removes only that entry, and `verify` checks it. Both lists come
  last in their tool's lookup order, so a skill of your own with the same name
  is the one that loads. A commented `openclaw.json` or `config.yaml` that
  lacks the entry is refused with the line to add, as for OpenCode and Qwen
  Code.
- **`research-scout` and `citation-auditor` keep a read-only tool list and
  reach a scholarly lookup server only when you name it.** Their `tools` list
  stays `Read, Glob, Grep, WebSearch, WebFetch`, so with no setting they reach
  no MCP tool and use the open web. A new profile key, `agent_mcp_servers`,
  maps an agent name to the MCP servers it may call, and the Claude Code
  install adds one `mcp__<server>__*` entry per server to that agent's list
  and to no other agent. Server names allow letters, digits, `-`, `_`, `:` and
  `.`; `*` and any other character are rejected, and a grant naming an unknown
  agent is reported and skipped. The plugin install reads no profile and keeps
  the plain list; a plugin user can get connector access with a user-level
  agent of their own. Other harnesses ignore the key.
- **Qwen Code reads Apothem's skill tool lists.** Skills now carry
  `allowedTools` as a list, the key and shape Qwen Code reads; it ignores
  `allowed-tools` and rejects a comma-separated string.
- **Codex helper files carry only keys Codex reads.** They no longer set
  `sandbox_mode = "read-only"`, which Codex ignores in a custom agent file:
  the session's own sandbox governs writes, and each read-only helper states
  it in its instructions.
- **Shared-folder advisories cover more readers.** Install now notes that Qwen
  Code also reads `~/.agents/skills/` (OpenClaw only under its default state
  directory) and that Cursor reads `~/.claude/agents/` and `~/.codex/agents/`.
- **Native config merges refuse a shape they cannot merge.** Where your file
  holds a scalar or a different kind of value at a key Apothem writes a list or
  mapping to, install refuses and writes nothing instead of replacing your
  value; an explicit `null` counts as absent.
- **Hook messages point at files the model can open.** Mandate, gate-bar and
  section references in the text hooks inject either name the shipped rule
  file they come from or say what they require, so they still mean something
  under a plugin install, where the rules are not loaded. No message grew.
- **Kimi Code loads Apothem's skills natively.** Skills and command skills now
  install to the project's `.kimi-code/skills/`, the folder Kimi Code reads,
  instead of a support folder it never scanned; update and uninstall clear the
  old copies, so each skill exists once. Helper definitions stay in the support
  folder until their tool names are mapped, and hooks are not written because
  Kimi keeps them in a user-level TOML file Apothem cannot yet edit and undo
  safely. A skill of yours with the same name as an Apothem skill is replaced
  after a backup.
- **The Codex plugin ships a root `plugin.json`.** The plugin now declares the
  Agent Plugins schema in `plugin.json` at its root, the format Codex documents
  for new packages, and keeps `.codex-plugin/plugin.json` as the documented
  fallback. The marketplace entry carries the `policy` block Codex asks for.
- **Claude Code receives commands as skills that survive compaction.** The
  plugin and the engine install now ship each command as a skill: a
  `SKILL.md` of at most about 5,000 tokens with the procedure the model
  needs every time, plus `references/` files for the pipeline contract,
  standing stanzas, decision tree and, for the longest commands, individual
  workflow steps, each behind a pointer that says when to read it. Claude
  Code keeps only the first 5,000 tokens of a skill after compaction, so the
  later steps of long commands such as `/apothem:plan-execute` were lost
  before. Commands are still invoked as `/apothem:<name>`; other harnesses
  are unchanged. Extra frontmatter keys now sit under `metadata`.
- **Hooks run one dispatcher per tool call, not one per guard.** On every
  surface (the Claude Code plugin and engine install, Codex, Qwen Code) each
  event and matcher now has one dispatcher entry that lists every guard it
  evaluates; one process reads the payload, runs them all, and returns one
  envelope. The plugin's bootstrap also caches the interpreter it found, so the
  PATH probe runs once instead of before every tool call. Measured on Windows, a Write went
  from five hook processes of about 1.5 seconds each to one of about 0.45
  seconds. The compaction tracker runs in the background, so it no longer
  delays any tool result.
- **A guard that fires says only what it found.** It injects the short
  `## Advisory` section of its message, filled with the path, identifier or
  primitive it matched, plus a pointer to the full procedure, instead of the
  whole message (2 to 7 KB). A guard that finds nothing stays silent.
- **The compaction advisory measures the context.** It reads the context size
  from the session transcript and asks the assistant to save state at half the
  window and again at three quarters, when it also tells you the session is
  long (at 120,000 and 250,000 tokens when the window is unknown; set
  `APOTHEM_CONTEXT_WINDOW_TOKENS` to give it).
  A compaction restarts its two-advisory budget. The old activity counters
  remain the fallback where no transcript exists.
- **The git-write reminder is a check.** It fires only when the command carries
  a plan-internal identifier, a numeric prefix on a suite-root plan file, or
  agent-attribution text, and names the finding.

- **One tagline and token-aligned marks.** The README, landing page, brand
  page, wordmark lockups and social images carry the tagline "one profile,
  every harness", and the logo, favicon, social images and animated mark use
  the design-system colour tokens; a light animated mark joins the dark one,
  and `scripts/dev/rebuild-assets-resvg.py` rebuilds every raster from its
  source.
- **`make lint` also runs `mypy`.** The target now matches the lint gate the
  docs describe: `ruff check`, `ruff format --check` and strict `mypy`.
- **Cursor, GitHub Copilot, Windsurf, Zed, CodeBuddy, Kiro and Trae get
  Apothem's skills and rules.** Installing any of them writes the skills, and
  each command as a skill, once to `~/.agents/skills/` (which Cursor, Copilot,
  Windsurf, Zed and Codex read) or to the tool's own folder
  (`~/.codebuddy/skills/`, `~/.kiro/skills/`, `~/.trae/skills/`), and the
  rules and templates they cite to `~/.config/apothem/`. A project still gets
  only its one rules file, which names those folders. Every install writes
  the same files; uninstall keeps a folder while another install still uses
  it and says which one. A write failure in your home stops that adapter's
  install before the project changes, a skill folder of yours with an
  Apothem skill's name is skipped with a warning, and folders are staged and
  renamed into place so an interrupted install leaves nothing half-written.
  Codex's skills now always go to `$HOME/.agents/skills`, even when
  `CODEX_HOME` points elsewhere. Trae's China edition, each tool's handling
  of unknown skill keys, and Zed's skill-count limit are not yet confirmed.

### Removed

- **Funding links.** `.github/FUNDING.yml` and the `Funding` URL in
  `pyproject.toml` are gone; the project takes no sponsorship.

### Fixed

- **The question guard names questions from one and reads "destructive" as
  the rule does.** Its findings said `[Q2]` for the third question; they now
  count from one. A recommended option is flagged as destructive for the
  operations the questions rule lists (delete, overwrite, revert uncommitted
  work and their synonyms) and for dropping a table or database, not for
  words like "retire" or "drop it from the copies".

## [1.1.0] - 2026-08-16

### Fixed

- **`status` and `verify` no longer swallow a profile that fails to load.**
  `status` hardcoded an empty warnings array and printed nothing in plain mode;
  with nothing installed there was no `unknown` drift cell either, so the
  failure left no trace at all. `verify --harness all` discarded the failure to
  read its exclusions, so excluded harnesses rejoined the sweep and the run died
  later on a missing project path that named them — with no sign of the real
  cause. Both now surface a structured advisory naming the diagnostic code and
  the fix.
- **The PowerShell interpreter locator no longer throws where its contract
  promises `$null`.** `find-pwsh.ps1` built its Windows install-root fallbacks
  with an unguarded `Join-Path $env:ProgramFiles`, which is unset under
  PowerShell on Linux and macOS. The list was built eagerly, so the throw
  pre-empted even the PATH probe that would have succeeded.
- **`migrate-workspace` reports a legacy data home it failed to remove.** The
  removal ignored errors, so when a locked file or a denied permission kept the
  directory on disk, the command still reported a clean migration and the next
  run found the same directory again. It now adds a note that names the
  directory: its records are already merged into the shared store and kept in
  the backup, so the directory can be deleted by hand.
- Documentation corrections across the conformity gate's hook scope, the design
  tokens' consumers, the OpenCode example's provenance, two harness convention
  pins, and four architecture pages that were unreachable from ten locale
  indexes.

## [1.0.2] - 2026-08-14

### Fixed

- **The `Stop` hook no longer re-asserts the session-end protocol on every turn.**
  `Stop` fires at the end of every assistant turn, not only at the end of a
  session, and the hook emitted `hooks/messages/stop.md` verbatim each time. Because
  that body reads as a fresh work order rather than a status check, every response
  triggered another firing and nothing the agent did changed what the hook
  asserted — the loop had no fixed point, and an operator could only escape it by
  restarting the harness, since hook configuration and message bodies are both
  snapshotted at session start. A new dispatch-routed handler,
  `hooks/session_end_gate.py`, supplies the missing termination condition: the
  protocol is emitted at most once per session, and only once the session has
  accumulated enough turn-ends to have state worth externalizing. The message file
  still owns the protocol text — the gate decides only when it is emitted — so its
  path and its cross-references from `rules/context-management.md` and
  `rules/auto-memory.md` are unchanged. Two environment variables tune it:
  `APOTHEM_SESSION_END_MIN_STOPS` (default `3`) sets the firing floor, and
  `APOTHEM_SESSION_END_ENABLED=0` silences the protocol entirely without editing
  installed plugin files.
- **The detection pseudocode in the canonical option-shapes rule is fenced as
  text rather than Python.** The block uses the hyphenated schema field names the
  same document defines in its field table, which are not valid Python.
  Correcting the fence language leaves the pseudocode byte-identical.

## [1.0.1] - 2026-07-07

Apothem is a host-agnostic AI-harness configuration manager: one governed shared
profile materializes into the native configuration of seventeen assistant
harnesses behind a conformity governance gate and signed, reproducible releases.

### Added

- **Shared-profile model.** One governed profile at
  `~/.config/apothem/profile.yaml` is the single source for the synced unit —
  rules, slash-commands, skills, hooks, output-styles, settings, schemas, docs,
  and MCP servers — plus the wrapped-workflow orchestrators that drive whole
  missions end to end (`/plan`, `/research`, `/audit`, and the `/fortress`
  closed-loop production-hardening pipeline).
- **Seventeen harness adapters.** Antigravity, Claude Code, CodeBuddy, Codex,
  Cursor, Gemini CLI, GitHub Copilot, Hermes, Kimi Code, Kiro, Open-Claw,
  OpenCode, Qwen Code, Trae, Windsurf, Zed, and GLM (Z.ai) each install, verify,
  update, and uninstall through a shared, reversible adapter contract that emits
  the tool's native file layout. Installs back up existing targets before
  replacement; uninstalls reverse cleanly with zero orphans.
- **CLI.** `quickstart`, `install`, `uninstall`, `update`, `verify`, `status`,
  `diff`, `rollback`, `migrate-workspace`, `harnesses`, `profile`, `doctor`, and
  `completion`, with dry-run reporting, drift detection, and structured JSON
  output (`--format json`). The engine is self-contained — the source tree
  carries its vendored dependencies and runs from a checkout as
  `python -m apothem` on system Python 3.10+.
- **Conformity governance gate.** A pre-emission validator suite checks the
  synced unit — authorship headers, frontmatter contracts, naming, determinism,
  cross-references, and harness capability coverage, including a cross-file
  binding-reciprocity validator that keeps every rule cross-binding closed at
  its cited peer — before any surface is materialized.
- **Install paths.** The Claude Code plugin
  (`/plugin marketplace add ahmed-g-gad/apothem`), a Gemini CLI extension, a
  Qwen Code extension, a Codex plugin, the npm shim
  (`npx @ahmed-g-gad/apothem <command>`), and the one-shot POSIX and PowerShell
  installers (`install.sh` / `install.ps1`) with matching update and uninstall
  scripts. The source of a VS Code-family extension is in `vscode-extension/`;
  this release attaches no packaged `.vsix`, and the extension is not listed on
  the Visual Studio Marketplace.

### Changed

- **Unified install layout.** Materialized machinery (hooks, the conformity
  gate, schemas, templates) and non-native cohorts (rules, skills, agents)
  install under a single Apothem-owned `.apothem/support/` tree inside each
  harness's configuration root, so each profile carries one Apothem-owned dotted
  directory rather than two similarly-named siblings.
- **Leaner always-on rules tier.** The always-loaded behavioral rules were
  consolidated to twenty-eight, with situational depth moved into demand-loaded
  companion rules, so a session — or a fleet of sub-agents — ingests fewer
  tokens up front while every discipline still fires where it applies.

### Security

- Every release attaches an sdist, a wheel, SHA-256 checksums, Sigstore cosign
  signatures, SLSA build provenance, and a CycloneDX SBOM as verification
  evidence; the npm package publishes with Sigstore build provenance signed
  from the GitHub Actions OIDC identity, and a conformity validator holds every
  release workflow to a provenance-signed, pinned publish path.
- The pipeline gates every change on lint, tests, type checks, a documentation
  build, CodeQL, OpenSSF Scorecard, dependency review, a scheduled OSV
  vulnerability scan, and supply-chain checks before publication. The one-shot
  installers pin their `click` / `rich` prerequisites to the engine's declared
  constraints and document an inspect-first alternative to the pipe-to-shell
  one-liner.
