OpenCode JSON कॉन्फ़िग के साथ-साथ नेटिव कमांड, स्किल और एजेंट डिस्कवरी डायरेक्टरी पढ़ता
है। Apothem एक `instructions` फ़ाइल सूची के साथ JSON कॉन्फ़िग रेंडर करता है और, जहाँ
OpenCode समर्थन करता है, साझा कॉर्पस को नेटिव डायरेक्टरी में परिवर्तित करता है।

## प्रयास तुलना

| कार्य | हस्तचालित कॉन्फ़िग | Apothem-प्रबंधित |
| ---- | --------------- | --------------- |
| नियम लिखना | कॉन्फ़िग और सहायक प्रॉम्प्ट हाथ से संपादित करें | साझा प्रोफ़ाइल से रेंडर या संदर्भित |
| कमांड, स्किल, एजेंट लिखना | हर OpenCode डायरेक्टरी हाथ से बनाए रखें | साझा Apothem कॉर्पस से परिवर्तित |
| कॉर्पस को अन्य एनवायरनमेंट के साथ संरेखित रखना | मैनुअल, प्रति टूल | `apothem update` पर स्वचालित |
| सतह इंस्टॉल / हटाना | मैनुअल | `apothem install` / `apothem uninstall` |
| कॉन्फ़िग सही है यह सत्यापित करना | मैनुअल निरीक्षण | `apothem verify --harness opencode` |

## Apothem क्या प्रबंधित करता है

opencode अडैप्टर `opencode.json` लिखता है, Apothem स्लैश कमांड को OpenCode की Markdown
कमांड फ़ाइलों में परिवर्तित करता है, स्किल को नेटिव स्किल सतह में कॉपी करता है, और
सहायक परिभाषाओं को Markdown सबएजेंट के रूप में अनुकूलित करता है। नियम, टेम्पलेट और हुक
प्रॉम्प्ट Apothem के सहायक सबट्री के अंतर्गत रहते हैं; नियमों को नेटिव `instructions`
सूची से संदर्भित किया जाता है।

## माइग्रेशन पथ

1. यदि आपने अभी तक नहीं बनाया है तो साझा प्रोफ़ाइल बनाने के लिए `apothem profile init` चलाएँ।
2. मौजूदा OpenCode नियम, कमांड, स्किल और एजेंट को साझा कॉर्पस में ले जाएँ।
3. नेटिव कॉन्फ़िग और डिस्कवरी डायरेक्टरी रेंडर करने के लिए `apothem install --harness opencode` चलाएँ।
4. कॉन्फ़िग पहुँच गया इसकी पुष्टि के लिए `apothem verify --harness opencode` चलाएँ।
5. हर बाद के बदलाव के लिए `apothem update --harness opencode` का उपयोग करें।
