Kimi Code प्रोजेक्ट-रूट की `AGENTS.md` को अपनी निर्देश फ़ाइल के रूप में पढ़ता है
और प्रोजेक्ट कॉन्फ़िगरेशन `<project>/.kimi-code/` के अंतर्गत रखता है, जिसमें
ऑपरेटर-स्वामित्व वाली `.kimi-code/mcp.json` MCP सतह भी शामिल है। आप उस निर्देश
फ़ाइल और उसके सहायक समूहों को हर प्रोजेक्ट के लिए, हमेशा, हाथ से लिख सकते हैं।
Apothem का kimi-code अडैप्टर साझा प्रोफ़ाइल से शासन सतह को `AGENTS.md` में एक
प्रबंधित ब्लॉक के रूप में रेंडर करता है और उसे हर हार्नेस और हर प्रोजेक्ट में
एकरूप रखता है। यह पृष्ठ उस कॉन्फ़िग को हाथ से अनुरक्षित करने और Apothem से
प्रबंधित करने की तुलना करता है।

## प्रयास तुलना

| कार्य | हस्तचालित कॉन्फ़िग | Apothem-प्रबंधित |
| ---- | --------------- | --------------- |
| `AGENTS.md` निर्देश सतह लिखना | हर प्रोजेक्ट के लिए हाथ से लिखना और फिर से सिंक करना | साझा प्रोफ़ाइल से रेंडर किया गया एक प्रबंधित ब्लॉक |
| नियम, कमांड, स्किल, एजेंट को सिंक में रखना | हर प्रोजेक्ट में हाथ से कॉपी करना | हर इंस्टॉल पर `<project>/.kimi-code/.apothem/support/` के अंतर्गत मटेरियलाइज़ होता है |
| रिफ़्रेश पर ऑपरेटर का गद्य सुरक्षित रखना | हाथ से मर्ज करना | सेंटिनल-सीमांकित ब्लॉक; उसके बाहर का ऑपरेटर का गद्य सुरक्षित रहता है |
| नियमों को अन्य हार्नेसों के साथ संरेखित रखना | हाथ से, प्रति टूल | `apothem update` पर अपने आप |
| कॉन्फ़िग सही है, यह सत्यापित करना | हाथ से निरीक्षण | `apothem verify --harness kimi-code --project <path>` |

## Apothem क्या प्रबंधित करता है

kimi-code अडैप्टर साझा नियमों और शासन सतह को प्रोजेक्ट-रूट की `AGENTS.md` के
प्रबंधित ब्लॉक में रेंडर करता है और कमांड, स्किल, हुक, एजेंट, नियम तथा टेम्पलेट
समूहों को `.kimi-code/.apothem/support/` के अंतर्गत इंस्टॉल करता है। यह
`.kimi-code/mcp.json` नहीं लिखता; MCP सतह ऑपरेटर-स्वामित्व वाली ही रहती है।
Kimi Code प्रोजेक्ट निर्देश `AGENTS.md` या `.kimi-code/AGENTS.md` से पढ़ता है;
अडैप्टर केवल प्रोजेक्ट-रूट की `AGENTS.md` लिखता है, और Kimi Code का दस्तावेज़ यह
नहीं बताता कि दोनों फ़ाइलें मौजूद होने पर उनमें से कौन-सी प्राथमिकता पाती है।
साझा नियमों में हर बदलाव अगले `apothem update` पर फ़ाइलों को फिर से रेंडर करता है।

## माइग्रेशन पथ

1. यदि आपने अभी तक साझा प्रोफ़ाइल नहीं बनाई है, तो उसे बनाने के लिए
   `apothem profile init` चलाएँ।
2. अपनी मौजूदा `AGENTS.md` के नियमों को साझा कॉर्पस में ले जाएँ।
3. `AGENTS.md` निर्देश सतह और `.kimi-code/.apothem/support/` समर्थन उप-वृक्ष को
   रेंडर करने के लिए `apothem install --harness kimi-code --project <path>` चलाएँ।
4. यह पुष्टि करने के लिए कि कॉन्फ़िग अपनी जगह पहुँच गई,
   `apothem verify --harness kimi-code --project <path>` चलाएँ।
5. हर बाद के बदलाव के लिए `apothem update --harness kimi-code --project <path>` का
   उपयोग करें।
