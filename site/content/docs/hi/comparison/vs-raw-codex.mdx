Codex उपयोगकर्ता निर्देश `AGENTS.md` से पढ़ता है, हुक `hooks.json` या
`config.toml` से लोड करता है, कस्टम एजेंट `agents/` के अंतर्गत खोजता है, और स्किल
साझा Codex स्किल रूट से खोजता है। Apothem का codex अडैप्टर इन सतहों को साझा
प्रोफ़ाइल से इंस्टॉल करता है, जबकि ऑपरेटर-स्वामित्व वाली `config.toml` सेटिंग्स को
अछूता छोड़ देता है।

## प्रयास तुलना

| कार्य | हस्तचालित कॉन्फ़िग | Apothem-प्रबंधित |
| ---- | --------------- | --------------- |
| `AGENTS.md` लिखना | उपयोगकर्ता निर्देश हाथ से संपादित करें | Codex बूटस्ट्रैप टेम्पलेट से इंस्टॉल |
| हुक लिखना | `hooks.json` या TOML हुक टेबल हाथ से लिखें | `~/.codex/hooks.json` में इंस्टॉल, Apothem हुक हेल्पर `~/.codex/hooks/` के अंतर्गत |
| कस्टम एजेंट लिखना | `~/.codex/agents/` के अंतर्गत TOML फ़ाइलें हाथ से लिखें | Apothem के Markdown एजेंट से परिवर्तित |
| पुन: उपयोग योग्य कमांड लिखना | स्किल एक-एक डायरेक्टरी हाथ से बनाएँ | `~/.agents/skills/*/SKILL.md` के रूप में लपेटा गया |
| नियमों को अन्य एनवायरनमेंट के साथ संरेखित रखना | मैनुअल, प्रति टूल | `apothem update` पर स्वचालित |
| कॉन्फ़िग सही है यह सत्यापित करना | मैनुअल निरीक्षण | `apothem verify --harness codex` |

## Apothem क्या प्रबंधित करता है

codex अडैप्टर `AGENTS.md`, `hooks.json`, हुक हेल्पर फ़ाइलें, परिवर्तित कस्टम एजेंट
और जनरेट किए गए स्किल इंस्टॉल करता है। यह `~/.codex/config.toml` को अधिलेखित नहीं
करता; मॉडल, सैंडबॉक्स, अनुमोदन, MCP और अन्य रनटाइम वरीयताएँ ऑपरेटर-स्वामित्व में
रहती हैं।

## माइग्रेशन पथ

1. यदि आपने अभी तक नहीं बनाया है तो साझा प्रोफ़ाइल बनाने के लिए
   `apothem profile init` चलाएँ।
2. अपने मौजूदा `AGENTS.md` के नियमों को साझा कॉर्पस में ले जाएँ।
3. Codex में मौजूदा `config.toml` रनटाइम सेटिंग्स को बनाए रखें, जब तक कि आप उन्हें
   कहीं और हाथ से प्रबंधित करना न चुनें।
4. Codex-नेटिव सतहें इंस्टॉल करने के लिए `apothem install --harness codex` चलाएँ।
5. फ़ाइलें पहुँच गईं इसकी पुष्टि के लिए `apothem verify --harness codex` चलाएँ।
6. हर बाद के बदलाव के लिए `apothem update --harness codex` का उपयोग करें।
