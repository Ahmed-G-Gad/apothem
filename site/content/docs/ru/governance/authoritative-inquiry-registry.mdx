> **Канонический реестр дисциплины авторитетного опроса.** Этот документ несёт каталог из семи обязательных категорий, перечисление исключённых автоматических решений и декларацию связей; содержательные таблицы и связи живут здесь, операционализированные `src/apothem/rules/authority-inquiry.md`.

При работе над проектом-хостом запрашивай — не выдумывай — по семи категориям ниже. Запросы маршрутизируются через канал структурированного запроса согласно `src/apothem/rules/interactive-questions.md`. Каждый вариант несёт трёхсегментную аннотацию (обоснование / рекомендация / указатель по умолчанию) и маркер рекомендации согласно M7.

| Категория | Запрещено выдумывать | Запрашивать потому что |
| -------- | ------------------- | --------------- |
| Идентичность | Имена, почта, дескрипторы, местоимения, организации, арендаторы, командные принадлежности, описания ролей | Привязывается к реальному человеку; создаёт артефакты реального мира (коммиты, PR, публичную атрибуцию) |
| Направление области | Какое поддерево, какая ветка, какое окружение (dev/staging/prod), какая цель (библиотеки vs сервисы), что обращено к пользователю vs только внутреннее | У пользователя есть неявный контекст, которого нет у ассистента; молчаливые выборы рассогласовывают |
| Предпочтение | Форматтер, линтер, тестовый фреймворк, генератор документации, провайдер CI, стратегия ветвления, соглашение о сообщениях коммитов, подписание релизов, схема версионирования, лицензия — *там, где хост не остановился ни на одном* | Каждое — это долгоживущее обязательство, сопротивляющееся молчаливому принятию |
| Безопасность | Каденция ротации секретов, разрешённые оболочки, разрешённый сетевой выход, список принятых рисков, список доверенных действий, специфика конечной точки аутентификации MCP-сервера | Неверная конфигурация безопасности высокозначима; молчаливые выборы рискуют молчаливой брешью |
| Именование | Новое соглашение, вводимое там, где у хоста его нет, или привязка имени (функция, флаг CLI, подкоманда, ключ конфигурации) там, где у пользователя есть неявные предпочтения | Имена долговечны; молчаливые выборы накапливаются в загрязнение пространства имён |
| Инфраструктура | Конечные точки, хосты, порты, пути, регионы, имена очередей, имена тем, имена таблиц | Привязываются к ресурсам реального мира; выдумывание вызывает сбои реального мира |
| Закрепления версий | Какая версия какой зависимости, там, где хост не закрепил и выбор важен (зависимости, значимые для безопасности, зависимости с изменением поведения, границы semver-major) | Долгохвостые последствия; молчаливые выборы обременяют пользователя |

**Обязательные запросы** (Идентичность, Направление области, Поза безопасности, Именование публичных поверхностей всегда обязательны) блокируют зависимые артефакты; эмиссия порождает плейсхолдеры `<USER-CONFIRM:id=<id>>`. **Опциональные запросы** пользователь может отклонить молчанием; ассистент тогда откатывается к рекомендованному варианту и фиксирует откат как находку, чтобы пользователь видел, что решение было принято.

## 1. Исключённые автоматические решения

Следующее ассистент решает без запроса — раскрывается в журнале изменений как «применено по умолчанию; откатить, если намерение иное»:

- **Чистая валидность.** Синтаксические ошибки, нарушения схемы, однозначные опечатки.
- **Чистая строгость.** Фольклор → процитирован; недостающие даты добавлены; непроверяемые утверждения помечены.
- **Универсально безопасная безопасность.** `deny .env*`, `deny ~/.ssh/**` чтения, `deny rm -rf:*`, `deny sudo:*`, `deny git push --force*` в защищённые ветки, `deny eval`/`exec` на недоверенный ввод.
- **Чистая нормализация форматирования.** EOL, концевые пробелы, единый стиль кавычек на файл *там, где у хоста есть установленный стиль и артефакт расходится*.
- **Ремонт внутренних ссылок, где исправление однозначно.** Мёртвый путь → единственный живой путь, обнаруженный поиском.

Всё за пределами этого исключения проходит через поверхность запроса.

## 2. Связи (§0.j five-direction)

- **Drives →** Каждая эмиссия артефакта проекта-хоста (ворота предэмиссии срабатывают при каждой записи значимого масштаба согласно `site/content/docs/governance/pre-emission-gate-registry.mdx`). Каждое представление множественных вариантов маршрутизируется через канал структурированного запроса согласно обязательству канонического канала. Принуждение механической доли в `src/apothem/conformity/*-grep.py`. Принуждение по правилам в `src/apothem/rules/{authority-inquiry,host-discovery,disclosure-ledger,ten-dimension-check,pre-emission-gate,expertise-posture,option-annotation,definitiveness,visual-leverage,bidirectional-binding,agile-sprints,canonical-layout,code-craft-*,systemic-participation,production-ready-prs}.md`.
- **Satisfies →** Ось внешнего соответствия, объявленная как первоклассное измерение управления наряду с осью CM-N (M = артефакты проектов-хостов; CM = внутренние артефакты экосистемы; обе ортогональны, обе применяются там, где применяются обе). Обязательство постоянных директив, что каждая загрузка сессии наследует набор M как всегда активный контекст.
- **Established by ↑** Сам `CLAUDE.md` (реестр внутренне присущ всегда активному контексту, а не выведен из внешнего состояния). Ратификация порога тривиального против нетривиального в `site/content/docs/governance/outward-conformity-registry.mdx` §1.
- **Cross-bound with ↔** Каждое правило, названное в таблице реестра внешнего соответствия в `site/content/docs/governance/outward-conformity-registry.mdx` (канонический корпус по мандату). `src/apothem/conformity/*-grep.py` (принуждение механической доли ворот). `src/apothem/rules/interactive-questions.md` (поверхность запроса маршрутизируется через обязательство канонического канала, которое определяет это правило).
