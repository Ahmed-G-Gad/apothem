Эта дорожная карта описывает, куда движется Apothem. Это заявление о
намерениях, а не обязательство; приоритеты меняются по мере развития проекта и
его пользователей. О том, что уже выпущено, см.
[журнал изменений](https://github.com/ahmed-g-gad/apothem/blob/main/CHANGELOG.md).
[ROADMAP.md](https://github.com/ahmed-g-gad/apothem/blob/main/ROADMAP.md) в
репозитории — единственная дорожная карта;
[страница дорожной карты](https://apothem.ahmedgad.com/docs/community/roadmap) на
сайте проекта генерируется из него.

Обозначения статусов: **запланировано** · **в работе** · **выпущено**.

## Текущий релиз

Текущая линия релизов поставляет независимый от хоста менеджер конфигурации
окружений: общий профиль (`~/.config/apothem/profile.yaml`), материализуемый в
нативную для окружений конфигурацию для зарегистрированных адаптеров и
управляемый через командную строку `apothem` (`quickstart` · `install` ·
`update` · `uninstall` · `rollback` · `verify` · `status` · `diff` ·
`harnesses` · `profile` · `doctor` · `migrate-workspace` · `completion`).

| Пункт | Статус | Примечания |
| ---- | ------ | ----- |
| Семнадцать адаптеров окружений | выпущено | Каждый с установкой, удалением, обновлением и проверкой; они перечислены на страницах [поддерживаемых окружений](https://apothem.ahmedgad.com/docs/harnesses) |
| Распространение шаблонов на основе манифеста | выпущено | Единый источник истины для распространения в `src/apothem/lib/propagation-manifest.yaml` |
| Сайт документации | выпущено | Публичный сайт с генерируемыми справочными указателями, фирменными материалами, машиночитаемым индексом сайта и руководствами по релизам |
| Подписанные релизы | выпущено | Каждый GitHub Release содержит подписанные артефакты, SBOM и происхождение сборки |
| Конвейеры `/plan` и `/research` | выпущено | Поэтапный конвейер планирования (спецификация, генерация, ревью и исполнение), а также тринадцатиэтапный конвейер исследования |
| Команды аудита и цикл `/fortress` | выпущено | Аудиты по запросу — безопасность, код, доступность, производительность, зависимости, цепочка поставок, модель угроз, архитектура, ревью кода, ревью документации и UX, — обёрнутые циклом упрочнения `/fortress` |
| Инфраструктура аудита и проверки дрейфа | выпущено | Сканеры инвентаризации и дрейфа, на которых основаны команды аудита |
| Шлюз соответствия | выпущено | Валидаторы заголовков авторства, именования, качества кода, уклончивых формулировок и взаимности привязок по каждой материализованной поверхности, с эталонными снимками behavior-diff, фиксирующими вывод каждого адаптера |
| Долговременная память и непрерывное обучение, включаемое по выбору | выпущено | Постоянный уровень памяти и включаемый по выбору цикл обучения, которые переносят подтверждённые соглашения между сессиями |
| Конвейер CI/CD и цепочка поставок подписанных релизов | выпущено | Каждое изменение перед релизом проходит шлюзы линтинга, тестов, проверки типов, сборки документации и проверок цепочки поставок |

## Долгосрочное видение

Apothem стремится стать способом по умолчанию, которым любой человек управляет
конфигурацией окружений во всех используемых им инструментах: написать
соглашения один раз, материализовать их везде и поддерживать их синхронизацию по
мере развития как предпочтений, так и окружений.

## Как повлиять на дорожную карту

- Откройте issue в
  [трекере задач](https://github.com/ahmed-g-gad/apothem/issues) или
  проголосуйте за существующий; запрос функции там — это способ предложить пункт
  дорожной карты. Популярные запросы продвигаются быстрее.
- О том, как предлагать и вносить изменения, см.
  [CONTRIBUTING.md](https://github.com/ahmed-g-gad/apothem/blob/main/CONTRIBUTING.md).
