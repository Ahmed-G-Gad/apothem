**Поставщик:** Tencent
**Имя установки:** `codebuddy`
**Статус:** GA
**Нативная конфигурация:** `<project>/.codebuddy/rules/apothem-rules.md`

## Установка

```bash
apothem install --harness codebuddy --project /path/to/project
```

Адаптер записывает один файл правил с областью проекта из общей поверхности правил и
управления Apothem.

**Записанные файлы:** `<project>/.codebuddy/rules/apothem-rules.md`

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общий профиль Apothem и отрисовывает файл правил проекта при каждом
запуске `apothem install` или `apothem update`. CodeBuddy читает каждый файл `*.md` в
`.codebuddy/rules/` как Markdown с необязательным YAML-фронтматтером (`alwaysApply`,
`paths`, `enabled`) согласно
[документации CodeBuddy Rules](https://www.codebuddy.ai/docs/ide/Rules); файл Apothem
несёт `alwaysApply: true`, поэтому поверхность управления применяется при каждом
взаимодействии. Общий профиль является источником истины; локальные для проекта правки
сгенерированного файла резервируются до того, как следующая синхронизация заменит
управляемое Apothem содержимое.

## Замечания о совместимости

Поверхность правил CodeBuddy имеет область проекта в `.codebuddy/rules/`. Адаптер
записывает выделенный файл `apothem-rules.md`, который сосуществует с любыми файлами
правил, написанными оператором в том же каталоге. Файл памяти проекта `CODEBUDDY.md` и
`.codebuddy/settings.json` (разрешения, MCP) принадлежат оператору; Apothem их не
записывает. Навыки, команды, агенты и хуки упоминаются как дисциплина внутри файла
правил — CodeBuddy не предоставляет для них поверхности файлов, принадлежащей адаптеру.
Соглашения поверхности поставщика, на которые опирается адаптер, зафиксированы в
`src/apothem/harnesses/codebuddy/STANDARD-CONVENTION-PIN.md` и сняты в снимок
относительно действующей документации CodeBuddy.

## Проверка

```bash
apothem verify --harness codebuddy --project /path/to/project
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Управляемый файл правил присутствует и не пуст.
3. Специфичная для адаптера процедура проверки сообщает об успехе.

## Обновление

```bash
apothem update --harness codebuddy --project /path/to/project
```

Заново выводит файл правил проекта из текущего состояния общего профиля. `install` и
`update` идемпотентны — повторный запуск перезаписывает управляемый файл последним
отрисованным содержимым.

## Удаление

```bash
apothem uninstall --harness codebuddy --project /path/to/project
```

Удаляет файлы нативной конфигурации, записанные адаптером, переименовывая управляемый
файл правил в резервную копию с меткой времени. YAML общего профиля и движок Apothem
не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Решение |
|---------|-----|
| Файл конфигурации не найден | Заново выполните `apothem install --harness codebuddy --project /path/to/project` |
| Проверка не прошла | Выполните `apothem update --harness codebuddy --project /path/to/project`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем заново выполните `apothem update --harness codebuddy --project /path/to/project` |

## Настроечные параметры

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предварительный просмотр установки без записи файлов. |
