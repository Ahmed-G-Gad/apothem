**Поставщик:** OpenCode
**Имя установки:** `opencode`
**Статус:** Бета
**Нативная конфигурация:** `~/.config/opencode/`

## Установка

```bash
apothem install --harness opencode
```

Адаптер записывает JSON-конфигурацию OpenCode, устанавливает навыки Apothem в
поверхность навыков OpenCode, преобразует промпты команд в файлы команд OpenCode
в формате Markdown и нормализует определения помощников Apothem как
субпомощники OpenCode.

**Записываемые файлы:**

```text
~/.config/opencode/opencode.json
~/.config/opencode/commands/
~/.config/opencode/skills/
~/.config/opencode/agents/
~/.config/opencode/.apothem/support/{rules,templates,hooks}/
```

## Сопоставление профиля с нативной конфигурацией

Адаптер рендерит `opencode.json` со списком файлов `instructions`, в котором
указаны ваш документ профиля и всегда действующие правила Apothem, а затем
распространяет каждую общую группу Apothem либо в нативную поверхность OpenCode,
либо в принадлежащее Apothem поддерево поддержки. Для существующих совпадающих
дочерних элементов, управляемых Apothem, создаются резервные копии перед
заменой.

## Заметки о совместимости

OpenCode объединяет каждый файл, указанный в списке `instructions`, в каждую
сессию ([правила OpenCode](https://opencode.ai/docs/rules/)). Поэтому список
указывает сначала ваш документ профиля, а затем только правила, у которых
`alwaysApply` равно `true`, — каждое отдельным явным путём
`~/.config/opencode/.apothem/support/rules/<name>.md`; OpenCode разворачивает
начальный `~/` в ваш домашний каталог. Правила с фильтрацией по путям, шаблоны и
промпты хуков остаются установленными как справочный материал в
`~/.config/opencode/.apothem/support/`, где правило, навык или команда, которые
ссылаются на один из них, читают его по требованию. Команды, навыки и
определения помощников используют нативные расположения обнаружения.

Документ профиля `~/.config/opencode/apothem/rules/00-apothem-profile.md`
содержит вашу идентичность и предпочтения из общего профиля и завершается
разделом о вспомогательных файлах Apothem, который называет абсолютный каталог в
`~/.config/opencode/.apothem/support/`, относительно которого разрешается каждая
ссылка в стиле репозитория (`rules/<name>.md`, `templates/...`, `hooks/...`). Он
является первой записью `instructions`, поэтому OpenCode загружает его в каждой
сессии.

`opencode.json`, записанный более ранним релизом, содержит единственный glob
`~/.config/opencode/.apothem/support/rules/*.md`, который загружает все правила.
`apothem install` и `apothem update` заменяют его списком всегда действующих
правил, а `apothem uninstall` удаляет обе формы. Ваши собственные записи
`instructions` сохраняются в любом случае.

## Проверка

```bash
apothem verify --harness opencode
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы дополнительно подтвердить, что установленные файлы соответствуют этому профилю.
3. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness opencode
```

Обновляет `opencode.json`, нативные команды, навыки, определения помощников и
дерево поддержки Apothem.

## Удаление

```bash
apothem uninstall --harness opencode
```

Удаляет файлы нативной конфигурации, записанные адаптером.
YAML общего профиля и движок Apothem не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness opencode` |
| Проверка не пройдена | Запустите `apothem update --harness opencode`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness opencode` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
