**Поставщик:** Open-Claw
**Имя установки:** `open-claw`
**Статус:** Предварительная версия
**Нативная конфигурация:** `~/.openclaw/openclaw.json`

## Установка

```bash
apothem install --harness open-claw
```

Адаптер записывает глобальный пользовательский файл конфигурации OpenClaw,
проецирует общий профиль в документ профиля и устанавливает группы поддержки
Apothem в корень окружения. Нативная конфигурация OpenClaw — это JSON;
материализатор рендерит один ключ, `skills.load.extraDirs`, а существующий файл
сохраняет свои остальные ключи.

**Записываемые файлы:** `~/.openclaw/openclaw.json`, документ профиля
`~/.openclaw/apothem/rules/00-apothem-profile.md` и файлы поддержки в
`~/.openclaw/.apothem/support/`

Документ профиля завершается разделом о вспомогательных файлах Apothem, который
называет абсолютный каталог в `~/.openclaw/.apothem/support/`, относительно
которого разрешается каждая ссылка в стиле репозитория (`rules/<name>.md`,
`templates/...`, `hooks/...`).

## Сопоставление профиля с нативной конфигурацией

Адаптер создаёт один ключ конфигурации. Он добавляет
`~/.openclaw/.apothem/support/skills` в `skills.load.extraDirs` — список
дополнительных каталогов навыков, которые читает OpenClaw; именно так OpenClaw
находит установленные навыки. Запись добавляется после всех записей, которые вы
уже указали, а ваши остальные ключи остаются как есть. Идентичность,
предпочтения и правила из профиля попадают в документ профиля. Общие команды, навыки, правила, шаблоны и промпты
хуков устанавливаются как вспомогательный материал в
`~/.openclaw/.apothem/support/`.

## Заметки о совместимости

Адаптер в предварительной версии. OpenClaw загружает навыки Apothem через `skills.load.extraDirs`, но сам по себе не загружает остальную часть поддерева поддержки и документ профиля: ни его файлы инструкций рабочей области, ни его конфигурация не указывают на них, поэтому после установки OpenClaw работает без правил и серверов MCP Apothem.

**Конфликты имён.** OpenClaw читает навыки из следующих источников, начиная с наивысшего приоритета, и когда одно и то же имя навыка встречается более чем в одном месте, побеждает источник с наивысшим приоритетом: папка `skills/` рабочей области, папка `.agents/skills/` рабочей области, `~/.agents/skills` (только для каталога состояния по умолчанию), папка `skills/` каталога состояния (по умолчанию `~/.openclaw/skills`), навыки workshop, встроенные навыки и навыки custodian и, наконец, папки, перечисленные в `skills.load.extraDirs`, вместе с навыками плагинов. Каталог Apothem является записью `extraDirs`, поэтому OpenClaw использует навык с тем же именем, который вы храните в любом из более ранних источников, а копия этого навыка от Apothem остаётся на диске неиспользуемой. Apothem записывает только в `openclaw.json` и в `~/.openclaw/.apothem/support/` и никогда не записывает в эти более ранние папки, поэтому установка, обновление и удаление не заменяют навык, который вы там храните.

`agents.defaults.skills` — это список разрешённых имён навыков; Apothem его не редактирует, поэтому если вы его ведёте, проверьте, что в нём указаны нужные вам навыки Apothem. `apothem update` сохраняет ключи, которые вы добавляете в `openclaw.json`. Серверы MCP находятся в блоке `mcp.servers` конфигурации OpenClaw, которым вы управляете с помощью `openclaw mcp add` и связанных подкоманд; адаптер не записывает туда ни одной записи. (Поведение OpenClaw соответствует его документации по [навыкам](https://docs.openclaw.ai/tools/skills), [конфигурации навыков](https://docs.openclaw.ai/tools/skills-config) и [расширениям конфигурации](https://docs.openclaw.ai/gateway/config-extensions), прочитанной 2026-10-24, и его документации по [CLI для MCP](https://docs.openclaw.ai/cli/mcp), прочитанной 2026-10-02.)

**Комментарии в `openclaw.json`.** OpenClaw читает свою конфигурацию как JSON5, а Apothem перезаписывает файл как обычный JSON. Если файл содержит комментарии или другой синтаксис JSON5, а записи нет, Apothem оставляет файл нетронутым, и установка останавливается с сообщением, в котором назван ключ. Объедините эту запись со своим файлом самостоятельно или преобразуйте файл в обычный JSON, затем снова запустите установку:

```json
{
  "skills": {
    "load": {
      "extraDirs": ["~/.openclaw/.apothem/support/skills"]
    }
  }
}
```

Запись, которую вы добавили сами, считается вашей: удаление оставляет её на месте.

## Проверка

```bash
apothem verify --harness open-claw
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а
   конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы
   дополнительно подтвердить, что установленные файлы соответствуют этому
   профилю.
3. `skills.load.extraDirs` в нативной конфигурации содержит
   `~/.openclaw/.apothem/support/skills`. Без этой записи OpenClaw не загружает
   установленные навыки; `apothem update` добавляет её снова.
4. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness open-claw
```

Повторно выводит документ профиля из текущего состояния общего профиля и
обновляет вспомогательные файлы; `openclaw.json` сохраняет ключи, которые в нём
уже есть, а запись Apothem в `skills.load.extraDirs` остаётся указанной один раз,
сколько бы раз вы ни обновляли. Запускайте после редактирования `~/.config/apothem/profile.yaml` или
обновления установленного пакета Apothem.

## Удаление

```bash
apothem uninstall --harness open-claw
```

Удаляет то, что добавил адаптер: его запись в `skills.load.extraDirs`, документ
профиля и поддерево поддержки. Ваши собственные ключи в `openclaw.json`
остаются на месте, включая ваши собственные записи `extraDirs`, а сам файл удаляется
только тогда, когда его создал Apothem и от вас в нём ничего не осталось. YAML
общего профиля и движок Apothem не затрагиваются.

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness open-claw` |
| Проверка не пройдена | Запустите `apothem update --harness open-claw`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Apothem задаёт в `openclaw.json` только запись `skills.load.extraDirs` и сохраняет уже имеющиеся в нём ключи, поэтому содержимое профиля туда не попадает. Содержимое профиля попадает в `~/.openclaw/apothem/rules/00-apothem-profile.md`: проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите команду из раздела [Обновление](#обновление) |
| Установка останавливается с сообщением о комментариях или синтаксисе JSON5 в `openclaw.json` | Apothem не перезаписывает файл, из которого ему пришлось бы удалить комментарии. Добавьте запись `skills.load.extraDirs`, показанную в разделе [Заметки о совместимости](#заметки-о-совместимости), самостоятельно или преобразуйте файл в обычный JSON, затем снова запустите установку |
| Навык Apothem не появляется в OpenClaw | Навык с тем же именем в рабочей области, `~/.agents/skills` или `~/.openclaw/skills` имеет приоритет над копией Apothem (см. [Заметки о совместимости](#заметки-о-совместимости)). Также запустите `apothem verify --harness open-claw` и проверьте, что ведущийся вами список разрешённых навыков `agents.defaults.skills` содержит имя этого навыка |
