- **Поставщик:** Open-Claw
- **Имя установки:** `open-claw`
- **Статус:** Предварительная версия
- **Нативная конфигурация:** `~/.openclaw/openclaw.json`

## Установка

```bash
apothem install --harness open-claw
```

Адаптер записывает глобальный пользовательский файл конфигурации OpenClaw,
проецирует общий профиль в документ профиля, записывает файл правил Apothem в
каждую рабочую область OpenClaw и устанавливает группы поддержки Apothem в
корень окружения. Нативная конфигурация OpenClaw — это JSON; материализатор
рендерит две записи, `skills.load.extraDirs` и запись хука
`bootstrap-extra-files`, а существующий файл сохраняет свои остальные ключи.

**Записываемые файлы:** `~/.openclaw/openclaw.json`, документ профиля
`~/.openclaw/apothem/rules/00-apothem-profile.md`, файл правил
`<workspace>/apothem/AGENTS.md` в каждой рабочей области и папка данных Apothem
`~/.openclaw/.apothem/` (её хранилища контекста, обучения и памяти, а также
файлы поддержки в `~/.openclaw/.apothem/support/`)

Каждая установка и каждое обновление удаляют в `~/.openclaw/apothem/rules/`
все файлы, которые туда положил не Apothem, предварительно сохранив их в наборе
резервных копий в `~/.apothem/backups/`. Эта резервная копия удаляется, как
только для окружения появляется 10 более новых наборов резервных копий, поэтому
храните свои файлы в другом месте.

Документ профиля завершается разделом о вспомогательных файлах Apothem, который
называет абсолютный каталог в `~/.openclaw/.apothem/support/`, относительно
которого разрешается каждая ссылка в стиле репозитория (`rules/<name>.md`,
`templates/...`, `hooks/...`).

## Сопоставление профиля с нативной конфигурацией

Адаптер создаёт две записи конфигурации:

- Он добавляет `~/.openclaw/.apothem/support/skills` в `skills.load.extraDirs` —
  список дополнительных каталогов навыков, которые читает OpenClaw; именно так
  OpenClaw находит установленные навыки. Запись добавляется после всех записей,
  которые вы уже указали.
- Он добавляет `apothem/AGENTS.md` в список путей записи
  `hooks.internal.entries.bootstrap-extra-files`; именно так OpenClaw
  загружает файл правил Apothem (см. [Правила в каждой рабочей области](#правила-в-каждой-рабочей-области)).

Ваши остальные ключи остаются как есть, и Apothem никогда не записывает
`hooks.internal.enabled`. Идентичность, предпочтения и правила из профиля
попадают в документ профиля и в файл правил каждой рабочей области. Общие
команды, навыки, определения помощников, правила, шаблоны и промпты хуков
устанавливаются как вспомогательный материал в `~/.openclaw/.apothem/support/`.

## Заметки о совместимости

Адаптер в предварительной версии. OpenClaw загружает навыки Apothem через
`skills.load.extraDirs`, а правила Apothem — через файл правил в каждой рабочей
области. Серверы MCP из Apothem он не загружает.

### Правила в каждой рабочей области

OpenClaw помещает в свой системный промпт шесть файлов из рабочей области:
`AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`, `BOOTSTRAP.md` и `MEMORY.md`.
Его встроенный хук `bootstrap-extra-files` добавляет другие файлы с одним из
этих имён, а пути читаются относительно рабочей области каждого сеанса. Apothem
записывает `apothem/AGENTS.md` в каждую рабочую область и указывает этот путь в
записи хука:

```json
{
  "hooks": {
    "internal": {
      "entries": {
        "bootstrap-extra-files": {
          "enabled": true,
          "paths": ["apothem/AGENTS.md"]
        }
      }
    }
  }
}
```

Файл содержит управляемый блок профиля и указатель на индекс правил в
`~/.openclaw/.apothem/support/`, через который доступен весь набор правил.
Поскольку файл называется `AGENTS.md`, OpenClaw загружает его также в сеансах
cron и во вспомогательных сеансах, которые запускает другой сеанс, — они
получают лишь часть из шести файлов. Apothem никогда не редактирует собственный
`AGENTS.md` рабочей области: OpenClaw создаёт его из шаблона, а редактирует
ассистент, работающий в этой рабочей области. Папка с именем `apothem` не
считается работой по настройке, поэтому рабочая область, которую OpenClaw ещё
не настроил, всё равно получает свои файлы первого запуска.

Apothem записывает файл в каждую рабочую область, существующую в вашем
домашнем каталоге: `agents.defaults.workspace` (иначе `OPENCLAW_WORKSPACE_DIR`,
иначе `~/.openclaw/workspace`) и `workspace` каждой записи `agents.entries`
(или каждого элемента более старого `agents.list`, который OpenClaw всё ещё
читает, когда `agents.entries` отсутствует). Запись, которой принадлежит
рабочая область по умолчанию, использует её напрямую, если у неё нет
собственного `workspace`: это запись с пометкой `default: true` (если только
`agents.ownership` не равно `"explicit"`), иначе единственная запись. Любая
другая запись без собственного `workspace` использует
`<agents.defaults.workspace>/<id>`, иначе `~/.openclaw/workspace-<id>`, где id
записан так, как OpenClaw записывает его в именах папок: в нижнем регистре, а
символы, кроме букв, цифр, `_` и `-`, заменены на `-` (так, `Bob Smith`
использует `workspace-bob-smith`).

- Рабочая область, которой ещё нет, пропускается без сообщения: как только
  OpenClaw её создаст, `apothem verify --harness open-claw` завершается
  неудачей, пока вы не запустите `apothem update --harness open-claw`.
- Следующие случаи пропускаются, каждый с одним предупреждением: рабочая
  область вне вашего домашнего каталога, рабочая область, доступная через
  ссылку (символическую ссылку или соединение Windows), путь, который является
  файлом, рабочая область, где `apothem/AGENTS.md` — папка, и рабочая область,
  чья папка `apothem` сама является другой рабочей областью (её `AGENTS.md` был
  бы собственным файлом той рабочей области). Apothem никогда не записывает и
  не удаляет через ссылку: файл правил в рабочей области, которая с тех пор
  стала ссылкой, остаётся на месте с предупреждением удалить его блок Apothem
  вручную.
- Когда рабочая область исчезает из конфигурации или файл больше не
  помещается (см. ограничения размера ниже), следующая установка или
  обновление убирает блок Apothem из файла, который был туда записан. Файл и
  его папка `apothem` удаляются, когда в них больше ничего не остаётся; текст,
  который вы добавили вне блока, остаётся.

Если в вашей конфигурации уже есть запись `bootstrap-extra-files`, Apothem
добавляет свой путь в список, который читает хук: первый непустой из `paths`,
`patterns` и `files`. Он никогда не создаёт второй список, который скрыл бы
ваш.

**Когда Apothem не трогает хук.** В этих случаях установка записывает файл
правил, но не меняет настройки хука и выводит предупреждение:

- `hooks.internal.enabled` равно `false`: вы отключили внутренние хуки.
- Запись `bootstrap-extra-files` содержит `enabled: false`.
- `hooks.internal.enabled` равно `true`, а в `hooks.internal.entries` не назван
  ни один хук (и `hooks.internal.load.extraDirs` пуст). Тогда OpenClaw
  загружает все подходящие хуки, и указание первого хука отключило бы
  остальные. Назовите хуки, которые вы используете, затем запустите
  обновление. Пакеты хуков, установленные через OpenClaw, перечислены в
  собственной базе данных состояния OpenClaw, которую Apothem не читает,
  поэтому Apothem обрабатывает этот случай так же, даже когда такой пакет
  установлен.
- `openclaw.json` содержит комментарии или другой синтаксис JSON5 (см.
  [Комментарии в `openclaw.json`](#заметки-о-совместимости)).

Когда файл правил не помещается ни в одну рабочую область в пределах обоих
ограничений размера, установка не записывает файл и не добавляет путь в запись
хука.

**Ограничения размера.** OpenClaw внедряет не более 20 000 символов на файл и
60 000 в сумме (`agents.defaults.bootstrapMaxChars` и `bootstrapTotalMaxChars`;
запись `agents.entries` может задать собственные значения, которые действуют
для её рабочей области). OpenClaw считает символы в единицах UTF-16, поэтому
эмодзи считается за два, и Apothem считает так же, включая окончания строк
(перевод строки Windows считается за два). С профилем по умолчанию файл правил
занимает несколько тысяч символов.

Файл правил загружается после шести файлов рабочей области и после остальных
файлов записи `bootstrap-extra-files`. В рабочей области, где он превысил бы
ограничение на файл или место, которое оставляет общее ограничение, OpenClaw
обрезал бы его или пропустил, и правила пришли бы повреждёнными: Apothem не
записывает его туда, объясняет причину в предупреждении и убирает копию,
оставленную более ранней установкой. Когда несколько записей используют одну
рабочую область, действует наименьшее ограничение. (Поведение OpenClaw
соответствует его документации по
[конфигурации хуков](https://docs.openclaw.ai/automation/hooks/configuration),
[встроенным хукам](https://docs.openclaw.ai/automation/hooks/bundled-hooks) и
[рабочей области и начальной загрузке](https://docs.openclaw.ai/gateway/config-agents/workspace-and-bootstrap),
прочитанной 2026-11-09.)

Файл правил, чей блок Apothem потерял маркер END, сохраняет старый текст
Apothem ниже своего маркера BEGIN, а обновление записывает блок Apothem рядом с
ним, поэтому этот старый текст учитывается в ограничении на файл. Когда файл
правил сверх ограничения содержит маркер BEGIN, который не начинает целого
блока (его маркер END пропал или маркер ваш), предупреждение называет файл и
каждый такой маркер по номеру строки. Затем оно называет каждую строку маркера,
которую меняет исправление этого файла, — те же строки, что и другие
предупреждения для этого файла, например «change line 3 by adding a word inside
its comment» («change lines 3 and 9 by adding a word inside each comment» для
двух строк, среди которых может быть маркер BEGIN, процитированный вами в блоке
кода). Когда файл заканчивается внутри блока кода, который не закрывает ни одна
строка, оно сначала предлагает добавить закрывающую строку этого блока кода,
например «add a line of 3 backticks below line 12». Там, где программа просмотра
Markdown может прочитать этот блок кода иначе, чем Apothem (строка над ним может
начинать блок HTML, или текст элемента списка продолжается у левого поля над
ним, а за ним следует строка с отступом), предупреждение не называет строк для
изменения: оно сообщает, что Apothem не может указать шаги, и называет строку,
открывающую блок кода, как и другие предупреждения для этого файла (см.
[Следование пронумерованному исправлению](/docs/install/troubleshooting#follow-a-numbered-fix)).
Оно предлагает вручную удалить старый текст ниже маркера, сохранив свой
собственный текст, либо сократить пользовательские правила профиля, либо
повысить ограничение.

### Навыки

**Конфликты имён.** OpenClaw читает навыки из следующих источников, начиная с
наивысшего приоритета, и когда одно и то же имя навыка встречается более чем в
одном месте, побеждает источник с наивысшим приоритетом: папка `skills/`
рабочей области, папка `.agents/skills/` рабочей области, `~/.agents/skills`
(только для каталога состояния по умолчанию), папка `skills/` каталога
состояния (по умолчанию `~/.openclaw/skills`), навыки workshop, встроенные
навыки и навыки custodian, а затем папки, перечисленные в
`skills.load.extraDirs`, вместе с навыками плагинов. Сеанс, работающий в
отдельной рабочей области выполнения — папке, отличной от его собственной
рабочей области, — также читает папки `skills/` и `.agents/skills/` этой папки
после всех перечисленных, поэтому навык Apothem побеждает навык с тем же
именем, хранящийся там. Каталог Apothem является записью `extraDirs`, поэтому
OpenClaw использует навык с тем же именем, который вы храните в любом из более
ранних источников, а копия этого навыка от Apothem остаётся на диске
неиспользуемой. Apothem записывает только в `openclaw.json`,
`~/.openclaw/apothem/rules/`, `~/.openclaw/.apothem/` и `apothem/AGENTS.md`
каждой рабочей области и никогда не записывает в эти более ранние папки,
поэтому установка, обновление и удаление не заменяют навык, который вы там
храните.

`agents.defaults.skills` — это список разрешённых имён навыков, а список
`agents.entries.<id>.skills` заменяет его для записи, к которой он относится.
Apothem не редактирует ни один из этих списков, поэтому если вы ведёте такой
список, проверьте, что в нём указаны нужные вам навыки Apothem.
`apothem update` сохраняет ключи, которые вы добавляете в `openclaw.json`.
Серверы MCP находятся в блоке `mcp.servers` конфигурации OpenClaw, которым вы
управляете с помощью `openclaw mcp add` и связанных подкоманд; адаптер не
записывает туда ни одной записи. (Поведение OpenClaw соответствует его
документации по [навыкам](https://docs.openclaw.ai/tools/skills),
[конфигурации навыков](https://docs.openclaw.ai/tools/skills-config),
[расширениям конфигурации](https://docs.openclaw.ai/gateway/config-extensions) и
[CLI для MCP](https://docs.openclaw.ai/cli/mcp), прочитанной 2026-11-03.)

**Комментарии в `openclaw.json`.** OpenClaw читает свою конфигурацию как JSON5,
а Apothem перезаписывает файл как обычный JSON. Если файл содержит комментарии
или другой синтаксис JSON5, Apothem никогда его не перезаписывает:

- Если записи `skills.load.extraDirs` нет, установка останавливается с
  сообщением о том, что файл содержит комментарии или синтаксис JSON5.
- Если отсутствует только запись хука, установка и обновление продолжаются,
  записывают файлы правил рабочих областей и выводят предупреждение о том, что
  нужно добавить (путь попадает в список, который уже использует ваша запись
  `bootstrap-extra-files`, если он у неё есть). Пока вы его не добавите,
  `apothem verify` завершается неудачей.
- Записи, которые Apothem сделал до того, как вы добавили комментарии,
  остаются в точности как есть, и обновление продолжается. Когда ограничения
  размера или ваши настройки хуков требуют убрать путь Apothem из записи хука,
  предупреждение просит удалить его вручную; файл правил, который больше не
  помещается, всё равно убирается.

Объедините эти записи со своим файлом самостоятельно или преобразуйте файл в
обычный JSON, затем снова запустите установку:

```json
{
  "skills": {
    "load": {
      "extraDirs": ["~/.openclaw/.apothem/support/skills"]
    }
  },
  "hooks": {
    "internal": {
      "entries": {
        "bootstrap-extra-files": {
          "enabled": true,
          "paths": ["apothem/AGENTS.md"]
        }
      }
    }
  }
}
```

Запись, которую вы добавили сами, считается вашей: удаление оставляет её на месте.

## Проверка

```bash
apothem verify --harness open-claw
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а
   конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы
   дополнительно подтвердить, что установленные файлы соответствуют этому
   профилю.
3. `skills.load.extraDirs` в нативной конфигурации содержит
   `~/.openclaw/.apothem/support/skills`. Без этой записи OpenClaw не загружает
   установленные навыки; `apothem update` добавляет её снова.
4. Запись `bootstrap-extra-files` содержит `apothem/AGENTS.md` в списке,
   который читает хук, если только ваши собственные настройки не мешают Apothem
   зарегистрировать его (см.
   [Правила в каждой рабочей области](#правила-в-каждой-рабочей-области)).
5. Каждая рабочая область, которую находит Apothem, содержит
   `apothem/AGENTS.md` со своим управляемым блоком. Рабочая область, созданная
   после установки, не проходит эту проверку, пока `apothem update` не запишет
   файл. Рабочая область, для которой установка сообщила о превышении
   ограничения размера файлом, не проходит её, пока вы не сократите
   пользовательские правила профиля или не повысите ограничение и затем не
   запустите обновление; ссылка, путь вне вашего домашнего каталога и
   отсутствующая рабочая область не проверяются. `apothem status` сообщает о
   файле правил, чей блок был отредактирован.
6. Ни один файл, в котором Apothem хранит свой блок (документ профиля и каждый
   файл правил, включая файл в рабочей области, которую установка больше не
   использует), не содержит маркера BEGIN, который не начинает целого блока,
   двух или более целых блоков между маркерами Apothem или пар маркеров,
   которые Apothem не может отличить от вашего текста. Обновление сохраняет
   такой маркер или оставляет такой файл как есть, поэтому проверка не
   проходит, пока вы не исправите файл вручную, как сказано в строке `Note:`.
   Файл правил записывается, только пока он укладывается в ограничение на
   файл, а старый текст Apothem, который вы оставляете ниже изменённой вами
   строки маркера, учитывается в этом ограничении, поэтому в примечании
   сказано, что следующее обновление запишет блок Apothem, «if the file then
   fits OpenClaw's per-file limit (bootstrapMaxChars)»; если он не
   укладывается, обновление называет файл в своём предупреждении о размере (см.
   [В файле есть маркер BEGIN Apothem без маркера END](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker),
   [Файл содержит два блока между маркерами Apothem](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers)
   и
   [Apothem не может отличить свой блок от вашего текста](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)).

## Обновление

```bash
apothem update --harness open-claw
```

Повторно выводит документ профиля и файл правил каждой рабочей области из
текущего состояния общего профиля и обновляет вспомогательные файлы;
`openclaw.json` сохраняет ключи, которые в нём уже есть, а записи Apothem в
`skills.load.extraDirs` и в записи хука остаются указанными один раз, сколько
бы раз вы ни обновляли. Каждое обновление записывает путь Apothem последним в
списке записи хука, поэтому он перемещается в конец, если вы поставили записи
после него. Текст, который вы добавляете в файл правил вне его управляемого
блока, остаётся. Файл правил в рабочей области, которую установка больше не
использует, теряет свой блок. Когда после этого в файле остаётся маркер BEGIN
без маркера END (ваша строка или то, что осталось от более старого блока,
потерявшего свой маркер END), обновление называет файл и строку маркера с
пронумерованным шагом, который меняет эту строку так, чтобы она больше не
читалась как маркер; `apothem verify` завершается неудачей, пока вы её не
измените. Любой старый текст Apothem ниже неё вам затем нужно удалить вручную.
Если такой файл содержит два разных блока между маркерами Apothem, обновление
оставляет его как есть и называет каждый блок по его строкам или блок Apothem
и окружающие его строки маркеров. Выполните одно из пронумерованных
исправлений из предупреждения, которые меняют строки маркеров BEGIN на месте:
если блок Apothem сохранён, следующая установка, обновление или удаление
убирает его, а если изменены все строки маркеров BEGIN, Apothem не находит там
своего блока. Если Apothem не может отличить свой блок в этом файле от вашего
текста (например, блок находится внутри вашего блока кода), обновление тоже
оставляет файл как есть, а его предупреждение называет каждую пару маркеров и
способ исправления; после исправления следующая установка, обновление или
удаление убирает блок Apothem (см.
[Apothem не может отличить свой блок от вашего текста](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)).
До тех пор `apothem verify` завершается неудачей и называет файл (см.
[Проверка](#проверка)).
Запускайте после редактирования `~/.config/apothem/profile.yaml` или
обновления установленного пакета Apothem.

## Удаление

```bash
apothem uninstall --harness open-claw
```

Удаляет то, что добавил адаптер: его запись в `skills.load.extraDirs`, его путь
в записи хука (и саму запись, если её создал Apothem), управляемый блок в
`apothem/AGENTS.md` каждой рабочей области (файл и папка удаляются, когда в них
больше ничего не остаётся), документ профиля и поддерево поддержки. Ваши
собственные ключи в `openclaw.json` остаются на месте, включая ваши собственные
записи `extraDirs` и настройки хуков, собственные файлы рабочей области
остаются как есть, а `openclaw.json` удаляется только тогда, когда его создал
Apothem и от вас в нём ничего не осталось.

Некоторые остатки требуют вашего участия:

- **Записи Apothem в `openclaw.json`, который содержит комментарии или другой
  синтаксис JSON5.** Удаление останавливается, ничего не изменив, и
  завершается с ошибкой, в которой названы записи для удаления.
- **Файл правил, доступный через ссылку, который всё ещё содержит блок
  Apothem.** Удаление убирает всё остальное, оставляет этот файл на месте и
  сообщает, что удаление не завершено (код выхода 2), называя ссылку. Отчёт
  также сообщает, загружает ли OpenClaw этот файл до сих пор: загружает, пока
  `openclaw.json` называет его в рабочей области, которую использует OpenClaw,
  потому что Apothem не смог изменить `openclaw.json` или потому что ему
  соответствует ваш собственный шаблон.
- **Файл правил, который Apothem не может перезаписать** (в папке, в которую
  вы не можете записывать, или файл только для чтения в Windows). Удаление
  сообщает об ошибке с именем файла, очищает файлы правил в других рабочих
  областях и останавливается, не изменив `openclaw.json` и файлы поддержки.
- **Файл правил, в котором Apothem не может отличить свой блок от вашего
  текста** (например, блок находится внутри вашего блока кода). Удаление
  убирает всё остальное, оставляет этот файл как есть и сообщает, что удаление
  не завершено (код выхода 2). Его предупреждение называет каждую пару
  маркеров и даёт пронумерованные исправления: выполните то, условие которого
  верно, прежде чем снова запустить удаление.

В каждом случае Apothem отмечает удаление как незавершённое и сохраняет свою
запись об установке, даже если позже вы добавите свой текст рядом с блоком.
Удалите названные записи, или блок Apothem (или файл), или исправьте файл,
затем снова запустите удаление, чтобы завершить его. Файл правил, чей блок
Apothem потерял строку END, тоже остаётся как есть с предупреждением, которое
его называет, но удаление всё равно завершается; удалите остаток блока
вручную. Пока установка остаётся на месте, каждая установка и каждое
обновление называют такой файл в рабочей области, которую установка больше не
использует, пока вы не удалите остаток блока. После завершения удаления
Apothem снова называет файл, только когда более поздняя установка записывает в
его рабочую область. В рабочей области, которую использует установка,
установка или обновление сохраняет текст такого файла правил, записывает блок
Apothem отдельно от него и называет файл. YAML общего профиля и движок Apothem
не затрагиваются.

## Шлюз соответствия

```bash
python3 -E -s ~/.apothem/src/apothem/conformity/gate.py --all .
```

Запускайте его из папки проекта. В Windows используйте `python` вместо
`python3` и полный путь, поскольку Windows PowerShell и cmd не раскрывают
`~`:
`$HOME\.apothem\src\apothem\conformity\gate.py` в PowerShell или
`%USERPROFILE%\.apothem\src\apothem\conformity\gate.py` в cmd. Это путь, куда
установщик помещает движок, а `-E -s` не пускает в шлюз ваш `PYTHONPATH` и
пользовательские site-packages; [Шлюз соответствия](/docs/conformity-gate)
объясняет и то и другое, а также другие способы установки.

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness open-claw` |
| Проверка не пройдена | Запустите `apothem update --harness open-claw`, затем проверьте снова. Если строка `Note:` называет файл с маркером Apothem, который нужно исправить, например файл правил, обновление этого не устраняет: исправьте этот файл вручную, как сказано в примечании, затем проверьте снова (см. [Проверка](#проверка), пункт 6) |
| Неожиданное содержимое конфигурации | Apothem задаёт в `openclaw.json` только свою запись в `skills.load.extraDirs` и свой путь в записи хука `bootstrap-extra-files` (плюс `enabled: true`, когда создаёт эту запись) и сохраняет уже имеющиеся в нём ключи, поэтому содержимое профиля туда не попадает. Содержимое профиля попадает в `~/.openclaw/apothem/rules/00-apothem-profile.md` и в `apothem/AGENTS.md` каждой рабочей области: проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите команду из раздела [Обновление](#обновление) |
| Установка останавливается с сообщением о комментариях или синтаксисе JSON5 в `openclaw.json` или предупреждает, что файл содержит синтаксис JSON5 | Apothem не перезаписывает файл, из которого ему пришлось бы удалить комментарии. Добавьте обе записи, показанные в разделе [Заметки о совместимости](#заметки-о-совместимости) (запись `skills.load.extraDirs` и запись хука `bootstrap-extra-files`), самостоятельно или преобразуйте файл в обычный JSON, затем снова запустите установку |
| OpenClaw не следует правилам Apothem | Запустите `apothem verify --harness open-claw` и проверьте предупреждения установки: рабочая область, которой не было на момент установки, отключённые внутренние хуки или открытое обнаружение хуков оставляют правила незагруженными (см. [Правила в каждой рабочей области](#правила-в-каждой-рабочей-области)). Затем запустите `apothem update --harness open-claw` |
| Навык Apothem не появляется в OpenClaw | Навык с тем же именем в рабочей области, `~/.agents/skills`, `~/.openclaw/skills` или среди навыков workshop или встроенных навыков OpenClaw имеет приоритет над копией Apothem (см. [Заметки о совместимости](#заметки-о-совместимости)). Также запустите `apothem verify --harness open-claw` и проверьте, что ведущийся вами список разрешённых навыков `agents.defaults.skills` или `agents.entries.<id>.skills` содержит имя этого навыка |
