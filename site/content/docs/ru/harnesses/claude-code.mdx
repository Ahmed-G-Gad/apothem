**Поставщик:** Anthropic
**Имя установки:** `claude-code`
**Статус:** GA
**Нативная конфигурация:** `~/.claude/`

## Установка

```bash
apothem install --harness claude-code
```

Адаптер `claude-code` устанавливает общий корпус Apothem в нативное дерево
обнаружения Claude Code. Агенты Markdown, правила, навыки, стили вывода,
помощники строки состояния и настройки устанавливаются в их нативных
расположениях; промпты команд дополнительно оборачиваются как навыки, чтобы
повторно используемые рабочие процессы оставались видимыми через текущую
поверхность навыков Claude Code.

**Записанные файлы:** `settings.json`, `agents/`, `rules/`, `skills/`,
`statuslines/`, `output-styles/` и вспомогательное поддерево `apothem/`
(`apothem/hooks/`, `apothem/conformity/`, `apothem/schemas/`,
`apothem/templates/`) в `~/.claude/`. Файлы команд преобразуются в дочерние
каталоги навыков. Диспетчер хуков и шлюз соответствия запускаются из своих
материализованных копий — записи хуков в `settings.json` вызывают
`~/.claude/.apothem/support/hooks/dispatch.py` и
`~/.claude/.apothem/support/conformity/gate.py` по абсолютному пути, поэтому на хосте не
требуется импортируемый пакет `apothem`.

Адаптер **не** управляет `CLAUDE.md` — этот файл является территорией,
принадлежащей оператору. Поверхность управления Apothem достигает Claude Code
через распространяемое дерево `rules/` и хук SessionStart, а не через
материализованный `CLAUDE.md`.

## Сопоставление профиля с нативной конфигурацией

При каждом `apothem install` или `apothem update` адаптер распространяет общий
корпус `apothem` в `~/.claude/` согласно манифесту распространения. Адаптер
напрямую использует нативные каталоги там, где это возможно, и преобразует промпты
команд в папки навыков. Существующие совпадающие дочерние элементы, управляемые
Apothem, резервируются перед заменой; несвязанные записи, созданные оператором,
сохраняются. `settings.json` объединяется, чтобы ключи, созданные оператором,
оставались восстанавливаемыми.

## Замечания о совместимости

Никакого преобразования не происходит. Установка проверяет, что профиль корректно сформирован и что все привязки хуков в settings.json разрешимы.

Claude Code применяет все привязки хуков из settings.json при каждом запуске сессии. Каждый адаптер проверяется относительно собственного нативного окружения — привилегированного «эталонного» окружения не существует.

## Проверка

```bash
apothem verify --harness claude-code
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Все обязательные поля из общего профиля присутствуют.
3. Специфичная для адаптера процедура проверки сообщает об успехе.

## Обновление

```bash
apothem update --harness claude-code
```

Заново выводит нативную конфигурацию из текущего общего профиля. Запускайте после
обновления установленного пакета `apothem`, чтобы распространяемая поверхность
соглашений (агенты, правила, навыки, строки состояния, стили вывода) отражала
новую версию. `CLAUDE.md` принадлежит оператору и никогда не затрагивается
адаптером.

## Удаление

```bash
apothem uninstall --harness claude-code
```

Удаляет файлы нативной конфигурации, записанные адаптером.
Установленный пакет `apothem` и исходный репозиторий не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Решение |
|---------|-----|
| Файл конфигурации не найден | Заново выполните `apothem install --harness claude-code` |
| Проверка не прошла | Выполните `apothem update --harness claude-code`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Заново выполните `apothem update`; источником истины является общий профиль `apothem`, а не `~/.claude/` |

## Настроечные параметры

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предварительный просмотр установки без записи файлов. |
