**Поставщик:** Anthropic
**Имя установки:** `claude-code`
**Статус:** GA
**Нативная конфигурация:** `~/.claude/`

## Установка

```bash
apothem install --harness claude-code
```

Адаптер `claude-code` устанавливает общий корпус Apothem в нативное дерево обнаружения
Claude Code. Markdown-исполнители, правила, навыки, output-стили и настройки
устанавливаются в свои нативные расположения; промпты команд преобразуются в навыки,
чтобы повторно используемые рабочие процессы оставались видимыми через текущую
поверхность навыков Claude Code. Рендерер строки состояния копируется в
`~/.claude/statuslines/`, но не подключается: Claude Code читает строку состояния из
настройки `statusLine`, которую адаптер оставляет незаданной. Чтобы включить её,
добавьте в `settings.json` запись `statusLine` с `"type": "command"`, которая запускает
`~/.claude/statuslines/render.py`. Значение `commandWindows` в фрагменте запускается в
Windows и называет интерпретатор без кавычек. Если путь к интерпретатору содержит
пробел, установка записывает в это значение его короткую форму Windows 8.3, когда она
есть на томе. Записи хуков в `settings.json` сохраняют полный путь.

**Записываемые файлы:** `settings.json`, блок Apothem в `CLAUDE.md`, `agents/`, `rules/`, `skills/`,
`statuslines/`, `output-styles/` и поддерево поддержки `.apothem/support/`
(`.apothem/support/hooks/`, `.apothem/support/conformity/`,
`.apothem/support/schemas/`, `.apothem/support/templates/`) в `~/.claude/`.
Файлы команд преобразуются в
дочерние каталоги навыков. Диспетчер хуков и шлюз соответствия запускаются из
своих материализованных копий — записи хуков в `settings.json` вызывают
`~/.claude/.apothem/support/hooks/dispatch.py` и
`~/.claude/.apothem/support/conformity/gate.py` по абсолютному пути, поэтому
импортируемый пакет `apothem` на хосте не нужен.

`~/.claude/CLAUDE.md` остаётся во владении оператора. Адаптер записывает в него
один блок Apothem, ограниченный маркерами-разделителями, который содержит
проекцию профиля (идентичность, предпочтения, правила, уровень серьёзности и
включённые по выбору варианты поведения) и раздел о вспомогательных файлах
Apothem, и дословно сохраняет каждую строку за пределами маркеров. Раздел о
вспомогательных файлах называет абсолютный каталог, относительно которого
разрешается каждая ссылка в стиле репозитория в установленных правилах,
навыках и исполнителях: `rules/<name>.md` — в `~/.claude/rules/`, а
`templates/...`, `schemas/...`, `hooks/...` и `conformity/...` — в
`~/.claude/.apothem/support/`. Остальная часть поверхности управления Apothem
достигает Claude Code через распространяемое дерево `rules/` и хук
SessionStart. OpenCode также загружает `~/.claude/CLAUDE.md`, когда
`~/.config/opencode/AGENTS.md` не существует, поэтому блок не называет своим
читателем ни один конкретный инструмент.

## Сопоставление профиля с нативной конфигурацией

При каждом запуске `apothem install` или `apothem update` адаптер
распространяет общий корпус `apothem` в `~/.claude/` согласно манифесту
распространения. Адаптер по возможности напрямую использует нативные каталоги
и преобразует промпты команд в папки навыков. Для существующих совпадающих
дочерних элементов, управляемых Apothem, создаются резервные копии перед
заменой; не связанные с ними записи, созданные оператором, сохраняются.
`settings.json` объединяется, чтобы ключи, созданные оператором, оставались
восстанавливаемыми.

Файлы, созданные оператором, сохраняются только вне папок ниже. Каждая установка и каждое обновление удаляют каждую из этих папок под `~/.claude/`, если она существует, независимо от того, создал ли её Apothem: `src/`, `conformity/`, `schemas/`, `hooks/`, `config/`, `scripts/`, `tools/`, `lib/`, `templates/`, `docs/`, `tests/`, `packaging/`, `mcp/`, `examples/`, `assets/`, `site/`, `public/` и `commands/`. Также удаляются `statuslines/__init__.py` и файлы `AGENTS.md` в `agents/`, `rules/`, `skills/`, `statuslines/` и `output-styles/`. Удалённая папка уходит целиком, включая файлы, которые вы в ней разместили. Слеш-команды, которые вы храните в `commands/`, тоже удаляются, а собственные командные подсказки Apothem устанавливаются как навыки в `skills/`. Скрипт хука, который вы храните в `hooks/`, удаляется, поэтому любая запись в `settings.json`, которая его вызывает, остаётся указывающей в никуда. Очистка выполняется до того, как установка запишет собственные файлы. Каждый удаляемый путь сначала копируется в `~/.apothem/backups/`, а запись об установке называет эту копию. Команда Uninstall её не восстанавливает. Чтобы восстановить удалённый путь, выполните `apothem rollback --harness claude-code --install-id ID` для установки, которая его удалила, как описано в [справочнике по rollback](/docs/cli-reference/rollback). Простой `apothem rollback` отменяет только последнюю установку. Записи об установке и их копии хранятся для 10 самых новых установок, поэтому удалённый путь можно восстановить, только пока его установка входит в их число. `apothem diff --harness claude-code` перечисляет эти удаления как `Prune stale files` до того, как вы выполните установку.

Установленные навыки, а также навыки, входящие в плагин Claude Code, содержат
`user-invocable` вместо `userInvocable` исходного корпуса, потому что Claude
Code читает только ключ с дефисом. Два контейнера шаблонов
(`plan-suite`, `research-suite`) задают ему значение `false`, поэтому они не
попадают в меню `/`. Каждый output-стиль задаёт
`keep-coding-instructions: true`, поэтому при выборе любого из них встроенные
инструкции Claude Code по программной инженерии сохраняются.

## Заметки о совместимости

Промпты команд преобразуются в каталоги навыков; исполнители, правила, навыки
и output-стили копируются как есть. Установка проверяет, что профиль корректно
сформирован и что все привязки хуков в settings.json разрешимы. Адаптер не
создаёт записей серверов MCP: регистрируйте серверы командой `claude mcp add`
(см. [Серверы MCP](/docs/reference/mcp)).

Claude Code применяет все привязки хуков из settings.json при каждом запуске сессии. Каждый адаптер проверяется относительно собственного нативного окружения — привилегированного «эталонного» окружения не существует.

### Ограничения правил разрешений

Шаблон настроек запрещает `Read(...)` для путей к секретам и кешам, таких как
`.env*` и `~/.ssh/**`. Claude Code применяет запрет `Read` к своим файловым
инструментам, к файловым командам, которые он распознаёт в Bash (`cat`, `head`,
`tail`, `sed`, `tee`), и к целям перенаправления. Он не применяет этот запрет к
поиску, который читает файлы, не называя их, например `grep -r pattern .`, или
к скрипту, который сам открывает файлы
([справочник по разрешениям](https://code.claude.com/docs/en/permissions)). В
macOS, Linux и WSL Claude Code не включает инструменты `Glob` и `Grep` в набор
инструментов по умолчанию и вместо них выполняет поиск через Bash, поэтому
разрешающие записи `Glob` и `Grep` из шаблона действуют только там, где эти
инструменты присутствуют. Чтобы запретить любому процессу читать путь,
включите песочницу Claude Code.

Навыки и определения помощников, в которых упоминается `TodoWrite`, также
упоминают `TaskCreate`, `TaskGet`, `TaskList` и `TaskUpdate`, потому что Claude
Code по умолчанию отключает `TodoWrite` в пользу этих инструментов.

## Проверка

```bash
apothem verify --harness claude-code
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а
   конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы
   дополнительно подтвердить, что установленные файлы соответствуют этому
   профилю.
3. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness claude-code
```

Повторно выводит нативную конфигурацию из текущего общего профиля. Запускайте
после обновления установленного пакета `apothem`, чтобы распространяемая
поверхность соглашений (исполнители, правила, навыки, строки состояния,
output-стили) отражала новую версию. В `CLAUDE.md` обновление перезаписывает
только блок Apothem между его маркерами.

## Удаление

```bash
apothem uninstall --harness claude-code
```

Удаляет блок Apothem из `~/.claude/CLAUDE.md` и сохраняет в нём любой другой
текст. Файл удаляется, только когда в нём больше ничего не остаётся. Удаляет
записи, добавленные адаптером в `~/.claude/settings.json` (ваши собственные
правила разрешений, ключи и обработчики хуков остаются, а файл удаляется, только
если его создал Apothem и ничего вашего в нём не осталось). Также удаляет файлы
Apothem в `~/.claude/agents/`, `~/.claude/rules/`, `~/.claude/skills/`,
`~/.claude/statuslines/`, `~/.claude/output-styles/` и
`~/.claude/.apothem/support/`; остальные файлы в этих каталогах остаются.
Резервная копия каждого файла создаётся в `~/.apothem/backups/` до того, как он
будет изменён или удалён.
Установленный пакет `apothem` и исходный репозиторий не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness claude-code` |
| Проверка не пройдена | Запустите `apothem update --harness claude-code`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Повторно запустите `apothem update`; источником истины является общий профиль `apothem`, а не `~/.claude/` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
