**Поставщик:** Alibaba Cloud
**Имя установки:** `qwen-code`
**Статус:** Бета
**Нативная конфигурация:** `~/.qwen/`

## Установка

```bash
apothem install --harness qwen-code
```

Адаптер записывает настройки Qwen Code, устанавливает якорь контекста `QWEN.md`,
регистрирует диспетчеры хуков Apothem, преобразует команды Apothem в файлы команд
Qwen в формате Markdown, устанавливает навыки как каталоги SKILL.md и адаптирует
определения помощников как субагенты Qwen.

**Записываемые файлы:**

```text
~/.qwen/settings.json
~/.qwen/QWEN.md
~/.qwen/apothem/rules/00-apothem-profile.md
~/.qwen/commands/
~/.qwen/skills/
~/.qwen/agents/
~/.qwen/.apothem/support/{rules,templates,hooks}/
```

Файл `~/.qwen/apothem/rules/00-apothem-profile.md` — это документ профиля.
Он содержит вашу идентичность и предпочтения из общего профиля.

## Сопоставление профиля с нативной конфигурацией

Адаптер рендерит документированные ключи `settings.json` для контекста и хуков,
записывает `QWEN.md` и встраивает команды, навыки и определения помощников
Apothem в нативные каталоги обнаружения Qwen Code. Правила, шаблоны и исходный
материал хуков остаются вспомогательным материалом в `~/.qwen/.apothem/support/`.

## Заметки о совместимости

`~/.qwen/.apothem/support/` — это вспомогательный материал, на который ссылаются
`QWEN.md` и команды хуков в настройках; это не пространство имён обнаружения,
принадлежащее поставщику.
Блок Apothem в `QWEN.md` завершается разделом о вспомогательных файлах Apothem,
который называет абсолютный каталог в `~/.qwen/.apothem/support/`, относительно
которого разрешается каждая ссылка в стиле репозитория (`rules/<name>.md`,
`templates/...`, `hooks/...`).

**Списки инструментов навыков.** `Qwen Code` читает список разрешённых
инструментов навыка из ключа фронтматтера `allowedTools` в camelCase, и значение
должно быть списком YAML. Ключ с дефисом `allowed-tools`, записанный для других
агентов, он игнорирует. Поэтому установленные навыки содержат `allowedTools` в
виде списка, по одной записи на строку, вместо строки `allowed-tools` через
запятую из исходного корпуса. Каждая запись сохраняет написание источника,
включая шаблоны вроде `Bash(git status *)`. Все остальные ключи навыка и тело
навыка устанавливаются без изменений.

**Папки навыков.** Адаптер записывает навыки в `~/.qwen/skills/`. `Qwen Code`
также читает `~/.agents/skills/`, а внутри проекта — `.qwen/skills/` и
`.agents/skills/`. Когда в двух папках есть навык с одним и тем же именем,
побеждает тот, что находится в `.qwen`, поэтому навык Apothem в
`~/.qwen/skills/` имеет приоритет над одноимённым навыком, который другой
адаптер записал в `~/.agents/skills/`.

**События хуков.** Адаптер подключает `SessionStart`, `PreToolUse`, `PreCompact`,
`PostCompact` и `Stop`. `Qwen Code` определяет 22 события хуков, и каждое из
этих пяти входит в их число. У трёх из 22 (`SessionDelete`, `TodoCreated` и
`TodoCompleted`) нет одноимённого события `Claude Code` (`Claude Code` называет
события задач `TaskCreated` и `TaskCompleted`); адаптер не подключает ни одно
из них.

## Проверка

```bash
apothem verify --harness qwen-code
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а
   конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы
   дополнительно подтвердить, что установленные файлы соответствуют этому
   профилю.
3. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness qwen-code
```

Обновляет `settings.json`, `QWEN.md`, нативные команды, навыки, субагенты и
поддерево поддержки Apothem.

## Удаление

```bash
apothem uninstall --harness qwen-code
```

Удаляет записи, которые адаптер добавил в `~/.qwen/settings.json` (ваши
собственные ключи, серверы MCP и обработчики хуков остаются на месте, а сам файл
удаляется только тогда, когда его создал Apothem и от вас в нём ничего не
осталось). Удаляет блок Apothem из `~/.qwen/QWEN.md` и из документа профиля
`~/.qwen/apothem/rules/00-apothem-profile.md` и сохраняет любой другой текст в
них; каждый файл удаляется только тогда, когда в нём не остаётся ничего другого.
Также удаляет файлы Apothem в `~/.qwen/commands/`, `~/.qwen/skills/`,
`~/.qwen/agents/` и `~/.qwen/.apothem/support/`; остальные файлы в этих папках
остаются. Перед изменением или удалением каждого файла создаётся его резервная
копия в `~/.apothem/backups/`. YAML общего профиля и движок Apothem не
затрагиваются.

python -m apothem.conformity.gate --all .

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness qwen-code` |
| Проверка не пройдена | Запустите `apothem update --harness qwen-code`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness qwen-code` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
