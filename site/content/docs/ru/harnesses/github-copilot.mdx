**Поставщик:** GitHub / Microsoft
**Имя установки:** `github-copilot`
**Статус:** GA
**Нативная конфигурация:** `<project>/.github/copilot-instructions.md`

## Установка

```bash
apothem install --harness github-copilot --project /path/to/project
```

Адаптер выводит файл инструкций проекта из общей поверхности правил и
управления Apothem.

**Записываемые файлы:** `<project>/.github/copilot-instructions.md`

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общий профиль Apothem и рендерит файл инструкций Copilot для
всего репозитория при каждом запуске `apothem install` или `apothem update`.
Общий профиль является источником истины; для локальных правок
сгенерированного файла в проекте создаётся резервная копия, прежде чем
следующая синхронизация заменит содержимое, управляемое Apothem.

Внутри блока Apothem раздел, отрендеренный из вашего профиля (оператор,
предпочтения, пользовательские правила, включённые по выбору варианты
поведения, имена серверов MCP), идёт первым, перед общим текстом управления.
GitHub отмечает, что более короткие файлы инструкций с большей вероятностью
обрабатываются ревью кода целиком
([Настройка ревью кода](https://docs.github.com/en/copilot/tutorials/customize-code-review)),
поэтому часть, относящаяся именно к вам, открывает файл.

## Заметки о совместимости

GitHub Copilot не предоставляет файлового пути для глобальных
пользовательских инструкций, которым мог бы управлять этот адаптер. Apothem
нацеливается на документированный файл инструкций в области проекта и
оставляет пользовательские настройки уровня IDE во владении оператора.

Apothem рассматривает `copilot-instructions.md` как один из голосов среди
поверхностей инструкций для ассистентов в проекте: проверка
многоповерхностной согласованности шлюза соответствия подтверждает, что его
общие утверждения остаются семантически согласованными с другими файлами
инструкций проекта, поэтому Copilot никогда не получает указаний,
противоречащих тому, что читает остальная часть набора инструментов.

## Проверка

```bash
apothem verify --harness github-copilot --project /path/to/project
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы дополнительно подтвердить, что установленные файлы соответствуют этому профилю.
3. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness github-copilot --project /path/to/project
```

Повторно выводит файл инструкций проекта из текущего состояния общего профиля.

## Удаление

```bash
apothem uninstall --harness github-copilot --project /path/to/project
```

Удаляет файлы нативной конфигурации, записанные адаптером.
YAML общего профиля и движок Apothem не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness github-copilot --project /path/to/project` |
| Проверка не пройдена | Запустите `apothem update --harness github-copilot --project /path/to/project`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness github-copilot --project /path/to/project` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
