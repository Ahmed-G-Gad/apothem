**Поставщик:** OpenAI
**Имя установки:** `codex`
**Статус:** Бета
**Нативная конфигурация:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml` и `~/.agents/skills/`

## Установка

```bash
apothem install --harness codex
```

Адаптер устанавливает нативные для Codex инструкции и хуки, преобразует
исполнителей Apothem в TOML-исполнителей Codex и оборачивает повторно
используемые промпты команд в навыки Codex.

**Записываемые файлы:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml`,
`~/.agents/skills/*/SKILL.md`, `~/.agents/skills/*/agents/openai.yaml` для
навыков, вызываемых пользователем, и вспомогательные файлы в
`~/.config/apothem/{rules,templates}/`.

Блок Apothem в `AGENTS.md` завершается разделом о вспомогательных файлах
Apothem, который называет абсолютный каталог, относительно которого
разрешается каждая ссылка в стиле репозитория в установленных навыках и
правилах: `rules/<name>.md` и `templates/...` — в `~/.config/apothem/`, а
`hooks/...` — в `~/.codex/hooks/`. Установка для Codex не поставляет дерево
`schemas/` или `conformity/`, поэтому раздел не перечисляет ни то, ни другое.

**Навыки, вызываемые пользователем.** Codex игнорирует ключ
`disable-model-invocation`. Для каждого навыка или команды, в исходнике которых
задано `disable-model-invocation: true`, адаптер записывает рядом с их
`SKILL.md` файл `agents/openai.yaml` с
`policy.allow_implicit_invocation: false`, поэтому Codex не выбирает такой навык
самостоятельно; вы по-прежнему можете запустить его явно с помощью
`$skill-name`. См.
[документацию Codex по навыкам](https://developers.openai.com/codex/skills).

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общие группы Apothem и устанавливает каждую в соответствующую
поверхность Codex: инструкции — в `AGENTS.md`, хуки — в `hooks.json` и
`hooks/`, исполнителей — в TOML, навыки — в `~/.agents/skills/`, а ненативные
правила и шаблоны в формате Markdown — в `~/.config/apothem/` как
вспомогательный материал.

Каждый преобразованный помощник задаёт `name`, `description` и
`developer_instructions`. Помощник, чей набор разрешённых инструментов после
применения списка запретов не включает ни одного инструмента редактирования
файлов (`Write`, `Edit`, `MultiEdit` или `NotebookEdit`), также задаёт
`sandbox_mode = "read-only"` — собственное ограничение записи Codex. `Bash` не
считается инструментом редактирования файлов, поэтому помощник, которому выдан
`Bash`, но ни один из этих инструментов, по-прежнему остаётся в режиме только
чтения. Ни модель, ни уровень усилий рассуждения не задаются, поэтому каждый
помощник наследует выбор сессии. В Codex нет списка инструментов или лимита
ходов для отдельного помощника, поэтому `tools` и `maxTurns` помощника не
переносятся.

## Заметки о совместимости

`~/.agents/skills/` — это общий корневой каталог, которым владеет Codex: его
загружают также восемь других поддерживаемых инструментов (их перечисляет
[реестр окружений](/docs/reference/harness-registry)), поэтому навыки Apothem,
которые туда записывает установка для Codex, появляются и в этих инструментах,
а удаление для Codex убирает их и из этих инструментов. Установка выводит
примечание, в котором названы эти инструменты.

Codex резервирует `~/.codex/rules/` для политик выполнения `.rules`. Apothem не
размещает там поведенческие правила в формате Markdown; он хранит их в
`~/.config/apothem/` и ссылается на них из `AGENTS.md` и установленных навыков.

## Проверка

```bash
apothem verify --harness codex
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а
   конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы
   дополнительно подтвердить, что установленные файлы соответствуют этому
   профилю.
3. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness codex
```

Обновляет загрузочную конфигурацию Codex, преобразованных исполнителей,
навыки и вспомогательные группы.

## Удаление

```bash
apothem uninstall --harness codex
```

Удаляет файлы нативной конфигурации, записанные адаптером.
YAML общего профиля и движок Apothem не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness codex` |
| Проверка не пройдена | Запустите `apothem update --harness codex`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness codex` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
