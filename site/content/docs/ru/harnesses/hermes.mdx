**Поставщик:** Hermes
**Имя установки:** `hermes`
**Статус:** Предварительная версия
**Нативная конфигурация:** `~/.hermes/config.yaml`

## Установка

```bash
apothem install --harness hermes
```

Адаптер преобразует общий профиль в глобальный пользовательский файл
конфигурации Hermes Agent и устанавливает вспомогательные группы Apothem в
корневой каталог окружения.

**Записываемые файлы:** `~/.hermes/config.yaml`, документ профиля
`~/.hermes/apothem/rules/00-apothem-profile.md` и вспомогательные файлы в
`~/.hermes/.apothem/support/`

Документ профиля завершается разделом о вспомогательных файлах Apothem,
который называет абсолютный каталог в `~/.hermes/.apothem/support/`,
относительно которого разрешается каждая ссылка в стиле репозитория
(`rules/<name>.md`, `templates/...`, `hooks/...`).

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общий профиль Apothem и рендерит нативную конфигурацию YAML, включая
перечень MCP из профиля. Серверы MCP берутся из раздела `mcp_servers` профиля. При
каждой установке и обновлении они рендерятся в `config.yaml`, а не копируются как файлы.
Адаптер также добавляет `~/.hermes/.apothem/support/skills` в `skills.external_dirs` —
список дополнительных каталогов навыков, которые читает Hermes; именно так Hermes находит
установленные навыки. Запись добавляется после всех записей, которые вы уже указали, а
ваши остальные ключи остаются как есть. Идентичность, предпочтения и правила профиля попадают в документ профиля. Общие команды,
навыки, определения помощников, правила, шаблоны и промпты хуков размещаются как
вспомогательный материал в `~/.hermes/.apothem/support/`.

## Заметки о совместимости

Адаптер в предварительной версии. Hermes загружает навыки Apothem через
`skills.external_dirs`, но самостоятельно не загружает остальную часть
вспомогательного дерева и документ профиля: ничто другое в `config.yaml` и ни
один из файлов контекста, которые читает Hermes, не указывает туда, поэтому
после установки Hermes работает без правил и хуков Apothem.

**Конфликты имён.** Hermes документирует следующий порядок приоритета для
навыков: навыки проекта (`<project>/.hermes/skills/` и
`<project>/.agents/skills/`), затем `~/.hermes/skills/`, затем
`skills.create_dir`, затем папки, перечисленные в `skills.external_dirs`.
Каталог Apothem является записью `external_dirs`, поэтому идёт последним.
Изученная документация Hermes не сообщает, какую копию загружает Hermes, когда
в двух расположениях есть навык с одинаковым именем; Apothem понимает этот
порядок так, что побеждают более ранние расположения, поэтому ожидайте, что
навык с тем же именем, который вы храните в более раннем расположении, будет
иметь приоритет над копией Apothem. Apothem записывает только в `config.yaml` и
в `~/.hermes/.apothem/support/` и никогда не записывает в эти более ранние
расположения, поэтому установка, обновление и удаление не заменяют навык,
который вы там храните.

`apothem update` сохраняет ключи, которые вы добавляете в `config.yaml`, включая
`skills.config` и ваши собственные записи `skills.external_dirs`.
Адаптер записывает перечень MCP из профиля под ключом верхнего уровня
`mcp_servers`, откуда Hermes читает серверы MCP. Более ранние релизы Apothem
записывали его под `auxiliary.mcp`, который Hermes читает как вспомогательную
модель для диспетчеризации инструментов MCP; и `apothem update`, и
`apothem uninstall` удаляют этот блок, когда он по-прежнему совпадает с тем, что
такой релиз записал бы из вашего текущего общего профиля (о случаях, когда он
остаётся, см. [Удаление](#удаление)). (Поведение Hermes описано по страницам его
руководства пользователя о
[навыках](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills),
прочитанной 2026-10-24, и о
[MCP](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/mcp.md),
прочитанной 2026-10-02.)

**Комментарии в `config.yaml`.** Apothem перезаписывает файл с помощью
библиотеки YAML, которая отбрасывает комментарии. Если файл содержит ваши
комментарии, а записи нет, Apothem оставляет файл нетронутым, и установка
останавливается с сообщением, в котором назван ключ. Добавьте запись
самостоятельно, затем снова запустите установку:

```yaml
skills:
  external_dirs:
    - ~/.hermes/.apothem/support/skills
```

Запись, которую вы добавили сами, считается вашей: если вы уже указали этот
каталог, Apothem сохраняет вашу запись как есть, а удаление оставляет её на
месте.

## Проверка

```bash
apothem verify --harness hermes
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а
   конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы
   дополнительно подтвердить, что установленные файлы соответствуют этому
   профилю.
3. `skills.external_dirs` в нативной конфигурации содержит
   `~/.hermes/.apothem/support/skills`. Без этой записи Hermes не загружает
   установленные навыки; `apothem update` добавляет её снова.
4. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness hermes
```

Повторно выводит нативную конфигурацию из текущего состояния общего профиля;
запись Apothem в `skills.external_dirs` остаётся указанной один раз, сколько бы
раз вы ни обновляли.
Запускайте после редактирования `~/.config/apothem/profile.yaml` или
обновления установленного пакета Apothem.

## Удаление

```bash
apothem uninstall --harness hermes
```

Удаляет то, что добавил адаптер: записи `mcp_servers` и запись
`skills.external_dirs`, которые его установка зафиксировала в `config.yaml`
(ваши собственные ключи остаются, включая ваши собственные записи
`external_dirs` и `skills.config`, а сам файл
удаляется, только если его создал Apothem и в нём не осталось ничего вашего),
документ профиля и вспомогательное дерево. YAML общего профиля и движок
Apothem не затрагиваются.

Для установки, выполненной более ранним релизом, который записывал серверы
профиля под `auxiliary.mcp`, этот блок также удаляется, если он по-прежнему
совпадает с тем, что этот релиз записал бы из вашего текущего общего профиля в
`~/.config/apothem/profile.yaml`. Это то же правило, которое применяет
`apothem update`, поэтому удаление без предварительного обновления не оставляет
устаревшего блока, пока серверы MCP профиля не изменились. Блок, который вы
отредактировали, блок, который больше не совпадает с серверами MCP вашего
текущего профиля, или блок, для сравнения с которым нет читаемого общего
профиля, остаётся на месте, а остальные ваши настройки `auxiliary` сохраняются
всегда.

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness hermes` |
| Проверка не пройдена | Запустите `apothem update --harness hermes`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness hermes` |
| Установка останавливается с сообщением о комментариях в `config.yaml` | Apothem не перезаписывает файл, из которого ему пришлось бы удалить комментарии. Добавьте запись `skills.external_dirs`, показанную в разделе [Заметки о совместимости](#заметки-о-совместимости), самостоятельно, затем снова запустите установку |
| Навык Apothem не появляется в Hermes | Навык с тем же именем в проекте или в `~/.hermes/skills/` может иметь приоритет над копией Apothem: Hermes документирует порядок поиска, но не правило разрешения конфликтов (см. [Заметки о совместимости](#заметки-о-совместимости)). Также запустите `apothem verify --harness hermes` |
