**Поставщик:** ByteDance
**Имя установки:** `trae`
**Статус:** GA
**Нативная конфигурация:** `<project>/.trae/rules/apothem-rules.md`

## Установка

```bash
apothem install --harness trae --project /path/to/project
```

Адаптер записывает один файл правил Trae с областью действия проекта на основе
общих правил Apothem и поверхности управления, а также помощников Apothem как
субагентов Trae в проекте (см. [Субагенты](#субагенты)).

Кроме того, он записывает навыки Apothem, а также правила и шаблоны, на которые
они ссылаются, в ваш домашний каталог пользователя, прежде чем затронуть проект
(см. [Файлы за пределами проекта](#файлы-за-пределами-проекта)).

**Записываемые файлы:**

- `<project>/.trae/rules/apothem-rules.md` — файл правил.
- `<project>/.trae/agents/<name>.md` для каждого помощника Apothem, в проекте.
- `~/.trae/skills/<name>/SKILL.md` для каждого навыка и каждой команды Apothem, в вашем домашнем каталоге пользователя.
- `~/.config/apothem/rules/` и `~/.config/apothem/templates/`, в вашем домашнем каталоге пользователя.

## Файлы за пределами проекта

Установка также записывает навыки Apothem в ваш домашний каталог пользователя,
прежде чем что-либо изменить в проекте:

| Папка | Что Apothem туда записывает |
| --- | --- |
| `~/.trae/skills/` | По одной папке с `SKILL.md` для каждого навыка Apothem и по одной для каждой команды Apothem (команда становится навыком с тем же именем). |
| `~/.config/apothem/rules/`, `~/.config/apothem/templates/` | Правила и шаблоны, на которые ссылаются навыки и файл правил. |

Эти папки являются общими. Они не принадлежат исключительно проекту:

- Каждый проект, в который вы устанавливаете `trae`, использует одну и ту же копию `~/.trae/skills/`, и установка каждый раз записывает в неё одни и те же файлы. Trae — единственный инструмент, который читает эту папку. Правила и шаблоны в `~/.config/apothem/` записываются также установками для других инструментов, с теми же файлами.
- `--project` выбирает, какой файл правил записать и к какому проекту
  относится установка. Он не меняет место, куда попадают навыки.
- Установка не добавляет в ваш репозиторий ни одного файла навыка или правила.
  Проект получает файл правил и файлы субагентов в `.trae/agents/`, а также
  папку данных `.apothem/`, которую создаёт каждая установка в проект.
- Папки в домашнем каталоге записываются первыми. Если это не удаётся,
  например потому что папка на пути является ссылкой, ведущей за пределы
  вашего домашнего каталога (ссылка, остающаяся внутри него, разрешается), или
  в неё нельзя записать, установка останавливается с ошибкой до того, как в
  проекте что-либо изменится.
- Папка навыка с именем навыка Apothem, которую Apothem не записывал,
  остаётся нетронутой, а установка выводит предупреждение с её именем.
  Переименуйте или переместите её, затем запустите `apothem update`.
  `apothem verify` завершается неудачей, пока это имя занято.
- В сумме файлы занимают несколько мегабайт.

Установка выводит примечание с названиями папок, которые она записывает за
пределами `--project`, а `--dry-run` их перечисляет.

## Субагенты

Trae читает субагента из файла Markdown в `<project>/.trae/agents/` согласно
[документации Trae по субагентам](https://docs.trae.ai/ide/subagents). Установка
записывает в эту папку по одному файлу на каждого помощника Apothem. Она
выполняет установку только для проекта: документация указывает папку уровня
пользователя как `~/.trae-cn/agents/`, тогда как все остальные пользовательские
папки Trae находятся в `~/.trae/`, а Apothem не подтвердил, какую из них читает
международная версия, поэтому не записывает ни в одну.

Каждый файл сохраняет инструкции помощника без изменений и содержит следующие
ключи фронтматтера:

| Ключ | Что записывает Apothem |
| --- | --- |
| `name`, `description` | Имя и описание помощника. Trae требует оба. |
| `tools` | Разрешённые помощнику инструменты в виде одной строки через запятую. |
| `disallowedTools` | Инструменты, запрещённые помощнику, в виде одной строки через запятую. Trae применяет его поверх `tools`. Опускается, если у помощника таких нет. |

Записываются только названия инструментов со страницы Trae о субагентах:

```text
Bash, Edit, Glob, Grep, Read, Skill, TodoWrite, WebFetch, WebSearch, Write, LSP
```

Инструмент, который указан в источнике, но отсутствует в этом списке (например
`MultiEdit` или `PowerShell`), не попадает ни в одно из полей. Инструмент с
шаблоном, такой как `Bash(rm *)`, невозможно выразить в списке через запятую: как
разрешённый инструмент он опускается, а как запрещённый — запрещает инструмент
целиком. Помощник, который не может редактировать файлы, сохраняет это
ограничение: он не перечисляет `Write` или `Edit` среди своих инструментов и
запрещает оба. Trae не документирует ограничение числа ходов, поэтому
`maxTurns` помощника не записывается. Установка не записывает ключ `model`,
поэтому помощник использует модель, выбранную в поле чата, а также не
записывает ключ `mcpServers`.

Что нужно знать:

- Англоязычная документация Trae предписывает включить **Settings > Beta > Subagents >
  Enable Subagents Directory**, прежде чем он загрузит `.trae/agents/`. Его
  китайская страница, обновлённая позже, сообщает, что функция обычно включена
  по умолчанию. Если Trae не показывает ни одного помощника, проверьте этот
  переключатель.
- Файлы субагентов — обычные файлы проекта. Зафиксируйте их вместе с проектом
  или укажите `.trae/agents/` в `.gitignore`; Apothem не делает этот выбор за вас.
- Ваш файл с именем помощника Apothem сохраняется в `~/.apothem/backups/`, а
  затем заменяется. Удаление не возвращает его на место. Файлы с другими
  именами никогда не затрагиваются.
- Документация Trae не сообщает, как он обрабатывает ключ фронтматтера, который
  в ней не указан, и действует ли `.trae/agents/` во втором окне объединённого
  «all-new TRAE» так же, как в окне IDE.

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общий профиль Apothem и рендерит файл правил проекта при каждом
запуске `apothem install` или `apothem update`. Общий профиль является
источником истины; для локальных правок сгенерированного файла в проекте
создаётся резервная копия, прежде чем следующая синхронизация заменит
содержимое, управляемое Apothem.

Файл начинается с фронтматтера YAML, который задаёт `alwaysApply: true` и
`description`, — это режим Always Apply в Trae согласно
[документации Trae по правилам](https://docs.trae.ai/ide/rules). За ним следует
управляемый Apothem блок; текст, который вы добавляете после блока, сохраняется
при каждой синхронизации.

## Заметки о совместимости

Текущая поверхность правил Trae имеет область действия проекта и находится в
`.trae/rules/`; глобальные правила размещаются в `~/.trae/user_rules`. Адаптер
записывает выделенный файл `apothem-rules.md` и никогда не перезаписывает
другие файлы правил в этом каталоге или ваши глобальные правила.
Поверхность серверов инструментов `.trae/mcp.json` и поверхность навыков
проекта `.trae/skills/` принадлежат оператору; Apothem их не записывает.

Trae документирует `~/.trae/skills/` для глобальных навыков. Общую для
инструментов папку `.agents/skills/` он читает только после включения настройки
`Enable .agents Skills
Directory`, поэтому установка записывает папку Trae. Китайская редакция
(TRAE CN) вместо этого документирует `~/.trae-cn/skills/`; в её журнале
изменений сказано, что глобальные каталоги навыков TRAE CN и международной
редакции совместимы, только для персональной редакции. Установка записывает
только `~/.trae/skills/`, и Apothem не подтвердил, читают ли её другие редакции
TRAE CN. Apothem также не подтвердил, как Trae обрабатывает ключ заголовка
`SKILL.md`, который в документации не указан.

## Проверка

```bash
apothem verify --harness trae --project /path/to/project
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует, включая папку `.trae/agents/`;
   управляемые файлы не пусты, а конфигурации JSON или YAML разбираются.
   Добавьте `--profile PATH`, чтобы дополнительно подтвердить, что
   установленные файлы соответствуют этому профилю. Для `.trae/agents/`
   проверяется, что папка существует, а не что в ней есть файл каждого
   помощника; команда
   `apothem diff --harness trae --project /path/to/project` перечисляет файлы
   помощников, которые отсутствуют или устарели.
3. Каждая папка навыка Apothem на месте и содержит `SKILL.md`, какая бы
   установка её ни записала, и ни одна папка навыка с именем Apothem не
   принадлежит тому, что Apothem не записывал. Неудачная проверка называет
   отсутствующие или чужие папки.
4. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness trae --project /path/to/project
```

Повторно выводит файл правил проекта из текущего состояния общего профиля.

Обновление также перезаписывает каждую папку навыка, файлы которой отличаются от текущих.
Если вы устанавливали более ранним выпуском, который не записывал навыки, обновление их добавляет.
Оно перезаписывает файлы субагентов, которые отличаются от текущих, и добавляет отсутствующие.

## Удаление

```bash
apothem uninstall --harness trae --project /path/to/project
```

Удаляет блок Apothem и фронтматтер, который Apothem записал над ним, из
`<project>/.trae/rules/apothem-rules.md` и сохраняет любой другой текст в нём.
Файл удаляется только тогда, когда в нём не остаётся ничего другого. Перед
изменением копия файла с временной меткой сохраняется в `~/.apothem/backups/`; в
проекте резервный файл не остаётся. YAML общего профиля и движок Apothem не
затрагиваются.

Удаление также удаляет файлы субагентов, которые оно записало в `<project>/.trae/agents/`,
и сохраняет любой другой файл там; папка удаляется, если остаётся пустой.
Оно удаляет папки навыков, которые записало в `~/.trae/skills/`, а также
правила и шаблоны в `~/.config/apothem/`, но только когда никакая другая
установка Apothem их больше не использует. Их может использовать другой проект
или другой инструмент, разделяющий эту папку. В таком случае удаление сохраняет
папки, выводит, какая установка их использует, и их удаляет последнее удаление.
Файлы, которые вы добавили в эти папки, остаются, а папка, оставшаяся пустой,
удаляется. Перед удалением каждая папка сохраняется в резервную копию в
`~/.apothem/backups/`.

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness trae --project /path/to/project` |
| Проверка не пройдена | Запустите `apothem update --harness trae --project /path/to/project`, затем проверьте снова |
| Trae не показывает ни одного помощника Apothem | Включите Settings > Beta > Subagents > Enable Subagents Directory, затем начните новый чат |
| `apothem verify` называет отсутствующую папку навыка | Запустите `apothem install --harness trae --project /path/to/project`; это восстановит папку |
| Установка или обновление предупреждает, что пропустило папку навыка | Папка с именем навыка Apothem уже существует в папке навыков, и Apothem её не записывал. Переименуйте или переместите её, затем запустите `apothem update` |
| Установка останавливается, не изменив проект | Запись в вашем домашнем каталоге не удалась. Прочитайте ошибку, исправьте названную в ней папку (ссылку, ведущую за пределы вашего домашнего каталога, файл на месте папки или папку только для чтения) и установите снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness trae --project /path/to/project` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
