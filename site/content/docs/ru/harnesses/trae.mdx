**Поставщик:** ByteDance
**Имя установки:** `trae`
**Статус:** GA
**Нативная конфигурация:** `<project>/.trae/rules/apothem-rules.md`

## Установка

```bash
apothem install --harness trae --project /path/to/project
```

Адаптер записывает один файл правил Trae с областью действия проекта на основе
общих правил Apothem и поверхности управления.

**Записываемые файлы:** `<project>/.trae/rules/apothem-rules.md`

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общий профиль Apothem и рендерит файл правил проекта при каждом
запуске `apothem install` или `apothem update`. Общий профиль является
источником истины; для локальных правок сгенерированного файла в проекте
создаётся резервная копия, прежде чем следующая синхронизация заменит
содержимое, управляемое Apothem.

Файл начинается с фронтматтера YAML, который задаёт `alwaysApply: true` и
`description`, — это режим Always Apply в Trae согласно
[документации Trae по правилам](https://docs.trae.ai/ide/rules). За ним следует
управляемый Apothem блок; текст, который вы добавляете после блока, сохраняется
при каждой синхронизации.

## Заметки о совместимости

Текущая поверхность правил Trae имеет область действия проекта и находится в
`.trae/rules/`; глобальные правила размещаются в `~/.trae/user_rules`. Адаптер
записывает выделенный файл `apothem-rules.md` и никогда не перезаписывает
другие файлы правил в этом каталоге или ваши глобальные правила.
Поверхность серверов инструментов `.trae/mcp.json` и поверхность навыков
`.trae/skills/` принадлежат оператору; Apothem их не записывает.

## Проверка

```bash
apothem verify --harness trae --project /path/to/project
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Каждая управляемая цель существует; управляемые файлы не пусты, а конфигурации JSON или YAML разбираются. Добавьте `--profile PATH`, чтобы дополнительно подтвердить, что установленные файлы соответствуют этому профилю.
3. Процедура проверки, специфичная для адаптера, сообщает об успехе.

## Обновление

```bash
apothem update --harness trae --project /path/to/project
```

Повторно выводит файл правил проекта из текущего состояния общего профиля.

## Удаление

```bash
apothem uninstall --harness trae --project /path/to/project
```

Удаляет файлы нативной конфигурации, записанные адаптером.
YAML общего профиля и движок Apothem не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness trae --project /path/to/project` |
| Проверка не пройдена | Запустите `apothem update --harness trae --project /path/to/project`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness trae --project /path/to/project` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
