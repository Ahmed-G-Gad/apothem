**Поставщик:** Moonshot
**Имя установки:** `kimi-code`
**Статус:** GA
**Нативная конфигурация:** `<project>/AGENTS.md` плюс `<project>/.kimi-code/.apothem/support/`

## Установка

```bash
apothem install --harness kimi-code --project /path/to/project
```

Адаптер записывает общую поверхность управления Apothem в `AGENTS.md` в корне
проекта как управляемый блок, ограниченный маркерами-разделителями (текст
оператора за пределами маркеров сохраняется), и размещает ненативные группы в
формате Markdown в принадлежащем Apothem дереве поддержки
`<project>/.kimi-code/.apothem/support/`.
Проектный `AGENTS.md` читают многие инструменты для написания кода помимо Kimi
Code, поэтому блок записывается как руководство для всего проекта, которое не
называет своим читателем ни один конкретный инструмент.

Kimi Code читает файл инструкций `AGENTS.md` в корне проекта, следуя
универсальному соглашению AGENTS.md, а конфигурация проекта размещается в
`<project>/.kimi-code/`. Поверхность `<project>/.kimi-code/mcp.json` принадлежит
оператору; Apothem называет её, но не создаёт в ней записей.

**Записываемые файлы:** `<project>/AGENTS.md` (управляемый блок) и группы
команд, навыков, хуков, исполнителей, правил и шаблонов в
`<project>/.kimi-code/.apothem/support/`.

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общий профиль Apothem и рендерит поверхность инструкций
`AGENTS.md` в корне проекта при каждом запуске `apothem install` или `apothem update`.
Поведенческие правила и корпус управления попадают в управляемый блок
`AGENTS.md`; группы команд, навыков, хуков, исполнителей, правил и шаблонов
размещаются в `.kimi-code/.apothem/support/`, и на них ссылается поверхность
инструкций. Такая раскладка — выбор адаптера, а не пробел в Kimi Code: Kimi Code
загружает навыки из `.kimi-code/skills/` и `.agents/skills/`, пользовательских
исполнителей — из `.kimi-code/agents/` и `.agents/agents/`, а хуки — из массива
`[[hooks]]` в `~/.kimi-code/config.toml`, но не загружает их из дерева поддержки,
поэтому копии Apothem в нём являются справочным материалом, на который указывает
блок `AGENTS.md`. Блок завершается разделом о вспомогательных файлах Apothem,
который называет относительно корня проекта каталог в
`.kimi-code/.apothem/support/`, относительно которого разрешается каждая ссылка
в стиле репозитория (`rules/<name>.md`, `templates/...`, `hooks/...`), поэтому
закоммиченный `AGENTS.md` не содержит путей, привязанных к конкретной машине.
(Поведение Kimi Code описано по его страницам о настройке
[навыков](https://moonshotai.github.io/kimi-code/en/customization/skills),
[субагентов](https://moonshotai.github.io/kimi-code/en/customization/agents) и
[хуков](https://moonshotai.github.io/kimi-code/en/customization/hooks), прочитанным
2026-10-02.)

## Заметки о совместимости

Kimi Code читает инструкции проекта из `AGENTS.md` или
`.kimi-code/AGENTS.md` и распознаёт `.kimi-code/mcp.json` как принадлежащую
оператору поверхность MCP; Apothem называет эту поверхность, но не создаёт в ней
записей. Отрендеренная поверхность инструкций напрямую управляет проектом. Kimi
Code не предоставляет файловой поверхности для строки состояния или
output-стиля, поэтому эти группы не материализуются.

Kimi Code работает на семействе моделей Kimi от Moonshot; актуальную модель и
поверхность конфигурации см. в
[справочнике по конфигурации от поставщика](https://moonshotai.github.io/kimi-code/en/configuration/config-files).

## Проверка

```bash
apothem verify --harness kimi-code --project /path/to/project
```

Команда verify подтверждает, что:

1. Нативная конфигурация существует по ожидаемому пути.
2. Все обязательные поля из общего профиля присутствуют.
3. Специфичная для адаптера процедура проверки сообщает об успехе.

## Обновление

```bash
apothem update --harness kimi-code --project /path/to/project
```

Повторно выводит управляемый блок `AGENTS.md` в корне проекта и группы поддержки
из текущего состояния общего профиля.

## Удаление

```bash
apothem uninstall --harness kimi-code --project /path/to/project
```

Удаляет файлы нативной конфигурации, записанные адаптером.
YAML общего профиля и движок Apothem не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness kimi-code --project /path/to/project` |
| Проверка не пройдена | Запустите `apothem update --harness kimi-code --project /path/to/project`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness kimi-code --project /path/to/project` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
