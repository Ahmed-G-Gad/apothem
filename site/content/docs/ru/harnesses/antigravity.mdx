**Поставщик:** Antigravity
**Имя установки:** `antigravity`
**Статус:** Предварительная версия
**Нативная конфигурация:** `~/.gemini/GEMINI.md` плюс
`~/.gemini/antigravity-cli/plugins/apothem/`

## Установка

```bash
apothem install --harness antigravity
```

Адаптер рендерит общий профиль в `~/.gemini/GEMINI.md` и устанавливает
вспомогательные группы Apothem в виде плагина Antigravity CLI.

**Записываемые файлы:** `~/.gemini/GEMINI.md`,
`~/.gemini/antigravity-cli/plugins/apothem/plugin.json`,
`~/.gemini/antigravity-cli/plugins/apothem/skills/`,
`~/.gemini/antigravity-cli/plugins/apothem/rules/`,
преобразованные определения локальных помощников внутри плагина,
`~/.gemini/antigravity-cli/plugins/apothem/.apothem/support/templates/` и
`~/.gemini/antigravity-cli/plugins/apothem/.apothem/support/hooks/`.

Блок Apothem в `~/.gemini/GEMINI.md` завершается разделом о вспомогательных
файлах Apothem, который называет абсолютный каталог, относительно которого
разрешается каждая ссылка в стиле репозитория: `rules/<name>.md` — в каталоге
`rules/` плагина, а `templates/...` и `hooks/...` — в каталоге
`.apothem/support/` плагина.

**Правила плагина.** Antigravity отбрасывает любой файл в каталоге `rules/`
плагина, который не начинается с допустимого `trigger`
([документация Antigravity по правилам](https://antigravity.google/docs/rules)),
поэтому каждое правило Apothem преобразуется при установке. Правило, которое
применяется всегда, получает `trigger: always_on`; правило, ограниченное
путями, получает `trigger: glob` с теми же шаблонами в `globs`; любое другое
правило получает `trigger: model_decision`. Каждое правило сохраняет свой
`description`. Antigravity распределяет общий бюджет в 20 000 токенов между
всегда применяемыми правилами и при превышении этого бюджета превращает самые
крупные из них в указатели, загружаемые по требованию.

**Манифест плагина.** `plugin.json` содержит только `name` и `description` —
два ключа, которые допускает схема плагинов Antigravity.

**Помощники плагина.** Определения помощников в каталоге `agents/` плагина
содержат `name` и `description`. Список `tools` в Antigravity использует
собственные имена инструментов, а документация предупреждает, что неизвестное
имя может привести к зависанию субагента, поэтому список инструментов не
выводится, и помощники наследуют инструменты родителя. Поскольку в Antigravity
ничто не обеспечивает ограничение «только для чтения», из описаний этих
помощников убирается метка «только для чтения».

**Общий пользовательский якорь.** `~/.gemini/GEMINI.md` также является якорем
пользовательской области для инструментов семейства Gemini. Адаптер Antigravity
хранит свой дополнительный материал Apothem внутри плагина `apothem` в
`~/.gemini/antigravity-cli/plugins/`, поэтому не претендует на общие каталоги
проектов Gemini CLI. Поскольку `~/.gemini/GEMINI.md` загружает более одного
инструмента, блок Apothem в нём записан как глобальные указания, которые не
называют своим читателем ни один конкретный инструмент.

## Сопоставление профиля с нативной конфигурацией

Адаптер читает общий профиль Apothem и рендерит якорь инструкций плюс
вспомогательные группы при каждом запуске `apothem install` или
`apothem update`.

## Заметки о совместимости

Адаптер в предварительной версии. Якорь `GEMINI.md` — это активное содержимое
инструкций; плагин Antigravity сохраняет преобразованные навыки команд,
переиспользуемые навыки, определения локальных помощников, правила, шаблоны и
вспомогательный материал хуков в чётко обозначенном пространстве имён,
принадлежащем Apothem.
Файлы хуков не регистрируются как активные события хуков Antigravity, пока
адаптер не получит слой трансляции схемы для `hooks.json` Antigravity.

## Проверка

```bash
apothem verify --harness antigravity
```

Команда verify подтверждает, что:

1. Нативный файл контекста существует по ожидаемому пути.
2. Файл манифеста плагина `plugin.json` существует, не пуст и разбирается как
   JSON. Проверка не сверяет имя плагина; после его изменения проверьте это
   поле самостоятельно.

## Обновление

```bash
apothem update --harness antigravity
```

Повторно выводит нативную конфигурацию из текущего состояния общего профиля.
Запускайте после редактирования `~/.config/apothem/profile.yaml` или
обновления установленного пакета Apothem.

## Удаление

```bash
apothem uninstall --harness antigravity
```

Удаляет блок Apothem из `~/.gemini/GEMINI.md` и сохраняет в нём любой другой
текст. Файл удаляется, только когда в нём больше ничего не остаётся. Также
удаляет ключи Apothem из `plugin.json` в каталоге плагина
`~/.gemini/antigravity-cli/plugins/apothem/`, сохраняя ваши, и удаляет файлы
Apothem в подкаталогах `skills/`, `rules/`, `agents/` и `.apothem/support/`
этого каталога; остальные файлы там остаются. Резервная копия каждого файла
создаётся в `~/.apothem/backups/` до того, как он будет изменён или удалён.
YAML общего профиля и движок Apothem не затрагиваются.

## Шлюз соответствия

```bash
python -m apothem.conformity.gate --all .
```

## Устранение неполадок

| Симптом | Исправление |
|---------|-----|
| Файл конфигурации не найден | Повторно запустите `apothem install --harness antigravity` |
| Проверка не пройдена | Запустите `apothem update --harness antigravity`, затем проверьте снова |
| Неожиданное содержимое конфигурации | Проверьте `~/.config/apothem/profile.yaml` или `--profile PATH`, затем повторно запустите `apothem update --harness antigravity` |

## Параметры конфигурации

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--dry-run` | `false` | Предпросмотр установки без записи файлов. |
