Apothem стремится к максимальной оценке OpenSSF Scorecard, сохраняя при этом честность публичного фасада относительно того, что Scorecard может и не может вывести из нового репозитория с единственным сопровождающим. Этот документ перечисляет каждую проверку, поверхность доказательств, которая её подкрепляет, и контроль, поддерживающий позицию в актуальном состоянии.

Текущая оценка доступна в [просмотрщике Scorecard](https://securityscorecards.dev/viewer/?uri=github.com/ahmed-g-gad/apothem); значок находится в [заголовке README](https://github.com/ahmed-g-gad/apothem/blob/main/README.md).

## Интерпретация оценки

Scorecard оценивает каждую проверку по шкале от 0 до 10, а общая оценка — это взвешенное среднее. Контроли, зависящие от истории репозитория, сторонней регистрации или разнообразия участников, отслеживаются явно, а не завышаются. Дрейф по любой проверке, контролируемой файлами, запускает немедленное исправление.

Рабочий процесс Scorecard запускает action с `file_mode: git`, так что Scorecard читает клон репозитория. Архивы исходного кода не содержат `.github/` (`export-ignore` в `.gitattributes`), поэтому в режиме архива, который action использует по умолчанию, рабочие процессы были бы скрыты от Dangerous-Workflow, Token-Permissions, Pinned-Dependencies и Packaging.

Pinned-Dependencies намеренно остаётся ниже 10, по двум причинам. На генератор SLSA ссылаются по тегу релиза — это единственное исключение из закрепления по SHA, потому что его происхождение привязано к этому тегу. Рабочий процесс evals устанавливает CLI Claude Code через `npm install --global` в версии, которая выбирается при каждом запуске. Установки Python в рабочих процессах, которые сканирует Scorecard, зафиксированы по хешам либо являются локальными установками самого пакета или wheel-пакетов, собранных в том же запуске.

## Ритм обновления

- **При каждом push:** рабочий процесс Scorecard перезапускается при каждом push в `main`.
- **Еженедельно:** по понедельникам в 02:30 UTC — улавливает изменения в вышестоящей методологии оценки + новые уязвимости, раскрытые в существующих закреплённых зависимостях.
- **При каждом релизе:** перед публичным продвижением сопровождающий проверяет действующую поверхность просмотрщика Scorecard и фиксирует любые ограничения, связанные с состоянием платформы.
