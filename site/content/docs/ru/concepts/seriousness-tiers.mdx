Apothem масштабирует накладные расходы на управление под уровень вовлечённости.
Быстрое исследование не нуждается в подписанных коммитах; продакшен-запуск — нуждается.

## Четыре уровня

| Уровень | Когда применять | Нижняя планка управления |
|------|-------------|-----------------|
| **EXPLORING** | Прототипы, одноразовые эксперименты | Линтинг + тесты + ключевые мандаты (критическая оценка, рассуждение о лучшем решении, прямая честность) |
| **PERSONAL_USE** | Личные инструменты, локальные скрипты | + Проверка типов + коммиты по фазам + PROGRESS.md |
| **SHARED** | Командные проекты, открытый исходный код | + проваленные проверки блокируют исполнение + коммиты по задачам + полная документация + параллельная проверка |
| **PUBLIC_LAUNCH** | Продакшен-сервисы, опубликованные пакеты | + Сканирование безопасности + подписанные коммиты + semver + обязательная повторная проверка |

## Значение по умолчанию для разовых задач

Когда уровень серьёзности не указан, Apothem по умолчанию использует **PERSONAL_USE**.

## Минимально жизнеспособное управление

На уровне EXPLORING три сквозных мандата всегда применяются независимо от уровня:
- CM-1 (Критическая оценка)
- CM-5 (Лучшее решение)
- CM-10 (Беспощадная честность)

## Эскалация уровня

Уровень серьёзности можно повысить в середине проекта. Когда проект PERSONAL_USE
переходит в SHARED, запустите полный локальный проход готовности к выпуску, чтобы
выявить любые пробелы в управлении, накопившиеся на более низком уровне.
