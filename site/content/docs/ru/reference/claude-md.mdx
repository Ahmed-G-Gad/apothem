`CLAUDE.md` — это всегда загружаемая конфигурация экосистемы. Среда выполнения
хост-harness загружает её при каждом взаимодействии, поэтому её
содержимое является *базовым контекстом*, который расширяет любой другой
артефакт.

## Разделы

| Раздел | Назначение |
|---------|---------|
| §1 Набор планирования | Именует мастер-шаблон набора планирования и восемь команд `/plan-<stage>` |
| §2 Когнитивная идентичность и архитектура ПО | Объявляет роль Старшего архитектора ПО и творческую позицию |
| §3 Каталоги артефактов | Корни на диске по классам (правила, команды, навыки, делегированные работники и т. д.) |
| §4 Управление с масштабом серьёзности | Линза масштабирования из четырёх уровней (EXPLORING / PERSONAL_USE / SHARED / PUBLIC_LAUNCH) |
| §5 Операционные директивы | Фреймворки решения задач, стратегического обнаружения и коммуникации |
| §6 Сквозные мандаты | Реестр CM-N (от CM-1 до CM-28) |
| §7 Реестры | Подреестры для команд, правил, делегированных работников, хуков, навыков, эволюции и пустых классов |

## Соглашения об идентификаторах мандатов

Три префикса несут разные значения:

- **CM-N** — конфигурационный мандат, определённый в когорте правил
  (`src/apothem/rules/operational-mandates.md` и пофайловых правилах по каждому мандату).
- **TM-N** — шаблонный мандат, определённый в
  `src/apothem/skills/plan-suite/master-template.md` §4.
- **CP-N** — основной принцип, определённый в том же шаблоне §6.

Шаблон набора планирования — это канонический реестр TM/CP; этапы конвейера
`/plan` разрешают перекрёстные ссылки через этот файл.
