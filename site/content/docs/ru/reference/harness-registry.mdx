Реестр окружений — это инвентарь адаптеров, служащий источником истины, который
используют CLI, документация, фикстурные тесты и проверка закреплений
соглашений. Источник во время выполнения — `src/apothem/lib/harness_registry.py`;
каждую строку ниже можно проследить до этого реестра, до файла
`capabilities.yml` каждого адаптера и до файла `STANDARD-CONVENTION-PIN.md`
каждого адаптера.

## Поддержка групп полезной нагрузки

Значения статуса: `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable` и
`discovery-pending`.

Группа со статусом `converted` переписывается в собственный формат окружения, и
для некоторых исходных полей в нём нет места. Для каждой преобразованной группы
команд, исполнителей или правил файл `capabilities.yml` адаптера содержит
отображение `conversion_losses`, которое указывает, что происходит с каждым
исходным полем фронтматтера:

| Значение | Смысл |
| --- | --- |
| `native:<field>` | Окружение читает его под этим полем. |
| `sidecar:<path>` | Оно записывается в отдельный файл рядом с преобразованным, например в `agents/openai.yaml` у Codex. |
| `filename` | Его несёт имя файла или папки. |
| `inlined` | Оно переносится в текст промпта или тела. |
| `ignored` | Оно остаётся в файле, но окружение его не читает. |
| `dropped` | Оно отбрасывается. |

## Общие корни

Некоторые цели установки загружаются другими окружениями, а не только тем,
которое их записывает. Реестр записывает каждый такой путь в `SHARED_ROOTS` с
одним зарегистрированным владельцем (адаптером, для которого вендор
документирует этот путь), соустановщиками, которые записывают в него те же
файлы, и читателями, чья документация вендора загружает его по умолчанию, а
также страницами вендора, на которых это показано, и датой, когда эти страницы
были получены.

Путь с соустановщиками — это папка уровня пользователя в домашнем каталоге,
которую несколько установок записывают с одинаковыми байтами. На машине, где
установлен только `Cursor`, нет `Codex`, который записал бы `~/.agents/skills/`,
поэтому каждая установка, называющая эту папку, записывает её, а журнал
установок подсчитывает установки, которые её используют. Учётным владельцем
является зарегистрированный владелец, пока он использует папку, а в противном
случае — самая старая установка, которая её использует; при удалении
зарегистрированного владельца ничего не перемещается. Удаление убирает папку,
только если её больше не использует ни одна другая установка (см.
[`uninstall`](/docs/cli-reference/uninstall#общие-папки-в-вашем-домашнем-каталоге)).
Установка читателя не кладёт в папку никаких файлов; установка владельца или
соустановщика делает содержимое Apothem доступным каждому читателю.

| Путь | Владелец | Соустановщики | Читатели |
| --- | --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, GitHub Copilot, Windsurf, Zed | Gemini CLI, Kimi Code, Open-Claw, OpenCode, Qwen Code |
| `~/.config/apothem/rules/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | нет |
| `~/.config/apothem/templates/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | нет |
| `~/.claude/skills/` | Claude Code | нет | Cursor, OpenCode |
| `~/.claude/agents/` | Claude Code | нет | Cursor |
| `~/.codex/agents/` | Codex | нет | Cursor |
| `~/.claude/CLAUDE.md` | Claude Code | нет | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | нет | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | нет | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | нет | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | нет | Zed |

`~/.config/apothem/rules/` и `~/.config/apothem/templates/` содержат файлы, на
которые ссылаются собственные навыки и файлы инструкций Apothem. Ни один другой
инструмент их не загружает, поэтому у них нет читателей и страниц вендора.
`CodeBuddy`, `Kiro` и `Trae` также записывают собственную папку навыков
(`~/.codebuddy/skills/`, `~/.kiro/skills/` и `~/.trae/skills/`); её загружает
только этот инструмент, поэтому она не является общим корнем.

Читатель указывается только там, где документация его вендора показывает
загрузку именно этого пути по умолчанию. Один читатель имеет условие, и
примечание установки повторяет его: `Open-Claw` индексирует `~/.agents/skills/`
только в своём каталоге состояния по умолчанию (он пропускает папку, когда
`OPENCLAW_STATE_DIR` указывает в другое место). Документация `Cursor` называет
`~/.codex/agents/` папкой совместимости с `Codex`, но не говорит, какие форматы
файлов `Cursor` там разбирает, а установка `Codex` записывает файлы TOML, поэтому
то, читает ли `Cursor` этих помощников, не подтверждено. Установка `Cursor` также
записывает собственную копию помощников в `<project>/.cursor/agents/`, которую
порядок приоритета вендора ставит выше импортируемых папок, поэтому в проекте с
установкой нативная копия заменяет копию из `~/.claude/agents/`.

Некоторые инструменты намеренно не являются читателями `~/.agents/skills/`:
документация `Antigravity`, `CodeBuddy`, `Kiro` и `Trae` не говорит, что они
загружают её по умолчанию (`Trae` загружает проектную папку `.agents/skills/`
только после включения настройки), поэтому `CodeBuddy`, `Kiro` и `Trae` получают
собственную папку навыков. Документация `Hermes` называет её только как пример
значения для `skills.external_dirs`. `GitHub Copilot` не является читателем
`~/.claude/agents/`: документация VS Code указывает эту папку для агента
Anthropic Claude, а не для агента, которого запускает `GitHub Copilot`.

Блок Apothem, который владелец записывает в общий файл инструкций, не называет
своим читателем ни один отдельный инструмент. `tests/unit/test_shared_roots.py`
завершается неудачей, когда адаптеры, записывающие цель реестра, не совпадают в
точности с её владельцем и её соустановщиками, и
когда у цели реестра, названной как межинструментальный файл инструкций
(`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `copilot-instructions.md`), нет
объявленного владельца. Единственное исключение — `~/.codex/AGENTS.md`, загрузку
которого не документирует ни одно другое зарегистрированное окружение.

## Хуки валидации

Реестр поддерживается в синхронизированном состоянии следующими проверками:

| Проверка | Назначение |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | Подтверждает, что у каждого адаптера есть закрепление соглашения возрастом не более 90 дней, которое ссылается как минимум на один URL вендора и не имеет просроченной цели обнаружения. CI запускает эту проверку на каждом pull request, еженедельно и перед релизом. |
| `python scripts/dev/check_vendor_urls.py` | Загружает каждый URL вендора, на который ссылаются закрепления и шаблоны окружений, и завершается неудачей на перемещённой или несуществующей странице, включая имя хоста, которое больше не разрешается, или сертификат, не прошедший проверку; тайм-аут, отклонённое или сброшенное соединение либо ошибка сервера 5xx регистрируются как недоступность и не приводят к неудаче. Его запускает еженедельный монитор соглашений. |
| `python -m apothem.conformity.gate --all .` | Запускает проверки соответствия документации и реализации. |
| `python -m pytest` | Прогоняет фикстурные тесты реестра и контрактные тесты адаптеров. |
