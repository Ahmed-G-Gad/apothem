Серверы Model Context Protocol (MCP) **принадлежат оператору**. Apothem ведёт
инвентарь MCP в общем профиле и проецирует его в нативную MCP-поверхность каждого
инструмента, но не создаёт собственных записей серверов — поверхность остаётся
под вашим управлением.

## Где регистрируются серверы MCP

Каждый инструмент регистрирует серверы MCP через свой собственный нативный
механизм, и Apothem соблюдает эту поверхность, а не перезаписывает её. В адаптере
Claude Code (одном из многих) серверы регистрируются командой `claude mcp add` в
`~/.claude.json` (пользовательская или локальная область) и в `.mcp.json` на
уровне проекта; другие адаптеры проецируют в свои собственные нативные
поверхности. Настройки, управляемые Apothem, никогда не несут блок `mcpServers`.

## Добавление сервера

Зарегистрируйте сервер через нативный механизм вашего инструмента; канонической
формой записи является ключ под `mcpServers`:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/some/path"]
    }
  }
}
```

Runtime инструмента загружает зарегистрированные серверы при старте сессии;
перезапустите инструмент, чтобы подхватить новые серверы.

## Конвенция именования

Инструменты MCP появляются у ассистента как `mcp__<server>__<tool>` согласно
стандартной конвенции именования MCP-инструментов инструмента.
