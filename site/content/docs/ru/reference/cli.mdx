CLI `apothem` — это основной интерфейс оператора для управления общим профилем и
адаптерами окружений.

## Глобальные флаги

| Флаг | Описание |
|------|-------------|
| `--version` | Выводит версию Apothem и завершает работу |
| `--help` | Выводит справку по команде |

## Подкоманды

### `apothem install`

Устанавливает адаптер окружения из общего профиля.

```bash
apothem install --harness <name|all> [--profile PATH] [--project PATH] [--dry-run] [--clean|--fresh] [--yes]
```

| Параметр | Описание |
|--------|-------------|
| `--harness <name>` | Имя адаптера окружения (см. канонические значения ниже). Обязательный. |
| `--profile PATH` | Путь к YAML общего профиля. По умолчанию `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--dry-run` | Предпросмотр установки без записи файлов. |
| `--clean`, `--fresh` | Включаемая по запросу установка с чистого листа: перед установкой создаёт резервную копию предыдущего состояния установки (`~/.claude`, `~/.codex`, `~/.agents`, `~/.config/apothem`) и удаляет его. |
| `--yes` | Пропускает подтверждение для каждой цели при удалении с чистого листа (обязателен для неинтерактивных запусков с `--clean`). |

Канонические значения `--harness`:

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

Используйте `--harness all --project <path>`, чтобы выбрать весь набор реестра.
Список `exclude_harnesses` из профиля учитывается при пакетном выборе во время
установки/обновления.

### `apothem update`

Заново выводит нативную конфигурацию адаптера окружения из текущего общего
профиля.

```bash
apothem update --harness <name|all> [--profile PATH] [--project PATH] [--dry-run]
```

| Параметр | Описание |
|--------|-------------|
| `--harness <name>` | Имя адаптера окружения. Обязательный. |
| `--profile PATH` | Путь к YAML общего профиля. |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--dry-run` | Предпросмотр обновления без записи файлов. |

`update` заново материализует вывод окружения. Он не обновляет пакет CLI Apothem;
для обновления пакета используйте менеджер пакетов, которым был установлен
Apothem.

### `apothem uninstall`

Удаляет нативную конфигурацию адаптера окружения.

```bash
apothem uninstall --harness <name|all> [--project PATH] [--yes]
```

| Параметр | Описание |
|--------|-------------|
| `--harness <name>` | Имя адаптера окружения. Обязательный. |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--yes` | Пропускает запрос подтверждения. |

### `apothem verify`

Проверяет, что управляемые цели адаптера окружения присутствуют и корректны.

```bash
apothem verify --harness <name|all> [--profile PATH] [--project PATH]
```

| Параметр | Описание |
|--------|-------------|
| `--harness <name>` | Имя адаптера окружения или `all`. Обязательный. |
| `--profile PATH` | YAML общего профиля, на соответствие которому выполняется проверка. Без него проверка чисто структурная. |
| `--project PATH` | Корень проекта для окружений с областью проекта. |

Без `--profile` проверка структурная: каждая управляемая цель должна
присутствовать и быть корректной. С `--profile` она дополнительно требует
соответствия профилю, поэтому установка, которая существует, но разошлась с
этим профилем, не проходит verify — используйте этот режим, чтобы подтвердить,
что конкретный профиль установлен точно.

Код выхода равен `0`, когда окружение проверено (и, с `--profile`, соответствует
профилю), и `1`, когда цель отсутствует или некорректна либо когда передан
`--profile` и установка разошлась с профилем.

### `apothem status`

Сообщает о состоянии установки, проверки и дрейфа для каждого
зарегистрированного окружения.

```bash
apothem status [--profile PATH] [--project PATH]
```

| Параметр | Описание |
|--------|-------------|
| `--profile PATH` | Общий профиль, используемый как базовая линия для дрейфа. Нечитаемый профиль по умолчанию понижает дрейф до `unknown`, а не прерывает проход. |
| `--project PATH` | Корень проекта для окружений с областью проекта. Без него такие окружения сообщают `needs-project`. |

Каждая строка сопоставляет флаг `installed` с флагом `verified`, и вместе они
дают состояние дрейфа:

| Состояние | Значение |
|-------|---------|
| `absent` | Apothem не выполнял установку в это окружение. |
| `in-sync` | Установлено и соответствует базовой линии профиля. |
| `drift` | Установлено, но больше не соответствует — исправьте с помощью `apothem update`. |
| `unknown` | Установлено, но базовый профиль не удалось прочитать. |

`installed` отвечает на вопрос «устанавливал ли сюда Apothem?», а не «есть ли
это окружение на машине?». Флаг определяется по собственным артефактам Apothem —
управляемому блоку внутри якоря инструкций и содержимому в принадлежащем
Apothem поддереве `.apothem/` — и никогда по принадлежащему вендору файлу,
который окружение записывает для себя. Окружение, каталог конфигурации которого
существует, но которого Apothem никогда не касался, сообщает `absent`, а
окружение, которое было удалено, сообщает `absent`, даже если опустевшие
каталоги остаются.

### `apothem profile`

Управляет общим профилем Apothem.

```bash
apothem profile show [--profile PATH]
apothem profile init [--profile PATH] [--force]
apothem profile set <key> <value> [--profile PATH]
apothem profile edit [--profile PATH]
```

| Подкоманда | Описание |
|------------|-------------|
| `profile init` | Создаёт минимальный каркас профиля, валидный по схеме. |
| `profile show` | Выводит разрешённый профиль в JSON в stdout. С `--json` документ начинается с `schema_version`. |
| `profile set <key> <value>` | Задаёт поле профиля. Значение сохраняется как литеральная строка: простые слова не приводятся к другим типам, поэтому `no` остаётся `"no"`, а `1.0` остаётся строкой. Исключения — `true`/`false` и явный ввод списков и отображений `[...]` / `{...}`. Собранный профиль проверяется по схеме до записи. |
| `profile edit` | Открывает профиль в `$EDITOR` (при отсутствии используется редактор по умолчанию для платформы). |

Параметр `--profile PATH` направляет каждую подкоманду на альтернативный файл
профиля. По умолчанию `~/.config/apothem/profile.yaml`.

### `apothem harnesses`

Перечисляет и показывает зарегистрированные адаптеры окружений.

```bash
apothem harnesses list
apothem harnesses show <name>
```

| Подкоманда | Описание |
|------------|-------------|
| `harnesses list` | Выводит таблицу всех зарегистрированных адаптеров с флагом статуса установки и путём вывода каждого. |
| `harnesses show <name>` | Выводит имя, состояние установки и путь вывода одного адаптера. |

### `apothem doctor`

Запускает системную диагностику установки Apothem.

```bash
apothem doctor
```

Выводит версию Apothem, интерпретатор Python, платформу, путь к разрешённому профилю и таблицу статуса установки по каждому окружению. Код выхода равен `1`, если не проходит какая-либо проверка: невалидный профиль, установленное окружение, которое не проходит проверку, зарегистрированная команда хука, которая не может запуститься, адаптер, который не удаётся загрузить или опросить, либо нечитаемый журнал. Окружение, которое не установлено, отмечается в отчёте и не считается сбоем; информационные примечания не меняют код выхода.
