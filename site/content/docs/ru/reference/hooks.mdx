Хуки срабатывают на событиях инструментов и загружают контексты сообщений, которые
ассистент воспринимает как дополнительные системные промпты. Подключение
находится в блоке хуков `settings.json` Claude Code (установка через движок) или
в `hooks.json` плагина (установка плагина), в файле хуков `hooks.json` Codex и
в карте хуков `settings.json` Qwen Code.

| Событие | Тайм-аут | Назначение |
|-------|--------:|---------|
| SessionStart | 30 секунд | Прочитать память, проверить состояние плана, сообщить о готовности; после сжатия контекста — доставить контекст восстановления |
| PreCompact | 30 секунд | Проверить, что состояние вынесено вовне перед сжатием контекста (Codex, Qwen Code; не регистрируется в Claude Code) |
| PostCompact | 30 секунд | Восстановить рабочее состояние после сжатия контекста (Codex, Qwen Code; не регистрируется в Claude Code) |
| Stop | 60 секунд | Протокол завершения сессии, включается по запросу |
| PostToolUse | 10 секунд | Упреждающая рекомендация по сжатию контекста, не более двух раз за сессию |
| PreToolUse (оболочка: Bash, PowerShell, `run_shell_command`) | 10 секунд | Изоляция артефактов git, локальность планов, защита от динамического eval |
| PreToolUse (Write/Edit/NotebookEdit/apply_patch) | 10 секунд | Изоляция ссылок на планы, заголовок авторства, локальность планов, защиты зависимостей и динамического eval |
| PreToolUse (AskUserQuestion) | 10 секунд | Корректность формы маркера `(Recommended)` |

## Диспетчер

Записи хуков, установленные движком, вызывают диспетчер по абсолютному пути
скрипта с интерпретатором, определённым при установке. Шаблоны содержат токены
`${PYTHON_BIN}` и `${HARNESS_ROOT}`, которые установщик подставляет во время
установки. Claude Code и Qwen Code материализуют диспетчер в
`<harness-root>/.apothem/support/hooks/`; Codex — в `<harness-root>/hooks/`.
Записи Claude Code используют exec-форму (`command` плюс `args`), поэтому им не
нужна оболочка. Плагин Claude Code запускает каждый хук как
`bash "${CLAUDE_PLUGIN_ROOT}/lib/apothem/hooks/lib/bootstrap.sh" <event> [<message-file>]`
в оболочке хуков Claude Code по умолчанию (`sh` в macOS и Linux, Git Bash в
Windows); загрузчик находит интерпретатор Python 3.10+ и запускает поставляемый
в комплекте диспетчер. В Windows без Git for Windows используйте установку
через движок (`apothem install --harness claude-code`), хукам которой в
exec-форме оболочка не нужна. Диспетчер — это автономный скрипт на стандартной
библиотеке: он сам настраивает свой `sys.path`, поэтому импортируемый пакет
`apothem` на хосте не нужен. В чекауте исходного кода модульная форма
`python -m apothem.hooks.dispatch <event>` (с `PYTHONPATH=src`) выполняет тот
же код для разработки. Диспетчер загружает `hooks/lib/resolve_root.py` для
разрешения корня экосистемы и делегирует работу `hooks/emit_hook_context.py` и
`hooks/session_start_bootstrap.py`.

## Контексты сообщений

Контексты Markdown для каждого события находятся в `src/apothem/hooks/messages/`:

- Жизненный цикл сессии: `sessionstart.md`, `precompact.md`, `postcompact.md`,
  `stop.md`, `posttooluse-proactive-compaction.md`
- Вызовы оболочки: `pretooluse-bash.md`, `pretooluse-bash-plan-guard.md`
- Запись файлов: `pretooluse-write.md`, `pretooluse-edit.md`,
  `pretooluse-notebookedit.md`, `pretooluse-write-plan-guard.md`,
  `pretooluse-write-header-guard.md`, `pretooluse-edit-header-guard.md`,
  `pretooluse-conformity.md`
- Защиты содержимого: `pretooluse-dependency-guard.md`,
  `pretooluse-eval-guard.md`
- Вопросы: `pretooluse-askuserquestion-recommended.md`

В Claude Code `postcompact.md` доставляется хуком SessionStart, когда сессия
возобновляется после сжатия контекста, поскольку Claude Code не передаёт вывод
хуков PreCompact и PostCompact ассистенту.

Каждый файл контекста загружается диспетчером, когда срабатывает его событие и
его аргумент контекста зарегистрирован в файле настроек. Строка комментария с
лицензией и завершающий раздел `## Bindings` удаляются до того, как текст
попадает к ассистенту; оба существуют для сопровождающих и шлюза соответствия.

## Контракт времени выполнения

Каждая зарегистрированная команда хука соблюдает один и тот же контракт,
который проверяет `tests/hooks/test_hook_contract.py` для плагина, установки
Claude Code через движок, Codex и Qwen Code:

- **Запускается из чистого чекаута.** Код выхода 0, а стандартный вывод пуст или
  содержит один объект JSON. Ни один хук не зависит от бита исполнения файла.
- **Регистрируется один раз.** Каждое сочетание события, сопоставителя и
  сообщения встречается один раз на поверхность, поэтому хук никогда не
  запускается дважды на одном вызове инструмента.
- **Ограничен.** Ни один выводимый текст не превышает 10 000 символов. Защита
  зависимостей срабатывает только тогда, когда запись нацелена на манифест
  зависимостей или lock-файл, а защита от динамического eval — только когда
  содержимое или команда содержит примитив вычисления или небезопасной
  десериализации. Рекомендация по сжатию контекста срабатывает не более двух
  раз за сессию.
- **Использует каналы, которые доставляет окружение.** Указания PreToolUse
  передаются в `hookSpecificOutput`; защита AskUserQuestion возвращает
  `additionalContext`, а при строгом режиме, включаемом по запросу, —
  `permissionDecision: deny`. Claude Code отбрасывает вывод PreCompact и
  PostCompact, поэтому в Claude Code контекст восстановления после сжатия
  приходит с событием SessionStart, источником которого является `compact`.
- **Никогда не запускает код проекта.** Загрузчик определяет собственное
  установленное дерево и никогда не берёт скрипт из открытого проекта. Указания
  при запуске сессии читаются из установленного дерева; каталог проекта
  читается только для сводок планов и памяти.
- **При сбое не блокирует работу (fail-open).** Отсутствующий файл сообщения,
  отсутствующий интерпретатор или повреждённое состояние дают код выхода 0 и
  валидный конверт.

| Переменная | По умолчанию | Действие |
| --- | --- | --- |
| `APOTHEM_HOOKS_DISABLE` | не задана | `1`, `true`, `yes` или `on` отключает каждый хук, маршрутизируемый диспетчером, и хук шлюза соответствия установки через движок |
| `APOTHEM_SESSION_END_ENABLED` | выключено | `1`, `true`, `yes` или `on` включает протокол завершения сессии на Stop. Хук Stop, который возвращает контекст, заставляет ассистента продолжить работу, поэтому протокол стоит один дополнительный ход за сессию; он никогда не срабатывает на остановке, которая уже следует за продолжением, вызванным хуком |
| `APOTHEM_SESSION_END_MIN_STOPS` | `3` | Число завершений хода, после которого может сработать протокол завершения сессии |
| `APOTHEM_PROACTIVE_COMPACTION_ENABLED` | включено | `0`, `false`, `no` или `off` отключает рекомендацию по сжатию контекста |
| `APOTHEM_PROACTIVE_COMPACTION_TOOL_THRESHOLD` | `18` | Вызовы инструментов на окно рекомендации |
| `APOTHEM_PROACTIVE_COMPACTION_OUTPUT_THRESHOLD` | `20000` | Байты вывода инструментов на окно рекомендации |
| `APOTHEM_HOOK_STATE_DIR` | см. ниже | Каталог для состояния хуков каждой сессии |

Состояние хуков каждой сессии хранится в каталоге конкретного пользователя,
создаваемом с режимом `0700`: `APOTHEM_HOOK_STATE_DIR`, если переменная задана,
иначе `${CLAUDE_PLUGIN_DATA}/state` для плагина Claude Code, иначе
`$XDG_STATE_HOME/apothem`, иначе `~/.local/state/apothem`
(`%LOCALAPPDATA%\apothem\state` в Windows).
