Определения слэш-команд хранятся как плоские файлы `.md` в каталоге `src/apothem/commands/`.
Канонический набор возглавляет учитывающий архитектуру конвейер набора планов,
который поставляется в виде восьми полноправных команд этапов, каждая из которых
вызывается напрямую как `/plan-<stage>`, плюс `/plan` — оркестратор, который
проводит цепочку этапов от начала до конца. Каждый этап — это собственный
зарегистрированный файл команды в `src/apothem/commands/plan-<stage>.md`, и
`/plan` не реализует заново ни один из них.

## Контракт frontmatter

Каждый файл команды несёт канонический frontmatter из восьми ключей.
Машиночитаемый контракт — [`command.schema.json`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas/command.schema.json)
(`additionalProperties: false`); этот блок его отражает:

```yaml
---
name: <slash-command name without leading slash>
version: <semver>
updated: <YYYY-MM-DD>
description: <one-line role>
argument-hint: <placeholder for the slash-command argument>
disable-model-invocation: <true | false>
portability: <portability classification, e.g. universal>
allowed-tools: <comma-separated read-only tools and scoped rules, e.g. "Read, Glob, Grep" or "Read, Bash(git log *)">
---
```

Проверка `frontmatter-cohort` валидатора (ветвь Command) проверяет этот
контракт в каждом файле команды. `allowed-tools` перечисляет инструменты,
которые окружение может запускать без запроса, пока команда активна, поэтому
по умолчанию этот список остаётся только для чтения: инструмент с побочными
эффектами (Bash, PowerShell, Write, Edit, NotebookEdit, WebFetch) появляется
только как ограниченное правило, например `Bash(git log *)`, а голый
подстановочный знак `"*"` отклоняется схемой. Команды с необратимыми побочными
эффектами или временем запуска, выбираемым оператором, задают
`disable-model-invocation: true`, поэтому запускает их только оператор:
`freshify`, `github-deploy-fresh`, `github-deploy-next`, `release-readiness`,
`elevate`, `fortress`, `workflow`, `plan-execute`, `research-experiment` и
`research-publish`. Остальные 35 команд задают `false` и сопоставляются с
запросом по своему описанию.

## Дисциплина написания

- **Самодостаточный рабочий процесс.** Тело каждой команды перечисляет рабочий
  процесс в виде нумерованных шагов, чтобы ассистент мог выполнить его с
  холодного старта.
- **Блок Bindings.** Каждая команда завершается каноническим блоком Bindings
  с пятью направлениями.
- **Только язык предметной области.** Никаких внутренних ссылок на планы в телах.
