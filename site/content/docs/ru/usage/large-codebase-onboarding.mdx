Используйте эту страницу, когда репозиторий слишком обширен для одного промпта,
сканирование всего дерева обходится дорого или у каждого сервиса свои команды
сборки и тестирования.

## Начните здесь

1. Установите или обновите целевой адаптер среды, затем запустите `apothem verify --harness <name>`.
2. Держите корневую контекстную поверхность короткой: карта проекта, критические команды и только указатели.
3. Размещайте локальные соглашения рядом с кодом, когда целевая среда поддерживает многослойный контекст.
4. Перенесите специализированные процедуры в `skills/`, `rules/` или документы команд с фильтрами путей.
5. Используйте делегированных работников только для чтения для широкого исследования, затем верните компактный набор находок перед редактированием.
6. Добавьте исключения для кэша, сгенерированных файлов, сборки и поставщиков на поверхность игнорирования среды, где это задокументировано.
7. Используйте LSP или инструменты по символам, когда они доступны; иначе используйте `rg`, суженные пути и явные области файлов.
8. Запускайте наиболее узкую команду линтинга или тестирования, охватывающую затронутый код; перед выпуском запускайте полный шлюз.

## Карта практик

| Практика | Привязка в Apothem |
|----------|-----------------|
| Лёгкий всегда загружаемый контекст | `src/apothem/rules/token-budget-discipline.md` держит всегда активные правила короткими; корневые контекстные файлы должны нести лишь указатели и критические подводные камни. |
| Экспертиза по запросу | `src/apothem/skills/README.md` определяет соглашение `SKILL.md`; сопутствующие правила, отфильтрованные по пути, держат узкие процедуры вне базового контекста. |
| Многослойный контекст | Каждая строка среды объявляет `layered_context_surface` в `src/apothem/harnesses/<name>/capabilities.yml`; `STANDARD-CONVENTION-PIN.md` остаётся авторитетом для строки. |
| Изолированное исследование | [Руководство по делегированным работникам](/docs/usage/using-agents) связывает отдельные контекстные окна и компактные контракты возврата. |
| Навигация по символам | `lsp_symbol_navigation` — отслеживаемая ячейка возможностей. Строки остаются в `tracked-gap`, пока не будет зафиксирована поддерживаемая поставщиком поверхность плагина или инструмента. |
| Поверхность игнорирования | `context_ignore_surface` фиксирует задокументированный механизм исключения. Адаптер Claude Code проецирует исключения сгенерированных файлов и кэша через `permissions.deny` в `settings.json`. |
| Обучение на хуках | Хуки пропускающего класса хранят молчание. Повторяющиеся находки маршрутизируются через цикл эволюции артефактов в `src/apothem/rules/persistent-conventions-vigilance.md`. |
| Периодическая ревизия | Проводите ревизию конфигурации каждые три-шесть месяцев, а также после крупных изменений среды или модели, используя периодичность планов `*-maintenance`. |

## Заметки по обслуживанию

Машиночитаемая строка возможностей среды несёт четыре ячейки для больших кодовых баз:
`context_ignore_surface`, `layered_context_surface`, `lsp_symbol_navigation`
и `hook_learning_capture`. Держите эти ячейки синхронизированными с соседним
`STANDARD-CONVENTION-PIN.md` всякий раз, когда меняется поверхность поставщика.
