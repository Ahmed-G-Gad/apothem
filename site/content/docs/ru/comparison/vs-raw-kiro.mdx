Kiro читает направление из каталога `.kiro/steering/` с файлами Markdown. Адаптер kiro
в Apothem рендерит выделенный файл направления `apothem-rules.md` из общего профиля.
Эта страница противопоставляет ручное сопровождение этой конфигурации управлению ею с
помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Написать правила направления | Вручную писать каждый файл в `.kiro/steering/` | Рендерятся из общего корпуса |
| Сохранить файлы основания нетронутыми | Помнить, что нельзя перезаписывать `product.md` / `tech.md` / `structure.md` | Адаптер записывает только `apothem-rules.md` |
| Поддерживать правила согласованными с другими средами | Вручную, по каждому инструменту | Автоматически при `apothem update` |
| Проверить корректность конфигурации | Ручная проверка | `apothem verify --harness kiro` |

## Чем управляет Apothem

Адаптер kiro рендерит общие правила в выделенный файл направления `apothem-rules.md` с
front matter `inclusion: always` и не трогает написанные оператором файлы основания
Kiro. У Kiro нет хука PreToolUse, поэтому намерение защитного ограждения живёт в прозе
правил, а не в точке перехвата вызова инструмента. Каждое изменение в общих правилах
заново рендерит файл при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если у вас его ещё нет.
2. Перенесите правила из вашего существующего `.kiro/steering/` в общий корпус.
3. Выполните `apothem install --harness kiro`, чтобы отрендерить файл направления `apothem-rules.md`.
4. Выполните `apothem verify --harness kiro`, чтобы подтвердить, что конфигурация установлена.
5. Используйте `apothem update --harness kiro` для каждого последующего изменения.
