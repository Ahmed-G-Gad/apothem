Эта страница рассматривает Apothem на фоне категорий инструментов, которые
операторы уже используют для управления конфигурацией ИИ-ассистентов
программирования. Она называет категории возможностей, а не конкретные
продукты — сравнение структурно и применимо независимо от того, к какому
инструменту в каждой категории вы обращаетесь.

## Категории

Операторы, управляющие конфигурацией ИИ-ассистентов в нескольких инструментах,
попадают в один из четырёх подходов:

1. **Ручная конфигурация по каждому инструменту.** Вы вручную правите нативный
   файл конфигурации каждой среды — один файл на инструмент, без общего
   источника.
2. **Инструменты конфигурации для одной среды.** Инструмент, посвящённый одной
   платформе ассистента, который хорошо управляет конфигурацией этой платформы,
   но не дотягивается до других инструментов, которые вы используете.
3. **Универсальные менеджеры dotfiles.** Инструмент, который ведёт
   версионирование и синхронизирует файлы конфигурации между машинами, но
   относится к каждому файлу как к непрозрачному тексту.
4. **Менеджеры конфигурации для нескольких сред.** Инструмент, который хранит
   один общий профиль и рендерит из него нативный формат каждой среды. Apothem
   относится к этой категории.

## Сравнение возможностей

| Возможность | Вручную по инструменту | Инструмент одной среды | Менеджер dotfiles | Apothem |
| ---------- | --------------- | ------------------- | --------------- | ------- |
| Покрывает множество сред | Да (ценой усилий) | Нет (одна среда) | Да (на уровне файлов) | Да (семнадцать адаптеров) |
| Единый общий источник истины | Нет | Нет | Нет | Да |
| Рендерит нативные форматы по средам | Вручную | Да (одна среда) | Нет | Да |
| Предотвращение дрейфа между средами | Вручную | Н/Д | Только синхронизация файлов | Да |
| Перевод формата (`.mdc`, `.toml`, встроенный `.md`) | Вручную | Для своей среды | Нет | Да |
| Команда верификации | Нет | По-разному | Нет | Да |
| Добавление новой среды | Больше ручной работы | Невозможно | Отслеживать больше файлов | Установить один адаптер |

## Где уместен каждый подход

**Ручная конфигурация по каждому инструменту** уместна для единственного
инструмента с конфигурацией, которую вы редко меняете. Стоимость растёт с каждым
добавленным инструментом и каждым правилом, которое вы поддерживаете
согласованным между ними.

**Инструменты для одной среды** уместны для операторов, приверженных одной
платформе. Они не решают проблему множества инструментов — в тот момент, когда
вы добавляете второго ассистента, вы снова поддерживаете две согласованные
конфигурации.

**Менеджеры dotfiles** уместны для синхронизации произвольных файлов между
машинами. Они перемещают байты между машинами, но не понимают форматы сред, так
что не могут ни отрендерить один профиль в семнадцать нативных форм, ни
верифицировать какую-либо из них.

**Apothem** уместен для операторов, запускающих несколько ИИ-ассистентов и
желающих единый источник истины. Вы пишете профиль один раз; Apothem рендерит,
устанавливает, обновляет и верифицирует нативную конфигурацию каждой среды.
