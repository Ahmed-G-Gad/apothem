Codex читает пользовательские инструкции из `AGENTS.md`, загружает хуки из
`hooks.json` или `config.toml`, обнаруживает пользовательские агенты в `agents/`
и обнаруживает скиллы из общего корня скиллов Codex. Адаптер codex в Apothem
устанавливает эти поверхности из общего профиля, не трогая принадлежащие
оператору настройки `config.toml`.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Написать `AGENTS.md` | Вручную править пользовательские инструкции | Устанавливается из шаблона начальной загрузки Codex |
| Написать хуки | Вручную писать `hooks.json` или TOML-таблицы хуков | Устанавливается в `~/.codex/hooks.json` с помощниками хуков Apothem в `~/.codex/hooks/` |
| Написать пользовательские агенты | Вручную писать TOML-файлы в `~/.codex/agents/` | Преобразуются из Markdown-агентов Apothem |
| Написать переиспользуемые команды | Собирать скиллы вручную, по одному каталогу за раз | Упаковываются как `~/.agents/skills/*/SKILL.md` |
| Поддерживать правила согласованными с другими средами | Вручную, по каждому инструменту | Автоматически при `apothem update` |
| Проверить корректность конфигурации | Ручная проверка | `apothem verify --harness codex` |

## Чем управляет Apothem

Адаптер codex устанавливает `AGENTS.md`, `hooks.json`, файлы-помощники хуков,
преобразованные пользовательские агенты и сгенерированные скиллы. Он не
перезаписывает `~/.codex/config.toml`; модель, песочница, согласование, MCP и
прочие предпочтения времени выполнения остаются за оператором.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если у вас его
   ещё нет.
2. Перенесите правила из вашего существующего `AGENTS.md` в общий корпус.
3. Сохраните существующие настройки времени выполнения `config.toml` в Codex,
   если только вы не решите управлять ими вручную в другом месте.
4. Выполните `apothem install --harness codex`, чтобы установить нативные
   поверхности Codex.
5. Выполните `apothem verify --harness codex`, чтобы подтвердить, что файлы
   установлены.
6. Используйте `apothem update --harness codex` для каждого последующего
   изменения.
