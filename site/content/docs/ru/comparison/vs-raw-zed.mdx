Zed читает инструкции агента из единственного плоского файла `.rules` в корне
проекта (рядом с семейством `AGENTS.md` / `CLAUDE.md`). Адаптер zed Apothem
рендерит этот файл из общего профиля. Эта страница противопоставляет ручное
сопровождение этой конфигурации управлению ею с помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Написать инструкции | Вручную писать файл `.rules` | Рендерится из общего корпуса |
| Сохранить предыдущий `.rules` | Самому не забыть скопировать его в сторону | Адаптер делает резервную копию существующего файла перед заменой |
| Поддерживать правила согласованными с другими средами | Вручную, по каждому инструменту | Автоматически при `apothem update` |
| Проверить корректность конфигурации | Ручная проверка | `apothem verify --harness zed` |

## Чем управляет Apothem

Адаптер zed рендерит общие правила в плоский файл `.rules` в корне проекта. У Zed
нет хука PreToolUse, поэтому намерение защитного ограждения живёт в тексте
правила, а не в точке перехвата вызова инструмента. Глобальный файл инструкций
`~/.config/zed/AGENTS.md` и блок контекстного сервера MCP из `.zed/settings.json`
принадлежат оператору и остаются нетронутыми. Каждое изменение общих правил
повторно рендерит файл при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если у вас его
   ещё нет.
2. Перенесите инструкции из вашего существующего `.rules` (и любое
   проектно-специфичное содержимое `AGENTS.md`, которое вы хотите сделать общим)
   в общий корпус.
3. Выполните `apothem install --harness zed`, чтобы отрендерить файл `.rules`.
   Ваш предыдущий `.rules` сначала резервируется.
4. Выполните `apothem verify --harness zed`, чтобы подтвердить, что конфигурация
   установлена.
5. Используйте `apothem update --harness zed` для каждого последующего изменения.
