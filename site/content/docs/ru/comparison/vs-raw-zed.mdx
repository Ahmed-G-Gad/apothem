Zed читает инструкции агента из единственного плоского файла `.rules` в корне
проекта (рядом с семейством `AGENTS.md` / `CLAUDE.md`). Адаптер zed Apothem
рендерит этот файл из общего профиля. Эта страница противопоставляет ручное
сопровождение этой конфигурации управлению ею с помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать инструкции | Вручную писать файл `.rules` | Отрендерено из общего корпуса |
| Сохранить прежний `.rules` | Самостоятельно не забыть скопировать его в резерв | Адаптер делает резервную копию существующего файла перед заменой |
| Поддерживать правила согласованными с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Проверять корректность конфигурации | Ручная инспекция | `apothem verify --harness zed --project <path>` |

## Чем управляет Apothem

Адаптер zed рендерит общие правила в плоский файл `.rules` в корне проекта. У Zed
нет хука PreToolUse, поэтому намерение защитного ограждения живёт в тексте
правила, а не в точке перехвата вызова инструмента. Глобальный файл инструкций
`~/.config/zed/AGENTS.md` и блок контекстного сервера MCP из `.zed/settings.json`
принадлежат оператору и остаются нетронутыми. Каждое изменение общих правил
повторно рендерит файл при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если у вас его ещё нет.
2. Перенесите инструкции из существующего `.rules` (и любое содержимое `AGENTS.md`, специфичное для проекта, которое вы хотите сделать общим) в общий корпус.
3. Выполните `apothem install --harness zed --project <path>`, чтобы отрендерить файл `.rules`. Ваш прежний `.rules` сначала сохраняется в резервную копию.
4. Выполните `apothem verify --harness zed --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Для каждого последующего изменения используйте `apothem update --harness zed --project <path>`.
