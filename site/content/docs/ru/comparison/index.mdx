Apothem — это независимый от хоста менеджер конфигурации окружений. Один общий
профиль в `~/.config/apothem/profile.yaml` материализуется в семнадцать нативных
поверхностей настроек окружений. Этот раздел задаёт рамку того, как оценивать Apothem
на фоне альтернатив, которые вы уже используете.

## Как Apothem сравнивается

Другие инструменты решают смежные части этой задачи. Файловые менеджеры
конфигурации, такие как **chezmoi** и **GNU Stow**, размещают или шаблонизируют
файлы, но никогда не переводят один источник в *нативную* конфигурацию каждого
окружения. CLI синхронизации правил между инструментами, такие
как **rulesync**, действительно генерируют нативные файлы по каждому инструменту
в большем числе инструментов, чем семнадцать у Apothem, и сопоставимо широкую
синхронизируемую единицу. Отличие Apothem — это **дисциплина управления и
жизненного цикла, распространяемая вокруг синхронизации**: механический шлюз
соответствия, детерминированные конвейеры, крепость аудита и обратимый
проверенный жизненный цикл.

| Возможность | Apothem | Файловые менеджеры конфиг. (chezmoi, Stow) | Синхр. правил между инструментами (rulesync) | Нативная конфиг. по инструменту |
| ---------- | :-----: | :----------------------------------: | :-----------------------------: | :--------------------: |
| Один источник в нативные схемы многих инструментов | Да — семнадцать адаптеров окружений | Нет — копия / символьная ссылка, без перевода | Да | Нет — один инструмент |
| Синхронизируемая единица | правила, навыки, хуки, слеш-команды, MCP | произвольные файлы | правила, игнорирование, MCP, команды, субагенты, навыки, хуки, разрешения | — |
| Корпус управления (правила поведения плюс механический шлюз соответствия) | Да — `python -m apothem.conformity.gate` | Нет | Нет | Нет |
| Детерминированные конвейеры планирования и исследования | Да — от `/plan-spec` до `/plan-execute`, тринадцатиэтапный `/research` | Нет | Нет | Нет |
| Крепость аудита, которая обнаруживает и устраняет | Да — обход из одиннадцати команд, цикл повторного аудита `/fortress` | Нет | Нет | Нет |
| Выпуски, укреплённые против цепочки поставок | Да — SBOM, Sigstore, SLSA, цель Scorecard | Нет | по-разному | Нет |
| Обратимый и проверенный жизненный цикл | Да — резервная копия, `apothem verify --json`, удаление без сирот | по-разному | по-разному | — |

Там, где конкурент сильнее, его называют поимённо: **rulesync** охватывает больше
инструментов и несёт сопоставимо широкую синхронизируемую единицу, и несколько
инструментов синхронизации материализуют нативные схемы. Apothem обменивает
сырое число инструментов на дисциплину управления, аудита и жизненного цикла,
распространяемую вокруг синхронизации, — шлюз соответствия, детерминированные
конвейеры `/plan` и `/research`, крепость аудита из одиннадцати команд,
устойчивую память и обратимый проверенный жизненный цикл, — которой инструмент
синхронизации правил не обладает.

## Как сравнивать

Сравнивайте по трём осям:

1. **Источник истины.** Где живут ваши правила, исполнители, команды и настройки?
   Apothem держит один общий корпус и рендерит из него нативный формат каждого
   окружения. Вручную поддерживаемая конфигурация хранит копию по каждому инструменту.
2. **Стоимость дрейфа.** Что происходит, когда вы меняете правило? Apothem
   распространяет изменение в каждое установленное окружение при запуске
   `apothem update`. Вручную поддерживаемая конфигурация требует править нативный
   файл каждого инструмента по отдельности и держать их выровненными по памяти.
3. **Проверка.** Как вы узнаёте, что каждое окружение настроено правильно? Apothem
   поставляется с `apothem verify --harness <name>` и `apothem doctor`. У вручную
   поддерживаемой конфигурации нет встроенной проверки.

## Матрица возможностей

Эта матрица противопоставляет Apothem двум альтернативам, к которым операторы
обращаются первыми: вручную поддерживать нативную конфигурацию каждого окружения и
управлять этими файлами через менеджер dotfiles общего назначения.

| Возможность | Вручную поддерж. конфиг. | Менеджер dotfiles | Apothem |
| ---------- | ---------------------- | --------------- | ------- |
| Единый общий источник истины | Нет (по копии на инструмент) | Нет (отслеживает файлы, а не профиль) | Да (один профиль) |
| Рендеринг нативных форматов окружения | Вручную | Нет | Да (материализатор по адаптеру) |
| Предотвращение дрейфа между окружениями | Ручное выравнивание | Только синхр. файлов | Да (`apothem update`) |
| Установка/удаление по окружению | Вручную | Частично (ссылка/копия) | Да (`install` / `uninstall`) |
| Встроенная проверка | Нет | Нет | Да (`verify` / `doctor`) |
| Перевод формата по инструменту | Нет | Нет | Да (`.mdc`, `.toml`, встроенный `.md`) |
| Семнадцать окружений из одного входа | Нет | Нет | Да |
