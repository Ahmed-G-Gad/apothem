Apothem — это независимый от хоста менеджер конфигурации ИИ-окружений. Один
общий профиль в `~/.config/apothem/profile.yaml` материализуется в семнадцать
нативных для окружений поверхностей конфигурации. Этот раздел задаёт рамку для
оценки Apothem в сравнении с альтернативами, которые вы уже используете.

## Как Apothem соотносится с другими инструментами

Сведения о сопоставимых проектах на этой странице актуальны на **2026-10-02** и
взяты из собственного README или документации каждого проекта (см.
[Источники](#источники)); перепроверяйте их при каждом минорном релизе.

Другие инструменты решают смежные части этой задачи. Файловые менеджеры конфигурации,
такие как **chezmoi** и **GNU Stow**, размещают, связывают или шаблонизируют файлы, но
никогда не переводят один источник в *нативную* схему конфигурации каждого окружения.
CLI-инструменты синхронизации генерируют файлы для каждого инструмента из одного
источника: **rulesync** генерирует нативную конфигурацию для 60 инструментов для
написания кода и двух открытых стандартов в рамках синхронизируемой единицы, которая
добавляет MCP, игнорируемые файлы, разрешения и проверки ревью; манифест Apothem не
синхронизирует ни одну из этих частей, а Apothem рендерит свои MCP-серверы из профиля
через материализаторы адаптеров, которые их создают. **ruler** распространяет один
каталог `.ruler/` на 33 цели, объединяя правила в файл инструкций каждого инструмента и
переводя серверы MCP, навыки и субагенты в нативную конфигурацию. Отличие Apothem — это
**дисциплина управления и жизненного цикла, поставляемая вместе с синхронизацией**:
механизированный шлюз соответствия, детерминированные конвейеры, последовательность аудиторских проверок и
обратимый проверяемый жизненный цикл.

| Возможность | Apothem | Файловые менеджеры конфигурации (chezmoi, Stow) | rulesync | ruler |
| ---------- | :-----: | :----------------------------------: | :------: | :---: |
| Один источник в нативные схемы многих инструментов | Да — семнадцать адаптеров окружений | Нет — копирование, символическая ссылка или шаблон, без перевода | Да — 60 инструментов плюс стандарты AGENTS.md и Agent Skills | Частично — правила объединяются в файл инструкций каждого инструмента; MCP, навыки и субагенты записываются в нативной форме |
| Синхронизируемая единица | правила, навыки, субагенты, слеш-команды, хуки, output-стили, строки состояния, шаблоны, валидаторы соответствия, схемы, шаблоны инструкций для каждого окружения и шаблон настроек Claude Code | произвольные файлы | правила, игнорирование, MCP, команды, субагенты, навыки, хуки, разрешения, проверки (инструкции проверок ревью кода) | правила, MCP, навыки, субагенты |
| Корпус управления (поведенческие правила плюс механический шлюз соответствия) | Да — `python -m apothem.conformity.gate` | Нет | Нет — его функция `checks` синхронизирует проверки ревью кода в инструменты; шлюза соответствия над правилами нет | Нет |
| Детерминированные конвейеры планирования и исследований | Да — от `/plan-spec` до `/plan-execute`, тринадцатиэтапный `/research` | Нет | Нет | Нет |
| Последовательность аудиторских проверок, которая обнаруживает и устраняет проблемы | Да — проход из одиннадцати команд, цикл повторного аудита `/fortress` | Нет | Нет | Нет |
| Долговременная память между сессиями | Да — хранилище `memory/records.json` в каталоге данных Apothem, создаётся при установке | Не сравнивалось | Не указано в его README | Не указано в его README |
| Релизы с усиленной защитой цепочки поставок | Да — SBOM, Sigstore, SLSA, целевой показатель Scorecard | Не сравнивалось | Не указано в его README | Не указано в его README |
| Обратимый, проверяемый жизненный цикл | Да — резервная копия, `apothem verify --json`, удаление без осиротевших файлов | chezmoi: `chezmoi verify` проверяет каждую цель; Stow: только символические ссылки | Не указано в его README | Резервные копии `.bak` и `ruler revert`; команды проверки в его README нет |

Там, где сопоставимый инструмент сильнее, это названо прямо: **rulesync** охватывает более чем в три раза больше инструментов и синхронизирует MCP, игнорируемые файлы, разрешения и проверки ревью, которых манифест Apothem не синхронизирует; **ruler** охватывает почти вдвое больше инструментов и имеет собственную команду отката. Apothem жертвует общим числом инструментов ради дисциплины управления, аудита и жизненного цикла, поставляемой вместе с синхронизацией, — шлюза соответствия, детерминированных конвейеров планирования и исследований, последовательности аудиторских проверок из одиннадцати команд, долговременной памяти и обратимого проверяемого жизненного цикла, — которых нет ни у одного из этих двух инструментов синхронизации.

## Как сравнивать

Сравнивайте по трём осям:

1. **Источник истины.** Где находятся ваши правила, исполнители, команды и
   настройки? Apothem хранит один общий корпус и рендерит из него нативный формат
   каждого окружения. Вручную поддерживаемая конфигурация хранит по одной копии
   на каждый инструмент.
2. **Цена дрейфа.** Что происходит, когда вы меняете правило? Apothem
   распространяет изменение на каждое установленное окружение при
   `apothem update`. Вручную поддерживаемая конфигурация требует, чтобы вы
   редактировали нативный файл каждого инструмента по отдельности и держали их
   согласованными по памяти.
3. **Проверка.** Как узнать, что каждое окружение настроено правильно? Apothem
   поставляет `apothem verify --harness <name>` и `apothem doctor`. У вручную
   поддерживаемой конфигурации нет встроенной проверки.

## Матрица возможностей

Матрица противопоставляет Apothem двум альтернативам, к которым операторы
обращаются в первую очередь: ручному сопровождению нативной конфигурации каждого
окружения и управлению этими файлами через менеджер dotfiles общего назначения.

| Возможность | Вручную поддерживаемая конфигурация | Менеджер dotfiles | Apothem |
| ---------- | ---------------------- | --------------- | ------- |
| Единый общий источник истины | Нет (по одной копии на инструмент) | Нет (отслеживает файлы, а не профиль) | Да (один профиль) |
| Рендеринг нативных форматов окружений | Вручную | Нет | Да (материализатор для каждого адаптера) |
| Предотвращение дрейфа между окружениями | Ручное согласование | Только синхронизация файлов | Да (`apothem update`) |
| Установка/удаление для каждого окружения | Вручную | Частично (символическая ссылка/копия) | Да (`install` / `uninstall`) |
| Встроенная проверка | Нет | Нет | Да (`verify` / `doctor`) |
| Перевод формата для каждого инструмента | Нет | Нет | Да (`.mdc`, `.toml`, встроенный `.md`) |
| Семнадцать окружений из одного входа | Нет | Нет | Да |
