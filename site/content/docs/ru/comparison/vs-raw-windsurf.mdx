Windsurf читает правила из каталога `.devin/rules/`. Адаптер windsurf в
Apothem рендерит правила на основе каталога из общего профиля. На этой странице
ручное сопровождение этой конфигурации сравнивается с управлением ею через
apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать правила | Вручную писать каждый файл в `.windsurf/rules/` | Отрендерено из общего корпуса |
| Сохранять единый формат правил | Вручную выбирать между `.windsurf/rules/` и одним файлом `.windsurfrules` | Адаптер пишет только `.devin/rules/` |
| Поддерживать правила согласованными с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Проверять, что конфигурация верна | Ручная инспекция | `apothem verify --harness windsurf --project <path>` |

## Чем управляет apothem

Адаптер windsurf рендерит общие правила в каталог `.devin/rules/`; он не пишет
один файл `.windsurfrules`. У Windsurf нет хука PreToolUse, поэтому намерение
ограждения живёт в тексте правил, а не в точке перехвата вызова инструмента.
Каждое изменение общих правил повторно рендерит каталог при следующем
`apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы этого ещё не сделали.
2. Перенесите правила из существующего `.windsurf/rules/` (и любого одиночного файла `.windsurfrules`) в общий корпус.
3. Выполните `apothem install --harness windsurf --project <path>`, чтобы отрендерить каталог `.devin/rules/`.
4. Выполните `apothem verify --harness windsurf --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Для каждого последующего изменения используйте `apothem update --harness windsurf --project <path>`.
