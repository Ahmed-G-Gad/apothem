Windsurf теперь называется Devin Desktop и читает правила из каталога
`.devin/rules/` (предпочтительное расположение, которое имеет приоритет над
резервным `.windsurf/rules/`). Адаптер windsurf в
Apothem рендерит правила на основе каталога из общего профиля. На этой странице
ручное сопровождение этой конфигурации сравнивается с управлением ею через
apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать правила | Вручную писать каждый файл в `.windsurf/rules/` | Отрендерено из общего корпуса |
| Сохранять единый формат правил | Вручную выбирать между `.windsurf/rules/` и одним файлом `.windsurfrules` | Адаптер пишет только `.devin/rules/` |
| Поддерживать правила согласованными с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Делиться переиспользуемыми навыками и командами | Вручную копировать каждую папку навыка в `~/.agents/skills/` и поддерживать копии актуальными | Записываются адаптером в `~/.agents/skills/`, одна копия для всех проектов, и обновляются при `apothem update` |
| Поддерживать переиспользуемых помощников в синхронизации | Вручную писать каждый файл субагента Devin Local в `.devin/agents/` и отслеживать имена инструментов Devin | Одиннадцать помощников записываются в `.devin/agents/` с переведёнными инструментами и обновляются при `apothem update` |
| Проверять, что конфигурация верна | Ручная инспекция | `apothem verify --harness windsurf --project <path>` |

## Чем управляет apothem

Адаптер windsurf рендерит общие правила в один файл,
`<project>/.devin/rules/apothem-rules.md`; он не пишет один файл
`.windsurfrules`. Он также записывает одиннадцать помощников Apothem как
субагентов Devin Local в `<project>/.devin/agents/`; три помощника, которым
нужны веб-инструменты, ждут, пока Devin задокументирует имена их инструментов.
Он регистрирует два хука Devin Local — начальную загрузку сессии и
предупреждение о размере контекста — в `<project>/.devin/config.local.json`;
более старый режим Cascade читает другой формат хуков (`hooks.json`), который
адаптер не записывает. Он не регистрирует защиту вызовов инструментов, поэтому
намерение ограждения живёт в тексте правил, а не в точке перехвата вызова
инструмента. Каждое изменение общих правил повторно рендерит файл при следующем
`apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы этого ещё не сделали.
2. Перенесите правила из существующего `.windsurf/rules/` (и любого одиночного файла `.windsurfrules`) в общий корпус.
3. Выполните `apothem install --harness windsurf --project <path>`, чтобы отрендерить каталог `.devin/rules/`.
4. Выполните `apothem verify --harness windsurf --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Для каждого последующего изменения используйте `apothem update --harness windsurf --project <path>`.
