GitHub Copilot читает свои инструкции из `.github/copilot-instructions.md`.
Адаптер github-copilot в Apothem рендерит этот файл из общего профиля. На этой
странице ручное сопровождение этой конфигурации сравнивается с управлением ею
через Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать инструкции | Вручную редактировать `.github/copilot-instructions.md` | Отрендерено: общие правила встроены в файл |
| Согласовывать инструкции с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Установка / удаление конфигурации | Создавать и удалять файл вручную | `apothem install` / `apothem uninstall` |
| Делиться переиспользуемыми навыками и командами | Вручную копировать каждую папку навыка в `~/.agents/skills/` и поддерживать копии актуальными | Записываются адаптером в `~/.agents/skills/`, одна копия для всех проектов, и обновляются при `apothem update` |
| Проверка корректности конфигурации | Ручная инспекция | `apothem verify --harness github-copilot --project <path>` |

## Чем управляет Apothem

Адаптер github-copilot встраивает общие правила в
`.github/copilot-instructions.md`. Copilot документирует хуки в
`.github/hooks/*.json`, которые адаптер не записывает, поэтому намерение ограждения целиком
несётся в отрендеренных инструкциях. Каждое изменение общих правил повторно
рендерит файл при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы этого ещё не сделали.
2. Перенесите содержимое существующего `.github/copilot-instructions.md` в общий корпус.
3. Выполните `apothem install --harness github-copilot --project <path>`, чтобы отрендерить файл инструкций.
4. Выполните `apothem verify --harness github-copilot --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Для каждого последующего изменения используйте `apothem update --harness github-copilot --project <path>`.
