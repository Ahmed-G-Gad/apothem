Kimi Code reads project-root `AGENTS.md` as its instruction file and keeps
project configuration under `<project>/.kimi-code/`, including the
operator-owned `.kimi-code/mcp.json` MCP surface. You can author that
instruction file and its supporting cohorts by hand, per project, forever.
Apothem's kimi-code adapter renders the governance surface into `AGENTS.md` as a
managed block from the shared profile and keeps it consistent across every
harness and every project. This page contrasts hand-maintaining that config
against managing it with Apothem.

## Effort comparison

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать поверхность инструкций `AGENTS.md` | Вручную писать и пересинхронизировать для каждого проекта | Один управляемый блок, отрендеренный из общего профиля |
| Поддерживать правила, команды, навыки и агенты в синхронизации | Ручное копирование для каждого проекта | Материализуется в `<project>/.kimi-code/.apothem/support/` при каждой установке |
| Сохранять прозу оператора при обновлении | Ручное слияние | Блок, ограниченный маркерами; проза оператора вне него сохраняется |
| Поддерживать правила согласованными с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Проверять корректность конфигурации | Ручная инспекция | `apothem verify --harness kimi-code --project <path>` |

## What Apothem manages

The kimi-code adapter renders the shared rules and governance surface into the
project-root `AGENTS.md` managed block and installs the commands, skills, hooks,
agents, rules, and templates cohorts under `.kimi-code/.apothem/support/`. It does not
author `.kimi-code/mcp.json`; the MCP surface stays operator-owned. The rendered
instruction surface drives the project directly. Every change to the shared
rules re-renders the files on the next `apothem update`.

## Migration path

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы этого ещё не сделали.
2. Перенесите правила из существующего `AGENTS.md` в общий корпус.
3. Выполните `apothem install --harness kimi-code --project <path>`, чтобы отрендерить поверхность инструкций `AGENTS.md` и поддерево поддержки `.kimi-code/.apothem/support/`.
4. Выполните `apothem verify --harness kimi-code --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Для каждого последующего изменения используйте `apothem update --harness kimi-code --project <path>`.
