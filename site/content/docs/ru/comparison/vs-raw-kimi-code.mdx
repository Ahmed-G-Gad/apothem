Kimi Code читает `AGENTS.md` в корне проекта как свой файл инструкций и хранит
конфигурацию проекта в `<project>/.kimi-code/`, включая принадлежащую оператору
поверхность MCP `.kimi-code/mcp.json`. Вы можете писать этот файл инструкций и
сопутствующие ему группы вручную, для каждого проекта, бесконечно. Адаптер
kimi-code в Apothem рендерит поверхность управления в `AGENTS.md` как управляемый
блок из общего профиля и поддерживает её согласованной во всех окружениях и во
всех проектах. Эта страница сопоставляет ручное сопровождение этой конфигурации с
управлением ею через Apothem.

## Сравнение усилий

| Задача | Сырая ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Создавать поверхность инструкций `AGENTS.md` | Вручную писать и повторно синхронизировать для каждого проекта | Один управляемый блок, отрендеренный из общего профиля |
| Поддерживать правила, команды, навыки и исполнителей в синхронизации | Ручное копирование для каждого проекта | Материализуется в `<project>/.kimi-code/.apothem/support/` при каждой установке |
| Сохранять прозу оператора при обновлении | Ручное слияние | Блок, ограниченный маркерами; проза оператора вне него сохраняется |
| Поддерживать согласованность правил с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Проверять корректность конфигурации | Ручной осмотр | `apothem verify --harness kimi-code --project <path>` |

## Чем управляет Apothem

Адаптер kimi-code рендерит общие правила и поверхность управления в управляемый
блок `AGENTS.md` в корне проекта и устанавливает группы команд, навыков, хуков,
исполнителей, правил и шаблонов в `.kimi-code/.apothem/support/`. Он не создаёт
`.kimi-code/mcp.json`; поверхность MCP остаётся принадлежащей оператору. Kimi Code
читает инструкции проекта из `AGENTS.md` или `.kimi-code/AGENTS.md`; адаптер
записывает только `AGENTS.md` в корне проекта, а документация Kimi Code не
сообщает, какой из этих двух файлов имеет приоритет, если существуют оба. Каждое
изменение общих правил повторно рендерит эти файлы при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы ещё
   этого не сделали.
2. Перенесите правила из существующего `AGENTS.md` в общий корпус.
3. Выполните `apothem install --harness kimi-code --project <path>`, чтобы
   отрендерить поверхность инструкций `AGENTS.md` и поддерево поддержки
   `.kimi-code/.apothem/support/`.
4. Выполните `apothem verify --harness kimi-code --project <path>`, чтобы
   подтвердить, что конфигурация на месте.
5. Для каждого последующего изменения используйте
   `apothem update --harness kimi-code --project <path>`.
