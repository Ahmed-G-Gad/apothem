Hermes читает `~/.hermes/config.yaml`. Apothem пишет нативную YAML-конфигурацию
(проецируя инвентарь MCP профиля в `auxiliary.mcp`) и устанавливает общие когорты
команд и skills под `~/.hermes/.apothem/support/skills/`. Собственный `skills.config`
Hermes — это список пакетов из реестра, поэтому Apothem его не пишет.

## Статус

**Предпросмотр.** Адаптер Hermes нацелен на текущий задокументированный файл
конфигурации и поверхность обнаружения skills. Когорты, не связанные со skills,
остаются вспомогательным материалом Apothem.

## Сравнение усилий

| Задача | Сырая ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать переиспользуемые skills | Редактировать вручную конфиг и каталоги skills | Написать один раз в общем корпусе |
| Держать когорты согласованными с другими средами | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Установить / удалить конфиг | Вручную | `apothem install` / `apothem uninstall` |
| Проверить корректность конфига | Ручная инспекция | `apothem verify --harness hermes` |

## Чем управляет Apothem

Адаптер Hermes пишет `config.yaml`, оборачивает слеш-команды Apothem в skills,
копирует skills Apothem в указанный вспомогательный каталог и хранит правила,
шаблоны, agents и материал hooks под вспомогательным поддеревом Apothem.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы ещё
   этого не сделали.
2. Перенесите переиспользуемые skills или промпты команд Hermes в общий корпус.
3. Выполните `apothem install --harness hermes`, чтобы отрендерить нативную
   конфигурацию и вспомогательный каталог skills.
4. Выполните `apothem verify --harness hermes`, чтобы подтвердить, что
   конфигурация установлена.
