OpenCode читает JSON-конфигурацию плюс нативные каталоги обнаружения команд, скиллов и
агентов. Apothem рендерит JSON-конфигурацию со списком файлов `instructions` и
преобразует общие корпуса в нативные каталоги там, где OpenCode их поддерживает.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Написать правила | Вручную править конфигурацию и вспомогательные промпты | Рендерятся или ссылаются из общего профиля |
| Написать команды, скиллы, агентов | Вручную сопровождать каждый каталог OpenCode | Преобразуются из общих корпусов Apothem |
| Поддерживать корпуса согласованными с другими средами | Вручную, по каждому инструменту | Автоматически при `apothem update` |
| Установить / удалить поверхность | Вручную | `apothem install` / `apothem uninstall` |
| Проверить корректность конфигурации | Ручная проверка | `apothem verify --harness opencode` |

## Чем управляет Apothem

Адаптер opencode записывает `opencode.json`, преобразует слеш-команды Apothem в файлы
команд OpenCode в формате Markdown, копирует скиллы в нативную поверхность скиллов и
адаптирует вспомогательные определения как Markdown-субагентов. Правила, шаблоны и
промпты хуков остаются под вспомогательным деревом Apothem; правила ссылаются из
нативного списка `instructions`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если у вас его ещё нет.
2. Перенесите существующие правила, команды, скиллы и агентов OpenCode в общий корпус.
3. Выполните `apothem install --harness opencode`, чтобы отрендерить нативную конфигурацию и каталоги обнаружения.
4. Выполните `apothem verify --harness opencode`, чтобы подтвердить, что конфигурация установлена.
5. Используйте `apothem update --harness opencode` для каждого последующего изменения.
