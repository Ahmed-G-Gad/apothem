CodeBuddy читает проектные правила из `.codebuddy/rules/*.md`. Вы можете писать
эти файлы вручную, для каждого проекта, бесконечно. Apothem управляет одним из
них за вас и сохраняет его согласованным в каждой среде и каждом проекте.

## Сырой подход

Ручное написание правил CodeBuddy означает:

- Копирование одних и тех же инженерных дисциплин в `.codebuddy/rules/` для
  каждого нового проекта.
- Рассинхронизацию по мере развития дисциплин — нет единого источника истины.
- Повторное выведение одних и тех же соглашений для Cursor, Windsurf, Claude Code
  и всех остальных инструментов, которые вы используете, потому что у каждого
  своя поверхность правил.

## Подход Apothem

Apothem хранит одну каноническую когорту правил в исходном репозитории и
проецирует её на нативную поверхность каждой среды. Для CodeBuddy он пишет:

```
<project>/.codebuddy/rules/apothem-rules.md
```

| Аспект | Сырой CodeBuddy | Apothem |
| --- | --- | --- |
| Источник истины | Файлы каждого проекта | Одна каноническая когорта |
| Согласованность между средами | Вручную для каждого инструмента | Проецируется автоматически |
| Обновления | Редактировать каждый проект вручную | `apothem update --harness codebuddy --project <path>` |
| Собственные правила оператора | Смешаны с дисциплинами | Не затронуты — Apothem пишет отдельный файл |
| Удаление | Удаление вручную | `apothem uninstall` с резервной копией с меткой времени |

## Что остаётся вашим

Apothem пишет только `apothem-rules.md`. Ваш файл памяти `CODEBUDDY.md`, ваши
разрешения и серверы MCP в `.codebuddy/settings.json`, а также любые другие
файлы правил, которые вы пишете, остаются полностью в собственности оператора.
Адаптер распознаёт эти поверхности, но никогда их не редактирует.

Полные команды жизненного цикла смотрите на
[странице среды CodeBuddy](/docs/harnesses/codebuddy).
