CodeBuddy читает проектные правила из `.codebuddy/rules/*.md`. Эти файлы можно вручную писать для каждого проекта бесконечно. Адаптер codebuddy в Apothem формирует один из них из общего профиля и поддерживает его согласованным во всех окружениях и во всех проектах. На этой странице сравнивается ручное сопровождение такой конфигурации с управлением ею через Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Написать правила | Копировать одни и те же дисциплины в `.codebuddy/rules/` для каждого проекта | Формируются из одного общего корпуса |
| Источник истины | Файлы каждого проекта | Одна каноническая группа |
| Поддерживать правила согласованными между окружениями | Выводить заново для каждого инструмента | Проецируются автоматически |
| Обновить правила | Вручную редактировать каждый проект | `apothem update --harness codebuddy --project <path>` |
| Удалить конфигурацию | Удалять вручную | `apothem uninstall` с резервной копией с меткой времени |

## Чем управляет Apothem

Адаптер codebuddy формирует общие правила в отдельном файле `<project>/.codebuddy/rules/apothem-rules.md` и ничего больше не записывает. Ваш файл памяти `CODEBUDDY.md`, разрешения и серверы MCP в `.codebuddy/settings.json`, а также любые другие файлы правил, которые вы пишете, полностью принадлежат оператору: адаптер распознаёт эти поверхности, но никогда их не редактирует. Каждое изменение общих правил перегенерирует файл при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы ещё этого не сделали.
2. Перенесите дисциплины из существующих файлов `.codebuddy/rules/` в общий корпус.
3. Выполните `apothem install --harness codebuddy --project <path>`, чтобы сформировать файл `apothem-rules.md` рядом с вашими нетронутыми правилами.
4. Выполните `apothem verify --harness codebuddy --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Используйте `apothem update --harness codebuddy --project <path>` для каждого последующего изменения.
