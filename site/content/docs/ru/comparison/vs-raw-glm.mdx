GLM (Z.ai) — это бэкенд моделей, на который совместимый инструмент
направляется заданием базового URL и ключа. Эти переменные окружения можно
экспортировать вручную: для каждого проекта, для каждой машины, бесконечно.
Адаптер glm Apothem фиксирует конечные точки бэкенда и заполнители,
настраиваемые оператором, в одном файле провайдера и записывает один и тот же
шаблон в каждый проект. Эта страница противопоставляет ручное подключение
этого бэкенда управлению им с помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Записать URL бэкенда | Запоминать и заново экспортировать для каждого проекта | Записываются в один файл провайдера |
| Источник истины | Собственные экспорты каждой оболочки | Один канонический файл провайдера |
| Поддерживать согласованность бэкендов между проектами | Заново подключать в каждом проекте | Один и тот же шаблон записывается в каждый проект, когда файла нет; последующие правки остаются в файле каждого проекта |
| Восстановить конфигурацию | Заново экспортировать в каждом проекте | `apothem update --harness glm --project <path>` записывает файл снова, только если он отсутствует |
| Удалить конфигурацию | Ручное удаление | `apothem uninstall` создаёт резервную копию файла, а затем удаляет его, только пока он остаётся неизменённым шаблоном, записанным Apothem |

## Чем управляет Apothem

Адаптер glm записывает единственный файл провайдера по пути
`<project>/.apothem/providers/glm.toml` и ничего больше не записывает. Он
фиксирует базовый URL, совместимый с Anthropic
(`https://api.z.ai/api/anthropic`), базовый URL, совместимый с OpenAI
(`https://api.z.ai/api/coding/paas/v4`), заполнитель токена аутентификации и
заполнители сопоставления моделей. Ваш ключ Z.ai и выбор идентификаторов
моделей остаются во владении оператора — Apothem никогда не записывает
настоящий секрет и не фиксирует ни одного идентификатора модели, меняющегося от
версии к версии.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы ещё
   этого не сделали. Файл glm ничего не берёт из профиля, но каждый запуск
   установки и обновления его загружает.
2. Выполните `apothem install --harness glm --project <path>`, чтобы записать
   файл провайдера `glm.toml`.
3. Заполните свой ключ Z.ai и нужные вам идентификаторы моделей по актуальной
   [документации Z.ai](https://docs.z.ai/devpack/tool/claude).
4. Выполните `apothem verify --harness glm --project <path>`, чтобы подтвердить,
   что конфигурация на месте.
5. Для каждого последующего изменения редактируйте
   `.apothem/providers/glm.toml`. Apothem никогда не перезаписывает
   существующий файл провайдера; `apothem update --harness glm --project <path>`
   записывает его снова, только если он отсутствует.
