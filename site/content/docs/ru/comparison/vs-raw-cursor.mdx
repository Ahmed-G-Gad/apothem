Cursor читает правила в формате MDC под `.cursor/rules/`. Формат MDC требует
полей frontmatter — `description`, `globs` и `alwaysApply`. Адаптер cursor от
Apothem рендерит эти файлы `.mdc` из общего профиля. Эта страница
противопоставляет ручное сопровождение такой конфигурации управлению ею с
помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать правила | Вручную писать каждый файл `.mdc` под `.cursor/rules/` | Отрендерены из общего корпуса |
| Писать frontmatter MDC | Вручную составлять `description` / `globs` / `alwaysApply` для каждого файла | Генерируется адаптером |
| Держать единый формат правил | Вручную выбирать между правилами MDC и единым файлом `.cursorrules` | Адаптер пишет только файлы MDC из `.cursor/rules/` |
| Держать правила согласованными с другими средами | Вручную, по каждому инструменту | Автоматически при `apothem update` |
| Проверить, что конфигурация верна | Ручная проверка | `apothem verify --harness cursor` |

## Чем управляет Apothem

Адаптер cursor рендерит общие правила в файлы `.mdc` под `.cursor/rules/`,
генерируя требуемый frontmatter MDC (`description`, `globs`, `alwaysApply`) для
каждого файла. Адаптер пишет только основанный на каталогах формат MDC, который
читает Cursor; он не пишет единый файл `.cursorrules`.
У Cursor нет хука PreToolUse, поэтому замысел ограждающих перил живёт в прозе
правил.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы ещё этого не сделали.
2. Перенесите правила из вашего существующего `.cursor/rules/` (и любого `.cursorrules`)
   в общий корпус.
3. Выполните `apothem install --harness cursor`, чтобы отрендерить файлы `.mdc`
   с правильным frontmatter MDC.
4. Выполните `apothem verify --harness cursor`, чтобы убедиться, что конфигурация развернута.
5. Используйте `apothem update --harness cursor` для каждого последующего изменения.
