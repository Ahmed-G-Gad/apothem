Gemini CLI читает единственный файл правил `GEMINI.md`. Адаптер gemini-cli в
Apothem рендерит его из общего профиля. Эта страница противопоставляет ручное
сопровождение этой конфигурации управлению ею с помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Написание правил | Вручную редактировать один `GEMINI.md` | Отрендерено: общие правила встроены в `GEMINI.md` |
| Поддержание правил согласованными с другими средами | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Установка / удаление конфигурации | Писать и удалять `GEMINI.md` вручную | `apothem install` / `apothem uninstall` |
| Проверка корректности конфигурации | Ручная инспекция | `apothem verify --harness gemini-cli` |

## Чем управляет Apothem

Адаптер gemini-cli встраивает общие правила в единственный `GEMINI.md`. У Gemini
CLI нет хука PreToolUse, поэтому намерение ограждающих барьеров выражается в
тексте правил, а не в точке перехвата вызова инструмента. Каждое изменение в
общих правилах повторно рендерит `GEMINI.md` при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы ещё этого не сделали.
2. Перенесите правила из вашего существующего `GEMINI.md` в общий корпус.
3. Выполните `apothem install --harness gemini-cli`, чтобы отрендерить и записать `GEMINI.md`.
4. Выполните `apothem verify --harness gemini-cli`, чтобы подтвердить, что конфигурация на месте.
5. Используйте `apothem update --harness gemini-cli` для каждого последующего изменения.
