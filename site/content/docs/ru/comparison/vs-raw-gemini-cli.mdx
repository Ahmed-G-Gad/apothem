Gemini CLI читает единственный файл правил `GEMINI.md`. Адаптер gemini-cli в
Apothem рендерит его из общего профиля. Эта страница противопоставляет ручное
сопровождение этой конфигурации управлению ею с помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать правила | Вручную редактировать один `GEMINI.md` | Отрендерено: указания для всего проекта в `GEMINI.md`; правила в `.gemini/.apothem/support/` |
| Поддерживать правила согласованными с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Установка / удаление конфигурации | Записывать и удалять `GEMINI.md` вручную | `apothem install` / `apothem uninstall` |
| Проверка корректности конфигурации | Ручная инспекция | `apothem verify --harness gemini-cli --project <path>` |

## Чем управляет Apothem

Адаптер gemini-cli записывает блок Apothem, ограниченный маркерами, в `<project>/GEMINI.md`: он содержит указания для всего проекта и ссылается на материалы Apothem. Правила, шаблоны и хуки помещаются в `<project>/.gemini/.apothem/support/` в виде файлов поддержки, а команды, навыки и агенты — в `<project>/.gemini/`. У Gemini CLI нет хука PreToolUse, поэтому намерение защитных ограничений выражается в тексте правил, а не в точке перехвата вызова инструмента. Каждое изменение общих правил повторно отрендерит `GEMINI.md` при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если вы этого ещё не сделали.
2. Перенесите правила из существующего `GEMINI.md` в общий корпус.
3. Выполните `apothem install --harness gemini-cli --project <path>`, чтобы отрендерить и записать `GEMINI.md`.
4. Выполните `apothem verify --harness gemini-cli --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Для каждого последующего изменения используйте `apothem update --harness gemini-cli --project <path>`.
