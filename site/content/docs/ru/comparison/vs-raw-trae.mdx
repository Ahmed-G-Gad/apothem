Trae читает правила из каталога `.trae/rules/`, чьи якоря поставщика —
`project_rules.md` и `user_rules.md`. Адаптер trae в Apothem рендерит в этом каталоге
выделенный файл `apothem-rules.md` из общего профиля. Эта страница противопоставляет
ручное сопровождение этой конфигурации управлению ею с помощью Apothem.

## Сравнение усилий

| Задача | Ручная конфигурация | Под управлением Apothem |
| ---- | --------------- | --------------- |
| Писать правила | Вручную писать каждый файл в `.trae/rules/` | Отрендерено из общего корпуса |
| Держать поверхность Apothem отдельно | Не забывать не перегружать `project_rules.md` | Адаптер пишет выделенный `apothem-rules.md` |
| Поддерживать правила согласованными с другими окружениями | Вручную, для каждого инструмента | Автоматически при `apothem update` |
| Проверять корректность конфигурации | Ручная инспекция | `apothem verify --harness trae --project <path>` |

## Чем управляет Apothem

Адаптер trae рендерит общие правила в выделенный файл `apothem-rules.md` в
`.trae/rules/` и оставляет нетронутыми принадлежащие оператору якоря `project_rules.md`
и `user_rules.md`. У Trae нет хука PreToolUse, поэтому намерение защитного ограждения
живёт в прозе правил, а не в точке перехвата вызова инструмента. Каждое изменение в
общих правилах заново рендерит файл при следующем `apothem update`.

## Путь миграции

1. Выполните `apothem profile init`, чтобы создать общий профиль, если у вас его ещё нет.
2. Перенесите правила из существующих файлов `.trae/rules/` в общий корпус.
3. Выполните `apothem install --harness trae --project <path>`, чтобы отрендерить файл `apothem-rules.md`.
4. Выполните `apothem verify --harness trae --project <path>`, чтобы подтвердить, что конфигурация установлена.
5. Для каждого последующего изменения используйте `apothem update --harness trae --project <path>`.
