Apothem поставляется с двумя скриптами установщика, которые вместе покрывают
современную матрицу настольных систем и серверов разработчика. Платформо-специфичной
сборки нет: движок — это [самодостаточная среда выполнения](/docs/architecture/self-contained-runtime),
которая работает из своего дерева исходного кода со встроенными зависимостями,
поэтому поддержка платформ — это в точности набор хостов, где один из двух
установщиков может разместить это дерево и запустить его. Два других пути установки
расширяют матрицу ещё сильнее: плагин Claude Code работает везде, где работает
Claude Code, а форма npx (`npx @ahmed-g-gad/apothem`) работает на любой ОС с
Node.js 18+.

## Матрица операционных систем и оболочек

| Семейство ОС | Поддерживаемые оболочки | Скрипт установщика |
| --------- | ---------------- | ---------------- |
| macOS | POSIX `bash` (системный bash или более новый bash, установленный пользователем) | `install.sh` |
| Linux | POSIX `bash` | `install.sh` |
| Подсистема Windows для Linux (WSL2) | POSIX `bash` | `install.sh` |
| BSD (FreeBSD, OpenBSD, NetBSD) | POSIX `bash` | `install.sh` |
| Termux (Android) | POSIX `bash` | `install.sh` |
| Контейнер Linux ChromeOS (Crostini) | POSIX `bash` | `install.sh` |
| Windows | Windows PowerShell 5.1+ | `install.ps1` |
| Любая платформа с PowerShell 7+ | PowerShell 7+ (кроссплатформенный) | `install.ps1` |

Два скрипта функционально эквивалентны друг другу. `install.sh` требует POSIX
`bash`. `install.ps1` требует Windows PowerShell 5.1 или новее, либо PowerShell 7+
на любой платформе, поддерживаемой самим PowerShell 7 — включая macOS и Linux, где
он является альтернативой `install.sh`.

## Единственное требование: системный Python

Apothem не устанавливает пакетов Python. Импорты движка выполняются против
интерпретатора, который у вас уже есть, со встроенным исходным кодом, добавленным в
начало `PYTHONPATH`. Каждый установщик проверяет это требование, прежде чем делать
что-либо ещё:

- **CPython 3.10 или новее.** Установщик прощупывает `python3`, `python` и имена с
  версиями (от `python3.14` до `python3.10`), принимая первый, который сообщает
  версию ≥ 3.10. В Windows он отвергает обёртки запуска из Microsoft Store, и
  встроенный локатор `find-python` применяет ту же нижнюю границу.
- **Библиотеки времени выполнения импортируемы.** Движок импортирует `click` и `rich` из системного интерпретатора; остальные сторонние зависимости встроены (vendored) в дерево исходного кода. Установщик проверяет, что обе импортируемы, называет любую отсутствующую и предлагает установить недостающие зависимости за вас — с вашим подтверждением или автоматически с `--yes` / `APOTHEM_AUTO_INSTALL_DEPS=1`.
- **`git`** нужен только для сетевой установки (скрипт клонирует дерево исходного
  кода). Локальная установка из извлечённой копии не требует `git`.

Если интерпретатор, библиотеки или `git` отсутствуют, установщик завершается с
диагностикой, называющей в точности то, что нужно предоставить, вместо того чтобы
угадывать или изменять ваше окружение.

## Как платформа становится поддерживаемой

Платформа поддерживается, когда выполняются оба условия:

1. Один из двух установщиков работает на ней — то есть на хосте есть POSIX
   `bash` (`install.sh`) или поддерживаемый PowerShell (`install.ps1`).
2. На ней работает интерпретатор CPython 3.10+ с импортируемыми `click` и
   `rich`.

Нет скомпилированного компонента, нет нативного расширения и нет платформо-специфичного
бинарного файла. Одно и то же дерево исходного кода работает везде, где работает
интерпретатор, поэтому приведённая выше матрица является полным, точным изложением
поддержки — ничего сверх этого не заявляется.

## Рекомендуемый следующий шаг

**Запустите установщик для вашей платформы** — `curl -fsSL https://apothem.ahmedgad.com/install.sh | bash` в POSIX-оболочке или `irm https://apothem.ahmedgad.com/install.ps1 | iex` в PowerShell — после подтверждения того, что интерпретатор CPython 3.10+ есть в вашем PATH.
