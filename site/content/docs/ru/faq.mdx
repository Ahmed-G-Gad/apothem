Распространённые вопросы, в порядке частоты.

## Что такое `apothem`?

Переносимая, не зависящая от хоста конфигурация, которая превращает ваш домашний
каталог в фреймворк управления, генерации идей и автоматизации
для разработки под управлением ассистента по написанию кода. Она объединяет поведенческие правила, творческие
стандарты, слэш-команды, постоянных делегированных исполнителей, хуки и навыки
в единую согласованную поверхность.

## С какими CLI ассистентов по написанию кода она работает?

Apothem не зависит от окружения. Адаптеры для конкретных окружений в каталоге
`src/apothem/harnesses/<harness>/` проецируют общий профиль в
нативный каталог конфигурации каждого инструмента; канонический список находится по адресу
[`site/content/docs/harnesses/`](/docs/harnesses) и в настоящее время охватывает следующие поддерживаемые окружения:

```text
Claude Code, GitHub Copilot, Cursor, Gemini CLI, Codex, Windsurf, OpenCode,
Antigravity, Open-Claw, Hermes, Qwen Code, CodeBuddy, Kiro, Trae, and Zed
```

Адаптер Claude Code материализуется в `~/.claude/`; его диспетчер хуков нейтрален к хосту —
он разрешает корень экосистемы сначала из `$CLAUDE_PROJECT_DIR`, затем
из `$LLM_PROJECT_DIR`, а затем откатывается к `$HOME/.claude`.

## Обязательно ли использовать конвейер наборов планов?

Нет. Конвейер наборов планов — это один из компонентов экосистемы.
Поведенческие правила, творческие стандарты, хуки и набор инструментов
валидаторов полезны сами по себе.

## Как настроить правила без форка репозитория?

Добавьте собственный файл правила в `src/apothem/rules/<my-rule>.md`
с каноническим frontmatter. Загрузчик правил подхватывает каждый
файл, соответствующий шаблону `src/apothem/rules/*.md`.

## Как временно отключить правило?

Либо переименуйте файл так, чтобы он не соответствовал шаблону `src/apothem/rules/*.md`,
либо переместите его в соседний каталог, который загрузчик не
сканирует.

## В чём разница между правилами, навыками и делегированными исполнителями?

- **Правила** управляют поведением — всегда активные или фильтруемые по пути
  обязательства, которым следует ассистент.
- **Навыки** — это переиспользуемые обнаруживаемые техники: сигнал
  обнаружения, процедура и хук обеспечения соблюдения.
- **Делегированные исполнители** — это постоянные роли с собственными ограничениями
  инструментов и системными подсказками, диспетчеризуемые через
  протокол оркестрации исполнителей.

## Как сообщить о проблеме безопасности?

См. `SECURITY.md`. Поддерживаемые каналы — это GitHub Security
Advisories и `me@ahmedgad.com`.

## Как внести вклад?

См. [Внесение вклада](/docs/developer-guide). Кратко: прочитайте
`CONTRIBUTING.md`, сделайте форк репозитория, откройте PR с заполненным
каноническим шаблоном PR и убедитесь, что десять классов проверок CI
проходят.

## Где хранится состояние экосистемы?

- **Состояние планов по набору** хранится в `<project>/.apothem/plans/{suite}/`.
- **Память по проекту** хранится в `projects/{hash}/memory/`.
- **Межпроектная память** хранится в `memory/`.
- **Черновики по сессии** хранятся в `<project>/.apothem/plans/{suite}/_inputs/`.

## Могу ли я продолжить длительную работу в новой сессии или на другой машине?

Да. Длительная работа выносит своё полное состояние в локальный для проекта
набор `.apothem/plans/` — контракт возобновления плюс протокол холодного старта —, так
что работа не живёт внутри одной истории чата. Поскольку состояние находится в
файлах вашего проекта, новая сессия на любой учётной записи или машине,
указывающая на тот же проект, продолжает работу на месте. Apothem сам не
переносит файлы между учётными записями; они перемещаются так же, как уже
перемещаются файлы вашего проекта (контроль версий, общая рабочая копия,
синхронизируемый каталог). См. [Возобновляемое планирование](/docs/concepts/resumable-planning).

## Нужен ли Apothem pip?

Нет — не для самого движка. Движок — это самодостаточное дерево исходного кода с
поставляемыми зависимостями — он запускается как `python -m apothem` из любого
извлечённого дерева, кэша npx или дерева плагина на системном Python 3.10+ и не
устанавливает никакого собственного кода в `site-packages` (`click` и `rich` —
единственные предварительные требования к интерпретатору). Единственное
необязательное исключение: если `click` или `rich` отсутствует, установщик
предлагает выполнить `pip install` только для этих двух за вас — с вашего
подтверждения или через `--yes` / `APOTHEM_AUTO_INSTALL_DEPS=1`. Собственные
пакеты Apothem никогда не устанавливаются в `site-packages`.

## Как хуки работают без установленного пакета?

`apothem install` материализует диспетчер хуков и шлюз соответствия
в корне окружения (для Claude Code: `~/.claude/.apothem/support/hooks/` и
`~/.claude/.apothem/support/conformity/`), а отрисованные записи хуков вызывают эти
скрипты по абсолютному пути. Оба являются автономными скриптами на стандартной библиотеке, поэтому хуки
работают на машине, которая никогда не видела `pip install`.

## Как полностью удалить?

Запустите `apothem uninstall --harness <name>` для каждого установленного окружения, удалите
движок согласно вашему каналу установки и удалите `~/.apothem/` (резервные копии) плюс
`~/.config/apothem/` (ваш профиль), если хотите нулевой остаток.
[Руководство по удалению](/docs/install/uninstalling) проходит по каждому каналу.
