Шлюз запускает только машинно проверяемые валидаторы. Обоснованное суждение, которого требуют пункты класса «Обоснованный», и обоснованная часть каждого пункта класса «Механический + обоснованный» оцениваются в ходе ревью.

## Шкала тяжести

У шлюза нет шкалы «Критический», «Важный» или «Рекомендательный» и нет порога в две находки. Без `--strict` (или `APOTHEM_CONFORMITY_STRICT=1`) шлюз сообщает о находках и завершается с кодом `0`. С `--strict` проверка одного файла или хука завершается с кодом `2`, если не проходит какой-либо сопоставитель, а запуск по всему корпусу (`--all` или `--all-perwrite`) завершается с кодом `2`, если не проходит блокирующий валидатор или сопоставитель; рекомендательные находки только выводятся в отчёт. Установленный хук Write/Edit не передаёт `--strict`, поэтому он сообщает о находках и запись продолжается, если только `APOTHEM_CONFORMITY_STRICT=1` не задана в его переменных окружения.

## Валидаторы

Механическая часть находится в [`src/apothem/conformity/`](https://github.com/ahmed-g-gad/apothem/tree/main/src/apothem/conformity), а оркестрирует её [`src/apothem/conformity/gate.py`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/conformity/gate.py).
Каждый валидатор запускается одним из трёх способов:

- **per-write**: при каждой ожидающей записи (`--hook`) или для каждого отслеживаемого файла с `--all-perwrite`.
- **standalone**: по всему репозиторию с `--all` или по одному с `--check <name>`.
- **change-set**: по проиндексированному diff, запускается напрямую как `python -m apothem.conformity.semver_stability_grep --staged`, а не через шлюз.

## Запуск шлюза

В установленном окружении шлюз запускается автоматически: `settings.json`
Claude Code подключает его как хук `PreToolUse`, который перед каждым Write/Edit
вызывает материализованную копию в `~/.claude/.apothem/support/conformity/gate.py`.
Затем шлюз проверяет только записи в пределах области действия своего хука, а
запись вне этой области проходит молча; [Запуск шлюза соответствия](/docs/usage/conformity-gate)
перечисляет эту область. В чекауте исходного кода тот же код запускается через
модульную форму; перед каждой командой `python` ниже добавляйте `PYTHONPATH=src`.
По умолчанию шлюз рекомендательный: он сообщает о находках и завершается с кодом
`0`. Добавьте `--strict`, чтобы завершаться с кодом `2` при блокирующей находке.
Неизвестное имя валидатора приводит к завершению с кодом `3`.

```shell
# Every standalone validator across the repository:
python -m apothem.conformity.gate --all .

# The same sweep, failing on a blocking finding (the CI form):
python -m apothem.conformity.gate --all --strict .

# Every per-write validator against every tracked file:
python -m apothem.conformity.gate --all-perwrite .

# One validator by name (names come from --list):
python -m apothem.conformity.gate --check naming-grep .

# List every registered validator as JSON:
python -m apothem.conformity.gate --list

# Single-file dispatch (mimics the PreToolUse hook):
echo '{"tool_input": {"file_path": "path/to/file", "content": "..."}}' \
    | python -m apothem.conformity.gate --hook
```

`python -m apothem.conformity.gate --help` выводит краткую справку по использованию.
Полную процедуру см. в [Запуск шлюза соответствия](/docs/usage/conformity-gate).
