Пошаговые руководства, ориентированные на задачи, по **созданию артефактов Apothem и управлению конвейером планов**. Каждое руководство отвечает на один конкретный вопрос.

Для рецептов первоначальной настройки — добавления окружения, редактирования профиля, запуска установщика — см. вместо этого раздел [Практические рецепты](/docs/how-to).

## Конвейер набора планов

### Как доработать сырой контент в спецификацию?

Вызовите `/plan-spec` с сырым контентом в качестве входных данных. Роль Forge выполняет шесть фаз преобразования (Discovery, Meticulous Consideration, Potency Mapping, Preservation Verification, Expertise Application, Question-Resolution Sweep) и выдаёт консолидированную спецификацию в `.apothem/plans/{suite}/_spec/spec.md`. Полный протокол см. в `src/apothem/commands/plan-spec.md`.

### Как сгенерировать набор планов из спецификации?

Вызовите `/plan-generate .apothem/plans/{suite}/_spec/spec.md` после того, как `/plan-spec` запишет спецификацию. Генератор выдаёт канонические инфраструктурные файлы и пофазные файлы `phases/NN-kebab-topic/PHASE.md`. См. `src/apothem/commands/plan-generate.md`.

### Как проверить сгенерированный план?

Вызовите `/plan-review path/to/plan-suite/`. Проверяющий применяет девять методик планирования и выдаёт оценочные карты. Проваленные оценочные карты блокируют выполнение на уровне SHARED+ до устранения. См. `src/apothem/commands/plan-review.md`.

### Как выполнить план?

Вызовите `/plan-execute path/to/plan-suite/ [phase-id]`. Без `phase-id` выполняется следующая ожидающая фаза. С конкретным идентификатором выполняется только эта фаза. См. `src/apothem/commands/plan-execute.md`.

### Как проверить статус плана?

Вызовите `/plan-status path/to/plan-suite/ [--verbose]`. Отчёт только для чтения. См. `src/apothem/commands/plan-status.md`.

## Создание артефактов

### Как добавить новое правило?

1. Выберите имя файла в формате kebab-case в каталоге `src/apothem/rules/`, например `src/apothem/rules/my-new-rule.md`.
2. Создайте фронтматтер (`name`, `description`, `pathFilter`, `alwaysApply`).
3. Напишите тело с каноническими разделами: Purpose, Obligations, Seriousness Scaling, Anti-Patterns, Enforcement, Bindings.
4. Запустите `python scripts/dev/validate_ecosystem.py --check frontmatter-cohort` для проверки.

Загрузчик правил работает на основе glob-шаблонов: он подхватывает каждый файл, соответствующий `src/apothem/rules/*.md`, поэтому запись в реестре не нужна. Достаточно поместить файл с каноническим именем в этот каталог — это и есть вся регистрация.

### Как добавить нового делегированного исполнителя?

Выберите имя файла в формате kebab-case в каталоге, показанном ниже, используя форму `my-worker.md`:

```text
src/apothem/agents/
src/apothem/agents/my-worker.md
```

Затем:

1. Создайте фронтматтер — включая `name`, `version`, `updated`, `description`, `tools`, `disallowedTools`, `maxTurns` и `effort`.

2. Напишите системный промпт в качестве тела.

Группа делегированных исполнителей загружается по glob-шаблону из `src/apothem/agents/*.md`, поэтому файл с каноническим именем подхватывается сразу после размещения — редактировать таблицу реестра не нужно.

### Как добавить новый хук?

1. Создайте контекстное сообщение в `src/apothem/hooks/messages/<event>-<scope>.md`.
2. Подключите хук в `settings.json`.
3. Обновите конвейер хуков.
4. Запустите `python scripts/dev/validate_ecosystem.py`.

## Шлюзы качества

### Как запустить локальные шлюзы качества?

```bash
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/dev/validate_ecosystem.py
python scripts/dev/chaos_pass.py
```

Конвейер CI запускает тот же набор параллельно.

### Как проверить фронтматтер одного класса артефактов?

```bash
python scripts/dev/validate_ecosystem.py --check frontmatter-cohort
```
