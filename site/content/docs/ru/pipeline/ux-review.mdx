**Роль:** Рецензент UX
**Позиция в конвейере:** последовательность аудиторских проверок

Обзор опыта разработчика по эргономике CLI, документации и онбордингу.

## Каноническое обращение

```bash
/ux-review
```

С аргументами:

```bash
/ux-review [path/to/repo/] [--focus SURFACE] [--dry-run]
```

## Входы

Развёрнутый репозиторий хоста с README, скриптами установки и точкой входа CLI

## Выходы

Находки UX в `_inputs/ux-review-findings.md`

## Ниже по течению

Этап обзора UX последовательности аудита и обзора

## Фазы рабочего процесса

Команда выполняет пять фаз: приём входных данных, проход по эргономике CLI, аудит потока установки и восстановления после ошибок, сканирование обнаруживаемости документации и выпуск находок с шлюзом валидации.

## Режимы отказа

| Симптом | Причина | Восстановление |
|---------|-------|----------|
| Предпосылка не выполнена | Зависимая фаза не завершена | Сначала завершите вышестоящую фазу |
| Шлюз качества FAIL | Выход не соответствует стандартам | Исправьте выход и перезапустите |
| Цель не развёрнута | В цели нет поверхности, обращённой к оператору | Передайте корень развёрнутого репозитория |

## Примеры

```bash
# Dry-run to preview what would happen
/ux-review --dry-run

# Execute against a host repository
/ux-review path/to/repo/
```
