**Роль:** Главный исследователь (проектирование исследования)
**Позиция в конвейере:** середина цепочки

Операционализирует гипотезы в проверяемые предсказания и проектирует исследование или эксперимент — переменные, контроли, выборку, инструменты, анализ мощности, угрозы валидности — затем создаёт предрегистрацию, которая замораживает план анализа до сбора данных.

## Каноническое обращение

```bash
/research-design
```

С аргументами:

```bash
/research-design [path/to/research-suite/]
```

## Входы

`_inputs/proposal.md` (план-запись из `/research-proposal`, предшествующего этапа), `_inputs/synthesis.md` (карта SOTA + формулировка пробела) и `_spec/research-spec.md` (гипотезы).

## Выходы

`_inputs/study-design.md` (операционализированные предсказания, спецификация переменных, контроли, выборка, инструменты, анализ мощности, угрозы валидности) + `_inputs/preregistration.md` (замороженный план анализа).

## Ниже по потоку

/research-experiment (потребитель ниже по потоку)

## Этапы рабочего процесса

Команда следует стандартному рабочему процессу конвейера `/research`:

1. **Загрузить контекст** — Прочитать синтез и гипотезы спецификации.
2. **Проверить Шлюз последовательности** — Подтвердить, что `_inputs/proposal.md` (и вышестоящие `_inputs/synthesis.md` и `_spec/research-spec.md`) существует; иначе остановиться с `Blocked: run /research-proposal first`.
3. **Спроектировать исследование** — Операционализировать предсказания; задать переменные, контроли, выборку, инструменты, мощность; перечислить угрозы валидности.
4. **Предрегистрировать** — Заморозить план анализа до любого сбора данных.
5. **Обновить манифест передачи** — Записать пути проекта исследования и предрегистрации.
6. **Выдать проект** — `_inputs/study-design.md` + `_inputs/preregistration.md`.

## Нижняя граница строгости

Для исследования, несущего сравнение, проект фиксирует и предрегистрирует эмпирическую нижнюю границу: единый унифицированный бюджет на все сравниваемые методы (равное настенное время и, где это осмысленно, равное число оценок), не менее тридцати повторений на экземпляр для стохастических методов, фактор абляции, отключающий по одному компоненту за раз, развёртки чувствительности по каждому параметру и автоматизированную конфигурацию на обучающем разбиении с оценкой на непересекающемся тестовом разбиении. Глубина нижней границы масштабируется под амбицию целевой площадки.

## Режимы отказа

| Симптом | Причина | Восстановление |
|---------|-------|----------|
| Blocked: run /research-proposal first | Нет плана-записи | Выполните `/research-proposal`, чтобы создать `_inputs/proposal.md` |
| Недостаточно мощный проект | Выборка слишком мала для эффекта | Заново выполните анализ мощности; измените размер выборки |
| План анализа не заморожен | Предрегистрация пропущена | Составьте `_inputs/preregistration.md` до сбора данных |

## Примеры

```bash
# Спроектируйте исследование и предрегистрируйте план анализа
/research-design path/to/research-suite/
```
