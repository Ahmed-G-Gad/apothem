**Роль:** Главный исследователь (оформление)
**Позиция в конвейере:** середина цепочки

Оформляет свободно сформулированный исследовательский вопрос или сырые заметки в `_spec/research-spec.md` уровня spec — проверяемый, фальсифицируемый набор гипотез с явной областью, критериями включения / исключения и метриками успеха — готовый для `/research-theory`.

## Каноническое обращение

```bash
/research-spec
```

С аргументами:

```bash
/research-spec [path/to/question-or-notes] [--suite-name NAME] [--quick SLUG]
```

## Входные данные

Свободно сформулированный исследовательский вопрос или сырые заметки (предоставленные оператором встроенно или в виде пути).

## Выходные данные

`_spec/research-spec.md` (вопрос, фальсифицируемые гипотезы, область, критерии включения / исключения, метрики успеха, глоссарий) + `_inputs/handoff-manifest.yml`. `--quick` вместо этого записывает облегчённую исследовательскую сводку, локальную для проекта.

## Ниже по потоку

/research-theory (потребитель ниже по потоку)

## Фазы рабочего процесса

Команда следует стандартному рабочему процессу конвейера `/research`:

1. **Загрузить контекст** — Прочитать вопрос / заметки, правила и любое существующее состояние набора.
2. **Оформить вопрос** — Разложить на фальсифицируемые гипотезы с явной областью и критериями включения / исключения; вывести каждую неоднозначность через канал структурированного запроса.
3. **Задать метрики успеха** — Указать измеримые критерии, по которым будет оцениваться исследование.
4. **Проверить выходные данные** — Подтвердить, что спецификация определённа (каждый пробел в авторитетных данных закрыт через канал структурированного запроса, ни один не оставлен как незаполненный заполнитель подтверждения) и проходит нижнюю границу мандата строгости.
5. **Обновить манифест передачи** — Записать путь к спецификации и счётчики открытых / решённых запросов.
6. **Выпустить спецификацию** — `_spec/research-spec.md` плюс манифест передачи.

## Нижняя граница строгости

Каждый заявленный вклад ограничен требованием быть отчётливым, существенным и независимо аблируемым, так чтобы его предельный эффект можно было позднее изолировать. Глубина требуемой нижней границы строгости масштабируется под амбицию целевой площадки; там, где эта амбиция не указана, она подтверждается через канал структурированного запроса, а не выдумывается.

## Режимы отказа

| Симптом | Причина | Восстановление |
|---------|-------|----------|
| Неразрешённая неоднозначность гипотезы | Вопрос недоопределён | Вывести через структурированный запрос; не выдумывать область |
| Нет измеримой метрики успеха | Цель сформулирована как деятельность, а не как результат | Переоформить как проверяемый, фальсифицируемый результат |
| Отсутствует входной вопрос | Не предоставлен текст / заметки | Предоставить исследовательский вопрос встроенно или в виде пути |

## Примеры

```bash
# Frame a question into a research spec
/research-spec ~/notes/retrieval-latency-study.md --suite-name retrieval-latency

# Lightweight project-local research brief
/research-spec --quick retrieval-latency
```
