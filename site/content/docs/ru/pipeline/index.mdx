Apothem поставляет учитывающий архитектуру конвейер `/plan`, тринадцатиэтапный
конвейер `/research`, а также последовательность аудита из одиннадцати команд —
это даёт каждому проекту структурированный путь от сырой прозы к коду
продакшен-уровня, проверенному по множеству осей, и от сырой идеи к
распространённой статье, прошедшей рецензирование.

## Обзор конвейера

```mermaid
flowchart LR
    accTitle: Plan pipeline command flow
    accDescr: Left-to-right flowchart of the apothem plan pipeline from the spec stage through the generate and review stages, then through a conditional architecture-bearing decision that either runs the design stage or skips directly to the execute stage. The orthogonal audit stage wraps the spec-through-review span as a closed remediation loop, and the re-entrant amend stage revises an existing suite and returns it to review.
    A[/plan-spec] --> B[/plan-generate]
    B --> C[/plan-review]
    AUD[/plan-audit<br/>orthogonal: wraps spec → review] -.->|closed-loop remediation| A
    AM[/plan-amend<br/>re-entrant: revises an existing suite] -.->|re-review| C
    C --> Q{Architecture-bearing suite?}
    Q -->|yes| F[/plan-design<br/>emit _inputs/design.md]
    Q -->|no| D[/plan-execute]
    F --> D
    D --> E[/plan-status]
    D --> G[Audit review sequence]
    G --> H[Completion milestone]
```

## Этапы планирования

Конвейер поставляется в виде восьми полноценных слэш-команд, по одной на этап;
каждую можно вызвать независимо как `/plan-<stage>`. Оркестратор
[/plan](/docs/pipeline/plan) ведёт их от миссии до выполненного набора планов.

| Этап | Роль | Позиция |
|-------|------|----------|
| [/plan-spec](/docs/pipeline/plan-spec) | Кузница — от прозы к спецификации | Начальный |
| [/plan-generate](/docs/pipeline/plan-generate) | Генератор — от спецификации к набору планов | Промежуточный |
| [/plan-review](/docs/pipeline/plan-review) | Аудитор — криминалистический аудит плана | Промежуточный |
| [/plan-design](/docs/pipeline/plan-design) | Архитектор — `_inputs/design.md` для наборов планов, затрагивающих архитектуру | Условный шлюз |
| [/plan-execute](/docs/pipeline/plan-execute) | Исполнитель — выполнение фаз | Конечный |
| [/plan-status](/docs/pipeline/plan-status) | Докладчик — статус только для чтения | Только чтение |
| [/plan-audit](/docs/pipeline/plan-audit) | Страж — обёртка замкнутого цикла вокруг spec → generate → review | Ортогональный (до выполнения) |
| [/plan-amend](/docs/pipeline/plan-amend) | Распорядитель — повторно входимая правка существующего набора планов | Повторно входимый |

`/plan-audit` ортогонален линейному потоку и не является этапом внутри него. Он
оборачивает `/plan-spec → /plan-generate → /plan-review` в единый замкнутый
цикл, запускает только недостающие предшествующие этапы, активно устраняет
находки и оставляет набор планов готовым к `/plan-execute`. Он отличается от описанной
ниже последовательности аудита, которая проверяет выполненную кодовую базу, а
не набор планов.

`/plan-design` — не универсальная церемония. `/plan-review` определяет,
изменяет ли набор планов поверхности, затрагивающие архитектуру. Если да,
`/plan-design` выпускает трассу проектирования, которую используют
`/plan-execute` и `/architecture-review`. Если нет, проверенный набор планов переходит
непосредственно к выполнению.

## Исследовательский конвейер

Исследовательский конвейер поставляется в виде тринадцати полноценных
слэш-команд, по одной на этап; каждую можно вызвать независимо как
`/research-<stage>`, а связывают их Шлюз последовательности и Манифест
передачи, под действием десяти мандатов строгости (авторитетные источники,
воспроизводимость, фальсифицируемость, целостность цитирования,
предрегистрация, этика / конфликты интересов, статистическая строгость,
открытая наука / FAIR, соответствие руководствам по отчётности, теоретическая
обоснованность / влияние).

```mermaid
flowchart LR
    accTitle: Research pipeline command flow
    accDescr: Left-to-right flowchart of the apothem research pipeline from the ideate stage through spec, theory, sources, synthesis, proposal, study design, experiment, analysis, paper, and peer review to publish and disseminate, with a revision loop from review back to paper.
    RI[/research-ideate] --> RS[/research-spec]
    RS --> RT[/research-theory]
    RT --> RSO[/research-sources]
    RSO --> RSY[/research-synthesis]
    RSY --> RPR[/research-proposal]
    RPR --> RD[/research-design]
    RD --> RE[/research-experiment]
    RE --> RA[/research-analysis]
    RA --> RP[/research-paper]
    RP --> RR[/research-review]
    RR --> RPU[/research-publish]
    RPU --> RDI[/research-disseminate]
    RR -.->|revision loop| RP
```

| Этап | Роль | Позиция |
|-------|------|----------|
| [/research-ideate](/docs/pipeline/research-ideate) | Сформулировать проблему — вопросы-кандидаты из затравки предметной области | Начальный |
| [/research-spec](/docs/pipeline/research-spec) | Сформулировать вопрос — фальсифицируемые гипотезы + границы | Промежуточный |
| [/research-theory](/docs/pipeline/research-theory) | Концептуальная рамка + теория изменений | Промежуточный |
| [/research-sources](/docs/pipeline/research-sources) | Систематический сбор источников | Промежуточный |
| [/research-synthesis](/docs/pipeline/research-synthesis) | Карта SOTA + анализ пробелов | Промежуточный |
| [/research-proposal](/docs/pipeline/research-proposal) | Цели + осуществимость + влияние + план предрегистрации | Промежуточный |
| [/research-design](/docs/pipeline/research-design) | Проектирование исследования + предрегистрация | Промежуточный |
| [/research-experiment](/docs/pipeline/research-experiment) | Выполнение + запись, воспроизводимо | Промежуточный |
| [/research-analysis](/docs/pipeline/research-analysis) | Результаты + статистика | Промежуточный |
| [/research-paper](/docs/pipeline/research-paper) | Черновик статьи высшего уровня | Промежуточный |
| [/research-review](/docs/pipeline/research-review) | Критика уровня рецензирования | Промежуточный |
| [/research-publish](/docs/pipeline/research-publish) | Пакет для площадки + подача | Промежуточный |
| [/research-disseminate](/docs/pipeline/research-disseminate) | Распространение + влияние + архивирование по FAIR | Конечный |

Оркестратор [/research](/docs/pipeline/research) в виде обёрнутого рабочего
процесса ведёт эти этапы от сырого вопроса до опубликованной статьи (сам он
этапом не является), независимо проверяя результат каждого этапа, прежде чем
следующий этап начнёт на нём строиться; `--quick` запускает только
`/research-sources` + `/research-synthesis` для однократного отчёта с цитатами.

Эмпирические этапы (источники, проектирование, эксперимент, анализ) и этапы написания
(статья, рецензирование, публикация, распространение) дополнительно опираются
на поверхности, операционализирующие строгость, — честное сравнение нескольких
методов, происхождение базовых методов для сравнения, каркас программы
экспериментов, план использования вычислительных ресурсов, включаемый по
желанию автономный цикл экспериментов, шлюз продвижения по критериям
готовности (definition of done) и ослепление с поэтапным раскрытием, — которые
добавляют операционные детали к десяти мандатам, не расширяя их.

## Последовательность аудита

Оркестратор [/audit](/docs/pipeline/audit) в виде обёрнутого рабочего процесса проходит по всем одиннадцати измерениям ниже за один параллельный проход — аналог `/plan` и `/research` для последовательности аудиторских проверок — и синтезирует один дедуплицированный отчёт о находках, отсортированный по серьёзности (только отчёт; устранение передаётся в `/elevate`). Каждое измерение можно также вызвать отдельно.

Оркестратор [/fortress](/docs/pipeline/fortress) в виде обёрнутого рабочего процесса замыкает цикл, о результатах которого сообщает `/audit`: он выявляет проблемы через `/audit`, проверяет каждую находку, устраняет каждую подтвердившуюся находку на поверхности, которой она принадлежит, повторяет аудит в ограниченном цикле и пропускает результат через шлюз [/release-readiness](/docs/pipeline/release-readiness) — аналог `/plan` и `/research` для упрочнения к продакшену.

| Команда | Область качества |
|---------|--------------|
| [/code-review](/docs/pipeline/code-review) | Качество кода |
| [/code-audit](/docs/pipeline/code-audit) | Корпус кода |
| [/security-audit](/docs/pipeline/security-audit) | OWASP / ASVS |
| [/perf-audit](/docs/pipeline/perf-audit) | Производительность |
| [/architecture-review](/docs/pipeline/architecture-review) | Архитектура |
| [/ux-review](/docs/pipeline/ux-review) | Опыт разработчика |
| [/a11y-audit](/docs/pipeline/a11y-audit) | Доступность |
| [/docs-review](/docs/pipeline/docs-review) | Документация |
| [/dependency-audit](/docs/pipeline/dependency-audit) | Зависимости |
| [/supply-chain-audit](/docs/pipeline/supply-chain-audit) | Цепочка поставок |
| [/threat-model-audit](/docs/pipeline/threat-model-audit) | Модель угроз |
