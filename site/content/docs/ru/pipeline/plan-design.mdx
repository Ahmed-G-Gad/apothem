**Роль:** Архитектор
**Позиция в конвейере:** условная, после проверки, до выполнения

Создаёт артефакт архитектурного проектирования в `_inputs/design.md`, когда
набор планов содержит работу, несущую архитектуру. Это намеренно условный шаг:
набор из прозы, документации, метаданных или узких фикстур переходит от
`/plan-review` прямо к `/plan-execute`; набор, изменяющий компоненты,
интерфейсы, схемы, поток данных, адаптеры, топологию выпуска, границы
безопасности или поведение во время выполнения, сначала проходит через
`/plan-design`.

## Каноническое обращение

```bash
/plan-design path/to/plan-suite/
```

С аргументами:

```bash
/plan-design [path/to/plan-suite/] [--refine-existing] [--dry-run]
```

## Входы

Проверенный набор планов + `_spec/spec.md` + `_inputs/handoff-manifest.yml` +
PASS-карточки проверки из `/plan-review`.

## Выходы

`_inputs/design.md` плюс дополненный `_inputs/handoff-manifest.yml`, несущий путь
артефакта проектирования, результат шлюза проектирования, результат покрытия по
семи осям и сводку Матрицы двунаправленных связей.

## Шлюз применимости

Запускайте `/plan-design`, когда хотя бы одна нижестоящая фаза объявляет или
подразумевает:

- Изменения раскладки исходников, границы пакета, границы адаптера или границы
  модуля.
- Публичные интерфейсы, протоколы, схемы, контракты конфигурации или поведение
  CLI.
- Поток данных между компонентами, упорядочивание жизненного цикла, переходы
  состояний или рёбра зависимостей.
- Архитектуру безопасности, производительности, конкурентности,
  наблюдаемости, развёртывания, выпуска или цепочки поставок.
- Последующий проход `/architecture-review`, который должен проследить
  реализацию обратно к артефакту проектирования.

Пропускайте `/plan-design`, когда набор ограничен правками текста, обновлениями
сгенерированной инвентаризации, узкими обновлениями фикстур, разовыми правками
документации или иной работой, реализацию которой можно проверить без
поверхности архитектурной трассировки. Путь пропуска явный: `/plan-review`
фиксирует неархитектурную классификацию, а затем `/plan-execute` продолжает с
проверенного набора планов.

## Ниже по потоку

`/plan-execute` потребляет артефакт проектирования для несущих архитектуру фаз.
`/architecture-review` потребляет тот же артефакт во время Последовательности
аудиторской проверки. Если `_inputs/design.md` отсутствует для работы, несущей
архитектуру, проверка архитектуры останавливается и перенаправляет набор обратно
через `/plan-design`.

## Фазы рабочего процесса

Команда следует шести фазам преобразования, специфичным для архитектуры:

1. **Приём входов** — Читает проверенный набор, карточки, выходы фаз и манифест
   передачи; блокирует при отсутствующих или неуспешных свидетельствах проверки
   на SHARED+.
2. **Архитектурная декомпозиция** — Обходит Архитектуру, Конкурентность,
   Производительность, Безопасность, Тестирование, Tooling и Наблюдаемость;
   выявляет компоненты, рёбра и открытые архитектурные вопросы.
3. **Проектирование интерфейсов компонентов** — Определяет публичные интерфейсы,
   контракты протоколов, схемы, инварианты, режимы отказа и границы инверсии
   зависимостей.
4. **Ратификация межкомпонентных связей** — Закрывает каждое ребро вверх по
   потоку, вниз по потоку, родственное, критериальное и якорное; выдаёт Матрицу
   двунаправленных связей, когда граф компонентов пересекает порог матрицы.
5. **Выдача артефакта проектирования** — Пишет `_inputs/design.md` с разделами
   компонентов, диаграммами, записями решений, результатом валидации и связями.
6. **Шлюз валидации проектирования** — Запускает пятнадцатиполосный шлюз
   предвыпуска; обновляет `_inputs/handoff-manifest.yml` только после того, как
   проектирование прошло.

## Форма артефакта проектирования

Выдаваемый `_inputs/design.md` содержит:

- Сводку с числом компонентов и покрытием по семи осям.
- По одному разделу на каждый основной компонент, упорядоченных от внутренних
  доменных поверхностей к внешним адаптерам и поверхностям оператора.
- Диаграммы Mermaid архитектуры, последовательности, состояния или зависимостей
  там, где структура иначе была бы неоднозначной.
- Установленные записи архитектурных решений с альтернативами, компромиссами и
  заметками об обратимости.
- Результат шлюза валидации и Матрицу двунаправленных связей, когда применимо.
- Собственные пятинаправленные связи артефакта с вышестоящими и нижестоящими
  поверхностями планирования.

## Режимы отказа

| Симптом | Причина | Восстановление |
|---------|-------|----------|
| Предпосылка неполна | Зависимая фаза не завершена | Сначала завершите вышестоящую фазу |
| Шлюз качества FAIL | Выход не соответствует стандартам | Исправьте выход и перезапустите |
| Отсутствует проверенный набор | Набор планов или карточки проверки отсутствуют | Запустите `/plan-generate`, затем `/plan-review` |
| Неархитектурный набор | Ни одной фазе не нужна поверхность архитектурной трассировки | Зафиксируйте пропуск и продолжите к `/plan-execute` |
| Проверка архитектуры блокирует | `_inputs/design.md` отсутствует для несущей архитектуру реализации | Запустите `/plan-design`, затем перезапустите `/architecture-review` |

## Примеры

```bash
# Dry-run для предпросмотра применимости, числа компонентов и открытых вопросов
/plan-design --dry-run

# Выдать проектирование для именованного несущего архитектуру набора
/plan-design path/to/plan-suite/
```
