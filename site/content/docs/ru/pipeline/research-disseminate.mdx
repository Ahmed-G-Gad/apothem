**Роль:** Главный исследователь (распространение и влияние)
**Положение в конвейере:** завершающее

Управляет распространением и влиянием после принятия. Публичные действия выполняет оператор; этап останавливается на готовом плане распространения и никогда не публикует автоматически.

## Каноническое обращение

```bash
/research-disseminate
```

С аргументами:

```bash
/research-disseminate [--suite-name NAME] [--override] [--archive REPO] [--preprint SERVER]
```

## Входные данные

Файл набора `_outputs/publication-record.md` (пакет для площадки + запись о подаче, созданные `/research-publish`).

## Выходные данные

`_outputs/dissemination-plan.md` (анонс препринта, план публичных артефактов с исходными данными каждого доклада, бюджетом времени и списком вопросов и резервных материалов, картой разделов каждого постера, таблицей происхождения рисунков и результатом проверки скомпилированного артефакта, запись о депонировании в FAIR-архив, план altmetrics и отслеживания влияния, цикл ответа / доработки и путь стадии 2 зарегистрированного отчёта).

## Ниже по потоку

Завершающий этап — план распространения является конечным артефактом конвейера. Цикл ответа рецензентам и доработки возвращает исправленную статью через `/research-review` для повторной проверки строгости, после чего повторно вызывается `/research-publish`, чтобы пересобрать пакет.

## Фазы рабочего процесса

Команда следует стандартному рабочему процессу конвейера `/research`:

1. **Загрузить контекст** — Прочитать `_outputs/publication-record.md`, правила и любое существующее состояние набора.
2. **Спланировать препринт и публичные артефакты** — Составить анонс препринта и спланировать каждый доклад и постер по исходным данным, бюджету времени, списку вопросов и резервных материалов и происхождению рисунков, с проверкой скомпилированного PDF для всего, что собрано.
3. **Зафиксировать депонирование в FAIR-архив** — Спланировать депонирование данных + кода в FAIR-репозиторий с постоянными идентификаторами.
4. **Настроить отслеживание влияния** — Спланировать altmetrics и отслеживание влияния относительно пути влияния из предложения.
5. **Подготовить цикл ответа** — Прочитать ограничения площадки для этапа ответа из реестра правил площадки в записи о публикации перед составлением, затем составить ответ рецензентам и, где применимо, путь стадии 2 зарегистрированного отчёта.
6. **Проверить и выпустить** — Подтвердить, что план выполним; выпустить `_outputs/dissemination-plan.md` плюс манифест передачи. Публичные действия выполняет оператор.

## Нижняя граница строгости

Публичные артефакты несут естественный доменный язык; там, где распространение предшествует деанонимизации, идентичность автора, учреждения и системы удерживается до назначенного этапа. FAIR-депозит — это долговечный, цитируемый пакет доказательств воспроизводимости, масштабированный под амбицию площадки, который позволяет независимой стороне воспроизвести исследование.

Доклады и постеры планируются исходя из их исходных данных: длительность слота, вид доклада, аудитория и то, делят ли вопросы слот, запрашиваются, а не предполагаются. Разделы в сумме дают время выступления, а время выступления плюс вопросы в слоте, переходы и резерв в сумме дают слот. Рисунок с данными — это собственный файл статьи или регенерация из записанных данных, а не перерисовка вручную или генеративным инструментом. Ответ, нарушающий заявленное ограничение площадки (предел длины, анонимность файлов ответа, политика ссылок, допуск новых результатов), не называется готовым.

## Режимы отказа

| Симптом | Причина | Восстановление |
|---------|-------|----------|
| Нет записи о депонировании в FAIR | Пропущен шаг архивирования | Выберите FAIR-репозиторий (`--archive`) и зафиксируйте план депонирования с постоянными идентификаторами |
| План пытается опубликовать автоматически | Превышена граница этапа | Остановитесь на готовом плане; каждое публичное действие выполняет оператор |
| Отсутствует запись о публикации | `/research-publish` ещё не запущен | Сначала запустите `/research-publish`, чтобы создать пакет для площадки |
| Перерисованный рисунок с данными в докладе или на постере | Рисунок был нарисован заново вместо повторного использования | Используйте файл статьи или регенерируйте его из записанных данных |
| Бюджет времени доклада не сходится | Слот, время выступления, вопросы или резерв оставлены незапланированными | Запросите исходные данные, затем подберите размер разделов так, чтобы бюджет в сумме давал слот |

## Примеры

```bash
# Спланировать распространение после принятия
/research-disseminate --suite-name retrieval-latency

# Зафиксировать сервер препринтов и FAIR-архив
/research-disseminate --preprint arXiv --archive Zenodo
```
