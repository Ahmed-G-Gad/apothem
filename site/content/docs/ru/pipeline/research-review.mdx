**Роль:** Главный исследователь (рецензирование)
**Позиция в конвейере:** середина цепочки

Подвергает статью состязательной критике на уровне рецензирования по стандартам места публикации — новизна, строгость, воспроизводимость, ясность, этика, статистическая проверка и соответствие правилам отчётности. Выдаёт **семиосевую** оценочную карту рецензента плюс отсортированный по серьёзности список обязательных правок с обоснованием на основе конкретного драйвера для каждой находки. Опровержение по умолчанию.

## Каноническое обращение

```bash
/research-review
```

С аргументами:

```bash
/research-review [path/to/research-suite/]
```

## Входные данные

Поставляемая статья в естественном для хоста расположении, которое зафиксировал этап статьи.

## Выходные данные

`_outputs/review-report.md` — **семиосевая** оценочная карта рецензента (новизна · строгость · воспроизводимость · ясность · этика · статистическая проверка · соответствие правилам отчётности), отсортированный по серьёзности (HIGH / MEDIUM / LOW) список обязательных правок с обоснованием на основе конкретного драйвера для каждой находки, вердикт по пакету воспроизводимости и повторному прогону, аудит целостности цитат и общий вердикт `accept · minor-revision · major-revision · reject`.

## Ниже по потоку

/research-publish (потребитель ниже по потоку). Вердикт `major-revision` или `reject` запускает цикл правок обратно к `/research-paper` для устранения обязательных правок перед повторным рецензированием.

## Фазы рабочего процесса

Команда следует стандартному рабочему процессу конвейера `/research`:

1. **Загрузить контекст** — Прочитать поставляемую статью.
2. **Проверить Шлюз последовательности** — Подтвердить, что статья существует; иначе остановиться с `Blocked: run /research-paper first`.
3. **Состязательное рецензирование** — Оценить семь осей (новизна · строгость · воспроизводимость · ясность · этика · статистическая проверка · соответствие правилам отчётности); выполнить повторный прогон воспроизводимости и аудит целостности цитат; опровержение по умолчанию; локализовать конкретные дефекты с доказательствами.
4. **Сортировать правки** — Ранжировать обязательные правки HIGH / MEDIUM / LOW с обоснованием на основе конкретного драйвера.
5. **Обновить манифест передачи** — Зафиксировать отчёт о рецензии и вердикт оценочной карты.
6. **Выдать рецензию** — `_outputs/review-report.md`.

## Нижняя граница строгости

Рецензия оценивает эмпирические утверждения по планке шлюза продвижения — достаточное воспроизведение, непараметрическая значимость с размером эффекта и рангами критической разности, а также паритет бюджета по сравниваемым методам — и трактует вердикт как явный шлюз продвижения: статья проходит лишь тогда, когда убедительно и значимо превосходит планку площадки, с залогированным прохождением. При площадке с двойным слепым рецензированием рецензент также помечает любую утечку идентичности как дефект анонимизации.

## Режимы отказа

| Симптом | Причина | Восстановление |
|---------|-------|----------|
| Blocked: run /research-paper first | Нет статьи | Запустите `/research-paper`, чтобы создать рукопись |
| Снисходительная оценка | Рецензент предположил лучший случай | Опровержение по умолчанию; оценивайте по имеющимся доказательствам |
| Находка без обоснования | Правка утверждается, но не обоснована | Приложите к каждой находке обоснование на основе конкретного драйвера |

## Примеры

```bash
# Отрецензировать статью и выдать оценочную карту рецензента
/research-review path/to/research-suite/
```
