**Роль:** Главный исследователь (публикация)
**Позиция в конвейере:** середина цепочки

Форматирует статью по шаблону площадки и собирает пакет для подачи — дополнительные материалы, заявление о доступности данных / кода, сопроводительное письмо, заявления об этике и конфликте интересов — плюс план препринта / архивирования с DOI и контрольный список подачи. Оператор подаёт пакет; конечный преемник — `/research-disseminate`, который доносит опубликованную работу до её аудитории.

## Каноническое обращение

```bash
/research-publish
```

С аргументами:

```bash
/research-publish [--suite-name NAME]
```

## Входные данные

Поставляемая статья и `_outputs/review-report.md` (правки рецензирования и его список неоценённых).

## Выходные данные

Отформатированный по площадке пакет для подачи в естественном для хоста месте (отформатированная рукопись + дополнительные материалы + заявление о доступности данных / кода + сопроводительное письмо + заявления об этике / конфликте интересов) + `_outputs/publication-record.md` (включая датированный реестр правил площадки: каждое правило с его официальной страницей-источником, датой прочтения и этапом подачи) + контрольный список подачи.

## Ниже по потоку

/research-disseminate (потребитель ниже по потоку) — подачу выполняет оператор, затем `/research-disseminate` доносит опубликованную работу до её аудитории. Когда площадка возвращает правки, снова запустите `/research-review` против исправленной статьи перед пересборкой пакета.

## Фазы рабочего процесса

Команда следует стандартному рабочему процессу конвейера `/research`:

1. **Загрузить контекст** — Прочитать статью и отчёт о рецензировании; закрепить площадку, цикл, трек и тип статьи и записать каждое правило площадки с его официальной страницей-источником, датой прочтения и этапом подачи.
2. **Проверить Шлюз последовательности** — Подтвердить, что `_outputs/review-report.md` существует и что его правки уровня HIGH устранены (или оператор явно принял остаточный риск); иначе остановиться с `Blocked: run /research-review first`.
3. **Оформить и упаковать** — Перенести каждое правило площадки с его страницей-источником, датой прочтения и этапом подачи, строить на нетронутом шаблоне площадки, считать страницы и слова так, как это делает площадка, и проверить скомпилированный PDF; затем собрать дополнительные материалы, доступность данных/кода, сопроводительное письмо, заявления об этике / конфликте интересов.
4. **Спланировать препринт / архивирование** — Зафиксировать план препринта и DOI; составить контрольный список подачи.
5. **Обновить манифест передачи** — Зафиксировать пакет подачи и запись о публикации.
6. **Выпустить пакет** — оформленный по площадке пакет подачи + `_outputs/publication-record.md`.

## Нижняя граница строгости

Форматирование чтит поэтапное раскрытие: для площадки с двойным слепым рецензированием идентичность автора, учреждения и системы вынесена в отдельно подаваемые метаданные и восстанавливается лишь на назначенном этапе готовой к печати версии. Архивный депозит несёт масштабированный под площадку пакет доказательств воспроизводимости (данные, код, закреплённое окружение, семена, журнал оборудования, результаты по экземплярам и рисунки). Для площадки с двойным слепым рецензированием на идентичность проверяются дополнительный архив и каждый связанный репозиторий или набор данных, а не только рукопись.

Правила площадки имеют источник и привязаны к этапу. Учитываются только собственные официальные страницы целевой площадки: соседняя площадка, более ранний цикл или родственный трек никогда не служат заменой, а пересборка для правки или для готовой к печати версии применяет ограничения этого этапа, а не ограничения первоначальной подачи. Правило, за которым не стоит официальная страница, запрашивается у оператора и помечается как не проверенное по площадке. Файлы шаблона площадки остаются в выпущенном виде, поэтому локально написанный стартовый файл сообщается как таковой. Страницы и слова считаются так, как это делает площадка, с записью исключённых разделов, и каждый рисунок и таблица проверяются в том размере и формате, в котором их получает площадка.

## Режимы отказа

| Симптом | Причина | Восстановление |
|---------|-------|----------|
| Blocked: run /research-review first | Нет отчёта о рецензировании или открыты правки уровня HIGH | Запустите `/research-review`, чтобы получить `_outputs/review-report.md`, либо устраните открытые правки HIGH и снова запустите `/research-review`, либо явно примите остаточный риск |
| Неустранённая правка HIGH | Замечание рецензирования пропущено | Устраните правку и снова запустите `/research-review` |
| Отсутствует доступность данных/кода | Поверхность воспроизводимости отсутствует | Добавьте заявление о доступности данных / кода перед подачей |
| Правило площадки без источника | Правило взято из другого цикла, трека или соседней площадки либо из памяти | Закрепите цель; запишите для правила официальную страницу, дату прочтения и этап либо спросите оператора и пометьте его как не проверенное |
| Шаблон изменён | Локальная правка меняет геометрию страницы или настройки шрифта площадки | Восстановите файлы площадки и меняйте макет только через параметры, которые документирует шаблон |

## Примеры

```bash
# Собрать пакет для подачи на площадку
/research-publish --suite-name <name>
```
