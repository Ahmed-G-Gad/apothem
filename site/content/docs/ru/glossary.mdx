Ключевые термины, используемые в документации, коде и управлении Apothem, в
алфавитном порядке.

## Адаптер
Класс, реализующий протокол `HarnessAdapter`, который преобразует общий
профиль в формат конфигурации, специфичный для окружения. Адаптеры размещаются
по одному на суб-пакет под `src/apothem/harnesses/<name>/`. См.
[Абстракция адаптера окружения](/docs/architecture/harness-adapter-abstraction).

## Последовательность аудиторских проверок
Аудиторский проход из одиннадцати команд, охватывающий код, ревью кода,
безопасность, производительность, архитектуру, UX, доступность, документацию,
зависимости, цепочку поставок и модель угроз. Управляется конвейером упрочнения
`/fortress`. См.
[Последовательность аудиторских проверок](/docs/concepts/review-fortress).

## Эталонный снимок behavior-diff
Зафиксированный снимок в `tests/fixtures/behavior-diff/`, с которым побайтово
сравниваются детерминированные оракулы установки и CLI, так что непреднамеренное
изменение плана установки, отрендеренной группы или вывода CLI улавливается как
расхождение, а не поставляется молча. Сравнение канонизирует байты, различающиеся
между платформами, чтобы корпус оставался переносимым между операционными
системами.

## Группа (cohort)
Сгруппированный набор синхронизируемых артефактов одного вида — правил, команд,
навыков, исполнителей, хуков, output-стилей, схем или шаблонов, — который движок
материализует в каждое окружение из единого общего профиля. Один профиль несёт
каждую группу; каждый адаптер проецирует их в нативную поверхность своего
окружения.

## Шлюз соответствия
Механическая часть пятнадцатипунктного шлюза предэмиссии — машинно-проверяемые
валидаторы в `src/apothem/conformity/gate.py`. Запускается перед выпуском каждого
артефакта; обоснованные пункты оцениваются в ходе ревью.

## Точка входа
Группа setuptools-точек входа `apothem.harnesses`, объявленная в `pyproject.toml`.
Она точно отражает реестр окружений; тест утверждает, что объявленные точки входа
равны зарегистрированным адаптерам, так что конвенционально-корректный, но
незарегистрированный адаптер проявляется как регрессия покрытия.

## Окружение
Платформа ассистента по написанию кода, которую Apothem поддерживает через
выделенный адаптер. Поддерживаемые платформы:

```text
Antigravity
Claude Code
CodeBuddy
Codex
Cursor
Gemini CLI
GitHub Copilot
GLM (Z.ai)
Hermes
Kimi Code
Kiro
Open-Claw
OpenCode
Qwen Code
Trae
Windsurf
Zed
```

См. [Окружения](/docs/harnesses).

## Реестр окружений
Каталог в `src/apothem/lib/harness_registry.py` (данные в
`harness_registry_data.py`), который перечисляет каждый адаптер и является
**авторитетным во время выполнения** — движок разрешает каждый адаптер из него,
поэтому он загружается из чистого чекаута. Обнаружение по файловым соглашениям
под `src/apothem/harnesses/` — это проверка соответствия на паритет, а не
резолвер времени выполнения.

## Хук
Команда, зарегистрированная на событии жизненного цикла окружения (PreToolUse,
PostToolUse, SessionStart, Stop). Нативная поверхность регистрации различается
по окружениям — файл настроек, выделенный манифест хуков или, когда окружение не
предоставляет нативной поверхности хуков, вспомогательный материал Apothem, на
который ссылается якорь инструкций. Скрипты хуков и их контексты сообщений
размещаются под `src/apothem/hooks/`.

## Материализатор
Опциональный метод адаптера `materialize_native_config(profile) -> str`, который
рендерит однофайловую нативную конфигурацию из общего профиля, для окружений, чья
конфигурация представляет собой одну структурированную поверхность (например,
файл настроек JSON или YAML). Адаптеры распространения шаблонов опускают
материализатор и вместо этого копируют или преобразуют группы согласно манифесту
распространения.

## Output-стиль
Определение в формате Markdown под `output-styles/`, которое формирует формат и
голос ответа ассистента (например, стиль concise-engineer или forensic-auditor).
Одна из синхронизируемых групп, которую устанавливает адаптер.

## Набор планов
Структурированная коллекция артефактов планирования (PREAMBLE.md, MASTER-PLAN.md,
PROGRESS.md, PLAN-NOTES.md, по-фазовые файлы PHASE.md), создаваемая командой
`/plan-generate` и исполняемая командой `/plan-execute`, под проектным каталогом
`.apothem/plans/` (устаревшее дерево `.plans/` обновляется через
`apothem migrate-workspace`).

## Шлюз предэмиссии
Пятнадцатипунктный блок согласования, записываемый до того, как артефакт будет
выпущен или вывод фазы будет считаться завершённым. Механические пункты
выполняются как шлюз соответствия; обоснованные пункты оцениваются в ходе ревью.
См. [Шлюз предэмиссии](/docs/governance/pre-emission-gate-registry).

## Манифест распространения
`src/apothem/lib/propagation-manifest.yaml` — объявляет для каждого адаптера
распространения шаблонов, какие группы он устанавливает, и любые преобразования в
нативный формат окружения (например, преобразование команд в форму TOML
окружения).

## Шлюзы готовности к релизу
Три шлюза конвергенции: локальное соответствие, непрерывная интеграция и
последовательность аудиторских проверок. Релиз продолжается только после
прохождения соответствующих шлюзов.

## Самодостаточная среда выполнения
Apothem вендорит свои Python-зависимости времени выполнения (такие как `pyyaml` и
`jsonschema`) под `src/apothem/_vendor/`, так что движок запускается из чистого
чекаута. Только `click` и `rich` разрешаются во время установки. См.
[Самодостаточная среда выполнения](/docs/architecture/self-contained-runtime).

## Уровень серьёзности
Один из четырёх уровней управления (EXPLORING, PERSONAL_USE, SHARED, PUBLIC_LAUNCH),
который определяет, какие средства контроля качества применяются. См.
[Уровни серьёзности](/docs/concepts/seriousness-tiers).

## Общий профиль
Файл YAML, прошедший проверку по схеме, по адресу `~/.config/apothem/profile.yaml`
или `--profile PATH`. Адаптеры окружений объединяют его с упакованными группами
Apothem и выводят нативную конфигурацию для каждого поддерживаемого окружения.

## STANDARD-CONVENTION-PIN
Файл `STANDARD-CONVENTION-PIN.md` по каждому адаптеру, фиксирующий URL
документации вендора, commit SHA, дату снимка и каноническое имя файла и схему, к
которым привязаны соглашения адаптера. Повторно проверяется на регулярной основе,
так что адаптер никогда не расходится молча с поверхностью вендора, на которую он
нацелен.

## Поддерево поддержки
Принадлежащий Apothem каталог, который установка окружения использует для групп,
для которых у окружения нет нативного примитива (правила, хуки, навыки или
исполнители). На него ссылаются из нативного якоря инструкций окружения, а не
принудительно помещают в зарезервированный вендором каталог.
