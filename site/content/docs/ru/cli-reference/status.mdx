Сообщает состояние установки, проверки и дрейфа для каждого зарегистрированного ассистента по написанию кода.

## Сводка

```
apothem status [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status` — это команда инспекции только для чтения. Она перебирает каждый зарегистрированный адаптер ассистента по написанию кода и сообщает три факта по каждому ассистенту: установлен ли он, проходят ли проверку его управляемые цели и отклонилась ли установленная конфигурация от общего профиля. Она ничего не записывает на диск.

Для каждого ассистента по написанию кода `status` сообщает:

| Столбец | Значение |
|---|---|
| `installed` | Управляемая конфигурация адаптера существует по его целевому пути. |
| `verified` | Управляемые цели адаптера присутствуют и действительны. |
| `drift` | Вердикт точности профиля (см. ниже). |

Значение `drift` — одно из:

| Значение | Значение |
|---|---|
| `in-sync` | Установленная конфигурация дословно несёт только что спроецированный общий профиль. |
| `drift` | Ассистент по написанию кода установлен, но его спроецированное содержимое профиля больше не совпадает с текущим общим профилем. Запустите `apothem install` снова, чтобы перепроецировать. |
| `absent` | Ассистент по написанию кода не установлен, поэтому сравнивать нечего. |
| `needs-project` | Ассистент по написанию кода с областью проекта был сообщён без `--project`, поэтому его цель не может быть разрешена. Передайте `--project PATH`, чтобы проверить его. |

Дрейф сообщается, но никогда не рассматривается как ошибка: `status` завершается с кодом 0, даже когда один или несколько ассистентов по написанию кода сообщают `drift`. Дрейф — это факт о вашей настройке, а не сбой команды.

Если общий профиль не удаётся загрузить, дрейф понижается до `absent` для установленных ассистентов по написанию кода (факты installed/verified по-прежнему сообщаются) вместо прерывания обхода.

## Параметры

| Параметр | Описание |
|---|---|
| `--project PATH` | Корень проекта для ассистентов по написанию кода с областью проекта. Без него ассистенты с областью проекта сообщают `needs-project`. |
| `--quiet`, `-q` | Подавляет информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводит дополнительный диагностический вывод. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключает коды цвета ANSI в выводе. |
| `-h`, `--help` | Показывает справку и завершает работу. |

## Вывод JSON

Конверт `--json` несёт одну строку результата на каждый зарегистрированный ассистент по написанию кода. Каждая строка несёт документированные ключи `harness`, `installed`, `verified` и `drift`.

```json
{
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

Изоляция сбоев по адаптерам: если один адаптер вызывает исключение при сообщении своего состояния, строка этого ассистента по написанию кода несёт `outcome: "error"` и `message`, остальные ассистенты по-прежнему сообщают нормально, а процесс завершается с кодом 2.

## Примеры

```bash
apothem status
apothem status --project .
apothem status --json
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Состояние сообщено (дрейф сообщается, а не является ошибкой) |
| 2 | По крайней мере один адаптер не смог сообщить своё состояние |
