Сообщает состояние установки, проверки и дрейфа для каждого зарегистрированного окружения.

## Сводка

```
apothem status [--profile PATH] [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status` — команда инспекции только для чтения. Она перебирает каждый
зарегистрированный адаптер окружения и сообщает три факта по каждому окружению:
установлено ли оно, проходят ли проверку его управляемые цели и отклонилась ли
установленная конфигурация от общего профиля. Она ничего не записывает на диск.

Для каждого окружения `status` сообщает:

| Столбец | Значение |
|---|---|
| `installed` | Управляемая конфигурация адаптера существует по его целевому пути. |
| `verified` | Управляемые цели адаптера присутствуют и действительны. |
| `drift` | Вердикт о соответствии профилю (см. ниже). |

Значение `drift` — одно из следующих:

| Значение | Смысл |
|---|---|
| `in-sync` | Установленная конфигурация дословно содержит заново спроецированный общий профиль. |
| `drift` | Окружение установлено, но его спроецированное содержимое профиля больше не совпадает с текущим общим профилем. Повторно запустите `apothem install`, чтобы спроецировать профиль заново. |
| `absent` | Окружение не установлено, поэтому сравнивать нечего. |
| `needs-project` | Об окружении с областью проекта сообщалось без `--project`, поэтому его цель не может быть разрешена. Передайте `--project PATH`, чтобы проверить его. |
| `unknown` | Профиль по умолчанию не удалось загрузить, поэтому у установленного окружения нет базовой линии для сравнения. Исправьте профиль, чтобы вернуть вердикт о дрейфе. |

О дрейфе сообщается, но он никогда не рассматривается как ошибка: `status`
завершается с кодом 0, даже когда одно или несколько окружений сообщают
`drift`. Дрейф — это факт о вашей настройке, а не сбой команды.

Если общий профиль по умолчанию не удаётся загрузить, дрейф для установленных
окружений понижается до `unknown` (факты installed/verified по-прежнему
сообщаются), а обход не прерывается. Явно указанный `--profile`, который не
удаётся загрузить, — это ошибка пользователя, и в этом случае выполнение
прерывается со структурированной ошибкой.

О понижении всегда сообщается: `status` выводит предупреждение с указанием
профиля и способа исправления, а конверт `--json` содержит соответствующую
запись `drift_baseline_unavailable` в `warnings`. Это важнее всего, когда не
установлено ни одного окружения, — тогда каждая строка показывает `absent` и ни
одной ячейки `unknown` нет, поэтому предупреждение — единственный сигнал того,
что базовая линия так и не загрузилась.

## Параметры

| Параметр | Описание |
|---|---|
| `--profile PATH` | YAML общего профиля, задающий базовую линию для дрейфа. Без него используется профиль по умолчанию (`~/.config/apothem/profile.yaml`). |
| `--project PATH` | Корень проекта для окружений с областью проекта. Без него окружения с областью проекта сообщают `needs-project`. |
| `--quiet`, `-q` | Подавляет информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводит дополнительную диагностику. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключает коды цвета ANSI в выводе. |
| `-h`, `--help` | Показывает справку и завершает работу. |

## Вывод JSON

Конверт `--json` содержит по одной строке результата на каждое
зарегистрированное окружение. Каждая строка содержит документированные ключи
`harness`, `installed`, `verified` и `drift`. При чистом обходе `warnings` пуст;
если профиль по умолчанию не удалось загрузить, он содержит одну запись
`drift_baseline_unavailable` с `path`, `code`, `reason` и `fix`.

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

Изоляция сбоев по адаптерам: если отдельный адаптер выбрасывает исключение при
сообщении своего состояния, строка этого окружения содержит `outcome: "error"` и
`message`, остальные окружения по-прежнему сообщают состояние как обычно, а
процесс завершается с кодом 2.

## Примеры

```bash
apothem status
apothem status --project .
apothem status --json
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Состояние сообщено (о дрейфе сообщается, это не ошибка) |
| 1 | Ожидаемая ошибка проверки (недопустимый `--profile` или несуществующий путь `--project`) |
| 2 | Хотя бы один адаптер не смог сообщить своё состояние |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка выводится как конверт JSON с кодом `cli.usage`. |
