Восстанавливает ассистента по написанию кода в состояние, предшествовавшее его записанной установке.

## Сводка

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` восстанавливает байты каждого выбранного ассистента по написанию кода в их состоянии до установки из корня резервных копий Apothem. Команда определяет записанный проход установки — по умолчанию последний или указанный через `--install-id` — восстанавливает каждую резервную копию, захваченную этой установкой, а затем добавляет запись `rollback` в журнал ассистента по написанию кода.

Подтверждение запрашивается для каждого ассистента по написанию кода, если не указан `--yes`. Параметры `--install-id` и `--last` выбирают проход установки и являются взаимоисключающими.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер ассистента по написанию кода для отката или `all` для набора уровня всего реестра (обязательно). |
| `--install-id ULID` | Откатывает указанный проход установки. По умолчанию последняя записанная установка. |
| `--last` | Откатывает последнюю записанную установку (значение по умолчанию; явная форма). Взаимоисключаем с `--install-id`. |
| `--yes` | Пропускает запрос подтверждения для каждого ассистента по написанию кода. |
| `--project PATH` | Корень проекта для ассистентов по написанию кода с областью проекта. Обязателен, когда выбранный набор включает адаптеры с областью проекта. |
| `--quiet`, `-q` | Подавляет информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводит дополнительную диагностическую информацию. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключает коды цветов ANSI в выводе. |
| `-h`, `--help` | Показывает справку и завершает работу. |

## Вывод JSON

```json
{
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Каждая восстановленная цель появляется в `results` с `"operation": "rollback"` и значением `outcome`, равным `created` или `updated` (а также в `files_written`). Цель, созданную установкой заново — без предыдущих байтов для восстановления — выводится с `"outcome": "skipped"`; неудавшееся восстановление получает `"outcome": "error"`. Если подходящей записи об установке не существует, команда сообщает об ошибке `rollback.no_record` с `"status": "error"`.

## Примеры

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Откат выполнен успешно или нечего восстанавливать (установка не захватила резервных копий) |
| 1 | Ожидаемая ошибка — нет записи об установке, конфликтующие селекторы, неизвестный ассистент по написанию кода, отсутствует корень проекта или прерванное подтверждение |
| 2 | Частичное восстановление после отката хотя бы одной цели |
