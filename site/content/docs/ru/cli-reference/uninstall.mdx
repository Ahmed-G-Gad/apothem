Удаляет конфигурацию адаптера окружения.

## Синтаксис

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

Удаляет цели окружения, которыми управляет адаптер, а затем каталоги,
созданные установкой, как только они становятся пустыми (каталог, содержащий
что-либо ваше, остаётся).

Память, контексты и хранилища обучения общего рабочего каталога резервно
копируются и удаляются только тогда, когда это последнее окружение,
установленное в этом каталоге. Удаление работает по месту, которое записала
установка, поэтому находит их там, где установка их записала (см. поля профиля
`workspace`). Каталог `plans/` никогда не удаляется.

Запрашивает подтверждение, если не указан `--yes`. Когда запрос невозможен —
`--format json` (текст запроса испортил бы единственный документ JSON) или
неинтерактивная оболочка (без TTY), — команда сразу отказывается выполняться
со структурированной ошибкой `uninstall.confirmation_required` (код выхода 1),
если не указан `--yes`. Если выбранное окружение не установлено, команда
завершается успешно (код выхода 0) и в обычном выводе печатает
`NAME is not installed; nothing to remove.`, где `NAME` — идентификатор окружения.

Общие хранилища данных в `.apothem/` в корне установки (`memory/`,
`contexts/`, `learning/`) остаются, пока другое установленное окружение в том же
корне всё ещё их использует. Когда удаляемое вами окружение — последнее в этом
корне, команда сначала копирует каждое хранилище в корень резервных копий
Apothem (`~/.apothem/backups/`), а затем удаляет его вместе со всем
содержимым. Всё, что вы храните в `plans/`, никогда не удаляется.

Удаление с `--harness all` намеренно исчерпывающее: оно охватывает каждое
зарегистрированное окружение, включая любые окружения, которые профиль
пропускает при установке через `exclude_harnesses`, — очистка затрагивает
состояние, которое могла оставить более широкая предыдущая установка.
Окружения, которые никогда не устанавливались, получают то же уведомление.

Псевдоним в продолженной форме `apothem uninstalling` (принимается также как
`apothem Uninstalling`) разрешается в тот же обработчик.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер окружения для удаления или `all` для набора уровня всего реестра (обязателен). |
| `--yes` | Пропустить запрос подтверждения. |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--quiet`, `-q` | Подавить информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводить дополнительную диагностическую информацию. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключить цветовые коды ANSI в выводе. |
| `-h`, `--help` | Показать справку и завершить работу. |

## Вывод JSON

Когда адаптер установлен и успешно удалён:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Когда адаптер не был установлен, команда завершается с кодом `0`. В выводе JSON
конверт содержит `"status": "success"` и `"action": "uninstalled"`, а строка
результатов содержит `"outcome": "skipped"` с сообщением `"not installed; no files
removed"`. Поле `status` никогда не принимает значение `"not_installed"`.

## Примеры

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Адаптер удалён или не был установлен |
| 1 | Окружение не найдено, подтверждение отклонено или недоступно (неинтерактивный режим или режим JSON без `--yes`), либо каждое удаление завершилось сбоем |
| 2 | Частичное удаление — как минимум одно окружение было удалено до сбоя |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка представляет собой конверт JSON с кодом `cli.usage`. |
