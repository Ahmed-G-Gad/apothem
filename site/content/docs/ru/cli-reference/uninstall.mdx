Удаляет конфигурацию адаптера окружения.

## Синтаксис

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

Удаляет цели окружения, которыми управляет адаптер, а затем каталоги,
созданные установкой, как только они становятся пустыми (каталог, содержащий
что-либо ваше, остаётся).

## Что удаляется при удалении

Установка записывает SHA-256 каждого файла, который она копирует на место
(навыки, команды, правила и тому подобное), в журнал установки
(`~/.apothem/state/<harness>/ledger.jsonl`). Удаление убирает такой файл,
только пока у него всё ещё то же содержимое, а затем каждую папку, в которой
ничего не осталось, включая пустую папку, которую вы создали внутри папки
Apothem. Всё остальное остаётся и получает строку `Warning:`: файл, который вы
добавили в папку Apothem, файл Apothem, который вы изменили, ваш собственный
файл с именем Apothem и путь, которого нет в записи установки. Файл, который
остаётся, сохраняет и свою папку.

Установка, записанная более ранним релизом, не указывает, какие файлы записал
Apothem. Для неё удаление сравнивает каждый файл с тем, что этот релиз
записывает по этому пути, и удаляет файлы с теми же байтами. В двух местах
хранится интерпретатор Python, который нашла установка: в команде строки
состояния и в комментарии шлюза соответствия. Такое место считается
совпадающим, только когда в нём записано `py -3` — единственный запускатель,
который туда записывал более ранний релиз, — или полный путь к файлу
интерпретатора на этом компьютере, и ничего больше. Путь, содержащий `&`, `#`
или `$` (имя пользователя Windows, например `R&D`), или не указывающий ни на
какой файл здесь, никогда не считается совпадающим, поэтому такой файл
остаётся. Путь к интерпретатору, который вы с тех пор обновили или удалили,
тоже не указывает ни на какой файл здесь, поэтому такой файл тоже остаётся:
выполните `apothem update`, затем снова удаление. Записи хуков Apothem в файле
настроек или хуков так не сравниваются: их узнают по скрипту-диспетчеру,
который они запускают, какой бы интерпретатор ни стоял перед ним, и удаляют
после резервного копирования файла.

Файл с именем, которое записывает Apothem, но с другим содержимым (записанный
тем более ранним релизом или изменённый вами), остаётся, и удаление не
завершается: оно печатает `✗ <harness> uninstall did not finish:` с числом
таких путей (папка считается один раз, а её файлы перечислены под её строкой
`Warning:`) и завершается с кодом `2`. То же происходит с путём, который
записал тот релиз и который этот релиз больше не записывает, поскольку его не
с чем сравнить. Установка вообще без записи (её журнал был удалён) завершается
так же, потому что ничто не показывает, какие из её файлов записал Apothem;
каждый путь, который она сохраняет вне ссылки, перечислен под одной строкой
`Warning:`, включая добавленные вами файлы, поскольку ничто их не различает.
Общие папки в вашем домашнем каталоге для неё тоже остаются. Некоторые части
всё же удаляются: строки Apothem в общем файле, например в файле правил или
`hooks.json` (файл, в котором больше ничего не осталось, тоже удаляется; файл,
блок которого потерял маркер END, остаётся как есть, см.
[Удаление, которое не завершилось](#удаление-которое-не-завершилось)),
хранилища памяти, контекстов и обучения в папке данных (сначала резервно
копируются; в них ваши данные, а не только данные Apothem), а для некоторых
окружений — папки более старой структуры, которые окружение помечает как
устаревшие. После строки `✗` строка `Note:
<harness> - no install record matched` называет общие папки, которые
удаление оставило, и то, что оно всё же удалило. Для окружения с областью
проекта она также советует проверить, что `--project` указывает на папку, в
которую вы выполняли установку, прежде чем запускать `apothem update`,
поскольку обновление в другой папке выполняет установку туда; папка взята в
кавычки, как в других печатаемых командах, или названа как есть, когда эти
кавычки не могут её передать, — в тех же случаях, что и в строке `Warning:`
хранилищ данных ниже. Когда предупреждение называет файл из-за маркера
Apothem, который удаление оставило (маркер BEGIN без END после него, два
разных блока между маркерами Apothem или пары маркеров, которые Apothem не
может определить), строка `✗` советует исправить этот файл перед обновлением,
с советом для его вида маркера (см.
[Удаление, которое не завершилось](#удаление-которое-не-завершилось)); для
окружения с областью проекта то же говорит и строка `Note:`. Из этой строки
исключается только `CLAUDE.md` или документ профиля, содержащий два разных
блока (см. ниже).
Строка `Note:` печатается и при `--quiet`, в поток ошибок. В выводе
`--format json` строка `uninstall` этого окружения имеет
`"outcome": "error"`, содержит это примечание в своём сообщении и имеет
`"detail": {"kept_reason": "no-record"}`.
`apothem update` записывает файлы этого релиза и регистрирует их, поэтому его
запуск и затем повторный `apothem uninstall` доводят дело до конца. Перед этим
скопируйте каждый перечисленный файл, который вы изменили или добавили:
обновление перезаписывает пути, которые оно записывает, и целиком заменяет
каждую запись папки Apothem, которую записывает целиком (сначала оно резервно
копирует и то и другое в `~/.apothem/backups/`, но ничто не возвращает их
обратно). Также сначала исправьте каждый файл, который предупреждение называет
из-за маркера Apothem (см.
[Удаление, которое не завершилось](#удаление-которое-не-завершилось)). Для
установки, записанной более ранним релизом, файл в папке Apothem с именем,
которое Apothem никогда не записывает, принадлежит вам: он перечислен под
строкой `Warning:` для изменённых или ваших файлов, остаётся, и удаление всё
равно завершается.

Когда последняя запись в этом месте — завершившееся удаление (а установка
после него, скажем, остановилась раньше, чем смогла себя записать), удаление
сравнивает каждый путь с тем, что записывает этот релиз, кроме общих папок в
вашем домашнем каталоге: они остаются как есть, как и при отсутствии записи
(см.
[Общие папки в вашем домашнем каталоге](#общие-папки-в-вашем-домашнем-каталоге)).
Оно удаляет файл, только когда у файла точно те же байты, и удаляет папку, в
которой нет файлов. Ничто там не показывает, какой интерпретатор нашла та
установка, поэтому файл, содержащий путь к интерпретатору (команда строки
состояния, комментарий в шлюзе соответствия), никогда не считается совпадающим
и остаётся. Пока шлюз остаётся, окружение по-прежнему считается установленным,
поэтому проверьте этот файл и удалите его вручную. Всё остальное тоже остаётся
(ваш файл, изменённый вами файл Apothem, кэш, записанный другой программой) и
получает строку `Warning:`, а удаление завершается. Файл, оставшийся в папке,
другие файлы которой были удалены, перечислен под строкой для изменённых или
ваших файлов; любой другой путь перечислен под строкой, которая говорит, что
его нет ни в одной записи установки, что он не совпадает с тем, что записывает
этот релиз, и что его можно удалить вручную, если он вам больше не нужен.
Файл с точно теми же байтами за ссылкой останавливает удаление, как это делают
собственные файлы Apothem за ссылкой для записанной установки (см. ниже). Если
такое удаление не завершается (скажем, из-за файла, который оно не смогло
удалить), окружение по-прежнему считается установленным, и повторный запуск
удаления работает так же, в том числе после установки, которая завершилась
сбоем и отменила собственные изменения. После отката или только незавершённых
удалений такой путь останавливает удаление, как при отсутствии записи.

Когда в этом месте не записано ни одной установки, как в случаях выше,
удаление также оставляет управляемый блок Apothem на месте: в
`~/.claude/CLAUDE.md` для Claude Code и в документе профиля
`apothem/rules/00-apothem-profile.md` в папке инструмента, настраиваемого
через один файл настроек, например Open-Claw, OpenCode или Qwen Code. Ничто не
показывает, какая установка записала этот блок, поэтому файл остаётся как
есть, а строка `Warning:` называет его; это предупреждение не останавливает
удаление. Если блок вам больше не нужен (Claude Code по-прежнему читает
`CLAUDE.md`), уберите его вручную с помощью пронумерованного исправления,
которое даёт предупреждение, например "Fix A: A1. Change
line 5: add a word inside its comment. Apothem then finds no block of its own
in this file." (см.
[Следование пронумерованному исправлению](/docs/install/troubleshooting#follow-a-numbered-fix)).
Предупреждение называет блок по его строкам, а исправление меняет строку его
маркера BEGIN на месте, так что ни одна ваша строка не начинает читаться иначе; старый текст
Apothem под ней, вплоть до строки его маркера END, затем удаляете вручную вы.
Ваш маркер BEGIN над блоком или маркер в паре маркеров, которую вы цитируете,
не входит в блок: исправление меняет и каждую такую строку, поскольку иначе
она читалась бы как маркер Apothem, когда блок будет убран. Когда этот файл
содержит два разных блока между маркерами Apothem (скажем, вашу пару маркеров
вне кода), удаление от первого маркера BEGIN до следующего маркера END забрало
бы с собой и ваш текст, поэтому предупреждение даёт для такого файла другой
текст (см.
[Удаление, которое не завершилось](#удаление-которое-не-завершилось)): оно
называет каждый блок по его строкам или блок Apothem и строки маркеров вокруг
него и объясняет, как исправить файл, сохранив ваш собственный текст. Когда
оно называет блок Apothem и строки маркеров вокруг него, оно затем советует
удалить блок Apothem вручную, если он вам больше не нужен. Когда оно называет
два или более целых блока, оно вместо этого советует выполнить
`apothem update`, затем снова
`apothem uninstall`: ваш маркер BEGIN над блоком Apothem и маркер END под ним,
которые этот текст не называет, образовали бы один блок после ручного удаления
блока Apothem, и следующее обновление заменило бы строки между ними. Повторный
запуск удаления сначала называет эти строки маркеров.
Это предупреждение тоже не останавливает удаление, и строка `✗` не называет
этот файл. Исправьте его и перед запуском `apothem update`: обновление его не
исправляет.

Память, контексты и хранилища обучения общего рабочего каталога резервно
копируются и удаляются только тогда, когда это последнее окружение,
установленное в этом каталоге. Удаление работает по месту, которое записала
установка, поэтому находит их там, где установка их записала (см. поля профиля
`workspace`). Каталог `plans/` никогда не удаляется. Здесь установка, папка
которой больше не существует (удалённый проект), всё равно считается
использующей хранилища, в отличие от общих папок ниже, и удаление сообщает об
этом (см. ниже).

Запрашивает подтверждение, если не указан `--yes`. Когда запрос невозможен —
`--format json` (текст запроса испортил бы единственный документ JSON) или
неинтерактивная оболочка (без TTY), — команда сразу отказывается выполняться
со структурированной ошибкой `uninstall.confirmation_required` (код выхода 1),
если не указан `--yes`. Если выбранное окружение не установлено, команда
завершается успешно (код выхода 0) и в обычном выводе печатает
`NAME is not installed; nothing to remove.`, где `NAME` — идентификатор окружения.
Файл со строками маркеров, которые Apothem не может отличить от вашего текста,
считается установленным, пока его перечисляет запись установки, а также пока
журнал установки невозможно прочитать: удаление тогда останавливается на
повреждённом журнале (код выхода 1) и называет его, как и для файла с целым
блоком, вместо того чтобы сообщить, что окружение не установлено.

Удаление останавливается, прежде чем что-либо удалить, когда ссылка выводит
папку инструмента в вашем домашнем каталоге за его пределы, например
`~/work/tool`, где `~/work` — ссылка на другой диск. В Windows соединение
считается ссылкой. В интерактивном запуске команда сначала не запрашивает
подтверждение. Запуск, который не может спросить (вывод JSON или отсутствие
терминала), всё равно сначала останавливается и требует `--yes`; ошибка ссылки
появляется, как только вы его передадите. Ошибка содержит `uninstall
refused: target path crosses a link`, называет ссылку и папку, к которой она
ведёт, и объясняет, что делать; команда завершается с кодом 1. Направьте ссылку
на папку внутри вашего домашнего каталога или замените её самой папкой и снова
выполните удаление. Если вы указываете папку путём за пределами домашнего
каталога, команда переходит по ссылке.

Общие хранилища данных в `.apothem/` в корне установки (`memory/`,
`contexts/`, `learning/`) остаются, пока другое установленное окружение в том же
корне всё ещё их использует. Когда удаляемое вами окружение — последнее в этом
корне, команда сначала копирует каждое хранилище в корень резервных копий
Apothem (`~/.apothem/backups/`), а затем удаляет его вместе со всем
содержимым. Всё, что вы храните в `plans/`, никогда не удаляется.

Когда единственные установки, удерживающие хранилища, находятся в папках,
которых больше не существует, команда сохраняет хранилища и печатает строку
`Warning:`, которая называет одну такую установку и шаги, освобождающие её.
Удаление в пустой воссозданной папке не находит ничего установленного, поэтому
шаги сначала снова устанавливают туда инструмент с тем же `--profile`, который
использовала та установка. Хранилища находятся вне этой папки, поэтому туда, где
они лежат, их поместил профиль той установки. Установка без него записывает
собственные хранилища, и удаление после неё оставляет эти без установки,
которая их использует. Apothem не записывает, какой профиль использовала
установка, поэтому предупреждение печатает `--profile <the profile it used>`,
чтобы вы подставили его сами. Для инструмента, установленного в проекте, шаги
такие:

```bash
mkdir -p /path/to/old-project
apothem install --harness cursor --project /path/to/old-project --profile /path/to/that-profile.yaml
apothem uninstall --harness cursor --project /path/to/old-project --yes
```

Предупреждение берёт папку в двойные кавычки в Windows и в одинарные в других
системах. Когда эти кавычки не могут передать папку, предупреждение даёт те же
шаги словами и называет папку как есть. В Windows это происходит, когда папка
содержит `$`, обратную кавычку, `%`, `!`, прямую или фигурную двойную кавычку
или управляющий символ, которые оболочка Windows изменила бы внутри двойных
кавычек; `&`, `^`, `|`, `<` или `>` в папке без пробела, которые PowerShell и
Git Bash тогда передают в `apothem.cmd` установщика без его кавычек, так что на
них реагирует командная строка; или две обратные косые черты подряд, как в
начале сетевого ресурса (`\\server\share`), которые Git Bash читает как одну. В
других системах это происходит, когда папка содержит прямую или фигурную
одинарную кавычку (оболочка может закончить одинарные кавычки и на фигурной),
управляющий символ, две обратные косые черты подряд или обратную косую черту в
конце (fish читает две как одну внутри одинарных кавычек, а одна в конце там
экранирует закрывающую кавычку).

Для инструмента, установленного в ваш домашний каталог, предупреждение даёт те
же шаги словами: папка, в которую он был установлен, могла быть получена из
переменной окружения (скажем, `XDG_CONFIG_HOME`), которую печатаемая команда не
повторила бы. Хранилища уходят вместе с этим удалением, когда никакая другая
установка их больше не использует. Вы также можете удалить хранилища вручную.

## Общие папки в вашем домашнем каталоге

Несколько установок могут использовать одну папку в вашем домашнем каталоге:
папку навыков (`~/.agents/skills/`, или `~/.codebuddy/skills/`,
`~/.kiro/skills/`, или `~/.trae/skills/`) и `~/.config/apothem/rules/` и
`~/.config/apothem/templates/`. Страница [install](/docs/cli-reference/install#folders-in-your-home-directory)
перечисляет, какой адаптер что записывает. Apothem записывает, какие установки
используют каждую папку, и удаление следует одному правилу: оно удаляет папку,
только когда её больше не использует никакая другая установка Apothem.

- Удаление одного инструмента сохраняет навыки, пока их использует другая
  установка, и сообщает об этом. Один инструмент, установленный в двух
  проектах, считается двумя установками, поэтому его удаление из проекта A
  сохраняет папки, пока их использует проект B. Последнее удаление удаляет их
  (см. второй пример ниже).
- Папка считается одной папкой, как бы ни был записан ваш домашний каталог при
  каждой установке. Когда ваш домашний каталог — ссылка, например `/home`,
  ведущая к `/var/home` в Fedora Silverblue, или профиль пользователя Windows,
  перенесённый за соединение, установка, выполненная через ссылку, и установка,
  выполненная через папку, к которой она ведёт, используют одни и те же папки.
  Два инструмента, установленные так, — это две установки, и удаление одного
  сохраняет папки для другого. Один инструмент, установленный обоими способами,
  — это одна установка: её удаление, при любой записи домашнего каталога,
  удаляет то, что записала любая из установок, и папки, которые не использует
  никакая другая установка. Если это удаление останавливается, не завершившись,
  обе установки остаются записанными, пока вы не исправите то, что его
  остановило, и не выполните удаление снова. Удаление находит установку, только
  если ваш домашний каталог записан одним из способов, которыми его записала
  установка этого инструмента; при любой другой записи оно не находит ничего
  для удаления.
- Удаляется только то, что перечислено в собственной записи установки.
  Установка, выполненная до того, как этими папками стали управлять, не имеет
  такой записи, поэтому её удаление ничего не удаляет в вашем домашнем
  каталоге. Файлы, которые вы добавили в папки, остаются, как и папка, которая
  носит имя навыка Apothem и которую Apothem не записывал.
- Установка, папка проекта которой больше не существует, игнорируется, поэтому
  удалённый проект не удерживает папки навсегда. Примечание называет её.
- Если запись установки, которая могла бы использовать папки, невозможно
  прочитать, удаление останавливается с ошибкой, прежде чем что-либо удалить, и
  установка остаётся записанной. Исправьте или переместите нечитаемую запись,
  затем снова выполните команду. Повреждённая запись инструмента, который
  никогда не записывает эти папки, игнорируется.
- Когда уходит последнее использование, оставшиеся пустыми папки тоже
  удаляются. Каждая папка резервно копируется в `~/.apothem/backups/` перед
  удалением.

Каждое удаление печатает одно `Note:` на папку, например `Note: <harness> -
~/.agents/skills/ was kept: still used by <harness> (/path/to/project)` или
`was removed: no other Apothem install uses it`. В конверте `--format json`
каждое примечание — это запись `warnings` с `"outcome": "advisory"`,
`"operation": "shared_root"` и `"role"`, равным `retained` или `released`. Она
содержит `path`, `holders` (установки, которые удерживают папку), `stale`
(игнорируемые установки), а также `kept` и `total` (сохранённые записанные
элементы и элементы, которые перечисляла установка).

Удаление также печатает строку `Warning:` для всего, что оно намеренно оставило
на месте. Apothem ничего не удаляет через символическую ссылку или соединение
Windows, поэтому ссылка в удаляемой им папке остаётся, как и оставшаяся от
более раннего релиза папка, к которой ведёт ссылка. Пути, сохранённые из-за
одной и той же ссылки или по одной и той же причине (не то, что записал
Apothem, нет в записи установки), печатаются одной строкой с их числом. Под
строкой для сохранённых путей перечислен каждый сохранённый файл, включая
файлы внутри сохранённой папки (сохранённая папка, в которой ничего нет,
указана сама). Файл, записанный Apothem, который он не смог удалить, указан
под строкой `✗`, которая о нём сообщает, а не как сохранённый файл. При
`--quiet` эти строки печатаются, только
когда удаление не завершается, и тогда в стандартный поток ошибок вместе со
строкой `✗`, чтобы пути, к которым относится её совет, оставались на виду.
Строка, которая называет маркер Apothem, оставленный в файле, печатается в
стандартный поток ошибок при `--quiet`, даже когда удаление завершается:
инструмент по-прежнему читает любой старый текст Apothem под этим маркером,
последующая установка сохраняет оба, и `verify` затем завершается сбоем, пока
вы их не удалите. В конверте `--format json`
каждая такая строка — это одна запись `warnings` с `"outcome": "warning"`,
`message` этой строки, `count` (сколько путей она охватывает), `paths` (каждый
из них) и, для сохранённых путей, `files` (каждый сохранённый файл). Эти
предупреждения не останавливают удаление. Четыре вида останавливают: файлы
установки, записанной более ранним релизом, которые отличаются от того, что
записывает этот релиз, файлы установки вообще без записи (см.
[Что удаляется при удалении](#что-удаляется-при-удалении)), файл, который
содержит два разных блока между маркерами Apothem, и файл, строки маркеров
которого Apothem не может отличить от вашего текста (см.
[Удаление, которое не завершилось](#удаление-которое-не-завершилось)).

С собственными файлами Apothem, к которым ведёт ссылка, иначе: большинство
инструментов всё ещё загружает их, поэтому удаление не завершено. (OpenClaw
больше не загружает свой файл правил, как только удаление убрало путь Apothem
из его записи хука, поэтому для OpenClaw строка `✗` говорит об этом, только
пока он всё ещё его загружает; см.
[OpenClaw](/docs/harnesses/open-claw#uninstalling).) Допустим, `~/.claude/rules` —
соединение с папкой dotfiles, в которой всё ещё лежат правила, записанные Apothem:
команда печатает `✗ <harness> uninstall did not finish:` со ссылкой и числом
оставленных путей, сохраняет установку записанной и завершается с кодом `2`.
Замените ссылку настоящей папкой с теми же файлами, затем снова выполните
команду. Для установки, запись которой перечисляет записанные ею файлы, папка
за ссылкой, в которой лежат только ваши собственные файлы или изменённые вами
файлы Apothem, не останавливает удаление: ссылка остаётся с предупреждением, и
удаление завершается. Для установки, записанной более ранним релизом, любой
файл за ссылкой с именем, которое записывает этот релиз, останавливает
удаление, изменён он или нет, потому что ничто не отличает его от того, что
записал тот релиз. Замените ссылку настоящей папкой с теми же файлами, затем
выполните шаги для такой установки, описанные выше: скопируйте каждый
изменённый вами файл, исправьте каждый файл, который предупреждение называет
из-за маркера Apothem, выполните `apothem update`, затем снова удаление.

Когда шаг удаления сообщает об ошибке (скажем, установленный файл, путь
которого выводит за пределы вашей домашней папки), команда печатает `✗ <harness> uninstall
did not finish: <reason>` вместо `Uninstalled`, по одному разу на причину с
числом путей, к которым она относится. Когда ссылка в папке вашего домашнего
каталога выводит эти пути за его пределы (`target escapes the allowed materialization root`),
строка также называет ссылку и папку, к которой она ведёт, и советует заменить
ссылку настоящей папкой; пути за двумя ссылками дают две строки. Ссылка
всё равно получает своё предупреждение о том, что она оставлена на месте.
Установка остаётся записанной, поэтому повторный запуск команды удаляет то,
что оставил первый запуск. Примечания об удержании не печатаются, потому что
описываемые ими папки не были освобождены.
В выводе JSON окружение получает строку `results` с `"outcome": "error"` и
`"operation": "uninstall"`, за которой следует по одной строке на каждый
неудавшийся шаг. Когда причины называют одну ссылку, эта строка содержит её в
`detail.symlink`, а папку, к которой она ведёт, — в `detail.leads_to`. Строка
шага перечисляет сохранённые им файлы как
`files`, а файлы, записанные Apothem, которые он не смог удалить, — как
`stuck`. `status` конверта — `"partial"`, а код выхода — `2`, когда удаление
убрало файлы до сбоя шага или когда было удалено другое окружение;
иначе `status` — `"error"`, а код выхода — `1`. `error` верхнего уровня
остаётся `null`: причины находятся в `results`. Удаление, которое
останавливается с исключением (скажем, из-за резервной копии, которую
невозможно записать), печатает `✗ <harness> uninstall
stopped after removing files:`, когда оно удалило файлы или убрало записи или
блок Apothem из файла, например `openclaw.json`, до остановки (или
`failed:`, когда оно ничего не изменило), с сообщением, и получает строку
`results` со своим сообщением, за которой следует по одной строке на каждый
шаг, завершившийся сбоем до этого.
Когда до остановки какой-либо шаг завершился сбоем или удаление нашло то, что
оставляет его незавершённым (собственные файлы Apothem за ссылкой, файлы
установки, записанной более ранним релизом, которые отличаются от того, что
записывает этот релиз, файлы установки без записи, файл, содержащий два разных
блока между маркерами Apothem, или файл со строками маркеров, которые Apothem
не может отличить от вашего текста), следует строка
`✗ <harness> uninstall did not finish:` для каждой причины, как выше, и тот же
текст добавляется в конец сообщения строки. Для установки без записи за ними
следует строка `Note:` с её проверкой папки `--project` для окружения с
областью проекта, а `detail` строки содержит `"kept_reason": "no-record"`, как
описано в
[Что удаляется при удалении](#что-удаляется-при-удалении). Когда эти причины
и шаги, завершившиеся сбоем до остановки, называют одну ссылку, строка
содержит её в `detail.symlink`, а папку, к которой она ведёт, — в
`detail.leads_to`. Команда завершается с кодом `2`
и `status` `"partial"`, когда она сначала удалила или изменила файлы, нашла
собственные файлы Apothem за ссылкой, сохранила файлы установки более раннего
релиза или установки без записи либо оставила файл, содержащий два разных
блока между маркерами Apothem или строки маркеров, которые Apothem не может
отличить от вашего текста, или когда было удалено другое окружение, иначе — с
кодом `1`. Непредвиденная ошибка (исключение, например резервная копия,
которую невозможно записать) внутри первого шага удаления Open-Claw,
Antigravity или Kimi Code не сообщает ни о чём, что сделал этот шаг
(см. [Удаление, которое не завершилось](#удаление-которое-не-завершилось)):
удаление печатает `failed:` и завершается с кодом `1` (`2`, когда было удалено
другое окружение), что бы ни изменил этот шаг. Когда шаг файла правил Open-Claw
вместо этого сообщает об ошибке (файл правил, который он не может
перезаписать, или `openclaw.json` с комментариями), это неудавшийся шаг, как
выше: удаление печатает `did not finish:`, записывает себя незавершённым с
резервными копиями этого шага и завершается с кодом `2`, когда этот шаг
изменил файл или нашёл файл правил Apothem за ссылкой, или когда было удалено
другое окружение, иначе — с кодом `1`. `Ctrl+C`
печатает `Aborted!` и завершается с кодом `1`, что бы удаление ни удалило к
тому моменту. Отклонённое удаление (скажем, из-за ссылки, которая выводит папку
за пределы вашего домашнего каталога) ничего не удаляет и завершается с кодом
`1`; его строка называет эту ссылку в `detail.symlink`, а папку, к которой она
ведёт, — в `detail.leads_to`, и за ней следует строка для отклонённого шага.

### Удаление, которое не завершилось

Когда удаление не завершается, оно добавляет в журнал установки запись
`uninstall-incomplete` вместо записи `uninstall`. Это происходит, когда шаг
завершился сбоем, когда собственные файлы Apothem остаются за ссылкой, когда
файл содержит два разных блока между маркерами Apothem или строки маркеров,
которые Apothem не может отличить от вашего текста (см. ниже), когда файлы
установки, записанной более ранним релизом, отличаются от того, что записывает
этот релиз, и когда у установки нет записи. Последние четыре случая
завершаются с кодом `2` и `status` `"partial"`, даже когда ничего не было
удалено, включая повторный запуск до того, как вы исправите то, что они
называют. Последние два завершаются только после `apothem update` (см.
[Что удаляется при удалении](#что-удаляется-при-удалении)). Удаление, которое
остановило исключение или `Ctrl+C`, добавляет — в зависимости от шага, на
котором оно остановилось:

- в первом шаге Open-Claw, который убирает блок Apothem из файла правил каждого
  рабочего пространства, или Antigravity и Kimi Code, который удаляет то, что
  оставила более старая структура: ничего, даже для файлов, которые этот шаг к
  тому моменту изменил; их резервные копии остаются в `~/.apothem/backups/` без
  записи, которая защитила бы их от `backups prune`;
- в шаге, который убирает записи Apothem из файла настроек инструмента,
  настраиваемого через один файл настроек, например Open-Claw, OpenCode или Qwen
  Code: запись — только когда первый шаг Open-Claw убрал блок Apothem из файла
  правил или резервно скопировал его, и ничего в остальных случаях, в том числе
  когда этот шаг нашёл файл правил Apothem за ссылкой;
- в шаге, который удаляет то, что перечисляет запись установки, — последнем
  шаге каждого удаления, кроме удаления OpenCode: запись, даже когда он ничего
  не изменил;
- в шаге, который удаление OpenCode выполняет после него и который закрывает
  установку, записанную под другим написанием её папки (скажем, когда
  `XDG_CONFIG_HOME` указывает на папку, к которой ведёт ссылка `~/.config`):
  больше ничего, поэтому та установка остаётся записанной. Последующий запуск
  её ещё не закрывает: когда файлов Apothem в папке больше нет, OpenCode
  считается там не установленным, поэтому
  `uninstall` его пропускает, и `status`, `verify` и `rollback` тоже не видят
  эту установку. Чтобы закрыть её, снова установите OpenCode в эту папку, затем
  удалите его: `apothem install --harness opencode --profile PATH` с
  профилем вне папки за ссылкой (его создаёт `apothem profile init --profile PATH`),
  затем `apothem uninstall --harness opencode`.

Когда ничего не добавляется, журнал остаётся прежним. Установка в любом случае
остаётся записанной. Кроме последнего случая, `apothem status`, `verify` и
`rollback` по-прежнему её видят, и окружение считается установленным, пока
что-то записанное установкой всё ещё лежит там в том виде, в каком она это
записала (см. ниже), поэтому повторный запуск `uninstall` доводит дело до
конца. У установки без записи нечего сохранять: окружение считается
установленным только из-за её файлов на диске, а
`rollback` нечего откатывать. `install`, `update`, `rollback` или
завершившееся `uninstall` этого окружения в этом месте заменяют состояние, как
и ручное удаление оставшихся файлов: когда ни одного файла Apothem не осталось
в том виде, в каком он их записал, и в его папке `.apothem` ничего нет,
окружение считается не установленным, что бы ещё ни лежало в папке. Первая
команда, которая проверяет, установлено ли окружение (`status`, `verify`,
`uninstall`), затем добавляет запись `uninstall`, которая закрывает установку.
Однако после завершившегося удаления никакая запись не перечисляет файлы,
записанные установкой, поэтому там состояние заменяют только установка,
обновление или завершающееся удаление.
`backups prune` сохраняет запись и резервные копии, на которые она ссылается,
пока сохраняется установка, к которой она относится. После завершившегося
удаления она сохраняет запись вместе с записью того удаления, поэтому повторный
запуск удаления по-прежнему работает так же.

Что по-прежнему учитывается: целый файл, записанный установкой, пока он не
изменён (для установки, записанной более ранним релизом, — пока он на месте);
всё, что находится в папках, в которые Apothem выполняет установку под
`.apothem`; и файл, в котором Apothem хранит управляемый блок рядом с вашим
собственным текстом, пока блок всё ещё в нём, что бы вы ни написали вокруг
него. Это `CLAUDE.md`, документ профиля, в который проецируется общий профиль,
файл правил в каждом рабочем пространстве OpenClaw, а также `AGENTS.md` и
другие файлы инструкций, в которые установка добавляет блок.

Управляемый блок идёт от маркера `<!-- BEGIN APOTHEM MANAGED BLOCK -->` до
следующего маркера `<!-- END APOTHEM MANAGED BLOCK -->`, каждый на отдельной
строке; Apothem читает маркер только так и только вне кода, как это сделала бы
программа просмотра Markdown; кодом считается огороженный блок кода (закрытый
ограждением из того же символа, не короче, без чего-либо после него) или код с
отступом на четыре колонки дальше его элемента списка (или поля) после пустой строки.
Поэтому маркер, который вы цитируете в предложении или примере кода, — это ваш
текст, а маркеры BEGIN и END, которые вы цитируете в двух отдельных блоках
кода, не образуют блок. Apothem закрывает ограждение кода, которое правило в
вашем профиле оставляет открытым в конце записываемого им блока; в блоке,
записанном более ранним релизом, такое ограждение скрывает маркер END, только
когда за ним следует ещё одна пара маркеров (см. ниже). Ограждение, которое вы
оставляете открытым до конца файла, читается как текст, сколько бы их ни было,
если только маркер BEGIN вне кода над ним не имеет свой маркер END в коде и за
ними не следует ещё одна пара маркеров.
Метка порядка байтов в начале файла (как её сохраняют некоторые редакторы
Windows) не скрывает маркер в первой строке. Маркеры внутри блока HTML или
цитаты либо после элемента списка, текст которого продолжается у левого поля,
всё ещё могут читаться иначе, чем в программе просмотра Markdown.

Если блок Apothem находится внутри вашего блока кода (ограждение, оставленное
открытым над ним и закрытое ограждением под ним или закрывающей строкой внутри
блока), или блок кода между маркером BEGIN и его маркером END
скрывает этот END, а за ним следует ещё одна пара маркеров, Apothem не может
отличить свой блок от вашего примера. Удаление оставляет такой файл как есть,
удаляет остальную часть установки и не завершается: оно печатает
`✗ <harness> uninstall did not finish:`, а затем "1 file(s) hold marker
lines Apothem cannot tell from your text, so Apothem left them as they are;
fix the marker lines each warning names, keeping your own text, then run
apothem uninstall again", и завершается с кодом `2`, включая повторный запуск.
Запись установки остаётся, поэтому последующая установка тоже оставляет файл
как есть, а следующее удаление снова называет его. Его предупреждение называет
каждую пару маркеров в файле по её строкам и каждый маркер BEGIN вне кода,
который не начинает пару маркеров. Без записи установки предупреждение
получает только маркер BEGIN, маркер END которого скрыт таким образом: пара
внутри вашего блока кода тогда считается вашим текстом, а удаление остаётся
незавершённым из-за этого маркера и из-за путей, которые не показывает ни одна
запись. Затем предупреждение даёт пронумерованные исправления и заканчивается
словами "Then run the
uninstall again.", например "Fix A: A1. Change line 6: add a word inside
its comment. Apothem then finds no block of its own in this file." Старый
текст Apothem под изменённой вами строкой, вплоть до строки его маркера END,
затем удаляете вручную вы. Если исправлений несколько, выберите то, условие
которого выполняется, и выполните каждый его шаг в указанном порядке: пара
маркеров, оставшаяся в этом файле, оставляет удаление незавершённым, даже если
она ваша, поэтому каждое исправление меняет строку маркера BEGIN каждой пары,
которую оно не называет блоком Apothem, и каждый маркер BEGIN, который не
начинает пару (см.
[Apothem не может отличить свой блок от вашего текста](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)).
Когда в файле больше нет такой пары, повторный запуск удаления завершает его.

Если маркер END
пропал, ничто не показывает, где кончается текст Apothem и начинается ваш,
поэтому удаление оставляет файл как есть, называет его в предупреждении и
завершается (если только что-то другое не оставляет его незавершённым,
например установка без записи); так же поступает повторная попытка после
незавершённого удаления. Если после удаления блока Apothem остаётся маркер
BEGIN без END после него (ваша строка или остаток более старого блока,
потерявшего свой маркер END), удаление называет этот файл и строку маркера
тоже, с пронумерованным шагом, который меняет эту строку (добавляет слово
внутрь её комментария), чтобы она больше не читалась как маркер: установка
сохраняет её как есть, а инструмент по-прежнему читает текст под ней. Любой
старый текст Apothem под ней затем удаляете вручную вы. `install` или `update`
сохраняет текст после такого маркера как есть, записывает блок Apothem
отдельно от него и называет файл, а `verify`
завершается сбоем, пока маркер не будет изменён (см.
[В файле есть маркер BEGIN Apothem без маркера END](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker)).

Файл, содержащий два разных блока между маркерами (пару маркеров, которую вы
цитируете вне блока кода, старый блок, маркер END которого вы вернули, или
блок, который вы вставили второй раз), остаётся как есть и называется, а
удаление не завершается: оно печатает `✗ <harness> uninstall did not finish:`,
а затем "1 file(s) hold two different blocks between Apothem's markers, so
Apothem left them as they are; fix each as its warning says, keeping your own
text (follow one of its numbered fixes, which change marker lines in place),
then run apothem uninstall again", и завершается с кодом `2`, включая повторный
запуск. Его предупреждение называет каждый блок по его строкам, как это делают
install и update, и даёт по одному пронумерованному исправлению на каждый блок
— на случай, если это блок Apothem: исправление меняет строку маркера BEGIN
каждого другого блока и сохраняет их текст (в файле, который начинается с
frontmatter Apothem, блок Apothem — тот, что сразу под ним). Не удаляйте блок
Apothem, чтобы сохранить свою пару: следующее удаление тогда убрало бы
единственный оставшийся блок — ваш собственный.
`apothem update` не исправляет такой файл: он оставляет файл с двумя целыми
блоками как есть, с тем же предупреждением, а `verify` завершается сбоем, пока
вы его не исправите (см.
[Файл содержит два блока между маркерами Apothem](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers)).

Маркер BEGIN над блоком Apothem и маркер END под ним образуют второй блок,
который проявляется, только когда блок Apothem убран. Предупреждение удаления
тогда называет блок Apothem и эти две строки маркеров, например "once the block
from line 5 to line 36 is out, the BEGIN marker at line 2 and the END marker at
line 39 make another", и советует не удалять блок Apothem: следующий запуск
тогда прочитал бы строки со 2 по 39 как блок Apothem. Его единственное
исправление вместо этого меняет эту строку маркера BEGIN, сохраняя ваш
собственный текст, и маркер END ниже затем ни с чем не образует пару; если
этот маркер BEGIN — остаток более старого блока Apothem, старый текст Apothem
под ним затем удаляете вручную вы.
Не помещайте обе строки в один блок кода: в нём оказался бы и блок Apothem.
`apothem update` не исправляет и такой файл, а `verify` завершается сбоем, пока
вы его не исправите. Номера строк считают отдельный CR концом строки, как и
CRLF и LF (см.
[В файле есть маркер BEGIN Apothem без маркера END](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker)).

Когда следующий шаг удаления — выполнить `apothem update`, а предупреждение
называет файл из-за маркера Apothem (в конверте `--format json` его `detail`
содержит `marker_left`), строка `✗` и предупреждение каждого пути, который
удаление сохраняет из-за более раннего релиза или отсутствующей записи,
советуют сначала исправить этот файл, с советом для его вида маркера.

Если журнал не может принять запись `uninstall-incomplete` (скажем, из-за
заполненного диска), журнал остаётся прежним, а строка `Warning:` называет
журнал и папки резервных копий, созданных удалением: никакая запись не
защищает эти резервные копии от `backups prune`, поэтому скопируйте те, что
вам нужны. Без записи об этом незавершённом проходе повторный запуск команды
может обнаружить, что окружение не установлено, и ничего не удалить; тогда
удалите вручную файлы, перечисленные строками `✗` и `Warning:`. Пока
окружение по-прежнему считается установленным, повторный запуск команды
работает как раньше: по записи установки или, после завершившегося удаления
без записанной с тех пор установки, так же, как тот проход (см.
[Что удаляется при удалении](#что-удаляется-при-удалении)). Когда запись
`uninstall` завершившегося удаления невозможно сохранить на
диск, удаление снова убирает её из журнала и заканчивается как незавершённое.
Оно завершается, с таким же предупреждением, когда журнал всё же
заканчивается завершившимся удалением: запись всё равно осталась в журнале,
или удаление следовало за завершившимся удалением. Прерывание (`Ctrl+C`) после
сохранения записи оставляет удаление завершённым.

Если папка остаётся из-за установки, которую вы не можете найти, примечание
называет её. Когда папка проекта была удалена, установка игнорируется, и папка
уходит при следующем удалении. Когда проект существует, но вы вручную убрали
блок Apothem из его файла правил, `uninstall` сообщает, что окружение не
установлено, и не снимает его притязание; выполните `install` для этого
окружения и проекта, затем `uninstall`, чтобы снять его. `apothem verify`
показывает, остаётся ли папка полной.

`--project` читается с переходом по ссылкам и раскрытием `~`. Установка,
выполненная из кода Python с папкой проекта, записанной по-другому, скажем
через ссылку, всё равно находится под тем написанием, которое хранит её
запись. `install` или
`update` записывает разрешённую папку. Как только установка проходит свои
проверки, она переносит установку, записанную под другим написанием, на
разрешённое, поэтому установка находится и после удаления ссылки; отклонённая
установка не меняет ни одной записи. `uninstall` переносит такую установку
так же, прежде чем что-либо удалить, поэтому незавершённое удаление
записывается под разрешённой папкой, где повторный запуск `uninstall` всё ещё
находит его после удаления ссылки. Папка, которую запись называет на диске
по-другому (путь `\\localhost\C$` к папке, записанной как `C:\...`), сохраняет
написание из записи, а установка или удаление в папке, у которой собственная
установка всё ещё на месте, оставляет запись под другим написанием как есть.
Написание, установка которого всё ещё на месте, идёт раньше того, установка
которого была удалена; из двух, что на месте, — то, у которого больше файлов в
папке, затем более новое. Установка, ни одного файла которой нет в папке, не
принимается за неё, если только её удаление не завершилось: тогда повторный
запуск `uninstall` завершает его. Имена папок сравниваются точно: в папке с
учётом регистра (скажем, созданной WSL) `Proj` и `proj` — две папки, и они
никогда не принимаются друг за друга, а удаление одной сохраняет общие папки,
которые использует другая. В обычной папке Windows это одна папка, пока она
существует; когда её нет, её находит только написание из записи. Клонированный
том, подключённый рядом с оригиналом, не принимается за него, когда Windows
может назвать оба тома.
Запись на другом сетевом ресурсе (путь `\\server\share` или буква диска,
сопоставленная с ним) сравнивается только по тексту, поэтому недоступный
ресурс не задерживает поиск записи. Примечания об общих папках
по-прежнему проверяют каждую записанную папку, поэтому они всё ещё могут
ожидать такой ресурс.

Три случая находятся не так, как можно было бы ожидать. Установка, которую
более ранний релиз записал дважды, один раз из командной строки и один раз из
Python через ссылку, сохраняет вторую запись после `uninstall`, и общие папки
остаются для неё. Удалите её из Python, записав папку так, как она была
установлена. Установка, записанная под написанием `\\localhost\C$` папки на
этом компьютере, не находится по её написанию `C:\`, поскольку запись на
сетевом ресурсе не ищется из другого места. И когда две установки были
выполнены через две ссылки на две разные папки, а одна ссылка позже была
направлена на другую папку, удаление берёт установку, у которой больше файлов
в этой папке. Если обе записали одни и те же имена файлов (две установки
одного релиза) или их записал более ранний релиз (он не перечислял свои
файлы), оно берёт более новую, файлы которой могут находиться в папке, к
которой раньше вела ссылка.

Удаление с `--harness all` намеренно исчерпывающее: оно охватывает каждое
зарегистрированное окружение, включая любые окружения, которые профиль
пропускает при установке через `exclude_harnesses`, — очистка затрагивает
состояние, которое могла оставить более широкая предыдущая установка.
Окружения, которые никогда не устанавливались, получают то же уведомление.

Псевдоним в продолженной форме `apothem uninstalling` (принимается также как
`apothem Uninstalling`) разрешается в тот же обработчик.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер окружения для удаления или `all` для набора уровня всего реестра (обязателен). |
| `--yes` | Пропустить запрос подтверждения. |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--quiet`, `-q` | Подавить информационный вывод; выводятся только ошибки. Незавершённое удаление всё равно печатает свои строки `Warning:`, перечисляющие то, что оно сохранило, в стандартный поток ошибок, а любое удаление печатает туда строку `Warning:`, которая называет маркер Apothem, оставленный в файле. |
| `--verbose`, `-v` | Принимается для единообразия с другими командами; эта команда не выводит дополнительных данных. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключить цветовые коды ANSI в выводе. |
| `-h`, `--help` | Показать справку и завершить работу. |

## Вывод JSON

Когда адаптер установлен и успешно удалён:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Когда адаптер не был установлен, команда завершается с кодом `0`. В выводе JSON
конверт содержит `"status": "success"` и `"action": "uninstalled"`, а строка
результатов содержит `"outcome": "skipped"` с сообщением `"not installed; no files
removed"`. Поле `status` никогда не принимает значение `"not_installed"`.

Результат, отклонённый на ссылке, называет ссылку в `detail.symlink`, а папку,
к которой она ведёт, — в `detail.leads_to`, как в
[`apothem install`](/docs/cli-reference/install#json-output).

## Примеры

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

Общая папка навыков остаётся, пока не уйдёт последняя установка, которая её
использует:

```bash
apothem install --harness codex
apothem install --harness cursor --project A
apothem uninstall --harness codex --yes                  # keeps ~/.agents/skills/, the cursor install uses it
apothem uninstall --harness cursor --project A --yes     # removes it: no install uses it now
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Адаптер удалён или не был установлен |
| 1 | Окружение не найдено, подтверждение отклонено или недоступно (неинтерактивный режим или режим JSON без `--yes`), ничего не было удалено, потому что каждое установленное окружение завершилось сбоем, прежде чем что-либо удалить или изменить, не назвало ни одной ссылки, из-за которой собственные файлы Apothem остаются на месте, не сохранило файлов установки более раннего релиза или установки без записи и не оставило файла, содержащего два разных блока между маркерами Apothem или строки маркеров, которые Apothem не может отличить от вашего текста (непредвиденная ошибка, исключение, внутри первого шага удаления Open-Claw, Antigravity или Kimi Code считается таким сбоем, что бы ни изменил этот шаг), или команда была прервана (`Ctrl+C`, что печатает `Aborted!`), что бы она ни удалила к тому моменту |
| 2 | Частичное удаление — удаление завершилось сбоем или остановилось после удаления файлов или удаления записей Apothem из одного из них (кроме непредвиденной ошибки внутри такого первого шага, см. `1`), как минимум одно окружение было удалено, а другое завершилось сбоем, удаление оставило собственные файлы Apothem на месте, потому что к ним ведёт ссылка, файл содержит два разных блока между маркерами Apothem или строки маркеров, которые Apothem не может отличить от вашего текста, файлы установки, записанной более ранним релизом, отличаются от того, что записывает этот релиз, или у установки нет записи, которая показала бы, какие файлы записал Apothem |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка представляет собой конверт JSON с кодом `cli.usage`. |
