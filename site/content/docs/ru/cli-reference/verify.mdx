Проверяет установку адаптера окружения.

## Синтаксис

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

Вызывает реализацию `verify()` каждого выбранного адаптера. Завершается с кодом
0 только тогда, когда все выбранные адаптеры сообщают, что их управляемые цели
присутствуют и корректны. Без `--profile` проверка **структурная** — каждая
управляемая цель должна присутствовать и быть корректной. С `--profile`
проверка дополнительно требует **соответствия профилю**, поэтому установка,
которая присутствует, но разошлась с профилем, не проходит verify; так команда
отвечает на вопрос «установлен ли ИМЕННО ЭТОТ профиль точно?», а не просто
«существует ли установка?».

Для адаптера, который записывает навыки в ваш домашний каталог, verify также
проверяет, что каждая ожидаемая им папка навыка существует и содержит
`SKILL.md`, какая бы установка её ни записала, поэтому машина, на которой
установлен только один из инструментов, разделяющих папку, проходит проверку.
Проверка не проходит, когда папка отсутствует и когда папка с именем навыка
Apothem принадлежит чему-то, что Apothem не записывал. Неудавшаяся строка
сообщает, что именно: в режиме plain за ней следует строка `Note:`, а в строке
JSON объект `user_level` перечисляет пути `missing` и `unlisted` и содержит
`message`. Выполните [`install`](/docs/cli-reference/install), чтобы
восстановить отсутствующую папку; переименуйте или переместите чужую папку,
затем выполните [`update`](/docs/cli-reference/update).

Проход с `--harness all` учитывает `exclude_harnesses` профиля — те же
исключения, которые применил пакетный запуск `install`/`update`, — поэтому
verify никогда не сообщает об отсутствии намеренно исключённого окружения.
Исключения берутся из `--profile`, если он указан, иначе — из профиля по
умолчанию; если профиль по умолчанию нечитаем или отсутствует, проверка
откатывается к полному реестру.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер окружения для проверки или `all` для набора уровня всего реестра (обязателен). |
| `--profile PATH` | YAML общего профиля, на соответствие которому выполняется проверка. Без него проверка чисто структурная. |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--quiet`, `-q` | Подавить информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводить дополнительную диагностическую информацию. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключить цветовые коды ANSI в выводе. |
| `-h`, `--help` | Показать справку и завершить работу. |

## Вывод JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Когда любое выбранное окружение отсутствует или некорректно, `status` равен
`error`, строка результата со сбоем содержит `verified: false`, а процесс
завершается с кодом 1.

## Примеры

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Окружение проверено — все управляемые цели присутствуют и корректны |
| 1 | Окружение не прошло проверку — управляемые цели отсутствуют или некорректны |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка представляет собой конверт JSON с кодом `cli.usage`. |
