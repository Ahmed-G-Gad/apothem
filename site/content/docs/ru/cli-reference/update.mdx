Переустанавливает конфигурацию адаптера окружения из текущего общего профиля.

## Синтаксис

```
apothem update --harness NAME|all [--profile PATH] [--dry-run]
                [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

`update` заново материализует вывод окружения из текущего общего профиля. Она
использует ту же проверку профиля, тот же выбор `--harness all`, ту же проверку
области проекта, то же поведение пробного запуска и тот же конверт JSON, что и
`install`, и печатает те же уведомления, включая примечание
`instruction_override`, когда ваш файл мешает инструменту загрузить то, что
записывает Apothem (см. [`install`](/docs/cli-reference/install)). Как и
`install`, она записывает разрешённую папку `--project` и переносит установку,
записанную под другим написанием этой папки, на неё. Она также предупреждает о
файле, который содержит маркер BEGIN без маркера END после него: текст после
этого маркера сохраняется как есть, а блок Apothem записывается отдельно от
него, поэтому предупреждение называет строку маркера, даёт пронумерованный шаг,
который изменяет эту строку, и говорит не добавлять вместо этого маркер END
обратно, что оставило бы два блока Apothem (см.
[Устранение неполадок](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker)).
Файл, который содержит два или более целых блока между маркерами Apothem,
остаётся как есть, с предупреждением, которое называет каждый блок по его
строкам (см.
[Файл содержит два блока между маркерами Apothem](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers)).
Файл, в котором Apothem не может отличить свой блок от вашего текста, например
свой блок внутри вашего блока кода, остаётся как есть, пока его перечисляет
запись об установке (нечитаемый журнал установки считается такой записью;
запись, сделанная под другим написанием папки, например вашего домашнего
каталога, достигнутого через ссылку, тоже считается, как и для удаления, когда
у написания, под которым вы запускаете команду, есть собственная ещё
действующая установка и инструмент записывает
[общие папки в вашем домашнем каталоге](/docs/cli-reference/install#folders-in-your-home-directory)),
с предупреждением, которое называет каждую пару маркеров в нём и способ
исправления (см.
[Apothem не может отличить свой блок от вашего текста](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)).
Это верно и рядом с маркером BEGIN, который не начинает пару маркеров,
например с тем, что осталось от блока Apothem после потери его маркера END:
предупреждение называет этот маркер BEGIN первым, и каждое пронумерованное
исправление в предупреждении изменяет его. Без записи об установке пара
маркеров, которую вы цитируете в коде, — это ваш текст, и обновление добавляет
свой блок после неё, с таким маркером BEGIN или без него, если только пара не
содержит в точности тот блок, который записывает обновление: тогда оно
оставляет файл как есть, с предупреждением. Файл, в котором маркер BEGIN вне
кода имеет свой маркер END в коде, а после них идёт ещё одна пара маркеров,
остаётся как есть с предупреждением, есть запись или нет. Правило в вашем
профиле, которое открывает блок кода и никогда его не закрывает, не приводит к
этому для блока, который записывает обновление: обновление закрывает этот блок
кода в конце блока. Блок, который более ранний выпуск записал из такого
правила, не имеет такой закрывающей строки, поэтому может привести к этому.
Ваш блок кода, который открывается выше блока Apothem и никогда не
закрывается, — другой случай: закрывающая строка в блоке закрывает его, так
что блок читается как код, и обновление, которое записывает такой блок, сразу
предупреждает и называет блок кода, который нужно закрыть выше маркера BEGIN.
Пробный запуск читает файл до какой-либо записи, поэтому не показывает, что
блок после записи читался бы как код. При пробном запуске предупреждение для
файла, оставленного как есть, говорит, что Apothem "would leave the file as it
is".

Обновление, которое оставляет файл как есть из-за его строк маркеров (два или
более целых блока либо пары маркеров, которые Apothem не может разместить),
завершается как частичное, как и установка: инструмент не получает из этого
файла актуального блока Apothem, поэтому вместо строки `✓` он печатает строку
`✗` в стандартный поток ошибок, которая называет файл, `status` конверта
`--format json` равен `"partial"`, а предупреждение для этого файла несёт
`"detail": {"left_as_is": "1"}`, и код выхода равен `2`. Каждое обновление
завершается так, пока вы не исправите строки маркеров, которые называет
предупреждение; ваш пример маркера в блоке кода тоже удерживает такой файл,
пока вы не измените его строку маркера BEGIN. Без `--quiet` такое обновление с
`--harness all` завершается итоговой строкой, которая начинается с `!` вместо
`✓` и считает файлы, оставленные как есть:
`! Updated <n> harnesses (<m> files written); <k> file(s) left as they are, named above.`
Пробный запуск по-прежнему завершается со `status` `"dry_run"` и кодом выхода
`0`.

В каждой папке, в которую записывает Apothem (папка навыков, файлы поддержки в
`.apothem/support/`), `update` сравнивает каждую запись, которую она
записывает. Файловая запись перезаписывается, когда отличается. Запись-папка
(навык, папка навыка команды или папка внутри файлов поддержки, например
`hooks/lib/`) заменяется целиком, когда что-либо в ней отличается от того, что
этот выпуск записывает туда: обновление сначала создаёт её резервную копию в
`~/.apothem/backups/`, поэтому файл, который вы добавили в неё, или файл
Apothem, который вы отредактировали, после этого из неё пропадает. Скопируйте
такой файл из набора резервных копий или перенесите его до обновления. Ваш
файл непосредственно в папке, в которую записывает Apothem
(`.apothem/support/hooks/mine.py`, например), и ваши собственные папки рядом с
папками Apothem не затрагиваются.

Для адаптеров с областью проекта, которые записывают навыки в ваш домашний
каталог (см.
[`install`](/docs/cli-reference/install#folders-in-your-home-directory)),
`update` также приводит эти папки в актуальное состояние и печатает то же
`Note:`, которое их называет. Адаптер, установленный до того, как он стал
записывать навыки, получает их при следующем обновлении. Папка навыка, которую
Apothem не записывал или запись которой он не может доказать, пропускается с
предупреждением, которое даёт способ исправления, как и для
[`install`](/docs/cli-reference/install#folders-in-your-home-directory).
Установка, которая ранее записала общую папку навыков, при следующем обновлении
перезаписывается в форму, общую для всех установок; каждая изменённая папка
предварительно резервно копируется.

Псевдоним в продолженной форме `apothem updating` (принимается также как
`apothem Updating`) разрешается в тот же обработчик.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер окружения для обновления или `all` для набора уровня всего реестра (обязателен). С `all` окружения, перечисленные в `exclude_harnesses` профиля, пропускаются, но окружение, названное явно, обновляется, даже если оно в этом списке. |
| `--profile PATH` | Путь к YAML общего профиля. По умолчанию `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Предпросмотр обновления без записи файлов. |
| `--project PATH` | Корень проекта для окружений с областью проекта. Обязателен, когда выбранный набор окружений включает адаптеры с областью проекта. |
| `--quiet`, `-q` | Подавить информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводить дополнительную диагностическую информацию. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключить цветовые коды ANSI в выводе. |
| `-h`, `--help` | Показать справку и завершить работу. |

## Вывод JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "update",
  "action": "updated",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

`--dry-run` возвращает `status: "dry_run"` и `files_written: []`. Обновление,
которое оставило файл как есть из-за его строк маркеров Apothem, возвращает
`status: "partial"` и завершается с кодом `2`.

## Примеры

```bash
apothem update --harness claude-code
apothem update --harness claude-code --dry-run
apothem update --harness all --project . --dry-run --json
apothem Updating --harness claude-code   # continuous-form alias
apothem updating --harness claude-code   # lowercase variant
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Адаптер успешно обновлён, или пробный запуск спланирован без ошибок |
| 1 | Ожидаемая ошибка проверки, профиля, окружения, проекта или адаптера |
| 2 | Частично: пакет остановился после как минимум одной записи, или обновление оставило файл, в котором Apothem хранит свой блок, как есть из-за его строк маркеров Apothem; `status` равен `"partial"` |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка представляет собой конверт JSON с кодом `cli.usage`. |
