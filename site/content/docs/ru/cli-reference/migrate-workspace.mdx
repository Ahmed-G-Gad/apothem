Переносит устаревшее рабочее пространство отдельного окружения в общую структуру `.apothem`.

## Сводка

```
apothem migrate-workspace [--project PATH] [--dry-run]
                          [--quiet|-q] [--verbose|-v]
                          [--format plain|json] [--json] [--no-color]
```

`migrate-workspace` сводит устаревший каталог данных отдельного окружения
(`.apothem/<harness>/...`) и устаревшее дерево `.plans/` в единый общий рабочий
каталог `.apothem/{plans,memory,learning,contexts}`. Базой служит разрешённый
корень `--project`, если он указан, иначе текущий рабочий каталог (значение по
умолчанию, локальное для проекта).

Хранилища памяти, контекстов и обучения отдельных окружений объединяются в общее
хранилище по id (объединением); сигналы обучения конкатенируются с удалением
дубликатов; конфликтующая запись (тот же id, другое тело) пропускается и никогда
не перезаписывается. Устаревшее дерево `.plans/` перемещается под
`.apothem/plans/`. Для каждого используемого источника сначала создаётся
резервная копия. Миграция идемпотентна — повторный запуск на уже перенесённом
дереве ничего не делает.

## Параметры

| Параметр | Описание |
|---|---|
| `--project PATH` | Корень проекта для адаптеров с областью проекта, которые материализуют конфигурацию в дерево проекта, а не в каталог конфигурации с областью пользователя. |
| `--dry-run` | Обнаруживает устаревшую структуру и сообщает, что было бы перенесено, ничего не записывая. |
| `--quiet`, `-q` | Подавляет информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводит дополнительную диагностику. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключает коды цвета ANSI в выводе. |
| `-h`, `--help` | Показывает справку и завершает работу. |

## Вывод JSON

Конверт `--json` содержит результат миграции. При завершённой миграции `status`
равен `success`, а полезная нагрузка сообщает количество объединённых записей,
было ли перемещено дерево `.plans/`, корень резервных копий и все пропущенные
конфликты. Вызов с `--dry-run` вместо этого сообщает `legacy_layout_detected`.

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "status": "success",
  "base": "/home/example/project",
  "migrated": true,
  "backup_root": "/home/example/project/.apothem/backups/migrate-20260101T120000Z",
  "memory_merged": 12,
  "contexts_merged": 4,
  "learning_merged": 7,
  "conflicts": [],
  "plans_moved": true,
  "notes": []
}
```

Когда устаревшая структура отсутствует, `migrated` равен `false` и ничего не
записывается. Конверт `--dry-run` не содержит счётчиков результата и сообщает
только об обнаружении:

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "base": "/home/example/project",
  "dry_run": true,
  "legacy_layout_detected": false
}
```

## Примеры

```bash
apothem migrate-workspace
apothem migrate-workspace --project .
apothem migrate-workspace --dry-run --json
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Миграция завершена или устаревшая структура не найдена (переносить нечего) |
| 1 | Ожидаемая ошибка — ошибка проверки или корня проекта либо сбой миграции |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка выводится как конверт JSON с кодом `cli.usage`. |
