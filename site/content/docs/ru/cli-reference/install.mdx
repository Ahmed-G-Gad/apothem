Устанавливает конфигурацию адаптера окружения из общего профиля.

## Синтаксис

```
apothem install --harness NAME|all [--profile PATH] [--dry-run]
                 [--clean|--fresh] [--yes] [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

Загружает и проверяет общий профиль, выбирает именованный адаптер или набор
`all` уровня всего реестра, проверяет план материализации и записывает нативную
конфигурацию окружения вместе со вспомогательными группами. Адаптеры с областью
проекта требуют `--project PATH`.

Псевдоним в продолженной форме `apothem installing` (принимается также как
`apothem Installing`) разрешается в тот же обработчик.

## Первый запуск без профиля

Когда `--profile` не указан и по пути по умолчанию
(`~/.config/apothem/profile.yaml`) профиля нет, `install` сначала записывает туда
стартовый профиль, печатает `Created a starter profile at <path>` и продолжает
работу. Стартовый профиль содержит поля идентичности-заполнители, поэтому
установка также печатает примечание об идентичности-заполнителе; настройте
профиль под себя, затем выполните [`update`](/docs/cli-reference/update), чтобы
применить его. При `--json` создание профиля сообщается как запись `warnings` с
`"operation": "profile_created"`.

- `--dry-run` никогда не записывает профиль: предпросмотр использует стартовый
  профиль в памяти и сообщает `"operation": "profile_scaffold_preview"`.
- Явно указанный `--profile PATH`, который не существует, никогда не создаётся;
  команда завершается с кодом 1 и `profile.not_found`.

## Предпросмотр радиуса поражения

`install --harness all` разветвляется на смешанные области: адаптеры с областью проекта записывают в корень, переданный через `--project`, а адаптеры с областью пользователя записывают в ваш домашний каталог, то есть за пределами этого корня. Прежде чем установка запишет какой-либо файл, команда выводит конкретные цели, сгруппированные под двумя заголовками: цели внутри корня проекта и цели в вашем домашнем каталоге. Единственное исключение — `--clean`: его шаг очистки выполняется до этого предварительного просмотра, записывает резервную копию и удаляет прежние цели, как описано ниже.

Когда выбор записывает за пределы корня проекта, интерактивное подтверждение
защищает записи, корнем которых служит домашний каталог. `--yes`,
неинтерактивная оболочка (без TTY), `--dry-run` и `--format json` — каждый из
этих вариантов продолжает работу без запроса. Только `--dry-run` ничего не
записывает; `--format json` пропускает предпросмотр и запрос подтверждения, но
всё равно выполняет записи. Отказ в запросе по домашнему каталогу прерывает
установку до записи. С `--clean` сначала выполняется шаг очистки с нуля под
собственным подтверждением для каждой цели: он записывает резервную копию в
`~/.apothem/backups` и удаляет подтверждённые цели. Эти удаления и резервная
копия сохраняются, если запрос на установку отклонён.

## Примечания о возможностях

Каждый адаптер проецирует только те возможности, которые его окружение
поддерживает нативно; о возможностях без нативной поверхности сообщается, они не
отбрасываются молча. В режиме plain это одно сгруппированное примечание на
окружение (например,
`Note: <harness> - 9 capabilities not projected; pass --verbose for detail`);
при `--verbose` каждая возможность печатает собственную строку с обоснованием.
Любое другое предупреждение адаптера в режиме plain тоже печатается отдельной
строкой `Warning:`, например предупреждение Zed, называющее файл инструкций,
который оказывается скрыт новым `.rules`. Конверт `--format json` всегда содержит полный
массив `warnings` независимо от уровня детализации.

Установка и обновление также печатают рекомендации в виде строк `Note:`.
Рекомендация никогда не меняет того, что записывает установка. Когда установка
записывает общий корень — путь, который загружают и другие инструменты
(например, папка навыков `~/.agents/skills/`), — примечание называет эти
инструменты. Когда установка нацелена на инструмент, который уже загружает
содержимое Apothem из общего корня другой установки, примечание называет эту
установку. В конверте `--format json` каждая рекомендация — это запись
`warnings` с `"outcome": "advisory"` и `"operation": "shared_root"`.

Для MCP-серверов профиля предусмотрены три рекомендации, каждая из которых
называет поле профиля:

| Операция | Условие | Исправление |
| --- | --- | --- |
| `mcp_deprecated_transport` | `transport: sse` (спецификация MCP объявляет HTTP+SSE устаревшим) | Используйте `streamable-http`, когда сервер его поддерживает. |
| `mcp_plain_http` | URL `http://` к хосту, который не является loopback | Используйте URL `https://`. |
| `mcp_literal_credential` | значение `headers` или `env`, похожее на токен (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`, `sk-`, `xoxa-`, `xoxb-`, `xoxo-`, `xoxp-`, `xoxr-`, `xoxs-`, либо `Bearer` с длинным токеном) | Храните секрет в переменной окружения и пишите ссылки вида `${GITHUB_TOKEN}`. |

Рекомендация об учётных данных никогда не печатает найденное значение.
Значение, содержащее ссылку `${...}`, никогда не помечается.

## Конфигурации оператора с комментариями

Некоторые конфигурации окружений — это файлы, которые вы также редактируете
сами, например `settings.json`, `opencode.json` (который может быть в формате
JSONC), `openclaw.json` (JSON5) и `config.yaml`. Установка объединяет свои ключи
с этими файлами и сохраняет каждый ключ, добавленный вами.

Объединение перезаписывает файл как обычный JSON или YAML, что удалило бы
комментарии, висячие запятые и синтаксис JSON5. Поэтому:

- Когда объединение не изменило бы ни одного значения (например, вы уже сами
  добавили ключи Apothem), файл остаётся побайтово неизменным.
- Когда объединение должно изменить значение в файле, который содержит
  комментарии или синтаксис JSON5, или в файле, который вообще не разбирается,
  установка ничего не записывает для этого окружения и завершается с кодом 1 и
  кодом ошибки `config.unparseable`. Поле `fix` называет ключи, которые добавила
  бы установка, чтобы вы могли преобразовать файл в обычный JSON или YAML либо
  добавить эти ключи вручную и запустить команду повторно.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер окружения для установки или `all` для набора уровня всего реестра (обязателен). С `all` окружения, перечисленные в `exclude_harnesses` профиля, пропускаются, но окружение, названное явно, устанавливается, даже если оно в этом списке. Зарегистрированные имена показывает `apothem harnesses list`. |
| `--profile PATH` | Путь к YAML общего профиля. По умолчанию `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Предпросмотр установки без записи файлов. |
| `--clean`, `--fresh` | Чистый лист по явному запросу: создать резервную копию и удалить прежнее состояние установки для каждого окружения перед установкой. |
| `--yes` | Пропустить подтверждение для каждой цели при удалении в режиме чистого листа (обязателен для неинтерактивных запусков с `--clean`). |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--quiet`, `-q` | Подавить информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Печатать обоснование каждой непроецированной возможности вместо сгруппированного примечания по окружению. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключить цветовые коды ANSI в выводе. |
| `-h`, `--help` | Показать справку и завершить работу. |

## Вывод JSON

Когда указан `--json` (или `--format json`), в stdout записывается один
документ JSON:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "install",
  "action": "installed",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": ["C:\\Users\\Example\\.claude\\settings.json"],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Для `--dry-run` ничего не записывается, а `results` перечисляет каждый путь,
который записала бы установка, — каждый с результатом, который у него был бы
(`created`, `updated` или `unchanged`), а для файла, который вы также
редактируете сами, — с унифицированным diff в `detail.diff`; это тот же план,
который показывает [`apothem diff`](/docs/cli-reference/diff):

```json
{
  "schema_version": 1,
  "status": "dry_run",
  "command": "install",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "created",
      "operation": "write_text",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "dry run: no filesystem changes made"
    }
  ],
  "warnings": [],
  "error": null
}
```

Когда указан `--clean`, конверт дополнительно содержит объект `clean`,
описывающий фазу удаления, — список решений по каждой цели, был ли запуск
предпросмотром, и каталог резервной копии с временной меткой (`null` в пробном
запуске):

```json
{
  "clean": {
    "dry_run": true,
    "backup_dir": null,
    "targets": [
      {
        "path": "C:\\Users\\Example\\.claude",
        "present": true,
        "removed": false,
        "skipped_reason": null
      }
    ]
  }
}
```

Пробный запуск с очисткой показывает предпросмотр обеих фаз в одном документе:
предпросмотр удаления в `clean` и предпросмотр новых записей в `results`.

Ожидаемые ошибки проверки используют тот же конверт и включают объект ошибки:

```json
{
  "schema_version": 1,
  "status": "error",
  "command": "install",
  "harness": "all",
  "files_written": [],
  "error": {
    "code": "project.required",
    "field": "project",
    "reason": "project-scope harnesses require --project: cursor, gemini-cli, github-copilot, kimi-code, windsurf, codebuddy, kiro, trae, zed, glm.",
    "fix": "Pass --project PATH or select only user-scope harnesses."
  }
}
```

## Примеры

```bash
apothem install --harness claude-code
apothem install --harness claude-code --dry-run
apothem install --harness cursor --project . --profile ~/profile.yaml --json
apothem install --harness all --project . --dry-run --json
apothem installing --harness claude-code   # continuous-form alias
apothem Installing --harness claude-code   # capitalized variant
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Адаптер успешно установлен, или пробный запуск спланирован без ошибок |
| 1 | Ожидаемая ошибка проверки, профиля, окружения, проекта или адаптера |
| 2 | Частичная пакетная материализация после как минимум одной записи |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка представляет собой конверт JSON с кодом `cli.usage`. |
