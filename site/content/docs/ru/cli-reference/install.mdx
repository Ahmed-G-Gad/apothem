Устанавливает конфигурацию адаптера окружения из общего профиля.

## Синтаксис

```
apothem install --harness NAME|all [--profile PATH] [--dry-run]
                 [--clean|--fresh] [--yes] [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

Загружает и проверяет общий профиль, выбирает именованный адаптер или набор
`all` уровня всего реестра, проверяет план материализации и записывает нативную
конфигурацию окружения вместе со вспомогательными группами. Адаптеры с областью
проекта требуют `--project PATH`. Папка читается с переходом по ссылкам и
раскрытием `~`, и запись об установке называет её именно так. Установка,
записанная под другим написанием папки, например через ссылку, которую сохранил
код Python или более ранний релиз, переносится на это написание, как только
установка проходит свои проверки
(см. [`uninstall`](/docs/cli-reference/uninstall)).

Псевдоним в продолженной форме `apothem installing` (принимается также как
`apothem Installing`) разрешается в тот же обработчик.

## Первый запуск без профиля

Когда `--profile` не указан и по пути по умолчанию
(`~/.config/apothem/profile.yaml`) профиля нет, `install` сначала записывает туда
стартовый профиль, печатает `Created a starter profile at <path>` и продолжает
работу. Стартовый профиль содержит поля идентичности-заполнители, поэтому
установка также печатает примечание об идентичности-заполнителе; настройте
профиль под себя, затем выполните [`update`](/docs/cli-reference/update), чтобы
применить его. При `--json` создание профиля сообщается как запись `warnings` с
`"operation": "profile_created"`.

- `--dry-run` никогда не записывает профиль: предпросмотр использует стартовый
  профиль в памяти и сообщает `"operation": "profile_scaffold_preview"`.
- Явно указанный `--profile PATH`, который не существует, никогда не создаётся;
  команда завершается с кодом 1 и `profile.not_found`.

## Предпросмотр радиуса поражения

`install --harness all` разветвляется на смешанные области: адаптеры с областью проекта записывают в корень, переданный через `--project`, а адаптеры с областью пользователя записывают в ваш домашний каталог, то есть за пределами этого корня. Прежде чем установка запишет какой-либо файл, команда выводит конкретные цели, сгруппированные под двумя заголовками: цели внутри корня проекта и цели в вашем домашнем каталоге. Третий заголовок перечисляет общие папки в вашем домашнем каталоге, в которые записывают адаптеры с областью проекта за пределами `--project`: папку навыков и `~/.config/apothem/` (см.
[Папки в вашем домашнем каталоге](#папки-в-вашем-домашнем-каталоге)). Единственное исключение — `--clean`: его шаг очистки выполняется до этого предварительного просмотра, записывает резервную копию и удаляет прежние цели, как описано ниже.

Когда выбор записывает за пределы корня проекта, будь то в папку адаптера с
корнем в домашнем каталоге или в общую папку, интерактивное подтверждение
защищает записи, корнем которых служит домашний каталог. `--yes`,
неинтерактивная оболочка (без TTY), `--dry-run` и `--format json` — каждый из
этих вариантов продолжает работу без запроса. Только `--dry-run` ничего не
записывает; `--format json` пропускает предпросмотр и запрос подтверждения, но
всё равно выполняет записи. Отказ в запросе по домашнему каталогу прерывает
установку до записи. С `--clean` сначала выполняется шаг очистки с нуля под
собственным подтверждением для каждой цели: он записывает резервную копию в
`~/.apothem/backups` и удаляет подтверждённые цели. Эти удаления и резервная
копия сохраняются, если запрос на установку отклонён.
Цели — это папки инструментов в вашем домашнем каталоге, которые перечисляет
запрос, в том числе `~/.agents` и `~/.config/apothem`.
У цели, которая сама является ссылкой (включая соединение Windows), удаляется
только ссылка, а ссылка внутри цели удаляется без перехода в неё. Когда
`~/.config` — ссылка, ведущая за пределы вашего домашнего каталога, шаг очистки
с нуля останавливается с `Clean-slate removal was refused`, прежде чем
создать резервную копию или что-либо удалить, поскольку удаление
`~/.config/apothem` удалило бы папку на другом конце этой ссылки. Ошибка
называет ссылку: замените её настоящей папкой или сделайте так, чтобы она вела к
папке внутри домашнего каталога. Шаг также останавливается, прежде чем
что-либо изменить и прежде чем создать начальный профиль, когда ваш домашний
каталог задан не полным путём, является корнем диска или файловой системы,
является ссылкой или соединением, ведущими к такому корню, или достигается
через зацикленную ссылку.

Шаг очистки с нуля удаляет профиль по умолчанию,
`~/.config/apothem/profile.yaml`, вместе с `~/.config/apothem` и затем
записывает его обратно. Профиль, который он не удалял, например переданный
через `--profile PATH` из другой папки, не записывается вообще. Обратная
запись подчиняется тому же правилу, что и любая другая запись профиля: она
отклоняется, когда ссылка вывела бы её за пределы домашнего каталога. Когда
профиль невозможно записать обратно, команда завершается с кодом 1, а ошибка
называет резервную копию, в которой он хранится. Код ошибки —
`clean_slate.profile_restore_refused`, когда запись отклонила ссылка, и
`clean_slate.profile_restore_failed`, когда не удалась сама запись.
Когда удаление останавливается на полпути, например на файле, который держит
открытым другая программа, сначала профиль записывается обратно. Затем команда
завершается с кодом 1 и кодом ошибки `clean_slate.removal_failed`, а ошибка
называет папку резервной копии. Если профиль невозможно записать обратно,
вместо этого выдаётся один из двух кодов ошибки профиля, указанных выше.

## Папки в вашем домашнем каталоге

Семь адаптеров с областью проекта записывают навыки Apothem, а также правила и
шаблоны, на которые ссылаются навыки, в папки в домашнем каталоге пользователя:

```text
cursor, github-copilot, windsurf, zed  ->  ~/.agents/skills/ (codex writes it too)
codebuddy                               ->  ~/.codebuddy/skills/
kiro                                    ->  ~/.kiro/skills/
trae                                    ->  ~/.trae/skills/
all seven                               ->  ~/.config/apothem/rules/ and templates/ (codex uses them too)
```

- `--project` выбирает файл правил и проект, к которому относится установка. Он
  не меняет того, куда попадают навыки: установка с `--project A` и установка с
  `--project B` записывают одни и те же папки.
- Каждая установка, которая называет папку, записывает одни и те же файлы.
  Вторая установка находит их и сообщает `unchanged`, а порядок, в котором вы
  выполняете установки, не имеет значения.
- Папки в домашнем каталоге записываются раньше всего, что находится в проекте.
  Если запись туда завершается сбоем, установка адаптера останавливается с
  ошибкой, а проект остаётся неизменным. Ошибка называет мешающий путь, например
  файл с именем `~/.agents` там, где должна быть папка.
- Каждая папка навыка записывается в скрытую папку `.<name>.apothem-staging`
  рядом с ней и переименовывается на место по завершении, поэтому неудачная или
  прерванная запись никогда не оставляет наполовину записанную папку навыка под
  её окончательным именем. Запустите установку снова, чтобы завершить её; она
  заменяет оставшуюся промежуточную папку.
- Ссылка на месте одной из этих папок или выше неё, какие создают
  менеджеры dotfile-файлов для `~/.config` или `~/.agents`, используется, когда
  она ведёт куда-либо внутри вашего домашнего каталога. На Windows соединение
  считается ссылкой. Ссылка, которая выходит за пределы вашего домашнего
  каталога, останавливает установку с `target escapes the
  allowed materialization root`, за которым следуют ссылка, папка, к которой она
  ведёт, и способ исправления: замените ссылку настоящей папкой. Через папку
  навыка, которая сама является ссылкой, запись никогда не выполняется:
  установка пропускает её с предупреждением или останавливается, если Apothem
  ранее записал туда этот навык. Ссылка внутри папки навыка, записанной
  Apothem, заменяется папкой, когда установка в следующий раз записывает этот
  навык.
- Папка окружения ниже `~/.config`, например `~/.config/opencode/` для OpenCode
  или `CODEX_HOME` там же, тоже использует ссылку на месте `~/.config`, которая
  ведёт куда-либо внутри вашего домашнего каталога. Ссылка на месте `~/.config`,
  которая выходит за пределы домашнего каталога, останавливает установку до
  записи какого-либо файла, как и ссылка на пути, который установка записывает
  внутри папки окружения. При первом запуске начальный профиль, тоже
  находящийся ниже `~/.config`, также не записывается через ссылку, выходящую
  за пределы домашнего каталога: запуск останавливается с `Apothem could
  not create the starter profile`, как и `apothem quickstart`, `apothem profile
  init`, `apothem profile set` и `apothem profile edit`. Чтобы хранить профиль
  вне домашнего каталога, сначала создайте его там с помощью `apothem
  profile init --profile PATH`, указав в PATH его собственный путь вне
  домашнего каталога, и передавайте тот же `--profile PATH` каждой команде. Это
  позволяет пройти только шаг профиля: установка, которая записывает ниже
  `~/.config`, всё равно останавливается на ссылке. Для OpenCode также задайте
  `XDG_CONFIG_HOME` (см. [OpenCode](/docs/harnesses/opencode)). Окружению,
  установка которого всегда записывает `~/.config/apothem/`, нужно, чтобы
  ссылка вела внутрь домашнего каталога; об этом сказано на странице этого
  окружения.
- Домашняя папка, которая сама является ссылкой, например профиль пользователя
  Windows, перенесённый на другой диск за соединением, используется: каждая
  запись остаётся внутри папки, к которой она ведёт.
- Установка не добавляет в ваш репозиторий ни одного файла навыка или правил.
  Проект получает файл правил адаптера, а также папку данных `.apothem/`,
  которую создаёт каждая установка в проект.
- Папка навыка, которая носит имя навыка Apothem и которую Apothem не
  записывал, пропускается. Установка печатает строку `Warning:`, а конверт
  `--format json` содержит запись `warnings` с `"outcome": "warning"` и
  `"operation": "skill_conflict"`, которая называет эту папку. Переименуйте или
  переместите папку, затем выполните [`update`](/docs/cli-reference/update).
- Это правило охватывает каждую общую папку навыков из таблицы выше:
  `~/.agents/skills/`, `~/.codebuddy/skills/`, `~/.kiro/skills/` и
  `~/.trae/skills/`. Запись об установке показывает, что папка навыка там
  принадлежит Apothem, пока папка её установки (проект или `CODEX_HOME`)
  действующая: она существует и всё ещё содержит один из файлов, которые эта
  установка в ней записала, с содержимым Apothem. Файл, которым владеет
  Apothem, засчитывается, пока он существует. Ваш файл, например файл
  инструкций, в который Apothem добавил свой блок, засчитывается, только пока
  он всё ещё содержит этот блок или, для файла без блока, содержимое, которое
  записал Apothem, поэтому заново клонированный проект, в котором осталась
  только собственная копия файла, не является действующим. Вспомогательные
  файлы, которые установка записывает в `.apothem/support/`, засчитываются;
  хранилища данных в `.apothem/` (память, контексты, планы) — нет, как и файл,
  к которому ведёт ссылка внутри папки установки.
- Любая другая запись, папка установки которой больше не существует, не
  содержит файлов Apothem или не может быть прочитана (диск или сетевой ресурс,
  который не отвечает, ошибка доступа), показывает, что папка навыка
  принадлежит Apothem, только пока эта папка содержит ровно те файлы, которые
  записала эта установка, без изменений, без добавленных файлов и без ссылок
  внутри. Папка, которая уже содержит то, что записывает этот релиз,
  сохраняется как есть, поэтому неотредактированная папка, записанная более
  ранним релизом, не затрагивается, пока она совпадает с тем, что записывает
  этот релиз.
- Сами общие папки никогда не считаются файлами папки установки, поэтому
  проект, установленный в домашнюю папку, не является действующим только
  потому, что существует `~/.agents/skills/` или `~/.config/apothem/`.
- Поэтому, когда папку навыка перечисляют только такие записи, установка
  пропускает её и оставляет нетронутой в трёх случаях: вы поместили туда
  собственный навык, вы его отредактировали (изменили, добавили или удалили
  файл) или её записал более ранний релиз, который не записывал свои файлы, а
  этот релиз записывает что-то другое.
  То же верно, когда её перечисляла только более ранняя установка в той же
  папке: установка, которая пропустила папку, не перечисляет её, и
  принадлежность всё равно не доказана, если папка не содержит ровно те файлы,
  которые записала та более ранняя установка.
  Предупреждение установки, обновления и пробного запуска называет причину и
  два пути дальше теми же словами, что и [`verify`](/docs/cli-reference/verify),
  которая сообщает, что окружение не
  проверено, и называет эти папки. Чтобы сохранить свой навык, оставьте его
  там. Чтобы использовать версию Apothem, переместите папку из папки навыков,
  затем выполните [`update`](/docs/cli-reference/update) для этого окружения
  (с `--project` для окружения с областью проекта).
- Каждая такая установка, обновление и пробный запуск печатают `Note:`, которое
  называет папки, записываемые за пределами `--project`. В конверте JSON это
  запись `warnings` с `"operation": "user_level_write"` и списком `paths`.

## Примечания о возможностях

Каждый адаптер проецирует только те возможности, которые его окружение
поддерживает нативно; о возможностях без нативной поверхности сообщается, они не
отбрасываются молча. В режиме plain это одно сгруппированное примечание на
окружение (например,
`Note: <harness> - 9 capabilities not projected; pass --verbose for detail`);
при `--verbose` каждая возможность печатает собственную строку с обоснованием.
Любое другое предупреждение адаптера в режиме plain тоже печатается отдельной
строкой `Warning:`, например предупреждение Zed, называющее файл инструкций,
который оказывается скрыт новым `.rules`, и предупреждение, называющее файл с
маркером BEGIN Apothem, после которого нет END: установка сохраняет текст после
этого маркера и записывает блок Apothem отдельно от него, поэтому
предупреждение называет строку маркера, даёт пронумерованные шаги, которые
изменяют эту строку и каждую другую строку маркера BEGIN, кроме той, что
открывает блок Apothem (в том числе маркер BEGIN, который вы цитируете в
коде), и говорит не добавлять вместо этого маркер END обратно, поскольку
тогда остались бы два блока Apothem (см.
[Устранение неполадок](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker)).
Так же работают предупреждение для файла, который содержит два или более целых
блока между маркерами Apothem и называет каждый блок по его строкам (см.
[Файл содержит два блока между маркерами Apothem](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers)),
и предупреждение для файла, где Apothem не может отличить свой блок от вашего
текста, которое называет каждую пару маркеров и способ её исправить (см.
[Apothem не может отличить свой блок от вашего текста](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)):
установка оставляет такой файл как есть (для пар маркеров — пока запись об
установке перечисляет этот файл; см. [`update`](/docs/cli-reference/update)).
Установка, которая оставляет такой файл как есть, завершается частично,
поскольку инструмент не получает из этого файла актуальный блок Apothem:
вместо строки `✓` она печатает в стандартный поток ошибок строку `✗`, которая
называет файл (поэтому `--quiet` её сохраняет), `status` конверта
`--format json` равен `"partial"`, предупреждение для этого файла содержит
`"detail": {"left_as_is": "1"}`, а код выхода — `2`. Каждая установка и
каждое обновление завершаются так, пока вы не исправите строки маркеров,
которые называет предупреждение. Без `--quiet` такая установка с
`--harness all` завершается итоговой строкой, которая начинается с `!` вместо
`✓` и подсчитывает файлы, оставленные как есть:
`! Installed <n> harnesses (<m> files written); <k> file(s) left as they are, named above.`
С `--clean` такая установка не печатает свой следующий шаг,
`apothem verify`, который проваливается, пока вы не исправите файл. В пробном
запуске предупреждение для файла, оставленного как есть, говорит, что Apothem
«would leave the file as it is», а запуск всё равно завершается со `status`
`"dry_run"` и кодом выхода `0`. Правило в вашем профиле, которое открывает
блок кода и никогда его не закрывает, не скрывает маркер END блока, который
записывает установка: установка закрывает этот блок кода в конце блока. В
блоке, который более ранний релиз записал из такого правила, такой
закрывающей строки нет. Ваш блок кода, который открывается выше блока Apothem
и никогда не закрывается, — другой случай: закрывающая строка в блоке
закрывает его, поэтому блок читается как код. Установка предупреждает о таком
блоке сразу, как только его записывает, и предупреждение называет блок кода,
который нужно закрыть выше маркера BEGIN (см.
[Apothem не может отличить свой блок от вашего текста](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)).
Пробный запуск читает файл до того, как что-либо записано, поэтому он не
показывает, что после записи блок читался бы как код.
Конверт `--format json` всегда содержит полный массив `warnings` независимо от
уровня детализации.

Установка и обновление также печатают рекомендации в виде строк `Note:`.
Рекомендация никогда не меняет того, что записывает установка. Когда установка
записывает общий корень — путь, который загружают и другие инструменты
(например, папка навыков `~/.agents/skills/`), — примечание называет эти
инструменты и заключает в скобки инструмент, который загружает путь только при
некотором условии, например `Open-Claw (only under its default state
directory)`. Установка, которая записывает папку, в которую записывают и другие
установки (роль `holder`), сообщает, что папка остаётся, пока не будет удалена
последняя установка Apothem, которая её использует, и называет установки,
которые используют её сейчас. Когда установка нацелена на инструмент, который
уже загружает содержимое Apothem из общего корня другой установки, примечание
называет установку, которая его поместила: зарегистрированного владельца, пока
он ещё использует папку, иначе самую старую установку, которая её использует. В
конверте `--format json` каждая рекомендация — это запись `warnings` с
`"outcome": "advisory"` и `"operation": "shared_root"`; её `role` — это `owner`,
`holder` или `reader`, `holders` перечисляет установки, использующие папку, а
`owner_of_record` называет зарегистрированного владельца.

Установка, которая регистрирует хуки, также печатает примечания о файле хуков.
Рекомендация `hook_review` называет шаг, который нужен инструменту, прежде чем
он запустит хуки (перезапуск и проверка либо доверие к рабочей области), или
опасность файла хуков, который фиксируется в репозитории и называет
интерпретатор этой машины. Рекомендация `hook_import` появляется для
инструмента, который также запускает хуки из файлов настроек Claude Code,
например тех, что записывает установка Apothem для Claude Code, и называет
собственный переключатель инструмента для отключения этого импорта и то, что
этот переключатель также останавливает. Каждая из них — это запись `warnings` с
`"outcome": "advisory"`, `harness`, `path` файла хуков и `message`.

Команда хука держит путь к проекту и путь к интерпретатору внутри двойных
кавычек, которые читают и `sh`, и Git Bash, и PowerShell. Путь, содержащий `$`,
обратную кавычку, двойную кавычку или обратную косую черту, заставил бы команду
запустить другой файл, поэтому установка (и `--dry-run`) останавливается с
ошибкой, которая называет путь, и ничего не записывает; переместите или
переименуйте проект и запустите команду снова. Пробел или апостроф в пути
допустимы.

Некоторые инструменты загружают только первый файл с текстом из фиксированного
списка в папке, поэтому ваш файл, стоящий перед тем, который записывает
Apothem, не даёт инструменту загрузить блок Apothem. Например,
[один из поддерживаемых инструментов](/docs/harnesses/codex#compatibility-notes)
читает `AGENTS.override.md` с текстом вместо `AGENTS.md`, который Apothem
записывает рядом с ним в домашней папке этого инструмента. Тогда установка и
обновление печатают примечание, которое называет этот файл, в том числе в
пробных запусках. Пустой файл переопределения пропускается, как и
символическая ссылка на `AGENTS.md`; жёсткая ссылка или копия получают
примечание, потому что установка, которая перезаписывает `AGENTS.md`,
оставляет её отдельным файлом. OpenCode 1 работает иначе: список
`instructions` в `opencode.jsonc`, даже пустой, заменяет список, который
Apothem записывает в `opencode.json` в той же папке. Файл `config.json`,
`opencode.json` или `opencode.jsonc` там, который он не может прочитать или
разобрать, верхний уровень которого не является объектом, значение
`instructions` которого не является списком строк или в котором `{file:path}`
называет файл, который он не может прочитать, не даёт ему загрузить никакую
свою конфигурацию, как и папка с одним из этих имён. Установка и обновление
печатают примечание `instruction_override` и для каждого такого файла, кроме
`opencode.json`, который они не могут разобрать даже как JSON5: его они
отклоняют с ошибкой `config.unparseable`
([примечания об OpenCode](/docs/harnesses/opencode#compatibility-notes)).
Примечание — это запись `warnings` с `"outcome": "advisory"` и
`"operation": "instruction_override"`, `harness`, `path` файла, о котором
примечание, `target`, который записывает установка, и `message`.

Для MCP-серверов профиля предусмотрены три рекомендации, каждая из которых
называет поле профиля:

| Операция | Условие | Исправление |
| --- | --- | --- |
| `mcp_deprecated_transport` | `transport: sse` (спецификация MCP объявляет HTTP+SSE устаревшим) | Используйте `streamable-http`, когда сервер его поддерживает. |
| `mcp_plain_http` | URL `http://` к хосту, который не является loopback | Используйте URL `https://`. |
| `mcp_literal_credential` | значение `headers` или `env`, похожее на токен (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`, `sk-`, `xoxa-`, `xoxb-`, `xoxo-`, `xoxp-`, `xoxr-`, `xoxs-`, либо `Bearer` с длинным токеном) | Храните секрет в переменной окружения и пишите ссылки вида `${GITHUB_TOKEN}`. |

Рекомендация об учётных данных никогда не печатает найденное значение.
Значение, содержащее ссылку `${...}`, никогда не помечается.

## Конфигурации оператора с комментариями

Некоторые конфигурации окружений — это файлы, которые вы также редактируете
сами, например `settings.json`, `opencode.json` (который может быть в формате
JSONC), `openclaw.json` (JSON5) и `config.yaml`. Установка объединяет свои ключи
с этими файлами и сохраняет каждый ключ, добавленный вами.

Объединение перезаписывает файл как обычный JSON или YAML, что удалило бы
комментарии, висячие запятые и синтаксис JSON5. Поэтому:

- Когда объединение не изменило бы ни одного значения (например, вы уже сами
  добавили ключи Apothem), файл остаётся побайтово неизменным.
- Когда объединение должно изменить значение в файле, который содержит
  комментарии или синтаксис JSON5, или в файле, который вообще не разбирается,
  установка ничего не записывает для этого окружения и завершается с кодом 1 и
  кодом ошибки `config.unparseable`. Поле `fix` называет ключи, которые добавила
  бы установка, чтобы вы могли преобразовать файл в обычный JSON или YAML либо
  добавить эти ключи вручную и запустить команду повторно.
- Когда ключ, который установка заполняет отображением или списком (например,
  `skills.external_dirs` в `config.yaml`), содержит в вашем файле скалярное
  значение или контейнер другой формы, установка ничего не записывает для этого
  окружения и завершается с кодом 1 и тем же кодом ошибки, потому что
  заполнение ключа отбросило бы ваше значение. Ошибка называет ключ; приведите
  его к названной в ней форме или удалите и запустите команду повторно. Ключ,
  который вы оставили пустым (`skills:`, под которым ничего нет), заполняется.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер окружения для установки или `all` для набора уровня всего реестра (обязателен). С `all` окружения, перечисленные в `exclude_harnesses` профиля, пропускаются, но окружение, названное явно, устанавливается, даже если оно в этом списке. Зарегистрированные имена показывает `apothem harnesses list`. |
| `--profile PATH` | Путь к YAML общего профиля. По умолчанию `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Предпросмотр установки без записи файлов. |
| `--clean`, `--fresh` | Чистый лист по явному запросу: создать резервную копию и удалить прежнее состояние установки для каждого окружения перед установкой. |
| `--yes` | Пропустить подтверждение для каждой цели при удалении в режиме чистого листа (обязателен для неинтерактивных запусков с `--clean`). |
| `--project PATH` | Корень проекта для окружений с областью проекта. |
| `--quiet`, `-q` | Подавить информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Печатать обоснование каждой непроецированной возможности вместо сгруппированного примечания по окружению. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключить цветовые коды ANSI в выводе. |
| `-h`, `--help` | Показать справку и завершить работу. |

## Вывод JSON

Когда указан `--json` (или `--format json`), в stdout записывается один
документ JSON:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "install",
  "action": "installed",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": ["C:\\Users\\Example\\.claude\\settings.json"],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Установка, которая оставила файл как есть из-за его строк маркеров Apothem,
имеет `status` `"partial"` и завершается с кодом `2` (см.
[Примечания о возможностях](#примечания-о-возможностях)).

Для `--dry-run` ничего не записывается, а `results` перечисляет каждый путь,
который записала бы установка, — каждый с результатом, который у него был бы
(`created`, `updated` или `unchanged`), а для файла, который вы также
редактируете сами, — с унифицированным diff в `detail.diff`; это тот же план,
который показывает [`apothem diff`](/docs/cli-reference/diff):

```json
{
  "schema_version": 1,
  "status": "dry_run",
  "command": "install",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "created",
      "operation": "write_text",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "dry run: no filesystem changes made"
    }
  ],
  "warnings": [],
  "error": null
}
```

Результат, отклонённый на ссылке, называет ссылку в `detail.symlink`, а путь,
к которому она ведёт, — в `detail.leads_to`. Результат, отклонённый потому, что
ссылка выводит папку инструмента за пределы вашего домашнего каталога, также
содержит способ исправления в `detail.fix`.

Когда указан `--clean`, конверт дополнительно содержит объект `clean`,
описывающий фазу удаления, — список решений по каждой цели, был ли запуск
предпросмотром, и каталог резервной копии с временной меткой (`null` в пробном
запуске):

```json
{
  "clean": {
    "dry_run": true,
    "backup_dir": null,
    "targets": [
      {
        "path": "C:\\Users\\Example\\.claude",
        "present": true,
        "removed": false,
        "skipped_reason": null
      }
    ]
  }
}
```

Пробный запуск с очисткой показывает предпросмотр обеих фаз в одном документе:
предпросмотр удаления в `clean` и предпросмотр новых записей в `results`.

Ожидаемые ошибки проверки используют тот же конверт и включают объект ошибки:

```json
{
  "schema_version": 1,
  "status": "error",
  "command": "install",
  "harness": "all",
  "files_written": [],
  "error": {
    "code": "project.required",
    "field": "project",
    "reason": "project-scope harnesses require --project: cursor, gemini-cli, github-copilot, kimi-code, windsurf, codebuddy, kiro, trae, zed, glm.",
    "fix": "Pass --project PATH or select only user-scope harnesses."
  }
}
```

## Примеры

```bash
apothem install --harness claude-code
apothem install --harness claude-code --dry-run
apothem install --harness cursor --project . --profile ~/profile.yaml --json
apothem install --harness all --project . --dry-run --json
apothem installing --harness claude-code   # continuous-form alias
apothem Installing --harness claude-code   # capitalized variant
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Адаптер успешно установлен, или пробный запуск спланирован без ошибок |
| 1 | Ожидаемая ошибка проверки, профиля, окружения, проекта или адаптера |
| 2 | Частичный результат: пакет остановился после как минимум одной записи, или установка оставила файл, в котором Apothem хранит свой блок, как есть из-за его строк маркеров Apothem (см. [Примечания о возможностях](#примечания-о-возможностях)); `status` равен `"partial"` |
| 64 | Ошибка использования: неизвестный параметр или команда либо отсутствующее или недопустимое значение параметра. При `--json` ошибка представляет собой конверт JSON с кодом `cli.usage`. |
