Предпросмотр ожидающих изменений конфигурации для одного ассистента по написанию кода.

## Сводка

```
apothem diff --harness NAME [--profile PATH] [--project PATH]
             [--quiet|-q] [--verbose|-v]
             [--format plain|json] [--json] [--no-color]
```

`diff` — это команда инспекции только для чтения. Она выполняет ту же материализацию,
что и команда `install`, но в режиме симуляции — на диск ничего не записывается. Затем
она отрисовывает по каждой запланированной цели операцию, целевой путь, исход и (для
принадлежащих оператору якорей, которые были бы объединены) унифицированный diff
изменения. Это ответ на вопрос «что `apothem install` сделал бы с этим ассистентом по
написанию кода прямо сейчас?» без внесения изменения.

Для целей, принадлежащих оператору — файлов, которые несут как ваше собственное
содержимое, так и управляемый Apothem блок — diff показывает точные строки, которые
изменились бы. Для остальных целей запланированная операция и исход сводятся в обобщённом
виде.

`diff` работает с одним ассистентом по написанию кода. В отличие от `status`, она не
принимает `all`; передайте одно имя ассистента по написанию кода.

## Параметры

| Параметр | Описание |
|---|---|
| `--harness NAME` | Адаптер ассистента по написанию кода для предпросмотра (обязательно; один ассистент, не `all`). |
| `--profile PATH` | Путь к YAML общего профиля. По умолчанию `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Корень проекта для ассистентов по написанию кода с областью проекта. Обязателен, когда выбранный ассистент имеет область проекта. |
| `--quiet`, `-q` | Подавляет информационный вывод; выводятся только ошибки. |
| `--verbose`, `-v` | Выводит дополнительный диагностический вывод. |
| `--format plain\|json` | Формат вывода (по умолчанию: `plain`). |
| `--json` | Сокращение для `--format json`. |
| `--no-color` | Отключает коды цвета ANSI в выводе. |
| `-h`, `--help` | Показывает справку и завершает работу. |

## Вывод JSON

Конверт `--json` отражает конверт установки в режиме симуляции. `status` равен
`dry_run`, `files_written` всегда пуст, а блок `materialization` и список `results`
несут полную детализацию запланированной цели. Поле `detail.diff` каждой принадлежащей
оператору строки результата несёт строку унифицированного diff.

```json
{
  "status": "dry_run",
  "command": "diff",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "sentinel_merge",
      "path": "C:\\Users\\Example\\.claude\\CLAUDE.md",
      "message": "dry run: no filesystem changes made",
      "detail": {
        "ownership_class": "operator-owned",
        "diff": "--- a/CLAUDE.md\n+++ b/CLAUDE.md\n@@ ..."
      }
    }
  ],
  "warnings": [],
  "error": null,
  "materialization": { "...": "..." }
}
```

## Примеры

```bash
apothem diff --harness claude-code
apothem diff --harness cursor --project .
apothem diff --harness claude-code --json
```

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Diff сообщён (ожидающие изменения сообщаются, а не являются ошибкой) |
| 1 | Ожидаемая ошибка проверки, профиля, ассистента по написанию кода или проекта |
