Apothem устанавливается менее чем за две минуты и работает рядом с вашей
существующей конфигурацией среды. Каждый путь запускает один и тот же
самодостаточный движок — дерево исходного кода несёт свои вендоренные
зависимости и запускается из чекаута на системном Python 3.10 или новее (см.
[самодостаточную среду выполнения](/docs/architecture/self-contained-runtime)).

**Два предварительных требования являются общими для каждого пути:** системный
**Python 3.10 или новее** в `PATH`, с импортируемыми под ним пакетами `click` и
`rich`. Пути npm-шима и плагинов инструментов дополнительно нуждаются в
**Node.js 18 или новее** для запуска `npx`. Раздел каждого канала ниже повторяет
его точные предварительные требования, одну готовую к копированию команду и шаг
проверки.

## Выберите канал

Доступно восемь каналов установки. Выбирайте по тому, как вы уже работаете.

| # | Канал | Что даёт | Предварительные требования |

| 2 | [npm-шим (`npx`)](#2-npm-шим-npx) | Полная среда, любой инструмент | Node 18+ · Python 3.10+ |
| 3 | [Одношаговые установщики](#3-одношаговые-установщики) | Полная среда + команда `apothem` | Python 3.10+ (`git` для сетевой установки) |
| 4 | [Расширение для семейства VS Code](#4-расширение-для-семейства-vs-code) | Полная среда из редактора | VS Code · Node 18+ · Python 3.10+ |
| 5 | [Загрузчик командной строки (хост-расширение)](#5-загрузчик-командной-строки-хост-расширение) | Загрузчик, который запускает движок | Его хост-инструмент · Node 18+ · Python 3.10+ |

<Callout title="Какие каналы дают полную среду">
  npm-шим (2), одношаговые установщики (3) и прямой движок (8) сами по себе
  материализуют весь синхронизируемый набор для любой среды. Три расширения
  командной строки (5–7) устанавливают небольшой **загрузчик**, который вызывает
  движок (`npx @ahmed-g-gad/apothem install`), чтобы материализовать полную
  среду — они являются точкой входа, а не полной поставкой сами по себе. Плагин

  его напрямую.
</Callout>

Каждый путь идемпотентен: повторный запуск безопасен и сходится к тому же
состоянию.

## 1. Плагин Claude Code

**Предварительные требования:** Claude Code и системный Python 3.10+ в `PATH`.

Путь плагина выполняется целиком внутри Claude Code. Он упаковывает движок
Apothem вместе с его слеш-командами, делегированными исполнителями, навыками,
правилами и хуками — всё это запускается из самодостаточного дерева плагина:

```text title="Inside Claude Code"
/plugin marketplace add ahmed-g-gad/apothem
/plugin install apothem@apothem
```

После установки набор команд Apothem (`/plan-spec`, `/code-review`,
`/security-audit` и остальные), включённые делегированные исполнители и навыки
доступны в каждой сессии Claude Code. Полный каталог команд см. в разделе
[Слеш-команды](/docs/reference/commands).

**Проверка:** запустите `/plugin` внутри Claude Code и подтвердите, что
**apothem** отображается как установленный, либо проверьте отчёт о расхождении из
терминала:

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 2. npm-шим (`npx`)

**Предварительные требования:** Node.js 18+ (для `npx`) и системный Python 3.10+
в `PATH`. Шим находит интерпретатор и передаёт каждую команду CLI встроенному
движку — ничего не размещается на вашей системе постоянно.

```bash title="npx"
npx @ahmed-g-gad/apothem install --harness claude-code
```

Он также запускается прямо из репозитория:

```bash title="npx from the repository"
npx github:ahmed-g-gad/apothem install --harness claude-code
```

Каждая команда из [справочника CLI](/docs/cli-reference) работает в этой форме;
замените `apothem` на `npx @ahmed-g-gad/apothem`. Это также путь установки для
OpenCode и любого другого инструмента, который не предоставляет отдельного реестра
плагинов или расширений — Apothem синхронизирует их прямо в их нативный каталог
конфигурации (`npx @ahmed-g-gad/apothem install --harness opencode`).

**Проверка:**

```bash title="Verify"
npx @ahmed-g-gad/apothem --version
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 3. Одношаговые установщики

**Предварительные требования:** системный Python 3.10+ в `PATH` (установщик
предлагает добавить предварительные требования `click` / `rich` за вас); `git`
нужен только для сетевой установки, которая клонирует исходный код.

Скрипты установки разрешают последний подписанный тег версии, проверяют его
подпись, размещают дерево исходного кода Apothem в `~/.apothem` на этом теге,
создают начальный профиль, если его нет, материализуют вашу первую среду и
проверяют результат. Повторный запуск идемпотентен: существующее дерево снова
обновляется до разрешённого тега, а среда повторно материализуется. Установка,
привязанная к тегу и проверенная, — путь по умолчанию и рекомендуемый.

```bash title="macOS · Linux · WSL2 · BSD — latest signed tag, verified"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell — latest signed tag, verified"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

Те же скрипты поставляются в чекауте под `scripts/installer/` — `install`,
`uninstall` и `update` в формах `.sh`, `.ps1` и `.bat` — так что вы можете
запускать их напрямую после клонирования:

```bash title="From a checkout"
APOTHEM_HARNESS=claude-code sh scripts/installer/install.sh                                 # POSIX
$env:APOTHEM_HARNESS = 'claude-code'; pwsh -NoProfile -File scripts/installer/install.ps1   # Windows
```

### Модель доверия

Без заданного `APOTHEM_REF` установщик разрешает наивысший тег версии
`vMAJOR.MINOR.PATCH` и загружает *именно его* — никогда подвижную ветку `main`.
Перед материализацией любой конфигурации подпись загруженного тега проверяется с
помощью `git verify-tag`; неподписанный, подделанный или непроверяемый тег
прерывает установку до того, как что-либо будет записано. Зафиксируйте
конкретную версию с помощью `APOTHEM_REF`:

```bash title="Pinned, verified install"
APOTHEM_REF=vMAJOR.MINOR.PATCH sh -c "$(curl -fsSL https://apothem.ahmedgad.com/install.sh)"
```

Замените `vMAJOR.MINOR.PATCH` на тег со
[страницы выпусков](https://github.com/ahmed-g-gad/apothem/releases).

Два явных переопределения ослабляют поведение по умолчанию: `APOTHEM_REF=main`
загружает подвижную ветку (без проверки), а `APOTHEM_ALLOW_UNVERIFIED=1`
понижает сбой проверки до предупреждения и продолжает — для офлайн, локального
или предварительно подписанного использования. Локальный чекаут через
`APOTHEM_SOURCE` ничего не загружает и пропускает проверку.

Затем движок выполняется прямо из размещённого дерева как самодостаточная среда
выполнения — его сторонние зависимости вендорены внутри дерева исходного кода,
поэтому реестр пакетов не задействуется:

```bash
PYTHONPATH="$HOME/.apothem/src" python -m apothem <command>
```

Оба скрипта читают одни и те же конфигурационные переменные окружения
(`APOTHEM_HOME`, `APOTHEM_REPO`, `APOTHEM_REF`, `APOTHEM_ALLOW_UNVERIFIED`,
`APOTHEM_SOURCE`, `APOTHEM_HARNESS`, `APOTHEM_PROFILE`, `APOTHEM_SKIP_VERIFY`,
`APOTHEM_AUTO_INSTALL_DEPS`); полную таблицу см. в разделе
[Переменные окружения установщика](/docs/how-to/installer-environment-variables),
а как работает модель вызова `python -m` — в разделе
[Самодостаточная среда выполнения](/docs/architecture/self-contained-runtime).

**Команда `apothem`.** После успешной установки установщик пишет шим `apothem`,
который перенаправляет во встроенный движок — POSIX в `$HOME/.local/bin`, Windows
в `%LOCALAPPDATA%\Microsoft\WindowsApps` (пользовательский каталог, уже
находящийся в стандартном `PATH` Windows). Установщик никогда не редактирует ваш
`PATH`. Как только каталог окажется в `PATH`, вы запускаете `apothem <command>`
напрямую, без ручного `PYTHONPATH`.

**Проверка:**

```bash title="Verify"
apothem verify --harness claude-code

# or, before the shim is on PATH, from the bundled source:
PYTHONPATH="$HOME/.apothem/src" python -m apothem verify --harness claude-code
```

## 4. Расширение для семейства VS Code

**Предварительные требования:** VS Code, Node.js 18+ и системный Python 3.10+ в
`PATH`.

Расширение **Apothem** устанавливается из
[Visual Studio Marketplace](https://marketplace.visualstudio.com/) — одно
расширение покрывает VS Code и его внутриредакторную поверхность
ассистента-компаньона. Его команды палитры (`Apothem: Install`, `Verify`,
`Update`, `Uninstall`, `Doctor`) запускают тот же движок через настроенный
исполнитель (по умолчанию `npx @ahmed-g-gad/apothem`; укажите в настройке
`apothem.runner` локальный чекаут, чтобы запускать из исходного кода).

**Проверка:** запустите команду **Apothem: Verify** из палитры команд редактора
или из терминала:

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 5. Загрузчик командной строки (хост-расширение)

**Предварительные требования:** его хост-инструмент командной строки, Node.js 18+
и системный Python 3.10+ в `PATH`.

Установите Apothem как расширение прямо из репозитория — команда несёт точный slug
хоста и среды:

```bash title="Install the extension"
gemini extensions install https://github.com/ahmed-g-gad/apothem
```

Это расширение — **загрузчик**, а не полная установка сама по себе: оно загружает
контекстный файл Apothem и добавляет команду `/apothem`, которая вызывает движок
(`npx @ahmed-g-gad/apothem`). Материализуйте полную среду, запустив установку
через него:

```bash title="Materialize the full harness"
npx @ahmed-g-gad/apothem install --harness gemini-cli --project .
```

**Проверка:**

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness gemini-cli --project .
```

## 6. Загрузчик командной строки (хост `qwen-code`)

**Предварительные требования:** его хост-инструмент командной строки, Node.js 18+
и системный Python 3.10+ в `PATH`.

Установите Apothem как расширение `--harness qwen-code` прямо из репозитория:


Как и расширение канала 5, это **загрузчик**: он загружает контекстный файл
Apothem и вызывает движок. Материализуйте полную среду, запустив установку через
него:

```bash title="Materialize the full harness"
npx @ahmed-g-gad/apothem install --harness qwen-code
```

**Проверка:**

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness qwen-code
```

## 7. Загрузчик командной строки (хост-плагин)

**Предварительные требования:** его хост-инструмент командной строки, Node.js 18+
и системный Python 3.10+ в `PATH`.

Добавьте репозиторий как маркетплейс плагинов, затем установите плагин — команда
несёт точный slug хоста и среды:

```bash title="Install the plugin"
codex plugin marketplace add ahmed-g-gad/apothem
codex plugin add apothem@apothem
```

Как и расширения каналов 5 и 6, это **загрузчик**, который вызывает движок.
Материализуйте полную среду, запустив установку через него:

```bash title="Materialize the full harness"
npx @ahmed-g-gad/apothem install --harness codex
```

**Проверка:**

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness codex
```

## 8. Прямой движок (`python -m apothem`)

**Предварительные требования:** системный Python 3.10+ с импортируемыми пакетами
`click` и `rich`, плюс чекаут репозитория. Node.js не требуется.

Запустите самодостаточный движок прямо из клона — дерево исходного кода несёт свои
вендоренные зависимости, так что `PYTHONPATH=src` — это вся настройка:

```bash title="Direct engine"
git clone https://github.com/ahmed-g-gad/apothem
cd apothem
PYTHONPATH=src python -m apothem install --harness claude-code
```

**Проверка:**

```bash title="Verify"
PYTHONPATH=src python -m apothem verify --harness claude-code
```

## Проверка любой установки

Каждый канал выше называет свою собственную команду проверки. Две общие формы:

```bash title="Installer path"
PYTHONPATH="$HOME/.apothem/src" python -m apothem verify --harness claude-code
```

```bash title="npx path"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

Замените имя среды на установленный вами адаптер; все поддерживаемые имена см. в
[списке сред](/docs/harnesses). Чтобы одним взглядом проверить каждый
зарегистрированный адаптер, запустите `apothem doctor` (или
`npx @ahmed-g-gad/apothem doctor`) в той же форме. Для пути плагина запустите
`/plugin` внутри Claude Code и подтвердите, что **apothem** отображается как
установленный.

## Предварительные требования кратко

- **Python 3.10 или новее** — каждый путь, запускающий движок, ищет его
  (`python3`, `python`, имена с версией и `py -3` в Windows).
- **импортируемые `click` и `rich`** под этим интерпретатором — две
  терминальные зависимости, которые движок не вендорит. Установщики проверяют
  обе, называют всё недостающее и предлагают установить это за вас — с вашего
  подтверждения или автоматически с `--yes` (`-Yes` в PowerShell) либо
  `APOTHEM_AUTO_INSTALL_DEPS=1`.
- **Node.js 18 или новее** — только пути npm-шима и плагинов инструментов.
- **Git** — только путь установщика, и только для сетевой формы (скрипт
  клонирует исходный код; локальный чекаут не требует клонирования).
- **Claude Code** — только путь плагина. **VS Code** и собственный хост-инструмент
  каждого загрузчика командной строки нужны только для их собственного канала
  (4–7).
