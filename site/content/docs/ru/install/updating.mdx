## Обновление плагина Claude Code

Обновите запись в маркетплейсе, затем обновите плагин из меню `/plugin`
внутри Claude Code:

```text title="Inside Claude Code"
/plugin marketplace update apothem
```

Откройте `/plugin`, выберите **apothem** и выберите действие обновления, когда в списке появится более новая
версия плагина.

## npx всегда запускает текущий релиз

`npx @ahmed-g-gad/apothem` разрешает текущий опубликованный пакет при каждом
запуске, поэтому обновлять нечего. Если устаревший кэш npx выдаёт более старую
копию, явно закрепите dist-тег:

```bash
npx @ahmed-g-gad/apothem@latest --version
```

## Обновление установки на основе инсталлятора

Перезапустите инсталлятор — он идемпотентен и обновляет существующее дерево до актуального состояния —
или запустите специальный скрипт обновления:

```bash title="macOS · Linux · WSL2 · BSD"
bash scripts/installer/update.sh
```

```powershell title="Windows · PowerShell"
pwsh -NoProfile -File scripts/installer/update.ps1
```

Скрипт обновления заново извлекает дерево исходного кода в `APOTHEM_HOME` (по умолчанию
`~/.apothem`) на `APOTHEM_REF` — если не задано, разрешается последний подписанный
тег релиза `vMAJOR.MINOR.PATCH`, значение тега закрепляет его, а `main` выбирает
движущуюся ветку. Перед повторной материализацией он проверяет подпись тега с помощью `git verify-tag`;
неподписанный или подделанный тег прерывает выполнение, если только
`APOTHEM_ALLOW_UNVERIFIED=1` не понизит прерывание до предупреждения. Затем он
заново материализует окружение, указанное в `APOTHEM_HARNESS` (значения по умолчанию согласно таблице
[переменных окружения инсталлятора](/docs/how-to/installer-environment-variables)),
запуская `apothem update` из обновлённого дерева. Требуется предыдущая установка: когда
по адресу `APOTHEM_HOME` дерева нет, а `APOTHEM_SOURCE` не задана, скрипт завершается с
сообщением, направляющим вас сначала к инсталлятору.

## Повторная материализация вывода окружения

После обновления движка или редактирования `~/.config/apothem/profile.yaml`
заново выведите установленную конфигурацию окружения. Адаптерам с областью действия пользователя не нужен
`--project`; адаптерам с областью действия проекта он нужен.

```bash
apothem update --harness claude-code
apothem update --harness cursor --project /path/to/project
apothem update --harness all --project /path/to/project
```

Запустите ту же команду с `--dry-run --json`, когда вам нужен машиночитаемый
предпросмотр без записи на файловую систему.

## Граница текущей команды

`apothem update` обновляет только вывод окружения. CLI не реализует
`update --self`, `update --check` или `update --apply`; обновляйте сам движок
через тот канал, которым вы устанавливали, — поток `/plugin`, свежий
запуск `npx` или скрипты инсталлятора/обновления выше.

## Проверка версии движка

```bash
apothem --version
npx @ahmed-g-gad/apothem --version
```
