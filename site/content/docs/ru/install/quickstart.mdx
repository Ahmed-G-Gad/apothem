Это самый быстрый путь от нуля до проверенной конфигурации среды: установить,
описать общий профиль, материализовать нативную конфигурацию одного инструмента,
подтвердить её и внести первую правку. Каждая команда настоящая, её можно
скопировать и вставить, и каждый шаг показывает, что выводит чистый запуск. Сама
установка занимает меньше двух минут; редактирование профиля — единственная
часть, которая длится ровно столько, сколько вы захотите.

К концу у вас будет рабочая конфигурация среды, сгенерированная из написанного
вами профиля, — и вы будете знать ту единственную команду, которая проталкивает
изменение профиля обратно в каждый инструмент.

<Callout title="Хотите версию с пояснениями и не торопясь?">
  [Вводный туториал](/docs/tutorials/getting-started) проходит ту же территорию с
  большим объяснением каждого шага и того, почему он важен. Эта страница —
  лаконичное, ориентированное на вывод пошаговое руководство.
</Callout>

В качестве примера среды вы будете использовать **Claude Code**: это значение по
умолчанию у установщика. Поменяйте имя адаптера на любом шаге, чтобы указать на
другой инструмент; в [списке сред](/docs/harnesses) есть все поддерживаемые имена.

## 1. Установка Apothem

Apothem распространяется как самодостаточная среда выполнения: движок работает
прямо из своего дерева исходного кода со встроенными зависимостями. Одна команда
загружает исходный код, размещает движок и материализует вашу первую среду.

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 7+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

Установщику нужен системный Python 3.10+ с импортируемыми `click` и `rich`, плюс
`git` для сетевой формы. Он проверяет предварительные требования, размещает движок
в `~/.apothem` и по завершении выводит точный вызов движка для вашей оболочки.

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="Команда `apothem`">
  Установщик размещает shim `apothem` в вашем `PATH`, так что вы запускаете движок
  напрямую как `apothem <command>`. Если каталог shim-а ещё не в `PATH`, баннер
  выводит самодостаточный запасной вариант —
  `PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>` — которому shim
  не нужен; добавляйте перед каждой командой точный префикс, который вывел ваш
  баннер.
</Callout>

[Руководство по установке](/docs/install) охватывает другие пути установки —
плагин Claude Code (`/plugin marketplace add ahmed-g-gad/apothem`, затем
`/plugin install apothem@apothem`); расширения для семейства VS Code и другие
нативные для инструмента расширения; и форму по требованию через npx
(`npx @ahmed-g-gad/apothem <command>`) — вместе с параметрами переменных окружения.

## 2. Создание общего профиля

`apothem profile init` записывает наименьший возможный валидный профиль в
`~/.config/apothem/profile.yaml`. Передайте `--profile PATH`, когда держите
профиль для конкретного проекта или CI в другом месте.

```bash
apothem profile init
apothem profile show --json
```

Этот скелет использует заполнительные фиктивные данные идентичности, и его
безопасно редактировать перед установкой любого вывода среды. `show --json`
перечитывает его и сообщает проверенный профиль.

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

Здесь же всплывает и некорректная правка: если YAML невалиден, `show` сообщит об
этом на этом этапе, до записи любой конфигурации среды. Сделайте профиль своим с
помощью `apothem profile edit` (откроет его в вашем редакторе) или задайте один
ключ на месте.

```bash
apothem profile set identity.name "Your Name"
```

## 3. Установка адаптеров сред

Материализуйте адаптер вашего основного harness. Это читает
ваш профиль и записывает нативную конфигурацию этого инструмента.

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

Адаптеры с областью проекта пишут внутрь проекта, а не в ваш домашний каталог,
поэтому им нужен `--project PATH`. Предварительно просмотрите любую установку без
записи файлов с помощью `--dry-run`.

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

Установите полный набор, поддерживаемый реестром, за один раз с помощью
`--harness all`. Поскольку этот выбор записывает файлы как с областью проекта, так
и с областью пользователя, команда выводит конкретные назначения, сгруппированные
по местоположению, и запрашивает подтверждение перед записью за пределами корня
проекта.

```bash
apothem install --harness all --project .
```

Все поддерживаемые имена см. в [полном списке сред](/docs/harnesses), а полный
набор параметров — в [справочнике install](/docs/cli-reference/install).

## 4. Проверка

Материализация — лишь половина работы: `verify` подтверждает, что ожидаемые
файлы конфигурации среды записаны и совпадают с тем, что объявляет профиль.

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

`verify` завершается с ненулевым кодом, если конфигурация отсутствует или
сместилась, поэтому он также служит шлюзом в скрипте настройки. Для проверки
состояния всей машины по каждому зарегистрированному адаптеру запустите:

```bash
apothem doctor
```

`doctor` сообщает статус установки каждого адаптера и завершается с ненулевым
кодом, если какой-либо зарегистрированный адаптер сообщает, что он не установлен.

## 5. Ваш первый запуск

Откройте harness, который вы только что настроили — Claude
Code в этом примере — и начните сессию в любом проекте. Правила и предпочтения,
которые вы записали в профиль на шаге 2, уже являются частью поведения этого
инструмента. Это и есть первый рабочий запуск: один профиль формирует реальную
сессию.

Когда вы позже измените профиль, примените его повторно без переустановки.

```bash
apothem update --harness claude-code
```
