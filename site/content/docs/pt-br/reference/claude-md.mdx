`CLAUDE.md` é a configuração de projeto sempre carregada. O harness anfitrião o carrega em cada interação, então o seu conteúdo é o *contexto de base* que todos os demais artefatos estendem. Ele permanece coerente com o `AGENTS.md` (a superfície canônica de instruções para agentes) e com o `.github/copilot-instructions.md`, que espelham as mesmas disciplinas.

## O que ele contém

O `CLAUDE.md` do projeto é escrito em seções de prosa — o cânone de superfícies de IA, o ciclo operacional plan → harden → ship, a finalidade do projeto e o layout do código-fonte, as disciplinas de planos, de release e de cabeçalho de arquivos, o tratamento de ambiguidades, e as convenções de código e de adaptadores de harness. Ele declara *o que o projeto é* e *como trabalhar nele*; não reafirma os mandatos de governança, que vivem no cohort de regras e são expostos ao runtime como arquivos de regra.

| Superfície de governança | Onde fica |
|---|---|
| Mandatos transversais (CM-N) | `src/apothem/rules/operational-mandates.md` e os arquivos de regra por mandato |
| Os quinze mandatos de produção (M-N) | os arquivos de regra por mandato (`definitiveness.md`, `pre-emission-gate.md`, `production-ready-prs.md`, …) |
| Identidade cognitiva e postura de arquitetura | `src/apothem/rules/cognitive-identity.md` |
| Governança escalada por seriedade | a seção *Seriousness Scaling* de cada regra |
| O pipeline `/plan` | os comandos `/plan-*` e `src/apothem/skills/plan-suite/` |
| Diretórios de artefatos | o layout do código-fonte — `rules/`, `commands/`, `skills/`, `agents/`, `hooks/` |

## Convenções de identificadores de mandato

Três prefixos têm significados distintos:

- **CM-N** — mandato de configuração, definido no cohort de regras
  (`src/apothem/rules/operational-mandates.md` e os arquivos de regra por mandato).
- **TM-N** — mandato de modelo, definido em
  `src/apothem/skills/plan-suite/master-template.md` §4.
- **CP-N** — princípio central, definido no mesmo modelo, §6.

O modelo da suíte de planejamento é o registro canônico de TM/CP; as etapas do pipeline `/plan` resolvem as referências cruzadas por meio desse arquivo.
