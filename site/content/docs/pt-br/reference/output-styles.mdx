Os perfis de output-style ficam em `src/apothem/output-styles/` e carregam
orientações de tom de operador por estilo. O harness host ativa um
estilo por sessão via `/output-style <name>`.

## Perfis canônicos

| Perfil | Arquivo | Tom |
|---------|------|------|
| Padrão | `src/apothem/output-styles/default.md` | Tom de base que todos os outros estilos complementam |
| Arquiteto padrão | `src/apothem/output-styles/default-architect.md` | Tom de Arquiteto de Software Sênior |
| Engenheiro conciso | `src/apothem/output-styles/concise-engineer.md` | Tom de engenharia em formato curto |
| Auditor forense | `src/apothem/output-styles/forensic-auditor.md` | Tom de auditoria achado por achado |

## Onde os estilos são instalados

`apothem install --harness claude-code` copia os estilos para
`~/.claude/output-styles/`. O plugin do Claude Code distribui os mesmos arquivos
na sua pasta `output-styles/`, que o Claude Code varre em busca de output-styles
de plugins ([referência de plugins](https://code.claude.com/docs/en/plugins-reference)),
de modo que os estilos podem ser selecionados com apenas o plugin instalado.
Nenhum outro harness tem uma superfície de output-style, então nenhuma outra
instalação os distribui.

## Contrato de frontmatter

```yaml
---
name: <style name>
description: <one-line tone summary>
keep-coding-instructions: true
---
```

`name` e `description` são obrigatórios. Todo estilo distribuído também define
`keep-coding-instructions: true`. O Claude Code deixa as suas instruções
internas de engenharia de software (como delimitar o escopo de mudanças, escrever
comentários e verificar o trabalho) fora de qualquer output-style personalizado,
a menos que esta chave seja `true`; o padrão dela é `false`. Os estilos do
Apothem mudam a forma como o trabalho é apresentado, não a forma como ele é
feito, por isso mantêm essas instruções. Consulte a
[referência de output-styles do Claude Code](https://code.claude.com/docs/en/output-styles).

## Redigir um novo perfil

Crie um novo arquivo `<name>.md` em `src/apothem/output-styles/` com o
frontmatter canônico, incluindo `keep-coding-instructions: true`, a menos que o
estilo não se destine a trabalho de engenharia; declare o tom no corpo e
ratifique invocando `/output-style <name>` no início da sua próxima sessão.
