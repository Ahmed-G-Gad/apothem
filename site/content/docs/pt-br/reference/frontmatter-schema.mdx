> **Referência canônica do frontmatter YAML em todas as classes de artefato.** O resumo na seção Conventions do [`CLAUDE.md`](https://github.com/ahmed-g-gad/apothem/blob/main/CLAUDE.md) é a declaração em linha; os JSON Schemas por classe em [`schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/schemas) (`additionalProperties` rejeita chaves desconhecidas) são o contrato legível por máquina e prevalecem em qualquer divergência. Esta página é o índice de chaves obrigatórias, e [`artifact-schema.mdx`](/docs/reference/artifact-schema) traz os templates e exemplos completos por classe — ambas são projeções legíveis por humanos desses schemas.

---

## 1. Forma do bloco de frontmatter

Todo artefato carrega frontmatter YAML no início, delimitado por linhas `---`. O banner canônico do cabeçalho de autoria conforme [`site/content/docs/reference/authorship-header.mdx`](/docs/reference/authorship-header) fica acima do frontmatter nos arquivos da família Markdown; o frontmatter vem imediatamente depois.

As chaves usam `kebab-case`. Os valores escalares ficam sem aspas ou entre aspas duplas; valores de string que contêm dois-pontos, cerquilhas ou outros caracteres significativos em YAML ficam entre aspas.

## 2. Campos obrigatórios por classe

O conjunto de chaves obrigatórias varia conforme a classe de artefato. A forma autoritativa é imposta por `scripts/dev/validate_ecosystem.py` e pelos JSON Schemas por classe sob o diretório `schemas/` (um arquivo de schema por classe de artefato).

```text
schemas/agent.schema.json
schemas/skill.schema.json
schemas/command.schema.json
schemas/output-style.schema.json
schemas/plan.schema.json
```

| Classe | Chaves obrigatórias |
|-------|---------------|
| `CLAUDE.md` (configuração raiz) | `name`, `version`, `updated`, `description`, `scope`, `portability` |
| Regras (`src/apothem/rules/*.md`) | `name`, `description`, `pathFilter`, `alwaysApply` |
| Comandos (`src/apothem/commands/*.md`) | `name`, `version`, `updated`, `description`, `argument-hint`, `disable-model-invocation`, `portability`, `allowed-tools` |
| Trabalhadores delegados (diretório canônico mostrado abaixo) | `name`, `version`, `updated`, `description`, `tools`, `disallowedTools`, `maxTurns`, `effort` |
| Skills (`src/apothem/skills/*/SKILL.md`) | `name`, `version`, `updated`, `description`, `archetype`, `userInvocable`, `disable-model-invocation`, `allowed-tools`; a instalação do Claude Code e o plugin renomeiam `userInvocable` para `user-invocable`, e o schema aceita exatamente uma das duas grafias |
| Output-styles (`src/apothem/output-styles/*.md`) | `name`, `description`; todo estilo distribuído também define `keep-coding-instructions: true` para que o Claude Code mantenha as suas instruções de engenharia de software |

Os schemas por classe em [`schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/schemas) carregam o conjunto completo de restrições, incluindo restrições de tipo, formato, enum e padrão, além de limites de tamanho: a `description` de uma skill ou de um comando tem no máximo 1.024 caracteres, o limite do [Agent Skills](https://agentskills.io/specification).

## 3. Validadores

`scripts/dev/validate_ecosystem.py` percorre a árvore de artefatos, aplica os conjuntos de chaves obrigatórias acima e reporta `[FAIL]` em qualquer artefato ao qual falte um campo obrigatório. O `frontmatter-grep` por gravação, em `src/apothem/conformity/frontmatter_grep.py`, impõe a mesma forma nos limites do hook PreToolUse de Write/Edit.
