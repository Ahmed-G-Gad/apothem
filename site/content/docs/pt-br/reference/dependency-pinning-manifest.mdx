> Postura ratificada de como o Apothem declara, fixa e bloqueia dependências.
> Público: contribuidores e consumidores a jusante que precisam entender o
> modelo de reprodutibilidade.

## Postura

O Apothem é uma CLI em Python com um pequeno conjunto de dependências de
runtime, além de uma cadeia de ferramentas maior de desenvolvimento, auditoria,
lançamento e documentação. As dependências de runtime usam limites inferiores
conservadores em `pyproject.toml`; o site faz commit de
`site/package-lock.json`; as GitHub Actions são fixadas por SHA imutável com
comentários de versão e são atualizadas pelo Dependabot.

| Classe | Declaração | Política de bloqueio |
|---|---|---|
| Dependências Python de runtime | `[project.dependencies]` em `pyproject.toml` | Faixas com limite inferior; sem bloqueio de runtime do Python commitado |
| Ferramentas de desenvolvimento / segurança | extras de `[project.optional-dependencies]` | Faixas com limite inferior; o CI instala as versões correspondentes atuais |
| Ferramentas de lançamento | `scripts/release/requirements-build-linux.txt` para os fluxos de trabalho de lançamento; o extra `release` em `[project.optional-dependencies]` para builds locais | Bloqueado por hash para os fluxos de trabalho de lançamento; gerado a partir do fechamento das ferramentas de lançamento. O extra `release` é uma faixa com limite inferior |
| Ferramentas exclusivas do CI | `.github/workflows/*.yml` | As ferramentas pip exclusivas do fluxo de trabalho usam fixações exatas (`pip`, `bandit`, `pip-audit`, `pip-licenses`, `pyinstaller`, `pre-commit`, `ruff`) |
| Site de documentação | `site/package.json` | `site/package-lock.json` commitado e consumido pelo `npm ci` |
| Empacotador do VS Code | `tools/vsce/package.json` | `tools/vsce/package-lock.json` commitado; os jobs de lançamento e publicação executam `npm ci --ignore-scripts` |
| CLIs de harness do channel-smoke | `tools/channel-smoke/package.json` | `tools/channel-smoke/package-lock.json` commitado e consumido pelo `npm ci` |
| GitHub Actions | Referências `uses:` fixadas por SHA com comentários de versão | O Dependabot propõe atualizações semanais; as exceções carregam marcadores `action-pinning-exempt:` |

## Ratificação de lançamento

| Superfície | Estado ratificado | Justificativa |
|---|---|---|
| Dependências de runtime | Os limites inferiores atuais ficam em `pyproject.toml` `[project.dependencies]` | Pisos estáveis atuais ratificados antes do lançamento; nenhum bloqueio conhecido por CVE de runtime |
| Ferramentas de desenvolvimento | Os limites inferiores atuais ficam no extra `dev` de `pyproject.toml` | Pisos estáveis mais recentes ratificados antes do lançamento |
| Ferramentas de segurança | Os limites inferiores atuais ficam no extra `security` de `pyproject.toml` | Pisos atuais de scanners ratificados antes do lançamento |
| Ferramentas de lançamento | O fechamento bloqueado por hash fica em `scripts/release/requirements-build-linux.txt` | O fluxo de trabalho de lançamento instala com `--require-hashes`; os scripts locais exigem que `build` já exista, em vez de instalar silenciosamente dependências em movimento |
| Ferramentas de documentação | As faixas atuais ficam em `site/package.json`; a resolução exata fica em `site/package-lock.json` | `npm outdated` não retorna nenhuma dependência de documentação desatualizada após a atualização do arquivo de bloqueio |
| GitHub Actions | As fixações por SHA existentes são mantidas para o lançamento atual; o fluxo de trabalho reutilizável do SLSA continua sendo a exceção documentada, fixada por tag, marcada com um comentário `action-pinning-exempt:` em `release.yml` | A reexecução do CI público está verde; atualizações amplas de versão major das Actions são deixadas de propósito para os pull requests de automação de dependências, para evitar mudanças desnecessárias na superfície de lançamento |
| Empacotamento npm | O fluxo de trabalho `publish-npm.yml` roda no push da tag `v*.*.*`, com `workflow_dispatch` como alternativa | O único pacote npm público é `@ahmed-g-gad/apothem`; a publicação aguarda a aprovação do operador para o ambiente `release`, concedida depois que `scripts/release/check-release-ready.sh` passa |

## Bloqueio

Os arquivos de bloqueio do Python são gerados sob demanda pelo contribuidor.
Eles não são commitados porque o fechamento de runtime do Apothem é pequeno, a
CLI oferece suporte a várias versões menores do Python e o CI exercita
intencionalmente as versões de ferramentas correspondentes mais recentes.

```sh
# Astral uv:
uv pip install -e ".[dev,security,release]"
uv pip freeze > requirements.dev.lock

# pip-tools:
pip-compile --extra=dev --extra=security --extra=release -o requirements.dev.lock pyproject.toml

# Plain pip:
pip install -e ".[dev,security,release]"
pip freeze > requirements.dev.lock
```

O site é diferente: `site/package-lock.json` é commitado e o CI usa `npm ci`,
de modo que o site de documentação renderizado tem um fechamento de Node
reprodutível.

## Justificativa

- **Por que fixações por faixa para o Python?** A CLI oferece suporte a uma
  ampla matriz de Python e o CI deve revelar problemas de compatibilidade com
  as ferramentas atuais antes que os usuários os encontrem.
- **Por que um bloqueio de Node commitado?** O site é um artefato estático
  implantado; o arquivo de bloqueio fornece builds `npm ci` deterministas para
  essa superfície pública.
- **Por que Actions fixadas por SHA?** As tags são mutáveis; os SHAs são
  imutáveis. O Dependabot propõe os incrementos de SHA e reescreve cada
  comentário de versão, enquanto o portão de lançamento registra qualquer
  retenção intencional.
- **O que o bot de atualização não toca.** As atualizações de versão do
  Dependabot (`.github/dependabot.yml`) cobrem as fixações das GitHub Actions,
  o arquivo de bloqueio do site, o arquivo de bloqueio do empacotador vsce
  (`tools/vsce`), o arquivo de bloqueio das CLIs de harness que o channel smoke
  instala (`tools/channel-smoke`) e os hooks de pre-commit. Os pisos de runtime
  em `pyproject.toml`, os requisitos de lançamento bloqueados por hash, o
  fechamento vendorizado em `src/apothem/_vendor/vendor.txt` e os hooks de
  pre-commit fixados em sincronia com `pyproject.toml` mudam à mão, porque o
  incremento de uma única fixação quebraria os arquivos com os quais eles
  concordam.
  A versão major de `@types/node` do site acompanha o piso de Node dele
  (`engines` e `.nvmrc`, Node 22), de modo que o Dependabot propõe apenas as
  atualizações minor e patch dele; eleve essa versão major junto com o piso.
  As atualizações de versão deixam intactos os blocos `overrides` do npm. As
  atualizações de segurança do Dependabot ainda cobrem todos os manifestos, de
  modo que um pull request de segurança pode propor uma dessas fixações, ou
  mover um override; adapte-o à mão ou feche-o.
- **Mesclando um pull request do Dependabot.** O padrão de squash do
  repositório usa o título do PR. Alguns títulos do Dependabot, principalmente
  os agrupados que nomeiam um diretório, ultrapassam o assunto de squash de 72
  caracteres; a verificação PR Title os aponta, e uma troca de título os
  corrige. Um pull request que altera um arquivo de bloqueio de ferramenta não
  executa nenhum job de `ci.yml`, então o fluxo de trabalho de auditoria npm o
  audita e o instala, empacota a extensão do VS Code para o arquivo de bloqueio
  do vsce e executa os testes de lançamento do vsce, e o fluxo de trabalho do
  channel smoke é executado para o arquivo de bloqueio do channel-smoke. O
  fluxo de trabalho Markdown Lint executa o hook markdownlint em um pull
  request de hooks de pre-commit; os outros hooks não são exercitados no CI,
  então execute `pre-commit run --all-files` no branch dele antes de mesclá-lo.
