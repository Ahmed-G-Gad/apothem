Pré-visualiza as alterações de configuração pendentes para um único harness.

## Sinopse

```
apothem diff --harness NAME [--profile PATH] [--project PATH]
             [--quiet|-q] [--verbose|-v]
             [--format plain|json] [--json] [--no-color]
```

`diff` é um comando de inspeção somente leitura. Ele executa a mesma materialização que
o comando `install` executaria, mas em modo de simulação — nada é escrito em disco. Em
seguida, ele renderiza, por alvo planejado, a operação, o caminho do alvo, o resultado
e (para âncoras de propriedade do operador que seriam mescladas) o diff unificado da
alteração. É a resposta para "o que o `apothem install` faria com este harness
agora mesmo?" sem fazer a alteração.

Para alvos de propriedade do operador — arquivos que carregam tanto seu próprio
conteúdo quanto um bloco gerenciado pelo Apothem — o diff mostra as linhas exatas que
seriam alteradas. Para outros alvos, a operação e o resultado planejados são
resumidos.

`diff` opera sobre um único harness. Diferentemente de `status`, ele
não aceita `all`; passe um nome de harness.

## Opções

| Opção | Descrição |
|---|---|
| `--harness NAME` | Adaptador de harness a pré-visualizar (obrigatório; um único assistente, não `all`). |
| `--profile PATH` | Caminho para o YAML do perfil compartilhado. Padrão: `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Raiz do projeto para os harness com escopo de projeto. Obrigatório quando o harness selecionado tem escopo de projeto. |
| `--quiet`, `-q` | Suprime a saída informativa; apenas erros são emitidos. |
| `--verbose`, `-v` | Emite saída de diagnóstico adicional. |
| `--format plain\|json` | Formato de saída (padrão: `plain`). |
| `--json` | Abreviação de `--format json`. |
| `--no-color` | Desativa os códigos de cor ANSI na saída. |
| `-h`, `--help` | Mostra a ajuda e sai. |

## Saída JSON

O envelope `--json` espelha o envelope da instalação em modo de simulação. `status` é
`dry_run`, `files_written` está sempre vazio, e o bloco `materialization` mais a lista
`results` carregam todo o detalhe do alvo planejado. O campo `detail.diff` de cada linha
de resultado de propriedade do operador carrega a string do diff unificado.

```json
{
  "status": "dry_run",
  "command": "diff",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "sentinel_merge",
      "path": "C:\\Users\\Example\\.claude\\CLAUDE.md",
      "message": "dry run: no filesystem changes made",
      "detail": {
        "ownership_class": "operator-owned",
        "diff": "--- a/CLAUDE.md\n+++ b/CLAUDE.md\n@@ ..."
      }
    }
  ],
  "warnings": [],
  "error": null,
  "materialization": { "...": "..." }
}
```

## Exemplos

```bash
apothem diff --harness claude-code
apothem diff --harness cursor --project .
apothem diff --harness claude-code --json
```

## Códigos de saída

| Código | Significado |
|---|---|
| 0 | Diff relatado (as alterações pendentes são relatadas, não são erro) |
| 1 | Erro esperado de validação, perfil, harness ou projeto |
