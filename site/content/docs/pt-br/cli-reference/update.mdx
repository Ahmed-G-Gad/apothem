Reinstala a configuração de um adaptador de harness a partir do perfil
compartilhado atual.

## Sinopse

```
apothem update --harness NAME|all [--profile PATH] [--dry-run]
                [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

`update` rematerializa a saída do harness a partir do perfil compartilhado
atual. Ele usa a mesma validação de perfil, a mesma seleção com
`--harness all`, a mesma verificação de escopo de projeto, o mesmo
comportamento de simulação e o mesmo envelope JSON que `install`.

Para os adaptadores com escopo de projeto que gravam skills no seu diretório
pessoal (consulte
[`install`](/docs/cli-reference/install#pastas-no-seu-diretório-pessoal)),
`update` também atualiza essas pastas e imprime a mesma `Note:` que as nomeia.
Um adaptador instalado antes de gravar skills as recebe na sua próxima
atualização. Uma pasta de skill que o Apothem não gravou é ignorada com um
aviso, como em [`install`](/docs/cli-reference/install#pastas-no-seu-diretório-pessoal).
Uma instalação que gravou a pasta de skills compartilhada anteriormente é
reescrita na forma que todas as instalações compartilham na sua próxima
atualização; cada pasta alterada é salva em backup antes.

O alias na forma contínua `apothem updating` (também aceito como
`apothem Updating`) resolve para o mesmo manipulador.

## Opções

| Opção | Descrição |
|---|---|
| `--harness NAME` | Adaptador de harness a atualizar, ou `all` para o conjunto de todo o registro (obrigatório). Com `all`, os harnesses listados em `exclude_harnesses` do perfil são ignorados, mas um harness nomeado explicitamente é atualizado mesmo quando listado. |
| `--profile PATH` | Caminho para o YAML do perfil compartilhado. O padrão é `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Mostra uma prévia da atualização sem gravar arquivos. |
| `--project PATH` | Raiz do projeto para os harnesses com escopo de projeto. Obrigatório quando o conjunto de harnesses selecionado inclui adaptadores com escopo de projeto. |
| `--quiet`, `-q` | Suprime a saída informativa; apenas os erros são emitidos. |
| `--verbose`, `-v` | Emite saída de diagnóstico adicional. |
| `--format plain\|json` | Formato de saída (padrão: `plain`). |
| `--json` | Abreviação de `--format json`. |
| `--no-color` | Desativa os códigos de cor ANSI na saída. |
| `-h`, `--help` | Mostra a ajuda e sai. |

## Saída JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "update",
  "action": "updated",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

`--dry-run` retorna `status: "dry_run"` e `files_written: []`.

## Exemplos

```bash
apothem update --harness claude-code
apothem update --harness claude-code --dry-run
apothem update --harness all --project . --dry-run --json
apothem Updating --harness claude-code   # continuous-form alias
apothem updating --harness claude-code   # lowercase variant
```

## Códigos de saída

| Código | Significado |
|---|---|
| 0 | Adaptador atualizado com sucesso ou execução de simulação planejada sem erros |
| 1 | Erro esperado de validação, de perfil, de harness, de projeto ou de adaptador |
| 2 | Materialização parcial do lote após pelo menos uma gravação |
| 64 | Erro de uso: uma opção ou um comando desconhecido, ou um valor de opção ausente ou inválido. Com `--json`, o erro é um envelope JSON com o código `cli.usage`. |
