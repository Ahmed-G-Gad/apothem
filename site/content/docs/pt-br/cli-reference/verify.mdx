Verifica a instalação de um adaptador de harness.

## Sinopse

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

Chama a implementação `verify()` de cada adaptador selecionado. Sai com 0
somente quando todos os adaptadores selecionados relatam que seus destinos
gerenciados estão presentes e válidos. Sem `--profile`, a verificação é
**estrutural** — todo destino gerenciado precisa estar presente e válido. Com
`--profile`, a verificação exige adicionalmente **fidelidade ao perfil**, de
modo que uma instalação presente, mas com desvio, não passa na verificação,
respondendo "ESTE perfil está instalado fielmente?" em vez de apenas "ele
existe?".

Uma varredura com `--harness all` respeita o `exclude_harnesses` do perfil — as
mesmas exclusões que o lote de `install`/`update` aplicou —, de modo que a
verificação nunca relata como ausente um harness excluído deliberadamente. As
exclusões vêm de `--profile`, quando fornecido; caso contrário, do perfil
padrão. Um perfil padrão ilegível ou ausente faz a verificação recair no
registro completo.

## Opções

| Opção | Descrição |
|---|---|
| `--harness NAME` | Adaptador de harness a verificar, ou `all` para o conjunto de todo o registro (obrigatório). |
| `--profile PATH` | YAML do perfil compartilhado contra o qual a fidelidade é verificada. Sem ele, a verificação é puramente estrutural. |
| `--project PATH` | Raiz do projeto para os harnesses com escopo de projeto. |
| `--quiet`, `-q` | Suprime a saída informativa; apenas os erros são emitidos. |
| `--verbose`, `-v` | Emite saída de diagnóstico adicional. |
| `--format plain\|json` | Formato de saída (padrão: `plain`). |
| `--json` | Abreviação de `--format json`. |
| `--no-color` | Desativa os códigos de cor ANSI na saída. |
| `-h`, `--help` | Mostra a ajuda e sai. |

## Saída JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Quando qualquer harness selecionado está ausente ou inválido, `status` é
`error`, a linha de resultado que falha carrega `verified: false` e o processo
sai com o código 1.

## Exemplos

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## Códigos de saída

| Código | Significado |
|---|---|
| 0 | Harness verificado — todos os destinos gerenciados estão presentes e válidos |
| 1 | Harness não verificado — destinos gerenciados ausentes ou inválidos |
| 64 | Erro de uso: uma opção ou um comando desconhecido, ou um valor de opção ausente ou inválido. Com `--json`, o erro é um envelope JSON com o código `cli.usage`. |
