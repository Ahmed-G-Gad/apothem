Migra um espaço de trabalho herdado por harness para o layout compartilhado `.apothem`.

## Sinopse

```
apothem migrate-workspace [--project PATH] [--dry-run]
                          [--quiet|-q] [--verbose|-v]
                          [--format plain|json] [--json] [--no-color]
```

`migrate-workspace` colapsa um diretório de dados herdado por harness
(`.apothem/<harness>/...`) e uma árvore `.plans/` herdada no único diretório de
trabalho compartilhado `.apothem/{plans,memory,learning,contexts}`. A base é a raiz
`--project` resolvida quando fornecida, caso contrário o diretório de trabalho
atual (o padrão local do projeto).

A memória, os contextos e os armazenamentos de aprendizado por harness se fundem
por união no armazenamento compartilhado por id; os sinais de aprendizado são
concatenados e deduplicados; um registro em conflito (mesmo id, corpo diferente)
é ignorado, nunca sobrescrito. Uma árvore `.plans/` herdada é movida sob
`.apothem/plans/`. Cada fonte consumida é submetida a backup primeiro. A migração
é idempotente — reexecutá-la sobre uma árvore já migrada é uma operação sem efeito.

## Opções

| Opção | Descrição |
|---|---|
| `--project PATH` | Raiz do projeto para os adaptadores com escopo de projeto que se materializam em uma árvore de projeto em vez de em um diretório de configuração com escopo de usuário. |
| `--dry-run` | Detecta o layout herdado e relata o que seria migrado sem escrever. |
| `--quiet`, `-q` | Suprime a saída informativa; apenas erros são emitidos. |
| `--verbose`, `-v` | Emite saída de diagnóstico adicional. |
| `--format plain\|json` | Formato de saída (padrão: `plain`). |
| `--json` | Abreviação de `--format json`. |
| `--no-color` | Desativa os códigos de cor ANSI na saída. |
| `-h`, `--help` | Mostra a ajuda e sai. |

## Saída JSON

O envelope `--json` carrega o resultado da migração. Em uma migração concluída,
`status` é `success` e a carga útil relata as contagens de registros mesclados,
se uma árvore `.plans/` foi realocada, a raiz de backup e quaisquer conflitos
ignorados. Uma invocação `--dry-run` relata, em vez disso, `legacy_layout_detected`.

```json
{
  "command": "migrate-workspace",
  "status": "success",
  "base": "/home/example/project",
  "migrated": true,
  "backup_root": "/home/example/project/.apothem/.backups/01J9Z…",
  "memory_merged": 12,
  "contexts_merged": 4,
  "learning_merged": 7,
  "conflicts": [],
  "plans_moved": true,
  "notes": []
}
```

Quando nenhum layout herdado está presente, `migrated` é `false` e nada é escrito.
O envelope `--dry-run` omite as contagens de resultado e relata apenas a detecção:

```json
{
  "command": "migrate-workspace",
  "base": "/home/example/project",
  "dry_run": true,
  "legacy_layout_detected": false
}
```

## Exemplos

```bash
apothem migrate-workspace
apothem migrate-workspace --project .
apothem migrate-workspace --dry-run --json
```

## Códigos de saída

| Código | Significado |
|---|---|
| 0 | Migração concluída, ou nenhum layout herdado encontrado (nada a migrar) |
| 1 | Erro esperado — um erro de validação ou de raiz de projeto, ou uma falha de migração |
