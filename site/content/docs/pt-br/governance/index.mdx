Esta seção documenta a governança de qualidade interna do projeto: os registros
de mandatos que definem o que cada artefato emitido deve satisfazer, a checagem
que verifica os artefatos antes de eles serem publicados, as categorias de
consulta que separam o que a ferramenta pode decidir do que ela deve perguntar, e
as políticas que governam as versões, os selos e o posicionamento do projeto.

Estas páginas são normativas para os mantenedores e para as verificações
automatizadas do repositório. Os guias de uso do dia a dia ficam em
[Guias](/docs/usage), e os esquemas e convenções que eles citam ficam em
[Referência](/docs/reference).

## Páginas

| Página | Descrição |
|------|-------------|
| [Mandatos transversais](/docs/governance/cross-cutting-mandates) | O registro de mandatos internos do ecossistema (CM-1–CM-28) que governa todas as interações e operações do fluxo. |
| [Registro de conformidade externa](/docs/governance/outward-conformity-registry) | O registro de quinze mandatos (M1–M15) que todo artefato gerado em um projeto anfitrião deve satisfazer. |
| [Registro da checagem de pré-emissão](/docs/governance/pre-emission-gate-registry) | A checagem de conformidade obrigatória de quinze barras executada antes de qualquer emissão de escopo significativo. |
| [Registro de consulta autoritativa](/docs/governance/authoritative-inquiry-registry) | As categorias de consulta obrigatórias e as exceções de decisão automática: o que é perguntado versus o que é decidido. |
| [Política de selos](/docs/governance/badge-policy) | As fontes de selos dinâmicos e estáticos para o README e como cada selo se mantém verdadeiro. |
| [Política de engenharia de versões](/docs/governance/release-engineering-policy) | Versionamento, marcação de versões, ciclos de descontinuação, mudanças incompatíveis e procedimentos de reversão. |
| [Posicionamento](/docs/governance/positioning) | Como o Apothem se enquadra: governança de ratificação de artefatos para o desenvolvimento assistido. |
