> **Registro canônico do portão de pré-emissão de quinze barras.** Este documento contém a tabela completa das quinze barras do portão e o bloco YAML do esquema de resultado do portão; a tabela substantiva e o esquema vivem aqui, operacionalizados por `src/apothem/rules/pre-emission-gate.md`.

Antes de qualquer emissão de artefato de escopo significativo (segundo o limiar entre trivial e não trivial em `site/content/docs/governance/outward-conformity-registry.mdx` §1), execute o portão de pré-emissão de quinze barras. Mecanize via hooks PreToolUse sempre que possível (os greps mecânicos em `src/apothem/conformity/*-grep.py`, orquestrados por `src/apothem/conformity/gate.py`); raciocine onde a mecanização for impossível. **A falha de qualquer barra individual bloqueia a emissão; revise até que cada barra passe; emita com o resultado do portão registrado.**

| # | Barra | Tipo de verificação | Falha → ação |
| - | --- | ---------- | ---------------- |
| 1 | M1 agnosticismo do anfitrião | raciocinada | revisar para coincidir com as convenções do anfitrião |
| 2 | M2 divulgação editorial | raciocinada | adicionar livro-razão de divulgação |
| 3 | M3 dez dimensões | mista (mecânica + raciocinada) | revisar na dimensão que falha |
| 4 | M4 autoaplicação | raciocinada (bloco de verificação presente) | registrar o bloco de verificação |
| 5 | M5 autoridade | mecânica (grep de marcador `<USER-CONFIRM:…>`) | reencaminhar à superfície de consulta |

## 1. Esquema do resultado do portão

Cada execução do portão registra o resultado na trilha de trabalho do artefato (um comentário oculto, um bloco de metadados, um arquivo de registro de emissão à parte — o que as convenções do anfitrião permitirem):

```yaml
conformity-attestation:
  artifact: <path-or-identifier>
  ecosystem-version: <git-commit-sha-or-equivalent ratifying the rule set in force>
  bars:
    M1-host-agnosticism:        pass | n/a (with reason)
    M2-editorial-disclosure:    pass | n/a
    M3-ten-dimensions:          pass | n/a
    M4-self-application:        pass
    M5-authority:               pass
    M6-expertise:               pass | n/a
    M7-option-annotation:       pass | n/a (no option set)
    M8-definitiveness:          pass
    M9-visual-leverage:         pass | n/a (subject not structural)
    M10-bidirectional-binding:  pass
    M11-agile-sprints:          pass | n/a (trivial work)
    M12-phase-layout:           pass | n/a
    M13-code-craft:             pass | n/a (not code)
    M14-systemicity:            pass
    M15-production-ready:       pass | n/a (no host-public-surface change)
  surfaced-gaps: []
  unresolved-inquiries: []
  amendments-disclosed: []
  date: <ISO-8601>
```

As marcações `n/a` são explícitas e raciocinadas — nunca omissões silenciosas. O campo `ecosystem-version` ancora o resultado do portão a um estado reproduzível do ecossistema de escopo de usuário (o commit git da árvore de fontes ativa do Apothem quando o portão foi executado — por exemplo, o checkout em `~/.claude/` para o adaptador do Claude Code), de modo que auditorias futuras possam repetir o portão contra os mesmos corpos de regras.
