Perguntas comuns, em ordem de frequência.

## O que é o `apothem`?

O Apothem é um gerenciador de configuração agnóstico de host para harnesses de
assistentes de programação. Você escreve um único perfil compartilhado e o Apothem o
materializa na superfície de configuração nativa de cada ferramenta — combinando
regras comportamentais, padrões criativos, slash commands, trabalhadores delegados
persistentes, hooks e skills em um único corpus governado que permanece consistente
em todos os harnesses.

## Com quais harnesses de assistentes ele funciona?

O Apothem é agnóstico de harness. Adaptadores por harness sob
`src/apothem/harnesses/<harness>/` projetam o perfil compartilhado para
o diretório de configuração nativo de cada ferramenta. O registro de harnesses usado em
tempo de execução é a fonte autoritativa do conjunto de harnesses suportados; as
[páginas de harnesses](/docs/harnesses) documentam cada um. Atualmente, o registro
abrange os seguintes harnesses suportados:

```text
Claude Code, GitHub Copilot, Cursor, Gemini CLI, Codex, Windsurf, OpenCode,
Antigravity, Open-Claw, Hermes, Qwen Code, CodeBuddy, Kiro, Trae, Zed,
GLM (Z.ai), and Kimi Code
```

O adaptador do Claude Code se materializa em `~/.claude/`; seu despachante de hooks é
neutro quanto ao host — ele resolve a raiz do ecossistema primeiro a partir de
`$CLAUDE_PROJECT_DIR`, depois de `$LLM_PROJECT_DIR`, e então tenta buscas relativas ao
script e ao diretório de trabalho, e por fim recorre a `$HOME/.claude`.

## Preciso usar o pipeline da suíte de planejamento?

Não. O pipeline da suíte de planejamento é um componente do ecossistema.
Regras comportamentais, padrões criativos, hooks e o conjunto de
validadores são úteis de forma independente.

## Como customizo as regras sem fazer fork do repositório?

Adicione uma string à lista `rules:` em `~/.config/apothem/profile.yaml` e execute
novamente a instalação ou a atualização. Arquivos de regra em `src/apothem/rules/`
editam a árvore de fontes empacotada, que o instalador a partir do arquivo substitui
quando executado com `--yes`.

## Como desabilito uma regra temporariamente?

Renomeie o arquivo para fora do padrão `src/apothem/rules/*.md`
ou mova-o para um diretório irmão que o carregador não
percorre.

## Qual a diferença entre regras, skills e trabalhadores delegados?

- **Regras** governam o comportamento — obrigações sempre ativas ou
  filtradas por caminho que o assistente segue.
- **Skills** são técnicas detectáveis reutilizáveis — um sinal de
  detecção, um procedimento e um hook de imposição.
- **Trabalhadores delegados** são papéis persistentes com suas próprias restrições
  de ferramentas e system prompts, despachados via o
  protocolo de orquestração de trabalhadores.

## Onde fica o estado do ecossistema?

- **O estado de planejamento por suíte** fica em `<project>/.apothem/plans/{suite}/`.
- **A memória do Apothem** fica em `.apothem/memory/` abaixo da raiz de instalação (para
  o Claude Code: `~/.claude/.apothem/memory/`; `~/.apothem/memory/` quando
  `workspace.scope` é `user-home`; `<project>/.apothem/memory/` para instalações de
  escopo de projeto). A auto-memória do próprio Claude Code fica sob a raiz de
  configuração do harness, em `projects/{hash}/memory/` (para o Claude Code:
  `~/.claude/projects/{hash}/memory/`).
- **A memória entre projetos** fica sob essa mesma raiz de configuração do harness, em
  `.apothem/memory/` (para o Claude Code: `~/.claude/.apothem/memory/`).
- **O scratch por sessão** fica em `<project>/.apothem/plans/{suite}/_inputs/`.

## Posso retomar um trabalho de longa duração em uma nova sessão ou em outra máquina?

Sim. Um trabalho de longa duração externaliza seu estado completo para uma suíte
`.apothem/plans/` local do projeto — um contrato de retomada mais um protocolo de
inicialização a frio —, de modo que o trabalho não vive dentro de um único
histórico de chat. Como o estado está nos arquivos do seu projeto, uma sessão
nova em qualquer conta ou máquina apontada para o mesmo projeto retoma o trabalho
no lugar. O Apothem não transfere os arquivos entre contas por conta própria;
eles viajam do mesmo jeito que os arquivos do seu projeto já viajam (controle de
versão, um checkout compartilhado, um diretório sincronizado). Consulte
[Planejamento retomável](/docs/concepts/resumable-planning).

## O Apothem precisa de pip?

Não — não para o engine em si. O engine é uma árvore de fonte autossuficiente com
dependências fornecidas — ele executa como `python -m apothem` a partir de
qualquer checkout, do cache do npx ou da árvore do plugin sobre o Python 3.10+ do
sistema, e não instala nada do seu próprio código em `site-packages` (`click` e
`rich` são os únicos pré-requisitos do interpretador). A única exceção opcional:
se `click` ou `rich` estiver faltando, o instalador oferece executar `pip install`
apenas para esses dois por você — com a sua confirmação, ou
`--yes` / `APOTHEM_AUTO_INSTALL_DEPS=1`. Os pacotes próprios do Apothem nunca são
instalados em `site-packages`.

## Como os hooks executam sem um pacote instalado?

`apothem install` materializa o despachante de hooks e o conformity gate
sob a raiz do harness (para o Claude Code: `~/.claude/.apothem/support/hooks/` e
`~/.claude/.apothem/support/conformity/`), e as entradas de hook renderizadas invocam esses
scripts por caminho absoluto. Ambos são scripts autônomos da biblioteca padrão, então os hooks
funcionam em uma máquina que nunca viu um `pip install`.

## Como desinstalo completamente?

Execute `apothem uninstall --harness <name>` para cada harness instalado, remova
o engine conforme seu canal de instalação e exclua `~/.apothem/` (backups) mais
`~/.config/apothem/` (seu perfil) se você quiser zero resíduo. O
[guia de desinstalação](/docs/install/uninstalling) percorre cada canal.
