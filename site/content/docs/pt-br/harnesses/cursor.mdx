**Fornecedor:** Anysphere
**Nome de instalação:** `cursor`
**Status:** GA
**Configuração nativa:** `.cursor/rules/` na raiz do projeto

## Instalação

```bash
apothem install --harness cursor --project /path/to/project
```

O adaptador renderiza um único arquivo de regras `.mdc` com escopo de projeto a
partir das regras compartilhadas do Apothem e da superfície de governança.

**Arquivos gravados:** `<project>/.cursor/rules/apothem-rules.mdc`

Esse arquivo é a instalação inteira: nenhum arquivo de regra, skill, comando,
template ou hook é colocado ao lado dele, então o próprio arquivo informa isso
em vez de apontar para arquivos do Apothem que não estão no projeto.

## Mapeamento do perfil para a configuração nativa

O adaptador lê o perfil compartilhado do Apothem e renderiza o arquivo de regras
do projeto a cada execução de `apothem install` ou `apothem update`. O perfil
compartilhado é a fonte da verdade; as edições locais do projeto no arquivo
gerado recebem backup antes que a próxima sincronização substitua o conteúdo
gerenciado pelo Apothem.

O arquivo começa com seu frontmatter YAML (`description`, `globs`,
`alwaysApply: true`), porque o Cursor lê o tipo de uma regra apenas a partir do
frontmatter no início do arquivo. O bloco gerenciado pelo Apothem vem depois
dele; o texto que você adiciona após o bloco é mantido a cada sincronização.

## Notas de compatibilidade

O Cursor 0.45+ suporta instruções em nível de projeto via `.cursor/rules/`. Por
padrão, o adaptador grava no diretório `.cursor/rules/` com escopo de projeto; o
Cursor não tem um caminho documentado de regras globais do usuário baseado em
arquivos para que este adaptador gerencie.

## Verificação

```bash
apothem verify --harness cursor --project /path/to/project
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Cada destino gerenciado existe; os arquivos gerenciados não estão vazios, e as configurações JSON ou YAML são analisadas sem erros. Adicione `--profile PATH` para também confirmar que os arquivos instalados correspondem a esse perfil.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness cursor --project /path/to/project
```

Deriva novamente o arquivo de regras do projeto a partir do estado atual do
perfil compartilhado.

## Desinstalação

```bash
apothem uninstall --harness cursor --project /path/to/project
```

Remove os arquivos de configuração nativa gravados pelo adaptador.
O YAML do perfil compartilhado e o motor do Apothem não são afetados.

## Conformity gate

```bash
python -m apothem.conformity.gate --all .
```

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness cursor --project /path/to/project` |
| Falha na verificação | Execute `apothem update --harness cursor --project /path/to/project` e depois verifique novamente |
| Conteúdo de configuração inesperado | Verifique `~/.config/apothem/profile.yaml` ou `--profile PATH` e depois execute novamente `apothem update --harness cursor --project /path/to/project` |
