**Fornecedor:** ByteDance
**Nome de instalação:** `trae`
**Status:** GA
**Configuração nativa:** `<project>/.trae/rules/apothem-rules.md`

## Instalação

```bash
apothem install --harness trae --project /path/to/project
```

O adaptador grava um arquivo de regras do Trae com escopo de projeto a partir da
superfície compartilhada de regras e governança do Apothem.

**Arquivos gravados:** `<project>/.trae/rules/apothem-rules.md`

## Mapeamento do perfil para a configuração nativa

O adaptador lê o perfil compartilhado do Apothem e renderiza o arquivo de regras
do projeto a cada execução de `apothem install` ou `apothem update`. O perfil
compartilhado é a fonte da verdade; as edições locais do projeto no arquivo
gerado recebem backup antes que a próxima sincronização substitua o conteúdo
gerenciado pelo Apothem.

O arquivo começa com um frontmatter YAML que define `alwaysApply: true` e uma
`description`, o que corresponde ao modo Always Apply do Trae conforme a
[documentação de regras do Trae](https://docs.trae.ai/ide/rules). O bloco
gerenciado pelo Apothem vem em seguida; o texto que você adiciona depois do
bloco é mantido a cada sincronização.

## Notas de compatibilidade

A superfície de regras atual do Trae tem escopo de projeto sob `.trae/rules/`;
as regras globais ficam sob `~/.trae/user_rules`. O adaptador grava um arquivo
`apothem-rules.md` dedicado e nunca sobrescreve os outros arquivos de regras
desse diretório nem as suas regras globais. A
superfície de servidores de ferramentas `.trae/mcp.json` e a superfície de
skills `.trae/skills/` pertencem ao operador; o Apothem não as grava.

## Verificação

```bash
apothem verify --harness trae --project /path/to/project
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Cada destino gerenciado existe; os arquivos gerenciados não estão vazios, e
   as configurações JSON ou YAML podem ser analisadas. Adicione `--profile PATH`
   para também confirmar que os arquivos instalados correspondem a esse perfil.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness trae --project /path/to/project
```

Deriva novamente o arquivo de regras do projeto a partir do estado atual do
perfil compartilhado.

## Desinstalação

```bash
apothem uninstall --harness trae --project /path/to/project
```

Remove o bloco do Apothem, e o frontmatter que o Apothem gravou acima dele, de
`<project>/.trae/rules/apothem-rules.md` e mantém qualquer outro texto nele. O
arquivo é excluído somente quando nada mais resta nele. Antes da alteração, uma
cópia do arquivo com carimbo de data e hora é salva em `~/.apothem/backups/`;
nenhum arquivo de backup é deixado no projeto. O YAML do perfil compartilhado e
o motor do Apothem não são afetados.

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness trae --project /path/to/project` |
| Falha na verificação | Execute `apothem update --harness trae --project /path/to/project` e depois verifique novamente |
| Conteúdo de configuração inesperado | Verifique `~/.config/apothem/profile.yaml` ou `--profile PATH` e depois execute novamente `apothem update --harness trae --project /path/to/project` |
