**Fornecedor:** Open-Claw
**Nome de instalação:** `open-claw`
**Status:** Prévia
**Configuração nativa:** `~/.openclaw/openclaw.json`

## Instalação

```bash
apothem install --harness open-claw
```

O adaptador traduz o perfil compartilhado para o arquivo de configuração global
de usuário do OpenClaw e instala os cohorts de suporte do Apothem sob a raiz do
harness. A configuração nativa do OpenClaw é JSON; o materializador renderiza
JSON para corresponder.

**Arquivos gravados:** `~/.openclaw/openclaw.json`, o documento de perfil
`~/.openclaw/apothem/rules/00-apothem-profile.md` e arquivos de suporte sob
`~/.openclaw/.apothem/support/`

O documento de perfil termina com uma seção de arquivos de suporte do Apothem
que nomeia o diretório absoluto sob `~/.openclaw/.apothem/support/` em relação
ao qual cada citação no estilo do repositório (`rules/<name>.md`,
`templates/...`, `hooks/...`) é resolvida.

## Mapeamento do perfil para a configuração nativa

O adaptador lê o perfil compartilhado do Apothem, mas não redige nenhuma chave
de configuração: `openclaw.json` é gravado como um objeto vazio. A identidade,
as preferências e as regras do perfil vão para o documento de perfil. Os
comandos, skills, regras, templates e prompts de hook compartilhados são
instalados como material de suporte sob `~/.openclaw/.apothem/support/`.

## Notas de compatibilidade

Adaptador em prévia. O OpenClaw não carrega por conta própria a árvore de
suporte nem o documento de perfil: nenhum de seus locais de skills, nenhum de
seus arquivos de instruções do workspace e nem sua configuração apontam para lá,
então, após a instalação, o OpenClaw roda sem as regras, as skills ou os
servidores MCP do Apothem. O OpenClaw lê skills das pastas `skills/` e
`.agents/skills/` do seu workspace, de `~/.agents/skills`, do seu diretório de
estado e de qualquer pasta listada em `skills.load.extraDirs`; para usar as
skills do Apothem, adicione você mesmo `~/.openclaw/.apothem/support/skills` a
essa lista; `apothem update` mantém as chaves que você adiciona a
`openclaw.json`. Os servidores MCP ficam no bloco `mcp.servers` da configuração
do OpenClaw, que você gerencia com `openclaw mcp add` e os subcomandos
relacionados; o adaptador não grava nenhuma entrada ali. (Comportamento do
OpenClaw conforme sua documentação de [skills](https://docs.openclaw.ai/tools/skills)
e de [CLI de MCP](https://docs.openclaw.ai/cli/mcp), lida em 2026-10-02.)

## Verificação

```bash
apothem verify --harness open-claw
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Todos os campos obrigatórios do perfil compartilhado estão presentes.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness open-claw
```

Deriva novamente a configuração nativa a partir do estado atual do perfil
compartilhado. Execute após editar `~/.config/apothem/profile.yaml` ou atualizar
o pacote do Apothem instalado.

## Desinstalação

```bash
apothem uninstall --harness open-claw
```

Remove os arquivos de configuração nativa gravados pelo adaptador.
O YAML do perfil compartilhado e o motor do Apothem não são afetados.

## Conformity gate

```bash
python -m apothem.conformity.gate --all .
```

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness open-claw` |
| Falha na verificação | Execute `apothem update --harness open-claw` e depois verifique novamente |
| Conteúdo de configuração inesperado | Verifique `~/.config/apothem/profile.yaml` ou `--profile PATH` e depois execute novamente `apothem update --harness open-claw` |
