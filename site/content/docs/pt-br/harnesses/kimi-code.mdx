**Fornecedor:** Moonshot
**Nome de instalação:** `kimi-code`
**Status:** GA
**Configuração nativa:** `<project>/AGENTS.md` mais `<project>/.kimi-code/.apothem/support/`

## Instalação

```bash
apothem install --harness kimi-code --project /path/to/project
```

O adaptador grava a superfície de governança compartilhada do Apothem no
`AGENTS.md` da raiz do projeto como um bloco gerenciado delimitado por
sentinelas (a prosa do operador fora das sentinelas é preservada) e mantém os
cohorts Markdown não nativos sob a árvore de suporte de propriedade do Apothem
em `<project>/.kimi-code/.apothem/support/`.
Um `AGENTS.md` de projeto é lido por muitas ferramentas de programação além do
Kimi Code, então o bloco é escrito como orientação para todo o projeto que não
nomeia nenhuma ferramenta específica como sua leitora.

O Kimi Code lê o arquivo de instruções `AGENTS.md` da raiz do projeto seguindo a
convenção universal do AGENTS.md, e a configuração do projeto fica sob
`<project>/.kimi-code/`. A superfície `<project>/.kimi-code/mcp.json` pertence
ao operador; o Apothem a nomeia, mas não redige nenhuma entrada.

**Arquivos gravados:** `<project>/AGENTS.md` (bloco gerenciado) e os cohorts de
comandos, skills, hooks, agentes, regras e templates sob
`<project>/.kimi-code/.apothem/support/`.

## Mapeamento do perfil para a configuração nativa

O adaptador lê o perfil compartilhado do Apothem e renderiza a superfície de
instruções `AGENTS.md` da raiz do projeto a cada execução de `apothem install`
ou `apothem update`. As regras comportamentais e o corpus de governança ficam no
bloco gerenciado do `AGENTS.md`; os cohorts de comandos, skills, hooks, agentes,
regras e templates são colocados sob `.kimi-code/.apothem/support/` e
referenciados a partir da superfície de instruções. Esse é o layout escolhido
pelo adaptador, não uma lacuna do Kimi Code: o Kimi Code carrega skills de
`.kimi-code/skills/` e `.agents/skills/`, agentes personalizados de
`.kimi-code/agents/` e `.agents/agents/`, e hooks do array `[[hooks]]` em
`~/.kimi-code/config.toml`, mas não os carrega da árvore de suporte, então as
cópias do Apothem ali são material de referência para o qual o bloco do
`AGENTS.md` aponta. O bloco termina com uma seção de arquivos de suporte do
Apothem que nomeia, em relação à raiz do projeto, o diretório sob
`.kimi-code/.apothem/support/` em relação ao qual cada citação no estilo do
repositório (`rules/<name>.md`, `templates/...`, `hooks/...`) é resolvida, de
modo que um `AGENTS.md` incluído em um commit não carrega nenhum caminho
específico de máquina. (Comportamento do Kimi Code conforme suas páginas de
personalização de
[skills](https://moonshotai.github.io/kimi-code/en/customization/skills),
[subagentes](https://moonshotai.github.io/kimi-code/en/customization/agents) e
[hooks](https://moonshotai.github.io/kimi-code/en/customization/hooks), lidas em
2026-10-02.)

## Notas de compatibilidade

O Kimi Code lê as instruções do projeto de `AGENTS.md` ou de
`.kimi-code/AGENTS.md` e reconhece `.kimi-code/mcp.json` como a superfície MCP
de propriedade do operador; o Apothem nomeia essa superfície, mas não redige
nenhuma entrada nela. A superfície de instruções renderizada conduz o projeto
diretamente. O Kimi Code não expõe nenhuma superfície de arquivos de statusline
ou de output-style, então esses cohorts não são materializados.

O Kimi Code roda sobre a família de modelos Kimi da Moonshot; consulte a
[referência de configuração do fornecedor](https://moonshotai.github.io/kimi-code/en/configuration/config-files)
para o modelo e a superfície de configuração atuais.

## Verificação

```bash
apothem verify --harness kimi-code --project /path/to/project
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Todos os campos obrigatórios do perfil compartilhado estão presentes.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness kimi-code --project /path/to/project
```

Deriva novamente o bloco gerenciado do `AGENTS.md` da raiz do projeto e os
cohorts de suporte a partir do estado atual do perfil compartilhado.

## Desinstalação

```bash
apothem uninstall --harness kimi-code --project /path/to/project
```

Remove os arquivos de configuração nativa gravados pelo adaptador.
O YAML do perfil compartilhado e o motor do Apothem não são afetados.

## Conformity gate

```bash
python -m apothem.conformity.gate --all .
```

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness kimi-code --project /path/to/project` |
| Falha na verificação | Execute `apothem update --harness kimi-code --project /path/to/project` e depois verifique novamente |
| Conteúdo de configuração inesperado | Verifique `~/.config/apothem/profile.yaml` ou `--profile PATH` e depois execute novamente `apothem update --harness kimi-code --project /path/to/project` |
