**Fornecedor:** AWS
**Nome de instalação:** `kiro`
**Status:** GA
**Configuração nativa:** `<project>/.kiro/steering/apothem-rules.md`

## Instalação

```bash
apothem install --harness kiro --project /path/to/project
```

O adaptador grava um arquivo de direcionamento (steering) do Kiro com escopo de
projeto a partir da superfície compartilhada de regras e governança do Apothem.

**Arquivos gravados:** `<project>/.kiro/steering/apothem-rules.md`

## Mapeamento do perfil para a configuração nativa

O adaptador lê o perfil compartilhado do Apothem e renderiza o arquivo de
direcionamento do projeto a cada execução de `apothem install` ou
`apothem update`. O perfil compartilhado é a fonte da verdade; as edições locais
do projeto no arquivo gerado recebem backup antes que a próxima sincronização
substitua o conteúdo gerenciado pelo Apothem.

O arquivo começa com seu front matter `inclusion: always`, porque o Kiro exige
que a configuração de inclusão seja o primeiro conteúdo do arquivo. O bloco
gerenciado pelo Apothem vem em seguida; o texto que você adiciona depois do
bloco é mantido a cada sincronização.

## Notas de compatibilidade

A superfície de direcionamento do Kiro tem escopo de projeto sob
`.kiro/steering/`. O adaptador grava um arquivo de direcionamento dedicado
`apothem-rules.md` com o front matter `inclusion: always` e nunca sobrescreve os
arquivos de base do Kiro redigidos pelo operador (`product.md`, `tech.md`,
`structure.md`). As especificações (specs) do Kiro (`.kiro/specs/`) e os hooks
de agente pertencem ao operador; o Apothem não os grava.

## Verificação

```bash
apothem verify --harness kiro --project /path/to/project
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Cada destino gerenciado existe; os arquivos gerenciados não estão vazios, e as configurações JSON ou YAML são analisadas sem erros. Adicione `--profile PATH` para também confirmar que os arquivos instalados correspondem a esse perfil.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness kiro --project /path/to/project
```

Deriva novamente o arquivo de direcionamento do projeto a partir do estado atual
do perfil compartilhado.

## Desinstalação

```bash
apothem uninstall --harness kiro --project /path/to/project
```

Remove os arquivos de configuração nativa gravados pelo adaptador.
O YAML do perfil compartilhado e o motor do Apothem não são afetados.

## Conformity gate

```bash
python -m apothem.conformity.gate --all .
```

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness kiro --project /path/to/project` |
| Falha na verificação | Execute `apothem update --harness kiro --project /path/to/project` e depois verifique novamente |
| Conteúdo de configuração inesperado | Verifique `~/.config/apothem/profile.yaml` ou `--profile PATH` e depois execute novamente `apothem update --harness kiro --project /path/to/project` |
