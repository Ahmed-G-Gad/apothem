**Fornecedor:** Anthropic
**Nome de instalação:** `claude-code`
**Status:** GA
**Configuração nativa:** `~/.claude/`

## Instalação

```bash
apothem install --harness claude-code
```

O adaptador `claude-code` instala o corpus compartilhado do Apothem na árvore de
descoberta nativa do Claude Code. Os agentes em Markdown, as regras, as skills,
os output styles e as configurações são instalados em seus locais nativos; os
prompts de comando são convertidos em skills para que os fluxos de trabalho
reutilizáveis permaneçam visíveis pela superfície de skills atual do Claude
Code. O renderizador de statusline é copiado para `~/.claude/statuslines/`, mas
não é conectado: o Claude Code lê sua linha de status da configuração
`statusLine`, que o adaptador deixa sem definir. Para ativá-lo, adicione ao
`settings.json` uma entrada `statusLine` de `"type": "command"` que execute
`~/.claude/statuslines/render.py`.

**Arquivos gravados:** `settings.json`, o bloco do Apothem em `CLAUDE.md`, `agents/`, `rules/`, `skills/`,
`statuslines/`, `output-styles/` e a subárvore de suporte `.apothem/support/`
(`.apothem/support/hooks/`, `.apothem/support/conformity/`,
`.apothem/support/schemas/`, `.apothem/support/templates/`) sob `~/.claude/`.
Os arquivos de comando são convertidos em
diretórios de skill filhos. O despachante de hooks e o conformity gate são
executados a partir de suas cópias materializadas — as entradas de hook do
`settings.json` invocam `~/.claude/.apothem/support/hooks/dispatch.py` e
`~/.claude/.apothem/support/conformity/gate.py` por caminho absoluto, de modo
que nenhum pacote `apothem` importável é necessário no host.

`~/.claude/CLAUDE.md` permanece de propriedade do operador. O adaptador grava
nele um único bloco do Apothem delimitado por sentinelas, que contém a projeção
do perfil (identidade, preferências, regras, seriedade e comportamentos ativados
por opção) e uma seção de arquivos de suporte do Apothem, e preserva literalmente
cada linha fora das sentinelas. A seção de arquivos de suporte nomeia o
diretório absoluto em relação ao qual cada citação no estilo do repositório nas
regras, skills e agentes instalados é resolvida: `rules/<name>.md` sob
`~/.claude/rules/`, e `templates/...`, `schemas/...`, `hooks/...` e
`conformity/...` sob `~/.claude/.apothem/support/`. O restante da superfície de
governança do Apothem chega ao Claude Code pela árvore `rules/` propagada e pelo
hook SessionStart. O OpenCode também carrega `~/.claude/CLAUDE.md` quando não
existe nenhum `~/.config/opencode/AGENTS.md`, então o bloco não nomeia nenhuma
ferramenta específica como seu leitor.

## Mapeamento do perfil para a configuração nativa

A cada `apothem install` ou `apothem update`, o adaptador propaga o corpus
compartilhado do `apothem` para `~/.claude/` conforme o manifesto de propagação.
O adaptador usa diretórios nativos diretamente onde possível e converte os
prompts de comando em pastas de skill. Os filhos existentes correspondentes
gerenciados pelo Apothem recebem backup antes da substituição; as entradas não
relacionadas criadas pelo operador são preservadas. O `settings.json` é mesclado
para que as chaves criadas pelo operador permaneçam recuperáveis.

As skills instaladas, e as skills empacotadas no plugin do Claude Code, carregam
`user-invocable` em vez do `userInvocable` do corpus de origem, porque o Claude
Code lê apenas a chave hifenizada. Os dois contêineres de templates
(`plan-suite`, `research-suite`) a definem como `false`, de modo que ficam fora
do menu `/`. Todo output style define `keep-coding-instructions: true`, de modo
que selecionar um deles mantém as instruções de engenharia de software
integradas do Claude Code.

## Notas de compatibilidade

Os prompts de comando são convertidos em diretórios de skill; agentes, regras,
skills e output styles são copiados como estão. A instalação valida que o perfil
está bem formado e que todas as vinculações de hook em settings.json são
resolvíveis. O adaptador não cria nenhuma entrada de servidor MCP: registre os
servidores com `claude mcp add` (consulte
[Servidores MCP](/docs/reference/mcp)).

O Claude Code aplica todas as vinculações de hook em settings.json a cada início de sessão. Cada adaptador é verificado contra seu próprio harness nativo — não existe um harness "de referência" privilegiado.

### Limites das regras de permissão

O template de configurações nega `Read(...)` em caminhos de segredos e de cache,
como `.env*` e `~/.ssh/**`. O Claude Code aplica uma negação de `Read` às suas
ferramentas de arquivo, aos comandos de arquivo que reconhece no Bash (`cat`,
`head`, `tail`, `sed`, `tee`) e aos alvos de redirecionamento. Ele não aplica a
negação a uma busca que lê arquivos sem nomeá-los, como `grep -r pattern .`, nem
a um script que abre arquivos por conta própria
([referência de permissões](https://code.claude.com/docs/en/permissions)). No
macOS, no Linux e no WSL, o Claude Code deixa as ferramentas `Glob` e `Grep` fora
do conjunto de ferramentas padrão e, em vez disso, faz as buscas pelo Bash, de
modo que as entradas do template que permitem `Glob` e `Grep` só têm efeito onde
essas ferramentas estão presentes. Para impedir que qualquer processo leia um
caminho, habilite o sandbox do Claude Code.

As skills e as definições de auxiliares que nomeiam `TodoWrite` também nomeiam
`TaskCreate`, `TaskGet`, `TaskList` e `TaskUpdate`, porque o Claude Code
desativa `TodoWrite` por padrão em favor dessas ferramentas.

## Verificação

```bash
apothem verify --harness claude-code
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Cada destino gerenciado existe; os arquivos gerenciados não estão vazios, e as configurações JSON ou YAML são analisadas sem erros. Adicione `--profile PATH` para também confirmar que os arquivos instalados correspondem a esse perfil.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness claude-code
```

Deriva novamente a configuração nativa a partir do perfil compartilhado atual.
Execute depois que o pacote `apothem` instalado for atualizado, para que a
superfície de convenções propagada (agentes, regras, skills, statuslines,
output-styles) reflita a nova versão. No `CLAUDE.md`, o update reescreve apenas
o bloco do Apothem entre suas sentinelas.

## Desinstalação

```bash
apothem uninstall --harness claude-code
```

Remove os arquivos de configuração nativa gravados pelo adaptador e retira o
bloco do Apothem do `CLAUDE.md`, deixando o seu próprio texto no lugar.
O pacote `apothem` instalado e o repositório de código-fonte não são afetados.

## Conformity gate

```bash
python -m apothem.conformity.gate --all .
```

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness claude-code` |
| Falha na verificação | Execute `apothem update --harness claude-code` e depois verifique novamente |
| Conteúdo de configuração inesperado | Execute novamente `apothem update`; o perfil compartilhado do `apothem` é a fonte da verdade, não `~/.claude/` |
