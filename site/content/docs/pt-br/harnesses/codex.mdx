**Fornecedor:** OpenAI
**Nome de instalação:** `codex`
**Status:** Beta
**Configuração nativa:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml` e `~/.agents/skills/`

## Instalação

```bash
apothem install --harness codex
```

O adaptador instala instruções e hooks nativos do Codex, converte os agentes do
Apothem em agentes TOML do Codex e encapsula prompts de comando reutilizáveis
como skills do Codex.

**Arquivos gravados:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml`,
`~/.agents/skills/*/SKILL.md`, `~/.agents/skills/*/agents/openai.yaml` para
skills invocadas pelo usuário e arquivos de suporte sob
`~/.config/apothem/{rules,templates}/`.

O bloco do Apothem em `AGENTS.md` termina com uma seção de arquivos de suporte
do Apothem que nomeia o diretório absoluto em relação ao qual cada citação no
estilo do repositório nas skills e regras instaladas é resolvida:
`rules/<name>.md` e `templates/...` sob `~/.config/apothem/`, e `hooks/...` sob
`~/.codex/hooks/`. A instalação do Codex não distribui nenhuma árvore
`schemas/` ou `conformity/`, então a seção não lista nenhuma das duas.

**Skills invocadas pelo usuário.** O Codex ignora a chave
`disable-model-invocation`. Para cada skill ou comando cuja origem define
`disable-model-invocation: true`, o adaptador grava `agents/openai.yaml` ao lado
do respectivo `SKILL.md` com `policy.allow_implicit_invocation: false`, de modo
que o Codex não escolhe a skill por conta própria; você ainda pode executá-la
explicitamente com `$skill-name`. Consulte a
[documentação de skills do Codex](https://developers.openai.com/codex/skills).

## Mapeamento do perfil para a configuração nativa

O adaptador lê os cohorts compartilhados do Apothem e instala cada um na
superfície correta do Codex: instruções em `AGENTS.md`, hooks em `hooks.json` e
`hooks/`, agentes em TOML, skills em `~/.agents/skills/` e regras/templates em
Markdown não nativos em `~/.config/apothem/` como material de suporte.

Cada auxiliar convertido define `name`, `description` e
`developer_instructions`. Um auxiliar cuja concessão de ferramentas não permite
gravar arquivos também define `sandbox_mode = "read-only"`, a restrição de
gravação própria do Codex. Nenhum modelo ou esforço de raciocínio é definido, de
modo que cada auxiliar herda as escolhas da sessão. O Codex não tem lista de
ferramentas nem limite de turnos por auxiliar, então os `tools` e o `maxTurns`
de um auxiliar não são transferidos.

## Notas de compatibilidade

`~/.agents/skills/` é uma raiz compartilhada de propriedade do Codex: outras
oito ferramentas suportadas também a carregam (o
[registro de harnesses](/docs/reference/harness-registry) as lista), então as
skills do Apothem que uma instalação do Codex grava ali também aparecem nessas
ferramentas, e uma desinstalação do Codex as remove dessas ferramentas. A
instalação imprime uma nota que nomeia essas ferramentas.

O Codex reserva `~/.codex/rules/` para políticas de execução `.rules`. O Apothem
não coloca regras comportamentais em Markdown ali; ele as mantém em
`~/.config/apothem/` e as referencia a partir do `AGENTS.md` e das skills
instaladas.

## Verificação

```bash
apothem verify --harness codex
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Cada destino gerenciado existe; os arquivos gerenciados não estão vazios, e as configurações JSON ou YAML são analisadas sem erros. Adicione `--profile PATH` para também confirmar que os arquivos instalados correspondem a esse perfil.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness codex
```

Atualiza o bootstrap do Codex, os agentes convertidos, as skills e os cohorts de
suporte.

## Desinstalação

```bash
apothem uninstall --harness codex
```

Remove os arquivos de configuração nativa gravados pelo adaptador.
O YAML do perfil compartilhado e o motor do Apothem não são afetados.

## Conformity gate

```bash
python -m apothem.conformity.gate --all .
```

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness codex` |
| Falha na verificação | Execute `apothem update --harness codex` e depois verifique novamente |
| Conteúdo de configuração inesperado | Verifique `~/.config/apothem/profile.yaml` ou `--profile PATH` e depois execute novamente `apothem update --harness codex` |
