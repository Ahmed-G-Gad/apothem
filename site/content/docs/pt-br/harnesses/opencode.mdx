**Fornecedor:** OpenCode
**Nome de instalação:** `opencode`
**Status:** Beta
**Configuração nativa:** `~/.config/opencode/`

## Instalação

```bash
apothem install --harness opencode
```

O adaptador grava a configuração JSON do OpenCode, instala as skills do Apothem
na superfície de skills do OpenCode, converte os prompts de comando em arquivos
de comando Markdown do OpenCode e normaliza as definições de auxiliares do
Apothem como subauxiliares do OpenCode.

**Arquivos gravados:**

```text
~/.config/opencode/opencode.json
~/.config/opencode/apothem/rules/00-apothem-profile.md
~/.config/opencode/commands/
~/.config/opencode/skills/
~/.config/opencode/agents/
~/.config/opencode/.apothem/support/{rules,templates,hooks}/
```

## Mapeamento do perfil para a configuração nativa

O adaptador renderiza `opencode.json` com uma lista de arquivos `instructions`
que nomeia o seu documento de perfil, as quatro regras centrais e o índice de
regras e, em seguida, propaga cada cohort compartilhado do Apothem para uma
superfície nativa do OpenCode ou para uma subárvore de suporte de propriedade do
Apothem. Os filhos existentes correspondentes gerenciados pelo Apothem recebem
backup antes da substituição.

## Notas de compatibilidade

O OpenCode combina todos os arquivos que a lista `instructions` nomeia em todas
as sessões ([regras do OpenCode](https://opencode.ai/docs/rules/)). Por isso, a
lista nomeia primeiro o seu documento de perfil e depois apenas as regras cujo
`alwaysApply` é `true`, cada uma com um caminho explícito
`~/.config/opencode/.apothem/support/rules/<name>.md`; o OpenCode expande o `~/`
inicial em relação ao seu diretório home. Essas regras são
`agnostic-posture`, `authority-inquiry`, `context-management`,
`session-closure` e o índice de regras, `apothem-rule-index`. O OpenCode não
limita nenhuma regra por caminho, então todas as outras regras são lidas sob
demanda. Elas permanecem instaladas como material de referência sob
`~/.config/opencode/.apothem/support/`, e o índice nomeia cada regra e a
situação que a exige. Uma regra, skill ou comando que cite uma regra, um
template ou um prompt de hook o lê dali. Os comandos, as skills e as
definições de auxiliares usam locais de descoberta nativos.

O documento de perfil `~/.config/opencode/apothem/rules/00-apothem-profile.md`
carrega a sua identidade e as suas preferências do perfil compartilhado e
termina com uma seção de arquivos de suporte do Apothem que nomeia o diretório
absoluto sob `~/.config/opencode/.apothem/support/` em relação ao qual cada
citação no estilo do repositório (`rules/<name>.md`, `templates/...`,
`hooks/...`) é resolvida. Ele é a primeira entrada de `instructions`, então o
OpenCode o carrega em todas as sessões.

Um `opencode.json` gravado por um lançamento anterior lista o glob único
`~/.config/opencode/.apothem/support/rules/*.md`, que carrega todas as regras,
ou um caminho explícito para cada uma das 28 regras que eram então sempre
ativas. `apothem install` e `apothem update` substituem qualquer uma das formas
pela lista acima, o que remove os 24 caminhos que não são mais carregados na
inicialização, e `apothem uninstall` remove todos eles. As suas próprias
entradas de `instructions` são mantidas em todos os casos.

## Verificação

```bash
apothem verify --harness opencode
```

O comando verify confirma que:

1. A configuração nativa existe no caminho esperado.
2. Cada destino gerenciado existe; os arquivos gerenciados não estão vazios, e
   as configurações JSON ou YAML podem ser analisadas. Adicione `--profile PATH`
   para também confirmar que os arquivos instalados correspondem a esse perfil.
3. A rotina de verificação específica do adaptador informa sucesso.

## Atualização

```bash
apothem update --harness opencode
```

Atualiza `opencode.json`, os comandos nativos, as skills, as definições de
auxiliares e a árvore de suporte do Apothem.

## Desinstalação

```bash
apothem uninstall --harness opencode
```

Remove as entradas que o adaptador adicionou a
`~/.config/opencode/opencode.json` (as suas próprias chaves, os servidores MCP e
as entradas de `instructions` permanecem, e o arquivo é excluído somente quando
o Apothem o criou e nada seu restou). Remove o bloco do Apothem do documento de
perfil `~/.config/opencode/apothem/rules/00-apothem-profile.md` e mantém
qualquer outro texto nele; esse arquivo é excluído somente quando nada mais
resta nele. Também remove os arquivos do Apothem em
`~/.config/opencode/commands/`, `~/.config/opencode/skills/`,
`~/.config/opencode/agents/` e `~/.config/opencode/.apothem/support/`; os
demais arquivos dessas pastas permanecem. Cada arquivo recebe backup em
`~/.apothem/backups/` antes de ser alterado ou removido. O YAML do perfil
compartilhado e o motor do Apothem não são afetados.

## Solução de problemas

| Sintoma | Correção |
|---------|-----|
| Arquivo de configuração não encontrado | Execute novamente `apothem install --harness opencode` |
| Falha na verificação | Execute `apothem update --harness opencode` e depois verifique novamente |
| Conteúdo de configuração inesperado | Verifique `~/.config/apothem/profile.yaml` ou `--profile PATH` e depois execute novamente `apothem update --harness opencode` |

## Ajustes de configuração

| Sinalizador | Padrão | Descrição |
|------|---------|-------------|
