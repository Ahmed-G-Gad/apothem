O Zed lê as instruções do agente a partir de um único arquivo plano `.rules` na
raiz do projeto (ao lado da família `AGENTS.md` / `CLAUDE.md`). O adaptador zed
do Apothem renderiza esse arquivo a partir do perfil compartilhado. Esta página
contrasta manter essa configuração à mão com gerenciá-la com o Apothem.

## Comparação de esforço

| Tarefa | Configuração manual | Gerenciada pelo Apothem |
| ---- | --------------- | --------------- |
| Escrever instruções | Escrever à mão o arquivo `.rules` | Renderizadas a partir do corpus compartilhado |
| Preservar um `.rules` anterior | Lembrar de copiá-lo para outro lugar você mesmo | O adaptador faz backup do arquivo existente antes de substituí-lo |
| Manter as regras alinhadas com outros harnesses | Manual, por ferramenta | Automático no `apothem update` |
| Compartilhar skills e comandos reutilizáveis | Copiar à mão cada pasta de skill para `~/.agents/skills/` e manter as cópias atualizadas | Gravados em `~/.agents/skills/` pelo adaptador, uma cópia para todos os projetos, e atualizados no `apothem update` |
| Verificar se a configuração está correta | Inspeção manual | `apothem verify --harness zed --project <path>` |

## O que o Apothem gerencia

O adaptador zed renderiza as regras compartilhadas no arquivo plano `.rules` da
raiz do projeto. O Zed não tem hook PreToolUse, então a intenção de proteção vive
na prosa da regra em vez de em um ponto de interceptação de chamada de
ferramenta. O arquivo de instruções global `~/.config/zed/AGENTS.md` e o bloco do
servidor de contexto MCP de `.zed/settings.json` são propriedade do operador e
ficam intocados. Cada mudança nas regras compartilhadas re-renderiza o arquivo no
próximo `apothem update`.

## Caminho de migração

1. Execute `apothem profile init` para criar o perfil compartilhado, caso ainda não o tenha.
2. Mova as instruções do seu `.rules` existente (e qualquer conteúdo de `AGENTS.md` específico do projeto que você queira compartilhar) para o corpus compartilhado.
3. Execute `apothem install --harness zed --project <path>` para renderizar o arquivo `.rules`. O seu `.rules` anterior recebe backup primeiro.
4. Execute `apothem verify --harness zed --project <path>` para confirmar que a configuração foi gravada.
5. Use `apothem update --harness zed --project <path>` para cada mudança posterior.
