O Kimi Code lê o `AGENTS.md` da raiz do projeto como seu arquivo de instruções e
mantém a configuração do projeto em `<project>/.kimi-code/`, incluindo a
superfície MCP `.kimi-code/mcp.json`, que pertence ao operador. Você pode
escrever esse arquivo de instruções e os cohorts que o acompanham à mão, projeto
a projeto, para sempre. O adaptador kimi-code do Apothem renderiza a superfície
de governança no `AGENTS.md` como um bloco gerenciado a partir do perfil
compartilhado e a mantém consistente em todos os harnesses e em todos os
projetos. Esta página contrasta a manutenção manual dessa configuração com o
gerenciamento dela pelo Apothem.

## Comparação de esforço

| Tarefa | Configuração manual | Gerenciada pelo Apothem |
| ---- | --------------- | --------------- |
| Escrever a superfície de instruções `AGENTS.md` | Escrever à mão e ressincronizar em cada projeto | Um único bloco gerenciado, renderizado a partir do perfil compartilhado |
| Manter regras, comandos, skills e agentes sincronizados | Cópia manual em cada projeto | Skills e comandos (como skills) em `<project>/.kimi-code/skills/`; auxiliares como subagentes em `<project>/.kimi-code/agents/`; regras, hooks e templates em `<project>/.kimi-code/.apothem/support/`, a cada instalação |
| Preservar a prosa do operador ao atualizar | Mesclagem manual | Bloco delimitado por sentinelas; a prosa do operador fora dele é preservada |
| Manter as regras alinhadas com outros harnesses | Manual, por ferramenta | Automático no `apothem update` |
| Verificar se a configuração está correta | Inspeção manual | `apothem verify --harness kimi-code --project <path>` |

## O que o Apothem gerencia

O adaptador kimi-code renderiza as regras compartilhadas e a superfície de
governança no bloco gerenciado do `AGENTS.md` da raiz do projeto e instala as
skills, e os comandos encapsulados como skills, em `.kimi-code/skills/`, o
diretório de skills do projeto que o Kimi Code carrega. Os auxiliares se tornam
subagentes do Kimi Code em `.kimi-code/agents/`, com os nomes de suas ferramentas
traduzidos para os que o Kimi Code reconhece. Os cohorts de hooks, regras e
templates vão para `.kimi-code/.apothem/support/`: o Kimi Code lê os hooks do
`~/.kimi-code/config.toml` no escopo do usuário, que o adaptador não grava. O
adaptador não escreve o `.kimi-code/mcp.json`; a superfície MCP continua pertencendo ao operador. O Kimi Code lê as instruções do
projeto de `AGENTS.md` ou de `.kimi-code/AGENTS.md`; o adaptador grava apenas o
`AGENTS.md` da raiz do projeto, e a documentação do Kimi Code não diz qual dos
dois arquivos prevalece quando ambos existem. Toda mudança nas regras
compartilhadas renderiza os arquivos novamente no próximo `apothem update`.

## Caminho de migração

1. Execute `apothem profile init` para criar o perfil compartilhado, caso você
   ainda não o tenha criado.
2. Mova as regras do seu `AGENTS.md` existente para o corpus compartilhado.
3. Execute `apothem install --harness kimi-code --project <path>` para renderizar
   a superfície de instruções `AGENTS.md`, as skills em `.kimi-code/skills/`, os
   subagentes em `.kimi-code/agents/` e a subárvore de suporte
   `.kimi-code/.apothem/support/`.
4. Execute `apothem verify --harness kimi-code --project <path>` para confirmar
   que a configuração foi gravada.
5. Use `apothem update --harness kimi-code --project <path>` para cada mudança
   posterior.
