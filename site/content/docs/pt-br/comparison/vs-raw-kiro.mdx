O Kiro lê o direcionamento de um diretório `.kiro/steering/` de arquivos Markdown. O
adaptador kiro do Apothem renderiza um arquivo de direcionamento `apothem-rules.md`
dedicado a partir do perfil compartilhado. Esta página contrasta manter essa
configuração à mão com gerenciá-la com o Apothem.

## Comparação de esforço

| Tarefa | Configuração manual | Gerenciada pelo Apothem |
| ---- | --------------- | --------------- |
| Escrever regras de direcionamento | Escrever à mão cada arquivo em `.kiro/steering/` | Renderizadas a partir do corpus compartilhado |
| Manter os arquivos de base intactos | Lembrar de não sobrescrever `product.md` / `tech.md` / `structure.md` | O adaptador escreve apenas `apothem-rules.md` |
| Manter as regras alinhadas com outros harnesses | Manual, por ferramenta | Automático no `apothem update` |
| Compartilhar skills e comandos reutilizáveis | Copiar à mão cada pasta de skill para `~/.kiro/skills/` e manter as cópias atualizadas | Gravados em `~/.kiro/skills/` pelo adaptador, uma cópia para todos os projetos, e atualizados no `apothem update` |
| Manter auxiliares reutilizáveis sincronizados | Escrever à mão cada arquivo de agente personalizado em `.kiro/agents/` e acompanhar as categorias de ferramentas do Kiro | Catorze auxiliares gravados em `.kiro/agents/` com suas ferramentas traduzidas, e atualizados no `apothem update` |
| Verificar se a configuração está correta | Inspeção manual | `apothem verify --harness kiro --project <path>` |

## O que o Apothem gerencia

O adaptador kiro renderiza as regras compartilhadas em um arquivo de direcionamento
`apothem-rules.md` dedicado com front matter `inclusion: always` e não toca nos
arquivos de base escritos pelo operador do Kiro. Ele também grava os catorze
auxiliares do Apothem como agentes personalizados do Kiro em `<project>/.kiro/agents/`,
para o Kiro IDE 1.0 e o Kiro CLI V3. O Kiro documenta hooks de agente, que o
adaptador não grava, então a intenção dos guarda-corpos vive na prosa das regras em vez de em um ponto de
interceptação de chamadas de ferramenta. Cada mudança nas regras compartilhadas
re-renderiza o arquivo no próximo `apothem update`.

## Caminho de migração

1. Execute `apothem profile init` para criar o perfil compartilhado, caso ainda não o tenha.
2. Mova as regras do seu `.kiro/steering/` existente para o corpus compartilhado.
3. Execute `apothem install --harness kiro --project <path>` para renderizar o arquivo de direcionamento `apothem-rules.md`.
4. Execute `apothem verify --harness kiro --project <path>` para confirmar que a configuração foi gravada.
5. Use `apothem update --harness kiro --project <path>` para cada mudança posterior.
