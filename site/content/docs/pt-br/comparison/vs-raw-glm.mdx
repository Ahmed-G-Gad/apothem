O GLM (Z.ai) é um backend de modelo para o qual uma ferramenta compatível é
apontada pela definição de uma URL base e de uma chave. Você pode exportar essas
variáveis de ambiente à mão, por projeto, por máquina, para sempre. O adaptador
glm do Apothem registra os endpoints do backend e marcadores de posição
configuráveis pelo operador em um único arquivo de provedor e grava o mesmo
template em todos os projetos. Esta página contrasta a conexão manual desse
backend com o gerenciamento dele pelo Apothem.

## Comparação de esforço

| Tarefa | Configuração manual | Gerenciada pelo Apothem |
| ---- | --------------- | --------------- |
| Registrar as URLs do backend | Memorizar e reexportar por projeto | Gravadas em um único arquivo de provedor |
| Fonte da verdade | As exportações de cada shell | Um único arquivo de provedor canônico |
| Manter os backends alinhados entre projetos | Reconectar por projeto | O mesmo template é gravado em cada projeto quando o arquivo está ausente; as edições posteriores permanecem no arquivo de cada projeto |
| Restaurar a configuração | Reexportar em cada projeto | `apothem update --harness glm --project <path>` grava o arquivo novamente somente quando ele está ausente |
| Remover a configuração | Exclusão manual | `apothem uninstall` faz backup do arquivo e depois o remove somente enquanto ele for o template não editado que o Apothem gravou |

## O que o Apothem gerencia

O adaptador glm grava um único arquivo de provedor em
`<project>/.apothem/providers/glm.toml` e não grava nada além disso. Ele
registra a URL base compatível com a Anthropic (`https://api.z.ai/api/anthropic`),
a URL base compatível com a OpenAI (`https://api.z.ai/api/coding/paas/v4`), um
marcador de posição para o token de autenticação e marcadores de posição de
mapeamento de modelos. Sua chave da Z.ai e suas escolhas de ID de modelo
permanecem de propriedade do operador — o Apothem nunca grava um segredo real e
não fixa nenhum ID de modelo volátil entre versões.

## Caminho de migração

1. Execute `apothem profile init` para criar o perfil compartilhado se você
   ainda não tiver. O arquivo glm não obtém nada do perfil, mas toda execução de
   instalação e de atualização o carrega.
2. Execute `apothem install --harness glm --project <path>` para gravar o
   arquivo de provedor `glm.toml`.
3. Preencha a sua chave da Z.ai e os IDs de modelo que você deseja a partir da
   [documentação da Z.ai](https://docs.z.ai/devpack/tool/claude) atual.
4. Execute `apothem verify --harness glm --project <path>` para confirmar que a
   configuração foi gravada.
5. Edite `.apothem/providers/glm.toml` a cada mudança posterior. O Apothem nunca
   reescreve um arquivo de provedor existente; `apothem update --harness glm --project
   <path>` o grava novamente somente quando ele está ausente.
