O CodeBuddy lê as regras do projeto em `.codebuddy/rules/*.md`. Você pode escrever esses arquivos à mão, por projeto, para sempre. O adaptador codebuddy do Apothem renderiza um deles a partir do perfil compartilhado e o mantém consistente em todos os harnesses e em todos os projetos. Esta página compara manter essa configuração à mão com gerenciá-la com o Apothem.

## Comparação de esforço

| Tarefa | Configuração manual | Gerenciada pelo Apothem |
| ---- | --------------- | --------------- |
| Escrever regras | Copiar e colar as mesmas disciplinas em `.codebuddy/rules/` em cada projeto | Renderizadas a partir de um único corpus compartilhado |
| Fonte de verdade | Os arquivos de cada projeto | Um cohort canônico |
| Manter as regras alinhadas entre harnesses | Derivar novamente por ferramenta | Projetadas automaticamente |
| Atualizar as regras | Editar à mão em cada projeto | `apothem update --harness codebuddy --project <path>` |
| Remover a configuração | Exclusão manual | `apothem uninstall` com backup com marca de tempo |

## O que o Apothem gerencia

O adaptador codebuddy renderiza as regras compartilhadas em um arquivo dedicado `<project>/.codebuddy/rules/apothem-rules.md` e não grava nenhum outro arquivo. Seu arquivo de memória `CODEBUDDY.md`, suas permissões e servidores MCP em `.codebuddy/settings.json` e quaisquer outros arquivos de regras que você escrever continuam pertencendo inteiramente ao operador: o adaptador reconhece essas superfícies, mas nunca as edita. Toda mudança nas regras compartilhadas re-renderiza o arquivo na próxima execução de `apothem update`.

## Caminho de migração

1. Execute `apothem profile init` para criar o perfil compartilhado, se você ainda não tiver um.
2. Mova as disciplinas dos seus arquivos existentes em `.codebuddy/rules/` para o
   corpus compartilhado.
3. Execute `apothem install --harness codebuddy --project <path>` para renderizar o
   arquivo `apothem-rules.md` ao lado das suas regras, que permanecem intocadas.
4. Execute `apothem verify --harness codebuddy --project <path>` para confirmar que a
   configuração foi aplicada.
5. Use `apothem update --harness codebuddy --project <path>` para cada mudança posterior.
