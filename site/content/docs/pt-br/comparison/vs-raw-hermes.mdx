O Hermes lê `~/.hermes/config.yaml`. O Apothem escreve a configuração YAML nativa
(projetando o inventário de MCP do perfil em `auxiliary.mcp`) e instala coortes
compartilhadas de comandos e skills sob `~/.hermes/.apothem/support/skills/`. O próprio
`skills.config` do Hermes é uma lista de pacotes de registro, então o Apothem não
o escreve.

## Status

**Prévia.** O adaptador do Hermes mira o arquivo de configuração atualmente
documentado e a superfície de descoberta de skills. As coortes que não são de
skills permanecem material de apoio do Apothem.

## Comparação de esforço

| Tarefa | Config à mão bruta | Gerenciado pelo Apothem |
| ---- | --------------- | --------------- |
| Escrever skills reutilizáveis | Editar à mão a config e os diretórios de skills | Escrever uma vez no corpus compartilhado |
| Manter as coortes alinhadas com outros ambientes | Manual, por ferramenta | Automático no `apothem update` |
| Instalar / remover a config | Manual | `apothem install` / `apothem uninstall` |
| Verificar se a config está correta | Inspeção manual | `apothem verify --harness hermes` |

## O que o Apothem gerencia

O adaptador do Hermes escreve `config.yaml`, envolve os comandos de barra do
Apothem como skills, copia as skills do Apothem para o diretório de apoio
referenciado e mantém as regras, modelos, agents e material de hooks sob a
subárvore de apoio do Apothem.

## Caminho de migração

1. Execute `apothem profile init` para criar o perfil compartilhado se você ainda
   não o fez.
2. Mova as skills ou os prompts de comandos reutilizáveis do Hermes para o corpus
   compartilhado.
3. Execute `apothem install --harness hermes` para renderizar a configuração
   nativa e o diretório de skills de apoio.
4. Execute `apothem verify --harness hermes` para confirmar que a configuração
   aterrissou.
