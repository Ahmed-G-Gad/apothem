Objetivo: habilitar mais uma ferramenta para que o Apothem materialize a configuração
nativa dessa ferramenta a partir do seu perfil compartilhado.

## Pré-requisitos

- Um perfil compartilhado em `~/.config/apothem/profile.yaml` (crie um com
  `apothem profile init` se ele ainda não existir).
- A CLI `apothem` no seu `PATH`. Se você instalou a árvore de fontes
  autocontida, prefixe cada comando com `PYTHONPATH="$HOME/.apothem/src"`
  e execute `python -m apothem` no lugar de `apothem` — ou use
  `npx @ahmed-g-gad/apothem`.

## Passos

1. Liste as ferramentas registradas e veja quais já estão instaladas:

   ```bash
   apothem harnesses list
   ```

   `apothem harnesses list` imprime cada id suportado; o mesmo conjunto está na
   [lista de ferramentas](/docs/harnesses) e no
   [registro de ferramentas](/docs/reference/harness-registry) gerado a partir do código-fonte. Escolha o id da sua ferramenta
   em vez de fixar a lista aqui — ela cresce conforme adaptadores são adicionados.

2. Inspecione a ferramenta-alvo para confirmar seu escopo e caminho de saída:

   ```bash
   apothem harnesses show cursor
   ```

   Uma linha `Scope: project` significa que o adaptador materializa em uma árvore de projeto
   e requer `--project PATH`; `Scope: user` materializa em um diretório de configuração
   de escopo de usuário e não precisa de flag de projeto.

3. Pré-visualize a instalação sem gravar arquivos:

   ```bash
   apothem install --harness cursor --dry-run
   ```

4. Instale o harness. Para um harness de escopo de usuário:

   ```bash
   apothem install --harness claude-code
   ```

   Para um harness de escopo de projeto, informe a raiz do projeto:

   ```bash
   apothem install --harness cursor --project /path/to/project
   ```

   Instale todas as ferramentas suportadas de uma vez com `--harness all` (ferramentas de escopo
   de projeto ainda precisam de `--project`; ids listados em `exclude_harnesses` no
   perfil são ignorados).

## Verificar

```bash
apothem verify --harness cursor
```

Uma linha `✓ <harness-id> is verified` confirma que os alvos gerenciados existem e são interpretáveis.
`apothem doctor` fornece a visão do sistema inteiro em todas as ferramentas.
