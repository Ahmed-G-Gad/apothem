## Remova primeiro as configurações de harness

O comando `apothem` simples usado nesta página é o shim que o instalador de uma única etapa (canal 3 do [guia de instalação](/docs/install)) grava; ele funciona quando o diretório desse shim está em `PATH`. Nos demais canais de instalação, substitua `apothem` por `npx @ahmed-g-gad/apothem`, como descreve o guia de instalação.

Antes de desinstalar o Apothem, remova a configuração de cada adaptador de
harness para deixar seus harnesses em um estado limpo. Execute
`apothem harnesses list` para ver quais adaptadores estão instalados no momento
e, em seguida, remova-os um de cada vez ou use o seletor que abrange todo o
registro:

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness cursor --project /path/to/project
apothem uninstall --harness all --project /path/to/project --yes
```

Passe `--yes` para pular o prompt de confirmação de cada harness.

## Remova o motor

A remoção corresponde ao canal de instalação que você usou. Os números dos
canais são os da
[tabela de canais de instalação](/docs/install#escolha-um-canal):

- **Plugin do Claude Code (canal 1)** — remova o plugin de dentro do Claude
  Code: `/plugin uninstall apothem@apothem` (a entrada do marketplace pode ser
  removida com `/plugin marketplace remove ahmed-g-gad/apothem`).
- **npx (canal 2)** — nada a remover; o `npx` roda a partir do seu cache.
  Limpe-o com `npm cache clean --force` se quiser eliminar a cópia em cache.
- **Instalador de uma única etapa (canal 3)** — execute o script de
  desinstalação correspondente a partir do checkout:
  `scripts/installer/uninstall.sh` (POSIX) ou `scripts/installer/uninstall.ps1`
  (PowerShell). Cada script remove o harness indicado por `--harness`
  (`-Harness` no PowerShell); se ele não for informado, usa `APOTHEM_HARNESS`;
  se também não estiver definido, usa o Claude Code. Ele também remove o shim do
  comando `apothem`. A origem vem de `APOTHEM_SOURCE`, quando definido, ou de
  `APOTHEM_HOME` (padrão `$HOME/.apothem`). A origem permanece, a menos que você
  passe `--remove-source` (`-RemoveSource` no PowerShell). Essa opção apaga
  somente o clone gerenciado em `APOTHEM_HOME`, e apenas quando ele tem um
  diretório `.git`. Com a localização padrão, ela também apaga os backups de
  instalação e o ledger em `~/.apothem/`. Ambos pedem confirmação antes de
  remover as configurações dos harnesses e a origem. `--yes` (`-Yes` no
  PowerShell) pula as confirmações. Ambos recusam alvos inseguros.
- **Extensão da família VS Code (canal 4)** — execute **Apothem: Uninstall**
  primeiro na paleta de comandos, para remover as configurações dos harnesses, e
  depois remova a extensão na visualização Extensões ou com `code --uninstall-extension ahmed-g-gad.apothem-vscode`
  (uma cópia instalada a partir de um `apothem.vsix` anterior é `ahmed-g-gad.apothem`).
  Por padrão, a extensão executa o motor por meio do `npx`, portanto a entrada
  **npx** acima cobre o cache.
- **Bootstraps de linha de comando (canais 5–7)** — remova a extensão ou o
  plugin com a ferramenta do respectivo host depois que as configurações dos
  harnesses tiverem sido removidas. Os hosts:

  ```text
  channel 5   Gemini CLI extension
  channel 6   Qwen Code extension
  channel 7   Codex plugin
  ```

  O bootstrap apenas adiciona contexto do assistente (um arquivo de contexto,
  um comando ou uma skill) que chama o motor por meio do `npx`, de modo que nada
  mais permanece. Os hosts de extensão dos canais 5 e 6 aceitam um comando de
  desinstalação; para o host de plugin do canal 7, desinstale `apothem` no
  navegador de plugins dele.

  ```bash
  gemini extensions uninstall apothem   # channel 5
  qwen extensions uninstall apothem     # channel 6
  ```
- **Motor direto (canal 8)** — nada a desinstalar; exclua o clone depois que as
  configurações de harness forem removidas.
- **Backups e estado** — os backups de instalação ficam sob
  `~/.apothem/backups/` e o livro-razão de instalação sob `~/.apothem/state/`.
  Ambos permanecem limitados: após cada instalação, desinstalação e reversão, o
  Apothem mantém os 10 registros de instalação mais recentes por raiz de
  instalação e os 10 conjuntos de backup mais recentes por harness, e nunca
  exclui um backup de que um registro mantido ainda precisa, de modo que as
  últimas 10 instalações ainda podem ser revertidas. Para manter menos, execute
  [`apothem backups prune --keep N`](/docs/cli-reference/backups) (adicione
  `--dry-run` para ver primeiro o que ele removeria); ele nunca remove o backup
  a partir do qual a reversão da instalação mais recente de um harness
  restaura. Depois que o motor for removido e você não precisar mais de nenhuma
  parte do histórico, exclua `~/.apothem/`.

## O que NÃO é removido

- O YAML do perfil compartilhado em `~/.config/apothem/profile.yaml` ou
  `--profile PATH` nunca é removido por `apothem uninstall`.
- Arquivos não relacionados criados pelo operador nos diretórios dos harnesses
  são preservados.
- As entradas que você adicionou a um arquivo de configurações compartilhado
  são preservadas: suas próprias regras de permissão, servidores MCP e handlers
  de hook permanecem. A desinstalação remove somente as chaves e as entradas de
  lista que o livro-razão de instalação registra como do Apothem (consulte
  [Configurações](/docs/reference/settings#mesclagem-no-seu-próprio-arquivo-de-configurações)).
- Os armazenamentos de dados compartilhados sob `.apothem/` na raiz de
  instalação (`memory/`, `contexts/`, `learning/`) permanecem enquanto outro
  harness instalado na mesma raiz ainda os usar. Desinstalar o último harness
  nessa raiz copia cada armazenamento para `~/.apothem/backups/` primeiro e
  depois o remove com tudo o que há dentro dele.
- As suítes de planejamento sob `<project>/.apothem/plans/` (e o legado `<project>/.plans/`) não são afetadas.

## Diretórios

A desinstalação também remove os diretórios que a instalação criou (por
exemplo, um `~/.claude/` que não existia antes da primeira instalação), quando
eles ficam vazios. Um diretório que ainda contém um arquivo seu, ou dados
que outro harness instalado usa, permanece. Diretórios que existiam antes da
instalação nunca são removidos.

Para limpar completamente uma raiz de harness, remova o caminho nativo do
harness documentado nas [páginas de referência de harnesses](/docs/harnesses)
depois de confirmar que você fez backup de quaisquer regras, auxiliares ou
arquivos de perfil personalizados que deseja manter.
