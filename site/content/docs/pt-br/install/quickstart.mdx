Este é o caminho rápido do zero até uma configuração de harness verificada:
instalar, escrever o perfil compartilhado, materializar a configuração nativa de
uma ferramenta, confirmá-la e fazer sua primeira edição. Todo comando é real e
pode ser copiado, colado e executado, e cada etapa mostra o que uma execução
limpa imprime. A instalação em si termina em menos de dois minutos; editar o
perfil é a única parte que leva o tempo que você quiser.

Ao final, você terá uma configuração de harness funcional gerada a partir de um
perfil que você escreveu — e conhecerá o único comando que propaga de volta uma
alteração do perfil para todas as ferramentas.

<Callout title="Quer a versão mais lenta e narrada?">
  O [tutorial de primeiros passos](/docs/tutorials/getting-started) percorre o
  mesmo terreno com mais explicação de cada etapa e de por que ela importa. Esta
  página é o roteiro conciso, centrado na saída.
</Callout>

Você usará o **Claude Code** como harness de exemplo — ele é o padrão do
instalador. Troque o nome do adaptador em qualquer etapa para mirar outra
ferramenta; a [lista de harnesses](/docs/harnesses) traz todos os nomes
suportados.

## 1. Instalar o Apothem

O Apothem é distribuído como um runtime autocontido — o motor é executado
diretamente a partir da sua árvore de código-fonte, com as dependências
incorporadas. Um único comando baixa o código-fonte, posiciona o motor e
materializa seu primeiro harness:

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 7+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

O instalador requer um Python 3.10+ do sistema com `click` e `rich`
importáveis, além de `git` para a forma via rede. Ele verifica os
pré-requisitos, posiciona o motor em `~/.apothem` e, ao concluir, imprime a
invocação exata do motor para o seu shell:

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="Primeira execução sem um perfil">
  Se você ainda não tem um perfil, o instalador copia o perfil de exemplo para
  `~/.config/apothem/profile.yaml` e segue adiante: ele materializa seu primeiro
  harness e o verifica na mesma execução. Os campos de identidade do exemplo são
  marcadores de posição, então a instalação imprime um aviso. Torne o perfil seu
  na Etapa 2 e depois aplique-o com `apothem update --harness <name>`, como na
  Etapa 5.
</Callout>

<Callout title="O comando `apothem`">
  O instalador coloca um shim `apothem` no seu `PATH`, então você executa o
  motor diretamente como `apothem <command>`. Se o diretório do shim ainda não
  estiver no `PATH`, o banner imprime uma alternativa autocontida —
  `PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>` — que não
  precisa de shim; anteponha a cada comando o prefixo exato que o seu banner
  imprimiu.
</Callout>

O [guia de instalação](/docs/install) cobre as outras rotas de instalação — o
plugin do Claude Code (`/plugin marketplace add ahmed-g-gad/apothem` e depois
`/plugin install apothem@apothem`); as extensões da família VS Code e as demais
extensões nativas das ferramentas; e a forma sob demanda com npx
(`npx @ahmed-g-gad/apothem <command>`) — junto com as opções de variáveis de
ambiente.

## 2. Criar o perfil compartilhado

`apothem profile init` grava o menor perfil válido segundo o schema em
`~/.config/apothem/profile.yaml`. Passe `--profile PATH` quando você mantiver em
outro lugar um perfil específico de um projeto ou de CI.

```bash
apothem profile init
apothem profile show --json
```

O esqueleto usa dados de identidade fictícios, como marcadores de posição, e
pode ser editado com segurança antes de você instalar qualquer saída de harness.
`show --json` o lê de volta e relata o perfil validado:

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

É também aqui que uma edição malformada aparece — se o YAML for inválido, `show`
o relata neste ponto, antes que qualquer configuração de harness seja gravada.
Torne o perfil seu com `apothem profile edit` (que o abre no seu editor) ou
defina uma única chave no lugar:

```bash
apothem profile set identity.name "Your Name"
```

## 3. Instalar adaptadores de harness

Materialize o adaptador do seu harness principal. Isso lê o seu perfil e grava
a configuração nativa dessa ferramenta:

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

Os adaptadores de escopo de projeto gravam dentro de um projeto em vez do seu
diretório pessoal, então precisam de um `--project PATH`. Pré-visualize qualquer
instalação sem gravar arquivos usando `--dry-run`:

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

Instale de uma vez todo o conjunto respaldado pelo registro com `--harness all`. Como essa seleção grava arquivos tanto de escopo de projeto quanto de escopo de usuário, o comando imprime os destinos concretos agrupados por local. Em um terminal interativo, ele pede confirmação antes de gravar fora da raiz do projeto. Uma execução sem terminal, uma execução com `--yes` ou uma execução com `--format json` grava sem perguntar; `--dry-run` não grava nada. Execute o conjunto completo com:

```bash
apothem install --harness all --project .
```

Consulte a [lista completa de harnesses](/docs/harnesses) para todos os nomes
suportados e a [referência de install](/docs/cli-reference/install) para o
conjunto completo de opções.

## 4. Verificar

Materializar é só metade do trabalho: `verify` confirma que os arquivos de configuração esperados do harness foram gravados e são válidos:

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

`verify` sai com código diferente de zero se um destino gerenciado estiver ausente, se um arquivo gerenciado estiver vazio ou se uma configuração JSON ou YAML não for analisada sem erros. Adicione `--profile PATH` para também falhar quando um arquivo instalado diferir desse perfil, o que faz do `verify` uma verificação de desvio; sem ele, uma configuração desatualizada ainda passa na verificação. Isso permite usá-lo como portão em um script de configuração. Para uma verificação de saúde da máquina inteira, abrangendo todos os adaptadores registrados, execute:

```bash
apothem doctor
```

`doctor` verifica cada harness instalado: ele deve passar na verificação, e cada
comando de hook que a sua instalação registrou deve iniciar. Um harness que você
não instalou é listado, mas não conta como falha, então, com um único harness
saudável, `doctor` sai com 0.

## 5. Sua primeira execução

Abra o harness que você acabou de configurar — o Claude Code, neste exemplo — e
inicie uma sessão em qualquer projeto. As regras e preferências que você
escreveu no perfil na Etapa 2 agora fazem parte do comportamento dessa
ferramenta. Essa é a primeira execução funcional: um perfil moldando uma sessão
real.

Quando você alterar o perfil mais tarde, reaplique-o sem reinstalar:

```bash
apothem update --harness claude-code
```
