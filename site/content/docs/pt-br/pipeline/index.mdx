O Apothem traz um pipeline `/plan` ciente da arquitetura, um pipeline
`/research` de treze estágios e uma sequência de auditoria de onze comandos —
o que dá a todo projeto um caminho estruturado da prosa bruta até um código de
nível de produção revisado em vários eixos, e de uma ideia bruta até um artigo
revisado por pares e disseminado.

## Visão geral do pipeline

```mermaid
flowchart LR
    accTitle: Plan pipeline command flow
    accDescr: Left-to-right flowchart of the apothem plan pipeline from the spec stage through the generate and review stages, then through a conditional architecture-bearing decision that either runs the design stage or skips directly to the execute stage. The orthogonal audit stage wraps the spec-through-review span as a closed remediation loop, and the re-entrant amend stage revises an existing suite and returns it to review.
    A[/plan-spec] --> B[/plan-generate]
    B --> C[/plan-review]
    AUD[/plan-audit<br/>orthogonal: wraps spec → review] -.->|closed-loop remediation| A
    AM[/plan-amend<br/>re-entrant: revises an existing suite] -.->|re-review| C
    C --> Q{Architecture-bearing suite?}
    Q -->|yes| F[/plan-design<br/>emit _inputs/design.md]
    Q -->|no| D[/plan-execute]
    F --> D
    D --> E[/plan-status]
    D --> G[Audit review sequence]
    G --> H[Completion milestone]
```

## Os estágios de planejamento

O pipeline é distribuído como oito slash commands de primeira classe, um por
estágio — cada um invocável de forma independente como `/plan-<stage>`. O
orquestrador [/plan](/docs/pipeline/plan) os conduz de uma missão até uma suíte
executada.

| Estágio | Papel | Posição |
|-------|------|----------|
| [/plan-spec](/docs/pipeline/plan-spec) | Forja — da prosa à especificação | Início |
| [/plan-generate](/docs/pipeline/plan-generate) | Gerador — da especificação à suíte de planejamento | Meio da cadeia |
| [/plan-review](/docs/pipeline/plan-review) | Auditor — auditoria forense do plano | Meio da cadeia |
| [/plan-design](/docs/pipeline/plan-design) | Arquiteto — `_inputs/design.md` para suítes que afetam a arquitetura | Portão condicional |
| [/plan-execute](/docs/pipeline/plan-execute) | Executor — execução de fases | Terminal |
| [/plan-status](/docs/pipeline/plan-status) | Relator — status somente leitura | Somente leitura |
| [/plan-audit](/docs/pipeline/plan-audit) | Guardião — envoltório de ciclo fechado de spec → generate → review | Ortogonal (antes da execução) |
| [/plan-amend](/docs/pipeline/plan-amend) | Zelador — emenda reentrante de uma suíte existente | Reentrante |

`/plan-audit` é ortogonal ao fluxo linear, e não um estágio dentro dele. Ele
envolve `/plan-spec → /plan-generate → /plan-review` como um único ciclo
fechado, executa somente os estágios anteriores que faltam, corrige ativamente
os achados e deixa a suíte pronta para `/plan-execute`. Ele é distinto da
sequência de revisão de auditoria abaixo, que audita uma base de código
executada, e não uma suíte de planejamento.

`/plan-design` não é uma cerimônia universal. `/plan-review` classifica se a
suíte altera superfícies que afetam a arquitetura. Se sim, `/plan-design` emite
o rastro de design que `/plan-execute` e `/architecture-review` consomem. Se
não, a suíte revisada segue diretamente para a execução.

## O pipeline de pesquisa

O pipeline de pesquisa é distribuído como treze slash commands de primeira
classe, um por estágio — cada um invocável de forma independente como
`/research-<stage>`, encadeados por um Portão de Sequência e um Manifesto de
Repasse, sob dez mandatos de rigor (fontes autoritativas, reprodutibilidade,
falseabilidade, integridade das citações, pré-registro, ética / conflitos,
rigor estatístico, ciência aberta / FAIR, conformidade com diretrizes de
relato, fundamentação teórica / impacto).

```mermaid
flowchart LR
    accTitle: Research pipeline command flow
    accDescr: Left-to-right flowchart of the apothem research pipeline from the ideate stage through spec, theory, sources, synthesis, proposal, study design, experiment, analysis, paper, and peer review to publish and disseminate, with a revision loop from review back to paper.
    RI[/research-ideate] --> RS[/research-spec]
    RS --> RT[/research-theory]
    RT --> RSO[/research-sources]
    RSO --> RSY[/research-synthesis]
    RSY --> RPR[/research-proposal]
    RPR --> RD[/research-design]
    RD --> RE[/research-experiment]
    RE --> RA[/research-analysis]
    RA --> RP[/research-paper]
    RP --> RR[/research-review]
    RR --> RPU[/research-publish]
    RPU --> RDI[/research-disseminate]
    RR -.->|revision loop| RP
```

| Estágio | Papel | Posição |
|-------|------|----------|
| [/research-ideate](/docs/pipeline/research-ideate) | Formular o problema — questões candidatas a partir de uma semente de domínio | Início |
| [/research-spec](/docs/pipeline/research-spec) | Enquadrar a questão — hipóteses falseáveis + escopo | Meio da cadeia |
| [/research-theory](/docs/pipeline/research-theory) | Arcabouço conceitual + teoria da mudança | Meio da cadeia |
| [/research-sources](/docs/pipeline/research-sources) | Coleta sistemática de fontes com um registro de busca reexecutável | Meio da cadeia |
| [/research-synthesis](/docs/pipeline/research-synthesis) | Mapa do estado da arte + análise de lacunas | Meio da cadeia |
| [/research-proposal](/docs/pipeline/research-proposal) | Objetivos + viabilidade + contingências + impacto + plano de dados + plano de pré-registro; matriz da chamada do financiador ou resposta de ressubmissão | Meio da cadeia |
| [/research-design](/docs/pipeline/research-design) | Desenho do estudo + pré-registro | Meio da cadeia |
| [/research-experiment](/docs/pipeline/research-experiment) | Executar + registrar, de forma reproduzível | Meio da cadeia |
| [/research-analysis](/docs/pipeline/research-analysis) | Resultados + estatística | Meio da cadeia |
| [/research-paper](/docs/pipeline/research-paper) | Rascunho de artigo de primeira linha | Meio da cadeia |
| [/research-review](/docs/pipeline/research-review) | Crítica no nível de uma revisão por pares | Meio da cadeia |
| [/research-publish](/docs/pipeline/research-publish) | Pacote para o veículo + submissão | Meio da cadeia |
| [/research-disseminate](/docs/pipeline/research-disseminate) | Disseminação + impacto + arquivamento FAIR | Terminal |

O orquestrador de fluxo de trabalho encapsulado [/research](/docs/pipeline/research) conduz esses estágios da
questão bruta até o artigo publicado (ele próprio não é um estágio),
verificando a saída de cada estágio de forma independente antes que o estágio
seguinte se apoie nela; `--quick` executa somente `/research-sources` +
`/research-synthesis`, para um relatório com citações em uma única passagem.

Os estágios empíricos (fontes, desenho, experimento, análise) e os estágios de
redação (artigo, revisão, publicação, disseminação) recorrem, além disso, a
superfícies que operacionalizam o rigor — comparação multimétodo justa,
procedência dos comparadores, uma estrutura de programa de experimentos, um
plano de utilização de computação, um ciclo autônomo de experimentos opcional
(opt-in), um portão de avanço baseado na definição de pronto, cegamento com
divulgação em etapas, um registro de busca, alocação de estudo e planejamento
de poder, disciplina de análise, contingências do plano, integridade de figuras
e planejamento de palestras e pôsteres — que acrescentam detalhe operacional
aos dez mandatos sem ampliá-los.

## Sequência de revisão de auditoria

O orquestrador de fluxo de trabalho encapsulado [/audit](/docs/pipeline/audit) varre todas as onze dimensões abaixo em uma única passagem paralela — o análogo, na fortaleza de auditoria, de `/plan` e `/research` — e sintetiza um único relatório de achados deduplicado e triado por severidade (somente relatório; a remediação é encaminhada para `/elevate`). Cada dimensão também pode ser invocada individualmente.

O orquestrador de fluxo de trabalho encapsulado [/fortress](/docs/pipeline/fortress) fecha o ciclo que o `/audit` relata: ele detecta por meio do `/audit`, verifica cada achado, corrige cada achado remanescente na superfície que o detém, audita novamente em um ciclo limitado e submete o resultado ao portão [/release-readiness](/docs/pipeline/release-readiness) — o análogo de blindagem para produção de `/plan` e `/research`.

| Comando | Área de qualidade |
|---------|--------------|
| [/code-review](/docs/pipeline/code-review) | Qualidade do código |
| [/code-audit](/docs/pipeline/code-audit) | Corpus de código |
| [/security-audit](/docs/pipeline/security-audit) | OWASP / ASVS |
| [/perf-audit](/docs/pipeline/perf-audit) | Desempenho |
| [/architecture-review](/docs/pipeline/architecture-review) | Arquitetura |
| [/ux-review](/docs/pipeline/ux-review) | Experiência do desenvolvedor |
| [/a11y-audit](/docs/pipeline/a11y-audit) | Acessibilidade |
| [/docs-review](/docs/pipeline/docs-review) | Documentação |
| [/dependency-audit](/docs/pipeline/dependency-audit) | Dependências |
| [/supply-chain-audit](/docs/pipeline/supply-chain-audit) | Cadeia de suprimentos |
| [/threat-model-audit](/docs/pipeline/threat-model-audit) | Modelo de ameaças |
