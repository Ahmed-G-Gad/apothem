**Papel:** Auditor de desempenho
**Posição no pipeline:** fortaleza

Audita frente a orçamentos de desempenho por classe (runtime de hooks, verify-ecosystem, conformity gate, testes, trabalhadores delegados, shell, lint), usando o método USE.

## Invocação canônica

```bash
/perf-audit
```

Com argumentos:

```bash
/perf-audit [path/to/repo/] [--focus CLASS] [--dry-run]
```

## Entradas

Repositório anfitrião que contém `hooks/`, `src/apothem/benchmarks/`, `tests/` e os stubs de bootstrap de hooks `hooks/lib/bootstrap.{sh,ps1}`

## Saídas

Achados de desempenho em `_inputs/perf-audit-findings.md`

## Downstream

A etapa de auditoria de desempenho da Sequência de Revisão de Auditoria

## Fases do fluxo de trabalho

O comando executa cinco fases de auditoria: ingestão de entrada, descoberta de orçamentos por classe, execução de benchmarks, identificação de caminhos críticos pelo método USE e emissão de achados com o portão de validação.

## Modos de falha

| Sintoma | Causa | Recuperação |
|---------|-------|----------|
| Portão de qualidade FAIL | A saída não atende aos padrões | Corrija a saída e execute novamente |
| Arquivo de entrada ausente | O repositório não tem `src/apothem/benchmarks/` | Adicione os drivers de benchmark e execute novamente; o comando se recusa a rodar até que existam |

## Exemplos

```bash
# Dry-run to preview what would happen
/perf-audit --dry-run

# Execute against a repository root
/perf-audit path/to/repo/
```
