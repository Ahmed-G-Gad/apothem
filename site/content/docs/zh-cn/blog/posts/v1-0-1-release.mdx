Apothem v1.0.1 是这款面向编码助手的与宿主无关配置管理器的发布版本：一份共享
配置档案、十七种编码助手、单一已签名版本，以及随版本本身附带的供应链
证据。

## 论点：一份配置档案，十七种编码助手

Apothem 读取 `~/.config/apothem/profile.yaml` 处的单一共享配置档案，并把它
物化为每种编码助手所期望的原生配置。你只需一次性编写自己的行为规则、技能、
钩子与约定。Apothem 会把它们渲染为十七个编码助手原生目标，并保持同步。

本版本中的十七个适配器：

- antigravity
- claude-code
- codebuddy
- codex
- cursor
- gemini-cli
- github-copilot
- glm
- hermes
- kimi-code
- kiro
- open-claw
- opencode
- qwen-code
- trae
- windsurf
- zed

向你的工作流添加一个工具，运行一条命令，你的配置即刻就位。移除一个工具时，Apothem 会删除它所写入的文件；共享的记忆、上下文与学习存储会在最后一个工具被移除时、备份之后一并移除，而 `plans/` 始终保留。

## 安装

多条安装路径，底层共用同一个 CLI：

1. **Claude Code 插件** —— 在 Claude Code 内部：

   ```text
   /plugin marketplace add ahmed-g-gad/apothem
   /plugin install apothem@apothem
   ```

2. **npx** —— 直接从 npm 包 `@ahmed-g-gad/apothem` 运行 CLI，无需安装步骤：

   ```bash
   npx @ahmed-g-gad/apothem profile init
   npx @ahmed-g-gad/apothem install --harness all --project .
   ```

3. **一次性脚本安装器** —— 放置一个自包含运行时与一个 `apothem` 启动器（在 POSIX 上为 `~/.local/bin/apothem`，当该目录不在 `PATH` 上时附带 PATH 提示；在 Windows 上为 WindowsApps 中的 `apothem.cmd`）：

   ```bash
   curl -fsSL https://apothem.ahmedgad.com/install.sh | sh    # POSIX
   ```

   POSIX 脚本默认校验发布标签的 GPG 签名，当维护者密钥不在本地密钥环中时中止。在维护者发布密钥指纹之前（参见 `SECURITY.md`），可设置 `APOTHEM_VERIFY=checksum` 以依据发布的 `SHA256SUMS` 校验归档文件，或设置 `APOTHEM_ALLOW_UNVERIFIED=1` 以在不校验标签的情况下继续。

   ```powershell
   irm https://apothem.ahmedgad.com/install.ps1 | iex         # Windows
   ```

4. **工具原生插件与扩展** —— 一个 Gemini CLI 扩展
   （`gemini extensions install https://github.com/ahmed-g-gad/apothem`）、一个
   Qwen Code 扩展（`qwen extensions install ahmed-g-gad/apothem`），以及一个
   Codex 插件（`codex plugin marketplace add ahmed-g-gad/apothem`）。覆盖
   VS Code 与 GitHub Copilot 的 VS Code 系扩展，其源代码位于仓库的
   `vscode-extension/` 目录中。该扩展未在 Visual Studio Marketplace 上架，
   本次发布也未附带打包好的 `.vsix`。

## 箱内之物

`apothem` CLI 暴露出你在完整配置生命周期中所需的操作者命令：

- `apothem install` —— 把配置档案物化到一种编码助手或全部编码助手。
- `apothem uninstall` —— 移除某种编码助手的已物化配置，而不触动共享配置
  文件。
- `apothem update` —— 在你编辑配置档案后重新物化。
- `apothem verify` —— 检测配置档案与某种编码助手磁盘配置之间的漂移。
- `apothem harnesses` —— 列出每个已注册的适配器。
- `apothem profile` —— 检视并管理共享配置档案。
- `apothem doctor` —— 诊断环境与配置问题。

每个工具适配器都实现统一的 `HarnessAdapter` 协议——`install`、`update`、`uninstall`、`is_installed`、`verify`——因此，无论底层厂商格式如何，从操作者的视角看，每个工具的行为都可预测。关于这一设计的更多内容，请阅读[适配器架构深度解析](/docs/blog/posts/multi-harness-adapter-design)，关于格式调和的更多内容，请阅读[跨工具约定收敛](/docs/blog/posts/cross-harness-convention-convergence)。
