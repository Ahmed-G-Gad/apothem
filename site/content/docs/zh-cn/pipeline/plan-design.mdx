**角色：** 架构师
**流水线位置：** 条件性的审查后、执行前

当计划套件包含承载架构的工作时，在 `_inputs/design.md` 处生成架构设计制品。
它特意是条件性的：散文、文档、元数据或狭窄夹具类套件会从 `/plan-review`
直接进入 `/plan-execute`；而变更组件、界面、模式、数据流、适配器、发布拓扑、
安全边界或运行时行为的套件，则先经过 `/plan-design`。

## 规范调用

```bash
/plan-design path/to/plan-suite/
```

带参数：

```bash
/plan-design [path/to/plan-suite/] [--refine-existing] [--dry-run]
```

## 输入

已审查的计划套件 + `_spec/spec.md` + `_inputs/handoff-manifest.yml` + 来自
`/plan-review` 的 PASS 审查记分卡。

## 输出

`_inputs/design.md`，外加一份增强的 `_inputs/handoff-manifest.yml`，其中携带
设计制品路径、设计门结果、七轴覆盖结果以及双向绑定矩阵摘要。

## 适用性门

当至少有一个下游阶段声明或暗示以下情形时，运行 `/plan-design`：

- 源布局、包边界、适配器边界或模块边界的变更。
- 公共界面、协议、模式、配置契约或 CLI 行为。
- 跨组件数据流、生命周期排序、状态转换或依赖边。
- 安全、性能、并发、可观测性、部署、发布或供应链架构。
- 后续的 `/architecture-review` 必须将实现追溯回某个设计制品。

当套件仅限于文案编辑、生成的清单刷新、狭窄夹具更新、一次性文档修复，或其他
无需架构追溯面即可验证实现的工作时，跳过 `/plan-design`。跳过路径是显式的：
`/plan-review` 记录该非架构分类，然后 `/plan-execute` 从已审查的计划套件继续。

## 下游

`/plan-execute` 在承载架构的阶段消费该设计制品。`/architecture-review`
在审计审查序列期间消费同一制品。若承载架构的工作缺失 `_inputs/design.md`，
架构审查会停止并将套件重新路由回 `/plan-design`。

## 工作流阶段

该命令遵循六个架构专属的转换阶段：

1. **输入摄取** — 读取已审查的套件、记分卡、阶段输出与交接清单；在 SHARED+
   级别上遇到缺失或失败的审查证据时阻断。
2. **架构分解** — 走查架构、并发、性能、安全、测试、工具链与可观测性；识别
   组件、边以及悬而未决的架构问题。
3. **组件界面设计** — 定义公共界面、协议契约、模式、不变式、失败模式与
   依赖反转边界。
4. **跨组件绑定批准** — 闭合每条上游、下游、同级、准则与锚定边；当组件图
   越过矩阵阈值时，发出一份双向绑定矩阵。
5. **设计制品发出** — 编写 `_inputs/design.md`，包含组件章节、图表、决策记录、
   验证结果与绑定。
6. **设计验证门** — 运行十五栏预发出门；仅在设计通过后才更新
   `_inputs/handoff-manifest.yml`。

## 设计制品形态

所发出的 `_inputs/design.md` 包含：

- 含组件计数与七轴覆盖的执行摘要。
- 每个主要组件一节，从内层领域面到外层适配器与操作者面依次排列。
- 在结构本来会含糊不清之处提供 Mermaid 架构、序列、状态或依赖图。
- 含备选方案、权衡与可逆性说明的已定架构决策记录。
- 适用时的验证门结果与双向绑定矩阵。
- 该制品自身指向上游与下游规划面的五向绑定。

## 失败模式

| 症状 | 原因 | 恢复 |
|---------|-------|----------|
| 前置条件未完成 | 所依赖的阶段尚未完成 | 先完成上游阶段 |
| 质量门 FAIL | 输出不达标 | 修复输出并重新运行 |
| 缺失已审查套件 | 计划套件或审查记分卡缺失 | 运行 `/plan-generate`，再运行 `/plan-review` |
| 非架构套件 | 没有阶段需要架构追溯面 | 记录跳过并继续到 `/plan-execute` |
| 架构审查阻断 | 承载架构的实现缺失 `_inputs/design.md` | 运行 `/plan-design`，再重新运行 `/architecture-review` |

## 示例

```bash
# 干运行，预览适用性、组件计数与悬而未决的问题
/plan-design --dry-run

# 为某个命名的承载架构套件发出设计
/plan-design path/to/plan-suite/
```
