**角色：** 生成器
**流水线位置：** 中段

从已编写的 `_spec/spec.md` 生成完整的主计划套件。

## 规范调用

```bash
/plan-generate
```

带参数：

```bash
/plan-generate [path/to/prose.md] [--mode NEW|OVERHAUL] [--seriousness LEVEL] [--context CONTEXT] [--mission MISSION] [--domain DOMAIN] [--dry-run]
```

## 输入

来自 `/plan-spec` 的已编写 `_spec/spec.md` + `_inputs/handoff-manifest.yml`（或操作者提供的散文）。

## 输出

`PREAMBLE.md`、`MASTER-PLAN.md`、`PROGRESS.md`、`PLAN-NOTES.md` 以及逐阶段的 `phases/**/PHASE.md` 文件，外加增补后的 `_inputs/handoff-manifest.yml`。

## 下游

/plan-review 或 /plan-execute（下游）

## 工作流阶段

该命令从已编写的规格生成一套完整的主计划套件：

1. **摄入需求** — 读取 `_spec/spec.md` 和上游交接清单；当规格缺失时以 `Blocked: run /plan-spec first` 拒绝。
2. **发现** — 以五道认知滤镜运行按严肃度分级的发现；通过结构化询问通道解决每一处权威数据缺口。
3. **分解** — 将工作拆解为一张无环的阶段图，并给出明确的依赖顺序。
4. **发出套件** — 编写 `PREAMBLE.md`、`MASTER-PLAN.md`、`PROGRESS.md`、`PLAN-NOTES.md` 以及每个 `phases/NN-topic/PHASE.md`。
5. **运行预发出门** — 针对每一件发出的工件运行十五条巡查；失败则阻断操作者批准，直至解决。

## 失败模式

| 症状 | 原因 | 恢复 |
|---------|-------|----------|
| Blocked: run /plan-spec first | 没有已编写的 `_spec/spec.md` | 运行 `/plan-spec` 以编写规格并发出交接清单 |
| 针对 `_inputs/` 文件生成 | 规格仍在征询过程中 | 先通过 `/plan-spec` 将 `_inputs/forge.md` 晋级为 `_spec/spec.md` |
| 预发出门失败 | 某件发出的工件未通过门 | 在操作者批准之前修复未通过的门 |

## 示例

```bash
# 试运行以预览生成的阶段图
/plan-generate --dry-run

# 从已编写的散文生成套件
/plan-generate path/to/prose.md --mode NEW
```
