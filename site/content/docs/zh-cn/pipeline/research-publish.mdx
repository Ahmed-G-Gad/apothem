**角色：** 首席研究者（发表）
**流水线位置：** 链路中段

将论文格式化为期刊模板并组装投稿包——补充材料、数据／代码可用性声明、投稿信、伦理与利益冲突声明——外加带 DOI 的预印本／归档计划和一份投稿清单。由操作者投递投稿包；终端后继是 `/research-disseminate`，它将已发表的工作传递给其受众。

## 规范调用

```bash
/research-publish
```

带参数：

```bash
/research-publish [--suite-name NAME]
```

## 输入

论文交付物和 `_outputs/review-report.md`（同行评审修订及其未判断清单）。

## 输出

宿主自然位置的期刊格式化投稿包（格式化的稿件＋补充材料＋数据／代码可用性声明＋投稿信＋伦理／利益冲突声明）＋ `_outputs/publication-record.md`（包括注明日期的发表场所规则登记册：每条规则连同其官方来源页面、阅读日期和投稿阶段）＋一份投稿清单。

## 下游

/research-disseminate（下游消费者）——由操作者执行投稿，随后 `/research-disseminate` 将已发表的工作传递给其受众。当期刊返回修订意见时，先对修订后的论文重新运行 `/research-review`，再重建投稿包。

## 工作流阶段

该命令遵循标准的 `/research` 流水线工作流：

1. **加载上下文**——读取论文与评审报告；固定发表场所、周期、投稿轨道和文章类型，并记录每条发表场所规则及其官方来源页面、阅读日期和投稿阶段。
2. **验证序列闸门**——确认 `_outputs/review-report.md` 存在，且其 HIGH 级修订已解决（或操作者已明确接受剩余风险）；否则以 `Blocked: run /research-review first` 停止。
3. **格式化与打包**——沿用每条发表场所规则及其来源页面、阅读日期和投稿阶段，在发表场所未经改动的模板上构建，按发表场所的方式统计页数和字数，并检查编译后的 PDF；然后组装补充材料、数据与代码可用性说明、投稿信、伦理与利益冲突声明。
4. **规划预印本／归档**——记录预印本与 DOI 计划；构建投稿清单。
5. **更新交接清单**——记录投稿包与发表记录。
6. **发出投稿包**——按目标刊物格式整理的投稿包，以及 `_outputs/publication-record.md`。

## 严谨性强制底线

格式化尊重分阶段披露：对于双盲发表场所，作者、机构和系统身份被剥离至单独提交的元数据，仅在指定的清样阶段才恢复。归档存放携带随发表场所伸缩的可复现性证据包（数据、代码、固定的环境、随机种子、硬件日志、逐实例结果和图表）。对于双盲发表场所，补充材料归档以及每个链接的存储库或数据集都会接受身份检查，而不仅仅是稿件。

发表场所规则须有来源且分阶段。只有目标自身的官方页面才算数：相邻的发表场所、更早的周期或同级投稿轨道绝不能充当替代，且为修订或清样而进行的重建执行的是该阶段的限制，而非初次投稿的限制。没有官方页面支撑的规则会询问操作者，并标记为未经发表场所核实。发表场所的模板文件保持原样发布，因此本地编写的起始文件会如实报告。页数和字数按发表场所的方式统计，并记录被排除的部分；每张图和表都按发表场所接收的尺寸和格式进行检查。

## 失败模式

| 症状 | 原因 | 恢复 |
|---------|-------|----------|
| Blocked: run /research-review first | 没有评审报告，或存在未解决的 HIGH 级修订 | 运行 `/research-review` 以生成 `_outputs/review-report.md`，或解决未决的 HIGH 级修订并重新运行 `/research-review`，或明确接受剩余风险 |
| 未处理的 HIGH 级修订 | 跳过了评审发现 | 处理该修订并重新运行 `/research-review` |
| 缺少数据／代码可用性 | 缺失可复现性界面 | 在投稿前补充数据／代码可用性声明 |
| 发表场所规则没有来源 | 该规则来自另一周期、投稿轨道或相邻的发表场所，或来自记忆 | 固定目标；为该规则记录官方页面、阅读日期和阶段，或询问操作者并将其标记为未经核实 |
| 模板被改动 | 本地编辑改变了发表场所的页面几何或排版设置 | 恢复发表场所的文件，且只通过模板文档中说明的选项更改版式 |

## 示例

```bash
# 组装期刊投稿包
/research-publish --suite-name <name>
```
