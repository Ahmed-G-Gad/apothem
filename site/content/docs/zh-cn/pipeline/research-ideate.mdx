**角色:** 首席研究员（问题构建）
**流水线位置:** 首阶段

从零开始构建问题空间——机会与缺口扫查、已被推翻的先验假设扫查，以及带排序的候选研究问题生成——`/research` 流水线的入口阶段。每个候选都依据一个先验理论锚点进行框定，扎根于既有研究，并以可证伪的形式陈述，可供 `/research-spec` 使用。

## 标准调用方式

```bash
/research-ideate
```

带参数:

```bash
/research-ideate [path/to/domain-notes] [--suite-name NAME] [--override] [--domain NAME]
```

## 输入

一个领域种子——自由格式的领域笔记（由操作者内联提供或以路径形式提供），或在从头开始时仅提供一个 `--domain` 名称。

## 输出

`_inputs/ideation.md`（已框定的问题空间、机会与缺口扫查、已被推翻的先验假设扫查，以及排序后的候选问题清单）以及研究套件文件夹中的交接清单。

## 下游

/research-spec（下游消费者——将所选候选框定为一份可证伪的规格）。

## 工作流阶段

该命令遵循标准的 `/research` 流水线工作流:

1. **加载上下文**——读取领域种子、规则以及任何既有的套件状态。
2. **扫查机会与缺口空间**——梳理该领域中已被研究的、有争议的，以及尚未解决的内容。
3. **扫查已被推翻的先验**——浮现出已被既有研究驳倒的假设，使清单不再重走已成定论的旧路。
4. **生成并排序候选**——产出候选研究问题，每个都以可证伪的形式陈述，按可处理性与影响力排序。
5. **验证输出**——确认每个候选都扎根于原始的既有研究且可被反驳；通过结构化询问通道解决每一处歧义。
6. **发出构想清单**——`_inputs/ideation.md` 以及交接清单。

## 失败模式

| 症状 | 原因 | 恢复方式 |
|---------|-------|----------|
| 没有可证伪的候选 | 领域种子过于宽泛或纯描述性 | 通过结构化询问收窄领域；将候选重新框定为可反驳的问题 |
| 候选重述了一个已被推翻的先验 | 跳过了既有研究扫查 | 运行已被推翻的先验扫查；丢弃或重新框定重叠的候选 |
| 缺少领域种子 | 未提供笔记或 `--domain` | 内联或以路径形式提供领域笔记，或传入 `--domain NAME` |

## 示例

```bash
# 扫查一个领域并生成排序后的候选问题
/research-ideate ~/notes/retrieval-systems.md --suite-name retrieval-latency

# 从一个裸的领域名称开始
/research-ideate --domain "vector-index recall under drift"
```
