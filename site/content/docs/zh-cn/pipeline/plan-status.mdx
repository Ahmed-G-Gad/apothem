**角色：** 报告器
**流水线位置：** 只读

只读的计划套件进度报告器——发出状态而不修改任何文件。

## 规范调用

```bash
/plan-status
```

带参数：

```bash
/plan-status [path/to/plan-suite/] [--verbose]
```

## 输入

任何生命周期状态下的任意计划套件——读取 `PROGRESS.md`、`PLAN-NOTES.md`、`MASTER-PLAN.md` 以及 `phases/` 报告。

## 输出

写入操作者输出流的战略状态报告。该命令为只读——它不创建也不修改任何文件。

## 下游

独立用于进度检查——与规范序列正交，可在任意时点以只读方式调用。

## 工作流阶段

该命令为只读——它读取套件的跟踪文件并报告；不写入任何内容：

1. **加载上下文** — 读取 `PROGRESS.md`、`PLAN-NOTES.md`、`MASTER-PLAN.md`，并扫描 `phases/` 中的现有报告。
2. **评估状态** — 巡览任务／阶段／工件维度并读取恢复契约。
3. **发出状态报告** — 将完成状态、阶段跟踪器和战略分析直接呈现给操作者。
4. **抽查** — 带 `--verbose` 时，评定套件健康度，并针对现有文件引用抽查证据（markdown 链接、行范围、提交 SHA），不修改任何文件。

## 失败模式

| 症状 | 原因 | 恢复 |
|---------|-------|----------|
| 缺失必需的跟踪文件 | 计划套件不完整 | 将缺口作为发现暴露；运行 `/plan-generate` 以创建套件 |
| 跟踪文件格式错误 | 章节被截断或无法解析 | 在报告中指出缺失／矛盾；修复交由具写入能力的命令处理 |
| 字段缺失或跨文件矛盾 | 跟踪漂移 | 明确报告该矛盾；不要臆造缺失值 |

## 示例

```bash
# 报告最近的计划套件
/plan-status

# 针对指定计划套件的详细健康度评定
/plan-status path/to/plan-suite/ --verbose
```
