**角色：** 首席研究员（传播与影响）
**流水线位置：** 终结

推动接收后的传播与影响。公开操作由操作者执行；本阶段止步于一份就绪的传播计划，绝不自动发布。

## 标准调用

```bash
/research-disseminate
```

带参数：

```bash
/research-disseminate [--suite-name NAME] [--override] [--archive REPO] [--preprint SERVER]
```

## 输入

套件的 `_outputs/publication-record.md`（由 `/research-publish` 生成的投稿包 + 投稿记录）。

## 输出

`_outputs/dissemination-plan.md`（预印本公告、公共制品计划（含每场演讲的需求信息、时间预算以及问题与备用清单，每张海报的版块布局，一份图表溯源表，以及编译后制品的结果）、FAIR 归档存放记录、altmetrics 与影响追踪计划、答辩 / 修订循环，以及注册报告第二阶段路径）。

## 下游

终结——传播计划是流水线的最终工件。审稿人答辩／修订循环会将修订后的论文经由 `/research-review` 送回以重新核验严谨性，然后重新调用 `/research-publish` 以重建交付包。

## 工作流阶段

该命令遵循标准的 `/research` 流水线工作流：

1. **加载上下文** —— 读取 `_outputs/publication-record.md`、规则以及任何现有的套件状态。
2. **规划预印本与公共制品** —— 起草预印本公告，并按需求信息、时间预算、问题与备用清单以及图表溯源规划每场演讲和每张海报，并对所构建的任何内容进行编译后 PDF 检查。
3. **记录 FAIR 归档存放** —— 规划将数据 + 代码存放至带持久标识符的 FAIR 仓库。
4. **设置影响追踪** —— 针对提案的影响路径规划 altmetrics 与影响追踪。
5. **准备答辩循环** —— 在起草之前，从出版记录的发表场所规则登记册中读取该发表场所对回复阶段的约束，然后起草审稿人答辩，并在适用时规划注册报告第二阶段路径。
6. **验证并发出** —— 确认计划可执行；发出 `_outputs/dissemination-plan.md` 以及交接清单。公开操作由操作者执行。

## 严谨性强制底线

公共制品携带自然的领域语言；当传播先于去匿名化时，作者、机构和系统身份留待指定阶段处理。FAIR 存放是那份持久、可引用、随发表场所抱负伸缩的可复现性证据包，使独立方能够复现本研究。

演讲和海报依据其需求信息进行规划：时段长度、演讲类型、受众，以及提问是否占用同一时段，均需询问，绝不假定。各部分之和等于演讲时间，而演讲时间加上时段内的提问、过渡和预留时间之和等于整个时段。数据图是论文自身的文件，或依据所记录的数据重新生成，绝不手工或用生成式工具重新绘制。违反所述发表场所约束（长度上限、回复文件的匿名性、链接政策、是否接纳新结果）的回复不会被视为就绪。

## 失败模式

| 症状 | 原因 | 恢复 |
|---------|-------|----------|
| 没有 FAIR 存放记录 | 跳过了归档步骤 | 选择一个 FAIR 仓库（`--archive`）并记录带持久标识符的存放计划 |
| 计划尝试自动发布 | 越过了阶段边界 | 止步于就绪计划；每一项公开操作均由操作者执行 |
| 缺少出版记录 | 尚未运行 `/research-publish` | 先运行 `/research-publish` 以生成投稿包 |
| 演讲或海报上的数据图被重新绘制 | 该图被重新绘制而非复用 | 使用论文的文件，或依据所记录的数据重新生成 |
| 演讲时间预算加总不符 | 时段、演讲时间、提问或预留时间未被规划 | 询问需求信息，然后确定各部分的长度，使预算加总等于时段 |

## 示例

```bash
# 接收后规划传播
/research-disseminate --suite-name retrieval-latency

# 固定预印本服务器与 FAIR 归档
/research-disseminate --preprint arXiv --archive Zenodo
```
