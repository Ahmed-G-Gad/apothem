**角色：** 性能审计者
**流水线位置：** 堡垒

依据每类性能预算进行审计（钩子运行时、verify-ecosystem、合规闸门、测试、委派工作者、shell、lint），采用 USE 方法。

## 规范调用

```bash
/perf-audit
```

带参数：

```bash
/perf-audit [path/to/repo/] [--focus CLASS] [--dry-run]
```

## 输入

包含 `hooks/`、`src/apothem/benchmarks/`、`tests/` 以及钩子引导桩 `hooks/lib/bootstrap.{sh,ps1}` 的宿主仓库

## 输出

性能发现项位于 `_inputs/perf-audit-findings.md`

## 下游

审计审查序列中的性能审计阶段

## 工作流阶段

该命令分为五个审计阶段：输入摄取、按类预算发现、基准执行、借助 USE 方法识别热路径，以及附带校验门的发现项输出。

## 失败模式

| 症状 | 原因 | 恢复 |
|---------|-------|----------|
| 质量门 FAIL | 输出未达到标准 | 修复输出并重新运行 |
| 缺失输入文件 | 仓库缺少 `src/apothem/benchmarks/` | 添加基准驱动程序后重新运行；在驱动程序存在之前，该命令将拒绝运行 |

## 示例

```bash
# Dry-run to preview what would happen
/perf-audit --dry-run

# Execute against a repository root
/perf-audit path/to/repo/
```
