从当前的共享配置档案重新安装一个工具适配器配置。

## 概要

```
apothem update --harness NAME|all [--profile PATH] [--dry-run]
                [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

`update` 会从当前的共享配置档案重新物化工具输出。它使用与 `install` 相同的配置档案校验、`--harness all` 选择、项目作用域检查、试运行行为以及 JSON 信封。

连续式别名 `apothem updating` 解析到同一个处理程序。

## 选项

| 选项 | 描述 |
|---|---|
| `--harness NAME` | 要更新的工具适配器，或用 `all` 表示覆盖整个注册表的集合（必填）。 |
| `--profile PATH` | 共享配置档案 YAML 的路径。默认为 `~/.config/apothem/profile.yaml`。 |
| `--dry-run` | 预览更新而不写入文件。 |
| `--project PATH` | 项目作用域工具的项目根目录。当所选的工具集合包含项目作用域适配器时必填。 |
| `--quiet`, `-q` | 抑制信息性输出；只输出错误。 |
| `--verbose`, `-v` | 输出额外的诊断信息。 |
| `--format plain\|json` | 输出格式（默认：`plain`）。 |
| `--json` | `--format json` 的简写。 |
| `--no-color` | 在输出中禁用 ANSI 颜色码。 |
| `-h`, `--help` | 显示帮助并退出。 |

## JSON 输出

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "update",
  "action": "updated",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

`--dry-run` 返回 `status: "dry_run"` 和 `files_written: []`。

## 示例

```bash
apothem update --harness claude-code
apothem update --harness claude-code --dry-run
apothem update --harness all --project . --dry-run --json
apothem Updating --harness claude-code   # continuous-form alias
apothem updating --harness claude-code   # lowercase variant
```

## 退出码

| 代码 | 含义 |
|---|---|
| 0 | 适配器更新成功，或试运行已顺利完成规划 |
| 1 | 预期内的校验、配置档案、工具、项目或适配器错误 |
| 2 | 在至少一次写入之后发生的部分批量物化 |
| 64 | 用法错误：未知的选项或命令，或缺失或无效的选项值。在 `--json` 下，该错误是一个代码为 `cli.usage` 的 JSON 信封。 |
