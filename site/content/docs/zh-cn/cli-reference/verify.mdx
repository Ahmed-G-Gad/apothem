验证一个工具适配器的安装。

## 概要

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

调用每个所选适配器的 `verify()` 实现。只有当所有所选适配器都报告其受管目标存在且有效时，才以 0 退出。未提供 `--profile` 时，该检查是**结构性**的——每个受管目标都必须存在且有效。提供 `--profile` 时，该检查还额外要求**配置档案保真度**，因此一个存在但已漂移的安装无法通过验证；它回答的是“被忠实安装的是否正是这份配置档案？”，而不只是“它是否存在？”。

对于将技能写入你主目录的适配器，验证还会检查它所期望的每个技能文件夹都存在且带有一个 `SKILL.md`，无论是哪次安装写入的，因此在一台只安装了共享某个文件夹的工具之一的机器上也能通过验证。当某个文件夹缺失时，以及当一个与某个 Apothem 技能同名的文件夹属于并非由 Apothem 写入的内容时，验证会失败。失败的行会说明是哪种情况：在纯文本模式下，其后会跟一条 `Note:` 行；在 JSON 行中，一个 `user_level` 对象会列出 `missing` 和 `unlisted` 路径以及一个 `message`。运行 [`install`](/docs/cli-reference/install) 以恢复缺失的文件夹；将外来的文件夹重命名或移走，然后运行 [`update`](/docs/cli-reference/update)。

`--harness all` 扫查会遵循配置档案的 `exclude_harnesses`——即 `install`/`update` 批处理所应用的相同排除项——因此验证绝不会将一个被有意排除的工具报告为缺失。提供 `--profile` 时，排除项来自它，否则来自默认配置档案；默认配置档案不可读或不存在时，会降级为完整的注册表。

## 选项

| 选项 | 描述 |
|---|---|
| `--harness NAME` | 要验证的工具适配器，或用 `all` 表示覆盖整个注册表的集合（必填）。 |
| `--profile PATH` | 用于核对保真度的共享配置档案 YAML。不提供它时，该检查纯粹是结构性的。 |
| `--project PATH` | 项目作用域工具的项目根目录。 |
| `--quiet`, `-q` | 抑制信息性输出；只输出错误。 |
| `--verbose`, `-v` | 输出额外的诊断信息。 |
| `--format plain\|json` | 输出格式（默认：`plain`）。 |
| `--json` | `--format json` 的简写。 |
| `--no-color` | 在输出中禁用 ANSI 颜色码。 |
| `-h`, `--help` | 显示帮助并退出。 |

## JSON 输出

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

当任何所选工具缺失或无效时，`status` 为 `error`，失败的结果行带有 `verified: false`，并且进程以代码 1 退出。

## 示例

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## 退出码

| 代码 | 含义 |
|---|---|
| 0 | 工具已通过验证——所有受管目标都存在且有效 |
| 1 | 工具未通过验证——受管目标缺失或无效 |
| 64 | 用法错误：未知的选项或命令，或缺失或无效的选项值。在 `--json` 下，该错误是一个代码为 `cli.usage` 的 JSON 信封。 |
