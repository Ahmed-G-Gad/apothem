将一个工具恢复到其已记录的安装之前的状态。

## 概要

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` 会将每个所选工具恢复到已记录的那次安装过程之前所处的状态——默认是仍然生效的最新一次安装，或由 `--install-id` 指定的那一次。因此，第二次 `rollback` 会撤销第一次所撤销的那次安装之前的安装。如果 `--install-id` 指定的安装已被某次回滚或卸载撤销，则会以 `rollback.already_reversed`（退出码 1）拒绝，且不做任何更改。它按照该次安装的台账记录，从最新的更改开始依次处理：

- 从该次安装所捕获的备份中，在记录的路径上恢复该次安装覆盖的每个文件和目录（被该次安装替换的目录会被精确恢复，不包含该次安装向其中添加的文件）；
- 移除该次安装创建的每个文件和目录，前提是它仍保留该次安装写入的内容：你此后在该路径创建的文件或你编辑过的文件会保留，并附带一行 `Warning:`（在 `--json` 下为一个 `warnings` 条目），容纳它的文件夹也同样保留。该次安装所创建文件夹内的空文件夹会被移除，包括你自己创建的。该行列出它保留的每个文件（包括被保留文件夹内的文件），无论是否有恢复失败；`warnings` 条目则将它们列为 `files`。由较早版本记录的安装不会说明它写入了什么，而回滚不会与当前版本进行任何比较，因此它创建的内容会保留：每个这样的路径都会得到一行 `Warning:`，说明回滚无法判断它是否属于 Apothem。它还会放回该次安装清除掉的任何旧有布局路径。当前版本不再清除的路径（一个可能存放你自己文件的文件夹）只会在缺少文件的位置恢复：那里现有的每个文件都会保留，输出会指明所用的备份。无法写入的文件会被列出，供你手动复制；如果回滚写入了其他任何文件，它随后会以退出码 2（部分结果）结束。
  对于现在是链接（符号链接或 Windows 联接点）的路径，或者备份中是文件夹而现在是文件（或反之）的路径，回滚绝不会穿过它写入。那里不会恢复任何内容；当该路径的备份已不存在时，也不会恢复任何内容。回滚仍以退出码 0 结束，并打印一行 `Warning:`（在 `--json` 下为一个 `warnings` 条目），指明可供手动复制的备份。只有当该次安装的记录仍在保留的最新 10 条之中（见下文）时，回滚才能处理它。`apothem backups prune --keep N` 会一次性修剪到 `N` 条；下一次安装、更新、卸载或回滚会再次修剪到 10 条。即使记录已被移除，备份集本身仍会保留，因此手动从中复制文件是可靠的恢复途径；
- 移除该次安装创建的共享数据存储（`memory`、`contexts`、`learning`），除非另一个已安装的工具仍在使用它们；
- 在该次安装创建的目录变空之后将其移除。

你主目录中一个其他安装也在使用的文件或文件夹（技能文件夹，或 `~/.config/apothem/`）会像共享数据存储一样处理：只要另一个安装仍列出它，回滚就会保留它，并且只会为使用它的最后一个安装恢复或移除它。对于该次安装发现已经存在的文件夹（在第一个工具之后安装的第二个工具），如果它是由一个此后已放弃它的安装所创建的，它就会随使用它的最后一个安装一并移除，因此回滚每个工具后不会留下任何东西，即使创建该文件夹的工具在此期间又被重新安装或更新过。被 Apothem 移除、又由你自己放回（例如从备份中）的文件夹属于你：回滚会保留它。回滚只会撤销以回滚运行时你主目录的拼写方式所记录的安装。当同一工具还以另一种主目录拼写方式安装过（通过指向它的链接，或在 Windows 或 macOS 上使用另一种大小写）时，那次安装仍在使用共享文件夹并会保留它们。工具自身文件夹中的文件会逐个处理：回滚最先写入它们的那次安装时，会移除另一次安装原样保留的文件（例如其钩子脚本），并保留另一次安装重写过的文件（例如其指令文件）且给出警告。之后以另一种主目录拼写方式运行 `apothem update`，使那次安装再次通过 `apothem verify`。以那种主目录拼写方式运行的回滚也会撤销那次安装。当一个可能使用该文件夹的安装的记录无法读取时，回滚会在更改任何内容之前以错误停止，并且不写入 `rollback` 记录；修复该记录后再次运行。

当某个链接将工具的文件夹引出你的主目录时，回滚同样会在更改任何内容之前停止，并且不写入 `rollback` 记录：例如 `CODEX_HOME` 或 `XDG_CONFIG_HOME` 拼写为主目录内的路径，如 `~/work/tool`，而 `~/work` 在安装之后变成了指向另一个驱动器的链接。在 Windows 上，联接点也算作链接。错误内容为 `rollback
refused: target path crosses a link`，并指明该链接及其指向的文件夹，命令会以退出码 1 结束，且不会先请求确认。让该链接指向主目录内的文件夹，或用文件夹本身替换它，然后再次运行回滚。你拼写为主目录之外路径的文件夹会被跟随。

回滚操作移除或替换的所有内容，都会先复制到 Apothem 备份根目录（`~/.apothem/backups/`）中，因此回滚本身也可以手动撤销。随后，回滚会向工具台账追加一条 `rollback` 记录。回滚较早的安装时，只会恢复或移除该较早安装所记录的目标，并会将同一根目录下此后的每次安装从台账的活动安装中剔除。之后的安装在这些目标之外添加的文件会保留在原位。

台账为每个安装根目录保留最新的 10 条安装记录（以及它们所引用的备份）；更早的安装将无法再按 id 回滚，并会报告 `rollback.no_record`。[`apothem backups prune`](/docs/cli-reference/backups) 可按需降低这一上限，并且绝不会移除最近一次安装恢复时所依据的备份。

来自较早版本、未标明该次安装创建了哪些文件的安装记录，回滚时只会恢复被覆盖的文件。

除非提供了 `--yes`，否则会按工具逐一提示确认。当无法进行提示时——`--format json`（提示文本会破坏单一的 JSON 文档）或非交互式 shell（无 TTY）——除非提供了 `--yes`，否则该命令会预先以一个结构化的 `rollback.confirmation_required` 错误（退出码 1）拒绝执行。`--install-id` 和 `--last` 用于选择安装过程，二者互斥。

`--harness all` 回滚是有意做到穷尽的：它覆盖每一个已注册的工具，包括配置档案的 `exclude_harnesses` 在安装时跳过的工具——恢复安装前的状态是一项清理操作，因此它会触及先前范围更广的安装可能留下的记录。没有已记录安装的工具，会在 `results` 中以一行 `"outcome": "error"` 的形式失败（参见 JSON 输出），运行会继续处理其余工具。该命令随后在没有任何目标被回滚时以退出码 1 结束，在至少一个目标被回滚且同时记录了失败时以退出码 2（部分结果）结束。

## 选项

| 选项 | 描述 |
|---|---|
| `--harness NAME` | 要回滚的工具适配器，或用 `all` 表示注册表范围的集合（必需）。 |
| `--install-id ULID` | 回滚指定的安装过程（如果它仍然生效）。默认为仍然生效的最新一次安装。 |
| `--last` | 回滚仍然生效的最新一次安装（即默认行为的显式形式）。与 `--install-id` 互斥。 |
| `--yes` | 跳过按工具逐一的确认提示。 |
| `--project PATH` | 项目范围工具的项目根目录。当所选集合包含项目范围适配器时必需。 |
| `--quiet`, `-q` | 抑制信息性输出；只输出错误。 |
| `--verbose`, `-v` | 输出额外的诊断信息。 |
| `--format plain\|json` | 输出格式（默认：`plain`）。 |
| `--json` | `--format json` 的简写。 |
| `--no-color` | 在输出中禁用 ANSI 颜色代码。 |
| `-h`, `--help` | 显示帮助并退出。 |

## JSON 输出

该示例展示的是单个指定工具的外层结构。在 `--harness all` 下，`harness` 为 `all`，`output_path` 为 `null`，而 `results` 承载所有被选中工具的行。

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

每个被恢复或移除的目标都会出现在 `results` 中，带有 `"operation": "rollback"`，且 `outcome` 为 `created` 或 `updated`（同时出现在 `files_written` 中）；`message` 说明该路径是被恢复还是被移除。恢复失败（例如备份已被删除）为 `"outcome": "error"`。未记录任何更改的安装以 `"outcome": "skipped"` 报告。未恢复任何内容的被清除路径（它现在是链接、备份中是文件夹而现在是文件或反之，或者其备份已不存在）在 `results` 中是一行 `skipped`，同时也是 `warnings` 中的一个条目，回滚仍以退出码 0 结束：

```json
{
  "harness": "claude-code",
  "outcome": "advisory",
  "operation": "rollback",
  "path": "C:\\Users\\Example\\.claude\\commands",
  "message": "left in place: C:\\Users\\Example\\.claude\\commands is now a link, so nothing was restored there; copy what you need from C:\\Users\\Example\\.apothem\\backups\\20261001T000000Z\\claude_code\\.claude\\commands"
}
```

在链接处被拒绝的结果会在 `detail.symlink` 中指明该链接，在 `detail.leads_to` 中指明它指向的文件夹，与 [`apothem install`](/docs/cli-reference/install#json-output) 中相同。

当针对单个指定的工具不存在匹配的安装记录时，该命令会报告一个 `rollback.no_record` 错误，并带有 `"status": "error"`；而已被回滚或卸载的安装的 `--install-id` 会报告 `rollback.already_reversed`。一旦台账已修剪掉该记录（见上文），这样的 id 会改为报告 `rollback.no_record`。在 `--harness all` 下，没有匹配记录的工具则改为 `results` 中的一行 `"outcome": "error"`。

## 示例

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## 退出码

| 代码 | 含义 |
|---|---|
| 0 | 回滚成功，或者没有可回滚的内容（该次安装未记录任何更改）；被清除的路径以一行 `Warning:`（在 `--json` 下为一个 `warnings` 条目）保留在原位时也是如此 |
| 1 | 预期内的错误——没有安装记录、选择器冲突、未知的工具、缺少项目根目录，或者确认被拒绝或无法进行（非交互模式或 JSON 模式下未提供 `--yes`） |
| 2 | 部分结果——至少一个目标已被回滚，同时还记录了一次失败（恢复失败，或者在 `--harness all` 下，某个工具没有安装记录） |
| 64 | 用法错误：未知的选项或命令，或者缺失或无效的选项值。在 `--json` 下，该错误是一个代码为 `cli.usage` 的 JSON 信封。 |
