将一个工具恢复到其已记录的安装之前的状态。

## 概要

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` 会将每个所选工具恢复到已记录的那次安装过程之前所处的状态——默认是最近一次，或由 `--install-id` 指定的那一次。它按照该次安装的账本记录，从最新的更改开始依次处理：

- 从该次安装所捕获的备份中，在记录的路径上恢复该次安装覆盖的每个文件和目录（被该次安装替换的目录会被精确恢复，不包含该次安装向其中添加的文件）；
- 移除该次安装创建的每个文件和目录，并放回该次安装清除掉的任何旧有布局路径；
- 移除该次安装创建的共享数据存储（`memory`、`contexts`、`learning`），除非另一个已安装的工具仍在使用它们；
- 在该次安装创建的目录变空之后将其移除。

回滚操作移除或替换的所有内容，都会先复制到 Apothem 备份根目录（`~/.apothem/backups/`）中，因此回滚本身也可以手动撤销。随后它会向工具账本追加一条 `rollback` 记录。回滚较早的安装时，只会恢复或移除该较早安装所记录的目标，并会将同一根目录下此后的每次安装从活动记录中剔除。之后的安装在这些目标之外添加的文件会保留在原位。

账本为每个安装根目录保留最新的 10 条安装记录（以及它们所引用的备份）；更早的安装将无法再按 id 回滚，并会报告 `rollback.no_record`。[`apothem backups prune`](/docs/cli-reference/backups) 可按需降低这一上限，并且绝不会移除最近一次安装恢复时所依据的备份。

在添加此行为之前的 Apothem 版本所写入的记录不会列出该次安装创建了哪些文件；回滚这样的记录只会恢复被覆盖的文件。

除非提供了 `--yes`，否则会按工具逐一提示确认。当无法进行提示时——`--format json`（提示文本会破坏单一的 JSON 文档）或非交互式 shell（无 TTY）——除非提供了 `--yes`，否则该命令会预先以一个结构化的 `rollback.confirmation_required` 错误（退出码 1）拒绝执行。`--install-id` 和 `--last` 用于选择安装过程，二者互斥。

`--harness all` 回滚有意做到穷尽：它覆盖每个已注册的工具，包括配置档案的 `exclude_harnesses` 在安装时跳过的工具——恢复安装前的状态是一项清理操作，因此它会触及先前一次范围更广的安装可能留下的记录。没有已记录安装的工具会逐个报告“没有可回滚的内容”。

## 选项

| 选项 | 描述 |
|---|---|
| `--harness NAME` | 要回滚的工具适配器，或用 `all` 表示注册表范围的集合（必需）。 |
| `--install-id ULID` | 回滚指定的安装过程。默认为最近一次记录的安装。 |
| `--last` | 回滚最近一次记录的安装（即默认行为的显式形式）。与 `--install-id` 互斥。 |
| `--yes` | 跳过按工具逐一的确认提示。 |
| `--project PATH` | 项目范围工具的项目根目录。当所选集合包含项目范围适配器时必需。 |
| `--quiet`, `-q` | 抑制信息性输出；只输出错误。 |
| `--verbose`, `-v` | 输出额外的诊断信息。 |
| `--format plain\|json` | 输出格式（默认：`plain`）。 |
| `--json` | `--format json` 的简写。 |
| `--no-color` | 在输出中禁用 ANSI 颜色代码。 |
| `-h`, `--help` | 显示帮助并退出。 |

## JSON 输出

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

每个被恢复或移除的目标都会出现在 `results` 中，带有 `"operation": "rollback"`，且 `outcome` 为 `created` 或 `updated`（同时出现在 `files_written` 中）；`message` 说明该路径是被恢复还是被移除。恢复失败（例如备份已被删除）为 `"outcome": "error"`。未记录任何更改的安装以 `"outcome": "skipped"` 报告。当不存在匹配的安装记录时，该命令会报告一个 `rollback.no_record` 错误，并带有 `"status": "error"`。

## 示例

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## 退出码

| 代码 | 含义 |
|---|---|
| 0 | 回滚成功，或者没有可回滚的内容（该次安装未记录任何更改） |
| 1 | 预期内的错误——没有安装记录、选择器冲突、未知的工具、缺少项目根目录，或者确认被拒绝或无法进行（非交互模式或 JSON 模式下未提供 `--yes`） |
| 2 | 至少一个目标已回滚之后的部分恢复 |
| 64 | 用法错误：未知的选项或命令，或者缺失或无效的选项值。在 `--json` 下，该错误是一个代码为 `cli.usage` 的 JSON 信封。 |
