Apothem 将治理开销按投入程度进行扩展。快速探索不需要签名提交；生产
上线则需要。

## 四个层级

| 层级 | 何时使用 | 治理底线 |
|------|-------------|-----------------|
| **EXPLORING** | 原型、用后即弃的实验 | 代码检查 + 测试 + 核心戒律（批判性评估、最优解推理、直接坦诚） |
| **PERSONAL_USE** | 个人工具、本地脚本 | + 类型检查 + 逐阶段提交 + PROGRESS.md |
| **SHARED** | 团队项目、开源 | + 失败的检查阻断执行 + 逐任务提交 + 完整文档 + 并行审查 |
| **PUBLIC_LAUNCH** | 生产服务、已发布的软件包 | + 安全扫描 + 签名提交 + 语义化版本 + 强制复审 |

## 临时默认

当未指定严肃度层级时，Apothem 默认采用 **PERSONAL_USE**。

## 最小可行治理

在 EXPLORING 层级，三条横切戒律无论层级如何均始终适用：
- CM-1（批判性评估）
- CM-5（最优解）
- CM-10（残酷坦诚）

## 层级升级

严肃度层级可在项目进行中升级。当一个 PERSONAL_USE 项目晋升为 SHARED 时，
请运行完整的本地发布就绪扫描，以捕捉在较低层级累积的任何治理缺口。
