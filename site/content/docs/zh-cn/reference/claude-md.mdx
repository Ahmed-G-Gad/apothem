`CLAUDE.md` 是始终加载的项目配置。宿主工具会在每次交互时加载它，因此其内容即为其他每个工件所扩展的*基线上下文*。它与 `AGENTS.md`（规范的智能体指令表面）以及 `.github/copilot-instructions.md` 保持一致，二者镜像的是同样的纪律。

## 所含内容

项目 `CLAUDE.md` 以散文章节的形式撰写，涵盖 AI 表面规范、计划 → 加固 → 交付的运行循环、项目宗旨与源码布局、计划 / 发布 / 文件头纪律、歧义处理，以及编码与工具适配器约定。它说明*项目是什么*以及*如何在其中工作*；它不重述治理强制要求，这些要求位于规则集合中，并以规则文件的形式呈现给运行时。

| 治理表面 | 所在位置 |
|---|---|
| 横切强制要求（CM-N） | `src/apothem/rules/operational-mandates.md` 以及各强制要求对应的规则文件 |
| 十五项生产强制要求（M-N） | 各强制要求对应的规则文件（`definitiveness.md`、`pre-emission-gate.md`、`production-ready-prs.md`，……） |
| 认知身份与架构姿态 | `src/apothem/rules/cognitive-identity.md` |
| 按严肃度分级的治理 | 各规则自身的 *Seriousness Scaling* 章节 |
| `/plan` 流水线 | `/plan-*` 命令与 `src/apothem/skills/plan-suite/` |
| 工件目录 | 源码布局——`rules/`、`commands/`、`skills/`、`agents/`、`hooks/` |

## 强制要求标识符约定

三个前缀各自承载不同的含义：

- **CM-N** —— 配置强制要求，定义于规则集合中
  （`src/apothem/rules/operational-mandates.md` 以及各强制要求对应的规则文件）。
- **TM-N** —— 模板强制要求，定义于
  `src/apothem/skills/plan-suite/master-template.md` §4。
- **CP-N** —— 核心原则，定义于同一模板的 §6。

计划套件模板是规范的 TM/CP 注册表；`/plan` 流水线的各阶段通过该文件解析交叉引用。
