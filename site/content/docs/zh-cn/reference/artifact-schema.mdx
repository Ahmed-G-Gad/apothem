**所有 Apothem 生态系统制品的逐类 YAML frontmatter 模板与必填字段。**

> **权威来源。** 机器可读、由闸门强制执行的契约是 [`src/apothem/schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas) 下的逐类 JSON Schema（`agent.schema.json`、`command.schema.json`、`skill.schema.json`……），每个 schema 都声明了 `additionalProperties`，因此合规闸门会拒绝未知键。本页与 [`frontmatter-schema.mdx`](/docs/reference/frontmatter-schema) 是这些 schema 的两个人类可读投影——本页承载逐类的**模板与完整示例**，frontmatter-schema 承载简洁的**必需键索引**。当某一页与 JSON Schema 不一致时，以 schema 为准。

## 概述

Apothem 源码树中的所有制品（位于 `src/apothem/` 下以及根配置表面中）都必须包含一个 YAML frontmatter 块（位于 `---` 分隔符之间），其中带有特定于其制品类型的必填字段与可选字段。本文档为每种类型定义规范 schema。

**通用规则：**

- frontmatter 符合 YAML 1.2
- 所有字符串值都使用双引号，空字符串写作 `""`
- 字段顺序：必填字段在前，可选字段按相关性分组
- frontmatter 中的注释使用 `#` 加一个空格：`# comment`
- 路径值必须为相对路径（不带前导 `/`），并使用正斜杠（`/`）以保证跨平台兼容性

**版本约定（带版本的制品类别——命令、辅助器、技能、CLAUDE.md）：**

- `version` 为**语义化版本**（`MAJOR.MINOR.PATCH`）。破坏性的 schema 或契约变更递增 MAJOR；增量式的非破坏性变更（新的可选字段、新增章节、新增反模式）递增 MINOR；澄清、格式修复或不改变行为的纯文档编辑递增 PATCH。
- `updated` 是最近一次编辑的 **ISO 8601 日期**（`YYYY-MM-DD`）。它必须随每次 `version` 递增而改变，也可以在不递增版本的链接刷新中单独更新。
- 新制品从 `v0.Y.Z` 起步。提升到 `vX.Y.Z` 表示该制品的契约已足够稳定，可以作为一项公开承诺。

## Schema：规则

**路径模式：** `src/apothem/rules/*.md`

**用途：** 行为强制规定与操作指令。

### 必填字段

```yaml
---
name: "kebab-case-identifier"
description: "One-line description"
pathFilter: "**/*.py, **/*.toml"
alwaysApply: true | false
---
```

| 字段 | 类型 | 用途 | 示例 |
| ----- | ---- | ------- | ------- |
| `name` | string | 机器可读标识符 | `"operational-mandates"` |
| `description` | string | 供注册表使用的单行描述 | `"Operational mandates CM-1–10"` |
| `pathFilter` | string | 以逗号分隔的 glob 列表，用于限定路径过滤规则的作用范围；始终生效规则上为空字符串（`""`） | `"**/*.py, **/*.toml"` |
| `alwaysApply` | boolean | 始终生效规则（处处加载）为 `true`；路径过滤规则（在 `pathFilter` 匹配时加载）为 `false` | `true` |

### 可选字段

规则不带任何可选 frontmatter 字段，并且——与其他制品类别不同——也不带 `version` / `updated` / `scope` / `portability` 字段。上述四个必填字段就是由 `frontmatter_grep` 强制执行的完整规则 frontmatter 契约。

### 示例

```yaml
---
name: "operational-mandates"
description: "Behavioral definitions for CM-1 through CM-10: violation indicators and recovery actions"
pathFilter: ""
alwaysApply: true
---

# Rule: Operational Mandates
...
```

## Schema：命令

**路径模式：** `src/apothem/commands/*.md`

**用途：** 斜杠命令定义（`/plan-execute`、`/freshify` 等）。

### 必填字段

```yaml
---
name: "command-name"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "What this command does"
argument-hint: "[argument-pattern]"
disable-model-invocation: true | false
portability: "universal"
allowed-tools: "Read, Glob, Grep"
---
```

| 字段 | 类型 | 用途 | 示例 |
| ----- | ---- | ------- | ------- |
| `name` | string | 命令名称（不含前导 `/`） | `"plan-execute"` |
| `version` | string | 语义化版本 | `"X.Y.Z"` |
| `updated` | string（ISO 8601） | 最近更新日期 | `"2026-04-20"` |
| `description` | string | 简短描述 | `"Executes a phase with quality gates"` |
| `argument-hint` | string | 用法模式；若无参数则为 `"[args...]"` | `"[path/to/plan] [phase-id]"` |
| `disable-model-invocation` | boolean | 若为 true，则只有操作者会启动该命令；模型绝不会自行调用它 | `true` |
| `portability` | string | 跨工具适配器的可移植性分类 | `"universal"` |
| `allowed-tools` | string | 命令运行期间预先批准的工具：只读工具，以及仅以限定范围规则（例如 `Bash(git log *)`）形式出现的有副作用工具。裸 `"*"` 通配符会被拒绝 | `"Read, Glob, Grep"` |

### 可选字段

命令不带任何可选 frontmatter 字段——上述八个必填字段就是由 `command.schema.json`（`additionalProperties: false`）强制执行的完整命令 frontmatter 契约。

### 示例

```yaml
---
name: "plan-execute"
version: "X.Y.Z"
updated: "2026-04-20"
description: "Executes a specific phase from a Master Plan Suite with conformity checking and quality gates"
argument-hint: "[path/to/plan-suite/] [phase-id] [--dry-run]"
disable-model-invocation: true
portability: "universal"
allowed-tools: "Read, Glob, Grep"
---

# /plan-execute — Execute a Specific Phase
...
```

## Schema：辅助器

**路径模式：**

```text
src/apothem/agents/*.md
```

**用途：** 用于并行探索、审计和质量闸门的持久化辅助器定义（也称为委派工作者）。

### 必填字段

```yaml
---
name: "agent-name"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "What this agent specializes in"
tools: "Tool1, Tool2, Tool3"
disallowedTools: "Write, Edit"
maxTurns: 20
effort: "high" | "medium" | "low"
---
```

| 字段 | 类型 | 用途 | 示例 |
| ----- | ---- | ------- | ------- |
| `name` | string | 辅助器标识符 | `"codebase-explorer"` |
| `version` | string | 语义化版本 | `"X.Y.Z"` |
| `updated` | string（ISO 8601） | 最近更新日期 | `"2026-04-20"` |
| `description` | string | 专长描述 | `"Deep codebase exploration"` |
| `tools` | string（逗号分隔） | 允许的工具 | `"Read, Glob, Grep, Bash"` |
| `disallowedTools` | string（逗号分隔） | 禁止的工具 | `"Write, Edit, TodoWrite"` |
| `maxTurns` | integer | 最大对话轮次（通常为 5–20；超过 20 的值需要一条内联理由注释） | `20` |
| `effort` | enum | 计算范围 | `"high"` |

### 可选字段

```yaml
permissionMode: "default"       # Permission handling
memory: user | project | local  # Persistent-memory scope; omit for none
pattern: "Research" | "Audit" | "Implementation" | "Quality"  # Agent team pattern
portability: "universal"
```

### 示例

```yaml
---
name: "codebase-explorer"
version: "X.Y.Z"
updated: "2026-04-20"
description: "Deep codebase exploration — find patterns, trace dependencies, discover conventions, map architecture"
tools: "Read, Glob, Grep, Bash"
disallowedTools: "Write, Edit, TodoWrite"
maxTurns: 20
effort: "high"
permissionMode: "default"
portability: "universal"
---

You are a codebase exploration specialist...
```

## Schema：技能

**路径模式：** `src/apothem/skills/*/SKILL.md`

**用途：** 带有检测信号和执行流程的可复用技术定义。

### 必填字段

```yaml
---
name: "skill-name"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "What this skill teaches"
archetype: "workflow-template"
userInvocable: true | false
disable-model-invocation: true | false
allowed-tools: "Read, Glob, Grep"
---
```

| 字段 | 类型 | 用途 | 示例 |
| ----- | ---- | ------- | ------- |
| `name` | string | 技能标识符 | `"plan-suite"` |
| `version` | string | 语义化版本 | `"X.Y.Z"` |
| `updated` | string（ISO 8601） | 最近更新日期 | `"2026-04-20"` |
| `description` | string | 该技能提供的内容 | `"Master Plan Suite template"` |
| `archetype` | string | 形态类别，一个 kebab-case 的 `<class>-template` 标识符 | `"workflow-template"` |
| `userInvocable` | boolean | 若为 true，用户可以显式请求该技能 | `false` |
| `disable-model-invocation` | boolean | 若为 true，则该技能只能通过显式调用到达 | `true` |
| `allowed-tools` | string | 技能运行期间预先批准的工具：只读工具，以及仅以限定范围规则（例如 `Bash(git log *)`）形式出现的有副作用工具。裸 `"*"` 通配符会被拒绝 | `"Read, Glob, Grep"` |

### 可选字段

```yaml
argument-hint: "[args...]"                           # Usage pattern if userInvocable
```

### 示例

```yaml
---
name: "ecosystem-audit"
version: "X.Y.Z"
updated: "2026-04-20"
description: "Comprehensive blind audit of the apothem ecosystem"
archetype: "audit-template"
userInvocable: true
disable-model-invocation: true
allowed-tools: "Read, Glob, Grep, Agent, TodoWrite"
argument-hint: "[--focus area] [--fix]"
---

## Purpose
...
```

## Schema：钩子

**路径模式：** `settings.json` 的 `hooks` 块，加上 `src/apothem/hooks/` 下的 Python 实现。

**用途：** 声明由事件触发的校验器和状态管理处理器，由宿主在明确定义的生命周期节点调用。

### 设置文件 Schema

顶层键 `hooks` 将事件名称映射到匹配器块数组：

```json
"hooks": {
  "<EventName>": [
    {
      "matcher": "<pattern>",
      "hooks": [
        {
          "type": "command",
          "command": "${PYTHON_BIN}",
          "args": ["${HARNESS_ROOT}/.apothem/support/hooks/dispatch.py", "<EventName>", "<message-name>"],
          "timeout": <seconds>,
          "statusMessage": "<short human-readable label>"
        }
      ]
    }
  ]
}
```

`-m apothem.hooks.dispatch` 形式仅用于在设置了 `PYTHONPATH=src` 的源码检出中进行开发。

| 字段 | 类型 | 用途 | 示例 |
| ----- | ---- | ------- | ------- |
| `matcher` | string | 工具名称模式（对与工具无关的事件则为 `"*"`） | `"Write"` |
| `hooks[].type` | 字面量 `"command"` | 目前唯一支持的钩子处理器类型 | `"command"` |
| `hooks[].command` | string | 可执行命令；Apothem 使用 `${PYTHON_BIN}` 占位符，在安装时解析 | `"${PYTHON_BIN}"` |
| `hooks[].args` | 字符串数组 | exec 形式的参数：`${HARNESS_ROOT}/.apothem/support/` 下的脚本路径，然后是其参数 | `["${HARNESS_ROOT}/.apothem/support/hooks/dispatch.py", "SessionStart"]` |
| `hooks[].timeout` | 整数（秒） | 宿主终止该钩子之前的最长运行时间 | `30` |
| `hooks[].statusMessage` | string | 在宿主界面中显示的简短标签 | `"Session start"` |

### 必需事件

Claude Code 模板注册四个事件：SessionStart、PreToolUse、PostToolUse 和 Stop。`scripts/dev/validate_hooks.py` 在 `settings.json` 中检查下表中的五个事件，这是不同的一组事件，并将其未找到的每一个事件作为警告而非失败报告。PostToolUse 已注册，但不在这五个事件之列。PreCompact 与 PostCompact 属于这五个事件，但未在 Claude Code 上注册（参见[钩子参考](/docs/reference/hooks)），因此检查器在 Claude Code 上会对这两者都发出警告。

> **超时值镜像规范的钩子事件预算**——下表为方便读者而复现了这些值；以规范来源为准。

| 事件 | 典型超时 | 用途 |
| ----- | --------------- | ------- |
| `SessionStart` | 30 秒 | 读取记忆、检查计划状态、报告就绪情况 |
| `PreToolUse` | 10 秒 | 校验写入是否符合内容隔离策略 + frontmatter |
| `PreCompact` | 30 秒 | 在上下文压缩之前验证状态已外部化 |
| `PostCompact` | 30 秒 | 在上下文压缩之后恢复工作状态 |
| `Stop` | 60 秒 | 会话结束时的外部化——恢复状态、输出、决策 |

`dispatch.py` 还在其事件白名单中接受 `UserPromptSubmit` 和 `Notification`，以实现向前兼容；两者都没有在随附模板中接线。添加一个采用相同 exec 形式模式的匹配器块即可启用。

### Python 层

每条钩子命令都经由同一个 Python 调度器路由：

| 文件 | 角色 |
| ---- | ---- |
| `src/apothem/hooks/dispatch.py` | 将 `SessionStart` 路由到 `session_start_bootstrap.main()`，并将其他每个白名单事件路由到 `emit_hook_context.main()`。始终以 0 退出。 |
| `src/apothem/hooks/session_start_bootstrap.py` | 会话启动钩子脚本——发出记忆和计划套件摘要上下文。 |
| `src/apothem/hooks/emit_hook_context.py` | 默认钩子发射器——写出一个携带已注册 `--context-file` 载荷的有效信封。 |
| `src/apothem/hooks/messages/*.md` | 由 `--context-file` 引用的静态上下文载荷。 |

### 校验

`scripts/dev/validate_hooks.py` 强制执行钩子契约：

- `settings.json` 可解析为 JSON，并声明表中五个事件中的每一个；缺失某个事件是警告，而非失败。
- 全部三个 Python 脚本都存在，并可解析为有效的 Python。
- 由 `--context-file` 参数引用的所有消息文件都存在。
- `src/apothem/hooks/**.py` 中不出现硬编码的绝对用户路径（`C:\Users\...` 等）。
- `src/apothem/hooks/` 和 `scripts/` 下的 shell 制品仅限于已批准的定位器 / 引导桩。

## Schema：CLAUDE.md

**路径：** `CLAUDE.md`（根目录）

**用途：** 项目范围的 Claude Code 指令。

### 必填 YAML Frontmatter

```yaml
---
name: "CLAUDE"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "Project-scoped Claude Code instructions for the Apothem source repository"
scope: "project"
portability: "project-local"
---
```

### 章节

`CLAUDE.md` 以散文式章节编写，详见 [`CLAUDE.md`](/docs/reference/claude-md)。没有任何校验器要求固定的章节列表：`scripts/dev/validate_ecosystem.py` 检查上述 frontmatter 键。

## 校验清单

每个制品都必须满足以下检查：

### Frontmatter 校验

- [ ] YAML 在语法上有效（无解析错误）
- [ ] 该制品类型的所有必填字段都存在
- [ ] `name` 遵循 kebab-case 约定
- [ ] `version` 为语义化版本（`MAJOR.MINOR.PATCH`）
- [ ] `updated` 为 ISO 8601 日期格式（`YYYY-MM-DD`）
- [ ] `description` 为非空字符串，且为单行
- [ ] 可选字段与预期的枚举值匹配（如适用）
- [ ] 字段名中没有拼写错误（使用 schema 中的规范名称）
- [ ] 没有多余的空白或格式问题

### 内容校验

- [ ] 内容在闭合 `---` 之后另起一行开始；在 Markdown 系列文件上，规范的 SPDX 头部行是其后的第一项内容
- [ ] 没有计划内部引用（符合 CM-7）
- [ ] 交叉引用可以解析（若列出了其他制品）
- [ ] 链接使用带正斜杠的相对路径

### 可移植性校验

- [ ] 没有硬编码的绝对路径（使用相对路径）
- [ ] universal 范围的制品中没有 Windows 专用语法
- [ ] 路径分隔符使用正斜杠
- [ ] 环境变量使用与平台无关的格式（`${VAR}` 或工具原生格式）

## 说明

- **一致性即安全：** 规范的 frontmatter 使自动化校验、工具支持和跨制品验证成为可能。偏差会迅速累积。
- **可移植性声明：** 并非所有制品都能做到 universal。显式声明约束——记录一条注意事项，胜过交付一个无声的缺陷。
- **名称使用 kebab-case：** 便于在 URL、脚本和命令行环境中使用。名称应避免空格、下划线和 camelCase。
- **版本递增卫生：** 每次改变行为的编辑都必须同时递增 `version` 和 `updated`。纯格式或拼写修复递增 PATCH；新的可选章节或反模式递增 MINOR；结构性重组或契约变更递增 MAJOR。
