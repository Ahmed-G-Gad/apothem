本部分记录项目的内部质量治理：定义每个产出工件必须满足之事的强制要求登记表、
在工件发布前检查它们的关卡、把工具可以决定之事与必须询问之事分开的询问类别，
以及治理发布、徽章和项目定位的策略。

这些页面对维护者和仓库中的自动化检查具有规范效力。日常使用指南位于
[指南](/docs/usage)之下，它们引用的模式与约定位于[参考](/docs/reference)之下。

## 页面

| 页面 | 描述 |
|------|-------------|
| [横切强制要求](/docs/governance/cross-cutting-mandates) | 治理所有交互与流水线操作的生态内部强制要求登记表（CM-1–CM-28）。 |
| [对外一致性登记表](/docs/governance/outward-conformity-registry) | 在宿主项目中生成的每个工件必须满足的十五项强制要求登记表（M1–M15）。 |
| [发布前关卡登记表](/docs/governance/pre-emission-gate-registry) | 在任何有意义范围的发布之前运行的强制十五栏一致性检查。 |
| [权威询问登记表](/docs/governance/authoritative-inquiry-registry) | 必需的询问类别与自动决策豁免项：哪些被询问，哪些被决定。 |
| [徽章策略](/docs/governance/badge-policy) | README 的动态与静态徽章来源，以及每个徽章如何保持真实。 |
| [发布工程策略](/docs/governance/release-engineering-policy) | 版本控制、发布打标签、弃用周期、破坏性变更以及回滚流程。 |
| [定位](/docs/governance/positioning) | Apothem 如何定位自身：面向助手驱动开发的工件批准治理。 |
