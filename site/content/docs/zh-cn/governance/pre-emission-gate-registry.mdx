> **十五关卡预发布闸门的规范登记册。** 本文档承载完整的十五关卡闸门表格与闸门结果模式 YAML 块；实质性的表格与模式存放于此，并由 `src/apothem/rules/pre-emission-gate.md` 操作化。

在发出任何有实质范围的工件之前（依据 `site/content/docs/governance/outward-conformity-registry.mdx` §1 中琐碎与非琐碎的阈值），运行十五关卡预发布闸门。可能时通过 PreToolUse 钩子实现机械化（由 `src/apothem/conformity/gate.py` 编排的、位于 `src/apothem/conformity/*-grep.py` 的机械 grep）；无法机械化之处则通过推理完成。**任一关卡失败即阻止发出；修订直至每道关卡都通过；发出时记录闸门结果。**

## 1. 闸门结果模式

每次闸门运行都将结果记录在制品的工作轨迹中（隐藏注释、元数据块、独立的发射日志文件——以宿主惯例所允许者为准）：

```yaml
conformity-attestation:
  artifact: <path-or-identifier>
  ecosystem-version: <git-commit-sha-or-equivalent ratifying the rule set in force>
  bars:
    M1-host-agnosticism:        pass | n/a (with reason)
    M2-editorial-disclosure:    pass | n/a
    M3-ten-dimensions:          pass | n/a
    M4-self-application:        pass
    M5-authority:               pass
    M6-expertise:               pass | n/a
    M7-option-annotation:       pass | n/a (no option set)
    M8-definitiveness:          pass
    M9-visual-leverage:         pass | n/a (subject not structural)
    M10-bidirectional-binding:  pass
    M11-agile-sprints:          pass | n/a (trivial work)
    M12-phase-layout:           pass | n/a
    M13-code-craft:             pass | n/a (not code)
    M14-systemicity:            pass
    M15-production-ready:       pass | n/a (no host-public-surface change)
  surfaced-gaps: []
  unresolved-inquiries: []
  amendments-disclosed: []
  date: <ISO-8601>
```

`n/a` 标记是显式且经推理给出的——绝非静默跳过。`ecosystem-version` 字段将闸门结果锚定到用户范围生态系统的一个可复现状态（即闸门运行时处于活动状态的 Apothem 源码树 git 提交——例如 Claude Code 适配器的 `~/.claude/` 检出），以便未来的审计能够依据相同的规则正文重放该闸门。
