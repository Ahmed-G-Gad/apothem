面向维护者的操作流程。每份操作手册都是一套有序、不依赖上下文的流程：它将一个已知的起始状态推进到一个经过验证的结束状态，其写法使一位称职的贡献者无需事先了解背景即可照做。

## 页面

| 页面 | 描述 |
|------|-------------|
| [Pages 启用](/docs/runbooks/pages-enablement) | 将 `apothem.ahmedgad.com` 从全新的 GitHub Pages 配置推进到一个返回 `200 OK` 的 HTTPS 着陆页。 |
| [发布周期](/docs/runbooks/release-cycle) | 将一次 `vX.Y.Z` 发布从干净的工作树推进到经过验证的 GitHub Release 和 npm 表面。 |
| [发布者账户设置](/docs/runbooks/publisher-account-setup) | 为 `@ahmed-g-gad/apothem` 配置 npmjs.com 受信任发布者，以及 GitHub 侧的发布前置条件。 |
| [发布恢复](/docs/runbooks/release-recovery) | 当发布切换序列中途失败时，将 `ahmed-g-gad/apothem` 恢复到可用状态。 |
| [编写新的工具适配器](/docs/runbooks/new-harness-adapter-authoring) | 编写并发布一个新的工具适配器，以作为第一方适配器纳入。 |
| [部署检查清单](/docs/runbooks/deployment-checklist) | 在部署或共享 Apothem 生态系统之前，运行飞行前验证检查清单。 |
| [单人维护者合并仪式](/docs/runbooks/solo-maintainer-merge) | 维护者何时可以直接合并自己的拉取请求，以及在保护要求一次批准并对管理员强制执行时所用的自合并仪式。 |
| [跨主机同步检查清单](/docs/runbooks/cross-machine-sync-checklist) | 验证 Claude Code 适配器在全新主机上能正确安装、校验和卸载，并附带完整的可移植性检查。 |
