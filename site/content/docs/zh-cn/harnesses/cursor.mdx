**厂商：** Anysphere
**安装名称：** `cursor`
**状态：** GA
**原生配置：** 项目根目录下的 `.cursor/rules/`

## 安装

```bash
apothem install --harness cursor --project /path/to/project
```

适配器根据共享的 Apothem 规则与治理表面渲染出单个项目级 `.mdc` 规则文件。

**写入的文件：** `<project>/.cursor/rules/apothem-rules.mdc`

该文件就是安装的全部内容：它旁边不会放置任何规则、技能、命令、模板或钩子文件，因此该文件会说明这一点，而不是指向项目中并不存在的 Apothem 文件。

## 配置档案到原生配置的映射

适配器在每次运行 `apothem install` 或 `apothem update` 时读取 Apothem 的共享配置档案，并渲染项目规则文件。共享配置档案是事实来源；在下一次同步替换由 Apothem 管理的内容之前，对生成文件的项目本地编辑会先被备份。

该文件以其 YAML 前置元数据（`description`、`globs`、`alwaysApply: true`）开头，因为 Cursor 只从文件开头的前置元数据读取规则的类型。由 Apothem 管理的区块紧随其后；你在该区块之后添加的文本会在每次同步时保留。

## 兼容性说明

Cursor 0.45+ 通过 `.cursor/rules/` 支持项目级指令。适配器默认写入项目级的 `.cursor/rules/` 目录；Cursor 没有可供此适配器管理的、有文档记载的基于文件的用户全局规则路径。

## 验证

```bash
apothem verify --harness cursor --project /path/to/project
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 每个受管目标都存在；受管文件非空，并且 JSON 或 YAML 配置可以解析。添加 `--profile PATH` 还可以确认已安装的文件与该配置档案相符。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness cursor --project /path/to/project
```

根据共享配置档案的当前状态重新派生项目规则文件。

## 卸载

```bash
apothem uninstall --harness cursor --project /path/to/project
```

从 `<project>/.cursor/rules/apothem-rules.mdc` 中移除 Apothem 区块，以及 Apothem 写在该区块上方的前置元数据，并保留其中的其他任何文本。仅当其中不再剩有任何其他内容时，才会删除该文件。在更改之前，会将该文件带时间戳的副本保存到 `~/.apothem/backups/` 下；项目中不会留下备份文件。共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness cursor --project /path/to/project` |
| 验证失败 | 运行 `apothem update --harness cursor --project /path/to/project`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness cursor --project /path/to/project` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
