**厂商：** Devin Desktop（原 Codeium Windsurf）
**安装名称：** `windsurf`
**状态：** GA
**原生配置：** `<project>/.devin/rules/apothem-rules.md`

Windsurf 现已成为 Devin Desktop，`.devin/rules/` 是首选的工作区规则位置（它优先于 `.windsurf/rules/`）。

## 安装

```bash
apothem install --harness windsurf --project /path/to/project
```

适配器根据共享的 Apothem 规则和治理表面，写入一个项目级的 Windsurf 规则文件。

**写入的文件：** `<project>/.devin/rules/apothem-rules.md`

## 配置档案到原生配置的映射

适配器读取 Apothem 的共享配置档案，并在每次 `apothem install` 或 `apothem update` 运行时渲染项目规则文件。共享配置档案是事实来源；在下一次同步替换 Apothem 管理的内容之前，对生成文件所做的项目本地编辑会被备份。

该文件以其 `trigger: always_on` 前置元数据开头，它设置该规则的激活模式。Apothem 管理的块紧随其后；你在该块之后添加的文本在每次同步时都会被保留。

## 兼容性说明

Windsurf 当前的规则表面位于 `.devin/rules/` 下，作用范围为项目级（这是首选位置，优先于用于向后兼容的回退位置 `.windsurf/rules/`）。工作流和机器本地的记忆归操作者所有；Apothem 不写入它们。单文件形式的 `.windsurfrules` 被有意不写入。

## 验证

```bash
apothem verify --harness windsurf --project /path/to/project
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 每个受管目标都存在；受管文件非空，并且 JSON 或 YAML 配置可以解析。添加 `--profile PATH` 还可以确认已安装的文件与该配置档案相符。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness windsurf --project /path/to/project
```

根据当前的共享配置档案状态，重新派生项目规则文件。

## 卸载

```bash
apothem uninstall --harness windsurf --project /path/to/project
```

从 `<project>/.devin/rules/apothem-rules.md` 中移除 Apothem 块，以及 Apothem 写在该块上方的前置元数据，并保留其中的其他任何文本。只有当该文件中不再剩下其他内容时，才会删除该文件。更改之前，会先将该文件带时间戳的副本保存到 `~/.apothem/backups/` 下；项目中不会留下备份文件。共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness windsurf --project /path/to/project` |
| 验证失败 | 运行 `apothem update --harness windsurf --project /path/to/project`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness windsurf --project /path/to/project` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
