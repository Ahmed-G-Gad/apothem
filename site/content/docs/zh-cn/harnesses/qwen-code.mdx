**厂商：** Alibaba Cloud
**安装名称：** `qwen-code`
**状态：** 测试版
**原生配置：** `~/.qwen/`

## 安装

```bash
apothem install --harness qwen-code
```

适配器写入 Qwen Code 设置，安装一个 `QWEN.md` 上下文锚点，注册 Apothem 钩子调度器，将 Apothem 命令转换为 Qwen Markdown 命令文件，将技能安装为 SKILL.md 目录，并将辅助器定义改编为 Qwen 子智能体。

**写入的文件：**

```text
~/.qwen/settings.json
~/.qwen/QWEN.md
~/.qwen/apothem/rules/00-apothem-profile.md
~/.qwen/commands/
~/.qwen/skills/
~/.qwen/agents/
~/.qwen/.apothem/support/{rules,templates,hooks}/
```

文件 `~/.qwen/apothem/rules/00-apothem-profile.md` 是配置档案文档。它携带共享配置档案中你的身份和偏好。

## 配置档案到原生配置的映射

适配器为上下文和钩子渲染有文档记载的 `settings.json` 键，写入 `QWEN.md`，并将 Apothem 命令、技能和辅助器定义编入 Qwen Code 的原生发现目录。规则、模板和钩子源材料仍作为支持材料保留在 `~/.qwen/.apothem/support/` 下。

## 兼容性说明

`~/.qwen/.apothem/support/` 是由 `QWEN.md` 和设置中的钩子命令引用的支持材料；它不是厂商拥有的发现命名空间。`QWEN.md` 中的 Apothem 块以一个 Apothem 支持文件小节结尾，该小节写明每条仓库式引用（`rules/<name>.md`、`templates/...`、`hooks/...`）所解析到的、位于 `~/.qwen/.apothem/support/` 下的绝对目录。

**技能工具列表。** `Qwen Code` 从驼峰式的 `allowedTools` 前置元数据键读取技能的工具允许列表，且该值必须是一个 YAML 列表。它会忽略为其他代理写入的连字符形式 `allowed-tools` 键。因此，已安装的技能以列表形式携带 `allowedTools`，每行一个条目，取代源语料库中以逗号分隔的 `allowed-tools` 字符串。每个条目都保留源中的拼写，包括 `Bash(git status *)` 这样的模式。其他每个技能键以及技能正文都按原样安装。

**技能文件夹。** 适配器将技能写入 `~/.qwen/skills/`。`Qwen Code` 还会读取 `~/.agents/skills/`，并在项目内读取 `.qwen/skills/` 和 `.agents/skills/`。当两个文件夹中存在同名技能时，`.qwen` 下的那个优先，因此 `~/.qwen/skills/` 中的 Apothem 技能优先于另一个适配器写入 `~/.agents/skills/` 的同名技能。

**钩子事件。** 适配器接入 `SessionStart`、`PreToolUse`、`PreCompact`、`PostCompact` 和 `Stop`。`Qwen Code` 定义了 22 个钩子事件，这五个都在其中。这 22 个中有三个（`SessionDelete`、`TodoCreated` 和 `TodoCompleted`）没有同名的 `Claude Code` 事件（`Claude Code` 将待办事件命名为 `TaskCreated` 和 `TaskCompleted`）；适配器不接入其中任何一个。

## 验证

```bash
apothem verify --harness qwen-code
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 每个受管目标都存在；受管文件非空，并且 JSON 或 YAML 配置可以解析。添加 `--profile PATH` 还可以确认已安装的文件与该配置档案相符。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness qwen-code
```

刷新 `settings.json`、`QWEN.md`、原生命令、技能、子智能体以及 Apothem 支持树。

## 卸载

```bash
apothem uninstall --harness qwen-code
```

移除适配器添加到 `~/.qwen/settings.json` 的条目（你自己的键、MCP 服务器和钩子处理程序会保留；只有当该文件由 Apothem 创建且其中没有你的任何内容时，才会删除该文件）。从 `~/.qwen/QWEN.md` 和配置档案文档 `~/.qwen/apothem/rules/00-apothem-profile.md` 中移除 Apothem 块，并保留其中的其他任何文本；每个文件只有在其中不再剩下其他内容时，才会被删除。同时移除 `~/.qwen/commands/`、`~/.qwen/skills/`、`~/.qwen/agents/` 和 `~/.qwen/.apothem/support/` 中的 Apothem 文件；这些文件夹中的其他文件会保留。每个文件在被更改或移除之前，都会先备份到 `~/.apothem/backups/` 下。共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness qwen-code` |
| 验证失败 | 运行 `apothem update --harness qwen-code`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness qwen-code` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
