**厂商：** Alibaba Cloud
**安装名称：** `qwen-code`
**状态：** 测试版
**原生配置：** `~/.qwen/`

## 安装

```bash
apothem install --harness qwen-code
```

适配器写入 Qwen Code 设置，安装一个 `QWEN.md` 上下文锚点，注册 Apothem 钩子调度器，将 Apothem 命令转换为 Qwen Markdown 命令文件，将技能安装为 SKILL.md 目录，并将辅助器定义改编为 Qwen 子智能体。

**写入的文件：**

```text
~/.qwen/settings.json
~/.qwen/QWEN.md
~/.qwen/commands/
~/.qwen/skills/
~/.qwen/agents/
~/.qwen/.apothem/support/{rules,templates,hooks}/
```

## 配置档案到原生配置的映射

适配器为上下文和钩子渲染有文档记载的 `settings.json` 键，写入 `QWEN.md`，并将 Apothem 命令、技能和辅助器定义编入 Qwen Code 的原生发现目录。规则、模板和钩子源材料仍作为支持材料保留在 `~/.qwen/.apothem/support/` 下。

## 兼容性说明

`~/.qwen/.apothem/support/` 是由 `QWEN.md` 和设置中的钩子命令引用的支持材料；它不是厂商拥有的发现命名空间。`QWEN.md` 中的 Apothem 块以一个 Apothem 支持文件部分结尾，该部分指明每条仓库式引用（`rules/<name>.md`、`templates/...`、`hooks/...`）据以解析的 `~/.qwen/.apothem/support/` 下的绝对目录。

## 验证

```bash
apothem verify --harness qwen-code
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 共享配置档案中的所有必填字段都已存在。
3. 适配器特定的验证例程报告成功。

## 更新

```bash
apothem update --harness qwen-code
```

刷新 `settings.json`、`QWEN.md`、原生命令、技能、子智能体以及 Apothem 支持树。

## 卸载

```bash
apothem uninstall --harness qwen-code
```

移除适配器写入的原生配置文件。共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness qwen-code` |
| 验证失败 | 运行 `apothem update --harness qwen-code`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness qwen-code` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
