**厂商：** 阿里云
**安装名称：** `qwen-code`
**状态：** 测试版
**平台原生配置：** `~/.qwen/`

## 安装

```bash
apothem install --harness qwen-code
```

该适配器写入 Qwen Code 设置，安装一个 `QWEN.md` 上下文锚点，注册 Apothem
钩子分发器，将 Apothem 命令转换为 Qwen Markdown 命令文件，将技能作为 SKILL.md
目录安装，并将辅助工具定义改造为 Qwen 子代理。

**写入的文件：**

```text
~/.qwen/settings.json
~/.qwen/QWEN.md
~/.qwen/commands/
~/.qwen/skills/
~/.qwen/agents/
~/.qwen/.apothem/support/{rules,templates,hooks}/
```

## 配置档案到平台原生配置的映射

适配器为上下文和钩子渲染已记录的 `settings.json` 键，写入 `QWEN.md`，并将
Apothem 命令、技能和辅助工具定义编织进 Qwen Code 的原生发现目录中。规则、模板
和钩子源材料则作为支持材料保留在 `~/.qwen/.apothem/support/` 之下。

## 兼容性说明

`~/.qwen/.apothem/support/` 是由 `QWEN.md` 和设置中的钩子命令引用的支持材料；它并非由
厂商所拥有的发现命名空间。

## 验证

```bash
apothem verify --harness qwen-code
```

verify 命令确认：

1. 平台原生配置存在于预期路径。
2. 共享配置档案中的所有必需字段均存在。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness qwen-code
```

刷新 `settings.json`、`QWEN.md`、原生命令、技能、子代理以及 Apothem 支持树。

## 卸载

```bash
apothem uninstall --harness qwen-code
```

移除适配器写入的平台原生配置文件。
共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness qwen-code` |
| 验证失败 | 运行 `apothem update --harness qwen-code`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness qwen-code` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
