**厂商：** Open-Claw
**安装名称：** `open-claw`
**状态：** 预览版
**原生配置：** `~/.openclaw/openclaw.json`

## 安装

```bash
apothem install --harness open-claw
```

适配器将共享配置档案转换为 OpenClaw 的用户全局配置文件，并在工具根目录下安装 Apothem 支持集合。OpenClaw 的原生配置是 JSON；物化器相应地渲染 JSON。

**写入的文件：** `~/.openclaw/openclaw.json`、配置档案文档 `~/.openclaw/apothem/rules/00-apothem-profile.md`，以及 `~/.openclaw/.apothem/support/` 下的支持文件

配置档案文档以一个 Apothem 支持文件部分结尾，该部分指明每条仓库式引用（`rules/<name>.md`、`templates/...`、`hooks/...`）据以解析的 `~/.openclaw/.apothem/support/` 下的绝对目录。

## 配置档案到原生配置的映射

适配器读取 Apothem 的共享配置档案，但不编写任何配置键：`openclaw.json` 被写为一个空对象。配置档案中的身份、偏好和规则进入配置档案文档。共享的命令、技能、规则、模板和钩子提示词作为支持材料安装在 `~/.openclaw/.apothem/support/` 下。

## 兼容性说明

预览版适配器。OpenClaw 不会自行加载支持树或配置档案文档：它的任何技能位置、工作区指令文件或配置都不指向那里，因此安装之后，OpenClaw 运行时不带有 Apothem 的规则、技能或 MCP 服务器。OpenClaw 从其工作区的 `skills/` 和 `.agents/skills/` 文件夹、`~/.agents/skills`、其状态目录，以及 `skills.load.extraDirs` 中列出的任何文件夹读取技能；若要使用 Apothem 技能，请自行将 `~/.openclaw/.apothem/support/skills` 添加到该列表中；`apothem update` 会保留你添加到 `openclaw.json` 中的键。MCP 服务器位于 OpenClaw 配置的 `mcp.servers` 块中，你通过 `openclaw mcp add` 及相关子命令管理它；适配器不在那里写入任何条目。（OpenClaw 的行为依据其[技能](https://docs.openclaw.ai/tools/skills)和 [MCP CLI](https://docs.openclaw.ai/cli/mcp) 文档，读取于 2026-10-02。）

## 验证

```bash
apothem verify --harness open-claw
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 每个受管目标都存在；受管文件非空，并且 JSON 或 YAML 配置可以解析。添加 `--profile PATH` 还可以确认已安装的文件与该配置档案相符。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness open-claw
```

根据当前的共享配置档案状态重新派生原生配置。在编辑 `~/.config/apothem/profile.yaml` 或升级已安装的 Apothem 包之后运行。

## 卸载

```bash
apothem uninstall --harness open-claw
```

移除适配器写入的原生配置文件。共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness open-claw` |
| 验证失败 | 运行 `apothem update --harness open-claw`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness open-claw` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
