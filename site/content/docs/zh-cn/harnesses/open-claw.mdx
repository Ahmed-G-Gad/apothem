**厂商：** Open-Claw
**安装名称：** `open-claw`
**状态：** 预览版
**原生配置：** `~/.openclaw/openclaw.json`

## 安装

```bash
apothem install --harness open-claw
```

适配器写入 OpenClaw 的用户全局配置文件，将共享配置档案投射为一份配置档案文档，并在工具根目录下安装 Apothem 支持集合。OpenClaw 的原生配置是 JSON；物化器渲染一个键 `skills.load.extraDirs`，而已存在的文件会保留其其他键。

**写入的文件：** `~/.openclaw/openclaw.json`、配置档案文档 `~/.openclaw/apothem/rules/00-apothem-profile.md`，以及 `~/.openclaw/.apothem/support/` 下的支持文件

配置档案文档以一个 Apothem 支持文件小节结尾，该小节写明每条仓库式引用（`rules/<name>.md`、`templates/...`、`hooks/...`）所解析到的、位于 `~/.openclaw/.apothem/support/` 下的绝对目录。

## 配置档案到原生配置的映射

适配器编写一个配置键。它将 `~/.openclaw/.apothem/support/skills` 添加到 `skills.load.extraDirs`，即 OpenClaw 读取的额外技能目录列表，OpenClaw 正是通过它找到已安装的技能。该条目排在你已列出的所有条目之后，你的其他键保持原样。配置档案中的身份、偏好和规则进入配置档案文档。共享的命令、技能、规则、模板和钩子提示词作为支持材料安装在 `~/.openclaw/.apothem/support/` 下。

## 兼容性说明

预览版适配器。OpenClaw 通过 `skills.load.extraDirs` 加载 Apothem 技能，但不会自行加载支持树的其余部分或配置档案文档：它的任何工作区指令文件或配置都不指向那里，因此安装之后，OpenClaw 运行时不带有 Apothem 的规则或 MCP 服务器。

**名称冲突。** OpenClaw 从以下来源读取技能，按优先级从高到低排列，当同一技能名称出现在多个位置时，优先级最高的来源胜出：工作区的 `skills/` 文件夹、工作区的 `.agents/skills/` 文件夹、`~/.agents/skills`（仅限默认状态目录）、状态目录的 `skills/` 文件夹（默认为 `~/.openclaw/skills`）、workshop 技能、捆绑技能和 custodian 技能，最后是 `skills.load.extraDirs` 下列出的文件夹以及插件技能。Apothem 目录是一个 `extraDirs` 条目，因此你保存在任何更早来源中的同名技能才是 OpenClaw 使用的那一个，而该技能的 Apothem 副本会闲置在磁盘上。Apothem 只写入 `openclaw.json` 以及 `~/.openclaw/.apothem/support/` 之下，绝不写入那些更早的文件夹，因此安装、更新和卸载都不会替换你保存在那里的技能。

`agents.defaults.skills` 是技能名称白名单；Apothem 不编辑它，因此如果你保留了一个白名单，请检查它是否写明了你想要的 Apothem 技能。
`apothem update` 会保留你添加到 `openclaw.json` 中的键。MCP 服务器位于 OpenClaw 配置的 `mcp.servers` 块中，你通过 `openclaw mcp add` 及相关子命令进行管理；适配器不在那里写入任何条目。（OpenClaw 的行为依据其[技能](https://docs.openclaw.ai/tools/skills)、[技能配置](https://docs.openclaw.ai/tools/skills-config)和[配置扩展](https://docs.openclaw.ai/gateway/config-extensions)文档（读取于 2026-10-24），以及其 [MCP CLI](https://docs.openclaw.ai/cli/mcp) 文档（读取于 2026-10-02）。）

**`openclaw.json` 中的注释。** OpenClaw 以 JSON5 格式读取其配置，而 Apothem 会将该文件重写为纯 JSON。当该文件带有注释或其他 JSON5 语法且缺少该条目时，Apothem 会保持该文件不变，安装会停止，并显示一条写明该键的消息。请自行将以下条目合并到你的文件中，或将该文件转换为纯 JSON，然后再次运行安装：

```json
{
  "skills": {
    "load": {
      "extraDirs": ["~/.openclaw/.apothem/support/skills"]
    }
  }
}
```

你自己添加的条目算作你的：卸载会将其保留在原处。

## 验证

```bash
apothem verify --harness open-claw
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 每个受管目标都存在；受管文件非空，并且 JSON 或 YAML 配置可以解析。添加 `--profile PATH` 还可以确认已安装的文件与该配置档案相符。
3. 原生配置中的 `skills.load.extraDirs` 列出了 `~/.openclaw/.apothem/support/skills`。没有该条目时，OpenClaw 不会加载已安装的技能；`apothem update` 会将其重新添加。
4. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness open-claw
```

根据当前的共享配置档案状态重新派生配置档案文档，并刷新支持文件；`openclaw.json` 保留其已有的键，并且无论你更新多少次，`skills.load.extraDirs` 中的 Apothem 条目都只列出一次。在编辑 `~/.config/apothem/profile.yaml` 或升级已安装的 Apothem 包之后运行。

## 卸载

```bash
apothem uninstall --harness open-claw
```

移除适配器添加的内容：它在 `skills.load.extraDirs` 中的条目、配置档案文档和支持树。你自己在 `openclaw.json` 中的键会保留，包括你自己的 `extraDirs` 条目，只有当该文件由 Apothem 创建且其中没有你的任何内容时，才会删除该文件。共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness open-claw` |
| 验证失败 | 运行 `apothem update --harness open-claw`，然后再次验证 |
| 意外的配置内容 | Apothem 在 `openclaw.json` 中只编写 `skills.load.extraDirs` 条目，并保留其中已有的键，因此配置档案内容不会落到那里。配置档案内容落在 `~/.openclaw/apothem/rules/00-apothem-profile.md` 中：请检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 [更新](#更新) 下的命令 |
| 安装停止，并显示一条关于 `openclaw.json` 中的注释或 JSON5 语法的消息 | Apothem 不会重写一个需要从中删除注释的文件。请自行添加 [兼容性说明](#兼容性说明) 下所示的 `skills.load.extraDirs` 条目，或将该文件转换为纯 JSON，然后再次运行安装 |
| 某个 Apothem 技能没有出现在 OpenClaw 中 | 工作区、`~/.agents/skills` 或 `~/.openclaw/skills` 中的同名技能优先于 Apothem 副本（参见[兼容性说明](#兼容性说明)）。另外请运行 `apothem verify --harness open-claw`，并检查你保留的任何 `agents.defaults.skills` 白名单是否写明了该技能 |
