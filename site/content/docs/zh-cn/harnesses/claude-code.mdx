**厂商：** Anthropic
**安装名称：** `claude-code`
**状态：** GA
**平台原生配置：** `~/.claude/`

## 安装

```bash
apothem install --harness claude-code
```

`claude-code` 适配器将共享的 Apothem 套组安装到 Claude
Code 的原生发现树中。Markdown 智能体、规则、技能、输出样式、
状态栏辅助工具和设置都安装到它们的原生位置；命令提示词
还会额外封装为技能，使可复用的工作流通过当前的 Claude Code
技能界面保持可见。

**写入的文件：** `~/.claude/` 下的 `settings.json`、`agents/`、`rules/`、
`skills/`、`statuslines/`、`output-styles/` 以及 `apothem/` 支持子树
（`apothem/hooks/`、`apothem/conformity/`、`apothem/schemas/`、
`apothem/templates/`）。命令文件被转换为子技能目录。钩子调度器和合规门从
它们的具现化副本中运行——`settings.json` 的钩子条目通过绝对路径调用
`~/.claude/.apothem/support/hooks/dispatch.py` 和
`~/.claude/.apothem/support/conformity/gate.py`，因此主机上无需任何可导入的
`apothem` 包。

该适配器**不**管理 `CLAUDE.md`——该文件是操作者自有的
领地。Apothem 治理界面通过传播的 `rules/` 树和 SessionStart 钩子触达 Claude
Code，而非通过具现化的 `CLAUDE.md`。

## 配置档案到平台原生配置的映射

在每次 `apothem install` 或 `apothem update` 时，适配器都会按传播清单将
共享的 `apothem` 套组传播到 `~/.claude/` 中。适配器在可能的情况下
直接使用原生目录，并将命令提示词转换为技能文件夹。在替换之前，会先备份
现有的、由 Apothem 管理的匹配子项；不相关的、操作者自行编写的条目会
被保留。`settings.json` 会被合并，以便操作者自行编写的键仍可恢复。

## 兼容性说明

不发生任何转换。安装会校验配置档案格式良好，且 settings.json 中所有钩子绑定均可解析。

Claude Code 在每次会话启动时应用 settings.json 中的所有钩子绑定。每个适配器都针对其自身的原生工具进行验证——不存在享有特权的“参考”工具。

## 验证

```bash
apothem verify --harness claude-code
```

verify 命令确认：

1. 平台原生配置存在于预期路径。
2. 来自共享配置档案的所有必填字段都存在。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness claude-code
```

从当前的共享配置档案重新派生平台原生配置。在已安装的
`apothem` 包更新之后运行，使传播的约定界面（智能体、规则、技能、状态栏、
输出样式）反映新版本。`CLAUDE.md` 由操作者自有，适配器从不触碰它。

## 卸载

```bash
apothem uninstall --harness claude-code
```

移除适配器写入的平台原生配置文件。
已安装的 `apothem` 包和源代码仓库不受影响。

## 合规门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness claude-code` |
| 验证失败 | 运行 `apothem update --harness claude-code`，然后再次验证 |
| 意外的配置内容 | 重新运行 `apothem update`；共享的 `apothem` 配置档案才是真实来源，而非 `~/.claude/` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
