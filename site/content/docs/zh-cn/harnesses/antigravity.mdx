- **厂商：** Google
- **安装名称：** `antigravity`
- **状态：** 预览版
- **原生配置：** `~/.gemini/GEMINI.md` 以及
  `~/.gemini/config/plugins/apothem/`

## 安装

```bash
apothem install --harness antigravity
```

该适配器将共享配置档案渲染到 `~/.gemini/GEMINI.md`，并将 Apothem 支持集合作为一个 Antigravity 插件安装。该插件文件夹由 Antigravity CLI、App 和 IDE 共用，因此三者都会加载该插件。

**写入的文件：** `~/.gemini/GEMINI.md`、`~/.gemini/config/plugins/apothem/plugin.json`、`~/.gemini/config/plugins/apothem/skills/`、`~/.gemini/config/plugins/apothem/rules/`、插件内已转换的本地辅助程序定义、`~/.gemini/config/plugins/apothem/.apothem/support/templates/`，以及 `~/.gemini/config/plugins/apothem/.apothem/support/hooks/`。安装还会创建 Apothem 数据文件夹（默认为 `~/.gemini/.apothem/`），其中包含 `contexts/`、`learning/`、`memory/` 和 `plans/`。

`~/.gemini/GEMINI.md` 中的 Apothem 区块以一个 Apothem 支持文件小节结尾，该小节写明每种仓库风格的引用所解析到的绝对目录：`rules/<name>.md` 位于插件的 `rules/` 下，`templates/...` 和 `hooks/...` 位于插件的 `.apothem/support/` 下。

**插件文件夹。** Antigravity 从 `~/.gemini/config/plugins/<name>/` 加载插件，无需注册步骤（[Antigravity 插件文档](https://antigravity.google/docs/plugins)），适配器会把 Apothem 插件写到那里。当前的 CLI 版本从此文件夹加载插件；CLI 会自行更新，因此如果你用 `AGY_CLI_DISABLE_AUTO_UPDATE=true` 关闭了更新，请先更新它，再依赖该插件。Antigravity App 和 IDE 加载同一个文件夹，因此 Apothem 插件及其始终开启的规则、技能和辅助程序定义在三者中都会生效。Antigravity 没有为插件记载按工具区分的开关：`plugin.json` 中没有任何字段能把插件限定于其中之一。较早的 Apothem 版本把插件写到 CLI 自己的数据文件夹 `~/.gemini/antigravity-cli/plugins/apothem/` 中；在这样的安装之上进行安装或更新时，会备份该文件夹并将其移除（参见[卸载](#卸载)）。

**插件规则。** Antigravity 会丢弃插件 `rules/` 目录中任何不以有效 `trigger` 开头的文件（[Antigravity 规则文档](https://antigravity.google/docs/rules)），因此每条 Apothem 规则都会在安装时被转换。始终适用的规则获得 `trigger: always_on`；限定于特定路径的规则获得 `trigger: glob`，并在 `globs` 中带有相同的模式；其他任何规则获得 `trigger: model_decision`。每条规则都保留其 `description`。有五条规则始终适用：`agnostic-posture`、`authority-inquiry`、`session-closure`、`context-management`，以及规则索引 `apothem-rule-index`，后者指明其他每条规则以及何时读取它。其他规则带有 `trigger: glob`。Antigravity 让所有始终开启的规则共享 20,000 个令牌的预算，超出该预算时会将其中最大的规则转为按需加载的指针；这五条规则总计约 11,000 个令牌，因此没有一条会被转为指针。

**插件清单。** `plugin.json` 只携带 `name` 和 `description`。Antigravity 的[构建插件页面](https://antigravity.google/docs/build-plugins)上发布的插件 schema 要求 `name`，还列出了 `displayName`、`version` 和 `author` 等键，并且不接受其他任何键，因此 `agy plugin validate` 会报告它未列出的键。

**插件辅助程序。** 插件 `agents/` 目录中的辅助程序定义携带 `name` 和 `description`。Antigravity 的 `tools` 列表使用它自己的工具名称，而其文档警告未知名称可能导致子智能体挂起，因此不会生成任何工具列表，辅助程序继承父级的工具。由于 Antigravity 上没有任何机制强制执行只读限制，这些辅助程序的描述会去掉“只读”标签。

**共享的用户锚点。** `~/.gemini/GEMINI.md` 同时也是 Gemini 系列工具的用户级锚点。Antigravity 适配器将其规则、技能、辅助程序定义、模板和钩子文件保留在 `~/.gemini/config/plugins/` 下的 `apothem` 插件内，因此不会占用通用的 Gemini CLI 项目目录。Apothem 数据文件夹位于插件之外，默认为 `~/.gemini/.apothem/`。由于不止一个工具会加载 `~/.gemini/GEMINI.md`，那里的 Apothem 区块被写成全局指引，不把任何单一工具指定为其读取者。

## 配置档案到原生配置的映射

适配器在每次运行 `apothem install` 或 `apothem update` 时读取 Apothem 的共享配置档案，并渲染指令锚点以及支持集合。

## 兼容性说明

预览版适配器。`GEMINI.md` 锚点是生效的指令内容；Antigravity 插件在一个清晰的、Apothem 自有的命名空间中保存已转换的命令技能、可复用技能、本地辅助程序定义、规则、模板以及钩子支持材料。
在适配器拥有针对 Antigravity `hooks.json` 的 schema 转换层之前，钩子文件不会被注册为生效的 Antigravity 钩子事件。

## 验证

```bash
apothem verify --harness antigravity
```

verify 命令确认：

1. 原生上下文文件 `~/.gemini/GEMINI.md` 存在且非空。
2. 插件文件夹中每个受管理的目标都已就位：插件清单 `plugin.json` 存在、非空，并且可以解析为 JSON，且插件的 `skills/`、`rules/`、`agents/`、`.apothem/support/templates/` 和 `.apothem/support/hooks/` 文件夹存在。缺少任何文件夹都会使检查失败。
   验证不会检查插件名称；更改该字段后请自行检查。

添加 `--profile PATH` 可同时确认已安装的文件与该配置档案相符。

## 更新

```bash
apothem update --harness antigravity
```

根据共享配置档案的当前状态重新派生原生配置。在编辑 `~/.config/apothem/profile.yaml` 或升级已安装的 Apothem 包之后运行。

## 卸载

```bash
apothem uninstall --harness antigravity
```

从 `~/.gemini/GEMINI.md` 中移除 Apothem 区块，并保留其中的其他任何文本。仅当其中不再剩有任何其他内容时，才会删除该文件。同时从插件文件夹 `~/.gemini/config/plugins/apothem/` 中的 `plugin.json` 移除 Apothem 的键并保留你自己的键，并移除该文件夹 `skills/`、`rules/`、`agents/` 和 `.apothem/support/` 子文件夹中的 Apothem 文件；其中的其他文件保持不变。数据文件夹中的 `memory/`、`contexts/` 和 `learning/` 存储也会被移除，除非另一个 Apothem 安装仍在使用它们。每个文件在被更改或移除之前，都会先备份到 `~/.apothem/backups/` 下。共享配置档案 YAML 和 Apothem 引擎不受影响。

由较早版本完成的安装把插件保存在 CLI 自己的数据文件夹 `~/.gemini/antigravity-cli/plugins/apothem/` 中。在这样的安装之上进行安装、更新或卸载时，会把该文件夹备份到 `~/.apothem/backups/` 下并将其移除，其中你自己的文件也包括在内。位于该路径、其上级或该文件夹内部的符号链接或 Windows 联接点会保留原样，并给出指明它的警告，它所指向的任何内容都不会被更改或备份。该路径上指向当前插件文件夹的链接在每次运行时都会保留原样并给出警告：卸载后它仍然存在，因此一旦不再有任何东西使用旧路径，请自行删除它。因此，卸载会移除较早的文件夹，而在当前文件夹中只移除上述 Apothem 文件。它会打印每条警告，并且在移除较早文件夹失败时报告失败而不是成功。

每次安装、更新和卸载还会把 `~/.antigravity/profile.yaml` 备份到 `~/.apothem/backups/` 下，然后将其移除。没有任何 Apothem 版本会写入该文件，因此在运行这些命令之一之前，请把你自己放在那里的文件移走。

安装、更新和卸载从不触及 Antigravity App 的数据文件夹 `~/.gemini/antigravity/`。（CLI 的数据文件夹是 `~/.gemini/antigravity-cli/`，IDE 的是 `~/.gemini/antigravity-ide/`。）App 的文件夹保存其 MCP 服务器的登录令牌（`mcp_oauth_tokens.json`）、会话记录（`brain/`）、旧版全局技能文件夹（`skills/`）以及 `sidecar_data/`。较早的版本把该文件夹当作 Apothem 在首次发布之前使用过的布局：它们在每次安装和更新时都把它备份到 `~/.apothem/backups/` 下并将其移除。CLI 自己的设置和会话历史（位于 `~/.gemini/antigravity-cli/`）未受影响。

如果你的某个 App 登录、会话记录或技能丢失了，副本位于 `~/.apothem/backups/<timestamp>/antigravity/.gemini/antigravity/`：每个发现了该文件夹的较早安装或更新各有一组，每组保存该文件夹在当时的状态。Apothem 只保留最新的 10 组 Antigravity 备份，因此较早安装的副本可能已经不在了，而下一次安装、更新、卸载或回滚还会再次清理。请先把你需要的备份组从 `~/.apothem/backups/` 中复制出来。

## 合规闸门

```bash
python3 -E -s ~/.apothem/src/apothem/conformity/gate.py --all .
```

请在你的项目文件夹中运行它。在 Windows 上，请用 `python` 代替 `python3`，并使用完整路径，因为 Windows PowerShell 和 cmd 不会展开 `~`：PowerShell 中为 `$HOME\.apothem\src\apothem\conformity\gate.py`，cmd 中为 `%USERPROFILE%\.apothem\src\apothem\conformity\gate.py`。该路径是安装程序放置引擎的位置，`-E -s` 让你的 `PYTHONPATH` 和用户 site-packages 不会进入闸门；[合规闸门](/docs/conformity-gate)解释了这两点以及其他安装方式。

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness antigravity` |
| 验证失败 | 运行 `apothem update --harness antigravity`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness antigravity` |
