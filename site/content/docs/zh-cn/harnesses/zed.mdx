**厂商：** Zed Industries
**安装名称：** `zed`
**状态：** GA
**平台原生配置：** `<project>/.rules`

## 安装

```bash
apothem install --harness zed --project /path/to/project
```

适配器从共享的 Apothem 规则和治理界面写出一个项目范围的 Zed 指令文件。Zed
将项目根目录下的单个扁平 `.rules` 文件（与 `AGENTS.md` / `CLAUDE.md` 家族并列）
读取为指令；它没有按工具划分的规则目录，因此整个 Apothem 界面都落在这一个
文件中。

**写入的文件：** `<project>/.rules`

## 配置档案到平台原生配置的映射

适配器读取 Apothem 的共享配置档案，并在每次 `apothem install` 或 `apothem update`
运行时渲染项目 `.rules` 文件。共享配置档案才是真实来源；在下一次同步替换由
Apothem 管理的内容之前，任何已存在的 `.rules`（或对生成文件的项目本地编辑）
都会先被备份。

## 兼容性说明

Zed 当前的指令界面是项目根目录下的扁平 `.rules` 文件。全局
`~/.config/zed/AGENTS.md` 指令文件和 MCP 上下文服务器块
（`.zed/settings.json` 的 `context_servers`）由操作者自有；Apothem 不会写入它们。

## 验证

```bash
apothem verify --harness zed --project /path/to/project
```

verify 命令确认：

1. 平台原生配置存在于预期路径。
2. 共享配置档案中的所有必填字段都存在。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness zed --project /path/to/project
```

从当前的共享配置档案状态重新派生项目 `.rules` 文件。

## 卸载

```bash
apothem uninstall --harness zed --project /path/to/project
```

移除适配器写入的平台原生配置文件，先将其重命名为带时间戳的备份。共享配置档案
YAML 和 Apothem 引擎不受影响。

## 合规门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness zed --project /path/to/project` |
| 验证失败 | 运行 `apothem update --harness zed --project /path/to/project`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness zed --project /path/to/project` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
