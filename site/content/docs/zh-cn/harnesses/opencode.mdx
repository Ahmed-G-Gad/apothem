**厂商：** OpenCode
**安装名称：** `opencode`
**状态：** 测试版
**原生配置：** `~/.config/opencode/`（或 `$XDG_CONFIG_HOME/opencode/`）

## 安装

```bash
apothem install --harness opencode
```

适配器写入 OpenCode 的 JSON 配置，将 Apothem 技能安装到 OpenCode 技能表面，将命令提示词转换为 OpenCode Markdown 命令文件，并将 Apothem 辅助器定义规范化为 OpenCode 子辅助器。

**写入的文件：**

```text
~/.config/opencode/opencode.json
~/.config/opencode/apothem/rules/00-apothem-profile.md
~/.config/opencode/commands/
~/.config/opencode/skills/
~/.config/opencode/agents/
~/.config/opencode/.apothem/support/{rules,templates,hooks}/
```

以上是默认路径。当 `XDG_CONFIG_HOME` 设置为某个文件夹的绝对路径时，适配器会改为写入 `$XDG_CONFIG_HOME/opencode/`，这是 OpenCode 1 和 OpenCode 2 都会读取的文件夹。相对路径的值或文件系统根目录不会被使用，安装会指出这一点。`OPENCODE_CONFIG_DIR` 不会被遵循：OpenCode 1 会在读取默认文件夹的同时读取该文件夹，而 OpenCode 2 则改读该文件夹，不再读取默认文件夹，因此当该变量指向另一个文件夹时，安装会警告 OpenCode 2 不会加载此安装。

## 配置档案到原生配置的映射

适配器渲染 `opencode.json`，其中的 `instructions` 文件列表指明你的配置档案文档、四条核心规则和规则索引，然后将每个共享的 Apothem 集合传播到 OpenCode 原生表面或 Apothem 自有的支持子树中。现有的、匹配的 Apothem 管理子项会在替换之前被备份。

## 兼容性说明

该安装同时适用于 OpenCode 1 和 OpenCode 2。它写入一份配置，OpenCode 1 按原样读取，OpenCode 2 则对其进行转换：两者读取同一个配置文件夹，OpenCode 2 会在内存中转换安装所写入的 OpenCode 1 形式，而不重写该文件。辅助器的 `permission` 列表和 `mcp` 服务器条目通过这一转换在 OpenCode 2 中加载。OpenCode 1 还会加载 Claude Code 安装写入 `~/.claude/CLAUDE.md` 的块，条件是 OpenCode 1 的配置文件夹中不存在 `AGENTS.md`，且 `OPENCODE_DISABLE_CLAUDE_CODE` 与 `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT` 均未设置；OpenCode 2 没有 `CLAUDE.md` 回退，因此不会加载该文件。

辅助器定义只包含 `deny` 规则，用于辅助器不得使用的工具。OpenCode 默认允许每一个工具，并会在读取 `.env` 或 `.env.*` 文件之前询问。辅助器中的 `allow` 规则会关闭这一询问，并会覆盖你自己的 OpenCode 配置中更严格的规则，因此辅助器遵循你的 `permission` 设置。

当共享配置档案列出 MCP 服务器时，安装会将它们写入 `opencode.json` 的 `mcp` 块。OpenCode 会替换 `{env:NAME}`，而不会替换 `${NAME}`，因此服务器的环境变量、请求头或 URL 中的每个 `${NAME}` 引用都会被写成 `{env:NAME}`。命令参数按原样复制：其中的引用留给服务器或它运行的 shell 去展开。环境变量或请求头值中的 `$NAME`，以及任何按原样保留的 `${...}` 形式（包括命令参数中的），都会按原样复制，并且安装会警告 OpenCode 不会展开它们。该警告会指出引用所在的位置，例如 `environment.TOKEN`，并且绝不打印该值。

OpenCode 会将 `{env:NAME}` 的值不经转义地插入它所读取的配置文本；只有当该文本否则无法解析时，OpenCode 2 才会对其转义。因此，包含反斜杠（例如 Windows 路径）、双引号或控制字符的值可能导致 OpenCode 1 无法读取该文件，并且在两个版本中，值中的 `\t` 或 `\n` 都会作为控制字符到达服务器。安装会在运行时检查每个这样的变量，并对包含这些字符的变量发出警告。请改为在 `harnesses.opencode.mcp_servers.<name>` 下将该值设置为 `{file:path}`，这样其他工具就能保留 `${NAME}` 引用。

OpenCode 会将 `instructions` 列表指明的每个文件合并到每个会话中（[OpenCode 规则](https://opencode.ai/docs/rules/)）。因此，该列表首先指明你的配置档案文档，然后只列出 `alwaysApply` 为 `true` 的规则，每条规则一个明确的路径，默认为 `~/.config/opencode/.apothem/support/rules/<name>.md`。OpenCode 会将开头的 `~/` 展开为你的主目录；当配置文件夹位于主目录之外时，路径为绝对路径，而支持树始终位于配置文件夹之下。这些规则是 `agnostic-posture`、`authority-inquiry`、`context-management`、`session-closure`，以及规则索引 `apothem-rule-index`。OpenCode 不按路径限定任何规则，因此其他每条规则都按需读取。它们仍作为参考材料安装在 `~/.config/opencode/.apothem/support/` 下，而该索引指明每条规则以及需要用到它的情形。引用某条规则、模板或钩子提示词的规则、技能或命令会从那里读取它。命令、技能和辅助器定义使用原生发现位置。

配置档案文档 `~/.config/opencode/apothem/rules/00-apothem-profile.md` 携带共享配置档案中你的身份和偏好，并以一个 Apothem 支持文件小节结尾，该小节写明每条仓库式引用（`rules/<name>.md`、`templates/...`、`hooks/...`）所解析到的、位于 `~/.config/opencode/.apothem/support/` 下的绝对目录。它是第一个 `instructions` 条目，因此 OpenCode 会在每个会话中加载它。

由较早发布写入的 `opencode.json` 列出单个通配模式 `~/.config/opencode/.apothem/support/rules/*.md`，它会加载每条规则；或者为当时始终启用的 28 条规则各列出一个明确的路径。`apothem
install` 和 `apothem update` 会将任一形式替换为上述列表，从而去掉不再在启动时加载的 24 个路径，而 `apothem uninstall` 会移除所有这些条目。在任何情况下，你自己的 `instructions` 条目都会被保留。

## 验证

```bash
apothem verify --harness opencode
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 每个受管目标都存在；受管文件非空，并且 JSON 或 YAML 配置可以解析。添加 `--profile PATH` 还可以确认已安装的文件与该配置档案相符。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness opencode
```

刷新 `opencode.json`、原生命令、技能、辅助器定义以及 Apothem 支持树。由安装写入、被你转换为 OpenCode 2 的 `mcp.servers` 形态且未作更改的 MCP 服务器，会被写回 `mcp` 下，两个 OpenCode 版本都会从那里读取它。只有当 `mcp.servers` 下的服务器在 `mcp` 中的条目已不存在，并且整体上与安装所写入的内容相符时，它才会被视为这种转换；你自己的同名服务器、你编辑过的转换以及你禁用的转换会保持原样。在保留这种转换的同时，更新还会再次将该服务器写入 `mcp` 下，因此 OpenCode 1 使用该副本，OpenCode 2 使用转换后的副本；若要在两个版本中都让该服务器保持关闭，请将其从配置档案中移除。这需要一份列出了安装所写入条目的安装记录；Apothem 开始保留该列表之前的记录不在涵盖范围内。

## 卸载

```bash
apothem uninstall --harness opencode
```

移除适配器添加到 `~/.config/opencode/opencode.json` 的条目（你自己的键、MCP 服务器和 `instructions` 条目会保留；只有当该文件由 Apothem 创建且其中没有你的任何内容时，才会删除该文件）。由安装写入、被你转换为 OpenCode 2 的 `mcp.servers` 形态且未作更改的 MCP 服务器也会被整体移除；`mcp.servers` 下的其他服务器会保留。你自己放在 `mcp.servers` 下、且与安装写入的某个服务器相符的服务器，在你移除了安装的 `mcp` 条目之后，将无法与转换后的副本区分，并会随之被移除；该文件会先被备份。从配置档案文档 `~/.config/opencode/apothem/rules/00-apothem-profile.md` 中移除 Apothem 块，并保留其中的其他任何文本；只有当该文件中不再剩下其他内容时，才会删除该文件。同时移除 `~/.config/opencode/commands/`、`~/.config/opencode/skills/`、`~/.config/opencode/agents/` 和 `~/.config/opencode/.apothem/support/` 中的 Apothem 文件；这些文件夹中的其他文件会保留。每个文件在被更改或移除之前，都会先备份到 `~/.apothem/backups/` 下。共享配置档案 YAML 和 Apothem 引擎不受影响。

由较早发布的版本在 `XDG_CONFIG_HOME` 指向另一个文件夹时于 `~/.config/opencode/` 中完成的安装会留在那里，OpenCode 从未读取过它。下一次安装会指出这一点；若要移除它，请在未设置 `XDG_CONFIG_HOME` 的情况下运行卸载。

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness opencode` |
| 验证失败 | 运行 `apothem update --harness opencode`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness opencode` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
