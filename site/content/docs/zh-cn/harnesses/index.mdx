Apothem 内置十七个工具适配器。每个适配器在平台支持的情况下将同一份共享集合转换为平台原生文件，在平台不支持的情况下则转换为 Apothem 自有的支持树。

## 受支持的工具

受支持的注册表恰好包含十七个适配器。请将这些精确的安装名称与 `--harness` 一起使用，或使用 `all` 来选择确定性的注册表集合：

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

详细的注册表矩阵、目标路径、能力状态、MCP 支持以及约定锚定证据见[技术注册表参考](/docs/reference/harness-registry)。

## 安装多个工具

安装单个工具，或使用 `all` 以确定性顺序选择整个注册表。项目作用域的工具需要 `--project PATH`；这包括 `all`，因为注册表同时包含用户作用域和项目作用域的目标。

```bash
apothem install --harness claude-code
apothem install --harness cursor --project /path/to/project
apothem install --harness gemini-cli --project /path/to/project
apothem install --harness all --project /path/to/project
```

## 验证你的安装

逐个验证每个工具适配器，或调用 `apothem doctor` 以获取覆盖每个已注册适配器、按适配器划分的安装状态汇总：

```bash
apothem verify --harness claude-code
apothem verify --harness all --project /path/to/project
apothem doctor
```

## 适配器的工作原理

每个适配器都实现了通过 setuptools 入口点注册的 `HarnessAdapter` 协议。在安装时，CLI 加载并校验共享 YAML 配置档案，通过注册表解析适配器，校验具现化方案，然后将平台原生配置写入工具的原生用户或项目位置。在更新时，它从当前的配置档案状态重新派生。

```
profile.yaml + packaged cohorts
    identity / preferences / rules
    commands / skills / delegated definitions / hooks / templates
         |
         +-- antigravity    --> ~/.gemini/GEMINI.md + ~/.gemini/antigravity-cli/plugins/apothem/
         +-- claude-code    --> ~/.claude/ native folders + ~/.claude/.apothem/support/
         +-- codex          --> ~/.codex/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- cursor         --> <project>/.cursor/rules/*.mdc + <project>/.cursor/agents/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- gemini-cli     --> <project>/GEMINI.md + <project>/.gemini/
         +-- github-copilot --> <project>/.github/copilot-instructions.md + <project>/.github/agents/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- windsurf       --> <project>/.devin/rules/ + <project>/.devin/agents/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- ...
```

## 你用户主目录中的技能

有七个项目范围的适配器会向你的项目写入一个规则文件（其中六个还会将 Apothem 的辅助器作为子代理文件写入项目；每个工具页面都会指出该文件夹），并且它们还会将 Apothem 的技能以及这些技能引用的规则和模板写入你用户主目录中的文件夹：

```text
cursor, github-copilot, windsurf, zed  ->  ~/.agents/skills/ (codex writes it too)
codebuddy                               ->  ~/.codebuddy/skills/
kiro                                    ->  ~/.kiro/skills/
trae                                    ->  ~/.trae/skills/
all seven                               ->  ~/.config/apothem/rules/ and templates/ (codex uses them too)
```

- 每个指定某个文件夹的安装都写入相同的文件，因此安装的顺序无关紧要，一份副本即可服务于每个项目。
- 安装会最先写入主目录中的文件夹。如果写入失败，它会在改动项目之前停止，并且不会向你的仓库添加任何技能或规则文件。
- 只有当没有其他 Apothem 安装仍在使用某个共享文件夹时，卸载才会移除它，并会说明是哪一次安装保留了它。
- 与某个 Apothem 技能同名、但并非由 Apothem 写入的技能文件夹会保持原样，并伴有一条警告。

每个工具页面都列出了它的文件夹。[工具注册表](/docs/reference/harness-registry#共享根目录)显示了哪些工具共享哪个文件夹。

协议规范参见[工具适配器抽象](/docs/architecture/harness-adapter-abstraction)。
