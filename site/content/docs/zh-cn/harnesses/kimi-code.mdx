**厂商：** Moonshot
**安装名称：** `kimi-code`
**状态：** GA
**原生配置：** `<project>/AGENTS.md` 以及 `<project>/.kimi-code/.apothem/support/`

## 安装

```bash
apothem install --harness kimi-code --project /path/to/project
```

适配器将共享的 Apothem 治理表面以一个由哨兵标记分隔的受管块写入项目根目录的 `AGENTS.md`（哨兵标记之外由操作者编写的文字会被保留），并将非原生的 Markdown 集合保存在位于 `<project>/.kimi-code/.apothem/support/` 的 Apothem 自有支持树下。除 Kimi Code 之外，还有许多编码工具会读取项目的 `AGENTS.md`，因此该块被写成面向整个项目的指导，不把任何单一工具指定为其读者。

Kimi Code 遵循通用的 AGENTS.md 约定读取项目根目录的 `AGENTS.md` 指令文件，项目配置位于 `<project>/.kimi-code/` 下。`<project>/.kimi-code/mcp.json` 表面归操作者所有；Apothem 会指明它，但不编写任何条目。

**写入的文件：** `<project>/AGENTS.md`（受管块），以及 `<project>/.kimi-code/.apothem/support/` 下的命令、技能、钩子、智能体、规则和模板集合。

## 配置档案到原生配置的映射

适配器读取 Apothem 的共享配置档案，并在每次 `apothem install` 或 `apothem update` 运行时渲染项目根目录的 `AGENTS.md` 指令表面。行为规则和治理语料落在 `AGENTS.md` 的受管块中；命令、技能、钩子、智能体、规则和模板集合被放置在 `.kimi-code/.apothem/support/` 下，并从指令表面引用。这是适配器所选择的布局，而不是 Kimi Code 的缺口：Kimi Code 从 `.kimi-code/skills/` 和 `.agents/skills/` 加载技能，从 `.kimi-code/agents/` 和 `.agents/agents/` 加载自定义智能体，并从 `~/.kimi-code/config.toml` 中的 `[[hooks]]` 数组加载钩子，但它不会从支持树加载这些内容，因此 Apothem 放在那里的副本是 `AGENTS.md` 块所指向的参考材料。该块以一个 Apothem 支持文件小节结尾，该小节以相对于项目根目录的形式，指明每种仓库风格的引用（`rules/<name>.md`、`templates/...`、`hooks/...`）所解析到的 `.kimi-code/.apothem/support/` 下的目录，因此已提交的 `AGENTS.md` 不携带任何特定于机器的路径。（Kimi Code 的行为依据其关于[技能](https://moonshotai.github.io/kimi-code/en/customization/skills)、[子智能体](https://moonshotai.github.io/kimi-code/en/customization/agents)和[钩子](https://moonshotai.github.io/kimi-code/en/customization/hooks)的自定义页面，读取于 2026-10-02。）

## 兼容性说明

Kimi Code 从 `AGENTS.md` 或 `.kimi-code/AGENTS.md` 读取项目指令，并将 `.kimi-code/mcp.json` 识别为归操作者所有的 MCP 表面；Apothem 会指明该表面，但不向其中编写任何条目。渲染出的指令表面直接驱动该项目。Kimi Code 不暴露状态栏或输出样式文件表面，因此这些集合不会被物化。

Kimi Code 运行在 Moonshot 的 Kimi 模型系列上；当前的模型和配置表面参见[厂商配置参考](https://moonshotai.github.io/kimi-code/en/configuration/config-files)。

## 验证

```bash
apothem verify --harness kimi-code --project /path/to/project
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 每个受管目标都存在；受管文件非空，并且 JSON 或 YAML 配置可以解析。添加 `--profile PATH` 还可以确认已安装的文件与该配置档案相符。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness kimi-code --project /path/to/project
```

根据当前的共享配置档案状态，重新派生项目根目录 `AGENTS.md` 的受管块和支持集合。

## 卸载

```bash
apothem uninstall --harness kimi-code --project /path/to/project
```

移除项目根目录 `AGENTS.md` 中的 Apothem 块，并保留哨兵标记之外的所有文本。只有当文件中已无其他内容时才会删除该文件。同时移除 Apothem 放置在 `<project>/.kimi-code/.apothem/support/` 下的支持文件。在变更之前，会在 `~/.apothem/backups/` 下保存每个文件的一份带时间戳的副本；项目中不会留下备份文件。共享配置档案 YAML 与 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness kimi-code --project /path/to/project` |
| 验证失败 | 运行 `apothem update --harness kimi-code --project /path/to/project`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness kimi-code --project /path/to/project` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
