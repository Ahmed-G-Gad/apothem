**厂商：** Google
**安装名称：** `gemini-cli`
**状态：** GA
**原生配置：** 项目本地的 `GEMINI.md` 和 `.gemini/`

## 安装

```bash
apothem install --harness gemini-cli --project /path/to/project
```

该适配器是项目级的。它安装项目的 `GEMINI.md`，将 Apothem 命令转换为 Gemini TOML 斜杠命令，规范化本地辅助程序定义，并将非原生的支持集合放置在 `.gemini/.apothem/support/` 下。其他编码工具也会读取项目的 `GEMINI.md`，因此其中的 Apothem 区块被写成项目范围的指引，不把任何单一工具指定为其读者。

**写入的文件：**

```text
GEMINI.md
.gemini/commands/*.toml
.gemini/agents/*.md
.gemini/skills/
.gemini/.apothem/support/
```

## 配置档案到原生配置的映射

适配器读取 Apothem 的共享集合，并将每个集合经由一个与 Gemini 兼容的表面进行路由。Markdown 规则、模板和钩子材料保留在 `.gemini/.apothem/support/` 下，因为它们是支持材料，而不是 Gemini 原生的规则目录。
`GEMINI.md` 中的 Apothem 区块以一个 Apothem 支持文件小节结尾，该小节以相对于项目根目录的形式，写明每种仓库风格的引用（`rules/<name>.md`、`templates/...`、`hooks/...`）所解析到的 `.gemini/.apothem/support/` 下的目录。这些路径是相对路径，因此已提交的 `GEMINI.md` 不携带任何特定于机器的路径。

`.gemini/commands/` 中每个转换后的命令都包含一个 `description` 和一个 `prompt`。提示词只包含该命令的指令；源文件顶部的 Apothem 元数据（版本、工具列表及类似字段）被省略，因此模型绝不会将其当作指令读取。Gemini 只有在你输入自定义命令时才会运行它。

`.gemini/agents/` 中的辅助程序定义保留其工具限制和轮次限制：源文件中的 `tools` 授权减去 `disallowedTools` 后，成为一个由 Gemini 工具名称组成的 Gemini `tools` 允许列表，`maxTurns` 则变为 `max_turns`。因此，只读的辅助程序不会获得 `write_file` 或 `replace` 工具。不设置任何模型，因此每个辅助程序都继承会话模型。

## 兼容性说明

对于使用全局 Gemini 配置档案的工具，`~/.gemini/` 仍属于用户级范围。Gemini CLI 适配器只写入通过 `--project` 传入的项目。

## 验证

```bash
apothem verify --harness gemini-cli --project /path/to/project
```

verify 命令确认：

1. 原生配置存在于预期路径。
2. 来自共享配置档案的所有必填字段都存在。
3. 适配器专属的验证例程报告成功。

## 更新

```bash
apothem update --harness gemini-cli --project /path/to/project
```

刷新 `GEMINI.md`、已转换的命令、本地辅助程序定义、已安装的技能，以及 `.gemini/.apothem/support/` 支持树。

## 卸载

```bash
apothem uninstall --harness gemini-cli --project /path/to/project
```

移除适配器写入的原生配置文件。
共享配置档案 YAML 和 Apothem 引擎不受影响。

## 合规闸门

```bash
python -m apothem.conformity.gate --all .
```

## 故障排查

| 症状 | 修复方法 |
|---------|-----|
| 找不到配置文件 | 重新运行 `apothem install --harness gemini-cli --project /path/to/project` |
| 验证失败 | 运行 `apothem update --harness gemini-cli --project /path/to/project`，然后再次验证 |
| 意外的配置内容 | 检查 `~/.config/apothem/profile.yaml` 或 `--profile PATH`，然后重新运行 `apothem update --harness gemini-cli --project /path/to/project` |

## 配置开关

| 标志 | 默认值 | 说明 |
|------|---------|-------------|
| `--dry-run` | `false` | 预览安装而不写入文件。 |
