这是从零到一份经过验证的工具配置的快速路径：安装、编写共享配置档案、物化一个工具的原生配置、确认它，并完成你的第一次编辑。每条命令都是真实的，可以复制粘贴运行，每一步都会展示一次干净运行所打印的内容。安装本身在两分钟内完成；编辑配置档案是唯一一个耗时由你自己决定的环节。

读完本页，你将拥有一份由你自己编写的配置档案生成的可用工具配置——并且你会知道那一条将配置档案的变更推送回每个工具的命令。

<Callout title="想要节奏更慢、带讲解的版本？">
  [入门教程](/docs/tutorials/getting-started)覆盖同样的内容，并对每一步及其重要性给出更多解释。本页是简洁、以输出为先的导览。
</Callout>

你将使用 **Claude Code** 作为示例工具——它是安装器的默认值。在任意一步替换适配器名称，即可指向另一个工具；[工具列表](/docs/harnesses)列出了每个受支持的名称。

## 1. 安装 Apothem

Apothem 以自包含运行时的形式发布——引擎携带 vendored 依赖，直接从其源码树运行。一条命令即可获取源码、放置引擎并物化你的第一个工具：

```bash title="macOS · Linux · WSL2"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell 7+"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

安装器要求系统中有可导入 `click` 和 `rich` 的 Python 3.10+，网络形式还需要 `git`。它会检查前置条件，将引擎放置在 `~/.apothem` 下，并在完成时打印适用于你所用 shell 的确切引擎调用方式：

```text
Installation complete.

The 'apothem' command is on your PATH.

Recommended first step — the guided setup (profile -> preview -> install):

  apothem quickstart
```

<Callout title="没有配置档案时的首次运行">
  如果你还没有配置档案，安装器会将示例配置档案复制到 `~/.config/apothem/profile.yaml` 并继续执行：它会在同一次运行中物化你的第一个工具并验证它。示例中的身份字段是占位值，因此安装会打印一条提示。在第 2 步中将配置档案改成你自己的，然后按照第 5 步的做法，用 `apothem update --harness <name>` 应用它。
</Callout>

<Callout title="`apothem` 命令">
  安装器会在你的 `PATH` 上放置一个 `apothem` 垫片，因此你可以直接以 `apothem <command>` 的形式运行引擎。如果该垫片所在的目录尚未加入 `PATH`，横幅会打印一个无需垫片的自包含回退方式——`PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>`——请将你的横幅所打印的确切前缀加在每条命令之前。
</Callout>

[安装指南](/docs/install)介绍了其他安装路径——Claude Code 插件（先运行 `/plugin marketplace add ahmed-g-gad/apothem`，再运行 `/plugin install apothem@apothem`）；VS Code 系列扩展以及其他工具原生扩展；以及按需运行的 npx 形式（`npx @ahmed-g-gad/apothem <command>`）——同时还介绍了各项环境变量选项。

## 2. 创建共享配置档案

`apothem profile init` 会将最小的、符合 schema 的配置档案写入 `~/.config/apothem/profile.yaml`。当你将某个项目专用或 CI 专用的配置档案保存在别处时，传入 `--profile PATH`。

```bash
apothem profile init
apothem profile show --json
```

该脚手架使用虚构的占位身份数据，在你安装任何工具输出之前编辑它是安全的。`show --json` 会将其读回并报告经过校验的配置档案：

```json
{
  "identity": {
    "name": "Example User",
    "email": "dev@example.invalid",
    "github": "example-user"
  }
}
```

格式错误的编辑也会在这里暴露出来——如果 YAML 无效，`show` 会在此处报告，早于任何工具配置被写入。使用 `apothem profile edit`（在你的编辑器中打开它）将配置档案改成你自己的，或者就地设置单个键：

```bash
apothem profile set identity.name "Your Name"
```

## 3. 安装工具适配器

物化你的主要工具所对应的适配器。这会读取你的配置档案，并写入该工具的原生配置：

```bash
apothem install --harness claude-code
```

```text
✓ Installed claude-code -> /home/you/.claude/settings.json
```

项目作用域的适配器写入项目内部，而不是你的主目录，因此它们需要一个 `--project PATH`。使用 `--dry-run` 可以预览任意安装而不写入文件：

```bash
apothem install --harness cursor --project . --dry-run
apothem install --harness cursor --project .
```

使用 `--harness all` 一次性安装由注册表支撑的整个集合。由于该选择会同时写入项目作用域和用户作用域的文件，命令会打印按位置分组的具体目标，并在写入项目根目录之外的位置之前请求确认：

```bash
apothem install --harness all --project .
```

每个受支持的名称见[完整工具列表](/docs/harnesses)，完整的选项集见 [install 参考](/docs/cli-reference/install)。

## 4. 验证

物化只完成了一半的工作——`verify` 会确认该工具预期的配置文件已经落地，并且与配置档案所声明的内容相符：

```bash
apothem verify --harness claude-code
```

```text
✓ claude-code is verified at /home/you/.claude/settings.json
```

如果配置缺失或发生了漂移，`verify` 会以非零状态退出，因此它也可以在配置脚本中充当闸门。要对每个已注册的适配器进行一次全机健康检查，运行：

```bash
apothem doctor
```

`doctor` 会检查每个已安装的工具：它必须通过验证，并且其安装所注册的每条钩子命令都必须能够启动。你尚未安装的工具会被列出，但不算失败，因此在只有一个健康工具的情况下，`doctor` 以 0 退出。

## 5. 你的第一次运行

打开你刚配置好的工具——本例中是 Claude Code——并在任意项目中启动一个会话。你在第 2 步中写入配置档案的规则和偏好，现在已成为该工具行为的一部分。这就是一次可用的首次运行：一份配置档案，塑造一次真实的会话。

之后修改配置档案时，无需重新安装即可重新应用它：

```bash
apothem update --harness claude-code
```
