Cursor 读取 `.cursor/rules/` 下 MDC 格式的规则。MDC 格式要求若干 frontmatter
字段——`description`、`globs` 和 `alwaysApply`。Apothem 的 cursor 适配器从
共享配置档案渲染一个 `.mdc` 规则文件。本页将手工维护该配置与用 Apothem 管理它
加以对比。

## 工夫对比

| 任务 | 手工配置 | Apothem 管理 |
| ---- | --------------- | --------------- |
| 编写规则 | 在 `.cursor/rules/` 下手工编写每个 `.mdc` 文件 | 从共享语料库渲染 |
| 编写 MDC frontmatter | 逐个文件手工编写 `description` / `globs` / `alwaysApply` | 由适配器生成 |
| 保持单一规则格式 | 在 MDC 规则与单个 `.cursorrules` 文件之间手工取舍 | 适配器写入一个 MDC 文件 `.cursor/rules/apothem-rules.mdc`，不写 `.cursorrules` |
| 让规则与其他工具保持对齐 | 手工，逐工具 | 在 `apothem update` 时自动完成 |
| 共享可复用的技能和命令 | 把每个技能文件夹手工复制到 `~/.agents/skills/` 并保持这些副本最新 | 由适配器写入 `~/.agents/skills/`，所有项目共用一份副本，并在 `apothem update` 时刷新 |
| 验证配置是否正确 | 手工检查 | `apothem verify --harness cursor --project <path>` |

## Apothem 管理什么

cursor 适配器把共享规则渲染为一个 `.mdc` 文件
`<project>/.cursor/rules/apothem-rules.mdc`，并生成所需的 MDC frontmatter
（`description`、`globs`、`alwaysApply`）。适配器
只写 Cursor 读取的基于目录的 MDC 格式；它不写单一文件的 `.cursorrules`。
它还把技能以及包装为技能的命令写入 `~/.agents/skills/`，并把这些技能引用的
规则和模板写入 `~/.config/apothem/`，两者都位于你的主目录中。
Cursor 在 `hooks.json` 文件中以及通过其插件格式记载钩子。适配器不构建插件；
它向项目的 `.cursor/hooks.json` 添加一个 `sessionStart` 条目，用于加载会话引导，
并保留你自己的条目不变。它不注册工具调用守卫，因此护栏意图存在于规则散文之中。

## 迁移路径

1. 如果你还没有创建共享配置档案，运行 `apothem profile init` 来创建它。
2. 把现有 `.cursor/rules/`（以及任何 `.cursorrules`）中的规则移入共享语料库。
3. 运行 `apothem install --harness cursor --project <path>`，以渲染带有正确 MDC frontmatter 的 `apothem-rules.mdc`。
4. 运行 `apothem verify --harness cursor --project <path>` 来确认配置已落地。
5. 之后的每次更改都使用 `apothem update --harness cursor --project <path>`。
