Open-Claw 读取 `~/.openclaw/openclaw.json`。Apothem 在
`~/.openclaw/.apothem/support/skills/` 下安装共享的命令集合和技能集合，并在其中编写
一个键 `skills.load.extraDirs`，该键列出这个目录，以便 OpenClaw 加载这些技能。它的
`agents.defaults.skills` 是一个归你所有的名称白名单，且 MCP 是一个 CLI 面，因此
Apothem 两者都不编写。

## 状态

**预览。** Open-Claw 适配器面向当前已文档化的配置文件和额外的技能目录面。非技能
集合仍属于 Apothem 支持材料。

## 工作量对比

| 任务 | 原生手工配置 | Apothem 管理 |
| ---- | --------------- | --------------- |
| 编写可复用技能 | 手工编辑配置和技能目录 | 在共享语料中编写一次 |
| 让各工具的集合保持一致 | 逐工具手动 | `apothem update` 时自动 |
| 安装 / 移除配置 | 手动 | `apothem install` / `apothem uninstall` |
| 验证配置是否正确 | 手动检查 | `apothem verify --harness open-claw` |

## Apothem 管理什么

Open-Claw 适配器写入 `openclaw.json`，把 Apothem 斜杠命令封装为技能，把 Apothem
技能复制进被引用的支持目录，并把规则、模板、agents 与钩子材料保留在 Apothem
支持子树下。
OpenClaw 以其技能来源中最低的优先级读取 `skills.load.extraDirs`，因此你的工作区、
`~/.agents/skills` 或 `~/.openclaw/skills` 中的同名技能会取代 Apothem 的副本被使用。

## 迁移路径

1. 如果尚未创建共享 profile，运行 `apothem profile init`。
2. 把可复用的 Open-Claw 技能或命令提示词移入共享语料。
3. 运行 `apothem install --harness open-claw` 以渲染原生配置和支持技能目录。
4. 运行 `apothem verify --harness open-claw` 以确认配置已落地。
