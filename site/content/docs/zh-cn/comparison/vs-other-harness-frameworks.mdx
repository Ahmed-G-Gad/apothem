本页将 Apothem 置于运维者已用来管理 AI 助手配置的各类工具之中加以阐述。它命名的是能力类别，而非具体产品——这种对比是结构性的，无论你在每个类别中选用哪个工具都适用。

## 类别

跨多个工具管理 AI 助手配置的运维者落入四种方式之一：

1. **手工逐工具配置。** 你手工编辑每个环境的原生配置文件——一个工具一个文件，没有共享来源。
2. **单环境配置工具。** 专用于某一个助手平台的工具，能把该平台的配置管理得很好，但触及不到你使用的其他工具。
3. **通用 dotfile 管理器。** 跨机器对配置文件进行版本控制并同步的工具，但把每个文件都当作不透明的文本。
4. **多环境配置管理器。** 持有一份共享配置档案、并据此渲染每个环境原生格式的工具。Apothem 属于这一类别。

## 能力对比

| 能力 | 手工逐工具 | 单环境工具 | dotfile 管理器 | Apothem |
| ---------- | --------------- | ------------------- | --------------- | ------- |
| 覆盖多个环境 | 是（靠工夫） | 否（一个环境） | 是（文件级） | 是（十七个适配器） |
| 单一共享事实来源 | 否 | 否 | 否 | 是 |
| 按环境渲染原生格式 | 手工 | 是（一个环境） | 否 | 是 |
| 跨环境漂移防护 | 手工 | 不适用 | 仅文件同步 | 是 |
| 格式翻译（`.mdc`、`.toml`、嵌入式 `.md`） | 手工 | 限其环境 | 否 | 是 |
| 验证命令 | 无 | 视情况 | 无 | 是 |
| 添加新环境 | 更多手工活 | 不可能 | 跟踪更多文件 | 安装一个适配器 |

## 每种方式适合何处

**手工逐工具配置** 适合配置很少改动的单个工具。每加一个工具、每多保持一条规则在各工具间对齐，成本都会增长。

**单环境工具** 适合专注于一个平台的运维者。它们解决不了多工具问题——你一加第二个助手，就又回到了让两份配置对齐的境地。

**dotfile 管理器** 适合跨机器同步任意文件。它们在机器之间搬运字节，却不理解环境格式，因此既不能把一份配置档案渲染成十七种原生形态，也无法验证其中任何一种。

**Apothem** 适合运行多个 AI 助手、想要单一事实来源的运维者。你只写一次配置档案；Apothem 会渲染、安装、更新并验证每个环境的原生配置。
