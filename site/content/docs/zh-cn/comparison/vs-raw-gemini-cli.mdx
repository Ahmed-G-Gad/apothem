Gemini CLI 读取单个 `GEMINI.md` 规则文件。Apothem 的 gemini-cli 适配器从共享配置档案渲染它。本页将手动维护该配置与用 Apothem 管理它进行对比。

## 工作量对比

| 任务 | 手工配置 | Apothem 管理 |
| ---- | --------------- | --------------- |
| 编写规则 | 手工编辑一个 `GEMINI.md` | 渲染：项目级指导写入 `GEMINI.md`；规则位于 `.gemini/.apothem/support/` 中 |
| 让规则与其他工具保持对齐 | 手工，逐工具 | 在 `apothem update` 时自动完成 |
| 安装 / 移除配置 | 手工写入和删除 `GEMINI.md` | `apothem install` / `apothem uninstall` |
| 验证配置是否正确 | 手工检查 | `apothem verify --harness gemini-cli --project <path>` |

## Apothem 管理什么

gemini-cli 适配器会在 `<project>/GEMINI.md` 中写入一个由哨兵标记界定的 Apothem 块，其中携带项目级指导并指向 Apothem 的材料。规则、模板和钩子作为支持文件落在 `<project>/.gemini/.apothem/support/` 下，命令、技能和代理则落在 `<project>/.gemini/` 下。Gemini CLI 在 `settings.json` 中记载了一个 `hooks` 对象，该对象仍归操作者所有，因此适配器不注册任何钩子，防护意图通过规则文本来表达，而不是通过工具调用拦截点。共享规则的每次更改都会在下一次 `apothem update` 时重新渲染 `GEMINI.md`。

## 迁移路径

1. 如果你还没有创建共享配置档案，运行 `apothem profile init` 来创建它。
2. 把现有 `GEMINI.md` 中的规则移入共享语料库。
3. 运行 `apothem install --harness gemini-cli --project <path>`，以渲染并写入 `GEMINI.md`。
4. 运行 `apothem verify --harness gemini-cli --project <path>` 来确认配置已落地。
5. 之后的每次更改都使用 `apothem update --harness gemini-cli --project <path>`。
