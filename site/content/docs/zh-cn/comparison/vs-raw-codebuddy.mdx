CodeBuddy 从 `.codebuddy/rules/*.md` 读取项目规则。你可以逐项目、长期地手写这些文件。Apothem 的 codebuddy 适配器会从共享配置档案渲染其中一个文件，并使其在每个工具与每个项目之间保持一致。本页将手工维护该配置与使用 Apothem 管理它进行对比。

## 工作量对比

| 任务 | 手工配置 | Apothem 托管 |
| ---- | --------------- | --------------- |
| 编写规则 | 逐项目将相同的纪律复制粘贴到 `.codebuddy/rules/` | 从一份共享语料库渲染 |
| 真相来源 | 每个项目各自的文件 | 一个规范的集合 |
| 使规则在各工具间保持一致 | 逐个工具重新推导 | 自动投影 |
| 更新规则 | 逐个项目手动编辑 | `apothem update --harness codebuddy --project <path>` |
| 移除配置 | 手动删除 | `apothem uninstall`，附带带时间戳的备份 |

## Apothem 管理的内容

codebuddy 适配器会将共享规则渲染到专用文件 `<project>/.codebuddy/rules/apothem-rules.md` 中，且不写入其他任何内容。你的 `CODEBUDDY.md` 记忆文件、你的 `.codebuddy/settings.json` 权限与 MCP 服务器，以及你自己编写的任何其他规则文件，都完全归操作者所有——适配器会识别这些表面，但从不编辑它们。对共享规则的每次变更，都会在下一次 `apothem update` 时重新渲染该文件。

## 迁移路径

1. 如果尚未创建共享配置档案，请运行 `apothem profile init`。
2. 将现有 `.codebuddy/rules/` 文件中的纪律迁移到共享语料库中。
3. 运行 `apothem install --harness codebuddy --project <path>`，在保持你自己的规则不变的同时渲染 `apothem-rules.md` 文件。
4. 运行 `apothem verify --harness codebuddy --project <path>`，以确认配置已落地。
5. 此后的每次变更都使用 `apothem update --harness codebuddy --project <path>`。
