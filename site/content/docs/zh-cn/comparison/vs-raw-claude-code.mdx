Claude Code（厂商为 Anthropic）将其原生配置保存在 `~/.claude/` 下。Apothem 的
claude-code 适配器是全表面适配器：它把共享语料库直接传播到那棵树中。本页将手工
维护配置与用 Apothem 管理它作对比。

## 工作量对比

| 任务 | 手工配置 | Apothem 托管 |
| ---- | --------------- | --------------- |
| 编写规则、代理、命令、技能 | 在 `~/.claude/` 中手工编辑每个表面 | 在共享语料库中写一次 |
| 维护输出样式和状态栏 | 逐表面手工编辑 | 从共享语料库传播 |
| 配置钩子 | 手工编辑 `settings.json` 钩子条目 | 传播（PreToolUse/PostToolUse/Stop/SessionStart） |
| 让配置与其他工具保持对齐 | 手工，逐工具 | 在 `apothem update` 时自动完成 |
| 验证配置是否正确 | 手工检查 | `apothem verify --harness claude-code` |

## Apothem 管理什么

适配器会把规则、代理、命令、技能、输出样式、状态栏以及 `settings.json` 传播到
`~/.claude/`。原生的 PreToolUse、PostToolUse、Stop 和 SessionStart 钩子从共享
语料库配置而来。

Apothem 会在你的用户作用域 `~/.claude/CLAUDE.md` 中写入一个由哨兵标记界定的受管块。`apothem update` 只重写该块，并保留块外的你的文本。项目中的 `CLAUDE.md` 文件不会被触及。Apothem 治理的是它周围被传播的表面。

## 迁移路径

1. 如果你还没有创建共享配置档案，运行 `apothem profile init` 来创建它。
2. 把现有 `~/.claude/` 中的规则、代理、命令和技能迁入共享语料库。
3. 保留 `CLAUDE.md` 原处。Apothem 会保留块外的你的文本，并且只重写该受管块。
4. 运行 `apothem install --harness claude-code` 来传播语料库。
5. 运行 `apothem verify --harness claude-code` 来确认配置已落地。
6. 之后的每次更改都使用 `apothem update --harness claude-code`。
