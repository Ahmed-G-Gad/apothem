Hermes 读取 `~/.hermes/config.yaml`。Apothem 写入原生 YAML 配置（将配置档案的 MCP 清单投射到 `mcp_servers` 中），并在 `~/.hermes/.apothem/support/skills/` 下安装共享的命令集合和技能集合，并把该目录列在 `skills.external_dirs` 下，以便 Hermes 加载它们。Hermes 自己的 `skills.config` 保存逐技能的设置，因此 Apothem 不编写它。

## 状态

**预览。** Hermes 适配器面向当前有文档记载的配置文件和技能发现表面。非技能集合仍作为 Apothem 支持材料。

## 工作量对比

| 任务 | 手工配置 | Apothem 托管 |
| ---- | --------------- | --------------- |
| 编写可复用技能 | 手工编辑配置和技能目录 | 在共享语料中编写一次 |
| 让集合与其他工具保持一致 | 手动，逐个工具 | 在 `apothem update` 时自动完成 |
| 安装 / 移除配置 | 手动 | `apothem install` / `apothem uninstall` |
| 验证配置是否正确 | 手动检查 | `apothem verify --harness hermes` |

## Apothem 管理什么

Hermes 适配器写入 `config.yaml`，将 Apothem 斜杠命令封装为技能，将 Apothem 技能复制到支持目录中，并将规则、模板、代理和钩子材料保留在 Apothem 支持子树下。它还会把 `~/.hermes/.apothem/support/skills` 添加到 `config.yaml` 中的 `skills.external_dirs`，以便 Hermes 加载这些技能。该列表在 Hermes 有文档记载的优先级顺序中排在最后，因此你项目中或 `~/.hermes/skills/` 中的同名技能很可能优先于 Apothem 的副本；所查阅的 Hermes 文档并未说明冲突规则。

## 迁移路径

1. 如果你尚未创建共享配置档案，运行 `apothem profile init` 来创建它。
2. 将可复用的 Hermes 技能或命令提示词移入共享语料。
3. 运行 `apothem install --harness hermes`，以渲染原生配置（它会把支持技能目录列在 `skills.external_dirs` 下）并安装技能。`apothem update` 会保留你添加到 `config.yaml` 的键。
4. 运行 `apothem verify --harness hermes`，以确认配置已落地。
