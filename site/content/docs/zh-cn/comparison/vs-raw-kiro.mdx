Kiro 从一个由 Markdown 文件组成的 `.kiro/steering/` 目录读取引导内容。Apothem 的
kiro 适配器从共享配置档案渲染一个专用的 `apothem-rules.md` 引导文件。本页将手工维护
那套配置与用 Apothem 管理它作对比。

## 工作量对比

| 任务 | 手工配置 | Apothem 管理 |
| ---- | --------------- | --------------- |
| 编写引导规则 | 在 `.kiro/steering/` 下手写每个文件 | 从共享语料库渲染 |
| 保持基础文件不受触碰 | 记得不要覆盖 `product.md` / `tech.md` / `structure.md` | 适配器只写入 `apothem-rules.md` |
| 让规则与其他工具保持对齐 | 手工，逐工具 | 在 `apothem update` 时自动完成 |
| 共享可复用的技能和命令 | 把每个技能文件夹手工复制到 `~/.kiro/skills/` 并保持这些副本最新 | 由适配器写入 `~/.kiro/skills/`，所有项目共用一份副本，并在 `apothem update` 时刷新 |
| 让可复用的辅助器保持同步 | 在 `.kiro/agents/` 下手写每个自定义智能体文件，并跟踪 Kiro 的工具类别 | 十四个辅助器写入 `.kiro/agents/`，其工具已转换，并在 `apothem update` 时刷新 |
| 验证配置是否正确 | 手工检查 | `apothem verify --harness kiro --project <path>` |

## Apothem 管理什么

kiro 适配器把共享规则渲染进一个带有 `inclusion: always` 前置元数据的专用
`apothem-rules.md` 引导文件，并且不触碰 Kiro 由操作者编写的基础文件。它还把 Apothem 的十四个辅助器
作为 Kiro 自定义智能体写入 `<project>/.kiro/agents/`，供 Kiro IDE 1.0 和 Kiro CLI
V3 使用。Kiro 记载了智能体钩子，而适配器不写入它们，因此防护意图寄居于规则散文中，而非工具调用拦截点。共享规则的每次
更改都会在下一次 `apothem update` 时重新渲染该文件。

## 迁移路径

1. 如果你还没有创建共享配置档案，运行 `apothem profile init`。
2. 把现有 `.kiro/steering/` 中的规则迁入共享语料库。
3. 运行 `apothem install --harness kiro --project <path>`，以渲染 `apothem-rules.md` 引导文件。
4. 运行 `apothem verify --harness kiro --project <path>` 来确认配置已落地。
5. 之后的每次更改都使用 `apothem update --harness kiro --project <path>`。
