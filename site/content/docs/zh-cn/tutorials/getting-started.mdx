本教程带你完整走完第一次 Apothem 设置。你从未安装任何东西开始，最终得到一份真实的工具配置——由你自己编写的配置档案生成、经过验证，并已确认可用。预计用时约十五分钟。下面的每条命令都是真实的，可以复制粘贴运行。

<Callout title="已经设置好了？">
  如果你只想要一份关于四个核心命令的简洁参考，请参阅[核心工作流](/docs/usage/getting-started)。本页是带引导的、从零到首次运行的导览。
</Callout>

完成本教程后，你将已经：

1. 通过脚本安装器安装了 Apothem。
2. 编辑了驱动每个工具的共享配置档案。
3. 物化了一个工具的原生配置。
4. 验证了该配置，并确认了一次可用的首次运行。

我们将全程使用 **Claude Code** 作为示例工具，因为它是安装器的默认值。同样的步骤适用于任何受支持的工具——当你看到[工具列表](/docs/harnesses)时替换名称即可。

## 你首先需要准备什么

- 一个类 Unix 的 shell（macOS、Linux 或 WSL）。PowerShell 安装器覆盖 Windows；本教程展示 `bash` 路径。
- 你的 `PATH` 上有 Python 3.10 或更新版本。使用 `python3 --version` 检查。
- 引擎从你的解释器中导入的两个运行时库：`click` 和 `rich`。技术栈的其余部分（`pyyaml`、`jsonschema`）已 vendored 到源码树中，因此只有这两个需要可被导入。安装器会检查它们，指出任何缺失项，并提出为你安装缺失的部分——这样你可以确认后继续。

Apothem 以捆绑的源码树形式发布，而不是以已发布的软件包形式发布——没有 `pip install` 步骤。安装器会克隆该源码树，并直接从中运行引擎。

## 第 1 步——安装 Apothem

运行网络安装器：

```bash
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

安装器执行以下步骤：

1. **前置条件检查。** 安装器会找到一个真实的 Python 3.10+ 解释器，并确认两个运行时库（`click` 和 `rich`）可被导入。如果缺少其中一个，它会指出该库并提出为你安装——或者设置 `APOTHEM_AUTO_INSTALL_DEPS=1`，在不提示的情况下安装。
2. **源码放置。** 捆绑的源码树会被克隆到 `~/.apothem`（可用 `APOTHEM_HOME` 环境变量覆盖）。重新运行会快进现有的克隆，而不是再复制一份。
3. **配置档案引导。** 如果你还没有配置档案，安装器会将示例配置档案复制到 `~/.config/apothem/profile.yaml`，然后**停下来，请你先编辑它**再继续。这是有意为之——示例使用占位身份数据，你应当在写入任何工具配置之前将它改成你自己的。我们会在第 2 步中完成这一点。

你可以通过环境变量来引导安装。你最可能用到的几个：

```bash
# Install a different harness as the default, and point at a project profile.
APOTHEM_HARNESS=cursor \
APOTHEM_PROFILE="$HOME/.config/apothem/profile.yaml" \
  curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

其他可识别的变量有 `APOTHEM_REPO` 和 `APOTHEM_REF`（克隆哪个远程仓库，以及检出哪个 git ref——未设置时会解析并验证最新的已签名发布标签；设置为某个标签可将其固定，设置为 `main` 则跟随不断前进的分支）、`APOTHEM_ALLOW_UNVERIFIED=1`（将标签签名验证失败降级为警告）、`APOTHEM_SOURCE`（使用现有的本地检出，而不是克隆），以及 `APOTHEM_SKIP_VERIFY=1`（跳过安装后的验证，而我们希望运行该验证，因此请保持它未设置）。

当安装器完成一次完整运行时，它会打印一个横幅，展示如何调用引擎。它会在你的 `PATH` 上放置一个 `apothem` 垫片（POSIX：`$HOME/.local/bin`；Windows：`%LOCALAPPDATA%\Microsoft\WindowsApps`），因此一旦该目录加入 `PATH`，你就可以直接运行引擎：

```bash
apothem <command>
```

如果垫片无法放置——或者其所在目录尚未加入 `PATH`——横幅会打印一个无需垫片的自包含回退方式：

```bash
PYTHONPATH="$HOME/.apothem/src" python3 -m apothem <command>
```

本教程的其余部分都写作 `apothem <command>`；如果你使用的是回退形式，请在命令前加上你的安装器横幅所打印的确切前缀。

## 第 2 步——将配置档案改成你自己的

位于 `~/.config/apothem/profile.yaml` 的共享配置档案是唯一的事实来源。每个工具适配器都会读取它，并从中派生该工具的原生配置。编辑一次，你安装的每个工具就会保持一致。

在引擎的编辑器中打开它，或者在任意文本编辑器中打开：

```bash
apothem profile edit
```

一份最小的有效配置档案如下所示：

```yaml
identity:
  name: "Example User"
preferences:
  style: "concise"
rules:
  - "Validate external input before writing files."
```

将占位的 `name` 替换为你自己的名字，并添加任何你希望每个工具都强制执行的规则。示例值请保持为虚构值——配置档案的设计初衷就是可以安全地共享。

确认引擎能够干净地读回你的编辑：

```bash
apothem profile show --json
```

如果 YAML 格式错误，你会在这里看到——修复后重新运行，再继续下一步。

## 第 3 步——物化一份工具配置

如果你在第 1 步中的运行完成了一次完整流程——也就是说，你原本已有配置档案，因此安装器没有在引导阶段停下——它已经为你物化了默认工具。首次运行时，它则会停在配置档案引导阶段，因此现在运行 `install`，从你刚编辑的配置档案物化该工具（这也会添加第二个工具）：

```bash
apothem install --harness claude-code
```

这会读取你的配置档案，并写入 Claude Code 的原生配置。要查看你可以指向的每个工具：

```bash
apothem harnesses list
```

有些工具是项目作用域的，而不是用户作用域的，这些工具需要一个 `--project` 路径，以便适配器知道应写入何处：

```bash
apothem install --harness cursor --project .
```

## 第 4 步——验证并确认首次运行

物化只完成了一半。现在确认配置已正确落地：

```bash
apothem verify --harness claude-code
```

`verify` 会检查该工具预期的配置文件是否存在，并且与配置档案所声明的内容相符。一次干净的运行意味着物化成功。

要对每个已注册的适配器进行一次全机健康检查，运行：

```bash
apothem doctor
```

`doctor` 会检查每个已安装的工具（它必须通过验证，并且其注册的钩子命令必须能够启动），并在任何检查失败时以非零状态退出。你尚未安装的工具会被列出，但不会导致它失败，因此它在配置脚本中是一个有用的闸门。

**你的第一次运行。** 打开你刚配置好的工具——在我们的示例中是 Claude Code——并在任意项目中启动一个会话。你写入配置档案的规则和偏好，现在已成为该工具行为的一部分。这就是一次可用的首次运行：你在第 2 步中编辑的配置档案正在塑造一次真实的会话。

## 你构建了什么

从一台空白机器开始，你安装了 Apothem，编写了一份共享配置档案，从中物化了一个工具的原生配置，验证了结果，并确认了它可用。配置档案是持久的产物——修改它一次，然后重新运行 `apothem update --harness <name>`，即可将变更推送到任意工具。

## 接下来去哪里

- **添加另一个工具。** [工具列表](/docs/harnesses)涵盖每个受支持的平台及其适配器名称。使用一个新的 `--harness` 重复第 3 步。
- **深入某一项任务。** [操作指南](/docs/how-to)是面向任务的做法，涵盖编写规则、编写计划以及运行合规闸门。
- **查阅具体细节。** [参考](/docs/harnesses)完整记录每个适配器、配置档案 schema 以及 CLI 表面。
- **规划比单个会话更长久的工作。** [可恢复的规划](/docs/concepts/resumable-planning)解释 Apothem 如何将长时间运行的工作外置到项目本地的 `.apothem/plans/` 套件中，使任何机器上的新会话都能就地恢复它。

## 推荐的下一步

**运行 `apothem doctor`** 来检查你的设置——它会报告每个已注册适配器的状态，因此你刚安装的工具会显示为健康，其余的则显示为尚未安装——然后再着手添加更多工具。
