Apothem 以 OpenSSF Scorecard 的最高分为目标，同时让公开门面如实说明 Scorecard 能从一个新的单维护者仓库推断出什么、不能推断出什么。本文档逐项列出每项检查、支撑它的证据表面，以及使该态势保持最新的控制措施。

当前分数见 [Scorecard 查看器](https://securityscorecards.dev/viewer/?uri=github.com/ahmed-g-gad/apothem)；徽章位于 [README 头部](https://github.com/ahmed-g-gad/apothem/blob/main/README.md)。

## 逐项检查证据矩阵

| 检查 | 证据表面 | 说明 |
|---|---|---|
| **Binary-Artifacts** | [binary-artifacts-sweep.md](/docs/security/binary-artifacts-sweep) | 源码中不跟踪任何可执行二进制文件；生成的分发归档保留在 `dist/` 中。 |
| **Branch-Protection** | [branch-protection-ruleset.md](/docs/security/branch-protection-ruleset) | `main` 在公开发布推广之前即受保护；在全新的发布提交落地之后，强制推送和删除均被阻止。 |
| **CI-Tests** | [`.github/workflows/ci.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/ci.yml) | Pytest 矩阵、ruff、mypy、CodeQL、Trivy、文档构建以及打包冒烟检查。 |
| **CII-Best-Practices** | OpenSSF Best Practices 注册 | 需要维护者在 OpenSSF Best Practices 站点完成注册；仅靠仓库文件无法完成此项。 |
| **Code-Review** | 分支保护 + CODEOWNERS | 除仓库管理员以外，所有人都必须通过拉取请求向 `main` 提交变更，并且在项目只有一位维护者期间，分支保护要求 0 个批准评审（参见 [branch-protection-ruleset.md](/docs/security/branch-protection-ruleset)）；在存在经过评审的 PR 之前，Scorecard 历史仍然有限。 |
| **Contributors** | [AUTHORS](https://github.com/ahmed-g-gad/apothem/blob/main/AUTHORS) | 一个新的单人维护项目无法制造多组织的贡献历史；随着贡献者加入，此项会自然改善。 |
| **Dangerous-Workflow** | 工作流审计 | 没有 `pull_request_target`；Actions 按 SHA 固定，并以显式权限限定作用域。 |
| **Dependency-Update-Tool** | [`renovate.json`](https://github.com/ahmed-g-gad/apothem/blob/main/renovate.json) | Renovate 覆盖 GitHub Actions、Python 清单、哈希锁定的发布依赖要求以及 npm 表面，同时让分组的依赖 PR 保持可用。 |
| **Fuzzing** | [`tests/property/`](https://github.com/ahmed-g-gad/apothem/tree/main/tests/property) | Hypothesis 属性测试检验解析器和 frontmatter 的不变式；上游 Scorecard 可能不会将 Hypothesis 认定为模糊测试集成。 |
| **License** | [LICENSE](https://github.com/ahmed-g-gad/apothem/blob/main/LICENSE) | 仓库根目录下的 MIT 许可证。 |
| **Maintained** | Git 历史 | 当前的发布提交和活跃的工作流节奏证明了维护状态；非常新的仓库可能会收到仓库年龄警告。 |
| **Packaging** | [`.github/workflows/`](https://github.com/ahmed-g-gad/apothem/tree/main/.github/workflows) | 发布、Pages 和 npmjs.com 工作流，产出 sdist、wheel、SBOM、SLSA 出处溯源和 Sigstore 签名。 |
| **Pinned-Dependencies** | 工作流审计 + 哈希锁定的依赖要求 | Actions 按 SHA 固定；发布工具的安装使用 `--require-hashes`；仅用于工作流的 pip 工具使用精确版本固定。 |
| **SAST** | [`.github/workflows/codeql.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/codeql.yml) | 覆盖 Python 和 Actions 的 CodeQL `security-extended` 查询。 |
| **Security-Policy** | [SECURITY.md](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md) | 协调披露策略、受支持版本矩阵和响应时间线。 |
| **Signed-Releases** | [`.github/workflows/release.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/release.yml) | Sigstore 无密钥签名、SLSA 出处溯源、SBOM、校验和以及发布产物。 |
| **Token-Permissions** | 工作流审计 | 工作流默认使用只读权限；写入作用域限于作业本地，并与部署/打包操作绑定。 |
| **Vulnerabilities** | [`.github/workflows/pip-audit.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/pip-audit.yml) + [`.github/workflows/dependency-review.yml`](https://github.com/ahmed-g-gad/apothem/blob/main/.github/workflows/dependency-review.yml) | 每周漏洞扫描和 CI 扫描，并上传 SARIF；依赖评审闸门会阻止引入存在漏洞或许可证不被允许的依赖的拉取请求。 |

## 分数解读

Scorecard 按 0-10 分制为每项检查评分，总分为加权平均值。依赖仓库历史、第三方注册或贡献者多样性的控制项会被明确跟踪，而不是被夸大宣称。任何受文件控制的检查一旦出现漂移，都会触发立即修复。

## 刷新节奏

- **每次推送：** Scorecard 工作流在每次推送到 `main` 时重新运行。
- **每周：** 周一 02:30 UTC——捕捉上游评分方法的变化 + 针对现有已固定依赖新披露的漏洞。
- **每次发布：** 在公开推广之前，维护者核验实时的 Scorecard 查看器表面，并记录任何平台状态限制。
