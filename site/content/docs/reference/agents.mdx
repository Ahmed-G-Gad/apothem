Persistent helpers live as flat files under the canonical helpers
directory with the `<name>.md` suffix. The canonical path is:

```text
src/apothem/agents/
```

Each helper is a focused role, such as research, audit, quality,
refactoring, or scaffolding, with its own tool restrictions and system prompt.

The table and the path list below show four of the helpers. The generated
inventory at the end of this page lists every helper definition.

## Frontmatter contract

```yaml
---
name: <agent name>
version: <semver>
updated: <YYYY-MM-DD>
description: <one-line role>
tools: <comma-separated tool list>
disallowedTools: <comma-separated deny list>
maxTurns: <integer>
---
```

`tools` is optional. A helper that omits it inherits every tool the session has,
connected MCP tools included, and `disallowedTools` carries its limit. All
fourteen shipped helpers list `tools`.

## Connected MCP servers

A helper that lists `tools` can call only what it lists. Claude Code admits an
MCP tool to that list only when the entry names the server, as in
`mcp__<server>__*`; a bare `mcp__*` is documented as a `disallowedTools` entry
and nowhere else. Server names belong to the person who connects them, so a
shipped helper cannot name them.

`citation-auditor` and `research-scout` look up scholarly sources. Each ships
`tools: Read, Glob, Grep, WebSearch, WebFetch` and denies the tools that write
files, run commands, start other helpers, or publish: `Write`, `Edit`,
`MultiEdit`, `NotebookEdit`, `Bash`, `PowerShell`, `Monitor`, `Agent`,
`Artifact`, and the task-list tools. With no profile setting, neither reaches an
MCP tool, and both look sources up through web search and web fetch.

To give one of them a connected scholarly index, name the server in the
profile's `agent_mcp_servers` key, which maps an agent name to server names. The
Claude Code engine install (`apothem install`) then appends one
`mcp__<server>__*` entry per named server to that agent's `tools` line, and
changes no other agent. The Gemini CLI install does the same with one
`mcp_<server>_*` entry per server in the agent's `tools` allowlist, for a server
name of letters, digits and `-`. On both, a server the agent's own
`disallowedTools` names stays denied. The entry admits every tool of that server, including
any that writes, so name only a server you trust for lookups: the helpers'
instructions limit them to search, look-up, read, verify, and resolve calls, but
the harness enforces only the names the `tools` line lists. A name for an agent
that does not exist, or that has no explicit `tools` line, is reported and
skipped.

Harnesses other than Claude Code and Gemini CLI ignore the key. The Claude Code plugin tree is assembled without
a profile and keeps the plain list, so a plugin user defines a user-level agent
under `~/.claude/agents/` instead. The profile syntax, the server-name rules, and
that workaround are on
[Give a helper access to MCP servers](/docs/reference/mcp#give-a-helper-access-to-mcp-servers).

## Per-harness conversion

A helper whose `tools` grant, after `disallowedTools`, includes no file-editing
tool (`Write`, `Edit`, `MultiEdit`, or `NotebookEdit`) is read-only. A helper
with no `tools` grant is read-only when `disallowedTools` denies at least
`Write` and `Edit`. Each harness that converts helpers enforces that
limit natively, states it in the helper's instructions, or drops the read-only label:

| Harness | Tool limit | Turn limit | Model and effort |
| --- | --- | --- | --- |
| Claude Code | `tools` / `disallowedTools` as written, plus any `mcp__<server>__*` entries the profile's `agent_mcp_servers` key adds to a listed `tools` line; with no `tools`, every tool is inherited, MCP included | `maxTurns` | inherited (not set) |
| Codex | none emitted; the helper's instructions state it, and the parent session's sandbox governs writes | not available | inherited (not set) |
| Gemini CLI | `tools` allowlist of Gemini tool names, plus any `mcp_<server>_*` entries the profile's `agent_mcp_servers` key adds to a listed explicit list; with no `tools`, the allowlist the denials imply plus `mcp_*` | `max_turns` | inherited (not set) |
| Qwen Code | `tools` / `disallowedTools` in Qwen tool names; with no `tools`, no list is emitted, so MCP tools are inherited and the denials apply | not mapped | `model: inherit` |
| OpenCode | `permission` (`allow` / `deny` per tool); MCP tools are not restricted | not mapped | inherited (not set) |
| Antigravity | none emitted; the description drops "read-only" | not available | inherited (not set) |
| CodeBuddy | `tools` / `disallowedTools` as comma strings, limited to the tool names CodeBuddy documents; no MCP entry | `maxTurns` | inherited (not set) |
| Trae | `tools` / `disallowedTools` as comma strings, limited to the tool names Trae documents; no MCP entry | not available | inherited (not set) |

Hermes, Open-Claw and Kimi Code receive the helper files as support material,
not as native helpers.
