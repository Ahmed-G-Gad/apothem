The harness registry is the source-of-truth adapter inventory used by the CLI,
documentation, fixture tests, and convention-pin validation. The runtime source
is `src/apothem/lib/harness_registry.py`; every row below is traceable to that
registry, the per-adapter `capabilities.yml`, and each adapter's
`STANDARD-CONVENTION-PIN.md`.

## Payload cohort support

Status values are `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable`, and
`discovery-pending`.

A `converted` cohort is rewritten into the harness's own format, and some
source fields have no place in it. For each converted commands, agents, or
rules cohort, the adapter's `capabilities.yml` carries a `conversion_losses`
map that says what happens to every source frontmatter field:

| Value | Meaning |
| --- | --- |
| `native:<field>` | The harness reads it under that field. |
| `sidecar:<path>` | It is written to a separate file next to the converted one, such as Codex's `agents/openai.yaml`. |
| `filename` | The file or folder name carries it. |
| `inlined` | It moves into the prompt or body text. |
| `ignored` | It stays in the file, but the harness does not read it. |
| `dropped` | It is left out. |

A test renders every converted file and checks the maps against the output.

## Shared roots

Some install targets are loaded by harnesses other than the one that writes
them. The registry records each such path in `SHARED_ROOTS` with one owner (the
only adapter that writes it) and the readers whose vendor docs load it by
default, with the vendor pages as evidence. Installing the owner puts Apothem
content in front of every reader, and uninstalling the owner removes it from
every reader.

| Path | Owner | Readers |
| --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, Gemini CLI, GitHub Copilot, Kimi Code, Open-Claw, OpenCode, Windsurf, Zed |
| `~/.claude/skills/` | Claude Code | Cursor, OpenCode |
| `~/.claude/CLAUDE.md` | Claude Code | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | Zed |

The Apothem block an owner writes into a shared instruction file names no
single tool as its reader. `tests/unit/test_shared_roots.py` fails when a
registry target is written by two adapters, or is named like a cross-tool
instruction file (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`copilot-instructions.md`), without a declared owner.

## Validation hooks

The registry stays synchronized through these checks:

| Check | Purpose |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | Confirms each adapter has a convention pin under 90 days old that cites at least one vendor URL and has no overdue discovery target. CI runs it on every pull request, weekly, and before a release. |
| `python scripts/dev/check_vendor_urls.py` | Fetches every vendor URL the pins and harness templates cite and fails on a moved or dead page, including a host name that no longer resolves or a certificate that fails verification; a timeout, a refused or reset connection, or a 500, 502, 503 or 504 that outlasts the retries is reported as unreachable and does not fail it. The weekly convention monitor runs it. |
| `python -m apothem.conformity.gate --all .` | Runs the documentation and implementation conformity checks. |
| `python -m pytest` | Exercises registry fixture tests and adapter contract tests. |
