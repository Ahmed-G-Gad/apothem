The harness registry is the source-of-truth adapter inventory used by the CLI,
documentation, fixture tests, and convention-pin validation. The runtime source
is `src/apothem/lib/harness_registry.py`; every row below is traceable to that
registry, the per-adapter `capabilities.yml`, and each adapter's
`STANDARD-CONVENTION-PIN.md`.

## Payload cohort support

Status values are `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable`, and
`discovery-pending`.

A `converted` cohort is rewritten into the harness's own format, and some
source fields have no place in it. For each converted commands, agents, or
rules cohort, the adapter's `capabilities.yml` carries a `conversion_losses`
map that says what happens to every source frontmatter field:

| Value | Meaning |
| --- | --- |
| `native:<field>` | The harness reads it under that field. |
| `sidecar:<path>` | It is written to a separate file next to the converted one, such as Codex's `agents/openai.yaml`. |
| `filename` | The file or folder name carries it. |
| `inlined` | It moves into the prompt or body text. |
| `ignored` | It stays in the file, but the harness does not read it. |
| `dropped` | It is left out. |

A test renders every converted file and checks the maps against the output.

| --- | --- | --- | --- |

## Shared roots

Some install targets are loaded by harnesses other than the one that writes
them. The registry records each such path in `SHARED_ROOTS` with one registered
owner (the adapter the vendor documents the path for), the co-installers that
write the same files to it, and the readers whose vendor docs load it by
default, plus the vendor pages that show it and the date they were retrieved.

A path with co-installers is a user-level folder in the home directory that
several installs write with the same bytes. A machine with only `Cursor`
installed has no `Codex` to write `~/.agents/skills/`, so each install that
names the folder writes it, and the install ledger counts the installs that use
it. The owner of record is the registered owner while it uses the folder, and
otherwise the oldest install that does; nothing moves when the registered owner
is uninstalled. An uninstall removes the folder only when no other install still
uses it (see [`uninstall`](/docs/cli-reference/uninstall#shared-folders-in-your-home-directory)).
Installing a reader puts no files in the folder; installing the owner or a
co-installer puts Apothem content in front of every reader.

| Path | Owner | Co-installers | Readers |
| --- | --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, GitHub Copilot, Windsurf, Zed | Gemini CLI, Kimi Code, Open-Claw, OpenCode, Qwen Code |
| `~/.config/apothem/rules/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | none |
| `~/.config/apothem/templates/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | none |
| `~/.claude/skills/` | Claude Code | none | Cursor, OpenCode |
| `~/.claude/agents/` | Claude Code | none | Cursor |
| `~/.codex/agents/` | Codex | none | Cursor |
| `~/.claude/CLAUDE.md` | Claude Code | none | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | none | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | none | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | none | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | none | Zed |

`~/.config/apothem/rules/` and `~/.config/apothem/templates/` hold the files
Apothem's own skills and instruction files cite. No other tool loads them, so
they have no readers and no vendor pages. `CodeBuddy`, `Kiro`, and `Trae` also
write a skills folder of their own (`~/.codebuddy/skills/`, `~/.kiro/skills/`,
and `~/.trae/skills/`); only that tool loads it, so it is not a shared root.

A reader is listed only where its vendor docs show a default load of that
exact path. One reader carries a condition, and the install note repeats it:
`Open-Claw` indexes `~/.agents/skills/` only under its default state directory
(it skips the folder when `OPENCLAW_STATE_DIR` points elsewhere). The `Cursor`
docs list `~/.codex/agents/` as a `Codex` compatibility folder but do not say
which file formats `Cursor` parses there, and a `Codex` install writes TOML
files, so whether `Cursor` reads those helpers is not confirmed. The `Cursor`
install also writes its own `<project>/.cursor/agents/` copy of the helpers,
which the vendor's precedence ranks above the folders it imports, so in an
installed project the native copy supersedes the one from `~/.claude/agents/`.

Some tools are deliberately not readers of `~/.agents/skills/`: the
`Antigravity`, `CodeBuddy`, `Kiro`, and `Trae` docs do not say they load it by
default (`Trae` loads the project `.agents/skills/` folder only after a setting
is switched on), which is why `CodeBuddy`, `Kiro`, and `Trae` get a skills
folder of their own. The `Hermes` docs name it only as an example value for
`skills.external_dirs`. `GitHub Copilot` is not a reader of `~/.claude/agents/`:
the VS Code docs list that folder for the Anthropic Claude agent, not for the
agent `GitHub Copilot` runs.

The Apothem block an owner writes into a shared instruction file names no
single tool as its reader. `tests/unit/test_shared_roots.py` fails when the adapters that
write a registry target are not exactly its owner and its co-installers, and when a registry target named like a
cross-tool instruction file (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`copilot-instructions.md`) has no declared owner. The one exception is
`~/.codex/AGENTS.md`, which no other registered harness documents loading.

## Validation hooks

The registry stays synchronized through these checks:

| Check | Purpose |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | Confirms each adapter has a convention pin that is at most 90 days old, cites at least one vendor URL, and has no overdue discovery target. CI runs it on every pull request, weekly, and before a release. |
| `python scripts/dev/check_vendor_urls.py` | Fetches every vendor URL the pins and harness templates cite and fails on a moved or dead page, including a host name that no longer resolves or a certificate that fails verification; a timeout, a refused or reset connection, or a 5xx server error is reported as unreachable and does not fail it. The weekly convention monitor runs it. |
| `python -m apothem.conformity.gate --all .` | Runs the documentation and implementation conformity checks. |
| `python -m pytest` | Exercises registry fixture tests and adapter contract tests. |
