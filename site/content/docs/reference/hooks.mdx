Hooks fire on tool events and load message contexts that the
assistant treats as additional system prompts. Wiring lives in
the Claude Code `settings.json` hook block (engine install) or the plugin's
`hooks.json` (plugin install), the Codex `hooks.json` hook file,
and the Qwen Code `settings.json` hooks map.

| Event | Timeout | Purpose |
|-------|--------:|---------|
| SessionStart | 30 seconds | Read memory, check plan state, report readiness; after compaction, deliver the recovery context |
| PreCompact | 30 seconds | Verify state externalized before compaction (Codex, Qwen Code; not registered on Claude Code) |
| PostCompact | 30 seconds | Restore working state after compaction (Codex, Qwen Code; not registered on Claude Code) |
| Stop | 60 seconds | Session-end protocol, opt-in |
| PostToolUse | 10 seconds | Context-size advisory: save state at the first mark, and at the second the operator is told the session is long; at most twice per compaction cycle; runs in the background on Claude Code |
| PreToolUse (shell: Bash, PowerShell, `run_shell_command`) | 10 seconds | Git-artifact isolation, plans locality, dynamic-eval guard |
| PreToolUse (Write/Edit/NotebookEdit/apply_patch) | 10 seconds | Plan-reference isolation, authorship header, plans locality, dependency and dynamic-eval guards |
| PreToolUse (AskUserQuestion) | 10 seconds | `(Recommended)`-marker well-formedness |

## Dispatcher

Engine-installed hook entries invoke the dispatcher by absolute script path
with an install-resolved interpreter. The templates carry the `${PYTHON_BIN}`
and `${HARNESS_ROOT}` tokens, which the installer renders at install time.
Claude Code and Qwen Code materialize the dispatcher under
`<harness-root>/.apothem/support/hooks/`; Codex under `<harness-root>/hooks/`.
Claude Code entries use exec form (`command` plus `args`), so they need no
shell. The Claude Code plugin runs each hook as
`bash "${CLAUDE_PLUGIN_ROOT}/lib/apothem/hooks/lib/bootstrap.sh" <event> [<message-file> ...]`,
in Claude Code's default hook shell (`sh` on macOS and Linux, Git Bash on
Windows); the bootstrap locates a Python 3.10+ interpreter and runs the
bundled dispatcher. It caches the interpreter it found in `interpreter-path`
(`interpreter-path-ps1` for `bootstrap.ps1`) under the hook state directory
(below) and reuses it while the interpreter still exists, so the PATH probe
runs once rather than before every tool call; delete the cache file to force a
new probe. Only an absolute state directory and an absolute cached path are
honoured.

Every surface registers one dispatcher entry per event and matcher, listing
every message that matcher evaluates: one process reads the payload once, runs
each guard, and answers with one envelope, so a Write starts one dispatcher
rather than one per guard. The Claude Code engine install also runs the
conformity gate (`gate.py --hook`) on Write and Edit as its own entry. On Windows without Git for Windows, use the engine install
(`apothem install --harness claude-code`), whose exec-form hooks need no shell.
The dispatcher is a standalone stdlib script: it bootstraps its own
`sys.path`, so no importable `apothem` package is needed on the host. From a source
checkout, the module form `python -m apothem.hooks.dispatch <event>` (with
`PYTHONPATH=src`) runs the same code for development. The dispatcher loads
`hooks/lib/resolve_root.py` for ecosystem-root resolution and delegates to
`hooks/emit_hook_context.py` and `hooks/session_start_bootstrap.py`.

## Message contexts

Per-event Markdown contexts live under `src/apothem/hooks/messages/`:

- Session lifecycle: `sessionstart.md`, `precompact.md`, `postcompact.md`,
  `stop.md`, `posttooluse-proactive-compaction.md`
- Shell calls: `pretooluse-bash.md`, `pretooluse-bash-plan-guard.md`
- File writes: `pretooluse-write.md`, `pretooluse-edit.md`,
  `pretooluse-notebookedit.md`, `pretooluse-write-plan-guard.md`,
  `pretooluse-write-header-guard.md`, `pretooluse-edit-header-guard.md`,
  `pretooluse-conformity.md`
- Guards on content: `pretooluse-dependency-guard.md`,
  `pretooluse-eval-guard.md`
- Questions: `pretooluse-askuserquestion-recommended.md`

On Claude Code, `postcompact.md` is delivered by the SessionStart hook when the
session resumes after compaction, because Claude Code does not pass PreCompact
or PostCompact hook output to the assistant.

Each context file is loaded by the dispatcher when its event fires
and its context argument is registered in the settings file. The license
comment line and the closing `## Bindings` section are removed before the text
reaches the assistant; both exist for maintainers and the conformity gate.

A guard that finds nothing injects nothing. A guard that fires injects only
the `## Advisory` section of its message, filled with what it found (the path,
the identifier, the primitive), followed by `Full procedure: <message-file>`.
The rest of the file is the full procedure, which the assistant reads only
when it needs the detail. Guards judge "inside the project" against the git
root above the tool call's working directory, never against the tree the hook
is installed in.

The authorship-header guard decides with the standard library alone, so it works
under the Claude Code plugin, where the `apothem` package is not importable. It
reads the header (`authorship-header.txt`) and the exemption list
(`header-exceptions.txt`) from the `schemas/` directory beside `hooks/` in the
tree it runs from, and picks the comment family from the file extension. It
speaks only in a git project that follows the convention, one whose tree carries
`src/apothem/schemas/authorship-header.txt`: the SPDX line is Apothem's own, so a
project without that file, and a directory with no `.git`, stay silent. There it
speaks when a Write leaves a file inside the project without the header, or an
Edit creates a file without it or strips it from a file that has it. An exempt
path, a path outside the project, a file type with no comment family, an edit
elsewhere in the file and an edit that names text to find in a file that does not
exist stay silent.

## Runtime contract

Every registered hook command meets the same contract, checked by
`tests/hooks/test_hook_contract.py` on the plugin, the Claude Code engine
install, Codex, and Qwen Code:

- **Runs from a plain checkout.** Exit 0, and standard output is empty or one
  JSON object. No hook depends on a file's executable bit.
- **Registered once.** Each event and matcher has one dispatcher entry per
  surface, listing every message it evaluates, so a guard never runs twice on
  one tool call.
- **Bounded.** No emitted text exceeds 10,000 characters. The dependency guard
  speaks only when a write targets a dependency manifest or lockfile, and the
  dynamic-eval guard only when the content or command contains an evaluation
  or unsafe-deserialization primitive written as code: a call with the
  parenthesis directly after the name and an argument after it (`eval(x)`, not
  the prose `eval (` or `eval()`, and not a definition such as `def exec(`), or
  a shell `eval` statement with a quoted string, a `$` expansion or a backtick
  command among its arguments. A shell command made only of searches, commits
  and `cd` (`grep`, `rg`, `git commit`, `git grep`, `git log`) names those
  constructs as data and is not scanned. The compaction advisory fires at most twice per compaction
  cycle.
- **Uses channels the harness delivers.** PreToolUse guidance travels in
  `hookSpecificOutput`; the AskUserQuestion guard returns `additionalContext`,
  or `permissionDecision: deny` under the strict opt-in. Claude Code discards
  PreCompact and PostCompact output, so on Claude Code the post-compaction
  recovery context arrives with the SessionStart event whose source is
  `compact`.
- **Never runs project code.** The bootstrap resolves its own installed tree
  and never takes a script from the opened project. Session-start guidance is
  read from the installed tree; the project directory is read only for plan
  and memory summaries.
- **Fails open.** A missing message file, a missing interpreter, or corrupt
  state yields exit 0 and a valid envelope.

| Variable | Default | Effect |
| --- | --- | --- |
| `APOTHEM_HOOKS_DISABLE` | unset | `1`, `true`, `yes` or `on` silences every dispatcher-routed hook and the engine install's conformity-gate hook |
| `APOTHEM_SESSION_END_ENABLED` | off | `1`, `true`, `yes` or `on` enables the session-end protocol on Stop. A Stop hook that returns context makes the assistant continue, so the protocol costs one extra turn per session; it never fires on a stop that already follows a hook-driven continuation |
| `APOTHEM_SESSION_END_MIN_STOPS` | `3` | Turn-ends before the session-end protocol may fire |
| `APOTHEM_PROACTIVE_COMPACTION_ENABLED` | on | `0`, `false`, `no` or `off` silences the compaction advisory |
| `APOTHEM_CONTEXT_WINDOW_TOKENS` | unset | Context-window size; with it (or Claude Code's `CLAUDE_CODE_AUTO_COMPACT_WINDOW`) the advisories fire at 50% and 75% of the window, otherwise at 120,000 and 250,000 tokens |
| `APOTHEM_PROACTIVE_COMPACTION_TOOL_THRESHOLD` | `18` | Tool calls per advisory window, used only when the context size cannot be measured |
| `APOTHEM_PROACTIVE_COMPACTION_OUTPUT_THRESHOLD` | `20000` | Tool-output bytes per advisory window, used only when the context size cannot be measured |
| `APOTHEM_HOOK_STATE_DIR` | see below | Directory for per-session hook state |

The compaction advisory measures the context from the newest usage record in
the session transcript (input plus cached tokens), so it reflects what the model
actually holds. A sharp drop in that size marks a compaction and restarts the
two-advisory budget. Where no transcript is available it counts tool calls and
output bytes instead.

Per-session hook state lives in a per-user directory created with mode `0700`:
`APOTHEM_HOOK_STATE_DIR` when set, else `${CLAUDE_PLUGIN_DATA}/state` for the
Claude Code plugin, else `$XDG_STATE_HOME/apothem`, else
`~/.local/state/apothem` (`%LOCALAPPDATA%\apothem\state` on Windows).
