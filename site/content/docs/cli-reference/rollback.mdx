Restore a harness to the state before its recorded install.

## Synopsis

```
apothem rollback --harness NAME|all [--install-id ULID | --last] [--yes]
                 [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

`rollback` returns each selected harness to the state it was in before the
recorded install pass — the latest by default, or the one named by
`--install-id`. Working through that install's ledger record, newest change
first, it:

- restores every file and directory the install overwrote from the backup the
  install captured, at its recorded path (a directory the install replaced is
  restored exactly, without the files the install added to it);
- removes every file and directory the install created, and puts back any
  legacy-layout path the install swept away;
- removes the shared data stores (`memory`, `contexts`, `learning`) the
  install created, unless another installed harness still uses them;
- removes the directories the install created, once they are empty.

Everything rollback removes or replaces is first copied into the Apothem backup
root (`~/.apothem/backups/`), so a rollback can itself be undone by hand. It
then appends a `rollback` record to the harness ledger. Rolling back an older
install also undoes every install after it at the same root.

The ledger keeps the newest 10 install records per install root (with the
backups they reference); an older install can no longer be rolled back by id
and reports `rollback.no_record`.

Records written by an Apothem release before this behaviour was added do not
list which files the install created; rolling back such a record restores the
overwritten files only.

Confirmation is prompted per harness unless `--yes` is supplied. When no
prompt is possible — `--format json` (prompt text would corrupt the single
JSON document) or a non-interactive shell (no TTY) — the command refuses up
front with a structured `rollback.confirmation_required` error (exit 1)
unless `--yes` is supplied. `--install-id` and `--last` select the install
pass and are mutually exclusive.

A `--harness all` rollback is deliberately exhaustive: it covers every
registered harness, including any the profile's `exclude_harnesses` skips
during install — restoring pre-install state is a cleanup operation, so it
reaches records a previously broader install may have left. Harnesses with
no recorded install report a per-harness "nothing to roll back".

## Options

| Option | Description |
|---|---|
| `--harness NAME` | Harness adapter to roll back, or `all` for the registry-wide set (required). |
| `--install-id ULID` | Roll back the named install pass. Defaults to the latest recorded install. |
| `--last` | Roll back the latest recorded install (the default; the explicit form). Mutually exclusive with `--install-id`. |
| `--yes` | Skip the per-harness confirmation prompt. |
| `--project PATH` | Project root for project-scope harnesses. Required when the selected set includes project-scope adapters. |
| `--quiet`, `-q` | Suppress informational output; only errors are emitted. |
| `--verbose`, `-v` | Emit additional diagnostic output. |
| `--format plain\|json` | Output format (default: `plain`). |
| `--json` | Shorthand for `--format json`. |
| `--no-color` | Disable ANSI color codes in output. |
| `-h`, `--help` | Show help and exit. |

## JSON output

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "rollback",
  "action": "rolled_back",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Each restored or removed target appears in `results` with
`"operation": "rollback"` and an `outcome` of `created` or `updated` (and in
`files_written`); the `message` says whether the path was restored or removed.
A failed restore (for example, a backup that was deleted) is
`"outcome": "error"`. An install that recorded no changes is reported with
`"outcome": "skipped"`. When no matching install record exists, the command
reports a `rollback.no_record` error with `"status": "error"`.

## Examples

```bash
apothem rollback --harness claude-code --last
apothem rollback --harness claude-code --install-id 01J9Z… --yes
apothem rollback --harness cursor --project . --last --json
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Rolled back successfully, or nothing to roll back (the install recorded no changes) |
| 1 | Expected error — no install record, conflicting selectors, unknown harness, missing project root, or confirmation declined or unavailable (non-interactive or JSON mode without `--yes`) |
| 2 | Partial restore after at least one target was rolled back |
| 64 | Usage error: an unknown option or command, or a missing or invalid option value. Under `--json` the error is a JSON envelope with code `cli.usage`. |
