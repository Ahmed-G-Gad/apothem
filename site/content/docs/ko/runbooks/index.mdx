메인테이너를 위한 운영 절차입니다. 각 런북은 순서가 정해져 있고 맥락에 의존하지
않는 절차입니다. 알려진 시작 상태를 검증된 종료 상태로 이끌며, 유능한 기여자가
사전 맥락 없이 따라 할 수 있도록 작성되었습니다.

## 페이지

| 페이지 | 설명 |
|------|-------------|
| [Pages 활성화](/docs/runbooks/pages-enablement) | 새로 만든 GitHub Pages 구성에서 `200 OK` HTTPS 랜딩 페이지까지 `apothem.ahmedgad.com`을 이끕니다. |
| [릴리스 주기](/docs/runbooks/release-cycle) | `vX.Y.Z` 릴리스를 깨끗한 작업 트리에서 검증된 GitHub Release 및 npm 표면까지 이끕니다. |
| [게시자 계정 설정](/docs/runbooks/publisher-account-setup) | `@ahmed-g-gad/apothem`을 위한 npmjs.com 신뢰할 수 있는 게시자와 GitHub 측 릴리스 전제 조건을 구성합니다. |
| [릴리스 복구](/docs/runbooks/release-recovery) | 릴리스 전환 시퀀스가 도중에 실패할 때 `ahmed-g-gad/apothem`을 동작 가능한 상태로 복원합니다. |
| [새 하니스 어댑터 작성](/docs/runbooks/new-harness-adapter-authoring) | 퍼스트파티 포함을 위해 새 하니스 어댑터를 작성하고 게시합니다. |
| [배포 체크리스트](/docs/runbooks/deployment-checklist) | Apothem 생태계를 배포하거나 공유하기 전에 사전 검증 체크리스트를 실행합니다. |
| [단독 메인테이너 병합 의식](/docs/runbooks/solo-maintainer-merge) | 메인테이너가 자신의 풀 리퀘스트를 직접 병합할 수 있는 경우와, 승인을 요구하고 이를 관리자에게도 적용하는 보호를 위한 자가 병합 의식입니다. |
| [머신 간 동기화 체크리스트](/docs/runbooks/cross-machine-sync-checklist) | 새 호스트에서 Claude Code 어댑터가 올바르게 설치, 검증, 제거되는지 전체 이식성 점검과 함께 확인합니다. |
