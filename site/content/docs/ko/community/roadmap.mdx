이 로드맵은 Apothem이 나아가는 방향을 설명합니다. 이는 의도의 표명이지 약속이
아니며, 우선순위는 프로젝트와 사용자가 변화함에 따라 바뀝니다. 이미 배포된
내용은 [변경 로그](https://github.com/ahmed-g-gad/apothem/blob/main/CHANGELOG.md)를
참조하세요. 저장소의
[ROADMAP.md](https://github.com/ahmed-g-gad/apothem/blob/main/ROADMAP.md)가
유일한 로드맵이며, 프로젝트 웹사이트의
[로드맵 페이지](https://apothem.ahmedgad.com/docs/community/roadmap)는 이
파일에서 생성됩니다.

상태 범례: **계획됨** · **진행 중** · **배포됨**.

## 현재 릴리스

현재 릴리스 라인은 호스트 비종속 하니스 구성 관리자를 제공합니다. 즉, 공유
프로필(`~/.config/apothem/profile.yaml`)을 등록된 어댑터용 하니스 네이티브
구성으로 머티리얼라이즈하며, `apothem` 명령줄(`quickstart` · `install` ·
`update` · `uninstall` · `rollback` · `backups` · `verify` · `status` ·
`diff` · `harnesses` · `profile` · `doctor` · `migrate-workspace` ·
`completion`)로
구동됩니다.

| 항목 | 상태 | 비고 |
| ---- | ------ | ----- |
| 열일곱 개 하니스 어댑터 | 배포됨 | 각각 설치, 제거, 업데이트, 검증을 갖춤. [지원 하니스](https://apothem.ahmedgad.com/docs/harnesses) 페이지에 목록이 있음 |
| 매니페스트 기반 템플릿 전파 | 배포됨 | `src/apothem/lib/propagation-manifest.yaml`에 있는 전파의 단일 진실 원천 |
| 문서 사이트 | 배포됨 | 생성된 레퍼런스 색인, 브랜드 자산, 기계 판독 가능한 사이트 색인, 릴리스 런북을 갖춘 공개 사이트 |
| 서명된 릴리스 | 배포됨 | 모든 GitHub Release에 서명된 아티팩트, SBOM, 빌드 출처가 포함됨 |
| `/plan` 및 `/research` 파이프라인 | 배포됨 | 명세, 생성, 검토, 실행 단계로 이루어진 계획 파이프라인과 13단계 리서치 파이프라인 |
| 감사 명령과 `/fortress` 루프 | 배포됨 | 보안, 코드, 접근성, 성능, 종속성, 공급망, 위협 모델, 아키텍처, 코드 리뷰, 문서 리뷰, UX에 대한 온디맨드 감사를 `/fortress` 강화 루프로 감쌈 |
| 감사 및 드리프트 검토 인프라 | 배포됨 | 감사 명령을 뒷받침하는 인벤토리 및 드리프트 스캐너 |
| 적합성 게이트 | 배포됨 | 머티리얼라이즈된 모든 표면에 대해 작성자 헤더, 명명, 코드 품질, 얼버무림 표현, 바인딩 상호성을 검사하는 검증기와, 각 어댑터의 출력을 고정하는 동작 diff 골든 |
| 영속 메모리와 옵트인 지속 학습 | 배포됨 | 확인된 규약을 세션 간에 이어 주는 영구 메모리 계층과 옵트인 학습 루프 |
| npm / npx 배포 | 배포됨 | `@ahmed-g-gad/apothem` 패키지가 `npx @ahmed-g-gad/apothem`을 통해 엔진을 실행함 |
| Claude Code 플러그인 등재 | 배포됨 | `/plugin marketplace add ahmed-g-gad/apothem`으로 설치 |
| CI/CD 파이프라인과 서명된 릴리스 공급망 | 배포됨 | 모든 변경은 릴리스 전에 lint, 테스트, 타입 검사, 문서 빌드, 공급망 검사를 통과해야 함 |

## 단기

| 항목 | 상태 | 비고 |
| ---- | ------ | ----- |
| 문서 가이드 | 진행 중 | 실제 하니스 설정을 위한 더 많은 작업 중심 가이드, 다이어그램, 예제 |
| npx 플랫폼 지원 범위 | 계획됨 | `@ahmed-g-gad/apothem` npx 진입점을 각 릴리스와 맞춰 유지하고 플랫폼 지원 범위를 넓힘 |
| 플러그인 등재 확대 | 계획됨 | 마켓플레이스 표면이 안정화됨에 따라 플러그인 등재를 확대 |
| 추가 하니스 어댑터 | 계획됨 | 구성 규약이 안정화되고 사용자가 요청하는 하니스를 추가 |
| 프로필 스키마 개선 | 계획됨 | 더 풍부한 하니스별 재정의 표면과 더 엄격한 검증 진단 |
| 적합성 게이트의 프로필 검증 | 계획됨 | 게이트 검사로서 공유 프로필을 스키마에 대해 검증 |
| 프로필 버전 관리와 마이그레이션 | 계획됨 | 프로필 형식에 버전을 매기고 이전 프로필을 새 버전으로 마이그레이션 |
| `apothem update --watch` | 계획됨 | 프로필이 변경되면 하니스 구성을 다시 머티리얼라이즈 |

## 장기 비전

Apothem은 누구나 자신이 사용하는 모든 도구에 걸쳐 하니스 구성을 관리하는 기본
방법이 되는 것을 목표로 합니다. 규약을 한 번 작성하고, 모든 곳에
머티리얼라이즈하며, 선호와 하니스가 모두 변화하는 동안에도 동기화 상태를
유지하는 것입니다.

  요청이 더 빨리 진행됩니다.

  [CONTRIBUTING.md](https://github.com/ahmed-g-gad/apothem/blob/main/CONTRIBUTING.md)를
