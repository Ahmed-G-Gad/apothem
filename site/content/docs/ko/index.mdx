Apothem은 호스트에 구애받지 않는 하니스 구성 관리자입니다. `~/.config/apothem/profile.yaml`
에 하나의 공유 프로필을 작성하면, Apothem이 이를 열일곱 개 하니스의
네이티브 구성 표면으로 머티리얼라이즈합니다 — Claude Code, Cursor, Gemini CLI, GitHub Copilot,
Codex, Windsurf, Zed, 그리고 등록된 카탈로그의 나머지입니다.

Apothem이 동기화하는 단위는 규칙만보다 넓습니다. 규칙, 슬래시 명령, 스킬, 훅,
출력 스타일, 설정(MCP 서버 포함), 스키마, 문서가 하나의 거버넌스된 단일 코퍼스로
함께 흐르며, 각 하니스의 네이티브 형식으로 머티리얼라이즈되거나, 도구에 대응하는 프리미티브가
없을 때는 Apothem 소유의 지원 하위 트리에 배치됩니다.

## 처음 오셨나요? 두 단계로 시작하기

1. **[설치](/docs/install/quickstart)** — 설치 경로(도구 네이티브 플러그인과 확장,
   `npx`, 원스텝 스크립트) 하나를 고르고 가이드가 있는 첫 단계를 실행합니다. 유일한
   사전 요건은 [Node.js](https://nodejs.org/)와 시스템 Python 3.10 이상입니다.
2. **[첫 번째 동작하는 실행에 도달하기](/docs/tutorials/getting-started)** — 공유
   프로필을 작성하고, 그로부터 하니스의 네이티브 구성을 머티리얼라이즈하며, 결과를 검증합니다.
   처음부터 끝까지 약 15분입니다.

## Apothem의 작동 방식

- **하나의 프로필, 여러 네이티브 구성.** 의도를 한 번만 작성하면 Apothem이 그것을
  각 도구의 네이티브 구성 표면으로 번역합니다 — 최소 공통분모로 평탄화하지 않습니다.
  [호스트에 구애받지 않는 자세](/docs/concepts/ai-platform-agnosticism)를 참고하세요.
- **운영 루프: 계획 → 강화 → 출시.** 계획 파이프라인(`/plan`)이 변경을 명세·생성·
  검토·실행으로 이끌고, 강화 파이프라인(`/fortress`)이 그 작업을 릴리스 게이트
  상태로 몰아가며, 릴리스 게이트가 루프를 닫습니다.
  [명령 파이프라인](/docs/pipeline)을 참고하세요.
- **경계를 넘어 살아남는 작업.** 장시간 작업은 전체 상태를 프로젝트 로컬 `.apothem/plans/`
  스위트로 외부화하므로, 어떤 계정이나 머신에서든 새 세션이 그 자리에서 재개합니다.
  [재개 가능한 계획](/docs/concepts/resumable-planning)을 참고하세요.

## 여기서 시작하기

- **[설치](/docs/install/quickstart)** — 설치 경로(도구 네이티브 플러그인과 확장,
  `npx`, 원스텝 스크립트)와 가이드가 있는 첫 실행.
- **[사용법](/docs/usage/getting-started)** — 프로필을 작성하고, 모든 하니스에
  설치하며, 검증하고 업데이트합니다.
- **[하니스](/docs/harnesses)** — 각 도구의 네이티브 표면과 변환 동작이 함께
  담긴, 열일곱 개 하니스의 카탈로그.
- **[명령 파이프라인](/docs/pipeline)** — `/plan`과 `/research` 파이프라인의 각 단계,
  감사-검토 시퀀스, workflow와 projectify 스킬, 그리고 외과적 조작을 위한 가드레일.
