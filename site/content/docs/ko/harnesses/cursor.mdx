**공급업체:** Anysphere
**설치 이름:** `cursor`
**상태:** 정식 출시
**네이티브 구성:** 프로젝트 루트의 `.cursor/rules/`

## 설치

```bash
apothem install --harness cursor --project /path/to/project
```

어댑터는 공유 Apothem 규칙과 거버넌스 표면으로부터 프로젝트 범위의 `.mdc` 규칙
파일을 하나 렌더링합니다.

**작성된 파일:** `<project>/.cursor/rules/apothem-rules.mdc`

## 프로필을 네이티브 구성으로 매핑

어댑터는 Apothem의 공유 프로필을 읽고 `apothem install` 또는 `apothem update`를
실행할 때마다 프로젝트 규칙 파일을 렌더링합니다. 공유 프로필이 신뢰할 수 있는
단일 출처입니다. 생성된 파일에 대한 프로젝트 로컬 편집 내용은 다음 동기화에서
Apothem이 관리하는 콘텐츠로 교체되기 전에 백업됩니다.

## 호환성 참고 사항

Cursor 0.45+는 `.cursor/rules/`를 통해 프로젝트 수준 지침을 지원합니다. 어댑터는
기본적으로 프로젝트 범위의 `.cursor/rules/` 디렉터리에 작성합니다. Cursor에는 이
어댑터가 관리할 수 있는, 파일 기반의 사용자 전역 규칙 경로가 문서화되어 있지
않습니다.

## 검증

```bash
apothem verify --harness cursor --project /path/to/project
```

verify 명령은 다음을 확인합니다:

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 공유 프로필의 모든 필수 필드가 존재합니다.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness cursor --project /path/to/project
```

현재 공유 프로필 상태에서 프로젝트 규칙 파일을 다시 파생합니다.

## 제거

```bash
apothem uninstall --harness cursor --project /path/to/project
```

어댑터가 작성한 네이티브 구성 파일을 제거합니다.
공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness cursor --project /path/to/project`를 다시 실행하세요 |
| 검증 실패 | `apothem update --harness cursor --project /path/to/project`를 실행한 다음 다시 검증하세요 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 다음 `apothem update --harness cursor --project /path/to/project`를 다시 실행하세요 |
