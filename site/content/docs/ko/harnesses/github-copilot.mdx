**공급업체:** GitHub / Microsoft
**설치 이름:** `github-copilot`
**상태:** GA
**네이티브 구성:** `<project>/.github/copilot-instructions.md`

## 설치

```bash
apothem install --harness github-copilot --project /path/to/project
```

이 어댑터는 공유 Apothem 규칙과 거버넌스 표면에서 프로젝트 지침 파일을 도출합니다.

**작성되는 파일:** `<project>/.github/copilot-instructions.md`

## 프로필에서 네이티브 구성으로의 매핑

어댑터는 `apothem install` 또는 `apothem update`를 실행할 때마다 Apothem의 공유
프로필을 읽고 저장소 전체에 적용되는 Copilot 지침 파일을 렌더링합니다. 공유
프로필이 진실의 원천입니다. 생성된 파일에 대한 프로젝트 로컬 편집은 다음 동기화가
Apothem이 관리하는 콘텐츠를 교체하기 전에 백업됩니다.

## 호환성 참고 사항

GitHub Copilot은 이 어댑터가 관리할 수 있는 파일 기반의 사용자 전역 지침 경로를
노출하지 않습니다. Apothem은 문서화된 프로젝트 범위 지침 파일을 대상으로 하며, IDE
수준의 사용자 설정은 운영자 소유로 남겨 둡니다.

Apothem은 `copilot-instructions.md`를 프로젝트의 어시스턴트 지침 표면 중 하나의
목소리로 취급합니다. 적합성 게이트의 다중 표면 일관성 검사는 그 공유 주장이
프로젝트의 다른 지침 파일과 의미적으로 정렬된 상태를 유지하는지 검증하므로, Copilot은
도구 체인의 나머지 부분이 읽는 내용과 모순되는 지침을 결코 받지 않습니다.

## 검증

```bash
apothem verify --harness github-copilot --project /path/to/project
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 공유 프로필의 모든 필수 필드가 존재합니다.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness github-copilot --project /path/to/project
```

현재 공유 프로필 상태에서 프로젝트 지침 파일을 다시 도출합니다.

## 제거

```bash
apothem uninstall --harness github-copilot --project /path/to/project
```

어댑터가 작성한 네이티브 구성 파일을 제거합니다.
공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness github-copilot --project /path/to/project`를 다시 실행 |
| 검증 실패 | `apothem update --harness github-copilot --project /path/to/project`를 실행한 다음 다시 검증 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 다음 `apothem update --harness github-copilot --project /path/to/project`를 다시 실행 |

## 구성 노브

| 플래그 | 기본값 | 설명 |
|------|---------|-------------|
| `--dry-run` | `false` | 파일을 작성하지 않고 설치를 미리 봅니다. |
