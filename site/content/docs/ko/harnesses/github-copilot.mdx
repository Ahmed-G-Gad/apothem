**벤더:** GitHub / Microsoft
**설치 이름:** `github-copilot`
**상태:** GA
**네이티브 구성:** `<project>/.github/copilot-instructions.md`

## 설치

```bash
apothem install --harness github-copilot --project /path/to/project
```

어댑터는 여러분의 공유 프로필과 공유 Apothem 규칙 및 거버넌스 표면으로부터
프로젝트 지침 파일을 도출합니다.

**작성되는 파일:** `<project>/.github/copilot-instructions.md`

## 프로필-네이티브 구성 매핑

어댑터는 `apothem install` 또는 `apothem update`를 실행할 때마다 Apothem의
공유 프로필을 읽고 저장소 전체에 적용되는 Copilot 지침 파일을 렌더링합니다.
공유 프로필이 진실의 원천입니다. 생성된 파일에 대한 프로젝트 로컬 편집은 다음
동기화가 Apothem 관리 콘텐츠를 교체하기 전에 백업됩니다.

Apothem 블록 안에서는 여러분의 프로필로부터 렌더링된 섹션(운영자, 선호, 사용자
지정 규칙, 옵트인한 동작, MCP 서버 이름)이 공유 거버넌스 텍스트보다 앞에
옵니다. GitHub는 지침 파일이 짧을수록 코드 리뷰가 파일 전체를 처리할 가능성이
높다고 설명하므로
([코드 리뷰 사용자 지정](https://docs.github.com/en/copilot/tutorials/customize-code-review)),
여러분에게 특화된 부분이 파일의 맨 앞에 옵니다.

## 호환성 참고 사항

GitHub Copilot은 이 어댑터가 관리할 수 있는 파일 기반 사용자 전역 지침 경로를
노출하지 않습니다. Apothem은 문서화된 프로젝트 범위 지침 파일을 대상으로 하며,
IDE 수준의 사용자 설정은 운영자 소유로 남겨 둡니다.

Apothem 저장소 안에서 `.github/copilot-instructions.md`는 그 저장소의 어시스턴트
지침 표면 가운데 하나의 목소리입니다. 해당 저장소의 체크아웃에서 적합성 게이트의
다중 표면 일관성 검사는 `AGENTS.md`, `CLAUDE.md`,
`.github/copilot-instructions.md`에 담긴 공유 주장을 비교합니다. 이 검사는 세
파일 가운데 하나가 빠뜨린 공유 주장과, `AGENTS.md`가 내세우는 주장에 모순되는
파일을 보고합니다. 이 검사는 Apothem이 여러분의 프로젝트에 작성하는 지침 파일을
읽지 않습니다. 이 게이트는 기본적으로 권고용입니다. 결과를 보고하고 `0`으로
종료합니다.

## 검증

```bash
apothem verify --harness github-copilot --project /path/to/project
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML
   구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면
   `--profile PATH`를 추가하세요.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness github-copilot --project /path/to/project
```

현재 공유 프로필 상태에서 프로젝트 지침 파일을 다시 도출합니다.

## 제거

```bash
apothem uninstall --harness github-copilot --project /path/to/project
```

`<project>/.github/copilot-instructions.md`에서 Apothem 블록을 제거하고, 그
바깥의 텍스트는 그대로 둡니다. 파일에 다른 내용이 남아 있지 않을 때에만 파일을
삭제합니다. 변경하기 전에 파일의 타임스탬프가 찍힌 사본이
`~/.apothem/backups/` 아래에 저장됩니다. 공유 프로필 YAML과 Apothem 엔진은
영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness github-copilot --project /path/to/project`를 다시 실행 |
| 검증 실패 | `apothem update --harness github-copilot --project /path/to/project`를 실행한 후 다시 검증 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 후 `apothem update --harness github-copilot --project /path/to/project`를 다시 실행 |

## 구성 노브

| 플래그 | 기본값 | 설명 |
|------|---------|-------------|
| `--dry-run` | `false` | 파일을 작성하지 않고 설치를 미리 봅니다. |
