- **벤더:** Open-Claw
- **설치 이름:** `open-claw`
- **상태:** 미리 보기
- **네이티브 구성:** `~/.openclaw/openclaw.json`

## 설치

```bash
apothem install --harness open-claw
```

어댑터는 OpenClaw의 사용자 전역 구성 파일을 작성하고, 공유 프로필을 프로필
문서로 투영하며, 각 OpenClaw 워크스페이스에 Apothem 규칙 파일을 작성하고, 하니스
루트 아래에 Apothem 지원 코호트를 설치합니다. OpenClaw의 네이티브 구성은 JSON이며,
머티리얼라이저는 `skills.load.extraDirs`와 `bootstrap-extra-files` 훅 항목이라는
두 항목을 렌더링하고 기존 파일은 자신의 다른 키를 유지합니다.

**작성되는 파일:** `~/.openclaw/openclaw.json`, 프로필 문서
`~/.openclaw/apothem/rules/00-apothem-profile.md`, 각 워크스페이스의 규칙 파일
`<workspace>/apothem/AGENTS.md`, 그리고 Apothem의 데이터 폴더
`~/.openclaw/.apothem/`(그 컨텍스트, 학습, 메모리 저장소와
`~/.openclaw/.apothem/support/` 아래의 지원 파일)

모든 설치와 업데이트는 `~/.openclaw/apothem/rules/`에서 Apothem이 넣지 않은 모든
파일을 `~/.apothem/backups/` 아래의 백업 세트에 저장한 뒤 삭제합니다. 그 백업은
하니스의 더 새로운 백업 세트가 10개 생기면 삭제되므로, 여러분의 파일은 다른 곳에
보관하세요.

프로필 문서는 Apothem 지원 파일 섹션으로 끝납니다. 이 섹션은 저장소 스타일의 각
인용(`rules/<name>.md`, `templates/...`, `hooks/...`)이 해석되는 기준인
`~/.openclaw/.apothem/support/` 아래의 절대 디렉터리를 명시합니다.

## 프로필에서 네이티브 구성으로의 매핑

어댑터는 구성 항목 두 개를 작성합니다.

- OpenClaw가 읽는 추가 스킬 디렉터리 목록인 `skills.load.extraDirs`에
  `~/.openclaw/.apothem/support/skills`를 추가하며, OpenClaw는 이를 통해 설치된
  스킬을 찾습니다. 이 항목은 여러분이 이미 나열한 항목 뒤에 들어갑니다.
- `hooks.internal.entries.bootstrap-extra-files` 항목의 경로 목록에
  `apothem/AGENTS.md`를 추가하며, OpenClaw는 이를 통해 Apothem 규칙 파일을
  로드합니다([각 워크스페이스의 규칙](#각-워크스페이스의-규칙) 참조).

여러분의 다른 키는 그대로 유지되며, Apothem은 `hooks.internal.enabled`를 절대
작성하지 않습니다. 프로필의 신원, 선호, 규칙은 프로필 문서와 각 워크스페이스의
규칙 파일에 들어갑니다. 공유 커맨드, 스킬, 도우미 정의, 규칙, 템플릿, 훅 프롬프트는
`~/.openclaw/.apothem/support/` 아래에 지원 자료로 설치됩니다.

## 호환성 참고 사항

미리 보기 어댑터입니다. OpenClaw는 `skills.load.extraDirs`를 통해 Apothem 스킬을,
각 워크스페이스의 규칙 파일을 통해 Apothem 규칙을 로드합니다. Apothem에서 MCP 서버는
로드하지 않습니다.

### 각 워크스페이스의 규칙

OpenClaw는 워크스페이스의 파일 여섯 개, 즉 `AGENTS.md`, `SOUL.md`, `IDENTITY.md`,
`USER.md`, `BOOTSTRAP.md`, `MEMORY.md`를 시스템 프롬프트에 넣습니다. 번들된
`bootstrap-extra-files` 훅은 이 이름 중 하나를 가진 파일을 더 추가하며, 경로는 각
세션의 워크스페이스를 기준으로 읽습니다. Apothem은 각 워크스페이스에
`apothem/AGENTS.md`를 작성하고 그 경로를 훅의 항목에 나열합니다.

```json
{
  "hooks": {
    "internal": {
      "entries": {
        "bootstrap-extra-files": {
          "enabled": true,
          "paths": ["apothem/AGENTS.md"]
        }
      }
    }
  }
}
```

이 파일에는 프로필의 관리 블록과 `~/.openclaw/.apothem/support/` 아래의 규칙
인덱스를 가리키는 포인터가 들어 있으며, 그 인덱스를 통해 전체 규칙 세트에 닿습니다.
파일 이름이 `AGENTS.md`이므로 OpenClaw는 여섯 파일 중 일부만 받는 cron 세션과 다른
세션이 시작하는 도우미 세션에서도 이 파일을 로드합니다. Apothem은 워크스페이스
자체의 `AGENTS.md`를 절대 편집하지 않습니다. OpenClaw가 템플릿에서 그 파일을 만들고,
그 워크스페이스에서 일하는 어시스턴트가 편집합니다. `apothem`이라는 폴더는 설정
작업으로 세지 않으므로, OpenClaw가 아직 설정하지 않은 워크스페이스도 첫 실행 파일을
받습니다.

Apothem은 홈 디렉터리에 존재하는 모든 워크스페이스에 이 파일을 작성합니다.
`agents.defaults.workspace`(없으면 `OPENCLAW_WORKSPACE_DIR`, 그것도 없으면
`~/.openclaw/workspace`), 그리고 각 `agents.entries` 항목의 `workspace`(또는
`agents.entries`가 없을 때 OpenClaw가 여전히 읽는 이전 `agents.list`의 각 항목의
것)입니다. 기본 워크스페이스를 소유한 항목은 자신의 `workspace`가 없을 때
그것을 직접 사용합니다. 그 항목은 `default: true`로 표시된 항목이며(`agents.ownership`이
`"explicit"`인 경우는 제외), 그렇지 않으면 유일한 항목입니다. 자신의 `workspace`가
없는 다른 항목은 `<agents.defaults.workspace>/<id>`를, 그것이 없으면
`~/.openclaw/workspace-<id>`를 사용하며, id는 OpenClaw가 폴더 이름에서 쓰는
방식대로 표기됩니다. 소문자로 바꾸고, 문자, 숫자, `_`, `-` 이외의 문자는 `-`로
바꿉니다(그래서 `Bob Smith`는 `workspace-bob-smith`를 사용합니다).

- 아직 존재하지 않는 워크스페이스는 메시지 없이 건너뜁니다. OpenClaw가 그
  워크스페이스를 만들고 나면, `apothem update --harness open-claw`를 실행할 때까지
  `apothem verify --harness open-claw`가 실패합니다.
- 다음은 각각 경고 하나와 함께 건너뜁니다. 홈 디렉터리 밖의 워크스페이스, 링크(심볼릭
  링크 또는 Windows 정션)를 통해 닿는 워크스페이스, 파일인 경로, `apothem/AGENTS.md`가
  폴더인 워크스페이스, 그리고 `apothem` 폴더 자체가 다른 워크스페이스인
  워크스페이스(그 `AGENTS.md`는 그 워크스페이스 자체의 파일이 됩니다). Apothem은
  링크를 통해 절대 쓰거나 삭제하지 않습니다. 그 뒤로 링크가 된 워크스페이스의 규칙
  파일은 그대로 두고, 그 Apothem 블록을 직접 삭제하라는 경고를 냅니다.
- 워크스페이스가 구성에서 빠지거나 파일이 더 이상 맞지 않으면(아래 크기 제한 참조),
  다음 설치나 업데이트는 그곳에 작성한 파일에서 Apothem 블록을 꺼냅니다. 파일과 그
  `apothem` 폴더는 그 안에 남은 것이 없을 때 삭제되며, 블록 바깥에 여러분이 추가한
  텍스트는 남습니다.

구성에 이미 `bootstrap-extra-files` 항목이 있으면, Apothem은 훅이 읽는 목록, 즉
`paths`, `patterns`, `files` 중 비어 있지 않은 첫 번째 목록에 자신의 경로를
추가합니다. 여러분의 목록을 가리는 두 번째 목록을 절대 새로 만들지 않습니다.

**Apothem이 훅을 그대로 두는 경우.** 다음 경우에 설치는 규칙 파일을 작성하지만 훅
설정은 바꾸지 않으며, 경고를 출력합니다.

- `hooks.internal.enabled`가 `false`입니다. 여러분이 내부 훅을 끈 경우입니다.
- `bootstrap-extra-files` 항목에 `enabled: false`가 있습니다.
- `hooks.internal.enabled`가 `true`이고 `hooks.internal.entries` 아래에 이름이 지정된
  훅이 없습니다(그리고 `hooks.internal.load.extraDirs`가 비어 있습니다). 그러면
  OpenClaw는 조건에 맞는 모든 훅을 로드하며, 첫 번째 훅에 이름을 붙이면 다른 훅이
  꺼집니다. 사용하는 훅에 이름을 붙인 다음 업데이트를 실행하세요. OpenClaw로 설치한
  훅 팩은 Apothem이 읽지 않는 OpenClaw 자체의 상태 데이터베이스에 나열되므로,
  Apothem은 그런 팩이 설치되어 있어도 이 경우를 같은 방식으로 처리합니다.
- `openclaw.json`에 주석이나 다른 JSON5 구문이 있습니다
  ([`openclaw.json`의 주석](#호환성-참고-사항) 참조).

규칙 파일이 두 크기 제한 안에서 어떤 워크스페이스에도 맞지 않으면, 설치는 파일을
작성하지 않고 훅 항목에 경로도 추가하지 않습니다.

**크기 제한.** OpenClaw는 파일당 최대 20,000자, 전체 60,000자를 주입합니다
(`agents.defaults.bootstrapMaxChars`와 `bootstrapTotalMaxChars`. `agents.entries`
항목은 자신의 값을 설정할 수 있으며, 그 값이 그 워크스페이스에 우선합니다).
OpenClaw는 문자를 UTF-16 단위로 세므로 이모지는 두 자로 세어지며, Apothem도 줄 끝을
포함해 같은 방식으로 셉니다(Windows 줄 바꿈은 두 자로 셉니다). 기본 프로필에서 규칙
파일은 수천 자 정도입니다.

규칙 파일은 여섯 워크스페이스 파일과 `bootstrap-extra-files` 항목의 다른 파일
다음에 로드됩니다. 파일당 제한을 넘거나 전체 제한이 남겨 두는 여유를 넘는
워크스페이스에서는 OpenClaw가 파일을 자르거나 건너뛰어 규칙이 깨진 채 도착하게
되므로, Apothem은 그곳에 파일을 작성하지 않고, 경고에서 그 이유를 말하며, 이전
설치가 남긴 사본을 꺼냅니다. 여러 항목이 워크스페이스 하나를 공유하면 가장 작은
제한이 적용됩니다. (OpenClaw 동작은
[훅 구성](https://docs.openclaw.ai/automation/hooks/configuration),
[번들 훅](https://docs.openclaw.ai/automation/hooks/bundled-hooks),
[워크스페이스와 부트스트랩](https://docs.openclaw.ai/gateway/config-agents/workspace-and-bootstrap)
문서(2026-11-09에 확인)에 따른 것입니다.)

Apothem 블록이 END 마커를 잃은 규칙 파일은 BEGIN 마커 아래에 이전 Apothem 텍스트를
유지하며, 업데이트는 그 옆에 Apothem의 블록을 작성하므로 그 이전 텍스트는 파일당
제한에 포함됩니다. 제한을 넘는 규칙 파일에 완전한 블록을 시작하지 않는 BEGIN
마커(END 마커가 사라졌거나 그 마커가 여러분의 것인 경우)가 있으면, 경고는 그 파일과
그런 각 마커를 줄 번호로 지목합니다. 그런 다음 그 파일의 수정이 바꾸는 모든 마커
줄, 즉 그 파일에 대한 다른 경고가 제시하는 것과 같은 줄을 지목합니다. 예를 들어
"change line 3 by adding a word inside its comment"(두 줄이면 "change lines 3 and 9
by adding a word inside each comment"이며, 코드 블록 안에 인용한 BEGIN 마커도 포함될
수 있습니다)입니다. 어떤 줄도 닫지 않는 코드 블록 안에서 파일이 끝나면, 경고는 먼저
그 코드 블록의 닫는 줄을 추가하라고 말합니다. 예를 들어 "add a line of 3 backticks
below line 12"입니다. Markdown 뷰어가 그 코드 블록을 Apothem과 다르게 읽을 수 있는
경우(그 위의 줄이 HTML 블록을 시작하거나, 목록 항목의 텍스트가 그 위에서 왼쪽 여백에
이어지고 들여쓴 줄이 뒤따르는 경우), 경고는 바꿀 줄을 지목하지 않습니다. 그 대신
Apothem이 단계를 제시할 수 없다고 말하고, 그 파일에 대한 다른 경고와 마찬가지로 코드
블록을 여는 줄을 지목합니다
([번호가 매겨진 해결책 따르기](/docs/install/troubleshooting#follow-a-numbered-fix)
참조). 경고는 여러분의 텍스트는 남긴 채 마커 아래의 이전 텍스트를 직접 삭제하거나,
프로필의 사용자 지정 규칙을 줄이거나, 제한을 올리라고 말합니다.

### 스킬

**이름 충돌.** OpenClaw는 다음 소스에서 우선순위가 높은 것부터 스킬을 읽으며, 같은
스킬 이름이 둘 이상의 위치에 나타나면 가장 높은 소스가 이깁니다: 워크스페이스
`skills/` 폴더, 워크스페이스 `.agents/skills/` 폴더, `~/.agents/skills`(기본 상태
디렉터리일 때만), 상태 디렉터리의 `skills/` 폴더(기본값 `~/.openclaw/skills`),
워크숍 스킬, 번들 및 커스터디언 스킬, 그다음으로
`skills.load.extraDirs` 아래에 나열된 폴더와 플러그인 스킬. 자신의 워크스페이스가
아닌 별도의 실행 워크스페이스 폴더에서 실행되는 세션은 이 모든 소스 다음에 그
폴더의 `skills/`와 `.agents/skills/` 폴더도 읽으므로, Apothem 스킬이 그곳에 있는
같은 이름의 스킬보다 우선합니다. Apothem 디렉터리는
`extraDirs` 항목이므로, 앞선 소스 중 어디에든 여러분이 두고 있는 같은 이름의
스킬이 OpenClaw가 사용하는 스킬이 되며, 그 스킬의 Apothem 사본은 디스크에서
사용되지 않은 채 남습니다. Apothem은 `openclaw.json`,
`~/.openclaw/apothem/rules/`, `~/.openclaw/.apothem/`, 각 워크스페이스의
`apothem/AGENTS.md`에만 작성하고 앞선 폴더에는 절대 작성하지 않으므로, 설치,
업데이트, 제거는 여러분이 그곳에 둔 스킬을 교체하지 않습니다.

`agents.defaults.skills`는 스킬 이름의 허용 목록이며, `agents.entries.<id>.skills`
목록은 그것이 속한 항목에 대해 이를 대체합니다. Apothem은 두 목록 모두 편집하지
않으므로, 허용 목록을 두고 있다면 원하는 Apothem 스킬이 그 목록에 적혀 있는지
확인하세요. `apothem update`는 여러분이 `openclaw.json`에 추가한 키를 유지합니다.
MCP 서버는 OpenClaw 구성의 `mcp.servers` 블록에 있으며, 이 블록은
`openclaw mcp add`와 관련 하위 명령으로 관리합니다. 어댑터는 그곳에 어떤 항목도
작성하지 않습니다. (OpenClaw 동작은 [스킬](https://docs.openclaw.ai/tools/skills),
[스킬 구성](https://docs.openclaw.ai/tools/skills-config),
[구성 확장](https://docs.openclaw.ai/gateway/config-extensions),
[MCP CLI](https://docs.openclaw.ai/cli/mcp) 문서(2026-11-03에 확인)에 따른
것입니다.)

**`openclaw.json`의 주석.** OpenClaw는 구성을 JSON5로 읽고, Apothem은 파일을 일반
JSON으로 다시 씁니다. 파일에 주석이나 다른 JSON5 구문이 있으면 Apothem은 그 파일을
절대 다시 쓰지 않습니다.

- `skills.load.extraDirs` 항목이 없으면, 설치는 파일에 주석이나 JSON5 구문이
  있다는 메시지와 함께 중단됩니다.
- 훅 항목만 없으면, 설치와 업데이트는 계속 진행해 워크스페이스 규칙 파일을 작성하고,
  무엇을 추가할지 알려 주는 경고를 출력합니다(`bootstrap-extra-files` 항목이 이미
  목록을 쓰고 있으면 경로는 그 목록에 들어갑니다). 그것을 추가할 때까지
  `apothem verify`는 실패합니다.
- 여러분이 주석을 추가하기 전에 Apothem이 작성한 항목은 그대로 유지되며, 업데이트는
  계속 진행됩니다. 크기 제한이나 여러분의 훅 설정 때문에 Apothem의 경로를 훅
  항목에서 빼야 할 때는 경고가 그것을 직접 제거하라고 요청합니다. 더 이상 맞지 않는
  규칙 파일은 그래도 꺼냅니다.

이 항목들을 직접 파일에 병합하거나 파일을 일반 JSON으로 변환한 다음 설치를 다시
실행하세요.

```json
{
  "skills": {
    "load": {
      "extraDirs": ["~/.openclaw/.apothem/support/skills"]
    }
  },
  "hooks": {
    "internal": {
      "entries": {
        "bootstrap-extra-files": {
          "enabled": true,
          "paths": ["apothem/AGENTS.md"]
        }
      }
    }
  }
}
```

여러분이 직접 추가한 항목은 여러분의 것으로 간주되며, 제거는 그 항목을 그대로
둡니다.

## 검증

```bash
apothem verify --harness open-claw
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML
   구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면
   `--profile PATH`를 추가하세요.
3. 네이티브 구성의 `skills.load.extraDirs`가
   `~/.openclaw/.apothem/support/skills`를 나열합니다. 이 항목이 없으면 OpenClaw는
   설치된 스킬을 로드하지 않습니다. `apothem update`가 이를 다시 추가합니다.
4. `bootstrap-extra-files` 항목이 훅이 읽는 목록에 `apothem/AGENTS.md`를
   나열합니다. 여러분의 설정이 Apothem의 등록을 막는 경우는 제외합니다
   ([각 워크스페이스의 규칙](#각-워크스페이스의-규칙) 참조).
5. Apothem이 찾은 모든 워크스페이스에 관리 블록이 든 `apothem/AGENTS.md`가 있습니다.
   설치 후에 만든 워크스페이스는 `apothem update`가 파일을 작성할 때까지 이 점검에
   실패합니다. 설치가 파일이 크기 제한을 넘는다고 보고한 워크스페이스는 프로필의
   사용자 지정 규칙을 줄이거나 제한을 올린 다음 업데이트를 실행할 때까지 이 점검에
   실패합니다. 링크, 홈 디렉터리 밖의 경로, 존재하지 않는 워크스페이스는 점검하지
   않습니다. `apothem status`는 블록이 편집된 규칙 파일을 보고합니다.
6. Apothem이 블록을 두는 어떤 파일(프로필 문서와 각 규칙 파일이며, 설치가 더 이상
   사용하지 않는 워크스페이스의 파일도 포함)에도 완전한 블록을 시작하지 않는 BEGIN
   마커, Apothem의 마커 사이에 있는 둘 이상의 완전한 블록, 또는 Apothem이 여러분의
   텍스트와 구별할 수 없는 마커 쌍이 없습니다. 업데이트는 그런 마커를 유지하거나 그런
   파일을 그대로 두므로, `Note:` 줄이 말하는 대로 파일을 직접 고칠 때까지 이 점검은
   실패합니다. 규칙 파일은 파일당 제한에 맞을 때만 작성되며, 여러분이 바꾸는 마커 줄
   아래에 남겨 둔 이전 Apothem 텍스트도 그 제한에 포함되므로, 그 메모는 다음
   업데이트가 Apothem의 블록을 작성한다고 하면서 "if the file then fits OpenClaw's
   per-file limit (bootstrapMaxChars)"라는 조건을 붙입니다. 맞지 않으면 업데이트는
   크기 경고에서 그 파일을 지목합니다
   ([파일에 END 마커가 없는 Apothem BEGIN 마커가 있음](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker),
   [파일이 Apothem의 마커 사이에 두 블록을 담고 있음](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers),
   [Apothem이 자신의 블록과 여러분의 텍스트를 구별할 수 없음](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)
   참조).

## 업데이트

```bash
apothem update --harness open-claw
```

현재 공유 프로필 상태에서 프로필 문서와 각 워크스페이스의 규칙 파일을 다시 도출하고
지원 파일을 새로 고칩니다. `openclaw.json`은 이미 가지고 있는 키를 유지하며,
`skills.load.extraDirs`와 훅 항목의 Apothem 항목은 몇 번을 업데이트하든 한 번만
나열됩니다. 각 업데이트는 훅 항목의 목록 맨 끝에 Apothem의 경로를 작성하므로, 그
뒤에 항목을 넣으면 경로는 끝으로 이동합니다. 규칙 파일의 관리 블록 바깥에 여러분이
추가한 텍스트는 남습니다. 설치가 더 이상 사용하지 않는 워크스페이스의 규칙 파일은
블록을 잃습니다. 그 결과 파일에 END 마커 없는 BEGIN 마커(여러분의 줄이거나, END
마커를 잃은 이전 블록의 남은 부분)가 남으면, 업데이트는 그 파일과 마커의 줄을
지목하고, 그 줄이 더 이상 마커로 읽히지 않도록 바꾸는 번호가 매겨진 단계를
제시합니다. 그 줄을 바꿀 때까지 `apothem verify`는 실패합니다. 그 아래에 있는 이전
Apothem 텍스트는 이후 여러분이 직접 삭제할 몫입니다. 그런 파일의 Apothem 마커 사이에
서로 다른 블록이 두 개 있으면, 업데이트는 파일을 그대로 두고 각 블록을 줄 번호로,
또는 Apothem의 블록과 그 주위의 마커 줄로 지목합니다. BEGIN 마커 줄을 그 자리에서
바꾸는 경고의 번호가 매겨진 수정 방법 중 하나를 따르세요. Apothem의 블록을 유지하면
다음 설치, 업데이트 또는 제거가 그 블록을 꺼내고, 모든 BEGIN 마커 줄을 바꾸면
Apothem은 그곳에서 자신의 블록을 찾지 못합니다. Apothem이 그 파일에서 자신의 블록과
여러분의 텍스트를 구별할 수 없으면(예를 들어 블록이 여러분의 코드 블록 안에 있는
경우), 업데이트는 그 파일도 그대로 두며, 경고는 각 마커 쌍과 그 수정 방법을
지목합니다. 수정하고 나면 다음 설치, 업데이트 또는 제거가 Apothem의 블록을 꺼냅니다
([Apothem이 자신의 블록과 여러분의 텍스트를 구별할 수 없음](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)
참조). 그때까지 `apothem verify`는 실패하고 그 파일을 지목합니다
([검증](#검증) 참조).
`~/.config/apothem/profile.yaml`을 편집하거나 설치된 Apothem 패키지를
업그레이드한 후에 실행하세요.

## 제거

```bash
apothem uninstall --harness open-claw
```

어댑터가 추가한 항목, 즉 `skills.load.extraDirs`의 항목, 훅 항목의 경로(그리고
Apothem이 만든 경우 그 항목 자체), 각 워크스페이스 `apothem/AGENTS.md`의 관리
블록(그 안에 남은 것이 없으면 파일과 폴더도 삭제), 프로필 문서, 지원 하위 트리를
제거합니다. 여러분이 직접 넣은 `extraDirs` 항목과 훅 설정을 포함해 `openclaw.json`에
있는 여러분의 키는 그대로 남고, 워크스페이스 자체의 파일도 그대로 남으며,
`openclaw.json`은 Apothem이 직접 만들었고 여러분의 항목이 하나도 남아 있지 않은
경우에만 삭제됩니다.

일부 남은 항목은 여러분이 직접 처리해야 합니다.

- **주석이나 다른 JSON5 구문이 있는 `openclaw.json` 안의 Apothem 항목.** 제거는
  아무것도 바꾸기 전에 중단되며, 제거할 항목을 지목하는 오류와 함께 종료됩니다.
- **링크를 통해 닿으며 여전히 Apothem 블록을 담고 있는 규칙 파일.** 제거는 나머지를
  모두 제거하고, 그 파일은 그대로 두며, 링크를 지목하면서 제거를 미완료(종료 코드 2)로
  보고합니다. 보고서는 OpenClaw가 여전히 그 파일을 로드하는지도 알려 줍니다.
  Apothem이 `openclaw.json`을 바꿀 수 없었거나 여러분의 패턴이 그 파일과 일치해서
  `openclaw.json`이 OpenClaw가 사용하는 워크스페이스에서 그 파일을 지목하는 동안에는
  로드합니다.
- **Apothem이 다시 쓸 수 없는 규칙 파일**(여러분이 쓸 수 없는 폴더에 있거나,
  Windows의 읽기 전용 파일). 제거는 그 파일을 지목하는 오류를 보고하고, 다른
  워크스페이스의 규칙 파일을 정리한 뒤, `openclaw.json`이나 지원 파일을 바꾸기 전에
  중단합니다.
- **Apothem이 자신의 블록과 여러분의 텍스트를 구별할 수 없는 규칙 파일**(예를 들어
  블록이 여러분의 코드 블록 안에 있는 경우). 제거는 나머지를 모두 제거하고, 그 파일은
  그대로 두며, 제거를 미완료(종료 코드 2)로 보고합니다. 그 경고는 각 마커 쌍을 지목하고
  번호가 매겨진 수정 방법을 제시합니다. 제거를 다시 실행하기 전에 해당하는 경우의
  수정 방법을 따르세요.

각 경우에 Apothem은 제거를 미완료로 기록하고 설치 기록을 유지하며, 이후 블록 옆에
여러분의 텍스트를 추가하더라도 마찬가지입니다. 지목된 항목이나 Apothem 블록(또는
파일)을 제거하거나 파일을 고친 다음, 제거를 다시 실행해 마무리하세요. Apothem
블록이 END 줄을 잃은 규칙 파일도 그것을 지목하는 경고와 함께 그대로 남지만, 제거는
그래도 완료됩니다. 블록의 나머지는 직접 삭제하세요. 설치가 그대로 있는 동안에는
블록의 나머지를 삭제할 때까지, 각 설치와 업데이트가 설치가 더 이상 사용하지 않는
워크스페이스의 그런 파일을 지목합니다. 제거가 완료된 뒤에는 이후의 설치가 그
워크스페이스에 작성할 때만 Apothem이 그 파일을 다시 지목합니다. 설치가 사용하는
워크스페이스에서는 설치나 업데이트가 그런 규칙 파일의 텍스트를 유지하고, Apothem의
블록을 그와 떨어진 곳에 작성하며, 그 파일을 지목합니다. 공유 프로필 YAML과 Apothem
엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python3 -E -s ~/.apothem/src/apothem/conformity/gate.py --all .
```

프로젝트 폴더에서 실행하세요. Windows에서는 `python3` 대신 `python`과 전체 경로를
사용하세요. Windows PowerShell과 cmd는 `~`를 확장하지 않기 때문입니다.
PowerShell에서는 `$HOME\.apothem\src\apothem\conformity\gate.py`, cmd에서는
`%USERPROFILE%\.apothem\src\apothem\conformity\gate.py`입니다. 이 경로는
설치 프로그램이 엔진을 두는 곳이며, `-E -s`는 여러분의 `PYTHONPATH`와 사용자
site-packages가 게이트에 닿지 않게 합니다. [적합성 게이트](/docs/conformity-gate)에서
둘 다와 다른 설치 방식을 설명합니다.

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness open-claw`를 다시 실행 |
| 검증 실패 | `apothem update --harness open-claw`를 실행한 다음 다시 검증. `Note:` 줄이 규칙 파일처럼 수정할 Apothem 마커가 있는 파일을 지목하면 업데이트로는 해결되지 않습니다. 메모가 말하는 대로 그 파일을 직접 고친 다음 다시 검증하세요([검증](#검증)의 6번 항목 참조) |
| 예기치 않은 구성 내용 | Apothem은 `openclaw.json`에 `skills.load.extraDirs`의 자기 항목과 `bootstrap-extra-files` 훅 항목의 자기 경로만 작성하고(그 항목을 만들 때는 `enabled: true`도), 이미 들어 있는 키를 유지하므로, 프로필 내용은 그곳에 들어가지 않습니다. 프로필 내용은 `~/.openclaw/apothem/rules/00-apothem-profile.md`와 각 워크스페이스의 `apothem/AGENTS.md`에 들어갑니다. `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 다음, [업데이트](#업데이트) 아래의 명령을 다시 실행하세요 |
| 설치가 `openclaw.json`의 주석이나 JSON5 구문에 관한 메시지와 함께 중단되거나, JSON5 구문이 있다고 경고함 | Apothem은 주석을 제거해야 하는 파일을 다시 쓰지 않습니다. [호환성 참고 사항](#호환성-참고-사항) 아래에 표시된 두 항목(`skills.load.extraDirs` 항목과 `bootstrap-extra-files` 훅 항목)을 직접 추가하거나 파일을 일반 JSON으로 변환한 다음 설치를 다시 실행하세요 |
| OpenClaw가 Apothem 규칙을 따르지 않음 | `apothem verify --harness open-claw`를 실행하고 설치 경고를 확인하세요. 설치 시점에 존재하지 않았던 워크스페이스, 꺼진 내부 훅, 열린 훅 검색은 규칙을 로드되지 않은 상태로 둡니다([각 워크스페이스의 규칙](#각-워크스페이스의-규칙) 참조). 그런 다음 `apothem update --harness open-claw`를 실행하세요 |
| Apothem 스킬이 OpenClaw에 나타나지 않음 | 워크스페이스, `~/.agents/skills`, `~/.openclaw/skills`, 또는 OpenClaw의 워크숍이나 번들 스킬 중에 있는 같은 이름의 스킬이 Apothem 사본보다 우선합니다([호환성 참고 사항](#호환성-참고-사항) 참조). 또한 `apothem verify --harness open-claw`를 실행하고, 두고 있는 `agents.defaults.skills` 또는 `agents.entries.<id>.skills` 허용 목록이 그 스킬을 명시하는지 확인하세요 |
