**공급업체:** Moonshot
**설치 이름:** `kimi-code`
**상태:** GA
**네이티브 구성:** `<project>/AGENTS.md` 및 `<project>/.kimi-code/.apothem/support/`

## 설치

```bash
apothem install --harness kimi-code --project /path/to/project
```

어댑터는 공유 Apothem 거버넌스 표면을 프로젝트 루트의 `AGENTS.md`에 센티널로
구분된 관리 블록으로 작성하고(센티널 바깥의 운영자 작성 문장은 보존됨),
네이티브가 아닌 Markdown 코호트는 `<project>/.kimi-code/.apothem/support/`에
있는 Apothem 소유 지원 트리 아래에 둡니다. 프로젝트 `AGENTS.md`는 Kimi Code
외에도 많은 코딩 도구가 읽으므로, 이 블록은 어느 한 도구도 독자로 지칭하지 않는
프로젝트 전체 지침으로 작성됩니다.

Kimi Code는 범용 AGENTS.md 규약에 따라 프로젝트 루트의 `AGENTS.md` 지침 파일을
읽으며, 프로젝트 구성은 `<project>/.kimi-code/` 아래에 있습니다.
`<project>/.kimi-code/mcp.json` 표면은 운영자 소유입니다. Apothem은 이 표면을
명시하지만 항목은 작성하지 않습니다.

**작성되는 파일:** `<project>/AGENTS.md`(관리 블록), 그리고
`<project>/.kimi-code/.apothem/support/` 아래의 명령, 스킬, 훅, 에이전트, 규칙,
템플릿 코호트.

## 프로필에서 네이티브 구성으로의 매핑

어댑터는 Apothem의 공유 프로필을 읽고 매 `apothem install` 또는 `apothem update`
실행마다 프로젝트 루트의 `AGENTS.md` 지침 표면을 렌더링합니다. 동작 규칙과
거버넌스 코퍼스는 `AGENTS.md`의 관리 블록에 안착하고, 명령, 스킬, 훅, 에이전트,
규칙, 템플릿 코호트는 `.kimi-code/.apothem/support/` 아래에 배치되어 지침
표면에서 참조됩니다. 이는 Kimi Code의 공백이 아니라 어댑터가 선택한
레이아웃입니다. Kimi Code는 스킬을 `.kimi-code/skills/`와 `.agents/skills/`에서,
사용자 정의 에이전트를 `.kimi-code/agents/`와 `.agents/agents/`에서, 훅을
`~/.kimi-code/config.toml`의 `[[hooks]]` 배열에서 로드하지만, 지원 트리에서는
로드하지 않습니다. 따라서 그곳에 있는 Apothem 사본은 `AGENTS.md` 블록이
가리키는 참조 자료입니다. 블록은 Apothem 지원 파일 섹션으로 끝납니다. 이 섹션은
저장소 스타일의 각 인용(`rules/<name>.md`, `templates/...`, `hooks/...`)이
해석되는 기준인 `.kimi-code/.apothem/support/` 아래의 디렉터리를 프로젝트 루트
기준 상대 경로로 명시하므로, 커밋된 `AGENTS.md`에는 머신별 경로가 담기지
않습니다. (Kimi Code의 동작은
[스킬](https://moonshotai.github.io/kimi-code/en/customization/skills),
[서브에이전트](https://moonshotai.github.io/kimi-code/en/customization/agents),
[훅](https://moonshotai.github.io/kimi-code/en/customization/hooks)에 관한 Kimi
Code 사용자 지정 페이지에 따른 것이며, 2026-10-02에 확인했습니다.)

## 호환성 참고 사항

Kimi Code는 `AGENTS.md` 또는 `.kimi-code/AGENTS.md`에서 프로젝트 지침을 읽고,
`.kimi-code/mcp.json`을 운영자 소유 MCP 표면으로 인식합니다. Apothem은 그
표면을 명시하지만 그 안에 어떤 항목도 작성하지 않습니다. 렌더링된 지침 표면이
프로젝트를 직접 구동합니다. Kimi Code는 상태 표시줄이나 출력 스타일 파일 표면을
노출하지 않으므로, 해당 코호트는 머티리얼라이즈되지 않습니다.

Kimi Code는 Moonshot의 Kimi 모델 제품군에서 실행됩니다. 현재 모델과 구성 표면은
[공급업체 구성 레퍼런스](https://moonshotai.github.io/kimi-code/en/configuration/config-files)를
참조하세요.

## 검증

```bash
apothem verify --harness kimi-code --project /path/to/project
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML 구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면 `--profile PATH`를 추가하세요.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness kimi-code --project /path/to/project
```

현재 공유 프로필 상태에서 프로젝트 루트의 `AGENTS.md` 관리 블록과 지원 코호트를
다시 도출합니다.

## 제거

```bash
apothem uninstall --harness kimi-code --project /path/to/project
```

어댑터가 작성한 네이티브 구성 파일을 제거합니다.
공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness kimi-code --project /path/to/project`를 다시 실행 |
| 검증 실패 | `apothem update --harness kimi-code --project /path/to/project`를 실행한 다음 다시 검증 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 다음 `apothem update --harness kimi-code --project /path/to/project`를 다시 실행 |

## 구성 노브

| 플래그 | 기본값 | 설명 |
|------|---------|-------------|
| `--dry-run` | `false` | 파일을 작성하지 않고 설치를 미리 봅니다. |
