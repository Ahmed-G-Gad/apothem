**벤더:** Moonshot
**설치 이름:** `kimi-code`
**상태:** GA
**네이티브 구성:** `<project>/AGENTS.md`, `<project>/.kimi-code/skills/`, `<project>/.kimi-code/agents/` 및 `<project>/.kimi-code/.apothem/support/`

## 설치

```bash
apothem install --harness kimi-code --project /path/to/project
```

어댑터는 공유 Apothem 거버넌스 표면을 프로젝트 루트의 `AGENTS.md`에 센티널로
구분된 관리 블록으로 작성합니다(센티널 바깥의 운영자 작성 문장은 보존됨).
스킬과 스킬로 감싼 커맨드는 Kimi Code의 네이티브 프로젝트 스킬 디렉터리인
`<project>/.kimi-code/skills/`에 설치하고, Apothem의 도우미는
`<project>/.kimi-code/agents/`에 Kimi Code 서브에이전트로 설치합니다
([서브에이전트](#서브에이전트) 참조). 나머지 코호트는
`<project>/.kimi-code/.apothem/support/`에 있는 Apothem 소유 지원 하위 트리
아래에 남습니다. 프로젝트 `AGENTS.md`는 Kimi Code
외에도 많은 코딩 도구가 읽으므로, 이 블록은 어느 한 도구도 독자로 지칭하지 않는
프로젝트 전체 지침으로 작성됩니다.

Kimi Code는 범용 AGENTS.md 규약에 따라 프로젝트 루트의 `AGENTS.md` 지침 파일을
읽으며, 프로젝트 구성은 `<project>/.kimi-code/` 아래에 있습니다. Kimi Code는
작업 디렉터리에서 위쪽으로 검색하여 `.git`을 포함하는 가장 가까운 디렉터리를
프로젝트 루트로 삼으므로, 저장소 루트를 `--project`로 전달하세요.
`<project>/.kimi-code/mcp.json` 표면은 운영자 소유입니다. Apothem은 이 표면을
명시하지만 항목은 작성하지 않습니다.

**작성되는 파일:** `<project>/AGENTS.md`(관리 블록), `<project>/.kimi-code/skills/`
아래의 스킬과 (스킬로서의) 커맨드, 각 Apothem 도우미에 대한
`<project>/.kimi-code/agents/<name>.md` 하나, 그리고
`<project>/.kimi-code/.apothem/support/` 아래의 훅, 규칙, 템플릿 코호트.

## 서브에이전트

Kimi Code는
[사용자 정의 서브에이전트에 관한 Kimi Code 문서](https://moonshotai.github.io/kimi-code/en/customization/agents.md)에
따라 `.kimi-code/agents/`(또는 `.agents/agents/`)의 Markdown 파일에서
서브에이전트를 읽습니다. 설치는 도우미 열네 개 모두에 대해 Apothem 도우미마다
파일 하나를 `<project>/.kimi-code/agents/`에 작성합니다. 프로젝트용으로만
설치하며 `~/.kimi-code/agents/` 폴더는 작성하지 않습니다.

각 파일은 도우미의 지침을 변경하지 않고 유지하며 다음 프런트매터 키를 담습니다.

| 키 | Apothem이 작성하는 것 |
| --- | --- |
| `name`, `description` | 도우미의 이름과 설명. |
| `tools` | 도우미의 허용 도구로, Kimi Code 도구 이름의 목록입니다. |
| `disallowedTools` | 도우미의 거부 도구로, Kimi Code 도구 이름의 목록입니다. Kimi Code는 이를 `tools` 뒤에 적용합니다. |

Kimi Code는 도구 이름을 대소문자까지 정확히 일치시키며, 해당하는 도구가 없는
이름에 대해 경고합니다. 그래서 설치는 Kimi Code가 다르게 표기하는 두 도구의
이름을 바꾸고(`WebFetch`를 `FetchURL`로, `TodoWrite`를 `TodoList`로), Kimi Code에
해당하는 도구가 없는 이름은 제외합니다: `MultiEdit`, `NotebookEdit`,
`PowerShell`, `Monitor`, `Artifact`, `TaskCreate`, `TaskUpdate`. 거부된 도구는
거부된 상태로 남습니다. 이렇게 해서 도우미의 허용 도구가 모두 사라지면 파일은
`tools: []`를 담으며, 이는 어떤 도구도 허용하지 않습니다. `tools`를 생략하면 모든
도구가 허용될 것입니다.

설치는 `model`(Kimi Code에는 서브에이전트용 모델 키가 없으며, 서브에이전트는 메인
세션의 모델이나 `config.toml`의 `[secondary_model]`을 사용합니다), `override`(프로젝트
파일이 내장 서브에이전트를 대체하게 할 것입니다), `subagents`, `whenToUse`, 또는
Apothem의 `maxTurns`, `version`, `updated`, `portability` 키를 절대 작성하지
않습니다.

알아 둘 사항:

- 서브에이전트 파일은 일반 프로젝트 파일입니다. 프로젝트와 함께 커밋하거나
  `.kimi-code/agents/`를 `.gitignore`에 나열하세요. Apothem은 대신 선택하지 않습니다.
- Kimi Code는 위임이 요청될 때 도우미를 사용합니다. 2026-10-25 릴리스부터는
  스스로 서브에이전트를 시작하는 대신 기본적으로 작업을 직접 처리하므로, 메시지나
  `AGENTS.md`에서 도우미를 이름으로 요청하세요. 사용자 정의 서브에이전트에 관한
  벤더 페이지는 여전히 자동 스케줄링을 설명하므로, 이는 바뀔 수 있습니다.
- `.kimi-code/agents/`의 프로젝트 수준 파일은 extra, 사용자, 플러그인 수준에 있는
  같은 이름의 정의보다 우선합니다. 여러분 자신의 도우미에는 Apothem의 것과 다른
  이름을 붙이세요. Kimi Code의 코드는 또한 Apothem이 절대 작성하지 않는 공유
  `.agents/agents/` 폴더보다 `.kimi-code/agents/`를 먼저 읽고, 같은 이름의 두 파일
  중 첫 번째를 유지합니다. 문서는 이를 밝히지 않습니다.
- Apothem 도우미의 이름을 가진 여러분의 파일은 `~/.apothem/backups/` 아래에
  저장된 다음 교체됩니다. 제거는 그 파일을 되돌려 놓지 않습니다. 다른 이름의
  파일은 절대 건드리지 않습니다.
- 이전 릴리스는 도우미 파일을 지원 하위 트리의
  `.kimi-code/.apothem/support/agents/`에 두었는데, Kimi Code는 그곳에서 이를
  로드하지 않았습니다. `apothem update`나 `apothem uninstall`은 그 사본을
  `~/.apothem/backups/` 아래에 저장한 뒤 제거합니다.

## 프로필-네이티브 구성 매핑

어댑터는 Apothem의 공유 프로필을 읽고 매 `apothem install` 또는 `apothem update`
실행마다 프로젝트 루트의 `AGENTS.md` 지침 표면을 렌더링합니다. 동작 규칙과
거버넌스 코퍼스는 `AGENTS.md`의 관리 블록에 안착합니다. 각 스킬과 스킬로 감싼 각
커맨드는 Kimi Code가 로드하는 프로젝트 스킬 디렉터리인
`.kimi-code/skills/<name>/SKILL.md`에 안착합니다. 어댑터는 그 Kimi 전용 폴더에만
작성하며, 다른 도구도 읽는 `.agents/skills/`에는 절대 작성하지 않습니다. 여러분이
직접 `.kimi-code/skills/`에 다른 이름으로 추가한 스킬은 설치, 업데이트, 제거 시에
유지됩니다. 그곳에서 Apothem 스킬과 같은 이름을 가진 스킬은 교체됩니다. 설치와
업데이트는 이를 덮어쓰고 제거는 이를 제거하며, 각각 `~/.apothem/backups/` 아래에
타임스탬프가 찍힌 사본을 만든 뒤에 수행하고, 설치는 이 충돌에 대한 안내를
출력하지 않습니다. 여러분 자신의 스킬에는 Apothem의 것과 다른 이름을 붙이세요.

훅, 규칙, 템플릿 코호트는 `.kimi-code/.apothem/support/` 아래에 배치되어 지침
표면에서 참조됩니다. Kimi Code는 지원 하위 트리에서 이를 로드하지 않으므로,
그곳에 있는 Apothem 사본은 `AGENTS.md` 블록이 가리키는 참조 자료입니다. 블록은
Apothem 지원 파일 섹션으로 끝납니다. 이 섹션은 저장소 스타일의 각
인용(`rules/<name>.md`, `templates/...`, `hooks/...`)이 해석되는 기준인
`.kimi-code/.apothem/support/` 아래의 디렉터리를 프로젝트 루트 기준 상대 경로로
명시하므로, 커밋된 `AGENTS.md`에는 머신별 경로가 담기지 않습니다. (Kimi Code의
동작은
[스킬](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/skills.html),
[도우미 정의](https://moonshotai.github.io/kimi-code/en/customization/agents.md),
[훅](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html)에
관한 Kimi Code 사용자 지정 페이지에 따른 것이며, 스킬과 훅은 2026-10-24에, 도우미
정의는 2026-10-27에 확인했습니다.)

## 네이티브로 설치되지 않는 항목

Kimi Code는 훅을 위한 네이티브 위치를 문서화합니다. 어댑터는 다음 이유로 아직
그곳에 작성하지 않습니다.

- **훅.** Kimi Code는 `~/.kimi-code/config.toml`(그 변수가 설정된 경우
  `$KIMI_CODE_HOME/config.toml`)의 `[[hooks]]` 배열에서 훅을 읽습니다.
  Apothem은 아무것도 작성하지 않습니다. 그 파일은 사용자 범위인 반면 이 어댑터는
  프로젝트 루트 아래에 작성합니다. 항목에는 필드 네 개만 허용되며(`event`와
  `command`는 필수, `matcher`와 `timeout`은 선택) 추가 필드가 있으면 구성이
  로드되지 않습니다. 그리고 Apothem에는 나중에 자신의 항목만 제거할 수 있는 TOML
  병합 기능이 없습니다. 훅 보조 스크립트는 지원 하위 트리에 남습니다.
- **스킬 프런트매터.** 벤더 페이지는 `SKILL.md` 키 `name`과
  `description`(둘 다 필수), `type`, `whenToUse`,
  `disableModelInvocation`(`disable-model-invocation`으로도 허용됨),
  `arguments`를 문서화합니다. 다른 키에 대한 규칙은 밝히지 않습니다. 스킬은
  Apothem 소스에 있는 프런트매터 그대로 설치되므로, `version`, `updated`,
  `archetype`, `userInvocable`, `argument-hint`, `portability`, `allowed-tools`
  같은 키가 Kimi Code에 도달하며, Kimi Code는 이를 무시하거나 거부할 수 있습니다.
- **같은 이름의 스킬.** Kimi Code는 프로젝트 수준에 사용자 수준보다 높은 우선순위를
  주므로, `<project>/.kimi-code/skills/`의 스킬은 다른 Apothem 어댑터가 작성하는
  `~/.agents/skills/`의 같은 이름 스킬보다 우선합니다. 벤더 페이지는 프로젝트 수준
  안에서 `.kimi-code/skills/`와 `.agents/skills/`가 서로 어떤 순위를 갖는지 밝히지
  않습니다.

## 호환성 참고 사항

Kimi Code는 `AGENTS.md` 또는 `.kimi-code/AGENTS.md`에서 프로젝트 지침을 읽고,
`.kimi-code/mcp.json`을 운영자 소유 MCP 표면으로 인식합니다. Apothem은 그
표면을 명시하지만 그 안에 어떤 항목도 작성하지 않습니다. 이 두 지침 파일 가운데
어댑터는 프로젝트 루트의 `AGENTS.md`만 작성하며, Kimi Code는 이 파일을 프로젝트
지침으로 읽습니다. 두 파일이 모두 있을 때 어느 쪽이 우선하는지는 Kimi Code
문서에 나와 있지 않습니다. Kimi Code는 상태 표시줄이나 출력 스타일 파일 표면을
노출하지 않으므로, 해당 코호트는 머티리얼라이즈되지 않습니다.

Kimi Code는 Moonshot의 Kimi 모델 제품군에서 실행됩니다. 현재 모델과 구성 표면은
[벤더 구성 참조](https://www.kimi.com/code/docs/en/kimi-code-cli/configuration/config-files)를
확인하세요.

## 검증

```bash
apothem verify --harness kimi-code --project /path/to/project
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 스킬 및 서브에이전트 디렉터리를 포함한 각 관리 대상이 존재하고, 관리되는
   파일은 비어 있지 않으며, JSON 또는 YAML 구성은 파싱됩니다. 설치된 파일이 그
   프로필과도 일치하는지 확인하려면 `--profile PATH`를 추가하세요.
   `.kimi-code/agents/`에 대한 검사는 폴더가 존재하는지이며, 각 도우미 파일이 그
   안에 있는지가 아닙니다. 명령
   `apothem diff --harness kimi-code --project /path/to/project`는 누락되었거나
   오래된 도우미 파일을 나열합니다.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness kimi-code --project /path/to/project
```

현재 공유 프로필 상태에서 프로젝트 루트의 `AGENTS.md` 관리 블록, 스킬,
서브에이전트 파일, 지원 코호트를 다시 도출합니다. 스킬이 `.kimi-code/skills/`로
옮겨지기 전에 만든 설치 위에서 업데이트하면 이전
`<project>/.kimi-code/.apothem/support/skills/` 디렉터리가 제거되므로, 각 스킬은
한 번만 존재합니다. 도우미가 `.kimi-code/agents/`로 옮겨지기 전의 설치 위에서
업데이트하면 같은 방식으로 이전 `<project>/.kimi-code/.apothem/support/agents/`
디렉터리가 제거됩니다. 제거되는 각 디렉터리의 타임스탬프가 찍힌 사본이 먼저
`~/.apothem/backups/` 아래에 저장됩니다.

## 제거

```bash
apothem uninstall --harness kimi-code --project /path/to/project
```

프로젝트 루트의 `AGENTS.md`에서 Apothem 블록을 제거하고 센티널 바깥의 텍스트는
모두 유지합니다. 파일은 그 안에 다른 내용이 남지 않은 경우에만 삭제됩니다.
또한 Apothem이 `<project>/.kimi-code/skills/` 아래에 배치한 스킬(여러분이 그곳에
다른 이름으로 추가한 스킬은 유지됨), `<project>/.kimi-code/agents/` 아래의
서브에이전트 파일(여러분이 그곳에 다른 이름으로 추가한 파일은 유지되며, 폴더는
비게 되면 제거됨), 그리고 한 번도 업데이트되지 않은 설치의 이전 지원 하위 트리
`skills/` 및 `agents/` 디렉터리를 포함하여
`<project>/.kimi-code/.apothem/support/` 아래의 지원 파일도 제거합니다. 변경 전에 각 파일의 타임스탬프가 찍힌 사본을
`~/.apothem/backups/` 아래에 저장하며, 프로젝트에는 백업 파일이 남지 않습니다.
공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness kimi-code --project /path/to/project`를 다시 실행 |
| 검증 실패 | `apothem update --harness kimi-code --project /path/to/project`를 실행한 후 다시 검증 |
| Kimi Code에 스킬이나 도우미가 없음 | `--project`가 저장소 루트(`.git`을 포함하는 디렉터리)를 지정하는지 확인한 후 설치를 다시 실행 |
| Kimi Code가 도우미를 전혀 사용하지 않음 | 이름으로 요청. Kimi Code는 위임이 요청되지 않으면 작업을 직접 처리함 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 후 `apothem update --harness kimi-code --project /path/to/project`를 다시 실행 |

## 구성 노브

| 플래그 | 기본값 | 설명 |
|------|---------|-------------|
| `--dry-run` | `false` | 파일을 작성하지 않고 설치를 미리 봅니다. |
