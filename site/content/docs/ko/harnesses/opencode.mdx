**벤더:** OpenCode
**설치 이름:** `opencode`
**상태:** 베타
**네이티브 구성:** `~/.config/opencode/`(또는 `$XDG_CONFIG_HOME/opencode/`)

## 설치

```bash
apothem install --harness opencode
```

어댑터는 OpenCode의 JSON 구성을 작성하고, Apothem 스킬을 OpenCode 스킬 표면에
설치하며, 커맨드 프롬프트를 OpenCode Markdown 커맨드 파일로 변환하고, Apothem
도우미 정의를 OpenCode 하위 도우미로 정규화합니다.

**작성되는 파일:**

```text
~/.config/opencode/opencode.json
~/.config/opencode/apothem/rules/00-apothem-profile.md
~/.config/opencode/commands/
~/.config/opencode/skills/
~/.config/opencode/agents/
~/.config/opencode/.apothem/support/{rules,templates,hooks}/
```

이것은 기본 경로입니다. `XDG_CONFIG_HOME`이 절대 경로의 폴더로 설정되면, 어댑터는
대신 `$XDG_CONFIG_HOME/opencode/`에 작성하며, 이 폴더는 OpenCode 1과 OpenCode 2가
모두 읽는 폴더입니다. 상대 경로 값이나 파일 시스템 루트는 사용되지 않으며, 설치가
이를 알려 줍니다. `OPENCODE_CONFIG_DIR`는 따르지 않습니다. OpenCode 1은 그 폴더를
기본 폴더와 함께 읽지만 OpenCode 2는 기본 폴더 대신 그 폴더를 읽으므로, 이 변수가
다른 폴더를 가리키면 설치는 OpenCode 2가 이 설치를 로드하지 않는다고 경고합니다.

## 프로필에서 네이티브 구성으로의 매핑

어댑터는 여러분의 프로필 문서, 네 개의 핵심 규칙, 그리고 규칙 색인을 명시하는
`instructions` 파일 목록과 함께 `opencode.json`을 렌더링한 다음, 공유된 각
Apothem 코호트를 OpenCode 네이티브 표면 또는 Apothem 소유 지원 하위 트리로
전파합니다. 일치하는 기존 Apothem 관리 하위 항목은 교체 전에 백업됩니다.

## 호환성 참고 사항

이 설치는 OpenCode 1과 OpenCode 2에서 모두 작동합니다. 설치는 하나의 구성을
작성하며, OpenCode 1은 이를 그대로 읽고 OpenCode 2는 번역해서 읽습니다. 두 버전은
같은 구성 폴더를 읽고, OpenCode 2는 설치가 작성한 OpenCode 1 형태를 파일을 다시
쓰지 않고 메모리에서 변환합니다. 도우미의 `permission` 목록과 `mcp` 서버 항목은 이
번역을 거쳐 OpenCode 2에서 로드됩니다. OpenCode 1은 자체 구성 폴더에 `AGENTS.md`가
없고 `OPENCODE_DISABLE_CLAUDE_CODE`도 `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT`도
설정되지 않았을 때, Claude Code 설치가 `~/.claude/CLAUDE.md`에 작성하는 블록도
로드합니다. OpenCode 2에는 `CLAUDE.md` 폴백이 없으므로 그 파일을 로드하지 않습니다.

도우미 정의에는 도우미가 사용해서는 안 되는 도구에 대한 `deny` 규칙만 들어
있습니다. OpenCode는 기본적으로 모든 도구를 허용하고 `.env` 또는 `.env.*` 파일을
읽기 전에 묻습니다. 도우미에 `allow` 규칙이 있으면 그 질문이 꺼지고 여러분의
OpenCode 구성에 있는 더 엄격한 규칙도 덮어쓰게 되므로, 도우미는 여러분의
`permission` 설정을 따릅니다.

공유 프로필이 MCP 서버를 나열하면, 설치는 이를 `opencode.json`의 `mcp` 블록에
작성합니다. OpenCode는 `${NAME}`이 아니라 `{env:NAME}`을 치환하므로, 서버의
환경, 헤더 또는 URL에 있는 각 `${NAME}`은 `{env:NAME}`으로 작성됩니다. 명령
인수는 쓰인 그대로 복사됩니다. 그곳의 참조는 서버나 서버가 실행하는 셸이
확장하도록 남겨집니다. 환경 또는 헤더 값에 있는 `$NAME`과, 쓰인 그대로 남은 모든
`${...}` 형태는 (명령 인수에 있는 것도 포함해서) 쓰인 그대로 복사되며, 설치는
OpenCode가 이를 확장하지 않는다고 경고합니다. 경고는 `environment.TOKEN`처럼
참조가 있는 위치를 명시하며 값은 절대 출력하지 않습니다.

OpenCode는 `{env:NAME}` 값을 자신이 읽는 구성 텍스트에 이스케이프하지 않고
삽입합니다. OpenCode 2는 그 텍스트가 그렇지 않으면 파싱되지 않는 경우에만
이스케이프합니다. 그래서 백슬래시(예: Windows 경로), 큰따옴표 또는 제어 문자가
있는 값은 OpenCode 1이 파일을 읽지 못하게 만들 수 있고, 두 버전 모두에서 그 안의
`\t` 또는 `\n`이 서버에 제어 문자로 전달됩니다. 설치는 실행될 때 이런 변수를 각각
검사하고, 그런 문자가 들어 있는 변수에 대해 경고합니다. 다른 도구가 `${NAME}`
참조를 유지하도록, 대신 그 값을 `harnesses.opencode.mcp_servers.<name>` 아래에
`{file:path}`로 설정하세요.

OpenCode는 `instructions` 목록이 명시하는 모든 파일을 모든 세션에 결합합니다
([OpenCode 규칙](https://opencode.ai/docs/rules/)). 따라서 이 목록은 여러분의
프로필 문서를 먼저 명시하고, 그다음 `alwaysApply`가 `true`인 규칙만 규칙마다
하나의 명시적 경로(기본값은
`~/.config/opencode/.apothem/support/rules/<name>.md`)로
명시합니다. OpenCode는 앞에 오는 `~/`를 여러분의 홈 디렉터리 기준으로
확장합니다. 구성 폴더가 홈 디렉터리 밖에 있으면 경로는 절대 경로가 되며, 지원 하위
트리는 항상 구성 폴더 아래에 있습니다. 그 규칙들은 `agnostic-posture`,
`authority-inquiry`, `context-management`, `session-closure`, 그리고 규칙 색인
`apothem-rule-index`입니다. OpenCode는 어떤 규칙도 경로로 범위를 지정하지
않으므로, 다른 모든 규칙은 필요할 때 읽힙니다. 이 규칙들은
`~/.config/opencode/.apothem/support/` 아래에 참조 자료로 설치된 채 남으며, 색인은
각 규칙과 그 규칙이 필요한 상황을 명시합니다. 규칙, 템플릿, 또는 훅 프롬프트를
인용하는 규칙, 스킬, 또는 커맨드는 그곳에서 이를 읽습니다. 커맨드, 스킬, 도우미
정의는 네이티브 디스커버리 위치를 사용합니다.

프로필 문서 `~/.config/opencode/apothem/rules/00-apothem-profile.md`는 공유
프로필에서 가져온 여러분의 신원과 선호를 담고, Apothem 지원 파일 섹션으로
끝납니다. 이 섹션은 저장소 스타일의 각 인용(`rules/<name>.md`, `templates/...`,
`hooks/...`)이 해석되는 기준인 `~/.config/opencode/.apothem/support/` 아래의 절대
디렉터리를 명시합니다. 이 문서는 첫 번째 `instructions` 항목이므로 OpenCode는
모든 세션에서 이 문서를 로드합니다.

이전 릴리스가 작성한 `opencode.json`은 모든 규칙을 로드하는 단일 glob
`~/.config/opencode/.apothem/support/rules/*.md`를 나열하거나, 당시 상시
적용이던 28개 규칙 각각에 대한 명시적 경로를 나열합니다. `apothem
install`과 `apothem update`는 어느 형태든 위의 목록으로 교체하며, 이때 더 이상
시작 시 로드되지 않는 24개의 경로가 빠집니다. `apothem uninstall`은 그것들을
모두 제거합니다. 여러분이 직접 작성한
`instructions` 항목은 어떤 경우에도 유지됩니다.

## 검증

```bash
apothem verify --harness opencode
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML
   구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면
   `--profile PATH`를 추가하세요.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness opencode
```

`opencode.json`, 네이티브 커맨드, 스킬, 도우미 정의, 그리고 Apothem 지원 하위 트리를
새로 고칩니다. 설치가 작성한 MCP 서버를 여러분이 변경하지 않고 OpenCode 2의
`mcp.servers` 형태로 변환한 경우, 그 서버는 `mcp` 아래에 다시 작성되며 두 OpenCode
버전이 모두 그곳에서 읽습니다. `mcp.servers` 아래의 서버는 해당 `mcp` 항목이 없고
설치가 작성한 것과 전체적으로 일치할 때에만 그 변환으로 간주됩니다. 같은 이름의
여러분 자신의 서버, 여러분이 편집한 변환본, 비활성화한 변환본은 그대로 남습니다.
그런 변환본이 있어도 업데이트는 서버를 `mcp` 아래에 다시 작성하므로, OpenCode 1은
그 사본을, OpenCode 2는 변환된 것을 사용합니다. 두 버전 모두에서 서버를 꺼 두려면
프로필에서 제거하세요. 이를 위해서는 설치가 작성한 항목을 나열한 설치 기록이
필요하며, Apothem이 그 목록을 보관하기 전의 기록은 대상이 아닙니다.

## 제거

```bash
apothem uninstall --harness opencode
```

어댑터가 `~/.config/opencode/opencode.json`에 추가한 항목을 제거합니다(여러분의
키, MCP 서버, `instructions` 항목은 그대로 남으며, 이 파일은 Apothem이 직접
만들었고 여러분의 항목이 하나도 남아 있지 않은 경우에만 삭제됩니다). 설치가 작성한
MCP 서버를 여러분이 변경하지 않고 OpenCode 2의 `mcp.servers` 형태로 변환한 경우,
그 서버도 통째로 제거되며 `mcp.servers` 아래의 다른 서버는 그대로 남습니다.
`mcp.servers` 아래에 있는 여러분 자신의 서버가, 여러분이 설치의 `mcp` 항목을 제거한
뒤에, 설치가 작성한 서버와 일치하면 변환된 사본과 구별할 수 없으므로 함께
제거되며, 그에 앞서 파일이 백업됩니다. 프로필 문서
`~/.config/opencode/apothem/rules/00-apothem-profile.md`에서 Apothem 블록을
제거하고 그 안의 다른 텍스트는 유지하며, 이 파일은 그 안에 다른 내용이 남아 있지
않은 경우에만 삭제됩니다. 또한 `~/.config/opencode/commands/`,
`~/.config/opencode/skills/`, `~/.config/opencode/agents/`,
`~/.config/opencode/.apothem/support/`에 있는 Apothem 파일을 제거하며, 그
폴더들의 다른 파일은 그대로 남습니다. 각 파일은 변경하거나 제거하기 전에
`~/.apothem/backups/` 아래에 백업됩니다. 공유 프로필 YAML과 Apothem 엔진은 영향을
받지 않습니다.

`XDG_CONFIG_HOME`이 다른 폴더를 가리키는 동안 이전 릴리스가 `~/.config/opencode/`에
만든 설치는 그 자리에 남아 있으며, OpenCode는 그것을 읽은 적이 없습니다. 다음
설치가 이를 알려 줍니다. 제거하려면 `XDG_CONFIG_HOME`을 설정하지 않은 상태로
제거를 실행하세요.

## 적합성 게이트

python -m apothem.conformity.gate --all .

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness opencode`를 다시 실행 |
| 검증 실패 | `apothem update --harness opencode`를 실행한 다음 다시 검증 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 다음 `apothem update --harness opencode`를 다시 실행 |

|------|---------|-------------|
