**벤더:** Anthropic
**설치 이름:** `claude-code`
**상태:** GA
**네이티브 구성:** `~/.claude/`

## 설치

```bash
apothem install --harness claude-code
```

`claude-code` 어댑터는 공유 Apothem 코퍼스를 Claude Code의 네이티브 디스커버리
트리에 설치합니다. Markdown 에이전트, 규칙, 스킬, 출력 스타일, 설정은 각자의
네이티브 위치에 설치됩니다. 커맨드 프롬프트는 스킬로 변환되므로, 재사용 가능한
워크플로가 현재 Claude Code 스킬 표면을 통해 계속 보입니다. 상태 표시줄
렌더러는 `~/.claude/statuslines/`에 복사되지만 연결되지는 않습니다. Claude Code는
상태 표시줄을 `statusLine` 설정에서 읽는데, 어댑터는 이 설정을 비워 둡니다.
켜려면 `~/.claude/statuslines/render.py`를 실행하는 `"type": "command"`의
`statusLine` 항목을 `settings.json`에 추가하세요.

**작성되는 파일:** `~/.claude/` 아래의 `settings.json`, `CLAUDE.md` 안의 Apothem 블록, `agents/`, `rules/`, `skills/`,
`statuslines/`, `output-styles/`, 그리고 `.apothem/support/` 지원 하위 트리
(`.apothem/support/hooks/`, `.apothem/support/conformity/`,
`.apothem/support/schemas/`, `.apothem/support/templates/`).
커맨드 파일은 자식 스킬 디렉터리로 변환됩니다. 훅 디스패처와 적합성 게이트는
머티리얼라이즈된 사본에서 실행됩니다. `settings.json`의 훅 항목은
`~/.claude/.apothem/support/hooks/dispatch.py`와
`~/.claude/.apothem/support/conformity/gate.py`를 절대 경로로 호출하므로, 호스트에
임포트 가능한 `apothem` 패키지가 필요하지 않습니다.

`~/.claude/CLAUDE.md`는 운영자 소유로 남습니다. 어댑터는 이 파일에 센티널로
구분된 Apothem 블록 하나를 쓰는데, 이 블록에는 프로필 투영(신원, 선호, 규칙,
심각도, 옵트인한 동작)과 Apothem 지원 파일 섹션이 들어 있으며, 센티널 바깥의
모든 줄은 그대로 보존합니다. 지원 파일 섹션은 설치된 규칙, 스킬, 에이전트에 있는
저장소 스타일의 각 인용이 해석되는 기준 절대 디렉터리를 명시합니다.
`rules/<name>.md`는 `~/.claude/rules/` 아래, `templates/...`, `schemas/...`,
`hooks/...`, `conformity/...`는 `~/.claude/.apothem/support/` 아래입니다. Apothem
거버넌스 표면의 나머지는 전파된 `rules/` 트리와 SessionStart 훅을 통해 Claude
Code에 도달합니다. OpenCode도 `~/.config/opencode/AGENTS.md`가 없으면
`~/.claude/CLAUDE.md`를 로드하므로, 이 블록은 어느 한 도구도 독자로 지칭하지
않습니다.

## 프로필-네이티브 구성 매핑

`apothem install` 또는 `apothem update`를 실행할 때마다 어댑터는 전파
매니페스트에 따라 공유 `apothem` 코퍼스를 `~/.claude/`로 전파합니다. 어댑터는
가능한 경우 네이티브 디렉터리를 직접 사용하고 커맨드 프롬프트를 스킬 폴더로
변환합니다. 일치하는 기존 Apothem 관리 하위 항목은 교체 전에 백업되며, 관련 없는
운영자 작성 항목은 보존됩니다. `settings.json`은 병합되므로 운영자가 작성한 키를
계속 복구할 수 있습니다.

설치된 스킬과 Claude Code 플러그인에 번들된 스킬은 소스 코퍼스의
`userInvocable` 대신 `user-invocable`을 지닙니다. Claude Code가 하이픈이 들어간
키만 읽기 때문입니다. 두 템플릿 컨테이너(`plan-suite`, `research-suite`)는 이
값을 `false`로 설정하므로 `/` 메뉴에 나타나지 않습니다. 모든 출력 스타일은
`keep-coding-instructions: true`를 설정하므로, 어느 출력 스타일을 선택해도
Claude Code의 내장 소프트웨어 엔지니어링 지침이 유지됩니다.

## 호환성 참고 사항

커맨드 프롬프트는 스킬 디렉터리로 변환되며, 에이전트, 규칙, 스킬, 출력 스타일은
있는 그대로 복사됩니다. 설치는 프로필이 올바른 형식인지, 그리고 settings.json의
모든 훅 바인딩이 해석 가능한지 검증합니다. 어댑터는 MCP 서버 항목을 작성하지
않습니다. 서버는 `claude mcp add`로 등록하세요([MCP 서버](/docs/reference/mcp)
참조).

Claude Code는 세션이 시작될 때마다 settings.json의 모든 훅 바인딩을 적용합니다. 각 어댑터는 자체 네이티브 하니스에 대해 검증됩니다 — 특권을 가진 "참조" 하니스는 없습니다.

### 권한 규칙의 한계

설정 템플릿은 `.env*`와 `~/.ssh/**` 같은 시크릿 및 캐시 경로에 대해
`Read(...)`를 거부합니다. Claude Code는 `Read` 거부를 자체 파일 도구, Bash에서
인식하는 파일 명령(`cat`, `head`, `tail`, `sed`, `tee`), 리디렉션 대상에
적용합니다. `grep -r pattern .`처럼 파일 이름을 지정하지 않고 파일을 읽는
검색이나, 스스로 파일을 여는 스크립트에는 이 거부를 적용하지 않습니다
([권한 참조](https://code.claude.com/docs/en/permissions)). macOS, Linux, WSL에서
Claude Code는 기본 도구 세트에서 `Glob`과 `Grep` 도구를 제외하고 대신 Bash로
검색하므로, 템플릿의 `Glob` 및 `Grep` 허용 항목은 해당 도구가 있는 곳에서만
효력을 가집니다. 모든 프로세스가 어떤 경로를 읽지 못하도록 차단하려면 Claude
Code 샌드박스를 활성화하세요.

`TodoWrite`를 지칭하는 스킬과 도우미 정의는 `TaskCreate`, `TaskGet`, `TaskList`,
`TaskUpdate`도 함께 지칭합니다. Claude Code가 이 도구들을 우선하여 `TodoWrite`를
기본적으로 꺼 두기 때문입니다.

## 검증

```bash
apothem verify --harness claude-code
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML
   구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면
   `--profile PATH`를 추가하세요.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness claude-code
```

현재 공유 프로필에서 네이티브 구성을 다시 도출합니다. 설치된 `apothem` 패키지가
업데이트된 후에 실행하여, 전파된 규약 표면(에이전트, 규칙, 스킬, 상태 표시줄,
출력 스타일)이 새 버전을 반영하도록 하세요. `CLAUDE.md`에서 update는 센티널
사이의 Apothem 블록만 다시 씁니다.

## 제거

```bash
apothem uninstall --harness claude-code
```

`~/.claude/CLAUDE.md`에서 Apothem 블록을 제거하고, 그 안의 나머지 텍스트는
그대로 둡니다. 파일은 그 안에 다른 내용이 하나도 남지 않은 경우에만 삭제됩니다.
어댑터가 `~/.claude/settings.json`에 추가한 항목을 제거합니다(여러분이 작성한
권한 규칙, 키, 훅 핸들러는 그대로 남으며, 파일은 Apothem이 만들었고 여러분의
내용이 하나도 남지 않은 경우에만 삭제됩니다). 또한 `~/.claude/agents/`,
`~/.claude/rules/`, `~/.claude/skills/`, `~/.claude/statuslines/`,
`~/.claude/output-styles/`, `~/.claude/.apothem/support/`에 있는 Apothem 파일을
제거하며, 그 폴더들의 다른 파일은 그대로 남습니다. 각 파일은 변경 또는 제거되기
전에 `~/.apothem/backups/` 아래에 백업됩니다.
설치된 `apothem` 패키지와 소스 저장소는 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness claude-code`를 다시 실행 |
| 검증 실패 | `apothem update --harness claude-code`를 실행한 후 다시 검증 |
| 예기치 않은 구성 내용 | `apothem update`를 다시 실행. 진실의 원천은 `~/.claude/`가 아니라 공유 `apothem` 프로필 |

## 구성 노브

| 플래그 | 기본값 | 설명 |
|------|---------|-------------|
| `--dry-run` | `false` | 파일을 작성하지 않고 설치를 미리 봅니다. |
