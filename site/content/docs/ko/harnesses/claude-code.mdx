**벤더:** Anthropic
**설치 이름:** `claude-code`
**상태:** GA
**네이티브 구성:** `~/.claude/`

## 설치

```bash
apothem install --harness claude-code
```

`claude-code` 어댑터는 공유 Apothem 코퍼스를 Claude Code의 네이티브 디스커버리 트리에 설치합니다. Markdown 에이전트, 규칙, 스킬, 출력 스타일, 설정은 각자의 네이티브 위치에 설치됩니다. 커맨드 프롬프트는 스킬로 변환되므로, 재사용 가능한 워크플로가 현재 Claude Code 스킬 표면을 통해 계속 보입니다. 상태 표시줄 렌더러는 `~/.claude/statuslines/`에 복사되지만 연결되지는 않습니다. Claude Code는 상태 표시줄을 `statusLine` 설정에서 읽는데, 어댑터는 이 설정을 비워 둡니다. 켜려면 `settings.json`에 `"type": "command"`인 `statusLine` 항목을 추가하고, 이 항목이 `~/.claude/statuslines/render.py`를 실행하도록 하세요. 스니펫의 `commandWindows` 값은 Windows에서 실행되며 인터프리터를 따옴표 없이 지정합니다. 인터프리터 경로에 공백이 있고 볼륨에 8.3 단축 형식이 있으면, 설치 프로그램은 이 값에 Windows 8.3 단축 형식을 씁니다. `settings.json`의 훅 항목은 전체 경로를 유지합니다.

**작성되는 파일:** `~/.claude/` 아래의 `settings.json`, `CLAUDE.md` 안의 Apothem 블록, `agents/`, `rules/`, `skills/`,
`statuslines/`, `output-styles/`, 그리고 `.apothem/support/` 지원 하위 트리
(`.apothem/support/hooks/`, `.apothem/support/conformity/`,
`.apothem/support/schemas/`, `.apothem/support/templates/`).
커맨드 파일은 자식 스킬 디렉터리로 변환됩니다. 훅 디스패처와 적합성 게이트는
머티리얼라이즈된 사본에서 실행됩니다. `settings.json`의 훅 항목은
`~/.claude/.apothem/support/hooks/dispatch.py`와
`~/.claude/.apothem/support/conformity/gate.py`를 절대 경로로 호출하므로, 호스트에
임포트 가능한 `apothem` 패키지가 필요하지 않습니다.

`~/.claude/CLAUDE.md`는 운영자 소유로 남습니다. 어댑터는 이 파일에 센티널로
구분된 Apothem 블록 하나를 쓰는데, 이 블록에는 프로필 투영(신원, 선호, 규칙,
심각도, 옵트인한 동작)과 Apothem 지원 파일 섹션이 들어 있으며, 센티널 바깥의
모든 줄은 그대로 보존합니다. 지원 파일 섹션은 설치된 규칙, 스킬, 에이전트에 있는
저장소 스타일의 각 인용이 해석되는 기준 절대 디렉터리를 명시합니다.
`rules/<name>.md`는 `~/.claude/rules/` 아래, `templates/...`, `schemas/...`,
`hooks/...`, `conformity/...`는 `~/.claude/.apothem/support/` 아래입니다. 이
섹션은 규칙 색인 `~/.claude/rules/apothem-rule-index.md`도 가리킵니다. Apothem
거버넌스 표면의 나머지는 전파된 `rules/` 트리와 SessionStart 훅을 통해 Claude
Code에 도달합니다. OpenCode도 `~/.config/opencode/AGENTS.md`가 없으면
`~/.claude/CLAUDE.md`를 로드하므로, 이 블록은 어느 한 도구도 독자로 지칭하지
않습니다.

## 프로필-네이티브 구성 매핑

`apothem install` 또는 `apothem update`를 실행할 때마다 어댑터는 전파
매니페스트에 따라 공유 `apothem` 코퍼스를 `~/.claude/`로 전파합니다. 어댑터는
가능한 경우 네이티브 디렉터리를 직접 사용하고 커맨드 프롬프트를 스킬 폴더로
변환합니다. 일치하는 기존 Apothem 관리 하위 항목은 교체 전에 백업되며, 관련 없는
운영자 작성 항목은 보존됩니다. `settings.json`은 병합되므로 운영자가 작성한 키를
계속 복구할 수 있습니다.

운영자가 작성한 파일은 아래 폴더 바깥에만 보존됩니다. 설치와 업데이트를 실행할 때마다, Apothem이 기록했는지와 관계없이 `~/.claude/` 아래에 존재하는 다음 폴더 각각을 제거합니다: `src/`, `conformity/`, `schemas/`, `hooks/`, `config/`, `scripts/`, `tools/`, `lib/`, `templates/`, `docs/`, `tests/`, `packaging/`, `mcp/`, `examples/`, `assets/`, `site/`, `public/`, `commands/`. 또한 `statuslines/__init__.py`와, `agents/`, `rules/`, `skills/`, `statuslines/`, `output-styles/` 안의 `AGENTS.md` 파일을 제거합니다. 제거되는 폴더는 그 안에 넣어 둔 파일까지 포함해 통째로 사라집니다. `commands/`에 보관한 슬래시 명령도 제거되며, Apothem은 자체 명령 프롬프트를 `skills/` 아래에 스킬로 설치합니다. `hooks/`에 보관한 훅 스크립트는 제거되므로, 이를 호출하는 `settings.json` 항목은 아무것도 가리키지 않게 됩니다. 이 정리(스위프)는 설치가 자체 파일을 쓰기 전에 실행됩니다. 제거되는 각 경로는 먼저 `~/.apothem/backups/`로 복사되며, 설치 기록에 그 복사본이 명시됩니다. 제거(uninstall)는 이를 복원하지 않습니다. 제거된 경로를 복원하려면, 그 경로를 제거한 설치에 대해 [롤백 참조](/docs/cli-reference/rollback)에 설명된 대로 `apothem rollback --harness claude-code --install-id ID`를 실행하세요. 옵션 없이 실행하는 `apothem rollback`은 가장 최근 설치만 되돌립니다. 설치 기록과 그 복사본은 가장 최근 10회 설치분까지만 보관되므로, 제거된 경로는 해당 설치가 그중에 있을 때에만 복원할 수 있습니다. 설치하기 전에 `apothem diff --harness claude-code`를 실행하면 이 제거 항목이 `Prune stale files`로 나열됩니다.

설치된 스킬과 Claude Code 플러그인에 번들된 스킬은 소스 코퍼스의
`userInvocable` 대신 `user-invocable`을 지닙니다. Claude Code가 하이픈이 들어간
키만 읽기 때문입니다. 두 템플릿 컨테이너(`plan-suite`, `research-suite`)는 이
값을 `false`로 설정하므로 `/` 메뉴에 나타나지 않습니다. 모든 출력 스타일은
`keep-coding-instructions: true`를 설정하므로, 어느 출력 스타일을 선택해도
Claude Code의 내장 소프트웨어 엔지니어링 지침이 유지됩니다.

두 종류의 스킬 모두 Apothem 전용 프런트매터 키(`version`, `updated`,
`archetype`, `portability`)를 따옴표로 묶인 문자열로 이루어진 끝부분의 `metadata:` 맵
아래에 이 고정된 순서로 담습니다. Claude Code는 알 수 없는 최상위 키를 무시하며,
개방형 스킬 형식은 클라이언트별 추가 항목을 `metadata`에 둡니다. 소스 파일은
변경되지 않습니다. 사용자 수준 스킬 폴더(`~/.agents/skills/`,
`~/.codebuddy/skills/`, `~/.kiro/skills/`, `~/.trae/skills/`)도 같은
`metadata` 형식을 사용하므로, 폴더를 공유하는 설치들이 서로의 파일을 다시 쓰는
일이 없습니다. 다른 모든 하니스는 이전과 같이 이 키들을 최상위에서 받습니다.

### 규칙과 시작 시 로드되는 항목

Claude Code는 규칙 파일의 프런트매터에 범위를 지정하는 `paths:` 목록이 없으면
시작 시 그 파일을 로드합니다. `paths:`가 있으면 일치하는 파일을 읽거나 편집할 때
규칙을 로드합니다. `**`로만 이루어진 목록은 아무 범위도 지정하지 않으므로 그
규칙도 시작 시 로드됩니다. 그런 목록을 쓰는 Apothem 규칙은 없습니다. 설치는 각
규칙의 `pathFilter`를 그 목록으로 바꿉니다. 다섯 개의 규칙은 이 필터가 없어
모든 세션에서 로드됩니다: `agnostic-posture`, `authority-inquiry`,
`session-closure`, `context-management`, 그리고 규칙 색인
`apothem-rule-index`. 다른 모든 규칙은 `paths:`와 함께 `~/.claude/rules/` 아래에
설치되며 일치하는 파일을 건드릴 때 로드됩니다.

Claude Code는 이 글롭을 `.gitignore` 의미론에 따라 작업 디렉터리를 기준으로 한
파일의 상대 경로와 대조하며, 작업 디렉터리 밖의 파일과는 절대 대조하지 않습니다.
자동 메모리 디렉터리는 `~/.claude/projects/` 아래에 있으므로
`auto-memory`와 `auto-memory-topic-files`는 경로 일치로 로드되는 일이 없습니다.
다른 프로젝트에서 `~/.claude/CLAUDE.md`나 `~/.claude/rules/` 아래의 파일을
편집해도 그 파일들로 범위가 지정된 규칙은 로드되지 않습니다. 이 규칙들은 색인을
통해 세션에 도달합니다.

색인은 각 규칙과 그 규칙이 필요한 상황을 명시합니다. `rules/<name>.md`를 절차로
인용하는 단계는 그 파일을 먼저 읽습니다. 컨텍스트 압축 후에는 적용하던 규칙을
다시 읽으세요. Claude Code는 일치하는 파일을 다시 건드릴 때까지 경로 범위 규칙을
다시 주입하지 않습니다. `apothem-rule-index.md`라는 이름은 예약되어 있습니다.
설치가 그 이름의 규칙 파일을 백업하고 덮어쓰기 때문입니다.

Apothem 자체 표면을 관장하는 규칙은 `CLAUDE.md`,
`AGENTS.md`, 그리고 `rules/`, `commands/`, `skills/`, `agents/`,
`hooks/`, `output-styles/` 아래의 Markdown으로 범위가 지정됩니다. 애플리케이션
저장소에는 이런 파일이 거의 없으므로, 그런 저장소에서 이 규칙들은 경로 일치가
아니라 색인, 규칙을 인용하는 스킬, 커맨드 또는 도우미, 그리고 훅을 통해 세션에
도달합니다.

규칙 사본은 커맨드 스킬과 마찬가지로 마지막 `## Bindings` 섹션 없이
작성됩니다. 이 섹션에는 유지 관리자와 적합성 게이트를 위한 상호 참조가 들어
있습니다. 소스 파일은 이 섹션을 유지하며, 다른 하니스가 받는 사본도 마찬가지입니다.

범위가 지정된 규칙을 모든 세션에서 켜 두려면, `~/.claude/CLAUDE.md`의 Apothem
블록 바깥 텍스트에서 그 규칙을 임포트해 볼 수 있습니다. 예:
`@rules/definitiveness.md`. Claude Code 메모리 페이지는 임포트를 문서화하며,
임포트된 경로는 임포트하는 파일을 기준으로 해석된다고 말합니다. 임포트된 규칙의
`paths` 목록이 어떻게 처리되는지는 말하지 않으며, Apothem은 이를 검증하지
않았습니다. `InstructionsLoaded` 훅으로 그 규칙이 시작 시 로드되고 경로 일치 시
두 번째로 로드되지 않는지 확인하세요.

### 커맨드 스킬과 참조 파일

컨텍스트 압축 후 Claude Code는 호출된 각 스킬의 처음 5,000 토큰만 다시
첨부하며, 세부 내용은 형제 파일에 두고 `SKILL.md`는 약 500줄 이하로 유지할 것을
권장합니다. 커맨드 프롬프트는 최대 67 KB에 이르므로, Claude Code 출력은 각
프롬프트를 슬림한 `SKILL.md`와 `references/` 아래의 파일들로 분할합니다.

- `## Bindings` 섹션은 삭제됩니다. 이는 적합성 게이트를 위한 유지 관리자
  텍스트이며 모델에는 전혀 필요하지 않습니다.
- Pipeline Contract, Foundational Stanzas, Decision Tree, 예시, 모드 섹션, 그리고
  인용된 몇몇 인벤토리는 참조 파일로 옮겨집니다. 제목은 그대로 남고, 그 아래의
  한 줄짜리 포인터가 파일을 명시하고 언제 읽어야 하는지 알려 줍니다. Pipeline
  Contract와 Foundational Stanzas의 포인터는 파일이 다루는 내용도 나열합니다.
- `SKILL.md`가 여전히 15,800바이트를 넘으면, 가장 큰 Workflow 단계부터
  차례로 `references/step-NN-<slug>.md`로 옮겨 크기에 맞을 때까지 계속합니다. slug는
  `Step N:` 접두사와 끝의 괄호로 묶인 의무 또는 규율 ID를 뺀 단계 제목입니다.
  600바이트 미만의 단계는 인라인으로 남습니다. 그래도 충분하지 않으면 Output,
  Mandates, Critical Rules, Instructions 섹션이 이 순서대로 옮겨집니다.
- 서문 뒤의 짧은 메모가 모델에게 파일의 위치
  (`${CLAUDE_SKILL_DIR}/references/`)와, 압축 후에는 현재 단계를 관장하는 파일을
  반드시(MUST) 다시 읽어야 한다는 것을 알려 줍니다.

설치가 덧붙이는 `## Installed Reference Paths` 메모를 포함해, 출력되는 모든
`SKILL.md`는 최대 140자의 설치 루트에 대해 17,000바이트 이하를 유지합니다.
플러그인은 그 메모 없이 같은 파일을 제공하며, 플러그인의 커맨드는 `skills/` 아래의
스킬이므로 `commands/` 폴더가 없습니다. 호출 `/apothem:<name>`은 변경되지
않습니다. 분할은 결정적이며 되돌릴 수 있습니다. `SKILL.md`와 그 참조 파일의
텍스트로 Bindings를 뺀 소스 커맨드를 다시 만들 수 있습니다. 소스 파일과 다른 모든
하니스의 출력은 변경되지 않습니다. 다른 도구도 `~/.claude/skills/`에서 스킬을
읽으므로 같은 파일을 보게 되며, `apothem install`이 그 도구들을 명시합니다.

모든 커맨드의 수치를 보려면 체크아웃에서 측정 스크립트를 실행하세요.

```bash
python scripts/dev/measure_claude_skills.py          # per-command table
python scripts/dev/measure_claude_skills.py --check  # exit 1 on a breach
```

이 스크립트는 소스, `SKILL.md`, 참조 파일의 크기, 예산까지의 여유분, 추정 토큰
수를 보고하며, 비교를 위해 네이티브 스킬을 나열합니다. 소스가 분할되지 않는
네이티브 스킬인 `research-suite`가 상한을 넘는 유일한 스킬입니다.

## 호환성 참고 사항

커맨드 프롬프트는 스킬 디렉터리로 변환되고 규칙은 위에서 설명한 대로
렌더링됩니다. 스킬과 출력 스타일은 있는 그대로 복사되며, 에이전트는 작성된
그대로 복사되지만 프로필의 `agent_mcp_servers` 키가 나열하는 도우미는 지정된
서버마다 `tools` 줄에 `mcp__<server>__*` 항목이 추가됩니다
([MCP 서버](/docs/reference/mcp#헬퍼에-mcp-서버-접근-권한-부여하기) 참조).
설치는 프로필이 올바른 형식인지, 그리고 settings.json의
모든 훅 바인딩이 해석 가능한지 검증합니다. 어댑터는 MCP 서버 항목을 작성하지
않습니다. 서버는 `claude mcp add`로 등록하세요([MCP 서버](/docs/reference/mcp)
참조).

`~/.claude/agents/`는 `~/.claude/skills/`와 마찬가지로 `Claude Code`가 소유하는
공유 루트입니다. 지원되는 다른 도구들이 이 폴더를 로드하므로, `Claude Code`
설치가 그곳에 작성하는 에이전트와 스킬은 그 도구들에서도 나타나며, 설치는 그
도구들을 명시하는 메모를 출력합니다.
[하니스 레지스트리](/docs/reference/harness-registry)는 각 루트를 읽는 도구를
나열합니다.

Claude Code는 세션이 시작될 때마다 settings.json의 모든 훅 바인딩을 적용합니다. 각 어댑터는 자체 네이티브 하니스에 대해 검증됩니다 — 특권을 가진 "참조" 하니스는 없습니다.

### 권한 규칙의 한계

설정 템플릿은 `.env*`와 `~/.ssh/**` 같은 시크릿 및 캐시 경로에 대해
`Read(...)`를 거부합니다. Claude Code는 `Read` 거부를 자체 파일 도구, Bash에서
인식하는 파일 명령(`cat`, `head`, `tail`, `sed`, `tee`), 리디렉션 대상에
적용합니다. `grep -r pattern .`처럼 파일 이름을 지정하지 않고 파일을 읽는
검색이나, 스스로 파일을 여는 스크립트에는 이 거부를 적용하지 않습니다
([권한 참조](https://code.claude.com/docs/en/permissions)). macOS, Linux, WSL에서
Claude Code는 기본 도구 세트에서 `Glob`과 `Grep` 도구를 제외하고 대신 Bash로
검색하므로, 템플릿의 `Glob` 및 `Grep` 허용 항목은 해당 도구가 있는 곳에서만
효력을 가집니다. 모든 프로세스가 어떤 경로를 읽지 못하도록 차단하려면 Claude
Code 샌드박스를 활성화하세요.

`TodoWrite`를 지칭하는 스킬과 도우미 정의는 `TaskCreate`, `TaskGet`, `TaskList`,
`TaskUpdate`도 함께 지칭합니다. Claude Code가 이 도구들을 우선하여 `TodoWrite`를
기본적으로 꺼 두기 때문입니다.

## 검증

```bash
apothem verify --harness claude-code
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML
   구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면
   `--profile PATH`를 추가하세요.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness claude-code
```

현재 공유 프로필에서 네이티브 구성을 다시 도출합니다. 설치된 `apothem` 패키지가
업데이트된 후에 실행하여, 전파된 규약 표면(에이전트, 규칙, 스킬, 상태 표시줄,
출력 스타일)이 새 버전을 반영하도록 하세요. `CLAUDE.md`에서 update는 센티널
사이의 Apothem 블록만 다시 씁니다.

## 제거

```bash
apothem uninstall --harness claude-code
```

`~/.claude/CLAUDE.md`에서 Apothem 블록을 제거하고, 그 안의 나머지 텍스트는
그대로 둡니다. 파일은 그 안에 다른 내용이 하나도 남지 않은 경우에만 삭제됩니다.
어댑터가 `~/.claude/settings.json`에 추가한 항목을 제거합니다(여러분이 작성한
권한 규칙, 키, 훅 핸들러는 그대로 남으며, 파일은 Apothem이 만들었고 여러분의
내용이 하나도 남지 않은 경우에만 삭제됩니다). 또한 `~/.claude/agents/`,
`~/.claude/rules/`, `~/.claude/skills/`, `~/.claude/statuslines/`,
`~/.claude/output-styles/`, `~/.claude/.apothem/support/`에 있는 Apothem 파일을
제거하며, 그 폴더들의 다른 파일은 그대로 남습니다. 각 파일은 변경 또는 제거되기
전에 `~/.apothem/backups/` 아래에 백업됩니다.
설치된 `apothem` 패키지와 소스 저장소는 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

저장소를 대상으로 실행하면, 게이트는 모든 규칙, 커맨드, 도우미, 스킬에
`## Bindings` 섹션을 요구합니다. 설치된 `~/.claude/` 트리를 대상으로 실행하면,
설치가 그 섹션을 빼므로 섹션이 없는 규칙 또는 스킬 사본을 허용하며, 섹션이 있으면
여전히 검사합니다.

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness claude-code`를 다시 실행 |
| 검증 실패 | `apothem update --harness claude-code`를 실행한 후 다시 검증 |
| 예기치 않은 구성 내용 | `apothem update`를 다시 실행. 진실의 원천은 `~/.claude/`가 아니라 공유 `apothem` 프로필 |
