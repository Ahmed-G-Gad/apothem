**벤더:** Antigravity
**설치 이름:** `antigravity`
**상태:** 미리 보기
**네이티브 구성:** `~/.gemini/GEMINI.md` 및
`~/.gemini/antigravity-cli/plugins/apothem/`

## 설치

```bash
apothem install --harness antigravity
```

어댑터는 공유 프로필을 `~/.gemini/GEMINI.md`로 렌더링하고 Apothem 지원
코호트를 Antigravity CLI 플러그인으로 설치합니다.

**작성되는 파일:** `~/.gemini/GEMINI.md`,
`~/.gemini/antigravity-cli/plugins/apothem/plugin.json`,
`~/.gemini/antigravity-cli/plugins/apothem/skills/`,
`~/.gemini/antigravity-cli/plugins/apothem/rules/`,
플러그인 내부의 변환된 로컬 도우미 정의,
`~/.gemini/antigravity-cli/plugins/apothem/.apothem/support/templates/`,
`~/.gemini/antigravity-cli/plugins/apothem/.apothem/support/hooks/`.

`~/.gemini/GEMINI.md`의 Apothem 블록은 Apothem 지원 파일 섹션으로 끝나며, 이
섹션은 저장소 스타일의 각 인용이 해석되는 기준 절대 디렉터리를 명시합니다.
`rules/<name>.md`는 플러그인의 `rules/` 아래, `templates/...`와 `hooks/...`는
플러그인의 `.apothem/support/` 아래입니다.

**플러그인 규칙.** Antigravity는 플러그인의 `rules/` 디렉터리에 있는 파일 중
유효한 `trigger`로 시작하지 않는 파일을 모두 버리므로
([Antigravity 규칙 문서](https://antigravity.google/docs/rules)), 각 Apothem
규칙은 설치 시 변환됩니다. 항상 적용되는 규칙은 `trigger: always_on`을 받고,
경로로 범위가 지정된 규칙은 `globs`에 같은 패턴을 담은 `trigger: glob`을 받으며,
그 밖의 규칙은 `trigger: model_decision`을 받습니다. 모든 규칙은 자신의
`description`을 유지합니다. Antigravity에서는 상시 적용 규칙 전체가 20,000토큰
예산 하나를 공유하며, Antigravity는 이 예산을 넘으면 가장 큰 규칙을 필요할 때 불러오는
포인터로 바꿉니다.

**플러그인 매니페스트.** `plugin.json`은 Antigravity의 플러그인 스키마가
허용하는 두 키인 `name`과 `description`만 담습니다.

**플러그인 도우미.** 플러그인의 `agents/` 디렉터리에 있는 도우미 정의는
`name`과 `description`을 담습니다. Antigravity의 `tools` 목록은 자체 도구
이름을 사용하며, 문서는 알 수 없는 이름이 서브에이전트를 멈추게 할 수 있다고
경고합니다. 그래서 도구 목록은 내보내지 않으며, 도우미는 부모의 도구를
상속합니다. Antigravity에는 읽기 전용 제한을 강제하는 장치가 없으므로, 해당
도우미의 설명에서는 "읽기 전용" 레이블이 빠집니다.

**공유 사용자 앵커.** `~/.gemini/GEMINI.md`는 Gemini 계열 도구의 사용자 범위
앵커이기도 합니다. Antigravity 어댑터는 추가 Apothem 자료를
`~/.gemini/antigravity-cli/plugins/` 아래의 `apothem` 플러그인 안에 두므로
일반 Gemini CLI 프로젝트 디렉터리를 점유하지 않습니다. 둘 이상의 도구가
`~/.gemini/GEMINI.md`를 로드하므로, 그곳의 Apothem 블록은 어느 한 도구도
독자로 지칭하지 않는 전역 지침으로 작성됩니다.

## 프로필-네이티브 구성 매핑

어댑터는 `apothem install` 또는 `apothem update`를 실행할 때마다 Apothem의
공유 프로필을 읽고 지침 앵커와 지원 코호트를 렌더링합니다.

## 호환성 참고 사항

미리 보기 어댑터입니다. `GEMINI.md` 앵커는 활성 지침 콘텐츠입니다.
Antigravity 플러그인은 변환된 커맨드 스킬, 재사용 가능한 스킬, 로컬 도우미 정의,
규칙, 템플릿, 훅 지원 자료를 명확한 Apothem 소유 네임스페이스에 보존합니다.
어댑터가 Antigravity `hooks.json`에 대한 스키마 변환 계층을 갖추기 전까지 훅
파일은 활성 Antigravity 훅 이벤트로 등록되지 않습니다.

## 검증

```bash
apothem verify --harness antigravity
```

verify 명령은 다음을 확인합니다.

1. 네이티브 컨텍스트 파일이 예상 경로에 존재합니다.
2. Apothem Antigravity CLI 플러그인 메타데이터가 존재하며 `apothem` 플러그인
   이름을 선언합니다.

## 업데이트

```bash
apothem update --harness antigravity
```

현재 공유 프로필 상태에서 네이티브 구성을 다시 도출합니다.
`~/.config/apothem/profile.yaml`을 편집하거나 설치된 Apothem 패키지를
업그레이드한 후에 실행하세요.

## 제거

```bash
apothem uninstall --harness antigravity
```

어댑터가 작성한 네이티브 구성 파일을 제거합니다.
공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness antigravity`를 다시 실행 |
| 검증 실패 | `apothem update --harness antigravity`를 실행한 후 다시 검증 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 후 `apothem update --harness antigravity`를 다시 실행 |
