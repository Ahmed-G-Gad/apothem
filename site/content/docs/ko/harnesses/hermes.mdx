**공급업체:** Hermes
**설치 이름:** `hermes`
**상태:** 미리 보기
**네이티브 구성:** `~/.hermes/config.yaml`

## 설치

```bash
apothem install --harness hermes
```

어댑터는 공유 프로필을 Hermes Agent 사용자 전역 구성 파일로 번역하고, 하니스
루트 아래에 Apothem 지원 코호트를 설치합니다.

**작성되는 파일:** `~/.hermes/config.yaml` 및 `~/.hermes/.apothem/support/` 아래의 지원
파일

## 프로필에서 네이티브 구성으로의 매핑

어댑터는 Apothem의 공유 프로필을 읽고 네이티브 YAML 구성을 렌더링합니다. Hermes
자체의 스킬 표면은 `skills.config` — Hermes가 동적 슬래시 명령으로 자동
노출하는 설치 가능한 레지스트리 패키지 — 이며, Apothem은 이를 작성하지 않습니다.
대신 Apothem은 공유 명령 및 스킬 콘텐츠를 `~/.hermes/.apothem/support/` 아래의 지원
자료로 전달하며, 네이티브 지시 앵커에서 참조합니다. 헬퍼 정의, 규칙, 템플릿,
훅 프롬프트도 마찬가지로 `~/.hermes/.apothem/support/` 아래의 지원 자료로 남습니다.

## 호환성 참고 사항

미리 보기 어댑터. 네이티브 YAML 구성이 활성 Hermes 표면입니다. Apothem은 스킬에
대해 문서화된 외부 스킬 디렉터리 훅을 사용하고, 다른 코호트는 설치된 안내를 위한
참조 자료로 유지합니다.

## 검증

```bash
apothem verify --harness hermes
```

verify 명령은 다음을 확인합니다:

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 공유 프로필의 모든 필수 필드가 존재합니다.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness hermes
```

현재 공유 프로필 상태에서 네이티브 구성을 다시 파생합니다.
`~/.config/apothem/profile.yaml`을 편집하거나 설치된 Apothem 패키지를
업그레이드한 후에 실행하세요.

## 제거

```bash
apothem uninstall --harness hermes
```

어댑터가 작성한 네이티브 구성 파일을 제거합니다.
공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness hermes`를 다시 실행하세요 |
| 검증 실패 | `apothem update --harness hermes`를 실행한 후 다시 검증하세요 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 후 `apothem update --harness hermes`를 다시 실행하세요 |

## 구성 노브

| 플래그 | 기본값 | 설명 |
|------|---------|-------------|
| `--dry-run` | `false` | 파일을 작성하지 않고 설치를 미리 봅니다. |
