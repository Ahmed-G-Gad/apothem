**벤더:** Hermes
**설치 이름:** `hermes`
**상태:** 미리 보기
**네이티브 구성:** `~/.hermes/config.yaml`

## 설치

```bash
apothem install --harness hermes
```

어댑터는 공유 프로필을 Hermes Agent 사용자 전역 구성 파일로 변환하고, 하니스
루트 아래에 Apothem 지원 코호트를 설치합니다.

**작성되는 파일:** `~/.hermes/config.yaml`, 프로필 문서
`~/.hermes/apothem/rules/00-apothem-profile.md`, 그리고
`~/.hermes/.apothem/support/` 아래의 지원 파일

프로필 문서는 Apothem 지원 파일 섹션으로 끝나며, 이 섹션은 저장소 스타일의 각
인용(`rules/<name>.md`, `templates/...`, `hooks/...`)이 해석되는 기준인
`~/.hermes/.apothem/support/` 아래의 절대 디렉터리를 명시합니다.

## 프로필-네이티브 구성 매핑

어댑터는 Apothem의 공유 프로필을 읽고, 프로필의 MCP 인벤토리를 포함한 네이티브 YAML 구성을 렌더링합니다. MCP 서버는 프로필의 `mcp_servers` 섹션에서 가져옵니다. 이들은 설치와 업데이트마다 파일로 복사되지 않고 `config.yaml`에 렌더링됩니다. 어댑터는 또한 Hermes가 읽는 추가 스킬 디렉터리 목록인 `skills.external_dirs`에 `~/.hermes/.apothem/support/skills`를 추가하며, Hermes는 이를 통해 설치된 스킬을 찾습니다. 이 항목은 여러분이 이미 나열한 항목 뒤에 들어가며, 여러분의 다른 키는 그대로 유지됩니다. 프로필의 신원, 선호, 규칙은 프로필 문서에 들어갑니다. 공유 커맨드, 스킬, 도우미 정의, 규칙, 템플릿, 훅 프롬프트는 `~/.hermes/.apothem/support/` 아래에 지원 자료로 배치됩니다.

## 호환성 참고 사항

미리 보기 어댑터입니다. Hermes는 `skills.external_dirs`를 통해 Apothem 스킬을
로드하지만, 지원 하위 트리의 나머지나 프로필 문서는 스스로 로드하지 않습니다.
`config.yaml`의 다른 어떤 항목도, Hermes가 읽는 어떤 컨텍스트 파일도 그곳을
가리키지 않으므로, 설치 후 Hermes는 Apothem의 규칙이나 훅 없이 실행됩니다.

**이름 충돌.** Hermes는 스킬에 대해 다음 우선순위를 문서화합니다: 프로젝트의
스킬(`<project>/.hermes/skills/` 및 `<project>/.agents/skills/`), 그다음
`~/.hermes/skills/`, 그다음 `skills.create_dir`, 그다음 `skills.external_dirs`
아래에 나열된 폴더. Apothem 디렉터리는 `external_dirs` 항목이므로 마지막에
옵니다. 검토한 Hermes 문서는 두 위치에 같은 이름의 스킬이 있을 때 Hermes가 어느
사본을 로드하는지 밝히지 않습니다. Apothem은 이 순서를 앞선 위치가 이기는
것으로 해석하므로, 앞선 위치에 여러분이 두고 있는 같은 이름의 스킬이 Apothem
사본보다 우선할 것으로 예상하세요. Apothem은 `config.yaml`과
`~/.hermes/.apothem/support/` 아래에만 작성하고 앞선 위치에는 절대 작성하지
않으므로, 설치, 업데이트, 제거는 여러분이 그곳에 둔 스킬을 교체하지 않습니다.

`apothem update`는 `skills.config`와 여러분이 직접 넣은 `skills.external_dirs`
항목을 포함해 여러분이 `config.yaml`에 추가한 키를 유지합니다. 어댑터는 프로필의
MCP 인벤토리를 Hermes가 MCP 서버를 읽는 최상위 `mcp_servers` 키 아래에 작성합니다.
이전 Apothem 릴리스는 이를 `auxiliary.mcp` 아래에 작성했는데, Hermes는 이 키를
MCP 도구 디스패치용 보조 모델로 읽습니다. `apothem update`와
`apothem uninstall`은 모두, 그 블록이 그러한 릴리스가 여러분의 현재 공유
프로필로부터 작성했을 내용과 여전히 일치할 때 그 블록을 제거합니다(블록이 남는
경우는 [제거](#제거) 참조).
(Hermes 동작은
[스킬](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)(2026-10-24에
확인)과
[MCP](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/mcp.md)(2026-10-02에
확인)에 관한 사용자 가이드 페이지를 따릅니다.)

**`config.yaml`의 주석.** Apothem은 주석을 삭제하는 YAML 라이브러리로 파일을 다시
씁니다. 파일에 여러분의 주석이 있고 항목이 없으면, Apothem은 파일을 건드리지 않고
설치는 그 키를 명시하는 메시지와 함께 중단됩니다. 항목을 직접 추가한 다음 설치를
다시 실행하세요.

```yaml
skills:
  external_dirs:
    - ~/.hermes/.apothem/support/skills
```

여러분이 직접 추가한 항목은 여러분의 것으로 간주됩니다. 이 디렉터리를 이미
나열하고 있다면 Apothem은 여러분의 항목을 그대로 유지하며, 제거는 그 항목을
그대로 둡니다.

## 검증

```bash
apothem verify --harness hermes
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML
   구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면
   `--profile PATH`를 추가하세요.
3. 네이티브 구성의 `skills.external_dirs`가
   `~/.hermes/.apothem/support/skills`를 나열합니다. 이 항목이 없으면 Hermes는
   설치된 스킬을 로드하지 않습니다. `apothem update`가 이를 다시 추가합니다.
4. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness hermes
```

현재 공유 프로필 상태에서 네이티브 구성을 다시 도출합니다. `skills.external_dirs`의
Apothem 항목은 몇 번을 업데이트하든 한 번만 나열됩니다.
`~/.config/apothem/profile.yaml`을 편집하거나 설치된 Apothem 패키지를
업그레이드한 후에 실행하세요.

## 제거

```bash
apothem uninstall --harness hermes
```

어댑터가 추가한 것을 제거합니다. 설치가 `config.yaml`에 기록한 `mcp_servers`
항목과 `skills.external_dirs` 항목(여러분이 직접 넣은 `external_dirs` 항목과
`skills.config`를 포함해 여러분의 키는 유지되며, 파일은 Apothem이 만들었고 여러분의 것이 하나도
남아 있지 않을 때만 삭제됨), 프로필 문서, 지원 하위 트리입니다. 공유 프로필 YAML과
Apothem 엔진은 영향을 받지 않습니다.

프로필의 서버를 `auxiliary.mcp` 아래에 작성한 이전 릴리스로 수행한 설치에서도,
그 블록이 해당 릴리스가 `~/.config/apothem/profile.yaml`의 여러분의 현재 공유
프로필로부터 작성했을 내용과 여전히 일치하면 그 블록이 제거됩니다. 이는
`apothem update`가 적용하는 것과 같은 규칙이므로, 먼저 업데이트하지 않고
제거해도 프로필의 MCP 서버가 바뀌지 않은 한 오래된 블록이 남지 않습니다. 여러분이
편집한 블록, 여러분의 현재 프로필의 MCP 서버와 더 이상 일치하지 않는 블록,
또는 비교 대상으로 읽을 수 있는 공유 프로필이 없는 블록은 그대로 남으며,
여러분의 나머지 `auxiliary` 설정은 항상 유지됩니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness hermes`를 다시 실행 |
| 검증 실패 | `apothem update --harness hermes`를 실행한 후 다시 검증 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 후 `apothem update --harness hermes`를 다시 실행 |
| 설치가 `config.yaml`의 주석에 관한 메시지와 함께 중단됨 | Apothem은 주석을 제거해야 하는 파일을 다시 쓰지 않습니다. [호환성 참고 사항](#호환성-참고-사항) 아래에 표시된 `skills.external_dirs` 항목을 직접 추가한 다음 설치를 다시 실행하세요 |
| Apothem 스킬이 Hermes에 나타나지 않음 | 프로젝트나 `~/.hermes/skills/`에 있는 같은 이름의 스킬이 Apothem 사본보다 우선할 수 있습니다. Hermes는 조회 순서는 문서화하지만 충돌 규칙은 문서화하지 않습니다([호환성 참고 사항](#호환성-참고-사항) 참조). 또한 `apothem verify --harness hermes`를 실행하세요 |
