**벤더:** OpenAI
**설치 이름:** `codex`
**상태:** 베타
**네이티브 구성:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml`, 그리고 `~/.agents/skills/`

## 설치

```bash
apothem install --harness codex
```

어댑터는 Codex 네이티브 지침과 훅을 설치하고, Apothem 에이전트를 Codex TOML
에이전트로 변환하며, 재사용 가능한 커맨드 프롬프트를 Codex 스킬로 래핑합니다.

**작성되는 파일:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml`,
`~/.agents/skills/*/SKILL.md`, 사용자 호출 스킬용
`~/.agents/skills/*/agents/openai.yaml`, 그리고
`~/.config/apothem/{rules,templates}/` 아래의 지원 파일.

`AGENTS.md`의 Apothem 블록은 Apothem 지원 파일 섹션으로 끝나며, 이 섹션은
설치된 스킬과 규칙에 있는 저장소 스타일의 각 인용이 해석되는 기준 절대
디렉터리를 명시합니다. `rules/<name>.md`와 `templates/...`는
`~/.config/apothem/` 아래, `hooks/...`는 `~/.codex/hooks/` 아래입니다. Codex
설치는 `schemas/`나 `conformity/` 트리를 제공하지 않으므로, 이 섹션은 둘 다
나열하지 않습니다.

**사용자 호출 스킬.** Codex는 `disable-model-invocation` 키를 무시합니다.
소스에서 `disable-model-invocation: true`를 설정한 모든 스킬 또는 커맨드에 대해,
어댑터는 해당 `SKILL.md` 옆에 `policy.allow_implicit_invocation: false`를 담은
`agents/openai.yaml`을 작성하므로 Codex가 스스로 그 스킬을 선택하지 않습니다.
`$skill-name`으로 명시적으로 실행하는 것은 여전히 가능합니다.
[Codex 스킬 문서](https://developers.openai.com/codex/skills)를 참조하세요.

## 프로필-네이티브 구성 매핑

어댑터는 Apothem의 공유 코호트를 읽고 각 코호트를 알맞은 Codex 표면에
설치합니다. 지침은 `AGENTS.md`로, 훅은 `hooks.json`과 `hooks/`로, 에이전트는
TOML로, 스킬은 `~/.agents/skills/`로, 네이티브가 아닌 Markdown 규칙/템플릿은
지원 자료로 `~/.config/apothem/`에 설치됩니다.

변환된 각 도우미는 `name`, `description`, `developer_instructions`를
설정합니다. 도구 권한에서 거부 목록을 적용한 뒤에 파일 편집 도구(`Write`,
`Edit`, `MultiEdit`, `NotebookEdit`)가 하나도 남지 않는 도우미는 Codex 자체의
쓰기 제한인 `sandbox_mode = "read-only"`도 설정합니다. `Bash`는 파일 편집
도구로 간주되지 않으므로, `Bash`만 부여받고 위 도구는 하나도 부여받지 못한
도우미도 여전히 읽기 전용입니다. 모델이나 추론 노력은 설정하지 않으므로 각
도우미는 세션의 선택을 상속합니다. Codex에는 도우미별 도구 목록이나 턴 제한이
없으므로, 도우미의 `tools`와 `maxTurns`는 이어지지 않습니다.

## 호환성 참고 사항

`~/.agents/skills/`는 Codex가 소유하는 공유 루트입니다. 지원되는 다른 도구 여덟
개도 이 루트를 로드하므로([하니스 레지스트리](/docs/reference/harness-registry)에
나열됨), Codex 설치가 그곳에 작성하는 Apothem 스킬은 그 도구들에도 나타나며,
Codex 제거는 그 도구들에서도 이 스킬을 제거합니다. 설치는 해당 도구들을
명시하는 안내를 출력합니다.

Codex는 `~/.codex/rules/`를 `.rules` 실행 정책용으로 예약합니다. Apothem은
그곳에 Markdown 동작 규칙을 두지 않으며, 이를 `~/.config/apothem/`에 두고
`AGENTS.md`와 설치된 스킬에서 참조합니다.

## 검증

```bash
apothem verify --harness codex
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML
   구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면
   `--profile PATH`를 추가하세요.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness codex
```

Codex 부트스트랩, 변환된 에이전트, 스킬, 지원 코호트를 새로 고칩니다.

## 제거

```bash
apothem uninstall --harness codex
```

어댑터가 작성한 네이티브 구성 파일을 제거합니다.
공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness codex`를 다시 실행 |
| 검증 실패 | `apothem update --harness codex`를 실행한 후 다시 검증 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 후 `apothem update --harness codex`를 다시 실행 |
