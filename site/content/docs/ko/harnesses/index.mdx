Apothem은 열일곱 개의 내장 하니스 어댑터를 제공합니다. 각 어댑터는 동일한 공유 코호트를, 플랫폼이 지원하는 경우 플랫폼 네이티브 파일로, 지원하지 않는 경우 Apothem 소유의 지원 트리로 변환합니다.

## 지원되는 하니스

지원 레지스트리에는 정확히 열일곱 개의 어댑터가 포함되어 있습니다. `--harness`와 함께 다음의 정확한 설치 이름을 사용하거나, 결정론적 레지스트리 집합을 위해 `all`을 사용하세요.

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

상세한 레지스트리 매트릭스, 대상 경로, 기능 상태, MCP 지원, 규칙-고정 증거는 [기술 레지스트리 참조](/docs/reference/harness-registry)에 있습니다.

## 여러 하니스 설치

하나의 하니스를 설치하거나, 결정론적 순서로 레지스트리를 선택하려면 `all`을 사용하세요. 프로젝트 범위 하니스에는 `--project PATH`가 필요합니다. 레지스트리에는 사용자 범위와 프로젝트 범위 대상이 모두 포함되어 있으므로 `all`도 여기에 해당합니다.

```bash
apothem install --harness claude-code
apothem install --harness cursor --project /path/to/project
apothem install --harness gemini-cli --project /path/to/project
apothem install --harness all --project /path/to/project
```

## 설치 검증

각 하니스 어댑터를 개별적으로 검증하거나, 등록된 모든 어댑터에 걸친 어댑터별 설치 상태 요약을 보려면 `apothem doctor`를 호출하세요.

```bash
apothem verify --harness claude-code
apothem verify --harness all --project /path/to/project
apothem doctor
```

## 어댑터 작동 방식

각 어댑터는 setuptools 진입점을 통해 등록된 `HarnessAdapter` 프로토콜을 구현합니다. 설치 시 CLI는 공유 YAML 프로필을 로드하고 검증하며, 레지스트리를 통해 어댑터를 해석하고, 구체화 계획을 검증한 다음, 플랫폼 네이티브 구성을 하니스의 네이티브 사용자 또는 프로젝트 위치에 작성합니다. 업데이트 시에는 현재 프로필 상태에서 다시 도출합니다.

```
profile.yaml + packaged cohorts
    identity / preferences / rules
    commands / skills / delegated definitions / hooks / templates
         |
         +-- antigravity    --> ~/.gemini/GEMINI.md + ~/.gemini/antigravity-cli/plugins/apothem/
         +-- claude-code    --> ~/.claude/ native folders + ~/.claude/.apothem/support/
         +-- codex          --> ~/.codex/ + ~/.agents/skills/ + ~/.config/apothem/{rules,templates}/
         +-- cursor         --> <project>/.cursor/rules/*.mdc
         +-- gemini-cli     --> <project>/GEMINI.md + <project>/.gemini/
         +-- github-copilot --> <project>/.github/copilot-instructions.md
         +-- windsurf       --> <project>/.devin/rules/
         +-- ...
```

프로토콜 명세는 [하니스 어댑터 추상화](/docs/architecture/harness-adapter-abstraction)를 참조하세요.
