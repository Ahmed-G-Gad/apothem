**공급업체:** Zed Industries
**설치 이름:** `zed`
**상태:** GA
**네이티브 구성:** `<project>/.rules`

## 설치

```bash
apothem install --harness zed --project /path/to/project
```

어댑터는 공유 Apothem 규칙 및 거버넌스 표면으로부터 프로젝트 범위 Zed 지침 파일
하나를 작성합니다. Zed는 다음 목록에서 처음으로 일치하는 프로젝트 지침 파일
하나를 읽습니다.

```text
.rules
.cursorrules
.windsurfrules
.clinerules
.github/copilot-instructions.md
AGENT.md
AGENTS.md
CLAUDE.md
GEMINI.md
```

도구별 규칙 디렉터리가 없으므로, 전체 Apothem 표면은 이 목록 맨 위에 있는 평면
`.rules` 파일에 안착합니다.

또한 Apothem의 스킬과 그 스킬이 인용하는 규칙 및 템플릿을, 프로젝트를 건드리기
전에 사용자 홈에 작성합니다([프로젝트 외부의 파일](#프로젝트-외부의-파일) 참조).

**작성되는 파일:**

- `<project>/.rules`: 지침 파일.
- 각 Apothem 스킬과 커맨드에 대한 `~/.agents/skills/<name>/SKILL.md`: 사용자 홈 안.
- `~/.config/apothem/rules/` 및 `~/.config/apothem/templates/`: 사용자 홈 안.

## 프로젝트 외부의 파일

설치는 프로젝트의 어떤 것도 변경하기 전에 Apothem의 스킬을 사용자 홈에도
작성합니다.

| 폴더 | Apothem이 그곳에 작성하는 것 |
| --- | --- |
| `~/.agents/skills/` | 각 Apothem 스킬마다 `SKILL.md`가 든 폴더 하나, 그리고 각 Apothem 커맨드마다 폴더 하나(커맨드는 같은 이름의 스킬이 됩니다). |
| `~/.config/apothem/rules/`, `~/.config/apothem/templates/` | 스킬과 지침 파일이 참조하는 규칙과 템플릿. |

이 폴더들은 공유됩니다. 프로젝트 전용이 아닙니다.

- `zed`를 설치하는 모든 프로젝트와, 그 폴더를 지정하는 다른 모든 Apothem 설치는 같은 사본을 사용하고 같은 파일을 작성하므로, 설치 순서는 중요하지 않습니다. 다른 여러 도구도 `~/.agents/skills/`를 읽습니다. [하니스 레지스트리](/docs/reference/harness-registry#공유-루트)가 그 도구들을 나열합니다.
- `--project`는 작성할 지침 파일과 설치가 속하는 프로젝트를 선택합니다. 스킬이
  가는 위치는 바꾸지 않습니다.
- 설치는 저장소에 스킬 파일이나 규칙 파일을 추가하지 않습니다. 프로젝트에는 지침
  파일, 그리고 모든 프로젝트 설치가 만드는 `.apothem/` 데이터 폴더가 생깁니다.
- 홈 폴더가 먼저 작성됩니다. 예를 들어 경로의 폴더가 홈 디렉터리 밖으로 나가는
  링크이거나(홈 안에 머무는 링크는 따라갑니다) 쓸 수 없어서 이 작업이 실패하면,
  설치는 프로젝트의 어떤 것도 변경되기 전에 오류와 함께 중단됩니다.
- Apothem 스킬의 이름을 가졌지만 Apothem이 작성하지 않은 스킬 폴더는 그대로 두며,
  설치는 그 폴더를 명시하는 경고를 출력합니다. 이름을 바꾸거나 옮긴 다음
  `apothem update`를 실행하세요. 그 이름이 점유되어 있는 동안 `apothem verify`는 실패합니다.
- 파일은 모두 합쳐 몇 메가바이트입니다.

설치는 `--project` 밖에 작성하는 폴더를 명시하는 안내를 출력하며, `--dry-run`은
그 폴더들을 나열합니다.

## 프로필에서 네이티브 구성으로의 매핑

어댑터는 Apothem의 공유 프로필을 읽고 매 `apothem install` 또는 `apothem update`
실행마다 프로젝트 `.rules` 파일을 렌더링합니다. 공유 프로필이 진실의 원천입니다.
이미 존재하는 모든 `.rules`(또는 생성된 파일에 대한 프로젝트 로컬 편집)는 다음
동기화가 Apothem 관리 콘텐츠를 교체하기 전에 백업됩니다.

## 호환성 참고 사항

Zed는 `AGENTS.md`를 기본 지침 파일로 지정하고, 프로젝트 `.rules`를 지원되는
호환성 파일로 유지합니다([Zed 지침](https://zed.dev/docs/ai/instructions)). Zed는
첫 번째 일치 항목만 읽으므로, 새 `.rules`는 프로젝트가 이미 의존하고 있는
`AGENTS.md`, `CLAUDE.md`, 또는 목록에서 더 아래에 있는 다른 모든 파일을 가립니다.
설치는 그 파일들을 절대 편집하지 않습니다. `.rules`에 Apothem 블록만 있고 우선순위가
더 낮은 파일에 여러분의 텍스트가 있으면, install과 update는 가려진 파일을 명시하는
경고를 출력합니다. 필요한 지침을 Zed에서 유지하려면 Apothem 블록 바깥의
`.rules`에 복사하세요.

전역 `~/.config/zed/AGENTS.md` 지침 파일과 MCP 컨텍스트 서버
블록(`.zed/settings.json`의 `context_servers`)은 운영자 소유입니다. Apothem은 이를
작성하지 않습니다.

Zed는 전역 스킬을 `~/.agents/skills/`에서만, 스킬마다 폴더 하나인 평면 레이아웃으로
로드하며, 이는 설치가 작성하는 레이아웃입니다. Zed는 프로젝트 로컬 스킬을 신뢰할 수
있는 워크트리로 제한하며, Zed 문서는 전역 폴더에 그러한 제한을 연결하지 않습니다.
한 보고는 Zed가 모델에 보내는 스킬 카탈로그에 크기 제한이 있다고 했습니다. Apothem은
이를 확인하지 않았으며, 모델 호출을 끄는 스킬이 그 제한에 포함되는지도 확인하지
않았습니다. Apothem 스킬의 이름과 설명은 모두 합쳐 약 20 KB입니다. Apothem은 또한
Zed가 나열하지 않는 `SKILL.md` 헤더 키를 Zed가 어떻게 처리하는지도 확인하지
않았습니다.

## 검증

```bash
apothem verify --harness zed --project /path/to/project
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 각 관리 대상이 존재하고, 관리되는 파일은 비어 있지 않으며, JSON 또는 YAML 구성은 파싱됩니다. 설치된 파일이 그 프로필과도 일치하는지 확인하려면 `--profile PATH`를 추가하세요.
3. 모든 Apothem 스킬 폴더가 어느 설치가 작성했든 `SKILL.md`와 함께 제자리에
   있고, Apothem 이름을 가진 스킬 폴더 중 Apothem이 작성하지 않은 것에 속하는
   폴더는 없습니다. 실패한 검사는 누락되었거나 외부의 폴더를 명시합니다.
4. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness zed --project /path/to/project
```

현재 공유 프로필 상태에서 프로젝트 `.rules` 파일을 다시 도출합니다.

업데이트는 파일이 현재 파일과 다른 스킬 폴더도 다시 작성합니다.
스킬을 작성하지 않던 이전 릴리스로 설치했다면 업데이트가 스킬을 추가합니다.

## 제거

```bash
apothem uninstall --harness zed --project /path/to/project
```

네이티브 구성 파일 `.rules`에서 Apothem의 관리 블록을 제거하고 사용자 고유의 텍스트는 유지합니다. 파일에 다른 내용이 남지 않은 경우에만 파일을 삭제합니다. 변경 전에 파일의 타임스탬프가 찍힌 사본을 `~/.apothem/backups/` 아래에 저장하며, 프로젝트에는 백업 파일이 남지 않습니다. 공유 프로필 YAML과 Apothem 엔진은 영향을 받지 않습니다.

제거는 `~/.agents/skills/`에 작성한 스킬 폴더와 `~/.config/apothem/`의 규칙 및
템플릿도 제거하지만, 다른 Apothem 설치가 더 이상 사용하지 않을 때만 제거합니다. 다른
프로젝트나 그 폴더를 공유하는 다른 도구가 사용 중일 수 있습니다. 그 경우 제거는
폴더를 유지하고 어느 설치가 사용 중인지 출력하며, 마지막 제거가 폴더를
제거합니다. 그 폴더들에 여러분이 추가한 파일은 남고, 비게 된 폴더는 제거됩니다.
각 폴더는 제거되기 전에 `~/.apothem/backups/` 아래에 백업됩니다.

## 적합성 게이트

```bash
python -m apothem.conformity.gate --all .
```

## 문제 해결

| 증상 | 해결 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness zed --project /path/to/project`를 다시 실행 |
| 검증 실패 | `apothem update --harness zed --project /path/to/project`를 실행한 다음 다시 검증 |
| `apothem verify`가 누락된 스킬 폴더를 명시함 | `apothem install --harness zed --project /path/to/project`를 실행. 이 명령이 폴더를 복원함 |
| 설치나 업데이트가 스킬 폴더를 건너뛰었다고 경고함 | Apothem 스킬의 이름을 가진 폴더가 이미 스킬 폴더에 있고 Apothem이 작성하지 않았음. 이름을 바꾸거나 옮긴 다음 `apothem update`를 실행 |
| 설치가 프로젝트를 변경하기 전에 중단됨 | 홈에서의 쓰기가 실패했음. 오류를 읽고, 오류가 명시하는 폴더(홈 디렉터리 밖으로 나가는 링크, 폴더가 있어야 할 자리의 파일, 읽기 전용 폴더)를 고친 다음 다시 설치 |
| 예기치 않은 구성 내용 | `~/.config/apothem/profile.yaml` 또는 `--profile PATH`를 확인한 다음 `apothem update --harness zed --project /path/to/project`를 다시 실행 |

## 구성 노브
