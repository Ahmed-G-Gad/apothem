**벤더:** Z.ai
**설치 이름:** `glm`
**상태:** GA
**네이티브 구성:** `<project>/.apothem/providers/glm.toml`

`glm` 어댑터는 GLM (Z.ai)을 **모델 백엔드**로 구성합니다. Anthropic 호환 또는
OpenAI 호환 프로토콜을 사용하는 도구에 백엔드 기본 URL과 키를 설정하여 GLM을
가리키게 하며, 다른 어댑터와 똑같이 `--harness glm`으로 어댑터를 선택합니다.
어댑터는 두 호환 표면을 모두 기록하는 프로바이더 구성 파일을 작성하므로,
호환되는 어떤 도구든 GLM 모델 제품군에 연결할 수 있습니다.

Z.ai는 자사 코딩 도구인 ZCode도 제공하며, Z.ai의
[문서](https://docs.z.ai/devpack/tool/zcode)는 이를 "Agentic
Development Environment"라고 부릅니다. 이 어댑터는 ZCode를 구성하지 않습니다.
Apothem은 ZCode 자체의 구성 표면을 확인하지 않았으므로, 어댑터는 ZCode를 위해
아무것도 작성하지 않습니다.

## 설치

```bash
apothem install --harness glm --project /path/to/project
```

어댑터는 GLM 백엔드 엔드포인트와 운영자가 구성할 수 있는 플레이스홀더를
기록하는 프로젝트 범위 프로바이더 파일 하나를 작성합니다.

**작성되는 파일:** `<project>/.apothem/providers/glm.toml`

## 프로필-네이티브 구성 매핑

프로바이더 파일은 두 백엔드를 기록합니다. Anthropic 호환 백엔드는 기본 URL
`https://api.z.ai/api/anthropic`을 사용합니다. Anthropic 프로토콜을 사용하는
도구는 `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, 그리고 선택적으로
`API_TIMEOUT_MS`를 설정하여 GLM으로 라우팅합니다. 파일의
`[backends.anthropic_compatible.env]` 테이블은 이 변수들을 나열하고,
`ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL`,
`ANTHROPIC_DEFAULT_HAIKU_MODEL`도 함께 나열하며, 이 변수들은 도구의 opus,
sonnet, haiku 역할을 GLM 모델에 매핑합니다. OpenAI 호환 백엔드는 기본 URL
`https://api.z.ai/api/coding/paas/v4`를 사용합니다. 인증 토큰은 여러분 자신의
Z.ai 키로 교체하는 플레이스홀더입니다 — Apothem은 실제 시크릿을 절대 작성하지
않습니다. 모델 ID는 버전에 따라 바뀌기 쉬우므로 Apothem은 어떤 모델 ID도
고정하지 않습니다. 파일에는 현재
[Z.ai 문서](https://docs.z.ai/devpack/tool/claude)를 참고하여 채우는
`<GLM_MODEL_ID>` 플레이스홀더가 들어 있습니다. 공유 프로필의 어떤 내용도 이
파일에 들어가지 않으며, 이 파일은 고정된 템플릿입니다.

### 역할-모델 매핑

역할-모델 매핑에 대한 Z.ai 자체의 설명이 서로 일치하지 않으므로, 파일은 세 개의
`ANTHROPIC_DEFAULT_*_MODEL` 값을 플레이스홀더로 남겨 두고 그 위에
`TODO(clarify)` 주석을 둡니다. 어떤 매핑을 사용할지는 여러분이 결정합니다.

- 벤더의 Anthropic 호환 설정 가이드에 있는 수동 `settings.json` 예시는 opus와
  sonnet을 `glm-5.3[1m]`에, haiku를 `glm-5.3-flash[1m]`에 매핑하고,
  `CLAUDE_CODE_AUTO_COMPACT_WINDOW`를 `1000000`으로 설정합니다.
- 같은 가이드에 명시된 기본 매핑은 세 역할 모두에 `GLM-5.3-Flash`를 나열합니다.
- Z.ai의 `@z_ai/coding-helper` 도구는 기본값이 `glm-5.3-flash`이며, 세 역할
  모두에 `[1m]`을 덧붙이고, 압축 창으로 `1048576`을 작성합니다.

Apothem은 이 값들 중 어느 것도 고정하지 않으며, 그중 하나를 선택하지도 않습니다.

## 호환성 참고 사항

GLM 백엔드는 규칙, 커맨드, 스킬, 훅을 위한 표면을 노출하지 않으므로, 어댑터는
백엔드 프로바이더 파일만 작성하며 그 밖에는 아무것도 작성하지 않습니다.
Apothem은 ZCode가 그러한 표면을 노출하는지 확인하지 않았습니다. 여러분의 Z.ai 키와 모델 ID 선택은 운영자 소유로
남습니다. 어댑터가 의존하는 벤더 표면 규약은
`src/apothem/harnesses/glm/STANDARD-CONVENTION-PIN.md`에 고정되어 있으며,
현재 게시된 Z.ai 문서를 기준으로 스냅샷됩니다.

GLM은 Z.ai의 GLM 모델 제품군을 실행합니다. 현재 백엔드, 모델, Anthropic 호환
구성 표면은 [벤더 구성 참조](https://docs.z.ai/devpack/tool/claude)를
확인하세요.

## 검증

```bash
apothem verify --harness glm --project /path/to/project
```

verify 명령은 다음을 확인합니다.

1. 네이티브 구성이 예상 경로에 존재합니다.
2. 프로바이더 파일이 존재하며 비어 있지 않습니다.
3. 어댑터별 검증 루틴이 성공을 보고합니다.

## 업데이트

```bash
apothem update --harness glm --project /path/to/project
```

프로바이더 파일은 일단 존재하면 여러분의 것입니다. `install`과 `update`는 둘 다
`.apothem/providers/glm.toml`이 없을 때에만 템플릿을 작성하며, 그 후에는 어느
쪽도 이 파일을 절대 덮어쓰지 않으므로, 여러분의 키 참조와 모델 선택은 다시
실행할 때마다 그대로 유지됩니다. 더 새로운 템플릿을 받으려면 기존 파일을 다른
곳으로 옮기고, `update`를 실행한 다음, 여러분의 값을 새 파일에 복사하세요.

## 제거

```bash
apothem uninstall --harness glm --project /path/to/project
```

프로바이더 파일은 Apothem이 만들었고 여전히 편집되지 않은 템플릿인 경우에만
제거하며, 제거 전에 먼저 Apothem 백업 루트 아래에 백업합니다. 이전 릴리스가
작성한 편집되지 않은 파일은 프로젝트에 대한 Apothem의 설치 기록이 Apothem이 그
파일을 작성했음을 보여 주면 해당됩니다. 매니페스트는 프로젝트가 제공받은 각
템플릿의 다이제스트를 기록합니다. 설치 기록이 없으면 현재 템플릿의 정확한
사본만 제거됩니다. 여러분이 만들었거나 편집한 파일은 그대로 남습니다. 공유 프로필 YAML과 Apothem 엔진은
영향을 받지 않습니다.

## 문제 해결

| 증상 | 해결 방법 |
|---------|-----|
| 구성 파일을 찾을 수 없음 | `apothem install --harness glm --project /path/to/project`를 다시 실행 |
| 검증 실패 | 프로바이더 파일이 없거나 비어 있습니다. 없는 경우 `apothem update --harness glm --project /path/to/project`를 실행합니다. 비어 있는 경우 먼저 `.apothem/providers/glm.toml`을 다른 곳으로 옮긴 다음 `update`를 실행하고 다시 검증합니다 |
| 예기치 않은 구성 내용 | `.apothem/providers/glm.toml`을 직접 편집합니다. Apothem은 기존 파일을 절대 다시 쓰지 않으며, 공유 프로필은 이 파일에 아무것도 추가하지 않습니다. 새 템플릿이 필요하면 파일을 다른 곳으로 옮기고 `apothem update --harness glm --project /path/to/project`를 실행합니다 |
