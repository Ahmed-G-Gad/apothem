> **권위 질의 규율의 정규 레지스트리.** 이 문서는 일곱 가지 필수 카테고리 목록, 예외된 자동 결정의 열거, 그리고 바인딩 선언을 담습니다. 실질적인 표와 바인딩은 여기에 있으며, `src/apothem/rules/authority-inquiry.md`에 의해 운용됩니다.

호스트 프로젝트에서 작업할 때는 아래 일곱 가지 카테고리에 대해 질의하라 — 지어내지 말라. 질의는 `src/apothem/rules/interactive-questions.md`에 따라 구조화 질의 채널을 통해 라우팅됩니다. 각 선택지는 세 단락 주석(근거 / 권장 / 기본 포인터)과 M7에 따른 권장 표시를 수반합니다.

| 카테고리 | 지어내기 금지 | 질의하는 이유 |
| -------- | ------------------- | --------------- |
| 정체성 | 이름, 이메일, 핸들, 대명사, 조직, 테넌트, 팀 소속, 역할 기술 | 실제 인물에 결속된다; 실세계 아티팩트(커밋, PR, 공개 귀속)를 생성한다 |
| 범위 방향 | 어느 하위 트리, 어느 브랜치, 어느 환경(dev/staging/prod), 어느 대상(라이브러리 vs 서비스), 사용자 대면인지 내부 전용인지 | 사용자는 어시스턴트에게 없는 암묵적 맥락을 갖는다; 침묵하는 선택은 어긋난다 |
| 선호 | 포매터, 린터, 테스트 프레임워크, 문서 생성기, CI 제공자, 브랜치 전략, 커밋 메시지 관례, 릴리스 서명, 버전 관리 체계, 라이선스 — *호스트가 어느 하나로 정하지 않은 경우* | 각각은 침묵하는 채택에 저항하는 장기적 약속이다 |
| 보안 | 비밀 순환 주기, 허용 셸, 허용 네트워크 송출, 수용 위험 목록, 신뢰 작업 허용 목록, MCP 서버 인증 엔드포인트 세부 사항 | 보안 오설정은 영향이 크다; 침묵하는 선택은 침묵하는 침해를 무릅쓴다 |
| 명명 | 호스트에 관례가 없는 곳에서 도입되는 새 관례, 또는 사용자가 암묵적 선호를 갖는 곳에서의 이름 바인딩(함수, CLI 플래그, 하위 명령, 설정 키) | 이름은 영속적이다; 침묵하는 선택은 네임스페이스 오염으로 누적된다 |
| 인프라 | 엔드포인트, 호스트, 포트, 경로, 리전, 큐 이름, 토픽 이름, 테이블 이름 | 실세계 리소스에 결속된다; 지어내기는 실세계 장애를 일으킨다 |
| 버전 고정 | 어느 의존성의 어느 버전, 호스트가 고정하지 않았고 선택이 중요한 경우(보안 관련 의존성, 동작 변경 의존성, semver-major 경계) | 롱테일 결과; 침묵하는 선택은 사용자에게 부담을 준다 |

**필수 질의**(정체성, 범위 방향, 보안 자세, 공개 표면 명명은 항상 필수)는 의존 아티팩트를 차단합니다; 발행은 `<USER-CONFIRM:id=<id>>` 자리표시자를 생성합니다. **선택적 질의**는 사용자가 침묵으로 거절할 수 있으며, 어시스턴트는 그때 권장 선택지로 폴백하고 그 폴백을 발견 사항으로 기록하여 사용자가 결정이 내려졌음을 볼 수 있게 합니다.

## 1. 예외된 자동 결정

다음은 어시스턴트가 질의 없이 결정합니다 — 변경 원장에 "기본으로 적용함; 의도가 다르면 되돌릴 것"으로 공개됩니다:

- **순수 유효성.** 구문 오류, 스키마 위반, 명백한 오타.
- **순수 엄밀성.** 통설 → 인용; 누락된 날짜 추가; 검증 불가능한 주장 표시.
- **보편적으로 안전한 보안.** `deny .env*`, `deny ~/.ssh/**` 읽기, `deny rm -rf:*`, `deny sudo:*`, 보호 브랜치로의 `deny git push --force*`, 신뢰할 수 없는 입력에 대한 `deny eval`／`exec`.
- **순수 형식 정규화.** EOL, 후행 공백, *호스트에 확립된 스타일이 있고 아티팩트가 그로부터 벗어난 경우*의 파일별 단일 따옴표 스타일.
- **수정이 명백한 경우의 내부 참조 복구.** 죽은 경로 → 검색으로 발견한 유일한 살아 있는 경로.

이 예외 밖에 있는 모든 것은 질의 표면을 거칩니다.

## 2. 바인딩 (§0.j five-direction)

- **Drives →** 모든 호스트 프로젝트 아티팩트 발행(`site/content/docs/governance/pre-emission-gate-registry.mdx`에 따라 사전 발행 게이트는 의미 있는 범위의 모든 쓰기에서 발동된다). 모든 다중 선택지 제시는 정규 채널 의무에 따라 구조화 질의 채널을 통해 라우팅된다. `src/apothem/conformity/*-grep.py`에서의 기계적 부분 강제. `src/apothem/rules/{authority-inquiry,host-discovery,disclosure-ledger,ten-dimension-check,pre-emission-gate,expertise-posture,option-annotation,definitiveness,visual-leverage,bidirectional-binding,agile-sprints,canonical-layout,code-craft-*,systemic-participation,production-ready-prs}.md`에서의 규칙별 강제.
- **Satisfies →** CM-N 축과 나란히 일급 거버넌스 차원으로 선언되는 대외 적합성 축(M = 호스트 프로젝트 아티팩트; CM = 생태계 내부 아티팩트; 둘은 직교하며, 둘이 적용되는 곳에서는 둘 다 적용된다). 모든 세션 부트스트랩이 M 집합을 항상 켜진 맥락으로 상속한다는 상주 지시 의무.
- **Established by ↑** `CLAUDE.md` 자체(이 레지스트리는 항상 켜진 맥락에 내재하며, 외부 상태에서 파생된 것이 아니다). `site/content/docs/governance/outward-conformity-registry.mdx` §1에서의 사소함 대 비사소함 임계값 비준.
- **Cross-bound with ↔** `site/content/docs/governance/outward-conformity-registry.mdx`의 대외 적합성 레지스트리 표에서 명명된 각 규칙(명령별 정규 본문). `src/apothem/conformity/*-grep.py`(게이트의 기계적 부분 강제). `src/apothem/rules/interactive-questions.md`(질의 표면은 그 규칙이 정의하는 정규 채널 의무를 통해 라우팅된다).
