> **열다섯 가지 생산 명령의 정규 레지스트리.** 이 문서는 열다섯 가지 명령 레지스트리(M1–M15) 전체, 사소함 대 비사소함 임계값 비준, M↔CM 상호 매핑 정책, 그리고 명령 도입 프로토콜을 담습니다. 실질적인 열거는 여기에 있으며, 명령별 규칙 파일들에 의해 운용됩니다.

이 생태계가 호스트 프로젝트(사용자의 호출 대상 — git 저장소, 문서 트리, 연구 코퍼스, 인프라 매니페스트, 스크래치패드) 안의 어떤 아티팩트를 생성, 편집, 재작업, 개조, 확장 또는 제거할 때, 생성되는 모든 아티팩트는 아래에 선언된 **열다섯 가지 명령 기준(M1–M15)**을 충족합니다. 이는 협상 불가하며 모든 생태계 표면(헬퍼, 어시스턴트, 명령, 훅, 응답, diff, 메시지)에 적용됩니다. 강제는 사전 발행 게이트로 이루어집니다(`site/content/docs/governance/pre-emission-gate-registry.mdx` 참조). 기계적 부분의 강제는 `src/apothem/conformity/*-grep.py`에 있으며 `src/apothem/conformity/gate.py`에 의해 오케스트레이션됩니다.

열다섯 가지 명령은 병행 어휘 정책에 따라 CM-N 명령과 **나란히** 작동합니다(`site/content/docs/governance/cross-cutting-mandates.mdx` 참조). M과 CM은 직교하는 거버넌스 차원입니다(M은 대외 축 — 호스트 프로젝트 아티팩트, CM은 대내 축 — 생태계 내부 아티팩트). 아래에 열거된 각 규칙은 그 명령의 정규 본거지입니다. 이 레지스트리는 색인입니다.

## 1. 사소함 대 비사소함 임계값(확정됨)

사소한 작업과 비사소한 작업을 가르는 임계값 — 비사소한 작업은 M11 ＋ M12 장치를 작동시킨다 — 은 **줄 수 ＋ 범위 하이브리드**입니다. 변경이 사소한 경우는, 그것이 ≤ 5줄의 단일 파일 편집이고 공개 API 표면 변경을 도입하지 않으며 동작 변화도 없는 경우입니다. 그 외 모든 것은 비사소합니다. M5의 한 번 확정 규율에 따라 한 번만 확정됩니다. 임계값은 여기에 사용자 범위로 존재하며, M1 호스트 발견을 존중하는 명시적 프로젝트 범위 선언에 의해서만 재정의됩니다(예: Claude Code용 `<project>/.claude/CLAUDE.md`, 또는 다른 harness용 동등한 프로젝트별 표면).

## 2. M↔CM 상호 매핑

각 M 번호 규칙 본문은 병행 어휘 정책을 사용하여 그 CM-N 상호 매핑을 인라인으로(그 `Cross-bound with ↔` 바인딩 안에) 선언합니다. M 명령이 가장 가까운 CM-N 유사물을 가질 때, 둘 다 적용되는 곳에서 두 규칙이 모두 적용됩니다(치환 없음). 매핑은 규칙 본문에 내재합니다. 이 레지스트리는 매핑 표를 복제하지 않고 축 정책을 요약합니다.

## 3. 명령 도입 프로토콜

새 M 번호 명령(예: 미래의 M16)을 추가하는 것은 **묶음 변경**입니다. 아래 각 구성 요소가 동일 변경 세트 안에 존재할 때에만 묶음이 레지스트리에 도달합니다. 침묵하는 추가 — 지지 묶음 없이 레지스트리 표에 새 M 행을 더하는 것 — 은 명령 축 표류를 낳으며 M14 체계 참여에 따라 비준수입니다.

| 필수 구성 요소 | 목적 | 안착 위치 |
| ------------------ | ------- | -------------- |
| **레지스트리 표의 명령 행** | 명령, 그 한 줄 요약, 그 정규 규칙을 명명한다 | 위의 본 레지스트리 표 |
| **CM-N 상호 매핑 셀** | §2 병행 어휘 정책에 따라 가장 가까운 CM-N 유사물을 선언한다(또는 새 축으로 `(no direct CM-N analog)`를 표시한다) | 새 규칙의 `Cross-bound with ↔` 행 |
| **정규 규칙 본문** | 명령의 실질적 명세(사전 조건／필요한 동작／공개 표면／실패 징후／다섯 방향 바인딩) | `src/apothem/rules/<mandate-name>.md` |
| **사전 발행 게이트 행** | 막대의 점검 종류(기계적／추론적／혼합)와 그 `Failure → action`을 명명한다 | 사전 발행 게이트 레지스트리 표(`site/content/docs/governance/pre-emission-gate-registry.mdx`) |
| **강제 표면** | `gate.py`에 의해 오케스트레이션되는 `src/apothem/conformity/<name>-grep.py`의 기계적 grep이거나, 운영자 자가 점검 앵커를 갖춘 명시적 추론적 막대 선언 중 하나 | `src/apothem/conformity/`(기계적) 또는 `reasoned`로 표시된 게이트 행(운영자 자가 점검) |
| **적합성 픽스처** | 명령의 실패 모드를 연습하는 `tests/conformity-scenarios/fixtures/F-<N>-<name>/` 아래의 픽스처. 검증기의 명령 목록이 새 막대를 포함하도록 갱신된다 | `tests/conformity-scenarios/` |
| **릴리스 증명 스키마 갱신** | 릴리스 증명의 `bars:` 블록이 새 행을 얻는다. 기존 아티팩트의 릴리스 증명 블록은 재감사될 때까지 새 행을 `n/a (with reason: pre-mandate-N artifact)`로 취급한다 | `site/content/docs/governance/pre-emission-gate-registry.mdx` §1 스키마 |
| **공개 원장 항목** | 구체적 동인(관찰된 패턴 재발, 노출된 보안 공백, 기존 열다섯이 다루지 못하는 능력)에 뿌리내린 근거와 함께 명령 도입을 기록한다 | `src/apothem/rules/disclosure-ledger.md`에 따른 변경 세트의 커밋 본문 또는 PR 설명 |

**적용 규율.** 묶음 없이 도착한 명령 제안은 리뷰에서 거부됩니다. 제안자는 묶음을 완성하거나 제안을 기존 명령의 확장으로 강등합니다. 기존 열다섯 명령은 명세의 대외 축으로 함께 채택되었습니다. 미래의 추가는 조각조각 안착하는 대신 동일한 모든-구성-요소-아니면-무-구성-요소 채택 박자를 존중합니다.

**강등／퇴역 프로토콜.** 확립된 M-N이 기존 CM-N 또는 다른 M-N과 중복됨이 발견될 때(구현 규칙 본문의 상호 매핑 커버리지 맵이 양방향으로 `direct` 인접을 보일 때), 강등은 대칭적 역과정입니다. 레지스트리 행이 퇴역하고, 게이트 행이 퇴역하며, 정규 규칙이 퇴역하고(그 내용은 `src/apothem/rules/clean-room-generation.md` §3 재작성 프로토콜에 따라 흡수 규칙에 접혀 들어감), 적합성 픽스처가 퇴역하며, 릴리스 증명 스키마의 `bars:` 블록이 행을 떨구고, 변경 세트가 흡수 규칙 인용과 함께 공개 원장에 기록됩니다. 강등은 동일한 모든-구성-요소-아니면-무-구성-요소 불변식을 보존합니다.
