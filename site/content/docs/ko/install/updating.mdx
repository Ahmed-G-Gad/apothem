## Claude Code 플러그인 업데이트

마켓플레이스 목록을 새로 고친 다음, Claude Code 내부의 `/plugin` 메뉴에서 플러그인을 업데이트하세요.

```text title="Inside Claude Code"
/plugin marketplace update apothem
```

`/plugin`을 열고 **apothem**을 선택한 뒤, 더 최신 플러그인 버전이 표시되면 업데이트 작업을 선택하세요.

## npx는 항상 현재 릴리스를 실행합니다

`npx @ahmed-g-gad/apothem`은 실행할 때마다 현재 게시된 패키지를 확인하므로 업데이트할 것이 없습니다. 오래된 npx 캐시가 이전 사본을 제공하는 경우, dist-tag를 명시적으로 고정하세요.

```bash
npx @ahmed-g-gad/apothem@latest --version
```

## 설치 프로그램 기반 설정 업데이트

설치 프로그램을 다시 실행하거나 — 이는 멱등적이며 기존 트리를 빨리 감기합니다 — 전용 업데이트 스크립트를 실행하세요.

```bash title="macOS · Linux · WSL2 · BSD"
bash scripts/installer/update.sh
```

```powershell title="Windows · PowerShell"
pwsh -NoProfile -File scripts/installer/update.ps1
```

업데이트 스크립트는 `APOTHEM_HOME`(기본값 `~/.apothem`)의 소스 트리를 `APOTHEM_REF`로 다시 체크아웃합니다 — 설정하지 않으면 최신 서명된 `vMAJOR.MINOR.PATCH` 릴리스 태그로 해석되고, 태그 값은 이를 고정하며, `main`은 움직이는 브랜치를 선택합니다. 다시 구체화하기 전에 `git verify-tag`로 태그의 서명을 검증합니다. 서명되지 않았거나 변조된 태그는 `APOTHEM_ALLOW_UNVERIFIED=1`이 중단을 경고로 격하하지 않는 한 중단됩니다. 그런 다음 새로 고쳐진 트리에서 `apothem update`를 실행하여 `APOTHEM_HARNESS`로 지정된 하니스(기본값은 [설치 프로그램 환경 변수](/docs/how-to/installer-environment-variables) 표에 따름)를 다시 구체화합니다. 이는 사전 설치를 필요로 합니다. `APOTHEM_HOME`에 트리가 없고 `APOTHEM_SOURCE`가 설정되지 않은 경우, 먼저 설치 프로그램으로 안내하는 메시지와 함께 종료됩니다.

## 하니스 출력 재구체화

엔진을 업데이트하거나 `~/.config/apothem/profile.yaml`을 편집한 후에는 설치된 하니스 구성을 다시 도출하세요. 사용자 범위 어댑터에는 `--project`가 필요 없지만, 프로젝트 범위 어댑터에는 필요합니다.

```bash
apothem update --harness claude-code
apothem update --harness cursor --project /path/to/project
apothem update --harness all --project /path/to/project
```

파일 시스템 쓰기 없이 기계 판독 가능한 미리 보기가 필요하면 동일한 명령을 `--dry-run --json`과 함께 실행하세요.

## 현재 명령 경계

`apothem update`는 하니스 출력만 업데이트합니다. CLI는 `update --self`, `update --check`, `update --apply`를 구현하지 않습니다. 엔진 자체는 설치한 채널을 통해 업데이트하세요 — `/plugin` 흐름, 새로운 `npx` 실행, 또는 위의 설치 프로그램/업데이트 스크립트입니다.

## 엔진 버전 확인

```bash
apothem --version
npx @ahmed-g-gad/apothem --version
```
