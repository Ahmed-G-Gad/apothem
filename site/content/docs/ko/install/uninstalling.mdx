## 하니스 구성을 먼저 제거하세요

이 페이지에서 쓰는 기본 `apothem` 명령은 원샷 설치 프로그램([설치 가이드](/docs/install)의 채널 3)이 작성하는 shim입니다. 이 shim의 디렉터리가 `PATH`에 올라가면 실행됩니다. 다른 설치 채널에서는 설치 가이드에 설명된 대로 `apothem` 대신 `npx @ahmed-g-gad/apothem`을 사용하세요.

Apothem을 제거하기 전에 각 하니스 어댑터 구성을 제거하여 하니스를 깨끗한 상태로
두세요. `apothem harnesses list`를 실행하여 현재 설치된 어댑터를 확인한 다음,
하나씩 제거하거나 레지스트리 전체 선택자를 사용하세요.

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness cursor --project /path/to/project
apothem uninstall --harness all --project /path/to/project --yes
```

하니스별 확인 프롬프트를 건너뛰려면 `--yes`를 전달하세요.

## 엔진 제거

제거 방법은 사용한 설치 채널에 맞춰 달라집니다. 채널 번호는
[설치 채널 표](/docs/install#채널-선택)의 번호입니다.

- **Claude Code 플러그인(채널 1)** — Claude Code 안에서 플러그인을 제거하세요: `/plugin uninstall apothem@apothem`(마켓플레이스 항목은 `/plugin marketplace remove ahmed-g-gad/apothem`으로 제거할 수 있습니다).
- **npx(채널 2)** — 제거할 것이 없습니다. `npx`는 자체 캐시에서 실행됩니다. 캐시된 사본까지 없애려면 `npm cache clean --force`로 캐시를 지우세요.
- **원샷 설치 프로그램(채널 3)** — 체크아웃에서 해당 제거 스크립트를 실행하세요: `scripts/installer/uninstall.sh`(POSIX) 또는 `scripts/installer/uninstall.ps1`(PowerShell). 각 스크립트는 `--harness`(PowerShell에서는 `-Harness`)로 지정한 하니스를 제거하고, 지정하지 않으면 `APOTHEM_HARNESS`를, 그것도 없으면 Claude Code를 제거합니다. 또한 `apothem` 명령 심(shim)도 제거합니다. 소스는 `APOTHEM_SOURCE`가 설정되어 있으면 그 값에서, 아니면 `APOTHEM_HOME`(기본값 `$HOME/.apothem`)에서 가져옵니다. `--remove-source`(PowerShell에서는 `-RemoveSource`)를 전달하지 않는 한 소스는 남습니다. 이 플래그는 `APOTHEM_HOME`의 관리되는 클론만 삭제하며, 그 클론에 `.git` 디렉터리가 있을 때에만 삭제합니다. 기본 위치를 사용하면 `~/.apothem/` 아래의 설치 백업과 원장도 함께 삭제합니다. 두 스크립트 모두 하니스 구성과 소스를 제거하기 전에 확인을 요청합니다. `--yes`(PowerShell에서는 `-Yes`)를 주면 확인 프롬프트를 건너뜁니다. 두 스크립트 모두 안전하지 않은 대상은 거부합니다.
- **VS Code 계열 확장(채널 4)** — 먼저 명령 팔레트에서 **Apothem: Uninstall**을 실행하여 하니스 구성을 제거한 다음, 확장 보기에서 또는 `code --uninstall-extension ahmed-g-gad.apothem-vscode`로 확장을 제거하세요(이전 `apothem.vsix`로 설치한 사본은 `ahmed-g-gad.apothem`입니다). 기본적으로 이 확장은 `npx`를 통해 엔진을 실행하므로, 위의 **npx** 항목이 캐시를 다룹니다.
- **명령줄 부트스트랩(채널 5–7)** — 하니스 구성이 모두 제거된 뒤에 호스트 도구로 확장 또는 플러그인을 제거하세요. 호스트는 다음과 같습니다:

  ```text
  channel 5   Gemini CLI extension
  channel 6   Qwen Code extension
  channel 7   Codex plugin
  ```

  부트스트랩은 `npx`를 통해 엔진을 호출하는 어시스턴트 컨텍스트(컨텍스트 파일,
  커맨드, 또는 스킬)만 추가하므로, 그 밖에 남는 것은 없습니다. 채널 5와 6의 확장
  호스트는 제거 명령을 제공하며, 채널 7의 플러그인 호스트에서는 해당 플러그인
  브라우저에서 `apothem`을 제거하세요.

  ```bash
  gemini extensions uninstall apothem   # channel 5
  qwen extensions uninstall apothem     # channel 6
  ```
- **직접 엔진(채널 8)** — 제거할 것이 없습니다. 하니스 구성이 제거되면 클론을
  삭제하세요.
- **백업 및 상태** — 설치 백업은 `~/.apothem/backups/` 아래에, 설치 원장은
  `~/.apothem/state/` 아래에 있습니다. 둘 다 크기가 제한됩니다. 설치, 제거, 롤백을
  할 때마다 Apothem은 설치 루트별로 최신 설치 기록 10개와 하니스별로 최신 백업
  세트 10개를 유지하며, 유지되는 기록이 아직 필요로 하는 백업은 절대 삭제하지
  않으므로 마지막 10개 설치는 여전히 롤백할 수 있습니다. 더 적게 유지하려면
  [`apothem backups prune --keep N`](/docs/cli-reference/backups)을 실행하세요
  (무엇을 제거할지 먼저 보려면 `--dry-run`을 추가하세요). 이 명령은 하니스의 최신
  설치를 롤백할 때 복원 원본이 되는 백업은 절대 제거하지 않습니다. 엔진이
  제거되었고 더 이상 어떤 이력도 필요하지 않다면 `~/.apothem/`을 삭제하세요.

## 제거되지 않는 것

- `~/.config/apothem/profile.yaml` 또는 `--profile PATH`에 있는 공유 프로필 YAML은
  `apothem uninstall`에 의해 절대 제거되지 않습니다.
- 하니스 디렉터리에 있는 관련 없는 운영자 작성 파일은 보존됩니다.
- 공유 설정 파일에 여러분이 추가한 항목은 보존됩니다. 여러분 자신의 권한 규칙,
  MCP 서버, 훅 핸들러는 그대로 남습니다. 제거는 설치 원장이 Apothem의 것으로
  기록한 키와 목록 항목만 제거합니다
  ([설정](/docs/reference/settings#여러분의-설정-파일에-병합하기) 참조).
- 설치 루트의 `.apothem/` 아래에 있는 공유 데이터 저장소(`memory/`, `contexts/`,
  `learning/`)는 같은 루트에 설치된 다른 하니스가 아직 사용하는 동안에는 남습니다.
  그 루트에서 마지막 하니스를 제거하면 각 저장소를 먼저 `~/.apothem/backups/`에
  복사한 다음, 그 안의 모든 내용과 함께 저장소를 제거합니다.
- `<project>/.apothem/plans/`(및 레거시 `<project>/.plans/`) 아래의 플랜 스위트는
  영향을 받지 않습니다.

## 디렉터리

제거는 설치가 생성한 디렉터리(예: 첫 설치 전에는 존재하지 않았던 `~/.claude/`)도
비게 되면 제거합니다. 여러분의 파일이나 설치된 다른 하니스가 사용하는 데이터를
여전히 담고 있는 디렉터리는 남습니다. 설치 전에 존재했던 디렉터리는 절대 제거되지
않습니다.

하니스 루트를 완전히 정리하려면, 보관하려는 사용자 지정 규칙, 헬퍼, 프로필 파일을
백업했는지 확인한 후 [하니스 참조 페이지](/docs/harnesses)에 문서화된 하니스
네이티브 경로를 제거하세요.
