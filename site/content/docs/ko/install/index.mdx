Apothem은 2분 이내에 설치되며 기존 하니스 구성과 나란히 동작합니다. 모든 경로는
동일한 자체 완결형 엔진을 실행합니다 — 소스 트리가 벤더링된 의존성을 지니며 시스템
Python 3.10 이상에서 체크아웃으로부터 실행됩니다(
[자체 완결형 런타임](/docs/architecture/self-contained-runtime) 참조).

**모든 경로가 공유하는 두 가지 사전 요건:** `PATH`에 있는 시스템 **Python 3.10
이상**, 그리고 그 아래에서 임포트 가능한 `click`과 `rich` 패키지. npm 심과 도구
플러그인 경로는 추가로 `npx`를 실행하기 위해 **Node.js 18 이상**이 필요합니다. 아래
각 채널의 섹션은 그 정확한 사전 요건, 복사해서 바로 쓸 수 있는 명령 하나, 그리고
검증 단계를 반복합니다.

## 1. Claude Code 플러그인

**사전 요건:** Claude Code, 그리고 `PATH`에 있는 시스템 Python 3.10+.

플러그인 경로는 전적으로 Claude Code 내부에서 실행됩니다. Apothem 엔진을 그 슬래시
명령, 위임 작업자, 스킬, 규칙, 훅과 함께 번들하며, 모두 자체 완결형 플러그인 트리에서
실행할 수 있습니다.

```text title="Inside Claude Code"
/plugin marketplace add ahmed-g-gad/apothem
/plugin install apothem@apothem
```

설치 후에는 Apothem 명령 세트(`/plan-spec`, `/code-review`, `/security-audit` 등),
번들된 위임 작업자, 그리고 스킬이 모든 Claude Code 세션에서 사용 가능합니다. 명령의
전체 카탈로그는 [슬래시 명령](/docs/reference/commands)을 참조하세요.

**검증:** Claude Code 내부에서 `/plugin`을 실행하고 **apothem**이 설치됨으로
나열되는지 확인하거나, 터미널에서 드리프트 보고를 확인하세요.

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 2. npm 심(`npx`)

**사전 요건:** Node.js 18+(`npx`용)와 `PATH`에 있는 시스템 Python 3.10+. 심은
인터프리터를 찾아 모든 CLI 명령을 번들된 엔진으로 전달합니다 — 시스템에 영구적으로
배치되는 것은 없습니다.

```bash title="npx"
npx @ahmed-g-gad/apothem install --harness claude-code
```

저장소에서 곧장 실행되기도 합니다.

```bash title="npx from the repository"
npx github:ahmed-g-gad/apothem install --harness claude-code
```

[CLI 레퍼런스](/docs/cli-reference)의 모든 명령이 이 형식으로 동작합니다. `apothem`을
`npx @ahmed-g-gad/apothem`으로 바꾸세요. 이는 별도의 플러그인이나 확장 레지스트리를
노출하지 않는 OpenCode를 비롯한 다른 모든 도구의 설치 경로이기도 합니다 — Apothem은
그것들을 네이티브 구성 디렉터리로 곧장 동기화합니다
(`npx @ahmed-g-gad/apothem install --harness opencode`).

**검증:**

```bash title="Verify"
npx @ahmed-g-gad/apothem --version
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 3. 원스텝 설치 프로그램

**사전 요건:** `PATH`에 있는 시스템 Python 3.10+(설치 프로그램이 `click` / `rich`
사전 요건을 대신 추가하겠다고 제안합니다). `git`은 소스를 클론하는 네트워크 설치에만
필요합니다.

설치 스크립트는 서명된 최신 릴리스 태그를 해석하고, 그 서명을 검증하고, Apothem
소스 트리를 해당 태그로 `~/.apothem`에 배치하고, 프로필이 없으면 초기 프로필을
생성하고, 첫 하니스를 머티리얼라이즈한 뒤 결과를 검증합니다. 재실행은 멱등적입니다 — 기존
트리는 해석된 태그로 다시 체크아웃되고 하니스는 다시 머티리얼라이즈됩니다. 태그 고정 검증
설치가 기본이자 권장 경로입니다.

```bash title="macOS · Linux · WSL2 · BSD — latest signed tag, verified"
curl -fsSL https://apothem.ahmedgad.com/install.sh | bash
```

```powershell title="Windows · PowerShell — latest signed tag, verified"
irm https://apothem.ahmedgad.com/install.ps1 | iex
```

동일한 스크립트가 체크아웃의 `scripts/installer/` 아래에 담겨 있습니다 — `.sh`,
`.ps1`, `.bat` 형식의 `install`, `uninstall`, `update` — 클론한 뒤 곧장 실행할 수
있습니다.

```bash title="From a checkout"
APOTHEM_HARNESS=claude-code sh scripts/installer/install.sh                                 # POSIX
$env:APOTHEM_HARNESS = 'claude-code'; pwsh -NoProfile -File scripts/installer/install.ps1   # Windows
```

### 신뢰 모델

`APOTHEM_REF`을 설정하지 않으면, 설치 프로그램은 가장 높은 `vMAJOR.MINOR.PATCH`
릴리스 태그를 해석하고 *그것*을 체크아웃합니다 — 움직이는 `main` 브랜치가
아닙니다. 어떤 구성도 머티리얼라이즈하기 전에, 가져온 태그의 서명이 `git verify-tag`로
검증됩니다. 서명되지 않았거나, 변조되었거나, 검증할 수 없는 태그는 무엇이든 쓰기
전에 설치를 중단합니다. 특정 릴리스로 고정하려면 `APOTHEM_REF`을 사용하세요.

```bash title="Pinned, verified install"
APOTHEM_REF=vMAJOR.MINOR.PATCH sh -c "$(curl -fsSL https://apothem.ahmedgad.com/install.sh)"
```

`vMAJOR.MINOR.PATCH`를
[릴리스 페이지](https://github.com/ahmed-g-gad/apothem/releases)의 태그로 바꾸세요.

두 가지 명시적 재정의가 기본 동작을 완화합니다. `APOTHEM_REF=main`은 움직이는
브랜치를 (검증 없이) 체크아웃하고, `APOTHEM_ALLOW_UNVERIFIED=1`은 검증 실패를
경고로 격하하고 계속 진행합니다 — 에어갭, 로컬, 또는 사전 서명된 릴리스 사용을
위함입니다. `APOTHEM_SOURCE`를 통한 로컬 체크아웃은 아무것도 가져오지 않으며 검증을
건너뜁니다.

그런 다음 엔진은 배치된 트리에서 직접 자체 완결형 런타임으로 실행됩니다 — 서드파티
의존성은 소스 트리 내부에 벤더링되어 있으므로, 패키지 레지스트리는 전혀 관여하지
않습니다.

```bash
PYTHONPATH="$HOME/.apothem/src" python -m apothem <command>
```

두 스크립트 모두 동일한 구성용 환경 변수(`APOTHEM_HOME`, `APOTHEM_REPO`,
`APOTHEM_REF`, `APOTHEM_ALLOW_UNVERIFIED`, `APOTHEM_SOURCE`, `APOTHEM_HARNESS`,
`APOTHEM_PROFILE`, `APOTHEM_SKIP_VERIFY`, `APOTHEM_AUTO_INSTALL_DEPS`)를
읽습니다. 전체 표는
[설치 프로그램 환경 변수](/docs/how-to/installer-environment-variables)를,
`python -m` 호출 모델의 작동 방식은
[자체 완결형 런타임](/docs/architecture/self-contained-runtime)을 참조하세요.

**`apothem` 명령.** 설치가 성공하면, 설치 프로그램은 번들된 엔진으로 전달하는
`apothem` 심을 씁니다 — POSIX는 `$HOME/.local/bin`에, Windows는
`%LOCALAPPDATA%\Microsoft\WindowsApps`에(기본 Windows `PATH`에 이미 있는 사용자
디렉터리). 설치 프로그램은 당신의 `PATH`를 결코 편집하지 않습니다. 그 디렉터리가
`PATH`에 올라오면 수동 `PYTHONPATH` 없이 `apothem <command>`를 직접 실행합니다.

**검증:**

```bash title="Verify"
apothem verify --harness claude-code

# or, before the shim is on PATH, from the bundled source:
PYTHONPATH="$HOME/.apothem/src" python -m apothem verify --harness claude-code
```

## 4. VS Code 계열 확장

**사전 요건:** VS Code, Node.js 18+, 그리고 `PATH`에 있는 시스템 Python 3.10+.

**Apothem** 확장은
[Visual Studio Marketplace](https://marketplace.visualstudio.com/)에서
설치합니다 — 하나의 확장이 VS Code와 그 에디터 내 컴패니언 어시스턴트 표면을
커버합니다. 팔레트 명령(`Apothem: Install`, `Verify`, `Update`, `Uninstall`,
`Doctor`)은 구성된 러너(기본값 `npx @ahmed-g-gad/apothem`; `apothem.runner` 설정을
로컬 체크아웃으로 가리키면 소스에서 실행)를 통해 동일한 엔진을 실행합니다.

**검증:** 에디터의 명령 팔레트에서 **Apothem: Verify** 명령을 실행하거나,
터미널에서 실행하세요.

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

## 5. 명령줄 부트스트랩 (확장 호스트)

**사전 요건:** 해당 호스트 명령줄 도구, Node.js 18+, 그리고 `PATH`에 있는 시스템
Python 3.10+.

Apothem을 저장소에서 곧장 확장으로 설치하세요 — 명령이 정확한 호스트와 하니스
slug를 담고 있습니다.

```bash title="Install the extension"
gemini extensions install https://github.com/ahmed-g-gad/apothem
```

이 확장은 그 자체로 전체 설치가 아니라 **부트스트랩**입니다. Apothem 컨텍스트
파일을 로드하고 엔진으로 셸 아웃하는(`npx @ahmed-g-gad/apothem`) `/apothem` 명령을
추가합니다. 이를 통해 install을 실행하여 전체 하니스를 머티리얼라이즈하세요.

```bash title="Materialize the full harness"
npx @ahmed-g-gad/apothem install --harness gemini-cli --project .
```

**검증:**

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness gemini-cli --project .
```

## 6. 명령줄 부트스트랩 (`qwen-code` 호스트)

**사전 요건:** 해당 호스트 명령줄 도구, Node.js 18+, 그리고 `PATH`에 있는 시스템
Python 3.10+.

Apothem을 저장소에서 곧장 `--harness qwen-code` 확장으로 설치하세요.

```bash title="Install the extension"
qwen extensions install ahmed-g-gad/apothem
```

채널 5의 확장처럼, 이것은 **부트스트랩**입니다. Apothem 컨텍스트 파일을 로드하고
엔진으로 셸 아웃합니다. 이를 통해 install을 실행하여 전체 하니스를 머티리얼라이즈하세요.

```bash title="Materialize the full harness"
npx @ahmed-g-gad/apothem install --harness qwen-code
```

**검증:**

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness qwen-code
```

## 7. 명령줄 부트스트랩 (플러그인 호스트)

**사전 요건:** 해당 호스트 명령줄 도구, Node.js 18+, 그리고 `PATH`에 있는 시스템
Python 3.10+.

저장소를 플러그인 마켓플레이스로 추가한 다음 플러그인을 설치하세요 — 명령이 정확한
호스트와 하니스 slug를 담고 있습니다.

```bash title="Install the plugin"
codex plugin marketplace add ahmed-g-gad/apothem
codex plugin add apothem@apothem
```

채널 5와 채널 6의 확장처럼, 이것은 엔진으로 셸 아웃하는 **부트스트랩**입니다. 이를
통해 install을 실행하여 전체 하니스를 머티리얼라이즈하세요.

```bash title="Materialize the full harness"
npx @ahmed-g-gad/apothem install --harness codex
```

**검증:**

```bash title="Verify"
npx @ahmed-g-gad/apothem verify --harness codex
```

## 8. 직접 엔진(`python -m apothem`)

**사전 요건:** `click`과 `rich` 패키지가 임포트 가능한 시스템 Python 3.10+, 그리고
저장소의 체크아웃. Node.js는 필요하지 않습니다.

자체 완결형 엔진을 클론에서 곧장 실행하세요 — 소스 트리가 벤더링된 의존성을
지니므로 `PYTHONPATH=src`가 전체 설정입니다.

```bash title="Direct engine"
git clone https://github.com/ahmed-g-gad/apothem
cd apothem
PYTHONPATH=src python -m apothem install --harness claude-code
```

**검증:**

```bash title="Verify"
PYTHONPATH=src python -m apothem verify --harness claude-code
```

## 임의의 설치 검증

위의 모든 채널은 각자의 검증 명령을 명시합니다. 두 가지 일반 형식은 다음과
같습니다.

```bash title="Installer path"
PYTHONPATH="$HOME/.apothem/src" python -m apothem verify --harness claude-code
```

```bash title="npx path"
npx @ahmed-g-gad/apothem verify --harness claude-code
```

하니스 이름을 설치한 어댑터로 바꾸세요. 지원되는 모든 이름은
[하니스 목록](/docs/harnesses)을 참조하세요. 등록된 각 어댑터를 한눈에 확인하려면
같은 형식으로 `apothem doctor`(또는 `npx @ahmed-g-gad/apothem doctor`)를
실행하세요. 플러그인 경로의 경우 Claude Code 내부에서 `/plugin`을 실행하고
**apothem**이 설치됨으로 나열되는지 확인하세요.

## 사전 요건 한눈에

- **Python 3.10 이상** — 엔진을 실행하는 각 경로가 이를 탐지합니다(`python3`,
  `python`, 버전이 붙은 이름, Windows에서는 `py -3`).
- 그 인터프리터에서 **`click`과 `rich`가 임포트 가능할 것** — 엔진이 벤더링하지
  않는 두 개의 터미널 대면 의존성입니다. 설치 프로그램은 둘 다 확인하고, 누락된
  항목의 이름을 알려 주며, 사용자를 대신해 설치하겠다고 제안합니다 — 사용자의
  확인을 받거나, `--yes`(PowerShell에서는 `-Yes`) 또는
  `APOTHEM_AUTO_INSTALL_DEPS=1`로 자동으로.
- **Node.js 18 이상** — npm 심과 도구 플러그인 경로만.
- **Git** — 설치 프로그램 경로만, 그리고 네트워크 형식에서만 필요합니다(스크립트가
  소스를 클론합니다. 로컬 체크아웃은 클론이 필요하지 않습니다).
- **Claude Code** — 플러그인 경로만. **VS Code**와 각 명령줄 부트스트랩 자체의
  호스트 도구는 각자의 채널(4–7)에만 필요합니다.
