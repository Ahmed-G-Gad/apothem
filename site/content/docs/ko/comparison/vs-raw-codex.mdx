Codex는 사용자 지침을 `AGENTS.md`에서 읽고, 훅을 `hooks.json` 또는 `config.toml`에서
로드하며, 사용자 정의 에이전트를 `agents/` 아래에서 발견하고, 공유 Codex 스킬
루트에서 스킬을 발견합니다. Apothem의 codex 어댑터는 운영자 소유의 `config.toml`
설정은 그대로 두면서 그 표면들을 공유 프로파일에서 설치합니다.

## 노력 비교

| 작업 | 수동 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| `AGENTS.md` 작성 | 사용자 지침을 손으로 편집 | Codex 부트스트랩 템플릿에서 설치 |
| 훅 작성 | `hooks.json` 또는 TOML 훅 테이블을 손으로 작성 | `~/.codex/hooks.json`에 설치하고 Apothem 훅 헬퍼를 `~/.codex/hooks/` 아래에 배치 |
| 사용자 정의 에이전트 작성 | `~/.codex/agents/` 아래에 TOML 파일을 손으로 작성 | Apothem의 Markdown 에이전트에서 변환 |
| 재사용 가능한 명령 작성 | 스킬을 한 디렉터리씩 손으로 구축 | `~/.agents/skills/*/SKILL.md`로 래핑 |
| 규칙을 다른 환경과 맞춰 유지 | 수동, 도구별 | `apothem update` 시 자동 |
| 구성이 올바른지 검증 | 수동 검사 | `apothem verify --harness codex` |

## Apothem이 관리하는 것

codex 어댑터는 `AGENTS.md`, `hooks.json`, 훅 헬퍼 파일, 변환된 사용자 정의
에이전트, 생성된 스킬을 설치합니다. `~/.codex/config.toml`은 덮어쓰지 않습니다.
모델, 샌드박스, 승인, MCP, 그 밖의 런타임 환경 설정은 운영자 소유로 남습니다.

## 마이그레이션 경로

1. 공유 프로파일을 아직 만들지 않았다면 `apothem profile init`을 실행합니다.
2. 기존 `AGENTS.md`의 규칙을 공유 코퍼스로 옮깁니다.
3. 다른 곳에서 손으로 관리하기로 선택하지 않는 한, Codex의 기존 `config.toml`
   런타임 설정을 그대로 유지합니다.
4. `apothem install --harness codex`를 실행해 Codex 네이티브 표면을 설치합니다.
5. `apothem verify --harness codex`를 실행해 파일이 안착했는지 확인합니다.
6. 이후의 모든 변경에는 `apothem update --harness codex`를 사용합니다.
