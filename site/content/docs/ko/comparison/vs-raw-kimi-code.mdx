Kimi Code는 프로젝트 루트의 `AGENTS.md`를 지침 파일로 읽고, 운영자가 소유하는
`.kimi-code/mcp.json` MCP 표면을 포함한 프로젝트 구성을 `<project>/.kimi-code/`
아래에 보관합니다. 이 지침 파일과 이를 뒷받침하는 코호트는 프로젝트마다 영원히
손으로 작성할 수 있습니다. Apothem의 kimi-code 어댑터는 공유 프로필에서
거버넌스 표면을 `AGENTS.md`에 관리 블록으로 렌더링하고, 모든 하니스와 모든
프로젝트에서 이를 일관되게 유지합니다. 이 페이지는 그 구성을 손으로 유지하는
것과 Apothem으로 관리하는 것을 대비합니다.

## 노력 비교

| 작업 | 수동 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| `AGENTS.md` 지침 표면 작성 | 프로젝트마다 직접 작성하고 다시 동기화 | 공유 프로필에서 렌더링된 관리 블록 하나 |
| 규칙, 커맨드, 스킬, 에이전트를 동기화 상태로 유지 | 프로젝트마다 수동 복사 | 설치할 때마다 `<project>/.kimi-code/.apothem/support/` 아래에 머티리얼라이즈 |
| 갱신 시 운영자 산문 보존 | 수동 병합 | 센티넬로 구분된 블록. 그 바깥의 운영자 산문은 보존됨 |
| 다른 하니스와 규칙을 일치 상태로 유지 | 수동, 도구별 | `apothem update` 시 자동 |
| 구성이 올바른지 검증 | 수동 검사 | `apothem verify --harness kimi-code --project <path>` |

## Apothem이 관리하는 것

kimi-code 어댑터는 공유 규칙과 거버넌스 표면을 프로젝트 루트 `AGENTS.md`의 관리
블록으로 렌더링하고, 커맨드, 스킬, 훅, 에이전트, 규칙, 템플릿 코호트를
`.kimi-code/.apothem/support/` 아래에 설치합니다. `.kimi-code/mcp.json`은 작성하지
않으며, MCP 표면은 운영자 소유로 남습니다. Kimi Code는 프로젝트 지침을
`AGENTS.md` 또는 `.kimi-code/AGENTS.md`에서 읽습니다. 어댑터는 프로젝트 루트의
`AGENTS.md`만 쓰며, Kimi Code 문서는 두 파일이 모두 있을 때 어느 쪽이 우선하는지
밝히지 않습니다. 공유 규칙을 변경할 때마다 다음 `apothem update` 시 파일을 다시
렌더링합니다.

## 마이그레이션 경로

1. 아직 공유 프로필을 만들지 않았다면 `apothem profile init`을 실행합니다.
2. 기존 `AGENTS.md`의 규칙을 공유 코퍼스로 옮깁니다.
3. `apothem install --harness kimi-code --project <path>`를 실행해 `AGENTS.md`
   지침 표면과 `.kimi-code/.apothem/support/` 지원 하위 트리를 렌더링합니다.
4. `apothem verify --harness kimi-code --project <path>`를 실행해 구성이
   안착했는지 확인합니다.
5. 이후의 모든 변경에는 `apothem update --harness kimi-code --project <path>`를
   사용합니다.
