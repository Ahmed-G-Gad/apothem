Hermes는 `~/.hermes/config.yaml`을 읽습니다. Apothem은 네이티브 YAML 구성을
작성하고(프로필의 MCP 인벤토리를 `mcp_servers`로 투영), 공유 명령 코호트와 스킬
코호트를 `~/.hermes/.apothem/support/skills/` 아래에 설치합니다. Hermes 자체의
`skills.config`는 레지스트리 패키지 목록이므로 Apothem은 이를 작성하지 않습니다.

## 상태

**프리뷰.** Hermes 어댑터는 현재 문서화된 구성 파일과 스킬 디스커버리 표면을
대상으로 합니다. 스킬이 아닌 코호트는 Apothem 지원 자료로 남습니다.

## 작업량 비교

| 작업 | 수동 직접 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| 재사용 가능한 스킬 작성 | 구성과 스킬 디렉터리를 손으로 편집 | 공유 코퍼스에 한 번 작성 |
| 코호트를 다른 하니스와 맞춰 유지 | 도구별 수동 | `apothem update` 시 자동 |
| 구성 설치 / 제거 | 수동 | `apothem install` / `apothem uninstall` |
| 구성이 올바른지 검증 | 수동 점검 | `apothem verify --harness hermes` |

## Apothem이 관리하는 것

Hermes 어댑터는 `config.yaml`을 작성하고, Apothem 슬래시 명령을 스킬로 감싸고,
Apothem 스킬을 참조되는 지원 디렉터리로 복사하며, 규칙, 템플릿, 에이전트, 훅
자료를 Apothem 지원 하위 트리 아래에 둡니다.

## 마이그레이션 경로

1. 아직 공유 프로필을 만들지 않았다면 `apothem profile init`을 실행해
   만듭니다.
2. 재사용 가능한 Hermes 스킬이나 명령 프롬프트를 공유 코퍼스로 옮깁니다.
3. `apothem install --harness hermes`를 실행해 네이티브 구성과 지원 스킬
   디렉터리를 렌더링합니다.
4. `apothem verify --harness hermes`를 실행해 구성이 안착했는지 확인합니다.
