Zed는 프로젝트 루트에 있는 단일 평면 `.rules` 파일에서 에이전트 지시를
읽습니다(`AGENTS.md` / `CLAUDE.md` 계열 옆에). Apothem의 zed 어댑터는 그 파일을
공유 프로파일에서 렌더링합니다. 이 페이지는 그 구성을 손으로 유지하는 것과
Apothem으로 관리하는 것을 대비합니다.

## 노력 비교

| 작업 | 수동 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| 지시 작성 | `.rules` 파일을 손으로 작성 | 공유 코퍼스에서 렌더링 |
| 이전 `.rules` 보존 | 직접 한쪽으로 복사해 두는 것을 기억 | 어댑터가 교체 전에 기존 파일을 백업 |
| 규칙을 다른 환경과 맞춰 유지 | 수동, 도구별 | `apothem update` 시 자동 |
| 구성이 올바른지 검증 | 수동 검사 | `apothem verify --harness zed` |

## Apothem이 관리하는 것

zed 어댑터는 공유 규칙을 프로젝트 루트의 평면 `.rules` 파일로 렌더링합니다. Zed에는
PreToolUse 훅이 없으므로 가드레일 의도는 도구 호출 가로채기 지점이 아니라 규칙 본문
안에 존재합니다. 전역 `~/.config/zed/AGENTS.md` 지시 파일과 `.zed/settings.json`의
MCP 컨텍스트 서버 블록은 운영자 소유이며 손대지 않습니다. 공유 규칙에 대한 모든
변경은 다음 `apothem update` 시 파일을 다시 렌더링합니다.

## 마이그레이션 경로

1. 공유 프로파일을 아직 만들지 않았다면 `apothem profile init`을 실행합니다.
2. 기존 `.rules`의 지시(그리고 공유하려는 프로젝트별 `AGENTS.md` 콘텐츠)를 공유
   코퍼스로 옮깁니다.
3. `apothem install --harness zed`를 실행해 `.rules` 파일을 렌더링합니다. 이전
   `.rules`가 먼저 백업됩니다.
4. `apothem verify --harness zed`를 실행해 구성이 안착했는지 확인합니다.
5. 이후의 모든 변경에는 `apothem update --harness zed`를 사용합니다.
