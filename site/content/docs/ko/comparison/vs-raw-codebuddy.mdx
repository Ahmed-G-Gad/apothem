CodeBuddy는 프로젝트 규칙을 `.codebuddy/rules/*.md`에서 읽습니다. 이 파일들을 프로젝트마다 손으로 영원히 작성할 수도 있습니다. Apothem의 codebuddy 어댑터는 그중 하나를 공유 프로필로부터 렌더링하고 모든 하니스와 모든 프로젝트에 걸쳐 일관되게 유지합니다. 이 페이지는 그 구성을 손으로 유지하는 것과 Apothem으로 관리하는 것을 대비합니다.

## 노력 비교

| 작업 | 수동 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| 규칙 작성 | 같은 규율을 프로젝트마다 `.codebuddy/rules/`에 복사·붙여넣기 | 하나의 공유 코퍼스에서 렌더링됨 |
| 진실 공급원 | 각 프로젝트의 자체 파일 | 하나의 정규 코호트 |
| 하니스 간 규칙 정렬 유지 | 도구별로 다시 도출 | 자동으로 투영됨 |
| 규칙 업데이트 | 모든 프로젝트를 손으로 편집 | `apothem update --harness codebuddy --project <path>` |
| 구성 제거 | 수동 삭제 | 타임스탬프 백업과 함께 `apothem uninstall` |
| 재사용 가능한 스킬과 커맨드 공유 | 각 스킬 폴더를 `~/.codebuddy/skills/`에 직접 복사하고 사본을 최신 상태로 유지 | 어댑터가 `~/.codebuddy/skills/`에 모든 프로젝트용 사본 하나로 작성하고, `apothem update` 시 갱신 |

## Apothem이 관리하는 것

codebuddy 어댑터는 공유 규칙을 전용 `<project>/.codebuddy/rules/apothem-rules.md` 파일로 렌더링합니다. 또한 모든 프로젝트가 공유하는 홈 디렉터리의 폴더 두 곳에 작성합니다. 스킬과 스킬로 감싼 커맨드는 `~/.codebuddy/skills/`에, 그 스킬들이 인용하는 규칙과 템플릿은 `~/.config/apothem/rules/`와 `~/.config/apothem/templates/`에 들어갑니다. `CODEBUDDY.md` 메모리 파일, `.codebuddy/settings.json`의 권한과 MCP 서버, 그리고 직접 작성한 다른 모든 규칙 파일은 전적으로 운영자 소유로 남습니다. 어댑터는 그 표면을 인식하지만 결코 편집하지 않습니다. 공유 규칙을 변경하면 다음 `apothem update` 때 규칙 파일이 다시 렌더링됩니다.

## 마이그레이션 경로

1. 아직 하지 않았다면 `apothem profile init`을 실행하여 공유 프로필을 만드십시오.
2. 기존 `.codebuddy/rules/` 파일의 규율을 공유 코퍼스로 옮기십시오.
3. `apothem install --harness codebuddy --project <path>`를 실행하여, 손대지 않은 자신의 규칙과 나란히 `apothem-rules.md` 파일을 렌더링하십시오.
4. `apothem verify --harness codebuddy --project <path>`를 실행하여 구성이 적용되었는지 확인하십시오.
5. 이후의 모든 변경에는 `apothem update --harness codebuddy --project <path>`를 사용하십시오.
