GLM (Z.ai)은 호환되는 하니스가 기본 URL과 키를 설정하여 가리키는 모델
백엔드입니다. 이 환경 변수를 프로젝트마다, 머신마다 손으로 영원히 export할 수도
있습니다. Apothem의 glm 어댑터는 백엔드 엔드포인트와 운영자가 구성할 수 있는
플레이스홀더를 하나의 프로바이더 파일에 기록하고, 동일한 템플릿을 모든
프로젝트에 작성합니다. 이 페이지는 그 백엔드를 손으로 연결하는 방식과 Apothem으로
관리하는 방식을 대비합니다.

## 노력 비교

| 작업 | 수동 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| 백엔드 URL 기록 | 프로젝트마다 외워 두었다가 다시 export | 하나의 프로바이더 파일에 기록됨 |
| 진실 공급원 | 각 셸 자체의 export | 하나의 정식 프로바이더 파일 |
| 프로젝트 간 백엔드 정렬 유지 | 프로젝트마다 다시 연결 | 동일한 템플릿이 각 프로젝트에 작성됨 |
| 구성 복원 | 모든 프로젝트에서 다시 export | `apothem update --harness glm --project <path>`는 파일이 없을 때만 파일을 다시 작성함 |
| 구성 제거 | 수동 삭제 | 백업과 함께 `apothem uninstall` |

## Apothem이 관리하는 것

glm 어댑터는 `<project>/.apothem/providers/glm.toml`에 단일 프로바이더 파일을
렌더링하며 그 밖에는 아무것도 작성하지 않습니다. 이 파일은 Anthropic 호환 기본
URL(`https://api.z.ai/api/anthropic`), OpenAI 호환 기본 URL
(`https://api.z.ai/api/coding/paas/v4`), 인증 토큰 플레이스홀더, 모델 매핑
플레이스홀더를 기록합니다. 여러분의 Z.ai 키와 모델 ID 선택은 운영자 소유로
남습니다 — Apothem은 실제 시크릿을 절대 작성하지 않으며 버전에 따라 바뀌기 쉬운
모델 ID를 고정하지 않습니다.

## 마이그레이션 경로

1. 공유 프로필을 아직 만들지 않았다면 `apothem profile init`을 실행해 만듭니다.
2. `apothem install --harness glm --project <path>`를 실행해 `glm.toml`
   프로바이더 파일을 렌더링합니다.
3. 현재 [Z.ai 문서](https://docs.z.ai/devpack/tool/claude)를 참고하여 여러분의
   Z.ai 키와 원하는 모델 ID를 채웁니다.
4. `apothem verify --harness glm --project <path>`를 실행해 구성이
   안착했는지 확인합니다.
5. 이후의 모든 변경에는 `.apothem/providers/glm.toml`을 편집합니다. Apothem은
   기존 프로바이더 파일을 절대 다시 쓰지 않으며, `apothem update --harness glm
   --project <path>`는 파일이 없을 때만 다시 작성합니다.
