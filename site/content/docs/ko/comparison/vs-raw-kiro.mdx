Kiro는 Markdown 파일로 구성된 `.kiro/steering/` 디렉터리에서 스티어링을 읽습니다.
Apothem의 kiro 어댑터는 공유 프로파일에서 전용 `apothem-rules.md` 스티어링 파일을
렌더링합니다. 이 페이지는 그 구성을 손으로 유지하는 것과 Apothem으로 관리하는 것을
대비합니다.

## 노력 비교

| 작업 | 수동 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| 스티어링 규칙 작성 | `.kiro/steering/` 아래 각 파일을 손으로 작성 | 공유 코퍼스에서 렌더링 |
| 기반 파일을 건드리지 않고 유지 | `product.md` / `tech.md` / `structure.md`를 덮어쓰지 않도록 기억 | 어댑터는 `apothem-rules.md`만 작성 |
| 규칙을 다른 환경과 맞춰 유지 | 수동, 도구별 | `apothem update` 시 자동 |
| 구성이 올바른지 검증 | 수동 검사 | `apothem verify --harness kiro` |

## Apothem이 관리하는 것

kiro 어댑터는 공유 규칙을 `inclusion: always` 프런트매터가 있는 전용
`apothem-rules.md` 스티어링 파일로 렌더링하고, Kiro의 운영자가 작성한 기반 파일은
건드리지 않습니다. Kiro에는 PreToolUse 훅이 없으므로 가드레일 의도는 도구 호출
가로채기 지점이 아니라 규칙 산문 안에 존재합니다. 공유 규칙에 대한 모든 변경은 다음
`apothem update` 시 파일을 다시 렌더링합니다.

## 마이그레이션 경로

1. 공유 프로파일을 아직 만들지 않았다면 `apothem profile init`을 실행합니다.
2. 기존 `.kiro/steering/`의 규칙을 공유 코퍼스로 옮깁니다.
3. `apothem install --harness kiro`를 실행해 `apothem-rules.md` 스티어링 파일을 렌더링합니다.
4. `apothem verify --harness kiro`를 실행해 구성이 안착했는지 확인합니다.
5. 이후의 모든 변경에는 `apothem update --harness kiro`를 사용합니다.
