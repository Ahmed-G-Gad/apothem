Kiro는 Markdown 파일로 구성된 `.kiro/steering/` 디렉터리에서 스티어링을 읽습니다.
Apothem의 kiro 어댑터는 공유 프로필에서 전용 `apothem-rules.md` 스티어링 파일을
렌더링합니다. 이 페이지는 그 구성을 손으로 유지하는 것과 Apothem으로 관리하는 것을
대비합니다.

## 노력 비교

| 작업 | 수동 구성 | Apothem 관리 |
| ---- | --------------- | --------------- |
| 스티어링 규칙 작성 | `.kiro/steering/` 아래의 각 파일을 직접 작성 | 공유 코퍼스에서 렌더링 |
| 기반 파일은 건드리지 않고 유지 | `product.md` / `tech.md` / `structure.md`를 덮어쓰지 않도록 기억해 둠 | 어댑터는 `apothem-rules.md`만 작성 |
| 다른 하니스와 규칙을 일치 상태로 유지 | 수동, 도구별 | `apothem update` 시 자동 |
| 재사용 가능한 스킬과 커맨드 공유 | 각 스킬 폴더를 `~/.kiro/skills/`에 직접 복사하고 사본을 최신 상태로 유지 | 어댑터가 `~/.kiro/skills/`에 모든 프로젝트용 사본 하나로 작성하고, `apothem update` 시 갱신 |
| 재사용 가능한 헬퍼를 동기화 상태로 유지 | 각 커스텀 에이전트 파일을 `.kiro/agents/` 아래에 직접 작성하고 Kiro의 도구 범주를 추적 | 헬퍼 14개를 도구를 변환하여 `.kiro/agents/`에 작성하고, `apothem update` 시 갱신 |
| 구성이 올바른지 검증 | 수동 검사 | `apothem verify --harness kiro --project <path>` |

## Apothem이 관리하는 것

kiro 어댑터는 공유 규칙을 `inclusion: always` 프런트매터가 있는 전용
`apothem-rules.md` 스티어링 파일로 렌더링하고, Kiro의 운영자가 작성한 기반 파일은
건드리지 않습니다. 또한 Apothem의 헬퍼 14개를 Kiro IDE 1.0과 Kiro CLI V3용
Kiro 커스텀 에이전트로 `<project>/.kiro/agents/`에 작성합니다. Kiro는 에이전트 훅을
문서화하지만 어댑터는 이를 작성하지 않으므로, 가드레일 의도는 도구 호출
가로채기 지점이 아니라 규칙 산문 안에 존재합니다. 공유 규칙에 대한 모든 변경은 다음
`apothem update` 시 파일을 다시 렌더링합니다.

## 마이그레이션 경로

1. 아직 공유 프로필을 만들지 않았다면 `apothem profile init`을 실행합니다.
2. 기존 `.kiro/steering/`의 규칙을 공유 코퍼스로 옮깁니다.
3. `apothem install --harness kiro --project <path>`를 실행해 `apothem-rules.md` 스티어링 파일을 렌더링합니다.
4. `apothem verify --harness kiro --project <path>`를 실행해 구성이 반영되었는지 확인합니다.
5. 이후의 모든 변경에는 `apothem update --harness kiro --project <path>`를 사용합니다.
