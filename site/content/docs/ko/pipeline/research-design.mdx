**역할:** 책임 연구원(연구 설계)
**파이프라인 위치:** 체인 중간

가설을 검증 가능한 예측으로 조작화하고 연구 또는 실험을 설계합니다 — 변수, 통제 조건, 실험 단위, 배정과 맹검, 표본, 도구, 검정력 분석, 타당도 위협 — 그런 다음 데이터 수집 전에 분석 계획을 동결하는 사전 등록을 생성합니다.

## 정규 호출

```bash
/research-design
```

인수 사용:

```bash
/research-design [--suite-name NAME]
```

## 입력

`_inputs/proposal.md`(`/research-proposal`, 이전 단계에서 나온 기록 계획), `_inputs/synthesis.md`(SOTA 지도 + 격차 진술), 그리고 `_spec/research-spec.md`(가설).

## 출력

`_inputs/study-design.md`(조작화된 예측, 변수 명세, 통제 조건, 실험 단위, 배정 및 맹검 계획, 표본, 도구, 검정력 분석, 타당도 위협) + `_inputs/preregistration.md`(합격 기준을 갖춘 통제 조건, 배정 및 맹검 계획, 결측 결과 처리, 그리고 모든 중간 분석을 포함한 동결된 분석 계획).

## 하류

/research-experiment(하류 소비자)

## 워크플로 단계

이 명령은 표준 `/research` 파이프라인 워크플로를 따릅니다.

1. **컨텍스트 로드** — 종합과 명세의 가설을 읽습니다.
2. **시퀀스 게이트 검증** — `_inputs/proposal.md`(및 상류의 `_inputs/synthesis.md`와 `_spec/research-spec.md`)가 존재하는지 확인합니다. 그렇지 않으면 `Blocked: run /research-proposal first`로 중단합니다.
3. **연구 설계** — 예측을 조작화합니다. 변수, 통제 조건, 도구를 명세합니다. 실험 단위, 시드가 고정된 배정, 맹검 계획, 실행 순서를 확정합니다. 계획된 분석에 맞게 표본 크기를 정합니다. 타당도 위협을 열거합니다.
4. **사전 등록** — 어떤 데이터 수집보다 먼저 분석 계획, 통제 조건, 배정, 맹검을 동결합니다.
5. **핸드오프 매니페스트 업데이트** — 연구 설계와 사전 등록의 경로를 기록합니다.
6. **설계 발행** — `_inputs/study-design.md` + `_inputs/preregistration.md`.

## 구조와 표본 크기

- **구조는 분석이 아니라 설계에서 확정됩니다.** 설계는 실험 단위와 분석 단위, 시드가 고정된 일정을 갖춘 배정 절차와 단위가 순차적으로 등록되는 경우의 배정 은폐, 맹검 대상(또는 맹검이 불가능한 이유), 장애 요인과 각각을 블록화·무작위화·고정하는 방법, 그리고 실행 순서를 명시합니다. 실험이 실행할 비교 대상과 양성 및 음성 대조군을 계획합니다. 동결 후에 추가된 대조군은 공개되는 이탈입니다.
- **단일 요인 스윕은 상호작용을 보여 줄 수 없습니다.** 구성 요소나 매개변수가 상호작용한다고 의심되는 경우, 설계는 의심되는 집합에 대한 결합 배치를 추가하고 주장하는 상호작용을 사전 등록합니다.
- **최소 관심 효과는 명세에서 나옵니다.** 이는 명세의 성공 지표 또는 종합이 근거를 제시하는 실질적 유의성 임계값으로 추적됩니다. 선행 연구가 보고한 효과는 그럴듯한 범위를 한정할 뿐 결코 최소 관심 효과를 대신하지 않습니다.
- **실행될 분석에 맞게 표본 크기를 정합니다.** 각 주요 주장의 목표(우월성, 비열등성 또는 동등성)와 단측·양측 여부는 설계에서 확정되며, 각각은 선언된 보정이 남기는 검정별 임계값에서 자체의 최소 관심 효과에 대해 검정력을 갖추도록 설계됩니다. 필요한 N은 그럴듯한 효과 전반에 걸친 범위로 보고됩니다. 실현 가능성이 N을 제한하면 그 N에서의 최소 탐지 가능 효과를 보고하고, 최소 관심 효과에 대해서는 검정력이 확보되지 않았다고 명시합니다.
- **허용치와 시뮬레이션.** N은 독립 단위를 세며 군집 내 상관을 반영해 부풀립니다. 수집 목표는 기록된 손실률을 통해 분석 N에서 도출됩니다. 계획된 분석에 맞는 닫힌 형식이 없는 경우 검정력은 시뮬레이션으로 추정하며 도구, 버전, 시드, 몬테카를로 오차를 기록합니다. 순차 규칙은 사전 등록에서 중간 분석 횟수와 경계를 확정합니다.

## 최저 엄밀성 기준

비교를 수반하는 연구의 경우, 설계는 경험적 하한을 고정하고 사전 등록합니다. 즉, 비교되는 모든 방법에 걸친 하나의 통일된 예산(동일한 실제 소요 시간과, 의미 있는 경우 동일한 평가 횟수), 확률적 방법에 대해 인스턴스당 최소 30회의 반복, 한 번에 한 구성 요소를 비활성화하는 절제(ablation) 요인, 각 매개변수에 대한 민감도 스윕, 그리고 분리된 테스트 분할에서 평가되는 훈련 분할에서의 자동 구성입니다. 하한의 깊이는 목표 게재처의 야심에 따라 조정됩니다.

## 실패 모드

| 증상 | 원인 | 복구 |
|---------|-------|----------|
| Blocked: run /research-proposal first | 기록 계획 없음 | `/research-proposal`를 실행하여 `_inputs/proposal.md` 생성 |
| 검정력 부족 설계 | 효과에 비해 표본이 너무 작음 | 계획된 분석에 대한 검정력 분석을 다시 실행; 표본 크기를 재조정하거나, 최소 탐지 가능 효과를 보고하고 최소 관심 효과에 대해서는 검정력이 확보되지 않았다고 명시 |
| 구조가 분석에 맡겨짐 | 단위, 배정, 맹검 또는 실행 순서가 설계에서 확정되지 않음 | 설계와 사전 등록에서 이를 확정; 사후에 적용하는 어떤 검정도 배치가 만들어 낸 교란을 분리하지 못함 |
| 선행 추정치가 목표 효과로 사용됨 | 단일 연구가 보고한 효과가 최소 관심 효과를 대신함 | 목표를 명세의 성공 지표에 근거; 선행 연구는 범위를 한정하는 데만 사용 |
| 분석 계획이 동결되지 않음 | 사전 등록 건너뜀 | 데이터 수집 전에 `_inputs/preregistration.md` 작성 |

## 예시

```bash
# 연구를 설계하고 분석 계획을 사전 등록합니다
/research-design --suite-name <name>
```
