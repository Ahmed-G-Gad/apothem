**역할:** 책임 연구자(게재)
**파이프라인 위치:** 체인 중간

논문을 게재처 템플릿에 맞춰 서식화하고 제출 패키지를 조립합니다 — 보충 자료, 데이터/코드 가용성 진술, 커버 레터, 윤리 및 이해상충 선언 — 그리고 DOI가 포함된 프리프린트/아카이브 계획과 제출 체크리스트. 운영자가 패키지를 제출합니다. 종단 후속 단계는 `/research-disseminate`로, 게재된 작업을 그 독자에게 전달합니다.

## 표준 호출

```bash
/research-publish
```

인수 사용:

```bash
/research-publish [path/to/research-suite/]
```

## 입력

논문 산출물과 `_outputs/review-report.md`(동료 평가 수정 사항).

## 출력

호스트에 자연스러운 위치의 게재처 서식 제출 패키지(서식화된 원고 + 보충 자료 + 데이터/코드 가용성 진술 + 커버 레터 + 윤리/이해상충 선언) + `_outputs/publication-record.md` + 제출 체크리스트.

## 하류

/research-disseminate(하류 소비자) — 운영자가 제출을 수행한 다음, `/research-disseminate`가 게재된 작업을 그 독자에게 전달합니다. 게재처가 수정 사항을 반환하면, 패키지를 다시 구성하기 전에 수정된 논문에 대해 `/research-review`를 다시 실행합니다.

## 워크플로 단계

이 명령은 표준 `/research` 파이프라인 워크플로를 따릅니다.

1. **컨텍스트 로드** — 논문과 평가 보고서를 읽습니다.
2. **시퀀스 게이트 검증** — `_outputs/review-report.md`가 존재하는지 확인합니다. 그렇지 않으면 `Blocked: run /research-review first`로 중단합니다.
3. **서식화 및 패키징** — 게재처 템플릿을 적용합니다. 보충 자료, 데이터/코드 가용성, 커버 레터, 윤리/이해상충 선언을 조립합니다.
4. **프리프린트/아카이브 계획** — 프리프린트와 DOI 계획을 기록합니다. 제출 체크리스트를 구성합니다.
5. **핸드오프 매니페스트 업데이트** — 제출 패키지와 게재 기록을 기록합니다.
6. **패키지 발행** — 게재처 서식 제출 패키지 + `_outputs/publication-record.md`.

## 최저 엄밀성 기준

서식화는 단계적 공개를 존중합니다. 이중 맹검 게재처의 경우, 저자, 소속 기관, 시스템 신원은 별도로 제출되는 메타데이터로 분리되고 지정된 최종 원고(camera-ready) 단계에서만 복원됩니다. 아카이브 기탁은 게재처 규모에 맞춘 재현성 증거 패키지(데이터, 코드, 고정된 환경, 시드, 하드웨어 로그, 인스턴스별 결과, 그림)를 담습니다.

## 실패 모드

| 증상 | 원인 | 복구 |
|---------|-------|----------|
| Blocked: run /research-review first | 평가 보고서 없음 | `/research-review`를 실행하여 `_outputs/review-report.md`를 생성 |
| 처리되지 않은 HIGH 수정 | 평가 발견 사항을 건너뜀 | 수정 사항을 처리하고 `/research-review`를 다시 실행 |
| 데이터/코드 가용성 누락 | 재현성 표면 부재 | 제출 전에 데이터/코드 가용성 진술을 추가 |

## 예시

```bash
# 게재처 제출 패키지 조립
/research-publish path/to/research-suite/
```
