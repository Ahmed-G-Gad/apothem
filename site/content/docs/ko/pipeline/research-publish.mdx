**역할:** 책임 연구자(게재)
**파이프라인 위치:** 체인 중간

논문을 게재처 템플릿에 맞춰 서식화하고 제출 패키지를 조립합니다 — 보충 자료, 데이터/코드 가용성 진술, 커버 레터, 윤리 및 이해상충 선언 — 그리고 DOI가 포함된 프리프린트/아카이브 계획과 제출 체크리스트. 운영자가 패키지를 제출합니다. 종단 후속 단계는 `/research-disseminate`로, 게재된 작업을 그 독자에게 전달합니다.

## 표준 호출

```bash
/research-publish
```

인수 사용:

```bash
/research-publish [--suite-name NAME]
```

## 입력

논문 산출물과 `_outputs/review-report.md`(동료 평가 수정 사항과 그 판단 불가 목록).

## 출력

호스트에 자연스러운 위치의 게재처 서식 제출 패키지(서식화된 원고 + 보충 자료 + 데이터/코드 가용성 진술 + 커버 레터 + 윤리/이해상충 선언) + `_outputs/publication-record.md`(날짜가 기록된 게재처 규칙 등록부 포함: 각 규칙과 그 공식 출처 페이지, 읽은 날짜, 제출 단계) + 제출 체크리스트.

## 하류

/research-disseminate(하류 소비자) — 운영자가 제출을 수행한 다음, `/research-disseminate`가 게재된 작업을 그 독자에게 전달합니다. 게재처가 수정 사항을 반환하면, 패키지를 다시 구성하기 전에 수정된 논문에 대해 `/research-review`를 다시 실행합니다.

## 워크플로 단계

이 명령은 표준 `/research` 파이프라인 워크플로를 따릅니다.

1. **컨텍스트 로드** — 논문과 평가 보고서를 읽습니다. 게재처, 주기, 트랙, 논문 유형을 고정하고, 각 게재처 규칙을 그 공식 출처 페이지, 읽은 날짜, 제출 단계와 함께 기록합니다.
2. **시퀀스 게이트 검증** — `_outputs/review-report.md`가 존재하고 그 HIGH 심각도 수정 사항이 해결되었는지 확인합니다(또는 운영자가 잔여 위험을 명시적으로 수용한 경우). 그렇지 않으면 `Blocked: run /research-review first`와 함께 중단합니다.
3. **서식화 및 패키징** — 각 게재처 규칙을 그 출처 페이지, 읽은 날짜, 제출 단계와 함께 유지하고, 수정되지 않은 게재처 템플릿 위에 구축하며, 게재처의 방식대로 페이지와 단어 수를 세고, 컴파일된 PDF를 검사합니다. 그런 다음 보충 자료, 데이터/코드 가용성, 커버 레터, 윤리/이해상충 선언을 조립합니다.
4. **프리프린트/아카이브 계획** — 프리프린트와 DOI 계획을 기록합니다. 제출 체크리스트를 구성합니다.
5. **핸드오프 매니페스트 업데이트** — 제출 패키지와 게재 기록을 기록합니다.
6. **패키지 발행** — 게재처 서식이 적용된 제출 패키지 + `_outputs/publication-record.md`.

## 최저 엄밀성 기준

서식화는 단계적 공개를 존중합니다. 이중 맹검 게재처의 경우, 저자, 소속 기관, 시스템 신원은 별도로 제출되는 메타데이터로 분리되고 지정된 최종 원고(camera-ready) 단계에서만 복원됩니다. 아카이브 기탁은 게재처 규모에 맞춘 재현성 증거 패키지(데이터, 코드, 고정된 환경, 시드, 하드웨어 로그, 인스턴스별 결과, 그림)를 담습니다. 이중 맹검 게재처의 경우 원고뿐 아니라 보충 자료 아카이브와 링크된 모든 저장소 또는 데이터셋도 신원 노출 여부를 검사합니다.

게재처 규칙은 출처가 있고 단계별로 적용됩니다. 대상 게재처 자체의 공식 페이지만 인정됩니다: 인접 게재처, 이전 주기, 또는 자매 트랙은 결코 대체물이 되지 않으며, 수정본이나 최종 원고(camera-ready)를 위한 재구성은 최초 제출의 한도가 아니라 해당 단계의 한도를 적용합니다. 뒷받침하는 공식 페이지가 없는 규칙은 운영자에게 질문하고 게재처에 대해 검증되지 않음으로 표시합니다. 게재처의 템플릿 파일은 배포된 그대로 유지되므로, 로컬에서 작성한 시작 파일은 그렇게 보고됩니다. 페이지와 단어 수는 제외된 섹션을 기록하면서 게재처의 방식대로 세며, 각 그림과 표는 게재처가 받는 크기와 형식으로 점검합니다.

## 실패 모드

| 증상 | 원인 | 복구 |
|---------|-------|----------|
| Blocked: run /research-review first | 평가 보고서가 없거나 해결되지 않은 HIGH 심각도 수정 사항이 있음 | `/research-review`를 실행하여 `_outputs/review-report.md`를 생성하거나, 해결되지 않은 HIGH 수정 사항을 처리한 뒤 `/research-review`를 다시 실행하거나, 잔여 위험을 명시적으로 수용하세요 |
| 처리되지 않은 HIGH 수정 | 평가 발견 사항을 건너뜀 | 수정 사항을 처리하고 `/research-review`를 다시 실행하세요 |
| 데이터/코드 가용성 누락 | 재현성 표면 부재 | 제출 전에 데이터/코드 가용성 진술을 추가하세요 |
| 출처 없는 게재처 규칙 | 규칙이 다른 주기, 트랙, 인접 게재처 또는 기억에서 나옴 | 대상을 고정하고, 규칙에 대한 공식 페이지, 읽은 날짜, 단계를 기록하거나, 운영자에게 질문하고 검증되지 않음으로 표시하세요 |
| 템플릿 변경됨 | 로컬 편집이 게재처의 페이지 기하나 서체 설정을 바꿈 | 게재처의 파일을 복원하고, 템플릿이 문서화한 옵션을 통해서만 레이아웃을 변경하세요 |

## 예시

```bash
# 게재처 제출 패키지를 조립합니다
/research-publish --suite-name <name>
```
