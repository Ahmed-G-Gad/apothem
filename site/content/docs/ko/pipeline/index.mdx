Apothem은 아키텍처를 인식하는 `/plan` 파이프라인, 13단계로 이루어진
`/research` 파이프라인, 그리고 11개 명령으로 이루어진 감사 시퀀스를
제공합니다. 이로써 모든 프로젝트는 가공되지 않은 산문에서 여러 축으로 검토된
프로덕션 수준의 코드에 이르는 구조화된 경로와, 가공되지 않은 아이디어에서
동료 심사를 거쳐 널리 알려진 논문에 이르는 구조화된 경로를 얻습니다.

## 파이프라인 개요

```mermaid
flowchart LR
    accTitle: Plan pipeline command flow
    accDescr: Left-to-right flowchart of the apothem plan pipeline from the spec stage through the generate and review stages, then through a conditional architecture-bearing decision that either runs the design stage or skips directly to the execute stage. The orthogonal audit stage wraps the spec-through-review span as a closed remediation loop, and the re-entrant amend stage revises an existing suite and returns it to review.
    A[/plan-spec] --> B[/plan-generate]
    B --> C[/plan-review]
    AUD[/plan-audit<br/>orthogonal: wraps spec → review] -.->|closed-loop remediation| A
    AM[/plan-amend<br/>re-entrant: revises an existing suite] -.->|re-review| C
    C --> Q{Architecture-bearing suite?}
    Q -->|yes| F[/plan-design<br/>emit _inputs/design.md]
    Q -->|no| D[/plan-execute]
    F --> D
    D --> E[/plan-status]
    D --> G[Audit review sequence]
    G --> H[Completion milestone]
```

## 계획 단계

이 파이프라인은 단계마다 하나씩, 8개의 일급 슬래시 명령으로 제공되며, 각
명령은 `/plan-<stage>`로 독립적으로 호출할 수 있습니다. [/plan](/docs/pipeline/plan)
오케스트레이터는 미션에서 실행된 스위트까지 이 단계들을 구동합니다.

| 단계 | 역할 | 위치 |
|-------|------|----------|
| [/plan-spec](/docs/pipeline/plan-spec) | 포지 — 산문을 명세로 | 시작 |
| [/plan-generate](/docs/pipeline/plan-generate) | 생성기 — 명세를 플랜 스위트로 | 중간 단계 |
| [/plan-review](/docs/pipeline/plan-review) | 감사자 — 포렌식 플랜 감사 | 중간 단계 |
| [/plan-design](/docs/pipeline/plan-design) | 아키텍트 — 아키텍처에 영향을 주는 스위트를 위한 `_inputs/design.md` | 조건부 게이트 |
| [/plan-execute](/docs/pipeline/plan-execute) | 실행기 — 단계 실행 | 마지막 |
| [/plan-status](/docs/pipeline/plan-status) | 보고자 — 읽기 전용 상태 | 읽기 전용 |
| [/plan-audit](/docs/pipeline/plan-audit) | 수호자 — spec → generate → review를 감싸는 닫힌 루프 | 직교(실행 전) |
| [/plan-amend](/docs/pipeline/plan-amend) | 관리자 — 기존 스위트의 재진입형 수정 | 재진입형 |

`/plan-audit`은 선형 흐름과 직교하며, 그 흐름 안의 한 단계가 아닙니다. 이
명령은 `/plan-spec → /plan-generate → /plan-review`를 하나의 닫힌 루프로
감싸고, 누락된 상위 단계만 실행하며, 발견 사항을 적극적으로 교정하고, 스위트를
`/plan-execute`를 실행할 수 있는 상태로 남깁니다. 이 명령은 아래의 감사 검토
시퀀스와 다릅니다. 감사 검토 시퀀스는 플랜 스위트가 아니라 실행된 코드베이스를
감사합니다.

`/plan-design`은 모든 경우에 거치는 절차가 아닙니다. `/plan-review`는 스위트가
아키텍처에 영향을 주는 표면을 변경하는지 분류합니다. 변경한다면 `/plan-design`이
`/plan-execute`와 `/architecture-review`가 사용하는 설계 추적을 출력합니다.
변경하지 않는다면 검토된 스위트는 바로 실행 단계로 넘어갑니다.

## 연구 파이프라인

연구 파이프라인은 단계마다 하나씩, 13개의 일급 슬래시 명령으로 제공됩니다. 각
명령은 `/research-<stage>`로 독립적으로 호출할 수 있고, 시퀀스 게이트와 핸드오프
매니페스트로 연결되며, 10가지 엄밀성 맨데이트(권위 있는 출처, 재현성, 반증
가능성, 인용 무결성, 사전 등록, 윤리 / 이해 상충, 통계적 엄밀성, 오픈 사이언스 /
FAIR, 보고 지침 준수, 이론적 근거 / 영향)를 따릅니다.

```mermaid
flowchart LR
    accTitle: Research pipeline command flow
    accDescr: Left-to-right flowchart of the apothem research pipeline from the ideate stage through spec, theory, sources, synthesis, proposal, study design, experiment, analysis, paper, and peer review to publish and disseminate, with a revision loop from review back to paper.
    RI[/research-ideate] --> RS[/research-spec]
    RS --> RT[/research-theory]
    RT --> RSO[/research-sources]
    RSO --> RSY[/research-synthesis]
    RSY --> RPR[/research-proposal]
    RPR --> RD[/research-design]
    RD --> RE[/research-experiment]
    RE --> RA[/research-analysis]
    RA --> RP[/research-paper]
    RP --> RR[/research-review]
    RR --> RPU[/research-publish]
    RPU --> RDI[/research-disseminate]
    RR -.->|revision loop| RP
```

| 단계 | 역할 | 위치 |
|-------|------|----------|
| [/research-ideate](/docs/pipeline/research-ideate) | 문제 정의 — 도메인 시드에서 후보 질문 도출 | 시작 |
| [/research-spec](/docs/pipeline/research-spec) | 질문 구성 — 반증 가능한 가설 + 범위 | 중간 단계 |
| [/research-theory](/docs/pipeline/research-theory) | 개념적 프레임워크 + 변화 이론 | 중간 단계 |
| [/research-sources](/docs/pipeline/research-sources) | 재실행 가능한 검색 기록을 갖춘 체계적인 출처 수집 | 중간 단계 |
| [/research-synthesis](/docs/pipeline/research-synthesis) | 최신 기술 수준(SOTA) 지도 + 공백 분석 | 중간 단계 |
| [/research-proposal](/docs/pipeline/research-proposal) | 목표 + 실현 가능성 + 비상 대책 + 영향 + 데이터 계획 + 사전 등록 계획; 연구비 공모 매트릭스 또는 재제출 응답 | 중간 단계 |
| [/research-design](/docs/pipeline/research-design) | 연구 설계 + 사전 등록 | 중간 단계 |
| [/research-experiment](/docs/pipeline/research-experiment) | 실행 + 기록, 재현 가능 | 중간 단계 |
| [/research-analysis](/docs/pipeline/research-analysis) | 결과 + 통계 | 중간 단계 |
| [/research-paper](/docs/pipeline/research-paper) | 최상위 수준의 논문 초안 | 중간 단계 |
| [/research-review](/docs/pipeline/research-review) | 동료 심사 수준의 비평 | 중간 단계 |
| [/research-publish](/docs/pipeline/research-publish) | 게재처용 패키지 + 제출 | 중간 단계 |
| [/research-disseminate](/docs/pipeline/research-disseminate) | 확산 + 영향 + FAIR 아카이빙 | 마지막 |

[/research](/docs/pipeline/research) 래핑 워크플로 오케스트레이터는 가공되지 않은
질문에서 게재된 논문까지 이 단계들을 구동하며(오케스트레이터 자체는 단계가
아닙니다), 다음 단계가 이전 단계의 출력 위에 작업을 쌓기 전에 각 단계의 출력을
독립적으로 확인합니다. `--quick`은 인용이 포함된 일회성 보고서를 위해
`/research-sources` + `/research-synthesis`만 실행합니다.

경험적 단계(출처, 설계, 실험, 분석)와 집필 단계(논문, 심사, 게재, 확산)는
엄밀성을 운영 수준으로 구체화하는 표면도 추가로 활용합니다. 공정한 다중 방법
비교, 비교 대상의 출처 정보, 실험 프로그램 스캐폴드, 컴퓨팅 활용 계획, 옵트인
자율 실험 루프, 완료 정의(definition-of-done) 진행 게이트, 단계적 공개를 동반한
맹검, 검색 기록, 연구 배정 및 검정력 계획, 분석 규율, 계획 비상 대책, 그림
무결성, 발표 및 포스터 계획이 여기에 해당하며, 이들은 10가지 맨데이트를 확장하지
않고 운영 세부 사항을 더합니다.

## 감사 검토 시퀀스

[/audit](/docs/pipeline/audit) 래핑 워크플로 오케스트레이터는 아래 11개 차원 전체를 하나의 병렬 패스로 훑으며(`/plan`과 `/research`에 대응하는 감사 요새), 중복을 제거하고 심각도별로 분류한 하나의 발견 사항 보고서로 종합합니다(보고 전용이며, 교정은 `/elevate`로 넘어갑니다). 각 차원은 개별적으로도 호출할 수 있습니다.

[/fortress](/docs/pipeline/fortress) 래핑 워크플로 오케스트레이터는 `/audit`가 보고하는 루프를 닫습니다. `/audit`를 통해 탐지하고, 각 발견 사항을 검증하고, 남은 모든 발견 사항을 해당 소유 표면에서 교정하고, 횟수가 제한된 루프로 다시 감사한 다음, 그 결과를 [/release-readiness](/docs/pipeline/release-readiness)로 게이트합니다. 이는 `/plan`과 `/research`에 대응하는 프로덕션 강화 오케스트레이터입니다.

|---------|--------------|

| [/security-audit](/docs/pipeline/security-audit) | OWASP / ASVS |
| [/perf-audit](/docs/pipeline/perf-audit) | 성능 |
| [/architecture-review](/docs/pipeline/architecture-review) | 아키텍처 |
| [/ux-review](/docs/pipeline/ux-review) | 개발자 경험 |
| [/a11y-audit](/docs/pipeline/a11y-audit) | 접근성 |
| [/docs-review](/docs/pipeline/docs-review) | 문서 |
| [/dependency-audit](/docs/pipeline/dependency-audit) | 종속성 |
| [/supply-chain-audit](/docs/pipeline/supply-chain-audit) | 공급망 |
