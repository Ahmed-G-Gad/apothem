**역할:** 수석 연구자(구성)
**파이프라인 위치:** 체인 중간

자유 형식의 연구 질문이나 원시 메모를 사양 등급의 `_spec/research-spec.md` — 명시적인 범위, 포함 / 제외 기준, 성공 지표를 갖춘 검증 가능하고 반증 가능한 가설 집합 — 으로 구성하여 `/research-theory`에 바로 넘길 수 있게 만듭니다.

## 표준 호출

```bash
/research-spec
```

인수 포함:

```bash
/research-spec [path/to/question-or-notes] [--suite-name NAME] [--quick SLUG]
```

## 입력

자유 형식의 연구 질문 또는 원시 메모(운영자가 인라인으로 또는 경로로 제공).

## 출력

`_spec/research-spec.md`(질문, 반증 가능한 가설, 범위, 포함 / 제외 기준, 성공 지표, 용어집) + `_inputs/handoff-manifest.yml`. `--quick`는 대신 경량의 프로젝트 로컬 연구 브리프를 작성합니다.

## 다운스트림

/research-theory(다운스트림 소비자)

## 워크플로 단계

이 명령은 표준 `/research` 파이프라인 워크플로를 따릅니다.

1. **컨텍스트 로드** — 질문 / 메모, 규칙, 그리고 기존 스위트 상태를 읽습니다.
2. **질문 구성** — 명시적인 범위와 포함 / 제외 기준을 갖춘 반증 가능한 가설로 분해합니다. 구조화 질의 채널을 통해 모든 모호함을 표면화합니다.
3. **성공 지표 설정** — 연구를 판단할 측정 가능한 기준을 진술합니다.
4. **출력 검증** — 사양이 확정적인지(모든 권위 데이터 공백이 구조화 질의 채널을 통해 해소되었고, 채워지지 않은 확인 자리표시자가 남지 않았는지) 확인하고, 엄밀성 의무의 하한을 통과하는지 확인합니다.
5. **인계 매니페스트 업데이트** — 사양 경로와 미해결 / 해결된 질의 수를 기록합니다.
6. **사양 발생** — `_spec/research-spec.md`와 인계 매니페스트.

## 최저 엄밀성 기준

주장된 각 기여는 뚜렷하고, 실질적이며, 독립적으로 절제(ablation) 가능하도록 제약되어, 이후 그 한계 효과를 분리할 수 있습니다. 요구되는 최저 엄밀성 기준의 깊이는 목표 게재처의 야심에 따라 조정됩니다. 그 야심이 명시되지 않은 경우에는 구조화 질의를 통해 확인하며 결코 지어내지 않습니다.

## 실패 모드

| 증상 | 원인 | 복구 |
|---------|-------|----------|
| 미해결 가설 모호함 | 질문이 충분히 명세되지 않음 | 구조화 질의로 표면화; 범위를 지어내지 마십시오 |
| 측정 가능한 성공 지표 없음 | 목표가 결과가 아니라 활동으로 진술됨 | 검증 가능하고 반증 가능한 결과로 재구성 |
| 질문 입력 누락 | 산문 / 메모가 제공되지 않음 | 연구 질문을 인라인으로 또는 경로로 제공 |

## 예제

```bash
# Frame a question into a research spec
/research-spec ~/notes/retrieval-latency-study.md --suite-name retrieval-latency

# Lightweight project-local research brief
/research-spec --quick retrieval-latency
```
