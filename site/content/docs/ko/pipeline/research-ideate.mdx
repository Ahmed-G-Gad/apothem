**역할:** 책임 연구자(문제 구성)
**파이프라인 위치:** 첫 단계

처음부터 문제 공간을 구성합니다 — 기회 및 격차 스캔, 무효화된 선행 가설 스캔, 그리고 순위 매기기를 동반한 후보 연구 질문 생성 — `/research` 파이프라인의 진입 단계입니다. 각 후보는 사전 이론적 앵커에 비추어 틀이 지어지고, 선행 연구에 근거하며, 반증 가능한 형태로 진술되어 `/research-spec`에 넘길 준비를 갖춥니다.

## 표준 호출

```bash
/research-ideate
```

인자 포함:

```bash
/research-ideate [path/to/domain-notes] [--suite-name NAME] [--override] [--domain NAME]
```

## 입력

도메인 시드 — 자유 형식의 도메인 노트(운영자가 인라인으로 또는 경로로 제공), 혹은 처음부터 시작할 때는 단순한 `--domain` 이름.

## 출력

`_inputs/ideation.md`(틀이 지어진 문제 공간, 기회 및 격차 스캔, 무효화된 선행 가설 스캔, 그리고 순위가 매겨진 후보 질문 목록)와 연구 스위트 폴더의 핸드오프 매니페스트.

## 다운스트림

/research-spec(다운스트림 소비자 — 선택된 후보를 반증 가능한 명세로 틀 짓습니다).

## 워크플로 단계

이 명령은 표준 `/research` 파이프라인 워크플로를 따릅니다:

1. **컨텍스트 로드** — 도메인 시드, 규칙, 그리고 기존 스위트 상태를 읽습니다.
2. **기회 및 격차 공간 스캔** — 해당 도메인에서 무엇이 연구되었고, 무엇이 논쟁 중이며, 무엇이 다루어지지 않은 채 남아 있는지 매핑합니다.
3. **무효화된 선행 가설 스캔** — 선행 연구에 의해 이미 반박된 가설을 드러내어 목록이 이미 정리된 지점을 다시 밟지 않도록 합니다.
4. **후보 생성 및 순위 매기기** — 후보 연구 질문을 산출하고, 각각을 반증 가능한 형태로 진술하며, 처리 용이성과 영향력으로 순위를 매깁니다.
5. **출력 검증** — 각 후보가 일차 선행 연구에 근거하고 반박 가능한지 확인합니다. 모든 모호함을 구조화된 질의 채널을 통해 해소합니다.
6. **아이디에이션 목록 발행** — `_inputs/ideation.md`와 핸드오프 매니페스트.

## 실패 모드

| 증상 | 원인 | 복구 |
|---------|-------|----------|
| 반증 가능한 후보 없음 | 도메인 시드가 너무 광범위하거나 순전히 서술적임 | 구조화된 질의로 도메인을 좁힙니다. 후보를 반박 가능한 질문으로 다시 틀 짓습니다 |
| 후보가 무효화된 선행 가설을 다시 진술함 | 선행 연구 스캔이 생략됨 | 무효화된 선행 가설 스캔을 실행합니다. 겹치는 후보를 버리거나 다시 틀 짓습니다 |
| 도메인 시드 누락 | 노트나 `--domain`이 제공되지 않음 | 도메인 노트를 인라인 / 경로로 제공하거나 `--domain NAME`을 전달합니다 |

## 예시

```bash
# 도메인을 스캔하고 순위가 매겨진 후보 질문을 생성합니다
/research-ideate ~/notes/retrieval-systems.md --suite-name retrieval-latency

# 단순한 도메인 이름에서 시작합니다
/research-ideate --domain "vector-index recall under drift"
```
