**역할:** 책임 연구원(이론적 정초)
**파이프라인 위치:** 체인 중간

구성된 연구 질문에 대한 기초적인 개념적·이론적 프레임워크를 구축합니다 — 체계적 검색과 종합 단계가 거슬러 올라가 참조하는 선험적 정초입니다. 모든 구성 개념은 일차 이론에 뿌리를 두며, 이론화된 모든 관계는 반증 가능한 형태로 진술됩니다.

## 표준 호출

```bash
/research-theory
```

인수와 함께:

```bash
/research-theory [--suite-name NAME] [--override] [--framework NAME]
```

## 입력

스위트의 `_spec/research-spec.md`(`/research-spec`이 생성한, 구성되고 반증 가능한 질문 집합).

## 출력

`_inputs/theory.md`(개념적 / 이론적 프레임워크, 변화 이론 / 논리 모델, 조작적 정의를 갖춘 구성 개념, 그리고 개념 모델 다이어그램).

## 다운스트림

/research-sources(다운스트림 소비자 — 체계적 검색은 포함 기준을 이 구성 개념들까지 거슬러 추적합니다).

## 워크플로 단계

이 명령은 표준 `/research` 파이프라인 워크플로를 따릅니다.

1. **컨텍스트 로드** — `_spec/research-spec.md`, 규칙, 그리고 기존 스위트 상태를 읽습니다.
2. **개념 모델 구성** — 구성 개념과 그 조작적 정의를 정의하고, 각각을 일차 이론에 뿌리내립니다.
3. **변화 이론 그리기** — 구성 개념을 기대 결과에 연결하는 논리 모델을 구축하고, 각 관계를 반증 가능한 형태로 진술합니다.
4. **모델 다이어그램화** — 다운스트림 단계가 참조하는 개념 모델 다이어그램을 발행합니다.
5. **출력 검증** — 모든 구성 개념이 이론에 뿌리내리고 모든 관계가 반증 가능한지 확인하며, 구조화된 질의 채널을 통해 모호성을 해소합니다.
6. **프레임워크 발행** — `_inputs/theory.md`와 업데이트된 핸드오프 매니페스트.

## 실패 모드

| 증상 | 원인 | 복구 |
|---------|-------|----------|
| 구성 개념에 조작적 정의가 없음 | 개념이 추상적으로 진술됨 | 구성 개념을 측정 가능한 용어로 정의하고 일차 이론을 인용 |
| 이론화된 관계가 반증 불가능 | 관계가 자명한 진리로 진술됨 | 관계를 반증 가능한 주장으로 다시 진술 |
| 스펙 입력 누락 | `/research-spec`이 아직 실행되지 않음 | 먼저 `/research-spec`을 실행하여 질문을 구성 |

## 예시

```bash
# 구성된 질문에 대한 이론적 프레임워크 구축
/research-theory --suite-name retrieval-latency

# 명명된 이론적 프레임워크에 고정
/research-theory --framework "information foraging theory"
```
