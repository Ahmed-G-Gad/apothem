**역할:** 아키텍트
**파이프라인 위치:** 조건부, 검토 후·실행 전

플랜 스위트에 아키텍처를 지닌 작업이 있을 때 `_inputs/design.md`에 아키텍처
설계 산출물을 생성합니다. 이것은 의도적으로 조건부입니다. 산문, 문서,
메타데이터 또는 좁은 픽스처 스위트는 `/plan-review`에서 `/plan-execute`로
곧바로 진행합니다. 컴포넌트, 인터페이스, 스키마, 데이터 흐름, 어댑터, 릴리스
토폴로지, 보안 경계 또는 런타임 동작을 변경하는 스위트는 먼저 `/plan-design`을
거칩니다.

## 정규 호출

```bash
/plan-design path/to/plan-suite/
```

인자와 함께:

```bash
/plan-design [path/to/plan-suite/] [--refine-existing] [--dry-run]
```

## 입력

검토된 플랜 스위트 + `_spec/spec.md` + `_inputs/handoff-manifest.yml` +
`/plan-review`의 PASS 검토 스코어카드.

## 출력

`_inputs/design.md` 및 설계 산출물 경로, 설계 게이트 결과, 7축 커버리지 결과,
양방향 바인딩 매트릭스 요약을 담은 보강된 `_inputs/handoff-manifest.yml`.

## 적용성 게이트

최소 하나의 하류 페이즈가 다음을 선언하거나 함의할 때 `/plan-design`을
실행합니다:

- 소스 레이아웃, 패키지 경계, 어댑터 경계 또는 모듈 경계의 변경.
- 공개 인터페이스, 프로토콜, 스키마, 구성 계약 또는 CLI 동작.
- 컴포넌트 간 데이터 흐름, 생명주기 순서, 상태 전이 또는 의존성 에지.
- 보안, 성능, 동시성, 관측 가능성, 배포, 릴리스 또는 공급망 아키텍처.
- 구현을 설계 산출물까지 거슬러 추적해야 하는 후속 `/architecture-review`
  패스.

스위트가 문안 편집, 생성된 인벤토리 갱신, 좁은 픽스처 업데이트, 일회성 문서
수정, 또는 아키텍처 추적 표면 없이 구현을 검증할 수 있는 그 밖의 작업에
국한될 때는 `/plan-design`을 건너뜁니다. 건너뛰기 경로는 명시적입니다.
`/plan-review`가 비아키텍처 분류를 기록하고, 이어서 `/plan-execute`가 검토된
플랜 스위트에서 계속합니다.

## 하류

`/plan-execute`는 아키텍처를 지닌 페이즈에 대해 설계 산출물을 소비합니다.
`/architecture-review`는 감사 검토 시퀀스 동안 동일한 산출물을 소비합니다.
아키텍처를 지닌 작업에 대해 `_inputs/design.md`가 없으면 아키텍처 검토가
중단되고 스위트를 `/plan-design`으로 되돌립니다.

## 워크플로 페이즈

이 명령은 여섯 개의 아키텍처 전용 변환 페이즈를 따릅니다:

1. **입력 수집** — 검토된 스위트, 스코어카드, 페이즈 출력, 인계 매니페스트를
   읽고, SHARED+에서 누락되거나 실패한 검토 증거에 대해 차단합니다.
2. **아키텍처 분해** — 아키텍처, 동시성, 성능, 보안, 테스트, 툴링,
   관측 가능성을 순회하여 컴포넌트, 에지, 미해결 아키텍처 질문을 식별합니다.
3. **컴포넌트 인터페이스 설계** — 공개 인터페이스, 프로토콜 계약, 스키마,
   불변식, 실패 모드, 의존성 역전 경계를 정의합니다.
4. **컴포넌트 간 바인딩 비준** — 상류, 하류, 형제, 준거, 앵커의 모든 에지를
   닫고, 컴포넌트 그래프가 매트릭스 임계값을 넘을 때 양방향 바인딩 매트릭스를
   발행합니다.
5. **설계 산출물 발행** — 컴포넌트 섹션, 다이어그램, 결정 기록, 검증 결과,
   바인딩을 담아 `_inputs/design.md`를 작성합니다.
6. **설계 검증 게이트** — 15개 바의 사전 발행 게이트를 실행하고, 설계가
   통과한 후에만 `_inputs/handoff-manifest.yml`을 갱신합니다.

## 설계 산출물 형태

발행된 `_inputs/design.md`는 다음을 포함합니다:

- 컴포넌트 수와 7축 커버리지를 담은 요약.
- 주요 컴포넌트마다 한 섹션, 내부 도메인 표면에서 외부 어댑터 및 운영자
  표면으로 순서대로 배열.
- 구조가 그렇지 않으면 모호할 곳에서의 Mermaid 아키텍처, 시퀀스, 상태 또는
  의존성 다이어그램.
- 대안, 트레이드오프, 가역성 메모를 담은 확정된 아키텍처 결정 기록.
- 해당하는 경우 검증 게이트 결과와 양방향 바인딩 매트릭스.
- 상류 및 하류 계획 표면을 향한 산출물 자체의 5방향 바인딩.

## 실패 모드

| 증상 | 원인 | 복구 |
|---------|-------|----------|
| 전제 조건 미완료 | 의존 페이즈가 완료되지 않음 | 먼저 상류 페이즈를 완료한다 |
| 품질 게이트 FAIL | 출력이 표준을 충족하지 않음 | 출력을 수정하고 재실행한다 |
| 검토된 스위트 누락 | 플랜 스위트 또는 검토 스코어카드 부재 | `/plan-generate`, 이어서 `/plan-review`를 실행한다 |
| 비아키텍처 스위트 | 아키텍처 추적 표면이 필요한 페이즈 없음 | 건너뛰기를 기록하고 `/plan-execute`로 계속한다 |
| 아키텍처 검토 차단 | 아키텍처를 지닌 구현에 `_inputs/design.md` 부재 | `/plan-design`을 실행하고 `/architecture-review`를 재실행한다 |

## 예시

```bash
# 적용성, 컴포넌트 수, 미해결 질문을 미리 보기 위한 드라이런
/plan-design --dry-run

# 명명된 아키텍처를 지닌 스위트에 대해 설계를 발행한다
/plan-design path/to/plan-suite/
```
