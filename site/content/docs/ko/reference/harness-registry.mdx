하니스 레지스트리는 CLI, 문서, 픽스처 테스트, 규약 핀 검증이 사용하는 진실
공급원 어댑터 인벤토리입니다. 런타임 소스는
`src/apothem/lib/harness_registry.py`이며, 아래의 모든 행은 그 레지스트리,
어댑터별 `capabilities.yml`, 각 어댑터의
`STANDARD-CONVENTION-PIN.md`까지 추적할 수 있습니다.

## 페이로드 코호트 지원

상태 값은 `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable`,
`discovery-pending`입니다.

`converted` 코호트는 하니스 자체 형식으로 다시 작성되며, 일부 소스 필드는 그
형식 안에 들어갈 자리가 없습니다. 변환된 명령, 에이전트, 규칙 코호트마다
어댑터의 `capabilities.yml`은 모든 소스 프런트매터 필드가 어떻게 되는지
밝히는 `conversion_losses` 맵을 담습니다.

| 값 | 의미 |
| --- | --- |
| `native:<field>` | 하니스가 그 필드 아래에서 읽습니다. |
| `sidecar:<path>` | 변환된 파일 옆의 별도 파일(예: Codex의 `agents/openai.yaml`)에 기록됩니다. |
| `filename` | 파일 또는 폴더 이름이 그 값을 담습니다. |
| `inlined` | 프롬프트 또는 본문 텍스트 안으로 옮겨집니다. |
| `ignored` | 파일에 남지만 하니스가 읽지 않습니다. |
| `dropped` | 제외됩니다. |

## 공유 루트

일부 설치 대상은 그 대상을 쓰는 하니스가 아닌 다른 하니스가 로드합니다.
레지스트리는 그런 경로마다 `SHARED_ROOTS`에 등록된 소유자 하나(벤더가 그 경로를
문서화한 대상 어댑터), 같은 파일을 그 경로에 쓰는 공동 설치자, 그리고 벤더
문서에서 기본적으로 그 경로를 로드하는 리더를 기록하며, 그 사실을 보여 주는 벤더
페이지와 그 페이지를 가져온 날짜도 함께 기록합니다.

공동 설치자가 있는 경로는 홈 디렉터리 안의 사용자 수준 폴더로, 여러 설치가 같은
바이트로 씁니다. `Cursor`만 설치된 머신에는 `~/.agents/skills/`를 쓸 `Codex`가
없으므로, 그 폴더를 지명하는 각 설치가 폴더를 쓰고, 설치 원장은 그 폴더를 사용하는
설치 수를 셉니다. 기록상 소유자는 등록된 소유자가 그 폴더를 사용하는 동안에는 등록된
소유자이고, 그렇지 않으면 그 폴더를 사용하는 가장 오래된 설치입니다. 등록된 소유자가
제거되어도 아무것도 이동하지 않습니다. 제거는 다른 어떤 설치도 그 폴더를 사용하지
않을 때만 폴더를 삭제합니다([`uninstall`](/docs/cli-reference/uninstall#홈-디렉터리의-공유-폴더) 참조).
리더를 설치해도 그 폴더에는 아무 파일도 놓이지 않습니다. 소유자나 공동 설치자를
설치하면 모든 리더 앞에 Apothem 콘텐츠가 놓입니다.

| 경로 | 소유자 | 공동 설치자 | 리더 |
| --- | --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, GitHub Copilot, Windsurf, Zed | Gemini CLI, Kimi Code, Open-Claw, OpenCode, Qwen Code |
| `~/.config/apothem/rules/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | 없음 |
| `~/.config/apothem/templates/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | 없음 |
| `~/.claude/skills/` | Claude Code | 없음 | Cursor, OpenCode |
| `~/.claude/agents/` | Claude Code | 없음 | Cursor |
| `~/.codex/agents/` | Codex | 없음 | Cursor |
| `~/.claude/CLAUDE.md` | Claude Code | 없음 | OpenCode, Windsurf |
| `<project>/AGENTS.md` | Kimi Code | 없음 | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | 없음 | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | 없음 | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | 없음 | Zed |
| `<project>/.cursor/rules/apothem-rules.mdc` | Cursor | 없음 | Hermes, Windsurf |

`~/.config/apothem/rules/`와 `~/.config/apothem/templates/`는 Apothem 자체의
스킬과 지침 파일이 인용하는 파일을 담습니다. 다른 어떤 도구도 이를 로드하지
않으므로, 리더도 벤더 페이지도 없습니다. `CodeBuddy`, `Kiro`, `Trae`는 자체 스킬
폴더(`~/.codebuddy/skills/`, `~/.kiro/skills/`, `~/.trae/skills/`)도 씁니다. 그
도구만 그 폴더를 로드하므로 공유 루트가 아닙니다.

리더는 벤더 문서가 바로 그 경로의 기본 로드를 보여 주는 곳에만 나열됩니다.
리더가 일부 경우에만 어떤 경로를 로드하면, 레지스트리가 그 조건을 기록하고
설치 안내가 이를 반복합니다.
`Open-Claw`는 기본 상태 디렉터리에서만 `~/.agents/skills/`를
인덱싱합니다(`OPENCLAW_STATE_DIR`가 다른 곳을 가리키면 그 폴더를 건너뜁니다).
`OpenCode` 1은 `~/.config/opencode/AGENTS.md`가 없을 때만
`~/.claude/CLAUDE.md`를 로드하며, `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` 또는
`OPENCODE_DISABLE_CLAUDE_CODE=1`이 설정되면 건너뜁니다. `OpenCode` 2는 같은
`~/.config/opencode/` 구성을 읽지만 `CLAUDE.md` 폴백이 없으므로
`~/.claude/CLAUDE.md`를 로드하지 않습니다. `Codex`는 각 폴더에서
`AGENTS.override.md`와 `AGENTS.md` 중 첫 번째를 사용하므로,
`<project>/AGENTS.md`는 프로젝트에서 그 옆에 `AGENTS.override.md`가 없을 때만
로드합니다. `CodeBuddy`는 프로젝트에 `CODEBUDDY.md`가 없을 때만
`<project>/AGENTS.md`를 프로젝트 메모리로 사용합니다. `Zed`는 목록의 첫 번째
프로젝트 지침 파일만 로드합니다. 목록은 `.rules`, `.cursorrules`,
`.windsurfrules`, `.clinerules`, `.github/copilot-instructions.md`, `AGENT.md`,
`AGENTS.md`, `CLAUDE.md`, 그다음 `GEMINI.md`입니다. 따라서
`<project>/.github/copilot-instructions.md`, `<project>/AGENTS.md`,
`<project>/GEMINI.md`는 프로젝트에 목록에서 그 파일보다 앞선 파일이 하나도 없을
때만 로드합니다. `Zed` 설치는 목록의 첫 번째 파일인 `<project>/.rules`를
작성하므로, `Zed`는 설치된 프로젝트에서는 이 세 파일을 하나도 로드하지 않습니다.

`Hermes`는 세션당 한 종류의 프로젝트 컨텍스트만 로드합니다. 비어 있지 않은 파일이
있는 첫 번째 종류가 로드되며, 순서는 `.hermes.md` 또는 `HERMES.md`, `AGENTS.md`
체인(각 폴더에서 비어 있지 않은 `AGENTS.override.md`가 그 옆의 `AGENTS.md`를
대체합니다), `CLAUDE.md`, 그다음 `Cursor` 규칙입니다. 따라서
`<project>/AGENTS.md`는 프로젝트에 `.hermes.md`나 `HERMES.md`가 없고 그 옆에
`AGENTS.override.md`도 없을 때만 로드하고,
`<project>/.cursor/rules/apothem-rules.mdc`는 프로젝트에 `.hermes.md`,
`HERMES.md`, `AGENTS.override.md`, `AGENTS.md`, `CLAUDE.md`가 모두 없을 때만
로드합니다. `Hermes`는 `.hermes.md`와 `HERMES.md`를 시작한 폴더에서 git 루트까지
올라가며 찾고, `AGENTS.md` 체인은 git 루트에서 아래로 내려오며 읽으므로, 프로젝트
위쪽 폴더에 있는 그러한 파일도 대상에 포함됩니다. 비어 있는 파일은 대상에
포함되지 않습니다. 비어 있는 `.hermes.md`는 그 옆의 `HERMES.md`도 가리므로, 그
`HERMES.md`에 텍스트가 있어도 `Hermes`는 `AGENTS.md` 체인으로 넘어갑니다. 이
조건들은 프로젝트에서 시작한 세션에 적용됩니다. 프로젝트 위쪽 폴더에서 시작한
세션도, 프로젝트에 어떤 `.hermes.md`나 `HERMES.md`가 있든, 프로젝트의 파일을 처음
다룰 때 `<project>/AGENTS.md` 또는 그 옆의 비어 있지 않은 `AGENTS.override.md`를
로드할 수 있습니다. `Hermes`는 홈 폴더와 일부 컨테이너 폴더에서는 이를
건너뜁니다.

`Cursor` 문서는 `~/.codex/agents/`를 `Codex` 호환
폴더로 나열하지만 `Cursor`가 그곳에서 어떤 파일 형식을 파싱하는지는 밝히지 않으며,
`Codex` 설치는 TOML 파일을 쓰므로 `Cursor`가 그 도우미를 읽는지는 확인되지
않았습니다. `Cursor` 설치는 또한 도우미의 자체 `<project>/.cursor/agents/` 사본을
쓰며, 벤더의 우선순위는 이를 가져오는 폴더보다 위에 두므로, 설치된 프로젝트에서는
네이티브 사본이 `~/.claude/agents/`에서 온 사본보다 우선합니다.

`Windsurf`는 Devin의 구성 가져오기를 통해 다른 도구의 규칙 파일을 읽으며, 이
기능은 기본적으로 켜져 있습니다. Devin Desktop의 Local 에이전트는 Devin CLI와 같은
방식으로 파일을 찾습니다. 그래서 `~/.claude/CLAUDE.md`에서 `Claude Code` 설치가
쓰는 블록과, `Cursor` 설치가 쓰는 `<project>/.cursor/rules/apothem-rules.mdc`를
로드하며, 이 파일은 `alwaysApply: true` 프런트매터 덕분에 모든 세션에서 활성
상태로 유지됩니다. 이 가져오기는 프로젝트의 `CLAUDE.md`도 읽지만, 어떤 Apothem
설치도 이 파일을 쓰지 않습니다.

일부 도구는 의도적으로 `~/.agents/skills/`의 리더가 아닙니다.
`Antigravity`, `CodeBuddy`, `Kiro`, `Trae` 문서는 이 폴더를 기본으로 로드한다고
밝히지 않으며(`Trae`는 설정을 켠 후에만 프로젝트 `.agents/skills/` 폴더를
로드합니다), 그래서 `CodeBuddy`, `Kiro`, `Trae`는 자체 스킬 폴더를 받습니다.
`Hermes` 문서는 이 폴더를 `skills.external_dirs`의 예시 값으로만 언급합니다.
`GitHub Copilot`은 `~/.claude/agents/`의 리더가 아닙니다. VS Code 문서는 그 폴더를
`GitHub Copilot`이 실행하는 에이전트가 아니라 Anthropic Claude 에이전트용으로
나열합니다.

소유자가 공유 지침 파일에 쓰는 Apothem 블록은 어느 단일 도구도 자신의

`tests/unit/test_shared_roots.py`는 레지스트리 대상을
쓰는 어댑터가 정확히 그 소유자와 공동 설치자가 아닌 경우, 그리고 도구 간 지침
파일(`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `copilot-instructions.md`)처럼 이름이
붙은 레지스트리 대상에 선언된 소유자가 없는 경우에 실패합니다. 다만
`~/.codex/AGENTS.md`는 제외되며, 등록된 다른 하니스는 이 파일을 로드한다고
문서화하지 않습니다.

## 검증 훅

레지스트리는 다음 검사를 통해 동기화 상태를 유지합니다.

| 검사 | 목적 |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | 각 어댑터에 작성된 지 90일 이내이고, 벤더 URL을 하나 이상 인용하며, 기한이 지난 디스커버리 대상이 없는 규약 핀이 있는지 확인합니다. CI가 모든 풀 리퀘스트마다, 매주, 그리고 릴리스 전에 실행합니다. |
| `python scripts/dev/check_vendor_urls.py` | 핀과 하니스 템플릿이 인용하는 모든 벤더 URL을 가져와, 이동했거나 사라진 페이지가 있으면 실패합니다. 더 이상 해석되지 않는 호스트 이름이나 검증에 실패하는 인증서도 여기에 포함됩니다. 타임아웃, 거부되거나 재설정된 연결, 5xx 서버 오류는 도달 불가로 보고되며 검사를 실패시키지 않습니다. 어떤 서버도 가질 수 없는 플레이스홀더 주소로만 해석되는 호스트 이름에는 요청을 보내지 않습니다. 벤더의 네임 서버는 검사가 실행되는 지역에 대해 이런 주소를 반환할 수 있습니다. 그런 호스트는 라우팅 불가로 보고되고, 검사를 실패시키지 않으며, 해당 페이지는 직접 확인해야 합니다. 주간 규약 모니터가 이를 실행하고, 실행할 때마다 그런 호스트 각각에 대해 경고하며, 모니터가 생성하는 이슈에 해당 페이지를 나열합니다. |
| `python -m apothem.conformity.gate --all .` | 문서 및 구현 적합성 검사를 실행합니다. |
| `python -m pytest` | 레지스트리 픽스처 테스트와 어댑터 계약 테스트를 실행합니다. |
