> **모든 아티팩트 클래스의 YAML 프런트매터에 관한 정식 참조.** [`CLAUDE.md`](https://github.com/ahmed-g-gad/apothem/blob/main/CLAUDE.md) Conventions에 있는 요약은 인라인 선언이고, [`src/apothem/schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas)의 클래스별 JSON 스키마(`additionalProperties`가 알 수 없는 키를 거부함)는 기계가 읽을 수 있는 계약이며 어떤 불일치에서든 우선합니다. 이 페이지는 필수 키 색인이고, [`artifact-schema.mdx`](/docs/reference/artifact-schema)는 클래스별 템플릿과 상세 예시를 담습니다 — 둘 다 이 스키마들을 사람이 읽을 수 있게 투영한 문서입니다.

---

## 1. 프런트매터 블록 형태

모든 아티팩트는 맨 앞에 `---` 줄로 구분된 YAML 프런트매터를 둡니다. Markdown 계열 파일에서는 프런트매터가 파일의 첫 번째 콘텐츠이고, [`site/content/docs/reference/authorship-header.mdx`](/docs/reference/authorship-header)에 따른 정식 작성자 헤더 배너는 닫는 `---` 뒤에 옵니다.

커맨드 키는 `kebab-case`를 사용합니다. 스킬 키는 `kebab-case`를 사용하되, 소스 코퍼스가 쓰는 camelCase 표기인 `userInvocable`만 예외입니다(Claude Code 설치는 이를 `user-invocable`로 이름 바꿉니다). 규칙과 위임 작업자의 키는 섹션 2의 필수 키 표에 나열된 대로 camelCase입니다. 스칼라 값은 따옴표 없이 쓰거나 큰따옴표로 묶으며, 콜론, 해시 기호 또는 그 밖의 YAML에서 의미를 갖는 문자가 들어 있는 문자열 값은 따옴표로 묶습니다.

## 2. 클래스별 필수 필드

필수 키 집합은 아티팩트 클래스에 따라 다릅니다. 권위 있는 형태는 `scripts/dev/validate_ecosystem.py`와 `src/apothem/schemas/` 디렉터리 아래의 클래스별 JSON 스키마(아티팩트 클래스당 스키마 파일 하나)가 강제합니다.

```text
src/apothem/schemas/agent.schema.json
src/apothem/schemas/skill.schema.json
src/apothem/schemas/command.schema.json
src/apothem/schemas/output-style.schema.json
src/apothem/schemas/plan.schema.json
```

| 클래스 | 필수 키 |
|-------|---------------|
| `CLAUDE.md`(루트 구성) | `name`, `version`, `updated`, `description`, `scope`, `portability` |
| 규칙(`src/apothem/rules/*.md`) | `name`, `description`, `pathFilter`, `alwaysApply` |
| 명령(`src/apothem/commands/*.md`) | `name`, `version`, `updated`, `description`, `argument-hint`, `disable-model-invocation`, `portability`, `allowed-tools` |
| 위임 작업자(정식 디렉터리는 아래에 표시) | `name`, `version`, `updated`, `description`, `tools`, `disallowedTools`, `maxTurns`, `effort` |
| 스킬(`src/apothem/skills/*/SKILL.md`) | `name`, `version`, `updated`, `description`, `archetype`, `userInvocable`, `disable-model-invocation`, `allowed-tools`. Claude Code 설치와 플러그인은 `userInvocable`을 `user-invocable`로 이름을 바꾸며, 스키마는 두 표기 중 정확히 하나만 허용합니다 |
| 출력 스타일(`src/apothem/output-styles/*.md`) | `name`, `description`. 배포되는 모든 스타일은 Claude Code가 소프트웨어 엔지니어링 지침을 유지하도록 `keep-coding-instructions: true`도 설정합니다 |

[`src/apothem/schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas)의 클래스별 스키마는 타입, 형식, enum, 패턴 제한과 길이 제한을 포함한 전체 제약 집합을 담습니다. 스킬 또는 명령의 `description`은 최대 1,024자이며, 이는 [Agent Skills](https://agentskills.io/specification) 한도입니다.

## 3. 검증기

`scripts/dev/validate_ecosystem.py`는 아티팩트 트리를 순회하며 위의 필수 키 집합을 적용하고, 필수 필드가 누락된 아티팩트마다 `[FAIL]`을 보고합니다. `src/apothem/conformity/frontmatter_grep.py`의 쓰기 단위 `frontmatter-grep`은 PreToolUse Write/Edit 훅 경계에서 같은 형태를 강제합니다.
