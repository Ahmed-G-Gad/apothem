> **생태계 전반에 걸친 파일명, 식별자, 브랜치 이름 형태에 대한 정규 참조.** [`CLAUDE.md`](https://github.com/ahmed-g-gad/apothem/blob/main/CLAUDE.md) 규칙의 요약은 인라인 선언이며, 이 페이지는 다운스트림 기여자가 인용하는 독립 참조입니다.

---

## 1. 파일 시스템 이름

파일과 폴더는 기본적으로 **kebab-case**를 사용합니다. 식별자에는 공백, 밑줄, 카멜 케이스가 없습니다.

정규 대문자 예외는 모든 기여자가 처음 접할 때 인식하는 발행 표면 싱글톤 파일에 예약되어 있습니다. `CLAUDE.md`, `README.md`, `LICENSE`, `CHANGELOG.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, 그리고 플랜 스위트 싱글톤(`MASTER-PLAN.md`, `PROGRESS.md`, `PHASE.md`, `SKILL.md`, `VERSION`)입니다. 그 외 모든 파일은 kebab-case를 사용합니다.

## 2. frontmatter 키

커맨드 frontmatter 키는 `kebab-case`를 사용합니다(예: `argument-hint`, `disable-model-invocation`, `allowed-tools`). 스킬 키는 `kebab-case`를 사용하되, 소스 코퍼스가 쓰는 camelCase 표기인 `userInvocable`만 예외입니다. Claude Code 설치는 이를 `user-invocable`로 이름 바꿉니다. 규칙과 위임 작업자의 키는 camelCase입니다(예: `pathFilter`, `alwaysApply`, `maxTurns`, `disallowedTools`). [frontmatter 스키마](/docs/reference/frontmatter-schema)의 필수 키 표에 각 클래스의 키가 나열되어 있습니다.

## 3. 브랜치 이름

브랜치는 `<type>/<short-description>`를 따르며, 타입은 닫힌 집합 `{feat, fix, chore, docs, refactor, test, perf, ci, build, style, revert, release}`에서 가져옵니다. 설명은 kebab-case이며 50자 미만입니다.

## 4. 숫자 접두사

파일 시스템 경로의 숫자 접두사(`NN-`)는 순서를 전달하며, 순서가 본질적인 곳——단계 폴더, 하위 단계 폴더, 마이그레이션 스크립트, 그리고 시퀀스가 계약의 일부인 기타 아티팩트 클래스——에만 적용됩니다. 형제 시퀀스가 없는 루트 수준 싱글톤은 숫자 접두사를 갖지 않습니다. 접두사를 추가하면 존재하지 않는 순서 관계를 잘못 알리게 됩니다. 전체 규율은 [`src/apothem/rules/canonical-layout.md`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/rules/canonical-layout.md) §2.1에 있습니다.

## 5. 검증기

`src/apothem/conformity/naming_grep.py`의 naming-grep이 기계적 강제 실행 표면입니다. CI는 `make validate`를 통해 이를 호출합니다.
