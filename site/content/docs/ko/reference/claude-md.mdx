`CLAUDE.md`는 항상 로드되는 생태계 구성입니다. 호스트 하니스 런타임이
모든 상호작용에서 이를 로드하므로, 그 내용은 다른 모든 아티팩트가 확장하는
*기준 컨텍스트*입니다.

## 섹션

| 섹션 | 목적 |
|---------|---------|
| §1 계획 스위트 | 마스터 계획 스위트 템플릿과 여덟 개의 `/plan-<stage>` 명령을 명명 |
| §2 인지 정체성 및 소프트웨어 아키텍처 | 시니어 소프트웨어 아키텍트 역할과 창의적 자세를 선언 |
| §3 아티팩트 디렉터리 | 클래스별 디스크 루트(규칙, 명령, 스킬, 위임 워커 등) |
| §4 심각도 스케일 거버넌스 | 4계층 스케일링 렌즈(EXPLORING / PERSONAL_USE / SHARED / PUBLIC_LAUNCH) |
| §5 운영 지시 | 문제 해결, 전략적 발견, 커뮤니케이션 프레임워크 |
| §6 횡단 강제 사항 | CM-N 레지스트리(CM-1부터 CM-28까지) |
| §7 레지스트리 | 명령, 규칙, 위임 워커, 훅, 스킬, 진화, 빈 클래스의 하위 레지스트리 |

## 강제 사항 식별자 규약

세 가지 접두사가 서로 다른 의미를 담습니다:

- **CM-N** — 구성 강제 사항. 규칙 코호트
  (`src/apothem/rules/operational-mandates.md`와 명령별 규칙 파일들)에 정의됩니다.
- **TM-N** — 템플릿 강제 사항.
  `src/apothem/skills/plan-suite/master-template.md` §4에 정의됩니다.
- **CP-N** — 핵심 원칙. 동일한 템플릿 §6에 정의됩니다.

계획 스위트 템플릿은 정규 TM/CP 레지스트리입니다. `/plan` 파이프라인 단계는 해당
파일을 통해 상호 참조를 해석합니다.
