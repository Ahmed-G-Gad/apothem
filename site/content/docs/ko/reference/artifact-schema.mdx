**Apothem 생태계의 모든 아티팩트에 대한 클래스별 YAML 프런트매터 템플릿과 필수 필드.**

> **기준 출처.** 기계가 읽을 수 있고 게이트가 강제하는 계약은
> [`src/apothem/schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas)
> 아래의 클래스별 JSON 스키마(`agent.schema.json`, `command.schema.json`,
> `skill.schema.json`, …)이며, 각 스키마는 `additionalProperties`를 선언하므로
> 적합성 게이트가 알 수 없는 키를 거부합니다.
> 이 페이지와 [`frontmatter-schema.mdx`](/docs/reference/frontmatter-schema)는
> 이 스키마들을 사람이 읽을 수 있게 투영한 두 문서입니다. 이 페이지는 클래스별
> **템플릿과 상세 예시**를 담고, frontmatter-schema는 간결한 **필수 키 색인**을
> 담습니다. 페이지가 JSON 스키마와 어긋나는 경우에는 스키마가 우선합니다.

## 개요

Apothem 소스 트리(`src/apothem/` 아래와 루트 구성 표면)의 모든 아티팩트는
아티팩트 타입별 필수 필드와 선택 필드를 갖춘 YAML 프런트매터 블록(`---`
구분자 사이)을 포함해야 합니다. 이 문서는 각 타입의 정식 스키마를 정의합니다.

**공통 규칙:**

- 프런트매터는 YAML 1.2를 준수합니다
- 모든 문자열 값은 비어 있지 않은 한 큰따옴표를 사용합니다
- 필드 순서: 필수 필드를 먼저 두고, 선택 필드는 관련성에 따라 묶습니다
- 프런트매터의 주석은 뒤에 공백이 오는 `#`를 사용합니다: `# comment`
- 경로 값은 상대 경로여야 하며(앞에 `/` 없음), 크로스 플랫폼 호환성을 위해 슬래시(`/`)를 사용해야 합니다

**버전 관리 규약(버전이 매겨지는 아티팩트 클래스 — 명령, 헬퍼, 스킬, CLAUDE.md):**

- `version`은 **시맨틱** 버전(`MAJOR.MINOR.PATCH`)입니다. 스키마나 계약에 대한 호환성을 깨는 변경에는 MAJOR를, 호환성을 깨지 않는 추가형 변경(새 선택 필드, 추가 섹션, 추가 안티패턴)에는 MINOR를, 동작 변경이 없는 명확화, 서식 수정, 문서 전용 편집에는 PATCH를 올립니다.
- `updated`는 가장 최근 편집의 **ISO 8601 날짜**(`YYYY-MM-DD`)입니다. 이 값은 `version`을 올릴 때마다 반드시 함께 바뀌어야 하며, 버전을 올리지 않는 링크 갱신에서는 독립적으로 업데이트할 수 있습니다.
- 새 아티팩트는 `v0.Y.Z`에서 시작합니다. `vX.Y.Z`로의 승격은 아티팩트의 계약이 공개적 약속이 될 만큼 안정적임을 나타냅니다.

## 스키마: 규칙

**경로 패턴:** `src/apothem/rules/*.md`

**목적:** 행동 맨데이트와 운영 지침.

### 필수 필드

```yaml
---
name: "kebab-case-identifier"
description: "One-line description"
pathFilter: "**/*.py, **/*.toml"
alwaysApply: true | false
---
```

| 필드 | 타입 | 목적 | 예시 |
| ----- | ---- | ------- | ------- |
| `name` | string | 기계가 읽을 수 있는 식별자 | `"operational-mandates"` |
| `description` | string | 레지스트리용 한 줄 설명 | `"Operational mandates CM-1–10"` |
| `pathFilter` | string | 경로 필터 규칙의 범위를 정하는 쉼표로 구분된 glob 목록. 상시 적용 규칙에서는 빈 문자열(`""`) | `"**/*.py, **/*.toml"` |
| `alwaysApply` | boolean | 상시 적용 규칙(어디서나 로드됨)은 `true`, 경로 필터 규칙(`pathFilter`가 일치할 때 로드됨)은 `false` | `true` |

### 선택 필드

규칙에는 선택 프런트매터 필드가 없으며, 다른 아티팩트 클래스와 달리 `version` / `updated` / `scope` / `portability` 필드도 없습니다. 위의 네 가지 필수 필드가 `frontmatter_grep`이 강제하는 규칙 프런트매터 계약의 전부입니다.

### 예시

```yaml
---
name: "operational-mandates"
description: "Behavioral definitions for CM-1 through CM-10: violation indicators and recovery actions"
pathFilter: ""
alwaysApply: true
---

# Rule: Operational Mandates
...
```

## 스키마: 명령

**경로 패턴:** `src/apothem/commands/*.md`

**목적:** 슬래시 명령 정의(`/plan-execute`, `/freshify` 등).

### 필수 필드

```yaml
---
name: "command-name"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "What this command does"
argument-hint: "[argument-pattern]"
disable-model-invocation: true | false
portability: "universal"
allowed-tools: "Read, Glob, Grep"
---
```

| 필드 | 타입 | 목적 | 예시 |
| ----- | ---- | ------- | ------- |
| `name` | string | 명령 이름(앞의 `/` 제외) | `"plan-execute"` |
| `version` | string | 시맨틱 버전 | `"X.Y.Z"` |
| `updated` | string (ISO 8601) | 최종 업데이트 날짜 | `"2026-04-20"` |
| `description` | string | 짧은 설명 | `"Executes a phase with quality gates"` |
| `argument-hint` | string | 사용 패턴, 없으면 `"[args...]"` | `"[path/to/plan] [phase-id]"` |
| `disable-model-invocation` | boolean | true이면 운영자만 명령을 시작하며, 모델은 절대 스스로 호출하지 않음 | `true` |
| `portability` | string | 하니스 어댑터 전반의 이식성 분류 | `"universal"` |
| `allowed-tools` | string | 명령이 실행되는 동안 사전 승인되는 도구: 읽기 전용 도구, 그리고 부작용이 있는 도구는 `Bash(git log *)` 같은 범위 지정 규칙으로만 허용. 단독 `"*"` 와일드카드는 거부됨 | `"Read, Glob, Grep"` |

### 선택 필드

명령에는 선택 프런트매터 필드가 없습니다. 위의 여덟 가지 필수 필드가 `command.schema.json`(`additionalProperties: false`)이 강제하는 명령 프런트매터 계약의 전부입니다.

### 예시

```yaml
---
name: "plan-execute"
version: "X.Y.Z"
updated: "2026-04-20"
description: "Executes a specific phase from a Master Plan Suite with conformity checking and quality gates"
argument-hint: "[path/to/plan-suite/] [phase-id] [--dry-run]"
disable-model-invocation: true
portability: "universal"
allowed-tools: "Read, Glob, Grep"
---

# /plan-execute — Execute a Specific Phase
...
```

## 스키마: 훅

**경로 패턴:** `settings.json`의 `hooks` 블록과 `src/apothem/hooks/` 아래의
Python 구현.

**목적:** 호스트가 명확히 정의된 라이프사이클 지점에서 호출하는 이벤트 트리거
검증기와 상태 관리 핸들러를 선언합니다.

### 설정 파일 스키마

`hooks` 최상위 키는 이벤트 이름을 매처 블록 배열에 매핑합니다.

```json
"hooks": {
  "<EventName>": [
    {
      "matcher": "<pattern>",
      "hooks": [
        {
          "type": "command",
          "command": "${PYTHON_BIN}",
          "args": ["${HARNESS_ROOT}/.apothem/support/hooks/dispatch.py", "<EventName>", "<message-name>"],
          "timeout": <seconds>,
          "statusMessage": "<short human-readable label>"
        }
      ]
    }
  ]
}
```

`-m apothem.hooks.dispatch` 형식은 `PYTHONPATH=src`를 설정한 소스 체크아웃에서 개발할 때 사용합니다.

| 필드 | 타입 | 목적 | 예시 |
| ----- | ---- | ------- | ------- |
| `matcher` | string | 도구 이름 패턴(도구와 무관한 이벤트에는 `"*"`) | `"Write"` |
| `hooks[].type` | 리터럴 `"command"` | 현재 지원되는 유일한 훅 핸들러 유형 | `"command"` |
| `hooks[].command` | string | 실행 가능한 명령. Apothem은 설치 시 해석되는 `${PYTHON_BIN}` 자리표시자를 사용 | `"${PYTHON_BIN}"` |
| `hooks[].args` | 문자열 배열 | exec 형식 인수: `${HARNESS_ROOT}/.apothem/support/` 아래의 스크립트 경로, 그다음 그 인수들 | `["${HARNESS_ROOT}/.apothem/support/hooks/dispatch.py", "SessionStart"]` |
| `hooks[].timeout` | 정수(초) | 호스트가 훅을 종료하기 전까지의 최대 실행 시간 | `30` |
| `hooks[].statusMessage` | string | 호스트 UI에 표시되는 짧은 레이블 | `"Session start"` |

### 필수 이벤트

Claude Code 템플릿은 SessionStart, PreToolUse, PostToolUse, Stop 이벤트를 등록합니다. PreCompact와 PostCompact는 Claude Code에 등록되지 않으며([훅 참조](/docs/reference/hooks)), `scripts/dev/validate_hooks.py`는 각각을 누락된 것으로 경고로 보고합니다. 아래 표는 `validate_hooks.py`가 확인하는 다섯 개 이벤트를 나열합니다:

> **타임아웃 값은 정식 훅 이벤트 예산을 그대로 따릅니다** — 아래 표는 독자의
> 편의를 위해 이를 재현한 것이며, 정식 출처가 우선합니다.

| 이벤트 | 일반적인 타임아웃 | 목적 |
| ----- | --------------- | ------- |
| `SessionStart` | 30초 | 메모리 읽기, 플랜 상태 확인, 준비 상태 보고 |
| `PreToolUse` | 10초 | 콘텐츠 격리 정책 + 프런트매터에 대한 쓰기 검증 |
| `PreCompact` | 30초 | 컨텍스트 압축 전에 상태가 외부화되었는지 확인 |
| `PostCompact` | 30초 | 컨텍스트 압축 후 작업 상태 복원 |
| `Stop` | 60초 | 세션 종료 외부화 — 재개 상태, 출력, 결정 |

`dispatch.py`는 향후 호환성을 위해 이벤트 화이트리스트에서
`UserPromptSubmit`과 `Notification`도 받아들입니다. 둘 다 배포되는 템플릿에는
연결되어 있지 않습니다. 활성화하려면 같은 exec 형식 패턴으로 매처 블록을
추가하세요.

### Python 계층

모든 훅 명령은 같은 Python 디스패처를 거칩니다.

| 파일 | 역할 |
| ---- | ---- |
| `src/apothem/hooks/dispatch.py` | `SessionStart`는 `session_start_bootstrap.main()`으로, 화이트리스트에 있는 다른 모든 이벤트는 `emit_hook_context.main()`으로 라우팅합니다. 항상 0으로 종료합니다. |
| `src/apothem/hooks/session_start_bootstrap.py` | 세션 시작 훅 스크립트 — 메모리와 플랜 스위트 요약 컨텍스트를 내보냅니다. |
| `src/apothem/hooks/emit_hook_context.py` | 기본 훅 이미터 — 등록된 `--context-file` 페이로드를 담은 유효한 엔벨로프를 씁니다. |
| `src/apothem/hooks/messages/*.md` | `--context-file`이 참조하는 정적 컨텍스트 페이로드. |

### 검증

`scripts/dev/validate_hooks.py`는 훅 계약을 강제합니다.

- `settings.json`이 JSON으로 파싱되고 모든 필수 이벤트를 선언합니다.
- 세 Python 스크립트가 모두 존재하고 유효한 Python으로 파싱됩니다.
- `--context-file` 인수가 참조하는 모든 메시지 파일이 존재합니다.
- 하드코딩된 절대 사용자 경로(`C:\Users\...` 등)가 `src/apothem/hooks/**.py`에 나타나지 않습니다.
- `src/apothem/hooks/`와 `scripts/` 아래의 셸 아티팩트는 승인된 로케이터 / 부트스트랩 스텁으로 제한됩니다.

## 스키마: CLAUDE.md

**경로:** `CLAUDE.md`(루트)

**목적:** 전역 생태계 구성 인덱스.

### 필수 YAML 프런트매터

```yaml
---
name: "CLAUDE"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "Global Claude Code ecosystem configuration and mandate index"
scope: "always-on"
portability: "universal"
---
```

### 필수 섹션(순서대로)

1. **§1 플랜 스위트** — 템플릿 위치 참조

## 검증 체크리스트

모든 아티팩트는 다음 검사를 충족해야 합니다.

### 프런트매터 검증

- [ ] YAML이 구문상 유효함(파싱 오류 없음)
- [ ] 아티팩트 타입의 모든 필수 필드가 있음
- [ ] `name`이 kebab-case 규약을 따름
- [ ] `version`이 시맨틱 버전임(`MAJOR.MINOR.PATCH`)
- [ ] `updated`가 ISO 8601 날짜 형식임(`YYYY-MM-DD`)
- [ ] `description`이 비어 있지 않은 한 줄 문자열임
- [ ] 선택 필드가 예상되는 enum 값과 일치함(해당하는 경우)
- [ ] 필드 이름에 오타가 없음(스키마의 정식 이름 사용)
- [ ] 불필요한 공백이나 서식 문제가 없음

### 콘텐츠 검증

- [ ] 콘텐츠가 닫는 `---` 바로 다음 새 줄에서 시작함
- [ ] 플랜 내부 참조가 없음(CM-7 준수)
- [ ] 상호 참조가 해석됨(다른 아티팩트를 나열하는 경우)
- [ ] 링크가 슬래시를 쓰는 상대 경로를 사용함

### 이식성 검증

- [ ] 하드코딩된 절대 경로가 없음(상대 경로 사용)
- [ ] universal 범위 아티팩트에 Windows 전용 구문이 없음
- [ ] 경로 구분자로 슬래시를 사용함
- [ ] 환경 변수가 플랫폼 독립적 형식을 사용함(`${VAR}` 또는 도구 네이티브)

## 참고

- **보안으로서의 일관성:** 정식 프런트매터는 자동화된 검증, 도구화, 아티팩트 간
  검증을 가능하게 합니다. 편차는 빠르게 누적됩니다.
- **이식성 선언:** 모든 아티팩트가 universal일 수는 없습니다. 제약을
  명시적으로 선언하세요 — 드러나지 않는 버그를 배포하는 것보다 주의 사항을
  문서화하는 편이 낫습니다.
- **이름에는 kebab-case:** URL, 스크립트, 명령줄 맥락에서 쓰기 쉽습니다.
  이름에는 공백, 밑줄, camelCase를 피하세요.
- **버전 올림 위생:** 동작을 바꾸는 모든 편집은 `version`과 `updated`를 함께 올려야 합니다. 순수한 서식 또는 오타 수정은 PATCH를, 새 선택 섹션이나 안티패턴은 MINOR를, 구조 재편이나 계약 변경은 MAJOR를 올립니다.
