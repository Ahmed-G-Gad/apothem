`apothem` CLI는 공유 프로필과 하니스 어댑터를 관리하는 주된 운영자
인터페이스입니다.

## 전역 플래그

| 플래그 | 설명 |
|------|-------------|
| `--version` | Apothem 버전을 출력하고 종료합니다 |
| `--help` | 명령의 도움말을 출력합니다 |

## 하위 명령

### `apothem install`

공유 프로필에서 하니스 어댑터를 설치합니다.

```bash
apothem install --harness <name|all> [--profile PATH] [--project PATH] [--dry-run] [--clean|--fresh] [--yes]
```

| 옵션 | 설명 |
|--------|-------------|
| `--harness <name>` | 하니스 어댑터 이름(아래의 정규 값 참조). 필수입니다. |
| `--profile PATH` | 공유 프로필 YAML의 경로입니다. 기본값은 `~/.config/apothem/profile.yaml`입니다. |
| `--project PATH` | 프로젝트 범위 하니스를 위한 프로젝트 루트입니다. |
| `--dry-run` | 파일을 쓰지 않고 설치를 미리 봅니다. |
| `--clean`, `--fresh` | 옵트인 클린 슬레이트: 설치하기 전에 이전 설치 상태(`~/.claude`, `~/.codex`, `~/.agents`, `~/.config/apothem`)를 백업하고 제거합니다. |
| `--yes` | 클린 슬레이트 제거 중 대상별 확인을 건너뜁니다(비대화형 `--clean` 실행에 필요). |

정규 `--harness` 값:

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

레지스트리 전체 집합을 선택하려면 `--harness all --project <path>`를 사용하세요.
프로필의 `exclude_harnesses` 목록은 install/update 배치 선택 중에
존중됩니다.

### `apothem update`

현재 공유 프로필에서 하니스 어댑터의 네이티브 구성을 다시 도출합니다.

```bash
apothem update --harness <name|all> [--profile PATH] [--project PATH] [--dry-run]
```

| 옵션 | 설명 |
|--------|-------------|
| `--harness <name>` | 하니스 어댑터 이름. 필수입니다. |
| `--profile PATH` | 공유 프로필 YAML의 경로입니다. |
| `--project PATH` | 프로젝트 범위 하니스를 위한 프로젝트 루트입니다. |
| `--dry-run` | 파일을 쓰지 않고 업데이트를 미리 봅니다. |

`update`는 하니스 출력을 다시 머티리얼라이즈합니다. Apothem CLI 패키지는
업데이트하지 않습니다. 패키지 업그레이드에는 Apothem을 설치한 패키지 관리자를
사용하세요.

### `apothem uninstall`

하니스 어댑터의 네이티브 구성을 제거합니다.

```bash
apothem uninstall --harness <name|all> [--project PATH] [--yes]
```

| 옵션 | 설명 |
|--------|-------------|
| `--harness <name>` | 하니스 어댑터 이름. 필수입니다. |
| `--project PATH` | 프로젝트 범위 하니스를 위한 프로젝트 루트입니다. |
| `--yes` | 확인 프롬프트를 건너뜁니다. |

### `apothem verify`

하니스 어댑터의 관리 대상이 존재하고 유효한지 검증합니다.

```bash
apothem verify --harness <name|all> [--profile PATH] [--project PATH]
```

| 옵션 | 설명 |
|--------|-------------|
| `--harness <name>` | 하니스 어댑터 이름 또는 `all`. 필수입니다. |
| `--profile PATH` | 충실도 검사의 기준이 되는 공유 프로필 YAML입니다. 이 옵션이 없으면 검사는 순전히 구조적입니다. |
| `--project PATH` | 프로젝트 범위 하니스를 위한 프로젝트 루트입니다. |

`--profile`이 없으면 검사는 구조적입니다. 모든 관리 대상이 존재하고 유효해야
합니다. `--profile`을 지정하면 충실도도 요구하므로, 존재하지만 그 프로필에서
드리프트한 설치는 verify에 실패합니다 — 특정 프로필이 충실하게 설치되었는지
확인하려면 이 옵션을 사용하세요.

종료 코드는 하니스가 검증되었을 때(그리고 `--profile`을 지정한 경우 그 프로필에
충실할 때) `0`이고, 대상이 없거나 유효하지 않을 때, 또는 `--profile`이
주어졌고 설치가 드리프트했을 때 `1`입니다.

### `apothem status`

등록된 모든 하니스의 설치, 검증, 드리프트 상태를 보고합니다.

```bash
apothem status [--profile PATH] [--project PATH]
```

| 옵션 | 설명 |
|--------|-------------|
| `--profile PATH` | 드리프트 기준선으로 사용할 공유 프로필입니다. 기본 프로필을 읽을 수 없으면 스윕을 중단하지 않고 드리프트를 `unknown`으로 낮춥니다. |
| `--project PATH` | 프로젝트 범위 하니스를 위한 프로젝트 루트입니다. 이 옵션이 없으면 그런 하니스는 `needs-project`를 보고합니다. |

각 행은 `installed` 플래그와 `verified` 플래그를 짝지으며, 두 플래그가
결합되어 드리프트 상태가 됩니다.

| 상태 | 의미 |
|-------|---------|
| `absent` | Apothem이 이 하니스에 설치하지 않았습니다. |
| `in-sync` | 설치되어 있고 프로필 기준선과 일치합니다. |
| `drift` | 설치되어 있지만 더 이상 일치하지 않습니다 — `apothem update`로 바로잡으세요. |
| `unknown` | 설치되어 있지만 기준선 프로필을 읽을 수 없었습니다. |

`installed`는 "이 하니스가 머신에 있는가?"가 아니라 "Apothem이 여기에
설치했는가?"에 답합니다. 이 플래그는 Apothem 자체의 아티팩트 — 지침 앵커 안의
관리 블록과 Apothem 소유 `.apothem/` 하위 트리 아래의 콘텐츠 — 를 기준으로
하며, 하니스가 스스로 쓰는 벤더 소유 파일을 기준으로 삼는 일은 절대 없습니다.
구성 디렉터리는 존재하지만 Apothem이 한 번도 건드리지 않은 하니스는 `absent`를
보고하고, 제거된 하니스는 비워진 디렉터리가 남아 있더라도 `absent`를
보고합니다.

### `apothem profile`

공유 Apothem 프로필을 관리합니다.

```bash
apothem profile show [--profile PATH]
apothem profile init [--profile PATH] [--force]
apothem profile set <key> <value> [--profile PATH]
apothem profile edit [--profile PATH]
```

| 하위 명령 | 설명 |
|------------|-------------|
| `profile init` | 스키마에 맞는 최소 프로필 스캐폴드를 생성합니다. |
| `profile show` | 해석된 프로필을 JSON으로 stdout에 출력합니다. `--json`을 지정하면 문서는 `schema_version`으로 시작합니다. |
| `profile set <key> <value>` | 프로필 필드를 설정합니다. 값은 리터럴 문자열로 저장됩니다. 맨 단어는 강제 변환되지 않으므로 `no`는 `"no"`로, `1.0`은 문자열로 남습니다. 단, `true`/`false`와 명시적인 `[...]` / `{...}` 목록 및 맵 입력은 예외입니다. 조립된 프로필은 쓰기 전에 스키마 검증을 거칩니다. |
| `profile edit` | `$EDITOR`에서 프로필을 엽니다(플랫폼 기본값으로 대체됩니다). |

`--profile PATH` 옵션은 각 하위 명령이 대체 프로필 파일을 가리키게 합니다.
기본값은 `~/.config/apothem/profile.yaml`입니다.

### `apothem harnesses`

등록된 하니스 어댑터를 나열하고 검사합니다.

```bash
apothem harnesses list
apothem harnesses show <name>
```

| 하위 명령 | 설명 |
|------------|-------------|
| `harnesses list` | 등록된 모든 어댑터를 설치 상태 플래그 및 출력 경로와 함께 표로 출력합니다. |
| `harnesses show <name>` | 한 어댑터의 이름, 설치 상태, 출력 경로를 출력합니다. |

### `apothem doctor`

Apothem 설치에 대한 시스템 진단을 실행합니다.

```bash
apothem doctor
```

Apothem 버전, Python 인터프리터, 플랫폼, 해석된 프로필 경로, 하니스별 설치 상태 표를 출력합니다. 어느 점검이든 실패하면 종료 코드는 `1`입니다. 예를 들면 잘못된 프로필, 설치되었지만 검증되지 않는 하니스, 시작할 수 없는 등록된 훅 명령, 로드하거나 프로브할 수 없는 어댑터, 읽을 수 없는 원장이 해당합니다. 설치되지 않은 하니스는 보고되지만 실패로 간주되지 않으며, 참고용 메모는 종료 코드를 바꾸지 않습니다.
