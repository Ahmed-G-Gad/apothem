> **다운스트림 기여자를 위한 정식 규범 참조.** 이 문서는 프로젝트 명세의 작성자 표기 및 파일 헤더 섹션(Spec §0.5 + §4.6)을 미러링합니다. 게시된 저장소와 함께 배포되는 독립형 참조입니다. 아키텍처 근거는 [ADR-0002](/docs/reference/authorship-header)에 기록되어 있습니다.

---

## 1. 정식 헤더 줄

생태계의 해당되는 모든 파일은 그 파일 타입 계열의 주석 구문으로 작성된 정식 SPDX 라이선스 식별자 한 줄로 시작해야 합니다(MUST). 그 앞에 올 수 있는 것은 셔뱅, 그리고 Markdown 파일에서는 YAML 프런트매터뿐입니다(§5). 이 줄은 파일의 기계가 읽을 수 있는 라이선스 마커입니다. 면제되지 않는 파일에서 이 줄의 존재는 협상할 수 없으며, 내용은 파일마다 즉흥적으로 쓰지 않고 단일 진실 공급원이 정합니다. 전체 저작권 문서는 저장소 루트의 [`LICENSE`](https://github.com/ahmed-g-gad/apothem/blob/main/LICENSE) 파일에 한 번만 있으며, 모든 소스 파일에 중복해서 넣지 않습니다.

### 1.1 정보 내용(불변)

정식 내용은 정확히 한 줄입니다.

1. `SPDX-License-Identifier: MIT` — FSFE가 관리하는 [REUSE 명세](https://reuse.software/spec/)에 따른 기계가 읽을 수 있는 라이선스 마커로, SPDX 툴체인(`reuse lint`, `scancode`), Linux 커널 도구, 다운스트림 라이선스 스캐너가 모호함 없이 파싱합니다. 시각적 테두리가 없고, 파일별 저작권, 웹사이트, 이메일, GitHub 줄도 없습니다 — 파일별 출처 정보는 설계상 SPDX 한 줄입니다(§4 참조).

### 1.2 참조 형식(`#` 주석 계열)

[`src/apothem/schemas/authorship-header.txt`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas/authorship-header.txt)에 있는 정식 텍스트(여기서는 `#` 주석 구문 형태로 적음)가 진실 공급원입니다.

```text
# SPDX-License-Identifier: MIT
```

이 텍스트가 **유일한** 권위 있는 출처입니다. `file-header` 검증기(§8)는 이 바이트 단위로 정확한 픽스처를 기준으로 실행됩니다. 파일의 헤더 줄과 이 픽스처 사이의 모든 차이(§2에 따른 구문 치환을 적용한 뒤)는 CI 실패입니다.

## 2. 파일 타입별 변형(바이트 단위로 정확)

줄의 *정보 내용*은 변하지 않으며, 파일 타입마다 달라지는 것은 *주석 구문*뿐입니다. 파일 타입별 변형 전체 표는 다음과 같습니다.

| 파일 타입 계열 | 주석 구문 | 변형 렌더링 |
|---|---|---|
| `#` 계열 — `.sh`, `.bash`, `.zsh`, `.py`, `.rb`, `.pl`, `.ps1`, `.yml`, `.yaml`, `.toml`, `.cff`, `.cfg`, `.gitignore`, `.gitattributes`, `.editorconfig`, `.shellcheckrc`, `.env.example`, `Makefile`, `Dockerfile`, `Procfile`, `CODEOWNERS`, `PKGBUILD`, `scripts/apothem` 같은 확장자 없는 셸 진입점 | `#` 줄 주석 | `# SPDX-License-Identifier: MIT` |
| `//` 계열 — `.js`, `.jsx`, `.mjs`, `.cjs`, `.ts`, `.tsx`, `.go`, `.rs`, `.java`, `.kt`, `.swift`, `.cs`, `.scala`, `.dart`, `.jsonc` | `//` 줄 주석 | `// SPDX-License-Identifier: MIT` |
| 블록 주석 계열 — `.html`, `.htm`, `.md`, `.markdown`, `.xml`, `.vue`(템플릿 영역), `.php`(템플릿 영역) | `<!-- ... -->` | `<!-- SPDX-License-Identifier: MIT -->` |
| MDX (`.mdx`) | `{/* ... */}` (JSX 표현식 주석) | `{/* SPDX-License-Identifier: MIT */}` |
| C 블록 계열 — `.c`, `.cc`, `.cpp`, `.h`, `.hpp`, `.css`, `.scss`, `.less` (`/* */`) | `/* ... */` | `/* SPDX-License-Identifier: MIT */` |
| `;` 계열 — `.ini`, 일부 `.lisp`/`.scm` | `;` 줄 주석 | `; SPDX-License-Identifier: MIT` |
| `--` 계열 — `.sql`, `.lua`, `.hs`, `.elm`, `.ada` | `--` 줄 주석 | `-- SPDX-License-Identifier: MIT` |
| 잠금 파일 / 생성된 파일 / JSON | 없음 / 해당 없음 | **면제.** §3 예외 목록 참조. |

**Markdown 변형(정식 렌더링):**

```markdown
<!-- SPDX-License-Identifier: MIT -->
```

HTML 주석(또는 MDX `{/* */}`) 래퍼는 보이지 않게 렌더링되므로, 렌더링된 화면은 깔끔하게 유지되면서도 소스 안의 라이선스 마커는 모든 파일 타입에서 기계가 읽을 수 있는 상태로 남습니다.

## 3. 예외 목록(범주 전체 면제)

다음 클래스는 SPDX 헤더 줄에서 **면제**됩니다. `file-header` 검증기의 적용 가능성 검사는 이들에 대해 `not-applicable`을 반환합니다.

- **`LICENSE`** — 그 자체가 법적 문서이며, `license-author-consistency` 검증기가 존재를 확인하는 권위 있는 저작권 줄을 담고 있습니다.
- **`*.svg` 에셋** — XML 주석은 줄 주석 마커로 쓰기에 취약하므로, SVG의 출처 정보는 에셋 README와 생성된 래스터 출력이 담습니다.
- **JSON 파일(`.json`)** — JSON에는 주석 구문이 없습니다. JSON 구성에 저작자 표기가 필요하면 형제 파일 `<file>.NOTICE.md`를 둡니다.
- **잠금 파일** — `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `Pipfile.lock`, `poetry.lock`, `go.sum` 등(기계가 관리).
- **생성된 파일** — `# Generated by ...` 또는 `// Generated by ...` 마커가 있는 모든 것, 또는 `.gitattributes`의 `linguist-generated=true`와 일치하는 모든 것.
- **벤더링된 서드파티 콘텐츠** — `vendor/`, `third_party/`, `node_modules/` 아래의 파일. 이들은 업스트림 자체의 라이선스/고지를 담고 있으며, 업스트림의 저작자 표기 위에 우리 마커를 주입하는 것은 라이선스 위반입니다.
- **`.audit/` 파일** — gitignore된 임시 산출물이며, 게시되는 트리의 범위 밖입니다.
- **플랜 파일(`<project-root>/.apothem/plans/**`, 그리고 레거시 `<project-root>/.plans/**`)** — gitignore된 임시 산출물이며, 출처 정보는 플랜의 프런트매터가 담습니다([`plans-discipline.md`](/docs/reference/plans-discipline) §3 참조).
- **빈 마커** — `.keep`, `.gitkeep` 등(의미상 0바이트).
- 모든 종류의 **바이너리 파일**.

예외 목록 자체는 [`src/apothem/schemas/header-exceptions.txt`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas/header-exceptions.txt)에 정규식/glob 목록으로 인코딩되어 있으며, 검증기의 적용 가능성 검사에 입력됩니다. 수정하려면 구조화된 질의와 새 ADR이 필요합니다.

## 4. 라이선스와의 상호작용

SPDX 줄은 프로젝트의 라이선스를 기계가 읽을 수 있게 선언하고, LICENSE 파일은 이를 권위 있게 선언합니다.

- **`SPDX-License-Identifier: MIT`** — [REUSE 명세](https://reuse.software/spec/)와 SPDX 표준에 따른 기계가 읽을 수 있는 라이선스 마커. 자동화된 라이선스 스캐너가 이 줄을 직접 파싱하며, SPDX 표현식 구문은 `reuse lint`, scancode-toolkit, FOSSology, Linux 커널 라이선스 도구와 서로 호환됩니다.

{/* REUSE-IgnoreEnd */}
- **저장소 루트 [`LICENSE`](https://github.com/ahmed-g-gad/apothem/blob/main/LICENSE)** — 전체 MIT 조건과 저작권자를 담은 권위 있는 법적 문서. 저작권 표기의 유일한 자리입니다. 파일별 헤더는 모든 파일에서 저작권을 다시 적는 대신, 공유된 SPDX 식별자를 통해 암묵적으로 이 문서를 참조합니다.

**한 줄 형식.** 파일별 출처 정보는 SPDX 한 줄이며, 저작권 문서는 루트 LICENSE에 한 번만 있습니다. 테두리가 있는 여러 줄 배너 상자(괘선 프레임으로 감싼 저작권, 웹사이트, 이메일, 연락처 줄)는 검증기가 거부합니다. 이런 상자는 기계가 읽을 수 있는 라이선스 마커가 REUSE/SPDX/SBOM 도구에 이미 제공하는 것 외에는 아무것도 더하지 않으면서 연락처와 저작권 메타데이터를 모든 파일에 중복시키기 때문입니다. `src/apothem/schemas/authorship-header.txt`의 바이트 단위로 정확한 픽스처가 한 줄 형식을 담고 있으며, 검증기는 이 픽스처를 기준으로 실행됩니다.

**상호 참조.** LICENSE 파일(MIT) — 충돌이 있으면 법적 문서가 우선합니다. ADR-0006은 배너 범위 축소를 비준한 근거를 문서화합니다.

## 5. 삽입 위치

- SPDX 줄은 파일의 **첫 번째 콘텐츠**이며, 예외는 두 가지입니다. 셔뱅 줄(`#!/usr/bin/env bash`, `#!/usr/bin/env python3` 등)은 항상 1번째 줄에 남고, SPDX 줄은 2번째 줄에서 시작합니다. YAML 프런트매터가 있는 Markdown / MDX 파일에서는 프런트매터가 먼저 옵니다(다음 항목).
- YAML 프런트매터가 있는 Markdown / MDX 파일에서는 도구가 파싱할 수 있도록 프런트매터가 바이트 0에 그대로 있고, SPDX 주석은 닫는 `---` 뒤에 오며, 그다음에 본문이 오는데 H1이 있는 파일에서는 본문이 H1로 시작합니다. `scripts/inject-header.py`가 주석을 이 위치에 둡니다.
- 빈 줄 하나가 SPDX 줄과 다음 콘텐츠(H1, 본문 등)를 구분합니다.

## 6. 헤더 가시성 정책

특히 Markdown 파일에서 SPDX 줄은 **기본적으로 보이지 않으며**, `<!-- ... -->`(MDX에서는 `{/* */}`)로 감싸 소스에서만 보입니다. README, CONTRIBUTING, CLAUDE.md, 지원되는 하니스의 지침 파일, 스킬 SKILL.md, 명령 본문, 출력 스타일, 문서 페이지에는 이 정책이 맞습니다. **보이는** 렌더링(출력 맨 위에 SPDX 줄을 일반 텍스트 또는 펜스 블록으로 두는 방식)은 출처 정보를 바로 읽을 수 있다는 이점이 있는 독립형 참조 문서에 허용됩니다. 정책은 `src/apothem/schemas/header-visibility.yaml`에서 파일 클래스별로 정하며(기본값은 *보이지 않음*), 그 줄 바로 뒤에 파일 범위 재정의 마커 `<!-- header-visibility: visible -->`를 둘 수 있습니다.

## 7. 인젝터 — `scripts/inject-header.{sh,py}`

다음을 수행하는 결정적 CLI입니다.

- 하나 이상의 파일 경로(또는 glob)를 받습니다.
- 예외 목록(§3)으로 적용 가능성을 판단합니다.
- 기존 헤더 상태(정식 / 잘못된 형식 / 없음)를 감지하고, 발견한 비정식 배너 블록은 제거하여 다시 실행해도 멱등이 되게 합니다.
- 파일 타입별로 올바른 SPDX 변형(§2)을 렌더링합니다.
- 셔뱅과 프런트매터를 존중하면서 올바른 위치(§5)에 삽입합니다.
- 세 가지 모드로 동작합니다. `fix-in-place`(씀), `emit-patch`(통합 diff를 출력), `check`(차이가 있으면 0이 아닌 코드로 종료 — CI에서 사용).
- 멱등: 두 번 실행해도 아무 변화가 없습니다.

인젝터는 `make headers-fix` 타깃이 호출하며, 이 타깃은 `scripts/inject-header.py --mode fix-in-place`를 실행합니다.

## 8. 검증기 — `file-header`(CI)

[`src/apothem/conformity/file_header_grep.py`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/conformity/file_header_grep.py)에 있습니다. 검증기는 작업 트리의 모든 파일에 대해 적용 가능성을(§3에 따라) 조회하고, 적용 대상이면 정식 SPDX 줄이 파일 맨 앞에 — 다른 모든 콘텐츠보다 앞에, 줄 앞에 허용되는 콘텐츠는 셔뱅뿐입니다(§5) — 있음을 단언합니다. Markdown 프런트매터 너머는 읽지 않습니다.

[`src/apothem/schemas/authorship-header.txt`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas/authorship-header.txt)의 바이트 단위로 정확한 픽스처가 뒷받침합니다. CI 요약에 파일별 diff와 전체 커버리지 %를 보고합니다. 차이가 있으면 빌드를 실패시킵니다.

## 9. 자체 강제 메커니즘

이 규율은 앞으로의 모든 세션과 모든 기여자를 거쳐서도 유지되어야 합니다. 필수 강제 표면은 다음과 같습니다.

1. **`src/apothem/schemas/authorship-header.txt`** — 바이트 단위로 정확한 정식 픽스처. 진실 공급원은 하나입니다.
2. **`scripts/inject-header.{sh,py}`** — 기계적 인젝터(§7).
3. **`file-header` CI 검증기**(§8) — 차이가 있으면 빌드를 실패시킵니다.
4. **Pre-commit 훅** — `conformity-corpus-perwrite` 훅이 추적되는 트리 전체에 대해 `file-header` 검증기(§8)를 실행합니다. 이 훅은 검사만 하며, 파일을 다시 쓰는 것은 인젝터(§7)이고 `make headers-fix`를 통해 수행합니다.
5. **`CLAUDE.md` 필수 동작 블록** — 해당되는 파일을 만들 때마다 정식 SPDX 줄을 주입하도록 어시스턴트에 지시합니다.
6. `.github/copilot-instructions.md`에 있는 **GitHub Copilot 지침 파일** — 파일을 생성할 때 Copilot이 같은 일을 하도록 지시합니다.
7. `src/apothem/hooks/messages/pretooluse-{write,edit}-header-guard.md`의 **PreToolUse 훅** — 해당되는 경로에 대한 Write/Edit 도구 호출을 가로채, SPDX 줄이 나중에 CI 실패로 발견되는 대신 파일을 만들 때 주입되게 합니다.
8. **PR 템플릿 체크박스** — 모든 새 파일이 정식 SPDX 줄을 담고 있다는, 기여자 대상 확인 항목.
9. **이 문서**(`site/content/docs/reference/authorship-header.mdx`) — 정식 규범 설명서.
