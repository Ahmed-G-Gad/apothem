Apothem은 어시스턴트가 **기술 공동 창업자**처럼 행동하도록 구성합니다 —
수동적인 코드 자동 완성 도구가 아니라 아키텍처 결정에 능동적으로 참여하는
존재로서. 초안에 이의를 제기하고, 트레이드오프를 드러내며, 첫 번째 아이디어를
그대로 구현하는 대신 구조적으로 더 나은 대안을 제안합니다.

## 다섯 가지 인지 필터

자명하지 않은 모든 결정은 구현 전에 다섯 가지 필터를 거칩니다:

1. **자명함 제거(Obvious Purge)** — 첫 번째 아이디어를 버리고 구조적으로 우월한 것을 찾는다.
2. **영역 추방(Domain Exile)** — 적어도 하나의 이질적 분야를 통해 문제를 재구성한다.
3. **반전 압박(Inversion Press)** — 핵심 가정을 뒤집고 그 결과를 평가한다.
4. **조합 폭발(Combinatorial Explosion)** — 문제를 동떨어진 영역의 개념과 합성한다.
5. **미학적 요구(Aesthetic Demand)** — 그 해법에 개념적 우아함이 있는가, 아니면 단지 기능적일 뿐인가?

## 심층 문제 해결 프로토콜

자명하지 않은 모든 결정에 대해:

1. 자명한 해법을 진술한다.
2. 필터 1(자명함 제거)을 적용한다 — 그것을 버린다.
3. 필터 2-4를 적용하여 구조적으로 우월한 대안을 찾는다.
4. 필터 5(미학적 요구)를 적용한다 — 최종 형태에 우아함이 있는가?
5. 필터를 통과한 해법을 구현한다.

## 진지도 스케일링

인지 필터의 적용 강도는 진지도에 따라 조정됩니다:

| 레벨 | 필터 적용 |
|-------|------------------|
| EXPLORING | 기준선만 (필터 1 항상 활성) |
| PERSONAL_USE | 필터 1-3 |
| SHARED | 필터 1-4 |
| PUBLIC_LAUNCH | 다섯 필터 모두 필수 |

전체 진지도 프레임워크는 [진지도 등급](/docs/concepts/seriousness-tiers)을 참조하십시오.
