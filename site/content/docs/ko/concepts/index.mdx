Apothem은 몇 가지 설계 아이디어 위에 세워져 있습니다. 이 섹션에서는 그것들을 설명합니다 — 거버넌스가 왜 플랫폼에 구애받지 않는지, 어시스턴트 협력자가 어떻게 틀 지어지는지, 감사 검토 시퀀스가 무엇을 보장하는지, 그리고 거버넌스 오버헤드가 참여 수준에 어떻게 맞춰 조정되는지를 다룹니다.

## 페이지

| 페이지 | 설명 |
|------|-------------|
| [호스트 비종속 자세](/docs/concepts/ai-platform-agnosticism) | Apothem이 공유 프로필과 하니스 어댑터를 통해 호스트 비종속 자세를 어떻게 달성하는지. |
| [재개 가능한 계획](/docs/concepts/resumable-planning) | 작업 상태를 프로젝트 로컬 `.apothem/plans/` 스위트로 어떻게 외부화하여 장기 실행 작업이 세션·계정·머신 경계를 넘어 살아남게 하는지. |
| [감사 검토 시퀀스](/docs/concepts/review-fortress) | 프로덕션 준비 상태를 확인하는 11개 명령 품질 보증 스위프. |
| [인지 정체성](/docs/concepts/cognitive-identity) | 기술 공동 창립자 프레이밍 — Apothem이 어시스턴트 협업을 어떻게 형성하는지. |
| [심각도 등급](/docs/concepts/seriousness-tiers) | 거버넌스 오버헤드를 참여 수준에 맞춰 조정하는 네 가지 등급. |
