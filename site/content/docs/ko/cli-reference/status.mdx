등록된 각 하니스에 대해 설치, 검증, 드리프트 상태를 보고합니다.

## 개요

```
apothem status [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status`는 읽기 전용 검사 명령입니다. 등록된 하니스 어댑터를 하나씩 순회하며 각 하니스에 대해 세 가지 사실을 보고합니다. 설치되었는지 여부, 관리 대상이 검증되는지 여부, 그리고 설치된 구성이 공유 프로필에서 드리프트되었는지 여부입니다. 디스크에는 아무것도 기록하지 않습니다.

각 하니스에 대해 `status`는 다음을 보고합니다.

| 열 | 의미 |
|---|---|
| `installed` | 어댑터의 관리 구성이 대상 경로에 존재함. |
| `verified` | 어댑터의 관리 대상이 존재하고 유효함. |
| `drift` | 프로필 충실도 판정(아래 참조). |

`drift` 값은 다음 중 하나입니다.

| 값 | 의미 |
|---|---|
| `in-sync` | 설치된 구성이 갓 투영된 공유 프로필을 그대로 담고 있음. |
| `drift` | 하니스는 설치되어 있지만, 투영된 프로필 내용이 더 이상 현재 공유 프로필과 일치하지 않음. `apothem install`을 다시 실행하여 재투영하세요. |
| `absent` | 하니스가 설치되어 있지 않아 비교할 대상이 없음. |
| `needs-project` | 프로젝트 범위 하니스가 `--project` 없이 보고되어 그 대상을 해석할 수 없음. 검사하려면 `--project PATH`를 전달하세요. |

드리프트는 보고될 뿐 결코 오류로 취급되지 않습니다. 하나 이상의 하니스가 `drift`를 보고하더라도 `status`는 0으로 종료됩니다. 드리프트는 당신의 설정에 대한 사실이지 명령의 실패가 아닙니다.

공유 프로필을 로드할 수 없는 경우, 설치된 하니스에 대해 드리프트는 `absent`로 강등되며(installed/verified 사실은 여전히 보고됨), 순회를 중단하지는 않습니다.

## 옵션

| 옵션 | 설명 |
|---|---|
| `--project PATH` | 프로젝트 범위 하니스의 프로젝트 루트. 없으면 프로젝트 범위 하니스는 `needs-project`를 보고합니다. |
| `--quiet`, `-q` | 정보성 출력을 억제하고 오류만 발행합니다. |
| `--verbose`, `-v` | 추가 진단 출력을 발행합니다. |
| `--format plain\|json` | 출력 형식(기본값: `plain`). |
| `--json` | `--format json`의 단축형. |
| `--no-color` | 출력에서 ANSI 색상 코드를 비활성화합니다. |
| `-h`, `--help` | 도움말을 표시하고 종료합니다. |

## JSON 출력

`--json` 봉투는 등록된 하니스마다 하나의 결과 행을 담습니다. 각 행은 문서화된 키 `harness`, `installed`, `verified`, `drift`를 담습니다.

```json
{
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

어댑터별 장애 격리: 단일 어댑터가 자신의 상태를 보고하는 중에 예외를 발생시키면, 해당 하니스의 행은 `outcome: "error"`와 `message`를 담고, 나머지 하니스는 여전히 정상적으로 보고하며, 프로세스는 코드 2로 종료합니다.

## 예시

```bash
apothem status
apothem status --project .
apothem status --json
```

## 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 상태 보고됨(드리프트는 보고되며 오류가 아님) |
| 2 | 적어도 하나의 어댑터가 자신의 상태를 보고하지 못함 |
