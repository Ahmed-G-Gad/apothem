하니스 어댑터 설치를 검증합니다.

## 개요

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

선택한 각 어댑터의 `verify()` 구현을 호출합니다. 선택한 모든 어댑터가 자신의
관리 대상이 존재하고 유효하다고 보고할 때만 0으로 종료합니다. `--profile`이
없으면 검사는 **구조적**입니다. 모든 관리 대상이 존재하고 유효해야 합니다.
`--profile`이 있으면 검사는 추가로 **프로필 충실도**를 요구하므로, 존재하지만
드리프트된 설치는 검증에 실패합니다. 이 검사는 단순히 "존재하는가?"가 아니라
"바로 이 프로필이 충실하게 설치되었는가?"에 답합니다.

`--harness all` 스윕은 프로필의 `exclude_harnesses`, 즉 `install`/`update`
일괄 작업이 적용한 것과 같은 제외 항목을 따르므로, verify는 의도적으로 제외된
하니스를 절대 누락으로 보고하지 않습니다. 제외 항목은 `--profile`이 지정되면
그 프로필에서, 그렇지 않으면 기본 프로필에서 가져옵니다. 기본 프로필을 읽을 수
없거나 없으면 전체 레지스트리로 대체됩니다.

## 옵션

| 옵션 | 설명 |
|---|---|
| `--harness NAME` | 검증할 하니스 어댑터, 또는 레지스트리 전체 집합을 뜻하는 `all`(필수). |
| `--profile PATH` | 충실도를 검사할 기준이 되는 공유 프로필 YAML. 이 옵션이 없으면 검사는 순수하게 구조적입니다. |
| `--project PATH` | 프로젝트 범위 하니스의 프로젝트 루트. |
| `--quiet`, `-q` | 정보성 출력을 억제합니다. 오류만 출력됩니다. |
| `--verbose`, `-v` | 추가 진단 출력을 내보냅니다. |
| `--format plain\|json` | 출력 형식(기본값: `plain`). |
| `--json` | `--format json`의 축약형. |
| `--no-color` | 출력에서 ANSI 색상 코드를 비활성화합니다. |
| `-h`, `--help` | 도움말을 표시하고 종료합니다. |

## JSON 출력

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

선택한 하니스 중 하나라도 누락되었거나 유효하지 않으면, `status`는 `error`가
되고, 실패한 결과 행은 `verified: false`를 담으며, 프로세스는 코드 1로
종료합니다.

## 예제

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 하니스 검증됨 — 모든 관리 대상이 존재하고 유효함 |
| 1 | 하니스 검증 안 됨 — 관리 대상이 누락되었거나 유효하지 않음 |
| 64 | 사용법 오류: 알 수 없는 옵션이나 명령, 또는 누락되었거나 잘못된 옵션 값. `--json`에서는 이 오류가 코드 `cli.usage`를 담은 JSON 봉투로 출력됩니다. |
