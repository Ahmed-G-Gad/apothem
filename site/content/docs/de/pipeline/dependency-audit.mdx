**Rolle:** Abhängigkeitsauditor
**Pipeline-Position:** Festung

Audit-Durchlauf pro Abhängigkeit (direkte + transitive) für Lizenz, CVE und Aktualität.

## Kanonischer Aufruf

```bash
/dependency-audit
```

Mit Argumenten:

```bash
/dependency-audit [path/to/repo/] [--focus MANIFEST_OR_DEP] [--dry-run]
```

## Eingaben

Abhängigkeitsmanifeste des Host-Repositorys

## Ausgaben

Abhängigkeitsbefunde unter `_inputs/dependency-audit-findings.md`

## Nachgelagert

Die dependency-audit-Stufe der Audit-Prüfsequenz

## Workflow-Phasen

Der Befehl durchläuft fünf Phasen: Eingabeaufnahme, Durchlauf je Abhängigkeit, Triage je Befund, Ausgabe der Befunde und das Validierungs-Gate.

## Fehlermodi

| Symptom | Ursache | Behebung |
|---------|-------|----------|
| Qualitätstor FAIL | Die Ausgabe erfüllt die Standards nicht | Behebe die Ausgabe und führe erneut aus |
| Fehlende Eingabedatei | Im Repository-Wurzelverzeichnis wird kein Abhängigkeitsmanifest aufgelöst | Übergib ein Repository-Wurzelverzeichnis, das ein Abhängigkeitsmanifest enthält |

## Beispiele

```bash
# Dry-run to preview what would happen
/dependency-audit --dry-run

# Execute against a repository root
/dependency-audit path/to/repo/
```
