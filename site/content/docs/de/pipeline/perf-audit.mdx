**Rolle:** Performance-Prüfer
**Pipeline-Position:** Festung

Prüft gegen die Performance-Budgets je Klasse (Hook-Laufzeit, verify-ecosystem, Konformitäts-Gate, Tests, delegierte Worker, Shell, Lint) nach der USE-Methode.

## Kanonischer Aufruf

```bash
/perf-audit
```

Mit Argumenten:

```bash
/perf-audit [path/to/repo/] [--focus CLASS] [--dry-run]
```

## Eingaben

Host-Repository, das `hooks/`, `src/apothem/benchmarks/`, `tests/` und die Hook-Bootstrap-Stubs `hooks/lib/bootstrap.{sh,ps1}` enthält

## Ausgaben

Performance-Befunde unter `_inputs/perf-audit-findings.md`

## Nachgelagert

Die Performance-Prüfungsstufe der Audit-Review-Sequenz

## Workflow-Phasen

Der Befehl durchläuft fünf Audit-Phasen: Eingabeaufnahme, Ermittlung der Budgets je Klasse, Ausführung der Benchmarks, Identifikation der Hot Paths nach der USE-Methode sowie Ausgabe der Befunde mit dem Validierungs-Gate.

## Fehlermodi

| Symptom | Ursache | Behebung |
|---------|-------|----------|
| Qualitätstor FAIL | Die Ausgabe erfüllt die Standards nicht | Behebe die Ausgabe und führe erneut aus |
| Fehlende Eingabedatei | Im Repository fehlt `src/apothem/benchmarks/` | Ergänze die Benchmark-Treiber und führe dann erneut aus; der Befehl verweigert die Ausführung, bis sie existieren |

## Beispiele

```bash
# Dry-run to preview what would happen
/perf-audit --dry-run

# Execute against a repository root
/perf-audit path/to/repo/
```
