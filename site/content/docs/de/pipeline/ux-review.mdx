**Rolle:** UX-Prüfer
**Pipeline-Position:** Festung

Developer-Experience-Review der CLI-Ergonomie, der Dokumentation und des Onboardings.

## Kanonischer Aufruf

```bash
/ux-review
```

Mit Argumenten:

```bash
/ux-review [path/to/repo/] [--focus SURFACE] [--dry-run]
```

## Eingaben

Bereitgestelltes Host-Repository mit einer README, Installationsskripten und einem CLI-Einstiegspunkt

## Ausgaben

UX-Befunde unter `_inputs/ux-review-findings.md`

## Nachgelagert

Die UX-Review-Stufe der Audit-Review-Sequenz

## Workflow-Phasen

Der Befehl durchläuft fünf Phasen: Eingabeaufnahme, Durchlauf der CLI-Ergonomie, Audit des Installationsablaufs und der Fehlerwiederherstellung, Sweep der Auffindbarkeit der Dokumentation sowie Ausgabe der Befunde mit dem Validierungs-Gate.

## Fehlermodi

| Symptom | Ursache | Behebung |
|---------|-------|----------|
| Voraussetzung unvollständig | Abhängige Phase nicht abgeschlossen | Schließe zuerst die vorgelagerte Phase ab |
| Qualitätstor FAIL | Die Ausgabe erfüllt die Standards nicht | Behebe die Ausgabe und führe erneut aus |
| Ziel nicht bereitgestellt | Dem Ziel fehlt die für Operatoren sichtbare Oberfläche | Übergib das bereitgestellte Repository-Wurzelverzeichnis |

## Beispiele

```bash
# Dry-run to preview what would happen
/ux-review --dry-run

# Execute against a host repository
/ux-review path/to/repo/
```
