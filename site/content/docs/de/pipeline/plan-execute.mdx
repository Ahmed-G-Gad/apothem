**Rolle:** Ausführer
**Pipeline-Position:** terminal

Führt eine bestimmte Phase aus einer Master-Plan-Suite mit Konformitätsprüfung aus.

## Kanonischer Aufruf

```bash
/plan-execute
```

Mit Argumenten:

```bash
/plan-execute [path/to/plan-suite/] [phase-id] [--dry-run]
```

## Eingaben

Generierte + geprüfte Plan-Suite; geprüfte `_inputs/handoff-manifest.yml`

## Ausgaben

REPORT.md-Dateien pro Phase, Codebasis-Artefakte, COMPLETION.md

## Nachgelagert

`/code-review` — der kanonische Einstiegspunkt der elf Befehle umfassenden Audit-Festungssequenz. `/plan-execute` ist die terminale Stufe der *Plan*-Pipeline; wenn die finale Phase abgeschlossen ist, wird der gebaute Code zur Prüfung an die Audit-Festung übergeben.

## Workflow-Phasen

Der Befehl folgt dem standardmäßigen `/plan`-Pipeline-Workflow:

1. **Kontext laden** — Plan-Suite, Regeln und den Wiederaufnahme-Vertrag lesen.
2. **Voraussetzungen prüfen** — Bestätigen, dass die Abhängigkeitsphasen abgeschlossen sind.
3. **Aufgaben ausführen** — Die Mission des Befehls erfüllen.
4. **Ausgaben prüfen** — Bestätigen, dass alle deklarierten Ausgaben existieren und die Qualitätstore bestehen.
5. **REPORT.md ausgeben** — Das Gate-Ergebnis des Pre-Emission-Gates wird erfasst.
6. **PROGRESS.md aktualisieren** — Verifizierte Ausgaben im Phasen-Ausgaberegister erfassen.

## Fehlermodi

| Symptom | Ursache | Behebung |
|---------|-------|----------|
| Voraussetzung unvollständig | Abhängige Phase nicht abgeschlossen | Schließe zuerst die vorgelagerte Phase ab |
| Qualitätstor FAIL | Die Ausgabe erfüllt die Standards nicht | Behebe die Ausgabe und führe erneut aus |
| Fehlende Eingabedatei | Plan-Suite-Datei fehlt | Führe `/plan-generate` aus, um sie zu erstellen |

## Beispiele

```bash
# Dry-run to preview what would happen
/plan-execute --dry-run

# Execute against a named plan suite
/plan-execute path/to/plan-suite/
```
