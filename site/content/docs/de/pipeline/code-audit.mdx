**Rolle:** Auditor
**Pipeline-Position:** Festung

Dateiübergreifendes forensisches Code-Audit auf Repository-Korpus-Ebene.

## Kanonischer Aufruf

```bash
/code-audit
```

Mit Argumenten:

```bash
/code-audit [path/to/repo/] [--focus AREA] [--dry-run]
```

## Eingaben

Host-Repository mit einem genehmigten Quelllayout, einer Basislinie der Testabdeckung und (ab SHARED+) einem bestandenen CI-Gate

## Ausgaben

Befunde auf Korpus-Ebene unter `_inputs/code-audit-findings.md`

## Nachgelagert

Die forensische Code-Audit-Stufe der Audit-Review-Sequenz

## Workflow-Phasen

Der Befehl durchläuft sechs forensische Phasen: Eingabeaufnahme, dateiübergreifender Durchlauf der Abhängigkeiten, Audit der Typhinweise und der Abdeckung, Erkennung von totem Code und Duplikaten, Audit der architektonischen Integrität sowie Ausgabe der Befunde mit dem Validierungs-Gate.

## Fehlermodi

| Symptom | Ursache | Behebung |
|---------|-------|----------|
| Qualitätstor FAIL | Die Ausgabe erfüllt die Standards nicht | Behebe die Ausgabe und führe erneut aus |
| Fehlende Eingabedatei | Keine Ausführung des CI-Gates und keine Basislinie der Testabdeckung ab SHARED+ | Führe zuerst die CI-Pipeline des Hosts aus, dann erneut |

## Beispiele

```bash
# Dry-run to preview what would happen
/code-audit --dry-run

# Execute against a repository root
/code-audit path/to/repo/
```
