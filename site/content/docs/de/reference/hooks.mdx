Hooks lösen bei Werkzeugereignissen aus und laden Nachrichtenkontexte, die der
Assistent als zusätzliche System-Prompts behandelt. Die Verdrahtung liegt im
Hook-Block der `settings.json` von Claude Code, der Hook-Datei `hooks.json` von Codex
und der Hook-Zuordnung der `settings.json` von Qwen Code.

| Ereignis | Timeout | Zweck |
|-------|--------:|---------|
| SessionStart | 30 Sekunden | Speicher lesen, Plan-Status prüfen, Bereitschaft melden |
| PreCompact | 30 Sekunden | Vor der Kompaktierung prüfen, ob der Zustand externalisiert ist |
| PostCompact | 30 Sekunden | Arbeitszustand nach der Kompaktierung wiederherstellen |
| Stop | 60 Sekunden | Externalisierung am Sitzungsende |
| PreToolUse (Bash) | 10 Sekunden | Bash-Validierung — Isolation von git-Artefakten |
| PreToolUse (Write/Edit/NotebookEdit/apply_patch) | 10 Sekunden | Isolation von Plan-Referenzen, Frontmatter-Prüfungen |

## Dispatcher

Installierte Hook-Einträge rufen den Dispatcher über den absoluten Skriptpfad auf.
Die Einstellungsvorlagen tragen das Token `${HARNESS_ROOT}` —
`python "${HARNESS_ROOT}/apothem/hooks/dispatch.py" <event> [<message-name>]`
— das der Installer zur Installationszeit zum realen Pfad des harness-Stammverzeichnisses
rendert (Claude Code und Qwen Code materialisieren den Dispatcher unter
`<harness-root>/apothem/hooks/`; Codex unter `<harness-root>/hooks/`). Der
Dispatcher ist ein eigenständiges Standardbibliotheks-Skript: Er initialisiert seinen eigenen `sys.path`,
sodass auf dem Host kein importierbares `apothem`-Paket benötigt wird. Aus einem
Quell-Checkout führt die Modulform `python -m apothem.hooks.dispatch <event>` (mit
`PYTHONPATH=src`) denselben Code für die Entwicklung aus. Der Dispatcher lädt
`hooks/lib/resolve_root.py` für die Auflösung des Ökosystem-Stammverzeichnisses und delegiert an
`hooks/emit_hook_context.py` und `hooks/session_start_bootstrap.py`.

## Nachrichtenkontexte

Die ereignisbezogenen Markdown-Kontexte liegen unter `src/apothem/hooks/messages/`:

- `postcompact.md`, `precompact.md`, `stop.md`
- `pretooluse-bash.md`, `pretooluse-write.md`, `pretooluse-edit.md`,
  `pretooluse-notebookedit.md`

Jede Kontextdatei wird vom Dispatcher geladen, wenn ihr Ereignis auslöst
und ihr Kontextargument in der Einstellungsdatei registriert ist.
