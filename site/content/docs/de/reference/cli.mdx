Die `apothem`-CLI ist die primäre Bedienoberfläche zum Verwalten des gemeinsamen
Profils und der Harness-Adapter.

## Globale Flags

| Flag | Beschreibung |
|------|-------------|
| `--version` | Gibt die Apothem-Version aus und beendet sich |
| `--help` | Gibt die Hilfe zum Befehl aus |

## Unterbefehle

### `apothem install`

Installiert einen Harness-Adapter aus dem gemeinsamen Profil.

```bash
apothem install --harness <name|all> [--profile PATH] [--project PATH] [--dry-run] [--clean|--fresh] [--yes]
```

| Option | Beschreibung |
|--------|-------------|
| `--harness <name>` | Name des Harness-Adapters (siehe kanonische Werte unten). Erforderlich. |
| `--profile PATH` | Pfad zur YAML-Datei des gemeinsamen Profils. Standard: `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Projektwurzel für Harnesses mit Projektbereich. |
| `--dry-run` | Vorschau der Installation ohne Schreiben von Dateien. |
| `--clean`, `--fresh` | Opt-in für einen leeren Ausgangszustand: sichert den bisherigen Installationszustand (`~/.claude`, `~/.codex`, `~/.agents`, `~/.config/apothem`) und entfernt ihn vor der Installation. |
| `--yes` | Überspringt die Bestätigung je Ziel beim Entfernen für den leeren Ausgangszustand (erforderlich für nicht interaktive `--clean`-Läufe). |

Kanonische `--harness`-Werte:

```text
antigravity
claude-code
codebuddy
codex
cursor
gemini-cli
github-copilot
glm
hermes
kimi-code
kiro
open-claw
opencode
qwen-code
trae
windsurf
zed
```

Verwenden Sie `--harness all --project <path>`, um die registryweite Menge
auszuwählen. Die `exclude_harnesses`-Liste des Profils wird bei der
Stapelauswahl für Installation/Aktualisierung berücksichtigt.

### `apothem update`

Leitet die native Konfiguration eines Harness-Adapters aus dem aktuellen
gemeinsamen Profil neu ab.

```bash
apothem update --harness <name|all> [--profile PATH] [--project PATH] [--dry-run]
```

| Option | Beschreibung |
|--------|-------------|
| `--harness <name>` | Name des Harness-Adapters. Erforderlich. |
| `--profile PATH` | Pfad zur YAML-Datei des gemeinsamen Profils. |
| `--project PATH` | Projektwurzel für Harnesses mit Projektbereich. |
| `--dry-run` | Vorschau der Aktualisierung ohne Schreiben von Dateien. |

`update` materialisiert die Harness-Ausgabe neu. Es aktualisiert nicht das Paket
der Apothem-CLI; verwenden Sie für Paket-Upgrades den Paketmanager, mit dem
Apothem installiert wurde.

### `apothem uninstall`

Entfernt die native Konfiguration eines Harness-Adapters.

```bash
apothem uninstall --harness <name|all> [--project PATH] [--yes]
```

| Option | Beschreibung |
|--------|-------------|
| `--harness <name>` | Name des Harness-Adapters. Erforderlich. |
| `--project PATH` | Projektwurzel für Harnesses mit Projektbereich. |
| `--yes` | Überspringt die Bestätigungsabfrage. |

### `apothem verify`

Prüft, ob die verwalteten Ziele eines Harness-Adapters vorhanden und gültig sind.

```bash
apothem verify --harness <name|all> [--profile PATH] [--project PATH]
```

| Option | Beschreibung |
|--------|-------------|
| `--harness <name>` | Name des Harness-Adapters oder `all`. Erforderlich. |
| `--profile PATH` | YAML-Datei des gemeinsamen Profils, gegen die die Treue geprüft wird. Ohne diese Option ist die Prüfung rein strukturell. |
| `--project PATH` | Projektwurzel für Harnesses mit Projektbereich. |

Ohne `--profile` ist die Prüfung strukturell: Jedes verwaltete Ziel muss
vorhanden und gültig sein. Mit `--profile` verlangt sie zusätzlich Treue, sodass
eine Installation, die existiert, aber von diesem Profil abgedriftet ist, bei
verify durchfällt — verwenden Sie die Option, um zu bestätigen, dass ein
bestimmtes Profil getreu installiert ist.

Der Exit-Code ist `0`, wenn der Harness verifiziert ist (und, mit `--profile`,
diesem Profil treu ist), und `1`, wenn ein Ziel fehlt oder ungültig ist oder
wenn `--profile` angegeben ist und die Installation abgedriftet ist.

### `apothem status`

Meldet den Installations-, Verifizierungs- und Drift-Zustand für jeden
registrierten Harness.

```bash
apothem status [--profile PATH] [--project PATH]
```

| Option | Beschreibung |
|--------|-------------|
| `--profile PATH` | Gemeinsames Profil, das als Drift-Basislinie dient. Ein nicht lesbares Standardprofil stuft den Drift auf `unknown` herab, statt den Durchlauf abzubrechen. |
| `--project PATH` | Projektwurzel für Harnesses mit Projektbereich. Ohne diese Option melden sie `needs-project`. |

Jede Zeile kombiniert ein `installed`-Flag mit einem `verified`-Flag, und beide
ergeben zusammen den Drift-Zustand:

| Zustand | Bedeutung |
|-------|---------|
| `absent` | Apothem hat nicht in diesen Harness installiert. |
| `in-sync` | Installiert und mit der Profil-Basislinie übereinstimmend. |
| `drift` | Installiert, aber nicht mehr übereinstimmend — beheben Sie dies mit `apothem update`. |
| `unknown` | Installiert, aber das Basislinienprofil konnte nicht gelesen werden. |

`installed` beantwortet die Frage „Hat Apothem hier installiert?“, nicht „Ist
dieser Harness auf dem Rechner vorhanden?“. Es stützt sich auf Apothems eigene
Artefakte — den verwalteten Block innerhalb eines Anweisungsankers und Inhalte
unter dem Apothem-eigenen `.apothem/`-Teilbaum —, niemals auf eine vendor-eigene
Datei, die der Harness für sich selbst schreibt. Ein Harness, dessen
Konfigurationsverzeichnis existiert, den Apothem aber nie angefasst hat, meldet
`absent`, und einer, der deinstalliert wurde, meldet `absent`, obwohl die
geleerten Verzeichnisse bestehen bleiben.

### `apothem profile`

Verwaltet das gemeinsame Apothem-Profil.

```bash
apothem profile show [--profile PATH]
apothem profile init [--profile PATH] [--force]
apothem profile set <key> <value> [--profile PATH]
apothem profile edit [--profile PATH]
```

| Unterbefehl | Beschreibung |
|------------|-------------|
| `profile init` | Erstellt ein schema-gültiges minimales Profilgerüst. |
| `profile show` | Gibt das aufgelöste Profil als JSON auf stdout aus. Mit `--json` beginnt das Dokument mit `schema_version`. |
| `profile set <key> <value>` | Setzt ein Profilfeld. Der Wert wird als literale Zeichenkette gespeichert: Bloße Wörter werden nicht umgewandelt, sodass `no` als `"no"` erhalten bleibt und `1.0` eine Zeichenkette bleibt. Ausgenommen sind `true`/`false` sowie explizite `[...]`- und `{...}`-Eingaben für Listen und Maps. Das zusammengesetzte Profil wird vor dem Schreiben gegen das Schema validiert. |
| `profile edit` | Öffnet das Profil in `$EDITOR` (greift ersatzweise auf den Plattformstandard zurück). |

Die Option `--profile PATH` richtet jeden Unterbefehl auf eine alternative
Profildatei aus. Standard: `~/.config/apothem/profile.yaml`.

### `apothem harnesses`

Listet registrierte Harness-Adapter auf und inspiziert sie.

```bash
apothem harnesses list
apothem harnesses show <name>
```

| Unterbefehl | Beschreibung |
|------------|-------------|
| `harnesses list` | Gibt eine Tabelle aller registrierten Adapter mit ihrem Installationsstatus-Flag und Ausgabepfad aus. |
| `harnesses show <name>` | Gibt Name, Installationszustand und Ausgabepfad eines Adapters aus. |

### `apothem doctor`

Führt Systemdiagnosen für die Apothem-Installation aus.

```bash
apothem doctor
```

Gibt die Apothem-Version, den Python-Interpreter, die Plattform, den aufgelösten Profilpfad und eine Installationsstatus-Tabelle je Harness aus. Der Exit-Code ist `1`, sobald eine Prüfung fehlschlägt: ein ungültiges Profil, ein installierter Harness, der nicht verifiziert, ein registrierter Hook-Befehl, der nicht starten kann, ein Adapter, der sich nicht laden oder prüfen lässt, oder ein nicht lesbares Ledger. Ein nicht installierter Harness wird gemeldet und gilt nicht als Fehler; Informationshinweise ändern den Exit-Code nicht.
