Die Harness-Registry ist das Adapter-Inventar, das als Quelle der Wahrheit dient
und von der CLI, der Dokumentation, den Fixture-Tests und der Validierung der
Konventions-Pins verwendet wird. Die Laufzeitquelle ist
`src/apothem/lib/harness_registry.py`; jede Zeile unten ist auf diese Registry,
die adapterspezifische `capabilities.yml` und die `STANDARD-CONVENTION-PIN.md`
jedes Adapters rückführbar.

## Unterstützung der Payload-Kohorten

Die Statuswerte sind `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable` und
`discovery-pending`.

Eine `converted`-Kohorte wird in das eigene Format des Harness umgeschrieben,
und manche Quellfelder haben darin keinen Platz. Für jede konvertierte
Commands-, Agents- oder Regel-Kohorte trägt die `capabilities.yml` des Adapters
eine `conversion_losses`-Map, die angibt, was mit jedem Frontmatter-Feld der
Quelle geschieht:

| Wert | Bedeutung |
| --- | --- |
| `native:<field>` | Der Harness liest es unter diesem Feld. |
| `sidecar:<path>` | Es wird in eine separate Datei neben der konvertierten geschrieben, etwa Codex' `agents/openai.yaml`. |
| `filename` | Der Datei- oder Ordnername trägt es. |
| `inlined` | Es wandert in den Prompt- oder Body-Text. |
| `ignored` | Es bleibt in der Datei, aber der Harness liest es nicht. |
| `dropped` | Es wird weggelassen. |

Ein Test rendert jede konvertierte Datei und prüft die Maps gegen die Ausgabe.

## Gemeinsame Wurzelverzeichnisse

Manche Installationsziele werden von anderen Harnesses geladen als dem, der sie
schreibt. Die Registry erfasst jeden solchen Pfad in `SHARED_ROOTS` mit einem
Eigentümer (dem einzigen Adapter, der ihn schreibt) und den Lesern, deren
Vendor-Dokumentation ihn standardmäßig lädt, mit den Vendor-Seiten als Nachweis.
Die Installation des Eigentümers stellt Apothem-Inhalte jedem Leser bereit, und
die Deinstallation des Eigentümers entfernt sie für jeden Leser.

| Pfad | Eigentümer | Leser |
| --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, Gemini CLI, GitHub Copilot, Kimi Code, Open-Claw, OpenCode, Windsurf, Zed |
| `~/.claude/skills/` | Claude Code | Cursor, OpenCode |
| `~/.claude/CLAUDE.md` | Claude Code | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | Zed |

Der Apothem-Block, den ein Eigentümer in eine gemeinsame Anweisungsdatei
schreibt, nennt kein einzelnes Werkzeug als seinen Leser.
`tests/unit/test_shared_roots.py` schlägt fehl, wenn ein Registry-Ziel von zwei
Adaptern geschrieben wird oder wie eine werkzeugübergreifende Anweisungsdatei
benannt ist (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`copilot-instructions.md`), ohne einen deklarierten Eigentümer zu haben.

## Validierungs-Hooks

Die Registry bleibt durch diese Prüfungen synchron:

| Prüfung | Zweck |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | Bestätigt, dass jeder Adapter einen Konventions-Pin hat, der weniger als 90 Tage alt ist, mindestens eine Vendor-URL zitiert und kein überfälliges Discovery-Ziel hat. Die CI führt die Prüfung bei jedem Pull Request, wöchentlich und vor einem Release aus. |
| `python scripts/dev/check_vendor_urls.py` | Ruft jede Vendor-URL ab, die die Pins und Harness-Templates zitieren, und schlägt bei einer verschobenen oder toten Seite fehl, einschließlich eines Hostnamens, der nicht mehr auflöst, oder eines Zertifikats, dessen Verifizierung fehlschlägt; ein Timeout, eine abgelehnte oder zurückgesetzte Verbindung oder ein 5xx-Serverfehler wird als nicht erreichbar gemeldet und lässt die Prüfung nicht fehlschlagen. Der wöchentliche Konventionsmonitor führt sie aus. |
| `python -m apothem.conformity.gate --all .` | Führt die Konformitätsprüfungen für Dokumentation und Implementierung aus. |
| `python -m pytest` | Führt die Registry-Fixture-Tests und die Adapter-Vertragstests aus. |
