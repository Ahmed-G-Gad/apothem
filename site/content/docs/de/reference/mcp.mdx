Model-Context-Protocol-(MCP-)Server sind **im Besitz des Operators**. Apothem
führt das MCP-Inventar im gemeinsamen Profil (`mcp_servers`). Ein Adapter,
dessen Tool seine MCP-Server in einer Konfigurationsdatei hält, die Apothem
ohnehin schreibt, projiziert dieses Inventar in diese Datei; jeder andere
Adapter legt keine Server-Einträge an, und die Server registrieren Sie weiterhin
selbst über das Tool.

## Wo MCP-Server registriert werden

Jedes Tool registriert MCP-Server über seinen eigenen nativen Mechanismus, und
Apothem respektiert diese Oberfläche, statt sie zu überschreiben. Auf Claude
Code registrieren sich Server mit `claude mcp add` in `~/.claude.json`
(Benutzer- oder lokaler Geltungsbereich) und in einer projektbezogenen
`.mcp.json`; der Claude Code-Adapter schreibt keine der beiden Dateien, und die
von Apothem verwalteten Claude Code-Einstellungen tragen niemals einen
`mcpServers`-Block.

## Einen Server hinzufügen

Registrieren Sie einen Server über den nativen Mechanismus Ihres Tools; die
kanonische Eintragsform ist ein Schlüssel unter `mcpServers`:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/some/path"]
    }
  }
}
```

Die Laufzeitumgebung des Tools lädt die registrierten Server beim Sitzungsstart;
starten Sie das Tool neu, damit es neue Server übernimmt.

## Namenskonvention

MCP-Werkzeuge erscheinen dem Assistenten als `mcp__<server>__<tool>` gemäß der
standardmäßigen MCP-Werkzeug-Namenskonvention des Tools.
