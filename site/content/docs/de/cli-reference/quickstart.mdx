Geführter erster Lauf: sicherstellen, dass ein Profil existiert, die
Schreibvorgänge in der Vorschau anzeigen, dann installieren.

## Übersicht

```
apothem quickstart [--harness NAME|all] [--project PATH] [--profile PATH]
                   [--yes] [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

`quickstart` ist der einzige geführte Einstiegspunkt für einen neuen Operator.
In einem linearen Ablauf (1) stellt der Befehl sicher, dass ein gemeinsames
Profil existiert — und legt ein Starterprofil mit einem Hinweis zur
Personalisierung an, falls keines gefunden wird; (2) zeigt er die konkreten
Dateien in der Vorschau an, die die ausgewählten Harnesses schreiben werden,
gruppiert nach Projektwurzel gegenüber Ihrem Home-Verzeichnis; (3) bittet er um
Bestätigung; (4) installiert er mit der gruppierten, entrauschten Ausgabe der
Fähigkeitshinweise; und (5) gibt er die empfohlenen nächsten Befehle aus.

Er setzt dieselben Bausteine zusammen, die der Befehl `install` verwendet —
er implementiert sie nicht neu. `--project` ist standardmäßig das
aktuelle Verzeichnis. `--harness` hat keinen Standardwert: Wenn es weggelassen
wird, fragt `quickstart`, welcher Harness installiert werden soll, sodass ein
erster Lauf die Konfiguration eines einzigen Harness schreibt. `--harness all`
installiert jeden unterstützten Harness und ist immer eine explizite Wahl.

## Verhalten

- **Harness** — ohne `--harness` listet ein interaktiver Lauf die unterstützten
  Namen (plus `all`) auf und fragt nach einem davon, bevor irgendetwas
  geschrieben wird. Ein Lauf, der nicht fragen kann — `--yes`, `--format json`
  oder kein Terminal —, stoppt mit einem Verwendungsfehler, der die Option
  `--harness` benennt, und schreibt nichts.
- **Profil** — wenn am aufgelösten Profilpfad keine Datei existiert, bietet
  `quickstart` an, ein Starterprofil anzulegen (legt es unter `--yes`, in einer
  nicht interaktiven Shell oder unter `--format json` automatisch an), und
  benennt die Platzhalter-Identitätsfelder, die anzupassen sind.
- **Vorschau + Bestätigung** — vor jedem Schreibvorgang werden die Ziele unter
  zwei Überschriften aufgeführt (Projektwurzel gegenüber Ihrem Home-Verzeichnis);
  ein interaktiver Lauf fragt nach Bestätigung, bevor er außerhalb des Projekts
  schreibt. `--yes`, eine nicht interaktive Shell und `--format json` fahren
  ohne Nachfrage fort. Ein Ablehnen bricht vor jedem Schreibvorgang ab.
- **Installation** — Fähigkeiten, die ein Harness nicht nativ unterstützt,
  werden als ein gruppierter Hinweis je Harness zusammengefasst (übergeben Sie
  `--verbose` für die Details je Fähigkeit); die vollständige Menge steht immer
  im warnings-Array von `--format json`.
- **Nächster Schritt** — die Terminalausgabe benennt die Folgebefehle (`apothem
  verify …`, `apothem doctor`).

## Optionen

| Option | Beschreibung |
|---|---|
| `--harness NAME` | Zu installierender Harness-Adapter oder `all` für die registry-weite Menge. Kein Standardwert: Ein interaktiver Lauf fragt nach; ein nicht interaktiver Lauf muss die Option übergeben. |
| `--profile PATH` | Pfad zur YAML-Datei des gemeinsamen Profils. Standard: `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Projektwurzel für Harnesses mit Projekt-Geltungsbereich. Standard: das aktuelle Verzeichnis. |
| `--yes` | Führt die vollständige geführte Abfolge nicht interaktiv aus (überspringt jede Abfrage). |
| `--quiet`, `-q` | Unterdrückt informative Ausgaben; nur Fehler werden ausgegeben. |
| `--verbose`, `-v` | Gibt die Begründung jeder nicht projizierten Fähigkeit aus statt des gruppierten Hinweises. |
| `--format plain\|json` | Ausgabeformat (Standard: `plain`). |
| `--json` | Kurzform für `--format json`. |
| `--no-color` | Deaktiviert ANSI-Farbcodes in der Ausgabe. |
| `-h`, `--help` | Zeigt die Hilfe an und beendet den Befehl. |

## JSON-Ausgabe

`--format json` gibt ein einzelnes Dokument aus, das jeden geführten Schritt
zusammenfasst:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "quickstart",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "steps": [
    {"step": "profile", "outcome": "created", "path": "…", "placeholder_identity": ["name", "email", "github"]},
    {"step": "install", "status": "success", "harness": "all", "files_written": ["…"], "warnings": [], "results": []},
    {"step": "recommend", "next": ["apothem verify --harness all --project .", "apothem doctor"]}
  ],
  "recommended_next": ["apothem verify --harness all --project .", "apothem doctor"]
}
```

## Beispiele

```bash
apothem quickstart                                  # asks which harness
apothem quickstart --harness claude-code --yes
apothem quickstart --harness all --project . --yes  # every harness, explicitly
apothem quickstart --harness claude-code --json
```

## Exit-Codes

| Code | Bedeutung |
|---|---|
| 0 | Geführter Lauf abgeschlossen |
| 1 | Erwarteter Validierungs-, Profil-, Harness-, Projekt- oder Adapterfehler |
| 2 | Teilweise Batch-Materialisierung nach mindestens einem Schreibvorgang |
| 64 | Verwendungsfehler: eine unbekannte Option oder ein unbekannter Befehl oder ein fehlender oder ungültiger Optionswert. Unter `--json` ist der Fehler ein JSON-Umschlag mit dem Code `cli.usage`. |
