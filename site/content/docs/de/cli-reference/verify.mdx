Verifiziert die Installation eines Harness-Adapters.

## Übersicht

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

Ruft die `verify()`-Implementierung jedes ausgewählten Adapters auf. Endet nur
dann mit Exit-Code 0, wenn alle ausgewählten Adapter melden, dass ihre
verwalteten Ziele vorhanden und gültig sind. Ohne `--profile` ist die Prüfung
**strukturell** — jedes verwaltete Ziel muss vorhanden und gültig sein. Mit
`--profile` verlangt die Prüfung zusätzlich **Profiltreue**, sodass eine
vorhandene, aber abgedriftete Installation bei verify durchfällt; die Prüfung
beantwortet also „Ist DIESES Profil originalgetreu installiert?“ statt nur
„Existiert es?“.

Für einen Adapter, der Skills in Ihr Home-Verzeichnis schreibt, prüft verify
außerdem, dass jeder erwartete Skill-Ordner mit einer `SKILL.md` existiert,
gleichgültig, welche Installation ihn geschrieben hat, sodass ein Rechner, auf dem
nur eines der Werkzeuge installiert ist, die sich einen Ordner teilen, die
Prüfung besteht. Sie schlägt fehl, wenn ein Ordner fehlt und wenn ein Ordner mit
dem Namen eines Apothem-Skills zu etwas gehört, das Apothem nicht geschrieben
hat. Eine fehlgeschlagene Zeile sagt, welcher Fall vorliegt: Im Plain-Modus folgt
ihr eine `Note:`-Zeile, und in der JSON-Zeile listet ein `user_level`-Objekt
`missing`- und `unlisted`-Pfade sowie eine `message` auf. Führen Sie
[`install`](/docs/cli-reference/install) aus, um einen fehlenden Ordner
wiederherzustellen; benennen Sie einen fremden Ordner um oder verschieben Sie ihn
und führen Sie dann [`update`](/docs/cli-reference/update) aus.

Ein Durchlauf mit `--harness all` berücksichtigt `exclude_harnesses` im Profil —
dieselben Ausschlüsse, die der `install`/`update`-Batch angewendet hat —, sodass
verify einen bewusst ausgeschlossenen Harness niemals als fehlend meldet. Die
Ausschlüsse stammen aus `--profile`, wenn angegeben, andernfalls aus dem
Standardprofil; ist das Standardprofil nicht lesbar oder fehlt es, fällt der
Durchlauf auf die vollständige Registry zurück.

## Optionen

| Option | Beschreibung |
|---|---|
| `--harness NAME` | Zu verifizierender Harness-Adapter oder `all` für die registry-weite Menge (erforderlich). |
| `--profile PATH` | YAML-Datei des gemeinsamen Profils, gegen die die Treue geprüft wird. Ohne die Option ist die Prüfung rein strukturell. |
| `--project PATH` | Projektwurzel für Harnesses mit Projekt-Geltungsbereich. |
| `--quiet`, `-q` | Unterdrückt informative Ausgaben; nur Fehler werden ausgegeben. |
| `--verbose`, `-v` | Gibt zusätzliche Diagnoseausgaben aus. |
| `--format plain\|json` | Ausgabeformat (Standard: `plain`). |
| `--json` | Kurzform für `--format json`. |
| `--no-color` | Deaktiviert ANSI-Farbcodes in der Ausgabe. |
| `-h`, `--help` | Zeigt die Hilfe an und beendet den Befehl. |

## JSON-Ausgabe

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Wenn ein ausgewählter Harness fehlt oder ungültig ist, lautet `status` `error`,
die fehlschlagende Ergebniszeile trägt `verified: false`, und der Prozess endet
mit dem Code 1.

## Beispiele

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## Exit-Codes

| Code | Bedeutung |
|---|---|
| 0 | Harness verifiziert — alle verwalteten Ziele vorhanden und gültig |
| 1 | Harness nicht verifiziert — verwaltete Ziele fehlen oder sind ungültig |
| 64 | Verwendungsfehler: eine unbekannte Option oder ein unbekannter Befehl oder ein fehlender oder ungültiger Optionswert. Unter `--json` ist der Fehler ein JSON-Umschlag mit dem Code `cli.usage`. |
