Installiert eine Harness-Adapterkonfiguration aus dem aktuellen gemeinsamen
Profil neu.

## Übersicht

```
apothem update --harness NAME|all [--profile PATH] [--dry-run]
                [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

`update` materialisiert die Harness-Ausgabe aus dem aktuellen gemeinsamen Profil
neu. Der Befehl verwendet dieselbe Profilvalidierung, dieselbe Auswahl mit
`--harness all`, dieselbe Prüfung des Projekt-Geltungsbereichs, dasselbe
Dry-Run-Verhalten und denselben JSON-Umschlag wie `install`.

Der Alias in Verlaufsform `apothem updating` (auch als `apothem Updating`
akzeptiert) wird auf denselben Handler aufgelöst.

## Optionen

| Option | Beschreibung |
|---|---|
| `--harness NAME` | Zu aktualisierender Harness-Adapter oder `all` für die registry-weite Menge (erforderlich). Bei `all` werden Harnesses übersprungen, die in `exclude_harnesses` des Profils aufgeführt sind; ein ausdrücklich benannter Harness wird dagegen auch dann aktualisiert, wenn er aufgeführt ist. |
| `--profile PATH` | Pfad zur YAML-Datei des gemeinsamen Profils. Standard: `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Vorschau der Aktualisierung, ohne Dateien zu schreiben. |
| `--project PATH` | Projektwurzel für Harnesses mit Projekt-Geltungsbereich. Erforderlich, wenn die ausgewählte Harness-Menge Adapter mit Projekt-Geltungsbereich enthält. |
| `--quiet`, `-q` | Unterdrückt informative Ausgaben; nur Fehler werden ausgegeben. |
| `--verbose`, `-v` | Gibt zusätzliche Diagnoseausgaben aus. |
| `--format plain\|json` | Ausgabeformat (Standard: `plain`). |
| `--json` | Kurzform für `--format json`. |
| `--no-color` | Deaktiviert ANSI-Farbcodes in der Ausgabe. |
| `-h`, `--help` | Zeigt die Hilfe an und beendet den Befehl. |

## JSON-Ausgabe

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "update",
  "action": "updated",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

`--dry-run` gibt `status: "dry_run"` und `files_written: []` zurück.

## Beispiele

```bash
apothem update --harness claude-code
apothem update --harness claude-code --dry-run
apothem update --harness all --project . --dry-run --json
apothem Updating --harness claude-code   # continuous-form alias
apothem updating --harness claude-code   # lowercase variant
```

## Exit-Codes

| Code | Bedeutung |
|---|---|
| 0 | Adapter erfolgreich aktualisiert oder Dry-Run sauber geplant |
| 1 | Erwarteter Validierungs-, Profil-, Harness-, Projekt- oder Adapterfehler |
| 2 | Teilweise Batch-Materialisierung nach mindestens einem Schreibvorgang |
| 64 | Verwendungsfehler: eine unbekannte Option oder ein unbekannter Befehl oder ein fehlender oder ungültiger Optionswert. Unter `--json` ist der Fehler ein JSON-Umschlag mit dem Code `cli.usage`. |
