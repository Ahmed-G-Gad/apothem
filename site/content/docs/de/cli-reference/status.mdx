Meldet den Installations-, Verifizierungs- und Drift-Zustand für jeden
registrierten Harness.

## Übersicht

```
apothem status [--profile PATH] [--project PATH]
               [--quiet|-q] [--verbose|-v]
               [--format plain|json] [--json] [--no-color]
```

`status` ist ein rein lesender Inspektionsbefehl. Er durchläuft jeden
registrierten Harness-Adapter und meldet drei Fakten pro Harness: ob er
installiert ist, ob seine verwalteten Ziele die Verifizierung bestehen und ob
die installierte Konfiguration vom gemeinsamen Profil abgedriftet ist. Er
schreibt nichts auf die Festplatte.

Für jeden Harness meldet `status`:

| Spalte | Bedeutung |
|---|---|
| `installed` | Die verwaltete Konfiguration des Adapters existiert an seinem Zielpfad. |
| `verified` | Die verwalteten Ziele des Adapters sind vorhanden und gültig. |
| `drift` | Das Urteil zur Profiltreue (siehe unten). |

Der Wert von `drift` ist einer der folgenden:

| Wert | Bedeutung |
|---|---|
| `in-sync` | Die installierte Konfiguration trägt das frisch projizierte gemeinsame Profil wortgetreu. |
| `drift` | Der Harness ist installiert, aber sein projizierter Profilinhalt stimmt nicht mehr mit dem aktuellen gemeinsamen Profil überein. Führen Sie `apothem install` erneut aus, um neu zu projizieren. |
| `absent` | Der Harness ist nicht installiert, es gibt also nichts zu vergleichen. |
| `needs-project` | Ein Harness mit Projektgeltungsbereich wurde ohne `--project` gemeldet, sodass sein Ziel nicht aufgelöst werden kann. Übergeben Sie `--project PATH`, um ihn zu inspizieren. |
| `unknown` | Das Standardprofil konnte nicht geladen werden, sodass ein installierter Harness keine Vergleichsbasis hat. Korrigieren Sie das Profil, um das Drift-Urteil wiederherzustellen. |

Drift wird gemeldet, niemals als Fehler behandelt: `status` beendet sich mit 0,
selbst wenn ein oder mehrere Harnesses `drift` melden. Drift ist eine Tatsache
über Ihre Einrichtung, kein Fehlschlag des Befehls.

Wenn das gemeinsame Standardprofil nicht geladen werden kann, wird Drift für
installierte Harnesses auf `unknown` herabgestuft (die Fakten zu Installation
und Verifizierung werden weiterhin gemeldet), statt den Durchlauf abzubrechen.
Ein explizit angegebenes `--profile`, das nicht geladen werden kann, ist ein
Benutzerfehler und bricht stattdessen mit einem strukturierten Fehler ab.

Die Herabstufung wird immer gemeldet: `status` gibt einen Hinweis aus, der das
Profil und die Korrektur nennt, und der `--json`-Umschlag trägt einen
entsprechenden `drift_baseline_unavailable`-Eintrag in `warnings`. Das ist vor
allem dann wichtig, wenn kein Harness installiert ist — jede Zeile lautet dann
`absent`, und es gibt keine `unknown`-Zelle, sodass der Hinweis das einzige
Signal dafür ist, dass die Vergleichsbasis nie geladen wurde.

## Optionen

| Option | Beschreibung |
|---|---|
| `--profile PATH` | YAML-Datei des gemeinsamen Profils, die die Drift-Vergleichsbasis festlegt. Ohne diese Option wird das Standardprofil (`~/.config/apothem/profile.yaml`) verwendet. |
| `--project PATH` | Projektwurzel für Harnesses mit Projektgeltungsbereich. Ohne diese Option melden Harnesses mit Projektgeltungsbereich `needs-project`. |
| `--quiet`, `-q` | Unterdrückt informative Ausgaben; nur Fehler werden ausgegeben. |
| `--verbose`, `-v` | Gibt zusätzliche Diagnoseausgaben aus. |
| `--format plain\|json` | Ausgabeformat (Standard: `plain`). |
| `--json` | Kurzform für `--format json`. |
| `--no-color` | Deaktiviert ANSI-Farbcodes in der Ausgabe. |
| `-h`, `--help` | Zeigt die Hilfe an und beendet den Befehl. |

## JSON-Ausgabe

Der `--json`-Umschlag trägt eine Ergebniszeile pro registriertem Harness. Jede
Zeile trägt die dokumentierten Schlüssel `harness`, `installed`, `verified` und
`drift`. `warnings` ist bei einem sauberen Durchlauf leer; wenn das
Standardprofil nicht geladen werden konnte, trägt es einen
`drift_baseline_unavailable`-Eintrag mit `path`, `code`, `reason` und `fix`.

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "status",
  "action": "status",
  "harness": "all",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "installed": true,
      "verified": true,
      "drift": "in-sync"
    },
    {
      "harness": "cursor",
      "installed": false,
      "verified": false,
      "drift": "needs-project"
    }
  ],
  "warnings": [],
  "error": null
}
```

Fehlerisolierung pro Adapter: Wenn ein einzelner Adapter beim Melden seines
Zustands eine Ausnahme auslöst, trägt die Zeile dieses Harness
`outcome: "error"` und eine `message`, die übrigen Harnesses melden weiterhin
normal, und der Prozess beendet sich mit Code 2.

## Beispiele

```bash
apothem status
apothem status --project .
apothem status --json
```

## Exit-Codes

| Code | Bedeutung |
|---|---|
| 0 | Zustand gemeldet (Drift wird gemeldet, ist kein Fehler) |
| 1 | Erwarteter Validierungsfehler (ungültiges `--profile` oder ein `--project`-Pfad, der nicht existiert) |
| 2 | Mindestens ein Adapter konnte seinen Zustand nicht melden |
| 64 | Verwendungsfehler: eine unbekannte Option oder ein unbekannter Befehl oder ein fehlender oder ungültiger Optionswert. Unter `--json` ist der Fehler ein JSON-Umschlag mit dem Code `cli.usage`. |
