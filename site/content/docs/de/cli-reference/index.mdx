Die `apothem`-Befehlszeilenschnittstelle verwaltet Harness-Adapterkonfigurationen
aus dem gemeinsamen Profil. Jede der folgenden Seiten dokumentiert einen
Unterbefehl: seine Übersicht, seine Optionen, sein Verhalten und seine Exit-Codes.

Jeder der Befehle `install`, `update` und `uninstall` akzeptiert außerdem einen
Alias in Verlaufsform (`installing`, `updating`, `uninstalling`), der in Flags
und Verhalten mit dem Basisbefehl identisch ist. Das Aktualisieren und
Deinstallieren über die Installationskanäle — das Claude Code-Plugin, `npx` und
die Ein-Schritt-Installer-Skripte — ist in den Installationsleitfäden
[Aktualisieren](/docs/install/updating) und
[Deinstallieren](/docs/install/uninstalling) dokumentiert, nicht durch die
Aliase selbst.

## JSON-Ausgabevertrag

Jeder Befehl akzeptiert `--json` (Kurzform für `--format json`) und schreibt dann
genau ein JSON-Dokument nach stdout. Jedes Dokument beginnt mit einem
`schema_version`-Schlüssel auf oberster Ebene, einer Ganzzahl, die derzeit `1`
ist:

```json
{"schema_version": 1, "status": "success", "command": "verify", "...": "..."}
```

- **Stabilität.** Innerhalb einer `schema_version` sind Änderungen additiv: Ein
  neuer Schlüssel kann hinzukommen, aber kein Schlüssel wird umbenannt oder
  entfernt, und kein Wert ändert seinen Typ. Alles andere erhöht
  `schema_version`.
- **Versionierte Artefakte.** `profile show --json` gibt das Profil selbst aus,
  daher ist seine `schema_version` die Version des Profilschemas (derzeit
  ebenfalls `1`).
- **Eine Ausnahme.** `harnesses list --json` gibt ein JSON-Array aus (ein Objekt
  je Harness), wie es das schon immer getan hat, und hat daher keinen Schlüssel
  auf oberster Ebene, der die Version tragen könnte. Es in ein Objekt zu
  verpacken, würde bestehende Parser brechen; bis eine Versionserhöhung das tut,
  behandeln Sie seine Form als `schema_version` `1`.
- **Fehler.** Erwartete Fehlschläge verwenden dieselbe Dokumentform mit
  `"status": "error"` und einem `error`-Objekt, das `code`, `field`, `reason`
  und `fix` trägt.

## Exit-Codes

Jeder Befehl verwendet dieselbe kleine Menge an Exit-Codes; jede Seite listet
diejenigen auf, die der Befehl zurückgeben kann.

| Code | Bedeutung |
|---|---|
| 0 | Erfolg |
| 1 | Erwarteter Fehlschlag: ein Validierungs-, Profil-, Harness-, Projekt- oder Adapterfehler |
| 2 | Teilergebnis: Ein Batch hat vor einem Fehlschlag etwas geschrieben oder entfernt (nur die Befehle, deren Seite ihn auflistet) |
| 64 | Verwendungsfehler: eine unbekannte Option oder ein unbekannter Befehl, eine fehlende Pflichtoption oder ein ungültiger Optionswert |

Ein Verwendungsfehler berührt niemals das Dateisystem. Unter `--json` (oder
`--format json`) gibt er statt des reinen Verwendungstexts ein einziges
Fehlerdokument mit `"code": "cli.usage"` aus, sodass Automatisierung ein falsch
geschriebenes Flag von einem teilweisen Schreibvorgang unterscheiden kann.

Für Slash-Befehle und die übergeordnete CLI-Übersicht siehe die Referenzseiten
[CLI-Übersicht](/docs/reference/cli) und [Slash-Befehle](/docs/reference/commands).
