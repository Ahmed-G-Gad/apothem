Entfernt eine Harness-Adapterkonfiguration.

## Übersicht

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

Entfernt die vom Adapter verwalteten Harness-Ziele und danach die Verzeichnisse,
die die Installation angelegt hat, sobald sie leer sind (ein Verzeichnis, das
irgendetwas von Ihnen enthält, bleibt bestehen).

Das Memory, die Kontexte und die Lernspeicher des gemeinsamen Arbeitsverzeichnisses
werden nur gesichert und entfernt, wenn dies der letzte Harness ist, der in
diesem Verzeichnis installiert ist. Die Deinstallation entfernt sie an dem Ort,
den die Installation vermerkt hat, sodass sie dort gefunden werden, wo die
Installation sie geschrieben hat (siehe die Profilfelder `workspace`). Das
Verzeichnis `plans/` wird nie entfernt.

Fragt nach Bestätigung, sofern nicht
`--yes` angegeben ist. Wenn keine Abfrage möglich ist — `--format json`
(der Abfragetext würde das einzelne JSON-Dokument verfälschen) oder eine nicht
interaktive Shell (kein TTY) —, verweigert der Befehl die Ausführung von
vornherein mit einem strukturierten Fehler `uninstall.confirmation_required`
(Exit-Code 1), sofern nicht `--yes` angegeben ist. Ist ein ausgewählter Harness
nicht installiert, ist der Befehl erfolgreich (Exit-Code 0) und gibt in der
einfachen Ausgabe `NAME is not installed; nothing to remove.` aus, wobei `NAME`
die Harness-ID ist.

Die gemeinsamen Datenspeicher unter `.apothem/` an der Installationswurzel
(`memory/`, `contexts/`, `learning/`) bleiben bestehen, solange ein anderer
installierter Harness an derselben Wurzel sie noch verwendet. Ist der Harness,
den Sie entfernen, der letzte an dieser Wurzel, kopiert der Befehl zuerst jeden
Datenspeicher in die Apothem-Sicherungswurzel (`~/.apothem/backups/`) und
entfernt ihn dann samt allem, was er enthält. Alles, was Sie in `plans/`
aufbewahren, wird niemals entfernt.

Eine Entfernung mit `--harness all` ist bewusst erschöpfend: Sie umfasst jeden
registrierten Harness, einschließlich derjenigen, die `exclude_harnesses` im
Profil bei der Installation überspringt — die Bereinigung erfasst auch Zustände,
die eine früher umfassendere Installation hinterlassen haben könnte. Harnesses,
die nie installiert wurden, erhalten denselben Hinweis.

Der Alias in Verlaufsform `apothem uninstalling` (auch als
`apothem Uninstalling` akzeptiert) wird auf denselben Handler aufgelöst.

## Optionen

| Option | Beschreibung |
|---|---|
| `--harness NAME` | Zu entfernender Harness-Adapter oder `all` für die registry-weite Menge (erforderlich). |
| `--yes` | Überspringt die Bestätigungsabfrage. |
| `--project PATH` | Projektwurzel für Harnesses mit Projekt-Geltungsbereich. |
| `--quiet`, `-q` | Unterdrückt informative Ausgaben; nur Fehler werden ausgegeben. |
| `--verbose`, `-v` | Aus Gründen der Konsistenz mit anderen Befehlen akzeptiert; dieser Befehl gibt keine zusätzliche Ausgabe aus. |
| `--format plain\|json` | Ausgabeformat (Standard: `plain`). |
| `--json` | Kurzform für `--format json`. |
| `--no-color` | Deaktiviert ANSI-Farbcodes in der Ausgabe. |
| `-h`, `--help` | Zeigt die Hilfe an und beendet den Befehl. |

## JSON-Ausgabe

Wenn der Adapter installiert ist und erfolgreich entfernt wurde:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Wenn der Adapter nicht installiert war, endet der Befehl mit dem Exit-Code `0`.
In der JSON-Ausgabe hat der Umschlag `"status": "success"` und
`"action": "uninstalled"`, und die Ergebniszeile hat `"outcome": "skipped"` mit
der Meldung `"not installed; no files
removed"`. Das Feld `status` ist niemals `"not_installed"`.

## Beispiele

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

## Exit-Codes

| Code | Bedeutung |
|---|---|
| 0 | Adapter deinstalliert oder war nicht installiert |
| 1 | Harness nicht gefunden, Bestätigung abgelehnt oder nicht verfügbar (nicht interaktiver Modus oder JSON-Modus ohne `--yes`) oder jede Entfernung fehlgeschlagen |
| 2 | Teilweise Entfernung — mindestens ein Harness wurde vor einem Fehlschlag entfernt |
| 64 | Verwendungsfehler: eine unbekannte Option oder ein unbekannter Befehl oder ein fehlender oder ungültiger Optionswert. Unter `--json` ist der Fehler ein JSON-Umschlag mit dem Code `cli.usage`. |
