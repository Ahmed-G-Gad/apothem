## Zuerst die Harness-Konfigurationen entfernen

Der auf dieser Seite verwendete bloße Befehl `apothem` ist der Shim, den der Ein-Schritt-Installer (Kanal 3 des [Installationsleitfadens](/docs/install)) anlegt; er läuft, sobald das Verzeichnis dieses Shims im `PATH` liegt. Verwenden Sie auf den anderen Installationskanälen `npx @ahmed-g-gad/apothem` anstelle von `apothem`, wie im Installationsleitfaden beschrieben.

Bevor Sie Apothem deinstallieren, entfernen Sie die Konfiguration jedes
Harness-Adapters, um Ihre Harnesses in einem sauberen Zustand zu hinterlassen.
Führen Sie `apothem harnesses list` aus, um zu sehen, welche Adapter derzeit
installiert sind, und entfernen Sie sie dann einzeln oder verwenden Sie den
Selektor für die gesamte Registry:

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness cursor --project /path/to/project
apothem uninstall --harness all --project /path/to/project --yes
```

Übergeben Sie `--yes`, um die Bestätigungsabfrage pro Harness zu überspringen.

## Die Engine entfernen

Die Entfernung richtet sich nach dem Installationskanal, den Sie verwendet
haben. Die Kanalnummern sind die der
[Tabelle der Installationskanäle](/docs/install#einen-kanal-wählen):

- **Claude Code-Plugin (Kanal 1)** — entfernen Sie das Plugin innerhalb von
  Claude Code: `/plugin uninstall apothem@apothem` (der Marketplace-Eintrag
  lässt sich mit `/plugin marketplace remove ahmed-g-gad/apothem` entfernen).
- **npx (Kanal 2)** — nichts zu entfernen; `npx` läuft aus seinem Cache. Leeren
  Sie ihn mit `npm cache clean --force`, wenn Sie die zwischengespeicherte Kopie
  entfernen möchten.
- **Ein-Schritt-Installer (Kanal 3)** — führen Sie das passende
  Deinstallationsskript aus dem Checkout aus: `scripts/installer/uninstall.sh`
  (POSIX) oder `scripts/installer/uninstall.ps1` (PowerShell). Beide fragen vor
  dem Entfernen nach einer Bestätigung und verweigern unsichere Ziele.
- **Erweiterung für die VS Code-Familie (Kanal 4)** — führen Sie zuerst
  **Apothem: Uninstall** über die Befehlspalette aus, um die
  Harness-Konfigurationen zu entfernen, und entfernen Sie dann die Erweiterung
  in der Erweiterungsansicht oder mit
  `code --uninstall-extension ahmed-g-gad.apothem`. Standardmäßig führt die
  Erweiterung die Engine über `npx` aus, sodass der Eintrag **npx** oben den
  Cache abdeckt.
- **Kommandozeilen-Bootstraps (Kanäle 5–7)** — entfernen Sie die Erweiterung
  oder das Plugin mit dem zugehörigen Host-Tool, nachdem die
  Harness-Konfigurationen entfernt sind. Die Hosts:

  ```text
  channel 5   Gemini CLI extension
  channel 6   Qwen Code extension
  channel 7   Codex plugin
  ```

  Der Bootstrap fügt nur Assistenten-Kontext hinzu (eine Kontextdatei, einen
  Command oder einen Skill), der die Engine über `npx` aufruft, sodass sonst
  nichts zurückbleibt. Die Erweiterungs-Hosts der Kanäle 5 und 6 bieten einen
  Deinstallationsbefehl; beim Plugin-Host von Kanal 7 deinstallieren Sie
  `apothem` in dessen Plugin-Browser.

  ```bash
  gemini extensions uninstall apothem   # channel 5
  qwen extensions uninstall apothem     # channel 6
  ```
- **Direkte Engine (Kanal 8)** — nichts zu deinstallieren; löschen Sie den Klon,
  sobald die Harness-Konfigurationen entfernt sind.
- **Backups und Zustand** — Installations-Backups liegen unter
  `~/.apothem/backups/` und das Installations-Ledger unter `~/.apothem/state/`.
  Beide bleiben begrenzt: Nach jeder Installation, jeder Deinstallation und
  jedem Rollback behält Apothem die neuesten 10 Installationsdatensätze pro
  Installationswurzel und die neuesten 10 Backup-Sätze pro Harness und löscht
  niemals ein Backup, das ein behaltener Datensatz noch benötigt, sodass sich
  die letzten 10 Installationen weiterhin zurückrollen lassen. Um weniger zu
  behalten, führen Sie
  [`apothem backups prune --keep N`](/docs/cli-reference/backups) aus (fügen
  Sie `--dry-run` hinzu, um zuerst zu sehen, was entfernt würde); es entfernt
  niemals das Backup, aus dem das Rollback der neuesten Installation eines
  Harness wiederherstellt. Sobald die Engine entfernt ist und Sie nichts mehr
  aus dem Verlauf benötigen, löschen Sie `~/.apothem/`.

## Was NICHT entfernt wird

- Das gemeinsame Profil-YAML unter `~/.config/apothem/profile.yaml` oder
  `--profile PATH` wird von `apothem uninstall` niemals entfernt.
- Nicht zugehörige, vom Operator verfasste Dateien in Harness-Verzeichnissen
  bleiben erhalten.
- Einträge, die Sie einer gemeinsam genutzten Einstellungsdatei hinzugefügt
  haben, bleiben erhalten: Ihre eigenen Berechtigungsregeln, MCP-Server und
  Hook-Handler bleiben bestehen. Die Deinstallation entfernt nur die Schlüssel
  und Listeneinträge, die das Installations-Ledger als Apothems eigene erfasst
  (siehe
  [Einstellungen](/docs/reference/settings#zusammenführen-mit-ihrer-eigenen-settings-datei)).
- Die gemeinsam genutzten Datenspeicher unter `.apothem/` an der
  Installationswurzel (`memory/`, `contexts/`, `learning/`) bleiben bestehen,
  solange ein anderer installierter Harness an derselben Wurzel sie noch
  verwendet. Die Deinstallation des letzten Harness an dieser Wurzel kopiert
  zuerst jeden Speicher nach `~/.apothem/backups/` und entfernt ihn dann
  mitsamt seinem gesamten Inhalt.
- Plan-Suiten unter `<project>/.apothem/plans/` (und dem veralteten `<project>/.plans/`) sind nicht betroffen.

## Verzeichnisse

Die Deinstallation entfernt außerdem die Verzeichnisse, die die Installation
erstellt hat (zum Beispiel ein `~/.claude/`, das vor der ersten Installation
nicht existierte), sobald sie leer sind. Ein Verzeichnis, das noch eine Datei
von Ihnen enthält oder Daten, die ein anderer installierter Harness verwendet,
bleibt bestehen. Verzeichnisse, die vor der Installation existierten, werden
niemals entfernt.

Um eine Harness-Wurzel vollständig zu bereinigen, entfernen Sie den
harness-nativen Pfad, der auf den [Harness-Referenzseiten](/docs/harnesses)
dokumentiert ist, nachdem Sie sich vergewissert haben, dass Sie alle
benutzerdefinierten Regeln, Helfer oder Profildateien gesichert haben, die Sie
behalten möchten.
