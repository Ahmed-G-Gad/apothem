Kiro liest die Steuerung aus einem `.kiro/steering/`-Verzeichnis mit Markdown-Dateien.
Der kiro-Adapter von Apothem rendert eine dedizierte `apothem-rules.md`-Steuerungsdatei
aus dem gemeinsamen Profil. Diese Seite stellt das Pflegen dieser Konfiguration von Hand
der Verwaltung mit Apothem gegenüber.

## Aufwandsvergleich

| Aufgabe | Manuelle Konfiguration | Von Apothem verwaltet |
| ---- | --------------- | --------------- |
| Steuerungsregeln verfassen | Jede Datei unter `.kiro/steering/` von Hand schreiben | Aus dem gemeinsamen Korpus gerendert |
| Fundamentdateien unberührt halten | Daran denken, `product.md` / `tech.md` / `structure.md` nicht zu überschreiben | Der Adapter schreibt nur `apothem-rules.md` |
| Regeln mit anderen Harnesses abgestimmt halten | Manuell, pro Werkzeug | Automatisch bei `apothem update` |
| Wiederverwendbare Skills und Befehle teilen | Jeden Skill-Ordner von Hand nach `~/.kiro/skills/` kopieren und die Kopien aktuell halten | Vom Adapter nach `~/.kiro/skills/` geschrieben, eine gemeinsame Kopie für alle Projekte, und bei `apothem update` aufgefrischt |
| Wiederverwendbare Helfer synchron halten | Jede Datei für benutzerdefinierte Agenten unter `.kiro/agents/` von Hand schreiben und die Werkzeugkategorien von Kiro nachverfolgen | Vierzehn Helfer mit übersetzten Werkzeugen nach `.kiro/agents/` geschrieben und bei `apothem update` aufgefrischt |
| Prüfen, ob die Konfiguration korrekt ist | Manuelle Inspektion | `apothem verify --harness kiro --project <path>` |

## Was Apothem verwaltet

Der kiro-Adapter rendert die geteilten Regeln in eine dedizierte
`apothem-rules.md`-Steuerungsdatei mit `inclusion: always`-Front-Matter und rührt die
vom Operator verfassten Fundamentdateien von Kiro nicht an. Außerdem schreibt er die
vierzehn Helfer von Apothem als benutzerdefinierte Kiro-Agenten in
`<project>/.kiro/agents/`, für Kiro IDE 1.0 und Kiro CLI V3. Kiro dokumentiert
Agent-Hooks, die der Adapter nicht schreibt, daher lebt die Schutzschranken-Absicht
in der Regelprosa statt an einem Tool-Aufruf-Abfangpunkt. Jede Änderung an den geteilten Regeln rendert die Datei
beim nächsten `apothem update` neu.

## Migrationspfad

1. Führen Sie `apothem profile init` aus, um das gemeinsame Profil zu erstellen, falls noch nicht geschehen.
2. Verschieben Sie die Regeln aus Ihrem vorhandenen `.kiro/steering/` in das gemeinsame Korpus.
3. Führen Sie `apothem install --harness kiro --project <path>` aus, um die Steuerungsdatei
   `apothem-rules.md` zu rendern.
4. Führen Sie `apothem verify --harness kiro --project <path>` aus, um zu bestätigen, dass die
   Konfiguration angekommen ist.
5. Verwenden Sie `apothem update --harness kiro --project <path>` für jede spätere Änderung.
