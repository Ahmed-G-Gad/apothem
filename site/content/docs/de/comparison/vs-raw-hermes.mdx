Hermes liest `~/.hermes/config.yaml`. Apothem schreibt die native
YAML-Konfiguration (und projiziert dabei das MCP-Inventar des Profils in
`mcp_servers`) und installiert gemeinsame Befehls- und Skill-Kohorten unter
`~/.hermes/.apothem/support/skills/`. Das eigene `skills.config` von Hermes ist
eine Liste von Registry-Paketen, daher verfasst Apothem es nicht.

## Status

**Vorschau.** Der Hermes-Adapter zielt auf die aktuell dokumentierte
Konfigurationsdatei und die Skill-Discovery-Oberfläche. Kohorten, die keine
Skills sind, bleiben Apothem-Unterstützungsmaterial.

## Aufwandsvergleich

| Aufgabe | Rohe Handkonfiguration | Von Apothem verwaltet |
| ---- | --------------- | --------------- |
| Wiederverwendbare Skills verfassen | Konfiguration und Skill-Verzeichnisse von Hand bearbeiten | Einmal im gemeinsamen Korpus schreiben |
| Kohorten mit anderen Harnesses abgestimmt halten | Manuell, je Werkzeug | Automatisch bei `apothem update` |
| Die Konfiguration installieren / entfernen | Manuell | `apothem install` / `apothem uninstall` |
| Prüfen, ob die Konfiguration korrekt ist | Manuelle Inspektion | `apothem verify --harness hermes` |

## Was Apothem verwaltet

Der Hermes-Adapter schreibt `config.yaml`, verpackt Apothem-Slash-Befehle als
Skills, kopiert Apothem-Skills in das referenzierte Unterstützungsverzeichnis
und hält Regeln, Templates, Agents und Hook-Material unter dem
Apothem-Unterstützungs-Teilbaum.

## Migrationspfad

1. Führen Sie `apothem profile init` aus, um das gemeinsame Profil zu
   erstellen, falls Sie das noch nicht getan haben.
2. Verschieben Sie wiederverwendbare Hermes-Skills oder Befehls-Prompts in das
   gemeinsame Korpus.
3. Führen Sie `apothem install --harness hermes` aus, um die native
   Konfiguration und das Unterstützungsverzeichnis für Skills zu rendern.
4. Führen Sie `apothem verify --harness hermes` aus, um zu bestätigen, dass die
   Konfiguration gelandet ist.
