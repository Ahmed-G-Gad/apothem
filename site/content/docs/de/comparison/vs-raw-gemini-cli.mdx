Gemini CLI liest eine einzige `GEMINI.md`-Regeldatei. Der gemini-cli-Adapter von
Apothem rendert sie aus dem gemeinsamen Profil. Diese Seite stellt die manuelle
Pflege dieser Konfiguration der Verwaltung mit Apothem gegenüber.

## Aufwandsvergleich

| Aufgabe | Manuelle Konfiguration | Von Apothem verwaltet |
| ---- | --------------- | --------------- |
| Regeln verfassen | Eine `GEMINI.md` von Hand bearbeiten | Gerendert: projektweite Leitlinien in `GEMINI.md`; Regeln unter `.gemini/.apothem/support/` |
| Regeln mit anderen Harnesses abgestimmt halten | Manuell, pro Werkzeug | Automatisch bei `apothem update` |
| Konfiguration installieren / entfernen | `GEMINI.md` von Hand schreiben und löschen | `apothem install` / `apothem uninstall` |
| Prüfen, ob die Konfiguration korrekt ist | Manuelle Inspektion | `apothem verify --harness gemini-cli --project <path>` |

## Was Apothem verwaltet

Der gemini-cli-Adapter schreibt einen durch Sentinel-Marker begrenzten Apothem-Block in `<project>/GEMINI.md`, der projektweite Leitlinien trägt und auf das Material von Apothem verweist. Regeln, Vorlagen und Hooks landen als Unterstützungsdateien unter `<project>/.gemini/.apothem/support/`, Befehle, Skills und Agenten unter `<project>/.gemini/`. Gemini CLI dokumentiert ein `hooks`-Objekt in `settings.json`, das im Besitz des Operators bleibt; daher registriert der Adapter keinen Hook, und die Absicht der Schutzplanken wird im Regeltext ausgedrückt und nicht an einem Abfangpunkt für Werkzeugaufrufe. Jede Änderung an den gemeinsamen Regeln rendert `GEMINI.md` beim nächsten `apothem update` neu.

## Migrationspfad

1. Führe `apothem profile init` aus, um das gemeinsame Profil zu erstellen, falls noch nicht geschehen.
2. Verschiebe die Regeln aus deiner vorhandenen `GEMINI.md` in den gemeinsamen Korpus.
3. Führe `apothem install --harness gemini-cli --project <path>` aus, um `GEMINI.md` zu rendern
   und zu schreiben.
4. Führe `apothem verify --harness gemini-cli --project <path>` aus, um zu bestätigen, dass die
   Konfiguration angekommen ist.
5. Verwende `apothem update --harness gemini-cli --project <path>` für jede spätere Änderung.
