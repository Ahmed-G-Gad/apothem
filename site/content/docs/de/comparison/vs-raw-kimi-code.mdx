Kimi Code reads project-root `AGENTS.md` as its instruction file and keeps
project configuration under `<project>/.kimi-code/`, including the
operator-owned `.kimi-code/mcp.json` MCP surface. You can author that
instruction file and its supporting cohorts by hand, per project, forever.
Apothem's kimi-code adapter renders the governance surface into `AGENTS.md` as a
managed block from the shared profile and keeps it consistent across every
harness and every project. This page contrasts hand-maintaining that config
against managing it with Apothem.

## Effort comparison

| Aufgabe | Manuelle Konfiguration | Von Apothem verwaltet |
| ---- | --------------- | --------------- |
| Die Anweisungsoberfläche `AGENTS.md` verfassen | Von Hand schreiben und je Projekt neu synchronisieren | Ein verwalteter Block, aus dem gemeinsamen Profil gerendert |
| Regeln, Befehle, Skills und Agenten synchron halten | Manuelles Kopieren je Projekt | Bei jeder Installation unter `<project>/.kimi-code/.apothem/support/` materialisiert |
| Vom Operator verfassten Text beim Aktualisieren bewahren | Manuelles Zusammenführen | Durch Sentinel-Marker begrenzter Block; vom Operator verfasster Text außerhalb davon bleibt erhalten |
| Regeln mit anderen Harnesses abgestimmt halten | Manuell, pro Werkzeug | Automatisch bei `apothem update` |
| Prüfen, ob die Konfiguration korrekt ist | Manuelle Inspektion | `apothem verify --harness kimi-code --project <path>` |

## What Apothem manages

The kimi-code adapter renders the shared rules and governance surface into the
project-root `AGENTS.md` managed block and installs the commands, skills, hooks,
agents, rules, and templates cohorts under `.kimi-code/.apothem/support/`. It does not
author `.kimi-code/mcp.json`; the MCP surface stays operator-owned. The rendered
instruction surface drives the project directly. Every change to the shared
rules re-renders the files on the next `apothem update`.

## Migration path

1. Führen Sie `apothem profile init` aus, um das gemeinsame Profil zu erstellen, falls noch nicht geschehen.
2. Verschieben Sie die Regeln aus Ihrer vorhandenen `AGENTS.md` in das gemeinsame Korpus.
3. Führen Sie `apothem install --harness kimi-code --project <path>` aus, um die Anweisungsoberfläche
   `AGENTS.md` und den Unterstützungs-Teilbaum `.kimi-code/.apothem/support/` zu rendern.
4. Führen Sie `apothem verify --harness kimi-code --project <path>` aus, um zu bestätigen, dass die
   Konfiguration angekommen ist.
5. Verwenden Sie `apothem update --harness kimi-code --project <path>` für jede spätere Änderung.
