Zed liest Agentenanweisungen aus einer einzigen flachen `.rules`-Datei im
Projektstamm (neben der `AGENTS.md` / `CLAUDE.md`-Familie). Der zed-Adapter von
Apothem erzeugt diese Datei aus dem gemeinsamen Profil. Diese Seite stellt das
Pflegen dieser Konfiguration von Hand der Verwaltung mit Apothem gegenüber.

## Aufwandsvergleich

| Aufgabe | Manuelle Konfiguration | Von Apothem verwaltet |
| ---- | --------------- | --------------- |
| Anweisungen verfassen | Die `.rules`-Datei von Hand schreiben | Aus dem gemeinsamen Korpus gerendert |
| Eine frühere `.rules` bewahren | Selbst daran denken, sie vorab beiseitezukopieren | Der Adapter sichert die vorhandene Datei vor dem Ersetzen |
| Regeln mit anderen Harnesses abgestimmt halten | Manuell, pro Werkzeug | Automatisch bei `apothem update` |
| Wiederverwendbare Skills und Befehle teilen | Jeden Skill-Ordner von Hand nach `~/.agents/skills/` kopieren und die Kopien aktuell halten | Vom Adapter nach `~/.agents/skills/` geschrieben, eine gemeinsame Kopie für alle Projekte, und bei `apothem update` aufgefrischt |
| Prüfen, ob die Konfiguration korrekt ist | Manuelle Inspektion | `apothem verify --harness zed --project <path>` |

## Was Apothem verwaltet

Der zed-Adapter erzeugt die geteilten Regeln in der flachen `.rules`-Datei des
Projektstamms. Zed hat keinen PreToolUse-Hook, daher lebt die Schutzabsicht im
Prosatext der Regel statt an einem Abfangpunkt für Werkzeugaufrufe. Die globale
Anweisungsdatei `~/.config/zed/AGENTS.md` und der MCP-Kontextserver-Block aus
`.zed/settings.json` gehören dem Operator und bleiben unangetastet. Jede Änderung
an den geteilten Regeln erzeugt die Datei beim nächsten `apothem update` neu.

## Migrationspfad

1. Führen Sie `apothem profile init` aus, um das gemeinsame Profil zu erstellen, falls noch nicht geschehen.
2. Verschieben Sie die Anweisungen aus Ihrer vorhandenen `.rules`-Datei (und jeden projektspezifischen
   Inhalt von `AGENTS.md`, den Sie teilen möchten) in das gemeinsame Korpus.
3. Führen Sie `apothem install --harness zed --project <path>` aus, um die `.rules`-Datei zu
   rendern. Ihre bisherige `.rules`-Datei wird vorher gesichert.
4. Führen Sie `apothem verify --harness zed --project <path>` aus, um zu bestätigen, dass die
   Konfiguration angekommen ist.
5. Verwenden Sie `apothem update --harness zed --project <path>` für jede spätere Änderung.
