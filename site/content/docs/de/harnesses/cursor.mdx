**Anbieter:** Anysphere
**Installationsname:** `cursor`
**Status:** GA
**Native Konfiguration:** `.cursor/rules/` im Projektstammverzeichnis

## Installation

```bash
apothem install --harness cursor --project /path/to/project
```

Der Adapter rendert aus der gemeinsamen Regel- und Governance-Oberfläche von
Apothem eine einzelne `.mdc`-Regeldatei auf Projektebene.

**Geschriebene Dateien:** `<project>/.cursor/rules/apothem-rules.mdc`

Diese Datei ist die gesamte Installation: Neben ihr wird keine Regel-, Skill-,
Command-, Template- oder Hook-Datei abgelegt, daher sagt die Datei dies selbst,
statt auf Apothem-Dateien zu verweisen, die sich nicht im Projekt befinden.

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest das gemeinsame Profil von Apothem und rendert bei jedem Lauf
von `apothem install` oder `apothem update` die Projekt-Regeldatei. Das
gemeinsame Profil ist die Quelle der Wahrheit; projektlokale Änderungen an der
generierten Datei werden gesichert, bevor die nächste Synchronisierung den von
Apothem verwalteten Inhalt ersetzt.

Die Datei beginnt mit ihrem YAML-Frontmatter (`description`, `globs`,
`alwaysApply: true`), weil Cursor den Typ einer Regel nur aus dem Frontmatter
am Anfang der Datei liest. Der von Apothem verwaltete Block folgt darauf; Text,
den Sie nach dem Block hinzufügen, bleibt bei jeder Synchronisierung erhalten.

## Kompatibilitätshinweise

Cursor 0.45+ unterstützt Anweisungen auf Projektebene über `.cursor/rules/`.
Der Adapter schreibt standardmäßig in das projektbezogene Verzeichnis
`.cursor/rules/`; Cursor hat keinen dokumentierten, dateibasierten Pfad für
benutzerweite globale Regeln, den dieser Adapter verwalten könnte.

## Verifizierung

```bash
apothem verify --harness cursor --project /path/to/project
```

Der Befehl verify bestätigt, dass:

1. die native Konfiguration am erwarteten Pfad existiert.
2. alle Pflichtfelder aus dem gemeinsamen Profil vorhanden sind.
3. die adapterspezifische Verifizierungsroutine Erfolg meldet.

## Aktualisierung

```bash
apothem update --harness cursor --project /path/to/project
```

Leitet die Projekt-Regeldatei aus dem aktuellen Zustand des gemeinsamen Profils
neu ab.

## Deinstallation

```bash
apothem uninstall --harness cursor --project /path/to/project
```

Entfernt die vom Adapter geschriebenen nativen Konfigurationsdateien.
Die YAML-Datei des gemeinsamen Profils und die Apothem-Engine bleiben unberührt.

## Konformitäts-Gate

```bash
python -m apothem.conformity.gate --all .
```

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness cursor --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness cursor --project /path/to/project` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness cursor --project /path/to/project` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Vorschau der Installation, ohne Dateien zu schreiben. |
