**Anbieter:** Zed Industries
**Installationsname:** `zed`
**Status:** GA
**Native Konfiguration:** `<project>/.rules`

## Installation

```bash
apothem install --harness zed --project /path/to/project
```

Der Adapter schreibt aus der gemeinsamen Regel- und Governance-Oberfläche von
Apothem eine Zed-Anweisungsdatei mit Projektgeltungsbereich. Zed liest eine
einzige Projekt-Anweisungsdatei, nämlich den ersten Treffer in dieser Liste:

```text
.rules
.cursorrules
.windsurfrules
.clinerules
.github/copilot-instructions.md
AGENT.md
AGENTS.md
CLAUDE.md
GEMINI.md
```

Es gibt kein werkzeugspezifisches Regelverzeichnis, daher landet die gesamte
Apothem-Oberfläche in der flachen Datei `.rules` an der Spitze dieser Liste.

**Geschriebene Dateien:** `<project>/.rules`

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest Apothems gemeinsames Profil und rendert die Projektdatei
`.rules` bei jedem Lauf von `apothem install` oder `apothem update`. Das
gemeinsame Profil ist die Quelle der Wahrheit; eine bereits vorhandene `.rules`
(oder projektlokale Änderungen an der generierten Datei) wird gesichert, bevor
die nächste Synchronisierung den von Apothem verwalteten Inhalt ersetzt.

## Kompatibilitätshinweise

Zed nennt `AGENTS.md` seine primäre Anweisungsdatei und behält die Projektdatei
`.rules` als unterstützte Kompatibilitätsdatei bei
([Zed-Anweisungen](https://zed.dev/docs/ai/instructions)). Weil Zed nur den
ersten Treffer liest, verdeckt eine neue `.rules` eine `AGENTS.md`, eine
`CLAUDE.md` oder jede andere weiter unten in der Liste stehende Datei, auf die
sich das Projekt bereits stützt. Die Installation bearbeitet diese Dateien
niemals. Wenn `.rules` nur den Apothem-Block enthält und eine Datei mit
niedrigerer Priorität Ihren Text enthält, geben Installation und Aktualisierung
eine Warnung aus, die die verdeckte Datei nennt; kopieren Sie die Anweisungen,
die Sie benötigen, außerhalb des Apothem-Blocks in `.rules`, damit sie in Zed
erhalten bleiben.

Die globale Anweisungsdatei `~/.config/zed/AGENTS.md` und der
MCP-Context-Server-Block (`.zed/settings.json` `context_servers`) gehören dem
Operator; Apothem schreibt sie nicht.

## Verifizierung

```bash
apothem verify --harness zed --project /path/to/project
```

Der verify-Befehl bestätigt, dass:

1. Die native Konfiguration am erwarteten Pfad existiert.
2. Alle Pflichtfelder aus dem gemeinsamen Profil vorhanden sind.
3. Die adapterspezifische Verifizierungsroutine Erfolg meldet.

## Aktualisierung

```bash
apothem update --harness zed --project /path/to/project
```

Leitet die Projektdatei `.rules` aus dem aktuellen Zustand des gemeinsamen
Profils neu ab.

## Deinstallation

```bash
apothem uninstall --harness zed --project /path/to/project
```

Entfernt die vom Adapter geschriebene native Konfigurationsdatei; zuvor wird sie
in eine Sicherung mit Zeitstempel umbenannt. Das YAML des gemeinsamen Profils
und die Apothem-Engine bleiben unberührt.

## Konformitäts-Gate

```bash
python -m apothem.conformity.gate --all .
```

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness zed --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness zed --project /path/to/project` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness zed --project /path/to/project` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Installation in der Vorschau anzeigen, ohne Dateien zu schreiben. |
