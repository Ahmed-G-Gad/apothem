**Anbieter:** AWS
**Installationsname:** `kiro`
**Status:** GA
**Native Konfiguration:** `<project>/.kiro/steering/apothem-rules.md`

## Installation

```bash
apothem install --harness kiro --project /path/to/project
```

Der Adapter schreibt aus der gemeinsamen Regel- und Governance-Oberfläche von
Apothem eine Kiro-Steering-Datei mit Projektgeltungsbereich.

**Geschriebene Dateien:** `<project>/.kiro/steering/apothem-rules.md`

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest Apothems gemeinsames Profil und rendert die Steering-Datei des
Projekts bei jedem Lauf von `apothem install` oder `apothem update`. Das
gemeinsame Profil ist die Quelle der Wahrheit; projektlokale Änderungen an der
generierten Datei werden gesichert, bevor die nächste Synchronisierung den von
Apothem verwalteten Inhalt ersetzt.

Die Datei beginnt mit ihrem Frontmatter `inclusion: always`, weil Kiro verlangt,
dass die Inclusion-Konfiguration der erste Inhalt der Datei ist. Der von Apothem
verwaltete Block folgt darauf; Text, den Sie nach dem Block hinzufügen, bleibt
bei jeder Synchronisierung erhalten.

## Kompatibilitätshinweise

Kiros Steering-Oberfläche hat Projektgeltungsbereich unter `.kiro/steering/`.
Der Adapter schreibt eine eigene Steering-Datei `apothem-rules.md` mit dem
Frontmatter `inclusion: always` und überschreibt niemals Kiros vom Operator
verfasste Grundlagendateien (`product.md`, `tech.md`, `structure.md`).
Kiro-Specs (`.kiro/specs/`) und Agent-Hooks gehören dem Operator; Apothem
schreibt sie nicht.

## Verifizierung

```bash
apothem verify --harness kiro --project /path/to/project
```

Der verify-Befehl bestätigt, dass:

1. Die native Konfiguration am erwarteten Pfad existiert.
2. Alle Pflichtfelder aus dem gemeinsamen Profil vorhanden sind.
3. Die adapterspezifische Verifizierungsroutine Erfolg meldet.

## Aktualisierung

```bash
apothem update --harness kiro --project /path/to/project
```

Leitet die Steering-Datei des Projekts aus dem aktuellen Zustand des gemeinsamen
Profils neu ab.

## Deinstallation

```bash
apothem uninstall --harness kiro --project /path/to/project
```

Entfernt die vom Adapter geschriebenen nativen Konfigurationsdateien.
Das YAML des gemeinsamen Profils und die Apothem-Engine bleiben unberührt.

## Konformitäts-Gate

```bash
python -m apothem.conformity.gate --all .
```

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness kiro --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness kiro --project /path/to/project` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness kiro --project /path/to/project` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Installation in der Vorschau anzeigen, ohne Dateien zu schreiben. |
