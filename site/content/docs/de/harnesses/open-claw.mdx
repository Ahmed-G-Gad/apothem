**Anbieter:** Open-Claw
**Installationsname:** `open-claw`
**Status:** Vorschau
**Native Konfiguration:** `~/.openclaw/openclaw.json`

## Installation

```bash
apothem install --harness open-claw
```

Der Adapter schreibt die benutzerweite globale Konfigurationsdatei von OpenClaw,
projiziert das gemeinsame Profil in ein Profildokument und installiert die
Apothem-Unterstützungskohorten unter dem Harness-Wurzelverzeichnis. Die native
Konfiguration von OpenClaw ist JSON; der Materializer rendert ein leeres
JSON-Objekt, und eine bestehende Datei behält ihre Schlüssel.

**Geschriebene Dateien:** `~/.openclaw/openclaw.json`, das Profildokument
`~/.openclaw/apothem/rules/00-apothem-profile.md` und Unterstützungsdateien unter
`~/.openclaw/.apothem/support/`

Das Profildokument endet mit einem Abschnitt zu den Apothem-Unterstützungsdateien,
der das absolute Verzeichnis unter `~/.openclaw/.apothem/support/` nennt, gegen
das jeder Verweis im Repository-Stil (`rules/<name>.md`, `templates/...`,
`hooks/...`) aufgelöst wird.

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest Apothems gemeinsames Profil, verfasst aber keine
Konfigurationsschlüssel: Eine neue oder leere `openclaw.json` wird als leeres
Objekt geschrieben, und eine bestehende Datei behält ihre Schlüssel. Identität,
Präferenzen und Regeln des Profils gehen in das Profildokument. Gemeinsame
Commands, Skills, Regeln, Templates und Hook-Prompts werden als
Unterstützungsmaterial unter `~/.openclaw/.apothem/support/` installiert.

## Kompatibilitätshinweise

Vorschau-Adapter. OpenClaw lädt den Unterstützungs-Teilbaum und das Profildokument nicht von sich aus: Weder seine Skill-Speicherorte noch seine Workspace-Anweisungsdateien noch seine Konfiguration verweisen dorthin, sodass OpenClaw nach der Installation ohne Apothems Regeln, Skills oder MCP-Server läuft. OpenClaw liest Skills aus den Ordnern `skills/` und `.agents/skills/` seines Workspace, aus `~/.agents/skills` und aus seinem Zustandsverzeichnis und filtert sie anschließend über die Zulassungsliste der Skill-Namen unter `agents.defaults.skills`. `skills.load.extraDirs` ist kein Skill-Lader; daher werden die Apothem-Skills unter `~/.openclaw/.apothem/support/skills` erst geladen, wenn Sie sie in einen dieser Ordner legen und in dieser Zulassungsliste benennen. `apothem update` behält die Schlüssel bei, die Sie zu `openclaw.json` hinzufügen. MCP-Server stehen im Block `mcp.servers` der OpenClaw-Konfiguration; diesen verwalten Sie mit `openclaw mcp add` und den zugehörigen Unterbefehlen. Der Adapter schreibt dort keine Einträge. (Verhalten von OpenClaw gemäß seiner Dokumentation zu [Skills](https://docs.openclaw.ai/tools/skills) und zur [MCP-CLI](https://docs.openclaw.ai/cli/mcp), gelesen am 2026-10-02.)

## Verifizierung

```bash
apothem verify --harness open-claw
```

Der Befehl verify bestätigt Folgendes:

1. Die native Konfiguration existiert am erwarteten Pfad.
2. Jedes verwaltete Ziel existiert; verwaltete Dateien sind nicht leer, und
   JSON- oder YAML-Konfigurationen lassen sich parsen. Fügen Sie `--profile PATH`
   hinzu, um außerdem zu bestätigen, dass die installierten Dateien zu diesem
   Profil passen.
3. Die adapterspezifische Verifizierungsroutine meldet Erfolg.

## Aktualisierung

```bash
apothem update --harness open-claw
```

Leitet das Profildokument aus dem aktuellen Zustand des gemeinsamen Profils neu
ab und aktualisiert die Unterstützungsdateien; `openclaw.json` behält die
Schlüssel, die bereits darin stehen. Führen Sie den Befehl aus, nachdem Sie
`~/.config/apothem/profile.yaml` bearbeitet oder das installierte Apothem-Paket
aktualisiert haben.

## Deinstallation

```bash
apothem uninstall --harness open-claw
```

Entfernt, was der Adapter hinzugefügt hat: das Profildokument und den
Unterstützungs-Teilbaum. Ihre eigenen Schlüssel in `openclaw.json` bleiben erhalten,
und die Datei wird nur gelöscht, wenn Apothem sie angelegt hat und nichts von
Ihnen übrig ist. Die YAML-Datei des gemeinsamen Profils und die Apothem-Engine
bleiben unberührt.

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness open-claw` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness open-claw` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Apothem schreibt keine Schlüssel in `openclaw.json` und behält die bereits darin enthaltenen Schlüssel bei; daher gelangt Profilinhalt nicht dorthin. Profilinhalt landet in `~/.openclaw/apothem/rules/00-apothem-profile.md`: Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann den Befehl unter [Aktualisierung](#aktualisierung) erneut aus |

| Flag | Standard | Beschreibung |
