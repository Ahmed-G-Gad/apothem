**Anbieter:** Devin Desktop (vormals Codeium Windsurf)
**Installationsname:** `windsurf`
**Status:** GA
**Native Konfiguration:** `<project>/.devin/rules/apothem-rules.md`

Windsurf ist jetzt Devin Desktop, und `.devin/rules/` ist der bevorzugte
Speicherort für Workspace-Regeln (er hat Vorrang vor `.windsurf/rules/`).

## Installation

```bash
apothem install --harness windsurf --project /path/to/project
```

Der Adapter schreibt aus der gemeinsamen Regel- und Governance-Oberfläche von
Apothem eine Windsurf-Regeldatei mit Projektgeltungsbereich.

**Geschriebene Dateien:** `<project>/.devin/rules/apothem-rules.md`

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest Apothems gemeinsames Profil und rendert die Regeldatei des
Projekts bei jedem Lauf von `apothem install` oder `apothem update`. Das
gemeinsame Profil ist die Quelle der Wahrheit; projektlokale Änderungen an der
generierten Datei werden gesichert, bevor die nächste Synchronisierung den von
Apothem verwalteten Inhalt ersetzt.

Die Datei beginnt mit ihrem Frontmatter `trigger: always_on`, das den
Aktivierungsmodus der Regel festlegt. Der von Apothem verwaltete Block folgt
darauf; Text, den Sie nach dem Block hinzufügen, bleibt bei jeder
Synchronisierung erhalten.

## Kompatibilitätshinweise

Die aktuelle Regel-Oberfläche von Windsurf hat Projektgeltungsbereich unter
`.devin/rules/` (der bevorzugte Speicherort, der Vorrang vor dem
Abwärtskompatibilitäts-Fallback `.windsurf/rules/` hat). Workflows und
maschinenlokale Memories gehören dem Operator; Apothem schreibt sie nicht. Die
Einzeldatei-Form `.windsurfrules` wird absichtlich nicht geschrieben.

## Verifizierung

```bash
apothem verify --harness windsurf --project /path/to/project
```

Der Befehl verify bestätigt Folgendes:

1. Die native Konfiguration existiert am erwarteten Pfad.
2. Jedes verwaltete Ziel existiert; verwaltete Dateien sind nicht leer, und
   JSON- oder YAML-Konfigurationen lassen sich parsen. Fügen Sie `--profile PATH`
   hinzu, um außerdem zu bestätigen, dass die installierten Dateien zu diesem
   Profil passen.
3. Die adapterspezifische Verifizierungsroutine meldet Erfolg.

## Aktualisierung

```bash
apothem update --harness windsurf --project /path/to/project
```

Leitet die Regeldatei des Projekts aus dem aktuellen Zustand des gemeinsamen
Profils neu ab.

## Deinstallation

```bash
apothem uninstall --harness windsurf --project /path/to/project
```

Entfernt den Apothem-Block und das Frontmatter, das Apothem darüber geschrieben
hat, aus `<project>/.devin/rules/apothem-rules.md` und behält jeden anderen Text
darin. Die Datei wird nur gelöscht, wenn darin nichts anderes mehr übrig ist.
Vor der Änderung wird eine mit Zeitstempel versehene Kopie der Datei unter
`~/.apothem/backups/` gespeichert; im Projekt bleibt keine Sicherungsdatei
zurück. Die YAML-Datei des gemeinsamen Profils und die Apothem-Engine bleiben
unberührt.

## Konformitäts-Gate

```bash
python -m apothem.conformity.gate --all .
```

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness windsurf --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness windsurf --project /path/to/project` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness windsurf --project /path/to/project` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Vorschau der Installation, ohne Dateien zu schreiben. |
