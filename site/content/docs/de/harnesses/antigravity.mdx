**Anbieter:** Antigravity
**Installationsname:** `antigravity`
**Status:** Vorschau
**Native Konfiguration:** `~/.gemini/GEMINI.md` sowie
`~/.gemini/antigravity-cli/plugins/apothem/`

## Installation

```bash
apothem install --harness antigravity
```

Der Adapter rendert das gemeinsame Profil nach `~/.gemini/GEMINI.md` und
installiert die Apothem-Unterstützungskohorten als Antigravity-CLI-Plugin.

**Geschriebene Dateien:** `~/.gemini/GEMINI.md`,
`~/.gemini/antigravity-cli/plugins/apothem/plugin.json`,
`~/.gemini/antigravity-cli/plugins/apothem/skills/`,
`~/.gemini/antigravity-cli/plugins/apothem/rules/`,
konvertierte lokale Helferdefinitionen innerhalb des Plugins,
`~/.gemini/antigravity-cli/plugins/apothem/.apothem/support/templates/` und
`~/.gemini/antigravity-cli/plugins/apothem/.apothem/support/hooks/`.

Der Apothem-Block in `~/.gemini/GEMINI.md` endet mit einem Abschnitt zu den
Apothem-Unterstützungsdateien, der das absolute Verzeichnis nennt, gegen das
jeder Verweis im Repository-Stil aufgelöst wird: `rules/<name>.md` unter dem
`rules/` des Plugins sowie `templates/...` und `hooks/...` unter dem
`.apothem/support/` des Plugins.

**Plugin-Regeln.** Antigravity verwirft jede Datei im `rules/`-Verzeichnis
eines Plugins, die nicht mit einem gültigen `trigger` beginnt
([Antigravity-Dokumentation zu Regeln](https://antigravity.google/docs/rules)),
daher wird jede Apothem-Regel bei der Installation konvertiert. Eine Regel, die
immer gilt, erhält `trigger: always_on`; eine auf Pfade beschränkte Regel
erhält `trigger: glob` mit denselben Mustern in `globs`; jede andere Regel
erhält `trigger: model_decision`. Jede Regel behält ihre `description`.
Antigravity teilt ein Budget von 20.000 Token auf die stets aktiven Regeln auf
und wandelt jenseits dieses Budgets die größten in Verweise um, die bei Bedarf
geladen werden.

**Plugin-Manifest.** `plugin.json` enthält nur `name` und `description`, die
beiden Schlüssel, die das Plugin-Schema von Antigravity zulässt.

**Plugin-Helfer.** Helferdefinitionen im `agents/`-Verzeichnis des Plugins
tragen `name` und `description`. Die `tools`-Liste von Antigravity verwendet
eigene Werkzeugnamen, und die Dokumentation warnt, dass ein unbekannter Name
den Subagent hängen lassen kann; daher wird keine Werkzeugliste ausgegeben, und
die Helfer erben die Werkzeuge des übergeordneten Agents. Weil auf Antigravity
nichts eine Nur-Lese-Beschränkung durchsetzt, entfällt in den Beschreibungen
dieser Helfer die Kennzeichnung „read-only“.

**Gemeinsamer Benutzeranker.** `~/.gemini/GEMINI.md` ist zugleich der Anker
auf Benutzerebene für Werkzeuge der Gemini-Familie. Der Antigravity-Adapter
hält sein zusätzliches Apothem-Material innerhalb des `apothem`-Plugins unter
`~/.gemini/antigravity-cli/plugins/`, sodass er keine generischen
Projektverzeichnisse von Gemini CLI beansprucht. Weil mehr als ein Werkzeug
`~/.gemini/GEMINI.md` lädt, ist der Apothem-Block dort als globale Anleitung
geschrieben, die kein einzelnes Werkzeug als Leser nennt.

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest das gemeinsame Profil von Apothem und rendert bei jedem Lauf
von `apothem install` oder `apothem update` den Anweisungsanker sowie die
Unterstützungskohorten.

## Kompatibilitätshinweise

Vorschau-Adapter. Der `GEMINI.md`-Anker ist aktiver Anweisungsinhalt; das
Antigravity-Plugin bewahrt konvertierte Command-Skills, wiederverwendbare
Skills, lokale Helferdefinitionen, Regeln, Templates und
Hook-Unterstützungsmaterial in einem klar abgegrenzten, Apothem-eigenen
Namensraum auf.
Hook-Dateien werden erst dann als aktive Antigravity-Hook-Ereignisse
registriert, wenn der Adapter über eine Schema-Übersetzungsschicht für das
`hooks.json` von Antigravity verfügt.

## Verifizierung

```bash
apothem verify --harness antigravity
```

Der Befehl verify bestätigt, dass:

1. die native Kontextdatei am erwarteten Pfad existiert.
2. die Metadaten des Apothem-Antigravity-CLI-Plugins existieren und den
   Plugin-Namen `apothem` deklarieren.

## Aktualisierung

```bash
apothem update --harness antigravity
```

Leitet die native Konfiguration aus dem aktuellen Zustand des gemeinsamen
Profils neu ab. Führen Sie den Befehl aus, nachdem Sie
`~/.config/apothem/profile.yaml` bearbeitet oder das installierte Apothem-Paket
aktualisiert haben.

## Deinstallation

```bash
apothem uninstall --harness antigravity
```

Entfernt die vom Adapter geschriebenen nativen Konfigurationsdateien.
Die YAML-Datei des gemeinsamen Profils und die Apothem-Engine bleiben unberührt.

## Konformitäts-Gate

```bash
python -m apothem.conformity.gate --all .
```

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness antigravity` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness antigravity` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness antigravity` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Vorschau der Installation, ohne Dateien zu schreiben. |
