**Anbieter:** Google
**Installationsname:** `gemini-cli`
**Status:** GA
**Native Konfiguration:** projektlokale `GEMINI.md` und `.gemini/`

## Installation

```bash
apothem install --harness gemini-cli --project /path/to/project
```

Der Adapter arbeitet auf Projektebene. Er installiert die `GEMINI.md` des
Projekts, konvertiert Apothem-Commands in Gemini-TOML-Slash-Commands,
normalisiert lokale Helferdefinitionen und legt nicht native
Unterstützungskohorten unter `.gemini/.apothem/support/` ab.
Auch andere Coding-Werkzeuge lesen eine `GEMINI.md` im Projekt, daher ist der
Apothem-Block darin als projektweite Anleitung geschrieben, die kein einzelnes
Werkzeug als Leser nennt.

**Geschriebene Dateien:**

```text
GEMINI.md
.gemini/commands/*.toml
.gemini/agents/*.md
.gemini/skills/
.gemini/.apothem/support/
```

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest die gemeinsamen Kohorten von Apothem und leitet jede über
eine Gemini-kompatible Oberfläche. Markdown-Regeln, Templates und
Hook-Material verbleiben unter `.gemini/.apothem/support/`, weil sie
Unterstützungsmaterial sind und kein Gemini-natives Regelverzeichnis.
Der Apothem-Block in `GEMINI.md` endet mit einem Abschnitt zu den
Apothem-Unterstützungsdateien, der relativ zum Projektstammverzeichnis das
Verzeichnis unter `.gemini/.apothem/support/` nennt, gegen das jeder Verweis im
Repository-Stil (`rules/<name>.md`, `templates/...`, `hooks/...`) aufgelöst
wird. Die Pfade sind relativ, damit eine committete `GEMINI.md` keinen
maschinenspezifischen Pfad enthält.

Jeder konvertierte Command in `.gemini/commands/` enthält eine `description`
und einen `prompt`. Der Prompt besteht nur aus den Anweisungen des Commands;
die Apothem-Metadaten am Anfang der Quelldatei (Version, Werkzeugliste und
ähnliche Felder) werden weggelassen, sodass das Modell sie niemals als
Anweisungen liest. Gemini führt einen benutzerdefinierten Command nur aus, wenn
Sie ihn eingeben.

Helferdefinitionen in `.gemini/agents/` behalten ihre Werkzeugbeschränkungen
und ihr Turn-Limit: Die `tools`-Freigabe der Quelle, abzüglich
`disallowedTools`, wird zu einer Gemini-`tools`-Erlaubnisliste aus
Gemini-Werkzeugnamen, und `maxTurns` wird zu `max_turns`. Ein Nur-Lese-Helfer
erhält daher kein Werkzeug `write_file` oder `replace`. Es wird kein Modell
gesetzt, sodass jeder Helfer das Modell der Sitzung erbt.

## Kompatibilitätshinweise

`~/.gemini/` bleibt Gebiet auf Benutzerebene für Werkzeuge, die ein globales
Gemini-Profil verwenden. Der Gemini CLI-Adapter schreibt nur in das über
`--project` übergebene Projekt.

## Verifizierung

```bash
apothem verify --harness gemini-cli --project /path/to/project
```

Der Befehl verify bestätigt Folgendes:

1. Die native Konfiguration existiert am erwarteten Pfad.
2. Jedes verwaltete Ziel existiert; verwaltete Dateien sind nicht leer, und
   JSON- oder YAML-Konfigurationen lassen sich parsen. Fügen Sie `--profile PATH`
   hinzu, um außerdem zu bestätigen, dass die installierten Dateien zu diesem
   Profil passen.
3. Die adapterspezifische Verifizierungsroutine meldet Erfolg.

## Aktualisierung

```bash
apothem update --harness gemini-cli --project /path/to/project
```

Aktualisiert `GEMINI.md`, die konvertierten Commands, die lokalen
Helferdefinitionen, die installierten Skills und den Unterstützungs-Teilbaum
`.gemini/.apothem/support/`.

## Deinstallation

```bash
apothem uninstall --harness gemini-cli --project /path/to/project
```

Entfernt den Apothem-Block aus `<project>/GEMINI.md` und behält jeden anderen
Text darin. Die Datei wird nur gelöscht, wenn darin nichts anderes mehr übrig
ist. Entfernt außerdem die Apothem-Dateien in `<project>/.gemini/commands/`,
`<project>/.gemini/skills/`, `<project>/.gemini/agents/` und
`<project>/.gemini/.apothem/support/`; andere Dateien in diesen Ordnern bleiben
bestehen. Vor der Änderung wird von jeder Datei eine mit Zeitstempel versehene
Kopie unter `~/.apothem/backups/` gespeichert; im Projekt bleibt keine
Sicherungsdatei zurück. Die YAML-Datei des gemeinsamen Profils und die
Apothem-Engine bleiben unberührt.

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness gemini-cli --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness gemini-cli --project /path/to/project` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness gemini-cli --project /path/to/project` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Vorschau der Installation, ohne Dateien zu schreiben. |
