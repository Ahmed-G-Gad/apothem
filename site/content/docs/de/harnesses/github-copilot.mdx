**Anbieter:** GitHub / Microsoft
**Installationsname:** `github-copilot`
**Status:** GA
**Native Konfiguration:** `<project>/.github/copilot-instructions.md`

## Installation

```bash
apothem install --harness github-copilot --project /path/to/project
```

Der Adapter leitet die Projekt-Anweisungsdatei aus der gemeinsamen Regel- und
Governance-Oberfläche von Apothem ab.

**Geschriebene Dateien:** `<project>/.github/copilot-instructions.md`

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest das gemeinsame Profil von Apothem und rendert bei jedem Lauf
von `apothem install` oder `apothem update` die repositoryweite
Copilot-Anweisungsdatei. Das gemeinsame Profil ist die Quelle der Wahrheit;
projektlokale Änderungen an der generierten Datei werden gesichert, bevor die
nächste Synchronisierung den von Apothem verwalteten Inhalt ersetzt.

Innerhalb des Apothem-Blocks steht der aus Ihrem Profil gerenderte Abschnitt
(Operator, Präferenzen, benutzerdefinierte Regeln, per Opt-in aktivierte
Verhaltensweisen, MCP-Servernamen) an erster Stelle, vor dem gemeinsamen
Governance-Text. GitHub weist darauf hin, dass kürzere Anweisungsdateien mit
größerer Wahrscheinlichkeit vom Code-Review vollständig verarbeitet werden
([Code-Review anpassen](https://docs.github.com/en/copilot/tutorials/customize-code-review)),
daher steht der Teil, der spezifisch für Sie ist, am Anfang der Datei.

## Kompatibilitätshinweise

GitHub Copilot stellt keinen dateibasierten, benutzerweiten globalen
Anweisungspfad bereit, den dieser Adapter verwalten könnte. Apothem zielt auf
die dokumentierte Anweisungsdatei auf Projektebene und überlässt die
Benutzereinstellungen auf IDE-Ebene dem Operator.

Apothem behandelt `copilot-instructions.md` als eine Stimme unter den
Assistenten-Anweisungsoberflächen des Projekts: Die oberflächenübergreifende
Kohärenzprüfung des Konformitäts-Gates verifiziert, dass die gemeinsamen
Aussagen dieser Datei semantisch mit den anderen Anweisungsdateien des Projekts
übereinstimmen, sodass Copilot niemals Anleitungen erhält, die dem
widersprechen, was der Rest der Toolchain liest.

## Verifizierung

```bash
apothem verify --harness github-copilot --project /path/to/project
```

Der Befehl verify bestätigt, dass:

1. Die native Konfiguration liegt am erwarteten Pfad.
2. Jedes verwaltete Ziel existiert; verwaltete Dateien sind nicht leer, und JSON- oder YAML-Konfigurationen lassen sich parsen. Fügen Sie `--profile PATH` hinzu, um außerdem zu bestätigen, dass die installierten Dateien zu diesem Profil passen.
3. Die adapterspezifische Verifizierungsroutine meldet Erfolg.

## Aktualisierung

```bash
apothem update --harness github-copilot --project /path/to/project
```

Leitet die Projekt-Anweisungsdatei aus dem aktuellen Zustand des gemeinsamen
Profils neu ab.

## Deinstallation

```bash
apothem uninstall --harness github-copilot --project /path/to/project
```

Entfernt die vom Adapter geschriebenen nativen Konfigurationsdateien.
Die YAML-Datei des gemeinsamen Profils und die Apothem-Engine bleiben unberührt.

## Konformitäts-Gate

```bash
python -m apothem.conformity.gate --all .
```

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness github-copilot --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness github-copilot --project /path/to/project` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness github-copilot --project /path/to/project` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Vorschau der Installation, ohne Dateien zu schreiben. |
