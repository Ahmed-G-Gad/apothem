**Anbieter:** Z.ai
**Installationsname:** `glm`
**Status:** GA
**Native Konfiguration:** `<project>/.apothem/providers/glm.toml`

GLM (Z.ai) ist ein **Modell-Backend**, kein Harness. Z.ai liefert keine eigene
GLM-Kommandozeile aus; stattdessen wird ein Werkzeug, das das
Anthropic-kompatible oder das OpenAI-kompatible Protokoll spricht, auf GLM
ausgerichtet, indem eine Backend-Basis-URL und ein Schlüssel gesetzt werden.
Der `glm`-Adapter schreibt eine Provider-Konfigurationsdatei, die beide
Kompatibilitätsoberflächen festhält, sodass sich jedes kompatible Werkzeug mit
der GLM-Modellfamilie verbinden lässt.

## Installation

```bash
apothem install --harness glm --project /path/to/project
```

Der Adapter schreibt eine einzelne Provider-Datei auf Projektebene, die die
Endpunkte des GLM-Backends und vom Operator konfigurierbare Platzhalter
festhält.

**Geschriebene Dateien:** `<project>/.apothem/providers/glm.toml`

## Zuordnung von Profil zu nativer Konfiguration

Die Provider-Datei hält zwei Backends fest. Das Anthropic-kompatible Backend
verwendet die Basis-URL `https://api.z.ai/api/anthropic`; ein Werkzeug, das das
Anthropic-Protokoll spricht, leitet seine Anfragen an GLM, indem es
`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` und optional `API_TIMEOUT_MS`
setzt. Dieselbe env-Tabelle listet `ANTHROPIC_DEFAULT_OPUS_MODEL`,
`ANTHROPIC_DEFAULT_SONNET_MODEL` und `ANTHROPIC_DEFAULT_HAIKU_MODEL` auf, die
die Rollen opus, sonnet und haiku des Werkzeugs GLM-Modellen zuordnen. Das
OpenAI-kompatible Backend verwendet die Basis-URL
`https://api.z.ai/api/coding/paas/v4`. Das Auth-Token ist ein Platzhalter, den
Sie durch Ihren eigenen Z.ai-Schlüssel ersetzen — Apothem schreibt niemals ein
echtes Geheimnis. Modell-IDs ändern sich von Version zu Version, daher pinnt
Apothem keine; die Datei enthält `<GLM_MODEL_ID>`-Platzhalter, die Sie anhand
der aktuellen
[Z.ai-Dokumentation](https://docs.z.ai/devpack/tool/claude) ausfüllen.

## Kompatibilitätshinweise

Weil GLM ein Backend und kein Harness ist, bietet es keine Oberfläche für
Regeln, Commands, Skills oder Hooks — der Adapter schreibt nur die
Backend-Provider-Datei und nichts anderes. Ihr Z.ai-Schlüssel und Ihre Wahl der
Modell-IDs bleiben im Besitz des Operators. Die Konventionen der
Vendor-Oberfläche, auf die sich der Adapter stützt, sind in
`src/apothem/harnesses/glm/STANDARD-CONVENTION-PIN.md` festgeschrieben und als
Snapshot gegen die aktuelle Z.ai-Dokumentation erfasst.

GLM führt die GLM-Modellfamilie von Z.ai aus; die aktuelle Backend-, Modell-
und Anthropic-kompatible Konfigurationsoberfläche finden Sie in der
[Konfigurationsreferenz des Anbieters](https://docs.z.ai/devpack/tool/claude).

## Verifizierung

```bash
apothem verify --harness glm --project /path/to/project
```

Der Befehl verify bestätigt, dass:

1. die native Konfiguration am erwarteten Pfad existiert.
2. die Provider-Datei vorhanden und nicht leer ist.
3. die adapterspezifische Verifizierungsroutine Erfolg meldet.

## Aktualisierung

```bash
apothem update --harness glm --project /path/to/project
```

Sobald die Provider-Datei existiert, gehört sie Ihnen. `install` schreibt die
Vorlage nur, wenn `.apothem/providers/glm.toml` fehlt, und danach überschreiben
weder `install` noch `update` sie jemals, sodass Ihr Schlüsselverweis und Ihre
Modellwahl jeden erneuten Lauf überstehen. Um eine neuere Vorlage zu
übernehmen, verschieben Sie Ihre Datei beiseite, führen `update` aus und
kopieren Ihre Werte in die neue Datei.

## Deinstallation

```bash
apothem uninstall --harness glm --project /path/to/project
```

Entfernt die Provider-Datei nur, wenn Apothem sie erstellt hat und sie noch die
unbearbeitete Vorlage ist, und sichert sie zuvor unter dem Wurzelverzeichnis
für Apothem-Sicherungen. Eine Datei, die Sie erstellt oder bearbeitet haben,
bleibt an Ort und Stelle. Die YAML-Datei des gemeinsamen Profils und die
Apothem-Engine bleiben unberührt.

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness glm --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness glm --project /path/to/project` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness glm --project /path/to/project` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |

| `--dry-run` | `false` | Vorschau der Installation, ohne Dateien zu schreiben. |
