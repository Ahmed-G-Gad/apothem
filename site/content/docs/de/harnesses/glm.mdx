**Anbieter:** Z.ai
**Installationsname:** `glm`
**Status:** GA
**Native Konfiguration:** `<project>/.apothem/providers/glm.toml`

Der `glm`-Adapter konfiguriert GLM (Z.ai) als **Modell-Backend**. Ein Werkzeug,
das das Anthropic-kompatible oder das OpenAI-kompatible Protokoll spricht, wird
auf GLM ausgerichtet, indem eine Backend-Basis-URL und ein Schlüssel gesetzt
werden, und Sie wählen den Adapter wie jeden anderen mit `--harness glm` aus. Er
schreibt eine Provider-Konfigurationsdatei, die beide
Kompatibilitätsoberflächen festhält, sodass sich jedes kompatible Werkzeug mit
der GLM-Modellfamilie verbinden lässt.

Z.ai liefert außerdem ein eigenes Coding-Werkzeug aus, ZCode, das die
[Dokumentation](https://docs.z.ai/devpack/tool/zcode) von Z.ai als „Agentic
Development Environment“ bezeichnet. Dieser Adapter konfiguriert ZCode nicht.
Apothem hat die eigene Konfigurationsoberfläche von ZCode nicht geprüft, daher
schreibt der Adapter nichts dafür.

## Installation

```bash
apothem install --harness glm --project /path/to/project
```

Der Adapter schreibt eine einzelne Provider-Datei auf Projektebene, die die
Endpunkte des GLM-Backends und vom Operator konfigurierbare Platzhalter
festhält.

**Geschriebene Dateien:** `<project>/.apothem/providers/glm.toml`

## Zuordnung von Profil zu nativer Konfiguration

Die Provider-Datei hält zwei Backends fest. Das Anthropic-kompatible Backend
verwendet die Basis-URL `https://api.z.ai/api/anthropic`; ein Werkzeug, das das
Anthropic-Protokoll spricht, leitet seine Anfragen an GLM, indem es
`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` und optional `API_TIMEOUT_MS`
setzt. Die Tabelle `[backends.anthropic_compatible.env]` in der Datei listet
diese Variablen und außerdem `ANTHROPIC_DEFAULT_OPUS_MODEL`,
`ANTHROPIC_DEFAULT_SONNET_MODEL` und `ANTHROPIC_DEFAULT_HAIKU_MODEL` auf, die
die Rollen opus, sonnet und haiku des Werkzeugs GLM-Modellen zuordnen. Das
OpenAI-kompatible Backend verwendet die Basis-URL
`https://api.z.ai/api/coding/paas/v4`. Das Auth-Token ist ein Platzhalter, den
Sie durch Ihren eigenen Z.ai-Schlüssel ersetzen — Apothem schreibt niemals ein
echtes Geheimnis. Modell-IDs ändern sich von Version zu Version, daher pinnt
Apothem keine; die Datei enthält `<GLM_MODEL_ID>`-Platzhalter, die Sie anhand
der aktuellen
[Z.ai-Dokumentation](https://docs.z.ai/devpack/tool/claude) ausfüllen. Aus dem
gemeinsamen Profil fließt nichts in diese Datei; sie ist eine feste Vorlage.

### Zuordnung von Rollen zu Modellen

Die eigenen Angaben von Z.ai zur Zuordnung von Rollen zu Modellen widersprechen
sich, daher lässt die Datei die drei Werte `ANTHROPIC_DEFAULT_*_MODEL` als
Platzhalter stehen und trägt darüber einen `TODO(clarify)`-Kommentar. Sie
entscheiden, welche Zuordnung Sie verwenden:

- Das manuelle `settings.json`-Beispiel in der Anthropic-kompatiblen
  Einrichtungsanleitung des Anbieters ordnet opus und sonnet `glm-5.3[1m]` und
  haiku `glm-5.3-flash[1m]` zu und setzt `CLAUDE_CODE_AUTO_COMPACT_WINDOW` auf
  `1000000`.
- Die angegebene Standardzuordnung derselben Anleitung listet `GLM-5.3-Flash`
  für alle drei Rollen auf.
- Das Werkzeug `@z_ai/coding-helper` von Z.ai verwendet standardmäßig
  `glm-5.3-flash`, hängt `[1m]` an alle drei Rollen an und schreibt ein
  Kompaktierungsfenster von `1048576`.

Apothem pinnt keinen dieser Werte und wählt nicht zwischen ihnen.

## Kompatibilitätshinweise

Das GLM-Backend bietet keine Oberfläche für Regeln, Commands, Skills oder Hooks,
daher schreibt der Adapter nur die Backend-Provider-Datei und nichts anderes.
Apothem hat nicht geprüft, ob ZCode solche Oberflächen bietet. Ihr Z.ai-Schlüssel und Ihre Wahl der
Modell-IDs bleiben im Besitz des Operators. Die Konventionen der
Vendor-Oberfläche, auf die sich der Adapter stützt, sind in
`src/apothem/harnesses/glm/STANDARD-CONVENTION-PIN.md` festgeschrieben und als
Snapshot gegen die aktuelle Z.ai-Dokumentation erfasst.

GLM führt die GLM-Modellfamilie von Z.ai aus; die aktuelle Backend-, Modell-
und Anthropic-kompatible Konfigurationsoberfläche finden Sie in der
[Konfigurationsreferenz des Anbieters](https://docs.z.ai/devpack/tool/claude).

## Verifizierung

```bash
apothem verify --harness glm --project /path/to/project
```

Der Befehl verify bestätigt, dass:

1. die native Konfiguration am erwarteten Pfad existiert.
2. die Provider-Datei vorhanden und nicht leer ist.
3. die adapterspezifische Verifizierungsroutine Erfolg meldet.

## Aktualisierung

```bash
apothem update --harness glm --project /path/to/project
```

Sobald die Provider-Datei existiert, gehört sie Ihnen. `install` und `update`
schreiben beide die Vorlage nur, wenn `.apothem/providers/glm.toml` fehlt, und
keiner von beiden überschreibt sie danach jemals, sodass Ihr Schlüsselverweis
und Ihre Modellwahl jeden erneuten Lauf überstehen. Um eine neuere Vorlage zu
übernehmen, verschieben Sie Ihre Datei beiseite, führen `update` aus und
kopieren Ihre Werte in die neue Datei.

## Deinstallation

```bash
apothem uninstall --harness glm --project /path/to/project
```

Entfernt die Provider-Datei nur, wenn Apothem sie erstellt hat und sie noch eine
unbearbeitete Vorlage ist, und sichert sie zuvor unter dem Wurzelverzeichnis
für Apothem-Sicherungen. Eine unbearbeitete Datei, die ein früheres Release
geschrieben hat, zählt dazu, wenn Apothems Installationsaufzeichnung für das
Projekt zeigt, dass es die Datei geschrieben hat: Das Manifest hält den Digest
jeder Vorlage fest, die das Projekt ausgeliefert hat. Ohne
Installationsaufzeichnung wird nur eine exakte Kopie der aktuellen Vorlage
entfernt. Eine Datei, die Sie erstellt oder bearbeitet haben, bleibt an Ort und
Stelle. Die YAML-Datei des gemeinsamen Profils und die
Apothem-Engine bleiben unberührt.

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness glm --project /path/to/project` erneut aus |
| Verifizierung fehlgeschlagen | Die Provider-Datei fehlt oder ist leer. Fehlt sie, führen Sie `apothem update --harness glm --project /path/to/project` aus. Ist sie leer, verschieben Sie zuerst `.apothem/providers/glm.toml` beiseite, führen Sie dann `update` aus und verifizieren Sie erneut |
| Unerwarteter Konfigurationsinhalt | Bearbeiten Sie `.apothem/providers/glm.toml` direkt; Apothem schreibt eine bestehende Datei niemals neu, und das gemeinsame Profil trägt nichts zu ihr bei. Für eine frische Vorlage verschieben Sie die Datei beiseite und führen `apothem update --harness glm --project /path/to/project` aus |
