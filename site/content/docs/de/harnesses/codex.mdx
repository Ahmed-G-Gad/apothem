**Anbieter:** OpenAI
**Installationsname:** `codex`
**Status:** Beta
**Native Konfiguration:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml` und `~/.agents/skills/`

## Installation

```bash
apothem install --harness codex
```

Der Adapter installiert Codex-native Anweisungen und Hooks, konvertiert
Apothem-Agents in Codex-TOML-Agents und verpackt wiederverwendbare
Command-Prompts als Codex-Skills.

**Geschriebene Dateien:** `~/.codex/AGENTS.md`, `~/.codex/hooks.json`,
`~/.codex/hooks/`, `~/.codex/agents/*.toml`,
`~/.agents/skills/*/SKILL.md`, `~/.agents/skills/*/agents/openai.yaml` für
vom Benutzer aufgerufene Skills sowie Unterstützungsdateien unter
`~/.config/apothem/{rules,templates}/`.

Der Apothem-Block in `AGENTS.md` endet mit einem Abschnitt zu den
Apothem-Unterstützungsdateien, der das absolute Verzeichnis nennt, gegen das
jeder Verweis im Repository-Stil in den installierten Skills und Regeln
aufgelöst wird: `rules/<name>.md` und `templates/...` unter
`~/.config/apothem/` sowie `hooks/...` unter `~/.codex/hooks/`. Die
Codex-Installation liefert keinen `schemas/`- oder `conformity/`-Baum aus,
daher führt der Abschnitt keinen von beiden auf.

**Vom Benutzer aufgerufene Skills.** Codex ignoriert den Schlüssel
`disable-model-invocation`. Für jeden Skill und jeden Command, dessen Quelle
`disable-model-invocation: true` setzt, schreibt der Adapter neben dessen
`SKILL.md` eine `agents/openai.yaml` mit
`policy.allow_implicit_invocation: false`, sodass Codex den Skill nicht von
sich aus auswählt; Sie können ihn weiterhin explizit mit `$skill-name`
ausführen. Siehe die
[Codex-Dokumentation zu Skills](https://developers.openai.com/codex/skills).

## Zuordnung von Profil zu nativer Konfiguration

Der Adapter liest die gemeinsamen Kohorten von Apothem und installiert jede in
die passende Codex-Oberfläche: Anweisungen nach `AGENTS.md`, Hooks nach
`hooks.json` und `hooks/`, Agents als TOML, Skills nach `~/.agents/skills/` und
nicht native Markdown-Regeln/-Templates als Unterstützungsmaterial nach
`~/.config/apothem/`.

Jeder konvertierte Helfer setzt `name`, `description` und
`developer_instructions`. Ein Helfer, dessen Werkzeugfreigabe nach Abzug ihrer
Sperrliste kein Werkzeug zum Bearbeiten von Dateien (`Write`, `Edit`,
`MultiEdit` oder `NotebookEdit`) enthält, setzt zusätzlich
`sandbox_mode = "read-only"`, die Codex-eigene Schreibbeschränkung. `Bash`
zählt nicht als Werkzeug zum Bearbeiten von Dateien, sodass ein Helfer, dem
`Bash` und keines dieser Werkzeuge freigegeben ist, weiterhin schreibgeschützt
ist. Weder Modell noch Reasoning-Aufwand werden gesetzt, sodass jeder Helfer
die Einstellungen der Sitzung erbt. Codex kennt keine Werkzeugliste und kein
Turn-Limit pro Helfer, daher werden `tools` und `maxTurns` eines Helfers nicht
übernommen.

## Kompatibilitätshinweise

`~/.agents/skills/` ist ein gemeinsames Wurzelverzeichnis, das Codex gehört:
Acht weitere unterstützte Werkzeuge laden es ebenfalls (die
[Harness-Registry](/docs/reference/harness-registry) listet sie auf), daher
erscheinen die Apothem-Skills, die eine Codex-Installation dort schreibt, auch
in diesen Werkzeugen, und eine Codex-Deinstallation entfernt sie aus diesen
Werkzeugen. Die Installation gibt einen Hinweis aus, der diese Werkzeuge nennt.

Codex reserviert `~/.codex/rules/` für `.rules`-Ausführungsrichtlinien. Apothem
legt dort keine Markdown-Verhaltensregeln ab; es hält sie in
`~/.config/apothem/` vor und verweist aus `AGENTS.md` und den installierten
Skills auf sie.

## Verifizierung

```bash
apothem verify --harness codex
```

Der Befehl verify bestätigt Folgendes:

1. Die native Konfiguration existiert am erwarteten Pfad.
2. Jedes verwaltete Ziel existiert; verwaltete Dateien sind nicht leer, und JSON- oder YAML-Konfigurationen lassen sich parsen. Fügen Sie `--profile PATH` hinzu, um außerdem zu bestätigen, dass die installierten Dateien zu diesem Profil passen.
3. Die adapterspezifische Verifizierungsroutine meldet Erfolg.

## Aktualisierung

```bash
apothem update --harness codex
```

Aktualisiert den Codex-Bootstrap, die konvertierten Agents, die Skills und die
Unterstützungskohorten.

## Deinstallation

```bash
apothem uninstall --harness codex
```

Entfernt die vom Adapter geschriebenen nativen Konfigurationsdateien.
Die YAML-Datei des gemeinsamen Profils und die Apothem-Engine bleiben unberührt.

## Konformitäts-Gate

```bash
python -m apothem.conformity.gate --all .
```

## Fehlerbehebung

| Symptom | Behebung |
|---------|-----|
| Konfigurationsdatei nicht gefunden | Führen Sie `apothem install --harness codex` erneut aus |
| Verifizierung fehlgeschlagen | Führen Sie `apothem update --harness codex` aus und verifizieren Sie dann erneut |
| Unerwarteter Konfigurationsinhalt | Prüfen Sie `~/.config/apothem/profile.yaml` oder `--profile PATH` und führen Sie dann `apothem update --harness codex` erneut aus |

## Konfigurationsschalter

| Flag | Standard | Beschreibung |
|------|---------|-------------|
| `--dry-run` | `false` | Vorschau der Installation, ohne Dateien zu schreiben. |
