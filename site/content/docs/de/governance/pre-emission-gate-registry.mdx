> **Kanonische Registry des fünfzehnstufigen Pre-Emission-Gates.** Dieses Dokument enthält die vollständige Tabelle der fünfzehn Stufen und den YAML-Block des Gate-Ergebnis-Schemas; die substanzielle Tabelle und das Schema werden hier geführt und durch `src/apothem/rules/pre-emission-gate.md` operationalisiert.

Vor jeder Artefaktemission von bedeutsamem Umfang (gemäß der Schwelle zwischen trivial und nicht trivial in `site/content/docs/governance/outward-conformity-registry.mdx` §1) führe das fünfzehnstufige Pre-Emission-Gate aus. Mechanisiere es über PreToolUse-Hooks, wo möglich (die mechanischen Greps in `src/apothem/conformity/*-grep.py`, orchestriert von `src/apothem/conformity/gate.py`); urteile dort, wo sich das nicht mechanisieren lässt. **Das Scheitern einer einzelnen Stufe blockiert die Emission; überarbeite, bis jede Stufe besteht; emittiere mit festgehaltenem Gate-Ergebnis.**

| # | Stufe | Prüfart | Fehlschlag → Maßnahme |
| - | --- | ---------- | ---------------- |
| 1 | M1 Host-Agnostizismus | abwägungsbasiert | überarbeiten, damit sie den Host-Konventionen entspricht |
| 2 | M2 redaktionelle Offenlegung | abwägungsbasiert | Eintrag im Offenlegungsregister ergänzen |
| 3 | M3 zehn Dimensionen | gemischt (mechanisch + abwägungsbasiert) | bei der nicht bestandenen Dimension überarbeiten |
| 4 | M4 Selbstanwendung | abwägungsbasiert (Verifizierungsblock vorhanden) | Verifizierungsblock erfassen |
| 5 | M5 Autorität | mechanisch (Grep nach dem Platzhalter `<USER-CONFIRM:…>`) | an die Rückfrage-Oberfläche weiterleiten |
| 6 | M6 Expertise | abwägungsbasiert (Abschnitt mit offengelegten Lücken vorhanden) | Lücken offenlegen; zitieren |
| 7 | M7 Optionsannotation | mechanisch (Optionsmenge trägt Empfehlungsmarkierung) | annotieren |
| 8 | M8 Bestimmtheit | mechanisch (Grep nach Absicherungsvokabular) | Absicherungsfloskeln zu Bedingungen aufwerten |
| 9 | M9 visuelle Hebelwirkung | gemischt (mechanisch: Verifizierungsdatum des Diagramms; abwägungsbasiert: Diagramm vorhanden, wo strukturell) | Diagramm erstellen / aktualisieren |
| 10 | M10 bidirektionale Bindung | mechanisch (Grep nach Bindungs-Reziprozität) | Halbkanten schließen |
| 11 | M11 agile Sprints | abwägungsbasiert (Sprint-Apparat instanziiert) | als Sprints umstrukturieren |
| 12 | M12 Phasenberichte & Layout | mechanisch (Grep nach verwaisten Ausgaben) + abwägungsbasiert | Zusammenfassung erstellen; verlagern |
| 13 | M13 Code-Handwerk | mechanisch (Lint / Formatierung / Typprüfung; Grep nach bare-except, magischen Zahlen, auskommentiertem Code) | überarbeiten |
| 14 | M14 Systemizität | gemischt (mechanisch: Herkunft des Erzeugers; abwägungsbasiert: deklariert Upstream / Downstream / Peers / Durchsetzer) | deklarieren; indexieren |
| 15 | M15 Produktionsreife | mechanisch (Grep nach production-ready-pr) + abwägungsbasiert | Tests / Doku / CHANGELOG ergänzen |

## 1. Schema des Gate-Ergebnisses

Jeder Gate-Lauf zeichnet das Ergebnis in der Arbeitsspur des Artefakts auf (ein verborgener Kommentar, ein Metadatenblock, eine separate Emissions-Log-Datei — was auch immer die Host-Konventionen erlauben):

```yaml
conformity-attestation:
  artifact: <path-or-identifier>
  ecosystem-version: <git-commit-sha-or-equivalent ratifying the rule set in force>
  bars:
    M1-host-agnosticism:        pass | n/a (with reason)
    M2-editorial-disclosure:    pass | n/a
    M3-ten-dimensions:          pass | n/a
    M4-self-application:        pass
    M5-authority:               pass
    M6-expertise:               pass | n/a
    M7-option-annotation:       pass | n/a (no option set)
    M8-definitiveness:          pass
    M9-visual-leverage:         pass | n/a (subject not structural)
    M10-bidirectional-binding:  pass
    M11-agile-sprints:          pass | n/a (trivial work)
    M12-phase-layout:           pass | n/a
    M13-code-craft:             pass | n/a (not code)
    M14-systemicity:            pass
    M15-production-ready:       pass | n/a (no host-public-surface change)
  surfaced-gaps: []
  unresolved-inquiries: []
  amendments-disclosed: []
  date: <ISO-8601>
```

`n/a`-Markierungen sind explizit und begründet — niemals stille Auslassungen. Das Feld `ecosystem-version` verankert das Gate-Ergebnis an einem reproduzierbaren Zustand des Ökosystems im Benutzerbereich (dem aktiven Git-Commit des Apothem-Quellbaums zum Zeitpunkt des Gate-Laufs — z. B. dem `~/.claude/`-Checkout für den Adapter für Claude Code), sodass künftige Audits das Gate gegen dieselben Regelkörper erneut ablaufen lassen können.
