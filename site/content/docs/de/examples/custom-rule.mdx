Dieses Beispiel fügt eine projektspezifische, dauerhaft aktive Regel hinzu, die
eine Benennungskonvention über alle Dateien hinweg durchsetzt.

## Regeldatei

```markdown
---
name: "kebab-filenames"
description: "Enforce kebab-case filenames in the src/ tree"
pathFilter: ""
alwaysApply: true
---

# Kebab-case filenames

All new files created under `src/` MUST use kebab-case naming
(lowercase letters, digits, and hyphens only — no underscores,
no camelCase, no PascalCase).

**Correct:** `src/styles/button-group.css`, `src/components/nav-bar.css`
**Incorrect:** `src/styles/buttonGroup.css`, `src/components/NavBar.css`

When in doubt, err on the side of more hyphens.
```

Speichern Sie dies unter `rules/kebab-filenames.md` im Installationsstamm Ihres Harness (`~/.claude/` für den Adapter für Claude Code; ersetzen Sie andernfalls den harness-nativen Pfad).

## Prüfen, ob die Regel korrekt aufgebaut ist

Führen Sie den Frontmatter-Validator gegen die soeben geschriebene Regeldatei aus. Verwenden Sie den ersten Befehl aus einem Apothem-Checkout, in dem `PYTHONPATH=src` das Paket importierbar macht. Verwenden Sie den zweiten nach einer Skript-Installation, bei der der Quellcode unter `$HOME/.apothem/src` liegt:

```bash
# From an Apothem checkout
PYTHONPATH=src python -m apothem.conformity.gate --check frontmatter-grep ~/.claude/rules/kebab-filenames.md

# After a script install
PYTHONPATH="$HOME/.apothem/src" python -m apothem.conformity.gate --check frontmatter-grep ~/.claude/rules/kebab-filenames.md
```

Eine korrekt aufgebaute Regel meldet einen fehlerfreien Durchlauf:

```json
{
  "orchestrator": "conformity-gate",
  "passed": true,
  "grep_count": 1
}
```

## An die Harnesses verteilen

Führen Sie den Update-Befehl einmal je installiertem Harness aus:

```bash
apothem update --harness claude-code
apothem update --harness cursor --project /path/to/project
```
