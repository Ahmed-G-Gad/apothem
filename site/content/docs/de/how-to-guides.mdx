Aufgabenorientierte Durchgänge zum **Verfassen von Apothem-Artefakten und zum Steuern der Plan-Pipeline**. Jede Anleitung beantwortet eine einzige konkrete Frage.

Für Rezepte zur Ersteinrichtung — ein Harness hinzufügen, das Profil bearbeiten, den Installer steuern — siehe stattdessen den Abschnitt [How-to-Rezepte](/docs/how-to).

## Plan-Suite-Pipeline

### Wie verfeinere ich Rohinhalt zu einer Spec?

Rufe `/plan-spec` mit dem Rohinhalt als Eingabe auf. Die Forge-Rolle durchläuft sechs Transformationsphasen (Discovery, Meticulous Consideration, Potency Mapping, Preservation Verification, Expertise Application, Question-Resolution Sweep) und gibt die konsolidierte Spec unter `.apothem/plans/{suite}/_spec/spec.md` aus. Siehe `src/apothem/commands/plan-spec.md` für das vollständige Protokoll.

### Wie erzeuge ich eine Plan-Suite aus einer Spec?

Rufe `/plan-generate .apothem/plans/{suite}/_spec/spec.md` auf, sobald `/plan-spec` die Spec geschrieben hat. Der Generator gibt die kanonischen Infrastrukturdateien plus die phasenweisen `phases/NN-kebab-topic/PHASE.md`-Dateien aus. Siehe `src/apothem/commands/plan-generate.md`.

### Wie prüfe ich einen generierten Plan?

Rufe `/plan-review path/to/plan-suite/` auf. Der Prüfer wendet die neun Planungstechniken an und gibt Scorecards aus. Fehlschlagende Scorecards blockieren die Ausführung bei SHARED+, bis sie behoben sind. Siehe `src/apothem/commands/plan-review.md`.

### Wie führe ich einen Plan aus?

Rufe `/plan-execute path/to/plan-suite/ [phase-id]` auf. Ohne `phase-id` läuft die nächste ausstehende Phase. Mit einer bestimmten ID läuft nur diese Phase. Siehe `src/apothem/commands/plan-execute.md`.

### Wie prüfe ich den Plan-Status?

Rufe `/plan-status path/to/plan-suite/ [--verbose]` auf. Schreibgeschützter Bericht. Siehe `src/apothem/commands/plan-status.md`.

## Artefakte verfassen

### Wie füge ich eine neue Regel hinzu?

1. Wähle einen kebab-case-Dateinamen unter `src/apothem/rules/`, z. B.
   `src/apothem/rules/my-new-rule.md`.
2. Verfasse das Frontmatter (`name`, `description`, `pathFilter`,
   `alwaysApply`).
3. Schreibe den Body mit den kanonischen Abschnitten: Purpose,
   Obligations, Seriousness Scaling, Anti-Patterns, Enforcement,
   Bindings.
4. Führe `python scripts/dev/validate_ecosystem.py --check
   frontmatter-cohort` aus, um zu verifizieren.

Der Regel-Lader arbeitet globbasiert: Er erfasst jede Datei, die `src/apothem/rules/*.md` entspricht, sodass kein Registry-Eintrag nötig ist. Das Ablegen der kanonisch benannten Datei im Verzeichnis ist die gesamte Registrierung.

### Wie füge ich einen neuen delegierten Worker hinzu?

Wähle einen kebab-case-Dateinamen im unten gezeigten Verzeichnis in der Form `my-worker.md`:

```text
src/apothem/agents/
src/apothem/agents/my-worker.md
```

Dann:

1. Verfasse das Frontmatter — einschließlich `name`, `version`, `updated`,
   `description`, `tools`, `disallowedTools`, `maxTurns` und
   `effort`.

2. Schreibe den System-Prompt als Body.

Die Kohorte delegierter Worker wird globbasiert aus `src/apothem/agents/*.md` geladen, sodass die kanonisch benannte Datei beim Ablegen erfasst wird. Es gibt keine Registry-Tabelle, die bearbeitet werden müsste.

### Wie füge ich einen neuen Hook hinzu?

1. Verfasse eine Kontextnachricht unter
   `src/apothem/hooks/messages/<event>-<scope>.md`.
2. Verdrahte den Hook in `settings.json`.
3. Aktualisiere die Hooks-Pipeline.
4. Führe `python scripts/dev/validate_ecosystem.py` aus.

## Qualitäts-Gates

### Wie führe ich die lokalen Qualitäts-Gates aus?

```bash
python -m ruff check .
python -m ruff format --check .
python -m mypy
python -m pytest -q
python scripts/dev/validate_ecosystem.py
python scripts/dev/chaos_pass.py
```

Die CI-Pipeline führt dieselbe Menge parallel aus.

### Wie prüfe ich das Frontmatter einer einzelnen Artefaktklasse?

```bash
python scripts/dev/validate_ecosystem.py --check frontmatter-cohort
```
