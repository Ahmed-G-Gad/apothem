**Vendor:** Hermes
**Install name:** `hermes`
**Status:** Preview
**Native config:** `~/.hermes/config.yaml`

## Installation

```bash
apothem install --harness hermes
```

The adapter translates the shared profile to the Hermes Agent user-global
configuration file and installs Apothem support cohorts under the harness root.

**Files written:** `~/.hermes/config.yaml`, the profile document
`~/.hermes/apothem/rules/00-apothem-profile.md`, and support files under
`~/.hermes/.apothem/support/`

## Profile-to-native-config mapping

The adapter reads Apothem's shared profile and renders the native YAML config,
including the profile's MCP inventory. The profile's identity, preferences, and
rules go into the profile document. Shared commands, skills, helper definitions,
rules, templates, and hook prompts land as support material under
`~/.hermes/.apothem/support/`.

## Compatibility notes

Preview adapter. Hermes does not load the support tree or the profile document
on its own: nothing in `config.yaml` and none of the context files Hermes reads
point there, so after install Hermes runs without Apothem's rules, skills, or
hooks. Hermes reads skills from `~/.hermes/skills/` and from every folder listed
under `skills.external_dirs` in `config.yaml`; to use the Apothem skills, add
`~/.hermes/.apothem/support/skills` to that list yourself; `apothem update`
keeps keys you add to `config.yaml`. The adapter writes
the profile's MCP inventory under `auxiliary.mcp`, but Hermes reads MCP servers
from the top-level `mcp_servers` key, so it does not load them; declare your
servers under `mcp_servers`. (Hermes behavior per its user guide pages on
[skills](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/skills.md)
and [MCP](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/mcp.md),
read 2026-10-02.)

## Verification

```bash
apothem verify --harness hermes
```

The verify command confirms that:

1. The native config exists at the expected path.
2. All mandatory fields from the shared profile are present.
3. The adapter-specific verification routine reports success.

## Updating

```bash
apothem update --harness hermes
```

Re-derives the native config from the current shared profile state.
Run after editing `~/.config/apothem/profile.yaml` or upgrading the installed
Apothem package.

## Uninstalling

```bash
apothem uninstall --harness hermes
```

Removes the native config files written by the adapter.
The shared profile YAML and Apothem engine are unaffected.

## Conformity gate

```bash
python -m apothem.conformity.gate --all .
```

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Config file not found | Re-run `apothem install --harness hermes` |
| Verification failed | Run `apothem update --harness hermes`, then verify again |
| Unexpected config content | Check `~/.config/apothem/profile.yaml` or `--profile PATH`, then re-run `apothem update --harness hermes` |
