**Vendor:** Devin Desktop (formerly Codeium Windsurf)
**Install name:** `windsurf`
**Status:** GA
**Native config:** `<project>/.devin/rules/apothem-rules.md`

Windsurf is now Devin Desktop, and `.devin/rules/` is the preferred
workspace-rules location (it takes precedence over `.windsurf/rules/`).

## Installation

```bash
apothem install --harness windsurf --project /path/to/project
```

The adapter writes one project-scope Windsurf rules file from the shared
Apothem rules and governance surface.

It also writes Apothem's skills, and the rules and templates they cite, to
your user home, before it touches the project (see
[Files outside the project](#files-outside-the-project)).

**Files written:**

- `<project>/.devin/rules/apothem-rules.md`, the rules file.
- `~/.agents/skills/<name>/SKILL.md` for each Apothem skill and command, in your user home.
- `~/.config/apothem/rules/` and `~/.config/apothem/templates/`, in your user home.

## Files outside the project

The install also writes Apothem's skills to your user home, before it changes
anything in the project:

| Folder | What Apothem writes there |
| --- | --- |
| `~/.agents/skills/` | One folder with a `SKILL.md` for each Apothem skill, and one for each Apothem command (a command becomes a skill of the same name). |
| `~/.config/apothem/rules/`, `~/.config/apothem/templates/` | The rules and templates that the skills and the rules file refer to. |

These folders are shared. They are not private to the project:

- Every project you install `windsurf` into, and every other Apothem install that names the folder, uses the same copy and writes the same files, so the order you install in does not matter. Several other tools read `~/.agents/skills/` too; the [harness registry](/docs/reference/harness-registry#shared-roots) lists them.
- `--project` chooses the rules file to write and which project the
  install belongs to. It does not change where the skills go.
- The install adds no skill or rule file to your repository. The project
  gets the rules file, plus the `.apothem/` data folder every project install
  creates.
- The home folders are written first. If that fails, for example because a
  folder in the path is a link that leaves your home directory (a link that
  stays inside it is followed) or cannot be written, the install stops
  with the error before anything in the project changes.
- A skill folder with an Apothem skill's name that Apothem did not write is
  left alone, and the install prints a warning that names it. Rename or move
  it, then run `apothem update`. `apothem verify` fails while that name is held.
- The files add up to a few megabytes.

The install prints a note that names the folders it writes outside `--project`,
and `--dry-run` lists them.

## Profile-to-native-config mapping

The adapter reads Apothem's shared profile and renders the project rules file
on every `apothem install` or `apothem update` run. The shared profile is the
source of truth; project-local edits to the generated file are backed up before
the next sync replaces the Apothem-managed content.

The file opens with its `trigger: always_on` frontmatter, which sets the rule's
activation mode. The Apothem-managed block follows it; text you add after the
block is kept on every sync.

## Compatibility notes

Windsurf's current rules surface is project-scoped under `.devin/rules/` (the
preferred location, which takes precedence over the `.windsurf/rules/`
backward-compat fallback). Workflows and machine-local memories are
operator-owned; Apothem does not write them. The single-file `.windsurfrules`
form is intentionally not written.

Devin Desktop (Windsurf) discovers `~/.agents/skills/`, so the skills the
install writes appear without further setup. It can also list the same names
from `~/.claude/skills/` when its Claude Code config import is on; its
documentation does not state the default. Apothem has not confirmed how
Windsurf treats a `SKILL.md` header key it does not list; the skills carry
`user-invocable`, `disable-model-invocation`, `allowed-tools`, `argument-hint`,
and a `metadata` map.

## Verification

```bash
apothem verify --harness windsurf --project /path/to/project
```

The verify command confirms that:

1. The native config exists at the expected path.
2. Each managed target exists; managed files are non-empty, and JSON or YAML
   configs parse. Add `--profile PATH` to also confirm that the installed files
   match that profile.
3. Every Apothem skill folder is in place with a `SKILL.md`, whichever
   install wrote it, and no skill folder with an Apothem name belongs to
   something Apothem did not write. A failed check names the missing or
   foreign folders.
4. The adapter-specific verification routine reports success.

## Updating

```bash
apothem update --harness windsurf --project /path/to/project
```

Re-derives the project rules file from the current shared profile state.

The update also rewrites any skill folder whose files differ from the current ones.
If you installed with an earlier release that wrote no skills, the update adds them.

## Uninstalling

```bash
apothem uninstall --harness windsurf --project /path/to/project
```

Removes the Apothem block, and the frontmatter Apothem wrote above it, from
`<project>/.devin/rules/apothem-rules.md` and keeps any other text in it. The
file is deleted only when nothing else remains in it. Before the change, a
timestamped copy of the file is saved under `~/.apothem/backups/`; no backup
file is left in the project. The shared profile YAML and Apothem engine are
unaffected.

The uninstall also removes the skill folders it wrote in `~/.agents/skills/` and the
rules and templates in `~/.config/apothem/`, but only when no other Apothem
install still uses them. Another project, or another tool that shares the
folder, may. In that case the uninstall keeps the folders, prints which install
uses them, and the last uninstall removes them. Files you added to those
folders stay, and a folder left empty is removed. Each
folder is backed up under `~/.apothem/backups/` before it is removed.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Config file not found | Re-run `apothem install --harness windsurf --project /path/to/project` |
| Verification failed | Run `apothem update --harness windsurf --project /path/to/project`, then verify again |
| `apothem verify` names a missing skill folder | Run `apothem install --harness windsurf --project /path/to/project`; it restores the folder |
| An install or update warns that it skipped a skill folder | A folder with an Apothem skill's name already exists in the skills folder and Apothem did not write it. Rename or move it, then run `apothem update` |
| An install stops before it changes the project | A write in your home failed. Read the error, fix the folder it names (a link that leaves your home directory, a file where a folder belongs, or a read-only folder), and install again |
| Unexpected config content | Check `~/.config/apothem/profile.yaml` or `--profile PATH`, then re-run `apothem update --harness windsurf --project /path/to/project` |
