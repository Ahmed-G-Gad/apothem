**Vendor:** Open-Claw
**Install name:** `open-claw`
**Status:** Preview
**Native config:** `~/.openclaw/openclaw.json`

## Installation

```bash
apothem install --harness open-claw
```

The adapter writes OpenClaw's user-global config file, projects the shared
profile into a profile document, and installs Apothem support cohorts under the
harness root. OpenClaw's native config is JSON; the materializer renders an
empty JSON object, and an existing file keeps its keys.

**Files written:** `~/.openclaw/openclaw.json`, the profile document
`~/.openclaw/apothem/rules/00-apothem-profile.md`, and support files under
`~/.openclaw/.apothem/support/`

The profile document ends with an Apothem support files section that names
the absolute directory under `~/.openclaw/.apothem/support/` each
repository-style citation (`rules/<name>.md`, `templates/...`, `hooks/...`)
resolves against.

## Profile-to-native-config mapping

The adapter reads Apothem's shared profile but authors no config keys:
a new or empty `openclaw.json` is written as an empty object, and an existing
file keeps its keys. The profile's identity,
preferences, and rules go into the profile document. Shared commands, skills, rules,
templates, and hook prompts are installed as support material under
`~/.openclaw/.apothem/support/`.

## Compatibility notes

Preview adapter. OpenClaw does not load the support tree or the profile
document on its own: none of its skill locations, its workspace instruction
files, or its config points there, so after install OpenClaw runs without Apothem's rules, skills, or
MCP servers. OpenClaw reads skills from its workspace `skills/` and
`.agents/skills/` folders, `~/.agents/skills`, its state directory, and any
folder listed in `skills.load.extraDirs`; to use the Apothem skills, add
`~/.openclaw/.apothem/support/skills` to that list yourself; `apothem update`
keeps keys you add to `openclaw.json`. MCP servers live in
the `mcp.servers` block of the OpenClaw config, which you manage with
`openclaw mcp add` and the related subcommands; the adapter writes no entries
there. (OpenClaw behavior per its [skills](https://docs.openclaw.ai/tools/skills)
and [MCP CLI](https://docs.openclaw.ai/cli/mcp) docs, read 2026-10-02.)

## Verification

```bash
apothem verify --harness open-claw
```

The verify command confirms that:

1. The native config exists at the expected path.
2. Each managed target exists; managed files are non-empty, and JSON or YAML
   configs parse. Add `--profile PATH` to also confirm that the installed files
   match that profile.
3. The adapter-specific verification routine reports success.

## Updating

```bash
apothem update --harness open-claw
```

Re-derives the profile document from the current shared profile state and
refreshes the support files; `openclaw.json` keeps the keys it already has.
Run after editing `~/.config/apothem/profile.yaml` or upgrading the installed
Apothem package.

## Uninstalling

```bash
apothem uninstall --harness open-claw
```

Removes what the adapter added: the profile document and the support tree. Your
own keys in `openclaw.json` stay, and the file is deleted only when Apothem
created it and nothing of yours is left. The shared profile YAML and Apothem
engine are unaffected.

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| Config file not found | Re-run `apothem install --harness open-claw` |
| Verification failed | Run `apothem update --harness open-claw`, then verify again |
| Unexpected config content | Check `~/.config/apothem/profile.yaml` or `--profile PATH`, then re-run `apothem update --harness open-claw` |
