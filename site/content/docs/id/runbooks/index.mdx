Prosedur operasional untuk para pemelihara. Setiap runbook adalah prosedur yang
berurutan dan bebas konteks: runbook menggiring keadaan awal yang diketahui
menuju keadaan akhir yang terverifikasi, ditulis agar kontributor yang cakap
dapat mengikutinya tanpa konteks sebelumnya.

## Halaman

| Halaman | Deskripsi |
|------|-------------|
| [Pengaktifan Pages](/docs/runbooks/pages-enablement) | Menggiring `apothem.ahmedgad.com` dari konfigurasi GitHub Pages yang baru ke halaman arahan HTTPS dengan `200 OK`. |
| [Siklus rilis](/docs/runbooks/release-cycle) | Menggiring rilis `vX.Y.Z` dari working tree yang bersih ke permukaan GitHub Release dan npm yang terverifikasi. |
| [Penyiapan akun penerbit](/docs/runbooks/publisher-account-setup) | Mengonfigurasi penerbit tepercaya npmjs.com untuk `@ahmed-g-gad/apothem` dan prasyarat rilis di sisi GitHub. |
| [Pemulihan rilis](/docs/runbooks/release-recovery) | Memulihkan `ahmed-g-gad/apothem` ke keadaan yang berfungsi ketika urutan cutover rilis gagal di tengah jalan. |
| [Penulisan adapter harness baru](/docs/runbooks/new-harness-adapter-authoring) | Menulis dan memublikasikan adapter harness baru untuk penyertaan pihak pertama. |
| [Checklist deployment](/docs/runbooks/deployment-checklist) | Menjalankan checklist verifikasi pra-penerbangan sebelum men-deploy atau membagikan ekosistem Apothem. |
| [Seremoni merge pemelihara tunggal](/docs/runbooks/solo-maintainer-merge) | Kapan pemelihara dapat men-merge pull request miliknya sendiri secara langsung, dan seremoni merge-mandiri untuk proteksi yang mensyaratkan persetujuan dan memberlakukannya bagi admin. |
| [Checklist sinkronisasi lintas-mesin](/docs/runbooks/cross-machine-sync-checklist) | Memverifikasi bahwa adapter Claude Code terpasang, tervalidasi, dan dicopot dengan benar pada host baru, dengan pemeriksaan portabilitas lengkap. |
