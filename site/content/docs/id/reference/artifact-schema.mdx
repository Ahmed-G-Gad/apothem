**Templat frontmatter YAML per-kelas dan field wajib untuk semua artefak ekosistem Apothem.**

> **Sumber kebenaran.** Kontrak yang terbaca mesin dan ditegakkan gerbang adalah
> JSON Schema per-kelas di bawah [`src/apothem/schemas/`](https://github.com/ahmed-g-gad/apothem/blob/main/src/apothem/schemas)
> (`agent.schema.json`, `command.schema.json`, `skill.schema.json`, …), yang
> masing-masing mendeklarasikan `additionalProperties` sehingga gerbang
> konformitas menolak kunci yang tidak dikenal. Halaman ini dan
> [`frontmatter-schema.mdx`](/docs/reference/frontmatter-schema) adalah dua
> proyeksi yang dapat dibaca manusia dari skema-skema tersebut — halaman ini
> memuat **templat dan contoh lengkap** per-kelas, sedangkan frontmatter-schema
> memuat **indeks kunci wajib** yang ringkas. Jika sebuah halaman tidak sesuai
> dengan JSON Schema, skema yang berlaku.

## Ikhtisar

Semua artefak di pohon sumber Apothem (di bawah `src/apothem/` dan permukaan
konfigurasi root) harus menyertakan blok frontmatter YAML (di antara pembatas
`---`) dengan field wajib dan opsional yang spesifik untuk tipe artefaknya.
Dokumen ini mendefinisikan skema kanonik untuk setiap tipe.

**Aturan Universal:**

- Frontmatter mematuhi YAML 1.2
- Semua nilai string menggunakan tanda kutip ganda, dan string kosong ditulis `""`
- Urutan field: field wajib lebih dulu, field opsional dikelompokkan menurut relevansi
- Komentar dalam frontmatter menggunakan `#` dengan spasi: `# comment`
- Nilai jalur harus relatif (tanpa `/` di awal) dan menggunakan garis miring maju (`/`) untuk kompatibilitas lintas platform

**Konvensi Versioning (kelas artefak berversi — command, pembantu, skill, CLAUDE.md):**

- `version` bersifat **semantik** (`MAJOR.MINOR.PATCH`). Naikkan MAJOR untuk perubahan skema atau kontrak yang tidak kompatibel; MINOR untuk perubahan aditif yang tetap kompatibel (field opsional baru, bagian tambahan, anti-pola tambahan); PATCH untuk klarifikasi, perbaikan format, atau suntingan khusus dokumentasi tanpa perubahan perilaku.
- `updated` adalah **tanggal ISO 8601** (`YYYY-MM-DD`) dari suntingan terbaru. Nilainya harus berubah pada setiap kenaikan `version` dan boleh diperbarui secara terpisah untuk penyegaran tautan yang tidak menaikkan versi.
- Artefak baru dimulai pada `v0.Y.Z`. Promosi ke `vX.Y.Z` menandakan bahwa kontrak artefak cukup stabil untuk menjadi komitmen publik.

## Skema: Aturan

**Pola jalur:** `src/apothem/rules/*.md`

**Tujuan:** Mandat perilaku dan direktif operasional.

### Field Wajib

```yaml
---
name: "kebab-case-identifier"
description: "One-line description"
pathFilter: "**/*.py, **/*.toml"
alwaysApply: true | false
---
```

| Field | Tipe | Tujuan | Contoh |
| ----- | ---- | ------- | ------- |
| `name` | string | Pengidentifikasi yang terbaca mesin | `"operational-mandates"` |
| `description` | string | Deskripsi satu baris untuk registri | `"Operational mandates CM-1–10"` |
| `pathFilter` | string | Daftar glob yang dipisahkan koma yang membatasi cakupan aturan berfilter jalur; string kosong (`""`) pada aturan yang selalu aktif | `"**/*.py, **/*.toml"` |
| `alwaysApply` | boolean | `true` untuk aturan yang selalu aktif (dimuat di mana saja); `false` untuk aturan berfilter jalur (dimuat ketika `pathFilter` cocok) | `true` |

### Field Opsional

Aturan tidak membawa field frontmatter opsional, dan — tidak seperti kelas artefak lainnya — juga tidak membawa field `version` / `updated` / `scope` / `portability`. Empat field wajib di atas adalah kontrak frontmatter aturan yang lengkap, yang ditegakkan oleh `frontmatter_grep`.

### Contoh

```yaml
---
name: "operational-mandates"
description: "Behavioral definitions for CM-1 through CM-10: violation indicators and recovery actions"
pathFilter: ""
alwaysApply: true
---

# Rule: Operational Mandates
...
```

## Skema: Command

**Pola jalur:** `src/apothem/commands/*.md`

**Tujuan:** Definisi slash command (`/plan-execute`, `/freshify`, dsb.).

### Field Wajib

```yaml
---
name: "command-name"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "What this command does"
argument-hint: "[argument-pattern]"
disable-model-invocation: true | false
portability: "universal"
allowed-tools: "Read, Glob, Grep"
---
```

| Field | Tipe | Tujuan | Contoh |
| ----- | ---- | ------- | ------- |
| `name` | string | Nama command (tanpa `/` di awal) | `"plan-execute"` |
| `version` | string | Versi semantik | `"X.Y.Z"` |
| `updated` | string (ISO 8601) | Tanggal pembaruan terakhir | `"2026-04-20"` |
| `description` | string | Deskripsi singkat | `"Executes a phase with quality gates"` |
| `argument-hint` | string | Pola penggunaan, atau `"[args...]"` jika tidak ada | `"[path/to/plan] [phase-id]"` |
| `disable-model-invocation` | boolean | Jika true, hanya operator yang memulai command; model tidak pernah memanggilnya atas inisiatifnya sendiri | `true` |
| `portability` | string | Klasifikasi portabilitas lintas adapter harness | `"universal"` |
| `allowed-tools` | string | Tool yang disetujui sebelumnya selama command berjalan: tool baca-saja, ditambah tool yang memiliki efek samping hanya sebagai aturan bercakupan seperti `Bash(git log *)`. Wildcard `"*"` polos ditolak | `"Read, Glob, Grep"` |

### Field Opsional

Command tidak membawa field frontmatter opsional — delapan field wajib di atas adalah kontrak frontmatter command yang lengkap, yang ditegakkan oleh `command.schema.json` (`additionalProperties: false`).

### Contoh

```yaml
---
name: "plan-execute"
version: "X.Y.Z"
updated: "2026-04-20"
description: "Executes a specific phase from a Master Plan Suite with conformity checking and quality gates"
argument-hint: "[path/to/plan-suite/] [phase-id] [--dry-run]"
disable-model-invocation: true
portability: "universal"
allowed-tools: "Read, Glob, Grep"
---

# /plan-execute — Execute a Specific Phase
...
```

## Skema: Pembantu

**Pola jalur:**

```text
src/apothem/agents/*.md
```

**Tujuan:** Definisi pembantu persisten (disebut juga pekerja terdelegasi)
untuk eksplorasi paralel, audit, dan gerbang kualitas.

### Field Wajib

```yaml
---
name: "agent-name"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "What this agent specializes in"
tools: "Tool1, Tool2, Tool3"
disallowedTools: "Write, Edit"
maxTurns: 20
effort: "high" | "medium" | "low"
---
```

| Field | Tipe | Tujuan | Contoh |
| ----- | ---- | ------- | ------- |
| `name` | string | Pengidentifikasi pembantu | `"codebase-explorer"` |
| `version` | string | Versi semantik | `"X.Y.Z"` |
| `updated` | string (ISO 8601) | Tanggal pembaruan terakhir | `"2026-04-20"` |
| `description` | string | Deskripsi spesialisasi | `"Deep codebase exploration"` |
| `tools` | string (dipisahkan koma) | Tool yang diizinkan | `"Read, Glob, Grep, Bash"` |
| `disallowedTools` | string (dipisahkan koma) | Tool yang dilarang | `"Write, Edit, TodoWrite"` |
| `maxTurns` | integer | Jumlah maksimum giliran percakapan (umumnya 5–20; nilai di atas 20 memerlukan komentar alasan sebaris) | `20` |
| `effort` | enum | Cakupan komputasi | `"high"` |

### Field Opsional

```yaml
permissionMode: "default"       # Permission handling
memory: user | project | local  # Persistent-memory scope; omit for none
pattern: "Research" | "Audit" | "Implementation" | "Quality"  # Agent team pattern
portability: "universal"
```

### Contoh

```yaml
---
name: "codebase-explorer"
version: "X.Y.Z"
updated: "2026-04-20"
description: "Deep codebase exploration — find patterns, trace dependencies, discover conventions, map architecture"
tools: "Read, Glob, Grep, Bash"
disallowedTools: "Write, Edit, TodoWrite"
maxTurns: 20
effort: "high"
permissionMode: "default"
portability: "universal"
---

You are a codebase exploration specialist...
```

## Skema: Skill

**Pola jalur:** `src/apothem/skills/*/SKILL.md`

**Tujuan:** Definisi teknik yang dapat digunakan ulang, dengan sinyal deteksi
dan prosedur eksekusi.

### Field Wajib

```yaml
---
name: "skill-name"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "What this skill teaches"
archetype: "workflow-template"
userInvocable: true | false
disable-model-invocation: true | false
allowed-tools: "Read, Glob, Grep"
---
```

| Field | Tipe | Tujuan | Contoh |
| ----- | ---- | ------- | ------- |
| `name` | string | Pengidentifikasi skill | `"plan-suite"` |
| `version` | string | Versi semantik | `"X.Y.Z"` |
| `updated` | string (ISO 8601) | Tanggal pembaruan terakhir | `"2026-04-20"` |
| `description` | string | Apa yang disediakan skill | `"Master Plan Suite template"` |
| `archetype` | string | Kelas bentuk, berupa pengidentifikasi `<class>-template` dalam kebab-case | `"workflow-template"` |
| `userInvocable` | boolean | Jika true, pengguna dapat meminta skill ini secara eksplisit | `false` |
| `disable-model-invocation` | boolean | Jika true, skill hanya dicapai melalui pemanggilan eksplisit | `true` |
| `allowed-tools` | string | Tool yang disetujui sebelumnya selama skill berjalan: tool baca-saja, ditambah tool yang memiliki efek samping hanya sebagai aturan bercakupan seperti `Bash(git log *)`. Wildcard `"*"` polos ditolak | `"Read, Glob, Grep"` |

### Field Opsional

```yaml
argument-hint: "[args...]"                           # Usage pattern if userInvocable
```

### Contoh

```yaml
---
name: "ecosystem-audit"
version: "X.Y.Z"
updated: "2026-04-20"
description: "Comprehensive blind audit of the apothem ecosystem"
archetype: "audit-template"
userInvocable: true
disable-model-invocation: true
allowed-tools: "Read, Glob, Grep, Agent, TodoWrite"
argument-hint: "[--focus area] [--fix]"
---

## Purpose
...
```

## Skema: Hook

**Pola jalur:** blok `hooks` pada `settings.json` ditambah implementasi Python
di bawah `src/apothem/hooks/`.

**Tujuan:** Mendeklarasikan validator yang dipicu peristiwa dan handler
manajemen status yang dipanggil host pada titik siklus hidup yang terdefinisi
dengan jelas.

### Skema Berkas Pengaturan

Kunci tingkat atas `hooks` memetakan nama peristiwa ke array blok matcher:

```json
"hooks": {
  "<EventName>": [
    {
      "matcher": "<pattern>",
      "hooks": [
        {
          "type": "command",
          "command": "${PYTHON_BIN}",
          "args": ["${HARNESS_ROOT}/.apothem/support/hooks/dispatch.py", "<EventName>", "<message-name>"],
          "timeout": <seconds>,
          "statusMessage": "<short human-readable label>"
        }
      ]
    }
  ]
}
```

Bentuk `-m apothem.hooks.dispatch` diperuntukkan bagi pengembangan dari checkout sumber dengan `PYTHONPATH=src`.

| Field | Tipe | Tujuan | Contoh |
| ----- | ---- | ------- | ------- |
| `matcher` | string | Pola nama tool (atau `"*"` untuk peristiwa yang tidak bergantung pada tool) | `"Write"` |
| `hooks[].type` | literal `"command"` | Satu-satunya tipe handler hook yang didukung saat ini | `"command"` |
| `hooks[].command` | string | Perintah yang dapat dieksekusi; Apothem menggunakan placeholder `${PYTHON_BIN}`, yang di-resolve saat pemasangan | `"${PYTHON_BIN}"` |
| `hooks[].args` | array string | Argumen bentuk exec: jalur skrip di bawah `${HARNESS_ROOT}/.apothem/support/`, lalu argumennya | `["${HARNESS_ROOT}/.apothem/support/hooks/dispatch.py", "SessionStart"]` |
| `hooks[].timeout` | integer detik | Waktu jalan maksimum sebelum host menghentikan hook | `30` |
| `hooks[].statusMessage` | string | Label singkat yang ditampilkan di UI host | `"Session start"` |

### Peristiwa Wajib

Templat Claude Code mendaftarkan empat peristiwa: SessionStart, PreToolUse, PostToolUse, dan Stop. `scripts/dev/validate_hooks.py` memeriksa `settings.json` untuk lima peristiwa pada tabel di bawah, yang merupakan kumpulan yang berbeda, dan melaporkan setiap peristiwa yang tidak ditemukannya sebagai peringatan, bukan kegagalan. PostToolUse terdaftar tetapi bukan salah satu dari kelima peristiwa itu. PreCompact dan PostCompact termasuk di antara kelima peristiwa itu tetapi tidak didaftarkan pada Claude Code ([referensi hook](/docs/reference/hooks)), sehingga pemeriksa memberi peringatan untuk keduanya di sana.

> **Nilai timeout mencerminkan anggaran peristiwa hook kanonik** — tabel di
> bawah mereproduksinya demi kemudahan pembaca; sumber kanonik yang berlaku.

| Peristiwa | Timeout Umum | Tujuan |
| ----- | --------------- | ------- |
| `SessionStart` | 30 detik | Membaca memori, memeriksa status rencana, melaporkan kesiapan |
| `PreToolUse` | 10 detik | Memvalidasi penulisan terhadap kebijakan isolasi konten + frontmatter |
| `PreCompact` | 30 detik | Memverifikasi bahwa status telah dieksternalisasi sebelum pemadatan konteks |
| `PostCompact` | 30 detik | Memulihkan status kerja setelah pemadatan konteks |
| `Stop` | 60 detik | Eksternalisasi akhir sesi — status untuk melanjutkan, keluaran, keputusan |

`dispatch.py` juga menerima `UserPromptSubmit` dan `Notification` dalam daftar
izin peristiwanya demi kompatibilitas ke depan; tidak satu pun dari keduanya
terhubung di templat yang dikirimkan. Tambahkan blok matcher dengan pola
bentuk-exec yang sama untuk mengaktifkannya.

### Lapisan Python

Setiap perintah hook dirutekan melalui dispatcher Python yang sama:

| Berkas | Peran |
| ---- | ---- |
| `src/apothem/hooks/dispatch.py` | Merutekan `SessionStart` ke `session_start_bootstrap.main()` dan setiap peristiwa lain dalam daftar izin ke `emit_hook_context.main()`. Selalu keluar dengan kode 0. |
| `src/apothem/hooks/session_start_bootstrap.py` | Skrip hook awal sesi — memancarkan konteks memori dan ringkasan suite rencana. |
| `src/apothem/hooks/emit_hook_context.py` | Pemancar hook default — menulis amplop valid yang membawa payload `--context-file` yang terdaftar. |
| `src/apothem/hooks/messages/*.md` | Payload konteks statis yang dirujuk oleh `--context-file`. |

### Validasi

`scripts/dev/validate_hooks.py` menegakkan kontrak hook:

- `settings.json` dapat diurai sebagai JSON dan mendeklarasikan masing-masing dari lima peristiwa pada tabel; peristiwa yang hilang adalah peringatan, bukan kegagalan.
- Ketiga skrip Python ada dan dapat diurai sebagai Python yang valid.
- Semua berkas pesan yang dirujuk oleh argumen `--context-file` ada.
- Tidak ada jalur pengguna absolut yang di-hardcode (`C:\Users\...` dsb.) yang muncul di `src/apothem/hooks/**.py`.
- Artefak shell di bawah `src/apothem/hooks/` dan `scripts/` dibatasi pada stub locator / bootstrap yang disetujui.

## Skema: CLAUDE.md

**Jalur:** `CLAUDE.md` (root)

**Tujuan:** Instruksi Claude Code yang berlingkup proyek.

### Frontmatter YAML Wajib

```yaml
---
name: "CLAUDE"
version: "MAJOR.MINOR.PATCH"
updated: "YYYY-MM-DD"
description: "Project-scoped Claude Code instructions for the Apothem source repository"
scope: "project"
portability: "project-local"
---
```

### Bagian

`CLAUDE.md` ditulis dalam bagian-bagian prosa, yang dijelaskan di [`CLAUDE.md`](/docs/reference/claude-md). Tidak ada validator yang mewajibkan daftar bagian yang tetap: `scripts/dev/validate_ecosystem.py` memeriksa kunci frontmatter di atas.

## Daftar Periksa Validasi

Setiap artefak harus memenuhi pemeriksaan berikut:

### Validasi Frontmatter

- [ ] YAML valid secara sintaksis (tanpa galat penguraian)
- [ ] Semua field wajib untuk tipe artefak tersebut ada
- [ ] `name` mengikuti konvensi kebab-case
- [ ] `version` bersifat semantik (`MAJOR.MINOR.PATCH`)
- [ ] `updated` berformat tanggal ISO 8601 (`YYYY-MM-DD`)
- [ ] `description` berupa string yang tidak kosong dan terdiri dari satu baris
- [ ] Field opsional cocok dengan nilai enum yang diharapkan (jika berlaku)
- [ ] Tidak ada salah ketik pada nama field (gunakan nama kanonik dari skema)
- [ ] Tidak ada spasi berlebih atau masalah format

### Validasi Konten

- [ ] Konten dimulai pada baris baru setelah `---` penutup; pada berkas keluarga Markdown, baris header SPDX kanonik adalah konten pertama setelahnya
- [ ] Tidak ada rujukan internal rencana (kepatuhan CM-7)
- [ ] Rujukan silang dapat di-resolve (jika mencantumkan artefak lain)
- [ ] Tautan menggunakan jalur relatif dengan garis miring maju

### Validasi Portabilitas

- [ ] Tidak ada jalur absolut yang di-hardcode (gunakan jalur relatif)
- [ ] Tidak ada sintaks khusus Windows dalam artefak berlingkup universal
- [ ] Pemisah jalur menggunakan garis miring maju
- [ ] Variabel lingkungan menggunakan format yang tidak bergantung pada platform (`${VAR}` atau format native tool)

## Catatan

- **Konsistensi sebagai Keamanan:** Frontmatter kanonik memungkinkan validasi
  otomatis, perkakas, dan verifikasi lintas artefak. Penyimpangan cepat
  menumpuk.
- **Deklarasi Portabilitas:** Tidak semua artefak dapat bersifat universal.
  Deklarasikan batasan secara eksplisit — lebih baik mendokumentasikan sebuah
  catatan peringatan daripada mengirimkan bug yang senyap.
- **Kebab-case untuk Nama:** Mudah digunakan dalam URL, skrip, dan konteks
  baris perintah. Hindari spasi, garis bawah, dan camelCase untuk nama.
- **Higiene Kenaikan Versi:** Setiap suntingan yang mengubah perilaku harus menaikkan `version` dan `updated` bersamaan. Perbaikan format atau salah ketik murni menaikkan PATCH; bagian opsional atau anti-pola baru menaikkan MINOR; reorganisasi struktural atau perubahan kontrak menaikkan MAJOR.
