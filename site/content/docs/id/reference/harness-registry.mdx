Registri harness adalah inventaris adapter yang menjadi sumber kebenaran, yang
digunakan oleh CLI, dokumentasi, pengujian fixture, dan validasi pin konvensi.
Sumber runtime-nya adalah `src/apothem/lib/harness_registry.py`; setiap baris di
bawah dapat dilacak ke registri itu, ke `capabilities.yml` per adapter, dan ke
`STANDARD-CONVENTION-PIN.md` milik setiap adapter.

## Dukungan kohor muatan

Nilai status adalah `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable`, dan
`discovery-pending`.

Kohor `converted` ditulis ulang ke dalam format milik harness itu sendiri, dan
sebagian field sumber tidak memiliki tempat di dalamnya. Untuk setiap kohor
command, agen, atau aturan yang dikonversi, `capabilities.yml` milik adapter
membawa map `conversion_losses` yang menyatakan apa yang terjadi pada setiap
field frontmatter sumber:

| Nilai | Arti |
| --- | --- |
| `native:<field>` | Harness membacanya di bawah field tersebut. |
| `sidecar:<path>` | Field ditulis ke berkas terpisah di samping berkas hasil konversi, misalnya `agents/openai.yaml` milik Codex. |
| `filename` | Field dibawa oleh nama berkas atau folder. |
| `inlined` | Field dipindahkan ke dalam teks prompt atau isi. |
| `ignored` | Field tetap ada di berkas, tetapi harness tidak membacanya. |
| `dropped` | Field dihilangkan. |

Sebuah pengujian merender setiap berkas hasil konversi dan memeriksa map
tersebut terhadap keluarannya.

| Harness | Payload native atau yang dikonversi | Payload pohon pendukung | Peringatan tidak didukung atau tertunda |
| --- | --- | --- | --- |

`Hermes`, `Kiro`, `Open-Claw`, `OpenCode`, dan `Qwen Code`.

## Root bersama

Sebagian target pemasangan dimuat oleh harness selain harness yang menulisnya.
Registri mencatat setiap jalur semacam itu di `SHARED_ROOTS` dengan satu pemilik
terdaftar (adapter yang didokumentasikan vendor untuk jalur tersebut), para
co-installer yang menulis berkas yang sama ke jalur itu, dan para pembaca yang
dokumentasi vendornya memuat jalur itu secara bawaan, beserta halaman vendor
yang memperlihatkannya dan tanggal halaman tersebut diambil.

Jalur dengan co-installer adalah folder tingkat pengguna di direktori home yang
ditulis oleh beberapa pemasangan dengan byte yang sama. Mesin yang hanya
memasang `Cursor` tidak memiliki `Codex` untuk menulis `~/.agents/skills/`,
sehingga setiap pemasangan yang menyebut folder itu menulisnya, dan ledger
pemasangan menghitung pemasangan yang menggunakannya. Pemilik tercatat adalah
pemilik terdaftar selama ia menggunakan folder itu, dan jika tidak, pemasangan
tertua yang menggunakannya; tidak ada yang berpindah ketika pemilik terdaftar
dicopot. Pencopotan menghapus folder itu hanya ketika tidak ada pemasangan lain
yang masih menggunakannya (lihat [`uninstall`](/docs/cli-reference/uninstall#folder-bersama-di-direktori-home-anda)).
Memasang pembaca tidak menempatkan berkas apa pun di folder itu; memasang
pemilik atau co-installer menempatkan konten Apothem di hadapan setiap pembaca.

| Jalur | Pemilik | Co-installer | Pembaca |
| --- | --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, GitHub Copilot, Windsurf, Zed | Gemini CLI, Kimi Code, Open-Claw, OpenCode, Qwen Code |
| `~/.config/apothem/rules/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | tidak ada |
| `~/.config/apothem/templates/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | tidak ada |
| `~/.claude/skills/` | Claude Code | tidak ada | Cursor, OpenCode |
| `~/.claude/agents/` | Claude Code | tidak ada | Cursor |
| `~/.codex/agents/` | Codex | tidak ada | Cursor |
| `~/.claude/CLAUDE.md` | Claude Code | tidak ada | OpenCode |
| `<project>/AGENTS.md` | Kimi Code | tidak ada | Antigravity, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | tidak ada | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | tidak ada | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | tidak ada | Zed |

`~/.config/apothem/rules/` dan `~/.config/apothem/templates/` memuat berkas yang
dikutip oleh skill dan berkas instruksi milik Apothem sendiri. Tidak ada tool
lain yang memuatnya, sehingga keduanya tidak memiliki pembaca dan halaman
vendor. `CodeBuddy`, `Kiro`, dan `Trae` juga menulis folder skill milik mereka
sendiri (`~/.codebuddy/skills/`, `~/.kiro/skills/`, dan `~/.trae/skills/`);
hanya tool tersebut yang memuatnya, sehingga folder itu bukan root bersama.

Sebuah pembaca dicantumkan hanya jika dokumentasi vendornya memperlihatkan
pemuatan bawaan atas jalur persis tersebut. Satu pembaca membawa syarat, dan
catatan pemasangan mengulanginya: `Open-Claw` mengindeks `~/.agents/skills/`
hanya di bawah direktori status bawaannya (ia melewati folder itu ketika
`OPENCLAW_STATE_DIR` menunjuk ke tempat lain). Dokumentasi `Cursor` mencantumkan
`~/.codex/agents/` sebagai folder kompatibilitas `Codex` tetapi tidak menyebut
format berkas mana yang diurai `Cursor` di sana, dan pemasangan `Codex` menulis
berkas TOML, sehingga apakah `Cursor` membaca helper tersebut belum
terkonfirmasi. Pemasangan `Cursor` juga menulis salinan helper miliknya sendiri
di `<project>/.cursor/agents/`, yang oleh urutan prioritas vendor ditempatkan di
atas folder yang diimpornya, sehingga di proyek yang terpasang salinan native
itu menggantikan salinan dari `~/.claude/agents/`.

Sebagian tool sengaja tidak menjadi pembaca `~/.agents/skills/`: dokumentasi
`Antigravity`, `CodeBuddy`, `Kiro`, dan `Trae` tidak menyatakan bahwa mereka
memuatnya secara bawaan (`Trae` memuat folder proyek `.agents/skills/` hanya
setelah sebuah pengaturan diaktifkan), itulah sebabnya `CodeBuddy`, `Kiro`, dan
`Trae` mendapat folder skill milik mereka sendiri. Dokumentasi `Hermes`
menyebutnya hanya sebagai contoh nilai untuk `skills.external_dirs`.
`GitHub Copilot` bukan pembaca `~/.claude/agents/`: dokumentasi VS Code
mencantumkan folder itu untuk agen Anthropic Claude, bukan untuk agen yang
dijalankan `GitHub Copilot`.

Blok Apothem yang ditulis pemilik ke dalam berkas instruksi bersama tidak
menyebut satu tool tunggal pun sebagai pembacanya.
`tests/unit/test_shared_roots.py` gagal ketika adapter yang menulis sebuah
target registri tidak persis sama dengan pemiliknya dan para co-installer-nya,
dan ketika sebuah target registri yang dinamai seperti
berkas instruksi lintas tool (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`copilot-instructions.md`) tidak memiliki pemilik yang dideklarasikan.
Satu-satunya pengecualian adalah `~/.codex/AGENTS.md`, yang tidak
didokumentasikan sebagai dimuat oleh harness terdaftar lain mana pun.

## Hook validasi

Registri tetap tersinkronisasi melalui pemeriksaan berikut:

| Pemeriksaan | Tujuan |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | Memastikan setiap adapter memiliki pin konvensi yang berusia paling lama 90 hari, mengutip setidaknya satu URL vendor, dan tidak memiliki target penemuan yang lewat tenggat. CI menjalankannya pada setiap pull request, setiap minggu, dan sebelum rilis. |
| `python scripts/dev/check_vendor_urls.py` | Mengambil setiap URL vendor yang dikutip pin dan templat harness, dan gagal pada halaman yang dipindahkan atau mati, termasuk nama host yang tidak lagi ter-resolve atau sertifikat yang gagal verifikasi; timeout, koneksi yang ditolak atau di-reset, atau galat server 5xx dilaporkan sebagai tidak terjangkau dan tidak menggagalkannya. Monitor konvensi mingguan menjalankannya. |
| `python -m apothem.conformity.gate --all .` | Menjalankan pemeriksaan konformitas dokumentasi dan implementasi. |
| `python -m pytest` | Menjalankan pengujian fixture registri dan pengujian kontrak adapter. |
