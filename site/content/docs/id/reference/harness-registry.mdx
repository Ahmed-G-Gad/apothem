Registri harness adalah inventaris adapter yang menjadi sumber kebenaran, yang
digunakan oleh CLI, dokumentasi, pengujian fixture, dan validasi pin konvensi.
Sumber runtime-nya adalah `src/apothem/lib/harness_registry.py`; setiap baris di
bawah dapat dilacak ke registri itu, ke `capabilities.yml` per adapter, dan ke
`STANDARD-CONVENTION-PIN.md` milik setiap adapter.

## Dukungan kohor muatan

Nilai status adalah `native`, `converted`, `support-tree`,
`profile-projected`, `unsupported`, `not-applicable`, dan
`discovery-pending`.

Kohor `converted` ditulis ulang ke dalam format milik harness itu sendiri, dan
sebagian field sumber tidak memiliki tempat di dalamnya. Untuk setiap kohor
command, agen, atau aturan yang dikonversi, `capabilities.yml` milik adapter
membawa map `conversion_losses` yang menyatakan apa yang terjadi pada setiap
field frontmatter sumber:

| Nilai | Arti |
| --- | --- |
| `native:<field>` | Harness membacanya di bawah field tersebut. |
| `sidecar:<path>` | Field ditulis ke berkas terpisah di samping berkas hasil konversi, misalnya `agents/openai.yaml` milik Codex. |
| `filename` | Field dibawa oleh nama berkas atau folder. |
| `inlined` | Field dipindahkan ke dalam teks prompt atau isi. |
| `ignored` | Field tetap ada di berkas, tetapi harness tidak membacanya. |
| `dropped` | Field dihilangkan. |

Sebuah pengujian merender setiap berkas hasil konversi dan memeriksa map
tersebut terhadap keluarannya.

| Harness | Payload native atau yang dikonversi | Payload pohon pendukung | Peringatan tidak didukung atau tertunda |

`Hermes`, `Kiro`, `Open-Claw`, `OpenCode`, dan `Qwen Code`.

## Root bersama

Sebagian target pemasangan dimuat oleh harness selain harness yang menulisnya.
Registri mencatat setiap jalur semacam itu di `SHARED_ROOTS` dengan satu pemilik
terdaftar (adapter yang didokumentasikan vendor untuk jalur tersebut), para
co-installer yang menulis berkas yang sama ke jalur itu, dan para pembaca yang
dokumentasi vendornya memuat jalur itu secara bawaan, beserta halaman vendor
yang memperlihatkannya dan tanggal halaman tersebut diambil.

Jalur dengan co-installer adalah folder tingkat pengguna di direktori home yang
ditulis oleh beberapa pemasangan dengan byte yang sama. Mesin yang hanya
memasang `Cursor` tidak memiliki `Codex` untuk menulis `~/.agents/skills/`,
sehingga setiap pemasangan yang menyebut folder itu menulisnya, dan ledger
pemasangan menghitung pemasangan yang menggunakannya. Pemilik tercatat adalah
pemilik terdaftar selama ia menggunakan folder itu, dan jika tidak, pemasangan
tertua yang menggunakannya; tidak ada yang berpindah ketika pemilik terdaftar
dicopot. Pencopotan menghapus folder itu hanya ketika tidak ada pemasangan lain
yang masih menggunakannya (lihat [`uninstall`](/docs/cli-reference/uninstall#shared-folders-in-your-home-directory)).
Memasang pembaca tidak menempatkan berkas apa pun di folder itu; memasang
pemilik atau co-installer menempatkan konten Apothem di hadapan setiap pembaca.

| Jalur | Pemilik | Co-installer | Pembaca |
| --- | --- | --- | --- |
| `~/.agents/skills/` | Codex | Cursor, GitHub Copilot, Windsurf, Zed | Gemini CLI, Kimi Code, Open-Claw, OpenCode, Qwen Code |
| `~/.config/apothem/rules/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | tidak ada |
| `~/.config/apothem/templates/` | Codex | CodeBuddy, Cursor, GitHub Copilot, Kiro, Trae, Windsurf, Zed | tidak ada |
| `~/.claude/skills/` | Claude Code | tidak ada | Cursor, OpenCode |
| `~/.claude/agents/` | Claude Code | tidak ada | Cursor |
| `~/.codex/agents/` | Codex | tidak ada | Cursor |
| `~/.claude/CLAUDE.md` | Claude Code | tidak ada | OpenCode, Windsurf |
| `<project>/AGENTS.md` | Kimi Code | tidak ada | Antigravity, Claude Code, CodeBuddy, Codex, Cursor, GitHub Copilot, Hermes, Kiro, OpenCode, Windsurf, Zed |
| `<project>/GEMINI.md` | Gemini CLI | tidak ada | Antigravity, GitHub Copilot, Zed |
| `~/.gemini/GEMINI.md` | Antigravity | tidak ada | Gemini CLI |
| `<project>/.github/copilot-instructions.md` | GitHub Copilot | tidak ada | Zed |

`~/.config/apothem/rules/` dan `~/.config/apothem/templates/` memuat berkas yang
dikutip oleh skill dan berkas instruksi milik Apothem sendiri. Tidak ada tool
lain yang memuatnya, sehingga keduanya tidak memiliki pembaca dan halaman
vendor. `CodeBuddy`, `Kiro`, dan `Trae` juga menulis folder skill milik mereka
sendiri (`~/.codebuddy/skills/`, `~/.kiro/skills/`, dan `~/.trae/skills/`);
hanya tool tersebut yang memuatnya, sehingga folder itu bukan root bersama.

Sebuah pembaca dicantumkan hanya jika dokumentasi vendornya memperlihatkan
pemuatan bawaan atas jalur persis tersebut. Ketika sebuah pembaca memuat suatu
jalur hanya dalam kasus tertentu, registri mencatat syaratnya, dan catatan
pemasangan mengulanginya. `Open-Claw` mengindeks
`~/.agents/skills/` hanya di bawah direktori status bawaannya (ia melewati
folder itu ketika `OPENCLAW_STATE_DIR` menunjuk ke tempat lain). `OpenCode` 1
memuat `~/.claude/CLAUDE.md` hanya jika folder konfigurasinya (secara default
`~/.config/opencode/`) tidak berisi `AGENTS.md`,
dan melewatinya ketika `OPENCODE_DISABLE_CLAUDE_CODE_PROMPT=1` atau
`OPENCODE_DISABLE_CLAUDE_CODE=1` ditetapkan. `OpenCode` 2 membaca konfigurasi
`~/.config/opencode/` yang sama tetapi tidak memiliki fallback `CLAUDE.md`,
sehingga ia tidak memuat `~/.claude/CLAUDE.md`. `Codex` mengambil yang pertama
dari `AGENTS.override.md` dan `AGENTS.md` di setiap folder, sehingga ia memuat
`<project>/AGENTS.md` hanya jika proyek tidak memiliki `AGENTS.override.md` di
sebelahnya. `CodeBuddy` memakai `<project>/AGENTS.md` sebagai memori proyek
hanya jika proyek tidak memiliki `CODEBUDDY.md`. `Claude Code` membaca
`AGENTS.md` pada rilis yang disebutkan
[halaman memorinya](https://code.claude.com/docs/en/memory#agents-md), dan
catatan instalasi memberikan rilis pertamanya. Di bawah setelan bawaan
**Project instructions**, ia memuat setiap `AGENTS.md` dan `.claude/AGENTS.md`
di folder kerja dan folder-folder di atasnya ketika sesi dimulai, tetapi hanya
jika tidak satu pun dari folder itu menyimpan `CLAUDE.md`, `.claude/CLAUDE.md`,
atau `CLAUDE.local.md`. Ia memuat `AGENTS.md` dari folder di bawah folder kerja,
seperti proyek yang dibuka dari folder induk, ketika alat Read-nya membuka
berkas di sana dan folder itu juga tidak memiliki satu pun dari ketiga berkas
tersebut. `~/.claude/CLAUDE.md` tidak dihitung, sehingga blok Apothem di sana
tetap dimuat bersama `<project>/AGENTS.md`. Setelan `claude-md-and-agents-md`
memuat kedua jenis berkas, sedangkan `claude-md` dan `managed-only` tidak
memuat `AGENTS.md` apa pun. Beberapa sesi tidak membaca `AGENTS.md` di bawah
setelan apa pun; halaman memori mencantumkannya. `Zed` hanya memuat berkas
instruksi proyek pertama dalam daftarnya: `.rules`, `.cursorrules`,
`.windsurfrules`, `.clinerules`, `.github/copilot-instructions.md`, `AGENT.md`,
`AGENTS.md`, `CLAUDE.md`, lalu `GEMINI.md`. Karena itu ia memuat
`<project>/.github/copilot-instructions.md`, `<project>/AGENTS.md`, dan
`<project>/GEMINI.md` hanya jika proyek tidak memiliki satu pun berkas yang
berada di depan berkas itu dalam daftar. Pemasangan `Zed` menulis
`<project>/.rules`, berkas pertama dalam daftar, sehingga `Zed` tidak memuat satu
pun dari ketiganya di proyek tempat ia dipasang.

`Hermes` memuat satu jenis konteks proyek per sesi: jenis pertama yang memiliki
berkas tidak kosong, dengan urutan `.hermes.md` atau `HERMES.md`, rantai
`AGENTS.md` (di setiap folder, `AGENTS.override.md` yang tidak kosong
menggantikan `AGENTS.md` di sebelahnya), `CLAUDE.md`, lalu aturan `Cursor`.
Karena itu ia memuat `<project>/AGENTS.md` hanya jika proyek tidak memiliki
`.hermes.md` atau `HERMES.md` dan tidak ada `AGENTS.override.md` di sebelahnya,
serta `<project>/.cursor/rules/apothem-rules.mdc` hanya jika proyek tidak
memiliki `.hermes.md`, `HERMES.md`, `AGENTS.override.md`, `AGENTS.md`, atau
`CLAUDE.md`. `Hermes` mencari `.hermes.md` dan `HERMES.md` dari folder tempat ia
dimulai hingga root git, dan membaca rantai `AGENTS.md` dari root git ke bawah,
sehingga berkas semacam itu di folder di atas proyek juga dihitung. Berkas
kosong tidak dihitung. `.hermes.md` yang kosong juga menyembunyikan `HERMES.md`
di sebelahnya, sehingga `Hermes` berpindah ke rantai `AGENTS.md` meskipun
`HERMES.md` itu berisi teks. Syarat-syarat ini berlaku untuk sesi yang dimulai
di proyek. Sesi yang dimulai di folder di atas proyek tetap dapat memuat
`<project>/AGENTS.md`, atau `AGENTS.override.md` yang tidak kosong di
sebelahnya, saat sesi itu pertama kali mengerjakan sebuah berkas di proyek, apa
pun `.hermes.md` atau `HERMES.md` yang dimiliki proyek. `Hermes` melewati hal ini
di folder home dan di beberapa folder kontainer.

Dokumentasi `Cursor` mencantumkan
`~/.codex/agents/` sebagai folder kompatibilitas `Codex` tetapi tidak menyebut
format berkas mana yang diurai `Cursor` di sana, dan pemasangan `Codex` menulis
berkas TOML, sehingga apakah `Cursor` membaca helper tersebut belum
terkonfirmasi. Pemasangan `Cursor` juga menulis salinan helper miliknya sendiri
di `<project>/.cursor/agents/`, yang oleh urutan prioritas vendor ditempatkan di
atas folder yang diimpornya, sehingga di proyek yang terpasang salinan native
itu menggantikan salinan dari `~/.claude/agents/`.

`Windsurf` membaca berkas aturan tool lain melalui impor konfigurasi Devin, yang
aktif secara bawaan, dan agen Local milik Devin Desktop menemukan berkasnya
dengan cara yang sama seperti Devin CLI. Karena itu ia memuat blok
`~/.claude/CLAUDE.md` yang ditulis oleh pemasangan `Claude Code`, dan berkas
yang ditulis oleh pemasangan `Cursor`, yaitu
`<project>/.cursor/rules/apothem-rules.mdc`, yang frontmatter
`alwaysApply: true`-nya membuatnya tetap aktif di setiap sesi. Impor itu juga
membaca `CLAUDE.md` proyek, yang tidak ditulis oleh pemasangan Apothem mana pun.

Sebagian tool sengaja tidak menjadi pembaca `~/.agents/skills/`: dokumentasi
`Antigravity`, `CodeBuddy`, `Kiro`, dan `Trae` tidak menyatakan bahwa mereka
memuatnya secara bawaan (`Trae` memuat folder proyek `.agents/skills/` hanya
setelah sebuah pengaturan diaktifkan), itulah sebabnya `CodeBuddy`, `Kiro`, dan
`Trae` mendapat folder skill milik mereka sendiri. Dokumentasi `Hermes`
menyebutnya hanya sebagai contoh nilai untuk `skills.external_dirs`.
`GitHub Copilot` bukan pembaca `~/.claude/agents/`: dokumentasi VS Code
mencantumkan folder itu untuk agen Anthropic Claude, bukan untuk agen yang
dijalankan `GitHub Copilot`.

Blok Apothem yang ditulis pemilik ke dalam berkas instruksi bersama tidak
menyebut satu tool tunggal pun sebagai pembacanya.
`tests/unit/test_shared_roots.py` gagal ketika adapter yang menulis sebuah
target registri tidak persis sama dengan pemiliknya dan para co-installer-nya,
dan ketika sebuah target registri yang dinamai seperti
berkas instruksi lintas tool (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`,
`copilot-instructions.md`) tidak memiliki pemilik yang dideklarasikan, kecuali
`~/.codex/AGENTS.md`, yang tidak didokumentasikan sebagai dimuat oleh harness
terdaftar lain mana pun.

## Hook validasi

Registri tetap tersinkronisasi melalui pemeriksaan berikut:

| Pemeriksaan | Tujuan |
| --- | --- |
| `python scripts/dev/validate_harness_convention_pins.py --today YYYY-MM-DD` | Memastikan setiap adapter memiliki pin konvensi yang berusia paling lama 90 hari, mengutip setidaknya satu URL vendor, dan tidak memiliki target penemuan yang lewat tenggat. CI menjalankannya pada setiap pull request, setiap minggu, dan sebelum rilis. |
| `python scripts/dev/check_vendor_urls.py` | Mengambil setiap URL vendor yang dikutip pin dan templat harness, dan gagal pada halaman yang dipindahkan atau mati, termasuk nama host yang tidak lagi ter-resolve atau sertifikat yang gagal verifikasi; timeout, koneksi yang ditolak atau di-reset, atau galat server 5xx dilaporkan sebagai tidak terjangkau dan tidak menggagalkannya. Nama host yang hanya ter-resolve ke alamat placeholder yang tidak mungkin dimiliki server mana pun (name server vendor dapat mengembalikan alamat semacam itu untuk wilayah tempat pemeriksaan dijalankan) tidak dikirimi permintaan: nama host itu dilaporkan sebagai tidak dapat dirutekan, tidak menggagalkan pemeriksaan, dan halamannya perlu diperiksa secara manual. Monitor konvensi mingguan menjalankannya, memberi peringatan tentang setiap host semacam itu pada setiap eksekusi, dan mencantumkan halamannya di issue yang dibuatnya. |
| `python scripts/dev/check_vendor_releases.py` | Menanyakan versi terkini kepada setiap kanal rilis di `scripts/dev/vendor-release-channels.json`: dist-tag paket npm, rilis terbaru repositori GitHub (atau, untuk kanal dengan pola tag, rilis stabil terbaru dengan tag yang cocok di antara 100 rilis terbaru), atau proyek PyPI. Untuk alamat installer, ia menanyakan ke mana alamat itu dialihkan. Ia membandingkan jawabannya dengan apa yang terakhir ditinjau. ## Kanal rilis

`scripts/dev/vendor-release-channels.json` memiliki satu entri untuk setiap
folder harness. Harness yang dipantau mencantumkan kanal rilisnya. Setiap kanal
mencatat versi yang terakhir ditinjau, beserta tanggalnya. Itu adalah versi
yang disebutkan pin-nya atau, jika pin tidak menyebutkan versi, versi yang
disajikan registri saat kanal itu dicatat. Sebuah catatan juga dapat hanya
menyimpan versi mayor. Setiap kanal mengutip frasa pin yang menyebutkannya.
Angka pertama sebuah versi adalah versi mayornya, termasuk 0, sehingga lini 0.x
yang berpindah dari 0.26 ke 0.27 melaporkan versi minor yang lebih baru dan
tidak gagal. Kanal dengan versi kalender, seperti nomor tahun.bulan.rilis milik
OpenClaw, melaporkan setiap rilis yang lebih baru tanpa gagal, dan tidak
memakai tingkat `watch`. Codex, Gemini CLI, Hermes, Qwen Code, dan GLM berada
pada lini 0.x, sehingga versi baru salah satunya dicantumkan dalam ringkasan
eksekusi dan tidak membuat issue sampai mencapai 1.0, kecuali kanalnya
menyetel tingkat `watch`.

OpenCode memiliki empat kanal. `opencode-ai` membawa OpenCode 1, dan
`@opencode/cli` membawa OpenCode 2. Rilis GitHub dari `anomalyco/opencode`
menunjukkan lini mayor baru apa pun paket npm yang mengirimkannya. Kanal
keempat menanyakan ke mana `opencode.ai/install` dialihkan. Pada 2026-11-03
alamat itu dialihkan ke skrip installer OpenCode 1. Skrip itu memasang versi
yang disebutkan dist-tag `latest` milik `opencode-ai` jika itu versi OpenCode 1,
dan tidak pernah memasang OpenCode 2. Keputusan OpenCode tanggal 2026-11-03
beralih ke penulisan format milik OpenCode 2 sendiri di tempat OpenCode 2
berjalan ketika salah satu dari dua sinyal muncul: OpenCode 2 mengumumkan
tanggal penghapusan terjemahannya atas format OpenCode 1, atau
`opencode.ai/install` atau `opencode-ai` berpindah ke OpenCode 2. Pemeriksaan
memantau sinyal kedua. Kanal `opencode-ai` dan kanal installer masing-masing
membawa pemicu: pemeriksaan gagal ketika versi `latest` milik `opencode-ai`
melewati versi mayor 1, atau ketika `opencode.ai/install` berhenti dialihkan ke
skrip OpenCode 1. Perubahan di dalam skrip itu tidak mengubah pengalihan,
sehingga pemeriksaan tidak melihatnya. Tidak ada registri yang menjawab sinyal
pertama, sehingga sinyal itu tetap diperiksa secara manual, paling lambat
2027-02-01 bersama tinjauan pin OpenCode berikutnya.

Antigravity, Cursor, Kiro, Trae, dan Windsurf tidak dipantau. Masing-masing
adalah aplikasi desktop, atau alat baris perintah yang dipasang dengan skrip,
dan pin-nya tidak menyebutkan kanal rilis yang dapat ditanyai skrip tanpa
kredensial. Berkas tersebut memberikan alasan untuk masing-masing.

Setelah Anda memeriksa ulang sebuah pin terhadap rilis baru atau target
pengalihan baru, perbarui kolom `reviewed`, `reviewed_on`, dan `reviewed_from`
kanal tersebut. Pemicu pada kanal versi menggagalkan pemeriksaan setiap minggu
sampai Anda menghapus atau mengubahnya. Pemicu pada alamat installer berhenti
setelah `reviewed` mencatat target baru, jadi catat target itu hanya setelah
tindakan pemicu selesai.
