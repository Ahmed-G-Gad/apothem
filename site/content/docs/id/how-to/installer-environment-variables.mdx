Tujuan: menjalankan `install.sh` / `install.ps1` tanpa menyunting skrip, dengan
menyetel variabel lingkungan sebelum Anda menjalankannya.

## Prasyarat

- Shell POSIX (`bash`) atau PowerShell 5.1+. Contoh PowerShell di bawah ini
  menjalankan `pwsh` (PowerShell 7+). Di Windows PowerShell 5.1, jalankan
  `powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1` sebagai
  gantinya.
- Variabel dibaca satu kali di bagian atas pemasang, jadi setel variabel tersebut
  dalam perintah yang sama (atau ekspor terlebih dahulu), lalu jalankan pemasang.

## Variabel pemasang

| Variabel | Mengendalikan | Default |
| --- | --- | --- |
| `APOTHEM_HOME` | Tujuan instalasi untuk pohon sumber yang dikloning | `$HOME/.apothem` |
| `APOTHEM_REPO` | Remote Git yang dikloning | `https://github.com/ahmed-g-gad/apothem` |
| `APOTHEM_REF` | Ref Git yang di-checkout; jika tidak disetel, me-resolve tag `vMAJOR.MINOR.PATCH` bertanda tangan terbaru, sebuah nilai tag mematoknya, dan `main` memilih branch yang bergerak. Ref non-tag seperti `main` membatalkan proses kecuali `APOTHEM_ALLOW_UNVERIFIED=1`. | tidak disetel (tag bertanda tangan terbaru) |
| `APOTHEM_ALLOW_UNVERIFIED` | Menurunkan kegagalan verifikasi tanda tangan tag dari pembatalan fatal menjadi peringatan ketika disetel ke `1` | `0` (verifikasi, gagal-tertutup) |
| `APOTHEM_VERIFY` | `signature` memverifikasi tanda tangan GPG tag rilis; `checksum` memasang arsip platform rilis setelah memeriksa SHA-256-nya terhadap `SHA256SUMS` rilis (integritas, bukan bukti siapa yang memublikasikannya) | `signature` |
| `APOTHEM_RELEASE_BASE` | Basis unduhan untuk mode checksum | `<APOTHEM_REPO>/releases/download` |
| `APOTHEM_SOURCE` | Pohon sumber lokal eksplisit yang digunakan alih-alih mengkloning | tidak disetel (kloning) |
| `APOTHEM_HARNESS` | Harness yang dipasang | `claude-code` |
| `APOTHEM_PROFILE` | Jalur ke YAML profil bersama | `$HOME/.config/apothem/profile.yaml` |
| `APOTHEM_SKIP_VERIFY` | Melewati langkah verifikasi pasca-instalasi ketika disetel ke `1` | `0` (verifikasi berjalan) |
| `APOTHEM_AUTO_INSTALL_DEPS` | Memasang prasyarat `click` / `rich` yang hilang secara otomatis, tanpa meminta konfirmasi, ketika disetel ke `1` | `0` (meminta konfirmasi, atau menolak dalam pipe non-interaktif) |
| `APOTHEM_BIN_DIR` | Direktori untuk shim perintah `apothem` yang ditempatkan | `$HOME/.local/bin` (POSIX); `%LOCALAPPDATA%\Microsoft\WindowsApps` (Windows) |
| `NO_COLOR` | Menonaktifkan keluaran berwarna ketika disetel ke nilai apa pun ([no-color.org](https://no-color.org/)); warna juga nonaktif setiap kali keluaran bukan terminal (pipe, berkas, log CI) | tidak disetel (warna hanya di terminal interaktif) |

`APOTHEM_SOURCE` lebih diutamakan daripada klon: ketika disetel ke checkout yang
berisi `src/apothem`, pemasang menggunakannya secara langsung, tidak pernah
menyentuh `APOTHEM_REPO` / `APOTHEM_REF`, dan melewati resolusi tag serta
verifikasi tanda tangan (tidak ada yang diambil untuk diverifikasi).

Ketika `APOTHEM_HOME` menunjuk ke direktori yang sudah ada dan bukan klon git,
pemasang menolak menghapusnya: pindahkan direktori itu ke tempat lain, arahkan
`APOTHEM_HOME` ke lokasi lain, atau berikan `--yes` (`-Yes` di Windows) untuk
mengizinkan penggantian. Direktori kosong yang usang diganti tanpa flag
tersebut.

## Model kepercayaan

Tanpa `APOTHEM_REF` yang disetel, pemasang me-resolve tag rilis bertanda tangan
terbaru dan memverifikasi tanda tangannya dengan `git verify-tag` sebelum
mematerialisasikan konfigurasi apa pun; tag yang tidak bertanda tangan atau telah
dirusak membatalkan instalasi. Tag bertanda tangan yang kunci publik pemeliharanya
tidak ada di keyring lokal justru membatalkan instalasi dengan panduan impor
kunci — impor kunci tersebut dan periksa sidik jarinya terhadap nilai yang
dipublikasikan di
[SECURITY.md](https://github.com/ahmed-g-gad/apothem/blob/main/SECURITY.md).
Patok rilis yang diketahui dengan `APOTHEM_REF=<tag>` (juga diverifikasi; sebuah
tag dari [halaman rilis](https://github.com/ahmed-g-gad/apothem/releases)), pilih
branch yang bergerak dengan `APOTHEM_REF=main` (tidak diverifikasi), atau setel
`APOTHEM_ALLOW_UNVERIFIED=1` untuk melanjutkan melewati kegagalan verifikasi
dengan peringatan (penggunaan air-gapped, lokal, atau rilis
pra-penandatanganan).

```bash title="Pinned, verified install"
APOTHEM_REF=vMAJOR.MINOR.PATCH bash install.sh
```

```bash title="Check the archive digest when the signing key is not imported"
APOTHEM_VERIFY=checksum bash install.sh
```

```bash title="Proceed without verification (interim / air-gapped)"
APOTHEM_ALLOW_UNVERIFIED=1 bash install.sh
```

## Langkah-langkah (POSIX bash)

1. Pasang harness non-default:

   ```bash
   APOTHEM_HARNESS=cursor bash install.sh
   ```

2. Patok tujuan instalasi dan pilih branch `main` yang bergerak. Branch bukan tag
   bertanda tangan, sehingga pemasang juga memerlukan
   `APOTHEM_ALLOW_UNVERIFIED=1`:

   ```bash
   APOTHEM_REF=main APOTHEM_ALLOW_UNVERIFIED=1 APOTHEM_HOME=/opt/apothem bash install.sh
   ```

3. Gunakan checkout lokal dan profil khusus, dengan melewati verifikasi:

   ```bash
   APOTHEM_SOURCE=/work/apothem \
   APOTHEM_PROFILE=/work/profile.yaml \
   APOTHEM_SKIP_VERIFY=1 \
   bash install.sh
   ```

## Langkah-langkah (PowerShell)

Setel setiap variabel pada `$env:` sebelum menjalankan pemasang:

```powershell
$env:APOTHEM_HARNESS = 'cursor'
pwsh -NoProfile -File install.ps1
```

```powershell
$env:APOTHEM_ALLOW_UNVERIFIED = '1'
$env:APOTHEM_REF = 'main'
$env:APOTHEM_HOME = 'C:\opt\apothem'
pwsh -NoProfile -File install.ps1
```

```powershell
$env:APOTHEM_SOURCE = 'C:\work\apothem'
$env:APOTHEM_PROFILE = 'C:\work\profile.yaml'
$env:APOTHEM_SKIP_VERIFY = '1'
pwsh -NoProfile -File install.ps1
```

## Verifikasi

Pemasang mencetak `✓ Harness <name> installed`, lalu (kecuali
`APOTHEM_SKIP_VERIFY=1`) `✓ verify passed`. Konfirmasikan secara independen:

```bash
apothem verify --harness cursor
```

Ketika profil belum ada, pemasang membuatnya dari contoh dan terus berjalan
untuk memasang dan memverifikasi dalam eksekusi yang sama. Kolom identitas pada
contoh adalah placeholder, sehingga instalasi mencetak sebuah catatan; sunting
`$APOTHEM_PROFILE`, lalu jalankan `apothem update --harness <name>` untuk
menerapkan identitas Anda. `--dry-run` tanpa profil menampilkan pratinjau dengan
contoh sebagai profilnya dan tidak menulis apa pun.
