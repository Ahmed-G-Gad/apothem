Memverifikasi pemasangan adapter harness.

## Ringkasan

```
apothem verify --harness NAME|all [--profile PATH] [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

Memanggil implementasi `verify()` milik setiap adapter yang dipilih. Keluar
dengan 0 hanya ketika semua adapter yang dipilih melaporkan bahwa target
terkelolanya ada dan valid. Tanpa `--profile`, pemeriksaannya bersifat
**struktural** — setiap target terkelola harus ada dan valid. Dengan
`--profile`, pemeriksaan juga mensyaratkan **fidelitas profil**, sehingga
pemasangan yang ada tetapi telah menyimpang gagal dalam verify, menjawab
"apakah profil INI terpasang secara setia?" alih-alih sekadar "apakah ia ada?".

Untuk adapter yang menulis skill ke direktori home Anda, verify juga memeriksa
bahwa setiap folder skill yang diharapkannya ada dengan sebuah `SKILL.md`,
pemasangan mana pun yang menulisnya, sehingga mesin yang hanya memasang salah
satu dari alat-alat yang berbagi sebuah folder tetap lolos verifikasi. Verify
gagal ketika sebuah folder hilang, dan ketika folder dengan nama skill Apothem
milik sesuatu yang tidak ditulis oleh Apothem. Baris yang gagal menyebutkan
yang mana: dalam mode plain, baris `Note:` mengikutinya, dan dalam baris JSON,
objek `user_level` mencantumkan jalur `missing` dan `unlisted` serta sebuah
`message`. Jalankan [`install`](/docs/cli-reference/install) untuk memulihkan
folder yang hilang; ganti nama atau pindahkan folder asing, lalu jalankan
[`update`](/docs/cli-reference/update).

Sapuan `--harness all` mematuhi `exclude_harnesses` milik profil — pengecualian
yang sama dengan yang diterapkan batch `install`/`update` — sehingga verify
tidak pernah melaporkan harness yang sengaja dikecualikan sebagai hilang.
Pengecualian tersebut berasal dari `--profile` jika diberikan, dan jika tidak,
dari profil default; profil default yang tidak dapat dibaca atau tidak ada
jatuh kembali ke registri lengkap.

## Opsi

| Opsi | Deskripsi |
|---|---|
| `--harness NAME` | Adapter harness yang akan diverifikasi, atau `all` untuk himpunan selingkup registri (wajib). |
| `--profile PATH` | YAML profil bersama yang menjadi acuan pemeriksaan fidelitas. Tanpanya, pemeriksaan murni bersifat struktural. |
| `--project PATH` | Root proyek untuk harness berlingkup-proyek. |
| `--quiet`, `-q` | Menekan keluaran informatif; hanya galat yang dipancarkan. |
| `--verbose`, `-v` | Memancarkan keluaran diagnostik tambahan. |
| `--format plain\|json` | Format keluaran (default: `plain`). |
| `--json` | Singkatan untuk `--format json`. |
| `--no-color` | Menonaktifkan kode warna ANSI dalam keluaran. |
| `-h`, `--help` | Menampilkan bantuan dan keluar. |

## Keluaran JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "verify",
  "action": "verified",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "unchanged",
      "operation": "verify",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed targets verified",
      "installed": true,
      "verified": true
    }
  ],
  "warnings": [],
  "error": null,
  "installed": true,
  "verified": true,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Ketika salah satu harness yang dipilih hilang atau tidak valid, `status`
bernilai `error`, baris hasil yang gagal membawa `verified: false`, dan proses
keluar dengan kode 1.

## Contoh

```bash
apothem verify --harness claude-code
apothem verify --harness claude-code --json
apothem verify --harness all --project .
```

## Kode keluar

| Kode | Arti |
|---|---|
| 0 | Harness terverifikasi — semua target terkelola ada dan valid |
| 1 | Harness tidak terverifikasi — target terkelola hilang atau tidak valid |
| 64 | Galat penggunaan: opsi atau perintah yang tidak dikenal, atau nilai opsi yang hilang atau tidak valid. Di bawah `--json`, galat berupa amplop JSON dengan kode `cli.usage`. |
