Memasang konfigurasi adapter harness dari profil bersama.

## Ringkasan

```
apothem install --harness NAME|all [--profile PATH] [--dry-run]
                 [--clean|--fresh] [--yes] [--project PATH]
                 [--quiet|-q] [--verbose|-v]
                 [--format plain|json] [--json] [--no-color]
```

Memuat dan memvalidasi profil bersama, memilih adapter bernama atau himpunan
`all` selingkup registri, memvalidasi rencana materialisasi, lalu menulis
konfigurasi native-harness beserta kohor pendukung. Adapter berlingkup-proyek
memerlukan `--project PATH`. Folder itu dibaca dengan tautannya diikuti dan `~`
diperluas, dan catatan pemasangan menyebutkannya dengan cara itu. Pemasangan
yang dicatat dengan ejaan lain dari folder itu, seperti tautan yang
dipertahankan oleh kode Python atau rilis sebelumnya, dipindahkan ke ejaan
tersebut setelah pemasangan lolos pemeriksaannya (lihat
[`uninstall`](/docs/cli-reference/uninstall)).

Alias bentuk-kontinu `apothem installing` (juga diterima sebagai
`apothem Installing`) di-resolve ke handler yang sama.

## Eksekusi pertama tanpa profil

Ketika `--profile` dihilangkan dan tidak ada profil di jalur default
(`~/.config/apothem/profile.yaml`), `install` terlebih dahulu menulis profil
awal di sana, mencetak `Created a starter profile at <path>`, lalu melanjutkan.
Profil awal membawa bidang identitas placeholder, sehingga pemasangan juga
mencetak catatan identitas-placeholder; personalisasikan profil, lalu jalankan
[`update`](/docs/cli-reference/update) untuk menerapkannya. Di bawah `--json`,
pembuatan ini dilaporkan sebagai entri `warnings` dengan
`"operation": "profile_created"`.

- `--dry-run` tidak pernah menulis profil: pratinjau menggunakan profil awal di
  memori dan melaporkan `"operation": "profile_scaffold_preview"`.
- `--profile PATH` eksplisit yang tidak ada tidak pernah dibuat; perintah keluar
  dengan kode 1 disertai `profile.not_found`.

## Pratinjau radius-dampak

`install --harness all` menyebar ke cakupan campuran: adapter berlingkup-proyek menulis di bawah root `--project` yang diberikan, sedangkan adapter berlingkup-pengguna menulis di bawah direktori home Anda — di luar root tersebut. Sebelum pemasangan menulis berkas apa pun, perintah ini mencetak target konkret yang dikelompokkan di bawah dua judul: yang berada di dalam root proyek dan yang berada di bawah direktori home Anda. Judul ketiga mencantumkan folder bersama di direktori home Anda yang ditulis oleh adapter berlingkup-proyek, di luar `--project`: folder skill dan `~/.config/apothem/` (lihat [Folder di direktori home Anda](#folder-di-direktori-home-anda)). Satu-satunya pengecualian adalah `--clean`: langkah pembersihan menyeluruh berjalan sebelum pratinjau ini, menulis cadangan dan menghapus target sebelumnya, sebagaimana dijelaskan di bawah.

Ketika pilihan tersebut menulis di luar root proyek, baik ke folder milik
adapter yang berakar di direktori home maupun ke folder bersama, sebuah
konfirmasi interaktif menjaga penulisan yang berakar di direktori home. `--yes`, shell
non-interaktif (tanpa TTY), `--dry-run`, dan `--format json` masing-masing
melanjutkan tanpa meminta konfirmasi. Hanya `--dry-run` yang tidak menulis apa
pun; `--format json` melewati pratinjau dan prompt konfirmasi tetapi tetap
melakukan penulisan. Menolak prompt direktori home membatalkan proses sebelum
pemasangan menulis. Dengan `--clean`, langkah awal bersih dijalankan lebih dulu
di bawah konfirmasi per target tersendiri: langkah itu menulis cadangan di bawah
`~/.apothem/backups` dan menghapus target yang dikonfirmasinya. Penghapusan
tersebut dan cadangannya tetap berada di tempatnya ketika prompt pemasangan
ditolak.
Targetnya adalah folder alat di direktori home Anda yang dicantumkan prompt,
termasuk `~/.agents` dan `~/.config/apothem`.
Target yang dirinya sendiri berupa tautan, termasuk junction Windows, hanya
kehilangan tautannya, dan tautan di dalam target dihapus tanpa dimasuki. Ketika
`~/.config` adalah tautan yang mengarah keluar dari direktori home Anda, langkah
awal bersih berhenti dengan `Clean-slate removal was refused` sebelum
mencadangkan atau menghapus apa pun, karena menghapus `~/.config/apothem` akan
menghapus folder di ujung lain tautan itu. Galat tersebut menyebutkan tautannya:
ganti dengan folder nyata, atau arahkan ke folder di dalam direktori home Anda.
Langkah ini juga berhenti sebelum mengubah apa pun, dan sebelum membuat profil
awal, ketika direktori home Anda bukan jalur lengkap, merupakan root drive atau
sistem berkas, merupakan tautan atau junction yang mengarah ke salah satunya,
atau dicapai melalui tautan yang berputar.

Langkah awal bersih menghapus profil default,
`~/.config/apothem/profile.yaml`, bersama `~/.config/apothem`, lalu menulisnya
kembali sesudahnya. Profil yang tidak dihapusnya, seperti profil yang Anda
berikan dengan `--profile PATH` dari folder lain, sama sekali tidak ditulis.
Penulisan kembali mengikuti aturan yang sama dengan setiap penulisan profil
lainnya: penulisan itu ditolak ketika sebuah tautan akan membawanya keluar dari
direktori home Anda. Ketika profil tidak dapat ditulis kembali, perintah keluar
dengan 1 dan galatnya menyebutkan salinan cadangan yang memuatnya. Kode galatnya
adalah `clean_slate.profile_restore_refused` ketika sebuah tautan menolak
penulisan, dan `clean_slate.profile_restore_failed` ketika penulisan itu sendiri
gagal. Ketika penghapusan berhenti di tengah jalan, misalnya pada berkas yang
sedang dibuka program lain, profil ditulis kembali terlebih dahulu. Perintah
kemudian keluar dengan 1 dengan kode galat `clean_slate.removal_failed`, dan
galatnya menyebutkan folder cadangan. Jika profil tidak dapat ditulis kembali,
galatnya adalah salah satu dari dua kode profil di atas sebagai gantinya.

## Folder di direktori home Anda

Tujuh adapter berlingkup-proyek menulis skill Apothem, beserta aturan dan
templat yang dirujuk oleh skill tersebut, ke folder di direktori home pengguna
Anda:

```text
cursor, github-copilot, windsurf, zed  ->  ~/.agents/skills/ (codex writes it too)
codebuddy                               ->  ~/.codebuddy/skills/
kiro                                    ->  ~/.kiro/skills/
trae                                    ->  ~/.trae/skills/
all seven                               ->  ~/.config/apothem/rules/ and templates/ (codex uses them too)
```

- `--project` memilih berkas aturan dan proyek tempat pemasangan tersebut
  berada. Opsi ini tidak mengubah ke mana skill ditulis: pemasangan dengan
  `--project A` dan pemasangan dengan `--project B` menulis folder yang sama.
- Setiap pemasangan yang menyebutkan sebuah folder menulis berkas yang sama.
  Pemasangan kedua menemukannya dan melaporkan `unchanged`, dan urutan
  pemasangan Anda tidak berpengaruh.
- Folder home ditulis sebelum apa pun di dalam proyek. Jika penulisan di sana
  gagal, pemasangan adapter berhenti dengan galat tersebut dan proyek tidak
  berubah. Galat menyebutkan jalur yang menghalangi, misalnya berkas bernama
  `~/.agents` di tempat yang seharusnya berupa folder.
- Setiap folder skill ditulis ke folder tersembunyi `.<name>.apothem-staging`
  di sebelahnya dan diganti namanya ke tempatnya setelah lengkap, sehingga
  penulisan yang gagal atau terputus tidak pernah meninggalkan folder skill
  setengah jadi dengan nama akhirnya. Jalankan pemasangan lagi untuk
  menyelesaikannya; pemasangan itu menggantikan folder staging yang tersisa.
- Tautan pada atau di atas salah satu folder ini, seperti yang dibuat oleh
  pengelola dotfile untuk `~/.config` atau `~/.agents`, diikuti ketika
  mengarah ke suatu tempat di dalam direktori home Anda. Di Windows, junction
  dihitung sebagai tautan. Tautan yang keluar dari direktori home Anda
  menghentikan pemasangan dengan `target escapes the
  allowed materialization root`, diikuti oleh tautannya, folder yang ditujunya,
  dan perbaikannya: ganti tautan itu dengan folder nyata. Folder skill yang
  dirinya sendiri berupa tautan tidak pernah ditulis melaluinya: pemasangan
  melewatinya dengan peringatan, atau berhenti jika Apothem pernah menulis
  skill itu di sana sebelumnya. Tautan di dalam folder skill yang ditulis
  Apothem diganti dengan folder pada saat berikutnya pemasangan menulis skill
  itu.
- Folder harness di bawah `~/.config`, seperti `~/.config/opencode/` milik
  OpenCode atau `CODEX_HOME` di sana, juga mengikuti tautan di `~/.config` yang
  mengarah ke suatu tempat di dalam direktori home Anda. Tautan di `~/.config`
  yang keluar dari direktori home Anda menghentikan pemasangan sebelum menulis
  berkas apa pun, demikian pula tautan pada jalur yang ditulis pemasangan di
  dalam folder harness. Pada eksekusi pertama, profil awal, yang juga berada di
  bawah `~/.config`, juga tidak ditulis melalui tautan yang keluar dari
  direktori home Anda: eksekusi berhenti dengan `Apothem could
  not create the starter profile`, seperti halnya `apothem quickstart`, `apothem profile
  init`, `apothem profile set`, dan `apothem profile edit`. Untuk menyimpan
  profil di luar direktori home Anda, buat profil itu di sana terlebih dahulu
  dengan `apothem
  profile init --profile PATH`, dengan PATH dieja sebagai jalurnya sendiri di
  luar direktori home Anda, lalu berikan `--profile PATH` yang sama ke setiap
  perintah. Itu hanya melewati langkah profil: pemasangan yang menulis di bawah
  `~/.config` tetap berhenti di tautan itu. Untuk OpenCode, tetapkan juga
  `XDG_CONFIG_HOME` (lihat [OpenCode](/docs/harnesses/opencode)). Harness yang
  pemasangannya selalu menulis `~/.config/apothem/` memerlukan tautan yang
  mengarah ke dalam direktori home Anda sebagai gantinya; halaman harness-nya
  menyatakan hal itu.
- Folder home yang dirinya sendiri berupa tautan, seperti profil pengguna
  Windows yang dipindahkan ke drive lain di balik junction, diikuti: setiap
  penulisan tetap berada di dalam folder yang ditujunya.
- Pemasangan tidak menambahkan berkas skill atau aturan apa pun ke repositori
  Anda. Proyek mendapatkan berkas aturan adapter, ditambah folder data
  `.apothem/` yang dibuat oleh setiap pemasangan proyek.
- Folder skill yang memiliki nama skill Apothem dan tidak ditulis oleh Apothem
  dilewati. Pemasangan mencetak baris `Warning:` dan amplop `--format json`
  membawa entri `warnings` dengan `"outcome": "warning"` dan
  `"operation": "skill_conflict"` yang menyebutkan folder tersebut. Ganti nama
  atau pindahkan folder itu, lalu jalankan [`update`](/docs/cli-reference/update).
- Aturan ini mencakup setiap folder skill bersama dalam tabel di atas:
  `~/.agents/skills/`, `~/.codebuddy/skills/`, `~/.kiro/skills/`, dan
  `~/.trae/skills/`. Catatan pemasangan menunjukkan bahwa folder skill di sana
  milik Apothem selama folder pemasangannya (proyek, atau `CODEX_HOME`) masih
  hidup: folder itu ada dan masih memuat salah satu berkas yang dicatat
  pemasangan tersebut di dalamnya, dengan konten Apothem. Berkas yang dimiliki
  Apothem dihitung selama berkas itu ada. Berkas milik Anda, seperti berkas
  instruksi yang ditambahi blok oleh Apothem, hanya dihitung selama masih
  memuat blok itu atau, untuk berkas tanpa blok, konten yang dicatat Apothem,
  sehingga proyek yang di-clone ulang yang hanya menyimpan salinan berkasnya
  sendiri tidak dianggap hidup. Berkas pendukung yang ditulis pemasangan di
  bawah `.apothem/support/` dihitung; penyimpanan data di bawah `.apothem/`
  (memori, konteks, rencana) tidak, begitu pula berkas yang dicapai melalui
  tautan di dalam folder pemasangan.
- Catatan lain mana pun, yang folder pemasangannya tidak lagi ada, tidak memuat
  berkas Apothem, atau tidak dapat dibaca (drive atau share jaringan yang tidak
  merespons, galat izin), menunjukkan bahwa folder skill milik Apothem hanya
  selama folder itu memuat persis berkas-berkas yang dicatat pemasangan
  tersebut, tanpa perubahan, tanpa berkas yang ditambahkan dan tanpa tautan di
  dalamnya. Folder yang sudah memuat apa yang ditulis rilis ini dibiarkan apa
  adanya, sehingga folder yang tidak disunting yang ditulis oleh rilis
  sebelumnya tidak terpengaruh selama masih cocok dengan apa yang ditulis rilis
  ini.
- Folder bersama itu sendiri tidak pernah dihitung sebagai berkas milik folder
  pemasangan, sehingga proyek yang dipasang di folder home tidak dianggap hidup
  hanya karena `~/.agents/skills/` atau `~/.config/apothem/` ada di sana.
- Jadi ketika hanya catatan seperti itu yang mencantumkan sebuah folder skill,
  pemasangan melewatinya dan membiarkannya tidak tersentuh dalam tiga kasus:
  Anda menaruh skill Anda sendiri di sana, Anda menyuntingnya (mengubah,
  menambahkan, atau menghapus berkas), atau rilis sebelumnya yang tidak
  mencatat berkasnya menulis folder itu dan rilis ini menulis sesuatu yang
  berbeda. Hal yang sama berlaku ketika hanya pemasangan sebelumnya di folder
  yang sama yang mencantumkannya: pemasangan yang melewati folder itu tidak
  mencantumkannya, dan folder itu tetap tidak terbukti kecuali memuat persis
  berkas-berkas yang dicatat pemasangan sebelumnya.
  Peringatan pemasangan, update, dan dry-run menyebutkan penyebabnya dan dua
  cara untuk melanjutkan, dengan kata-kata yang sama seperti
  [`verify`](/docs/cli-reference/verify), yang melaporkan harness itu sebagai
  tidak terverifikasi dan menyebutkan folder-folder tersebut. Untuk
  mempertahankan skill Anda, biarkan di sana. Untuk menggunakan versi Apothem,
  pindahkan folder itu keluar dari folder skill, lalu jalankan
  [`update`](/docs/cli-reference/update) untuk harness tersebut (dengan
  `--project` untuk harness berlingkup-proyek).
- Setiap pemasangan, update, dan dry run semacam itu mencetak `Note:` yang
  menyebutkan folder yang ditulisnya di luar `--project`. Dalam amplop JSON,
  catatan ini berupa entri `warnings` dengan `"operation": "user_level_write"`
  dan daftar `paths`.

## Catatan kemampuan

Setiap adapter hanya memproyeksikan kemampuan yang didukung secara native oleh
harness-nya; kemampuan tanpa permukaan native dilaporkan, bukan dibuang
diam-diam. Dalam mode plain, ini berupa satu catatan terkelompok per harness
(misalnya `Note: <harness> - 9 capabilities not projected; pass --verbose for detail`);
di bawah `--verbose`, setiap kemampuan mencetak baris alasannya sendiri.
Peringatan adapter lainnya juga dicetak pada baris `Warning:` tersendiri dalam
mode plain, misalnya peringatan Zed yang menyebutkan berkas instruksi yang
disembunyikan oleh `.rules` yang baru, dan peringatan yang menyebutkan berkas
yang memuat penanda BEGIN Apothem tanpa END setelahnya: pemasangan
mempertahankan teks setelah penanda itu dan menulis blok Apothem terpisah
darinya, sehingga peringatan itu menyebutkan baris penandanya, memberikan
langkah-langkah bernomor yang mengubah baris itu dan setiap baris penanda BEGIN
lainnya kecuali yang membuka blok Apothem (termasuk penanda BEGIN yang Anda
kutip di dalam kode), dan meminta Anda untuk tidak menambahkan kembali penanda
END sebagai gantinya, karena itu
akan menyisakan dua blok Apothem (lihat
[Pemecahan masalah](/docs/install/troubleshooting#a-file-has-an-apothem-begin-marker-with-no-end-marker)).
Begitu pula peringatan untuk berkas yang memuat dua blok utuh atau lebih di
antara penanda Apothem, yang menyebutkan setiap blok berdasarkan baris-barisnya
(lihat
[Sebuah berkas memuat dua blok di antara penanda Apothem](/docs/install/troubleshooting#a-file-holds-two-blocks-between-apothems-markers)),
dan peringatan untuk berkas tempat Apothem tidak dapat membedakan bloknya dari
teks Anda, yang menyebutkan setiap pasangan penanda dan cara memperbaikinya
(lihat
[Apothem tidak dapat membedakan bloknya dari teks Anda](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)):
pemasangan membiarkan berkas seperti itu apa adanya (untuk pasangan penanda,
selama catatan pemasangan mencantumkan berkas itu; lihat
[`update`](/docs/cli-reference/update)). Pemasangan yang membiarkan berkas
seperti itu apa adanya berakhir sebagai parsial, karena alat tidak mendapat
blok Apothem terkini dari berkas itu: sebagai pengganti baris `✓`, pemasangan
mencetak baris `✗` di standard error yang menyebutkan berkasnya (sehingga
`--quiet` mempertahankannya), `status` amplop `--format json` bernilai
`"partial"` dan peringatan berkas itu membawa
`"detail": {"left_as_is": "1"}`, dan kode keluarnya `2`. Setiap pemasangan dan
update berakhir seperti itu sampai Anda memperbaiki baris penanda yang
disebutkan peringatan. Tanpa `--quiet`, pemasangan seperti itu dengan
`--harness all` diakhiri dengan baris ringkasan yang diawali `!` sebagai
pengganti `✓` dan menghitung berkas yang dibiarkan apa adanya:
`! Installed <n> harnesses (<m> files written); <k> file(s) left as they are, named above.`
Dengan `--clean`, pemasangan seperti itu tidak mencetak langkah berikutnya,
`apothem verify`, yang gagal sampai Anda memperbaiki berkas itu. Dalam dry run,
peringatan untuk berkas yang dibiarkan apa adanya menyatakan bahwa Apothem
"would leave the file as it is", dan eksekusi tetap berakhir dengan `status`
`"dry_run"` dan kode keluar `0`. Aturan dalam profil Anda yang membuka blok kode
dan tidak pernah menutupnya tidak menyembunyikan penanda END dari blok yang
ditulis pemasangan: pemasangan menutup blok kode itu di akhir blok. Blok yang
ditulis rilis sebelumnya dari aturan seperti itu tidak memiliki baris penutup
seperti itu. Blok kode milik Anda yang dibuka di atas blok Apothem dan tidak
pernah ditutup adalah kasus yang berbeda: baris penutup di dalam blok
menutupnya, sehingga blok terbaca sebagai kode. Pemasangan memperingatkan
tentang blok seperti itu segera setelah menulisnya, dan peringatan itu
menyebutkan blok kode yang perlu ditutup di atas penanda BEGIN (lihat
[Apothem tidak dapat membedakan bloknya dari teks Anda](/docs/install/troubleshooting#apothem-cannot-tell-its-block-from-your-text)).
Dry run membaca berkas sebelum apa pun ditulis, sehingga tidak menunjukkan
bahwa blok akan terbaca sebagai kode setelah ditulis.
Amplop `--format json` selalu membawa larik `warnings` lengkap terlepas dari
tingkat verbositas.

Perintah install dan update juga mencetak pemberitahuan sebagai baris `Note:`.
Sebuah pemberitahuan tidak pernah mengubah apa yang ditulis pemasangan. Ketika
sebuah pemasangan menulis root bersama, yaitu jalur yang juga dimuat oleh alat
lain (misalnya folder skill `~/.agents/skills/`), catatan tersebut menyebutkan
alat-alat itu, dan menempatkan alat yang memuat jalur tersebut hanya dalam
kondisi tertentu di dalam tanda kurung, misalnya `Open-Claw (only under its default state
directory)`. Pemasangan yang menulis folder yang juga ditulis oleh pemasangan
lain (peran `holder`) menyatakan bahwa folder tersebut tetap ada sampai
pemasangan Apothem terakhir yang menggunakannya dicopot, dan menyebutkan
pemasangan yang menggunakannya saat ini. Ketika sebuah pemasangan menargetkan
alat yang sudah memuat konten Apothem dari root bersama milik pemasangan lain,
catatan tersebut menyebutkan pemasangan yang menempatkannya: pemilik terdaftar
selama pemilik itu masih menggunakan folder tersebut, atau jika tidak,
pemasangan tertua yang menggunakannya. Dalam amplop `--format json`, setiap
pemberitahuan adalah entri `warnings` dengan `"outcome": "advisory"` dan
`"operation": "shared_root"`; `role`-nya adalah `owner`, `holder`, atau
`reader`, `holders` mencantumkan pemasangan yang menggunakan folder tersebut,
dan `owner_of_record` menyebutkan pemilik tercatat.

Pemasangan yang mendaftarkan hook juga mencetak catatan tentang berkas hook.
Pemberitahuan `hook_review` menyebutkan langkah yang dibutuhkan alat sebelum
menjalankan hook (memulai ulang dan meninjau, atau memercayai workspace), atau
bahaya dari berkas hook yang di-commit oleh sebuah repositori dan menyebutkan
interpreter mesin ini. Pemberitahuan `hook_import` muncul untuk alat yang juga
menjalankan hook di berkas pengaturan Claude Code, seperti yang ditulis oleh
pemasangan Apothem untuk Claude Code, dan menyebutkan sakelar milik alat itu
sendiri untuk mematikan impor tersebut serta apa saja yang juga dihentikan oleh
sakelar itu. Masing-masing adalah entri `warnings` dengan
`"outcome": "advisory"`, `harness`, `path` berkas hook, dan sebuah `message`.

Perintah hook memuat jalur proyek dan jalur interpreter di dalam tanda kutip
ganda, yang dibaca oleh `sh`, Git Bash, dan PowerShell. Jalur yang berisi `$`,
backtick, tanda kutip ganda, atau backslash akan membuat perintah menjalankan
berkas lain, sehingga pemasangan (dan `--dry-run`) berhenti dengan galat yang
menyebutkan jalur tersebut dan tidak menulis apa pun; pindahkan atau ganti nama
proyek lalu jalankan lagi. Spasi atau apostrof dalam jalur tidak menjadi masalah.

Beberapa alat hanya memuat berkas pertama yang berisi teks dari daftar tetap di
sebuah folder, sehingga berkas milik Anda yang berada di depan berkas yang
ditulis Apothem mencegah alat memuat blok Apothem. Misalnya,
[salah satu alat yang didukung](/docs/harnesses/codex#compatibility-notes)
membaca `AGENTS.override.md` yang berisi teks alih-alih `AGENTS.md` yang ditulis
Apothem di sebelahnya di folder home alat itu. Install dan update kemudian
mencetak catatan yang menyebutkan berkas itu, termasuk dry run. Override yang
kosong dilewati, begitu pula tautan simbolik ke `AGENTS.md`; hard link atau
salinan mendapat catatan, karena pemasangan yang menulis ulang `AGENTS.md`
membuatnya menjadi berkas terpisah. OpenCode 1 bekerja dengan cara berbeda:
daftar `instructions` dalam `opencode.jsonc`, bahkan yang kosong, menggantikan
daftar yang ditulis Apothem ke `opencode.json` di folder yang sama.
`config.json`, `opencode.json`, atau `opencode.jsonc` di sana yang tidak dapat
dibaca atau diurai, yang tingkat teratasnya bukan objek, yang nilai
`instructions`-nya bukan daftar teks, atau yang memiliki `{file:path}` yang
menyebutkan berkas yang tidak dapat dibaca menghentikannya dari memuat
konfigurasi apa pun, demikian pula folder dengan salah satu nama itu. Install
dan update juga mencetak catatan
`instruction_override` untuk setiap berkas seperti itu, kecuali `opencode.json`
yang bahkan tidak dapat diurai sebagai JSON5, yang ditolak dengan galat
`config.unparseable`
([catatan OpenCode](/docs/harnesses/opencode#compatibility-notes)). Catatan itu
adalah entri `warnings` dengan `"outcome": "advisory"` dan `"operation": "instruction_override"`,
`harness`, `path` berkas yang dibahas catatan itu, `target` yang ditulis
pemasangan, dan sebuah `message`.

Server MCP pada profil mendapatkan tiga pemberitahuan, masing-masing
menyebutkan bidang profil yang bersangkutan:

| Operasi | Kondisi | Perbaikan |
| --- | --- | --- |
| `mcp_deprecated_transport` | `transport: sse` (spesifikasi MCP menyatakan HTTP+SSE usang) | Gunakan `streamable-http` ketika server mendukungnya. |
| `mcp_plain_http` | URL `http://` ke host yang bukan loopback | Gunakan URL `https://`. |
| `mcp_literal_credential` | nilai `headers` atau `env` yang berbentuk seperti token (`ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`, `sk-`, `xoxa-`, `xoxb-`, `xoxo-`, `xoxp-`, `xoxr-`, `xoxs-`, atau `Bearer` dengan token panjang) | Simpan rahasia dalam variabel lingkungan dan tulis referensi bergaya `${GITHUB_TOKEN}`. |

Pemberitahuan kredensial tidak pernah mencetak nilai yang ditemukannya. Nilai
yang berisi referensi `${...}` tidak pernah ditandai.

## Konfigurasi operator dengan komentar

Beberapa konfigurasi harness adalah berkas yang juga Anda sunting, seperti
`settings.json`, `opencode.json` (yang mungkin berupa JSONC), `openclaw.json`
(JSON5), dan `config.yaml`. Pemasangan menggabungkan kuncinya ke dalam
berkas-berkas ini dan mempertahankan setiap kunci yang Anda tambahkan.

Penggabungan menulis ulang berkas sebagai JSON atau YAML biasa, yang akan
membuang komentar, koma di akhir, dan sintaks JSON5. Oleh karena itu:

- Ketika penggabungan tidak akan mengubah nilai apa pun (misalnya, Anda sudah
  menambahkan sendiri kunci-kunci Apothem), berkas dibiarkan apa adanya, byte
  demi byte.
- Ketika penggabungan harus mengubah sebuah nilai dalam berkas yang membawa
  komentar atau sintaks JSON5, atau dalam berkas yang sama sekali tidak dapat
  di-parse, pemasangan tidak menulis apa pun untuk harness tersebut dan keluar
  dengan kode 1 serta kode galat `config.unparseable`. Bidang `fix` menyebutkan
  kunci yang akan ditambahkan pemasangan, sehingga Anda dapat mengonversi
  berkas ke JSON atau YAML biasa, atau menambahkan kunci tersebut secara manual
  lalu menjalankan ulang.
- Ketika kunci yang diisi pemasangan dengan mapping atau list (misalnya
  `skills.external_dirs` di `config.yaml`) berisi nilai skalar, atau bentuk
  kontainer yang lain, dalam berkas Anda, pemasangan tidak menulis apa pun
  untuk harness tersebut dan keluar dengan kode 1 serta kode galat yang sama,
  karena mengisi kunci itu akan membuang nilai Anda. Galat menyebutkan kunci
  tersebut; ubah ke bentuk yang disebutkannya, atau hapus, lalu jalankan ulang.
  Kunci yang Anda biarkan kosong (`skills:` tanpa isi di bawahnya) akan diisi.

## Opsi

| Opsi | Deskripsi |
|---|---|
| `--harness NAME` | Adapter harness yang akan dipasang, atau `all` untuk himpunan selingkup registri (wajib). Dengan `all`, harness yang tercantum dalam `exclude_harnesses` pada profil dilewati, tetapi harness yang disebut secara eksplisit tetap dipasang meskipun tercantum. Jalankan `apothem harnesses list` untuk nama-nama yang terdaftar. |
| `--profile PATH` | Jalur ke YAML profil bersama. Default-nya `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Mempratinjau pemasangan tanpa menulis berkas. |
| `--clean`, `--fresh` | Awal bersih opt-in: mencadangkan dan menghapus keadaan pemasangan per-harness sebelumnya sebelum memasang. |
| `--yes` | Melewati konfirmasi per target selama penghapusan awal bersih (wajib untuk eksekusi `--clean` non-interaktif). |
| `--project PATH` | Root proyek untuk harness berlingkup-proyek. |
| `--quiet`, `-q` | Menekan keluaran informatif; hanya galat yang dipancarkan. |
| `--verbose`, `-v` | Mencetak alasan setiap kemampuan yang tidak diproyeksikan, alih-alih catatan per harness yang dikelompokkan. |
| `--format plain\|json` | Format keluaran (default: `plain`). |
| `--json` | Singkatan untuk `--format json`. |
| `--no-color` | Menonaktifkan kode warna ANSI dalam keluaran. |
| `-h`, `--help` | Menampilkan bantuan dan keluar. |

## Keluaran JSON

Ketika `--json` (atau `--format json`) diberikan, satu dokumen JSON ditulis ke
stdout:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "install",
  "action": "installed",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": ["C:\\Users\\Example\\.claude\\settings.json"],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Pemasangan yang membiarkan berkas apa adanya karena baris penanda Apothem-nya
memiliki `status` `"partial"` dan keluar dengan kode `2` (lihat
[Catatan kemampuan](#catatan-kemampuan)).

Untuk `--dry-run`, tidak ada yang ditulis dan `results` mencantumkan setiap
jalur yang akan ditulis pemasangan, masing-masing dengan hasil yang akan
diperolehnya (`created`, `updated`, atau `unchanged`) dan, untuk berkas yang
juga Anda sunting, diff terpadu di `detail.diff` — rencana yang sama dengan yang
ditampilkan [`apothem diff`](/docs/cli-reference/diff):

```json
{
  "schema_version": 1,
  "status": "dry_run",
  "command": "install",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "created",
      "operation": "write_text",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "dry run: no filesystem changes made"
    }
  ],
  "warnings": [],
  "error": null
}
```

Hasil yang ditolak di sebuah tautan menyebutkan tautan itu di `detail.symlink`
dan jalur yang ditujunya di `detail.leads_to`. Hasil yang ditolak karena sebuah
tautan membawa folder alat keluar dari direktori home Anda juga membawa
perbaikannya di `detail.fix`.

Ketika `--clean` diberikan, amplop juga membawa objek `clean` yang menjelaskan
fase penghapusan — daftar disposisi per target, apakah eksekusi tersebut
merupakan pratinjau, dan direktori cadangan bercap waktu (`null` dalam dry
run):

```json
{
  "clean": {
    "dry_run": true,
    "backup_dir": null,
    "targets": [
      {
        "path": "C:\\Users\\Example\\.claude",
        "present": true,
        "removed": false,
        "skipped_reason": null
      }
    ]
  }
}
```

Dry run awal bersih mempratinjau kedua fase dalam satu dokumen: pratinjau
penghapusan di bawah `clean` dan pratinjau penulisan baru di bawah `results`.

Galat validasi yang diharapkan menggunakan amplop yang sama dan menyertakan
objek galat:

```json
{
  "schema_version": 1,
  "status": "error",
  "command": "install",
  "harness": "all",
  "files_written": [],
  "error": {
    "code": "project.required",
    "field": "project",
    "reason": "project-scope harnesses require --project: cursor, gemini-cli, github-copilot, kimi-code, windsurf, codebuddy, kiro, trae, zed, glm.",
    "fix": "Pass --project PATH or select only user-scope harnesses."
  }
}
```

## Contoh

```bash
apothem install --harness claude-code
apothem install --harness claude-code --dry-run
apothem install --harness cursor --project . --profile ~/profile.yaml --json
apothem install --harness all --project . --dry-run --json
apothem installing --harness claude-code   # continuous-form alias
apothem Installing --harness claude-code   # capitalized variant
```

## Kode keluar

| Kode | Arti |
|---|---|
| 0 | Adapter berhasil dipasang atau dry-run direncanakan dengan bersih |
| 1 | Galat validasi, profil, harness, proyek, atau adapter yang diharapkan |
| 2 | Parsial: batch berhenti setelah setidaknya satu penulisan, atau pemasangan membiarkan berkas tempat Apothem menyimpan bloknya apa adanya karena baris penanda Apothem-nya (lihat [Catatan kemampuan](#catatan-kemampuan)); `status` bernilai `"partial"` |
| 64 | Galat penggunaan: opsi atau perintah yang tidak dikenal, atau nilai opsi yang hilang atau tidak valid. Di bawah `--json`, galat berupa amplop JSON dengan kode `cli.usage`. |
