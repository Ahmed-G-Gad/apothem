Memigrasikan ruang kerja warisan per-harness ke tata letak `.apothem` bersama.

## Ringkasan

```
apothem migrate-workspace [--project PATH] [--dry-run]
                          [--quiet|-q] [--verbose|-v]
                          [--format plain|json] [--json] [--no-color]
```

`migrate-workspace` menyatukan direktori data warisan per-harness
(`.apothem/<harness>/...`) dan pohon `.plans/` warisan ke dalam satu direktori
kerja bersama `.apothem/{plans,memory,learning,contexts}`. Basisnya adalah root
`--project` yang telah di-resolve bila disediakan, dan jika tidak, direktori
kerja saat ini (default lokal-proyek).

Penyimpanan memori, konteks, dan pembelajaran per-harness digabung secara union
ke dalam penyimpanan bersama berdasarkan id; sinyal pembelajaran disambung lalu
dideduplikasi; rekaman yang berkonflik (id sama, isi berbeda) dilewati, tidak
pernah ditimpa. Pohon `.plans/` warisan dipindahkan ke bawah `.apothem/plans/`.
Setiap sumber yang dikonsumsi dicadangkan terlebih dahulu. Migrasi ini
idempoten — menjalankannya ulang pada pohon yang sudah dimigrasi tidak
melakukan apa pun.

## Opsi

| Opsi | Deskripsi |
|---|---|
| `--project PATH` | Root proyek untuk adapter berlingkup-proyek yang melakukan materialisasi ke pohon proyek alih-alih ke direktori konfigurasi berlingkup-pengguna. |
| `--dry-run` | Mendeteksi tata letak warisan dan melaporkan apa yang akan dimigrasi tanpa menulis. |
| `--quiet`, `-q` | Menekan keluaran informatif; hanya galat yang dipancarkan. |
| `--verbose`, `-v` | Memancarkan keluaran diagnostik tambahan. |
| `--format plain\|json` | Format keluaran (default: `plain`). |
| `--json` | Singkatan untuk `--format json`. |
| `--no-color` | Menonaktifkan kode warna ANSI dalam keluaran. |
| `-h`, `--help` | Menampilkan bantuan dan keluar. |

## Keluaran JSON

Amplop `--json` membawa hasil migrasi. Pada migrasi yang selesai, `status`
bernilai `success` dan payload melaporkan jumlah rekaman yang digabung, apakah
pohon `.plans/` dipindahkan, root cadangan, dan konflik apa pun yang dilewati.
Pemanggilan `--dry-run` sebagai gantinya melaporkan `legacy_layout_detected`.

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "status": "success",
  "base": "/home/example/project",
  "migrated": true,
  "backup_root": "/home/example/project/.apothem/backups/migrate-20260101T120000Z",
  "memory_merged": 12,
  "contexts_merged": 4,
  "learning_merged": 7,
  "conflicts": [],
  "plans_moved": true,
  "notes": []
}
```

Ketika tidak ada tata letak warisan, `migrated` bernilai `false` dan tidak ada
yang ditulis. Amplop `--dry-run` menghilangkan jumlah hasil dan hanya
melaporkan deteksi:

```json
{
  "schema_version": 1,
  "command": "migrate-workspace",
  "base": "/home/example/project",
  "dry_run": true,
  "legacy_layout_detected": false
}
```

## Contoh

```bash
apothem migrate-workspace
apothem migrate-workspace --project .
apothem migrate-workspace --dry-run --json
```

## Kode keluar

| Kode | Arti |
|---|---|
| 0 | Migrasi selesai, atau tidak ditemukan tata letak warisan (tidak ada yang perlu dimigrasi) |
| 1 | Galat yang diharapkan — galat validasi atau root proyek, atau kegagalan migrasi |
| 64 | Galat penggunaan: opsi atau perintah yang tidak dikenal, atau nilai opsi yang hilang atau tidak valid. Di bawah `--json`, galat berupa amplop JSON dengan kode `cli.usage`. |
