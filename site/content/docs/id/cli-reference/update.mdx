Memasang ulang konfigurasi adapter harness dari profil bersama saat ini.

## Ringkasan

```
apothem update --harness NAME|all [--profile PATH] [--dry-run]
                [--project PATH]
                [--quiet|-q] [--verbose|-v]
                [--format plain|json] [--json] [--no-color]
```

`update` mematerialisasi ulang keluaran harness dari profil bersama saat ini.
Perintah ini menggunakan validasi profil, pemilihan `--harness all`, pemeriksaan
cakupan proyek, perilaku dry-run, dan amplop JSON yang sama dengan `install`.

Untuk adapter berlingkup-proyek yang menulis skill ke direktori home Anda
(lihat [`install`](/docs/cli-reference/install#folder-di-direktori-home-anda)),
`update` juga memperbarui folder tersebut dan mencetak `Note:` yang sama yang
menyebutkannya. Adapter yang dipasang sebelum ia menulis skill mendapatkannya
pada update berikutnya. Folder skill yang tidak ditulis oleh Apothem dilewati
dengan peringatan, seperti pada [`install`](/docs/cli-reference/install#folder-di-direktori-home-anda).
Pemasangan yang sebelumnya menulis folder skill bersama ditulis ulang ke dalam
bentuk yang dibagikan oleh setiap pemasangan pada update berikutnya; setiap
folder yang berubah dicadangkan terlebih dahulu.

Alias bentuk-kontinu `apothem updating` (juga diterima sebagai
`apothem Updating`) di-resolve ke handler yang sama.

## Opsi

| Opsi | Deskripsi |
|---|---|
| `--harness NAME` | Adapter harness yang akan diperbarui, atau `all` untuk himpunan selingkup registri (wajib). Dengan `all`, harness yang tercantum dalam `exclude_harnesses` pada profil dilewati, tetapi harness yang disebut secara eksplisit tetap diperbarui meskipun tercantum. |
| `--profile PATH` | Jalur ke YAML profil bersama. Default-nya `~/.config/apothem/profile.yaml`. |
| `--dry-run` | Mempratinjau pembaruan tanpa menulis berkas. |
| `--project PATH` | Root proyek untuk harness berlingkup-proyek. Wajib ketika himpunan harness yang dipilih mencakup adapter berlingkup-proyek. |
| `--quiet`, `-q` | Menekan keluaran informatif; hanya galat yang dipancarkan. |
| `--verbose`, `-v` | Memancarkan keluaran diagnostik tambahan. |
| `--format plain\|json` | Format keluaran (default: `plain`). |
| `--json` | Singkatan untuk `--format json`. |
| `--no-color` | Menonaktifkan kode warna ANSI dalam keluaran. |
| `-h`, `--help` | Menampilkan bantuan dan keluar. |

## Keluaran JSON

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "update",
  "action": "updated",
  "harness": "claude-code",
  "profile_path": "C:\\Users\\Example\\.config\\apothem\\profile.yaml",
  "project": null,
  "files_written": [],
  "results": [],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

`--dry-run` mengembalikan `status: "dry_run"` dan `files_written: []`.

## Contoh

```bash
apothem update --harness claude-code
apothem update --harness claude-code --dry-run
apothem update --harness all --project . --dry-run --json
apothem Updating --harness claude-code   # continuous-form alias
apothem updating --harness claude-code   # lowercase variant
```

## Kode keluar

| Kode | Arti |
|---|---|
| 0 | Adapter berhasil diperbarui atau dry-run direncanakan dengan bersih |
| 1 | Galat validasi, profil, harness, proyek, atau adapter yang diharapkan |
| 2 | Materialisasi batch parsial setelah setidaknya satu penulisan |
| 64 | Galat penggunaan: opsi atau perintah yang tidak dikenal, atau nilai opsi yang hilang atau tidak valid. Di bawah `--json`, galat berupa amplop JSON dengan kode `cli.usage`. |
