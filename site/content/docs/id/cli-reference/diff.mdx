Pratinjau perubahan konfigurasi yang tertunda untuk satu harness.

## Ringkasan

```
apothem diff --harness NAME [--profile PATH] [--project PATH]
             [--quiet|-q] [--verbose|-v]
             [--format plain|json] [--json] [--no-color]
```

`diff` adalah perintah inspeksi hanya-baca. Perintah ini menjalankan materialisasi
yang sama dengan yang akan dijalankan perintah `install`, tetapi dalam mode
dry-run — tidak ada yang ditulis ke disk. Untuk setiap target yang tertunda,
perintah ini merender sebuah aksi dalam bahasa sederhana (misalnya `Write file`,
`Merge directory`, `Install skills`, atau `Prune stale files`), jalur target,
status pratinjau (`would create`, `would update`, `would remove`, atau
`no change`), dan — untuk jangkar milik operator yang akan digabungkan — diff
terpadu dari perubahan tersebut. Status dihitung dengan membandingkan sumber
dengan target yang saat ini ada di disk, sehingga target yang sudah cocok
terbaca `no change` dan disembunyikan dari tampilan default. Perintah ini
menjawab pertanyaan "apa yang akan dilakukan `apothem install` terhadap harness
ini sekarang?" tanpa membuat perubahan tersebut.

Rencana ini mencakup setiap jalur yang ditulis oleh pemasangan: entri manifest,
berkas konfigurasi milik harness itu sendiri (misalnya `opencode.json` atau
`config.yaml`), jangkar instruksi atau dokumen profil tempat profil bersama
diproyeksikan (seperti `CLAUDE.md`), dan penyimpanan data bersama di bawah
`.apothem/`. Tepat setelah pemasangan, `diff` tidak melaporkan perubahan
tertunda apa pun; pemasangan ulang setelah itu tidak menulis apa pun dan tidak
membuat cadangan baru. `install --dry-run` menampilkan rencana yang sama.

Untuk adapter yang menulis skill ke direktori home Anda, rencana mencantumkan
folder tersebut beserta jalur home-nya, sebelum berkas proyek, dan folder skill
yang tidak ditulis oleh Apothem muncul sebagai peringatan `skill_conflict`.

Untuk target milik operator — berkas yang membawa konten Anda sendiri sekaligus
blok yang dikelola Apothem — diff menampilkan baris persis yang akan berubah.
Untuk target lainnya, aksi yang direncanakan dan status pratinjaunya diringkas.

Tampilan default hanya mencantumkan perubahan yang tertunda. Berikan `--verbose`
untuk melihat rencana lengkap, termasuk target yang tidak berubah, yang
dianotasi dengan jenis dan hasil operasi internal mentah. Amplop `--json` tidak
terpengaruh oleh lapisan tampilan: amplop ini selalu membawa bidang `operation`
dan `outcome` mentah untuk konsumen mesin.

`diff` beroperasi pada satu harness. Tidak seperti `install` atau `verify`,
perintah ini tidak menerima `all`; berikan satu nama harness.

## Opsi

| Opsi | Deskripsi |
|---|---|
| `--harness NAME` | Adapter harness yang akan dipratinjau (wajib; satu harness, bukan `all`). |
| `--profile PATH` | Jalur ke YAML profil bersama. Default-nya `~/.config/apothem/profile.yaml`. |
| `--project PATH` | Root proyek untuk harness berlingkup-proyek. Wajib ketika harness yang dipilih berlingkup-proyek. |
| `--quiet`, `-q` | Menekan keluaran informatif; hanya galat yang dipancarkan. |
| `--verbose`, `-v` | Menampilkan rencana lengkap, termasuk target yang tidak berubah, yang dianotasi dengan jenis dan hasil operasi mentah. |
| `--format plain\|json` | Format keluaran (default: `plain`). |
| `--json` | Singkatan untuk `--format json`. |
| `--no-color` | Menonaktifkan kode warna ANSI dalam keluaran. |
| `-h`, `--help` | Menampilkan bantuan dan keluar. |

## Keluaran JSON

Amplop `--json` mencerminkan amplop pemasangan dry-run. `status` bernilai
`dry_run`, `files_written` selalu kosong, dan blok `materialization` beserta
daftar `results` membawa detail lengkap target yang direncanakan. Bidang
`detail.diff` pada setiap baris hasil milik operator membawa string diff
terpadu.

```json
{
  "schema_version": 1,
  "status": "dry_run",
  "command": "diff",
  "action": "dry_run",
  "harness": "claude-code",
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "sentinel_merge",
      "path": "C:\\Users\\Example\\.claude\\CLAUDE.md",
      "message": "dry run: no filesystem changes made",
      "detail": {
        "ownership_class": "operator-owned",
        "diff": "--- a/CLAUDE.md\n+++ b/CLAUDE.md\n@@ ..."
      }
    }
  ],
  "warnings": [],
  "error": null,
  "materialization": { "...": "..." }
}
```

## Contoh

```bash
apothem diff --harness claude-code
apothem diff --harness cursor --project .
apothem diff --harness claude-code --json
```

## Kode keluar

| Kode | Arti |
|---|---|
| 0 | Diff dilaporkan (perubahan tertunda dilaporkan, bukan galat) |
| 1 | Galat validasi, profil, harness, atau proyek yang diharapkan |
| 64 | Galat penggunaan: opsi atau perintah yang tidak dikenal, atau nilai opsi yang hilang atau tidak valid. Di bawah `--json`, galat berupa amplop JSON dengan kode `cli.usage`. |
