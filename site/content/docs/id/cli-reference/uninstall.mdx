Menghapus konfigurasi adapter harness.

## Ringkasan

```
apothem uninstall --harness NAME|all [--yes] [--project PATH]
                   [--quiet|-q] [--verbose|-v]
                   [--format plain|json] [--json] [--no-color]
```

Menghapus target harness yang dikelola adapter, lalu direktori yang dibuat
pemasangan setelah direktori tersebut kosong (direktori yang berisi apa pun
milik Anda tetap ada).

Memori, konteks, dan penyimpanan pembelajaran dari direktori kerja bersama dicadangkan dan dihapus hanya ketika ini adalah harness terakhir yang dipasang di direktori tersebut. Penghapusan dilakukan di lokasi yang dicatat oleh pemasangan, sehingga penghapusan menemukannya di mana pun pemasangan menulisnya (lihat bidang profil `workspace`). Direktori `plans/` tidak pernah dihapus.

Meminta konfirmasi kecuali
`--yes` diberikan. Ketika prompt tidak mungkin ditampilkan — `--format json`
(teks prompt akan merusak dokumen JSON tunggal) atau shell non-interaktif
(tanpa TTY) — perintah menolak sejak awal dengan galat terstruktur
`uninstall.confirmation_required` (keluar 1) kecuali `--yes` diberikan.
Jika harness yang dipilih tidak terpasang, perintah berhasil (keluar 0) dan, pada keluaran biasa, mencetak `NAME is not installed; nothing to remove.`, dengan `NAME` berupa id harness.

Penyimpanan data bersama di bawah `.apothem/` pada root pemasangan (`memory/`,
`contexts/`, `learning/`) tetap ada selama harness terpasang lain pada root yang
sama masih menggunakannya. Ketika harness yang Anda hapus adalah yang terakhir
pada root tersebut, perintah terlebih dahulu menyalin setiap penyimpanan ke root
cadangan Apothem (`~/.apothem/backups/`), lalu menghapusnya beserta seluruh
isinya. Apa pun yang Anda simpan di `plans/` tidak pernah dihapus.

## Folder bersama di direktori home Anda

Beberapa pemasangan dapat menggunakan satu folder di direktori home Anda: folder
skill (`~/.agents/skills/`, atau `~/.codebuddy/skills/`, `~/.kiro/skills/`, atau
`~/.trae/skills/`) serta `~/.config/apothem/rules/` dan
`~/.config/apothem/templates/`. Halaman [install](/docs/cli-reference/install#folder-di-direktori-home-anda)
mencantumkan adapter mana yang menulis folder mana. Apothem mencatat pemasangan
mana yang menggunakan setiap folder, dan pencopotan mengikuti satu aturan:
pencopotan menghapus sebuah folder hanya ketika tidak ada pemasangan Apothem
lain yang masih menggunakannya.

- Mencopot satu alat mempertahankan skill selama pemasangan lain masih
  menggunakannya, dan memberitahukannya. Satu alat yang dipasang di dua proyek
  dihitung sebagai dua pemasangan, sehingga mencopotnya dari proyek A
  mempertahankan folder tersebut selama proyek B masih menggunakannya.
  Pencopotan terakhir menghapusnya (lihat contoh kedua di bawah).
- Hanya apa yang tercantum dalam catatan milik pemasangan itu sendiri yang
  dihapus. Pemasangan yang dibuat sebelum folder tersebut dikelola tidak
  memiliki catatan semacam itu, sehingga mencopotnya tidak menghapus apa pun di
  direktori home Anda. Berkas yang Anda tambahkan ke folder tersebut tetap ada,
  begitu pula folder yang memiliki nama skill Apothem dan tidak ditulis oleh
  Apothem.
- Pemasangan yang folder proyeknya sudah tidak ada diabaikan, sehingga proyek
  yang dihapus tidak menahan folder tersebut selamanya. Catatan menyebutkannya.
- Jika catatan pemasangan yang dapat menggunakan folder tersebut tidak dapat
  dibaca, pencopotan berhenti dengan galat sebelum menghapus apa pun, dan
  pemasangan tetap tercatat. Perbaiki atau pindahkan catatan yang tidak dapat
  dibaca itu, lalu jalankan perintah lagi. Catatan rusak milik alat yang tidak
  pernah menulis folder ini diabaikan.
- Ketika penggunaan terakhir hilang, folder yang tersisa kosong juga dihapus.
  Setiap folder dicadangkan di bawah `~/.apothem/backups/` sebelum dihapus.

Setiap pencopotan mencetak satu `Note:` per folder, misalnya `Note: <harness> -
~/.agents/skills/ was kept: still used by <harness> (/path/to/project)`, atau
`was removed: no other Apothem install uses it`. Dalam amplop `--format json`,
setiap catatan adalah entri `warnings` dengan `"outcome": "advisory"`,
`"operation": "shared_root"`, dan `"role"` bernilai `retained` atau `released`.
Entri itu membawa `path`, `holders` (pemasangan yang mempertahankan folder),
`stale` (pemasangan yang diabaikan), serta `kept` dan `total` (entri tercatat
yang dipertahankan dan entri yang dicantumkan oleh pemasangan).

Jika sebuah folder tetap ada karena pemasangan yang tidak dapat Anda temukan,
catatan menyebutkannya. Ketika folder proyek telah dihapus, pemasangan tersebut
diabaikan dan folder itu ikut terhapus pada pencopotan berikutnya. Ketika
proyek ada tetapi Anda menghapus blok Apothem dari berkas aturannya secara
manual, `uninstall` melaporkan harness tersebut sebagai tidak terpasang dan
tidak melepaskan klaimnya; jalankan `install` untuk harness dan proyek
tersebut, lalu `uninstall`, untuk melepaskannya. `apothem verify` menunjukkan
apakah sebuah folder masih lengkap.

Penghapusan `--harness all` sengaja dibuat menyeluruh: penghapusan ini mencakup
setiap harness yang terdaftar, termasuk harness apa pun yang dilewati
`exclude_harnesses` milik profil saat pemasangan — pembersihan menjangkau
keadaan yang mungkin ditinggalkan oleh pemasangan sebelumnya yang lebih luas.
Harness yang tidak pernah dipasang menerima pemberitahuan yang sama.

Alias bentuk-kontinu `apothem uninstalling` (juga diterima sebagai
`apothem Uninstalling`) di-resolve ke handler yang sama.

## Opsi

| Opsi | Deskripsi |
|---|---|
| `--harness NAME` | Adapter harness yang akan dihapus, atau `all` untuk himpunan selingkup registri (wajib). |
| `--yes` | Melewati prompt konfirmasi. |
| `--project PATH` | Root proyek untuk harness berlingkup-proyek. |
| `--quiet`, `-q` | Menekan keluaran informatif; hanya galat yang dipancarkan. |
| `--verbose`, `-v` | Diterima demi konsistensi dengan perintah lain; perintah ini tidak mencetak keluaran tambahan. |
| `--format plain\|json` | Format keluaran (default: `plain`). |
| `--json` | Singkatan untuk `--format json`. |
| `--no-color` | Menonaktifkan kode warna ANSI dalam keluaran. |
| `-h`, `--help` | Menampilkan bantuan dan keluar. |

## Keluaran JSON

Ketika adapter terpasang dan berhasil dihapus:

```json
{
  "schema_version": 1,
  "status": "success",
  "command": "uninstall",
  "action": "uninstalled",
  "harness": "claude-code",
  "profile_path": null,
  "project": null,
  "files_written": [],
  "results": [
    {
      "harness": "claude-code",
      "outcome": "updated",
      "operation": "uninstall",
      "path": "C:\\Users\\Example\\.claude\\settings.json",
      "message": "managed files removed"
    }
  ],
  "warnings": [],
  "error": null,
  "output_path": "C:\\Users\\Example\\.claude\\settings.json"
}
```

Ketika adapter belum terpasang, perintah keluar dengan `0`. Dalam keluaran JSON,
amplop memiliki `"status": "success"` dan `"action": "uninstalled"`, dan baris
results memiliki `"outcome": "skipped"` dengan pesan `"not installed; no files
removed"`. Bidang `status` tidak pernah bernilai `"not_installed"`.

## Contoh

```bash
apothem uninstall --harness claude-code
apothem uninstall --harness claude-code --yes
apothem uninstall --harness cursor --project . --yes
apothem uninstall --harness all --project . --yes
apothem uninstalling --harness cursor --project . --yes   # continuous-form alias
```

Folder skill bersama tetap ada sampai pemasangan terakhir yang menggunakannya
dicopot:

```bash
apothem install --harness codex
apothem install --harness cursor --project A
apothem uninstall --harness codex --yes                  # keeps ~/.agents/skills/, the cursor install uses it
apothem uninstall --harness cursor --project A --yes     # removes it: no install uses it now
```

## Kode keluar

| Kode | Arti |
|---|---|
| 0 | Adapter dihapus, atau memang tidak terpasang |
| 1 | Harness tidak ditemukan, konfirmasi ditolak atau tidak tersedia (mode non-interaktif atau JSON tanpa `--yes`), atau setiap penghapusan gagal |
| 2 | Penghapusan parsial — setidaknya satu harness telah dihapus sebelum terjadi kegagalan |
| 64 | Galat penggunaan: opsi atau perintah yang tidak dikenal, atau nilai opsi yang hilang atau tidak valid. Di bawah `--json`, galat berupa amplop JSON dengan kode `cli.usage`. |
