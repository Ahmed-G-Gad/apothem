**Vendor:** Google
**Nama instalasi:** `gemini-cli`
**Status:** GA
**Konfigurasi native:** `GEMINI.md` dan `.gemini/` lokal-proyek

## Instalasi

```bash
apothem install --harness gemini-cli --project /path/to/project
```

Adapter ini berlingkup proyek. Adapter memasang `GEMINI.md` proyek, mengonversi
command Apothem menjadi slash command TOML Gemini, menormalkan definisi helper
lokal, dan menempatkan kohor pendukung non-native di bawah `.gemini/.apothem/support/`.
Alat koding lain juga membaca `GEMINI.md` proyek, sehingga blok Apothem di
dalamnya ditulis sebagai panduan untuk seluruh proyek yang tidak menyebut satu
alat pun sebagai pembacanya.

**Berkas yang ditulis:**

```text
GEMINI.md
.gemini/commands/*.toml
.gemini/agents/*.md
.gemini/skills/
.gemini/.apothem/support/
```

## Pemetaan profil ke konfigurasi native

Adapter membaca kohor bersama Apothem dan merutekan masing-masing melalui
permukaan yang kompatibel dengan Gemini. Aturan Markdown, templat, dan materi
hook tetap berada di bawah `.gemini/.apothem/support/` karena semuanya adalah materi pendukung,
bukan direktori aturan native Gemini.
Blok Apothem di `GEMINI.md` diakhiri dengan bagian berkas pendukung Apothem
yang menyebutkan, relatif terhadap akar proyek, direktori di bawah
`.gemini/.apothem/support/` tempat setiap kutipan bergaya repositori
(`rules/<name>.md`, `templates/...`, `hooks/...`) di-resolve. Jalur-jalur
tersebut relatif sehingga `GEMINI.md` yang di-commit tidak membawa jalur khusus
mesin.

Setiap command yang dikonversi di `.gemini/commands/` memuat sebuah
`description` dan sebuah `prompt`. Prompt tersebut hanya berisi instruksi
command; metadata Apothem di bagian atas berkas sumber (versi, daftar alat, dan
bidang serupa) dihilangkan, sehingga model tidak pernah membacanya sebagai
instruksi. Gemini menjalankan command kustom hanya ketika Anda mengetikkannya.

Definisi helper di `.gemini/agents/` mempertahankan batas alat dan batas
gilirannya: izin `tools` dari sumber, dikurangi `disallowedTools`, menjadi
daftar-izin `tools` Gemini yang berisi nama-nama alat Gemini, dan `maxTurns`
menjadi `max_turns`. Karena itu, helper read-only tidak mendapat alat
`write_file` maupun `replace`. Tidak ada model yang disetel, sehingga setiap
helper mewarisi model sesi.

## Catatan kompatibilitas

`~/.gemini/` tetap menjadi wilayah lingkup pengguna bagi alat yang menggunakan
profil Gemini global. Adapter Gemini CLI hanya menulis ke proyek yang
diteruskan melalui `--project`.

## Verifikasi

```bash
apothem verify --harness gemini-cli --project /path/to/project
```

Perintah verify memastikan bahwa:

1. Konfigurasi native ada di jalur yang diharapkan.
2. Semua bidang wajib dari profil bersama ada.
3. Rutin verifikasi khusus adapter melaporkan keberhasilan.

## Pembaruan

```bash
apothem update --harness gemini-cli --project /path/to/project
```

Menyegarkan `GEMINI.md`, command yang dikonversi, definisi helper lokal, skill
yang terpasang, dan pohon pendukung `.gemini/.apothem/support/`.

## Pencopotan

```bash
apothem uninstall --harness gemini-cli --project /path/to/project
```

Menghapus berkas konfigurasi native yang ditulis oleh adapter.
YAML profil bersama dan mesin Apothem tidak terpengaruh.

## Gerbang konformitas

```bash
python -m apothem.conformity.gate --all .
```

## Pemecahan masalah

| Gejala | Perbaikan |
|---------|-----|
| Berkas konfigurasi tidak ditemukan | Jalankan ulang `apothem install --harness gemini-cli --project /path/to/project` |
| Verifikasi gagal | Jalankan `apothem update --harness gemini-cli --project /path/to/project`, lalu verifikasi lagi |
| Konten konfigurasi tidak terduga | Periksa `~/.config/apothem/profile.yaml` atau `--profile PATH`, lalu jalankan ulang `apothem update --harness gemini-cli --project /path/to/project` |

## Tombol konfigurasi

| Flag | Default | Deskripsi |
|------|---------|-------------|
| `--dry-run` | `false` | Pratinjau instalasi tanpa menulis berkas. |
