**Vendor:** Zed Industries
**Nama instalasi:** `zed`
**Status:** GA
**Konfigurasi native:** `<project>/.rules`

## Instalasi

```bash
apothem install --harness zed --project /path/to/project
```

Adaptor menulis satu berkas instruksi Zed berlingkup proyek dari aturan dan
permukaan tata kelola Apothem bersama. Zed membaca satu berkas instruksi
proyek, yaitu kecocokan pertama dalam daftar ini:

```text
.rules
.cursorrules
.windsurfrules
.clinerules
.github/copilot-instructions.md
AGENT.md
AGENTS.md
CLAUDE.md
GEMINI.md
```

Tidak ada direktori aturan per-alat, sehingga seluruh permukaan Apothem
mendarat di berkas `.rules` datar di urutan teratas daftar tersebut.

**Berkas yang ditulis:** `<project>/.rules`

## Pemetaan profil ke konfigurasi native

Adaptor membaca profil bersama Apothem dan merender berkas `.rules` proyek pada
setiap kali `apothem install` atau `apothem update` dijalankan. Profil bersama
adalah sumber kebenaran; setiap `.rules` yang sudah ada sebelumnya (atau
suntingan lokal-proyek pada berkas yang dihasilkan) dicadangkan sebelum
sinkronisasi berikutnya mengganti konten yang dikelola Apothem.

## Catatan kompatibilitas

Zed menetapkan `AGENTS.md` sebagai berkas instruksi utamanya dan mempertahankan
`.rules` proyek sebagai berkas kompatibilitas yang didukung
([instruksi Zed](https://zed.dev/docs/ai/instructions)). Karena Zed hanya
membaca kecocokan pertama, `.rules` yang baru menyembunyikan `AGENTS.md`,
`CLAUDE.md`, atau berkas lain yang lebih rendah dalam daftar yang sudah
diandalkan proyek. Instalasi tidak pernah menyunting berkas-berkas tersebut.
Ketika `.rules` hanya berisi blok Apothem dan sebuah berkas berprioritas lebih
rendah berisi teks Anda, install dan update mencetak peringatan yang menyebutkan
berkas yang tersembunyi; salin instruksi yang Anda perlukan ke dalam `.rules` di
luar blok Apothem agar instruksi tersebut tetap terbaca di Zed.

Berkas instruksi global `~/.config/zed/AGENTS.md` dan blok server konteks MCP
(`.zed/settings.json` `context_servers`) dimiliki operator; Apothem tidak
menulisnya.

## Verifikasi

```bash
apothem verify --harness zed --project /path/to/project
```

Perintah verify mengonfirmasi bahwa:

1. Konfigurasi native ada di jalur yang diharapkan.
2. Setiap target terkelola ada; berkas terkelola tidak kosong, dan konfigurasi JSON atau YAML dapat diurai. Tambahkan `--profile PATH` untuk juga memastikan bahwa berkas yang terpasang cocok dengan profil tersebut.
3. Rutin verifikasi khusus adapter melaporkan keberhasilan.

## Pembaruan

```bash
apothem update --harness zed --project /path/to/project
```

Menurunkan ulang berkas `.rules` proyek dari keadaan profil bersama saat ini.

## Pencopotan

```bash
apothem uninstall --harness zed --project /path/to/project
```

Menghapus blok terkelola Apothem dari berkas konfigurasi native `.rules` dan mempertahankan teks Anda sendiri. Berkas dihapus hanya ketika tidak ada yang tersisa di dalamnya. Sebelum perubahan, salinan berkas yang diberi cap waktu disimpan di bawah `~/.apothem/backups/`; tidak ada berkas cadangan yang tertinggal di proyek. YAML profil bersama dan mesin Apothem tidak terpengaruh.

## Gerbang konformitas

```bash
python -m apothem.conformity.gate --all .
```

## Pemecahan masalah

| Gejala | Perbaikan |
|---------|-----|
| Berkas konfigurasi tidak ditemukan | Jalankan ulang `apothem install --harness zed --project /path/to/project` |
| Verifikasi gagal | Jalankan `apothem update --harness zed --project /path/to/project`, lalu verifikasi lagi |
| Konten konfigurasi tidak terduga | Periksa `~/.config/apothem/profile.yaml` atau `--profile PATH`, lalu jalankan ulang `apothem update --harness zed --project /path/to/project` |

## Tombol konfigurasi

| Flag | Default | Deskripsi |
|------|---------|-------------|
| `--dry-run` | `false` | Pratinjau instalasi tanpa menulis berkas. |
