**Vendor:** Tencent
**Nama instal:** `codebuddy`
**Status:** GA
**Konfigurasi native:** `<project>/.codebuddy/rules/apothem-rules.md`

## Instalasi

```bash
apothem install --harness codebuddy --project /path/to/project
```

Adaptor menulis satu berkas aturan berlingkup-proyek dari permukaan aturan dan tata
kelola Apothem bersama.

**Berkas yang ditulis:** `<project>/.codebuddy/rules/apothem-rules.md`

## Pemetaan profil ke konfigurasi native

Adaptor membaca profil bersama Apothem dan merender berkas aturan proyek pada setiap
jalannya `apothem install` atau `apothem update`. CodeBuddy membaca setiap berkas
`*.md` di bawah `.codebuddy/rules/` sebagai Markdown dengan frontmatter YAML opsional
(`alwaysApply`, `paths`, `enabled`) sesuai
[dokumentasi CodeBuddy Rules](https://www.codebuddy.ai/docs/ide/Rules); berkas Apothem
membawa `alwaysApply: true`, sehingga permukaan tata kelola diterapkan pada setiap
interaksi. Profil bersama adalah sumber kebenaran; suntingan lokal-proyek pada berkas
yang dihasilkan dicadangkan sebelum sinkronisasi berikutnya mengganti konten yang
dikelola Apothem.

## Catatan kompatibilitas

Permukaan aturan CodeBuddy berlingkup-proyek di bawah `.codebuddy/rules/`. Adaptor
menulis berkas `apothem-rules.md` khusus yang berdampingan dengan berkas aturan apa pun
yang ditulis operator di direktori yang sama. Berkas memori proyek `CODEBUDDY.md` dan
`.codebuddy/settings.json` (izin, MCP) milik operator; Apothem tidak menulisnya. Skill,
perintah, agen, dan hook dirujuk sebagai disiplin di dalam berkas aturan — CodeBuddy
tidak mengekspos permukaan berkas milik adaptor untuk mereka. Konvensi permukaan vendor
yang menjadi sandaran adaptor disematkan di
`src/apothem/harnesses/codebuddy/STANDARD-CONVENTION-PIN.md`, di-snapshot terhadap
dokumentasi CodeBuddy langsung.

## Verifikasi

```bash
apothem verify --harness codebuddy --project /path/to/project
```

Perintah verify mengonfirmasi bahwa:

1. Konfigurasi native ada di jalur yang diharapkan.
2. Berkas aturan terkelola hadir dan tidak kosong.
3. Rutin verifikasi khusus adaptor melaporkan keberhasilan.

## Pemutakhiran

```bash
apothem update --harness codebuddy --project /path/to/project
```

Menurunkan-ulang berkas aturan proyek dari keadaan profil bersama saat ini. `install`
dan `update` bersifat idempoten — menjalankan ulang menimpa berkas terkelola dengan
konten terender terbaru.

## Pencopotan

```bash
apothem uninstall --harness codebuddy --project /path/to/project
```

Menghapus berkas konfigurasi native yang ditulis oleh adaptor, mengganti nama berkas
aturan terkelola menjadi cadangan bertanda waktu. YAML profil bersama dan mesin Apothem
tidak terpengaruh.

## Gerbang konformitas

```bash
python -m apothem.conformity.gate --all .
```

## Pemecahan masalah

| Gejala | Perbaikan |
|---------|-----|
| Berkas konfigurasi tidak ditemukan | Jalankan ulang `apothem install --harness codebuddy --project /path/to/project` |
| Verifikasi gagal | Jalankan `apothem update --harness codebuddy --project /path/to/project`, lalu verifikasi lagi |
| Konten konfigurasi tak terduga | Periksa `~/.config/apothem/profile.yaml` atau `--profile PATH`, lalu jalankan ulang `apothem update --harness codebuddy --project /path/to/project` |

## Tombol konfigurasi

| Flag | Default | Deskripsi |
|------|---------|-------------|
| `--dry-run` | `false` | Pratinjau instalasi tanpa menulis berkas. |
