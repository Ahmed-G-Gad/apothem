**Vendor:** Z.ai
**Nama instalasi:** `glm`
**Status:** GA
**Konfigurasi native:** `<project>/.apothem/providers/glm.toml`

GLM (Z.ai) adalah **backend model**, bukan alat pengodean tersendiri. Z.ai tidak
menyediakan antarmuka baris perintah GLM resmi miliknya sendiri; sebagai
gantinya, alat yang menggunakan protokol yang kompatibel dengan Anthropic atau
yang kompatibel dengan OpenAI diarahkan ke GLM dengan menyetel base URL backend
dan sebuah kunci. Apothem tetap memasukkan GLM ke dalam adapter harness-nya,
sehingga Anda memilihnya dengan `--harness glm` seperti adapter lain. Adapter
`glm` menulis berkas konfigurasi penyedia yang mencatat kedua permukaan
kompatibilitas tersebut sehingga alat kompatibel apa pun dapat disambungkan ke
keluarga model GLM.

## Instalasi

```bash
apothem install --harness glm --project /path/to/project
```

Adapter menulis satu berkas penyedia berlingkup proyek yang mencatat endpoint
backend GLM dan placeholder yang dapat dikonfigurasi operator.

**Berkas yang ditulis:** `<project>/.apothem/providers/glm.toml`

## Pemetaan profil ke konfigurasi native

Berkas penyedia mencatat dua backend. Backend yang kompatibel dengan Anthropic
menggunakan base URL `https://api.z.ai/api/anthropic`; alat yang menggunakan
protokol Anthropic dirutekan ke GLM dengan menyetel `ANTHROPIC_BASE_URL`,
`ANTHROPIC_AUTH_TOKEN`, dan secara opsional `API_TIMEOUT_MS`. Tabel
`[backends.anthropic_compatible.env]` di dalam berkas mencantumkan variabel-variabel
tersebut dan juga `ANTHROPIC_DEFAULT_OPUS_MODEL`,
`ANTHROPIC_DEFAULT_SONNET_MODEL`, dan `ANTHROPIC_DEFAULT_HAIKU_MODEL`, yang
memetakan peran opus, sonnet, dan haiku milik alat ke model GLM. Backend yang
kompatibel dengan OpenAI menggunakan base URL
`https://api.z.ai/api/coding/paas/v4`. Token autentikasi adalah placeholder
yang Anda ganti dengan kunci Z.ai Anda sendiri — Apothem tidak pernah menulis
rahasia sungguhan. ID model mudah berubah antarversi, sehingga Apothem tidak
mematok satu pun; berkas tersebut membawa placeholder `<GLM_MODEL_ID>` yang
Anda isi dari [dokumentasi Z.ai](https://docs.z.ai/devpack/tool/claude) yang
terkini. Tidak ada apa pun dari profil bersama yang masuk ke berkas ini; berkas
ini adalah templat tetap.

## Catatan kompatibilitas

Karena GLM adalah backend dan bukan alat pengodean, GLM tidak mengekspos
permukaan untuk aturan, command, skill, atau hook — adapter hanya menulis berkas
penyedia backend dan tidak ada yang lain. Kunci Z.ai Anda dan pilihan ID model
Anda tetap menjadi milik operator. Konvensi permukaan vendor yang menjadi
sandaran adapter dipatok di `src/apothem/harnesses/glm/STANDARD-CONVENTION-PIN.md`,
yang di-snapshot terhadap dokumentasi Z.ai yang berlaku.

GLM menjalankan keluarga model GLM dari Z.ai; lihat
[referensi konfigurasi vendor](https://docs.z.ai/devpack/tool/claude) untuk
permukaan konfigurasi backend, model, dan kompatibel-Anthropic yang terkini.

## Verifikasi

```bash
apothem verify --harness glm --project /path/to/project
```

Perintah verify memastikan bahwa:

1. Konfigurasi native ada di jalur yang diharapkan.
2. Berkas penyedia ada dan tidak kosong.
3. Rutin verifikasi khusus adapter melaporkan keberhasilan.

## Pembaruan

```bash
apothem update --harness glm --project /path/to/project
```

Berkas penyedia menjadi milik Anda begitu berkas itu ada. `install` dan `update`
sama-sama menulis templat hanya ketika `.apothem/providers/glm.toml` tidak ada,
dan keduanya tidak pernah menimpanya setelah itu, sehingga referensi kunci dan
pilihan model Anda bertahan pada setiap eksekusi ulang. Untuk mengambil templat
yang lebih baru, pindahkan berkas Anda ke tempat lain, jalankan `update`, lalu
salin nilai-nilai Anda ke berkas yang baru.

## Pencopotan

```bash
apothem uninstall --harness glm --project /path/to/project
```

Menghapus berkas penyedia hanya ketika Apothem yang membuatnya dan berkas itu
masih berupa templat yang belum disunting, dengan terlebih dahulu
mencadangkannya di bawah akar cadangan Apothem. Berkas yang Anda buat atau
sunting dibiarkan di tempatnya. YAML profil bersama dan mesin Apothem tidak
terpengaruh.

## Gerbang konformitas

```bash
python -m apothem.conformity.gate --all .
```

## Pemecahan masalah

| Gejala | Perbaikan |
|---------|-----|
| Berkas konfigurasi tidak ditemukan | Jalankan ulang `apothem install --harness glm --project /path/to/project` |
| Verifikasi gagal | Berkas penyedia hilang atau kosong. Jika berkas hilang, jalankan `apothem update --harness glm --project /path/to/project`. Jika berkas kosong, pindahkan `.apothem/providers/glm.toml` ke tempat lain terlebih dahulu, lalu jalankan `update` dan verifikasi lagi |
| Konten konfigurasi tidak terduga | Sunting `.apothem/providers/glm.toml` secara langsung; Apothem tidak pernah menulis ulang berkas yang sudah ada, dan profil bersama tidak menambahkan apa pun ke dalamnya. Untuk templat yang baru, pindahkan berkas ke tempat lain lalu jalankan `apothem update --harness glm --project /path/to/project` |
